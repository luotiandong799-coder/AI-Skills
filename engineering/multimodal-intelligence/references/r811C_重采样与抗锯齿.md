## 实拉来源（WebFetch 200 逐字，≥2 独立域）

### 源1 · Pillow《Resampling filters compared: which one to use, measured》
URL: https://pillowpython.com/guides/resampling-filters/
（Tested with Pillow 13.0.0 · Python 3.13 · Updated 2026-11-22，实测数据页）

逐字引文与数据：
- "Every resize in Pillow uses a resampling filter, and the choice decides whether a shrunk image is crisp, blurry or full of moiré patterns, and how long it takes."
- Short answer 逐字："Use `Image.LANCZOS` for shrinking photos, `Image.BICUBIC` when you want nearly the same quality a little faster, and `Image.NEAREST` only for pixel art or masks whose exact values must not be blended. Pillow 13 adds `Image.MKS2013`, which measured sharper than `LANCZOS` with about as little aliasing and runs faster; it is not available on Pillow 12 or older. `Image.ANTIALIAS` was the old name of `LANCZOS` and was removed in Pillow 10."
- 八滤波器枚举：NEAREST=0 / BOX=4 / BILINEAR=2 / HAMMING=5 / BICUBIC=3 / LANCZOS=1 / MKS2013=6 / MKS2021=7。
- "The short names (`Image.LANCZOS`) and the enum (`Image.Resampling.LANCZOS`) are the same value. The enum only exists in Pillow 9.1 and newer … resize() uses `BICUBIC` for photos when you pass no filter (for `1` and `P` images it uses `NEAREST`)."
- "MKS2013 and MKS2021 are new in Pillow 13: John Costella's \"Magic Kernel Sharp\" filters, which build a sharpening step into the kernel. They reach 2.5 and 4.5 source pixels to each side (LANCZOS reaches 3). They work in `resize()` and `thumbnail()`, but not in `rotate()` or `transform()`, which only accept NEAREST, BILINEAR and BICUBIC."
- 缩小 4× 残留假图案标准差（越小越干净）：NEAREST 90.8 / BOX 10.4 / BILINEAR 1.2 / HAMMING 4.9 / BICUBIC 1.0 / LANCZOS 0.6 / MKS2013 1.1 / MKS2021 0.9。
- 缩小 4× 真实细节保留（越大越锐）：NEAREST 91.3 / BOX 70.6 / BILINEAR 54.2 / HAMMING 66.4 / BICUBIC 69.7 / LANCZOS 79.1 / MKS2013 84.3 / MKS2021 75.5；"NEAREST scores high only because it keeps everything, aliasing included. Among the clean filters MKS2013 keeps the most."
- "Read the two charts together. `BILINEAR` is clean but soft; `LANCZOS` is clean and sharp; `MKS2013` kept about 7% more contrast than `LANCZOS` for barely more leftover pattern."
- 速度（1600→400 缩小 / 400→1600 放大，ms）：NEAREST 0.08/0.78 · BOX 3.12/5.75 · BILINEAR 5.13/7.32 · HAMMING 5.24/7.57 · BICUBIC 9.12/10.51 · LANCZOS 14.38/13.90 · MKS2013 10.98/12.86 · MKS2021 21.25/19.51。
- "`LANCZOS` costs about 10 ms more than `BILINEAR` per photo here, and `BILINEAR` is already nearly free of aliasing on the test pattern … For photos the extra milliseconds are worth paying; it only matters when you resize thousands of images per second."
- "Enlarging cannot add detail; the filter only decides how to fill the gaps."；"`NEAREST` keeps hard pixel edges (right for pixel art and QR codes); `BILINEAR` is soft; `BICUBIC` and `LANCZOS` are sharper but add faint light and dark halos along edges."
- 大图：`resize(LANCZOS)` 167.6ms → `resize(LANCZOS, reducing_gap=3)` 55.1ms → `reduce(10)` 13.0ms；"largest pixel difference with reducing_gap: 3"；"The result differs from a plain resize by at most a few levels, which is invisible. `thumbnail()` uses `reducing_gap=2.0` by default, and for JPEGs it also asks the decoder for a smaller image with `draft()`"。
- 按用途选型表逐字：Thumbnails/web images from photos→LANCZOS（"Least aliasing; the cost is small"）；Pillow 13→MKS2013；Many images speed matters→BICUBIC or reducing_gap；Pixel art/icons/QR enlarged→NEAREST（"Keeps hard edges and exact colours"）；Segmentation masks/label maps→NEAREST（"Other filters blend labels into values that mean nothing"）；Shrinking by exact integer factor→reduce(n) or BOX；Machine-learning preprocessing→"whatever the model was trained with — Usually `BILINEAR` or `BICUBIC`; mismatches cost accuracy"。

### 源2 · JOVANA Education《影像取樣》Glossary
URL: https://jovanaeducation.com/zh/glossary/image-sampling

逐字引文（繁体原文）：
- "取樣是把圖片數位化的「空間那一半」…該網格的間距,即取樣率…主宰了影像最多能承載的最細空間細節。"
- "「多細才夠細」由奈奎斯特–香農取樣定理精確回答。若入射影像沒有高於某個最大值 f_max 的空間頻率…那麼以高於 2 f_max 的取樣率——奈奎斯特率,亦即最細細節每個週期至少兩個取樣——就能精確擷取訊號,於是原則上連續影像可被無誤地重建。"
- "取樣慢於此即為欠取樣（undersampling）：高頻無法被表示,而且它們不會單純消失,反而會偽裝成虛假的低頻。這就是混疊（aliasing）的根本原因。"
- "實際的後果是：你必須在取樣之前先做頻帶限制（band-limit）。真實場景含有任意細的細節…解法是先稍微模糊,以抗鋸齒光學低通濾鏡,或對每個像素的面積取平均,移除高於奈奎斯特極限的頻率,使剩下的能被忠實取樣。"
- "同樣的邏輯也支配軟體中的每一次縮放與縮小：要正確縮小影像,你必須先低通濾波再次取樣,絕不能只是丟掉像素。"
- "靠單純跳過像素（最近鄰）來縮小是欠取樣,會產生混疊——鋸齒狀斜線、閃爍的細線、紋理上的摩爾紋。在降低解析度前務必先低通濾波（例如面積平均或高斯模糊）；同樣的「先濾波再次取樣」規則也適用於建構 SIFT 與 CNN 前處理所用的影像金字塔。"

## 判非
- 「缩小=低通滤波再重采样」不是「丢像素」；最近邻缩小=欠采样=混叠（锯齿/摩尔纹/闪烁），此规则同样适用 SIFT/CNN 图像金字塔。
- 滤波器选型是混叠残留×锐度×速度三维实测权衡，非口号：LANCZOS 最干净锐利但有振铃且最慢；NEAREST 残留混叠 90.8 远高于其余（≤10.4）；MKS2013 在 Pillow 13 又锐又快但只支持 resize/thumbnail。
- 报缩放须写滤波器名+库版本+reducing_gap：库默认（照片 BICUBIC、1/P 图 NEAREST）会暗中改变结论；ML 预处理跟随训练口径（BILINEAR/BICUBIC），mask/标签图必须 NEAREST。
