# AI 智能体记忆与技能治理（Memory & Skill Governance）

记忆与技能是**同一条知识流水线**的两段：超限的记忆该压缩合并外置，技能库该体检去重防漂移。本技能是这套统一治理的方法论总纲——记忆层与技能层用同一套判据宪法、同一条事件驱动流程。

## 部署形态与何时用

本技能是**定时自动巡检的治理守护**：部署为定时任务（如每日固定时刻 cron/调度器）后全自动执行，无需人工触发、无需每次对话手动唤起。

- 记忆逼近容量上限（黄线/红线），怕越涨越多、越久越乱——自动治理消化存量
- 记忆里混进了身份定义、操作手册、过期事件，分不清该留哪——自动分层归位
- 技能库出现同名双副本、内容重叠冗余、引用漂移——自动体检并累积建议清单

> 自动侧到清单与报告为止；删除/不可逆动作永远等人工裁决（见治理哲学）。

## 治理哲学

> **能自动的自动（零信息丢失），删信息才问人；日常静默，红线上报。可逆操作全自动，删除/不可逆永远人工。**

| 层级 | 处置动作 | 自动化边界 |
|:--|:--|:--|
| P0 自动 | MERGE 合并 / COMPRESS 压缩 / TO-SKILL 外置（自动建）/ TO-ARCHIVE 归档（留短指针） | 脚本执行+护栏校验，零人工 |
| P1 只累积 | DELETE-CANDIDATE 删除候选、技能合并/归档候选 | 只进待决清单，等用户裁决 |
| P2 人工 | 技能生命周期变更（合并/归档/改名/删）、共享库新建技能、任何不可逆动作 | 用户确认后执行 |

**红线**：治理绝不因超限自动"删/并技能"——技能是资产；自动只做检测+建议清单累积。删除/不可逆动作永远人工。

## 分层治理模型（判据宪法）

统一治理覆盖六类内容，每层"装什么、上限、怎么治"各不相同：

| 层 | 内容 | 上限 | 治理模式 | 判据核心 |
|:--|:--|:--|:--|:--|
| L0 身份层 | 人格/沟通风格/固化行为约束（跨上下文稳定、无路径无ID） | 10k | LLM 仲裁，建议稿人工确认，双向流动 | 身份/人格 |
| L1 记忆层 | 环境事实骨架、带坐标行为规则、指向权威位置的指针 | 4k | 差异驱动自动+人工清单 | 高频注入层，清重复副本 |
| L1 画像层 | 用户是谁——核心偏好、身份事实、纠正史 | 4k | 同记忆，动作收窄 | 偏好永不外置 |
| L2 技能层 | 可复用工作流（SKILL.md） | 无 | 只收不压，体检人工 | TO-SKILL 落点/共享独有 |
| L3 外部记忆 | 事实/事件/实体的权威存储 | 大容量 | 不压缩，定期审计 | 权威存储，零丢失 |
| — 杂项 | 配置/凭据/游离文件 | — | 不压/归并 | 人工 |

**单向流动铁律**：操作程序（命令/路径/配置/工具用法/踩坑修复步骤）→ 技能层；事实重复品 → 外部记忆删副本；固化行为/人格 → 身份层上移。**画像层（用户核心偏好）永不外置技能**。

## 触发机制（定时调度 + 差异驱动）

部署为**定时任务**（每日固定时刻 cron/调度器），到点自动运行，不依赖对话触发：

| 场景 | 动作 |
|:--|:--|
| 首日（无昨日快照） | 建基线；已 ≥85% 黄线 → 存量治理一次（消化存量） |
| 当日净增 ≥ 阈值（如 300 字符） | LLM 整文件治理 |
| 占用 ≥ 90% 红线 | 无论差异强制治理（慢速积累兜底） |
| 差异小且未触红线 | **静默**（不打扰），快照更新，下次再看 |

治理顺序按占用率降序：⛔ 99%+ 熔断优先 → ≥90% 红线档 → 85-90% 黄线档。

## 五类处置动作（判据）

治理引擎逐条判定 + 人工裁决共用同一套判据：

| 动作 | 含义 | 自动化 | 示例 |
|:--|:--|:--|:--|
| **KEEP** | 原样保留 | — | 操作铁律/身份定义/红线/用户核心偏好/行为规范 |
| **MERGE** | 同主题多条（重复对）→ 合并一条 | P0 自动 | 同一事件被记两次 |
| **COMPRESS** | 删冗余叙事保留全部事实 | P0 自动 | 长文自指文档、重复措辞 |
| **TO-SKILL** | 纯程序性细节外置技能，记忆留指针 | P0 自动* | 命令/路径/配置/工具用法/踩坑修复步骤 |
| **TO-ARCHIVE** | 历史事件/过时状态 → 记忆留一行指针 | P0 自动 | 已修复事故的完整经过 |
| **DELETE-CANDIDATE** | 完全过期无价值 | P1 只累积，人工裁决 | 已失效技术状态且无指针价值 |

\* TO-SKILL 例外：目标技能需新建于共享库 → P2 人工确认（私有库可自动建）。

**逐条判定细则（喂模型的判据 prompt 模板）**：

```
你是 AI 智能体的记忆治理专家。给定若干条记忆条目（每条已编号），逐条给出处置建议。
动作判据：
- KEEP = 操作铁律/身份定义/红线/用户核心偏好/行为规范——原样保留，不得压缩删除
- MERGE = 同主题多条（同一事件/主题被记两次的重复条目对）→ 合并一条，两条差异细节全部保留
- COMPRESS = 删冗余叙事，保留全部专名/命令/端口/路径/数字/日期/结论
- TO-SKILL = 纯程序性细节（命令/路径/配置/工具用法）→ 外置技能，记忆留一句指针
- TO-ARCHIVE = 历史事件/过时状态 → 留一行指针
- DELETE-CANDIDATE = 完全过期无价值（红线动作，仅建议不执行）
规则：
1. 先通读全部条目找重复对/同主题组再逐条判定——两条记同一事件的必须 MERGE 成一条，不只 COMPRESS 其中一条
2. 含"铁律""规范""义务""红线""禁止"字样的行为规则条目 → KEEP
3. 压缩/合并必须保留全部专名/ID/路径/端口/群ID/日期/结论
4. 拿不准倾向 KEEP（宁保守不错杀）
只输出 JSON 数组：{"id","action","reason","merged_with","output_text"}。无任何额外内容。
```

## 写入五问（防新增膨胀——写新记忆前自问）

1. 与已有条目同主题？→ 合并更新，不新增
2. 新说法覆盖旧说法？→ 替换旧的，不并存
3. 操作细节/步骤/命令？→ 进技能，不进记忆
4. 临时状态/进行中？→ 不写记忆（用会话/任务清单）
5. 核心偏好/身份定义？→ 画像层；环境事实 → 记忆层

## 外置次序铁律（TO-SKILL 执行前置）

从记忆裁剪细节外置到技能前，必须先核对目标技能内容：

1. **先核对**：查看目标技能（及 references）——该信息是否已包含？
2. **已包含** → 才可裁剪记忆对应细节（记忆留一行指针/结论）
3. **未包含** → **先补技能再裁记忆**：缺失信息完整补进技能，确认收录后才裁剪
4. 外置后留档 diff（改了哪个技能、补了什么、从哪条记忆裁了什么）

**禁止**：裁了记忆、技能里又没有 = 信息真空。宁可技能冗余，不可信息丢失。

## 技能调整关联性铁律（技能治理前置）

**对任何技能做调整（改名/合并/归档/删改/移动路径）前，必须四维排查并同步调整，不留遗漏**——否则引用方照旧引用即失效：

1. **记忆层**：grep 全部记忆文件中的技能名/路径/用法
2. **技能层**：grep 各 SKILL.md frontmatter（related_skills）与正文互引
3. **任务层**：查定时任务/调度挂载的技能参数
4. **文档层**：知识沉淀文档、脚本注释、外部记忆中的引用

改前把"排查范围 + 命中清单 + 同步调整计划"留档；调整动作连所有命中引用一起改完，逐条验证引用方可用。**先排查后动手，宁可慢不可漏。**

## 安全护栏（全部强制）

1. **专名校验**：原条目路径/ID/端口/日期/commit 必在成品稿，缺失补回、补不回转人工（模型丢专名是高频失败）
2. **MERGE 两稿并集**：同组两条合并稿各缺对方独有细节 → 并集去重后再校验
3. **防膨胀护栏**：COMPRESS 稿须 <95% 原文长度；MERGE 稿须 <95% 两原条目之和；TO-ARCHIVE 仅当原条目 ≥200 字符（短条目归档指针开销 ~30 字符无收益）；已含 archive/归档/留档/指针 的条目禁再归档（防叠指针）
4. **归档留短指针**：`〔已归档<date>, 全文见治理留档〕`
5. 备份先行保留 14 天 / 单次降幅 ≤40% / 同文件治理间隔 ≥24h / 全审计留档
6. **达标即停**：降到 <85% 即停，不做超额治理

**膨胀 bug 实证（勿重蹈）**：一条 65 字符的指针条目被 TO-ARCHIVE 叠成 127 字符（+62 反膨胀）——**短条目 + 指针类条目双禁归档**，缺一不可。

## 模型稿长度护栏

- COMPRESS/MERGE 稿须明显缩短（目标 ≤60% 原文），**"压缩"后变大是最隐蔽的失败模式**——护栏拦截后转人工，绝不应用未过校验的输出
- 强规则：单条 ≥250 字且以程序操作为主 → **直接 TO-SKILL，不得 COMPRESS 搪塞**（模型对巨型手册常给"COMPRESS"但稿=原文，护栏正确拦截但治理停摆——应改判外置）

## 技能层健康检测（自动只检测+累积）

| 检测项 | 规则 | 输出 |
|:--|:--|:--|
| 同名双副本 | 全库按 name 去重，md5 比对 | 冲突清单（同内容=冗余副本/异内容=冲突） |
| description 超长/多行 | frontmatter description >150 字符或含换行折叠符 | 建议重写清单 |
| 冗余/重复技能 | 同主题多技能（title/关键词相似） | 候选合并清单（P1 累积） |
| 引用漂移 | related_skills 指向不存在的技能名 | 断链清单 |
| 索引可见性 | platforms 缺当前系统 / name 非法 | 隐藏技能清单 |
| 使用频率 | 近 30 天加载次数 | 低使用清单（只报告不处置） |

**技能资产红线**：自动侧只做检测 + 建议清单累积；合并/归档/改名/删除永远人工确认。用户点"按建议执行" ≠ 授权物理归档——归档在用户眼里等同删除；物理移动前单独列明"哪些技能移到哪"再等确认，默认全保留。

## 待决清单格式（人工裁决用）

```markdown
## 技能治理待决清单（<日期>）
### 建议合并（人工裁决）
- [ ] `<技能A>` + `<技能B>` 高度重复 → 建议并成 `<总纲>`，旧技能归档
### 建议归档（人工裁决）
- [ ] `<技能C>` 30 天零加载 + 内容已被 X 覆盖 → 归档候选
### 断链修复（待执行确认）
- [ ] `<技能D>` related_skills 指向不存在的 `<E>` → 改为 `<F>`
```

## 治理执行七步动作链（单文件）

```
① 备份        → 带时间戳备份
② 读档切分    → 读记忆/画像文件，按节切条目（每条带行号/序号）
③ 打包喂入    → 整文件单次喂 LLM（全局视野，跨条目重复对天然可见，不切片）
④ 模型分类    → LLM 按判据 prompt 输出处置 JSON 数组
⑤ 校验合成    → 逐条动作核验（确定性脚本，不信任模型输出）：
   KEEP → 不动；MERGE → 组内两稿并集+专名集合校验；COMPRESS → 专名校验+长度护栏；
   TO-SKILL → 外置次序铁律先核对技能；TO-ARCHIVE → 仅 ≥200 字符非指针类；DELETE → 不应用进清单
⑥ 安全应用    → 同组 MERGE 只应用一条；单次降幅 ≤40% 上限内执行
⑦ 复测留档    → 复测占用率 <85% 即停；留档 diff
```

**校验失败条目 = 跳过 + 进待决人工清单，绝不应用未过校验的输出。**

## 执行纪律

- 自动侧产出 = 清单 + 报告，零文件变更
- 记忆写入只走标准记忆工具/存储接口，脚本禁直改记忆文件（防漂移）
- 任何文件变更：先备份 → 改 → 验证（可读 + 语法）→ 留档
- 补丁门控：每次打补丁后跑一次验证；验证不过就回滚，不"没证据就继续前进"
