## 四、抓取脚本修复（fetchall v2）

`yt/r154wb/fetchall.py`（稳定副本 `yt/fetchall_v2.py`，下轮 `cp` 到新轮目录）三处改动：

1. **GitHub 认证**：自动从 `gh auth token` 取令牌，只对 `api.github.com` 加 `Authorization: Bearer`（匿名 60/h → 5000/h）。
   - **脚本不落盘令牌**（`.ghtok` 在收尾时删除，每次运行现取）。
2. **国内站绕开 VPN 隧道**：匹配 `*.cn` / `aliyun.com` / `zhipuai.cn` / `feishu.cn` / `qq.com` / `tencent.com` / `volces.com` 的 URL，**优先显式直连**（`ProxyHandler({})`），失败再走隧道。
   - 原因：系统 `ProxyEnable=1` 时 Python 的 `urllib` 读系统代理，**「直连」其实也走了隧道**，导致国内站被绕出国 → 502。这是**假阴性**，必须显式建无代理 opener 才是真直连。
3. **失败分类写进摘要**：`_summary.txt` 保留 `HTTP<code>` / `URLError:<type>`，便于按类归因（本轮就是靠这个抓出限流根因）。

## 五、给下轮的铁律（新增）

1. **开工第一步先验配额**：`curl -s -H "Authorization: Bearer $(gh auth token)" https://api.github.com/rate_limit` → `core.remaining` 低于 200 就直接停下报告，不要跑出一堆 403 还宣称「全量实拉」。
