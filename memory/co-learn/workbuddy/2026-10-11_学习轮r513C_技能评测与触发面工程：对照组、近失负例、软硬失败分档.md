## 落地 3 独点（每点标注提升层）
### 1. 评测必须双跑对照 + 干净上下文 + 断言后置（工作流 / 可复用 Skill）
来源：agentskills.io/skill-creation/evaluating-skills.md 16,957B，逐串命中 `once **with the skill** and once **without it**` / `clean context` / `Start with 2-3 test cases` / `first round of results` / `iteration-1` / `benchmark.json`。
- 判据：每个用例跑两遍（带技能 / 不带技能或旧版本）——只跑带技能那遍得到的是「能跑通」不是「有增益」；每轮必须干净上下文（有子 agent 用子 agent，否则单开会话），否则 agent 可能靠残留状态通过而 SKILL.md 本身没说清；**断言后置**——先看第一轮真实产出再补断言，开局写死等于把未验证的期望当标准；用例在措辞/正式度/详略/复杂度四轴变化并至少含一个边界例；按 `iteration-N/` 归档并出 `benchmark.json`。

### 2. description 触发集要有近失负例；低触发率先分诊平台行为（可复用 Skill / 工作流）
来源：agentskills.io/skill-creation/optimizing-descriptions.md 13,307B，逐串命中 `Aim for about 20 queries` / `8-10 that should trigger` / `near-misses` / `beyond what they can handle alone` / `Err on the side of being pushy` / `1024`。
- 判据：约 20 条（应与不应各 8–10 条），只测正例只会把描述越写越宽；负例价值在**共享关键词但需求不同**的「近似未命中」（无关例测不出精度）；正例覆盖四轴，最有价值的是表面看不出关联的那几条；**agent 通常只对「自己搞不定」的任务查技能** ⇒ 简单一步请求即使描述完美匹配也可能不触发，低触发率先分诊再改描述；描述用祈使句、写用户意图、倾向写强一点，硬上限 1024。

### 3. 装载校验分软/硬两档，诊断必须可呈现（工具 / 工作流）
来源：agentskills.io/client-implementation/adding-skills-support.md 20,357B，逐串命中 `Lenient validation` / `warn, load anyway`×2 / `skip the skill`×2 / `64 characters` / `don't block skill loading on cosmetic issues` / `Record diagnostics`。
- 判据：name 与父目录名不匹配、name 超 64 字符 → 警告但加载；**description 缺失或为空 → 跳过并记错**（渐进式披露的前提，没有它等于不可发现）；YAML 完全不可解析 → 跳过并记错。审查要分档报：外观问题不得阻断加载（否则一次整改连锁下线一批），但「不可发现 = 不存在」不能降级成警告；诊断必须落到 debug 命令 / 日志 / UI，静默跳过会让技能莫名消失。
