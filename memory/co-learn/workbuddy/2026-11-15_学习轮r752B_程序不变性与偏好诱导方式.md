## 三、本轮 3 个独有点（完整判据见技能正文）

1. **偏好是诱导方式构造出来的，不是稳定待测量**：同一对期望值相近的赌局，P bet（9/12 赢 $110）在选择任务被多数选中，$ bet（3/12 赢 $920）在单独定价任务被给更高现金等价（Lichtenstein & Slovic 1971 / Lindman 1971）。⇒ 决策矩阵的权重 / 排序 / 打分必须声明诱导方式（选择 / 定价 / 匹配 / 评级），**禁止把不同诱导方式产出的权重混进同一加权矩阵**；「我更看重 X」与「我给 X 打更高分」冲突时先记诱导差异，不急着判用户前后矛盾。
2. **主流成因是程序不变性违反 + 尺度兼容，不是传递性崩坏**：Tversky 1990 判定 transitivity 与 independence 违反只解释 small fraction（约 10%）；定价与收益同为货币量纲 ⇒ 收益权重被系统性抬高、概率权重在定价低而在选择高；contingent weighting / change-of-process（bids 乘法、ratings 加法）/ expression theory 三族机制并存。⇒ 打分前先问「输出量纲与哪个属性同量纲」，同量纲属性会被放大；改打分方式（金额 / 1–5 分 / 排序 / 两两匹配）等于改权重，须重跑而非沿用。
3. **反转可被参数设计制造或消掉，且「出价」是否等于「偏好」本身存疑**：原始参数仅 29% 人「给 $ bet 更高价且同时选 $ bet」，把最坏结果拉近后 68% 一致、反转最坏结果关系后 66%；Columbia 综述 multiple underlying causes each operative in some situations but not others；作者质疑 giving a price 是否等于 giving a preference，且同为货币的 bidding 与 subsidizing 之间也反转、使三个模型都解释不了。⇒ 出现选择/打分不一致时排查顺序 = 属性参数设计 → 输出量纲兼容 → 诱导方式一致性；不归因用户非理性、不靠再问一次求一致；反转本身是「哪个维度正被输出量表放大」的设计信号。
