## 二、独点清单 + 判非重复理由（3 文件 3 组）

### 1. wb-skill-authoring 2.77.0 —— 输入检查门四则
- **检查面只有"本次运行输入"**（历史/依赖/检索文档/附件都不在面内）。
- **默认 fail-open**：护栏失败抛专用异常会被拦；普通钩子异常只记日志继续；依赖外部服务时服务挂了=放行，要 fail-closed 必须自己翻译异常。
- **字面量护栏是筛子不是防火墙**：模式是字面子串非正则；输入转小写、配置的模式不转（自定义必须小写）；误报与漏报双向存在。
- **拦下 vs 改写是两个开关**（抛错终止 vs 掩码放行）；**自定义模式是扩展不是覆盖**（要关默认项得逐个关）。
- **细化配置可能静默失效**（带斜杠/连字符的类别名匹配不上 → 异常非策略拒绝 → 未包装的护栏放行）。
- 判非重复：与 §供应链四道闸 分工——那条管装进来之前怎么审，本条管运行时输入门的检查面与失败姿态。增量 ≥85%。

### 2. wb-context-compressor 3.57.0 —— 存下来的东西决定以后能重放什么
- 三个存储开关**只裁剪写进库的副本**，本次模型该收的照收、**token 计量仍反映真实用量**。
- 关掉工具消息会**连发起调用的那条助手消息一起删**（为维持合法消息序列）→ 裁剪粒度比直觉粗。
- **后续运行只能重放库里还剩的东西**；工具消息被裁后模型会以为那工具从没用过 → 官方点明会造成幻觉。
- **"不存"和"挪走"是两件事**（完全丢弃 vs 外置到对象存储留引用）。
- 判非重复：与 §快照覆盖面边界（挂载卷不在内）分工——那条管快照圈住哪些文件系统，本条管持久化开关裁掉哪些消息及其对重放的后果。增量 ≥80%。

### 3. wb-context-compressor 3.57.0 —— 记忆作用域由"人"划，标识符漏传会静默串味
- 会话历史（一个 session_id，答"刚聊了什么"）vs 记忆（一个 user_id 跨所有会话，答"我知道这人什么"）。
- **两个 id 每次都要传；不传 user_id 时记忆落到 `default` 用户** ← 跨用户串味的静默入口。
- 记忆写入两个主体：自动式（后台抽取，管理器**可能判定什么都不值得存**）vs agentic 式（agent 用工具调用决定）。
- 截断（默认 3 条运行）与会话摘要**叠加**而非二选一。
- 判非重复：与 §记忆三态按作用域分家（r156-A）分工——那条管三态怎么分，本条管分家所需标识符、漏传时的默认归宿、写入主体。增量 ≥55%。
