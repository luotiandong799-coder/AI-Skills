- 关键原文事实：
  - **Activity 默认带重试策略**（退避系数 2.0、初始 1s、最大间隔 100s、最大次数 0=无限），**Workflow 默认没有**；理由是重放会重复同样逻辑、不解决外部依赖问题还烧资源。**重试策略不适用于 Workflow Task Execution**（后者重试到 Workflow Execution Timeout，指数退避、最大间隔 10 分钟）。
  - 三类超时：Schedule-To-Start（排队时长，**设计上不可重试**——重试会放回同一队列）、Start-To-Close（单次执行；**服务端不检测 worker 崩溃，靠它兜底**）、Schedule-To-Close（整体，一次执行只算一次）。长任务配心跳 + 心跳超时。
  - Task Queue **首次使用时动态创建**，名字错配 = 静默新建空队列 → worker 收不到任务、流程卡住且**没有任何错误**。
  - Continue-As-New：状态传给**事件历史清零的新执行**，可无限重复；同时规避版本漂移。
  - 版本行为 **Pinned vs Auto-Upgrade**：选 Auto-Upgrade 就要自己用 patching 保证 replay-safe；**Independent Activity** 跑在不属于本流程版本的队列上、不继承调用方版本；子流程**只在队列属于父版本时才继承**，Continue-As-New 链继承 Pinned。
  - 优雅停机：有窗口则让在飞动作跑完，本地动作到点发 cancel；无窗口或超期才硬停。
