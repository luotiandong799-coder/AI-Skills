## 三、本轮 3 个独有点（完整判据见技能正文）

1. **触发面就是权限面：能写产出事件 = 能驱动下游全部执行**：官方逐字「granting the `can_create` permission on Assets is effectively equivalent to granting "trigger" permissions on all downstream Dags」，因「**implicit trust** model for data-aware scheduling」，能建 Asset Event 者可触发任意下游 Dag「**even if the user does not have permission to view or edit the downstream Dags**」⇒ 委派/编排的授权清单必须把「谁能产生该事件」列入下游触发权限面，而不是只审「谁能改下游定义」；上游产出方与下游执行方可以互相不可见、靠一个 URI 字符串耦合 ⇒ 权限评审按**事件可达集**画，不按 DAG 可见性画；跨团队须显式收窄（3.3.0 `producer_teams` 默认只收同团队或 global 事件）。URI 与 `extra` 明文落库不加密 ⇒ 凭据/token/私密路径一律不写进 asset 标识或元数据。与 r753C（SI `pull_request_target`：危险是执行检出物不是 checkout）**不同轴**：那条是 CI 检出物带写 token，本条是数据事件跨身份越权触发且下游不可见。
2. **Asset 是逻辑 URI 字符串，不是数据校验**：官方「makes no assumptions about the content or location … treats the URI like a string」、正则/glob「will not work」、URI 与 host 均大小写敏感（后者「**differs from RFC 3986**」）、「The `extra` field **does NOT affect the identity**」且同 URI 多份 extra「**not guaranteed which one will be stored**」、`pre_execute`/`post_execute` 钩子「**not rerun when a task is retried**」⇒ **事件到达 ≠ 数据正确/完整**；调度器只记「某任务声明更新了某个字符串」。生产/消费必须**精确 URI 对齐**（大小写差一字符即静默断链，host 大小写敏感与常识相反），禁止用正则/glob 声明一类产物，`extra` 不得作为身份或可靠判据，需要可靠元数据走事件级 `Metadata` 并显式处理重试不重跑钩子。与 r733A「交接边界须校验输出质量、按 schema 而非 transcript」同向，本条给出**数据事件这一具体交接介质的失效清单**。
3. **事件触发的 run 没有 data interval；同一段代码须按触发类型分叉**：3.0 起 Asset 事件/REST 未指定 `logical_date` 的 run 默认 `logical_date=None`、「**do not have a data interval**」，访问 `data_interval_start`/`data_interval_end`/`logical_date`「**will raise a `KeyError`**」；官方要求「use `dag_run.logical_date` and **perform appropriate checks or fallbacks if supporting multiple trigger types**」⇒ 同一段任务代码同时被定时与事件触发时，取数不能一律按 `Now` 或 `data_interval`。同批版本事实：unified `schedule` 取代 `schedule_interval`/`timetable`、`catchup_by_default=False`、Dataset→Asset 全量改名（含 timetable/listener/config 键）⇒ 编排规则、参数名、类/模块路径**必须绑版本引用**（2.4 Datasets → 3.0 Assets → 3.3 producer_teams），与 r752C「术语与参数绑版本」同源但落在调度模型与上下文契约。
