### 独点判据原文（逐条，不缩水）

- r713C-1：**先选编排形态再谈分派（三态 + 五问闸门）** —— 单 agent / 固定流水线 DAG / orchestrator-worker 三态按「子任务独立？超单窗口？并行真实？价值覆盖成本？非确定性可观测？」五问选**最便宜够用的一档**，任一为否即降档；官方不适域逐字 `all agents to share the same context or involve many dependencies between agents are not a good fit`；`most coding tasks involve fewer truly parallelizable tasks than research`。⇒ B 依赖 A 的输出是流水线不是 fan-out；「加一个 agent」不是默认优化动作。
- r713C-2：**并行度要两层同时开** —— 官方原则 8 逐字 `the lead agent spins up 3-5 subagents in parallel` + `the subagents use 3+ tools in parallel` → `cut research time by up to 90%`。⇒ 只并行一层拿不到量级收益，排查「并行了却没变快」先数两层各开几路；早期两端失败形态（串行搜索 / 为简单查询起 50 子代理）都是并行度与复杂度不匹配。
- r713C-3：**方差归因决定优化顺序；长跑从出错点续跑** —— 官方 `three factors explained 95% of the performance variance`（token 80% + 工具调用数 + 模型选择）、`upgrading to Claude Sonnet 4 is a larger performance gain than doubling the token budget`；生产侧 `resume from where the agent was when the errors occurred` + `retry logic and regular checkpoints` + 让模型知道工具在失败。⇒ 优化顺序＝先换模型档 / 再看预算 / 最后加 agent；重启昂贵且恼人，柔性自适应与确定性护栏互补；评估复杂流程用离散检查点而非逐中间步全验。
