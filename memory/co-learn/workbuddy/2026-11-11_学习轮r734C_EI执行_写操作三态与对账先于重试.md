### 独点判据原文（逐条，不缩水）

- **r734C-1 ★写结果必须三态，超时是「未知」不是「失败」；未知态禁止让模型重新生成调用**：vdf.ai 逐字三态与 "It must not ask the model to regenerate the call: regeneration can change parameters and turn one ambiguous operation into a new one"；reazromen "A timeout is an ambiguity boundary"；hyperacademia "Unknown is not a temporary synonym for failure"。判据：① EDG 步骤状态除成功／失败外须有 `OUTCOME_UNKNOWN`／`RECONCILING`／`MANUAL_REVIEW`，CCS 不得据超时签 FAIL 并触发重发；② 未知态保持同一 operation identity 去查或按契约重放，禁止模型自行重写参数重试；③ 与 §九「前置违反归调用方」分工：三态是「结果不可判定」，不是「断言被违反」，不能混成一条 Guard。

- **r734C-2 ★重试权在对账者不在执行器；「查无此对象」是弱证据**：developers.dev 逐字 "no retry loop in the executor"、"A lookup that finds nothing is weak evidence"（没到／还在跑／已提交但读路径滞后／被拒），转 `FAILED_TERMINAL` 须三条文档化前置同时成立（read-after-write 或已过传播上限；已过 deadline 且能 cancel/fence 迟到；同键重放不可用或返回「无副作用」确定错误），否则保持 UNKNOWN 并留活的对账任务；四类目标能力表 A–D 决定对账手法；UNKNOWN 是 saga 中先于补偿的显式分支。reazromen / GitHub jpcaparas "Retries are for transient failures, not uncertainty"。判据：① EDG 每步 Guard 标注目标属 A/B/C/D 哪类，未标注按最弱档 D；② 补偿必须在未知态收敛之后；③ 重试资格由**结果可判定性**决定，不由错误码或重试次数决定。

- **r734C-3 ★契约要写 effect class 与 point of no return；补偿不是回滚，验收断言业务后果**：vdf.ai 字段表逐字 `Effect class | Read, reversible, compensable, or irreversible`、`Success receipt | Stable target ID, version, timestamp, and effect`、`Point of no return | Stage after which automatic reversal is unsafe`；FAQ "Compensation is a new, domain-specific action ... does not erase history, may not restore the exact original state, and can itself fail"；"A sent message cannot be unsent"；不可逆动作排最后 + 人工审批；验收 "Assert business outcomes ... not merely successful HTTP responses"；幂等键按业务意图生成、留存超过最大重放窗口（reazromen "The idempotency window is part of the contract"）。判据：① CCS 证书须记 success receipt 与 effect class，HTTP 200 不构成业务完成证明；② 故障注入覆盖 dispatch 后／目标 commit 后／receipt 入库前／补偿中途，并测「同键不同参数」「留存过期后重放」；③ 与 `engineering/ei-reliability` 的 Saga 骨架分工：那边管「不丢状态、能续能回」，本节管「三态、对账资格、补偿不是撤销」。
