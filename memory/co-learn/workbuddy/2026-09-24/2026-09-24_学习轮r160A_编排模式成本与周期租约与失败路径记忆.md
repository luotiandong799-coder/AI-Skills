## 二、独点清单 + 判非重复理由（3 文件 3 组）

### 1. `engineering/wb-execute-discipline` 3.01.17 → 3.01.18
**多 agent 编排：模式决定成本，终止事件不等于成功**
- 四模式成本结构不同（coordinate 两次 leader 调用 / route 跳过合成 / broadcast 同步串行只有异步才并发 / tasks 循环到 max_iterations）。
- **route 默认仍改写任务**，`determine_input_for_members=False` 才透传。
- **旧开关冲突只 warning 就静默改写 mode**。
- **★终止事件不等于成功**：`TeamRunCompleted` 取消的运行也会发。
- 成员与团队重试分开配；部分结果 ≠ 完整结果。
- 判非重复：豆包 r160-B 是**通用模式目录**（谁决定路径 / 适用场景）；本条是**同一框架实测的成本与失败面**（透传开关、flag 静默降级、终止事件语义、重试分层）。增量在"坑位"不在"目录"。重叠 <60%。

**周期任务：租约协调 ≠ 只跑一次**
- **★租约 300 秒过期且不续租** → 超 5 分钟的任务会被再次认领。
- **★租约只协调 worker，不保证外部副作用 exactly-once** → 周期动作必须自己幂等。
- **重试是独立行、无内置死信队列** → 耗尽后要自己捞失败行。
- **★`session_id` 不去重 run 或写入** → 幂等键必须落在目标系统。
- 调度器走 HTTP 打自己端点（默认 127.0.0.1:7777，换端口要改 base_url）。
- `if_exists` 三值决定重启是否幂等（默认 `raise`）。
- semaphore 只限并发不限配额；`File(url=)` 只留引用；后台流续播依赖事件是否还在（10,000 条 / 30 分钟）。
- 判非重复：本技能此前无"周期任务/调度"面；与 §限流退避（单次调用）不同层（那是调用级、这是任务级）。增量 ≥80%。
- 提升层：工作流（周期任务执行纪律）。

### 2. `defaults/wb-context-compressor` 3.62.0 → 3.63.0
**把失败路径写进长期记忆：三档学习模式与抽取器边界**
- 错误 → 诊断根因 → 存成可复用纠正 → 下次先检索再动手。
- `ALWAYS`（后台抽取）/ `AGENTIC`（模型显式存，默认）/ `PROPOSE`（仅指令要求先问）。
- **★`PROPOSE` 不是闸门**：保存工具本身无确认拦截，真批准要走显式 HITL。
- **★抽取器忽略 system 消息、工具调用与工具结果，且可能判定"没什么值得存"**。
- 两类记忆分仓：学到的纠正（跨用户迁移）vs 决策日志（审计线索）。
- 判非重复：**本条正是长期候选池「失败路径记忆（负样本进长期记忆）」的落地**，此前从未落实；与 §记忆召回复合评分（怎么排序）不同面（本条管"负样本要不要进、怎么进"）。增量 ≥80%。
- 提升层：可复用 Skill（记忆写入策略）。

### 3. `engineering/wb-skill-authoring` 2.77.0 → 2.78.0
**暴露面与身份边界的默认姿态：默认关掉的隔离要自己打开**
- **★用户隔离对 JWT 调用者默认 Off**（有读权限即可跨用户查）。
