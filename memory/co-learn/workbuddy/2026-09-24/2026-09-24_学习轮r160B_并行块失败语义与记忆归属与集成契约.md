## 二、独点清单 + 判非重复理由（3 文件 3 组）

### 1. `engineering/wb-execute-discipline` 3.01.18 → 3.01.19
**工作流的失败与并发语义：并行块整块失败，串行才是默认**
- **★并行分支任一步抛错 → 整个并行块失败**，其它分支结果一并作废；韧性要在步骤内 try/catch 把失败编码成类型化成功结果，下游过滤。
- **★同步点隐式**：`.parallel()`/`.foreach()` 都等全部完成，结果不能边完成边下传。
- **★并发默认相反**：`.parallel()` 无上限参数；`.foreach()` 默认 `concurrency: 1`（串行）。
- schema 是一条链（首步入口/末步出口/相邻步对齐，不对齐用输入映射）。
- 循环终止要自己判 `iterationCount` 并抛错。
- 判非重复：本技能此前无"工作流并发/失败传播"面；与 §周期租约（A 轮本技能另一节）不同层（那条管调度，本条管同一次运行内的分支）。增量 ≥75%。
- 提升层：工作流（并发与失败传播设计）。

### 2. `defaults/wb-context-compressor` 3.63.0 → 3.64.0
**记忆归谁 ≠ 谁发的：跨平台身份会静默裂开**
- **★默认把记忆挂在 `platform:userId` 上 → 同一人在不同入口是两份记忆**（SSO 场景必裂）。
- 群聊可"会话拥有记忆、发送者仍是 actor"。
- **★归属解析只在新线程创建时跑一次**，复用线程永不回调 → 改逻辑不影响历史对话。
- **★id 冲突只 warning 就改用生成 id**，绝不覆盖已有线程。
- 判非重复：与 §记忆作用域由 user_id 划分（不传落 default 用户）不同面 —— 那条管"漏传会串味"，本条管"**传对了也会因为入口不同而裂开**"。增量 ≥70%。
- 提升层：可复用 Skill（记忆归属模型）。

### 3. `engineering/wb-spec-driven` 1.82.0 → 1.83.0
**集成面要在规约里写清三件事：运行时契约 / 降级路径 / 解析时机**
- **★运行时契约缺失的表现是"跑一半就没了"**：serverless 上 webhook 返回 200 后后台任务被杀，必须显式传 `waitUntil`（不同平台要求不同）。
- **★降级路径要写明"降成什么"**：不支持的附件转成文本摘要（不是丢也不是崩）；链接内联默认 HEAD 探测类型并比对白名单，探测不可信可强制指定类型绕过。
- **★解析时机决定改动影响面**：身份/线程解析只在新线程触发一次；请求上下文每消息新建、**必须在调默认处理器之前写入**。
- 处理器三态（省略/`false`/包裹函数）对应三种意图。
- 判非重复：本条是 §规约要给每道门写三件事（检查什么/检查不到什么/失败姿态）的**集成侧扩展实例**，同族不同面（那条管检查门，本条管外部集成的契约与降级）。增量 ≥60%。
- 提升层：工作流（集成契约与降级设计）。
