## 独点：2 条
**D14：检索/上下文选择按"决策效用"排序，不是语义相似度——排序依据是"这段上下文会不会改变 agent 的下一步动作"**（来源：arXiv 2606.08151 CICL《Decision-Aware Memory Cards》2026-09-04 v3 实拉）
- 四组件效用：action shift（改变动作）/ success gain（支持更好结果）/ need signal（成为成功必需）/ risk·cost（避免有害选择）——候选单元按预期影响打分，不按相似度。
- 实例化可跨模型：hosted LLM judge / 本地代理 / 轻量 ranker 同一协议，judge 信号分列报告不合并成一个分。
- 实证：BM25 top-50 重排 hit@1 0.58→0.78；受控诊断移除 top-utility 单元 F1 0.245→0.000（决策关键证据确实存在）。
- 判据：**重排的排序标准是"对下一步动作的预期影响"**——问"去掉这段，动作会变吗"而不是"它像不像任务"；证据分级 supported/limited/deferred 分列报告。
- 与 ctx §RAG 检索升级互补：那条管"检索怎么召回"，本条管"召回后按什么排序"。
- 提升层：工作流/可复用 Skill。

**D15：去重/记忆压缩——表面相似只用于"提议候选对"，删除/合并/保留必须由 LLM 按事实价值判**（来源：arXiv 2606.13177 MEMREFINE，2026 实拉）
- 机制：表面相似性反映不了事实价值——相似度只用来生成候选对，delete/merge/preserve 决策交给 LLM judge 基于事实内容判断，迭代压缩到预算达标；多个记忆框架+长对话基准上超规则基线。
- 判据：**"看着像"只能进候选，不能直接删**——判删/判合要看事实内容（数值、来源、时间、口径是否真冗余）；规则式相似度去重会误杀表面像、事实不同的条目。
- 与 ctx §记忆自维护（promote/prune/re-validate）分工：那条管"三类处置"，本条管"处置决策怎么判"。
- 提升层：工作流/可复用 Skill。
