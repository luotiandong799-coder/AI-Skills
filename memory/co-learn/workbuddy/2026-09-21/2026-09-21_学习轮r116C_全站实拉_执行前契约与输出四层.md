## 独点：3 条
**D23：执行前语义契约验证——代码/工具调用执行前先生成契约 rubric、打分、迭代修复**（来源：arXiv 2605.09730 RubricRefine 2026 实拉）
- 机制：pre-execution semantic contract verification 作为可靠性原语——**静默契约违反对执行反馈不可见**（代码能跑但违背契约，执行不报错）；生成 registry-conditioned rubric，对照显式契约检查给候选代码打分，运行时前迭代修复。
- 判据：**校验点不止"执行后"，执行前也要验**——对"能跑但违背契约"的静默失败，执行反馈永远抓不到；用契约 rubric 在执行前打分+修复。
- 与 ED §工具结果断言层分工：断言层管"执行后结果合理性"，本条管"执行前契约满足度"。
- 提升层：工具/工作流。

**D24：输出有效性四层——syntactic/schema/semantic/state**（来源：richards.ai《Tool-use reliability, function-calling robustness, and structured output enforcement》2026-05 实拉）
- 机制：校验结构化输出按四层逐层过——语法有效（可解析 JSON/调用格式）→ 模式有效（满足声明 schema：必填/enum/数组形状/类型）→ 语义有效（调对了工具/实体/单位/时间/消歧）→ 状态有效（调用对当前状态合法）。
- 判据：**只验语法和模式 = 漏掉语义与状态错误**——模型输出合法但调错实体/单位/在当前状态非法，前两层验不出来；四层逐层过，哪层不过就修哪层。
- 提升层：工具/可复用 Skill（输出校验分层）。

**D25：技能推荐前质量三信号——安装数/来源信誉/GitHub stars**（来源：SkillsMP《meta-find-skills》官方页面 2026-09-15 实拉）
- 机制：不基于搜索结果直接推荐技能——优先安装数 1K+ 的技能、<100 谨慎；来源信誉（官方源 vercel-labs/anthropics/microsoft 比未知作者可信）；源仓库 GitHub stars <100 存疑。skills.sh 安装榜是"流行度信号"不是"质量评审"。
- 判据：**装之前先看三个信号**——安装数（真实使用）、来源（官方 vs 未知作者）、stars（社区认可）；流行不等于好，但"无人装+来源不明+低 star"三重缺信号时默认不装。
- 与 sa §闭合邻域评测分工：那条管"装上后怎么测激活/成功率"，本条管"装之前从生态怎么筛"。
- 提升层：工作流/可复用 Skill。
