## 独点：2 条
**D16：工具注入扫描范围必须覆盖 inputSchema 的全部字符串字段，不只顶层 description**（来源：beyondscale《MCP Tool Poisoning: Enterprise Defense Playbook》2026-05-20 实拉）
- 机制：攻击者用所有可用字符串字段分发载荷——参数描述、enum 值、example 字段都可能藏指令；预部署扫描必须扩展到这些字段，且在 CI 里作为阻断门（扫描失败不部署）。
- 判据：**"扫 description 过了"≠工具干净**——第三方工具/技能的全字符串面都要扫；扫描是 CI 阻断门不是提醒。
- 与 ctx §工具面安全注入预检分工：那条管"扫哪些模式"，本条管"扫哪些字段"。
- 提升层：工具/工作流。

**D17：恶意技能三类攻击模式——hidden override（隐藏覆盖）/disguised transfer（伪装转移）/remote bootstrap（远程引导）；审计标签 3-way（benign/suspicious/malicious）**（来源：arXiv 2606.11435《Agent Skill Evaluation and Evolution》2026-08-26 实拉）
- 机制：技能包级审计按三类模式+3-way 标签分类；semantics-preserving rewrites（保持语义的重写）用来做 attack-exact-consistency 验证（改个说法是否仍是同一攻击）。
- 判据：**审技能/工具时按三类模式对号**——正文偷偷覆盖用户指令（hidden override）、把恶意载荷伪装成正常数据转移（disguised transfer）、安装时从远端拉取执行（remote bootstrap，与 ClawHavoc"fetch-and-execute 技能可在审查后变坏"互证）；标签三态不是非黑即白，suspicious 需人工。
- 与 D5 三层审计分工：D5 管"审计流程怎么做"，D17 管"恶意形态长什么样"。
- 提升层：可复用 Skill/工作流。
