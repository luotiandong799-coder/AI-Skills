## 三、判不落（本轮其余候选，逐条理由）
- `CREDENTIALS_OVERWRITE_DATA` 环境变量放凭据「不受保护会泄漏给用户」；推荐 REST endpoint → 结论方向正确（秘密存放位置按可读面评级）但**本轮不落**：与既有「备份是泄漏面 / 不写含明文回滚备份」同族，且主导出的是"别用环境变量"这一操作建议而非可复用判据；转候选池，待与既有条目做合并评估。
- 无 auth token 的 overwrite endpoint **只能调用一次** → 一次性端点作无鉴权场景的默认保护，机制有趣但与 SA「一次性提权四要素（单次使用）」重叠 >60%，判非。
- credential 继承（`googleSheetsOAuth2Api` extends `googleOAuth2Api`）父级参数向下传递 → 其**「不传递」的一面已抽进 Cap91③**，传递面属平台实现细节，排除。
- Pipedream 官方 OAuth client 默认 scope 可能宽于用例 → 与 **Cap86「默认作用域越大越接近漏洞」** 重叠 >60%，判非。
- Pipedream 改 scope 后须重新连接账号才生效 → 与 SA SKILL.md L199「形态转换不重新授权」/ ag L381「revoke 只强制重新授权」同族，判非。
- Pipedream 部分 app 的 triggers 不支持自定义 OAuth client（Discord/Dropbox/Slack/Zoom） → 平台特定限制，§5 排除。
- n8n 多分支时**不能在环境间直接拷贝**，须经 Git provider 合并 → 结论与 WB 既有的「唯一真身 / 禁强推 / 必经仓库」纪律同族，重叠 >60%，判非。
- `/source-control/pull` + `force:true` 自动拉取 → 平台 API 细节，且文档正文端点（`/api/v1/source-control/pull`）与示例端点（`/version-control/pull`）**自身不一致**，属文档缺陷个案不可当方法复用，判非。
- compare-versions 的 diff 面板方向（top = 将被更新方）/ 仅可推拉者可见 diff → UI 呈现与角色绑定个案，非底层法，判非。
- `share-credentials-securely.md` 3,448B：内容为共享操作步骤与权限角色说明，无新硬判据，判非。
- `n8n-packages/limits-and-permissions.md` 10,455B：社区包/私有包的许可与节点可用性限制，属平台许可运营面，§5 排除。
