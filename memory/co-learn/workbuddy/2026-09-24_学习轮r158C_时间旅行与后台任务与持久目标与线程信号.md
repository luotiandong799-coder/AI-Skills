## 二、独点清单 + 判非重复理由（2 文件 4 组）

### 1. wb-execute-discipline 3.01.12 —— 时间旅行：前置校验必须在动任何东西之前失败
- 语义＝**重建前序 + 从目标步继续**（前序从快照或提供的 context 重建，不是重跑也不是只跑一步）。
- **两类失败在执行前报出且快照原样不动**：工作流定义变过（步骤改名）／记录的运行没走到目标步的前一步。
- 三用：复现失败 / 换输入测单步 / **跑一个从未运行过的工作流的任意步**。
- 依赖持久化快照（没配存储就没这能力）；挂起态带 suspend/resume 载荷。
- 判非重复：与 §检查点事件驱动 分工——那条管运行内部落点续跑，本条管落点之后从指定步骤反向重入及其前置合法性校验。增量 ≥80%。

### 2. wb-execute-discipline 3.01.12 —— 后台任务：资格两层，且"有资格"≠"真后台"
- 开管理器**不会**让任何工具自动后台化；工具层或 agent 层**必须**有一处声明合格。
- 合格默认 `deferred`；想只给模型一个选项要显式设 `foreground`。
- 模型可**逐次调用**用参数字段覆盖前台/延后/等待并覆盖超时与重试。
- 结果落进记忆 + 空闲时自动重新唤起 agent 处理（省的是等待不是后续处理）。
- 全局并发 / 单 agent 并发 / 背压（排队）/ 默认超时要显式给。
- 判非重复：与 §端到端超时由最严一层决定（r156-C）分工——那条管超时边界，本条管长调用改后台的资格、处置与并发代价。增量 ≥85%。

### 3. wb-execute-discipline 3.01.12 —— 持久目标：judge 是激活开关
- 目标存线程状态（跨重载与进程重启、跨中途新消息），与"每次传的一次性判定"区别在持久化位置。
- **解析不出 judge → 不评分、不消耗预算、不发任何信号**（静默 no-op，装配完必须验证它真的判过一次）。
- 三结局：继续（注入反馈）/ 完成 / **暂停**（预算耗尽，调高后可续）。
- 在后台任务、工具循环中间、只更新工作记忆的迭代上是 no-op。
- 判非重复：与 §门 vs 记录两档（r156-B）分工——那条管拦截强度分档，本条管一个"由模型驱动的门"在缺模型时如何静默失效。增量 ≥75%。

### 4. wb-context-compressor 3.58.0 —— 交互单位是线程，消息与信号是两条通道
- 订阅线程而非每次新开流：唤醒空闲 agent 或把输入**投进正在跑的循环**，否则排队。
- **用户 authored 内容走消息接口，系统生成内容（后台任务通知/策略提醒/处理器上下文）走信号接口**。
- `queueMessage` 保轮次顺序（忙时等活动跑完再开新一轮，闲时立即跑）。
- 带属性的内容以 XML 包裹交给模型（归属可追溯）；持久状态与持久通知各有一条专用通道。
- 投递行为对"忙/闲"两态可分别配置。
- 判非重复：与 §已加载状态两形态（r157-B）分工——那条管工具按需发现的状态存在哪，本条管输入侧内容怎么进入一个已经存在的运行。增量 ≥80%。
