### 独点判据原文（逐条，不缩水）

- **r736C-1 ★驱逐 ≠ 删除：可见性与可检索性是两个独立验收点**：上下文是有界缓存，库才是状态真身。判据：① 治理动作凡写「移出/压缩/归档/驱逐」必须**显式声明是否同时删持久层**，默认分离；② 验收分两点取证：`当前上下文是否仍包含`（注入侧）与 `历史能否检索回来`（检索侧），只验前者会把「看不见」误判成「已清理」或把「已清理」误判成「还在」；③ 与 agent-guild Cap34「注入侧截断 ≠ 磁盘不完整、截断是迁移信号」同向，本条补运行时语义；④ 与 §五「零信息丢失防膨胀」一致——压缩的对象是每轮要付的 token，不是历史本身。
- **r736C-2 ★常驻是挂载关系，共享块是一个跨 agent 的单一写面**：判据：① 分层不能只按「重不重要」切，要按「**每轮必须可见 vs 按需检索**」切——重要但低频的材料应放可检索层；② shared blocks 须维护**挂载清单与写者**，一个 agent 改块全体下一轮同变，把共享块当私有块改＝静默跨 agent 污染；③ 与 agent-guild「共享记忆乐观锁 / 先读 content_sha256 再条件提交」互补：那条防并发写覆盖，本条防挂错对象；④ 本机映射：用户级 `MEMORY.md`=每轮常驻块、模块 `MEMORY.md`=按需检索层、C 盘 junction=共享挂载面，三者写入权限与生效半径不同，不能一把 Edit 全改。
