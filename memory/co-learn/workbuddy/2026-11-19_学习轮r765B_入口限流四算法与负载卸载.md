## 三、本轮三独点（EI · engineering/ei-reliability 1.6.0→1.7.0）

1. 四种算法按「对突发做什么 + 记什么状态」分，非优劣排序：固定窗口 2× 边界突发 / 滑动日志精确但内存涨 / 滑动计数加权近似（Cloudflare 默认）/ 令牌桶允许最多 B 突发（AWS/Stripe 默认）/ 漏桶抹平突发但加延迟；突发大小与持续速率是令牌桶两个独立旋钮。
2. rate limiter 与 load shedder 是两类控制；Stripe 四种：Request Rate / Concurrent（治 CPU 密集端点，重试反加剧过载）/ Fleet Usage（预留 20% 给关键）/ Worker Utilization（四级逐步卸载，慢恢复防 flapping）；shedder 依据系统整体状态非单用户。
3. 生产落地 fail-open（异常/Redis 挂掉 API 仍可用）+ kill switch/feature flag + dark launch（先看会挡哪些流量）；客户端 429+Retry-After+jitter 退避；分布式用 Redis 原子操作，局部桶+周期同步防热点键/时钟漂移。
