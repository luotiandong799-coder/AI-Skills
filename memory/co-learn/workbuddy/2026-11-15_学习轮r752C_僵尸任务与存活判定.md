## 三、本轮 3 个独有点（完整判据见技能正文）

1. **僵尸与 undead 是方向相反的两类失配，处置也相反**：zombie = 登记为在跑、执行体已没了（心跳停 / OOMKilled / liveness 重启 / 缩容迁移），编排器清理并发回调；undead = 执行体在发心跳、登记里却没有它（多因人工在 UI 改状态），让进程自检自杀。⇒ 委派排障先分方向，把两类一律当「卡住重试」会同时漏掉槽位泄漏与野进程。
2. **僵尸检测是四条 AND，且清理必须显式释放并发预算**：TI.state==RUNNING ∧（job 非 RUNNING ∨ latest_heartbeat<limit_dttm）∧ job_type==LocalTaskJob ∧ queued_by_job_id==当前 scheduler job；`_purge_zombies` 发 TaskCallbackRequest 并 `remove_running=True`，源码注释点名 executor 不再把僵尸计入 parallelism。⇒ 存活判定四要素缺一即误清/漏判，回收必须连带释放资源槽（与 r748C pool 呼应），检测门不能只写「超时 N 秒」。
3. **「卡住」有两条独立门；状态漂移不指根因；术语/参数须绑版本**：queued 超 `scheduler.task_queued_timeout`（默认 600s，常无任务日志因 worker 从未跑）vs running 心跳超时（日志戛然而止）；官方明写 The message itself does not identify the root cause，排查梯五步且「状态被外部改过」是待查项不是根因；2.11.2 叫 Zombie（变量 LOCAL_TASK_JOB_HEARTBEAT_SEC / SCHEDULER_ZOMBIE_TASK_THRESHOLD / ZOMBIE_DETECTION_INTERVAL）→ 3.0.6 改称 Task Instance Heartbeat Timeout（整组变量改名）。⇒ 排障按「有无日志」先分叉，规则与配置引用必须绑版本，不把某版默认值写成通用事实。
