## 三、本轮 3 个独有点（完整判据见技能正文）

1. **多因素实验不可用不是算力问题是参数不独立；「层」是参数子集不是流量切片**：蓝色对字色与底色都是合法值但同时取蓝色页面不可读 ⇒ 不能「每个参数独立实验」。Google 解法是把参数划成互不相交子集、每子集关联一层、同一参数不得出现在多个层，每个请求最多同时在 N 个实验（每层一个）。判「能不能分层」看参数独立性，不是看模块边界；单层架构另有**流量饥饿**（上游吃满请求）与**偏置**（上游只放英语请求）两个独立采样结构缺陷，加权修不回来。报告须附「参数→层」映射表 + N。
2. **域 / 层 / 实验三分且可双向嵌套；发布层测跨特性交互，正常层测不出来**：域切流量、层切参数，是两个正交维度（层里还能再切域）。非重叠域让一个实验改任意参数，重叠域每层各一个；**发布层（Launch layers）总在默认域、参数最多同属一个发布层+一个正常层、只覆盖「新默认值」且被正常实验层优先覆盖** ⇒ 它是灰度机制不是实验层，把它当普通实验层会写出「上线后实验组突变对照组」的假结论。想测 A 特性 × B 特性交互，靠两个正常层的交集流量功效不足，须用发布层大流量或明确写「本轮不检验交互」。
3. **层间正交不是天然的：哈希必须掺 layer salt，且同层只许一种分配类型**：只按用户 ID 哈希各层复用同一桶号 ⇒ 跨层完全相关，carryover effect 把 A 层效应混进 B 层读数；正交由 `mod = f(cookie, layer) % 1000` 换来。上线前跑 A/A 交叉表验独立；同层混用分配类型会让名义流量相同而实际样本不同（1% cookie > 1% random），实验与对照必须同型。四种类型有固定优先序（user id → cookie → cookie+date → random），改顺序等于改所有在跑实验的样本池，须按配置变更评审；分流配置集中可审计，私写分流是 SRM 与鬼实验来源。
