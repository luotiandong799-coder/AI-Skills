## 三、本轮独有点（判重净新）

1. 控制器是授权边界不是界面细节：tools=model-controlled → 检查点在每次调用（scope + per-call audit + 按用户解析身份，「The model is not a principal; it is acting for one」）；resources=application-driven → 在 attach 时由代码一次性裁决（「A resource the host never attaches is a resource the model never reads」）；prompts=user-controlled → 人点击。⇒ 先选控制器再选消息形状，host 可预先决定的读做成工具等于把一次裁决摊成高频低可见度的逐次裁决。
2. 清单集合是协议不变量不是会话状态：官方「MAY be empty and MAY change over time but MUST NOT vary per-connection or as a side effect of other requests on the connection」「MAY vary by the authorization presented on the request … since credentials are per-request input, not connection state」⇒ 按会话里发生过什么增删能力违反规范，按授权裁剪必须走每请求凭据；2026-07-28 起 list/read 结果必带 resultType/ttlMs>=0/cacheScope，「a cache MUST NOT share private responses across authorization contexts」。
3. resource_link 不等于已登记资源、工具是地板不是全集：「A resource link in a tool result is not guaranteed to appear in resources/list」「If the model has to find data by itself during a conversation, a resource alone is not enough」；「Tools are the only primitive every client supports」⇒ 工具作地板、另两原语渐进增强且禁止双份暴露（「That doubles the surface and keeps every read a model decision」）；收缩工具面按「host 能否预先决定」筛（31→约 13，约 6000 tokens 定义），必须是工具的读带 annotations 并按用户下发只读切片。

- 判重：`application-controlled` / `control axis` / `resource_link` / `read_only_hint` / `31 tools` / `6000 tokens` / `not vary per-connection` 全库 SKILL.md **0 命中**；`cacheScope`/`ttlMs` 在 co-learn 的命中均为豆包 r381B 已学「列表结果带 ttlMs+cacheScope 提示 + list_changed 过期」缓存 hint 本体 ⇒ 本轮不重复该结论，只取集合稳定性与授权隔离语义；`resultType` 1 / `ttlMs` 2 命中同属该已学缓存面。豆包自留地 WB 0 落地。
