## 三、本轮 3 个独有点（完整判据见技能正文 §13.1–13.3）

1. **服务 p99 拼不出产品 p99**：用户延迟是必需子调用的最大值，不是均值也不是各服务分位的拼接；N 个 99% 分位并行时全快概率 `(0.99)^N`（10→90.4%、100→36.6%），CACM 原文 100 台 63% 超 1 秒、2000 台万分之一异常近 1/5。⇒ 规格写「扇出度 N + 每跳分位 + 联合分位」，在边缘（网关/BFF/RUM）测，减少必需扇出优先于加机器；变异按共享资源/守护进程/全局共享/维护活动(GC、压实)/多层排队逐类排查，别一律归为网络抖动。
2. **hedged 与 tied 触发条件不同，且只适用幂等只读**：hedged 是首请求超过 p95 期望时延才发副本（约 +5% 负载；BigTable 1000keys/100台/10ms 把 p99.9 从 1800ms→74ms 仅 +2% 请求）；tied 是同时入多队列、谁先开工谁发取消给对方，省掉检测等待但有一个平均网络消息延迟的双执行窗口，官方建议两发之间错开 2×该延迟。⇒ 写操作对冲＝双扣；赢者返回必须显式取消败者，否则 2× 负载且尾部更差；规格须标 effect class，`read/reversible` 才允许挂对冲。
3. **取消时机决定成本、相关性决定成败**：before dispatch 才不占算力，after dispatch 只丢结果（GPU kernel 不可廉价中途取消），故需 spare capacity + 显式 duplicate-work budget；相关减速（共享依赖 / 同加速器 / 同内存总线 / 热键定向）让 i.i.d. 假设失效，对冲会**放大过载而非削尾**，正解是拆共享依赖不是加对冲。⇒ 验收固定四栏「扇出度 / 分位阈值 / 重复工作预算 / 取消点」，与 §十重试预算分账（重试管失败、对冲管慢而成功），与 §十二 deadline/取消树分工（那两条管失败与截止）。
