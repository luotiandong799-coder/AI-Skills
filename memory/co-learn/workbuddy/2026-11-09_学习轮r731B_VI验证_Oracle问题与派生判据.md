### 独点判据原文（逐条，不缩水）

- **r731B-1 ★验证前先声明 oracle 来源**：Barr 逐字「We have placed them with derived test oracles, because, in practice, metamorphic relations are **usually manually inferred from a white-box inspection of a SUT**」；回归测试「It rests on the **implicit assumption that the previous version can serve as an oracle** for existing functionality」；「The biggest challenge in metamorphic testing is **automating the discovery of metamorphic relations**」。判据：① 验收报告须写明判定基准（人写期望 / 派生关系 / 参考实现 / 隐式不变量）及其来源，不能只写「已验证」；② 改版/换模型时旧版输出不能直接当真值，隐含假设已失效；③ 蜕变关系靠人工从规格推导，「自动发现关系」是未解难题不是既有能力。与 §6.3 既有一句「换问法不应改变事实」分工：那句是 MR 的一个实例，本条管基准与假设登记。
- **r731B-2 ★蜕变关系的形式约束**：逐字 `f(x1)o1 f(x2)o2 ... : [expr ∧ k ≥ 2]`、「a constraint on the values of **stimulating the single SUT f at least twice**, observing the responses, and imposing a constraint on how they interrelate」；非数值例 `R_OR: A1=(A2∪A3) ⇒ |A2| ≤ |A1|`（搜索引擎结果集）；「When the SUT is **nondeterministic** ... defining metamorphic relations solely in terms of **output equality is usually insufficient**」→ set intersection / statistical metamorphic testing。判据：MR 必须写成可执行的**两跑对照**（排序不变 / 包含 / 长度不增 / 集合交集 / 统计区间），不是单次输出断言；LLM/Agent 输出逐字相等不成立，禁止用 equality 当唯一关系。
- **r731B-3 ★属性测试闭环**：Hypothesis 官方逐字「`@given` ... takes a *strategy*, which describes the type of inputs」、「**By default, Hypothesis generates 100 random inputs**」、「Hypothesis doesn't just find *any* counter-example ... it knows how to **simplify the examples** it finds to produce **small easy to understand ones**」；`Falsifying example: ... s=''` 与 `s='001'`；`@example("")`「ensure that particular edge cases ... are tested every time」「although Hypothesis will remember failing examples, **we don't recommend distributing that database**」；`.filter()` 优于复杂条件、`assume()` 丢弃整例、`@composite` 让生成值相互依赖。判据：验收不能只写单个样例，要写属性（round-trip / 幂等 / 不变量 / 不崩溃）+ 生成策略 + 最小反例；失败反例须显式固化为 `@example` 回归样例，不依赖本地失败数据库；生成范围贴合真实域，避免过滤器丢弃过多样本。
