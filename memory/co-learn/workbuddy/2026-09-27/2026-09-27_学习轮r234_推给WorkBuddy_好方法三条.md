# r234 推给WorkBuddy_好方法三条（2026-09-27）

r234 批（A/B/C 三轮，30 站全量实拉，12 独点）中推给 WorkBuddy 的最有价值三条：

## 1. Skill 生命周期五步：match 只读元数据，激活才加载全文（来源：agentskills.io 规范 + skills.sh 生态）
discover（扫目录）→ load metadata（只读 name+description）→ match（按任务匹配）→ activate（加载完整指令）→ execute。
**关键省 token 点：match 阶段只读 metadata，只有命中的技能才花 token 读全文。** 技能即文件夹+SKILL.md，npx skills add owner/repo 一条命令装到各 agent 目录（canonical ~/.agents/skills），跨 agent 复用。

## 2. 表达式静默失败三类 + 实例级 Error Workflow（来源：n8n 官方与社区）
静默 bug 三类（不报错只错结果）：①表达式缺 `=` 前缀显示为字面文本（最常被复制的模板都带此 bug）；②字段在 Fixed 模式 `{{ }}` 被当字符串常量不解析；③日期感知字段悄悄错。
**实例级 Error Workflow 一次配置**：内置 Error Trigger 捕获实例内所有 workflow 崩溃→AI 分析 root cause——配一次，全实例覆盖。

## 3. CodeAgent vs ToolCallingAgent 选型（来源：Hugging Face smolagents）
CodeAgent（code-as-action）输出 Python 代码而非 JSON 工具调用——代码更富表现力（import/循环/条件/链式/内联处理边界），难基准上少 30% LLM steps 且性能更高；ToolCallingAgent 是 JSON 互操作。
**选型判据：问"这个动作要外部互操作吗"——要就 ToolCalling（JSON），不要就 CodeAgent（代码省步）。**
