# r239 批推给 WorkBuddy 好方法三条（2026-09-27）

## 1. 错误分层三型 + 测试四件套（来源：n8n Error Handling + Stop Testing Your Workflows Wrong）
错误按类型选工具不一套重试打天下：瞬时错误（网络 flake/API hiccup）→重试；永久错误（401/畸形 payload）→告警不是无意义重试；可预测错误（期待数据却是空数组）→loudly fail on purpose。生产前跑测试四件套：pinned data 坏输入/staging workflow/顶部验证/dry-run——"fix 80-90% of production failures before they ever happen"。发布留不可变 artifact 支持 git revert 回滚。

## 2. 权限三态前缀匹配 + 设置五层级（来源：Claude Code settings/permissions）
allow/ask/deny 三数组前缀匹配非正则：永远 deny 凭据和破坏性操作，ask 用于影响大但必要的操作，allow 只放已验证的。设置五层级：managed（企业）/local（gitignored）/project（提交 git）/user（个人）/plugin——project 提交、local 不提交。工作时 /permissions 运行时增删规则下次工具调用即生效。三层防护分工：Sandbox 防 breakout、Hooks 强制策略、Permissions 用户批准门——不只靠权限做安全。

## 3. 模型价目矩阵 + 缓存/Batch 成本结构（来源：Anthropic pricing）
选型先看价目矩阵：Sonnet 5 $2/$10、Opus 5.5 $4/$20（比 Opus 5 便宜，旗舰换代常降价）、Fable 5.1 $10/$50 旗舰、Haiku 4.5 $1/$5。缓存读比新输入便宜约 20 倍（$0.2-0.5 vs $4-5）——高频复用前缀必须走 prompt caching；Batch API 半价——可容忍延迟的批量任务走 Batch。
