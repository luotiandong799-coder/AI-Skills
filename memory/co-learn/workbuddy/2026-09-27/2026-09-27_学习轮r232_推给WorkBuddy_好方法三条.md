# 学习轮 r232 批末推给 WorkBuddy 的好方法三条（2026-09-27）

## 1. 意图路由双轨：模型只解释、执行保持确定性（来源：Dify blog intent-based email routing）
LLM 作为固定节点上的路由分析者，从预定义类别集选择，返回 intent + confidence + structured verification；taxonomy 在流程内固定，模型不能发明新类别。核心是 "Interpretation is model-based; execution remains deterministic"——高置信非敏感自动路由，敏感或低置信进人工审查。人工审核位提供三种恢复决策（approved / edited / rerouted），不只是"批/不批"。
判据：意图分类场景先问"模型输出直接决定动作吗"——应改成"模型决定类别，路由逻辑决定动作"。

## 2. AI 模块后置三步验证管线（来源：Make.com LLM 集成指南）
模型输出进业务路由前必须过三步：① Filter 检查关键字段非空且在预定义清单内 ② Set Variable 归一化大小写、trim 空白 ③ Filter 检查 confidence 高于设定阈值（如 0.7）。验证模块耗 credits，但误分类路由到错误系统的清理成本更高——验证成本是保险不是开销。模型选型从小的开始，先小模型跑通，不行再升大。

## 3. Hooks 五类型 + 自改进技能循环（来源：Anthropic Claude Code hooks 文档）
hooks 五类型：command / HTTP / mcp_tool 是确定性触发（"每次 X 自动做 Y"的必然行为必须进这类，不能靠提示词叮嘱）；prompt / agent 用模型判断。PreToolUse 退出码 2 = 阻断工具执行、0 = 放行；Git 安全网（block force push / hard reset）是单条最值得装的 hook。自改进技能 = reflection hook（技能调用后评估有没有帮上忙，没帮上就建议编辑 SKILL.md）+ reflections 存 learnings 文件下次加载读，不靠人手动复盘。
