# r240 批推 WorkBuddy 3 条（2026-09-27）

## WB-1 上下文工程四件套 + 广播并行 + API 幂等（源：n8n Blog / Dify，r240-B/A 精华）
- **上下文四件套分工**：IF/Switch 动态选上下文路由 + Code 节点压缩数据（总结历史/提取结构化事实再进窗口）+ 子工作流隔离（每子 agent 只带自己工具数据）+ memory 节点管历史轮数。
- **窗口量化**：Window Buffer 5-10 轮（4096 token）；事务型 agent 4-6 条；session key 映射用户/会话 ID 而非执行 ID；Postgres 审计（5-20ms）/ Redis 低延迟（1-5ms）按需选。
- **广播模式**：一触发器同时激活多 Agent 并行，延迟 O(n)→O(1)，等全部返回再聚合——互不依赖的任务别默认串行排队。
- **API 幂等三件套**：Idempotency-Key（24h TTL）防重试重复执行 + per-tenant 并发守卫（超限 429）+ 定时清理卡死执行。
- 提升层：工作流。

## WB-2 多 agent 四角色 + 两 agent 链质量门 + hooks 优先级（源：Make / Anthropic，r240-B/C 精华）
- **四角色是分工模板**：Router（分类路由）/ Specialist（领域专精）/ Validator（质量合规评审）/ Orchestrator（协调收结果）——要拆多 agent 先对号入座。
- **两 agent 链质量门**：Agent1 起草 → Agent2 按质量 rubric 评估，通过才发、不通过重写——交付型生成（邮件/文案/代码）出口默认挂评审 agent。
- **hooks 优先级 deny > ask > allow**：任一 deny 一票否决；hooks 当安全代码用（阻断读 secret 路径、编辑 .github/.claude/.mcp.json/部署清单）；只装自己审过的 hook（CVE-2025-59536 恶意 repo 注入 hooks）。
- 提升层：工作流 / 可复用 Skill。

## WB-3 RAG 排障顺序 + 调试四步 + 发现顺序（源：Dify / n8n / skills.sh，r240-C 精华）
- **RAG 排障先查检索再改 prompt**：缺失或分错块的源无法靠 prompt 修复；Agentic RAG 让 agent 低质量时换 collection/切外部搜索。
- **调试四步不动生产**：开失败执行日志 → 找失败节点记名+错误消息 → 查节点输入 → 判数据是否如预期；debug 字段（_debug_sample）看失败前一刻快照；Fallback Service：continueOnFail+IF 切备用。
- **技能发现顺序**：先查 leaderboard（安装量=久经考验）再 CLI 搜索；开放市场（~67万）自己审 vs 策展集（80 个带 Snyk 扫描）按场景选。
- 提升层：工作流 / 工具。
