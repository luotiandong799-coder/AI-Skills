# r237 批推给 WorkBuddy 的好方法三条（2026-09-27）

## 1. Agent 单职责 boring 准则 + 推理不因工具失败丢失（来源：n8n Agents 发布 + Shopify triage agent，2026-09-27 实拉）
- **agent 每个只做一件事**，且"work 且 boring 是对 workflow 的最高评价"——职责窄到"就这一件事"。
- **输出必须带 reasoning 字符串 + confidence 分数，绝不只是 verdict**——即使外部 API 调用失败，失败告警也携带推理链；低置信/模糊案例先路由人工，再触发外部动作。
- 应用：任何 agent 化任务（含定时任务里的多步处理）拆分到单职责单元；结果汇报带推理与置信度；工具失败不吞掉已产生的推理。

## 2. Skill 编写官方规格与触发调优（来源：Anthropic/Claude 官方 Agent Skills 文档，2026-09-27 实拉）
- **规格**：SKILL.md body <500 行；文件引用一层深；渐进披露按需展开；name ≤64 字符、仅小写字母数字连字符、禁保留词；description 非空 ≤1024 且具体含术语。
- **触发双向诊断**：该加载没加载（undertriggering）→ description 加细节/术语关键词；无关查询也加载（overtriggering）→ 加 negative triggers、更具体。
- 应用：写/改技能先过规格三关；触发异常按两向诊断，不靠猜。

## 3. LLM 路由三模式：成本强制 / SLA 分级 / Failover（来源：n8n LLM Routing 官方博客，2026-09-27 实拉）
- **查询级成本强制**：把计算成本钉在每次查询级别执行，不在聚合账单里事后发现超支。
- **SLA 分级路由**：premium 用户给更快更强的模型、free 用户给成本优化响应；**路由决策发生在 session 级、第一个 token 处理之前**。
- **Failover routing**：监测 provider 可达性，主模型不可用或降级自动改道，无需改凭据改 workflow。
- 应用：多模型/多 provider 场景按这三层设计路由；成本按查询级预算；降级自动切换。
