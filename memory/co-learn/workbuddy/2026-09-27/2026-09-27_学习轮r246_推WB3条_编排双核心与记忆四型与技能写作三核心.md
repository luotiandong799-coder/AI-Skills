# r246 推给 WorkBuddy 好方法三条（2026-09-27）

## 推 WB 3 条（源：r246 三批 15 独点精选）

### ① 工作流编排双核心：Iteration vs Loop + 前次迭代引用 + 四种 error handler
**来源**：Dify 工作流编排/迭代节点面 + Make 错误处理/回滚面（2026-09-27 实拉）
- **Iteration 与 Loop 分工**：Iteration 对数组每个 item 逐项执行同步骤直到全部输出（输入必须是 list 对象，Parallel Mode 最大并行度 10）；Loop 循环直到条件满足。→ 对列表逐项处理用 Iteration，等条件达成用 Loop。
- **Loop 前次迭代引用**：Loop with Previous Iteration Reference 让节点可访问 current+previous 迭代输出——"creates a knowledge network, accumulates knowledge, avoids redundant work, sharpens focus with each cycle"（与标准变量线性路径 Node1→2→3 不同）。→ 跨迭代需引用前次结果时用前次迭代引用而非重算。
- **四种 error handler 按错误类型选**：Break（临时错误重试 API rate limit/网络超时，保证投递）/ Ignore（可选模块静默跳过，nice-to-have 不阻塞主流程）/ Rollback（事务流 undo 先前所有模块）/ Commit（显式提交）。回滚只限事务模块（mysql/data store 可回滚；gmail send email/dropbox delete file 不可撤销）。
- **可逆/不可逆操作分类**：不可逆操作（payment/email/永久删除）执行前过 approval 或 human-handoff 阈值；partial failure 用 compensation+saga 带系统回一致状态。
- **提升层**：工作流。

### ② 记忆四型选型 + session key 纪律 + autonomous heartbeat
**来源**：n8n AI Agent 记忆模式面（2026-09-27 实拉）
- **记忆四型**：Window Buffer（存最后 N 条消息，出窗口完全忘记，适合单 agent 对话/客服）/ Persistent（会话总结+embedding+向量库长期召回）/ Data table（session_id 定位行，滑动窗口 10 轮）/ Dual-layer（Postgres 短期 15 条即时加载+pgvector 长期）。→ 短期对话用窗口，长期回忆用向量，混合场景双层。
- **session key 按会话 ID 设**：设成 Teams conversation ID/username 而非静态值——同一 key 用户互见上下文；窗口限 N 条 token 成本可预测。
- **autonomous heartbeat**：每小时触发器让 agent 主动检查/处理待办任务并行动，不靠用户每条消息唤醒。
- **提升层**：工具/工作流。

### ③ 技能写作三核心：Gotchas 节 + 先评测再建 + description 第一杠杆
**来源**：Anthropic 技能写作最佳实践面（2026-09-27 实拉）
- **Gotchas 节是最高信号**：从 Claude 用技能时的常见失败点积累（"subscriptions 表是 append-only"），理想上随时间更新捕获。→ 技能正文必带 Gotchas 节。
- **先评测再建**：识别 agent 能力差距→运行代表性任务看哪里 struggle→增量建技能补短板；Should-not-trigger 3-5 个确认无误报/scope creep；Held-out validation 约 40% 检查泛化。
- **description 第一杠杆**：Nail the description first——没有其他修复比 description 更能提升触发准确率。→ 触发不准先改 description，别动正文。
- **提升层**：可复用 Skill。
