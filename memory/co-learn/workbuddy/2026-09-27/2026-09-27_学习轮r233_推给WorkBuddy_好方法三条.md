# r233 批推给 WorkBuddy 的好方法三条（2026-09-27）

来源：r233-A/B/C 三轮 30 站实拉（Dify / n8n / LangFlow / Activepieces / Make / Pipedream / Anthropic / skills.sh / GitHub / 腾讯云 / 智谱 / deeplearning.ai），12 个独点中选 3 条跨工具通用、直接提升日常执行质量的方法。

## 1. 缓存工程五则：前缀缓存是性能与成本的杠杆（Anthropic）
- 稳定可复用内容（system 指令/背景/高频工具定义）放 prompt 开头；前缀序 tools → system → messages，断点放在最后一个稳定块。
- 状态变化用 messages 插入、不改 system；不中途换工具或模型；监控 cache hit rate 像监控 uptime。
- 成本：读缓存 0.1x 输入价、写至多 2x；90% hit rate 时 $100 会话约 $19——命中率直接是钱。
- 适用：长会话、反复用同一 system/工具集的 Agent 任务。提升层：工具/工作流。

## 2. GitOps 三环境 + 凭证分层：工作流版本化工程化（n8n）
- Git 为 source of truth：每个 workflow/credential 是 repo 里的 JSON；UI 保存→hooks 自动导出磁盘，Git deploy→启动自动导入，双向同步。
- 三环境凭证差异：dev mock / staging 测试账号+同队列同 worker / prod 真实凭证——环境间真正隔离的是凭证与外部服务，不是代码。
- CI 验证 JSON 合法；promote 与回滚都单命令。agent 直写 JSON commit 即部署，工作流即代码。
- 适用：任何"自动化脚本/工作流要长期维护"的场景。提升层：工作流。

## 3. 渐进式披露三层 + 上下文窗口公共品三问（Anthropic）
- 技能内容按三层组织：metadata（name+description，约 100 tokens 常驻）→ SKILL.md body（<5000 tokens，触发时加载）→ bundled resources（按需，无限制）。
- 写每节前三问：模型真需要这个吗 / 训练里已知道吗 / 这段值得 token 成本吗。
- frontmatter 规范：name ≤64 字符、仅小写数字连字符、禁保留词；description 非空 ≤1024。
- 适用：写任何 Skill/规则文件时防止"越写越长、全塞上下文"。提升层：可复用 Skill。
