# 学习轮 r231 推给 WorkBuddy 的好方法（3 条）（2026-09-27）

来源：r231-A/B/C 三轮实拉（skillsmp/Dify/n8n/LangFlow/Activepieces/Make/Pipedream/Anthropic/GitHub/WaytoAGI 等 30 站次），选 3 条对 WorkBuddy 可直接吸收的跨轮好方法。

## 1. 技能静默成本 + 描述截断治理（Anthropic 实测 + Claude Code 实践）
- 技能不触发也花钱：5 技能 × 7 小时实测，dormant skills 描述层 231K tokens 占 11%，3 个从没触发的技能占 18% 账单——**每个 description 每轮都进上下文**，装技能不是免费。
- 触发短语放描述最前：**上下文压力下 description 会被截断**，截掉的就是调用入口；/doctor 可检查描述是否被缩短。
- 副作用技能（deploy/commit/notify）设 disable-model-invocation: true，禁止模型顺手自动调用。
- 诊断表：技能不加载→描述加细节关键词；过度触发→加负面触发；输出不一致→加 examples/ 好输出示例。
- 提升层：可复用 Skill。

## 2. waitpoint 幂等 + HITL 四要素（Activepieces + 多源）
- waitpoint=durable checkpoint：run 标记 PAUSED、状态持久化、resume 信号=HTTP 调用 resume URL 或 scheduled job；**同一 pausing action 会跑两次（一次创建 waitpoint、一次读 resume payload）——会暂停的步骤必须幂等**。
- HITL 四要素：interrupt（风险动作前暂停不丢上下文）/ notification（按类型/风险路由到对的人）/ review interface（展示 proposed action + agent 推理，审的人不能盲目点）/ resume（proceed / modify-then-proceed / cancel 从暂停点精确恢复）。
- 审批队列要 owner/SLA/提醒/过期行为/fallback；**执行前重验时间敏感事实**（proposed 时有效、approved 时可能已过期）。
- 提升层：工作流。

## 3. 错误处理五指令 + 子流程隔离（Make + n8n）
- 错误处理指令各有操作后果：Resume（忽略继续）/ Ignore（跳过记录）/ Break（停跑）/ Commit（**标记 bundle 已处理即使出错，防重复处理**）/ Rollback（**撤销先前所有操作，事务原子性**）——选哪个是"这记录还重不重跑"的语义决策，不是风格。
- **场景可以"成功"却啥也没写**：router filter 全放空/搜索返回零 bundle/错误被忽略——结果校验要查"目标记录确实写入了"，错误路径用 if/else 而不是 router。
- **工具错误隔离在子流程边界**：HTTP 调用包进独立 sub-workflow + Continue on Fail，子流程总能完成并回干净响应给 agent，主流程不会死。
- 三响应模式标准化：transient→退避重试；数据问题→隔离+通知附 bundle；升级带上下文（module/operation ID+一键重试链接）。
- 提升层：工作流。
