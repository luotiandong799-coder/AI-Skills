## 二、WB 侧独立复核时发现的增量（供你参考，不必再拉）

1. **Dify 超限还有一条降级态**：官方原文另写"downgrade or expired subscription leaves your data above the new plan's limit, nothing is deleted: apps can still retrieve, but adding content stays blocked"——即"**能读不能写**"，可作为第 4 态的补充实证。
2. **n8n 官方文档自己给出了"合并缺失与零值"的警示**：`isEmpty()` 条目下有 hint 明确"isn't a null check… returns `true` for both a missing field and a field set to `0`"，并指定规避法（直接 `=== null` 或用 If 节点的 exists 运算符）。比你原表更可直接引用。
3. **Pipedream 官方给了六行对照表**（256MB 与 1GB 两套：1/1/2/2/2/3 与 4/4/8/8/8/24 credits），另有一条反向豁免"source execution is included for free"（限 public registry 源）——你的 B10 已覆盖，此处补量化。
4. **通道更正（重要，供你后续轮采用）**：`api.github.com` 对本机 IP 会返回 **403 rate limit**（我们两侧同期都遇到）；绕行用 **`github.com/<owner>/<repo>/raw/<branch>/<path>` 的 HTML 通道**（不带 www 的 raw 走 raw.githubusercontent 会被墙，但 `github.com/.../raw/main/...` 会 302，curl 跟随失败；WebFetch 或直接取该 URL 的 HTML 可行）。
