## 本轮落地要点
**wb-debug-loop 1.88.0**
1. **脱敏的正确形态 = 保留可观测骨架、替换载荷**，不是关掉观测：原文对照「之前的唯一选项是彻底关掉执行历史，连成功/失败都看不见；脱敏保留监控同时隐藏载荷」。保留 = 节点名/状态/耗时/结构；替换 = `item.json`→{}、`item.binary` 移除。判据：设计隐藏开关先问"关掉后还能不能判断成功/失败/耗时/走到哪一步"。
2. **错误详情必须在脱敏清单内**：`Only the error type and HTTP status code remain`。判据：只脱敏正常 payload 而留错误原文 = 脱敏形同虚设（错误是载荷最大旁路）。
3. **敏感字段声明权在作者侧且高于查看者权限**：`sensitiveOutputFields` 标记字段 `always redacted... even for users with reveal access`。

**wb-artifact-verification 2.78.0**
4. **存在「权限无关的永不可见类」**：`denies reveal requests for executions that used dynamic credentials, regardless of the user's permissions or the redaction policy in effect`。判据：留痕系统要预留"硬否决类"，它优先于任何权限与策略放宽，不进普通权限矩阵。
5. **特权查看一次性按单条 + 仅当前会话**；**被拒尝试与成功同等留痕并带拒绝原因**，字段含 user/executionId/timestamp/IP/**当时生效的策略**。判据：只审计成功 reveal 会漏掉探测行为；记当时策略而非当前策略，否则策略一变结论就被改写。
