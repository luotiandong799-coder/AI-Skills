### 独点判据原文（逐条，不缩水）

- **r738A-1 ★重试是战术，恢复是策略，两者不共用一套计数**：xgrid 逐字「Retry is a tactic where we are re-executing a failed operation.」/「Recovery is a strategy where resuming a workflow from a known good state without re-executing completed steps.」/「Do not use application-layer retries as a substitute for durable state.」 ⇒ 应用层 `for i in range(3)` 在 Worker 崩溃时「if the worker crashes on attempt two, the retry count resets」，而服务端协调的 activity 重试让「retry count, back-off timing, and failure state survive any worker restart」。判据：① 恢复资格由**外部历史**判定，不由进程内计数器判定；② 「已完成步骤不重跑」要能举证（历史里有记录），否则只是「从头再来了一次且恰好幂等」；③ 多 agent 长跑先问「checkpoint 存的是结果还是可重放的事件序列」。与 §8.3「resume from where / regular checkpoints」分工：那条给恢复点，本条给凭什么敢跳过。
- **r738A-2 ★确定性约束落在编排代码，副作用落在 Activity，边界按「碰不碰外部系统」划**：Temporal 官方逐字「The Temporal Platform requires that Workflow Definitions are deterministic.」/「Non-deterministic work such as API calls, and database queries should be placed in Activities, which Temporal retries reliably.」；官方 FAQ 对 LLM 更严「Workflow code must be deterministic — it is replayed from history whenever a Worker recovers from a failure.」，同一 prompt 两次调用可能不同，故 LLM 调用、**prompt 本身**、凭据读取都必须进 Activity（「Prompt versioning and replay safety」）。判据：① 编排代码出现 `random` / `now()` / 直接 HTTP / 遍历无序 map，重放时可能产出与历史不同的 Command 序列 → nondeterminism error；② 换 prompt 只影响新执行、在飞执行仍按历史里的 Activity 结果重放，这本身就是版本隔离；③ 凭据不要从 Workflow 参数传（会被序列化进历史），在 Activity 内从 secret store 取。
- **r738A-3 ★幂等键与补偿动作是设计期产物，编排代码改动要给在飞执行留桥**：官方逐字「A Retry Policy makes Activity completion observable exactly once, but it does not make the Activity code execute exactly once.」 ⇒ Worker 在回报完成前崩溃时副作用会重做；幂等键用 Workflow Run ID + Activity ID，**不要含 attempt number**（重试间必须稳定）。补偿「Compensating activities must be defined at the time the forward activity is written, not after a partial failure is observed in production.」；改编排逻辑会破坏重放，故需 Worker Versioning 或三步 Patching（`patched()` 写 marker → `deprecate_patch()` → 旧执行退留存后移除），官方 danger 注记 2025 年前实验版 Worker Versioning 于 2026-03 从 Server 移除。判据：① 每个写操作配一个与尝试次数无关的幂等键 + 一个已写好的反向动作；② 「exactly once 可观测」≠「副作用只发生一次」；③ 部署新编排前问「有没有在飞执行会拿旧历史重放新代码」，有则先 patch 再发；④ 事后补恢复被标注 3–5× 成本（厂商立场，仅作量级参考）。
