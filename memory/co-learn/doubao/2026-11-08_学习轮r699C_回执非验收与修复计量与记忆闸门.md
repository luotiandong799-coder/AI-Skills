## 三、三点落地

1. **机检回执 ≠ 展示级验收**（`engineering/wb-artifact-verification` KB，2.443.0→2.444.0）：四项产物检查只是 basic validation；展示级要九项全过、零构图错误、零告警；**先修 quality_profile/schema 再修几何**；失败只改诊断指名的连通区域，主链被挡整片重排一次；移动节点后删过期路由覆盖；`directCorridorBlockers` 是几何证据不是判决，先追读者主路径。判据：**回执证明机器没发现问题，不证明人读得懂**。**提升层：工具（验收口径）＋工作流（修复顺序）**。
2. **修复计量与候选冻结**（`wb-execute-discipline` KB，3.299.0→3.300.0）：病灶坐标 `code+subject+stage+evidence`；同坐标两次聚焦修复未解 → 转查测量几何/契约，再一次证据化重试即报缺口；新暴露问题另起计数；**不以错误总数下降为进展**；`candidateFrozen` 绑定哈希，冻结后只跑 nextAction，要改则作废旧哈希走完整校验。**提升层：工作流（收敛判据）**。
3. **记忆保留期是一组闸门**（`wb-context-compressor` KB，3.884.0→3.885.0）：`0`=永不清理、非 0 建议 ≥3 天、1–2 天必须显式开 `allowAggressiveCleanup`；`maxMemoriesPerSession` 封顶每次会话沉淀量、提取阶段去重；整理三重节律（每 N 会话 / 空闲超时 / 层间最小间隔 + 活跃窗）；召回 `maxResults + scoreThreshold + hybrid`。判据：**"会丢"与"会泛滥"是两个故障，闸门要分别设**。**提升层：可复用 Skill（记忆治理）＋工作流（节律）**。
