## 二、落地点（5 个真独点，4 条主点 + 1 条机制点）

### 1. 工具目录只放可信名字与描述（工具层）
原文 `a bounded directory of the available trusted tool names and descriptions`；MCP/client 工具的 `untrusted names and descriptions are not copied into the system prompt`；调用链是 search 紧凑描述 → describe 选中工具的完整 schema → call；`catalogMode: "direct-only"` 不进目录、保持可见；目录须 `cache-stable`。与既有"延迟加载省 token"（L4558）分工：本条管"谁的描述有资格进提示"。

### 2. 审批只能收紧，UI 缺失按 deny 兜底（工具层）
`policy + allowlist + (optional) user approval` 三者同时同意；`approvals can only tighten config-derived security/ask, never loosen them`；UI 不可用时 `ask fallback (default: deny)`。

### 3. 批准绑定精确执行上下文（工具层）
`bind the exact execution context: cwd, exact argv, env binding when present, and pinned executable path`。审批对象是"这一次执行"，不是"这个命令名"。

### 4. 多文件多 hunk 用结构化补丁（工作流层）
`*** Begin Patch` + `*** Add File` / `*** Update File` / `*** Move to:`；原文 `ideal for multi-file or multi-hunk edits where a single edit call would be brittle`。一次成型、整体成立或整体失败。

### 5. 进度卡是单值状态，只归父会话（工作流层）
每次调用 `replaces the whole card`；durable session state，重连从 Gateway 读最新卡；transcript 只留短回执；`Spawned sub-agents never receive progress_card`；建卡门槛 ≥2 个有意义顺序步骤，不得为凑卡编步骤。
