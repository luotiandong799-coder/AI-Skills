## 10 次实拉（逐站留痕）
1. Eval 数据集治理（强）：**golden set 语义化版本（major=使历史比较失效的变更/rubric 更换、minor=扩展覆盖、patch=修单项）；发布后不可变（never modify released version in place）；每 release 不可变 tag+changelog**；**分数下降三归因（model regression/rubric change/set change）需 diff-able 版本**；分桶+月度漂移刷新；覆盖 200-500 任务分层（routine 50%/edge/rare）+季度覆盖审计
2. Trace 重放回归（强）：**Record 模式全量记录三类数据（LLM 调用=完整 request+response+当时工具定义；工具调用=函数+参数+结果；时间戳）；Replay 模式用确定性 stub 替代 live LLM/tools 按记录序列返回**；**生产失败→确定性回归测试**；**point-in-time replay：用新模型/新 prompt 重评估历史决策**；JSONL trace steps+因果顺序重放+两个回归检查（聚合阈值门+分布感知置换检验）
3. 故障注入/可靠性（强）：**可靠性三维面 R(k,ε,λ)=pass^k 重复一致性 × 语义等价扰动鲁棒性 × 受控工具/API 故障容错（timeouts/rate limits/partial responses/schema drift）**；**rate limiting 是最具破坏性的故障类型（比 timeout/partial 更甚）**；**动作蜕变关系=以终态等价判定正确性（不看过程文本看结果状态）**；环境混沌注入（工具+LLM 故障）
4. 上下文位置（强）：**V 形放置（最重要的块放头尾，最弱埋中间，损失 ~15-25 分）**；**激进 rerank 到 3-5 块通常优于塞 20 块（每个额外低值块都加宽"中间"）**；**recency 提升常强于 primacy：问题/最终指令放最后 10%**；位置感知 rerank 需显式开启
5. 结构化输出验证（中-强）：**验证分三层：语法（可解析）→ schema（必填键/类型/enum）→ 业务（领域合理性：退款金额不应为负、cron 匹配产品限制）——业务层最常被跳过**；校验失败把错误喂回模型重试（D78 已收）
6. 记忆层级（中-强）：**procedural 记忆最好表示成指令而非数据（学到的经验注入为 system-prompt 指令，不从 vector store 检索）**；异步整合守护进程把 episodic 蒸馏成语义事实（与 D86 同族）；episodic 条目结构=目标+动作序列+工具+参数+结果+评估
7. Prompt injection 评测：AgentRedBench 215 场景/24 集成/5 攻击类型/无守卫 ASR 32-81%；ClawSafety 120 用例三通道（技能文件/可信邮件/网页）；ASPI 歧义放大 728 场景——数据点
8. GitHub 生态：deepseek-harness "Everything is a Plugin"；Karpathy rules（think before coding/state assumptions/never guess）；everything-claude-code 菜单式配置合集——生态/已覆盖
9. 平台探活：Langflow 1.11 HITL+A2A 协议+AG-UI 流式；Dify 聊天构建 Agent（自动生成可复用 skills）；n8n agent 响应流式+能力 pill 实时可见——平台功能
10. Anthropic Skills：企业评测要求（每 Skill 3-5 个代表性查询=该触发/不该触发/歧义边界）；跨模型测试（Haiku/Sonnet/Opus 效果因模型而异）；渐进披露 metadata ~100 tokens——与 sa 重叠
