## 三、三点落地

1. **三类问题分开测**（`engineering/wb-agent-evaluation` KB + 指针，1.147.0→**1.148.0**）：答案质量 / 工具速度稳定 / 模型 token 与工具调用成本三账分开；实验先冻结（仓库 SHA、问题集、模型与提示、预算、先后顺序、预热）；两组同条件且互相隔离，重复次数与聚合方式在看结果前定，**保留每次运行含失败与零结果**；"看起来干净"的工作副本不算冻结，要独立 detached worktree 并在索引前、每组开跑前复验。**提升层：工作流（评测口径）**。
2. **资源预算配发布权仲裁**（`wb-execute-discipline` KB + 指针，3.300.0→**3.301.0**）：四类上限（文件数/源码字节/进程树记账内存/整次时长）默认关；记账内存按整棵进程树（`phys_footprint` 而非 `resident_size`），探针间隔 ≤250ms；**worker 与 supervisor 谁先申领发布权谁赢**——超限先到则旧状态原样保留，worker 先申领则限流不再生效；时长上限与静默超时不同源；三次拿不到可信测值即 fail closed。**提升层：工作流（资源治理）**。
3. **索引排除五层与排除回执**（`wb-debug-loop` KB + 指针，1.367.0→**1.368.0**）：排除发生在文件发现期，内置跳过 → 仓库 `.gitignore` → 嵌套 `.gitignore` → 项目排除文件（可否定）→ 全局，**先拒者胜**；`.git`/`node_modules`/工作树元数据为**不可否定安全核**；被跳过的子树要在返回里报 `excluded{dirs≤25,count,truncated}`；按**全路径后缀**排除"名字太普遍"的生成物目录。**提升层：工具（索引治理）**。
