## 四、提炼核心方法与关键事实

1. **单用途起步+预算铁律**：single-purpose agents do one thing well 再渐进；简单系统便宜易 debug metrics 清晰；Every agent must have a budget——turns/tokens/tools/wall-clock。Or it's not an agent, it's a bug；Start with single agent，add coordination only when demonstrably fails；Pattern>framework。
2. **workflow vs agent 选型**：能定序走 workflow（prompt chaining/routing/parallelization）；需自主决策才 agent 节点；workflow 作 tools 传给 agents；非确定性步骤锚定 immutable triggers；keep deterministic deterministic（AI 分类/总结/抽取，验证后才改数据，高影响动作 confidence thresholds/human approval）。
3. **模型路由+工具最小化**：cheap/local 做分类/摘要/草稿，strong 只审复杂决策/安全/代码——premium reasoning only where it changes the outcome；每 agent/LLM node 连不同模型=配置决策非架构变更；Limit Tools 只给需要的（太多混淆 AI）；Clear Tool Descriptions 写"何时/如何使用"。
4. **增量构建测试纪律**：一次加一组件测一组件；先 knowledge files 测检索正确再加 tools 逐个 chat 验证；Keep It Simple minimal components 起步每步测；系统提示词划能力边界+工具清单定外部接触面。
5. **管线状态图化**：Plan→Act→Check/Adapt→Memory 四步；生产最大陷阱=开放循环（DAGs+cyclic state machines 让 LLM 只在严格验证状态内选 transitions）；Thin orchestrator separate routing from reasoning；编排三模式（Sequential/Supervisor+Specialists/Parallel Fan-Out）。
6. **技能工程脚手架**：description=load gate（[what]+[when]+[capabilities]+trigger phrases+negative triggers）；instructions 写 delta from baseline；五层方法论（Intent/Knowledge/Execution/Evaluation/Governance）；skill contracts（invocation conditions/contraindications/constraints/output specs）；metadata 轻载 resources on demand；团队技能库像软件治理（owner/version/permission/retirement）。
