## 二、落地点（4 个真独点）

### 1. `allowed-tools` 是「预先批准清单」（可复用 Skill 层）
spec 原文 `pre-approved tools the skill may use`（Experimental，支持度因实现而异）。语义是授权面：写进去的默认放行，没写的由宿主决定；不拦任何东西。判据：只写最小集、不能当权限控制、不能假设对方一定按它约束。

### 2. `compatibility` 是例外字段，不是必填（可复用 Skill 层）
1–500 字符，声明目标产品/系统包/网络访问；原文明确「Most skills do not need the compatibility field」。判据：只在「不写就会有人装完跑不起来」时才写；每份都抄「兼容所有环境」= 把契约稀释成噪音。

### 3. `metadata` 键名要避开通用词（工具层）
任意 string→string 映射，官方建议键名相对唯一防冲突。判据：`version`/`author` 这类通用键在多来源合流时最易互相覆盖，要么加前缀、要么把版本信息放规范字段与索引。

### 4. `skills-ref validate ./my-skill` 当交付门（工具/工作流层）
机检 frontmatter 合法性与命名规范：name 必须与父目录同名、只小写/数字/连字符、不得首尾连字符、不得连续 `--`、≤64；description ≤1024。判据：通读只能确认「我看得懂」，校验器确认「机器装得上」；name 与目录名不一致是人眼最难发现的静默失效。
