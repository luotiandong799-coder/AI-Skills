## 二、核心方法与关键事实（带来源，可内化）

1. **评估层级对齐执行结构**：Runs（单步决策）/Traces（完整 turn：final response+trajectory+state changes）/Threads（多 turn：semantic intent+outcome+trajectory）三级各测各的；约一半测试用例是单步（快便宜定向）；N-1 testing 用生产前缀只测最后一 turn。（LangChain Agent Evals 2026-06-23）
2. **Trajectory 评估别僵化**：别断言特定工具调用顺序——agent 常走合法非预期路径；评分 outcome+决策质量允许部分 credit；严格有序匹配只留安全/正确性必要场景。（LangChain）
3. **LLM-as-judge 五纪律**：judge≠生成模型（self-preference bias）、judge 只看可见响应不看隐藏 reasoning、rubric 围绕可观察证据（"cites the 14-day window" 是 rubric" sounds helpful" 不是）、单判据 rubric 比复合可靠、校准集（clear passes/failures/borderline）人类先打 judge 对照+非完美分 worked example 防默认高分+reason-then-score。（Anthropic Platform Docs + OpenRouter + AWS Bedrock）
4. **golden dataset 四桶配比**：Happy path 40%（应近 100%）/Edge 30%（模糊+边界）/Adversarial 15%（注入+幻觉+应拒）+Regression 15%（生产 bug 永久锁定）；case 结构含 expected_behavior/required_tools/forbidden_behaviors；known-correct=领域专家签过；每个严重生产失败成为永久 test case；规模 focused 150-300/multi-step 300-600。（Amir + Zalt + CallSphere）
5. **capability 与 regression 两套评估分开**：capability 从低 pass rate 爬 hill、regression 应近 100% 下降=坏了；能力达标后毕业进 regression suite。（AWS LangSmith 2026-05-28）
6. **Agent-as-a-Judge 分层评测**：确定性→结构化 LLM→主动取证 Agent→多 Judge 仲裁→人工；第零层可观测性（无 Trace ID/Artifact Store/工具调用记录，Judge 无法取证）；第六层 Meta-Evaluation（Judge 也是生产模型要回归测试）；竞争点从 Judge 模型大小转向评测系统设计。（CSDN 2026-10-13）
7. **评测→生产闭环六阶段**：instrument→trace→dataset→evaluator→score→CI gate；先建 dataset（"everything else is plumbing around that asset"）；最小回归门三件套（golden dataset+experiment+threshold 抛 RegressionError）；采样 10% 成功+100% 失败；漂移检测每周 200 生产 case 同 rubric 与 CI baseline 差 >5 分=数据集需新例子；优化最差切片非平均分。（CallSphere + Langfuse + Zalt）
8. **rubric 六原则**（Outcomes grader）：每判据可检查/让 grader 挣得通过（要 concrete evidence）/描述 goal 不描述 steps/预判 writer shortcuts/强制反馈格式/告诉 grader 忽略什么——grader 与 writer 独立 context，看不到 writer reasoning。（Claude Cookbook 2026-05-03）
9. **生产可观测性四指标+四轴分工**：token usage/latency/tool error rate/task success rate；trace 答时间去哪/metrics 答是否正常/logs 答发生了什么/append-only event store 答能否重建 run（override 也记事件，唯一真相源）；span 七属性 run_id/task_id/agent.role/model.name/tool.name/gate.result/artifact.path 连审计；被拦截的调用也要记（blocked unsafe call 是安全信号）。（Make + HOTL Week 12）
10. **SkillSpector 评分契约与 CI gate**：exit code 0/1/2 稳定契约；policy 只允许 SAFE 时查 recommendation 字段；baseline suppression 让 rescan 只显新问题；71 patterns 含 MCP tool poisoning 语义层。（NVIDIA v2.12.0 + x-cmd + andrew.ooo）
