## 三、三点（各附提升层）

1. **文档共创的顺序纪律**（dw）：先立"全章节标题 + `[待写]` 占位"骨架；从**未知最多**的章节先写（决策文档=核心提案、规格=技术路线），**摘要留最后**；每节六步（5–10 澄清问 → 5–20 候选 → keep/remove/combine **并要一句理由**（理由用于学优先级）→ 缺口检查 → 起草 → 精准替换）；编辑只做局部替换不重打全文；**连续 3 轮无实质修改后才问"还能删什么"**；80% 时通读查跨节一致/重复矛盾/slop；有图必补 alt。**提升层：工作流 + 可复用 Skill**。
2. **读者测试**（dw）：交付前预测 5–10 个读者真会问的问题，**只给问题 + 正文、零上下文**交给独立会话作答；必跑三探针（哪里含糊 / 默认读者已知什么 / 有无自相矛盾）。判据：**连续答对且不再冒新缺口才算就绪**，只答对一两题不算；失败回到对应章节定点修，不整篇重写；通过后仍要作者自己终读并复核事实与链接。**提升层：工作流**。
3. **评测问题六属性**（agent-eval）：独立 / 只读 / 复杂多步 / 真实 / **可验证（唯一答案、可字符串比对）** / 稳定（答案不随时间漂移）；判据：**没被自己解过的题不算题**——无解题、多解题、藏在一次查询之外的题，会把"题烂"记成"能力差"。**提升层：工作流（评测集构造）**。
