## 独点（10）

**1. 编排层级与事件驱动 choreography 六件套**（来源：arXiv 2606.20058《Autonomous Event-Driven Multi-Agent Orchestration》2026 + Zylos《Graph-Based Agent Workflow Orchestration》2026-04-14 + FutureAGI《Five Named Shapes》2026-05-20 + Dokki《Orchestration State and Human Control》2026-07-21 + VikasGoyal《Agentic AI Report》2026-04-01 实拉）：**编排收敛=结构化编排模式替代自由式 prompt 循环（LLM 推理跑在确定性执行图内：显式状态/重试/交接）；编排层级=控制面（谁决定下一步）与执行面（谁干活）比例要健康，LLM 推理在确定性图内；事件驱动 orchestration=Task Manager 两能力：相关事件合并成统一任务（跨事件上下文）+优先级抢占；事件驱动 choreography（无中央规划者）=松耦合独立扩展但端到端状态难 debug，六件套=correlation ID+事件 schema+幂等消费者+重放控制+死信处理+process view 从事件重建完整任务；DAG Plan&Execute=planner 前置生成 DAG 执行图+executor 分发+replanner 条件变化自适应（规划与执行分离，并行 agent 调用+系统化故障恢复；agent discovery 两阶段借鉴 Anthropic Skills）；生产多混合=graph/supervisor 外层+ReAct 循环在叶层**。提升层：可复用 Skill。

**2. 框架选型实证矩阵**（来源：JATIR《Benchmarking Multi-Agent Frameworks》2026 + the-agent-report《Framework Landscape Mid-2026》2026-07-23 + the-agent-report《Benchmark 2026》2026-07-04 + N-iX《Full comparison》2026-09-01 + aiworkflowlab《LangGraph vs CrewAI vs AutoGen》2026-07-14 实拉）：**LangGraph=State Graph（有向图：节点 Python 函数或 LLM agent+条件边路由+checkpoint 每步快照按 thread 组织=容错恢复+会话记忆），34.5M 月下载/400+ 平台企业（Klarna/Elastic/Cisco/Uber/LinkedIn/BlackRock/JPM）——企业/数据密集/安全关键首选；CrewAI=角色制团队（44.6K stars，任务定义+角色目标）——内容生成/速度团队首选；AutoGen/AG2=维护模式无新功能，微软推荐迁移 Agent Framework（MAF 1.0）；基准延迟=Hermes 0.7s p50/0.5% timeout 最优 vs LangGraph 0.8s/1.2% vs CrewAI 1.4s/3.8% vs AutoGen 1.1s/2.1%；心智模型三型=有向图 vs 角色团队 vs 群对话；token 效率=LangGraph 高/CrewAI 中/AutoGen 低；human-in-loop=LangGraph interrupt 节点/AG2 原生任何参与者**。提升层：工具。

**3. Agent 生命周期管理（ALM）与 loop 三硬停**（来源：IBM《Agent Lifecycle Management》2026-06-23 + 阿里云《AgentLoop》2026-08-27 + Differentiated《Loop/Harness Engineering》2026-06-28 + agent-cookbook《14-step Roadmap》2026-07-06 + Viblo《Three Hard Stops》2026-06-25 实拉）：**ALM 监测清单=输入输出/对话迹/工具调用与响应/延迟吞吐/错误率失败类型/token 成本/任务成功率/用户反馈/策略违规/幻觉与接地指标/升级审批率/安全事件异常访问（监测退化即干预）；AgentLoop 渐进路径=可观测性（五分钟观测基线）→迹转资产（pipeline 自动转结构化数据集+标注建 ground truth）→评估体系（在线实时质量评估+数据集实验回测基准线）→持续优化闭环（记忆库经验库数据飞轮）；loop 六部分=trigger/workspace/durable state/tooling and context surfaces/verification/exit controls（plan→act with tools→run checks→inspect→repair→persist→repeat until verifiable condition）；**三硬停=最大迭代数上限（全停）/无进展检测（N 轮无可测变化即停）/token 或美元预算硬顶**；一 skill（项目上下文 SKILL.md）+一 state 文件（markdown/Linear 记 done/next，明天续跑非重启）+一 gate（test/type...）**。提升层：工作流。

**4. 编排反模式清单**（来源：Microsoft Learn《Agent Design Patterns》2026-02-13 + INOVAWAY《MCP/A2A 6 Anti-Patterns》2026-03-26 + llm4agents《Four Canonical Patterns》2026-05-29 + Microsoft《Stop Letting Agents Run the Workflow》2026-09-01 + NASSCOM《Failure Playbook 2026》2026-06-23 + lobehub《multi-agent-orchestration》2026-09-23 实拉）：**五坑=复杂模式用于简单任务（顺序/并发够用就不上复杂编排）/无意义特化 agent/忽视多跳通信延迟/并发 agent 共享可变状态（事务不一致）/确定性模式用于天然非确定性工作流；协调税=2 agent 1 连接/3 agent 3/5 agent 10——每个额外 agent 乘复杂度非加价值；公平幻觉=每个 agent 都要 planning → 全得上最贵模型（付六倍 frontier 价）；盲聚合=supervisor 拼接 worker 输出不综合（委员会散文：内部矛盾/重复），修正=显式综合步骤（supervisor 对 worker 输出推理）；Microsoft 四修正=确定性工作流+agent 只在显式边界内行动/窄职责最小上下文最小权限一个类型化契约/审批做成不可绕过的 transition guard（不靠"模型该知道何时请求批准"）/工具调用当受控业务操作（schema+幂等+策略检查）；预算 15x=per-agent 成本不含协调开销/重试/共识轮**。提升层：可复用 Skill。

**5. 单 vs 多 agent 量化决策框架**（来源：theaiagentindex《Multi-agent orchestration》2026-07-01 + AIPromptsHub《When to Fan Out》2026-06-21 + GrowthEngineer《6-Question Decision Framework》2026-05-04 + MindStudio《Decision Framework》2026-07-12 + Stanford CS224G Lecture 7 实拉）：**默认单 agent（多 agent 加复杂度/成本/失败面，只在遇到具体限制时加，非预期限制）；两个正当理由=真并行（独立子任务并行减墙钟）+上下文隔离（每 agent 干净上下文避免长累积 token 与质量下降）；协调开销=编排消息与摘要额外 10-30% token；实证=单 agent ~4x chat token、多 agent ~15x（Anthropic）、40%+ 多 agent 试点 6 个月内失败；6 问框架=并行需求/上下文压力/角色特化/可靠性预算/可观测性成熟度/运维成本，≥4 答 yes 才多 agent；三域以上才拆（跨域专业 agent 专属上下文优于单体争窗口）；斯坦福对比=上下文分区/模块化提示/严格图工作流/更高延迟（agent 间调用）/复杂编排**。提升层：可复用 Skill。

**6. 生产级可观测性四能力与 span 图谱**（来源：Microsoft Foundry《From Observability to ROI》2026-06-03 + Alice Labs《Agent Observability Guide 2026》2026-08-03 + FutureAGI《Agent Observability》2026-07-05 + Maxim《Buyer's Guide》2026-04-27 + MLflow《Top 5 Tools》2026-09-30 + AWS《OpenSearch Agent Health》2026-09-01 实拉）：**四能力=Trace（端到端每步 telemetry：prompt/model call/tool invocation/sub-agent hop）/Evaluate（单轮+多轮粒度质量安全任务完成评分）/Monitor（实时告警）/Optimize（生产信号转排名证据支持的改进）；迹后三能力=框架生态灵活性/迹后动作（评测绑定）/成本控制；2026 生产 run 20-100 spans+多 MCP server+A2A 交接，唯一可 debug=graph view 绑 eval score（flame graph 是线性请求瀑布不适用）；OpenTelemetry GenAI 语义约定+OpenInference span kinds=LLM/CHAIN/TOOL/RETRIEVER/EMBEDDING/AGENT；OpenSearch Agent Health=目的构建 agent 迹分析+评估（连 OTel 数据）；failproof=pre-tool/post-tool/stop 钩子+失败聚类命名模式+策略阻止坏动作落地**。提升层：工具。

**7. 企业成本治理与 token chaos**（来源：CallITDev《AI Agent FinOps》2026-09-22 + Tentoro《Orchestration Without Token Chaos》2026-06-30 + MaximusLabs《Tiered Routing Cost》2026-07-29 + adamarant《12 Mistakes》2026-05-23 + Trantor《AELA CIO Guide》2026-05-04 + McKinsey《Economics of Agentic Workflows》2026 实拉）：**token 账非线性=orchestrator 分解分发付三份（orchestrator token+每个专家 token+agent 间消息也过 LLM），naive 多 agent 同结果 5-10x 单 agent token；MCP 工具元数据开销=多 server 30,000+ token 消失于工具描述，极端 82,000/200,000（41% 上下文全花工具描述——选型工具面就是上下文预算）；per-agent 成本归属=tag agent ID/task ID/tenant ID 推同一 dashboard（否则无人能答"agent 是否付得起自己账单"）；集成工程低估 30-50%（认证层/schema 映射/错误处理/每边界测试）；分层路由降本=frontier-only $18.40/M→混合平均 $6.07→全分层路由 $2.31/M（-87.4%）；治理内置架构=审计迹核心功能成本一小部分、访问控制在编排层定义=十分之一工程（retrofit 贵 10x+）**。提升层：工作流。

**8. 多 agent 评测基准**（来源：arXiv 2609.31590《AgentWorld》2026-09-28 + arXiv 2609.24662《DUMA-Bench》2026 + ACL《Agentic CLEAR》2026 + ACM《Catalogue of Evaluation Metrics》2026-05-21 + SemanticScholar《PolyWorkBench》2026-07-07 实拉）：**AgentWorld=长周期多 agent 协作基准（100 人工标注任务+100 增强变体，MMORPG 沙盒，平均 50+ 轮交互，3-20 agent 角色能力各异——测协作非聚合个体，现有基准缺陷=竞争设置/20 步内短地平线/只聚合个体表现）；DUMA-Bench=双控多 agent 安全基准（agent 与用户都影响共享环境态，8 安全域 35 可执行任务非纯 prompt 项）；Agentic CLEAR=自动多级评估（curated traces HAL 50，SWE-bench mini+TAU-bench airline）；MOASEI 2026=任务中心指标（总任务完成/平均完成时间/完成价值优先于域奖励）；软件工程多 agent 指标目录（outcome=completeness 无占位符/executability 编译可运行/人视角 failure-flawless 评分）；PolyWorkBench=多语言长周期工作流（结构评分+可执行验证+LLM 语义评估混合）**。提升层：工具。

**9. 工作流平台编排实证（n8n/Dify/Make）**（来源：AYAutomate《n8n vs Dify》2026-04-29 + n8n Blog《Introducing n8n Agents》2026-09-25 + n8n Blog《15 Best Practices》2026-01-08 + Dify《Agent Node Best Practices》2026-08-27 + Christopher Alarcon《n8n AI Agent Tutorial》2026-06-14 实拉）：**组合最强生产= n8n 触发与路由（RSS/ticket/CSV→API 调用→post 处理→动作）+Dify 推理与 RAG（LLM-first 应用：chatbot/agent/RAG）；n8n agent 设计=窄工具（一工具一职责：取账户上下文/加备注/Page on-call）+boring reliability（"it works and it's boring"最高赞誉）；n8n 15 实践核心=dev/staging/prod 三环境（staging 镜像 prod 配置+测试账号+同 queue worker+真实负载模式测试后才 promote）；Dify agent 节点最佳实践=清晰工具描述（agent 何时用何工具）/合理迭代限制（防 runaway 成本）/详细指令（角色目标约束偏好）/记忆管理平衡上下文与 token；edge case 测试清单=空数据集/缺字段/意外类型/超大数据集；修复环=收紧 prompt+加正确输出示例+收窄工具范围**。提升层：工作流。

**10. Durable orchestration 与显式协调规则**（来源：Microsoft Learn《Durable Extension》2026-08-31 + TrueFoundry《LangGraph Checkpointing》2026-06-16 + Zylos《Hierarchical Multi-Agent Discipline》2026-04-14 + Ciphernutz《State Machine Comparison》2026-07-23 + DEV《State Machines Planning Loops》2026-09-20 实拉）：**Durable agents=Agent Framework 编程模型+Durable Task 基础设施（跨请求自动持久化状态/失败恢复不丢上下文不重做/分布式无状态 worker 按需扩展/checkpoint graph workflow/暂停等人工输入或外部事件不耗算力）；LangGraph checkpoint 按 thread 保存每步快照=容错恢复+会话记忆；分层 supervisor=3-8 专家 worker 关键纪律：worker 窄工具集窄 prompt+**协调规则显式写**（谁可写共享内存/每个 agent 访问哪些工具/停止条件/升级触发）而非从 prompt 涌现（无显式规则失败看似随机实为未定义多 agent 契约）；动态 agentic loop vs 静态编排按任务不确定性=plan-execute-observe-replan（开放研究/编码）vs decide-act-observe-decide（反应式）vs 固定流水线（确定性业务）**。提升层：可复用 Skill。
