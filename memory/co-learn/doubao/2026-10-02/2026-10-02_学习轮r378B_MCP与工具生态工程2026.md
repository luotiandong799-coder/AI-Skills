## 独点（10）

**1. MCP 2026-07-28 规范重大修订：stateless core**（来源：MCP 官方博客《2026-07-28 Release Candidate》2026-05-21 + MCP 官方博客《2026-07-28 Specification》2026-07-28 + 规范 changelog + SDK beta 博客 2026-06-29 实拉）：**核心=砍掉 initialize/notifications/initialized 握手，每个请求在 _meta 自描述（protocolVersion+client capabilities，io.modelcontextprotocol/protocolVersion）；能力来自 server/discover；无状态=远程 server 可像普通 Web 服务部署 Serverless/边缘节点，round-robin 负载均衡无需 sticky session；显式句柄替代隐式会话=需记忆状态时服务器返回 handle，模型后续显式传递（状态对模型可见，消除黑盒会话）；扩展框架=任意服务器处理（extensions），Tasks 从实验核心移入 io.modelcontextprotocol/tasks 扩展（poll-based tasks/get+新 tasks/update，SEP-2663）；MCP Apps（SEP-1865）=服务器交付沙箱 iframe 内渲染的交互 HTML 界面，工具声明 UI 模板供 host 预取/缓存/安全审查，UI 动作走同一 JSON-RPC 与审计路径；MRTR（SEP-2322）=工具可返回 InputRequiredResult 中途向用户提问；授权加固+正式弃用策略**。提升层：工具/工作流。

**2. MCP 三原语精确契约**（来源：MCP 官方《Architecture overview》+ Microsoft《mcp-for-beginners》2026-09-10 + AI/TLDR《Three Primitives》2026-06-12 + aiturnpoint《Access-Control Architecture》2026-05-25 实拉）：**Tools=可执行函数（模型发起动作：文件操作/API 调用/DB 查询），controlled by=application（host 授权模型调用），可副作用；Resources=模型可读的数据源（文件内容/DB 记录/API 响应），controlled by=application，经 resources/read 调用，只读无副作用、可缓存，用 URI+MIME type+可选 template 定义，返回 text 或 binary；Prompts=用户选用的可复用模板（系统提示/few-shot/带参工作流），controlled by=user，经 prompts/get，只读可缓存，返回 PromptMessage 序列；判据=每个原语先问「谁控制发起」——模型=Tools、应用=Resources、用户=Prompts；Prompts 是生产 server 中最少实现的原语，却是免硬编码重复多步工作流的正确接口（如 code-review 带 file path 参数/summarize-pr 拉取 PR 数据）**。提升层：可复用 Skill（MCP 开发接口设计）。

**3. MCP 上下文税与渐进披露四方案**（来源：Kognita《Tool Definitions Eating 26% of Context》2026-05-16 + NiteAgent《Cut Context Consumption by 98%》2026-05-29 + MCP.Directory《Context Bloat Fixes》2026-05-01 + Gurubase《Hidden Token Cost》2026-05-13 + InfoQ《Cloudflare Code Mode》2026-04-16 + Focused《Stop Eager-Loading》2026-05-05 实拉，与 r377A「MCP 元数据开销 41%」判重：一句事实已落，本点补治理方案）：**上下文税=工具定义在 agent 处理任何消息前已烧 55,000+ token（单个 Playwright 快照 56KB/200K 窗口，20 个 GitHub issue 59KB）；四方案=①Tool Search 工具（Anthropic GA 2026-02）：把工具发现本身暴露为工具，主线程只驻留相关工具——77K→8.7K tokens（-85% 保留 95% 上下文）；②registry meta-tool：不预载全部 schema，暴露单一注册表工具按需查询当前任务所需工具 schema；③渐进披露/惰性加载（Focused）：按意图惰性加载工具再治理审计执行；④Code Mode（Cloudflare 2026-02-20）：用代码代写 API 端点——2500+ API 端点 1.17M tokens→~1,000 tokens（-99.9% 固定开销与 API 面大小无关）；反模式=全局配置挂一堆未用 server**。提升层：工具/工作流。

**4. MCP 计算服务端化与 server 审计**（来源：MindStudio《10 MCP Optimization》2026-04-29 + Unblocked《Tool Overload》2026-05-16 + Codex《Schema Bloat》2026-09-25 实拉）：**反模式=server 返回大数据集、agent 在上下文里排序/过滤/聚合——为数据集每个 token 付费；正模式=在 MCP server 内暴露聚合工具（server 端做排序/过滤/聚合再返回结果），模型只付结果 token；实测=三个 MCP server 烧 14%（上下文）就明显降回答质量且像模型退化（其实是工具过载）；最高性价比优化=审计并禁用未用 server（工具 schema 是系统提示税，每多一个 server 都在吃预算）；工具面上限=Claude Desktop 实际 3-5、Cursor 40 工具上限（超出静默丢弃）、VS Code 5-8 server 推荐**。提升层：工具/工作流。

**5. **6. MCP 安全：OWASP 沙箱与审批检查点**（来源：OWASP《MCP Security Cheat Sheet》2026-10-01 + MCP 官方《Security Best Practices》+《Secure MCP Server Development v1.0》2026-02 + Top-MCPs《Security》2026-05-26 + Google《Secure Agent Interactions》2026-07-17 + DZone《Hallucinated Privilege》2026-05-06 实拉，与 r376B「工具面四威胁」判重：威胁已落，本点补防护部署）：**沙箱隔离=本地 server 跑容器/chroot/应用沙箱，rootless 模式+只读根文件系统+最小 base image，firejail/seccomp 过滤；限制文件系统访问到所需目录、默认禁网络；stdio 传输=server 只能访问 MCP client（本地 server 用 stdio 天然缩小攻击面）；敏感 server（支付/认证/PII）与通用 server 分离部署；高风险动作（删数据/转钱/系统级变更）设审批检查点=暂停并要求人类显式确认（MCP elicitations）；LLM-as-a-Judge=高风险动作用独立上下文 LLM 会话+策略 prompt 审批（定义允许/禁止的调用与参数）；hallucinated privilege=agent 默认只读（IAM 角色/DB 用户字面不能 INSERT/UPDATE/DELETE，LLM 再努力也做不到）；注入扫描=工具输出视为不可信，重回上下文前扫嵌入指令**。提升层：工具/工作流。

**7. MCP 认证三阶段与实测安全测量**（来源：arXiv 2605.22333《Authentication Security in Real-World Remote MCP Servers》+ MarkTechPost《Best Auth Platforms 2026》2026-05-25 + MCP 官方《OAuth Client Credentials》+《Authorization tutorial》+ IETF《MCP DID Framework》实拉）：**远程 MCP OAuth 工作流三阶段=P1 Discovery & Registration、P2 Authorization、P3 Token Exchange + 可选委托阶段 PA（68.07% 的 119-server 子集出现）——多数缺陷=这些阶段间的 broken binding（client identity↔callback endpoint 绑定断裂等）；规范要求=OAuth 2.1+PKCE（实现授权时必需）、全端点 HTTPS、authorization server metadata 可发现（RFC8414）、Protected Resource Metadata（RFC 9728）暴露、Resource Indicators（RFC 8707）校验防 token audience confusion；DCR（动态客户端注册 RFC7591）非普适硬要求；Client Credentials 扩展=机器对机器认证（client ID+secret 或签名 JWT assertion，无需浏览器重定向）；桌面/CLI 客户端 DCR 时设 application_type 防 localhost 回调被拒；DID 作 client identity=JWT iss 设 DID 免预注册共享密钥**。提升层：工具。

**8. MCP 服务器测试五桶**（来源：Codex《MCP Server Testing Frameworks》2026-09-25 + ChatForest《pytest-mcp Cookbook》2026-03-29 + Microsoft《Mock STDIO Responses》2026-09-23 + Apigene《Test MCP Servers》2026-04-12 + NiteAgent《Testing in CI/CD》2026-06-09 + FastMCP《Tests》2026-09-17 实拉）：**五桶=①单元测试：server 是普通 Python/TS 对象，直接 mock 依赖（AsyncMock 换 weather_api，不经过传输层测 handler 逻辑）；②集成测试：真实 JSON-RPC over curl（HTTP）或原始 stdin（stdio）打真实 server；③协议一致性（conformance）：MCP Inspector（npx @modelcontextprotocol/inspector）官方交互工具=显示发现工具与 schema、手动调用、支持 stdio/SSE；CI 用 headless 模式做协议校验；④断言与指标：pytest-mcp 插件提供 tool_was_called()/tool_arguments_match()/cost_under()；⑤模拟上游：Dev Proxy MockStdioResponsePlugin 拦截 stdin 返回 mock 响应、Apidog mock server 模拟上游 API 保测试确定性；认证测试=FastMCP Client 带 BearerAuth 验证受保护工具拒绝无效 token**。提升层：工具/可复用 Skill。

**9. MCP 可观测性与调试**（来源：MCP 官方《Debugging》+ Stainless《Real-Time MCP Monitoring》2026-08-31 + TheNeuralBase《Observability and Logging》2026-04-23 + DEV《Trace Every Tool Call》2026-09-24 + Alibaba《End-to-end Tracing based on MCP》2026-06-22 + AWS《AgentCore gateway logging》2026-08-25 + LobeHub《MCP Observability System》2026-08-31 实拉）：**官方日志位置=macOS ~/Library/Logs/Claude/mcp*.log、Windows %APPDATA%\Claude\logs（tail -f mcp*.log）；结构化日志=每条含 timestamp+message type（tools/call）+tool name+arguments+result/error；生产日志级别=INFO 非 DEBUG（防无界日志）；新版规范=logging/setLevel 操作退役，改 _meta 内 modelcontextprotocol/logLevel 字段，server 按级别发 notifications/message；跟踪=OTel/ARMS 全链路（LangChain agent+SLS MCP server 自动收集），AWS 加 Mcp-Method 头标记方法；实践=无需厂商，一下午可加 structured logs+JSON formatter；开源=MCP Observability System（实时事件日志+WebSocket 广播+dashboard，exporter 支持 n8n webhook/LangSmith/Obsidian）**。提升层：工具/工作流。

**10. MCP 工具 schema 设计纪律**（来源：AWS《MCP strategies: Tool definitions》2026-09-30 + AWS《DESIGN_GUIDELINES》2026-08-25 + SEP-2106《JSON Schema 2020-12》2026-01-06 + arXiv 2603.13417《Design Patterns for Deploying MCP》+ mcp-framework《Tools Overview》实拉，与 r377C「工具描述 when_to_use」判重：描述内容已落，本点补 schema 与契约纪律）：**每个工具四字段齐备=name/description/inputSchema/outputSchema；Python 用 Pydantic 模型=字段描述内联文档化+自动类型校验+枚举约束（Literal 固定值集、Field ge/le/min_length/max_length）——schema 自文档化提升 LLM 对合法参数的理解；描述当提示写=指导 LLM 决策；outputSchema（2026-07-28 新）=host 可产精确返回类型（如 LogEntry），structuredContent 可任意 JSON 值（不再限对象）；实现不得自动解引用外部 $ref URI、应限 schema 深度与校验时间；副作用显式声明=read-only vs write+幂等保证（「Read-only. Idempotent. Safe to retry.」）；必填参数用 ... 默认值标注、可选参数给合理默认并标 Optional；判据=模糊或不诚实的描述=坏工具（agent 找不到、调错、信了 handler 不兑现的承诺）**。提升层：可复用 Skill（MCP 工具开发契约）。
