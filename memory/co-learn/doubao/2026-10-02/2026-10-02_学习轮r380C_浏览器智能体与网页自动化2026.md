## 独点（10）

**1. 浏览器 Agent 感知三架构**（来源：Sciencx《Three Architectures》2026-05-05 + BestAIWeb《DOM vs Screenshots》2026-05-16 + dev.to《Browser-use 100k》2026-09-20 + arXiv 2410.05243《Universal Visual Grounding》2026 实拉，与 r367B 判重：QA 看界面已落，本点补 agent 感知选型增量）：**三种感知=accessibility tree（a11y 树：角色/名称/值/状态，紧凑语义快、抗视觉重绘、无 per-site selector；但 DOM 撒谎时失效——富文本编辑器/shadow DOM/无 ARIA 自定义控件）+截图视觉（坐标点击，处理 DOM/a11y 不可靠页但 token 贵）+hybrid（一通道失败换另一通道）；Browser-use 用 Set-of-Mark（SoM）视觉 grounding=注入 JS 取每个可交互候选的 bounding box→画带数字徽标的彩色框 [1][2][15]→截标注状态图；UC Berkeley/Michigan A11y-CUA=从 a11y 树学习通用 GUI grounding**。提升层：工具/可复用 Skill。

**2. Playwright MCP 五阶段 + accessibility snapshot**（来源：AI Agents Kit《Playwright MCP》2026-09-22 + Playwright docs + sdet.qa《Self-Operating QA》2026-08-14 + anhtu《Playwright 2026》2026-04-20 实拉）：**Playwright MCP=开源 MCP server 把浏览器自动化方法暴露为 AI 可调工具（Chromium/Firefox/WebKit，免手写 selector）；通信五阶段=AI 客户端发意图→MCP 解析→确定性浏览器交互→快照回传→AI 推理下一步；用结构化 accessibility snapshot 而非截图——agent 行动 token 轻/确定性/基于角色而非像素猜测；agent loop=读页面状态→选工具→行动→读新状态→循环至任务满足；支持 --max-tabs 并发上限与 --caps 能力边界（防 runaway）；npx @playwright/mcp@latest 即可装**。提升层：工具。

**3. 表单/验证码/登录自动化纪律**（来源：CapSolver《Login Blocked Fix》2026-06-16 + captchaai《Form Submission》2026-05-02 + dev.to《Claude+Playwright CAPTCHA》2026-06-08 + Browserless《Web Agents》2026-07-30 实拉）：**验证码 token 仅 ~120 秒有效——最后一步解+立即提交（不提前解）；用显式等待（WebDriverWait）不用固定 sleep（动态加载字段）；登录=保留 session 状态（cookies/localStorage/设备标识/CSRF 字段/路由上下文，RFC 6265）——会话连续性始于第一个字段之前；架构=Claude 决策层+Playwright 执行层（agent 看页面快照自己决定下一步，适应新拦截模式不需改代码）；账号所有权/状态不明时暂停不猜；CAPTCHA 在 agent 正驱动的会话内解（agent 不能中途切出去找独立 solver 而丢位置）；in-session solveCaptchas=true；重试 2-3 次仍失败→诚实停止交人工；solver API=检测 DOM→提参→API→注入 token 回页面**。提升层：工作流。

**4. 恢复分类学：显式分类恢复不盲目重试**（来源：surfs.dev《Deterministic Browser Agents》2026-06-02 + arXiv 2607.24167《FCPAgent》2026-08-29 + arXiv 2504.11788《WebRollback》+ Yunque《Recovery Protocol》2026 实拉）：**七类恢复=stale target（DOM 重渲染失效句柄：detached element 错误）/occluded target（被遮）/unexpected modal（意外弹窗）/navigation divergence（导航偏离）/partial form failure（部分表单失败）/anti-bot challenge（反爬挑战）/no-effect action（无效果动作）——按类定恢复策略不是"retry 3 次"；FCPAgent plan-test-repair=动作执行前轻证据匹配+LLM 诊断验证混合，证伪后按 scope 定位到执行/技能/规划层修最小部分（WebArena +13.8%）；WebRollback=显式回滚机制回退到轨迹上一状态（贪心单向搜索难恢复错误态）；Yunque 三阶段恢复=异常诊断（分析执行历史找根因）→轨迹剪枝（从上下文剪掉无效交互痕迹防污染后续决策）→再生成（备选输出）；错误注入自纠正=把"System Error: Action had no visible effect"作为 user 消息注入对话让 VLM 上下文学习调整（不显式 replan）**。提升层：工作流/可复用 Skill。

**5. 浏览器 Agent 评测基准**（来源：Steel.dev《WebArena Leaderboard》2026-09-30 + anhtu《Benchmarks 2026》2026-05-18 + Awesome Agents《Leaderboard》2026-04-17 + baeseokjae《Exploiting Benchmarks》2026-07-19 实拉）：**WebArena=812 任务全模拟环境（电商/论坛/CMS/GitLab 克隆）真实浏览器操作，人类基线 78%；2024 首 agent 14%→2026-06 领跑 WebTactix 74.3%（OpAgent 71.6）逼近人类；动态 eval 比静态多项选择难作弊得多但可作弊——BenchJack 自动化管线 3 轮内把 WebArena 几乎全部可 hack 任务补掉；OSWorld 测真实电脑任务（Anthropic Sonnet 4.5 61.4% vs 4 个月前 42.2%）；读法=浏览器基准各测不同面（任务复杂度/站点多样性/视觉 vs 文本/歧义容忍），没有单一数字讲全故事；同一模型栈下框架差距小（Pipecat vs LiveKit 0.7pt）而换模型栈差距巨大（28pt）——模型选择 > 框架选择**。提升层：工作流。

**6. 浏览器 Agent 安全：间接注入是第一威胁**（来源：CSA《PleaseFix》2026-03-28 + selina《Incognito Lie》2026-07-13 + praesidia《Securing》2026-07-17 + SystemsHardening《Injection Defence》2026-05-08 实拉，与 r368D/370D 判重：注入纵深已落，本点补浏览器特化增量）：**浏览器 agent=最大不可信输入（每页都可攻击者控制）×最大权限（认证会话）——结构性信任失败；PleaseFix=零点击浏览器 agent 劫持（无需用户点击/无恶意代码/无社工，只要 agent 处理恶意内容）；隔离 profile=无持久凭证/无保存密码/无用户真实会话 cookie，ephemeral 隔离 profile 把爆炸半径限制到当前任务凭证范围；DOM 是注入面=隐藏文本/ARIA 标签/alt 属性/屏幕外元素都到达模型（白字隐藏指令/零宽字符/图片元数据/HTML 注释）；防御=domain allow-list+状态变更动作 gating（工具调用层阻断恶意导航，比内容过滤有效）+策略否决（veto 型外部策略状态，注入指令不拥有策略状态）；incognito 对 agentic browser 是谎言（继承认证会话）；LLM 无法可靠区分指令与数据（同为文本到达）——结构性防御优先**。提升层：可复用 Skill。

**7. 开源栈对比：determinism vs autonomy 决策轴**（来源：dreaming.press《Browser Use vs Stagehand vs Playwright MCP》2026-07-23 + AgDex《Compare by Architecture》2026-08-01 + Stagehand docs + CalBot《Alternatives》2026-07-24 实拉）：**Browser-use=Python 自主 web agent（多 tab 导航/多步推理/视觉 bounding-box 反馈环），100k+ stars；Stagehand=Browserbase 的 MIT SDK（TypeScript 优先，act()/extract()/observe() 自愈动作+Zod 结构化提取+网络级安全，CDP 直驱无 Playwright 依赖），给"脚本的确定性+agent 的灵活性"；Playwright MCP=TS server 角色（结构化 a11y 快照免视觉模型）；决策轴=信任模型多少自由发挥——任务会重复跑选确定性（脚本优先），探索性任务选自主；Browser-use Cloud=托管（代理轮换/stealth/CAPTCHA/并行），开源版=自定义工具/代码级集成/自托管；Skyvern=内置凭证库/2FA/CAPTCHA 视觉免 DOM selector（$149 Pro）；Steel=Browserbase 开源替代（6400 stars 可自托管 $29/290 浏览器小时）**。提升层：工具。

**8. 结构化提取：schema 保证语法不保证数值**（来源：Firecrawl《Extraction Tools》2026-09-07 + Context.dev《Extraction APIs》2026-06-27 + arXiv 2606.14821《Co-Scraper》+ arXiv 2602.15189《ScrapeGraphAI-100k》+ Apify《SmartSchema》2026-06-08 实拉）：**grammar-constrained 采样保证输出可解析但不保证值对（BAML 实录：gpt-5.2 对 0.46kg 行返回 quantity=1，schema 合法但事实错）；WebLists 基准=SOTA web agent 结构化提取 recall 31% vs CSS selector 记录-回放 66%——大规模提取用程序化循环不是 LLM agent（agent 输出几 K token 上限）；Pydantic 验证失败→重试一次→再失败记 URL 跳过不写坏数据；token 级 schema 约束=JSON 错误率 0 vs 提示式 12-15%（Apify 实测）；Co-Scraper=查询感知 DOM 剪枝+可复用 wrapper 合成（Qwen3-8B 微调，SWDE F1 94.78% 复用 90.39%）；ScrapeGraphAI-100k=每事件扁平化（URL+schema+Markdown+响应）+jsonschema-rs 校验（原始语料平均有效 93%，无效保留 response_is_valid=false 供研究失败模式）**。提升层：工作流/可复用 Skill。

**9. 浏览器 Agent Token 成本治理**（来源：Tencent Cloud《Claude Skills》2026-05-20 + BrowserAct《Reduce MCP Tokens》2026-09-10 + arXiv 2511.19477《Building Browser Agents》+ arXiv 2606.15017《Budget-Constrained Study》2026 实拉）：**工具 token 单价=agent-browser 200-400/页 vs Playwright MCP 2000-6000/页（复杂 DOM）vs Playwright CLI ≈MCP 的 1/4；40 动作工作流=纯 Playwright MCP 80K-150K tokens vs MCP discover+脚本 30K-50K vs CLI-first 5K-15K（跑两次以上的任务选 CLI-first）；智能快照裁剪=轻量模型滤快照 10000→500-1000 tokens/步，主 LLM 输入减 90%——工具调用 +34%（偶发重请求）但总成本 -57%；对话历史压缩防长程上下文丢失；工具定义裁剪=40 工具注册只用 5 个/阶段×80 tokens×8 步=省 22.4K tokens/任务（-27%，叠加缓存）；预算约束研究=香草 ICL 基线在同等总推理预算下胜过在线记忆/技能模块（AWM/ASI/ReasoningBank）——增强模块的 token 开销常未被与 actor 推理成本一起报告**。提升层：工作流/可复用 Skill。

**10. 浏览器 Agent 训练与未来**（来源：arXiv 2608.24848《BrowserForge》2026-09-05 + arXiv 2602.14721《WebWorld》2026-09-01 + WebSailor-V2（ICLR2026）+ Wuying DAO-GRPO + arXiv 2609.04304《Iris》2026-09-16 + Fara-1.5 2026-06-23 实拉）：**数据=BrowserForge 用 Common Crawl 拓宽站点分布本身（规模与多样性同增，Proposer-Solver 循环+清洗管线让无监督开放网页可作训练数据）；WebWorld=首个大规模开放网页模拟器（1M+ 交互 30+ 步长程仿真）；WebSailor-V2=稠密环状知识图谱造数据+仿真/真实双环境 RL（GRPO leave-one-out 降方差），30B MoE 激活 3B 在 BrowseComp-EN 35.3 反超 671B DeepSeek-V3.1；DAO-GRPO=长程稀疏浏览器反馈下加稠密进度监督+突出行为关键决策+与执行决策上下文对齐训练；SFT-RL climbing（Iris）=每轮 RL 把最难解决+最高效 rollout 送回下一轮监督 pass 交替爬升；self-supervised 主驱动=forward dynamics（生成预测未来界面状态）远超 inverse inference（UI-Oceanus）；数据多样性=纯网页抓取产生太多平凡页面加载+太少错误恢复——Fara-1.5 60% 真站轨迹+40% 合成（表单填充/视觉 grounding/VQA/拖拽/指令遵循与安全）**。提升层：工具/工作流。
