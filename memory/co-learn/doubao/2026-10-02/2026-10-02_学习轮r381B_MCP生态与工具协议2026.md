## 独点（10）

**1. MCP 2026-07-28 规范：无状态核心+Streamable HTTP**（来源：MCP 官方 Blog《2026-07-28 Release Candidate/Specification》2026-07-28 + MCP Roadmap 2026-08-22 + Microsoft《MCP C# SDK v2.0》2026-07-28 实拉）：**启动以来最大改版=核心默认无状态（stateless），HTTP 表面标准化使普通 HTTP 基础设施可路由 MCP 流量；Multi Round-Trip Requests（MRTR）=交互式工具不再需要长活会话；server/discover 替代初始化握手（每请求自包含，旧版本用 initialization handshake）；Streamable HTTP=新实现 SHOULD NOT 用 HTTP+SSE、现有实现 SHOULD 迁移（HTTP+SSE 进弃用注册表）；正式弃用策略=协议可在不破坏既有构建的前提下演进（弃用功能注册表）；C# SDK v2.0 标志着"回到地基重新思考 MCP 在 HTTP 上如何工作"**。提升层：工具/工作流。

**2. 授权强化：iss 校验+PKCE+token audience**（来源：MCP 官方 2026-07-28 授权安全考量 + Stacklok《MCP Security Checklist》2026-03-21 + Codersera《How to Secure MCP》2026-06-30 + Practical DevSecOps《MCP OAuth 2.1》2026-05-13 实拉）：**六个 SEP 把授权对齐生产 OAuth 2.0/OIDC 部署；客户端必须校验授权响应的 iss 参数（RFC 9207，SEP-2468）——低成本缓解 MCP 单客户端多服务器模式高发的 mix-up 攻击（恶意 authorization_endpoint 在认证会话建立前拦截 token=CVE-2025-6514 类）；Dynamic Client Registration 设 application_type 让授权服务器区分；PKCE 强制（OAuth 2.1 §7.5.2）用 S256 挑战法——AI agent 是公共客户端（本地 IDE/临时容器不能安全存静态 client secret）；MUST 只接受显式为该 MCP 服务器签发的 token（RFC 8707/9068 aud 校验）；code verifier 只存内存模块作用域、token 交换后清除（localStorage/sessionStorage/cookie 持久存储=攻击者可读）；访问令牌分钟级过期非小时级；token rotation+每请求校验 signature/iss/aud/exp/scope**。提升层：可复用 Skill。

**3. MCP Tasks 扩展：异步长任务生命周期**（来源：MCP 官方《Tasks Overview》2026 + SEP-2663《Tasks Extension》2026-08-28 + tasks.extensions.modelcontextprotocol.io 2026-09-09 实拉）：**服务器对 tools/call 可回 task handle（resultType:task + 唯一 taskId + 初始状态 + ttlMs + pollIntervalMs），客户端用 tasks/get/update/cancel 驱动；任务生命周期=working→input_required（服务器需客户端输入，经 InputRequests）/completed（result 含最终输出）/failed（JSON-RPC 错误）/cancelled（不一定 honored）/unknown（意外状态回退）；任务必须 durable 创建后才回响应；客户端尊重 pollIntervalMs 轮询到终态；mid-flight 输入=tasks/input_response 带 InputResponses+Task 元数据恢复 working；statusMessage 可为任何状态提供上下文（进度/阻塞原因/取消理由/完成摘要/失败细节），可暴露给端用户或模型**。提升层：工作流/可复用 Skill。

**4. MCP Apps + Skills over MCP 扩展**（来源：MCP 官方 Extensions Overview 2026-09-18 + Skills Over MCP Working Group Charter 2026-09-28 + dev.to《Skills over MCP is final》2026-09-24 + skillsovermcp.com 2026-07-15 实拉，与 r369B（Agent Skills 能力包）判重：本点补 MCP 传输层技能分发增量）：**MCP 扩展轨=Tasks（异步长任务）+MCP Apps（服务器渲染 UI=会话客户端内联交互式 UI 元素）+Skills over MCP（SEP-2640 Final，agent skills=富结构化工作流指令经 MCP 发现/加载）；Skill 格式=SKILL.md 的 name 与目录匹配+license/compatibility/metadata frontmatter（owner 等）；两种服务模式=skill-md（SKILL.md+兄弟资源作 MCP resources 按需逐文件取，agent 加载技能时读取）/archive（单 ZIP 归档打包）；skills-over-mcp.com=把任何 SKILL.md GitHub 仓库变成团队可共享的 MCP 服务器 URL（加进 Claude Code/Cursor/Codex）；MCPJam=连接服务器+发现技能+Playground 加载，能检查 agent 是否真按指令执行而不只看最终答案**。提升层：可复用 Skill/工作流。

**5. MCP 客户端最佳实践：工具错误语义+缓存 hint**（来源：MCP 官方《Client Best Practices》2026-07-28 版 + AgentPatterns《MCP Client Design》2026-09-19 实拉）：**MCP 工具错误=成功响应带 isError:true（不是传输失败）——生成的 wrapper 应转成抛异常供模型写的代码 try/catch；未捕获错误终止脚本时作为脚本结果浮出让模型自纠（告诉它哪里错+下一步试什么）；每个列表结果（tools/list、server/discover、resources/read）带 ttlMs+cacheScope 提示——list_changed 通知到达即视为过期即使 TTL 未到；静态缓存 tools/list 本地+list_changed/TTL 过期/显式刷新重取；动态发现=暴露搜索接口让 agent 调用时只取匹配工具 schema——Anthropic Tool Search Tool 报告约 -85% token（对比一次性加载全部定义）**。提升层：工作流/可复用 Skill。

**6. MCP 连接生命周期：timeout+重连+幂等**（来源：The Neural Base《Connection Lifecycle》2026-04-23 + velias《mcp-client-credentials-auth AGENTS.md》2026-08-26 + LangChain《mcp-adapters》2026-09-21 + qualixar《slm-mcp-hub ARCHITECTURE》2026-08-31 实拉）：**initialize() 必须加 timeout（asyncio.wait_for 5.0s）防死/慢服务器无限挂起——生产必加；50+ 并发会话用连接池或按请求会话（别 for 循环逐 session）；自动重连=检测 onclose/Phase 3 连接失败/过期 Streamable HTTP 会话（HTTP 404 或 session-loss 消息无 onclose），指数退避 1-60s+jitter 无限重连，连接稳定 30s 后退避重置；stdio transport 重启=langchain mcp-adapters restart enabled/maxAttempts 3/delayMs 1000；幂等重连=后端连接中断时仅当后端发过 resumption token 才重试一次（token=后端已确认进度可续点），无 token 干净失败——hub 不盲目重执行幂等性未知的工具**。提升层：工具/工作流。

**7. MCP 服务器生产实践：结构化错误+outcome 导向工具**（来源：RaftLabs《MCP Server Development》2026-03-19 + LUNARTECH《Production-Ready MCP》2026-07-06 + GoClaw《MCP Server Best Practices》2026-04-27 + arXiv 2603.13417《Design Patterns for Deploying AI Agents with MCP》2026 实拉）：**返回错误对象不抛异常：机器可读 error code+人类可读 message（LLM 用它向用户解释）+suggested remediation（让 LLM 优雅自愈）——"Customer ID 12345 not found. Verify and try again."好于 "Error: 404"；工具设计=单一清晰责任+action-oriented 服务前缀命名（github_create_issue）+写操作/副作用在描述里显式标注+全参数类型化 JSON Schema（enum/maxLength 约束）；outcome-oriented=按最终业务结果设计工具（封装完整工作流、最小输入、聚合处理后返回）减少会话内调用次数、降低模型卡在琐碎操作链的风险；参数扁平化用原始类型；每工具输入校验（Pydantic/Zod 拒绝多余）+输出剥离 secrets/PII（PII 脱敏是服务器责任非模型）；限流=按 token 与 user 防失控 agent 耗尽上游 API；审计日志=每工具调用结构化记录 user ID/工具名/参数 hash/结果 hash；资源限制=max payload/执行时间/并发**。提升层：可复用 Skill。

**8. MCP 网关与企业治理**（来源：AWS《Governing AI Assets with MCP Gateway》2026-06-17 + Docker《MCP Enterprise Gateway》2026-09-04 + systemprompt《Enterprise MCP Gateway Guide》2026-04-16 + dev.to《Bifrost Multi-Tenant》2026-09-05 实拉）：**网关=代理层在 AI agents 与 MCP servers 之间：agent 连网关，网关做认证/限流/记录/转发，MCP server 永不见原始客户端连接；认证与授权用企业同一 source of truth（IAM/OAuth/JWT 入站+出站 credential providers 协议版本升级不需换凭证）；Observability=OpenTelemetry traces+metrics 流入现有后端（Splunk/Datadog/New Relic/Honeycomb/Grafana Cloud）无独立栈；注册表暴露 webhooks（新 server 注册时校验工具描述）；secrets=调用时从现有 store 读取（不存环境变量）；policy=写在网关或委托现有策略引擎；多租户隔离=租户 scope 在网关层强制（Bifrost=Prometheus+OTLP 导出，5000 rps 下每请求仅 11 微秒开销）；企业选型四必备=OAuth 2.0/2.1+token refresh+SSO 进 IdP+secrets 比环境变量强+每工具日志/成本归因/OTLP+自托管 VPC 或气隙；AI Gateway tier=OTLP token 用量指标+portal 内建 token 消耗仪表盘**。提升层：工具/工作流。

**9. MCP 安全清单：SSRF+token 校验+权威参考**（来源：MCP 官方《Security Best Practices》2026-08-03 + AIBuzz《MCP Security for Beginners》2026-06-02 + exploreagentic《Threat Model》2026-06-09 + modelcontextprotocol.org draft 2026 实拉，与 r370D 判重：Agent 安全纵深已落，本点补 MCP 规范特化增量）：**SSRF=OAuth metadata discovery 阶段客户端从攻击者可控的 URL fetch（发现端点是 SSRF 面）——block 私有 IP 段 egress；每请求 token 校验（signature/iss/aud/exp/required scope）；服务器 MUST NOT 接受非为它签发的 token；绝不把客户端 token 透传给上游 API；allow-list+验证每个工具输入；敏感/不可逆操作要求人工确认；权威参考=NSA《CSI_MCP_SECURITY》美国政府最高权威 MCP 安全参考+MITRE ATLAS 2025-10 新增 14 个 agent 攻击技术+Cloud Security Alliance AICM Framework 2026-03——合规文档用这些；CVE-2025-6514=恶意 authorization_endpoint 拦截 token——OAuth 2.1+PKCE 强制防**。提升层：可复用 Skill。
