## 独点（10）

**1. OTel GenAI 语义约定稳定化：gen_ai.* span 类型+属性词表+eval-as-span-attribute**（来源：belsoft + futureagi-otel + openinference + zylos-telemetry 实拉）：OpenTelemetry GenAI 语义约定 2026 发布 stable 版——**LLM 调用（gen_ai.client.chat）/agent 调用（gen_ai.agent.invoke）/工具执行（gen_ai.tool.execute）三类 span 类型**+标准化属性词表（token 用量/模型身份/finish reason/agent 元数据，如 gen_ai.usage.input_tokens/gen_ai.request.model）；**eval-as-span-attribute=评测分数直接挂 span 上**（一次 trace 同时是观测与评测）；传统 APM 对 LLM 三大盲区=**静默语义失败/上下文窗口耗尽/失控 token 成本**。判据：**可观测性用厂商中立标准（OTel），别锁进专有 agent SDK**。提升层：工具/工作流。

**2. 跨 agent 边界 trace 上下文传播：W3C Trace Context+span 层级+跨 MCP 传播**（来源：redhat + willvelida + ag2-otel + zylos-multi-agent 实拉）：**trace ID 跨服务恒定、parent span ID 传递（version-traceid-spanid-sampled）**——协调 agent 调子 agent（HTTP/MQ）时上下文必须传播，子 agent span 成为父 span 的孩子；**无传播=断开的 trace（每条 agent 各一个新 trace ID，因果链全断）**；span 层级=**root/agent/LLM/tool/retriever/embedding**；OpenLLMetry 已实现**跨 MCP server 的 trace 传播**——从 web 界面经编排 agent 跨多个 MCP 到单个工具调用成一条连贯 trace。判据：**多 agent 可观测性=context propagation，span 采集不传播等于没采**。提升层：工具。

**3. 流式 LLM 指标：TTFT/TPOT/inter-token latency+按模板成本归因**（来源：openlegion + maxim-gateway + ai-tldr + zalt 实拉）：**TTFT（time-to-first-token）=交互 agent 的主要 UX 指标，不是端到端延迟**（P99 目标：交互<2000ms/批量<10000ms）；TPOT=首 token 后流式吞吐；**inter-token latency=节流/换模型/供应商降级的信号**；成本最可行动指标=**per-request 成本按功能/prompt 模板拆分**——总月费只告诉你账单，按模板成本告诉你哪个 prompt 在烧钱（系统消息 200→2000 token 一次文案修改就涨 10 倍）；reasoning 模型单轮烧 10-40K 输出 token。判据：**延迟看 TTFT 不看 e2e，成本按模板归因不按总额**。提升层：工作流。

**4. Agent 生产质量指标：成功率/工具调用精度/一致性区间+分层阈值**（来源：NVIDIA-agent-eval + futureagi-tool-selection + aws-strands + mcpbr-mcptoolbench 实拉）：**Task success rate=release gate（环境是否到达目标态）；Tool-call precision=correct_calls/calls_issued——幻觉工具名与多余调用只在这里现形，成功率看不出来；Consistency=3-5 次 trial 的成功率区间（90%/74% 的分裂不是 84%，要报 82-88% 范围而非点估计）**；tool selection accuracy 三信号=覆盖所需工具/对可用工具集的有效性/实际调用成功率；AWS 三层部署闸=**tool usage>95%/reasoning>85%/output quality>90% 三层全过才部署**。判据：**成功率是顶层门，工具精度与一致性才是诊断层——点估计掩盖分裂**。提升层：可复用 Skill。

**5. 离线/在线评测双轨，同 evaluator 模板贯穿四层**（来源：langchain + aws-langsmith + futureagi-eval 实拉）：**离线=curated dataset+参考输出（CI/回归/变体对比，确定性可复现）；在线=生产 trace 无参考（监控/drift/连续质量）**——部署前后两套互补；**四层（离线 benchmark→CI regression→inline guardrails→生产可观测性）跑同一 evaluator 模板**：CI 分预测运行时分成、运行时 block 映射回 CI 回归。判据：**离线在线共用 evaluator，分数才可比——两套不同模板等于两份不可比评测**。提升层：工作流。

**6. 生产失败→用例闭环：capture→sample→lock 三环+失败分群晋升回归**（来源：confident-ai + codeables + latitude + futureagi 实拉）：**instrument 记录每个 agent run 为结构化 trace（输入/工具调用/中间态/输出）→filter/sample 用查询+分析浮出高信号对话（失败/边界/代表成功）→label/lock 转成带 ground-truth 的数据集（按需重跑）**；生产 trace 流入**标注队列→双审一致→promote 进数据集**（活跃产品每周 30-80 行）；**失败分群（HDBSCAN 聚类失败 trace）→判官写立即修复→trace 晋升为回归测试**——生产事故变永久回归覆盖。判据：**trace 只记不评=半套；失败必须闭环成数据集才叫可观测**。提升层：工作流。

**7. Golden set 维护纪律：200 例分层+污染+月/季/年刷新**（来源：divinci + techearl + futureagi-golden + langfuse + ai-tldr 实拉）：**200 例分层比 5000 例未分层更管用**（five well-defined slices）；构成=**happy 60%/edge 20%（长输入/短输入/怪字符/多语言）/adversarial 10%（注入/应拒请求）/regression 10%（每个修过的 bug=一例，修之前先入集）**；**污染=测试用例进了微调数据→分数虚高（QA 基准泄漏实测 1-45%）**；刷新节奏=**每月 promote 新生产模式+退役不再触发的、每季加新 jailbreak/注入变体、每年全量重标基线（label drift 不叠加）**，每次刷新升版本+diff。判据：**golden set 当测试套件维护：逃逸 bug 成用例、重复合并、过时显式退役**。提升层：可复用 Skill。

**8. Drift 检测四法+LLM 专用四信号+judge drift 固定快照**（来源：futureagi-drift + mlflow + niteagent + insightfinder + menuagentic + nautilus-compass 实拉）：**PSI（<0.1 稳定/0.1-0.2 中度/0.2+ 显著，按特征分桶 (actual-expected)×ln 比值和）；KS 检验（连续分布 CDF 最大距离）；eval-score 跟踪（drift+eval drop 同时出现才告警，单 drift 不警）；输出分布监控（预测分布变化=上游供应商变更的领先指标）**；LLM 专用 4-signal=**token 长度分布 KL 散度/embedding 余弦漂移对滚动基线/LLM-as-judge 评分流水线/拒答率指纹**；**judge drift=同一 judge prompt 同输入不同分数分布（供应商静默换模型）——固定 judge 模型到 dated snapshot+月度校准，聚合偏移超噪声底就告警**；persona drift 黑盒检测=prompt 与行为锚文本的 BGE-m3 余弦加权 top-k。判据：**drift 告警要"信号+影响"双条件，judge 本身也会漂移**。提升层：可复用 Skill。

**9. Agent 事故响应：六步 RCA+五类静默失败分类+复盘进记忆**（来源：latitude-rca + silent-failures-2606.14589 + respan + futureagi-playbook 实拉）：RCA 六步=**定义失败→映射层→重建 trace（从失败往回走到第一个分歧步）→隔离→确定性重放→验证修复**（先搞清为什么失败再 patch，one-off fix 和系统性修复分开）；五类静默失败=**环境平台怪癖/设计假设不匹配/错误吞没稀释/链式幻觉编造（LLM 特有最危险——系统不报错还主动把错误转成连贯叙事）/操作遗漏与取证盲区**；ResolveIQ 五阶段=**incident→hindsight recall（历史经验）→reasoning→engineer action→hindsight retain（解决后复盘进 agent 记忆）→未来事故**。判据：**静默失败比显式报错危险——链式幻觉是 LLM 系统独有，事故后复盘必须沉淀进记忆**。提升层：可复用 Skill。

**10. Trace span 必含字段+五 bug 形状+症状→信号→根因映射**（来源：respan + latitude-debug + futureagi-failure-modes 实拉）：**span 必含=model name/prompt hash/tool name/full arguments/full result/token counts/latency/error mode——缺一项就少一类诊断能力**；五 bug 形状=**卡死循环/幻觉工具参数/上下文丢失/路径规划错误/跨部署静默退化**；症状→trace 信号→根因映射=**wrong tool（tool span 名与用户意图不符）→工具描述歧义或目标漂移→先查有没有相似工具描述混淆模型**；失败分类五类=tool errors（参数/权限/不存在工具）/retrieval errors（wrong-chunk/missing-context/hallucinated-source）/planning/reasoning/context errors。判据：**调试 agent 用树不用 print——一次运行一条路径，print 看不到另一条路**。提升层：工作流。
