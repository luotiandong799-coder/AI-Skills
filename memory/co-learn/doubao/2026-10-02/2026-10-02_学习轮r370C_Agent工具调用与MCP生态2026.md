## 独点（10）

**1. 工具调用准确率衰减曲线 + 失败模式统计**（来源：presenc + datarekha + belsoftsolutions 实拉）：**准确率随工具数衰减：5 工具 85-91%、20+ 工具 65-78%（生产部署天花板）、30 工具目录 ~80% vs 5 工具同任务 97%；参数不匹配（选对工具填错参）占工具调用失败 60-75%，比选错工具更常见**；**生产五失败模式=幻觉参数/该用 enum 却给自由 JSON/工具选择歧义（描述重叠）/静默 schema 漂移（模型按旧 schema 调用）/过度积极重试循环——每个有结构性修复**；**开源模型（Llama 4/Qwen 3）落后闭源 frontier**。判据=工具目录 >10-15 个时准确率开始退化，先缩目录再怪模型。提升层：工作流。

**2. 工具 schema 设计九规范**（来源：ai-tldr-designing + futureagi + egoistai + alicelabs + zylos 实拉）：**verb_noun 命名（search_products 不 search 不 customer_tool）**；**description 写给模型当 prompt fragment 用：含 when to use + when NOT to use（负例防误用）+ 参数含义——"Do NOT call for returns/refunds, use process_return" 比只写用途有效**；**type 全标注+enum 约束固定选项（celsius/fahrenheit 二选一模型不会幻觉第三值）+format 提示（date-time）**；**required 数组标全必需字段——required 参数放进 optional 数组是最常见调用错误**；**additionalProperties:false 拒未知字段**；**读写分开（query_database/update_database 减歧义+缩小每个工具 schema 攻击面）**；**描述含具体示例**。判据=工具 schema 是写给"细心但没经验的新员工"看的 API。提升层：可复用 Skill。

**3. 工具错误响应=契约的一部分；no-results 与 failure 必须区分**（来源：tianpan-400 + scienx + aiagents-codeguides 实拉）：**错误响应是 API 告诉模型"下一步怎么做"最有信息量的部分——只集成 happy path 的 agent 没真正集成工具**；**模糊失败态是 agent loop 第二大成因：搜索返回空数组（成功调用）与超时（失败调用）对模型长得一样**；**结构化错误观察：host boundary 捕获、转成结构化 tool observation 返回模型、每个 call ID 都回一条 tool message（含失败）**；**错误消息进上下文/日志前先剥离 secrets**。判据=工具契约三部分=成功响应+错误响应+限流头，都写进工具描述与处理逻辑。提升层：工作流。

**4. 错误恢复五层 + 循环检测**（来源：genai.club + ai-tldr-errors + llmversus + agentpatterns 实拉）：**五层=retry budget（per-tool 连续失败返回 terminal"勿再调此工具"）/fallback chains（主工具 429 时备用工具）/error context（失败信息入下一次上下文）/observability（按 tool 名+迭代数记错误=可靠性基线）/chaos tests（故意搞挂工具测恢复）**；**循环检测=相同参数 hash 重复调用即 LoopDetectedError→升级人工（llmversus 3-attempt outer loop+escalation）**；**context-injected error recovery 在失败瞬间给模型更好信息（首重试前），loop detection 事后打断已形成循环——前者减轻后者负担，实测重试减少 25-40%**；**全局 step cap 兜底**。判据=恢复是渐进升级：self-correct→fallback→degrade→escalate，别让模型无限重试同错。提升层：工作流。

**5. 工具评测基准三件套**（来源：gorilla-bfcl + taubench + benchmarkingagents + arxiv-toolfailbench + presenc 实拉）：**BFCL v4=agentic 层（agentic web search 多跳+错误恢复、memory persistence、format sensitivity=工具 schema 重排后模型答案偏移多少）；tau-bench=端到端多轮任务完成（pass^k 可靠性随 k 衰减，Claude Sonnet 4.5 airline 0.700/retail 0.862 目前最强多轮工具分）；ToolFailBench=模型是否真用工具结果写最终答案（1,000 任务五专业域+无需工具的 control queries，规则分类器+双 LLM judge）**；**量化事实=90th MT-Bench 模型仍可 12% 失败复杂嵌套工具 schema——聊天能力与工具调用能力不同轴**。判据=选工具模型看 BFCL+tau-bench 组合，别只看聊天榜。提升层：可复用 Skill。

**6. 动态工具路由三模式**（来源：pypi-adaptive-tools + arxiv-dynamic-react + arxiv-atlas + microsoft-model-router 实拉）：**ATR=轻 LLM（Haiku/GPT-4o-mini）在工具进 system prompt 前按查询过滤——上下文 token 减 ~90%、选择准确率提升**；**Dynamic ReAct=两级 search_tools（每查询 k1=20 候选→去重→每应用上限 k2=5）+load_tools 按需加载——大规模 MCP 环境可扩展**；**Atlas=双路（training-free cluster routing 用经验先验做领域对齐 + RL multi-step routing 探索 OOD 泛化）**；**model router=按请求路由模型（greeting→便宜快速、复杂工具链→frontier），部署单端点零路由逻辑**。判据=工具多到装不进上下文时必须路由：先轻 LLM 过滤再全量注入。提升层：工具。

**7. MCP 服务发现协议栈 2026**（来源：modelcontextprotocol + ietf-mcp-dns + microsoft-windows-mcp + tencent-registry 实拉）：**server/discover 请求每 server 必须实现（_meta 带协议版本+client 能力+身份），响应可缓存；list 结果可缓存（SEP-2549 TTL）**；**IETF draft=DNS TXT _mcp.<domain> 记录广告 presence/endpoint/transport/crypto identity/capability profile，互补 .well-known/mcp/server-card（crypto identity envelope 绑 Sovereign-tier handle）**；**官方 MCP Registry（registry.modelcontextprotocol.io）=统一服务目录+开源 OpenAPI 规范可建子注册表（不取代社区/企业注册表，作上游数据源）**；**Windows ODR=本地 app/远程 server 注册+隔离环境默认+仅可访问批准资源（降低跨 prompt 注入威胁）**；**Azure API Center=企业 API 清单内的 MCP 注册端点（VS Code/Copilot 可发现连接）**。判据=发现先于连接：server 能力/版本未知前不调用工具。提升层：工具。

**8. MCP 治理/网关：策略前置评估+防篡改审计**（来源：microsoft-agt + bedrock-agentcore + mcp-gate-policy + mintmcp 实拉）：**Microsoft Agent Governance Toolkit（AGT）=开源 runtime 治理层，位于 MCP client 与 tool servers 之间，每个工具调用先过 definition scanning→policy evaluation→response inspection——governs agent actions not model outputs**；**Bedrock AgentCore gateway=Cedar 确定性策略（同输入同决策不受 LLM 行为影响）+Lambda 拦截器+consent elicitation（MCP -32042 错误让 agent 引导用户浏览器授权）+每日志带 principal/policy ID/guardrail flag**；**mcp-gate-policy=防篡改审计日志（append-only+fsync+SHA-256 hash-chain，verify() 检出任何改序/删改）+启发式威胁扫描（prompt/command injection、secret 外泄、路径遍历）+NIST/OWASP 映射合规报告**；**33% 组织缺证据级审计日志（SOC2/HIPAA/GDPR 场景）；日志必须归属具体 agent 而非创建它的人，导出 SIEM**。判据=工具调用治理=策略前置评估（确定性）+不可篡改审计（hash-chain）+按 agent 归属。提升层：工具。

**9. Programmatic Tool Calling + HyFunc + 结构化输出硬约束**（来源：gpt-5.6 + arxiv-hyfunc + aiwiki + aibuzz 实拉）：**GPT-5.6 Programmatic Tool Calling=Responses API 内过滤大量中间工具数据、只保留关键、工作流中途自适应——更少 token/轮次/引导，不再要求开发者脚本化每步**；**HyFunc=hybrid-model cascade：大模型蒸馏用户意图成单 soft token→轻量检索器选函数→小 prefix-tuned 模型生成最终调用（避免大模型全序列生成+冗余上下文处理），dynamic templating 在 vLLM 内注入样板参数语法**；**结构化输出=解码层硬约束（strict:True 需 additionalProperties:false+全字段 required，GPT-5.4 保证工具参数精确匹配 JSON schema 非 best effort）——与 function calling 区分：结构化输出是终端答案无工具执行**。判据=能上结构化输出硬约束就别靠模型自觉；工具调用中间数据能过滤就过滤。提升层：模型/工具。

**10. 工具生态规模与远程 MCP 主流化**（来源：taskade + nango + aws-agent-registry 实拉）：**10,000+ 公开 MCP server（独立普查达 17,000）、Anthropic 官方 SDK 97M+ 月下载、MCP 2025-12 加入 Agentic AI Foundation、2026-07-28 spec 无状态化（更易扩展）；production readiness 因 server 而异（per-user auth/tool quality/observability 差异大，约 10,000 活跃 server 中质量参差）**；**远程 MCP server 成主流：GitHub/Vercel/Linear/Notion/Supabase/Stripe/Figma/Hugging Face 提供 OAuth 远程端点——消除本地凭证泄露风险、CI 环境可用、厂商更新免用户重装**；**AWS Agent Registry GA=私有受治理目录+集中 agent 发现层**。判据=优先官方/知名团队的远程 MCP（OAuth 免凭证落地），自建走本地 stdio。提升层：工具。
