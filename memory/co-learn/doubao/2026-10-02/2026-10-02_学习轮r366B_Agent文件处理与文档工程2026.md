## 独点（10）

**1. 表格提取混合管线：OCR+LLM 重构，不用图像直喂**（来源：ai-engine-hybrid + theneuralbase + mixpeek 实拉）：OCR API 读 PDF 出每页精确文本（不发明）→ LLM 收 **OCR 文本而非图像**重构表格为 HTML（system prompt 禁止修改任何值）；**传 OCR 文本把 LLM 输入从 ~51,000 token（base64 图像）砍到几分之一**；vision LLM 看图成本 $0.003-0.01/页，pdfplumber bbox 裁剪+LLM-as-parser 便宜（~$0.0001/表）但需精确 bbox 校准；**HTML 输出保留 rowspan/colspan，复杂表优于 Markdown**。判据：**表格提取按"谁强谁干"分工——OCR 管无幻觉文本，LLM 管结构重构**。提升层：工具/工作流。

**2. 表格提取两遍验证+符号 sanity 规则（neurosymbolic）**（来源：mixpeek + Ten-2508.09324 + theneuralbase + aitoolsguidebook 实拉）：**两遍=第一遍检测表区域出 HTML，第二遍验证结构（列数相等/无孤儿 cell）并用不同 prompt/model 重提取失败**；Ten=**符号 sanity 规则查结构违规→critique LLM 翻译成可操作反馈→定向修正再生成**（连续对话）；**表格错误几乎总是系统性的**（off-by-one 行、列错位）——抽查三随机行 cell-by-cell 即暴露；验收三信号=**row_count/col_count 完全匹配、header_match、cell_accuracy≥0.95**。判据：**表格提取必须验证——结构完整性用确定性规则查，不靠肉眼**。提升层：工具/工作流。

**3. Chunk 质量五维评测+基准事实：512 递归=默认**（来源：rpsarathy + prem + arXiv-2603.06976 + rajatgautam 实拉）：五维=**semantic coherence（块内单主题）/context preservation（原意保留度）/coverage（关键想法全出现）/redundancy（重叠适量）/balance**；**recursive character 512 token+50-100 overlap=2026 最大真实文档测试 69% 精度、零模型调用，胜过所有更贵替代**；systematic 研究（36 方法×6 域×5 embedding）：Paragraph Group Chunking 最佳（nDCG@5≈0.459，P@1≈24% vs 固定尺寸 2-3%）；**overlap 无 measurable 收益只涨索引成本**；**sentence-level chunking 在 ~5000 token 上下文内匹敌 semantic**。判据：**先测块质量五维，再选策略——多数文档 512 递归足够，别为语义块多付成本**。提升层：工具/工作流。

**4. Parent-Child 双层块：small child 检索+large parent 生成**（来源：pavlo + stochasticsandbox + futureagi 实拉）：**同一内容两个表征：小 child 块（精确，检索用）挂接大 parent 块（上下文，生成用）——检索命中 child 后传 parent 给模型**；**这是第一个真正绕过 precision-vs-context 取舍的策略**（复杂文档首选）；hierarchical chunking 树=叶子句子/高层摘要（RAPTOR 参考实现）；semantic chunking 缺陷=块大小不稳定（50→2000 token）、索引慢（每句 embed）、只对长无结构文档值（会议记录/无标题论文）。判据：**要 precision 又要 context——用双层表征，不是加大单块**。提升层：工作流。

**5. PDF 解析工具选型：Docling 自托管开源首选**（来源：kanopy + firecrawl + docling-2501.17887 + spheron + ianas + aiworkflowlab 实拉）：表格结构提取正确率 **LlamaParse 89% > Docling 83% > Unstructured hi_res 71% > fast mode 42%**（**跳过 layout 分析就掉链**）；简单表（2-4 列无合并）都 >90%，复杂表（跨列头/嵌套行/混合数字文本）差距拉大；**Docling=IBM 开源 MIT，TableFormer 专治表格+DoclingDocument 统一表征**（layout/reading order/表 cell/formula/图位置），61k stars，**MCP server+docling-serve+document_key 缓存（转换一次查询多次）**；MinerU=公式识别 UniMERNet（科学论文 LaTeX 最佳）+PP-OCRv6；有监管/隐私场景选 Docling（全本地）。判据：**解析器按文档复杂度选——简单文档快模式就够，复杂表/公式上专用解析**。提升层：工具。

**6. 文档智能双路径：Schema 固定→Parse，开放问答→Agent**（来源：bem + ACL-2026-industry.133 + datarekha + futureagi 实拉）：**路径一 Parse：字段已知（schema 相同）、要确定性 auditable 输出、高吞吐（数千份/日）**；**路径二 Agent：问题开放/跨节推理/交互探索，上下文完整性不可妥协**；**ACL 实证：多格式文档理解中"何时用工具"决策直接加 +40 点 Word/+35 Excel/+28 PPT**（不直接喂模型）；实现=python-docx/openpyxl（**保留计算值**）/python-pptx；section 在 header/page break/table boundary 分割；**表格绝不 mid-row 拆分**；agentic RAG 三支柱=query classification/retrieve-or-answer-directly routing/multi-hop refinement。判据：**先判问题形态再选管线——要字段走 Parse，要推理走 Agent，别默认全喂模型**。提升层：工作流。

**7. OCR 模型选型：专用模型赢原始 OCR，frontier 赢吞吐/复杂提取**（来源：ofox + ai-tldr + intuitionlabs + noqta + clarion 实拉）：**GLM-OCR/PaddleOCR-VL 等专用小模型在原始 OCR 基准打败所有 frontier LLM**；Gemini 3.1 Pro=1M 上下文最低成本卷文档处理，Claude Opus 4.6=复杂结构化提取精度优先；**三层管线=OCR 读文字→layout 分析赋空间语义→LLM 推理提取/分类/规范化**；**防幻觉字段提取**：200-300 DPI 转图+明确 prompt（"提取本页表格为 Markdown，含表头"）；**跨页表逐页处理再拼接行**。判据：**OCR 按任务选——纯文字量用专用模型，复杂结构化用 frontier，别只用一张模型打天下**。提升层：工具/工作流。

**8. 数据清洗管线：规范化/丢弃低价值/去重三档+增量去重**（来源：ai-tldr-clean + NVIDIA-NeMo-Curator + microsoft-databricks + PUFFER-2608.28622 + imagetotable 实拉）：规范化=合并 PDF 错断行、标准 newline 让段落边界真实；**丢弃低于最小长度的块/纯标点/孤立页码/空 cell**；**去重三档=exact（MD5）/fuzzy（MinHash+LSH，~80% 相似近重复）/semantic（embedding）**；metadata 先挡（同 title+date 多来源）；**PUFFER=增量模糊去重：每 LSH band 存 immutable 数据集标记段，历史 band-key 精确检查不按语料大小吃 RAM**（连续演进语料）；7 点 QA 清单=blank rows 排序浮顶、duplicate rows COUNTIF、小计对账、per-supplier row-count 基线。判据：**清洗三档顺序做——先规范化再丢弃最后去重，检索才有多样性**。提升层：工具/工作流。

**9. 文档解析评测：分元素指标+源可溯性+输出合规是主瓶颈**（来源：ExtractBench-2607.29677 + PureDocBench-2605.07492 + RealDocBench-2606.07401 + VAREX-2603.15118 + MPDocBench-2605.22100 实拉）：**分元素评估**：文本=Normalized Levenshtein、表格=HTML+TEDS/TEDS_S、公式按专用指标；**ExtractBench 四维=正确完整输出+源可溯性+跨挑战鲁棒性+规模化成本**；**RealDocBench=per-question 所有 keys 正确才计分（严格）——下游 agent 是否拿到全正确记录**；**VAREX 关键发现：<4B 模型主瓶颈是结构化输出合规（schema echo 压低 45-65pp）而非提取能力，2B 提取微调 +81pp**；**Direct VLM 便宜但长记录截断，coding agents 更鲁棒但贵得多**——架构选择显成本差异。判据：**解析评测按元素分指标+按架构显成本——没有单一架构全赢**。提升层：可复用 Skill/工具。

**10. Tier-based 文档编排：简单页便宜解析器，复杂页高级模型**（来源：llamaindex-best-ocr + PureDocBench-2605.07492 + bem + aipromptshub 实拉）：**按页面复杂度路由：简单页给便宜解析器，高级模型只留给复杂页**（tier-based agentic orchestration）；RAG→Agent 升级三条件=多步推理/写或执行动作/动态文档；**架构分元素各有所长：pipeline 架构文本强（Avg-Text 73.42）、E2E 表格强（Avg-Table 76.90）、VLM 公式强（Avg-Formula 66.14）**。判据：**文档管线按元素×页面复杂度分层——贵的模型用在它改变结果的地方**。提升层：工作流。
