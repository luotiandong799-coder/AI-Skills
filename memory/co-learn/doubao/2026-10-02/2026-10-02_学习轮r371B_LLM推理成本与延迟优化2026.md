## 独点（10）

**1. Prefix caching 工程化：断点纪律与热感知调度**（来源：Claude prompt-caching 官方 + Tencent prefix caching 全景 + HotPrefix + UniCache + llm-academy 实拉）：**Anthropic 缓存断点两种开法：自动缓存（cache_control 顶层单字段，系统自动把断点放最后可缓存块并随对话前移——多轮对话用）vs 显式断点（最多 4 个 cache_control，前缀匹配到标记为止——控制强）；缓存读 0.1×、写 1.25×（5 分钟 TTL）/2×（1 小时 TTL）**；**提示词结构工程硬规则：静态内容（系统指令/角色/护栏/工具描述）全前置、动态部分（用户问题/最新轮次）放末尾——单个空格/字节差异即缓存失效，一次 cache-busting 改动 wipe out 后续全部调用收益**；**HotPrefix=hotness-aware KV 调度：只把热 cache 留 GPU、冷迁 host 内存，热升冷降动态提权；UniCache=统一逐出策略（联合复用模式+跨任务缓存分配）vLLM 实现命中率 +17.32%、延迟 −3.63×；稀疏 prefix caching=循环/混合模型在稀疏 checkpoint 位置存精确状态、命中时从最深 checkpoint 续算**。判据=提示布局按"静态前置动态尾"排，断点放在最贵的静态块末尾。提升层：工作流。

**2. Prefill-Decode 分离（DPD）平台矩阵**（来源：vLLM MORI-IO blog + AWS DPD + NVIDIA EPD + arxiv PrfaaS/DuetServe 实拉，与 r355A「吞吐与延迟分离」为 2026 平台级增量）：**prefill 计算密集、decode 内存带宽密集，同 GPU 时 prefill 长提示导致 ITL 尖刺**；**vLLM MORI-IO=单节点 8-GPU MI300X 上分离（AMD 连接器）goodput 2.5×；AWS DPD=独立 GPU 池+EFA RDMA 传输 KV，独立扩展+延迟隔离（decode 实例纯 decode batch）；NVIDIA Dynamo EPD=encode-prefill-decode 三段分离（多模态视觉编码分离，TTFT 快 5×）；Prefill-as-a-Service=跨数据中心把长上下文 prefill 卸载到 compute-dense 集群、KV 走以太网传回 PD 集群（本地 PD 无需海量 KV 内存）；DuetServe=单 GPU 内 SM 级分区默认聚合模式、预测到 TBT 违约才启用相位隔离**。判据=长提示/多模态流量大时上 DPD；单节点小负载用 DuetServe 式按需分区。提升层：工具。

**3. Speculative decoding+KV 量化前沿**（来源：QuantSpec + SpeCache + CoQuant + CompressKV + AIStackInsights 实拉）：**QuantSpec=self-speculative（draft 与 target 同架构），分层 4-bit 量化 KV cache+4-bit 权重，70B 总缓存降到 56GB（−60%）保持 76% 接受率**；**KV 量化分层按注意力层对量化误差敏感度分配精度（信息密度高的层高精度）**；**CoQuant=协方差感知旋转后再 2-bit KV 量化（去相关 outlier）；CompressKV=语义检索头（少数头专司语义检索）用其注意力分数决定保留 token——只留 3% KV 保 95% 效果**；**SpeCache=低比特 KV 副本存 GPU 供 speculative 验证**；**KV cache 是数据库不是缓冲区：PagedAttention 16 tokens/block 分块+block table+copy-on-write 共享，碎片率 50%→<10%**。判据=内存受限先 KV 量化（FP8/INT8 起步），2-bit 用旋转预处理的（CoQuant）而非裸量。提升层：模型/工具。

**4. Continuous batching 吞吐-延迟四旋钮**（来源：Runpod + martinuke0 + AI/TLDR + MLflow 实拉，与 r355A batching 基础为旋钮级增量）：**连续 batching（Orca 2022 引入/vLLM 默认）=请求完成立即插入新请求，GPU 常满，吞吐比静态 batching 高 10-25×（共享负载），利用率 60-85%**；**四个旋钮互斥权衡：max batch size/max concurrent sequences（同 decode 请求数→吞吐↑ 单用户延迟↑）、max-num-batched-tokens（每调度步 token 预算→吞吐↑ TTFT 略差）、concurrency limit（接受请求数，长队 inflate TTFT）、KV-cache memory/gpu-memory-utilization（大 batch 空间→吞吐↑）**；**MLflow 实测 PagedAttention+连续 batching p99 延迟与 TTFT 较替代方案好 2.2-2.3×**。判据=先按 SLO 定延迟上限再调 batch 旋钮，吞吐和延迟是同一组旋钮的两端。提升层：工具。

**5. Token 优化策略：CoD/Draft-Thinking/coupling tax**（来源：tokenoptimize + arxiv Draft-Thinking + arxiv coupling tax + Token-Budget-Aware 实拉，与 r344C CoD 基础为 2026 增量）：**Chain of Draft=每步 ~5 词草稿，比 CoT 省 92.4% 推理 token 保同精度；Draft-Thinking=长 CoT 模型自适应提示（推理深度模型可选行为），MATH500 上推理预算 −82.6% 仅性能 −2.6%（平均 token 预算 5,xxx→低得多）**；**coupling tax=推理轨迹与最终答案共享一个输出 token 预算时，长轨迹会挤占答案——Qwen3 三规模 GSM8K/MATH500/BBH 上非思考模式在 ≤2048 token 每个预算点匹配或超过思考模式（小预算场景不要无脑开 thinking）**；**token-budget-aware=提示词里写明合理预算让模型动态调推理长度；JSON 比 YAML/TSV 结构化输出贵 ~2×（内部管道换格式可省一半）**。判据=按问题复杂度选推理深度（简单任务关 thinking/用低 effort），推理 token 也计输出价。提升层：工作流。

**6. Semantic caching 五种形态+阈值纪律**（来源：FutureAGI + valuestream + masterprompting + devopsboys + ACM 多轮语义缓存 实拉，与 r351A gateway 语义缓存一句为独立展开增量）：**2026 五种命名缓存：exact-match KV cache（字节哈希，如 prefix caching）/embedding 语义缓存（cosine 超阈值）/混合（精确+语义串行）/prompt-template cache（按模板 ID+变量绑定）/response-fragment cache（可复用响应块如工具输出/检索块——agent runtime 最常用）**；**语义缓存在 FAQ/客服类命中 35-45%，QPS 翻三倍零额外 LLM 调用；实现=query embedding→向量库 ANN（cosine>0.92）→命中返回缓存响应，miss 才调模型**；**阈值纪律：太松=真不同问题返回错答案，太紧=退化成精确缓存——0.80-0.95 区间调；多轮语义缓存（Higress WAF 插件）=融合多轮上下文+归一化查询+两档距离规则分离命中/域内新/域外请求**。判据=FAQ/客服类先上语义缓存，命中率 <20% 检查阈值与 embedding 模型。提升层：工具。

**7. 推理 SLO 工程：TTFT 分解与调度器**（来源：Spheron SLO guide + IETF terminology + arxiv Kairos + EdenAI 实拉，与 r355A 延迟指标为分解级增量）：**TTFT=T_net_in+T_queue+T_prefill（网络入站 5-30ms 区域+队列等待+prefill 计算）；ITL=inter-token latency 决定感知流畅度；p99 TTFT 管尾部**；**用户行为：每 +1 秒延迟弃用率 +7%，交互应用 TTFT 目标亚 200ms**；**Kairos=SLO-aware 调度（面向 DPD 的请求不平衡驯服）：TTFT SLO 达成 +23.9%、TPOT SLO +27.1%、端到端 SLO +33.8%、decode 吞吐 +19.3%**；**provider 实测：Groq LPU TTFT ~120ms 最低、Cerebras ~150ms 吞吐领先（均为开源权重模型——性能换能力权衡）；APIpulse 基准 GPT-4o mini ~220ms/Haiku 4.5 ~250ms/Sonnet 4.6 ~450ms/Opus ~800ms**。判据=按交互类型定 SLO（聊天 TTFT<200ms/ITL 稳，批处理不用），预算内先攻 T_queue（batching/路由）。提升层：工作流。

**8. Distillation 2026：Minitron/Needle/EdgeRazor**（来源：artificialus Minitron + LocalAI Master + ai.doocs Needle + arxiv EdgeRazor 实拉）：**Minitron=对已训大模型做 depth/width/attention-head/MLP 四类剪枝+用 <3% 原始训练数据 KD 恢复质量——模型族成本 1.8× 便宜且多个基准上剪枝+蒸馏版反超从零训练版**；**Needle=把 Gemini 3.1 tool calling 能力蒸馏进 26M 参数模型（比最小开源 coding 模型小一个数量级，可跑手机/手表/眼镜）**；**EdgeRazor=混合精度量化感知蒸馏三模块（混合精度结构量化逐层位宽控制+层自适应特征蒸馏动态选最有信息特征+熵感知 KL 双向平衡）；R1-Distill-Qwen-32B ≈85% R1 推理能力 @1/8 规模；Muon 优化器+GPTQ+LoRA+数据蒸馏管道 6GB→3GB**。判据=蒸馏何时值：教师质量高+学生目标窄（tool calling/单任务）+需端侧部署；模型族用 Minitron 式先训大再剪。提升层：模型。

**9. Prompt caching 官方纪律与成本杠杆**（来源：Claude 官方 prompt-caching + DevelopersDigest + AgentPatterns architectural discipline + dev.to 85% 案例 实拉，与 r344C 缓存基础为官方纪律增量）：**prompt caching 是多数应用还没拉的最大单一成本杠杆；cached input 0.1×、写 1.25×/2×，5 分钟 TTL；正确配置后长上下文 TTFT 从秒级降到几百 ms**；**85% 账单削减案例=每个 agent 调用（间隔 <5 分钟的生产 agent 几乎总是 win）在消息块末尾加 cache_control breakpoint**；**AgentPatterns 架构纪律：一次 cache-busting 改动会抹掉后续每次调用的收益——提示布局（什么放哪、什么可变、什么顺序）是架构决定不是优化细节**；**长对话 agent：静态护栏/工具 schema/角色放断点前，对话轮次放断点后（Anthropic 自动缓存模式适合多轮成长历史）**。判据=每次调用 <5 分钟间隔的 agent 必开缓存；断点位置=最贵且最静态的块尾。提升层：工作流。

**10. 推理成本实测：reasoning tokens 计价与 2026 定价表**（来源：AI Economy Playbook + IntuitionLabs + Azure OpenAI pricing + 光明网 实拉，与 r370A 成本复合为数据层增量）：**所有 reasoning tokens 按输出计价——o3 的 200-token 可见答案实际成本 1,700-5,200 输出 token（5-20× 隐藏倍数）；控制用 reasoning.effort（GPT-5.2：none/low/medium/high/xhigh，pro 只 medium+）**；**2026 定价样本：Azure GPT-6 Astra short 输入 $10/缓存读 $1/缓存写 $12.50/输出 $50（缓存读 10× 折扣，长上下文输入 $20/输出 $75）；Sonnet 4.6 缓存读 $0.60 vs 基础 $3（1/5）；OpenAI o-series 输出 $4.40-$600/M 跨度巨大**；**DeepSeek 系统优化后百万 token 成本 130 元→3 元以下、离线 0.3 元（400× 降幅）——最优与最差 Token 性能/成本差距可达 100×**。判据=先计量（tokenomics 记账）再优化；reasoning 模型预算按输出价算不是可见 token。提升层：工作流。
