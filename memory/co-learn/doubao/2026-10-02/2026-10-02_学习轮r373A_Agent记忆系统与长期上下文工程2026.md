## 独点（10）

**1. 记忆系统三代架构：第三代放弃向量检索做内生记忆**（来源：MIT 科技评论 智能体长期记忆 + Redis long-term memory + Cognee lifecycle 实拉）：**第一代=外挂资料库（静态存储）；第二代=更聪明资料库（检索更智能，但存储仍静态、检索仍被动、记忆系统不自主进化）；第三代=内生记忆（彻底放弃向量检索，RL 端到端训练模型学会记忆写入/压缩/遗忘/调用）**；**外挂范式=read-before-reasoning, write-after-acting 循环（接收输入→读工作记忆+查长期库→组装上下文窗口→LLM 推理→工具调用→观察）**；**选型判据=按生命周期覆盖度选不按标签：系统管理 writes/updates/retrieval/provenance/consolidation/forgetting 哪些阶段、记忆控制权在哪层，不同工作负载（个性化/工作流连续性/演进知识/累积经验/多 agent 共享）对栈的要求完全不同**。判据=先问"我的记忆系统要不要自主进化"，要则走内生路线或至少设计 consolidation 自治。提升层：模型。

**2. 记忆框架选型矩阵：Mem0 蒸馏优先 vs Zep 时序图 vs Letta 三层自编辑**（来源：AI Workflow Lab + Developers Digest + anhtu memory frameworks + Mem0 官方 实拉）：**Mem0=distillation-first：原始回合不是存储单元，提取后的事实才是；五轮闲聊产零记忆、一轮含载荷事实产恰好一条记忆；混合存储=向量 embedding+属性图关系+KV 结构化事实三层，写时自动提取/去重/三层入库，检索三路合并**；**Zep Graphiti=history-first：原始对话回合先入库→实体提取→时序知识图（bi-temporal valid_from/invalid_at 双时态处理事实变化，不覆盖旧事实）**；**Letta MemGPT=agent 自主记忆：Core（常驻上下文）/Recall（对话日志）/Archival（按需分页调入）三层，agent 自读写编辑自己的记忆块**；**选型=个性化/聊天历史压缩→Mem0；有状态长时运行 agent→Letta；时序事实/CRM/客服→Zep；全都要自托管=三者均 Apache 2.0（Zep 需图数据库）**。判据=按"事实还是历史才是记忆单元"决定框架。提升层：工具。

**3. 遗忘是功能不是缺陷：六遗忘策略+删除义务远超删行**（来源：Zylos consolidation + Zylos controlled forgetting + FadeMem + ACM ACT-R 实拉）：**无界保留劣化三机制=proactive interference（旧记忆干扰新）/context dilution（上下文稀释）/contradiction accumulation（矛盾累积）——选择性遗忘实证提升准确率**；**六种已形式化遗忘策略：FIFO/LRU/Priority Decay/Reflection-Summary/Random-Drop/Hybrid，在简单性/语义保真/隐私保证/算力间取舍**；**FadeMem=双层记忆层级+自适应指数衰减（受语义相关性/访问频率/时间模式调制）+LLM 引导冲突消解+智能融合——相关保留无关淡出**；**合规=GDPR Art.17 与 EU AI Act 对 agent 记忆的删除义务，简单数据库删行不满足——记忆影响 embeddings、summaries、有时模型参数，需要 machine unlearning 与影响面追踪**。判据=记忆系统必须内置遗忘策略（默认 FIFO 起步），删除=影响面级操作非删行。提升层：工作流。

**4. 记忆投毒 ASI06：五层纵深防御+信任层级**（来源：securetom + al-ice + SMSR + MAPLE-Guard + Vectorize ASI06 + zerodaycyber 实拉）：**OWASP 2026 新威胁分类 ASI06 Memory Poisoning：写穿 prompt 层，输出校验在下游失效——比 prompt injection 更难防**；**防御五层=写时输入控制/带来源净化（provenance）/信任感知检索/范围隔离/行为监控，无单层足够但正确分层让攻击不经济（Agent Security Bench 最高平均 ASR 84.30%）**；**permission-aware vector DB=严格按 user/agent 逻辑分区（OWASP LLM08），写时每条记忆打 source/author/trust classification 标签；最小权限记忆访问=agent 不应有 procedural memory 写权限（OWASP LLM06）**；**SMSR=写时 HMAC-SHA256 provenance 标签（对抗未签名注入的密码学硬边界）+查询时随机记忆消融+多数投票聚合（带认证鲁棒界）；MAPLE-Guard=写/检索/晋升/跨 agent 复用四门控，ASR 38.2% 显著下降**；**信任层级写进 system prompt=system_seed > document > tool_output > conversation；身份与特权永不来自记忆，只来自认证上下文**。判据=记忆写口=新攻击面，按五层防御；信任层级显式声明。提升层：工具。

**5. 记忆评测四维框架：Recall≠answer accuracy**（来源：FutureAGI memory eval + BenchD + AgentMemBench + automem 实拉）：**四维评测=①Recall（该轮正确事实浮现，top-k 命中/hit-rate by fact id）②Freshness（事实更新后用最新版本，valid_at 新于同 key 旧写）③（Consistency 一致性）④（Privacy 隐私边界）**；**关键=Recall@10≠答案准确率——召回只是证据在 top10 出现，下游模型仍可能误解/错组/答出无支撑答案，检索与生成必须分开评**；**基准=LoCoMo（1540 题多会话，Mem0 92.5%）/LongMemEval（94.4%）/AMA-Bench（长时记忆+因果推理 57.22% 超基线 11.16%）/AgentMemBench（EKV 全面胜出：Recall@5 0.792/MRR 0.677）**；**工程实践=Claude Code MEMORY.md 200 行上限；只取 top10 结果 3,142 token vs 全载上下文 22,610 token=86% 节省——记忆检索必须限额注入**。判据=检索与生成两个计分板；记忆注入限额。提升层：工作流。

**6. 多 agent 共享记忆治理：四失败模式+四原语**（来源：arxiv governed shared memory + arxiv shared vs distributed + AWS S3 + NVIDIA Agora 实拉）：**共享记忆四失败模式=unauthorized leakage（越权泄露）/stale propagation（陈旧传播）/contradiction persistence（矛盾存续）/provenance collapse（来源坍缩）；四治理原语=scoped retrieval（范围化检索）/temporal supersession（时序取代）/provenance tracking（来源追踪）/policy-governed propagation（策略治理传播）**；**架构二分=共享池（知识复用易但需 coherence 支持：互覆盖/读陈旧/版本不一致）vs 分布式（每 agent 本地+选择性同步，隔离扩展好但协调成本）**；**Git 作共享记忆后端实证=NVIDIA Agora append-only 不可变 Git 提交：13 自治 worker 1703 贡献协调，缩小 62% 与训练模型差距；生产实践=个人 vs 共享双存储分离（AWS S3 Vectors），腾讯 TencentDB Agent Memory Team Memory 90 天 20000 stars**。判据=共享记忆必须带治理原语，默认 append-only+来源追踪。提升层：工作流。

**7. 内生记忆/记忆原生 RL：恒定上下文+潜在压缩**（来源：MemSearcher + Mem-W + Metis + Memory-R1 + AgeMem 实拉）：**MemSearcher=LLM-as-Memory-Manager：把 ReAct 线性拼接历史换成固定长度内存+自然语言摘要，每轮 context=(q, m_{i-1}) 而非 (q, t1, a1, o1, …)——多轮搜索下 context 恒定**；**Mem-W=潜在记忆原生 GUI agent：轨迹到潜在压缩器把变长观测-动作段映射为定长潜在块，推理时同一压缩器收历史轨迹+进行中 episode 前缀**；**Metis=第一个记忆基础模型：持久记忆状态放进模型 backbone，历史信息压入该状态、记忆注意力读出，在线更新无梯度——"agent memory 还是外部模块是历史事故不是设计"**；**Memory-R1=双 agent PPO 微调（Memory Manager 执行结构化记忆操作+Answer Agent 用 Memory Distillation 策略过滤 RAG 检索并推理）；AgeMem=三阶段渐进 RL+step-wise GRPO，Qwen3-4B 达 54.31%**。判据=长期记忆性能瓶颈时考虑记忆原生微调路线，context 恒定是核心度量。提升层：模型。

**8. 记忆整合失效：LLM 连续更新记忆会越用越差**（来源：arxiv useful memories become faulty + Auto-Dreamer 实拉）：**实证=连续更新的文本记忆随经验累积变无用——cleanest case 里 agent 在自己记忆构建所依据的问题上变差；病根在 consolidation loop 本身=当前 LLM 不可靠判断哪些 episode 该归组/哪些区分该在压缩中存活/何时经验该保持 episodic——错误分组轨迹、过度泛化**；**修复=互补学习系统理论：快会话获取与慢跨会话整合解耦（Auto-Dreamer）：consolidator 把选定工作区当只读证据，做有界工具调用检查条目+provenance 关联源轨迹，合成新鲜紧凑替换集（跨会话抽象并取代旧条目）——离线整合、不实时改记忆**；**判据=记忆整合=离线批处理操作，不是每轮增量合并；整合质量必须评测（防整合本身引入退化）**。提升层：工作流。

**9. 上下文组装五规则：阈值/去重/元数据/位置/动态 K**（来源：toolsku context engineering + interviewsvector memory tiers + mem0 augmented prompt 实拉）：**五规则=①relevance threshold 不注入 <0.7 分文档（噪声增加幻觉）②去重=同文档 chunk 合并（防 token 浪费）③元数据保留 source/time/version（无溯源=合规风险）④位置优先=最相关文档放最前（Lost in the Middle 效应）⑤Dynamic Top-K=按剩余预算调 K（超预算时硬截断劣于动态降 K）**；**三层记忆注入=短期（最后 N 轮 verbatim，便宜高保真小）/工作台（当前任务紧凑结构化 scratchpad：计划/已决/开放问题，重写不追加）/长期（持久事实按需检索像检索文档）**；**注入时序=记忆只在 prompt 生成时取——用户上下文中途变化必须重新调用增强函数否则 LLM 永远看不到更新；高频同用户同窗口缓存增强 prompt（如 5 分钟）**。判据=注入前过五规则检查表；记忆注入时机=prompt 生成时。提升层：工作流。

**10. 记忆系统生命周期选型：writes 到 forgetting 谁管决定一切**（来源：Cognee lifecycle + EverMind MemCells + loki-mode 实拉）：**选型按生命周期覆盖度不按标签：系统管理 writes/updates/retrieval/provenance/consolidation/forgetting 哪些阶段、记忆控制权在哪层——工作负载不同（个性化/工作流连续性/演进知识/累积经验/多 agent 共享）需求不同，浅层=workflow persistence+managed memory API，深层=应用自有存储栈+全生命周期自治**；**EverMind=MemCells/MemScenes/语义整合/重构回忆结构化生命周期+profile 编辑删除 by user/agent/session 治理；多主体记忆=显式发送者归属+user/agent 范围化检索**；**时间索引工程=loki-mode：episodic 存为日期目录（YYYY-MM-DD/task-id.json）让日期目录提供时间导航，index.json 放记忆根（不在 episodic 下）——索引层与存储层分离**。判据=先列自己工作负载要哪几阶段生命周期再选平台；时间=episodic 记忆的第一索引维度。提升层：工具。
