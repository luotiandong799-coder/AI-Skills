## 独点（10）

**1. Agentic RAG 五模式+五层架构**（来源：rapidclaw《RAG Architecture for AI Agents》2026-04-30 + FutureAGI《Agentic RAG in 2026》2026-05-14 实拉）：**五个典型模式=迭代检索（retrieve-reason-retrieve 直到证据够）/查询分解（拆子查询）/假设驱动检索（HyDE）/跨语料三角测量/证据加权综合；五层架构=planner→retriever→re-ranker→reflection/grader→generator**；**vanilla RAG=一次检索固定 pipeline；agentic RAG=agent 决定何时检索、检索什么、不够再检索——基础 RAG 检索一次猜一次就作答**；**判据=hybrid RAG 是多数查询的生产基线，agentic 是多跳/歧义/规划重查询的升级路径，不为所有查询上 agentic（贵 2.5x）**。提升层：工作流。

**2. 混合检索生产基线：BM25+dense→RRF→cross-encoder→LLM**（来源：AI Workflow Lab《Hybrid Search RAG Pipelines》2026-05-03 + LLM Versus《Hybrid Search 2026》2026-04-16 + AIPromptsHub《RRF》2026-06-21 实拉）：**生产模式已定论=BM25+dense→RRF→cross-encoder reranker→LLM；RRF=sum(1/(k+rank_i))，k=60 标准平滑常数，实现 10 行 Python、检索系统无关**；**纯向量比混合差 5-15%（BEIR 实证）：BM25 抓精确关键词匹配（产品码/名称/技术术语），dense 抓语义改写，两路互补**；**查询时同 query 发两通道各 top-50→RRF 合并 ~50 唯一 chunk→reranker 选 top-5-10；加权 RRF=wd/(K+rd)+ws/(K+rs)；SPLADE-v3 学习稀疏表示可替代纯 BM25**。提升层：工作流。

**3. 切块策略选型+chunking 可摆动召回 ±9 分**（来源：FutureAGI《Advanced RAG Chunking 2026》2026-05-14 + AI Workflow Lab + 博客园《RAG 文档切分》2026-05-08 实拉）：**切块选择按语料类型（技术文档/客服 Q&A/法律合同各异），固定大小=最后手段不是默认**；**语义切块=嵌入相似度变化点（段落/句级语义转移检测器），适合长文自然语言源，ingestion 慢（每句嵌入）+块大小不一致（50-2000 token）且对多数文档类型提升 marginal；parent-child=小块召回大块上下文（两种粒度都存，ParentDocumentRetriever）；RAPTOR 层级树=多跳长文档；句子级+窗口=保句单位加跨句上下文（spaCy/NLTK）**；**固定 512/1024 token 适用=日志/流水记录/无结构长文本/粗粒度全文搜索；不适用=合同/政策/FAQ/技术文档/代码/表格**。提升层：工作流。

**4. Contextual Retrieval+Late Chunking 双技术**（来源：AI Wiki《contextual retrieval》2026-06-07 + Mixpeek《Chunk Contextualization》2026-06-17 + arXiv《LATE CHUNKING》2409.04701 实拉）：**contextual retrieval（Anthropic 2024-09）=每 chunk embedding 前用 LLM 写短情境描述（属哪文档/哪节/指代哪些实体）prepend 到 chunk——"The company's revenue grew 3%"单独成 chunk 会丢上下文**；**late chunking（Jina 2024）=先整篇用长上下文 embedding 模型过 transformer，token 级 embedding 后再切块 mean-pooling——块向量含全文档信息（jina-embeddings-v3 late_chunking=true 参数）**；**两技术合用 cut retrieval failure 35-67% vs naive fixed-size（Anthropic 基准；法律/技术规格语料 70-80%），成本 50 美分/千 chunk**；**局限=late chunking 只在单文档内有效，跨文档关系捕获不了（跨文档用 topic-aligned chunking 或 GraphRAG）**。提升层：工具。

**5. 查询重写工程（多轮 RAG 关键）**（来源：ACL SemEval-2026 Task 8 多系统 + arXiv《EviReform》2026-08 实拉）：**多轮对话查询重写=把上下文依赖的 utterance 解析指代/省略成 standalone query——检索提升 ~10%**；**双通道=最后用户轮原文（保留表面措辞）+LLM 重写（解隐式约束减歧义）合成为检索 query；重写模型=小可训练模型足够（Qwen 1.5B 4-bit 量化或 0.6B）；重写提示模板显式要求"解决指代、恢复隐式实体、强调域术语"**；**多样性重写=生成五种互补改写各针对不同失败模式（Minimal 解指代/Corpus-Specific 域术语/HyDE 假想文档）+嵌套 RRF 合并**。提升层：工作流。

**6. Reranker 选型 2026 矩阵**（来源：GGUF《Top 20 Reranker 2026》2026-08-04 + Local AI Master《Cross-Encoders Guide》2026-05-02 + Python Data Bench 2026-09-04 实拉）：**默认=BGE-Reranker-v2-M3（通用/多语/全支持）；速度=Jina Reranker v3.5（listwise scoring 每次查询可负担）；质量=Qwen3-Reranker-4B/8B 或 BGE-v2.5-Gemma2（推理重检索）；精度=ZeroEntropy zerank（多项 2026 leaderboard 榜首）**；**cross-encoder=query+doc 联合过 transformer 全交叉注意力（比 bi-encoder 准但 O(n)/query）；ColBERT late-interaction 中间态（latency 优于 cross-encoder、准确高于 bi-encoder）**；**实测=加 reranker 是单次最大质量跃升（+18 NDCG@10）**。提升层：工具。

**7. RAG 评估三指标+变异测试+金丝雀非对称评分**（来源：Deepchecks《Evaluating RAG》arXiv 2026 + arXiv《Knowledge-Gap Canaries》2608.26385 + Microsoft《RAG evaluators》2026-06-03 实拉）：**RAGAS 三指标=faithfulness（回答忠实于上下文）/answer relevance（回答相关查询）/context relevance（上下文匹配查询）**；**知识变化变异测试（metamorphic）=对 28k mutants 违规率 4.9-10.2%，oracle F1 0.927-1.000 vs 最佳 RAGAS 0.570——知识库更新后必须重测**；**金丝雀非对称评分=Q=Pr[correct]-k·Pr[wrong]（k=4）：正确 +1、错误 -4、弃权 0——惩罚幻觉鼓励"不知道就说不知道"；Microsoft 双评估器=有 ground truth 用 Document Retrieval（Fidelity/NDCG/XDCG/Max Relevance/Holes），无 ground truth 用 LLM judge 1-5 阈值**。提升层：工作流。

**8. 三档路由架构+CA-RAG 成本效用**（来源：Rag About It《5 Strategies》2026-05-03 + eCorpIt《Agentic RAG costs 2.5x》2026-07-28 + arXiv《Cost-Aware Query Routing》2606.02581 实拉）：**三档=①语义缓存（hash 查 Redis，命中零 embedding 零 LLM）②简单查询→便宜模型（Haiku 3.5 $0.80/$4 per M，1/8 Sonnet 成本）③复杂→高配模型/agentic**；**分类器路由（T5-Large 训复杂度标签）三分路由匹配 always-expensive 基线但成本大降；CA-RAG=按查询从策略目录选（无检索直推→top-k=10），效用=质量估计-延迟惩罚-计费 token 惩罚**；**先分类再路由到最便宜能答的路径=杀 Retrieval Tax；SchemaRouter 实证=planning-level over-fetch 过度优化反效果（减字段数掉到 0.56 准确率，召回保留投影才恢复）**。提升层：工作流。

**9. GraphRAG：知识图谱+层级社区摘要**（来源：Microsoft Research《GraphRAG》+ 腾讯云《什么是 GraphRAG》2026-09-21 实拉）：**GraphRAG=LLM 从非结构化文本抽实体关系建知识图谱+层级社区检测+社区摘要——回答跨文档/主题抽象问题（"数据集里的顶级主题是什么"）远超向量 RAG**；**Graph-augmented RAG 五步=向量检索→图遍历（citation/causal/组织层级边）→语义重排→RRF 融合（平衡语义相关与结构重要）→LLM 生成；CosmosAIGraph OmniRAG=按用户意图动态选 DB 查询/向量匹配/图遍历**；**判据=跨文档关系/多跳/主题综合问题用图，单文档事实用向量；图提取成本高（LLM 抽实体关系）**。提升层：工作流。

**10. 会话 RAG 记忆四层分类**（来源：Wicked Smart Data《Stateful Multi-Turn RAG》2026-09-23 + vc.ru《记忆与 RAG 区别》2026-05-20 + 本体引导记忆论文 实拉）：**四层=Short-term（当前会话最近交互，工作记忆）/Long-term（跨会话推理，episodic）/Entity memory（命名实体：客户/产品/事件+出现上下文"turn N 讨论过 X"）/User memory（用户偏好，Mem0 类）**；**stateful 三件套=query reformulation（带历史重写）+滚动历史压缩（sliding window+summary）+session memory（会话级 DAG 持久化推理与证据）；用户记忆与知识库分离层=用户记忆管历史偏好，知识库存产品文档/FAQ 供检索**。提升层：工作流。
