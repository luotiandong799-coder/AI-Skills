## 独点（10）

**1. 记忆框架选型矩阵 2026**（来源：mem0-state + mcp-directory + cognee-open-source + anhtu-letta 实拉）：**Mem0=工业成熟、快/便宜检索、实体链接（spaCy）写进平行向量子集合并入排序、图 DB 可选，分数 LoCoMo 92.5/LongMemEval 94.4/BEAM-1M 64.1、检索 <7K token/查询，风险=记忆治理（cloud 依赖）**；**Zep/Graphiti=时序知识图谱（31.2K stars）、每条事实带 validity window（何时为真 vs 说过什么）、被覆盖事实 invalid_at 不丢历史、时序推理场景 graph beats vector（如"三月份我对用户 X 知道什么"）**；**Letta=self-editing memory blocks+sleep-time compute（74% LoCoMo）、2026 新增 Letta Code+Skill Library+Git 版本化记忆（memory-as-code 趋势）**；**Cognee=唯一 graph-native 框架+ECL（Extract-Cognify-Load）管道让记忆成为主动自改进层**；**Hindsight=before_run/after_run hooks 注入/持久化**。判据=静态偏好与近期上下文选 Mem0（快省 token）、长运行对话图演变选 Zep（时序付费）、记忆要可版本化回滚选 Letta。提升层：工具。

**2. 记忆基准三件套 2026 + LongMemEval-V2**（来源：mem0-benchmarks + benchd + scale-icml-lme-v2 实拉）：**LoCoMo=长对话问答、LongMemEval=跨会话（时序/多会话/知识更新/单助手五类题）、BEAM-1M/10M=生产规模记忆（百万 token 上下文）——三者互补成 2026 记忆评测事实标准**；**LongMemEval-V2（ICML 2026 oral）=多模态 web agent 轨迹的环境经验回忆（451 手工题，interface affordances/workflows/state dynamics/recurring failure modes），评测"系统能否积累环境特定经验"**；**分数参照=LLM 基线无记忆 57.6%、LangChain/LlamaIndex 框架级 59%、专用记忆系统 90%+——框架默认记忆≈无记忆**；**评测口径注意=benchd verified vs 厂商 self-reported 分开看**。判据=选记忆方案先看其在三类基准的 verified 分，别信厂商自报。提升层：可复用 Skill。

**3. 记忆架构三分层：向量/图/关系型各司其职**（来源：atlan-agentic-memory + agentled-vector-vs-graph + zylos-agent-native-data + cognee-agent-memory 实拉）：**episodic 层=向量库做快速相似查找、semantic 层=图谱做实体关系多跳遍历、state 层=关系/事务存储处理进行中状态与并发写协调——向量库是记忆层的组件不是替代品**；**向量检索"语义相似的事实"，图检索"通过关系连接的事实"（Project:Alpha 依赖问题=向量返回提到相似词的事实、图遍历沿 typed edges 全列依赖）**；**向量失败模式=精确 ID/多跳/矛盾/时间四类（silent staleness：在过期数据上流利作答）；图失败模式=ontology drift（schema 变更后查询失效或误导）；有治理的元数据图=完整覆盖全数据资产但依赖摄取管道健康**。判据=先想问题类型：模糊语义→向量、实体关系/时序→图、并发状态→事务存储，别让一个存储扛三类。提升层：工作流。

**4. 记忆写回协议：每轮四步+选择性持久化+五分类更新判定**（来源：eroncavalcante + baylabs + levelop + atlan-implement 实拉）：**每轮循环=retrieve before reasoning→LLM call→store new exchange（回合末蒸馏持久价值：摘要/新事实/任务结果存 embeddings，别存一切）**；**write selectively=持久 durable facts/decisions/preferences 不存原始记录、长对话合并为一条干净事实；metadata=source/timestamp/confidence 便于过滤与过期；按 user+project 分作用域防租户间泄露**；**响应后五分类更新判定=add new fact/merge existing/update stale/delete outdated/ignore——append-only 记忆退化快，保留冲突信息（旧 deadline vs 新 deadline）必然产出矛盾**；**writeback 前加 review 步骤（signed-write 模式），写路径与读路径同样安全敏感**。判据=记忆系统要"更新判定"不只是"追加判定"——不会更新/删除的记忆三天就自相矛盾。提升层：工作流。

**5. 记忆合并四模式+异步合并不阻塞**（来源：arxiv-auto-dreamer + recmem + clawrxiv + zylos-episodic + channel-async 实拉）：**四合并策略对比（90 天模拟 27 agents）=recency-only/frequency-only/surprise-weighted/sleep-replay（海马回放）——surprise-weighted 保留 91.4% 最优**；**Auto-Dreamer=离线合并器把选定区域当只读证据、bounded tool-use 检查条目与来源轨迹、合成紧凑替代集跨会话抽象并取代旧条目**；**RecMem 三层=subconscious 原始交互单元（低成本检索）/episodic 事件叙事/semantic 细粒度事实——只在新的交互与潜意识层找到足够相似历史时才触发高层合并（合并时机是关键设计）**；**异步合并（MAGMA slow path/SCM sleep cycle/Anthropic Dreaming）=从不阻塞交互、幂等可重试——交互延迟不可恢复，合并可重试，绝不在响应路径上跑 LLM 记忆结构化**。判据=合并是后台进程不是响应路径的一部分；surprise-weighted 比 recency/frequency 保留更全。提升层：工作流。

**6. Anthropic Dreaming 异步合并模式**（来源：channel-async-consolidation + zylos-episodic + anhtu-letta 实拉）：**post-session async consolidation 是多数 agent 记忆栈缺失的一层；Harvey 实测 6× 提升**；**合并排除项=天气/闲聊/会话级客套/agent 表达不确定的事实（low-confidence 不入语义）**；**实现要点=session 结束后异步跑合并进程、合并结果写回语义层供下个 session 检索、与 wb-context-compressor 的"日志→长期两级沉淀"同构但专用于 agent 记忆栈**。判据=每次会话结束都有一次"睡眠式"合并，而不是只在窗口撑满时压缩。提升层：工作流。

**7. 记忆安全 ASI06：五层防御+Agent Memory Guard**（来源：owasp-agent-memory-guard + vectorize-memory-poisoning + owasp-ast10 + selina-memory-namespacing + al-ice 实拉）：**OWASP Agentic AI Top 10 将记忆投毒列为 ASI06（区别于 LLM Top 10 的独立攻击面）——Agent Security Bench 最高平均攻击成功率 84.30%**；**五层防御=write-time input controls（写路径信任评分，外部数据源先过验证门）/memory sanitization with provenance（每条观察带来源元数据）/trust-aware retrieval（低信任条目权重衰减）/scope isolation（按 user/task/domain 分命名空间防交叉污染）/behavioral monitoring（异常写监测+回滚能力）**；**Agent Memory Guard=OWASP ASI06 参考实现（runtime 防御层）**；**避免自动 re-ingest agent 输出进受信记忆；temporal decay=旧且未验证条目检索权重低；OWASP AST10=任何 skill 写 MEMORY.md/SOUL.md 先隔离验证再 commit（签了名+信誉干净的 skill 安装后仍可投毒）**。判据=记忆是可写状态=攻击面——写入路径按安全敏感处理、检索把记忆当不可信输入。提升层：可复用 Skill。

**8. Embedding 模型迁移：双写+回填+lazy 按需**（来源：aws-backfill + ai-tldr-migration + knowmina-lazy + tianpan-reindex + topperblog-versioning + devlery-mongodb 实拉）：**标准迁移流程=旧索引继续服务→开 dual-write（新文档双模型双索引，冻结增量为零）→后台 backfill（百万级记忆数天+消耗 embedding 配额）→切换流量**；**lazy migration=按需 re-embed（版本化 embedding metadata，冷行检索空结果直到被 touch）——避免一次性计算峰值，适合低流量个人部署**；**MemClaw 两级=eager backfill CLI 幂等可重跑（先 dry-run 估范围）/lazy 零动作**；**MongoDB Atlas Automated Voyage AI Embeddings=文档写/更新时自动生成 embedding（消除外部 embedding 服务调用+队列+worker+sync job+vector store 更新路径这些 brittle 活动部件——故障面收敛）**；**选 embedding 模型要慎重=换模型要重嵌入全语料，昂贵且永久影响**。判据=迁移永远双写先行、回填后台跑；能收敛的活动部件（自动 embedding）优先收敛。提升层：工具。

**9. 记忆进模型：parametric memory 趋势**（来源：developersdigest-memory-into-model 实拉）：**Memory Decoder at Scale（arXiv 2607.27919）=6.9B 参数长期记忆模块 300B tokens 预训练，410M 基座+6.9B 记忆模块胜过 12B 基座（37.34 vs 37.24，17 基准平均）——参数记忆有规模定律不是 demo**；**趋势=记忆从外部存储（向量/图/DB）向模型参数迁移；分工=外部记忆可更新/可审计/可治理，参数记忆低延迟高容量——生产栈两者互补**。判据=跟踪参数记忆基准，但生产记忆仍以外部分层为主（可审计优先）。提升层：模型。

**10. MCP 记忆服务工具形态（local-first 三形态）**（来源：local-memory-mcp + m3-memory + mneme-lobehub + memclaw-lobehub 实拉）：**local-memory-mcp=单 SQLite 文件+stdio、无服务器无账号无 API key、数据不出本机——零 infra 记忆层**；**M3 Memory=100+ MCP 工具（conversation grouping/refresh lifecycle/agent registry/handoffs/entity-graph extraction/files-memory layer 整目录摄取）、hybrid search（FTS5+vector+MMR）、99.2% LongMemEval-S@k=10**；**Mneme=单 Rust 二进制零依赖（--db 指定本地文件）**；**选型判据=local-first 三件套按需取：零依赖单二进制（Mneme）/文件+混合检索全功能（M3）/最简 SQLite（local-memory-mcp）；先验证工具描述无注入再装（呼应 r369B 工具面安全）**。提升层：工具。
