## 独点（10）

**1. 记忆分层认知架构：working/episodic/semantic/procedural 四层+专属存储引擎**（来源：zylos-memory-architecture + survey-2602.06052 + callsphere + superkind 实拉）：2026 共识=认知科学四层：**working=活跃上下文窗口（快/高保真/容量受限）；episodic=时间戳具体记录（"用户 1 月 5 日纠正了日期格式"，tuple=(timestamp, agent_id, user_id, event_type, content, embedding)，存 Postgres/向量库；semantic=蒸馏后的无上下文事实（"用户偏好 DD/MM/YYYY"），知识图谱+向量；procedural=可执行技能与可复用计划（Voyager 把 Minecraft 例程存成可调用 JS 函数按技能索引），实现为工具定义/系统提示/技能文件**；Letta recall memory=可搜索 SQLite/PostgreSQL 全量消息日志、archival memory=向量库长期知识。判据：**"Memory is the agent's notebook, not your knowledge base"——记忆按层选存储，不是一张表存所有**。提升层：工具/工作流。

**2. 记忆价值函数：多因子评分决定写什么**（来源：multi-factor-value-2606.12945 + mem0-eviction + zylos-retention 实拉）：**V(m)=Σwᵢfᵢ(m) 七因子（情绪强度/目标相关性/价值对齐/自我-用户相关性/任务效用/可靠性/使用历史）**，权重从数据学习（认知心理学 value-directed remembering 支撑）；生产简化=**Score=w₁×Recency+w₂×Importance+w₃×Relevance**——Recency=时间衰减（decay^hours_since_access，decay≈0.995/h）、Importance=写时 LLM 或用户信号（thumbs up/"记住这个"/显式 pinning）赋分、Relevance=记忆 embedding 与当前 query 余弦。判据：**salience scoring 把淘汰问题从"什么时候删"变成"值不值得存"——写时无分值的记忆是垃圾输入**。提升层：可复用 Skill。

**3. 遗忘策略四杠杆+自适应衰减**（来源：forgetting-2604.02280 + adaptive-decay-feather + chanl-forgetting + mem0-compression 实拉）：**forgetting policy 四杠杆=importance（决定留不留）/merge（相关记忆合并）/decay（降可召回性不删除）/eviction（真删）**——是存储之上的策略层不是存储特性；**exponential decay 比线性更贴近 Ebbinghaus 遗忘曲线**（30 天前与 300 天前的事实不该同等权重）；**自适应衰减=半衰期+重要性+召回次数加权**，Feather DB 以此在 LongMemEval 超过静态存储；**stale memories cause hallucinations——过期记忆不清理=幻觉源**。判据：**遗忘是策略不是缺陷——decay 与 eviction 分开管，过期事实主动衰减**。提升层：可复用 Skill。

**4. 记忆检索两阶段+rerank：粗召回→精排序**（来源：memtier-2605.03675 + memreranker-2605.06132 + mnemis + redis-agentic 实拉）：**两阶段=Stage 1 语义层 BM25 粗检 top-5 session ID→Stage 2 只在这些 session 范围内加载 episodic 条目精评分**（检索池从全量缩到聚焦子集，防上下文溢出）；**通用 reranker 只靠语义相似度缺推理能力——召回语义相关但没含答题所需核心信息**（MemReranker 三缺陷：相关性分数失真/多轮证据缺失/无关描述干扰）；**Mnemis 双路由=System-1 相似搜索（embedding+关键词 top-k）+System-2 全局选择（LLM 沿类别层级下钻选实体再取连边）→rerank 融合**；cross-encoder reranker 联合注意力打分提升长文档 QA。判据：**记忆检索要两段式+记忆专用 reranker，通用语义 rerank 会漏关键证据**。提升层：工具/工作流。

**5. 上下文压缩四策略+MemRefine LLM 判定**（来源：zylos-compaction + mem0-context-compression + memrefine-2606.13177 + gisting + amp 实拉）：四策略=**provider-native 摘要 API/锚定迭代压缩（持久 section 模板）/外部记忆卸载（MemGPT/Letta/Cognee）/检索增强 episodic 记忆**——生产平台组合使用；**prompt caching 与压缩根本性冲突**（缓存前缀被压缩破坏）；**MemRefine=表面相似度只用于提候选对，delete/merge/preserve 决策交给 LLM judge 按事实内容判定、迭代到预算达标**——相似≠同义，规则基线在紧预算下失准；**Amp 反压缩立场=递归摘要性能逐步衰减（引 OpenAI 内部研究），换线程 /handoff 打包要点审查编辑**。判据：**压缩决策按事实价值不按表面相似——LLM judge 判定优于规则；缓存与压缩二选一要算账**。提升层：工具/工作流。

**6. 记忆投毒防御：OWASP ASI06+写时签名+读时验证+系统提示剥离**（来源：asi06-llm-hacking + smsr-2606.12703 + mind-2607.28103 + memghost + vectorize-poisoning 实拉）：**记忆投毒是延时注入向量——不可信内容一个会话读入、写进长期记忆、干净会话被静默操纵（甚至跨用户）**；MemGhost=单封钓鱼邮件植入持久后门（实测 87.5% 成功率）；命名攻击=MINJA/AgentPoison/Sleeper Memory/Memory Control Flow；**防御：①pre-ingestion scanning（零宽字符/白底白字/零号字体/CSS 隐藏指令，OWASP LLM08）；②SMSR=写时 HMAC-SHA256 provenance 标签+查询时随机消融+多数聚合（可证明鲁棒界）；③信任决策在读取时不在写入时——读时按来源标记（user-issued/tool-output/environment-observed）分级；④Claude Code v2.1.50 具体修复=把用户记忆从系统提示剥离；⑤审计轨迹→SIEM+HMAC webhook+行为异常检测+快照回滚**。判据：**持久状态按不可信输入对待——写时签名、读时验证、可回滚，缺一环中毒不可恢复**。提升层：工作流。

**7. 记忆评测基准：LoCoMo/LongMemEval/PersonaMem+成本对比**（来源：agentmembench-2608.00009 + automem-2606.04315 + graphify-benchmark + streammembench 实拉）：**LoCoMo=多会话长期对话 1986 QA（hindsight 92.0% vs cognee 80.3% vs hybrid-search 79.1%）；LongMemEval=信息提取/多会话推理/时间理解/知识更新四维，历史变长掉点 30-60%（评模型不评记忆架构）；PersonaMem=多选题；AgentMemBench=首个系统比较记忆管理策略而非模型**；实测对比=**AutoMEM LoCoMo 67.3 vs DCI-Lite 45.0（+22.3pp）vs long context 61.5**；graphify LOCOMO recall@10=0.497 vs bm25 0.362 vs mem0 0.048、ingest 成本 ~$1.40 vs supermemory $15.67 vs mem0 $3.48。判据：**选记忆系统看基准分和 ingest 成本两个数——召回和开销一起比，mem0 类向量库在小样本上可能远差于图/混合**。提升层：可复用 Skill。

**8. 图记忆：演化式知识图谱+双路由检索**（来源：sage-2605.12061 + mage-2605.10064 + mnemis + cognee + memgraphrag 实拉）：**SAGE=memory writer 增量建图+Graph Foundation Model reader 检索反馈（自演化闭环，多跳 QA/开放域检索超文档 RAG）；MAGE=四子图共演化（经验子图存教师纠错+学习者正确轨迹）**；**记忆演化三阶段=initial connection formation（新任务快速建跨层联想）→feedback-driven refinement（闭环编辑子图拓扑：补缺边/剪干扰/条件旁路直到执行成功）→long-term consolidation（成功轨迹聚类成稳定 procedural circuits）**；**SUPERSEDES 关系=改变的决定留在图中作历史、标记哪个版本现在生效**（历史可回溯、当前态检索排除已取代）；Cognee ECL=Extract-Cognify-Load 管线（LLM 抽实体关系+共置向量 embedding 的混合图）；MemGraphRAG=共享记忆多 agent 协同建图（动态解决逻辑冲突）。判据：**图记忆的价值=多跳导航+世界模型演化，不是替代向量——关系是头等公民**。提升层：工具/工作流。

**9. 记忆巩固与睡眠机制：Knowledge Seeding 上行蒸馏+Dreaming 合成排练**（来源：language-models-need-sleep-2606.03979 + hebbian-distillation + prateek-dreaming + habr 实拉）：**Sleep 范式=醒来吸收（快速更新记忆模块）+睡眠巩固（短时脆弱记忆蒸馏成稳定长期知识，replay 防遗忘）**；两阶段=**①Knowledge Seeding 上行蒸馏（小我记忆蒸馏进大网络增容量保知识，generalized distillation=on-policy 蒸馏+RL 模仿）；②Dreaming=RL 生成课程化合成数据排练新知识精修旧能力**；工程化变体：**Hebbian Distillation=节点累积权重超阈值 δ_hub 触发，检索 hub+强连邻居让 LLM 合成共同主题抽象成语义条目**；**跨 agent 层面=多个专家 agent 独立收敛的工作流晋升共享记忆、重构记忆而非只追加（剪枝过期/解决矛盾/重复强化高信号条目）**；MEMIT 快权写入→LoRA 慢权巩固。判据：**巩固是周期离线动作不是实时——"日记天天记，档案定期整合"，睡眠期负责提炼与冲突消解**。提升层：工作流。

**10. 编码 agent 记忆实践：CLAUDE.md 是 context 不是配置+auto memory+CHANGELOG 进度文件**（来源：claude-code-memory + karpathy-claude-md + terenceluk + anthropic-long-running 实拉）：**CLAUDE.md/AGENTS.md 每会话开始加载、Claude 视作上下文而非强制配置——要真正阻止必须 PreToolUse hook**（规则只引导，hook 才阻断）；官方指导=**200 行以内、记录 agent 常错、每次反复出错后更新**；两级=根 CLAUDE.md（仓库共享）+本地个人偏好；**auto memory=Claude 自动写（学习偏好/纠正/代码推不出的项目上下文），每会话前 200 行或 25KB 加载**；**CHANGELOG.md 进度文件=agent 的可移植长期记忆（当前状态/已完成/失败方法及原因/关键检查点精度表/已知限制）——失败方法尤其重要，否则后续会话重复踩坑**；Karpathy 四规则=Think Before Coding/Simplicity First/Surgical Changes/Goal-Driven Execution（每条带可套到 diff 的测试句）。判据：**规则文件管"怎么行为"，hook 管"不能做什么"，进度文件管"别重踩失败"——三件套各司其职**。提升层：可复用 Skill。
