## 独点（10）

**1. 结构化输出三档技术选型**（来源：openai《Structured Outputs》2024-08-06 + respan《Structured Outputs vs JSON Mode》2026-05-11 + kanopy《Structured Output Patterns》2026-04-17 + techearl《Reliable JSON》2026-05-18 + thepromptbench《Reliable JSON Guide》2026-07-13 实拉）：**三档=①Structured Outputs（json_schema+strict:true）：采样器推理时约束，输出 token 流对 schema 数学可证合法（100% schema 匹配）——gold standard，OpenAI 专属；②JSON mode（json_object）：只保证合法 JSON 无 schema 强制——legacy，旧模型或无法用 structured 时用；③原生 tool use/function calling（Anthropic tool use strict schema、Gemini response_schema）——参数级 schema 强制；判据=能原生结构化就原生，验证库兜底**。提升层：工具。

**2. 约束解码原理与实现层**（来源：openai《Structured Outputs 技术细节》2024-08-06 + NVIDIA TensorRT-LLM《Guided Decoding》2026-09-26 + AWS《Bedrock Structured Outputs》2026-02-06 + llguidance《1.8.0》2026-09-25 + arXiv《TruncProof》2026-08-28 + guidance-ai 官网 2026-04-19 实拉）：**原理=JSON Schema→CFG（上下文无关文法）→每 token 采样时屏蔽非法 token（动态约束解码——每生成一个 token 后重算合法集，非事前算好）；实现层：OpenAI structured outputs 官方实现；AWS Bedrock=schema→grammar 编译（首次请求更慢）+grammar 缓存 24h+约束生成；TensorRT-LLM 双后端 XGrammar（JSON schema/regex/EBNF/structural tag）+LLGuidance；llguidance≈50μs/token（128k tokenizer）起步开销可忽略；guidance=纯 Python CFG 控制层；TruncProof=LL(1) 解析器近似"完成合法输出所需最少 token"，保证 token 限额下也合法 JSON**。提升层：工具。

**3. 输出校验+修复+重试三层**（来源：ai-tldr《Validate and Sanitize LLM Outputs》2026-06-12 + futureagi《Input/Output Validation》2026-02-17 + llm-output-guard《0.2.0》2026-10-02 + outputguard《2.1.2》2026-09-27 + instructor《max_retries》2026-03-04 + devopsboys《Instructor+Pydantic》2026-06-14 实拉）：**三层顺序=修复（repair 先行，免模型调用）：json_repair 启发式补缺逗号/未转义引号/截断补全；重试（retry）：把验证错误注入新 prompt 让模型自纠（"你输出 X 但校验失败因 Y，请修正"——带具体错误 vs 无脑重试）；升级（escalate）：fallback 值或人工；库=Instructor（Pydantic 校验失败自动注入错误重试，max_retries 默认 0 必须显式设）/Pydantic AI/outputguard 15 修复策略/llm-output-guard schema 无关；实测=首轮约 8% 响应不过校验，带具体 Pydantic 错误重试后二次失败率 <1%**。提升层：工具/可复用 Skill。

**4. 重试参数与失败分类**（来源：zalt《Non-Deterministic AI Reliable》2026-06-28 + clarion《Resilient Pipelines》2026-05-06 + theneuralbase《Retry and Error Handling》2026-04-22 + ai-tldr《Handle LLM Failures》2026-06-12 + osvaldorestrepo《Retry Design》2026-05-02 实拉）：**默认 3 次总数（1 原+2 重试）；transient（429/503/超时）才重试——指数退避 1s/2s/4s+jitter 防惊群；逻辑/幻觉错误重试无意义；validation 失败 1 次自纠足够（3+ 次浪费 token 不可恢复错误）；错误反馈必须带具体错误对象非"请重试"；max_tokens 截断要查 finish_reason==length/stop_reason==max_tokens——这是加 max_tokens 不是重试；分层=retry（同 provider 更聪明时机）→fallback routing（换模型/provider）→degraded mode（耗尽后给减载但可用的响应）**。提升层：工作流。

**5. 失败模式分类**（来源：arXiv《Structured Output Control for SE》2026 + tencent cloud《JSON 防御 95%→99.9%》2026-08-11 + aijsonmedic《Repair Guide》2026-07-30 + aitoolsguidebook《Not Machine-Parseable》2026-05-25 + futureagi《Evaluating Structured Output Modes》2026-05-20 + vpawar《Reliable Structured Data》2026-08-25 实拉）：**五类失败按修法分：①截断（max_tokens 太低中段断 JSON——最常见的 remaining 失败，加配额）；②代码围栏/散文包裹（Expecting value line1 col1——剥离围栏）；③结构错误（语法合法但缺 required 字段/类型错/嵌套深一层——schema 校验（Pydantic v2））；④语义退化（最危险：schema 全过但 enum 塌缩到安全默认/数值返均值/幻觉凑数（要 3 个关键词生成 2 真 1 假）——"看起来像成功，出货的是它"）；⑤模型版本自动升级突发失败（几个月正常突然坏——查模型 bump）；另：'null' 字符串 vs null、7 个 bullet vs schema max 5**。提升层：工作流。

**6. Schema 设计原则**（来源：explainx《Structured Output Schema Guide》2026-06-29 + aipromptshub《Schema Design Patterns》2026-06-08 + tensoria《Structured Outputs Production》2026-05-15 + nisai《Structured Outputs Guide》2026-07-14 + 火山引擎《结构化输出》2026-06-27 + bytejson《Schema Tutorial》2026-07-21 实拉）：**①枚举>自由文本（enum 约束精确值，免 'high'/'High'/'HIGH' 漂移，还缩小生成时有效词表提升小模型准确率）；②required 全部字段，optional 用 type:["string","null"] 表达（strict 模式不接受 optional——"填或 null"二选一）；③additionalProperties:false；④description 写格式示例（"ISO 8601 date e.g. 2026-07-14" > 裸 string）；⑤从真实 sample payload 起步再收紧，over-wide schema（一切 string|null）重新引入混乱；⑥判别联合用 discriminated union**。提升层：可复用 Skill。

**7. LLM-as-judge 偏差与缓解**（来源：arXiv《Judging the Judges》2026-08-27 + futureagi《Judge Prompt Engineering》2026-04-20 + ai-tldr《Judge Biases》2026-06-12 + arXiv《Autorubric》2026-08-31 + arXiv《PReMISE》2026-06-01 + arXiv《Rulers》2026-08-25 实拉）：**五大偏差：position bias（成对交换顺序可翻转偏好，首/末选项被多选；~25% 比较是位置驱动）；verbosity bias（长答案赢即使无增量）；self-preference bias（模型奖励自家家族 10-25%）；calibration drift（judge 模型小版本升级 rubric 分数漂移）；prior leakage（ground-truth 参考在 judge 上下文被鹦鹉学舌）；缓解=成对双交换+一致性过滤（同答案两次都赢才算数，翻转丢弃/标 tie）、答案隔离参考；rubric 写作=锁定 rubric+证据锚定打分（引用 sent_id）+边界论证（为何不 +1 也不 -1）+anti-halo 约束（禁止全 trait 同分）；R=5 随机重跑测 rubric 稳定性（flip rate）**。提升层：可复用 Skill。

**8. 评测框架选型**（来源：deepeval《Top 5 Frameworks》2026-07-22 + aiworkflowlab《Eval Comparison》2026-06-03 + codeguilds《Measure What Your Model Does》2026-07-22 + cadence《Best Eval Frameworks》2026-05-24 + scrolltest《DeepEval vs Promptfoo》2026-06-02 + omk-comparison 2026-09-06 实拉）：**按生态与场景选：Promptfoo（MIT，CLI+YAML，21.7k stars）=prompt A/B+红队+CI（GitHub Action 带 PR 评论）——JS/CLI-first 首选；DeepEval（Apache 2.0，pytest 原生，30M+ PyPI 下载）=14+ 指标含 bias/toxicity，CI gate 质量回归可 fail build——Python/pytest 生态首选；Ragas=RAG 专项；LangSmith=托管 SaaS 追踪+eval（$39/seat）；Inspect AI=安全/能力评测+agent 沙箱隔离；lm-evaluation-harness=学术基准；判据=评测跑在 CI 里才最有价值**。提升层：工具。

**9. Eval-Driven Development（EDD）**（来源：qaskills《EDD Guide 2026》2026-06-15 + arXiv《When Better Prompts Hurt》2026 + deepeval《EDD》2026-06-15 + mlflow《EDD Cookbook》2026-03-18 + futureagi《Prompt Regression Testing》2026-03-14 + chirag《Golden Datasets》2026-06-18 实拉）：**EDD=先写评测后写 prompt——把 prompt engineering 从"tweak and eyeball"变成 TDD 式（断言分数阈值非精确输出）；流程=①golden set ~100 条（含预期输出，优先覆盖失败模式非追求量）②定义 3-5 个与表现强相关指标 ③迭代直到全过 ④CI gate 每 PR 跑；prompt 回归测试=pytest for prompts：固定套件对 prompt 版本断言 rubric 下限（Groundedness>=0.85）+对前版分数向量 delta；评测连续管道=发布前离线+高价值路由同步 inline+全 live trace 异步+模拟持续（2026 年评测不再是单次离线 pass）**。提升层：工作流。

**10. 输出侧安全**（来源：balacode《5 Layers》2026-06-15 + respan《Injection Detection》2026-05-22 + stochasticsandbox《Output Filters》2026-03-27 + botmonster《7-stage Defense》2026-05-11 + rapidclaw《Validate Before You Act》2026-04-20 + maxim《Injection Defense》2026-06-02 实拉）：**输出也是不可信输入：①工具调用执行前 schema 校验参数——"注入经 malformed tool call"的后门（参数必须匹配注册 JSON schema，不匹配拒绝并重 prompt；工具调用当 SQL 查询对待：参数化+类型化+allowlist）；②PII 检测=regex+NED（邮箱/电话/SSN/卡号 Luhn 校验 13-19 位/API key 模式 sk-...48）；③system prompt 泄漏检测=输出含 system prompt 子串超相似度阈值（抓"repeat your instructions"攻击）；④refused-then-complied=会话级追踪（前面拒答后面答了=有翻转）；⑤secrets 检测=Gitleaks 222 凭证模式零外呼；⑥URL/markdown 注入=剥离非白名单外域 URL；判据=输出过滤与输入过滤同等对待**。提升层：可复用 Skill。
