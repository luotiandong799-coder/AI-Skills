## 独点（10）

**1. 生产深 agent 运行时八需求-能力映射**（来源：LangChain《The runtime behind production deep agents》2026-04-20 实拉）：**生产要求与运行时能力一一对应：guardrails→middleware、multi-tenancy→认证授权+Agent Auth+RBAC、人工监督→interrupt/resume、实时交互→streaming+并发控制（double-texting）、可观测→tracing+time travel、代码执行→sandboxes、集成→MCP/A2A/webhooks、定时→cron**。判据=选运行时按生产需求清单逐项核对能力表，缺项要自己补层。提升层：工作流。

**2. 生产 agent 部署栈全链路**（来源：Alice Labs《Production AI Agents Deployment Guide 2026》2026-08-03 实拉）：**标准生产栈=durable orchestrator（LangGraph/Claude Agent SDK）+ PostgresSaver 持久化状态 + LLM gateway（缓存+预算）+ Firecracker/gVisor 沙箱执行工具 + OpenTelemetry GenAI traces + 四段发布门（shadow→canary→percentage→full）**；**发布门控与监控栈并行，缺任一环部署就是 demo**。判据=按此栈检查自己的部署：编排器可持久、状态可恢复、模型调用过网关、工具在沙箱、链路可追踪。提升层：工作流。

**3. 自托管 hosting 拓扑三模式**（来源：AgentPatterns《Production Hosting Topology for Self-Hosted Agent SDK Runtimes》2026-07-07 实拉）：**Ephemeral=一容器一任务无会话存储（bug-fix 运行/文档提取/CI 一次性）；Long-running=持久容器+多 SDK 子进程+本地盘+可选 SessionStore 镜像（自主 agent/Slack 机器人持续流量）；Hybrid=临时容器启动时从 SessionStore hydrate（长间隔会话/暂停-恢复研究/客服 agent）**；**硬教训：无 SessionStore 就关容器=丢 transcript——hybrid 模式 SessionStore 强制**。判据=按会话间隔选拓扑：任务间无间隔用 ephemeral、连续流量用 long-running、长间隔/暂停恢复用 hybrid。提升层：工具。

**4. 发布四阶段门+门控指标**（来源：FutureAGI《Agent Rollout Strategies 2026》2026-05-20 + cordum 实拉）：**Stage1 Shadow=100% 镜像零用户影响，门控=per-rubric 分布 24-72h 内差 ≤1 分；Stage2 Canary=1-5% 实时流量分层，门控=containment×(1-FalseResolution) 在基线噪声底内；Stage3 Percentage=10/25/50% 实时，门控=per-rubric deltas 在 7 天基线上 Welch's t-test p<0.05；Stage4 Full**；**写操作/工具调用的 agent 配对 policy simulation+幂等重试+审批**。判据=每个门控都必须有数值指标+回滚触发条件，不许靠"demo 感觉"。提升层：工作流。

**5. durable agents 平台四家**（来源：Cloudflare Workflows 2026-09-29 + Microsoft Durable Extension + AWS Lambda durable functions + Vercel Workflows 实拉）：**Cloudflare Workflows=每 LLM/tool 调用成一个 step（自包含独立可重试），任何 step 失败自动重试、整个 workflow 崩溃从最后成功 step 恢复；waitForEvent() 可暂停数小时/天等人批（人工审批场景）**；**Microsoft Durable Task Extension=注册 agent 即自动 durable（持久会话+内置 API 端点+分布式扩展，agent 逻辑零改动）**；**AWS Lambda durable functions=两个模式：callbacks for HITL 审批+异步 agent 调用、polling 长外部任务**；**Vercel Workflows=framework defined infrastructure（部署时自动推断配置）**。判据=长任务 agent 必须 durable：崩溃从最后成功点续跑，不重跑已完成步骤。提升层：工具。

**6. checkpoint 状态管理三原则+CRAB**（来源：AWS Well-Architected AGENTREL03-BP03 + OpenLegion + arxiv CRAB 实拉）：**三原则：自然边界持久化（每节点/工具调用后存 durable storage——in-memory dev/SQLite 小规模/Postgres 生产）、每步幂等（重放同输入同结果）、executor 自定义状态用 OnCheckpointingAsync/OnCheckpointRestoredAsync 回调**；**CRAB=语义感知 checkpoint/restore 运行时（沙箱 agent 累积 OS 状态，高效 C/R 支持故障恢复+抢占式 spot 实例省钱+RL Tree GRPO 复用快照）**；**ScyllaDB=持久性是默认不是配置开关（每写即落盘）**。判据=长工作流无 checkpoint=每次失败付全量重启成本；checkpoint 间隔=自然边界（文档处理后/用户决策后/工具调用后）。提升层：工作流。

**7. 沙箱隔离谱系选型**（来源：GKE Agent Sandbox + Red Hat layered sandboxing + Windows MXC + Azure Container Apps + agentic-ai 实拉）：**gVisor=拦截 syscall 防容器内逃逸升级到集群（共享内核策略强制）；Kata Containers=每 pod 独立 kernel（硬件虚拟化 VT-x 隔离边界，内核漏洞不跨 pod）**；**Red Hat OpenShell 两模式：whole agent in sandbox（agent 进程+工具+代码全在边界内、无凭证、仅经策略代理出网——适合开发机/CI 有真凭证场景）vs sandbox as execution environment（agent 脑在外、工具执行进沙箱）**；**Windows MXC=策略驱动执行层抽象进程/会话/微VM/容器隔离（开发者声明 agent 可访问什么，OS 负责执行）**；**Azure Container Apps Sandboxes=microVM+预热池+多租户隔离**；**选型矩阵=本地 Docker Sandbox（brew install docker/tap/sbx 微VM 免 Docker Desktop）/E2B（SDK 云原生）/Daytona（stateful 快照+专用 kernel）/Modal（GPU/ML 推理）**。判据=按信任级别选隔离深度：共享内核策略（gVisor）够则不上 VM（Kata），每多一层隔离多一份运维。提升层：工具。

**8. 限流预算三层+成本速度断路器**（来源：dreaming.press + TrueFoundry + AgentPatterns unbounded-consumption + arxiv AgentRM 实拉）：**三层限流：Layer1 provider rate limits（429 全 agent 一起打）；Layer2 应用内（max iterations/cooldown/circuit breaker per agent per task）；Layer3 基础设施预算上限（花光即停，比时间限流更鲁棒）**；**cost-velocity breaker=spike detection：单请求成本超工作负载均值 50-100×（如 $50 vs 常 $0.05）即使无速率模式也熔断**；**四种 bound 互补：per-call token cap（单调用输出）/per-task iteration cap（循环深度如 LangChain max_iterations=15 或 LangGraph recursion_limit 默认 25）/fan-out concurrency cap（并行宽度）/cost-velocity breaker（每分钟美元滚动均值）——单用任一都漏（便宜循环贵调用/贵输入）**；**AgentRM=OS 式资源管理器：token bucket 每模型 API+TCP 拥塞控制式 AIMD backoff+admission control；bounded batch dispatch=N×avg_tokens×price=批成本运行前可预测，N=10 起调**。判据=成本失控四围栏：深度+宽度+单次+速度，四者缺一不可。提升层：工作流。

**9. LLM gateway 2026 矩阵**（来源：dev.to 9 gateways + agentgateway + APISIX + MLflow 实拉）：**LiteLLM=Python 生态事实标准（阿里云 FC 上做 model proxy：单模型 proxy 模式/多模型 load balancing 模式）**；**Bifrost=Go 编译型网关（自托管/VPC/K8s/air-gapped，11µs 延迟 @5,000rps，统一 LLM+MCP gateway 企业治理）**；**APISIX AI Gateway=100+ 网关插件一个网关管 API+AI 双流量（multi-provider proxying+token limits+prompt controls+RAG）**；**agentgateway=语义缓存+token 预算+prompt redaction+推理路由（latency/cost/model-aware 选最暖副本）**；**MLflow AI Gateway=集中管理 MCP servers 访问（agent 连外部工具/数据源时代的凭证与治理中心）**。判据=模型调用全部走网关：路由/故障转移/缓存/限流/成本追踪集中一处，改 provider 不动应用。提升层：工具。

**10. 边缘部署内存优化+量化前沿**（来源：NVIDIA Jetson blog + Edge AI Vision on-device + FreeToken 实拉）：**Jetson 五层软件栈（BSP/JetPack→推理管道→推理框架→量化）内存优化可回收 10-12GB 保精度：BSP 层关图形桌面省 865MB+关网络省 32MB**；**量化=16-bit 训练 4-bit 部署（GPTQ/AWQ 4× 内存降）——难点是 outlier activations，SmoothQuant/SpinQuant 通过重塑激活分布处理；2-bit 及以下模型学的是根本不同的表征不是高精度压缩版（ParetoQ）**；**FreeToken=动态 co-execution 让消费硬件跑 frontier MoE（UC Berkeley+MIT）**；**端侧 LLM 三强=Llama 3.1 8B Instruct/GLM-4-9B-0414/Qwen2.5-VL-7B（SiliconFlow）**。判据=边缘部署先做内存审计（关无用服务）再谈量化；>4-bit 精度优先 SmoothQuant 式激活重塑。提升层：模型/工具。
