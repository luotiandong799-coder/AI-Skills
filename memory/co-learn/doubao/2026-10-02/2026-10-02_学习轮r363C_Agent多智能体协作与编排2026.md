## 独点（10）

**1. 编排模式选型：agent 数×任务动态×容错需求**（来源：aipromptshub 2026-06-21 + qubittool 2026-05-21 实拉）：四模式=supervisor（hub-and-spoke，单控制器路由专业 worker，3-8 agent 确定性工作流）/swarm（peer-to-peer handoff 无中心，客服动态对话）/hierarchical（嵌套 supervisor，15+ agent 企业级）/agent network（完全去中心，共享内存或消息总线）；**选错模式是多 agent 系统贵 3-5 倍的最常见原因**；supervisor 主风险=manager 瓶颈，swarm 主风险=死循环/成本失控。判据：**模式选型=agent 数（3-8→supervisor / 15+→hierarchical）×任务动态（确定性→supervisor / 开放探索→swarm）×容错需求，先选模式再动手**。提升层：工作流。

**2. 编排本质=谁持有 state 和控制**（来源：dreaming.press 2026-07-06 + velsof 2026-05-22 实拉）：supervisor 中心持有计划、每步子结果回中心、中心每跳重读累积 transcript——可读可控但 token 成本随对话增长扇出；swarm/handoff=控制和历史转移给活动 agent；**handoff 太贪婪=Agent A 传完整 12K token 对话给 Agent B，而 B 只需要压缩摘要**——生产 handoff 两坑：传太多（上下文膨胀）与手写摘要丢细节。判据：**交接=传"结构化状态+摘要"不传完整 transcript；中心式可读但贵，对等式省但难控——按可观测需求选**。提升层：工作流/工具。

**3. Handoff 是 lossy 压缩事件：五类退化+结构化交接契约**（来源：usewire 2026-05-01 + agentpatterns.ai 2026-07-07 + harness-engineering 2026-04-02 实拉）：五类上下文在交接边界可预期退化=因果推理/隐式约束/不确定性信号/时间顺序/负空间（"不该有的事"）；退化跨跳复合——管线第 1 个 agent 可靠第 5 个不可靠；**修复不是更大上下文窗口而是结构化交接契约**；结构化 handoff object 胜过 prose summary——prose 静默退化、structured 缺字段时 loud 失败（Pydantic ValidationError）；handoff doc 只带会话独有内容=session intent/对话内决定（含推理，未入 PRD/ADR 的）/未决问题/单一 next action/持久工件引用（接收者直接读）。判据：**agent 交接=结构化契约只传会话独有内容（intent/决定/未决/next action/引用），缺字段 loud 失败，不传 prose 摘要**。提升层：工作流/可复用 Skill。

**4. Blackboard 黑板模式回归：共享状态=bug 的家**（来源：openlegion 2026-06-01 + callsphere 2026-04-23 + agentpatternscatalog 2026-05-31 + yennj12 2026-09-30 实拉）：黑板=共享持久 key-value 空间，多 agent 读写在上面协作（起源 HEARSAY-II 1970s）；三组件=knowledge sources（专家 agent 读状态→做贡献→写回）/blackboard（分层共享结构：低层事实/中层假设/高层计划）/control（选下一个运行的 agent）；两种共享=message pool（人人看人人，AutoGen GroupChat/MetaGPT）/blackboard+订阅（订阅相关事件，Context-Aware MCP/Matrix）——**两者都是多 agent 系统唯一的有状态部分，也正是有趣 bug 的家**；参考失效模式=记忆中毒——一个 agent 幻觉"事实"，其他 agent 读黑板后复述放大。判据：**多 agent 共享状态用黑板（读-贡献-写回）+订阅，且对黑板上写入内容做来源校验防记忆中毒**。提升层：工具/工作流。

**5. 唯一 orchestrator 规则 + LangGraph 显式图**（来源：aiworkflowlab 2026-02-07 + alicelabs 2026-05-23 + ailearningguides 2026-05-06 实拉）：**关键设计规则=必须精确指定一个 agent 为 orchestrator 防协调冲突**——两个 agent 都认为自己在协调→重复工作/矛盾指令/竞态条件；supervisor 是多数生产系统的工作马；LangGraph 显式图执行=确定协调/并行/条件路由，**编排逻辑与 agent 行为分离**——可独立增删演进专业 agent 且保持清晰可审计执行路径；生产状态持久化=PostgresSaver（并发多进程+实例失败存活+标准观测备份），SqliteSaver 只用于单机 demo。判据：**编排器唯一且显式（状态机+LLM 决策选下个节点），编排逻辑与 agent 行为分离，状态持久化用 Postgres**。提升层：工具/工作流。

**6. A2A vs MCP 分工：agent 到 agent vs agent 到工具**（来源：howaiworks 2026-07-20 + mintmcp 2026-09-10 + blog.mcpservers 2026-07-11 实拉）：MCP=agent 到工具/数据源（垂直向下，核心单位=tool call，发现=server capability 协商）；A2A=agent 到 agent（水平跨组织/系统边界，核心单位=task 有状态生命周期，发现=well-known URL 的 Agent Card 描述能力与认证）；**ACP 已于 2025-08 并入 A2A 不再独立**——诚实框架是"MCP vs A2A"不是"MCP vs A2A vs ACP"；2026-04 150+ 组织支持 A2A，官方 SDK 覆盖 Python/JS/Java/Go/.NET/Rust。判据：**协议分工=MCP 管"作用于世界"（工具层）、A2A 管"两个决策者协作"（任务层）；跨框架互操作用 A2A，单 agent 接工具用 MCP**。提升层：工具/工作流。

**7. 多 agent 成本失控：深度限制+硬预算+对账**（来源：futureagi 2026-05-22 + nasscom 2026-06-23 + dev.to 826 线程事件 2026-09-27 实拉）：**编排深度无界=一个粗心顶层请求 spawn 几十 worker**，token 消耗指数乘；硬步骤预算（支持 agent max_steps=12）；每任务/每 agent/每 fleet 硬支出上限（如 $5/会话）由编排层强制——命中即杀进程/撤工具/抛 BudgetExhaustionException 给人工；**826 线程爆炸 $78,000 实例**暴露缺 spawn limits/实时计量可见性/客户端与服务端 token 计数对账；retry storm 昂贵（验证失败重试看似无害）。判据：**多 agent 成本=编排深度上限+每任务/agent/fleet 硬支出熔断+实时计量与双端 token 对账——预算从被动指标变主动安全特性**。提升层：工具/工作流。

**8. 死锁与 ping-pong 防护：消息超时+循环签名检测**（来源：rizz.dev 2026-04-10 + runguard 2026-06-04 实拉）：死锁=两个 agent 互等输出——都"active"无崩溃无错误，只是成本涨零产出；**修复=每个 inter-agent message 设 30s 超时，无响应 orchestrator 重指派任务**；false consensus=reviewer 问 coder 两个都同意错误答案——需独立校验而非互相确认；ReAct tool repeat loop 检测=normalized argument signature（去标点+小写）检测循环——raw string 比较会漏掉"cosmetically different"参数。判据：**编排防护=agent 间消息 30s 超时+重指派；工具循环用归一化参数签名检测；审阅方不能与被审方互相确认**。提升层：工具/工作流。

**9. 多 agent debate 的共识幻觉：同质 debate 不如隔离自纠**（来源：caisconf 2026-07-02 + arXiv 2603.28488 + SELENE（ACL 2026-industry）实拉）：**debate 确实产生 agreement，但该 agreement 是协议内生的——不能当校准的正确性信号**；同质多 agent debate 三失效路径=谄媚顺从（modal adoption 最高 85.5%）/上下文脆弱（peer rationale 破坏先前正确推理最高 70%）/共识崩塌（plurality 投票丢弃已存在正确答案，oracle gap 达 32.3pp）；**隔离自纠（同一模型多次采样多数投票）胜过无引导同质 debate**；SELENE=选择性辩论启动（仅高认知不确定性触发）+证据加权自洽（EWSC）；MAR=分离 act/diagnose/critique/aggregate 减共享盲点。判据：**辩论类提升=先测"共识是否协议内生"；低成本优先自洽采样，必须辩论时异构+选择性触发+证据加权**。提升层：模型/工作流。

**10. Agent 观测：span-per-tick 追踪+会话回放**（来源：mlflow 2026-06-11 + zylos 2026-04-29 + 51CTO 2026-09-30 实拉）：span-per-tick tracing=每离散推理步一个 span 嵌套层次——父 trace 全 agent 运行含子 span 每 LLM 调用/工具调用/记忆读写/子 agent handoff；**会话回放=从存储数据重建完整 agent 执行，不重跑 LLM 调用**——需存每 LLM 请求响应全文（非摘要）/每工具参数结果/每 turn 上下文窗口状态（或可重建的 patch log）/时间与模型参数；record once replay offline（0.93ms 零 API 零成本）；**trace 重放对新模型版本/prompt 变体=受控实验**——可隔离"改 system prompt 是否修复"；prompt tracing 必存 system/user/agent 生成 prompt/tool 响应/记忆注入。判据：**agent 观测=span-per-tick 全量 trace（每 LLM/工具/记忆/交接）+完整请求响应落盘支持离线回放与版本 diff——回放让调试变成受控实验**。提升层：工具/工作流/可复用 Skill。
