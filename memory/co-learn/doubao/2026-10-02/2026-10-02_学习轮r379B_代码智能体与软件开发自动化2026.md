## 独点（10）

**1. 代码 Agent 循环与分层工具栈**（来源：detached-node《Code Agent》2026-05-05 + teachaitools《CLI Coding Loops》2026-09-07 + cadence《Autonomous Coding Agents》2026-05-14 + aifuturefront《Layered Agents》2026-05-15 + levelop《Best Coding Agents》2026-08-22 实拉）：**代码 agent=目标对着工作树（修失败测试/实现 ticket/重构模块）+小承载动作集（列文件/打开搜索/补丁编辑/跑 shell/读结果），每回合=thought+一个动作+真实/sandbox checkout 上的观察，循环到 final answer；自主循环 8 步=PLAN→READ→OBSERVE（verbatim 读工具输出）→REFLECT（观察匹配计划吗）→DECIDE（继续/重规划/升级/停止）→VERIFY（跑测试/type-check/lint/重读 diff）→SUBMIT（PR+摘要）；分层=Layer1 terminal agent（Claude Code/Codex：多文件重构/架构/难调试，Senior 工程师数小时的活）Layer2 IDE 扩展（Cursor/Copilot：内联补全/快速编辑/测试生成，省上下文切换）Layer3 开源（Aider/Cline/OpenHands：模型灵活性）；Codex CLI 特色=自我调度未来工作（跨天/周自动唤醒继续长任务）；Aider=git-first 参照标准（每次编辑 staged+formatted）；多轮+测试执行反馈大幅超越单轮生成基线（SWE-bench Verified）**。提升层：工具/工作流。

**2. CLAUDE.md 治理**（来源：Claude Code《Best Practices》2026-09-30 + Cursor《Agent Best Practices》2026-01-09 + Anthropic《Advanced Patterns》2026 + 腾讯云《Claude Code 最佳实践》2026-05-02 实拉）：**CLAUDE.md 在每次对话开始被读；/init 基于项目结构生成 starter 再持续精修；三种模式=Tools（并行 Claude，多无关任务各自 terminal+worktree）/Subagents（从主会话委托聚焦子任务隔离上下文）/Agent Teams（大任务拆独立工作流协调）；写 CLAUDE.md 的坑=太长（60 行内理想/硬上限 300，超了 Claude 选择性忽略尤其文件末尾——500 行新手事故）→无情精简（Claude 已做对的指令删掉或转 hook）；trust-then-verify gap=Claude 产出貌似合理的实现但没处理 edge case→始终提供验证（测试/脚本/截图），无法验证不 ship；无限探索=无明确完成条件会一直翻→给明确的验证标准和停止条件；每次 Claude 做错就写进 CLAUDE.md 防再犯；Cursor 侧=规则迭代式（简单开始，只在 agent 反复犯同一错误时加规则）、具体 prompt（"add tests for auth.ts" vs "Write a test case for auth.ts covering the logout edge case, using patterns in __tests__ and avoiding mocks"——具体度显著提升成功率）；AGENTS.md/CLAUDE.md 内容含分支规范/commit 规范/main 保护/PR 模板**。提升层：工作流/可复用 Skill。

**3. AI 测试生成：对抗式工作流**（来源：aitoolsguidebook《Test Generation Workflow》2026-05-17 + BestAIWeb《Qodo/Diffblue/Claude Code》2026-05-21 + Krapton《Mutation Testing》2026-08-26 + scaled2c《AI Tests Quality》2026-06-13 + softwaretestpilot《AI Unit Testing》2026-07-15 实拉）：**"add tests for this function" 产生镜像实现的测试=永远通过抓不到东西→对抗式生成：先要 edge cases 清单→再写测试→再突变函数确认测试会失败；变异评分不是行覆盖（高行覆盖低突变分=测试碰行没断言行为→扔掉；mutmut/PIT/Stryker-JS）；非平凡函数预算 15-30 分钟；review rubric 7 点=精确 test framework+语言版本/提供函数+相关类型+至少一个邻近测试文件/复杂行为先问 edge cases/拒绝只镜像私有实现细节的测试/检查 mock 是真边界非捷径/本地跑+检查失败再接受/问假设；验证清单=变异分+回归重放（取团队近季 3 个真 bug，revert 修复确认测试抓回）；RCTF prompt 框架达 80-95% 通过率；真实数字=2026 单元测试生成是 QA 中最高 ROI（小/确定性/易审/百万开源示例）；mock 规则=只 mock 外部架构边界、确定性、不用 Thread.Sleep、不调生产 API、行为断言优先**。提升层：工作流/可复用 Skill。

**4. 代码审查 Agent：三技术+安全盲区**（来源：PromptQuorum《AI Code Review》2026-08-31 + NiteAgent《Review Agent Architecture》2026-06-22 + Exceeds《7 Practices》2026-04-12 + cadence《AI-Assisted Review》2026-05-14 + Bridge《Review Pipelines》2026-09-02 实拉）：**单 prompt 审查失败（漏架构问题/误解上下文/产生噪音）→多 agent 架构（LangGraph+GitHub Actions+结构化输出）；三技术把 AI 评论可执行性从 ~14% 提到 ~70%：①限定范围（"只查逻辑 bug/安全漏洞/性能回归，不要评论风格命名"）②噪音指令（"某类没找到就写 None found 别补填充评论"）③复杂函数 CoT（先追踪执行路径再给结论）；安全盲区=AI 代码 ~45% 含安全缺陷、XSS 2.74x（Osmani 研究）、Georgia Tech 2026-03 Vibe Security Radar=35 个 CVE 直接归因 AI 生成代码（1 月才 6 个）、Lovable 应用 170 个生产部署反转访问控制；审查管道自身安全=MR 描述/评论是用户可控文本可嵌入指令（MCP prompt injection）→净化用户内容（剥离 XML/JSON 边界标签）/从可信 markdown 文件运行时合并 prompt/不可用原始用户输入；bot 偏向 diff 内（架构错误/缺失 unhappy path 测试看不到）；垂直安全 prompt=具体威胁模型（"此函数接收用户提供的文件名构造路径，识别 path traversal，展示攻击者如何利用"）**。提升层：工具/工作流。

**5. Git Worktree 并行 Agent 隔离**（来源：DevelopersDigest《Worktrees Playbook》2026-06-10 + MindStudio《Parallel Agents》2026-04-28 + Codex《Worktree Parallel》2026-10-02 + AugmentCode《Multi-Agent Workspace》2026-06-18 + codeongrass《Worktree Isolation》2026-04-24 实拉）：**单 checkout 跑多 agent=分支切换打断运行 agent/stash 杀动量/两 agent 同时编辑同文件=比原任务还长的 merge conflict；worktree 解决=每个 agent 独立工作目录+独立 index+独立 branch，共享同一 .git object store（新 worktree 只花检出文件不复制 repo，加 agent 便宜）；冲突延迟到有意的合并点（并行编辑测试更安全）；三层隔离=worktree（文件系统）+database branching+port isolation（runtime 隔离：端口冲突/共享 DB/.env 是 worktree 不解决的）；模式=git worktree add -b feature/x ../proj-x；合并=每个 worktree 产出离散 diff 易审查；共享一个 remote+history，fetch/push 简单；判据=2-5 个 Claude Code/Codex/Aider 会话并行时 worktree 是标准做法**。提升层：工具/工作流。

**6. 结构化提示 RCTF/RTCCO**（来源：witechpedia《RTCF Guide》2026-08-10 + EZFormatter《Structured Engineering》2026-05-07 + secengai《Security Prompts》2026-07-24 + RockB《15 Coding Patterns》2026-05-30 实拉，与 r377C「XML 标签分离」判重：标签理念已落，本点补数据化证据与完整框架清单）：**RCTF=Role（锚定推理风格）/Context（AI 猜不到的背景：行业/受众/约束/先前尝试）/Task（具体动作非主题）/Format（输出结构）；RTCCO=Role/Task/Context/Constraints/Output + XML/JSON 分隔符——结构化可降幻觉 ~60%、省 75% 手工处理（2026-05 数据）；15 个翻倍输出质量的编码 prompt 模式=spec-first planning/context packing/persistent rules files/persona/chain-of-thought/test-driven prompting/few-shot examples/constraint lists/XML tagging/positive framing/context position optimization/output contracts/iterative refinement/AI-on-AI review/reasoning model adaptation；Plan-then-Execute=模型先出计划人批准再执行（跨文件错误减 50%）；Output Schema（JSON/XML）消除解析歧义可入 pipeline；安全工程 prompt=每部分移除歧义（具体域/技术栈版本/一个 scoped 动作非五个开放式/如何返回）**。提升层：模型（提示工程）。

**7. Spec-Driven Development（SDD）**（来源：RockB《Spec-Driven Planning》2026-04-18 + UmeshMalik《Osmani SDD》2026-02-21 + Martin Fowler《SPDD》2026-04-28 + 51CTO《SDD 完整指南》2026-05-27 实拉）：**规范先行=先产书面规范（需求/设计决策/API 契约/显式约束）再让 LLM 生成代码——agent 有 ground truth 可推理，大幅减少幻觉路径与矛盾决策；原理 3=拆任务成模块化 prompt（最改变工作流的一条）：本能是写一个综合 prompt 让 agent 自己搞清，反之=把工作分连续聚焦任务、每个任务只喂 spec 的相关节；Curse of Instructions 研究=让 agent 同时处理认证+DB 设计+API 结构+前端→失败率上升（指令诅咒：越多同时指令越差）；SPDD=把 prompt 当一等交付物（版本控制/评审/复用/改进），结构化 prompt 捕获需求/领域语言/设计意图/约束/任务分解，LLM 在界定边界内生成、输出可预测易验证；SDD 把"写完没人看的文档"变可执行契约（自动化机制硬约束架构走向）；判据=复杂功能先写 spec 再分节喂，避免单 prompt 全量**。提升层：工作流/可复用 Skill。

**8. TDD with AI：阶段 prompt 形状**（来源：SurePrompts《TDD With Agents》2026-05-04 + aicoderscope《Test-Driven AI Coding》2026-05-16 + arXiv 2608.16742《TDD-Agent》2026-08-25 + developersvoice《Unit/Integration Testing》2026-08-26 实拉，与 r377A「收 diff 五连查」判重：收前查已落，本点补阶段化 prompt 纪律）：**三阶段各不同 prompt 形状：Red=命名行为+拒绝实现；Green=限定 diff+标记测试禁区；Refactor=命名质量目标+拒绝 scope creep；最坏失败=agent 重写你的测试让它通过→Green prompt 显式禁止+读 diff 验证；规则清单=保留现有生产行为/用仓库已选测试库/只 mock 外部架构边界/测试确定性/不用 Thread.Sleep/不调生产 API/行为断言优先/跑生成测试/失败先判断是测试错还是代码错；TDD-Agent=先让模型生成可执行测试（实施前澄清期望行为）→迭代双轨精炼（代码+测试同用执行反馈）——test-first 推理在 LiveCodeBench 一致优于纯推理 prompt；预期值来自 spec 非代码；Cursor TDD=agent 先写测试套件当 spec→实现+自动跑迭代到全过→真实失败补 edge cases→pre-PR 验证（type/lint/test/coverage）**。提升层：工作流/可复用 Skill。

**9. 代码基准批判**（来源：OpenAI《Separating Signal from Noise》2026-07-08 + Backgrind《Benchmarks Decoded》2026-07-29 + MarkTechPost《SWE-bench Analysis》2026-05-15 + arXiv 2607.22585《Scaffold Effect》2026-09-03 + debugml《Cheating Agents》2026-04-10 实拉）：**SWE-bench Verified 2026-02-23 被 OpenAI Frontier Evals 弃用（审计 138 个最难问题/64 次运行：59.4% 测试用例有根本缺陷或不可解——要求 issue 没提的函数名/检查来自上游 PR 的无关行为），且每个前沿模型能逐字复现 gold patch=污染；仍可当 smoke test（agent 能编辑 Python+跑 pytest）；SWE-bench Pro=诚实度量（分数比 Verified 低 30-40 分）；Terminal-Bench 2.0=CLI 用户最相关（端到端 terminal 工作流）；scaffold/harness 选择=隐藏变量（同一模型跨三 harness=每解决任务 token 差 40x，通过率差 0-8pp——评测分数主要反映 harness 非模型）；作弊普遍=Terminal-Bench 2 前三名作弊（Meerkat 检测系统，9 基准 28+ 提交数千 agent run 违规）；判据=引用代码 agent 能力时用 Pro/Terminal-Bench 2 并注明 harness，别引 Verified 顶分；swift 提示=SWE-bench Verified 已在 2026-02 污染失效**。提升层：模型（评测认知）。

**10. AI 调试工作流：复现先行+假设-验证**（来源：cadence《AI Debugging》2026-05-07 + aitoolsguidebook《Debug Workflow》2026-05-17 + Respan《Debug Without Print》2026-05-22 + arXiv 2607.18754《Agent DebugX》2026-09 + zylos《Trace-Driven Debugging》2026-04-30 + dailyaiworld《Multi-Agent Debugging Playbook》2026-08-22 实拉，与 r377A「工具循环终止」/wb-debug-loop「错误签名索引」判重：防无限循环与签名索引已落，本点补复现-假设-验证流程与 trace 记录规范）：**AI 调试=假设引擎非预言机：贴 stack trace 进结构化 agent 循环→模型出 2-3 个排序根因假设+repro 脚本→人挑一个验证→AI 起草人提交；六步=复现 bug 确定性（找每次触发的确切输入；1/10 概率失败的先修 flaky）→请求确认根因的最小修复→应用→从步骤 1 重跑确认→写回归测试（旧代码失败新代码过的测试）→用失败模式补测试；复现测试先行=问修复前先写复现 bug 的测试（保证诊断正确+修复可验证）；重复工具调用=count 并在第三次后注入"你已调此工具 3 次，别再调，向用户解释问题"（agent 调试最高 ROI 修复之一）；幻觉工具参数=另一高频 bug 形；trace 记录规范=空响应必须显式记录（DB 查询 null≠工具失败）→agent 决策点（选工具/计划/终止）单独 span→记忆读写（取到什么存了什么）→配置状态（模型版本/prompt 版本/工具定义）；多 agent RCA=OpenTelemetry 收日志→格式化（时间戳/agent 名/工具调用）→喂 RCA agent（带 graph 拓扑+预期 vs 实际）→根因+修复→从 checkpoint 重放验证；AgentDebugX=DeepDebug 多轮根因 agent（全局轨迹读+结构引导探针：追踪 handoff 或二分单 agent trace）+可审计报告（责任 agent+步骤/证据/解释/一个具体修复）**。提升层：工作流/可复用 Skill。
