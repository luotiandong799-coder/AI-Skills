## 独点（10）

**1. 多模态 Agent 架构三模式**（来源：NiteAgent《Multi-Modal AI Agents in Production》2026-05-25 + Sean Weldon《Any-to-Any Native Multimodal Agents》2026-05-25 + NVIDIA《Nemotron 3 Nano Omni》2026-04-28 + 智源《GLM-5V-Turbo》2026-04-29 实拉）：**模式一=Monolithic（单一 VLM 处理所有模态）：简单、保持跨模态上下文、简单输入最低延迟，但图像重负载昂贵、每模态控制有限；模式二=Specialist Router（生产主流）：路由器按模态分发到专家模型再融合结果——企业级主导模式；模式三=Agentic Function Calling（原生多模态）：Gemini 类原生模型作推理引擎，经 function calling 动态选择专门生成模型而非预定工作流（any-to-any）；2026 趋势=原生多模态（GLM-5V-Turbo 弃 LLM+vision encoder 拼接范式，视觉 token 直接参与 CoT/工具选择/动作 grounding；Nemotron 30B 混合 MoE 单模型原生支持文本/图/视频/音频，Mamba 层管序列记忆+Transformer 层管精确推理）；判据=简单输入单体、多样输入专家路由、需要生成输出选 agentic function calling**。提升层：工具/工作流。

**2. VLM 三层架构与两种视觉注入**（来源：FutureAGI《How Multimodal LLMs Work》2026-05-14 + Anhtu《Multimodal AI 2026》2026-06-16 + BestAIWeb《Multimodal Pipeline 2026》2026-04-21 实拉）：**三层=vision encoder（ViT 切图 16×16 patch）+ connector+LLM backbone——每一层单独规格，边界失败=整体失败；connector 三选项=A 投影（LLaVA/NVLM/Pixtral：两层 MLP+GeLU 映射 patch embedding→LLM token，最常用）/B 交叉注意力（Llama 3.2 Vision：每层"瞄一眼"图像特征，保留文本 token 流）/C Q-Former 类；视觉注入两方式=visual tokens 直接拼接进文本 token 流（简单可扩展最常用）vs 交叉注意力层（Llama 3.2 用）；判据=选模型先查其 connector 类型与输入分辨率上限，Pixtral 用轻量线性投影=更快但表达弱**。提升层：模型（选型）。

**3. 文档理解 Agent：schema-first+置信度路由+验证循环**（来源：Sapirex《Schema-First Design》2026-06-17 + Anhtu《IDP 2026》2026-06-10 + Noqta《VLM Beat OCR》2026-05-31 + IterationLayer《Confidence Routing》2026-04-20 + arXiv 2605.17159《MADP》2026-08-25 + Tensoria《Invoice OCR AI》2026-05-18 实拉）：**六阶段=ingest 归一化（deskew/denoise/split pages+文档分类——错分类级联错 schema，第一要测）→layout parsing（读层：文本/表格/标题/列表）→extraction→validation→confidence routing→consumption；schema-first=agent 处理图像前先有绝对定义的输出 JSON schema（认知锚点），必填字段+嵌套对象；置信度路由=每字段置信度打分，>阈值自动通过、低于阈值标记人工复核（85% 阈值，GPT-4o-mini 处理低置信字段+业务校验=算术检查 net/tax/gross）；MADP 多智能体实测=Direct LLM on PDF 60.0%→+分类器 65%→+分割器 72.5%→+解析器 90%→+验证器+PFTFI 92.5%（20 类）；判据=验证器（validate 结构化输出符合 schema）是文档 agent 的必需组件，不验证不入下游**。提升层：工作流/可复用 Skill。

**4. 视觉 token 计费与缓存成本**（来源：AI/TLDR《Image Token Cost》2026-06-12 + Roboflow《Vision Token Counts》2026-05-04 + TheNeuralBase《VLM Token Cost per Image》2026-04-23 + OpenAI/Gemini 定价 2026-03~08 实拉）：**图像按像素尺寸+供应商 tiling 逻辑换算成 token 计费（不是文件计费）；detail 档位=low（固定低价）/high/original/auto（patch_budget 2500 max_dim 2048 vs 10000/6000）；OpenAI 实测=图像输入 $5/M token、缓存输入 $0.50/M（缓存便宜 10 倍）；Gemini Context Cache Storage 按时计费（$1-4.5/M token/hr）；判据=反复用同一批文档/截图做多轮处理时把图像放缓存（10x 降价），低 detail 只够 OCR/粗看、high detail 才够细读图表；Claude 3.5 Sonnet 2024-10 起从平 $0.30/图改按 token 计（~$0.0006/图）**。提升层：工具（成本优化）。

**5. 视频理解 Agent：多粒度采样+时间戳轴**（来源：arXiv 2606.01631《TimeLogic CVPR 2026》2026-09-18 + arXiv 2605.26680《DynFrame》2026-08-25 + ICLR《FrameThinker》2026 + CVPR《LensWalk》2026 + arXiv 2512.00805《SpecTemp》2026-09-30 + arXiv 2602.04094《VideoBrain》2026-08-30 实拉）：**agentic 视频理解的共性=主动探索取代固定采样；TimeLogic=Think-Act-Observe 循环+多粒度采样工具包（global overview/structured temporal scan/segment skim/dense focus），每个观察带绝对时间戳→时序关系降维成共享时间轴上的数值比较；FrameThinker=两轮 spotlighting（稀疏扫描建泛理解→锁定时间分段→目标 zoom-in 取帧）；DynFrame=把时间窗+采样密度当原生 token 单次自回归发射（帧率自适应从超参数变成可学习决策：短运动敏感事件取密集帧、长程语义取稀疏帧）；LensWalk=reason-plan-observe 闭环（每步指定观察的时间范围+采样密度）；VideoBrain=CLIP 语义检索 agent+Uniform 密集采样 agent 双互补；SpecTemp=轻量 draft MLLM 快速探索提显著帧+强 target MLLM 验证（镜像大脑协作）；判据=长视频别均匀采样，按问题类型路由采样策略**。提升层：工作流/可复用 Skill。

**6. 图像编辑 Agent：迭代循环纪律**（来源：DEV《GPT Image 2.5 Prompt Guide》2026-09-22 + arXiv 2603.29602《IMAGAgent》2026-09-16 + PaperNotes《VisionDirector CVPR 2026》2026-06-18 + arXiv 2605.17969《Generation Navigator》2026-09-24 + fal.ai《Edit Images Like a Pro》2026-06-20 实拉）：**多轮编辑工作流=从强基生成/已批准参考出发→把前次输出作为新输入图→每轮只请求一个变化→每轮重申完整保留清单→检查结果再继续；需要像素级完美的区域=把批准的局部编辑合成回主图（composite）；关键纪律=一条 prompt 塞 5 个请求通常只回 3 个且不告知——一次一改；VisionDirector=training-free VLM 闭环控制器把长指令拆目标→分阶段编辑→验证回滚（R1 式推理循环），GRPO 微调 planner 学会更早 STOP/VERIFY/EDIT（GenEval +7%）；Generation Navigator=Stop（保留满意图）/Refine（原地改局部）/Regenerate（结构有缺陷重启新 prompt）三态决策，PRE-GRPO 分解整条轨迹奖励；MIRA=原子编辑指令+逐步反馈迭代感知-推理-行动；迭代微调=三个短 prompt 优于一个长 prompt（写评语→针对性修）**。提升层：工作流/可复用 Skill（生图提示词默认含负面约束与一致性关键词，模板类图按骨架复用替换）。

**7. 多模态 RAG：Late Interaction 与 MLLM 三角色**（来源：arXiv 2509.18095《MetaEmbed》2026-08-25 + TheNeuralBase《Late interaction with patch embeddings》2026-04-23 + arXiv 2601.03262《Roles of MLLMs in VRD Retrieval》2026 + Google《Gemini Embedding 2》2026-03-10 + EdenAI《Image Embeddings》2026-08-08 实拉）：**late interaction=图像 patch 各自编码成独立向量入库而非融合单向量，查询时找出相关 patch 再融合最终表示（细粒度召回）；MetaEmbed=训练时多向量、测试时弹性 late interaction 缩放（兼顾表达力与检索规模）；VRD RAG 中 MLLM 三角色=Modality-Unifying Captioners（把版式依赖语义转文字）/Multimodal Embeddings（统一空间）/End-to-End Representers；Gemini Embedding 2=首个原生多模态 embedding（文本/图/视频/音频/文档统一空间，100+ 语言，RAG/语义搜索/聚类）；模型=CLIP 仍是基线（最广生态）/SigLIP 轻量/JinaCLIP v2 多语言+Matryoshka；判据=细粒度图像检索（图内找物/局部语义）用 late interaction，整体相似度 CLIP 单向量够**。提升层：工具。

**8. GUI Agent：截图 grounding 与 a11y tree**（来源：Seed《UI-TARS-1.5》+ FreeAITool《UI-TARS-Desktop》2026-08-23 + arXiv 2606.06560《MacArena》2026-08-26 + WalkingLabs《GUI Agent Training》2026-09-15 + fazm《Computer Use Agent》2026-04-10 实拉）：**桌面 GUI agent 范式转变=无法用 DOM 的客户端（CAD/legacy）读原始图形帧（1920×1080~4K），原生截图 grounding；UI-TARS=7B 微调模型直接从截图+指令输出屏幕坐标（click(x,y)/type/scroll/drag），带 CoT 规划；双模型架构（Agent S）=主 LLM 管高层推理+专门 grounding 模型（UI-TARS-1.5-7B）做像素级 UI 元素检测（模块化升级+成本优化）；a11y tree=macOS/Windows 暴露的结构化 UI 层级（元素标签/角色/边界框）免视觉解析——MacArena 观察=截图+可选 a11y tree，有 a11y 时定位更准；判据=有 a11y 树用 a11y+截图，无 DOM 用 grounding 模型；产品=UI-TARS-desktop（38k★）本地推理保屏幕数据不出主机**。提升层：工具。

**9. 语音 Agent：1 秒预算与混合检索**（来源：Finn《RAG for Voice Agents》2026-07-26 + SmartStackDev《Voice Agent Guide》2026-05-17 + Kanopy《AI Voice Agent》2026-04-28 + AWS《Realtime Voice》2026-05-20 实拉）：**硬约束=人感知沉默 ~800ms，>1.2s 开始抢话——ASR→检索→LLM→TTS 整环 ~1 秒预算；阶段分配=ASR finalization 150-300ms+其余压缩；实践=流式 ASR 发部分转写（Deepgram endpointing 300ms/enhanced 模型）、chunk 4KB≈128ms@16kHz PCM（小块降延迟大块提吞吐）、SSE 逐 delta 推送 TTS、barge-in+静音检测+重提示作错误恢复；语音 RAG 加速三件=混合检索（BM25+密集+RRF 融合）非纯向量/预取知识/缓存；状态=内存+Redis 亚秒访问；每阶段单独插桩找瓶颈；判据=语音延迟预算决定了检索结构（混合+预取），保真 grounding 也不许超时静默**。提升层：工作流。

**10. 多模态安全评测：因子化与视觉风险难检测**（来源：arXiv 2608.25490《MMJailBench》2026-09-03 + ACL《USB Safety Benchmark》2026 + arXiv 2603.13385《VisualLeakBench》2026-09-16 + arXiv 2606.23892《ReaLM》2026-08-13 + Semantic Scholar《MIR-SafetyBench》2026-07-01 实拉）：**MMJailBench=因子化基准拆解多模态 jailbreak 来源（有害意图×prompt framing×视觉语义×指令载体四因子受控组合），逐因子查模型拒绝/遵从行为；USB 发现=风险定位（RIRT/SIRT/RIST/SIST 四配置）强烈影响安全率——模型最难检测 RIST/SIST（视觉-only 风险与跨模态风险，文本显式风险相对易识别）；VisualLeakBench=OCR 注入+情境 PII 泄漏审计（1000 张合成对抗图+8 类 PII+50 张真实截图）；MIR-SafetyBench=多图推理安全（2676 实例/9 种多图关系）——发现多图推理更强的模型可能更脆弱；ReaLM=物理世界 VLM 统一红队基准（12 攻击方法+3 模型无关防御统一评估）；判据=多模态安全测的不是单图有害性，而是「单图安全组合后不安全」与「视觉-only 风险」两个盲区**。提升层：模型/工作流（安全评估）。
