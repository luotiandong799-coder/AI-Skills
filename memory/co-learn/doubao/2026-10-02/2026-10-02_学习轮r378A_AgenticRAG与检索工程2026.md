## 独点（10）

**1. Agentic RAG 自纠正循环三模式**（来源：aloknecessary《Designing Self-Correcting Retrieval Loops》2026-06-17 + Microsoft Learn《Develop an agentic RAG solution》2026-07-01 + syncsoft《8-Stage Stack Beats Traditional RAG 2.3x》2026-05-16 + IoT Digital Twin《Retrieval Inside the Agent Loop》2026-07-26 + arXiv 2501.09136《Survey on Agentic RAG》实拉）：**关键架构区别=reflection agent 位于检索与生成之间，有权把循环送回检索改查询，仅在判定累积上下文足够时进入生成；三模式（复杂度递增）=迭代查询精化（单检索工具每轮改查询）/多工具路由（按查询类型选检索工具）/多阶段规划（plan→retrieve→grade→re-plan→retrieve→reason→answer，模型决定每分支）；2026 Systematization of Knowledge 论文把该循环形式化为有限视界部分可观察 MDP——多跳 QA 34%→78%（2.3x lift）vs 单次 RAG；ReAct 模式=receive→reason→retrieve→observe→evaluate sufficient→answer；一句话=标准 RAG 是 pipeline，agentic RAG 是 reasoning loop**。提升层：工作流。

**2. Chunking 四策略与 2026 生产配方**（来源：WebCraft《Chunking Strategies 2026》2026-06-24 + CallSphere《Recursive/Semantic/Late/Contextual Compared》2026-04-24 + Airbyte《Chunking Strategies》2026-06-24 + Stochastic Sandbox《Reliable RAG Systems》2026-04-28 + SuperML《Production Pipeline 2026》2026-06-05 + 阿里云《RAG 性能优化》2026-09-28 实拉）：**fixed-size= MVP baseline 非生产（recall 降 20-74% vs semantic；块从章节标题中段开始又在下一节中段结束=两个主题的嵌合体，检索精度双降）；semantic=逐句嵌入找余弦相似度断裂点（主题转移处切），块大小不一（50-2000 token）阈值敏感；递归=段落边界优先→句边界→行（尊重文档自然结构）；2026 生产最小配方=语义/递归切分+overlap 10-15%+metadata；late chunking=长上下文模型先整文档编码再按块 mean-pool token embeddings（保留文档级上下文，Jina 2024）；contextual retrieval（Anthropic）=块前 prepend LLM 生成 50-100 token 文档感知摘要，top-20 检索失败 -35%~-49%，+BM25+rerank 共 -67%**。提升层：工作流。

**3. 混合检索 RRF 与 rerank 两阶段**（来源：InfoQ《Vector Search Alone Isn't Enough》2026-06-02 + arXiv 2604.01733《BM25 to Corrective RAG Benchmark》2026-08-15 + 腾讯云《混合检索全攻略》2026-04-16 + arXiv 2609.01617《RRF Fusion + KG Expansion》2026-09-03 + ACL SemEval 2606.10381 实拉）：**双路互补=BM25 精确术语/编号/缩写/专有名词/错误码 + 向量同义词/语义；RRF 融合=K=60 典型（S_RRF=Σ w/(K+r)），变长 chunk 大块总超小块需长度调整；两阶段=hybrid RRF 取 50 候选→cross-encoder rerank（query-doc 联合编码，query-aware 相关性，bi-encoder 做不到）取 top-10；三路加权实证=w_v=0.50/w_b=0.35/w_g=0.15（向量/BM25/知识图谱邻居）；生产检索基线=Hybrid Search+Rerank；单路盲区=「苹果2024年03财报」BM25 定位准但不懂语义、向量对缩写极不敏感——都要**。提升层：工作流。

**4. RAG 评测四指标诊断读法**（来源：DEV《Four Core Metrics & How to Read Them Diagnostically》2026-09-17 + Anyscale《RAG Evaluation》2026-07-07 + RAGAS 文档 + Microsoft Learn《RAG evaluators》2026-06-03 + ML Digest《Evaluating RAG》2026-07-10 + mudassirkhan《Metrics That Matter》2026-05-21 实拉，与 r377B「RAG 四指标」判重：定义已落，本点补诊断读法与组合解读）：**四指标回答两问题=retriever 找到对块吗（context precision+context recall）+generator 用对了吗（faithfulness+answer relevance）；faithfulness=答案拆原子声明逐一 LLM-judge 查能否从上下文逻辑推断（Supported/Total，0.6=40% 声明无依据即严格幻觉）；faithfulness 可 100% 却完全 irrelevant（问法国首都答法国是西欧国家）；Precision@k=|Dk∩G|/k、Recall@k=|Dk∩G|/|G|；诊断组合=recall 差→检索问题、faithfulness 差→生成问题、relevance 罚 incomplete/redundant/答非所问；生产四维=检索召回/答案忠实/groundedness/延迟-质量权衡——只测一两个维度=虚假安全感**。提升层：工作流。

**5. Metadata 过滤与权限映射**（来源：AWS《Auto-Generated Filters》2026-08-18 + DataAIHub《Metadata Filtering》2026-07-20 + Wicked Smart《Structured Attributes》2026-09-23 + XBSTACK《Knowledge Base Agents》2026-05-17 + Technovids《Production RAG》2026-06-01 + AI Flow Review《Secure SaaS Search》2026-07-31 + CSDN《RAG 元数据》2026-06-09 实拉）：**两阶段=元数据预过滤（生效日期/文档类型/当事方/自定义字段，每文档 ≤10KB）→语义搜索收窄集合；metadata 字典=chunk_id/doc_id/section_title/parent_headers（标题层级 H1-H3 入 metadata→heading-aware chunking+检索带章节头）/source_url/document_type/division/product_line/topic_tags/access level/version/supersedes/updated_at（增量更新）；多租户 tenant_id 强制=防跨客户 chunk 泄漏（查询前必须匹配）；查询时把认证用户权限翻译成 metadata filter——永不接受未映射权限；高频过滤字段建索引（Qdrant declare index 别假设；Weaviate ACORN 过滤策略在高度选择性 filter 下保 recall）；schema 演化=版本化字段名**。提升层：工作流。

**6. 查询改写多策略互补**（来源：arXiv 2609.05637《Better Together: Complementary Query Rewriting》2026-09-09 + arXiv 2603.10524《SemEval 2026 Task 8 Query Rewriting》+ ACL H-RAG《Hierarchical Parent-Child Retrieval》+ TREC《LLM Reformulation》+ ACM《RAGnRoll》2026-09-08 实拉）：**改写单独最多与强基线打平，组合方法超线性增益——不同策略在不同问题上失败（post-hoc 并集 S1+S3+S4+HyDE 的 HIT@10 +12.5：51.70 vs 39.22）；五改写变体=Minimal（消解指代/省略）/Corpus-Specific（领域术语适配）/Hypothetical Document Embedding（HyDE）/受控扩展（Tip-of-the-Tongue 场景 PRF 无效时用）；多轮改写=把上下文相关话语改独立查询消除 anaphora/ellipsis；改写 prompt 指令=已独立时原样返回（短查询关键）；预检索问题规划=结构化规划给迭代检索语义引导+结构化证据提取滤噪（多跳 QA）**。提升层：工作流。

**7. 文本+表格异构文档 RAG**（来源：arXiv 2604.01733《Text-and-Table Benchmark》2026-08-15 + arXiv 2504.09554《Mixture-of-RAG》+ TableRAG《Heterogeneous Document Reasoning》+ arXiv 2605.01495《FT-RAG》+ arXiv 2601.10215《Topo-RAG》2026-08-26 + Cohere《Agentic RAG for PDFs with Mixed Data》2026-09-13 实拉）：**T2-RAGBench=23088 查询/7318 混合文本表格文档基准，10 检索策略比较——传统 RAG 在结构化表格上欠佳（检索粒度粗+表格语义理解不足）；MixRAG 三阶段=层级行列表示 H-RCL（表格拆成含祖先层级路径的自然语句让 embedding 理解结构化数据）/集成检索+LLM rerank 证据对齐/多步推理 RECAP；TableRAG=SQL 式四步（上下文敏感查询分解/文本检索/SQL 编程执行/组合中间答案）；Topo-RAG=双架构：叙述文本走 dense retriever+表格走 Cell-Aware Late Interaction 保空间关系（SEC-25 合成企业语料 nDCG +18.4%）；FT-RAG=表格拆 entry 级语义单元构图+结构邻居扩展**。提升层：工作流。

**8. CAG 上下文缓存取代 RAG**（来源：arXiv 2412.15605《Don't Do RAG: Cache-Augmented Generation》2026 + minhleduc《Ditching Pure RAG for Context Caching》2026-08-16 + arXiv《RAGCache》+ arXiv 2510.10129《CacheClip》2026-08-28 + ACM《CacheBlend》实拉）：**CAG=知识体量有限可控时预载全部相关知识进扩展上下文并缓存运行时参数，推理免检索步骤（跳过实时检索与 KV 重算）；生产 agentic 实证=纯向量 RAG 换 long-context prompt caching+轻量本地路由模型：中位 agent 步延迟 -68%、月 API 推理支出 -80%（确定性上下文复用优于碎片块）；CacheBlend=复用 KV cache（无论前缀）选择性重算小部分 token 融合多检索文本；CacheClip=aux-LLM 选重要 token 恢复跨块依赖+共享前缀消除 attention sinks+滑动窗口分组保局部连贯+CPU-GPU 混合（重算比可调平衡质量与成本）；判据=知识静态有限→CAG，知识动态大→RAG**。提升层：工具/工作流。

**9. GraphRAG 社区检测与图遍历**（来源：Microsoft Learn《Explore GraphRAG with PostgreSQL》2026-09-10 + Microsoft《Bookshelf》2026-03-07 + Azure《Graph-augmented RAG patterns》2026-07-08 + msdocs GraphRAG + AWS《Unified KG-RAG：GraphRAG+LightRAG》2026-09-14 + GitHub Jamie-BitFlight claude_skills 实拉）：**GraphRAG=从源数据用 LLM 抽知识图谱（实体+关系）+社区检测+层级摘要；三步=图抽取→社区检测与实体摘要→查询时图遍历/社区摘要增强提示；擅长=跨文档抽象问题（「这个数据集 top themes？」）vs 向量 RAG；全局搜索=用社区摘要推理语料库（GraphRAG 明显改进）；混合检索=语义 rerank+图遍历 RRF 融合（citation/因果/组织层级/域边关系，平衡语义相关与结构重要）；工程=向量索引 >100 万用 DiskANN 否则 HNSW；统一栈=graphrag+lightrag（hkuds）on AWS Apache-2.0**。提升层：工作流。

**10. Embedding 选型与上下文感知嵌入**（来源：InsiderLLM《Embedding Models for RAG》2026-02-08 + Nexios《Production RAG Guide》2026-06-03 + LlamaIndex《Basic Strategies》2026-09-17 + BestAIWeb《Voyage 4 vs NV-Embed-v2 vs BGE-M3》2026-03-20 + LocalAIMaster《Ollama Semantic Search》2026-04-23 + Voyage AI《voyage-context-4》2026-06-29 + AI Workflow Lab《Chunking 2026》2026-05-26 实拉）：**选型四因素=维度（大=表达强但存储/计算多）/上下文窗口（一次嵌入多少文本）/域性能/成本；chunk 尺寸跟随模型 max tokens（all-minilm 256→150-200 token、mxbai-embed 512→300-450、nomic/bge-m3 8192→500-1000）；超窗口静默截断=无报错只是向量更差；overlap=块长 5-20%（512 token 块 50 token 重叠，存储 +10% 防跨块查询落空）；本地推荐=Qwen3-Embedding 0.6B-4B（MTEB 竞争力、单 GPU 可服务）/BGE-M3（MIT 许可证、8192 上下文）/NV-Embed-v2 注意 CC-BY-NC-4.0 禁商用；voyage-context-4=MoE 骨架+内置 auto-chunking+原生重叠块（把 chunking 移出设计关注，39 数据集 8 域平均胜出）**。提升层：工具。
