## 独点（10）

**1. 工具故障分级：BLOCKING/ENHANCING/OPTIONAL 三档处理 + partial failure 识别**（来源：agentlist 2026-06-29 + openlegion 2026-06-01 + zylos 2026-05-30 实拉）：BLOCKING（订单/支付/核心业务 API）→慷慨超时+重试+备份 provider 回退；ENHANCING（推荐/个性化/上下文增强）→中等超时+回退默认数据；OPTIONAL（分析/遥测）→极短超时+吞失败；**partial failure（HTTP 200 但响应截断/畸形/缺必需字段）最难检测——naive 错误处理完全漏掉，因为 HTTP 状态是成功**；修复=调成功前按预期 schema 验证响应形状，不匹配按瞬时错误处理；permanent errors（401/403）不重试直接死信队列。判据：**工具失败按业务影响分级处置（阻塞重试回退/增强回退默认/可选吞掉），且 HTTP 200 不算成功——先验响应形状再认成功**。提升层：工具/工作流。

**2. 验证失败与语义失败的专门恢复路径**（来源：zylos 2026-04-16 + arXiv 2606.01416 2026-08-12 实拉）：验证失败=模型生成的工具参数 schema 校验不过——可能 schema 描述问题（模型困惑）或模型能力问题（无法表达参数结构）；**验证失败触发专门恢复路径——把验证错误喂回模型附清晰解释，而不是通用重试**；语义失败=工具返回成功但语义错——升级/回退替代实现/人工介入；自愈编排按失败类映射=过时/不足上下文→刷新检索/换源/更新记忆；矛盾证据→交叉独立源/调验证器/请求澄清；验证或语义失败→检索支持证据/证据约束重生成/加验证步骤，预算内仍不达标才升级。判据：**工具失败先分类（验证/语义/瞬时/永久）再选恢复动作，验证错误回喂模型附解释，通用重试只用于瞬时**。提升层：工具/工作流。

**3. 结构化输出 vs function calling 决策规则**（来源：dev.to ayinedjimi 2026-09-16 + aiworkflowlab 2026-06-06 + kunalganglani 2026-09-18 实拉）：**决策规则=确定性提取用结构化输出；模型需决定执行哪个动作用 function calling**；结构化输出=生成级约束解码匹配 JSON schema（strict:true/response_schema）——保证 payload 匹配 schema；function calling=路由决策+schema——模型从 N 工具选或全跳过；三层结构保证谱=plain prompting（hope）→JSON mode（只保证合法 JSON，不保证键）→structured outputs（schema 级保证）；**function calling 不必真调函数——定义"function"名 postprocess 之类当结构化输出用**；结构化输出管"不调用外部、模型只返回结果"场景（triage 决策/类型化摘要/下一步 pipeline 对象）。判据：**按"要不要执行动作"选——纯返回结果用结构化输出，选工具执行用 function calling**。提升层：工具/工作流。

**4. 工具定义 token 开销与四步优化**（来源：aipromptshub 2026-06-21 + axiomstudio 2026-04-04 + claudearchitectcertification 2026-05-18 实拉）：**工具 schema 每次模型调用都重发并按输入 token 计费**——中等文档化工具约 200 token，50 工具=10000+ token/每次调用；优化四步=描述砍到最小正确句/删掉复述参数名的参数描述（"query(string): the search query" 无增量）/有默认值的可选参数从 schema 移除并硬编码进实现/**usage logging 杀 <1% 调用率工具**；典型一轮优化降 65% 输入 token（5395→1895）；manifest 保持 <25% 窗口+每工具 cap ~200 token+渐进披露（一行表面、细节放 schema/按需）+动态注册。判据：**工具面按 token 计费审计——描述最小化/默认值硬编码/低调用率移除/渐进披露，manifest <25% 窗口**。提升层：工具/可复用 Skill。

**5. 工具 schema 质量=函数调用准确率最大单一杠杆**（来源：swarmsignal 2026-06-11 + alicelabs 2026-05-23 + dreaming.press 2026-06-25 实拉）：Composio 基准=未优化 schema 33% 准确率→多重 schema 优化 74%；**模糊参数描述直接增加幻觉调用**；RAG-MCP 基准 13.62% tool-selection 错误；**工具描述质量是 prompt 工程变量里影响最强且最被忽视的一个**——大多数团队十分钟写完再也不看；好 schema 设计=参数命名明确具体一致（q→search_query / id→customer_id or order_id / type→notification_type）；写描述用 Anthropic tokenizer 审计。判据：**工具 schema 质量按基准测（未优化 vs 优化可差 41pp）——参数命名去歧义、描述精准简短，且是持续可调杠杆**。提升层：可复用 Skill/工作流。

**6. 幂等键：agent 三重重复源 + 语义派生键**（来源：openlegion 2026-06-01 + dreaming.press 2026-08-01 + 72technologies 2026-05-20 实拉）：**agent 比后端多一层重复源=模型自己会重发相同工具调用**（确认重调/模糊响应后重试）；幂等键构造=hash(agent_id+task_id+tool_name+call_number)，call_number=该工具调用在 run 内顺序计数；**键必须从请求语义内容确定性派生、调用前生成**——既扛网络重试也扛模型重发；三级幂等都要=run-level（调用方生成稳定 run_id+副作用日志）/step-level（planner→tool→observation 循环可重试）/tool-level（单个副作用可调两次）——**跳过任一级都会把重复漏进生产**。判据：**幂等键=语义内容 hash 调用前生成（agent_id+task_id+tool+call_number），run/step/tool 三级全建**。提升层：工具/工作流。

**7. Verify-before-retry 包装器：查后置条件再决定重试**（来源：arXiv 2608.02645 + omnitechnicus 2026-05-03 实拉）：**不确定工具结果时不立即重试，先检查预期后置条件是否已满足**——动作已成功则避免不必要重试（非原子失败场景下纯系统层改变提升可靠性，不需改 LLM）；未成功则带更好证据重试；每 LLM 调用包确定性验证层=LLM 生成→验证器检查→通过才继续；**验证包装器=agent 化分布式系统的核心原语**——与"验证执行面不等于生产执行面"（r350C）互补：那条管验证环境差异，本条管验证作为执行前置门槛。判据：**工具返回不确定时先 verify 后置条件（已成功不重试/未成功带证据重试），不用盲重试**。提升层：工具/工作流。

**8. 输出验证三守卫 + 三层验证**（来源：velsof 2026-06-14 + supergood 2026-03-10 + aiagents.codeguides 2026-07-16 实拉）：三守卫=字节长度上限（32KB 慷慨/256KB 特殊，超出=agent 理解错问题）/JSON 嵌套深度上限（8 层，合法 schema 大多 4-5 层）/字段类型与范围；三层验证=Tier1 schema/type（structured outputs 管大部分）/Tier2 语义验证（字段级验证器/格式/范围/跨字段逻辑）/Tier3 业务逻辑验证（领域规则/策略约束/人工阈值）——**schema 完美合法仍可能错到损坏数据/触发坏决策**；guardrail 时机边界=Output guardrail 最终输出生成后 / Tool input guardrail 工具执行前 / Tool output guardrail 工具执行后——三时机分开定义。判据：**输出验证=长度+嵌套深度+类型三守卫，schema→语义→业务三层递进；schema 合法不等于正确**。提升层：工具/可复用 Skill。

**9. 工具数量衰减曲线与检索式路由分解**（来源：zylos 2026-04-16 + sixdegree 2026-03-22 + arXiv 2606.17519 + MDPI 2026-04-09 实拉）：**~50 工具=84-95% 准确率；200 工具=41-83%；740 工具≈近零**（GPT-5.4 Mini 150 工具直接失败）；生产实测=110-agent/584-tool 企业目录，under-specified 请求路由 F1 随目录扩降 16-23pp；**oracle 分解=退化来自 retrieval gap+rank gap+decision gap**；修复=检索式工具选择（contextual decomposition 把大目录分解，end-to-end recall 0.340→0.494 Ultratool）+description augmentation 提升 Recall@1；**deferred loading（动态注册）有帮助但关不上 gap**。判据：**工具目录超 ~50 上检索式路由（分解+描述增强），动态注册只缓解不解决衰减**。提升层：工具/工作流。

**10. 沙箱六维资源上限 + 工具级策略引擎**（来源：agentixforce 2026-05-08 + cdovey 2026-06-05 + callsphere 2026-03-16 实拉）：沙箱配置=CPU（0.5 cores）/内存（256MB）/FS 临时只写/网络默认 deny+allowlist/系统调用过滤/PID 隔离（--pids-limit 128=fork-bomb 防御）/墙上时钟超时 30s/输出字节上限（1MB）；**policy engine=工具级 allow/deny 矩阵（web_search ALLOW / exec_shell DENY / write_db DENY）**；host 与 executor 分离保护 API key；每 job 临时目录只读挂载+可写 /tmp 限额；--cpus 1 防单任务饿死宿主；agt_sandbox YAML 声明式策略=action allow/max_cpu/max_memory_mb/timeout_seconds/network_default deny/network_allowlist。判据：**代码执行类工具=六维硬上限（CPU/内存/网络/系统调用/PID/墙上时钟）+工具级 allow/deny 策略引擎+host-executor 分离**。提升层：工具/工作流。
