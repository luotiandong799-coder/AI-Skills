## 独点（10）

**1. Agent Trace 三层层级：session→reasoning→tool 子 span**（来源：MLflow agent monitoring + Zylos observability + TraceAI span kinds + 腾讯云 实拉）：**推荐层级=顶层 span 代表 agent session 或 user turn→其下 reasoning spans 捕获每次规划/思考步→tool call spans 作为触发它们的 reasoning span 的子节点（结果记 span attribute）——分布式追踪 parent-child 是主导模式，可重建"哪步推理选了哪工具、结果如何"**；**span kinds 语义=CHAIN（通用逻辑）/LLM（模型调用）/TOOL/ RETRIEVER/EMBEDDING/AGENT/RERANKER/GUARDRAIL（合规检查）/EVALUATOR（评测 span）**；**causality health 三检查=orphan-span rate/缺 parent span id/trace 跨服务边界分裂——W3C trace context 传播 2026 不可协商；latency shape=p99 trace 时长+slowest span kind by route**。判据=每个工具调用与子 agent 步必须注册为当前推理轮的 child span，断层级即失去归因能力。提升层：工具。

**2. OpenTelemetry GenAI 语义约定：invoke_agent/plan/execute_tool**（来源：OTel gen-ai semantic conventions + Microsoft trace agent + AWS AgentCore 实拉）：**agent 级 span=invoke_agent（顶层每 turn，带 user prompt 与最终响应）→chat（推理 span，读消息历史+模型回复）→execute_tool（读工具名/参数/结果）**；**plan span=决策阶段：agent 制定策略前，生成计划的 LLM 调用是其子节点，计划产出的工具/任务 spans 是 invoke_agent 下的兄弟**；**关键属性=gen_ai.agent.name/id/description（invoke_agent）/gen_ai.tool.definitions（可用工具定义）/gen_ai.tool.call.arguments 与 .result（execute_tool）/gen_ai.prompt.name（提示模板名）/gen_ai.operation.name=plan（决策阶段）**。判据=agent 插桩用标准 span 名与属性，跨厂商可比。提升层：工具。

**3. Agent 失败分类学：六类簇+三类+五类静默**（来源：arxiv beyond leaderboard + Wink + arxiv silent failure 实拉）：**综合六类失败簇（按推理到动作流水线阶段）=①工具调用与参数级错误 ②规划与约束满足失败 ③长地平线上下文累积退化 ④多 agent 协调失败 ⑤对抗/欠规约条件下的安全失败 ⑥度量有效性问题（评测本身失效）**；**Wink 生产轨迹三分=Specification Drift/Reasoning Problems/Tool Call Failures，约 30% 轨迹含此类 misbehavior**；**静默失败五类=环境平台怪癖/设计假设不匹配/错误吞没与稀释/链式幻觉捏造/操作遗漏与取证盲点——D 类最危险：LLM 不只漏报，还把错误主动转成叙事掩盖（系统看似正常实则已坏）**；**顺序=incident review 从 trace 前到后走（walk the trace front-to-back），无分类学的复盘是 theater**。判据=事故复盘先按分类学归簇，再决定修复；静默失败靠结构校验抓不靠日志。提升层：工作流。

**4. 失败归因自动化：把失败轨迹转结构化图再定位**（来源：Who&When Pro + AgentRx + Adaptive Influence Graphs + TRACE + AgenTracer 实拉）：**Who&When Pro=大规模自动失败归因基准，揭示模型跨模态/协议/模型家族的系统性归因模式（LLM 归因不可全信，需基准校准）**；**AgentRx=域无关诊断框架定位失败轨迹中的关键失败步，step localization 平均提升 75%+失败类别归因**；**AIG=两阶段：失败 trace→结构化影响图→agent 主导遍历找关键错误——更丰富的 trace 表示持续改进归因，图构建+agent 定向遍历最强，Who&When 新 SOTA**；**TRACE=挖历史轨迹隐式不满信号（用户纠正/改写模式/放弃线索）诊断上下文失败，无需显式反馈收集——作用于 context 层无需重训**；**AgenTracer=反事实重放+程序化故障注入自动标注 2.5K 失败轨迹，训练轻量 8B 失败追踪器定位到 agent 与步骤，超 Gemini-1.5-Pro/Claude-3.5-Sonnet**。判据=失败归因=自动化管道不是人肉排查；归因模型要过基准。提升层：模型。

**5. Trace-linked eval+回放：让"为何失败"可回答**（来源：Zylos trace-linked evals + AgentLens + DynamicMCPBench 实拉）：**trace-linked eval=评测结果附到产出它的特定 trace：LLM-as-judge 标记幻觉时，失败链接回确切的 prompt 文本/检索块/工具输出/当时 system prompt——"为何失败"可回答而非猜测**；**回放=捕获 trace 对新模型版本/新 prompt 版本重放对比（LangSmith/Braintrust 支持），对比 agent 行为差而非只比分数**；**AgentLens=揭示 SWE-agent lucky pass 问题：多个通过方案合并成 PTA 正确行为空间，过程级评估抓"走运通过但过程错"（1,815 轨迹标注质量分/浪费信号/分叉点）**；**DynamicMCPBench=活 MCP server 上跑，轨迹蒸馏成 path-agnostic effect checkpoints，按"是否重现效果"打分永不按最终答案——效果打分防 lucky pass 与作弊**。判据=每个失败都要能回放+打分关联 trace；评估按效果不按答案。提升层：工作流。

**6. Agent 成本追踪：网关归因+四 KPI**（来源：GuardionAI gateway + Braintrust cost traces + PredictionGuard + TokenTelemetry 实拉）：**最可靠=所有 agent 流量过内联 AI gateway：拦截 LLM provider HTTP 响应、解析 usage 对象 token 数、经自定义 HTTP 头归因到特定 agent ID——单请求成本从 $0.0001 到 $0.50 取决于模型/输入长度，必须逐调用归因**；**trace 树定位=每 LLM 调用/tool 调用成 span 带 input/output tokens+latency+估算成本，trace 树显示多步工作流哪步增成本；custom tags 按 user/feature/model/env 分解——暴露对失败函数的重试与跨调用 oversized context**；**四 KPI=每请求总 token（超滚动基线硬限告警）/全 fleet token 消耗率/prompt-to-completion 比例（低于基线比例告警）/每成功任务成本（按 tenant 与业务流归因）**；**本地零成本=TokenTelemetry 100% 本地开源，直接读 Claude Code/Codex/Gemini CLI/Cursor/Copilot 已写日志文件，无 SDK 无云**。判据=成本可见性=网关层统一插桩；按成功任务成本归因。提升层：工具。

**7. 回归测试生命周期：生产失败→冻结轨迹重放**（来源：Kanopy + Zylos regression + autoolize 三层 + niteagent 实拉）：**生产失败到测试用例生命周期=生产失败→捕获 trace→记录工具输入输出→对冻结工具响应重跑 agent→确定性回归套件（CI 模式=约 30-case golden replay suite 每 PR <5 分钟，任何回归指标低于阈值阻塞合并）**；**每次生产失败必须成为回归测试，并 tag 触发它的 incident id 可追溯——回归套件=编码所有硬学教训的最有价值资产**；**三层 eval harness=①prompt unit tests（锁定 fixture 上的已知回归，~$1-5/月，每 PR CI 门禁）②outputs property tests（未知回归+schema 漂移，~$5-20，每 PR+每小时抽样生产流量）③golden-trace drift（数据漂移+质量慢退化，~$10-40，夜间对生产流量）**；**三层各抓不同失败类=工具调用层（确定性可断言 schema）→任务层→生产在线监控（抓没想过的失败模式）——单层 pass/fail 不够**。判据=生产失败必有回归测试；三层 harness 各司其职。提升层：工作流。

**8. 监控四支柱+隐藏指标：spans-per-node 抓失控循环**（来源：varasrinivas 四支柱 + getclaw 业务 KPI + digitalelliptical 隐藏指标 + FutureAGI 实拉）：**四支柱=延迟百分位（多快）/token 成本（多贵）/成功失败分解（多可靠）/漂移（多稳定）——仪表盘四象限给完整健康图，单一指标优化会静默伤其它**；**业务级 KPI=85%+ 任务通过率/审批负载 <20 分钟每天/每结果成本 $0.20-2.00（含返工）/异常率 <5%/风险事件零（触碰钱/访问/敏感数据）**；**隐藏指标=tool retry & loop 频率（同工具同参数多次调用=验证错误信号）/context 窗口饱和与压缩率（防 needle-in-haystack 退化）/每成功任务成本按 tenant 归因/retrieval precision 漂移（precision@5 0.87→0.74 三周→0.61 三月，无人注意直到 demo 系统开始说谎）**；**最强单一回归指标=spans-per-node 分布：健康 run 紧密聚集，失控循环=长尾离群（坏部署后几分钟暴露）；第二强=handoff edge 完整性（子 span 未链回父=A2A/子 agent 边界断裂）**。判据=仪表盘四象限+隐藏指标对；spans-per-node 分布进告警。提升层：工作流。

**9. Prompt 版本管理：drift 检测靠行为不靠 diff**（来源：Respan + FutureAGI lifecycle + Logic 实拉）：**原则=每个 prompt 有版本、改动产生新版本、旧版本可访问、回滚=一次配置更改；git-native=prompt 作 txt/md/yaml 在应用仓库，commit history=版本历史（免费/进 code review/可 diff）**；**prompt drift=prompt 文本没变行为随时间变——模型静默更新权重/检索上下文移位/输入分布变化都会触发；检测=对比固定版本下近期 trace 与早期基线行为，diff prompt 字符串不够**；**生命周期三阶段=版本化（id+diff）→gated promotion（eval-on-PR+canary ramp 门禁 floor/paired CI/safety flip，证明候选胜过现任才放量）→deprecation（归档标记+drain window+cache eviction 防 ghost-serving 旧版本）**；**无 eval 的版本管理=只是 diff 追踪**；**漂移信号=更低 schema 合规/更高升级率/上升 token 成本/更多人工纠正**。判据=prompt 升版=软件发布流程；drift 用行为基线检测。提升层：工作流。

**10. 结构化 agent 日志 schema：六字段类+三面+防篡改链**（来源：Microsoft Learn structured logging + AgentTrace taxonomy + IETF AAT 实拉）：**最小可用六字段类=①trace correlation（trace_id/span_id，无=日志是孤立岛）②agent identity（agent_id/agent_version）③session context（session_id/customer_tier）④operation details（operation_type/model_id）⑤performance（input/output token/latency_ms）⑥outcome（status/error_code）；时间戳=ISO 8601 毫秒精度 UTC，绝不相对时间**；**AgentTrace 三面 taxonomy=cognitive（推理链/决策理由/置信分）/operational（工具调用/参数/结果）/contextual（用户/环境），schema 满足四性质=consistency（合规表示）/causality（时间保真）/fidelity（忠实内外行为）/interoperability（框架无关）**；**IETF AAT=JSON 记录含 agent identity/action classification/outcome/trust level，SHA-256 hash chaining 防篡改（RFC 8785 规范化）+可选 ECDSA 签名非否认——审计记录对齐 NIST SP 800-53 AU 族/EU AI Act Art.12 可追溯义务**。判据=每条 agent 日志过六字段类检查表；敏感环境审计链上哈希。提升层：可复用 Skill。
