## 独点（10）

**1. LangGraph 生产四能力 + Supervisor 使用判据**（来源：inductivee-langgraph-prod + xbstack-langgraph-supervisor + devto-langgraph-patterns 实拉）：**生产与原型四能力分界=PostgresSaver 持久状态（工作流跨进程重启存活）/interrupt() 人类介入中断（关键决策点暂停等批准）/并行 fan-out-fan-in（子代理并发）/中间事件一等流式**；**Supervisor 只在该用场景用=任务需要显式角色分离+独立工具权限+跨阶段可恢复 handoff；Supervisor 拥有路由/状态合并/失败决策，Worker 只处理一个有界子任务**；**handoff 只带已验证 state+下一目标+约束+audit ID，不默认全量对话**；判据=把图当软件不当魔法——状态持久化+中断+并行+流式四件套齐了才够生产。提升层：可复用 Skill。

**2. 多智能体框架选型矩阵 2026**（来源：the-agent-report + promptgenius + autogpt-11-frameworks + gurusup 实拉）：**OpenAI Agents SDK（26.9K stars/10.3M 月下载）=handoff+guardrails+sessions 三原语、LiteLLM 100+ 模型、OpenAI 栈最快路径，限制=紧耦合 OpenAI+复杂分支/长时状态不如 LangGraph checkpoint**；**CrewAI（52.8K stars/5.2M 下载）=角色制 crew 最简上手（20 行原型）、2026 新=A2A 任务执行工具+DMN 模式+FlowDefinition（each/if 表达式+crew actions）**；**AutoGen=会话式多代理（群聊/嵌套/双人聊天）HITL 一等公民、v0.4 架构重写重置生态**；**Microsoft Agent Framework 1.0=Semantic Kernel+AutoGen 合并、workflow engine 四模式（sequential/concurrent/handoff/group chat）全流式、A2A+MCP 跨运行时**。判据=按核心抽象选：Agent+Runner（SDK）/角色 crew（CrewAI）/会话组（AutoGen）/workflow engine（MAF）/显式图（LangGraph）。提升层：工具。

**3. 编排模式 2026：确定性主干+LLM 定点注入**（来源：zylos-graph-orchestration + spikefu-pantheon + msft-agent-framework 实拉）：**Anthropic 工程指南称 2026 获胜路径=确定性主干编排流+LLM 智能只在特定步骤注入；agent 有意被调用，完成即控制权回主干；主干=LangGraph（LLM-native）或 Temporal（企业持久性），流程不是自由形式——有定义状态/迁移/终止条件**；**Microsoft 三阶梯=direct call→single agent with tools→multi-agent，强先验只在 prompt 复杂度/工具过载/安全边界真正要求时才爬级**；**sequential 编排在两个场景是坏匹配=阶段可尴尬并行（embarrassingly parallel）、工作流需要回溯**。判据=先问"下一步能否在开始前完整列出来"——不能才上 agent，agent 不能则上多 agent。提升层：工作流。

**4. Anthropic Managed Agents 多智能体 + brain/hands 解耦**（来源：claude-managed-agents + anthropic-managed-agents-engineering + anthropic-multiagent-systems 实拉）：**lead agent 把工作拆块委托 specialist（各自模型/prompt/工具）；specialists 并行在共享文件系统上工作并把成果贡献进 lead 的上下文；事件持久所以 lead 可中途 check-in 其他 agent**；**brain/hands 解耦=单容器失败会丢所有手的状态→把手变成工具 execute(name, input)→string——接口支持任意自定义工具/MCP server/自有工具，harness 不改变模型**；**Anthropic 多智能体研究=agent-agent 交互量可能超过 human 交互，机构设计按人速监督的前提被打破**。判据=智能规模化后容器是瓶颈——脑与手分离使每只手独立可替换。提升层：工作流。

**5. A2A 协议：跨框架 agent 互操作标准**（来源：a2a-linux-foundation + a2a-v1.0 + a2a-spec 实拉）：**Google 发起捐赠 Linux Foundation、150+ 组织采用、落进主要云平台、v1.0 2026-03 生产就绪（多协议绑定+版本协商+通用语义模型）**；**核心目标=能力发现/交互模式协商/事务**；**与 MCP 分工=工具经 MCP 暴露、agent 间经 A2A 协作（build with any framework, equip with MCP, connect with A2A）**；**企业级安全=OpenAPI 认证方案内建**；**2026-08 成为 Agentic AI Foundation（AAIF）Growth Stage 项目；电信版 A2A-T=多厂商系统对接从 2-6 个月压缩至天级+电信级多层级鉴权**。判据=单平台内编排够用，跨技术栈/组织边界才需要 A2A。提升层：工具。

**6. n8n Agents 与工作流互相调用**（来源：n8n-agents + n8n-complex-agent-patterns + n8n-workflows 实拉）：**n8n Agents 没取代工作流=路径不确定让 Agent 判断下一步、步骤确定让工作流照规则执行，两者互相调用**；**模式A=Agent 主导工作流（开放问题由 Agent 选路，具体动作照既定流程）模式B=Message an Agent（主流程不变，某一步交给已发布 Agent）**；**manager agent+sub-agent tools 委派=主 agent 配多个子 agent 工具各有 role/memory/模型**；**成本模式=Director 用强模型（O3）拆任务，specialists 用便宜模型（GPT-4.1-mini）保质量降本**。判据=能列出步骤走工作流、列不出走 agent——两种形态可互相调用而非二选一。提升层：工作流。

**7. 共享记忆治理：fleet-memory 四失败模式+并发四异常**（来源：arxiv-governed-shared-memory + agentpatterns-shared-state-isolation + techrxiv-mas-memory + yennj-shared-memory-blackboard 实拉）：**多 agent 共享记忆四失败模式=unauthorized leakage（越权泄露）/stale propagation（陈旧传播）/contradiction persistence（矛盾滞留）/provenance collapse（来源坍缩）；治理原语=scoped retrieval（作用域检索）/temporal supersession（时间取代）/provenance tracking（来源追踪）/policy-governed propagation（策略治理传播）**；**共享可变状态并发四异常=stale-generation/phantom-tool/causal-cascade/tool-effect reordering——写入须带隔离纪律（经典数据库并发控制同源）**；**黑板模式（订阅相关事件）vs message pool（全员看全消息，AutoGen GroupChat/MetaGPT）——共享态是唯一有状态部分也是 bug 高发区；参考失败=memory poisoning：一个 agent 幻觉"事实"其他 agent 传播**。判据=共享记忆必须有协议：何时可写、如何传播、谁来取代、来源可追踪。提升层：可复用 Skill。

**8. 多智能体成本：token 复合与 role-tiering**（来源：augmentcode-cost-compounding + haktansuren-token-usage + zylos-observability-cost + ailearningguides 实拉）：**Anthropic 实测=单 agent 约 4×chat token、MAS 约 15×chat token；成本复合=编排开销+重复上下文传输+验证层+重试循环+协调税叠加在每次 handoff——3 个 agent 可到 10×；token 用量解释 BrowseComp 80% 性能方差**；**观测数据=OpenAI 内部 Codex 占周输出 token 99.8%；Anthropic 并行 C 编译器项目 20 亿输入 token/1.4 亿输出**；**role-tiering 降本模式=按角色分模型档位：researcher 用便宜快模型（多数调用是简单搜索）、planner 用推理模型、reviewer 用便宜模型+few-shot rubric、generator 按输出重要性配模型——别给每个 agent 上最贵模型**。判据=多 agent 是 token 放大器——按角色 tier 模型、按 handoff 审计开销。提升层：工作流。

**9. The Illusion of Multi-Agent Advantage**（来源：arxiv-illusion-multiagent + jongkwan-evaluation 实拉）：**arXiv 2606.13003=CoT-SC（自洽采样）持续优于自动化 MAS 框架、经常在 <10% 计算成本下达到更高准确率——当前框架的架构复杂度是随机采样的低效替代**；**五维评测轴=coordination cost/message quality/inter-agent misalignment/error propagation；MAS 失败分类学+拓扑选择一次过**；**成本先行=协调成本第一且巨大（15×token）**。判据=先跑单 agent+多次采样基线，再决定是否引入多 agent——架构复杂度换不来采样效率。提升层：可复用 Skill。

**10. MAF 生产级四组件+域服务分布原则**（来源：msft-build2026 + msft-agent-framework + devblogs-agent-framework 实拉）：**生产级 agent 四组件=instructions（定义行为）/tools（能行动）/memory（跨上下文保留）/workflow（运行方式）；.run() 一次性取全结果或流式**；**MAF 生产发布=稳定 API+长期支持承诺、多 provider（Foundry/Azure OpenAI/OpenAI/Anthropic/Bedrock/Gemini/Ollama）、MCP 动态发现外部工具**；**Keep domain services distributed=把 specialist 的指令移进 orchestrator 而非再放一个模型（snow resort demo：advisor 经 A2A 调 specialists，各自持有指令与工具）**；**BUILD 2026 新=Agent Harness/Hosted Agents/CodeAct；企业=Keycloak SSO+structured outputs+response ID+事件父子层级**。判据=生产 agent=指令+工具+记忆+工作流四件套；跨域编排只搬指令不搬模型。提升层：工作流。
