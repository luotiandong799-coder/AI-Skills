## 独点（10）

**1. EDD（Eval-Driven Development）三件套与双分数板**（来源：QASkills《EDD 2026 Guide》2026-06-15 + FutureAGI《LLM Evaluation Glossary》2026-05-22 + DeepEval《EDD》2026-06-15 + AI/TLDR《Writing Tests Before You Tweak》2026-06-13 + JatinBansal《EDD for LLM Systems》2026-05-19 实拉）：**EDD=写 prompt 前先写评估，TDD 适配非确定性世界：不断言精确输出，断言 labeled dataset 分数超阈值；eval 合同三件=黄金数据集+评分法+通过率阈值（构建必须达标才 ship，旧 Gherkin 验收标准变成 eval cases）；golden set 小到可手工策展、稳到可当契约；双分数板=golden 分数（系统变才变）与 live 分数（系统或数据变都变：周三营销后用户查询变了，golden 冻结六个月不代表）分开展示；采用团队 prompt 变更周期缩短 40-60%，部署后质量事故降幅更大——每次 prompt 变更先被同一数据集同一 rubric 评分再触达用户**。提升层：工作流。

**2. 黄金集四桶分层与规模实证**（来源：FutureAGI《Golden Set Design 2026》2026-05-16 + Langfuse《Golden Dataset Evaluation》2026-09-20 + QASkills《Golden Dataset Guide》2026-07-07 + divinci《Automated Regression Testing》2026-05-26 + barkingiguana《Building a Golden Dataset》2026-07-31 + AI/TLDR《Build an Eval Suite》2026-06-12 实拉）：**四桶=生产样本分层迹导出 60%+对抗 15%（jailbreak 语料/scanners/红队）+专家手写 edge 15%+失败回放 10%（Error Feed 聚类/历史事故——不回归已付过费的 bug）；规模=PR 快速门几十条/完整回归数百到上千；200 条分层 > 5000 条不分层（分层比规模重要）；三性质=分层代表性（30% 流量德语则 30% golden 德语）/版本身份（input+上下文+判断信息足够判好）+从生产失败生长不冻结；staleness 判据=距上次提升生产失败 >14 天（高流量面）说明集不再反映流量；cohort drift>25% 预警**。提升层：工作流。

**3. 三层评估栈与 judge 校准纪律**（来源：DataVLab《Human Evaluation Practical Guide》2026-08-03 + COMPEL《Judge Calibration》2026-04-06 + FutureAGI《Human vs LLM Annotation》2026-05-14 + Koji《Human Evaluation Five Parts》2026-09-27 + AgentPatterns《Spot-Checking》2026-10-02 + MLflow《Align Judges》2026-06-23 实拉）：**三层栈=自动指标每 commit 抓明显回归+LLM-as-judge 大样本方向信号+人类小样本精选验证自动化/高利害决策/抓其他层漏的（比例按场景：研究团队 95% 自动 5% 人类）；校准=100-500 样本 judge 与人类独立打分，Cohen kappa>0.7 才可信；pilot 200 双标样例 kappa>0.6 后 scale+5-10% 人工验证+月度重采样抓 judge drift+固定节奏更新 rubric；人类评测五件套=具体锚点 rubric+冻结真实输入样本+每项≥2 独立评分者+度量的 inter-rater 一致性+盲随机呈现；Anthropic 实证=LLM judge 打分通过的幻觉被人类抓/系统级失败单输出分数不可见/源选择偏差（SEO 内容农场）从输出文本不可检测——人类 spot-check 必须留**。提升层：工作流。

**4. LLM-as-judge 偏差研究：风格偏差与锚定偏差**（来源：arXiv 2604.23178《Judging the Judges》2026-08-28 + arXiv 2608.25869《Anchoring Bias》2026-09-03 + arXiv 2605.09227《Two Ways to De-Bias》2026-08-26 + arXiv 2609.31184《Accounting for Bias》2026-09-28 + ICLR《BIASSCOPE》2026 + ACL《Reasoning Model Is Superior Yet Suffers from Biases》2026 实拉）：**风格偏差 dominant（0.76-0.92 全部模型）远超位置偏差（≤0.04）却研究最少；锚定偏差=prior scores 仅作上下文元数据也锚定判断（192,000 评估中 8 模型 7 有显著锚定）——评估独立性被破坏，评分不得携带前次分数；去偏两法=后验校准（保留便宜 judge 接受偏差，配对锚点 true vs biased 拟合转换到人类评分：参数化小锚分层贝叶斯线性校正）vs 提示指令（指示忽略呈现线索）；共享校准是风险因素：J 小（校准不匹配）系统性偏差放大，J 与 ΔJ 须作前置诊断先查再信校正估计；BIASSCOPE=LLM 驱动自动发现偏差（JudgeBench 验证，偏差发现从被动人工清单转主动自动探索）；推理模型作 judge 更强但受浅层质量偏差（length/concreteness 可刷高分），指令误对齐反而更少**。提升层：模型/工具。

**5. Agent 双轨评估：工具轨迹+响应质量**（来源：Google Codelabs《Agents CLI in Agent Platform》2026-05-14 + Microsoft Foundry《Agent Evaluators》2026-09-30 + Microsoft Learn《Agent Evaluators Preview》2026-02-13 + arXiv 2607.11818《MM-ToolSandBox》2026 实拉）：**ADK 评估两独立事=工具轨迹（对工具+对参数，确定性精确匹配）+响应质量（LLM judge：最终答案相关性/帮助性/接地）；只 rubric 评分会放行读起来好但幻觉的答案，只轨迹无法知道用户是否得有用回复——必须两者都测；Foundry 五件套=Tool Call Accuracy（对工具对参数无冗余）/Tool Selection/Tool Input Accuracy/Tool Output Utilization（推理与最终响应正确用工具结果）/Tool Call Success（无技术错误）；process eval vs system eval=工具调用成功属过程，任务完成属系统（多 agent 时评主 orchestrator）；Agent SR=agent judge 五独立标准全过才 pass（任务完成/指令遵循/工具使用有效性/无副作用/信息准确）；ClawsBench 实证=工具不安全动作率 7-33% 与任务成功率 39-64% 无一致排序——两指标独立追踪**。提升层：工具。

**6. RAG 评测四指标与语义层诊断**（来源：QASkills《Ragas Metrics Complete Guide》2026-05-01 + DEV《RAG Evaluation with RAGAs》2026-07-14 + Ragas Docs《v0.3→v0.4 Migration》2026-09-21 + AI/TLDR《RAG Evaluation Metrics》2026-06-12 + arXiv 2601.22025《When Better Prompts Hurt》2026 实拉）：**RAGAS 四数答两问=检索层（context precision 检索到的是否相关+context recall 该召回的召回没）与生成层（faithfulness 答案每个原子声明能否从检索上下文推断+answer relevance 答案与问题语义相似）；诊断关键=faithfulness 1.0+低 context recall=系统准确总结不完整信息，同样危险；answer relevance 罚过度 hedging/填充（高 faithfulness+recall 仍可低 relevance）；faithfulness 计算两步=提取答案原子声明→LLM judge 逐条对照上下文→支撑比例；Nvidia context relevance=两独立 judge 0/1/2 评分转 [0,1] 平均；0.5-0.75 低接地常见因=prompt 允许自由回答**。提升层：可复用 Skill。

**7. CI/CD 门与 prompt as code**（来源：Brightlume《CI/CD for AI》2026-04-17 + Zylos《Agent-Native CI/CD》2026-05-17 + Promptfoo《CI/CD Integration》2026-09-28 + Red Hat《Automated AI Evaluations》2026-06-11 + PromptQuorum《Prompt Review Workflow》2026-04-01 + ShawnMayzes《CI/CD for AI Evals》2026-06-22 实拉）：**prompt as code=Git 存 prompt 与代码（YAML/JSON 结构化可 diff 可 review：version/model/system_prompt 字段），prompt/代码/数据必须一起版本化才能 trace 回归；Zylos 两门=Gate1 机械门（秒级抓机械错误省 eval 算力）+Gate2 离线 eval（每 PR 触 prompt/tool def/model 变更跑全量 golden）；三层 CI=smoke evals 每 PR/全套 merge/每周生产回放真实流量；judge 模型升级陷阱=先跑 eval 套件更新基线再当阈值门（Claude Haiku 4.5/4.6 同 rubric 不同分，否则 CI 无故失败或放行降质）；评分历史存证=单次跑 pass/fail 历史给趋势；人工审批门=自动检查过→≥1 领域专家+1 安全评审→回归测试→才部署**。提升层：工作流。

**8. 漂移检测四信号与响应分级**（来源：FutureAGI《Data Drift Detection 2026》2026-05-20 + FutureAGI《Model vs Data Drift》2026-05-14 + InsightFinder《4 Statistical Signals》2026-04-17 + valuestreamai《Monitoring Guide》2026-05-07 + Latitude《Continuous Drift Detection》2026-06-18 + DEV《Tiny Drift Detector》2026-09-30 实拉）：**四信号=token 长度分布 KL 散度+嵌入余弦漂移对滚动基线+自动化 LLM-as-judge 评分管道+拒绝率指纹聚类分解（各抓别的漏的，同时出现=强信号）；embedding 漂移实现=golden 集质心（同一 embedder 检索用）+7 日滚动质心+余弦距离超 30 日基线 2 标准差告警+意图标签 KL（topic-classifier/HDBSCAN，新簇出现即查）；output drift=宿主模型静默换 checkpoint（托管模型极常见）→监测平均响应长度/情绪分布；PSI≥0.25=显著漂移考虑 prompt/检索更新；响应三级=observe/investigate/act（回滚/prompt patch/retriever 重索引/人工回退），告警前先定响应**。提升层：工具。

**9. 评测工具选型矩阵**（来源：AI Workflow Lab《Frameworks Comparison》2026-06-03 + Calmops《Complete Guide》2026-06-24 + benchmarkingagents《Eval Tools Compared》2026-07-07 + DeepEval《Top 5 Platforms》2026-08-04 + agentnative《Promptfoo vs DeepEval》2026-07-26 + genai.qa《Promptfoo vs DeepEval》2026-04-24 + citehawk《AI Evaluation Tools》2026-10-02 实拉）：**选型判据=CI/CD 集成（DeepEval pytest 原生/promptfoo CLI+GH Actions）/LLM-as-judge 内建/多轮支持（RAGAS 无）/许可证与自托管（LangSmith 商业 SaaS 自托管仅企业版/Ragas+DeepEval Apache2/promptfoo MIT）/栈语言（promptfoo Node CLI 非 Python 栈零摩擦；DeepEval 假设 Python 进程，非 Python 服务要 sidecar）；LangSmith=LangChain 生态默认（tracing+dataset+experiment 强）；promptfoo=安全/CI 门优先（40+ 红队插件：prompt injection/jailbreaks/PII/indirect injection/BOLA/SQL via LLM）+YAML 声明式非 Python 工程师可读可扩展；Langfuse=MIT 免费自托管 dashboard+长程迹存储；Braintrust=eval-first 工程工作流（dataset/experiment/scorer/并排/online evals）；治理=org-wide gate 强制 pre-launch+live；迹存储 $1-3/GB**。提升层：工具。

**10. 回归测试与失败回放闭环**（来源：TechEarl《Evals That Catch Regressions》2026-05-18 + FutureAGI《Regression Testing Glossary》2026-05-21 + Logic《Evals Explained》2026-07-02 + Respan《How to Test AI Models》2026-05-10 + Iron Mind《Test Suite Pattern》2026-05-17 + Braintrust《Turn Failures into Regression Tests》2026-05-29 实拉）：**回归定义=每模型/prompt/retriever/tool 变更重跑固定 prompt/trace/dataset/evaluator 阈值对比最后通过基线（catch 部署前质量降）；关键回归=人类评审会漏的 5% 流量切片静默变差；离线测试=每变更跑+任一标准降>5% 阻止部署+新旧版本分数 diff 呈现；在线监控=生产流量样本连续跑+周环比降>5pp 告警+重试率尖峰告警+每活跃用户成本尖峰告警；失败回放闭环=生产迹当回归源真相：抓失败迹→标失败模式→提升 span 进回归数据集→写重复模式 scorer→同 scorer CI 与 live 流量都跑（每诊断的幻觉/检索 miss/工具调用错/指令遵循失败/schema 违规都成保护未来的测试，同 bug 不 ship 两次）；回滚路径=每个 prompt/model 版本必须可回滚**。提升层：工作流。
