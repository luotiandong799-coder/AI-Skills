## 独点（10）

**1. VLA 具身模型统一架构：DiT 动作解码器+统一状态-动作表示**（来源：qwen-vla + starVLA + qwen-robotmanip + vla-foundry 实拉）：**Qwen-VLA=在视觉-语言栈上扩到连续动作与轨迹生成，核心=基于扩散 Transformer（DiT）的动作解码器**（感知/理解/推理/行动一个模型，跨形态/任务族/环境迁移）；**StarVLA 三种动作输出策略=Qwen-FAST（离散 token 动作）、Qwen-OFT（MLP 头直接回归连续动作）、Qwen-PI（flow-matching 扩散生成连续动作）**——选型看任务需求；**Qwen-RobotManip=统一 80 维状态-动作表示（单臂/双臂/灵巧手/移动体共享）+camera-frame end-effector delta pose 动作（视觉相似动作数值相近，抽象形态差异）+in-context policy adaptation（读执行历史作隐式上下文）**；VLA Foundry=LLM→VLM→VLA 流水线支持从零训练或 pretrained backbone。判据：**VLA 的统一价值=一个模型跨环境，动作解码与表示对齐决定可迁移性**。提升层：模型/工具。

**2. 工具调用错误处理：宿主边界捕获+结构化错误+retry budget**（来源：codeguides-tool-errors + ai-tldr-tool-errors + learnixo + aiwave-function-calling 实拉）：**catch at host boundary，不在 agent loop 内捕获——把工具失败转成结构化 tool observation 喂回模型**（工具永不向调用方抛异常，内部 catch 全部失败返回可读 error dict，LLM 能读能改）；**错误分两类=可修型（坏参数/无结果/校验失败→clear error string 让模型修正下一次调用；模型自修正参数错误 ~80% 二次尝试成功）vs 致命型（auth 撤销/配额耗尽/工具宕机→停止循环干净上报）**；**retry budget 防无限循环；每个 call ID 都要 append tool message 包括失败；secret 从错误消息剥离再进上下文/日志**；no-progress 循环检测=停止或升级。判据：**错误是指令不是事故——结构化错误回灌让模型自愈，致命错误要停**。提升层：工具/工作流。

**3. 工具 schema：strict mode=token 级约束解码**（来源：strict-schema-openai-anthropic + dreaming-press + aaif-json-schema-2020-12 + aiworkflowlab 实拉）：**strict: true 把 schema 从"模型读的提示"变成"解码器被迫遵循的语法"**（OpenAI constrained decoding / Anthropic grammar-constrained sampling，双端都消除类型错误）；**前提=每个属性都列进 required+additionalProperties:false（"缺字段"与"幻影字段"两类错误一次杀掉）**；**JSON Schema Draft 2020-12 是 2026 标准（MCP 2026-07-28 SEP-2106 升级 inputSchema/outputSchema）——旧 Draft 7 在 Gemini/Groq 造成解析失败**；**Pydantic v2 的 model_json_schema() 行为变化=ge=0 生成 exclusiveMinimum:0（必须 >0 而非 >=0），接 0 合法值要用 ge=0.0+allow_inf_nan=False**；**生产永远验证模型与供应商真的支持 schema 强制——不支持就保留 fallback 解析，parse-then-validate 仍需存在**。判据：**strict 管生成，边界校验管执行——两件事都要，schema 版本用 2020-12**。提升层：可复用 Skill。

**4. Agent 沙箱化：ASI05+隔离技术选型+默认拒绝网络出口**（来源：aisuperthinkers + mxc + menuagentic-isolation + cloud-run-sandbox + langchain-sandbox-output 实拉）：**OWASP ASI05 把沙箱化从建议变要求——跑 LLM 生成代码必须隔离，不是 Docker 不是 hope 不是"以后审查"**；**按威胁模型选型：Firecracker microVM（多租户/不可信输入，独立内核 <150ms 启动）/gVisor（计算密集 K8s，用户态拦截 syscall 近容器速度）/MXC（微软 OS 级策略沙箱，Windows/WSL 内建，开源于 microsoft/mxc MIT）/remote-only（彻底移除本地执行）**；**Google Cloud Run 沙箱=凭证与 env 隔离（不访问服务 env vars/不调用 metadata server）+网络出口 deny-by-default（被诱导跑脚本试图外传数据，系统层直接阻断）**；**沙箱不消除注入威胁只收爆炸半径——沙箱输出当不可信数据：模型不得对执行输出里的命令式文本未经确认就行动**。判据：**隔离按爆炸半径选，出口默认全关，沙箱输出仍不可信——三层缺一不可**。提升层：工作流。

**5. UI 感知双通道：a11y 树 vs 截图像素，结构化 2-4x 快/4-10x token 省**（来源：fazm-a11y-tree + prophetchrome + lapu + gui-state-belief-2607.04334 实拉）：**a11y 树/accessibility snapshot=读屏幕阅读器用的语义结构（role/name/value/state）——1-5KB（250-1250 token）vs 截图 100KB+（1500-5000+ token）/步，4-10x token 省，2-4x 快，分辨率无关抗布局抖动**；**代价=坏 a11y 的站点树稀疏（div 冒充按钮无 role）、Canvas/WebGL 对树不可见、Shadow DOM 部分可见——老 app/游戏引擎不可见**；**像素路线=通用（桌面/游戏/远程桌面都能干）但慢贵（~1-1.5K image token/截图）且 grounding 是已知瓶颈（多显示器坐标偏移/dynamic DPI/高 token 成本）**；**2026 双通道=像素+结构冗余读入，benchmark 开始测 state-belief 归因（agent 的界面状态信念来自像素还是结构还是先验）**。判据：**有结构用结构（快省稳），没结构才上像素；双通道读入比单选鲁棒**。提升层：工具/工作流。

**6. GUI agent 评测：OSWorld 369/人类 72.4%/OSWorld 2.0 长时任务**（来源：osworld-2.0-2606.29537 + hackworld + aimultiple + aiwiki-computer-use 实拉）：**OSWorld=369 任务真实 Linux/Win/macOS VM 自由键鼠控制，人类专家基线 72.4%**（GPT-5.5 78.7%/Kimi K2.6 73.1% 已过基线；模型+scaffolding+retry 策略是完整 agent 系统分）；**OSWorld 2.0=108 个长时真实工作流，median 人类完成 ~1.6 小时、平均 318 工具调用（vs 1.0 的 ~30）——长时规划是新的评测维度**；WebArena 812/VisualWebArena 910/Windows Agent Arena/MacOSWorld 覆盖平台矩阵；**HackWorld=web 漏洞利用 agent 基准，最佳仅 11.1% 成功率——瓶颈是策略推理与工具编排而非感知**。判据：**选 GUI agent 看 OSWorld-Verified 分+长时任务表现；漏洞场景差距在编排不在感知**。提升层：可复用 Skill。

**7. 任务预算治理：模型可见倒计时+五指标硬顶组合**（来源：task-budgets-claude + themainthread-five-limits + promptise-budget + dailyaiworld 实拉）：**task budget=跨整个 agentic loop 的顾问性 token 上限（含 thinking/tool calls/tool results/final output），直接以运行倒计时呈现给模型——模型看着计数器做运行期决策；区别于 max_tokens=每请求硬顶、模型不可见**（Claude task budgets beta 需 header，min 20000 token）；**生产硬顶五指标组合：max_steps（循环迭代上限）/max_tool_calls（总工具调用数）/max_tokens_input（累计输入 token）/max_cost_usd（会话美元上限）/timeout_seconds（墙钟时限）**；**per-run+per-day 双预算（每天 UTC 某时重置）+每个工具标注成本单元**；真实案例=SaaSNext 递归工具循环 9 小时烧 $47,000，budget enforcer（PydanticAI structured output+Temporal durable execution）实时追踪+自动断路器。判据：**预算对模型可见才会被遵守——单靠 max_tokens 拦不住循环，五指标+双范围+断路器才闭环**。提升层：工作流。

**8. 工具编排框架：TROVE 只提交首个技能+Osprey 逐轮能力过滤+POLARIS 编译护栏**（来源：trove-2609.05019 + osprey-2508.15066 + polaris-2601.11816 + agentflow-planactreflect 实拉）：**TROVE=路由当"暂定意图"：只提交首个顶层技能执行，其余保留为未执行后缀，据边界结果逐轮验证/编辑路由——commit 到哪算哪，不赌整条链**；**Osprey=每次交互按能力分类过滤可用工具（逐轮相关性过滤）——防 prompt 爆炸、防不必要工具加载，大工具清单上扩到不淹没模型**；**POLARIS=计划器产类型检查的 DAG→rubric 引导选一个合规计划→validator-gated 检查+有界修复环+编译的策略护栏在副作用发生前拦截/路由**；PlanActReflect=标准 ReAct 易卡死，加专用 critic 节点检查"已完成工作判定任务完没完，还是该再计划"（PLAN/ACT/REFLECT 三个 agent 实例）。判据：**编排三件套=渐进提交（TROVE）、动态过滤（Osprey）、编译护栏（POLARIS）——别一次赌整条路由**。提升层：可复用 Skill。

**9. Computer use API 工程：四步循环+坐标映射+工具集**（来源：apidog-cua + microsoft-foundry-computer-use + virtualme-spec + claude-computer-toolset + hub-cissychen 实拉）：**四步循环=Perceive（截图）→Decide（截图+目标给模型拿下一步动作）→Act（driver 执行 click/type/scroll）→Check（新截图判定目标完成否）**——"模型是 decide 步，其余都是工程"；**坐标映射=controller 保持 scale factor，把模型输出的 API 空间坐标映射回屏幕空间再调用 xdotool**（reference computer-use scaling approach）；**脆弱点=多显示器坐标偏移、dynamic DPI scaling、每截图 ~1-1.5K image token 成本（~1.5-5K token/交互步）**；**Claude computer_toolset=一个 entry 给 17 个成员工具（click/type/scroll 等）**；Microsoft Foundry/Google Gemini/OpenAI CUA 均有官方 computer use tool 进 agent loop。判据：**computer use 成败在坐标映射与循环闭环——模型只负责 decide，scale 与 DPI 处理是工程侧硬功夫**。提升层：工具。

**10. Agent 循环终止模式：verifier done-check+no-progress 检测+框架默认上限**（来源：agentnative-loop-termination + openlegion + codeguides + aiwiki-task-budgets 实拉）：**定义"done"四件套=verifier done-check（结果验证器判断目标达成）/iteration caps/token 与 time 预算/no-progress 检测（连续 N 轮输出/动作无实质进展就停或升级）**；**框架默认=OpenAI Agents SDK max_turns=10、LangGraph recursion_limit 文档写 25 vs 1000 的差异要按实际引擎版本确认、CrewAI max_iter=20——默认值偏保守但存在**；**让 agent 在撞顶前退出（出口条件=达成/预算用尽/无进展），而不是撞到硬顶后报错——budget 是顾问性信号、cap 是最后防线**；工具错误里 retry budget 与循环 cap 同源（防无限循环双保险）。判据：**循环终止要显式出口三条件（完成/预算尽/无进展）——只靠 max_turns 撞墙是设计缺陷**。提升层：可复用 Skill。
