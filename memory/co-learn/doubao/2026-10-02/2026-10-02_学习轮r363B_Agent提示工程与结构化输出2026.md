## 独点（10）

**1. 输出契约四问：模糊输出是"模型今天很笨"的头号原因**（来源：NovaKit《Context Beats Cleverness》2026-04-19 实拉）：要什么字段、什么顺序、什么类型？什么应省略 vs 包含？畸形输入时的失败响应是什么？最大长度多少？——四问逐项定死；机器消费的输出用 JSON schema 或结构化输出（OpenAI response_format / Anthropic tool-use），不用自由文本。判据：**prompt 收口=输出契约四问（字段/省略/失败响应/长度）逐项明确，机器消费必用 schema**。提升层：工作流/可复用 Skill。

**2. 结构化输出四级保证：语法保证≠语义正确**（来源：thepromptbench 2026-07-13 + kanopy 2026-04-17 + tensoria 2026-05-15 + zylos 2026-04-11 实拉）：四级递增——①prompt 要 JSON 再解析（什么都不保证）②provider JSON mode（保证可解析不保证形状）③schema mode/约束解码（保证精确结构）④function calling（工具调用副产物返回结构化参数）；2026-07 起 OpenAI/Google/多数本地运行时提供真约束解码；OpenAI structured outputs 数学上不可能违反 schema，代价约 +10-15ms schema 编译延迟；**"100% JSON 可靠性"只是语法保证——语义失败（错值/误认字段/拒绝伪装成合法 JSON）仍存在**。判据：**结构化输出按保证级别选（语法保证靠约束解码），语法通过后仍要语义校验**。提升层：模型/工具。

**3. 约束解码会降推理质量：CRANE 交替窗口缓解**（来源：Zylos 2026-04-11 实拉）：约束解码在 grammar 约束强迫模型偏离高概率 token 序列时可降低推理质量；CRANE（ICML 2025）显示受约束与不受约束窗口交替可缓解——**结构化输出不是免费午餐，重推理任务要评估约束代价**。判据：**约束解码用于输出形状强制，推理密集任务若质量下降改用交替窗口或后置校验**。提升层：模型/工作流。

**4. 六层 prompt 结构：每层职责分离**（来源：futureagi《AI Prompting for LLMs in 2026》2026-05-14 实拉）：2026 提示词通常六层=system prompt（persona/语气/响应风格/硬约束）/tool definitions（可调用函数 schema）/retrieved context（按查询裁剪的向量库或网页片段）/conversation history（聊天早轮）/（其余层）；每层独立更新、独立注入，不混在一个块里。判据：**prompt 按六层分离组装（system/工具定义/检索上下文/历史），各层职责单一不混写**。提升层：工作流/可复用 Skill。

**5. Few-shot 选择纪律：2-5 个 sharp examples 胜过一博物馆平庸例子**（来源：dev.to edo911 2026-09-24 + digitalinsight 2026-06-08 实拉）：好例子=diverse 且 slightly annoying——edge cases/near-misses/format traps；**8 个几乎相同的 happy-path 样本教会模型"听起来对但脆弱"**；例子四标准=代表性（真实输入非理想玩具）/一致（同一标注逻辑/语气/格式）/最小（刚够教模式）/多样（覆盖变体不引入矛盾）。判据：**few-shot 选例=2-5 个代表真实输入分布、含边界与格式陷阱的例子，不堆 happy-path**。提升层：工作流/可复用 Skill。

**6. 上下文预算五桶：system 一次优化、工具 lazy 注册、输出预留**（来源：foojay 2026-05-22 + agentixforce 2026-05-13 实拉）：五桶典型占比=system prompt 5-15%（500-4000 token，一次性优化、激进压缩）/tool schemas 10-40%（每工具 100-400 token，**lazy registration 只含当前任务阶段相关工具**）/retrieved 20-60%（最大杠杆几乎总是）/history 10-30%（线性增长直到压缩）/model output 5-20%（verbose 贵）——**输出预留常被忘，导致截断**。判据：**上下文预算=五桶分层，工具按任务阶段 lazy 注册、输出 token 显式预留防截断**。提升层：工具/工作流。

**7. Context Window Packing 模式：packing policy + 三回收策略 + 调用前审计**（来源：agentpatternscatalog 2026-06-02 实拉）：定义 packing policy=预留 N token 给 system+tools+response，其余按 history（压缩后）/retrieved（rerank 后 top-k）/current state 分配；三回收策略=eviction（丢最旧）/summarisation（压缩）/selection（相关性排序）；**每次调用前审计 token 数**——保证窗口边缘行为可预测、取舍可检查。判据：**上下文打包=显式 policy+三策略（丢/压/选）回收+每次调用前 token 审计**。提升层：工作流/可复用 Skill。

**8. Prompt 模板漂移检测：hash 钉模板、eval 集钉 hash**（来源：futureagi《Eval Data Drift Detection》2026-05-20 + aitoolsguidebook 2026-05-25 实拉）：夜间 hash 活跃 prompt 模板，与 eval 集存储的模板 hash 对比、失配报警；**每个 eval 集版本钉到它撰写时对应的模板 hash**（system_msg+few_shot+tool_schema 拼接后 hash）；每次 agent 调用记录 prompt version + sha256 前缀。判据：**模板漂移=模板 hash 夜间比对+eval 集钉模板 hash+每次调用记 version/sha——漂移是静默的，hash 是唯一自动捕获手段**。提升层：工具/工作流。

**9. DSPy 自动优化：给训练集+metric，优化器调 prompt 到收敛**（来源：dspy.ai 2026-03~09 实拉）：MIPROv2=bootstrap few-shot 候选+基于任务动态提案指令+贝叶斯优化找最优组合（可联合优化指令与示例）；GEPA=反射进化优化器——维护候选程序种群、验证集评分、**LLM 反射（基于 metric 的逐预测器自然语言反馈）提案指令编辑**、Pareto-frontier 采样；COPRO=指令候选按 breadth×depth 生成评分保留最优；核心=表达任务为结构化签名而非手写 prompt，换代码/metric 后 re-compile。判据：**提示优化=给训练集+metric 用优化器（MIPROv2/GEPA）自动迭代到收敛，不靠手工猜 prompt 技巧**。提升层：模型/工具/工作流。

**10. 重试分级五层降级链 + context length 永不原样重试**（来源：dev.to correctover 2026-07-02 + dev.to multigrid 2026-08-08 实拉）：错误分级=transient 5xx/timeout 用指数退避+全抖动（0.5/1/2/4s 至上限 8-10s）；**429/过载 503 快速重试=给已说没余量的系统加负载**；401/403/429 quota 不重试——告警+降级模式；五层降级链=①retry backoff（2-30s）②provider rotation（1-5s）③model downgrade（1-3s）④verified failover（950ms-3s）⑤cache-on-failure（~50ms）；**context length exceeded 永不原样重试**——截断/总结/换长上下文模型后再试。判据：**LLM 失败处理=错误分级（transient 重试/429 退避/quota 不重试）+五层降级链+context 超限先改请求再重试**。提升层：工具/工作流。
