## 独点（10）

**1. 双流混合融合（Dual-Stream Hybrid Fusion）：a11y 树+像素 grounding 双通道，点击坐标吸附到最近合法框**（来源：agdex-desktop-gui 实拉）：纯视觉 grounding=100% 普适（任何像素都能点）但**单像素 miss-click 高频**；纯 OS accessibility 树=约 60% 覆盖（自定义 UI/canvas 上失效）；**双流=98% 覆盖且优雅回退**——agent 内存中维护活跃 a11y 树快照+同时抓屏幕像素，VLM 预测目标视觉元素后，运行时把坐标**吸附到树里最近的合法 bounding box**，消除单像素点错。判据：**坐标只是中间量，最终点击目标=最近合法语义元素——双通道互为修正**。提升层：工作流/工具。

**2. 感知三架构+按场景选型：视觉/结构化/DOM 混合**（来源：scien-cx + openlegion + ailearningguides 实拉）：①**Vision-based**（截图+像素坐标，Claude CU/Operator）——通用（不感知是浏览器还是桌面）但每步贵；②**Structured extraction**（DOM/a11y 快照文本喂模型，Playwright MCP/browser-use）——token 低、web 任务精度高、好调试，但只限浏览器；③DOM+视觉混合。**DOM 提取快省但盲视觉布局（CSS 隐藏元素仍出现在 DOM，agent 会点看不见的东西）；a11y 树=用户真实所见语义（role/name/value/state）、跨站免 per-site selector、比截图感知快**。判据：**浏览器内优先结构化/a11y，跨域桌面优先视觉——感知方式按环境选**。提升层：工具/工作流。

**3. OS 语义层：LUMOS 语义蓝图（stable identifiers+action affordances）+指针语义 grounding**（来源：LUMOS-2606.30697 实拉）：把原生 accessibility 元数据和浏览器 UI 结构转成机器可读语义蓝图（**稳定标识符/角色/名称/值/边界/可行动作**）；支持**实时指针语义定位**——通过 OS 自动化 API 查光标下/附近的 UI 元素；比 OCR 像素级文本提取更稳定且隐私友好（MMPro 同向：直接用原生元素坐标+语义标签做跨模态对齐）。判据：**桌面 agent 的感知层应建在 OS 语义上而非像素 OCR——稳定、隐私、可行动**。提升层：工具。

**4. GUI grounding 评测：Element/Click Accuracy=预测点落在目标 bbox 内即命中**（来源：AutoGUI-v2-2604.24441 + WinDeskGround-2605.16402 + GUI-CEval-2603.15039 实拉）：**Element Accuracy 成主指标（预测点∈目标元素 bbox 即对）**；WinDeskGround 细化=落在**有效可点击区域**才算 hit（多窗口桌面）；GUI-CEval 按能力维度分层——**Perception/Grounding 达 82-90%，Reflection/Evaluation 仅 21-49%：推理与修正能力远落后于感知**（在线真实交互成功率 33%）；AutoGUI-v2 提 NID（Normalized Interference Density）量化目标周围视觉杂波——按区域/动作类型分解指标。判据：**评测 GUI agent 不能只看整体成功率——感知强、修正弱是 2026 通病，要按能力维度看**。提升层：可复用 Skill。

**5. 合成轨迹数据管线：结构化代理生成→像素映射→多 agent 验证**（来源：MolmoWeb-2604.08516 + AgentTrek + WebFactory-2603.05044 + Anchor + OpenMobile-2604.15093 实拉）：高质量训练数据=**AxTree Agent（有结构化页面数据）执行任务记录动作→动作映射回截图像素坐标**（模型输入纯视觉也能对齐）；质量保障多 agent=**Planner 设子目标/Operator 执行/Verifier 用 LLM-as-judge 确认完成**；**Anchor=分支点轨迹扩展**（从少量已验证种子示范识别状态变化分支点→生成状态接地的新任务变体→verifier 做状态感知检查+轨迹级一致性）；OpenMobile=**learner/expert 策略切换**——捕获标准模仿学习常缺的错误恢复数据；WebFactory=行为意图对齐反馈。判据：**GUI 训练数据三环节=结构化执行生成+像素映射+多 agent 验证——缺验证环节数据全是噪声**。提升层：工作流/可复用 Skill。

**6. GUI agent 失败四分类+对应解法，生产自愈五层**（来源：Learning-from-Failure-2606.31270 + gemini-self-healing 实拉）：LLM 分析 OSWorld 轨迹归四类失败=**grounding errors（点错元素）/competency gaps（能力缺）/knowledge deficiencies（知识缺）/redundant loops（重复循环）**→对应解法=**visual search（视觉搜索）/terminal execution（终端执行）/knowledge support（知识支持）/repetition warnings（重复警告）**；生产自愈架构五层=**触发→失败分类器（打四类标签）→恢复 playbook（每标签有配方）→视觉漂移监控（站点变了先发现）→人工升级阈值（带截图上下文）**。判据：**失败先分类再恢复——同一种重试策略对四类失败都无效**。提升层：可复用 Skill。

**7. 视觉错误恢复：wait-and-retry+状态对比+弹窗检测+harness 层看门狗**（来源：max-gherman + callsphere + fazm 实拉）：按钮没响应=页面还在加载/弹窗遮挡/元素误认——**恢复靠视觉推理：动作后无预期视觉变化→等待→再截图对比**；显式处理 unexpected dialogs（cookie 横幅/会话超时弹窗/意外重定向/过期状态）；**fazm harness 层修三坑=per-tool wall-clock watchdog 合成失败事件（SDK 静默把已取消 prompt 的输出当下一响应）/中断后 5s time-to-first-token 竞态/resume 不安全时 priorContext replay 到新 session**。判据：**视觉 agent 的恢复=动作后对比屏幕状态，harness 层必须有看门狗合成失败**。提升层：工具/工作流。

**8. GUI agent 安全：沙箱化浏览器 profile+高风险动作授权层+seccomp 隔离+一次性短命会话**（来源：systemshardening + anomity + mech-app + createos 实拉）：**agent 浏览器 profile 无持久凭据/无保存密码/无真实会话 cookie**；高风险动作（URL 栏输入/含 secret 表单/文件删除/发邮件）走**授权层=可 HITL 确认/限流/阻止**；**seccomp-bpf namespace 隔离**禁凭据读取 syscall、禁访问内部服务；CVE-2025-47241=自动化库 URL 白名单绕过——**"人能绕过的浏览器/OS 层控制，足够强的 agent 也能绕过"**；凭据走 **broker 注入**：一身份一服务一任务、最短生命周期。判据：**agent 驱动的是隔离 VM/容器不是你的桌面；prompt 里的安全策略只是行为不是授权**。提升层：工作流。

**9. 长时程桌面 CUA：Orchestrator+Reflection-Memory Agent+专用 Tool Agents**（来源：OS-Symphony + IntentCUA-2602.17049 + UFO² + GUI-Owl-1.5 实拉）：OS-Symphony=**统一 Reflection Message Protocol**（编排者+反思记忆 agent 压缩执行轨迹维持状态+工具 agent），SOTA（OSWorld 65.8/WindowsAgentArena 63.6/MacOSArena 46.0）；IntentCUA=Planner/Plan-Optimizer/Critic 共享记忆，**把原始交互轨迹抽象成多视图 intent 表示+可复用技能**，减少冗余重规划、缓解跨应用错误传播；GUI-Owl-1.5=**device-conditioned 交互协议**（系统消息定义各平台动作空间）+滑动窗口压缩交互历史+动作空间扩到外部工具/API/MCP；Cua 2.0=多 agent 同机不同窗口、各带 session+合成光标。判据：**长时程桌面可靠=轨迹压缩成意图记忆+角色分工（编排/反思/工具）**。提升层：工具/工作流。

**10. 结构化感知下的动作用元素引用而非坐标：bid 编号动作空间**（来源：BrowserGym + agentpatternscatalog + Playwright MCP + niteagent 实拉）：BrowserGym 原语=**click(bid)/dblclick(bid)/fill(bid,value)/press(bid,key)**——bid=编号的交互元素引用；**结构化状态（编号 a11y 树）→动作走元素引用，DOM 变化后引用仍稳，像素坐标一变就断**；Playwright MCP=浏览器 a11y 树快照直接暴露语义元素引用（角色/标签/可聚焦元素→可执行动作）；Browser Agent 组件=**Agent（对结构化页面状态推理发紧凑动作）+Browser Driver+编号 a11y 提取器+小动作词汇表+动作后 Page Snapshotter**。判据：**结构化感知下动作一律用元素引用（bid）——坐标是纯视觉架构才需要的**。提升层：工具/可复用 Skill。
