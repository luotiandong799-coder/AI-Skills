## 独点（10）

**1. A2A 协议定位与 2026 演进**（来源：a2aprotocol.ai 官网 2026-09-30 + agent2agent.info《What is A2A》2026-09-15 + google/A2A GitHub docs 2026-06-24 + practicallogix《2026 Agent Interoperability Reset》2026 实拉）：**A2A=Google 发起的开放标准，2025-04 发布→2025-06 捐 Linux Foundation→2025-08 IBM 的 ACP 并入→2026-03 v1.0 生产就绪；50+ 伙伴（Atlassian/Box/Cohere/Intuit/LangChain/MongoDB/PayPal/Salesforce/SAP/ServiceNow…）；2026 A2A+MCP+AGENTS.md 同入 AAIF（Linux Foundation 治理伞）——两巨头标准同一治理机构；作用=跨框架（LangGraph/CrewAI/ADK/Genkit）跨厂商 agent 发现能力、协商交互、安全委托任务，不暴露内部状态**。提升层：工具。

**2. A2A 核心概念模型**（来源：google/A2A llms.txt 2026-06-24 + a2a-protocol.org v1.0.0 规范 2026-08-25 + maeste《Agentic System A2A》2026 实拉）：**五要素：AgentCard=JSON(-LD) 能力广告（固定 /.well-known/agent-card.json：name/description/version/supported_interfaces（URL+protocol binding+tenant+protocol version）/capabilities（streaming/push_notifications/extensions）/skills）；Message=单轮通信（问题/答案/指示/更新）；Task=有状态工作单元（可立即完成或长期跟踪）；Part=内容容器（text/file 等类型化）；Artifact=任务具体产出（文档/图像）；状态机 7 态=SUBMITTED/WORKING/COMPLETED/FAILED/CANCELED/REJECTED（终态）+INPUT_REQUIRED/AUTH_REQUIRED（中断态）**。提升层：工具。

**3. A2A vs MCP vs ACP 分工**（来源：a2a-protocol.org《A2A and MCP Comparison》2026-09-15 + a2aprotocol.ai《AI Protocols Analysis Report》2026-06-13 + mcpservers.org《A2A vs MCP》2026-07-11 + ACM《Security Analysis of Agentic Protocols》2026 实拉）：**A2A=agent↔agent 水平互操作（跨组织/框架边界），核心单元=Task 有状态生命周期，发现=Agent Card 著名 URL，方向=水平；MCP=agent↔tool 垂直进能力层，核心单元=tool call/resource read，发现=initialize 协商，方向=垂直，解决 M×N 集成；ACP（BeeAI/IBM，local-first）已并入 A2A；典型边界：MCP 单组织内、A2A 跨组织；用 MCP 连接两个 agent=interface confusion 用错层**。提升层：工具。

**4. A2A v1.0 技术细节**（来源：a2a-protocol.org《What's New v1.0》2026-09-30 + v1.0.0 规范 + a2a-js migration-guide 2026-07-26 + a2aprotocol.ai《Sample Methods》2026-05-25 实拉）：**传输 MUST HTTP(S)；负载=JSON-RPC 2.0（除 SSE 流包装外）；流式=SSE 实时更新；版本协商=A2A-Version header（v1.0 SDK 自动发，服务端 DefaultRequestHandler 校验）；v1 改数字枚举（TASK_STATE_*）+ROLE_*；任务 ID 幂等=goal+session 哈希确定性生成（重试同 ID，接收层先查重）；结果回传=push-notification webhook（X-A2A-Notification-Token+JWT 签名/HMAC/API key 验真，防假 A2A Server）+GetTask 兜底（防 webhook 丢失）**。提升层：工具。

**5. A2A 安全**（来源：a2a-protocol.org v0.2.0 规范（Transport Security）2026 + beyondscale《A2A Security CISO Guide》2026-04-24 + arnav.au《Securing A2A》2026-07-16 + theorydelta《Multi-Hop OAuth Delegation》2026-06-15 + praesidia《Delegation Abuse Threat Model》2026-05-26 + arXiv《Secure A2A Application》2026 实拉）：**生产 MUST HTTPS（TLS1.2+ 强套件）；认证=OAuth 2.1 授权码+PKCE、M2M client credentials+sender constraints、短时 JWT 严格 audience（TTL<15min）；令牌按 agent+skill 粒度 scope、refresh 轮换；委托=每 hop 新受限 token、scope 只减不增（等价授权不能超过委托方）、最大委托深度限制（RFC8693 token exchange 模式）；威胁=编排者凭证库持久化跨任务复用（短时+每任务显式再授权+凭证使用审计）；能力声明验证防 agent 伪造（认证在 HTTP 层、授权在 server 内：每 skill 定义哪些 caller 可看/可调/哪些 tenant/资源/后台动作/审批规则/审计事件）；Model Armor 保护 A2A agent**。提升层：可复用 Skill。

**6. A2A 生态实施与 SDK**（来源：a2a-adapter PyPI 0.2.12 2026-05-29 + stacka2a.dev《SDKs by Language》2026-04-09 + crewAI《A2A Agent Delegation》2026-08-15 + Google Codelabs《Scale Agents》2026-07-23 + Google Cloud Agent Registry 2026-09-24 实拉）：**a2a-adapter=三行 setup（import/create/serve）内建 n8n/LangChain/LangGraph/CrewAI/OpenClaw/Hermes/Claude Code/Codex/Ollama 适配器+流式自动检测；LangGraph Platform=每 assistant 零配置自动 A2A 端点 /a2a/{assistant_id}+Agent Card 从元数据自动生成；CrewAI=A2AServerConfig 把 crew 暴露为 A2A server；Google ADK=BaseAgent 委托；发现=Agent Registry（Google Cloud，支持 v1 supportedInterfaces 显式声明）/Azure Cosmos 中心注册表（agent 启动注册、运行时查询，消除硬编码端点，支持数百 agent 规模）；Gemini Enterprise 可注册任意 A2A agent 进 web app**。提升层：工具。

**7. A2A 编排反模式六条**（来源：inovaway《6 Anti-Patterns》2026-03-26 + agentpatterns《Over-Orchestrated》2026-06-28 + zenml《Multi-Agent Infrastructure Gaps》2026-10-01 + zylos《Hierarchical Coordination》2026-03-01 + sudoall《Coordination Playbook》2026-06-24 + belsoft《A2A Enterprise Implementation》2026-06-20 + invra《Broken by Default》2026-05-16 实拉）：**①reliability paradox：95% 可靠×5 agent=77%、×10=60%（链长指数衰减——每 hop 要校验层）；②over-orchestration：单循环没试过就上编排/子 agent（交接上下文丢失代价常超协调收益——默认先一个 agent 持全上下文）；③delegation loops：A→B→A 无限循环（真实案例两 agent 互求澄清 11 天 $47k——需循环检测+终止规则+明确任务边界防"out of scope"再委托）；④interface confusion：MCP 当 agent 间协议用；⑤no validation：无接收层校验（模型解释非确定，同样 malformed 输入 9 次对 1 次错）；⑥no versioning：编排 prompt 更新输出格式变下游崩；加 ⑦context leakage：串行化全会话历史进任务消息=PII/内部细节泄漏给链上每 agent——每任务只传最小上下文；⑧no goal gate：无硬目标门的 agent 循环 over-run（不"够了"停，只在窗口满/token 尽/步数上限停）**。提升层：工作流。

**8. 多 agent 编排模式 2026**（来源：sukruyusufkaya《Orchestration Patterns》2026-09-30 + AWS《Multi-Agent Architectures》2026-10-01 + acingai《Agents in Production》2026-04-23 + mlflow《Production-Ready Agents》2026-05-28 实拉）：**六模式带强弱：orchestrator-worker（控制+扩展，但编排者=单点故障+误解任务全错向+管理 token 消耗大）；parallel fan-out+synthesis（路由器同任务并扇出多专家+合成器统一输出——跨域评估（安全/成本/合规/性能）专用）；evaluator-critic（产生眼与评审眼分离，writer-editor 关系，显著提质量）；collaborative/debate（多视角但可能绕圈）；tightly scoped sub-agents（每子 agent 单一职责可换件——Google Bake-Off 1h→10min）；硬目标门（goal gate）：任何无显式终止状态的循环=贵转圈，需步骤上限/token 预算**。提升层：工作流。

**9. Agent 互操作标准栈 2026**（来源：informertech《ARD》2026-06-18 + InfoQ《ARD Specification》2026-07-14 + Cisco Outshift《Agentic Resource Discovery》2026-09-21 + w3c-cg《Agent Network Protocol White Paper》2026-08-27 + dailyaiworld《A2A 1.0 Joins AAIF》2026-08-18 + generativeprogrammer《Emerging Standards》2026-09-26 实拉）：**三层标准栈：MCP=agent→tool（单元=tool call/发现=tool listing/边界=单组织）；A2A=agent→agent（单元=Task/发现=/.well-known/agent-card.json/边界=跨组织）；AGENTS.md=agent↔repo（单元=instructions/发现=仓库内文件/边界=单 repo）；ARD（Agentic Resource Discovery 2026-06-17，11 公司）=MCP 之前阶段的统一发现/验证/信任机制（AGNTCY Agent Directory 联邦发现实现）；UCP（Google+Shopify+IBM）=agent 商业交易域扩展；IETF 草案=OpenA2A 身份（Ed25519 challenge-response+ML-DSA）、PACE over MOQT（QUIC 媒体会话）**。提升层：工具。

**10. 生产实施决策**（来源：AppsFlyer 治理多 agent 平台 2026-08-31 + IBM《Production Agentic AI》2026-08-23 + Microsoft《Multi-agent Patterns》2026-07-06 + 36kr《GPT-5.4 Codex Harness》2026-04-16 + anyscale《Ray Serve Multi-Agent》2026-05-07 实拉）：**编排 agent 只做 plan-before-act（意图→治理执行计划），不回答问题；不依赖 roadmap 项平台（接口后接，战略选项落地再换）；eval 非可选（tracing 看单次、evals 判变好变坏跨多次）；内部流优先平台原生编排，跨平台用 A2A+MCP-fronted agents，统一 SDK 标准化安全；每子 agent 单职责可换件（模块化）；AI agent 基建层趋势：OpenAI Codex harness 把控制流/模型调用/工具路由/暂停恢复与沙盒（读写文件/装依赖/跑代码）两层解耦——第三方框架空间被压缩**。提升层：工作流。
