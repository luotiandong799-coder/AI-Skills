## 独点（10）

**1. MCP 2026-07-28 规范：stateless 核心+Apps/Tasks 扩展**（来源：MCP 官方 release-candidate + Cloudflare MCP v2 实拉）：**2026 最大修订=stateless 核心：每请求自描述（协议版本+客户端能力内联 _meta），capabilities 来自 server/discover，任何 server 实例可处理任何请求——在普通 HTTP 基础设施（round-robin LB 无需 DPI，Mcp-Method/Mcp-Name HTTP 头）上扩展**；**扩展一 MCP Apps（SEP-1865）=server 渲染交互 HTML 界面，host 在沙箱 iframe 渲染；工具提前声明 UI 模板供 host 预取/缓存/安全审查后才运行；渲染 UI 与 host 走同一 JSON-RPC，UI 动作=直接工具调用同审计同意路径**；**扩展二 Tasks=长时运行：server 以 task handle 应答 tools/call，客户端用 tasks/get/update/cancel 轮询驱动，任务创建 server 主导**；**授权更贴近 OAuth/OpenID Connect+正式弃用策略让协议可进化不破坏既有**；**实际效果=server 可在单个 Cloudflare Worker 运行，无需有状态基础设施**。提升层：工具。

**2. MCP 服务端三层架构：协议适配层与业务逻辑解耦**（来源：Semantic Scholar serverless MCP + Microsoft build MCP server + OpenAI custom MCP 实拉）：**三层=①protocol adapter 层（外部客户端与内部应用逻辑的边界：协议消息翻译成标准应用请求+响应转回协议格式，封装解析/模式校验/错误编码——所有协议特定逻辑在此）②application logic 层（暴露给 LLM 的实质功能，协议无关，操作泛型请求对象——同一业务逻辑可服务多种协议/接口形态，提升可复用性与可测性）③runtime environment 层（serverless 平台管理）**；**分层隔离五职责=ChatGPT→HTTPS /mcp→MCP tools→Service layer→DB/外部 API，认证授权与前端资源各自分离**；**微软生产纪律=必须认证（除非场景明确需要否则禁匿名）/凭据当秘密（不硬编码不进源码，进 Key Vault）/下游调用最小权限（只 scope 暴露工具所需）/记录监控工具调用**。判据=自建 server 先按三层拆再写工具；认证=默认要求。提升层：工具。

**3. MCP 客户端执行架构：host 作 broker+沙箱+函数 stub**（来源：MCP client best practices + richards.ai sandbox profile 实拉）：**集成模式=host 注入函数 stub→经进程内或 stdio 通道拦截调用（网络权限全程拒绝）→作为 tools/call 分发到 MCP server；三组件=①沙箱（隔离环境跑模型生成代码，无直接网络，唯一外界接口=生成的函数 stub 路由回 host）②host=broker（收沙箱函数调用→映射正确 MCP server→执行工具→返回结果；授权 token 与凭据由 host 持有，永不暴露给生成代码）③model（只见沙箱返回，通常是工具输出）**；**安全沙箱执行 profile=无继承环境只显式 allowlist/只读项目挂载/独立 scratch 挂载/不挂 home/无 SSH agent socket/无 Docker socket/无云凭据文件/网络除非需要否则禁用/进程超时+内存限制/工具级 seccomp-AppArmor profile/哈希固定包**。判据=模型代码一律进沙箱；凭据只进 host 不进生成代码。提升层：工具。

**4. MCP 工具治理控制面：管动作不管输出**（来源：Microsoft Agent Governance Toolkit + AAAI InfrastructureSentinel + MTGUARD 实拉）：**AGT=开源运行时治理层，坐在 MCP client 与工具 server 之间，每次工具调用执行前按策略评估——管 agent 动作不管模型输出；治理管道=定义扫描→策略评估→响应检查**；**InfrastructureSentinel=专门 guardian LLM 解读自然语言策略+上下文推理，四控制点=输入消息过滤/工具选择验证/执行时验证/事后审计——按用户角色/操作时机/系统上下文动态执行策略，替代硬编码规则**；**MTGUARD 混合分析=按工具调用生命周期三阶段三组件=执行前参数审计器（查工具调用参数）/执行中行为监视器（监控工具行为）/执行后结果验证器（审计执行结果）**。判据=工具调用=动作面，治理层放 client-server 之间；策略=自然语言可解释+四控制点。提升层：工具。

**5. MCP 工具描述质量：评分 rubric+smell 自动检测器**（来源：arxiv MCP tool descriptions are smelly + AWS MCP tool design 实拉）：**首个结构化评分 rubric 评估工具描述各组件质量+首个自动化 smell scanner（FM-based）识别质量问题——工具描述是 agent 效率的第一杠杆**；**改进描述=第一步：澄清值含义（数字单位/格式）/自然语言如何映射到参数/工具用途边界；但过头=bloat：多 MCP server 载入客户端时 context 与成本快速膨胀**；**返回形状影响行为：工具返回 50 字段/结果会快速填满上下文——返回要精简（只回必要字段），工具粒度=粗工具一次干多步 vs 细工具多次往返的取舍**；**判据=描述写"值是什么/自然语言怎么映射/工具干什么"，返回瘦身，载入前先审描述**。提升层：可复用 Skill。

**6. MCP 生态规模 2026：10000 server 里程碑**（来源：Daily AI World registry + DEV MCP guide + DEV ecosystem categories 实拉）：**官方 registry 2026-09-01 超 10000 注册 server（1 月 2000→9 月 10000，9 个月 5 倍增长，最快协议生态）；公开 server 2025 Q1 约 1200→2026-04 9400+，SDK 月下载 9700 万（2026-03）**；**生态构成=4800+ server 跨 40+ 主要目录（Glama/MCP.so/Smithery/PulseMCP）+40+ 类别（浏览器自动化到生物信息学）+1000+ 聚合/agent 服务组合 MCP 工具**；**官方参考 server=filesystem/git/github/gitlab/postgres/sqlite/brave search/slack/sentry；厂商维护=Stripe/Linear/Notion/Asana/Cloudflare/Supabase/Vercel/Square/PayPal/Atlassian/Zapier——五大厂商（Anthropic/OpenAI/Google/Microsoft/AWS）全支持，成事实互操作层**；**作用=企业 agent 连接整个工具栈无需自定义集成代码，部署从数周缩到数小时**。提升层：工具。

**7. MCP 网关与工具联邦：把 server 当微服务治理**（来源：agentgateway + IETF MCP-AX + IETF agent-gw 实拉）：**agentgateway（Linux Foundation AAIF 项目）=tool federation：聚合多 MCP server 到单端点；协议支持 stdio/HTTP-SSE/Streamable HTTP；OpenAPI 集成把现有 REST API 暴露为 MCP 原生工具；内置 MCP auth 规范合规（Auth0/Keycloak）+A2A 网关 agent 间路由身份追踪**；**把 MCP server 当微服务=发现/签名并 scope 每次工具调用/保留 agent 调用审计轨迹；IETF MCP-AX=层级工具命名空间委托（master-subagent 结构，Namespace Prefix 点分字符串建立层级所有权，跨异构网络组合）**；**IETF agent-gw 四能力=A2A Gateway（agent 间通信：协议翻译/认证安全/异步任务/点对点网络/agent 路由注册发现）/MCP Gateway（工具调用）/Model Routing Gateway（LLM 调用）/Network Gateway（底层网络）**。判据=工具面大了先上网关做联邦+审计；A2A 与 MCP 互补分工。提升层：工具。

**8. MCP 测试纪律：Inspector 三步+故意测错**（来源：MCP Inspector 官方 + Aident testing + MCPJam 实拉）：**官方 Inspector=web 图形/CLI/桌面三客户端一体；核心流程=Connect→List Tools→Run Tool 三步；连接成功≠测试完成，测试从连接后开始**；**测试纪律=故意测无效输入：缺必填字段/非法枚举值/错标量类型/请求不存在记录；期望=server 清晰拒绝+不执行操作+返回足够上下文修复输入且不泄露秘密/内部堆栈——一次只测一个失败（含五个错误的请求只证明"有东西坏了"不定位）**；**MCPJam=16 client 配置×170+ 模型跨客户端测试+OAuth 调试+测试用例管理（AI 生成）+CLI E2E 评估门禁回归，gate regressions 到每个部署**。判据=每个 server 交付前过无效输入测试集；回归门禁进 CI。提升层：工具。

**9. MCP OAuth 机器身份：Client Credentials 扩展**（来源：MCP 授权扩展 + 2026-07-28 RC blog 实拉）：**趋势=调用者从"人在浏览器批准访问"转向"云工作负载 agent 自带身份、代表缺席用户、或委托更窄权限给子 agent"——需要标准化身份委派**；**OAuth Client Credentials 扩展=机器对机器认证：client 用应用级凭据（client ID+secret 或签名 JWT 断言）而非委派用户凭据，直接向授权服务器证明身份拿 access token，无需浏览器重定向/用户交互——自动化系统连 MCP server 的通道**；**Enterprise-Managed Authorization=企业集中访问控制框架；2026-07-28 RC 授权整体更贴近 OAuth/OpenID Connect 部署**。判据=无人在场的 agent 工作负载用 Client Credentials；企业用集中授权。提升层：工具。

**10. MCP 供应链治理：租户白名单+锁版本+凭证有效期**（来源：抖音 MCP 安全拆解 + Microsoft 供应链 实拉）：**威胁清单=恶意/被劫持服务器/供应链攻击/同名工具遮蔽（拦截可信调用）/凭证管理风险（泄露 OAuth/API key）；工具描述投毒最阴=恶意服务器把指令塞进工具 description，随定义原样进入模型上下文——提示注入变种且每次会话都生效**；**缓解三层=①接入前把描述当不可信输入审查 ②锁 server 版本拒绝静默更新 ③每 server 配最小权限凭证并设有效期**；**微软=租户级 MCP server 发布者/服务器白名单（官方 catalog 提供一手可验证来源 server）→关闭"允许所有连接"→只启用 agent 实际需要的特定工具（不禁用=每工具都是注入成功后的爆炸半径）**。判据=接入=扩权限流程：审描述/锁版本/最小凭证/白名单/只启所需。提升层：工具。
