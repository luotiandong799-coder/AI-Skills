## 落地 7 独点（每点标注提升层）

### 1. 表格 RAG 三模式谱系：双检索 / NL2SQL+双 embedding / 图感知（工具·工作流）
来源：arxiv-2410.04739-tableRAG / lobehub-tabular-rag / aclanthology-T-RAG+MultiTableQA
- **TableRAG（百万 token 表理解）**：查询扩展 + schema 检索 + cell 检索，先定位关键信息再喂 LLM——减少 prompt 长度、缓解信息丢失；Arcade/BIRD-SQL 两个百万 token 基准。
- **Tabular RAG 三互补模式组合**：NL2SQL（精确聚合/join）+ 行级 embedding（语义模糊行搜）+ schema 级 embedding（跨多表路由）——按查询类型选，不只有 SQL 一条路。
- **T-RAG（表语料感知）**：分层记忆索引（表=节点、多特征聚类成异构超图）+ 多阶段检索 + 图感知上下文组织；MultiTableQA=3 任务类型 57,193 表 23,758 问（跨表 QA 首个基准）。
- 判据：单表精确查询走 NL2SQL、模糊行语义走行 embedding、多表路由走 schema embedding——三个检索面互补，缺一个就漏一类查询。

### 2. 表格解析工具分型：格子/流表/OCR/TableFormer（工具）
来源：markaicode-rag-tables / ai-tldr-pdf-tables / docling-tableformer / google-docai-gemini-table / llamaindex-table-parsing / arxiv-2507.12425-structured-enterprise
- **格子表（lattice）=可见网格线→Camelot；流表（stream）=空白对齐→pdfplumber**；扫描图像表必须 OCR 管线，pdfplumber 对图像型 PDF 直接返回空。
- **Docling TableFormer**：百万级表格训练，处理部分边框/空单元格/合并单元格；docling-pdf 纯 Rust 管线。
- **Gemini layout parser**：财务报告/技术手册复杂表（合并单元格+多层表头）是 RAG 常见失败点，专用解析器对齐表头与单元格。
- **LlamaParse v2**：分层配置（Fast/Cost Effective/Agentic/Agentic Plus）、自动纠偏、页级置信分。
- 判据：先按表型选解析器，再考虑是否升级到 TableFormer/VLM 档；企业表合并单元格场景不要用基础格子解析器。

### 3. 表格表示效应：HTML 最稳 / Markdown 生产默认 / 嵌入对齐（模型·工作流）
来源：theneuralbase-table-rag / arxiv-2606.09578-tabverse / arxiv-2601.04202-teletables / arxiv-2605.31550-str / then euralbase-ocr-table-preservation
- **TabVerse（受控跨格式基准）**：同一表格内容对齐多结构格式+渲染图，3 任务（QA/结构理解 SUC/结构重建 SR）——**表示选择显著影响表格理解**；HTML 是最稳文本格式（QA/SUC 上最鲁棒），LaTeX/Markdown 波动；结构敏感任务文本>渲染图像（Gemma-3 文本 +7-10pp）；模型族依赖（InternVL3.5 图像不差）。
- **TeleTables**：HTML 最强（显式标记层级单元格关系）；多格式拼接小模型微增益（Llama3.1-8B JSON+MD +5.2pp）；图像表示明显更差。
- **STR（语义三元组重建）**：把层级显式写出来（TripletQL）比 HTML/Markdown 都高 F1 且输入 token 更低——增益来自"把层级写进文本"而非更短。
- **嵌入对齐**：embedding 模型主要训练于散文；Markdown 管道符/短横是 embedding 锚点；生产默认 Markdown（平衡可读性与 LLM 推理），JSON 显式 schema，HTML 精确版式——但最终按你的检索集实测选，不无脑 Markdown。
- 判据：结构化敏感任务给 HTML/显式层级文本，别只靠渲染图像；"表示选择"与"路由"分开测。

### 4. 表格理解评测方法论：复杂度=推理步骤数（可复用 Skill·工作流）
来源：tablebench.github.io / ojs-aaai-34739 / arxiv-2506.18421-treb / semanticscholar-wildtablebench / arxiv-2605.05955-tablevista / arxiv-2601.07280-reasontabqa / arxiv-2506.13405-realhitbench
- **TableBench**：4 大类（事实检查/数值推理/数据分析/可视化）18 子类，**任务复杂度按所需推理步骤数定义**。
- **TReB**：26 子任务分类学=浅理解+深推理双维。
- **TableVista**：3000 题×10 视觉变体=30000 多模态样本，评测 29 模型。
- **WildTableBench**：首个自然表格图像 QA 基准（真实世界表格图像，非渲染）。
- **ReasonTabQA**：1932 表 30 工业域、双语、4 复杂结构类型、细粒度推理路径标注（thinking/no-thinking 双模式）。
- 判据：评测自己的表问答管道时按推理步骤数分层报告（单步检索 vs 多步数值推理分开算），别只看总分——单针类分数会掩盖推理断崖。

### 5. NL2SQL 安全执行纵深：安全不依赖模型（工具）
来源：lobehub-tabular-rag / rawgithub-sibyl / tencent-nl2sql-2727492 / pypi-sql-guardrail / oracle-select-ai-profiles / arxiv-2607.22115-rbac
- **双层防御**：只读 DB 角色（GRANT SELECT only，DB 自身拒绝写入即使 LLM 发 DROP）+ SELECT-only 关键字检查——**安全不依赖模型**；再加 SET TRANSACTION READ ONLY + 应用层守卫（belt-and-suspenders）。
- **腾讯企业级三层**：语法预检（正则+AST 拦截 99% DML/DDL）+ 血缘校验（动态 schema 检索杜绝幻觉字段）+ 执行沙箱（云函数只读实例隔离）+ **执行结果驱动自愈**（SQL 报错或返回空值自动触发反思修正）。
- **sql-guardrail/queryguard**：拦 WHERE 1=1、缺 tenant filter、禁列、失控扫描（max_rows=500）、allow_select_star=False；never touches DB。
- **Oracle AI Profile**：enforce_object_list=生成 SQL 不可触及未点名表（scope 是约束不是建议）；SHOWSQL=不执行预览候选 SQL。
- **schema trimming**：schema 全量塞上下文撑爆+困惑模型——先路由到相关表再喂（与 schema 级 embedding 同源）。
- 判据：只读角色是主防御（安全不依赖模型），关键字检查是次防御，沙箱是兜底；错误/空结果驱动反思重写，不把失败当终态。

### 6. 表分块进阶：列感知标签 / 文本化组装 / H-RCL 祖先路径（工具·工作流）
来源：theneuralbase-tabular-pipelines / ragaboutit-9-context-tricks / datasciocean-mixrag / arxiv-2504.09554-mixrag / logic-inc-table-extraction / bswen-table-structure-embeddings
- **列感知 chunk**：按行切但保留列元数据标签（[PRODUCT]Widget[/PRODUCT] [REVENUE]1000000[/REVENUE]），数字带列名才可解释。
- **文本化组装（table-aware assembly）**：检索到的表转标准文本=管道分隔+数值列类型标注+简短 caption——+10-15% token 但 TabFact 定量推理准确率 +22%。
- **H-RCL（MixRAG）**：表格分解为带祖先层级路径的自然语言句（"2026 财年 > Q2 > 营收 > 数值 X"）让 embedding 理解结构化数据——表级摘要 HiT@1 36.27% vs 全 H-RCL 54.10%（数据无坐标=垃圾）；两阶段检索=BM25+Embedding 找父文档→LLM 文档内微型向量检索滤噪控上下文。
- **类型化映射**：入库前把提取列映射到类型化 schema 字段（Revenue 落数值字段非文本 blob）。
- 判据：层级/坐标信息必须显式进 embedding 文本；检索先粗后细（文档级→文档内微检索）；数字列带类型标注。

### 7. 表格 Agent：自演化 spreadsheet agent / pandas 事实校验（工具）
来源：arxiv-2606.10316-tabclaw / arxiv-2509.06278-tablemind / repanda-panwiki / cohere-querying-structured-data
- **TabClaw**：交互式自演化表格 agent——澄清歧义意图→暴露可编辑执行计划→ReAct 流式工具循环→专才 agent 并行多表推理→显式共识+不确定性标记合成；记录已完成工作流、提取持久用户记忆、蒸馏技能。
- **TableMind**：自主程序化 agent=工具增强表推理（TabFact/TabMWP/WTQ/HiTab/FinQA 分拆 RL 训练集）。
- **RePanda**：把声明转可执行 pandas 查询做可解释可验证的事实校验（结构化事实核查）；PanWiki=WikiTableQuestions 映射 pandas 数据集。
- **Cohere 工具模式**：工具描述里写清 dataframe 列名+必须先 import pandas+读特定 CSV——工具 schema 自带上下文。
- 判据：表问答/表核查优先"生成可执行代码（SQL/pandas）+沙箱执行"而非直接让模型读表答——可执行、可验证、可复算。
