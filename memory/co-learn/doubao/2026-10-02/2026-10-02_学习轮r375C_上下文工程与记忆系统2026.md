## 独点（10）

**1. Claude Code 上下文纪律：/clear 阈值 + outcome-not-steps + output styles 机制**（来源：Claude Code《Best practices》2026-09-30 + Anthropic Help《Give Claude context》2026-04-15 + Claude《Steering Claude Code》2026-06-18 + Claude《New rules of context engineering for Claude 5》2026-07-24 实拉）：**/clear 纪律=无关任务间清上下文；同一错误连续两次纠正仍错→污染上下文已成立，/clear 并把学到的东西写进更好的初始 prompt（不是第三次纠正）；CLAUDE.md 过度指定=每条规则都吃上下文且可能互相矛盾（少指定+指现有代码模式/模型，如"看 HomePage 怎么实现 widget 再照做"）；State outcome not steps（"无邮箱用户崩在验证步"优于"打开 userService.ts 第 42 行加 null 检查"）；Claude 5 新规则=从"给例子"转向"设计接口"（新模型判断力强，例子反而约束探索空间）；output styles（claude/output-styles/）=注入 system prompt、**永不 compacted**、每 session 加载、首请求后缓存、指令遵循权重最高——要克制使用**。提升层：工作流。

**2. Prompt caching 经济模型与结构纪律**（来源：IntuitionLabs《LLM Prompt Caching》2026 + ValueStreamAI《AI Caching Strategies 2026》2026-05-15 + DevToolLab《Prompt Caching 2026》2026-06-19 + arXiv 2601.06007《Don't Break the Cache》2026-08-28 实拉）：**Anthropic 档位=cache write 5min TTL 1.25x / 1h TTL 2x / read 0.1x（最新模型 0.025x）/ 最小缓存 token=1024（Sonnet/Opus 级）/4096（Haiku 4.5）/ 5min TTL 命中免费刷新；盈亏平衡点 h*=(w−1)/(1−r)——标准档约 **1 次命中即回本**；结构纪律=静态内容在前、动态内容最后（放错缓存永不命中）；边界控制实证=只缓存 system prompt、排除动态工具结果，比 naive 全量缓存更一致（全量缓存反而增延迟）；长程 agent 评测=caching 减 41-80% 成本 + TTFT 改善 13-31%；DeepSeek 磁盘缓存免存储费+命中输入 $0.0028/1M（折让 98%）；Reasonix 四支柱把前缀命中率稳定在 90%+**。提升层：工具。

**3. 三层记忆架构 2026 共识 + Mem0 四作用域**（来源：Zylos《AI Agent Memory Architecture》2026-05-28 + DevToolLab《Agent Memory 2026》2026-06-22 + Programming Helper《Stateful Agentic Systems 2026》2026-04-27 + Fountain City《8 Knowledge Systems Compared》2026-05-04 实拉）：**三层=Tier1 in-context 工作记忆（当前 session 原始缓冲+工具调用+活动状态，session 结束清空）/Tier2 session 压缩记忆（预算 1,000-3,000 tokens：compaction 摘要+关键决策+约束清单，session resume/compaction 后注入）/Tier3 长期持久存储（跨 session 知识+用户偏好+学习工作流，vector+graph 存储）；episodic（交互记录）/semantic（事实知识）/procedural（技能）三型分工；Mem0=vector+graph+key-value 三层存储+四作用域 user_id/agent_id/run_id/app_id（+可选 org_id），个人化记忆按作用域隔离防串**。提升层：工作流。

**4. 上下文压缩流派与失败模式分类（F1/F2/F3）**（来源：arXiv 2609.32961《Beyond Token Savings》2026 + arXiv 2601.07190《Active Context Compression》2026 + EMNLP Survey《Context Compression》2026 + Preprints《ReSumTool-30B》2026-07 实拉）：**三维分类=压缩目标（压什么）/机制（怎么转换与保留）/控制策略（谁决定何时触发）；失败模式三型=F1 压缩前决策错误/F2 压缩中信息损失/F3 压缩后访问失败；anchored iterative summarization=结构化持久摘要（session intent/文件修改/决策/next steps 四节），触发时只压新增 span 并与既有摘要合并（结构强制保留）；Focus Agent（黏菌启发）=agent 自主决定何时 consolidate 关键学到→持久 Knowledge 块+主动剪枝原始交互历史；ReSumTool-30B（Qwen3-30B SFT）=轨迹近预算时调专用摘要工具压成"reasoning state"（已验证证据+剩余信息缺口清单+下一步）再继续**。提升层：工作流。

**5. RAG 上下文窗口实证：k=20 平衡点 + 二阶段 rerank + chunk 策略**（来源：arXiv 2606.28360《Carolina Guide》2026 + arXiv 2609.22124《RRF k=60 Top-100》2026 + RAGSmith《Chunking precision-recall》2026-08 + di37《Context Engineering Bootcamp Day3》2026 实拉）：**检索深度实证=成功率 k=5→20 提升后平台化，k=100 无额外增益但五倍成本——**k=20 是质量-成本平衡点**；rerank=高效检索器（高召回）→重排器（高精度）两阶段转 robust；RRF 融合=候选集 k=60 截断 Top-100；chunk 小=高精度/大=高召回，overlap 滑窗跨边界保信息；chunk 策略=fixed-size（海量杂乱语料，速度优先）/recursive 分层（有标题的结构化文档，推荐）；"Lost in the Middle"=长上下文中段信息利用差——re-rank 缓解；替代 chunking 不总优于官方固定窗（过度碎片化缺上下文+证据跨块分割是主因）**。提升层：工具。

**6. 长上下文 agent 预算实证：130K 可靠窗口 + 60-70% 主动区 + keep-verbatim zones**（来源：FlowVerify《200K advertise vs 130K reliable》2026-06-26 + AgentNative《Context Compaction Pattern》2026-07-26 + MarkTechPost《4 Mechanisms Beat Context Overflow》2026-09-12 + Zylos《Context Window Economics》2026-05-27 实拉）：**广告 200K 实际可靠 ~130K（工具定义+模型退化吃掉差）；11/12 模型 >32K token 任务性能跌破 50%；实用天花板=名义窗口 60-70%（不是满窗）；主动压缩区=60-70% 利用率就触发（不是 90%+ 恐慌区）；keep-verbatim zones 永不压缩=system prompt+tool schemas（字节稳定保前缀缓存命中）+任务陈述+验收标准+最近几轮（生产共识≈最后几轮原样）；Deep Agents=工具结果 >20K tokens 外置 offload+85% 窗口驱逐旧编辑；compaction 必须命名保留什么=session intent+next steps 字段；实测工程=turn token 25K→12K（-52%）/缓存命中 0→72%/月成本 -72%/p50 延迟 -57%**。提升层：工作流。

**7. 记忆系统评测基准与图形检索补盲**（来源：Mem0《State of AI Agent Memory 2026》2026-04-01 + KeyMem《Graph-Augmented Vector Retrieval》2026 + MemMachine《Ground-Truth-Preserving》2026 + HydraDB《Storage Is Not Memory》2026-09-23 实拉）：**LongMemEval=500 问六类：单会话用户回忆/单会话助手回忆/单会话偏好回忆/知识更新/时间推理/多会话回忆（知识更新与多会话最挑）；BEAM=1M/10M token 规模压测；纯向量检索多跳与时间推理失败→KeyMem=原始对话轮存知识图谱+关键词向量+图遍历双路；MemMachine=ground-truth-preserving 存原始 episod 最小化 LLM 提取+contextualized retrieval（核匹配扩展邻居上下文，语义相关证据跨轮分布时召回提升）；存储≠记忆=检索为中心架构（SQLite FTS5 词法+sqlite-vec 稠密双路，事件原文 verbatim 存消息表+元数据）**。提升层：工具。

**8. Claude Code hooks 事件矩阵与阻断语义**（来源：Claude Code《Hooks guide/Reference》2026-09-30 + ThePromptShelf《Hooks Automation Guide 2026》2026-07-12 + Vibe Coding《Hooks Complete Guide》2026-07-17 + DataCamp《Claude Code Hooks》2026-09-29 实拉）：**事件=PreToolUse（参数创建后、工具执行前：拦截危险命令，exit 2 阻断并把理由回馈 Claude，保护永不触碰的文件）/PostToolUse（工具完成后：收 tool_response，自动格式化/lint/类型检查/触发测试/审计日志，**不可撤销工具**）/UserPromptSubmit/Stop/SubagentStop；matcher 按工具名（Task/Bash/Glob/Grep/Edit/Write）；MCP tool hooks=server 字段+plugin:: 前缀限定（不触发 OAuth）；官方 hook-development skill=PostToolUse 分析 edit 结果给反馈；审计模式=jq 输出 {ts, cmd, exit} >> bash-audit.jsonl**。提升层：工具。

**9. 子代理上下文隔离与注入防御：Visor 盲视 + 子代理输出传播威胁流**（来源：AgentVisor《Semantic Virtualization》2026 + LangChain DeepAgents《THREAT_MODEL DF11》2026-08-30 + ACM《Weaponizing Words》2026 + OpenAI《Designing AI Agents to Resist Prompt Injection》2026-03-11 实拉）：**context isolation=Visor 对原始外部上下文架构性盲视（C_t 不可见），决策只基于可信系统指令+用户查询+净化执行历史（tool_name/canonicalized args 结构化字段）；威胁流 DF11=async subagent 完成输出无净化注入 ToolMessage→污染主 agent（远程子代理处理不可信内容即传播点）；对策=provenance tagging+内容分仓+"untrusted context"角色+跨上下文指令防火墙+deny-by-default 工具策略+system 消息签名标注；OpenAI Safe Url=检测"会话学到信息将外传第三方"→展示确认或阻断（导航/书签同机制）；AgentSecCore=本地零 token 安全内核三层纵深（注入/危险代码/技能篡改/敏感数据）；Intent-Scoped Authorization=授权令牌绑原始意图哈希防 confused-deputy**。提升层：工作流。

**10. 上下文工程 Playbook：Write-Select-Compress-Isolate（WSCI）**（来源：dreaming.press《WSCI Playbook》2026-07-28 + Codex《Write-Select-Compress-Isolate Masterclass》2026-06-19 + Maraj《Context Engineering Playbook》2026-04-10 + Ranjan Kumar《Separates Production Agents from Demos》2026-04-17 + Packmind《Complete Playbook》2026-04-03 + MQDIR《Hidden Lever》2026-04-28 实拉）：**四动作每动作映射可调用 API 原语=Write（memory tool 写窗外，scratchpad 外部化笔记/中间发现/事实，选择性检索）/Select（只选下一步所需，readable_roots 排除无关目录）/Compress（压已有，automatic compaction 保留最近消息 verbatim 压旧轮）/Isolate（独立 subagent 隔离）；位置规则=关键内容放头（system prompt/CLAUDE.md 缓存区）或尾（当前任务），中段注意力弱（50K 参考文档竞争中段）；历史 token 预算硬执行=128K 名义用 60-70%；Living Documentation=CLAUDE.md 每次重大变更（换库/改部署）都更新——过期上下文比无上下文更糟；ACE playbook=结构化子弹集合（唯一 ID+section tag+usage 元数据统计成败贡献次数）替代散文式 system prompt**。提升层：工作流。
