## 独点（10）

**1. 工作流平台选型三问 + 双平台运行模式**（来源：baeseokjae 2026-05-10 + 1337skills 2026-05-30 + 00011000 2026-06-23 实拉）：选型三问=需要多控制/多安全审计/多快上线；Dify=完整生产环境（后端 API server+PostgreSQL+向量库+Redis+API gateway+prompt 版本管理+RBAC 单 Docker Compose）；n8n=事件触发跨系统自动化（400+ connectors）；Langflow=LangChain 可视化 IDE；**常见错误=把这些工具当直接替代品——成熟工程团队常同时跑两个：n8n 做跨系统自动化 + Dify 做对话/RAG 应用**；核心需求决定=文档知识库+细粒度 RAG→Dify；外部系统集成+自动触发→n8n；快速 bot 部署多通道→Coze；技术透明全控→Flowise。判据：**先答三问再选型；自动化与 AI 应用两类诉求可双平台并行，不互斥**。提升层：工具/工作流。

**2. LLMOps GitOps：prompt 路径即版本号 + commit hash 锚定**（来源：CSDN ByteChat 2026-05-10 实拉）：prompt 版本锚定=每个 prompt 变体存 `prompts/v1.2.0/summarize.yaml`，**路径即版本号**；Router 配置通过 Git commit hash 显式引用 prompt 路径实现不可变锚定；拓扑快照表=Commit Hash｜Router Version｜Weight Ref｜Prompt Ref（sha256:8f9e...）——**可复现发布=router 配置引用 git commit hash 而非"最新版本"**；服务上线周期从 72h 压到 11min 的实战路径。判据：**prompt 与 router 配置全部 git 版本化，router 显式钉 commit hash——"最新"不可作为发布引用**。提升层：工作流/可复用 Skill。

**3. Eval gate 三触发条件 + 程序化 pass/fail**（来源：futureagi 2026-05-20 + 2026-07-08 + truefoundry 2026-08-27 实拉）：三触发=floor（任意路由 per-route mean 低于钉死地板：groundedness<0.85 / answerRefusal<0.90 / citation validity<0.99 合规路由）/ paired CI（候选 vs 前版 per-case delta 的 bootstrap 95% CI 全低于零）/ safety flip（任何安全 rubric 变坏）；**candidate 对 pinned dataset 跑 evaluator，阈值对着 Production 版本——更低则 exit non-zero 构建失败，Production 标签不动**；**质量测量属于 promotion step**——dashboard 事后查只告诉"多少人先看到了回归"。判据：**发布门=floor+paired CI+safety flip 三触发程序化拦截，候选对钉死数据集与现网版本对赌**。提升层：工作流/可复用 Skill。

**4. Agent 四阶段门禁 + AI 特有 soak 时间**（来源：alicelabs 2026-08-03 + futureagi 2026-05-20 + agentpatterns 2026-09-30 实拉）：shadow（复制真实流量到候选、零用户影响、离线评分）→canary（1-5% 真实流量带共享 correlation ID）→percentage（10-50% + A/B eval metrics）→full；**跳过一阶段=ship 一个生产事故**；**AI canary 比经典软件需更长 soak——web service 10 分钟，agent 可能需 2 小时（幻觉与一致性信号慢）**；canary gate 指标=Containment Rate×(1−False Resolution Rate)；**traffic split 在 router 层做，agent 只收一个 policy**；policy 变更同样走 canary（5-10% 流量+自动回滚）。判据：**发布走 shadow→canary→percentage→full 四阶段，AI 任务 soak 按小时计，split 在 router 不在 agent**。提升层：工作流。

**5. HITL 五级自主度 + 可逆性画线**（来源：anhtu.dev 2026-05-25 + perform.digital 2026-06-02 + superkind 2026-04-14 实拉）：L1 Assisted（AI 建议人执行）→L2 Step approval（人批每步）→L3 Supervised（高险暂停）→L4 On-the-loop（边界内跑人可干预）→L5 Autonomous+audit（事后审查）；**画线标准=可逆性**——起草回复/检索记录/分类工单=可逆低风险让 agent 跑；退款/对外发邮件/删数据=不可逆必须人批；**L4 要 earned——先在 L2/L3 攒足够 approvals 与置信才毕业进 policy 内自治**；approval loop=propose（完整草稿+诊断+建议动作+引用证据）→human review→approved 且非过期 sign-off 才执行。判据：**自主度按可逆性定级——不可逆动作必人批，L4 边界内自治是攒出来的不是默认的**。提升层：工作流/可复用 Skill。

**6. 三层成本追踪 + per-agent 归因**（来源：braintrust 2026-06-21 + zylos 2026-06-14 + avghumans 2026-08-03 实拉）：聚合 dashboards 无法定位哪个 prompt/feature/step/model 导致增长；**有效成本追踪=请求级三层=每个 LLM 调用附 token+估算成本 / span 级追踪抓工具调用与检索步 / tag 分组按用户/功能/模型/环境拆**；per-agent 归因=每个部署 agent 有 identity，token 持续按 identity 追踪，成本尖峰能定位责任 agent 并检出模型更新后的行为变化；**cost-anomaly alert=flow 日成本日环比 >50% 报警**；virtual key 五级层级=org/team/user/key/tag 取最低天花板生效。判据：**成本追踪=调用级 token+span 级调用链+tag 级分组三层；每 agent 独立 identity 归因，日环比 >50% 报警**。提升层：工具/工作流。

**7. Context rot 与 dumb zone：退化 onset 是绝对阈值非百分比**（来源：zylos 2026-04-19 + agentpatterns 2026-09-20 + runtype 2026-03-26 实拉）：context rot=窗口溢出前噪声已降质——2025 年 18 个 frontier 模型全随输入增长性能下降；**dumb zone=退化 onset 更接近绝对 token 阈值（32K-100K）而非固定百分比——"50% 窗口内完成"启发式不成立**；RULER 17 模型=声称更大窗口不产生成比例更晚退化；LOCA-bench=Claude 4.5 Opus 96%（8K）→15%（256K），GPT-5.2-Medium 72%→21%；**对策=proactive 压缩（ACON 类）+anchored summarization+selective summarization 按下游需要保（技术决策/干系人/开放问题），target 60-80% utilization（质量 25% 填充已退化）**。判据：**上下文治理按绝对 token 阈值（32K-100K 区）设压缩点，非百分比；目标利用 60-80%**。提升层：工具/工作流。

**8. Golden set 构建：money paths + risk paths**（来源：evalvista 2026-04-06 + Google ADK codelab 2026-04-16 实拉）：golden set 每例=user query+精确 tool call 轨迹+完美最终回答三要素，用来测回归；**从 money paths 开始=驱动结果的 20-50 个任务（预约/工单解决/退款阻止）**；再加 risk paths=合规/安全/敏感主题；回归类别=RAG（引用缺失/错 doc/grounding 差）/policy（不安全内容/PII 处理/拒绝失败）/workflow（多步计划停滞或循环）；eval 数据集 shape=versioned object（query/trajectory/response/reference）。判据：**golden set=钱路径+风险路径 20-50 例起步，每条含 query+轨迹+完美答案，回归按 RAG/policy/workflow 三类分**。提升层：可复用 Skill/工作流。

**9. 生产 harness 占可靠性 98%：校验与权限放 harness 不放 prompt**（来源：mlflow 2026-06-09 实拉）：**harness 代码管可靠性=生产 harness 占 agent 可靠性的 98%——validation 与 permissions 放 harness 不放 prompt**；job-specific 窄工具带类型化 schema 减少静默失败与治理风险（与 r364A「schema 质量最大杠杆」同源互证）；context 25% 填充质量已退化→anchored summarization 目标 60-80% 利用。判据：**可靠性预算=98% 投 harness（校验/权限/重试机制），prompt 只承担行为引导**。提升层：工作流/可复用 Skill。

**10. Observation masking 优于纯 summarization 的主动压缩**（来源：agentnative 2026-07-26 + arXiv 2608.22963 2026-08-25 + arXiv 2605.08580 实拉）：SWE-bench 数据（arXiv 2508.21433）实测=**observation masking 匹配或击败纯 summarization（~52% 成本降 + ~2.6% solve rate 提升；summarization 同成本但轨迹长 15%）**——纯摘要在大上下文最昂贵时刻额外耗一次 LLM 调用且 lossy 不可预测；textual debt=长轨迹自我生成文本主导上下文压制关键证据——pruning 删冗余文本不丢证据；Slipstream=trajectory-grounded compaction validation，context rot 报 14-85% 准确率降。判据：**长轨迹优先掩蔽观察（省 52% 成本还提 solve rate），纯摘要作为兜底不默认**。提升层：工具/工作流。
