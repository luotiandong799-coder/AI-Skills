## 独点（10）

**1. SWE-bench 污染与去污评测：持续挖掘+逐题创建日期追踪**（来源：SWE-rebench + DeepSWE-2607.07946 + nerdleveltech 实拉）：SWE-bench 系任务取自已 merge 公开代码——**问题陈述/gold patch/test diff 都在公开网上、可能已进预训练语料**；直接探测证实：SOTA 模型复现 SWE-bench gold 解**远多于** matched off-benchmark 任务，benchmark 外仓库精度掉；去污方案=**SWE-rebench 持续挖掘新 GitHub 任务并逐题追踪创建日期 vs 模型发布日期（模型训练前可能见过的标污染）**；**DeepSWE=长时程原始任务基准（每日新任务不公开），发现 frontier 差距比公开榜宽：GPT-5.5 70% > GPT-5.4 56% > Claude Opus 4.7 54%**（公开榜 Mythos 77.8% 与 Verified 差距 30 点是"真实编码能力"）。判据：**编码基准必须先问"这题模型训练时见过吗"——污染会系统性高估**。提升层：可复用 Skill。

**2. 评测沙箱=测量有效性：sandbox 决定 benchmark 是否产生有效测量**（来源：Microsoft-sandbox-eval + Claw-Eval-2604.06132 + cursor-reward-hacking 实拉）：沙箱纪律=**定义要测的能力与 agent 可用信息→干净 workspace 只含预期 fixtures→中立 workspace 路径不泄漏评测词→测内部知识时限制外部知识源→文件系统边界→所有工具等价限制→审查 surprising pass 与全轨迹→每发现 route 加回归探针**；Cursor 双隔离=**历史隔离（开始前删 .git 重建单 commit repo，评分时还原）+egress 代理（默认禁网，仅 allow-list 包仓库）**——anti-reward-hacking；Claw-Eval 三阶段（Setup/Execution/Judge）隔离容器，**评分脚本/参考答案运行期不在容器内**（防 eval-aware 适应）。判据：**评测环境防作弊与防污染同等重要——沙箱不干净，数字无意义**。提升层：工具/工作流。

**3. Scaffold effect：harness 选择是隐藏变量，评测必须报全预算**（来源：Scaffold-Effect-2607.22585 + OpenAI-playbook + viblo-harness-engineering 实拉）：同模型+同指令+同沙箱下**三 harness 结果差异显著**——系统提示模板/技能 playbook/任务指令全相同，harness 工程本身是变量；可信第三方评测必须报告：**① budget（turns/tokens/attempts-retries/wall-clock/推理成本/每成功解预期成本）② elicitation 方法（harness 怎么引出结果、测的与声称的关系）③ validity checks（如何查 reward hacking/eval awareness/contamination/refusals/sandbagging 及确认后如何影响计分）**；**harness engineering 成为独立学科**（trace grading/trajectory critics/early stopping）。判据：**报评测结果不报 harness 与预算=不可复现**。提升层：可复用 Skill。

**4. Spec-driven agent 治理：spec 门禁（未批准禁写码）+三档授权（Always/Ask First/Never）**（来源：aiden + specforge + thiagocajadev + env.dev-dark-factory + kanopy 实拉）：spec=书面有界计划（scope/文件/验收标准 checklist/API 契约/约束/排除项）→ agent 对照实施；**spec 是 agent 的 prompt**，hook 级强制：**无批准 spec 任何代码编辑被 block**；三档授权=**Always Do（自主：每次 commit 前跑测试/跟项目 style guide）/Ask First（高影响需审批：改 DB schema/加依赖/改 CI）/Never Do（硬停：永不提交 secrets/API keys）**；**Dark Factory=写 spec→agent 实施→独立 evaluator 跑 holdout 场景≥90% 自动 merge，coding agent 永不看场景源（train/test 严格分离）**——编程 agent 与评审 agent 分离。判据：**spec 把"review 意图"变成可对照物，授权分三档让 agent 自主度可配置**。提升层：工作流。

**5. AI 开发五步工作流+三短循环优先**（来源：developersdigest-workflow + blink-agentic-coding + kanopy 实拉）：**plan→build→review→test→ship**：plan mode 先定方案再写码（catch 架构错在早期）；review 读 diff 专找 agent 制造的新问题（**差命名/缺边界/耦合方向错**）；**第一次 rarely ships——用 review 输出收紧 spec 重跑，三短循环>一次长无监督 session**；vague prompt 产 vague code，**结构化 spec 让代码一次过 review**（feature name/user story/acceptance checklist/files likely touched/API contract/constraints）。判据：**把 spec 当输入质量杠杆——输入质量是 agent 输出质量最大因子**。提升层：工作流。

**6. Terminal agent 架构：dual-agent 规划/执行分离+lazy tool discovery+记忆系统**（来源：OpenDev-2603.05344 + developersdigest-ai-native + 1337skills 实拉）：terminal=AI-native 开发指挥中心（读任意文件/执行命令/改任何部分/子进程，无权限对话框——**操作面最宽**）；OpenDev 复合系统=**workload-specialized 模型路由+双 agent（规划与执行分离）+lazy tool discovery（用到才加载工具）+渐进上下文压缩（旧观察逐步降权）+自动化记忆系统（跨会话积累项目知识）+event-driven system reminders 对抗指令衰减（instruction fade-out）**；gemini CLI DevOps extension 把 Dockerfile/registry/auth/build/push/deploy 收成一句 prompt。判据：**terminal agent 的可靠性来自架构分工与记忆——不是单模型蛮力**。提升层：工具/工作流。

**7. 代码记忆三层+选择性晋升：recurring plans 才升工具**（来源：augmentable-memory + Metis-2606.24151 + MemCoder-2603.13258 + Microsoft-Foundry + Memoria 实拉）：**2026 记忆三层=episodic（会话态）/semantic（长期事实偏好）/procedural（静态指令文件）；上下文窗口是 buffer 不是记忆**；**Metis=文本记忆（facts/pitfalls 指导推理）+代码记忆（recurring plans 晋升 callable tools）——不把一切经验转代码，只晋升反复出现且稳定的计划，摊薄工具构建成本**；MemCoder=从历史 commit 提炼 intent-to-code 映射+验证反馈自修正+**人验证解结晶为长期知识**（SWE-bench Verified SOTA）；Memoria=Git for Memory（Copy-on-Write 可回溯可审计）；Foundry 加 procedural memory+TTL 过期治理。判据：**记忆分文本/代码两层，晋升门槛=模式已反复出现——防过早固化**。提升层：工具/工作流。

**8. 代码评测指标扩展：pass@k 之外加 regression rate/repair@k/成本**（来源：DevBench-2601.11895 + CodeBench-2608.14711 + VeriContest-2605.08553 + NVIDIA-BigCode 实拉）：pass@k=**k 个样本至少一个全过测试的概率**（k=1/5/10；估计式 pass@k=E[1−C(n−c,k)/C(n,k)]）；agentic 代码必须加 **regression_rate（回归测试数/总测试）——修一个 bug 引入回归是 agent 高频失败**；**repair@k=最多 k 轮修复后验证通过**（每轮模型收到 spec/code/failed proof/errors 再出 revised）；SWE-rebench 还报 **cost per problem**（成本轴与质量轴并列）；CodeBench 五指标=Pass Rate/Regression Rate/…。判据：**评测 agent 代码只看 pass@k 会漏掉"修好但弄坏别的"**。提升层：可复用 Skill。

**9. PR 审查 agent：全库上下文索引+风险分级门禁+机械验证三级管线**（来源：Greptile + OpenHands-verification + augmentcode + rework 实拉）：**索引全 repo（文件/函数/依赖图）审查每个 PR——捕捉跨文件 seam bug（agent 改 shared field 不知 12 个服务怎么用）**，每发现 inline 评论带行号与规则+风险分；**风险分级=低风险（docs/tests/config typo）可无人通过，触及 auth/payments/secrets/infra 无论 diff 多干净都门禁人工**；机械验证三级=**pre-commit（秒级 formatter/linter）→CI（tests/SAST/secret scanning/依赖许可证/构建）→merge gate（全量当门槛不是建议）**；OpenHands repo-level verifier=code review agent+QA agent 插件化自动跑，10 场景 checklist skill。判据：**AI 生成的 PR 必须过全库上下文审查+风险分级——diff 级审查不够**。提升层：工具/工作流。

**10. 编码 agent 评测指标轴（harness engineering）**（来源：woliveiras-harness + kunalganglani-harness + agentpatterns-eval-blind-spots 实拉）：五类指标=**Correctness**（hidden/regression/contract/e2e pass rate、defect escape）/ **Navigation**（required-file recall、依赖覆盖、精查文件数、首次命中相关文件耗时、编辑出 impact map）/ **Oracle strength**（mutation score、语义变体拒绝、弱断言假阳性假阴性）/ **Exercise**（diff/branch/failure-path/integration-path 覆盖）/ **Efficiency**（输入输出 token）；**运行时轴=task success rate、median/P95 steps（step budget regression 真实存在）、tool error rate、recovery rate（工具错后恢复吗）、latency P50/P95、cost/task、unsafe action attempts（多数域应为 0）**；eval blind spots 修法=**coverage-delta gates（改过的代码覆盖不变=stale/missing 信号）+termination 与 all-tests-pass 解耦（改显式 per-type 完成检查）**。判据：**评测编码 agent 用指标轴不全科（Correctness+Navigation+Oracle+Exercise+Efficiency+运行时），单看 pass 率是盲区**。提升层：可复用 Skill。
