## 独点（10）

**1. 长上下文基准方法论转向：从单点分数到长度能力曲线**（来源：arxiv 2605.28079《ATLAS》2026-08-27 + crfm.stanford.edu《HELM Long Context》2026-04-20 + datarekha《Long-context vs RAG》2026-04-20 + openai《GPT-5.4》2026-03-05 实拉）：**可靠的长上下文基准要同时回答"模型能做什么"和"能持续做多长"——ATLAS=分层能力分类学（区分基础操作与应用负载，失败可归因）+8K-1M 几何长度网格+曲线积分 AUC 分数（长度感知评分替代单点指标）+ATLAScore 调和平均聚合惩罚不平衡轮廓+端到端不确定性传播；RULER 头条发现=每模型 RULER 分数比同长度单针 NIAH 低 10-25 点（推理比检索难、差距随长度增长）；GPT-5.4 Graphwalks BFS 0K-128K 93.0% vs 256K-1M 21.4%（长度断崖在 1M 级依然普遍）**。提升层：工作流。

**2. 长上下文失败模式三分：分布坍缩/安全税/注意力漂移**（来源：arxiv 2601.02023《Not All Needles Are Found》2026-09-15 + arxiv 2602.22175《DySCO》2026-09-17 + linkresearcher《普林斯顿 DySCO》2026-03-16 + arxiv 2601.07226《NoisyBench》2026-09-16 实拉）：**Distributional Collapse=证据分散在 agent 记忆/长上下文各处时性能系统性下降（非检索失败，是分布问题）；Safety Tax=反幻觉提示成功减少虚构的同时，过度保守拒答抑制了正确且推理密集的响应；注意力漂移=模型"有信息但注意力对不齐"——DySCO 解码期动态放大检索特定注意力头对抗漂移，MRCR/LongBenchV2 128K 相对增益最高 25%（免训练、适度附加计算）；NoisyBench=上下文干扰物下 SOTA 模型性能暴跌最高 80%，错误预测对干扰 token 分配过高注意力**。提升层：模型。

**3. 长上下文 agent 四层压缩级联与按任务类调触发窗口**（来源：zylos《Context Engineering for Long-Running Agents》2026-06-20 + agentpatterns《Context Compression Strategies》2026-09-16 + agentnative《Context Compaction Pattern》2026-07-26 + learn.agentpatterns《Compaction》2026-06-18 + hermes《Context Compression》2026-09-30 + mem0《ContextCompressor》2026-05-14 + loomcycle《Context Compaction》2026-06-12 实拉）：**四层级联各层按压力阈值激活：Layer1 Tool Output 压缩（always-on，>2000 token 截断写盘+文件路径引用+10 行预览，零 LLM 调用）→Layer2 Input Eviction（~85% 水位，写型调用 >500 token 参数落盘后移除，85% 给压缩操作留 headroom）→Fast Pruning（85-90%，剪除超保留窗口的旧工具输出）→Aggressive Masking（90-95%，只留最近输出）；触发窗口按任务类调=推理密集 50-60%（CLAUDE_AUTOCOMPACT_PCT_OVERRIDE）、混合 70-80%、检索密集 95 默认、60-70% 为可辩护默认（从台账数据调，不按轶事）；Hermes 参考参数=threshold 0.50/target_ratio 0.20/protect_last_n 20/+1-iteration 自防抖（防压缩后立即再触发）**。提升层：可复用 Skill。

**4. 上下文是编排资源：四操作编目 + 永不压缩层**（来源：oracle《Four Operations》2026-09-28 + langchain《Context Management for Deep Agents》2026-01-28 + marktechpost《4 Mechanisms》2026-09-12 + arxiv 2609.00749《ContextPipe》2026 + cs224g《More Context Engineering》2026 实拉）：**每个到达模型的 token 由四操作之一支付：load eagerly（常驻）/fetch just-in-time（按需）/compact（压缩）/hand to sub-agent（隔离给子代理）——编排器每一步都在执行这个决策；Deep Agents 纪律=offload >20000 token 工具结果+85% 水位驱逐旧编辑；compaction 必须点名保留内容（session intent+next steps 字段；Claude Code 重读 5 个最近文件）；ContextPipe=每 section 带 token 成本+缓存范围 Global/Session/None（按波动性排序，Global 最稳）+压缩优先级 First/Normal/LastResort/Never——Identity/Constraints 永不压缩**。提升层：工作流。

**5. 长记忆评测的 oracle 分离与"记忆维护是瓶颈"判据**（来源：longmemeval-github + oracle《Agent Memory is a Database Problem》2026-08-10 + arxiv 2606.27472《Supersede》2026-08-31 + arxiv 2606.29914《MemDelta》2026 + arxiv 2606.17328《MemTrace》2026-08-27 + arxiv 2605.12493《LongMemEval-V2》2026 实拉）：**oracle 子集=每问 haystack 只含证据会话，检索不是瓶颈，隔离"能否找到并推理正确记忆"（recall=1.0 时剩余失败不可能是伪装的检索失败）；Supersede=用有界自维护记忆替换完整上下文使知识更新 92%→77%（gpt-5.4，McNemar p<0.005），瓶颈是记忆维护不是理解；MemDelta=受控评估一次只变一个组件（verbatim RAG 匹配全上下文 GPT-4o-mini 但排名跨模型翻转，Gemini 全上下文 +14pp vs Sonnet 反转）；MemTrace=长期记忆失败是"时间性证据使用失败"（旧新提及与无关会话竞争→注意力稀释+弱时间组织）；LME-V2=451 题 5 能力（静态状态回忆/动态状态跟踪/工作流知识/环境坑/前提意识）、500 轨迹 1M+ tokens**。提升层：工作流。

**6. KV 缓存压缩四系 2026：驱逐/合并/频域/结构化**（来源：acm《Token Skipping》2026 + arxiv 2605.09649《Make Each Token Count》2026 + openreview《KVzip》2026 + papernotes《FreqKV》2026-07-14 + structkv + cofldus《ResKV》2026-08-06 + arxiv 2609.35621《Cartridges++》2026-09-28 + papernotes《RetroAttention》2026-07-02 实拉）：**驱逐系（H2O/SnapKV/PyramidKV/TokenSkipping）=丢低重要 token，干净快速但被丢 token 的 softmax 贡献永久消失（TokenSkipping=配额流式 O(1) 每 token 决策+reservoir sampling 自适应百分位；Make Each Token Count=全缓存注意力不是最优、学习未来效用全局保留驱逐）；合并系（ResKV）=把驱逐 token 折入幸存者，信息聚合保留；频域系（FreqKV）=DCT 后只压精度不丢 token（能量集中低频）；结构化系（StructKV）=跨层累积注意力识别全局拓扑重要性（防局部层休眠误丢）；关键权衡=Cartridges++ 压缩 KV 对 on-context 查询更好但原生 KV 保 off-context 能力（启发式变体保留更佳）；RetroAttention=解码加载新 KV 时回溯修正历史查询注意力输出（比 Quest 高 21.9%，扩大有效 KV 暴露）**。提升层：工具。

**7. prompt caching 与上下文编辑的精确控制**（来源：claude《Prompt caching》2026-10-02 + claude《Context editing》2026-09-30 + claude《Preserved thinking》2026-10-02 + anthropic《CLAUDE.md context》2026-04-15 + 01me《Context Engineering from Claude》2026 实拉）：**automatic caching=单 cache_control 顶层字段自动把断点放最后一个可缓存块并随对话前移（多轮最佳）；explicit breakpoints=块级断点把不同波动性内容分缓存（system/背景/工具定义等稳定内容放 prompt 前部收益最大）；context editing=选择性清除精确策展"上下文是有限资源、无关内容退化模型焦点"；clear_thinking_20251015 管理 thinking 块（默认按模型类：保留全部 prior vs 仅最后轮）；thinking 块保留=prompt 缓存保持 vs 清除=在清除点使缓存失效；drop_block 不扣费但会话 token 可能反而增加（模型会重想重建被丢 thinking）；CLAUDE.md 内容寻址=任何改动使缓存失效、下次全价**。提升层：工具。

**8. 动态上下文窗口与按步型差异化上下文形状**（来源：aiexpert《Context Engineering》2026-05-16 + sureprompts《Context Window Management》2026-04-20 + maxim《Selective Context Injection》2026-05-12 + zylos《Context Window Economics》2026-05-27 实拉）：**agent 运行的各步可配置不同上下文形状：决策步小上下文（聚焦即时决策）/综合步大上下文（含多源）/生成步中上下文（风格格式参考）——编排管理"哪段内容进哪步"；动态上下文选择=分析查询判断哪些历史回合仍相关，只注入对应片段（不整段历史）；典型长会话组合=稳定 system prompt 顶部+分层引用材料按优先级+滑动窗口封尾+摘要折叠滑出窗口+截断硬兜底（检索与之配套从窗口外按需拉回）；Zylos Tier 预算=短期窗口 1-3K token、会话摘要 1-3K token、持久记忆无限存储但检索小片段**。提升层：工作流。

**9. ACON 失败驱动压缩与类型化压缩保规则**（来源：arxiv 2510.00615《ACON》2026-08-31 + arxiv 2601.07190《Active Context Compression》2026-09-03 + arxiv 2608.22752《Compaction Cliff》2026-08-24 + pi-context-prune 2026-09-01 实拉）：**ACON=Agent Context Optimization 通过失败驱动自然语言指南优化压缩策略本身+蒸馏成小压缩器——峰值 token 省 26-54%、小模型作长程 agent 能力 +46%（缓解上下文分心）；Active Context Compression/Focus=给 agent 自主记忆管理工具+激进提示，22.7% token 缩减保持相同准确率、平均 6.0 次自主压缩/任务（峰值实例省 57%）；Compaction Cliff/TypeCompact=确定性类型感知三操作：TypeCompact 就地按类型保真重写/TypeDecompose 太大主题分区并跨分区复制安全规则/TypeRetrieve 外部取回时范围内规则先钉住——比最强单次 LLM 压缩器每比率保留 2-4× 更多安全规则**。提升层：工具。

**10. 1M 时代长上下文 vs RAG 转型判据**（来源：aliyun《DeepSeek V4 1M 时代 RAG 还需要吗》2026-04-30 + acm《RAG for Data Management》2026 + datarekha《Long-context vs RAG》2026-04-20 + papernotes《Q-RAG》2026-09-19 + arxiv 2603.08329《SPD-RAG》2026-03-09 + arxiv 2606.15906《MAGE-RAG》2026-06-14 实拉）：**1M 上下文让"整个知识库一次喂给模型"成为可能，RAG 不消亡但转型：从被上下文限制逼出的"检索+拼接"进化为以模型能力为中心的"检索+导航"（成本控制/注意力稀释/幻觉约束三大价值仍成立）；长上下文 RAG 走分层-证据-图路线：SPD-RAG=按文档轴分解子代理（每文档专用代理聚焦检索+token 约束合成层递归 map-reduce）；MAGE-RAG=离线证据图（页节点+元素节点，编码包含/阅读序/版式邻接/章节层级/语义邻居）+在线证据控制器按显式预算迭代激活-打开-搜索-剪枝；Q-RAG=值函数 RL 只微调 embedder（LLM 冻结），10M 上下文多步检索 SOTA（BabiLong/RULER）**。提升层：工作流。
