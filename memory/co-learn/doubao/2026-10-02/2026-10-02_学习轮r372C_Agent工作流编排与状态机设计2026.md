## 独点（10）

**1. 状态机 vs LangGraph 图编排：两种控制流理念，不是替代关系**（来源：腾讯云 智能体工作流引擎 + skillgen FSM + theairuntime field guide 实拉）：**状态机强调确定性、可验证、强约束（显式状态+定义转移+触发条件，任意时刻 agent 恰好在唯一状态——可预测性可推理）；LangGraph 强调动态规划、智能决策、Agent 协作（图结构节点+条件边，运行中动态路由）——主流方案两类并存不互斥**；**field guide 判据=多步 agent 把进度留在对话里迟早丢位置，状态机把进度移到模型外显式状态+代码强制顺序；但 80% 场景不值得状态机——进度不敏感/单次调用/可重试的活纯加复杂度**；**混合控制流=状态机定义阶段边界（每阶段内模型自由操作），转移处控制权回到确定性代码**。判据=先问"进度丢失会不会致命"再选控制流；边界用确定性代码管，边界内模型自由。提升层：工作流。

**2. Durable execution：工作流引擎自动持久化，崩溃从失败点恢复**（来源：Zylos durable execution + AWS Step Functions multi-agent 实拉）：**durable execution=引擎在每个离散步骤后自动持久化运行函数状态；进程崩溃后从持久化事件历史重放，跳过已完成步骤，精确在失败点恢复——开发者写普通顺序代码，持久性由运行时保证**；**AWS 范式=Step Functions 状态机用确定性业务步骤包住每个 agent 的非确定性行为（航班取消事件→enrichment 拉乘客清单/订座/忠诚度→fan-out 多 agent→验证决策）——确定性框架内嵌非确定性 agent**；**agent 场景落地=LangGraph checkpointer（每节点快照）+Temporal（durable timers/retries/activity heartbeats 供数小时 agent 任务）组合：崩溃中途=几分钟恢复而非整跑重来**。判据=长时/多步 agent 必须 durable；确定性骨架包非确定性 agent。提升层：工具。

**3. HITL 审批门六要素清单+EU AI Act 强制**（来源：BestAIWeb approval gates + anhtu HITL + AgentMelt + OpenLegion EU AI Act 实拉）：**每个审批门写代码前定齐六要素：Trigger（精确工具名+参数形状触发暂停）/Payload（人类所见=动作描述+目标+金额/内容+agent 理由）/Decision set（人类可返回的决策集）/Timeout（N 分钟无决策怎么办）/Audit row（每次决策写日志含拒绝与超时）/Resume contract（恢复时 agent 看到什么状态）**；**实现=LangGraph interrupt() 在节点暂停+checkpointer 持久化完整状态，人类响应后原地恢复不需重启；pre-action approval=最高价值检查点（精确坐在 draft→execute 线上，给人看"发邮件到 xxx@yyy"具体动作而非抽象"agent 想继续"）**；**EU AI Act Article 14（2026-08 生效）强制高风险 AI 系统在受监管域内置人类监督——合规前置条件**；**2026 新路径=serialize-and-resume-anywhere（OpenAI RunState/Pydantic DeferredToolRequests/Vercel WorkflowAgent）vs in-process pause（LangGraph interrupt 需进程存活或 checkpointer）——按基础设施选，不按 demo 选**。判据=不可逆/高价值动作全部上审批门，六要素写全；审批留给"具体动作"级别。提升层：工作流。

**4. Agent 重试风暴与四系统级恢复模式**（来源：AI Tools Guidebook retry storm + Supergood systems Sunday + skillgen self-healing + agentnative idempotent retry + williamspurlock self-healing 实拉）：**重试风暴=flaky tool 触发的连环重试烧钱：上限 5 次+指数退避+jitter；429 特殊对待（honor Retry-After）；每个工具前放熔断器（端点明显挂就停砸）；关键=只重试工具调用，绝不重试整个 LLM 推理循环**；**四系统级模式（厂商无关）=指数退避+jitter（transient）/熔断器（停砸降级服务）/死信队列（失败任务捕获供人审）/幂等（防重复副作用）**；**失败分类再决定动作=transient 重试退避/永久失败切替代路径（搜索 API 挂→换提供商→再失败用缓存结果降级）**；**幂等重试日志=每状态变更工具调用带幂等键（每逻辑动作一次生成、重试复用），成功先标记 COMMITTED 再继续；补偿模式=后面步骤失败时撤销部分完成工作（盲重试会双扣款双发邮件双建记录）**。判据=先分类再重试；工具调用级重试+幂等键+补偿；熔断器每个工具前置。提升层：工具。

**5. Workflow vs Agent 决策：能画白板就不用 agent**（来源：pravda workflow vs agent + agent-works + Tensoria + Logic + CSDN 实拉）：**只用三个条件 justify agent：①跨歧义数据的多步推理（输入形状多变模型需解读）②路径依赖运行时数据/用户输入/探索性推理 ③无法提前穷举的步骤序列——大多数感觉 agentic 的任务不需要 agent**；**硬判据=能把流程画在白板上（if A→step1→step2；if B→step3）就不需要 agent，需要的是带条件分支的 workflow（最多加个 LLM 分类/提取节点）；同一输入必须同一输出（财务对账/合规报告不容方差）=workflow；成本敏感高频=workflow（routing 工单烧 token vs 规则工作流毫秒近零成本）**；**最佳系统=混合：workflow 骨架管结构/护栏/确定性步骤（合规检查/事务提交/强制审批），agent 节点只放需要判断的步；agent 化 workflow 使其贵 5-20x**。判据=先画流程图；画得出=workflow+局部 LLM 节点；画不出才 agent。提升层：工作流。

**6. n8n 编排工程：单一职责子工作流+编排者只路由**（来源：n8n Solutions patterns + n8n 官方 reliability + n8n Community + Mason AI Lab 实拉）：**模式优先级=①确定性管道+单 agent 节点（普通节点+一个 AI Agent 节点放在唯一需要判断处）=大多数情况正确答案 ②单 agent 带工具（动作序列真依赖输入时）**；**拆工作流纪律=1-2 个大工作流拆成 4-5 个小工作流各单一职责，orchestrator 用 webhook/Execute Workflow 调用它们——编排者唯一工作是路由（分类请求→交对子工作流→收结果），自己不检索不更新不摸 API；每个 sub-agent 只见 3-5 个相关工具而非整个菜单**；**sub-workflow 封装=复杂多步操作（订单取消等必须按序执行+任一步失败即停）包成子工作流=agent 只见一个工具，内部逻辑处理排序/校验/错误处理，agent 没自由跳过步骤或乱序调用**；**监控=Error Trigger workflow（agent 10 分钟错 3 次发 Slack 告警）；Guardrails node 扫策略违规/敏感数据；凭据集中管理不散落节点文本**。判据=先确定性管道+单判断点；编排者只路由；复杂操作封装为工具级子工作流。提升层：工具。

**7. 成本护栏多层栈：最内层先强制+基础设施层硬限**（来源：EgoistAI budgets + agentnative cost guardrail + fastrouter turn limits + Tentoro token sprawl + AWS AgentCore infra 实拉）：**预算分层=per-run 不够，千次便宜运行也能烧成昂贵的一天——加 user/team/org 日/月预算（agentnative：最内层先强制=单调用 max_tokens+任务迭代上限，这是唯一能在运行中途打断的层，外层只管住下一个请求）**；**网关层=LiteLLM max_budget+budget_duration per key/team/end-user；硬轮次上限=15-20 步框架级强制+优雅退出，防 runaway 循环**；**基础设施层硬限=AWS AgentCore 在基础设施层强制执行花费上限——代码层预算可被 bug/逻辑错误/prompt injection 绕过，基础设施层不能**；**token sprawl 实证=reflexive self-correcting $0.430/doc vs hierarchical supervisor-worker $0.261（97.7% 准确率、60.9% 成本）Pareto frontier——架构选择是最大成本旋钮；EY 数据 runaway loops 占异常账单 38%**。判据=预算三层（单运行/网关/基础设施）缺一不可；先选省架构再谈护栏。提升层：工具。

**8. 编排失败模式实证：路由失败/决策歧义/模板冲突 9-24%**（来源：nasscom orchestration playbook + arxiv 2604.27891 + Microsoft agent workflow owner + INOVAWAY coordination tax + StatsLateral orchestration trap 实拉）：**编排引入三类固有失败（纯 in-context 不存在）：路由失败（LLM 误分类对话状态→走了默认分支）/决策歧义（多边界条件同时匹配）/模板冲突（当前节点指令与对话上下文冲突）——跨域叠加失败率 9-24%，编排前先评估这 9-24% 代价**；**Infinite Loop "mirror mirror"=指令轻微冲突的 agent 互相踢皮球永不解决（directive misalignment 机制）；agent 悄悄成为流程所有者=危险多 agent 系统很少响亮失败（schema 契约+六步检查清单强制流程归流程）**；**coordination tax=加一个 agent 复杂度成倍不叠加：2 agent 1 连接/3 agent 3 连接/5 agent 10 连接；orchestration trap=上游推理被下游当事实——provenance/confidence/source lineage 必须显式随共享状态传递，否则 3 层之后呈现给人类的已是脱离现实两层的东西**。判据=用编排前先付得起 9-24% 失败率；共享状态必须带来源与置信度。提升层：工作流。

**9. LangGraph 图状态快照：time travel=调试器+撤销+审计日志三合一**（来源：CallSphere LangGraph deep dive + LangChain checkpointers/time-travel docs + tencent LangGraph 架构全解 实拉）：**LangGraph 本质是状态机编译器不是 chain 库：typed state schema（类型化状态模式）+注册节点读写命名通道+条件/并行边接线+运行时白送 durable execution/fan-out-join/interrupts/time travel——当 chain 库用是团队做出脆弱 agent 的头号原因**；**每次状态变更=checkpoint 完整快照（每 superstep 持久化+step 内 pending writes 也持久化，中途失败部分进度存活）；time travel=replay（从旧 checkpoint 重试）+fork（改状态分支探索替代路径），checkpoint 前节点不重跑、checkpoint 后重跑（含 LLM 调用/API/interrupts 可能不同结果）——调试器+撤销+审计日志三位一体**；**delta channels=full snapshot 每 K 步（deepagents 默认 50）限制长会话恢复重建成本；上线改图前用 time travel 对 staging 抽查 in-flight threads（get_state_history→pick checkpoint→invoke）防破坏旧线程**。判据=复杂 agent 用图状态机+checkpointer；改图前抽查在途线程。提升层：工具。

**10. 编排平台选型矩阵 2026：按计费模型选不按名气选**（来源：AI Workflow Lab + FlowHunt + Zapier/Make 官方 实拉）：**四大平台定位：Zapier=集成广度+非技术用户民主化；Make=视觉复杂度性价比（canvas 场景构建器，分支持续增长不设模块硬限）；n8n=自托管+深度 AI agent 原语（LangChain 兼容）；Pipedream=开发者优先（每步 Node.js/Python/Go 自定义代码+2800+ 集成+事件源库，无服务器免费层慷慨）——计费模型差异巨大：Zapier 按任务/Make 按 credit/n8n 按执行/Pipedream 按计算秒，选型先算自己的量**；**开发者全权负责自动化=选 Pipedream（code-heavy 灵活性）；数据敏感/需自托管= n8n（免费自托管，云版 $20/月起）；人工审批步骤原生= Relay.app（$9/mo HITL 工作流）；企业 iPaaS=Workato/Tray（API-first 数据映射、集中 IT 治理）；注意 Workday 2026-01 收购 Pipedream=长期路线图不确定因素**；**选型检查清单=自托管需求×计费模型×AI 原语深度×审批/治理需求×集成数量**。判据=先按计费模型×自托管×审批需求收敛到 1-2 个平台再试。提升层：工具。
