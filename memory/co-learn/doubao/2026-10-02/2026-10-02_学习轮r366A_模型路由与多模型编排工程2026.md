## 独点（10）

**1. Cascade 成本模型：升级率盈亏平衡点 r*=1−c_cheap/c_big**（来源：vibeengines-handbook + agentnative-cascade + FrugalGPT-TMLR 实拉）：cascade 每请求都付 c_cheap（无论是否升级），**盈亏平衡升级率 r*=1−c_cheap/c_big——升级率低于 r* 才划算**；**初始阈值从价格阶梯推而非直觉**（$1.20→$25 是 ~20x，一次升级只有当预期质量提升值 20x token 才做）；FrugalGPT 最多省 98% 推理成本且匹配/超越 GPT-4 单模型精度，同成本还能提 4% 精度——因为找到"便宜模型对但旗舰错"的查询并定向它们。判据：**cascade 值不值由升级率与价格比共同决定，先算 r* 再设阈值**。提升层：工具/工作流。

**2. 路由分类器四层混合：rule→embedding→LLM classifier，实现为 cascade 而非单分类器**（来源：alivedise-BEE-30037 + genai4a11 + dev.to-routing-guide 实拉）：rule filters 先处理最高置信已知 case（关键词/用户层级/显式 flag，近零成本）→ embedding similarity router 处理大部分流量（毫秒级）→ **LLM classifier 只处理 embedding 层无法解析的真歧义**；**必须实现为 cascade——便宜的 classifier 先上，只有它无法置信解决才升级到贵的**；router 类型延迟×精度表：rule ~0ms/低、embedding classifier 5-20ms/中、small LLM judge 50-200ms/高、RouteLLM（trained）10-50ms/高。判据：**路由本身也要按 cascade 原则省钱——决策层成本分层，不是一层全做**。提升层：工具/工作流。

**3. 多维能力路由：多头需求预测+选最便宜够用模型**（来源：arXiv 2605.17106 HyDRA + arXiv 2605.07112 Switchcraft 实拉）：HyDRA=轻量 ModernBERT 编码器 **K=4 独立 sigmoid 头预测每查询多维能力需求**（reasoning/code generation/debugging/tool use），**配置驱动 shortfall matching 选满足需求的最便宜模型——模型目录变更零重训**（SWE-Bench 质量保 0.3 内）；Switchcraft=先预测"正确模型集合"再**选最低 profile 成本者**（实际 input/output token 计费×单价，天然捕获 chattiness）。判据：**路由不按单标签分难度，按能力向量匹配+成本最小化**。提升层：工具/工作流。

**4. Session affinity 与 sticky-context 升级策略**（来源：NVIDIA-NeMo-Switchyard + agentnative-cascade + pi-model-router 实拉）：LLM classifier 路由后**保持会话亲和——后续轮次不重复重分类未实质变化的工作**；升级时**sticky-context 策略：定义哪些会话状态随升级携带**——重发完整 agent 上下文到 frontier 是升级成本隐藏处；pi-model-router 细节=**模型换掉后 re-assert router model**、context 太满升档找大窗口模型、模型失败按序 fallback 再 surface error。判据：**每轮重分类=浪费；升级成本藏在"重发多少上下文"里，先定携带策略**。提升层：工作流。

**5. 路由三模式+成本-质量拨盘（Balanced/Cost/Quality+alpha）**（来源：Azure-Foundry-model-router + RouteLLM-alpha + truefoundry 实拉）：三模式=**Balanced（质量成本最优，默认）/Cost（激进便宜，复杂 prompt 接受略降）/Quality（永远最高质量模型）**；RouteLLM 单一可调 alpha 阈值=成本-质量拨盘——**调高更多流量走便宜，调低更多上旗舰；成本控制变成团队拥有的拨盘而非 prompt 属性**；tier floor/ceiling=router 只降级不升级（user 指定 ceiling 为上限），quality mode 加 confidence gate（分类器置信 <0.65 拒绝降级）。判据：**路由策略先选模式，再调单一拨盘——成本取舍是配置不是代码**。提升层：工具/工作流。

**6. Per-step 路由策略评测：rubric 每步+质量带+误路由代价**（来源：futureagi-routing-policies-2026 + agentpatternscatalog-complexity-routing 实拉）：**换模型的路由策略必须证明该步质量停在预先承诺带内**（"Haiku 允许 formatter 当 rubric 分在 0.03 内"）；**rubric 按 step 不按 trajectory**（planner/tool-caller/formatter/responder 各自一档）；监控指标=分类器 held-out 精度按难度桶（尤其 hard tail recall）/各 tier 流量占比（揭示路由假设与现实漂移）/predicted-hard 与 predicted-easy 车道质量差（误路由代价）/分类器每请求延迟成本。判据：**路由正确性按步骤测量——换便宜的步与换贵的步用不同质量带**。提升层：工作流/可复用 Skill。

**7. Shadow 流量+canary 评估路由（shadow ≠ canary）+质量路由**（来源：futureagi-shadow-canary-2026 + ai-tldr-model-upgrade + respan-quality-routing 实拉）：**shadow=镜像路由无用户影响，canary=百分比路由可回滚**；**质量路由=用生产流量得分选模型**（LLM-judge/rule/human/online evals 跑 live traces），能回答"上个月换便宜模型质量是否真的守住"而非"uptime 是否守住"——**需要 router 下挂 eval 层、分数与同一 request ID 绑定**；model upgrade 指标表=format compliance（parse 错误率）/tool use accuracy/latency（p95 SLA）/cost per request/error rate。判据：**路由变更按模型升级对待：影子+canary+五类指标回归**。提升层：工作流/可复用 Skill。

**8. 路由漂移检测：CUSUM+escalation rate+silent cache decay**（来源：ctiber-QoS-CUSUM + generalcompute-cascade + futureagi-agent-command-center + collabnix 实拉）：**供应商静默未文档更新（量化/alignment shift）→ 临时漂移，API 是黑箱**；CUSUM 检测质量分数分布位移（SLA 约束路由、ε-greedy re-admission）；**escalation rate 随时间漂移——上季 70% 节省这季可能 40%，升高则评分函数需重训或小模型微调新查询类型**；**silent cache hit-rate decay**：similarity 0.92 设好 hit 30%、六周后 12%（prompt 模式漂移），按 prompt template/team/date 切片；三 ratio=cache hit rate 升/旗舰调用占比降/**tokens per completed task（唯一抓 agent 循环二次方爆炸的指标，cost per request 会掩盖）**。判据：**路由与缓存都要漂移监控——静默退化比故障更贵**。提升层：工具/工作流。

**9. Cascade 评分函数设计：precision>recall+SLM defer 替代 router**（来源：FrugalGPT + jatinbansal + generalcompute + UCCI-2605.18796 + cascade-router + distil-defer 实拉）：评分函数=小 judge 模型/模型自身 log-probs/验证器跑 schema/正则结构化检查；**judge 拒绝 30% 好答案=白花钱升级——precision 比 recall 重要**；UCCI=token-level margin 不确定度→isotonic regression 映射 per-query 错误概率+成本约束选升级阈值；Cascade=子 5ms 复杂度分类器乐观分发+运行时 schema 验证器；**更省的路：训练 SLM 知道何时 defer（发出 defer_to_larger_model tool call，orchestrator 尊重它）——无独立分类器/无阈值调参**。判据：**评分函数先测 precision；能用模型内建 defer 就别建外部 router**。提升层：工具/工作流。

**10. Agent 场景路由退化：单轮 router 误路由多步轨迹+按角色分模型**（来源：arXiv 2609.22951 AgentRouter + dev.to-tiered-routing + gsd-build-model-profiles + Avriz-bandit 实拉）：RouteLLM 在 agent 场景成本削减仅 31.4%（**单轮偏好 router 误路由复杂度依赖累积轨迹上下文的步骤**）；FrugalGPT 44.1%（顺序探测 48ms 开销）；DAAO 36.2% 但质量最高 98.1%；AgentRouter 专攻多步 agentic workflow；**按角色分配模型 profile**（Opus 规划/调试、Sonnet 执行、Haiku 映射/审计——角色优先级决定模型档）；Avriz shadow-first bandit=从已有 metering 行组装奖励（success +1.0/−cost 加权），**不收集新 telemetry，600 秒 turn 窗口归属决策**。判据：**agent 场景路由必须考虑轨迹上下文——单轮训练的 router 直接照搬会误路由**。提升层：工作流。
