## 独点（10）

**1. LLM-as-judge 校准回路：kappa 门槛+reference-guided grading**（来源：FutureAGI llm-as-a-judge + kraghavan field guide + DeepEval 实拉）：**部署 judge 前先校准：抽 100-300 条生产 trace（覆盖用例形态）→ 2-3 人工标注者用同一条 judge 将用的 rubric 打分 → 算 Cohen's kappa（2 人）/Krippendorff's alpha（3+）→ judge 跑同一批 → kappa<0.7 必须重写 rubric（锚点更具体/加例子/缩窄分数标尺），kappa≥0.7 才可信**；**reference-guided grading=让 judge 先自己解一遍题再按自己答案评分（MT-Bench 数学评分失败率 ~70%→~15%，是 judge 领域最大的单个数字改善）；position-swap/order randomization=双向比较只信一致裁决（MT-Bench 与 Vertex AutoSxS 标配）**；**rubric 四性质=命名标准分解（faithfulness/relevance/completeness/conciseness 分开打分，不坍缩成单一好感分）+每个分数档位可操作性定义（不写"5=优秀"写"5=答案满足…"）+正交+完整；一次 judge 调用只评一个标准，多标准同评掉性能**。判据=judge 上线前 kappa 门+评分先解题，rubric 按标准分解。提升层：工作流。

**2. Judge 可靠性审计四要素+family bias 实证**（来源：arxiv 2607.08535 judge audit + CSDN 生产级评估体系 实拉）：**judge 分数只有同时报告四要素才可解释：评的 slice（哪批）/扰动敏感性（简单扰动下 judge 偏多少）/重复判断相关性（correlated repeated judgments）/协议级决策可审计性——缺任一要素不接受为可靠结果**；**实证踩坑：团队用 GPT-4 当 groundedness judge 评自家 GPT-4 生产输出，三个月 dashboard 全绿，专家人工评 50 条 Cohen's kappa 仅 0.31——family bias 系统性高估自家模型、length-confidence bias 低估流畅幻觉**；**独立 judge=选与被评模型不同家族的模型，防 self-preference**。判据=judge 换模型/换批次必须重审计四要素，同家族 judge 结果打折看。提升层：模型。

**3. 双层评估：工具轨迹（确定性）+回复质量（judge），缺一不可**（来源：Google ADK evaluations + Microsoft Foundry agent evaluators + agentnative step vs outcome 实拉）：**轨迹层=agent 是否调了正确的工具/正确的参数（确定性 exact-match）；回复层=最终答案是否相关/有用/grounded（LLM judge）——rubric 单独可能放过"读起来好但幻觉"的答案，轨迹单独看不出用户是否得到有用回复，两轨都要**；**Foundry 组件评估器=Intent Resolution(1-5 默认过 3)/Task Adherence(0/1 默认 1)/Groundedness(1-5 默认 3)/Task Completion(0/1 默认 1)；step-level vs outcome-level=step-level 告诉你"第 7 步用 customer name 而非 ID 调 search_orders"（ToolCorrectness/ArgumentCorrectness 分解），outcome-only 在 40 步运行红标时不知道修哪步（最差调试回路）；Phoenix OTel 原生轨迹评分附 span=回归二分定位到具体工具调用**。判据=评测套件必须同时含确定性轨迹断言+judge 回复评分。提升层：工具。

**4. EDD 评估驱动开发：先写 eval 再建，回归防退化**（来源：XYZBytes eval-driven + Red Hat EDD + loomstack TDD-EDD 对比 + HKU LangSmith deep agents 实拉）：**EDD=写系统前先定义正确行为（Anthropic 做法：先用 eval 定义能力，迭代到 agent 通过）——TDD 在概率系统下的形态：确定性二进制→阈值语义评分、exact match→semantic/rubric**；**output-only evals 说谎：只评最终输出的 agent 比全轨迹评估多过 20-40% 测试用例——掩盖生产中最要命的失败**；**能力 eval 问"agent 能做好什么"（瞄准当前挣扎任务，低通过率起步往上爬）vs 回归 eval 问"还保留旧能力吗"（接近 100% 通过率，下滑=坏了）；agent 成熟后高通过率能力 eval 可毕业进回归套件**；**失败分类法 failure taxonomy 精准定位问题；修完对已知好/坏对话各跑一遍验证修复**。判据=新能力先写 eval 再迭代；回归套件同批固定用例跑多版本横向对比。提升层：工作流。

**5. Golden dataset 工程：冻结版本化+生产失败采样+坏集信号**（来源：alpeshnakrani golden eval set + FutureAGI golden + Langfuse + freeCodeCamp eval platform 实拉）：**golden set=冻结的版本化真实生产流量样本+专家标注参考答案；按 intent 分层并对抗性尾部过加权——测"什么会坏"不测"容易的路"；大多数功能 200-400 条够用**；**成长路线：seed 周 100-300 行（需求/拒答/已知边界，逐行打 cohort 标签=发布门最低线）→ 2-8 周从生产失败采样（eval_score<threshold 或 user_feedback=negative 的 trace 转测试用例）→ 定期刷新不逐条长**；**版本化=golden-v4-2026-06 新命名不覆盖，pin prompt-template hash+embedder 版本+retrieval-corpus snapshot 进 dataset metadata，旧版本保持活**；**坏集信号=每个 frontier 模型都 95%+（饱和，区分不了模型）/80% 用例单 intent（头部赢掩盖尾部失败）——稳定指标在坏集上是最糟情况=自信的错误**。判据=golden set 冻结+版本化+对抗尾加权，指标饱和即换集。提升层：工作流。

**6. 合成 eval 数据：生成 10x 留 10%+四重过滤**（来源：FutureAGI synthetic data definitive guide + arxiv StateGen + Apple environment-free 实拉）：**三种生成模式组合：persona-prompted（措辞与意图变体）+taxonomy-stratified（覆盖关键格子）+evolution（deepen/broaden/obscure/adversarial 制造生产流量不会自然出现的多跳与对抗尾）**；**一个过滤器干重活：embedding dedupe+cross-family LLM judge+mode-collapse 检测（pairwise cosine distance/entropy/HDBSCAN 簇数）+5% 人工抽查——生成 10 倍只留过筛的 10%**；**StateGen 架构=四角色循环（persona 用户模拟/被测 agent/state-grounded 工具模拟/多轴 judge）+权威 state manager 维护结构化世界状态跨轮——backend-is-truth 不变量从构造上消除工具调用幻觉（工具模拟响应永远与权威状态一致）**；**Apple environment-free=仅凭 API 规格让 LLM 当 on-the-fly digital world model 生成有状态环境轨迹（teacher agent 迭代解题+LLM 模拟器生成连贯 API 响应）**。判据=合成数据按"生成+过滤"两级流水线，模式坍缩检测必配。提升层：工具。

**7. 生产持续评估：渐进阈值+agent 无代码也会漂移**（来源：gettiaconsulting eval production + FutureAGI drift 5 + Microsoft regression agent drift 实拉）：**评分对比部署基线，渐进告警：两次连续运行全局分差<2%=正常噪声；2-5% 持续 24-48h=调查；>5%=优先告警+人工评审降级样本**；**drift 五来源=model update/tool change/RAG corpus 更新/system prompt 编辑/用户分布漂移（上线 6 个月后真实用户用俚语、多语切换、长 prompt、截图、跟进链——手写或上线月流量采样的 eval set 没有）**；**与传统软件不同 agent 无代码变更也漂移：模型部署/上下文窗口调整/训练数据渐变静默降质——回归测试在 CI/CD 质量门比对每个新版本 vs gold baseline**；**comparative drift detection=异常率/输出长度分布/工具调用模式对比参照基线，任一 20% 跳变=深查信号；生产失败转未来测试用例=生产反馈回路**。判据=生产监控按基线+渐进阈值，五类漂移源全监控。提升层：工作流。

**8. 轨迹过程级评估：AgentLens 幸运过关 PTA+工具选择精度**（来源：arxiv AgentLens lucky pass + FutureAGI TSA + TruLens 实拉）：**lucky pass problem=SWE-agent 凭运气过关（正确最终结果但过程混乱）——AgentLens 把同一任务多个通过解合并成 PTA 前缀树参考空间，过程级评估暴露"运气过关"，1,815 条轨迹+47 任务级 PTA 参考发布**；**Tool-Selection Accuracy 三信号加权=40% 必需工具覆盖（used_required/required）+30% 有效性（调用 available_tools 之外扣分）+30% 单次 ToolCall 成功率**；**TruLens 每步评分附解释=低分直接指向错哪（"search_policies 用了含订单号的原文，返回退货政策而非审批；get_order 该调没调"）**。判据=轨迹评估合并多通过解建正确行为空间，逐 span 评分定位。提升层：工具。

**9. 专家人回环校准：先校准再标注+regime stabilizer 陷阱**（来源：Galileo expert-in-the-loop + HEAL CHI regime stabilizer + INSTA JUDGE + Stack Overflow tier 实拉）：**多名 SME 先校准到共享标准（inter-annotator 高到可当 ground truth）再标注——不校准收集的是观点，校准后是发布流程可信的测量仪器；把专家推理转化为无需持续人工的 eval 逻辑**；**隐藏失败模式=human-as-regime-stabilizer：人类评估者的上下文框架与交互模式可诱导独立 LLM agent 语义收敛（实证 17 个场景收敛>95%）——高表观一致掩盖归因不稳定、破坏独立性假设**；**INSTA JUDGE=用自动 prompt 优化（APO+distribution-preserving few-shot sampling DPFS）对齐 judge 偏见与人类；成本分层=置信度校准（temperature scaling/isotonic）后 Tier1 自动处理 85% 流量、Tier2 异步专家审——路由决定"信 LLM 判断还是升级人类"**。判据=人类回环先校准，警惕表面一致性陷阱，按置信度分层升级。提升层：模型。

**10. 评估框架矩阵 2026：按轨迹/CI/观测选型**（来源：FutureAGI frameworks 2026 + MLflow top5 + agentura + AWS strands evals 实拉）：**选型判据：LangSmith=原生轨迹语义（LangChain/LangGraph 栈）；Future AGI=trajectory-first 评分+span evals+模拟+网关护栏 Apache2.0 混合运行时；Braintrust=买 UI 与 hosted experiment；DeepEval=pytest 风格 CI 记录+最大开源指标库（G-Eval/DAG/QAG 三技术）；Phoenix=OpenTelemetry-first 轨迹在开源栈；MLflow=最广指标覆盖+rule-based/LLM judge 双支持+人类 reviewer 标注反哺自动 judge；Ragas=RAG 聚焦**；**PR 级回归=Agentura 像 pytest for AI agents，每个 PR 测 accuracy/safety/cost/guardrails 防合并前回归；AWS Strands Evals=10 个内置评估器+自然语言 rubric 定义自定义标准+任务函数连接 agent 输出**。判据=按"轨迹语义/CI 集成/观测追踪/人类反哺"四需求选框架，不追全家桶。提升层：工具。
