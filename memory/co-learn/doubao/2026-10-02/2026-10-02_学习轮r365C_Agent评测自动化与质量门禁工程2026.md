## 独点（10）

**1. 离线 trace 评测：评估已存轨迹不重放请求、跨框架 OTel 解耦**（来源：agentevals-cli 2026-09-28 + Azure Foundry cloud-eval + AWS Bedrock AgentCore + arXiv 2608.07346 实拉）：**评估存储的 OTel 轨迹文件完全离线（agentevals run 不需服务器）**，不重放原始请求/不需 live agent；**只要 telemetry 走 OpenTelemetry，评估服务可评分任何 SDK 底下的 agent（Bedrock AgentCore 跨框架解耦）**；Lifecycle-Aligned Evaluation=每个 metric 注册在特定执行阶段+细粒度评估维度；BTS-AgentBench=只读遥测日志→可执行多轮任务基准（归一化 tool store+静态任务编译）。判据：**评测与执行解耦——trace 落盘即被测对象，框架无关**。提升层：工具/工作流。

**2. Eval 按 cadence 分层：PR 快速门+main 夜间全量+成本信号**（来源：menuagentic field-guide + futureagi 五层 + ai-tldr + genai4a11 实拉）：tiered 存活纪律=**cheap code-graders（~ms）跑 pre-commit hooks / LLM judges（~s）跑 preview deploys / judge calibration 月度跑 versioned human gold set**；五层=deterministic（每 commit，零成本）/regression eval（golden set，每个 PR sharded，cents）/integration（tool calls/retrieval/multi-turn，nightly）/red-team（adversarial，pre-canary nightly）/canary（1-5% 真实流量，每 release）；**PR 跑小快样本 pre-merge 分钟级阻塞，full dataset 昂贵 judge 夜间跑 main、可一小时、alert 不 block 人**；标准 gate=functionality 99%+/regression 95%+/safety 99.5%+。判据：**按 cost×latency 分 cadence——门禁要快，全量要省，人只在夜间被 alert**。提升层：工作流/可复用 Skill。

**3. 相对基线门禁：对比 last known-good 而非绝对阈值**（来源：qaskills 2026-07-07 + dailyaiworld 2026-09-16 + multigrid + futureagi + EvalGate 实拉）：绝对阈值 0.80 固定地板**会保持绿色但强系统静默退化向它**；**基线比较=候选统计上显著差于生产才失败**；正确问题=非劣效检验（能不能排除新系统比基线差超 δ），门禁设在配对差置信区间下界；**30-example 的 95% CI 约 ±0.07**——小样本固定阈值必误判；EvalGate=paired bootstrap significance on per-case deltas+PASS/BLOCK/INCONCLUSIVE 三态（无法判定升级层级）；per-evaluator delta 阈值（Groundedness 掉 ≤2 点；safety-critical cohort TaskCompletion 一掉即 fail）+风险表分级（gold/irrevocable→human read；core logic→judge+delta；long tail→watchbar）。判据：**门禁的断言单元是"相对基线的显著差"，不是"高于一根刻死的线"**。提升层：工具/工作流。

**4. Tool-call 四步契约独立评分 + no-call slice**（来源：futureagi 2026-05-20 + qveris + callsphere + NVIDIA 实拉）：四步=**决定调不调/选哪个工具/构造参数/整合结果**，分步独立打分；**no-call slice（10-15% 该安静的样本）测 irrelevance precision/recall——会调工具不是本事，该不调时不调才是**；工具选择=function_name_match+F1 per tool；参数=schema valid+语义 grounded；callsphere 标签三元组=expected_tool+expected_args+rationale；qveris 四 gate=relevance/contract/operating quality/execution semantics（**过一个 gate 不保证下一个自动过**）。判据：**工具评测按调用生命周期逐层分解，沉默正确性与调用正确性同等计分**。提升层：工具/工作流。

**5. 评测随机性量化：pass@1 波动 2.2-6.0pp、temp=0 仍有方差**（来源：arXiv 2602.07150 + arXiv 2410.03492 + arXiv 2502.08943 + ICLR 2026 实拉）：6 万轨迹/25.58B token/1.88M tool calls 系统性分析——**单次 pass@1 估计随运行变化 2.2-6.0 百分点，即使 temperature 0 标准差超 1.5pp**；重复 1-30 次影响均值+预测区间；层次统计模型用多 generation 降方差；**报告 μ/σ/Δ 而非单分数**；mlflow 四类 metric=outcome（process-blind）/process（trajectory 级）/reliability（worst-of-n、variance across seeds）/**cost（tokens/task、wall time、dollar）**。判据：**agentic eval 必须有 error bars——单次分数之间的差可能小于同一模型自身的运行差**。提升层：工具/工作流。

**6. Judge 校准纪律：月度 kappa<0.6 告警+版本钉死**（来源：menuagentic + grepture + futureagi 2026-08-27 + scorable + galileo + dailyaiworld 实拉）：gold set=200-500 human-labeled traces per rubric；**每月 judge vs human kappa（Cohen's kappa/Krippendorff alpha），<0.6 告警**；prompt-template hash+embedder 版本+检索语料快照**钉进 dataset metadata（golden-v4-2026-06 命名版本，不覆盖写）**；**换 judge 模型/judge prompt/rubric 即校准失效，每次变更重校准**（季度至少、新 rubric 月度、dailyaiworld 两周）；gold set 增量旋转=每月加生产 trace 样本+轮出等量最旧样本（**不轮转会拿旧分布评分；整换失去连续性**）。判据：**judge 校准是可维护的数字（kappa），不是一次性的信任**。提升层：工作流/可复用 Skill。

**7. Trace-to-Dataset 闭环：生产失败→回归库**（来源：dailyaiworld 2026-08-07 + callsphere 2026-05-05 + codeables + langchain-forum + azure agentops + diego-rodriguez 实拉）：五步=find trace/reproduce from trace/promote to regression dataset/fix+re-evaluate/ship behind gate；**生产不是终点，生产教下一版评测集**——失败 trace→回归 case、安全事件→red-team scenario、延迟成本→release criterion；**5-10 个同类失败 trace 就建一个命名数据集**（rag-citation-failures-march-2026），每行=原输入+坏输出+期望输出；**每周把代表失败 promote 进 golden dataset——CI 管 merge，tracing 看 gate 漏了什么**。判据：**评测集从生产失败生长，不只从合成生成**。提升层：工作流。

**8. Golden set 治理：三层隔离+200 起步分层**（来源：egoistai 2026-08-19 + koji + rockb + divinci + businesstechnavigator + agentropic 实拉）：三层=**dev（工程师可见，快迭代）/release-gate（eval service，回归决策，定期更换）/sealed audit（少数托管人，独立能力估计）**；**可见集两季度内变训练目标而非测试**；分层比例=routine 50%/edge 30%/safety 20%（或 happy 60/edge 20/adversarial 20）；**200 分层案例胜过 5000 不分层**（五片 200 起，postmortem 逐 case 扩 replay bucket）；必须记录 tool-call ground truth 供确定性回归；agentropic 三集=regression set（从 incident 生长，near-100% pass，hard block）/adversarial red-team（NIST 对齐 guardrail）/fictional；**测量 label agreement——未测的集错误率未知**。判据：**golden set 是版本化资产：分层+隔离+旋转，不让可见集被训练污染**。提升层：工作流/可复用 Skill。

**9. 成本当评测轴+发布标准：四轴评分**（来源：NVIDIA 2026-09-21 + mlflow + futureagi 实拉）：NVIDIA 四轴=**task success rate（release gate）/tool call accuracy（per-step）/trajectory quality/cost（tokens per task、wall time、dollar）**；**延迟/成本问题变 release criterion（Azure AgentOps）**；llmci 内置 latency 指标；**judge 成本超生产 5% 调采样率**。判据：**agent 发布不只是"成功率高不高"，还有"值不值"——成本与成功率同轴评分**。提升层：工具/工作流。

**10. 确定性优先评分栈：deterministic gate 先行，LLM judge 只在语义层**（来源：stochasticsandbox 2026-05-12 + assevra 2026-09-06 + futureagi 四层栈实拉）：deterministic evals 不调 LLM（json validity/结构属性）**每 commit 跑，fast cheap**；assevra 阈值表=task-completion ≥0.90/tool-call validation ≥0.95/action correctness ≥0.95/**prompt injection 1.00（全 deterministic）**；四层栈每层=deterministic rubric + LLM-judge rubric 双轨（**确定性管结构可断言部分，judge 管语义不可断言部分**）；**评测金字塔底=确定性，LLM judge 是顶层的少数**。判据：**能用确定性断言的绝不上 LLM judge——judge 只补语义覆盖，成本与噪声都因此压低**。提升层：工具/工作流。
