## 独点（10）

**1. Claude 5 上下文工程新规则：examples→interfaces 转向与渐进披露**（来源：Claude Blog《The New Rules of Context Engineering for Claude 5 Generation Models》2026-07-24 + Claude Blog《Steering Claude Code》2026-06-18 + Claude Blog《Harnessing Claude's Intelligence》2026-04-02 + Claude Code Docs《Extend Claude with Skills》2026-10-01 实拉）：**新模型判断力更强可少显式规则；工具用法最大规则从前「给例子」转向「设计接口」（例子反约束探索空间）；system prompt 简洁=「写代码读起来像周围代码：匹配注释密度/命名/惯用法」；skills=轻量指南按需查找（渐进披露：长技能拆多文件；只有 name+description 会话启动预载，全文调用时 Read 才载；skills 编码个人/团队/产品特有的意见/知识/最佳实践——非通用知识）；CLAUDE.md 保持简短只描述 repo 用途；context awareness=模型追踪剩余上下文窗口（token budget）自主管理上下文**。提升层：可复用 Skill。

**2. 上下文五输入预算与 context rot**（来源：SurePrompts《Context Engineering: The 2026 Replacement》2026-05-05 + MyEngineeringPath《Context Windows & Cost》2026-03-20 + ASOasis《Context Window Optimization》2026-04-30 + anhtu.dev《Context Engineering for AI Agents》2026-08-06 + Claude Docs《Context Windows》2026-10-01 + AgentixForce《Budgeting Strategies》2026-05-13 实拉）：**上下文=预算五输入=system prompt（稳定常缓存）/检索上下文（本轮抓取）/对话历史记忆（或压缩摘要）/工具输出/少样本示例；128K 预算示例=system 2,000（1.6%）+few-shot 3,000（2.3%）+保留输出；context rot=token 增长精度与召回退化——更大窗口不自动更好，curation 优于灌注（Chroma 2025 研究）；每个 token 必须「付房租」；prompt 密度设计=角色目标一句话任务陈述/约束先于参考/最小脚手架（紧凑 bullet+编号步骤+一致分隔符）/schema-first 输出（短 key 减输出 token 使解析确定性）；工具定义惰性注册=每工具 100-400 token，只含当前任务阶段相关**。提升层：工作流。

**3. 长文档与数据密集输入结构化 + 查询末尾效应**（来源：Claude Docs《Prompting Best Practices》2026-09-30 + Claude Docs《Prompting Claude Sonnet 5》2026-09-29 实拉）：**>20K token 大文档/数据密集输入=长数据放顶部（文档与长输入靠近 prompt 顶部、位于查询/指令/示例之前，全模型性能提升）；查询放末尾可提升回答质量（recency 效应）；清晰直接=把 Claude 当聪明但缺上下文的新员工；要 above-and-beyond 显式请求而非让模型推断；金律=prompt 给同事看最小上下文能否理解；Sonnet 5 无 temperature→propose options before building（构建前先提 4 个不同方向：bg hex/accent hex/typeface，跨 runs 产生意义不同设计方向，给用户控制）**。提升层：模型/工作流。

**4. 工具描述即选择杠杆：when_to_use 实证**（来源：AI/TLDR《Tool Calling Best Practices》2026-06-12 + HustletoAI《600 Tool-Calling Tests》2026-04-18 + Together.ai《Best Practices》2026-09-19 + Nalar《Design Reliable LLM Tool Calls》2026-09-03 + datarekha《99% Reliability》2026-05-18 + CSDN《Function Calling vs Prompt》2026-09-22 实拉）：**描述字段=工具选择精度首要杠杆：写 when to use 与 when not to use（不只写做什么），模型靠描述非名字消歧相似工具；实证=600 测试加 when_to_use/when_not_to_use 两字段语义相似工具对选择错误 -15-20%；工具调用五失败模式=幻觉参数/自由 JSON 当 enum/歧义工具选择/静默 schema 漂移/过度急切重试循环——各有结构性修复（enum 约束/schema 校验/描述消歧/版本检查/指数退避）；工具调用是结构化数据不是权限；读工具与改状态工具分离；错误协议入 system prompt=读错误→瞬态（timeout/限流）同参数重试一次→参数错修复重试一次→否则报告；原生 function calling vs 纯 prompt 拼参=参数准确率高/格式稳定/维护成本低**。提升层：可复用 Skill。

**5. reasoning effort 取代 temperature 控 CoT**（来源：DEV《Prompt Engineering: What's New in Sept 2026》2026-09-18 + SurePrompts《Advanced 2026》2026-04-08 + Claude Docs《Effort》2026-09-30 + Google Cloud《Thinking》2026-09-28 + Google Cloud《Get Started with Gemini 3》2026-10-01 实拉）：**reasoning effort=模型级旋钮取代 temperature 控制隐藏 CoT token（Claude thinking.effort/GPT-5.4 reasoning.effort/Gemini Deep Think toggle）；通过 API 设 effort 不用语言强制（别在 user message 里 coax effort）；Claude Sonnet 5 effort 默认 high、最硬任务 xhigh（max 更高）；low 仅 cache 查找；结构化输出配方=严格 schema（JSON Schema/ProtoBuf）+effort Medium/High+原生结构化模式+agentic workflow 包裹（并行降延迟）+域特定 few-shot（few-shot 优于 temperature 技巧）；thinking 模型=内生成思考过程再响应（多步规划/数学/代码强），prompt 直接简洁**。提升层：模型。

**6. 提示测试五步与四维评估**（来源：Best Prompts《Prompt Testing 2026》2026-03-29 + MyEngineeringPath《Prompt Testing & Optimization》2026-03-20 + AIPromptsHub《Measuring Prompt Quality》2026-06-15 + PromptBuilder《How to Test AI Prompts》2026-08-26 + TechDailyShot《5 Prompt Auditing Workflows》2026-04-05 + arXiv 2510.12728《Data-Prompt Co-Evolution》2026-08-31 实拉）：**测试五步=最小 prompt→跑 5-10 次（stochastic 一次≠信号）→诊断失败模式（格式/幻觉/漏约束）→一次只改一个变量（无例外）→版本化 prompt（与测试集+评分 rubric 一起存）；四维评估=格式合规（二元可全自动无 judge）/精确率/召回率/忠实度/稳定性+任务特定（schema 有效性/延迟/工具正确性/拒绝行为）——precision 提取时空字段该留空不猜；数据-prompt 共演化四步=发现失败（合成输入跑模型）→阐述理由（人标正确性+错误假设）→邻域探测（围绕理由生成相似输入入测试集）→精化规格（修订 prompt 指令）；对抗生成=50 代表例→强基础模型合成扰动（paraphrase/typos/恶意输入/畸形 JSON）**。提升层：工作流。

**7. 自动化提示优化：六优化器与评价函数**（来源：FutureAGI《Six Optimizers, Six Different Jobs》2026-05-20 + FutureAGI《Automatic Prompt Optimization》2026-05-29 + Amazon Science《Promptimus》2026-05-14 + FutureAGI《Prompt Optimization at Scale》2026-05-14 + arXiv 2609.26261《Coding Agents are Strong Prompt Optimizers》2026-09-23 + arXiv 2605.21781《Reflective Prompt Tuning》2026-09-16 实拉）：**APO=搜索算法：评价器打分——先定义一次好=eval，算法做剩下的（收敛向更高测量性能）；2026 六优化器=ProTeGi/GEPA/PromptWizard/MetaPrompt/BayesianSearch/RandomSearch 接入 CI；变体生成三法=模板组合搜索（3-5 可调槽：system 风格/示例数/格式指令/persona）+meta-prompting loops（LLM 基于历史分提新变体，OPRO 变体）+文本梯度；Promptimus=评估→反馈生成→策略与编辑生成→候选评估四步循环（20 基准 16 最优，样本高效模型无关）；RPT=reflective controller 每轮 evaluate_prompt→读报告→PATCH 或 STOP；Coding agents=语料规模反思替代迭代搜索（单次离线 pass ~$1.60，无需 held-out 验证集）**。提升层：工具。

**8. Gemini 提示设计策略：分解指令与串联提示**（来源：Gemini API Docs《Prompting Strategies》2026-09-18 + Google Cloud《Prompt Design Strategies》2026-09-22 + Google Cloud《Few-Shot Examples》2026-09-25 + arXiv 2606.07548《Advanced Prompting on Gemini Flash》2026 + Google Gemini《Guiding AI Responses》2026-06-22 实拉）：**分解指令=一个提示一条指令（按用户输入选择处理哪个）——多条指令拆多提示；串联提示=多连续步骤每步一个提示顺序串联（上一步输出=下一步输入，最后输出=最终输出）——复杂任务优于单巨型 prompt；few-shot 最优示例数=需实验（太少学不到模式，太多过拟合响应到示例）；delimiters=三引号/XML/章节标题分隔指令与输入；CoT=逐步思考改善复杂逻辑/数学/推理减少逻辑跳跃与幻觉；Gemini Flash 实证=角色扮演+多 shot CoT 示例+详细格式规则组合 Concept Level Score 0.720 vs 基线大幅提升**。提升层：工作流。

**9. 提示注入防御独有增量：Refuser Clause 与 anti-fabrication**（来源：rapidclaw《Production Playbook》2026-04-20 + promptshields《Defending》2026-04-22 + prompt-architects《46 Attacks》2026-06-18 + AI/TLDR《Practical Mitigations》2026-06-11 + nesyona《How to Harden Your Prompts》2026-06-01 + securedai《Explained》2026-05-15 实拉，与 r376B 七层骨架重叠>60%，仅取独有增量）：**Refuser Clause Pattern=告诉模型拒什么+怎么拒（显式拒绝类别清单+具体攻击示例列忽略）；anti-fabrication discipline=点名所需证据类型+缺口标 [unverified] 而非猜测填补（与 wb-doc-writing 缺口标记法同源落地到防御）；EchoLeak 教训=模型回显注入内容本身就是泄露通道（输出过滤须含指令回显检测）；工具使用模式异常监测=统计显著偏差告警（行为监测而非仅内容过滤）；AI 安全回归测试=注入测试套件集成 CI（与评测门同轨）；不可逆动作人工审批+markdown image 外泄通道剥离/代理未知域链接（模型"渲染"→用户浏览器发请求）**。提升层：可复用 Skill。

**10. 推理模型提示转变与 prompt-as-code**（来源：Claude Docs《Effort》2026-09-30 + Google Cloud《Thinking》2026-09-28 + Google Cloud《Gemini 3》2026-10-01 + DEV《What's New Sept 2026》2026-09-18 + Brightlume《CI/CD for AI》2026-04-17 实拉）：**推理模型改变提示方式=不要求逐步思考（模型内部思考，外部只给精确简洁指令）；长数据位置/格式规则仍适用；effort 档位=Claude max/high/xhigh 权衡智能 vs token 花销；温度不接受→propose-options-before-building 模式产生多样输出；context awareness=Sonnet 5/4.6/4.5+Haiku 4.5 追踪剩余 token 预算自主管理（agent 场景重要）；并行 agent 编排原语直接进 prompt 语言（Claude 4.6 Opus/GPT-5.4 Pro）；prompt-centric toolchains=IDE 扩展/CI pipeline/prompt-as-code 仓库把 prompt 当源文件对待（与 r377B 的 prompt as code 同源强化：版本化+diff+review）**。提升层：模型。
