## 独点（10）

**1. 原生视觉模型取代 OCR 流水线：单模型通读+手写体优势**（来源：Zylos multimodal agents + Awesome Agents doc understanding + Transformance VLM + OfoxAI OCR ranking 实拉）：**2026 原生视觉模型单次推理通读复杂文档——GPT-5.4/Claude Opus 4.6 直接解释密集扫描件/手写表单/工程图/图表报告，替代 Tesseract+布局检测+表格解析+自定义后处理的拼接流水线**；**DocVQA 上 Opus 4.6 与 Qwen2.5-VL-72B 均超 96% 越过人类基线**；**手写体是 VLM 最强项：支票栏/签收单/发票边注 85-95% vs 传统 OCR 40-60%（模型用周围上下文消歧字符而非逐字孤立识别）**；**OCR 模型排行 2026：GLM-OCR 94.62 登顶、Gemini 3.1 Pro 手写档案最强、GPT-5.4 结构化输出流水线最佳——正确做法不是锁单模型，是拿代表样本测 2-3 个（benchmark 94 分在你的发票版式上可能只有 80 分）**。判据=标准文档优先单模型直读；手写/低质量扫描 VLM 碾压 OCR；选型按自己文档抽样测。提升层：模型。

**2. 文档理解路线三选与六阶段 IDP：错误级联第一原则**（来源：juejin 数据知识化 + anhtu.dev IDP 2026 + harshith OCR pipeline 实拉）：**三条路线权衡：①流水线（图像处理→布局分析→内容识别→元素块关系整合）——每环节可单独打磨、问题好定位，代价是错误逐级叠加前一步跑偏全链跟着偏；②通用大模型直读——跳过复杂流水线但难控制；③混合（OCR+结构→chunk→长上下文 LLM）**；**六阶段 IDP=ingest/classify→layout parsing→extraction→validation→confidence routing→consumption；第一件事先测量的是分类：invoice 还是 contract 分错=下游 schema 全错级联**；**理想生产栈=OCR+结构提取（干净文本/保留布局/准确表格/相关嵌入图，Markdown 富 HTML 表格为理想输出格式）→ 逻辑分段（Definition/职责子句归一化）→ 长上下文 LLM**。判据=先做文档分类再做提取，分类错误是最大级联源头。提升层：工作流。

**3. 长文档 agentic 视觉：thinking with images+证据 zoom+大纲导航**（来源：arxiv InSight-doc + ACL DocLens + EMNLP DocAgent + arxiv DocAtlas + SlideAgent 实拉）：**InSight-doc=retriever-free 端到端"thinking with images"——把裁剪、缩放当工具增强 CoT 推理（超越页面检索范式）；DocLens=工具增强多 agent 从整文档"镜头式"zoom 到相关页具体视觉元素，采样-裁决机制产出单一可靠答案（MMLongBench-Doc/FinRAGBench-V SOTA）**；**DocAgent=四件套：outline 构造（树状提纲导航）+actor（按提纲检索生成初答）+reviewer（交叉核对精修）+memory（任务无关知识反思迁移）；DocAtlas=mutable-state 交互——每页三类内容（全页布局图+markdown 渲染+图表裁剪子图）按需自适应装配 observation 而非固定喂入**。判据=长文档不整塞：先大纲→按需裁剪/缩放/页检索→双 agent 生成+复核。提升层：工作流。

**4. 多模态 RAG 三种索引路线+混合架构**（来源：BigDataBoutique mRAG + LLM Versus + QubitTool cross-modal + VLD-RAG 实拉）：**三条索引路线：①caption-and-index（文字描述配图再索引）②统一视觉 embedding（Cohere Embed 4/voyage-multimodal-3 图文同空间）③page-as-image（ColPali/ColQwen2 页面图像 patch 级表示+late interaction 类 ColBERT）——纯文本 RAG 静默丢弃企业文档中图表/表格/图解的大半信号**；**生产混合=稠密（SigLIP）快速召回+late-interaction（ColPali）精度重排两段式；V-RAG 1.0 实证 late-interaction 比 CLIP 回答召回高 9.3 分（硬多轮查询差距更大）**；**VLD-RAG=page-preserving 多模态索引（解析文本+页级元数据+稠密视觉表示）+稀疏/稠密混合检索+检索/回答/验证三 agent 工作流跨页推理；HIVE=初始检索→LLM 补偿查询合成（显式表达 top-k 候选的视觉与逻辑缺口）→二次检索→验证重排**。判据=图表含量高的语料放弃文本-only RAG；先稠密召回再 late-interaction 重排。提升层：工具。

**5. 视觉 token 成本工程：分辨率与平铺即账单**（来源：AI/TLDR vision token + Awesome Agents input limits + token0 + VisionSqueezer + arxiv ERASE + Sony UniCompress 实拉）：**图像 token 非固定费：同 2048×2048 截图 Claude ~1590 token/GPT-4o high ~1105/Gemini 3 low 仅 280；1024×1024=Sonnet 1398 token vs Gemini Flash 258（价差 ~220 倍）；供应商静默缩放=Claude 1568px/GPT-4.1 2048px/Gemini 低清（发 4000px 也会被偷偷降）**；**优化：①smart resize 缩到模型实际处理的最大分辨率（token0）②OCR routing=文字为主图（截图/文档/发票/收据）OCR 提取文本替代视觉 token（文本 token 便宜得多）③对齐内部网格边界省 token（VisionSqueezer 数学吸附网格省 90%）④ERASE=自适应两阶段 token pruning；Sony UniCompress=统一压缩视觉 token 4x、理解准确率掉 3 分内、生成 FID 掉 5 点内（UniTok 生成推理 32.25→18.96 分钟）**。判据=发送前按目标模型实际分辨率重采样；文字图走 OCR 路由；token 预算是视觉 pipeline 第一成本旋钮。提升层：工具。

**6. 图表理解：table-chart gap 机制+工具集成推理**（来源：arxiv 2606.01679 + CVPR ChartAgent + ChartNet + Chart-FR1 + START 实拉）：**table-chart gap=图信息编码进了模型中间表示但到不了预测位置（表格无此断点，跨模型家族一致）——层探针+注意力分析证实：不是没编码，是没路由**；**修复方向：ChartAgent=Think-Observe-Execute-Reflect 工具集成推理（视觉感知工具+推理工具），黑盒映射→可观察/可回放/可验证推理链+证据包供事后核验；ChartNet=150 万五元组（代码/图像/数据表/文本/带推理 QA）代码引导合成，2B 微调超 GPT-4o 与 72B 开源；Chart-FR1=视觉焦点驱动稠密图细粒度推理（GPT-4o/Qwen2.5-VL 随信息密度下降，Chart-FR1 稳定）；START=chart-element grounding+chart-to-code 生成双学习**。判据=图表 QA 别只信最终答案，上工具化推理链+证据包。提升层：模型。

**7. 统一多模态 embedding：单一语义空间+锁定对齐塔**（来源：Google Gemini Embedding 2 + arxiv jina v5 omni + Alibaba Qwen3-VL-Embedding/Reranker + OmniSONAR 实拉）：**2026 原生多模态 embedding 把文本/图像/视频/音频/文档映射进单一统一空间（Gemini Embedding 2 覆盖 100+ 语言，任意组合输入同表征）——简化"各自嵌入再拼接"的复杂管道**；**工程关键=jina-embeddings-v5-omni 锁定对齐塔（frozen backbone 文本+新模态编码器，只训连接组件 0.35% 参数）保持几何结构防表示坍缩；OmniSONAR=文本/语音/代码/数学统一空间，千语言无坍缩（高资源语言不掉点）**；**配套重排=Qwen3-VL-Reranker 取（query, document）跨模态对重排，弥补 embedding 召回精度**。判据=多模态检索优先原生统一 embedding+配套跨模态 reranker，不再各自嵌入拼接。提升层：工具。

**8. GUI/桌面 agent 2026：像素级感知+紧凑 VLM 解析器**（来源：DEV agdex GUI agents + arxiv ScreenParse + MLHive UI-DETR-1 + arxiv UI-Mate + Liquid LFM2.5-VL-3B 实拉）：**桌面 GUI agent=VLA 基础模型直接经原始屏幕像素感知+像素坐标 grounding+System-2 刻意推理，经模拟硬件外设交互（无需 API/HTML 解析/知道底层技术栈）**；**ScreenParse=自动化流水线（Webshot 渲染多样 URL+提取标注+VLM 重标注+质量过滤）产 316M 紧凑 ScreenVLM 解码 ScreenTag 标记（structure-aware loss 给结构关键 token 加权）——4x 快于 2B VLM、够小可端侧；UI-DETR-1=70.8% WebClick 超越 OmniParser（视觉感知模型 fine-tune 面向自主计算机交互）；UI-Mate=SFT 学交互协议+坐标 grounding→agentic RL 在线可验证环境强化；LFM2.5-VL-3B 端侧读屏 grounding 工具调用**；**成本警示=截屏感知的每次截图都是多模态推理调用，规模上叠加很快**。判据=GUI 自动化优先截屏感知路线；解析用紧凑 ScreenTag 模型替代大 VLM；缓存截图成本。提升层：工具。

**9. 多模态 agent 评测基准矩阵 2026**（来源：arxiv AgentVista + VTC-Bench + VideoGAIA + CocoaBench + TOBench + EgoBench 实拉）：**AgentVista=209 任务 25 子域 7 类（电商/地理/社会/科技/娱乐/文化/学术），查询锚定细节丰富视觉状态（日常照片/截屏/技术图），单图与多图输入；VTC-Bench=32 种 OpenCV 视觉操作工具链组合 680 题——测多工具组合与长视野多步规划；VideoGAIA=视频理解多轮工具增强（迭代感知视频+调外部工具+跨轮整合证据）271 任务；CocoaBench=视觉+搜索+编码灵活组合的长视野统一数字 agent；TOBench=100 可执行任务 27 MCP server 324 工具，closed-loop 多模态验证=执行工具→检查渲染/转换产物→输出失败自纠正；EgoBench=1045 egocentric 视频任务+用户-agent-工具交互环境（多 agent 模拟用户）**。判据=多模态 agent 评测按"视觉状态丰富度+工具组合+闭环验证"选基准，不只测感知。提升层：工具。

**10. 跨模态对齐工程：统一空间可比性+几何体积度量**（来源：SJTU unified multimodal retrieval + CVPR MOVER + QubitTool cross-modal + RagAboutIt vision RAG fixes 实拉）：**跨模态检索成败=不同模态 embedding 是否真在同一向量空间可比（cross-modal alignment engineering）；SJTU 框架三件=统一多模态编码器（消模态壁垒）+编码后残差融合（保单模态语义一致+捕跨模态交互）+缩放训练策略（修模态学习失衡，均衡三模态样本分布强化视觉表征）**；**对齐可度量=MOVER/GAVE 用跨模态 embedding 张成的平行多面体体积当方向对齐指标（体积小=向量方向对齐=语义一致）；OCR 需配空间锚定=V-RAG fix：OCR 提取文本不知道它出现在页上哪个位置，检索要把查询"左上"与图像真实区域对齐——纯 OCR 文本索引是"盲的"**。判据=多模态检索上线前先验跨模态对齐（同空间可比），OCR 索引必须带空间坐标。提升层：模型。
