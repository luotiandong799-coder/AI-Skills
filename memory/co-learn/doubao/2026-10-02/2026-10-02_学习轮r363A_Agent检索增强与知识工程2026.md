## 独点（10）

**1. 混合检索管线已定形：BM25 + 稠密向量 → RRF 融合 → 交叉编码器重排 → LLM**（来源：aiworkflowlab 2026-05-03 + InfoQ 2026-06-12 + dev.to 2026-09-21 实拉）：2026 生产模式已基本定形——稀疏 BM25（精确关键词）+ 稠密向量（语义相似）并行检索，RRF 融合，前 K 块入 LLM 前可选交叉编码器二次重排；混合检索比纯向量检索在大多数真实任务上高 10-25%；RRF 融合=文档在向量搜索排第 1、BM25 排第 3 的，比两者都排第 2 的得分更高。判据：**检索层基线=混合（BM25+稠密）并行+RRF 融合+可选交叉编码器重排，纯向量不再是默认**。提升层：工具/工作流。

**2. RRF 无长度偏差：倒数排名融合免归一化**（来源：InfoQ《打破向量检索的局限》2026-06-12 实拉）：可变长度分块的 RAG 系统中，不调整会大块恒定胜过小块；RRF 用 1/(k+rank) 融合两个排序列表而非分数——无需分数归一化，天然免疫长度偏差；在将前 K 个文本块输入 LLM 前可选交叉编码器做二次重排序。判据：**跨检索器融合用 RRF（排名驱动）不用加权分数（长度敏感）**。提升层：工具。

**3. Contextual Retrieval + Late Chunking 组合：检索失败率降 35-67%**（来源：aiworkflowlab 2026-05-26 + LobeHub 2026-09-23 实拉）：contextual retrieval=embedding 前把短 LLM 生成上下文前置到每个 chunk（chunk 自含语境，配 prompt caching ~90% 成本节省）；late chunking=用长上下文模型 embed 整篇文档再池化 token 向量成 chunk——组合相对 naive 定长分块把检索失败率降 35-67%（Anthropic 公开基准 + Jina late-chunking 论文）。判据：**分块策略升级优先做"contextual 前置 + late chunking 池化"，一次索引成本换持续检索质量**。提升层：工具/可复用 Skill。

**4. 结构感知分块：段落法最优，表格保表头**（来源：arXiv 2602.16974 + arXiv 2605.00318 + Oracle 2026-07-16 实拉）：分块方法分类学=结构方法（段落/固定大小/句子）平均效果高于 LLM 引导方法（LumberChunker/proposition-based）与语义分割——四个 embedding 模型上段落分块 nDCG@10 最高；表格=行级单元构建 key-value 块（STC）、token 约束按结构边界切分；**表头/行标签/单位随每个检索片段保留，不让行变成一串断开的数字**（12 无列名/行标签/单位无意义）。判据：**分块按文档结构边界切（段落级），表格按行级 key-value 块且表头随片段保留**。提升层：工具/可复用 Skill。

**5. RAG 评测双族四指标：检索族与生成族分开测**（来源：dev.to 2026-09-18 + metafiedlab 2026-06-08 实拉）：RAG 系统两个失效面=检索（找对上下文吗）与生成（模型用对了吗）——**分开测量、分开修复，最大错误=测一族就宣布完成**；RAGAS 四指标最重诊断权重=faithfulness（答案声明被上下文支持的比例，幻觉检测器）/answer_relevancy/context_precision/context_recall；生产阈值=faithfulness>0.85、answer relevancy>0.8、context precision>0.75、context recall>0.8（内部工具 0.7 可接受）。判据：**RAG 质量=检索族（precision/recall）+生成族（faithfulness/relevancy）两族都测，阈值按面向客户/内部工具分层**。提升层：工具/工作流。

**6. RAG 生产三 SLO 与观测三支柱**（来源：ailearningguides 2026-05-18 + polystreak 2026-04-11 实拉）：三 SLO=延迟（端到端 p95<3s）/可用性（99.9% 请求有响应）/质量（eval 集分数>0.75）——**质量 SLO 最难，定义、测试、报警三者缺一不可**；观测三支柱=tracing（这一请求发生了什么，按请求按步骤）/metrics（系统随时间表现，小时/日/周聚合）/evaluation（答案正确性，按响应质量评分）——多数团队先做 metrics（仪表盘）其实最不该先做。判据：**RAG 生产观测=tracing+metrics+evaluation 三支柱，质量 SLO 显式定义并报警**。提升层：工作流。

**7. 检索覆盖率：happy path 偏差是最大失效模式**（来源：10decoders 2026-09-03 实拉）：覆盖率=系统对生产真实查询分布（含尾部边界案例/与索引文档不同术语）的检索能力；**开发者策展测试集 95% 覆盖率可能在生产分布只有 60%——测试集偏向 happy path 时覆盖缺口只在规模下显形**；构建含期望分布尾部的测试集，逐查询判定索引语料是否含答案（有些查询本质不可答），测可答查询中被检索出有用上下文的比例。判据：**检索评测补"覆盖率"维度——测试集含分布尾部，先判可答性再测检索命中**。提升层：工作流。

**8. Agentic RAG：自查询分解 + 自适应重查 + 自纠正重写**（来源：Markaicode 2026-03-12 + channel.tel 2026-04-01 实拉）：SelfQueryRetriever=LLM 把问题分解为语义搜索 + 元数据过滤（naive RAG 把每个问题当纯语义相似，完全忽略结构化元数据）；自适应检索循环=低置信度时重新查询；自纠正检索=检测到无关文档后重写查询——"5 个检索文档中 3 个无关 → 重写查询"，重写策略=用更具体术语/拆复合问题/加目标文档会出现的关键词/去歧义词。判据：**agent 检索三层=自查询（语义+元数据过滤）→低置信自适应重查→无关文档驱动重写**。提升层：工作流/可复用 Skill。

**9. 查询变换技术矩阵：按场景选增益**（来源：LobeHub query-transformations 2026-09-23 实拉）：五技术量化增益与成本——step-back（细节重问题 +5-10% 召回/1 次 LLM 调用）/RAG-fusion（+15-25%/1 次 LLM+N 次搜索，通用质量提升）/子查询分解（多跳问题 +20-30%/1 次 LLM+N 次检索，多部分问题）/查询路由（异构索引，1 次分类器调用）/同义词扩展（关键词密集域 +5%，近乎免费）。判据：**查询变换按问题类型选——多部分用分解、细节重问题用 step-back、异构索引用路由，不一律堆叠**。提升层：工具/工作流。

**10. 上下文压缩与 Prompt Caching：压缩近免费、缓存读零头**（来源：louisbouchard 2026-08-18 + Redis 2026-07-01 实拉）：2026 严肃提供商普遍提供 prompt caching——重发已处理上下文按零头计费（Gemini 约 90% off；DeepSeek $0.14→$0.0028/M 约 50 倍便宜），缓存 token 已计算过、首 token 返回更快；LLMLingua 族=小模型评分 token 困惑度、丢低信息 token——20x 压缩比仅 1.5% 推理性能损失；contextual retrieval 全套配 prompt caching 约 90% 成本节省。判据：**成本优化=prompt caching 缓存读零头+LLMLingua 式 token 级压缩（20x 压 1.5% 损）——先查缓存再谈降模型**。提升层：工具/可复用 Skill。
