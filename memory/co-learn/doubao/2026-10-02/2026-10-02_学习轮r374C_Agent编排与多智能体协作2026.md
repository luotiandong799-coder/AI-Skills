## 独点（10）

**1. 编排六模式量化矩阵+选错成本 3-5x**（来源：anhtu.dev《6 Patterns for Production Agent Coordination》2026-04-21 + Beam AI 2026-04-15 + AIPromptsHub《Multi-Agent Coordination》2026-06-21 实拉）：**六模式=Sequential Pipeline/Supervisor/Orchestrator-Worker/Fan-Out-Fan-In/Router/Hierarchical（+Swarm/Blackboard 变体）；量化矩阵=Sequential（延迟=sum 全链/成本低-中/复杂度低，适合 ETL、多步验证）/Supervisor（中高/中/中，任务分解）/Fan-Out-Fan-In（延迟=max 一路/成本 N×/中，批量多源实时）/Router（最低/最低/低-中，API 网关、客服混合负载）/Hierarchical（高/高/高，10+ agents 大组织）**；**选错模式=多智能体系统成本 3-5x 最常见原因**；**微软三种=顺序链式/并发（扇出扇入 MapReduce，每代理独立分析再合并）/编排者路由**。提升层：工作流。

**2. Anthropic 多智能体研究系统委派纪律**（来源：Anthropic《How we built our multi-agent research system》+ CSDN 2026-09-23 实拉）：**教编排者如何委派=每个子代理需要 objective+output format+工具与来源指引（缺一子代理即无方向乱跑）；工具设计选择关键=agent-tool 接口与 HCI 同等重要，给 agent 显式启发式=先检查所有可用工具/工具匹配用户意图/广泛外部探索用 web search/偏好专用工具而非通用——bad tool descriptions 会把 agent 带完全错的路**；**架构=Orchestrator（Lead Researcher，理解目标/定策略/拆任务/决定是否继续研究）+Workers（Subagents 执行）两层**。提升层：工作流。

**3. Orchestrator-Worker 成本模型**（来源：Beam AI 2026-04-15 + datarekha 2026-05-28 + Agent Patterns 2026-07-02 实拉）：**orchestrator 用强模型、workers 用便宜任务特定模型=成本降 40-60%**；**三部件=中央 LLM 拥有计划+一组窄范围 worker+共享状态对象在两者间传递；orchestrator 不执行子任务、workers 互不协调；每个 worker 收到 bounded subtask+自己的工具集、独立探索后把结果交回 orchestrator**；**单问责点（single accountability point）=客服路由/跨职能流程首选**。提升层：工作流。

**4. Subagent 上下文隔离+委派三对象契约**（来源：Zylos《Context Engineering: Runtime Discipline》2026-04-19 + Augment Code《Token Cost Context Constraints》2026-06-18 + DEV《Sub-Agent Pipelines》2026-10-01 + Microsoft《subagents duplicate messages》2026-08-28 实拉）：**2025-2026 生产主导模式=isolated subagent contexts：coordinator 显式选择传什么给每个子代理，子代理在自己 token 预算内运行；子代理输出当工具结果=带来源的数据、不继承父权威；实测=isolated subagents 9K tokens vs skills-based 15K**；**委派三对象=subagent task（编排者交给子代理什么：objective+格式+边界）/subagent result（子代理交回什么）/orchestrator report（编排者组装统一输出）；子代理=独立 persona+专属 system prompt+独立工作流配置（一等公民非子任务执行器）**；**避免重复消息=父代看不到子代理与用户交换只经定义输出学结果：输入收集在开始前、输出读取在完成后、指示子代理不直接发消息给用户；三种输出槽=findings（答 scopedRequest）/openQuestions（未答部分交回父代继续）/interactionSummary（已答摘要防重复）**。提升层：工作流。

**5. Durable Execution 检查点恢复**（来源：AWS Well-Architected《AGENTREL03-BP03》2026-09-30 + LangChain《runtime behind deep agents》2026-04-20 + Cloudflare《Project Think》2026-04-21 实拉）：**长跑 workflow 无检查点=每次失败付全量重启成本；在自然边界持久化状态+每步幂等=从最后完成点恢复而非重做；LangGraph=每 super-step 写 checkpoint（Postgres 默认）thread_id 作持久游标，worker 崩溃即从 checkpoint 恢复**；**重放陷阱=非确定性操作和副作用要包装避免恢复时重复，独立副作用隔离=replay 从持久化拿结果而非重做；Cloudflare Project Think=kernel-like runtime：agent 平台重启存活+关系记忆树+自写代码沙箱执行；bolted-on try/except=输家玩法，赢家栈把 state/retries/validation 外部化为一等基础设施**。提升层：工具。

**6. 每代理显式 token 预算+优先级裁剪**（来源：Microsoft Learn《Optimize token usage multi-agent》2026-09-30 + Kaman《Adaptive Context Management》+ DEV《Context Budget Accounting》2026-06-24 实拉）：**按任务复杂度给每代理显式 token 预算=简单 lookup 2000/推理 4000/复杂策略解释 8000；超预算=context assembler 在调用前应用激进压缩；预算执行走优先级=低优先级内容先裁**；**子代理预算表（Kaman）=MCP 32K/Tool 48K/Workflow 64K/Analysis 48K/Composition 32K；四角色预算=Orchestrator（最高上下文窗+最低调用频次）/Subagent（最小窗只任务范围）/Critic（常被塞不需要的上下文=应瘦身）/Formatter（只该拿结构化数据）**。提升层：工作流。

**7. 工具设计四纪律+目录规模治理**（来源：AI/TLDR《Tool Calling Best Practices》2026-06-12 + codeguides《Tool Use Best Practices》2026-07-16 + Machine Learning Mastery《Roadmap to Tool Calling》2026-05-07 + FutureAGI《Function Calling 2026》2026-05-14 实拉）：**命名=verb_noun snake_case <64 字符（模型第一个读的是名字，直接影响选择）；描述=写触发条件+非目标（"何时用/不是干什么/用哪个兄弟工具"）；相似工具显式消歧（"search_web 实时数据 / query_knowledge_base 2025 前索引内部文档"）；参数带示例值+required 标全真必填（optional 造成幻觉调用）+additionalProperties:False**；**目录规模=5 个清晰工具显著优于 50 个可扫描（选型准确率随规模下降+大目录吃掉推理 token）；平行结果冲突=定义解决策略（暴露给用户或优先级规则）；读工具与状态改变工具分离（失败后果不同）；重试上限防无限循环（max_iterations=5+每调用 token cap）**。提升层：工具。

**8. 三层恢复模式+重试风暴治理**（来源：MyEngineeringPath《Agent Debugging》2026-03-20 + OpenLegion《Agent Reliability》2026-06-01 + AI Tools Guidebook《Retry Storm》2026-05-25 实拉）：**三层=指数退避（瞬时失败默认，勿立即重试锤打已承压服务）/fallback 策略（持久失败）/checkpoint 恢复（长任务）；错误类型分表=瞬时 5xx/超时 3 次 full jitter cap 20s→DLQ+告警/LLM 429 3+SDK 重试 Retry-After 头优先/Anthropic overloaded 60s/120s/240s/永久 4xx 0 次立即 DLQ；基础配置=base 0.5s multiplier 2.0 max 30s（0.5/1/2/4/8/16/30）**；**重试风暴修复=上限 5 次+指数退避 jitter+429 尊重 Retry-After+每工具 circuit breaker（停止锤打已挂端点）+只重试工具调用不重试整个 LLM 推理循环；timeout stacking=用户 30s 预算/agent 20s/工具 15s 叠到 50s——budget propagation 每层尊重外层预算**。提升层：工具。

**9. HITL 审批门四组件+毕业机制**（来源：LangChain《Human-in-the-loop》2026-10-01 + anhtu《Approval Gate》2026-05-25 + Pickaxe《earn autonomy》2026-07-28 + explainx《blast radius》2026-06-28 实拉）：**审批门四组件缺一失败=agent 提动作+推理→gate 暂停持久化状态（checkpoint）→通知审批人（Slack/email/UI）→恢复执行；LangChain 四决策类型=approve（原参数执行）/edit（改参数后执行）/reject（跳过执行+拒绝反馈回 agent）/respond（human 消息当合成工具结果，ask_user 型工具）**；**授权粒度=哪些动作 autopilot/哪些批量审批/哪些逐一审批/哪些永不离开人（审批是产品功能不是政策备忘——agent 行动前就知道规则）；批准三轴=工具单位/动作内容/阈值；毕业机制=按动作类型跟踪错误率，<~5% 将该动作从 in-the-loop 毕业 on-the-loop（逐动作挣自主权不是一天全给）；blast radius=影响实体数/金额/人数定门槛（$1 API vs $500；1 人 vs 50000 人消息）**。提升层：工作流。

**10. Agent 评估三框架+ECP 便携合同**（来源：FutureAGI《Agent Metrics Frameworks》2026-05-20 + Mastra《Agent Evaluation》2026-06-22 + CSDN《Demystifying evals》2026-08-12 + arXiv《Evaluation Context Protocol》2608.19263 实拉）：**三种 agent 指标框架=trajectory-first（评估路径不只终点：工具调用序列/步骤效率/探索性）/task-completion-first（完成率+部分得分，按任务类型/工具组合/用户段细分定位弱项）/output-quality-first——按 bug surface 选不是按厂商**；**评分器分层=正确性优先确定性检查/语义质量用结构化 LLM 量表/关键安全条件硬门槛不被平均分抵消/支持部分得分并区分失败层级/LLM 评分器允许输出"未知"/定期与人类专家对齐/防投机（防游戏化评分）**；**ECP=Evaluation Context Protocol 厂商中立便携合同：agent 暴露 user-visible output+工具调用+audit 上下文，程序化检查跨框架与 CI 统一跑**。提升层：工作流。
