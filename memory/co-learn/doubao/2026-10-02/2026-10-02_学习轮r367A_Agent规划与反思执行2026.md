## 独点（10）

**1. 任务解耦规划：Supervisor 分解+前驱依赖图+拓扑调度**（来源：Task-Decoupled-2601.07577 实拉）：规划器把总目标分解成语义一致的子任务、推断子任务间的 prerequisite 关系、产出**有向依赖图**（每节点=带独立规格说明的解耦子任务）；执行期 Supervisor 做**拓扑调度——重复选择 prerequisite 已满足的 ready 节点执行**，满足前绝不提前执行。判据：**计划=图不是列表——依赖未满足的步骤是缺陷**。提升层：工作流。

**2. PseudoAct：伪代码计划合成+引导执行两阶段分离**（来源：PseudoAct-2602.23668 实拉）：ReAct 是依据增长执行历史 h<t 逐个选原子动作 a_t 的**反应式**决策（无全局结构）；PseudoAct 把决策重构成**编程过程**——先用用户查询+动作集合成伪代码计划（显式分支/循环/步骤），再按计划引导执行。判据：**先出伪代码计划再执行——把隐式反应变成显式程序**。提升层：模型/工作流。

**3. 反思循环：generate→critique→improve + critic-in-the-loop 条件循环 + 可配置重试上限**（来源：zylos-self-correction + sitepoint-patterns + taskade + langgraph 实拉）：反思=**围绕模型搭的循环（plumbing），不是模型内特性**——跑模型产出→跑模型打分→差则喂回批评再跑；LangGraph 生产共识形态=agent→critic→[accept | revise→agent] 条件循环，**带可配置最大重试数防死循环**；实证：2-3 次迭代内输出通过，适合可程序化/LLM 自评的质量场景。判据：**生成与评判分离是 agent 抓错的机制——同模型既生成又评判等于没查**。提升层：工作流。

**4. FCPAgent：可证伪承诺计划（FCU）+ plan-test-repair 循环**（来源：FCPAgent-2607.24167 实拉）：每计划步=**Falsifiable Commitment Unit（FCU）**：落地到可复用技能的 subgoal+确认证据+反证证据+置信分；执行组织成 plan-test-repair 循环；**混合承诺测试=行动前检查候选行动（防破坏性动作）、执行后检查观察**（确认真的生效）。判据：**计划的每一步都要自带"怎么证伪它"——没有可证伪性的计划无法失败定位**。提升层：可复用 Skill。

**5. 计划漂移监控：Judge/Advisor 分离，阻塞/非阻塞 drift 分类**（来源：agentpatterns-LivePlan 实拉）：monitor 实时建两视图=**含 thought 节点的 action graph + phase-sequence 抽象**，对照固定算法检查、发现分两类：**阻塞 drift（plan violation/过早打补丁/跳步骤/跳验证/思维-行动振荡）→立即停执行；非阻塞 drift（单相长停滞/相时长超限/重复动作成 back-edge）→附建议继续跑**——同一次运行里 judge（停/继续）与 advisor（建议）分流。判据：**漂移监控要有"停/继续"与"贴建议"两条道——混一起会把执行卡死或漏掉告警**。提升层：可复用 Skill。

**6. 执行后验证三原则：独立证据源+scope drift 超 20% 强制重规划**（来源：algomox + agiflow + prefactor 实拉）：Verify 用**独立证据源**检查期望后置条件——**remediation API 返回 HTTP 200 ≠ 问题修复（只证明请求被接受）**；agent 自查任务成功有 45-48%（单控制域）/75.8%（自评 agent）假成功率——**自评不看系统真实状态=无可靠信号**；scope drift 检测=Gate 2 做 **plan-output diff（完成子任务输出 vs spec 授权范围），文件/函数改动偏离>20% 触发 block 并强制重规划**。判据：**验证不信工具自称成功，成功与否以系统状态为准**。提升层：工作流。

**7. 失败恢复分层：re-execute vs replan + 监控五触发类型三分支**（来源：Goal2Skill-2604.13942 + agentixforce-replanning 实拉）：恢复策略=**失败且重试次数<N→重执行当前子任务；超时或次数超限→整体重规划（基于记忆更新计划）**；执行中 monitor 查五触发类型=**工具失败/新信息推翻假设/预算超限/目标漂移/质量门失败**→三分支：**本地重规划/升级人工/继续执行**。判据：**恢复不是一律重试——次数上限后必须换策略（重规划），否则死循环重试**。提升层：工作流。

**8. 规划评测：APB 五设置诊断+OrchestrationBench DAG 图编辑距离**（来源：APB-2606.04874 + OrchestrationBench + DeepPlanning 实拉）：APB=4209 多模态例/22 域/**5 设置**（整体规划/反馈条件逐步规划/多余工具鲁棒性/坏工具/不可解任务）——发现 MLLM 通病：长时程规划弱、工具噪声鲁棒性差、校准拒绝差、推理时精炼差；**OrchestrationBench 把每个编排目标形式化为有向无环图（节点带 pending/running/completed 状态）用图编辑距离打分——解决"端到端评测说不清规划错在哪"**；DeepPlanning=离线沙箱+规则 checker，可复现可验证。判据：**规划评测要分设置诊断（含鲁棒性/不可解），端到端分数说不清错在哪**。提升层：可复用 Skill。

**9. Checkpoint-and-resume：superstep 级持久化+thread_id 光标+pending-writes ledger+无效恢复定义**（来源：langchain-runtime + agentnative-checkpoint + Safe-to-Resume-2608.29381 + MS-durable 实拉）：durable execution=托管 task queue+**自动 checkpoint（LangGraph 每次 superstep 写持久层，thread_id 当持续光标）**——worker 崩溃从最后完成点恢复不重来；**pending-writes ledger 记录部分失败并行批里已成功的输出，只补失败**；MS durable=每次 await/yield 自动 checkpoint、崩溃从最后完成步继续；**Safe-to-Resume 定义无效恢复两类：checkpoint 漏内部状态（incomplete internal state coverage）+无效恢复转换**——恢复安全性可形式化验证。判据：**长时程 agent 的持久化粒度=step 级，恢复要防"漏了内部状态还当恢复成功"**。提升层：工具/工作流。

**10. 规划成本护栏：per-run 硬顶+5-10 迭代上限+重复调用 3 次升人工+progressive disclosure 四级**（来源：coffee-guardrails + zonflip-cost-control + clawhub + vinish 实拉）：**per-run 硬 token 顶（超限终止，无论完成状态）；per-workflow 最大步数（12 步正常则 20 步报警）；per-time-period 成本告警**；agent 重复同一工具调用 3 次→HITL 升级；**progressive disclosure 四级=L0 名称（1-5 tok）/L1 摘要（10-30）/L2 schema（50-200）/L3 示例（200-500）**——技能/工具信息按需加载、用完可卸载（MS Agent Framework 的 discover/load/unload 形状），成本与上下文都省。判据：**护栏按 run/workflow/time-period 三层设，信息按层渐进披露——别让全部技能描述常驻上下文**。提升层：工作流。
