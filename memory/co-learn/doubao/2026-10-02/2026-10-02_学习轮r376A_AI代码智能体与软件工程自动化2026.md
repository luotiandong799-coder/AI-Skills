**2. **3. 终端代码 agent 选型矩阵与工作流**（来源：Graham Miranda《Vibe Coding 2026》2026-06-17 + InsiderLLM《Local Alternatives to Claude Code》2026 + GitHub Blog《Copilot CLI GA》2026-02-25 + RockB《Terminal vs IDE》2026-05-21 + PromptQuorum《Cline vs Aider》2026-08-27 实拉）：**OpenCode=开源终端 agent（172K stars，MIT，model-agnostic 75+ providers，SLIM 插件系统，AST-aware patches，本地运行代码不上服务器）；Aider=Git-native（40.6K stars，每个 edit 自动 commit 可审查可撤销，terminal-only SSH/无 IDE 场景）；Cline=VS Code agent（57K stars/5M+ installs，Apache-2.0，Plan/Act 模式分离，BYOK 配 Ollama 零成本）；Copilot CLI GA=/diff 会话内审查+/review 提交前 sanity check+Esc-Esc undo/rewind；选型决策表=已住终端选 terminal agent、前端/自动补全选 IDE、SSH/容器/CI 支持与复杂多文件重构选 terminal agent；Claude Code 148K stars=terminal agents eating the IDE 信号（特权执行上下文 vs 静态分析）**。提升层：工具。

**4. **5. **7. 代码 agent 失败分类学与恢复协议**（来源：arXiv 2602.17037《Wink: Recovering from Misbehaviors》2026 + Codex《Coding Agent Failure Taxonomy》2026-06-03/08-05 + SurePrompts《Agent Debugging Prompts》2026-04-20 + MQDIR《When the agent is wrong》2026-04-29 + ACM《Localization Framework for Reasoning Faults》2026-09-09 + AgentPatterns《Anti-Patterns》2026-05-27 + RohitRaj《9 Production Bugs》2026-05-29 实拉）：**Wink taxonomy=约 30% 轨迹含 misbehavior，三主类=Specification Drift（规格漂移）/Reasoning Problems（推理问题）/Tool Call Failures（工具调用失败），异步自干预提供定向纠偏 nudging；最高频失败=Confident wrongness（幻觉 API 方法/错误类型签名/错误文件路径——**任何具体主张必须对照实际代码验证**）；恢复四 pattern=inspection/rollback/re-scoping/root-cause（不总重启——agent 已积累的尝试/所见/失败有价值）；Silent Tool Rot=会话内任务成功不认证可复用工具（96.8% 保存的合成工具 held-out 评测零分但本地跑得干净，pass-rate 仪表盘看不到 rot）；AI 生成代码九反模式=phantom validation/optimistic auth/IDOR/race conditions/connection-pool exhaustion/retry storms/God components/orphan migrations/console.log observability（~100 用户以下内部工具可跳 review）**。提升层：可复用 Skill。

**9. 代码 LLM 多维评测（pass@1 之外）**（来源：OpenHands《AI Coding Benchmarks Explained》2026-06-25 + DataCamp《Best LLM for Coding 2026》2026-09-25 + arXiv 2606.27406《Implicit Software World Models》2026 + arXiv 2608.22529《.NET Benchmarking the Titans》2026 实拉）：**2026 有效基准=SWE-bench Pro/Terminal-Bench 2.1 & 4.0/LiveCodeBench v6（SWE-bench Verified 饱和失去区分度）；LiveBench=月度轮换+客观 ground truth 无 LLM judge（低污染）；仓库特定评测器=TrajectoryScore/ToolSelectionAccuracy/TaskCompletion/StepEfficiency（自家金集，不只 pass@1）；隐式软件世界模型=三类预测任务三类指标（outcome prediction=分类精度/resource prediction=wall time/memory 对数线性校准/profiling=ranking）；.NET 评测=Composite Quality Score（correctness/complexity/nesting/style/performance 五归一化分量）+任务难度 vs 模型行为解耦（cyclomatic complexity 配对 Pearson）；StepCodeBench=553 独立仓库/33 语言（阶跃自建，可复现 agent 能力）**。提升层：工具。

**10. 企业治理：安全 Catch-22 与采纳基建**（来源：Shehzan《AI Coding Agents: From 92% Adoption to Production》2026-06-16 + RockB《State of AI Coding Agents 2026》2026-05-25 + NerdLevelTech《Governance Gap: 97% Adoption, 30% Control》2026-06-28 + Anthony West《AI Dark Code》2026-09-15 + desightstudio《How CTOs Restructure Dev Teams》2026-07-08 实拉）：**assistant 在开发者权限内运作（读代码/建议改）vs agent 需要工具执行权限（跑测试/建分支/查日志/查库/触发部署）→Security Catch-22：agent 权限越广越有用、但越广越危险（assistant 不会意外泄露 secrets，能跑命令的 agent 会）——安全团队必须定义**独立的 agent 权限模型**（非沿用开发者权限）；2026=97% 企业团队用 AI 编码工具但 <30% 有完整治理（正式追踪/扫描/监督）；治理真空是最大失败模式（不是工具被拒——开发者想用）；赢家差异不在工具选择（多数用 Claude Code+Cursor+Copilot 组合）而在**采纳基建**=何时/如何用 agent 的明确指引+AI vs 人工代码质量测量+不拖慢 CI 的治理流程；监管=新加坡 IMDA 2026-01 首个国家级 agentic AI 治理框架（agent 身份管理+人类问责检查点）+NIST AI Agent Standards Initiative 2026-02**。提升层：工作流。
