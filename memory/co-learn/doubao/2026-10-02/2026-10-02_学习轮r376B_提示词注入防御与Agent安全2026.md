## 独点（10）

**1. 多模态注入四载体与跨模态攻击**（来源：CSA《Image-Based Prompt Injection》2026-03-08 + arXiv 2609.04533《Repeat-After-Me》2026 + ACL 2026《Reference Attack》2026 + arXiv 2607.28165《AudioAgentSecurity》2026 实拉）：**图像注入四嵌入技术=typographic text（排版文本）/steganographic encoding（隐写）/adversarial pixel perturbations（对抗像素扰动）/physical-world signage（物理世界标志）——绕过文本层字符级 sanitization（文本过滤器扫消息输入不扫图像内容）；Repeat-After-Me=黑盒自适应视觉注入（Qwen3.6-27B ASR>80%、GPT-5.5 47%，真实设定=良性用户 prompt 与注入任务语义无关）；Reference Attack=参考引导跨模态 jailbreak（非文本模态嵌恶意 prompt+文本递归符号引用，MLLM 语义重建逐步恢复有害内容）；AudioAgentSecurity=首个并发音频注入基准（8 真实任务场景，malicious audio 隐形 piggyback 用户语音劫持 agent）；ROP（Reasoning-Oriented Programming）=把有害目标分解成空间隔离、语义良性的视觉 gadgets，绕过早层感知级安全对齐（攻击发生在晚段推理）**。提升层：工作流。

**2. 供应链攻击四形态：slopsquatting/phantom squatting/LLMO abuse/DDIPE**（来源：CSA《Slopsquatting》2026-04-19 + Unit42《Phantom Squatting》2026-06-30 + ReversingLabs《LLMO Abuse》2026-07 + arXiv 2604.03081《DDIPE》2026 + Aviatrix《LiteLLM Breach》2026-05-11 实拉）：**slopsquatting=LLM 幻觉包名被攻击者先注册劫持（大型研究=近 1/5 AI 生成代码引用不存在的包，真实恶意包已积累数万下载）；phantom squatting=LLM 幻觉品牌域名被注册拦截 AI 流量；LLMO abuse（知识注入）=写恶意包文档说服 LLM 该包是正确依赖（文档越可信越可能被 coding agent 推荐）；DDIPE=文档驱动隐式载荷执行：恶意逻辑嵌在 skill 文档的代码示例/配置模板里，agent 正常任务复用示例时无显式 prompt 即执行（LLM 管线生成 1,070 对抗 skills/81 种子/15 MITRE ATT&CK 类别，四框架五模型 ASR 11.6%-3x）；LiteLLM 事件=TeamPCP 先攻破 Trivy（LiteLLM CI 用的安全扫描器）拿维护者发布凭据，推 1.82.7/1.82.8 恶意版本（双 base64 多阶段载荷）；恶意 LLM API router=应用层代理全明文访问载荷但无加密完整性（payload injection AC-1/secret exfiltration AC-2）**。提升层：工作流。

**3. 防御评测实证：依赖模型自保的防御全破，输出过滤唯一有效**（来源：arXiv 2604.23887《Evaluation of Prompt Injection Defenses》2026 + arXiv 2606.26479《Out-of-Band Defenses》2026 + arXiv 2606.18530《Domain-Camouflaged Injection》2026 + arXiv 2605.01078《Sonar》2026 实拉）：**九种防御配置 20,000+ 攻击评测：**每个依赖模型自保的防御最终都被破**；唯一守住=输出过滤（应用代码在交付用户前检查模型响应，15,000 攻击零泄露）；跨模型确认非单模型问题（Gemini 2.5 Pro/GPT-5.4/Claude Sonnet 都脆弱）；out-of-band 防御（Biba 完整性/reference monitoring/least privilege）只在静态基准验证过——in-band 防御曾看似强大直到 adaptive defense-aware 攻击 90%+ 破十二个（评测协议必须自适应攻防）；paraphrasing retrieved content=域伪装注入最一致有效防御（ASR 减 55-84%，每模型优于 Llama Guard 4）；spotlighting 模型依赖强（Claude Haiku 减半、Llama 3.1 8B 无效）；Sonar=NLI 语义净化（检测与可信指令不兼容的文本 span 隔离删除，九防御对比下多数据集 ASR 近零且保持任务效用）**。提升层：可复用 Skill。

**4. 红队评测矩阵与自对弈自动化**（来源：RohitAI《OpenAI GPT-Red》2026-07-17 + arXiv 2609.24662《DUMA-Bench》2026 + arXiv 2607.18063《Adaptive Adversaries》2026 + arXiv 2605.10779《LITMUS》2026 + 智源《FAR.AI Minimal Standard 1.0》2026-08-04 实拉）：**GPT-Red=自对弈强化学习：攻击者搜索有效失败+防御者种群学习抵抗，持出集间接注入竞技场 84% scenario success vs 人类红队 13%（GPT-5.1），前身攻击已贡献生产模型训练（GPT-5.3 起）——**价值是循环不是单个分数**；自适应攻击评估=限制首轮 ASR 0-1%，放 15 轮自适应攻击后显著升高（多轮评测是必要协议）；DUMA-Bench=35 可执行多轮任务/八安全域（retrieval poisoning/cross-agent manipulation/不安全下游输出/可信数据过度共享/基础设施滥用），每任务=安全策略+可变环境状态+域工具+对抗工件+断言；LITMUS=819 高风险用例/三对抗范式（jailbreak speaking/skill injection/entity wrapping）+语义-物理双验证+OS 级状态回滚；FAR.AI=67 种易获取静态越狱技术分类+组合攻击空间+旗舰模型基准（Claude Fable 5/GPT-5.6 Sol/Gemini 3.1 Pro/Grok）；Agent Security Bench=ICLR 2025 最高 ASR 84.3%、防御"有限有效性"**。提升层：工具。

**5. 防护工具矩阵：promptfoo/garak/NeMo/Guardrails AI/LLM Guard**（来源：TestMu《9 Best AI Red Teaming Tools》2026-09-21 + promptfoo《Release Notes》2026-09-30 + PyPI《garak 0.16.0》2026 + Kanopy《Guardrails AI vs NeMo vs LLM Guard》2026-05-26 + FutureAGI《Guardrails Platforms 2026》2026-05-20 实拉）：**promptfoo=25.1K stars/测试运行器式红队（YAML 描述应用+攻击目标→按目标生成对抗用例而非重放固定载荷，50+ 漏洞类型/CI-CD 集成/OpenAI+Anthropic 使用，2026-03 被 OpenAI 收购，新 System Prompt Override plugin 测系统指令操纵）；garak=NVIDIA LLM 漏洞扫描器（nmap 式：探幻觉/数据泄漏/注入/错误信息/毒性/越狱，CLI+测试套件）；NeMo Guardrails=Colang DSL 可编程对话控制（五轨=输入/检索/对话/执行/输出）；Guardrails AI=40+ 结构输出验证器；LLM Guard=输入+输出扫描器；选型约束=架构先决（Azure 栈→Prompt Shields/Cisco 生态→AI Defense/零预算→OpenAI Moderation/开源自托管→Rebuff 分层检测含 canary tokens）；GA Guard 实测=Core F1 0.899/29ms、Thinking 0.906/650ms**。提升层：工具。

**6. 间接注入 RAG 实证与净化管线**（来源：arXiv 2601.10923《Hidden-in-Plain-Text》2026 + OWASP《LLM Prompt Injection Prevention Cheat Sheet》2026-09-29 + Mandiant《AI Risk and Resilience 2026》2026-09-19 + Preprints《Multi-Vector Voting Routing》2026-09-16 实拉）：**残余 ASR 三桶与最优开关=可见命令式（49%，attribution 标签最有效 ASR 78%）/代码零宽与同形混淆（31%，normalization 66%）/查询对齐用户查询镜像注入任务（20%，sanitize+attribution 61%）；间接注入对只看 user turn 的防御不可见（载荷提前放入知识库，查询者无需是攻击者）；OWASP RAG poisoning=向量库投毒文档"忽略之前指令"、操纵检索结果含攻击者内容；Mandiant=把全部检索 RAG 数据（社区论坛/工单/外部 partner feed）当不可信输入；防御纵深=数据分段+租户隔离向量索引（公开 agent 不能查敏感跨租户数据）+context isolation+least-privilege 工具执行+运行时 guardrails；Multi-Vector Defense=三语义空间嵌入+梯度提升分类器平行打分+自适应熵路由（低熵正常分类/高熵送二级本地分类器）**。提升层：工作流。

**7. Agent 最小权限四层模型与动态边界**（来源：Mohith《Tool permissions for agents》2026-05-10 + AWS《AGENTSEC03-BP03》2026-09-23 + anomity《Least Privilege》2026-06-21 + BeyondScale《Task-Scoped Credentials》2026-04-09 + arXiv 2601.11893《SEAGENT MAC》2026 实拉）：**四层=1 普通凭据 2 会话级细粒度权限 3 capability tokens（危险工具需窄于一般凭据的令牌：单操作/单资源/短时窗）4 confirmation gates（最危险工具=金融交易/批量更新/破坏性操作需 agent 循环外显式用户确认——agent 提议、独立流程确认）；AWS 动态边界三层=service identity（IAM role/permission boundary 宽限）/transaction（session policy/session tags/IAM Conditions 每操作约束）/user identity（token 资源侧评估）；task-scoped credentials=任务开始签发、完成即撤销（token 载荷=具体工具+具体 scope read:contacts 非 read:*+资源过滤器），替代长命服务账号；审计=审有效权限集而非角色名+配行为轨迹供事后重建；SEAGENT=策略驱动 MAC：agent/tool/RAG 数据库静态标签+执行流图细粒度规则（block/prompt user/allow）+SEMemory 跨多轮上下文选择追踪；**最普遍错误=subtractive assignment（从全量删，残留意外访问）——应零起点只加必需**。提升层：可复用 Skill。
