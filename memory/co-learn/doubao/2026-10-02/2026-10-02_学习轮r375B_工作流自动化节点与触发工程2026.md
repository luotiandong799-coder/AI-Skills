## 独点（10）

**1. n8n AI Agent 生产化六条可靠化清单**（来源：n8n Blog《Make AI Agents More Reliable》2026-05-26 + DEV《n8n Agentic Design Patterns》2026-08-21 实拉）：**①版本控制=prompt 存 agent 工作流外便于回滚与版本管理 ②逻辑路由=分支逻辑在每阶段把 agent 能力限制在边界内 ③输出 schema=output parser 强制可预测 JSON 格式 ④工具设计=清晰描述+静态/表达式/agentic 参数三型策略 ⑤子工作流=把多步操作封装成可控可测单元 ⑥Guardrails=在问题输入输出造成影响前过滤；拓扑层模式=Orchestrator-Executor（子工作流+AI Agent Tool 节点）/Pipeline 链/并行 Fan-Out-Fan-In（分支+merge）——行为层（Agent 节点 Tool Use/ReAct）与拓扑层（编排模式）两个维度都要设计**。提升层：工作流。

**2. n8n 生产 AI Playbook=确定性步骤+AI 步骤混排**（来源：n8n《Production AI Playbook》2026-04-02 + n8n Template Store《LLM Agent Workflows》2026-05-28 + wearetandem《n8n 完整教程》2026-08-10 实拉）：**确定性节点与 AI 节点分工=分类用快便宜模型/生成用更强模型；子工作流抽取复用模式=改一次所有调用它的工作流受益；记录 AI 输入输出供迭代（存确切 prompt/response）**；**输入先规范化=webhook/表单原始输入先过 Code 节点（jsCode）剥离 null/trim 空白/强 schema——否则 agent 节点不报干净解析错误，要么幻觉输出要么静默超时；Return Intermediate Steps=工具调用出错时第一反射（看 agent 决策细节）；Max Iterations 设 10 建立防无限推理循环安全栏；上线前六查=测试→加固→逐节点调试→看中间步骤→max iterations→子工作流拆分**。提升层：工作流。

**3. Dify 变量作用域契约+跨节点全路径引用**（来源：DeepWiki《Dify Workflow Fundamentals》2026-08-29 + PromptIndexHub《Variables Between Nodes》2026-05-22 实拉）：**变量作用域五档=start.*（所有下游节点/单次执行）/{node_name}.*（该节点下游）*/sys.*（全部节点，sys.conversation_id 除外在 Chatflow）*/env.*（大多数节点非 Trigger/应用生命周期）/会话变量（Chatflow 内 sys.conversation_id 生命周期）；跨节点变量是手写契约=源节点必须声明为输出+接收节点必须用全路径格式引用，缺任一边数据就消失（工作流照常执行、不报错、数据静默丢失）；LLM 节点引用={{variable_name}}，注入前替换；Context Variables=知识检索节点输出注入外部知识并保留来源归因（RAG 应用）**。提升层：工具。

**4. Dify 迭代/循环节点工程=并行+会话变量跨轮+break**（来源：Dify《Iteration Node》2026-05-14 + Dify Blog《跨平台文案》+ 技术栈《迭代进阶》2026-08-07 + LobeHub《dify-workflow-skills》2026-09-23 实拉）：**迭代节点输入=上游数组（Parameter Extractor/Code/知识检索/HTTP 响应）；内置变量=items[object]（当前元素）+index[number]（从 0 起）；处理模式=顺序/并行（Parallel Mode 最大并行度设 10，推理模型如 DeepSeek R1 慢则开并行大幅提速）；迭代数组 30 元素上限=解析节点先截断留余量；长 JSON 粘贴用 paragraph 而非 text-input 变量类型；跨轮引用=第 n 轮输出赋给会话变量再全局引用（当前迭代依赖前轮输出时）；循环节点=loop_count 设最大迭代+break_conditions 提前退出+跨迭代状态保持**。提升层：工作流。

**5. Make 错误处理四指令+Rollback/Retry handler+DLQ**（来源：Make Help《Rollback/Retry error handler》2026-09-08 + Make Academy《Incomplete Executions》2026-05-21 + WorkflowPick《Make 错误处理指南》2026-05-12 实拉）：**四指令=Resume（忽略错误继续下一模块）/Ignore（跳过当前 bundle 继续其他 bundle——实践最常用）/Rollback（取消自场景开始的所有变更）/Commit（确认错误前已完成的变更）；Rollback error handler=模块报错即停场景并撤销已做变更（数据库回滚）；Retry error handler=暂停失败 bundle、存错误消息+映射+剩余场景，可自动或手动重试；Incomplete executions=保存场景 blueprint+模块设置+输入输出数据，可重跑防信息丢失；Fallback module=主 API 失败路由到备份服务（并行错误路径第一个成功者胜）；DLQ=高价值场景（订单/支付）失败记录进 Google Sheet 绝不静默丢弃；重试=固定间隔非指数退避（限流场景设 5-10 分钟长间隔）**。提升层：工具。

**6. Make 错误分类处理手册**（来源：ThinkBot《Make Scenario Playbook》2026-07-07 + Use Apify《Make 错误处理》2026-03-15 实拉）：**瞬时错误=退避重试然后隔离到 incomplete executions 人工分诊；数据校验错误=跳过或路由到隔离存储并带 reason code；认证与权限错误=立即告警+暂停或停止调度防抖动（修好前别反复撞）；限流=放慢、批量、等待，避免放大突发的重试；系统变量取元数据（错误消息/模块名/时间）；四指令按错误类型选=断连重试类用 Break（重试上限 1-10+间隔分钟数）/忽略类用 Ignore**。提升层：工作流。

**7. Pipedream 凭据治理=env var+secret props+轮换纪律**（来源：Pipedream Docs《Python/Env Vars/Components》2026-08-30 + codetoolboxhub《CI/CD Secrets》2026-04-15 实拉）：**代码步用 process.env/os.environ 引用账户级环境变量=密钥不落代码+换 API key 无需逐步更新；components（sources/actions）里 env var 不可直接访问（组件可能被任何人用）——sources 用 secret props 引用敏感数据，actions 在对象浏览器里选变量传给步骤；未支持的第三方服务=自定义凭据存 env var；令牌刷新=重连账户生成新 token；轮换纪律=高权限凭据月度轮换/中风险季度，泄露立即撤销，用短时令牌（STS 15 分钟）限制爆炸半径，最小权限作用域到具体 job/环境（构建 job 不该看到生产库密码）；打印安全变量=始终掩码显示**。提升层：工具。

**8. Activepieces 企业控制+AI Agent 审批等待**（来源：Activepieces《AI Agents with enterprise control》2026-10-01 + 《AI Agent Builder》2026-09-25 + 腾讯云《Activepieces 22K Star》2026-07-16 实拉）：**企业三件=凭据加密+数据屏蔽（敏感细节永不进日志）+SSO/audit log（变更审计：谁在何时改了什么配置）；AI agent builder=你设目标+选可用 app/flow/文件，agent 自己决定步骤执行，任何想先检查的动作等审批（HITL 内建）；工具选择四源=任何 app 动作/自有自动化/MCP server/上传文件；自带模型自带 key=管理员配一次 provider；开源 Zapier 替代 22K stars；模板=Lead Nurturing（定时选 lead+配对文章+AI 写个性化邮件）/Client Inquiry Reply**。提升层：工具。

**9. LangFlow 模板化多智能体+结构化输出链**（来源：Langflow《Multi-agent/CSV/RAG/Chunk Classification》2026-08 实拉）：**Simple Agent 模板起步→改工具→agent 当 tool 用组多智能体 flow；LLM-agnostic=API key 配置切模型；模板模式=CSV Agent（LLM+CSV 路径对话查数据）/RAG 双检索（URL tool+vector DB，agent 按问题自选工具再综合）/chunk 分类链=Split Text（chunk size+overlap）→Loop 逐块→Type Converter→Structured Output 组件保证分类输出预定义字段（text/category/explanation）；webhook-first 反馈分析=Webhook 收 JSON payload→解析组件规范化→情感/紧急度分析→If-Else 高危告警；字段提取=Text Input 定义字段（名称/定义/规则/示例：contract_value 转数值忽略货币符号）——结构化输出组件保证 AI 输出合规**。提升层：工作流。

**10. 无代码规模化天花板+成本交叉点+选型矩阵**（来源：Zalt《No-Code vs Custom》2026-06-25 + ValueStreamAI《Business Automation 2026》2026-07-26 + aitoolbox《n8n vs Zapier vs Make》2026-05-29 + n8n《2026 AI Agent Dev Tools》2026-07-16 + ClawHub《Agentic Workflow Designer》2026-10-01 实拉）：**成本交叉点=3,000-8,000 runs/月：Zapier 3 步 50,000 triggers=$3,000/月 vs $20 VPS 跑 n8n；无代码天花板=复杂度>10-20 自动化/顺序执行瓶颈/静默失败（API 超时不报错丢 48h 销售数据）/按任务计费反向缩放/无版本控制审计；分支>4-5 条件=视觉构建器不可维护；payload 上限=Zapier 10MB/Make 15MB/n8n 流式无硬限；并发=~100 并发用户性能退化；选型矩阵（Codability/Enterprise%）=Google Gemini EAP 80/74、Gumloop 71/48、CrewAI 65/48、Flowise 63/37、Dify 59/46、Langflow 35/30；定位=n8n=自托管+代码可扩自动化/Dify=LLM 应用与 RAG/chatbot/Make=可视化 SaaS/Zapier=最快普通自动化；国产化三维度=n8n 国产化适配 Yes+审计留痕可导出+凭据集中管理（Make/Zapier 日志留存有限+连接器各自持凭据）**。提升层：工作流。
