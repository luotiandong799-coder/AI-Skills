## 独点（10）

**1. Agent 数据面六原则：上下文越多泄漏越大+embedding 继承敏感级**（来源：ShShell agentic-security-guardrails + TechTarget reasoning-layer + Okta 实拉）：**更多上下文提升答案质量同时等比放大泄漏、注入面与审计复杂度——上下文量是安全旋钮不是白拿的免费精度**；**embedding 治理硬规则：受限数据一旦被嵌入，embedding 索引必须继承该数据敏感级（向量库要租户隔离/访问控制/保留策略/加密/删除工作流/日志），"向量不可人类可读"不构成脱敏**；**token-level redaction=进 embedding 模型前先剥 PII/管制字段；向量库分段=按租户+密级分桶，不建一个巨型桶**；**数据层风险=未失窃的暴露：检索过滤配置错误让 AI 向无权限用户总结文档——模型看到的必须等于用户能看的**。判据=数据进 pipeline 前先问"这级敏感度允许进上下文吗"，检索过滤按用户可见性预滤。提升层：工作流。

**2. ORCHIDEAS 框架：安全学科×设计面的映射**（来源：Cloud Security Alliance ORCHIDEAS 2026-06-05 实拉）：**六个支柱每个把一条安全学科钉到一个具体设计面：Autonomy→fail-safe defaults+privilege separation 钉在 action 边界；Identity & Intent→capability-based security+complete mediation 钉在授权；Data & Memory Governance→least privilege+compositionality 钉在数据生命周期；Context→zero trust 钉在运行时窗口；Runtime→complete mediation+defense in depth 钉在飞行中决策；Human Oversight & Oversight 钉在人类监督**。判据=设计 agent 时按"设计面×学科"查表补洞，不是笼统"加安全"。提升层：工作流。

**3. 可逆 Redaction 层：token vault+全路径净化**（来源：gptnest + Philterd + dev.to reversible redaction + Strac 四模式 + OpenAI Privacy Filter 实拉，与 r362B redaction 基础为 agent 工具面增量）：**PII→结构化占位符 [PERSON_01]/[REDACTED:type]，mapping 存短生命周期内存 vault（scope 到当前请求），响应返回时恢复——LLM 全程只见 token 但理解上下文**；**redaction 必须坐在每个出站模型调用路径上且是硬依赖：每个 hop（工具调用→模型→再工具→再模型）都是新出站请求=新泄漏机会，工具结果会带回新 PII——只 redact 首条用户消息不够，PostToolUse hook 拦截每次工具返回过 PII scanner 再进上下文**；**四模式选型：Redact（删）/Mask（部分显示留后四位）/Tokenize（格式保持 token 保 shape 供下游逻辑）/Vault（加密移出）；OpenAI Privacy Filter=开源权重小模型做高吞吐 PII 检测 redaction**。判据=每跳模型调用都过净化层，不是只在入口。提升层：工具。

**4. RAG 检索授权：双层独立授权+过滤在检索时不在检索后**（来源：AWS Verified Permissions multi-tenant RAG + AWS Builder fence + Truto document-level RBAC 实拉）：**双层授权互不依赖：层1 API access（Lambda Authorizer 决定能否调 API）、层2 document access（middleware 调 Verified Permissions 决定能查哪些 KB 资源并构造 metadata filter）——层1 坏层2 仍正确**；**六原则：identity before retrieval / policy travels with data（ingestion 时附访问元数据）/ filter during retrieval not after（metadata filter 与 kNN 同查询，OpenSearch）/ least-privilege compute / full audit trail / model sees only what the user can see（预滤上下文）**；**多租户隔离=向量库层 namespace+JWT 确定性隔离（silo index-per-tenant 或 pool namespace），"让 LLM 自己管访问控制"是架构反模式**。判据=授权不放在模型推理里，放检索前的过滤与 API 层。提升层：工作流。

**5. OWASP Agentic Skills Top 10：技能生态专属风险清单**（来源：OWASP AST10 whitepaper + AST01 + proposal + agentkit capability manifest 实拉）：**AST01 恶意技能=隔离执行+静态分析 SKILL.md 可疑指令/混淆/异常 YAML+发布者密钥签名校验+动态沙箱跑（监控文件系统/网络/进程/持久机制 SOUL.md/MEMORY.md 修改）；AST06 弱隔离=容器 sandbox 为默认、host-mode 显式 opt-in；AST07 update drift=不可变 pin 版本防"自动更新"携毒；权限 manifest 缺失=技能被授予超其声明功能的权限，爆炸半径过大——合法技能可被下游注入武器化执行它本不该跑的 DROP TABLE**；**agentkit=内核外设计：即使 goal 被注入改写，extraCapabilities/allowedHosts/allowedReadPaths 仍在 LLM 推理之外保持强制**。判据=装技能按装依赖的流程审：静态扫描+签名+沙箱跑+权限清单最小化。提升层：工具。

**6. 记忆毒化（ASI06）：写门+检索筛+信任层级**（来源：OWASP ASI06 + arxiv AM-Sentry + MAPLE-Guard + al-ice + Microsoft memory safety + securetom 实拉，与 r362B 记忆投毒为 2026 官方化增量）：**OWASP 2026 把记忆毒化列入 Agentic Top10 ASI06——对手在一会话写入不可信内容、未来会话被它驱动支付/改设置/数据外传，检测器漏 66% 毒化条目**；**AM-Sentry=memory-saving policy 三级约束+retrieval screen 逐条审查检索条目过滤隐藏指令；MAPLE-Guard=write/retrieval/promotion/cross-agent reuse 四门设闸（毒化条目入共享记忆前拦下，ASR 3x→大降）；信任层级硬规则：system_seed > document > tool_output > conversation——身份与权限永不来自记忆，永远来自认证上下文**；**记忆文件当代码审：AGENTS.md/MEMORY.md/SOUL.md 需与依赖 bump 同级审批（agent 可无人值守写=带 markdown 后缀的提权路径）；temporal decay=旧条目检索降权；pre-ingestion scanning=白字/零字体/CSS 隐藏指令/注入标记**。判据=外部数据写记忆过验证门，检索集整体评估不只单条。提升层：工作流。

**7. MCP 安全官方规范：OAuth2.1 强制+token delegation+41% 无认证**（来源：modelcontextprotocol.io security_best_practices + OAuth2.1 guide + airbyte + gingerlabs + CSA MCP-by-design RCE 实拉，与 r339D MCP 基础为官方规范增量）：**远程 MCP 认证是强制不是可选（OAuth 2.1/OIDC，每请求验证 iss/aud/exp/JWKS 签名+时钟偏差；PKCE S256 无例外）；token delegation=把用户上下文与权限传给 MCP server 同时限权+保留 server 独立 NHI（RFC 8693）；五不破：不 session 认证（spec 禁）/不无验证 passthrough/不接外来 aud token/必 HTTPS/凭据 30-90 天轮换**；**工具层 default deny+按 principal/tenant/action scope+参数校验视同 HTTP body 校验+速率限制+per-tool kill switch；容器执行由 host 注入凭据且容器不可读凭据；实测 41% MCP server 无认证**；**CSA：模型上下文可被外部内容影响的环境（浏览网页/读不可信 repo/处理用户文档）应禁用或沙箱 MCP STDIO——零点击注入只需模型渲染攻击者内容**。判据=每个远程 MCP 走 OAuth 委托+aud 校验，STDIO 在不可信输入环境禁用。提升层：工具。

**8. Agent 审计追踪标准：IETF AAT 哈希链+EU AI Act Art.19**（来源：IETF draft agent-audit-trail + lawr + ai-crescent + openlegion + EU AI Act 实拉，与 r339B 可验证审计为 2026 标准增量）：**IETF Agent Audit Trail（AAT）草案=JSON 记录必填 agent identity/action classification/outcome/trust level，SHA-256 哈希链（RFC 8785 canonicalization）tamper-evident+可选 ECDSA 防否认**；**EU AI Act Art.19（2026-08-02 生效）=高风险系统自动日志最少 6 个月、详细到可重建系统做了什么为什么——含决策/提示词/工具调用/委派权限/结果的全法证轨迹；记录内容：毫秒时间戳+agent id+版本+tool name+执行状态（含拒绝）+参数摘要+所用凭据+结果摘要**；**哈希链验证=从 record 1 前向重算，任何断裂=篡改及位置；agent 审计日志≠应用日志，按 agent_id/session_id/时间范围查询进 SIEM 作独立事件类**。判据=审计记录设计成可重建因果+防篡改，不是能跑就行。提升层：工具。

**9. NHI 治理：agent 身份按人账号全生命周期管**（来源：CSA NHI whitepaper + iamroadmap + xyzbytes + IDMWORKS NIST 实拉）：**2026 定义性新 NHI 类别=AI agent（动态目标驱动、运行时选工具、单会话链几十个 API 调用 vs 传统服务账号静态可预测）；非人身份超人类 80:1，仅 ~21% 组织有实时 agent 注册表、~28% 能追溯 agent 动作到人 sponsor**；**agent 身份同人账号生命周期：创建需文档化理由+owner、周期访问评审、退役自动吊销全部关联凭据（只 20% 组织有正式 API key 吊销流程）；每 agent 每功能 scoped 凭据绝不共享，无任何 agent 可无人类审批执行的硬停动作**；**Shift IAM left=在 DevOps 生命周期内嵌动态/短命身份控制+事件驱动认证+从人类授权到 agent 每次动作的可验证密码学审计链（NIST 2026-02-17 AI Agent Standards Initiative 启动）**。判据=每个 agent 有 owner+生命周期+可追溯到 sponsor 的凭据。提升层：工作流。

**10. Secret Vault Proxy：凭据永不进上下文**（来源：dev.to token vaults + openlegion credential + SUDP arxiv + Infisical Agent Vault + anomity 实拉）：**正确架构=vault 置于 agent 与凭据之间，agent 只见 vault 引用（$CRED{stripe_key} opaque handle）不见明文——执行层取凭据用完即弃，值永不进上下文**；**存储=AES-256-GCM 认证加密+envelope encryption（KMS/HSM 管 KEK 包每连接 DEK），base64 不是加密，数据库 dump 只见密文**；**SUDP 协议=三角色：requester 提 canonical 操作→user 用 fresh authenticator grant 授权→custodian 一次性兑现 bounded use——可复用权威不跨 requester 边界（agent 提操作、不取 secret）**；**vault proxy 形态（Infisical Agent Vault 2026-04-22 MIT）=TLS 拦截注入正向代理：agent 出站请求过代理、凭据在代理层附加、agent 从不看/存/记底层 secret；短命凭据 15 分钟；vault 管全生命周期=加密存储/轮换/吊销/注入/scope/审计日志**。判据=agent 任何时刻无法输出真实凭据明文（模型不会背出它没见过的东西）。提升层：工具。
