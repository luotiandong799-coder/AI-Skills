## 独点（10）

**1. RAGAS 四指标评估矩阵**（来源：51CTO《阿里二面 RAGAS》2026-04-09 + ACL EACL-Demo《RAGAs》+ arXiv 2601.22025《When Better Prompts Hurt》2026 实拉）：**四指标=检索端 Context Precision（检索结果里多少真正有用）+Context Recall（回答所需关键信息有没有被检索到）+生成端 Faithfulness（答案是否忠实于检索上下文、无幻觉）+Answer Relevancy（答案是否紧扣用户问题不跑题）——形成"精确性×完整性"×"检索×生成"评估矩阵；失败可发生在检索/生成/整合任一处，有效评估必须隔离来源才能定向改进；Faithfulness 计算=把答案分解成原子声明（短自含陈述）→每条声明逐条核对能否从检索文档追溯（QASkills 拆解实录）；RAGAS 是 reference-free 框架（无需人工参考答案）；配套指标 FactualCorrectness（对照参考答案）+ResponseGroundedness（是否 grounded 于给定上下文，识别幻觉）**。提升层：工作流/可复用 Skill。

**2. 混合检索 RRF：k=60 标准融合**（来源：AIPromptsHub《Hybrid Search 2026》2026-06-21 + Redis《Reciprocal Rank Fusion》2026-08-09 + InfoQ《Vector Search Alone Isn't Enough》2026-06-02 + Markaicode《Ollama Hybrid》2026-07-02 实拉）：**生产 RAG 标准混合算法=RRF：每个检索系统返回排序列表，融合分=Σ 1/(k+rank_i)，k=60 是标准平滑常数（原始论文值，Elasticsearch 默认）；RRF 完全忽略原始分数只用排名位置——消除 BM25 分数与余弦相似度量纲不兼容问题，无需归一化；实现 10 行 Python、检索系统无关（BM25/稠密/稀疏皆可）；召回提升 25-40% vs 纯向量；生产两阶段=BM25+dense 并行检索 top-k（k=50-200）→RRF 融合→cross-encoder rerank→LLM；重排序成本=总成本 3-7%，但检索 20 文档只传 top3 省下 LLM token 远超重排成本；ColBERT-v2/学习式稀疏（SPLADE 系）为可选第四路**。提升层：工作流/可复用 Skill。

**3. 分块策略 2026：contextual retrieval+late chunking 组合**（来源：AI Workflow Lab《Chunking 2026》2026-05-26 + Atlan《Chunking Guide》2026-05-20 + AIPromptsHub《Chunking Benchmarked》2026-06-21 + The Neural Base《Chunking Cheat Sheet》2026-04-12 实拉）：**2026 最佳组合=contextual retrieval（embedding 前给每 chunk 前置一段短 LLM 生成的上下文）+late chunking（长上下文模型整文档 embedding 后池化 token 向量成 chunk）——检索失败率 -35~67% vs 朴素定长（Anthropic 基准+Jina 论文）；语义分块（相邻句 embedding 相似度骤降=主题切换边界）单策略最高：技术文档 recall@10 ≈71%/支持问答 69%/法律合同 62%，代价=索引时全语料 embedding 一遍；chunk 大小甜点区 256-512 tokens（~800-1500 字符），<200 tokens 孤立碎片、>1000 tokens LLM 浪费预算在无关文本；父子分块=索引小 chunk 精准检索+生成时用大 parent 上下文；分块按查询类型=事实型 256-512/分析型 1024+；分块决策四问=文档分页否/查询类型/交叉引用密度/领域词汇**。提升层：工作流/可复用 Skill。

**4. Agentic RAG 五模式+查询改写代价**（来源：Future AGI《Agentic RAG 2026》2026-05-14 + arXiv 2601.05264《Engineering the RAG Stack》2026 + Alok《Self-Correcting Retrieval Loops》2026-06-17 + Future AGI《RAG Architecture》2026-08-26 实拉）：**生产 agentic RAG 反复出现的五模式=查询改写与分解（改写检索友好形式、可选拆子查询）/多跳检索（retrieve-reason-retrieve 直到证据足够）/工具路由（按查询在向量/BM25/网页/SQL/reranker 间选）/草稿自检（评估检索文档相关性、自动重写搜索）/工具使用检索 agent；多跳分解=复杂查询拆独立子问题并行检索重组（"跨 A/B/C 维度比较 X 和 Y"变 6 次检索调用，延迟可并行、成本随 fan-out 线性涨）；查询改写=HyDE（生成假设答案再 embedding）/step-back（改写更泛化查询检索后再特化）/分解——硬基准 recall +5~15pt 但加一次 LLM 调用延迟+新失败模式；GraphRAG=LLM 生成知识图谱+层级社区摘要，超越朴素 RAG 的全面性与多样性（Neo4j 承载）；动态遍历=置信门控防过度扩展（早期 graph RAG 遍历膨胀到数千弱相关节点）**。提升层：工作流。

**5. 生产监控五类失败+逐题失败分析**（来源：Redis《RAG Debugging Guide》2026-08-01 + The Neural Base《Per-question Failure Analysis》2026-04-15 + dev.to《Trace Green Answer Wrong》2026-09-17 + Braintrust《RAG Observability》2026-06-21 实拉）：**失败不是随机，聚成五类=检索（retrieval）/排序（ranking）/接地（grounding）/新鲜度（freshness）/延迟（latency）——答案错先定位阶段再动 prompt；逐题失败分析三问：①检索候选里有没有含答案的文档？无→检索失败 ②有→它在不在 top-4？不在→排序失败 ③在→LLM 答案是否事实正确且 grounded？否→生成失败——必须能指出具体失败阶段；"trace 是绿的但答案错"=你在监控模型不是观察系统——要能回答"它看到了什么证据、为什么这证据变成这答案"；RAG 可观测性=检索/重排/上下文组装/生成全阶段 trace 级可见，最强工具实时给生产流量打分（groundedness/faithfulness/答案相关）；检索与生成失败分开记录评分——先评检索质量，只在检索得好的查询上评推理，按失败类型路由给对应工程团队**。提升层：工作流/可复用 Skill。

**6. 查询改写代价与置信门控路由**（来源：arXiv 2609.05637《Better Together》2026 + arXiv 2507.00355《Question Decomposition》2026 + arXiv 2605.27220《Coverage Illusion》2026-08 + arXiv 2604.01733《Corrective RAG》2026 实拉）：**改写很贵：网页 QA 上 +9~18× 运行时；分解 16.7s/query 额外开销——但子查询可缓存复用（qd+rr 缓存后延迟与基线相同）；每个查询都跑全部策略是浪费——让基线信号决定何时需要帮助：S1 的 top-1 reranker 分数干净分离命中与未命中→置信门控路由；coverage illusion=预检索路由失败→后检索级联：O(1) 检查检索器输出（无需训练/服务设施）决定是否升级检索，真实用户查询 +0.140 CO 分/-31.8% 延迟，仅 27.8% 查询用 LLM 增强（vs Always-HyDE 全量）；多查询扩展=GPT-4.1-mini 温度 0 生成 3 个语义不同变体→各自检索→RRF k=60 合并 4 列表（原始+3 变体）；反模式：领域上下文过度特化查询（引入原问题没有的行话）与多余变体稀释主信号（SemEval 实测均 0.350）**。提升层：工作流。

**7. RAG token 预算表+查询感知压缩**（来源：72Technologies《Token Budgets for RAG》2026-06-27 + varunsingla《AI Tokenomics》2026-08-05 + AWS《Query-aware Compression》2026-08-21 + Zenodo《Token Optimization Framework》2026 + DigitalOcean《RAG Cost Breakdown》2026-08-14 实拉）：**预算表=system prompt 400-800（硬顶/月度复审）/工具函数定义 0-1500（只放路由相关）/检索块 2000-4000（主杠杆）/对话历史 1000-2000（超出摘要）/用户查询 200-500（截断/摘要长粘贴）；查询感知压缩=小模型逐句给检索 chunk 评查询相关性→只传高相关句（~20% 检索文本）→输入 token 减 50-80% 精度保持（AWS Bedrock 实装：压缩是唯一新增步骤，小模型 token 单价低，在贵答案调用前瘦身）；优化管线实测=输入 token -57.1%/总 token -54.4%/每请求成本 -44.6%/延迟 -48.6%，同时检索精度 0.643→0.870、groundedness 0.854→0.882、成功率 54%→（Zenodo）；embedding 成本=query embedding 仅 $0.04/1K 查询 vs 重排 $21.50 vs 答案生成 $16.05（DigitalOcean 1K/日）——答案生成与重排是成本大头；近重复 chunk 去重防上下文冗余**。提升层：工作流/可复用 Skill。

**8. Embedding 选型 2026**（来源：AI Workflow Lab《Best Embedding 2026》2026-06-28 + Future AGI《Embedding Models》2026-05-14 + arXiv 2604.17778《TeleEmbedBench》2026 + datarekha《Embeddings Shootout》2026-05-01 实拉）：**OpenAI text-embedding-3-small（$0.02/1M）是最便宜主流选择，Matryoshka 降维到 512d 精度损失极小，6.5x 便宜于 3-large（$0.13）质量差异边际；Jina v3=89 语言多语基准超更大模型（1024d/570M）；BGE-M3=100+ 语言开源多语检索第一（跨语言 OpenReview 实测）；LLM-based embedder（Qwen3/EmbeddingGemma）全面超 sentence-transformer 族、对噪声/不完整查询更鲁棒；领域微调>通用提示——电信特定指令提示在自然语言规格上反而降检索、在结构化稀疏代码上提升（TeleEmbedBench 实证）→先测后调；欧洲公司实测 text-embedding-3-small 超 E5-base；选型判据=真实查询+文档抽样测 nDCG/Hit Rate 2-3 个候选，算真实成本（API 价+延迟+维度存储）；Voyage 3-large 1024d 84.2% top-3 精度最佳（多语子集优势扩大）**。提升层：工具/工作流。

**9. RAG 访问控制：ACL 元数据随 chunk 存+两层强制**（来源：OWASP《RAG Security Cheat Sheet》2026-05-06 + arXiv 2605.05287《Securing the Agent》2026 + arXiv 2509.14608《Participant-Aware Access Control》2026 + GenAI-Security-Project《LLM09 Vector Weaknesses》2026-09-06 实拉，与 r368D 判重：MCP/Agent 安全已落，本点补 RAG 检索侧特化增量）：**访问控制元数据（分类/所有者/允许角色/租户）随每个向量 chunk 存储而非只随源文档；访问控制在检索时执行而非仅摄取时（权限可能已变更）；两层强制=搜索前资源级 ABAC 授权+检索后 chunk 级过滤（相似度搜索×授权谓词组合）；支持 predicate pushdown 的后端=向量搜索内原生应用租户过滤保持完美 recall；无 pushdown 时后置过滤保安全但大语料 recall 退化（跨租户文档污染 top-k 集）；participant-aware：Alice 让 AI 起草回复 Bob 时，检索内容必须 Alice+Bob 都可访问，否则显式取得同意或内容必须（邮箱场景）；LLM09=租户 scope 在索引查询内强制不是后置过滤、客户端提供的 scope 是建议不是控制、服务端校验、embedding/相似度端点作一等 API 加每租户限流、高敏负载物理隔离索引、chunk 级 ACL（公开文档可含机密段落）；Azure=文档级访问控制 Entra 用户组+敏感度标签+Purview 策略查询时校验**。提升层：可复用 Skill。

**10. 评估驱动迭代：golden set+失败回填闭环**（来源：arXiv 2601.22025《Golden Set》2026 + ergodic.in《Evaluating RAG in Production》2026-06-15 + The Neural Base《Iteration Methodology》2026-04-14 + Future AGI《Synthetic Datasets》2026-05-14 实拉）：**golden set=50-200 用例优先覆盖失败模式而非体积，含每个主要用例的代表例+触发已知失败模式的对抗输入，随 prompt 模板一起版本控制，小到每次变更都能跑；线上→线下闭环=自动化评分（快但不完美）→人工审阅评分低/用户标记的样本→修正回填 golden set——今天的难生产案例=明天的回归测试，golden set 不静态、朝真实问题生长；检索 eval pack=至少 100 个标注场景（来源 span 标注），切片=25 已知答案/25 改写/20 干扰/10 新鲜度版本/10 多源/10 不可答或禁用源；问题类型分布=40% 简单事实/25% 多跳/15% 比较/10% 时间/10% 对抗（不可答/越界）；三阶段循环=Measure（真实查询跑全管线记录中间输出 top-k 前后+最终答案质量）→Diagnose（失败归类：文档在检索输出但排太低=重排问题）→Fix（对症改）；合成数据质量门=目标 30% 中难+20% 难题、人类抽查 5-10% 拒绝 >5% 失败、合格率 >95%；MLflow 生成约束=按关键点+源 passage 生成仅可由该 passage 回答的问题（防外部世界知识）、答案映射回关键点（可算 Completeness）、后置检查过滤**。提升层：工作流/可复用 Skill。
