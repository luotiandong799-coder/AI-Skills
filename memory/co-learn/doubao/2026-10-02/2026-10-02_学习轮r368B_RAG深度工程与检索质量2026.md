## 独点（10）

**1. Parent-Child 分块：小块检索+大块上下文，两个粒度分开优化**（来源：futureagi-chunking + parent-child-genai + stochastic-sandbox + neuralbase-chunking 实拉）：**child 块（128-256 token）嵌入索引用于检索——语义边界清晰指向具体事实；parent 块（1024-2048 token）单独存，child 命中时返回 parent 给 LLM**——"小块的召回+大块的上下文"；LangChain=ParentDocumentRetriever、LlamaIndex=HierarchicalNodeParser+AutoMergingRetriever；**语义分块（相邻句 cosine 距离超阈值切）对转录/客服日志好，但 NAACL 2025（arXiv:2410.13070）实证=固定 200 词块在检索与生成上打平或更优**；recursive 尊重结构边界。判据：**检索精度与生成上下文是两个目标——parent-child 同时优化，别用单粒度妥协**。提升层：工具/工作流。

**2. 查询转换四原子操作：HyDE/step-back/分解/消歧**（来源：query-survey-2412.17558 + google-codelabs + microsoft-decomposition + semeval-rewriting 实拉）：四原子操作=**Expansion（加词/上下文/生成内容）/Decomposition（拆复杂查询为原子子查询，各独立检索聚合，再跑原查询带累积上下文）/Disambiguation（消歧多解释）/Abstraction（step-back 提升到高层概念）**；**HyDE=问-答向量相似度常低于答-答——让 LLM 先"幻觉"一个完美答案、嵌入它再检索**（对精确数值/实体查询域反而有害）；**dual-view rewriting=同时把查询分解成稀疏检索关键词+扩写成稠密检索语义短语，动态调节双通道权重**；multi-turn=LLM 重写最后 turn 为自包含问题（消代词/隐含引用，temp 0.1）。判据：**查询转换按查询特征选操作——数值精确域禁 HyDE、多跳必分解、模糊先消歧**。提升层：工作流。

**3. Agentic RAG 模式：Self-RAG 反思 token / CRAG 评估器+web 回退 / 成本表**（来源：self-rag-crag + aiworkflowlab + marsdevs-cost + searchcans 实拉）：**Self-RAG=生成中内嵌反思 token：Retrieve（要不要检索还是参数知识直接答）/IsRel（检索块相关吗）/IsSup（生成被检索块支持吗）**；**CRAG=生成器不动、加外部轻量 T5 评估器+web 搜索修正环——检索质量差时路由到实时 web 搜索再生成（可挂任何 RAG 之上）**；Reflective RAG=反思标注机制显式指导策略；**成本现实表：CRAG 2-3x 延迟/3-5x token、Adaptive RAG 1.2-2x/1.5-2x（分类器前置）、ReAct over docs 3-5x/4-8x、multi-hop 3-6x/5-10x**；**反思=有界重试循环，更优设计=细粒度错误检测分类+只重跑牵连的组件而非整个 query+置信度停止准则（边际增益低于阈值即停）**。判据：**agentic RAG 是成本换准确——模式按知识库质量与查询流难度选，反思要有界**。提升层：可复用 Skill。

**4. RAG 评测指标：检索层+生成层分开测**（来源：futureagi-rag-eval + openlayer + respan-rag-eval + mlflow 实拉）：检索层=**precision@k（噪声比信号）/recall@k（必要块有没有召回——高精度召回一块而漏三块照样答错）/MRR（最相关块位置）/nDCG（分级相关+位置加权）**；生成层=**faithfulness（每个 claim 都可归因到检索上下文，RAGAS 参考自由 LLM judge）/answer relevance/groundedness/citation accuracy（引用确实含所引 claim）**；**citation accuracy 抓最差失败类=自信引用错段落——用户信带引用答案甚于不带，错引比不引伤害更大**；RAGVue=单遍结构化分析把答案分解最小 claim 并分类 supported/partially hallucinated/fully hallucinated。判据：**检索与生成是两个失败面，分开测分开修——上下文 precision 好而 citation accuracy 差=生成锚定问题**。提升层：可复用 Skill。

**5. RAG 生产失败分类与证据缺口**（来源：the-neural-base-failure + ginno-failure + evidence-gaps-2609.37469 + predictionguard 实拉）：三大失败=**retrieval silence（检索空/无关→LLM 无好上下文就幻觉）/retrieval noise（检索到但淹没在无关块里→上下文窗口被污染忽略信号）/generation failure（块完美但 LLM 编造或矛盾=纯生成问题）**；**citation hallucination 企业环境约 33%；temporal staleness=检索到 2022 旧版而非 2026 新版——时间穿越幻觉，多家金融机构称其是最大幻觉源（旧文档还在向量库、语义相似被一起检索，LLM 错误调和矛盾）**；**证据缺口=检索到对实体没对事实——即使明确指令 abstain，12 个生成器仍对 40.0-99.3% 证据不足问题作答**；weak grounding=RLHF 把模型调成"乐于助人优先于严格事实"，系统提示没锚定来源就礼貌幻觉。判据：**RAG 幻觉是工程失败不是模型谜团——检索层修召回，生成层修锚定，时间戳要进元数据**。提升层：工作流。

**6. GraphRAG：Leiden 社区检测+k-core 替代+分层社区摘要**（来源：graphrag-leiden-core-2603.05207 + aws-graphrag-lightrag + ragu + omd-graphrag 实拉）：**GraphRAG 核心赌注=索引时一次性花贵推理、查询时保持便宜——ingestion 用 LLM 抽实体-关系图，Leiden 社区检测找内聚簇，LLM 自底向上生成多层社区摘要，全局查询用社区级摘要答**；**k-core 替代 Leiden=稀疏图上（平均度常数）模块度优化有指数多近优划分、Leiden 社区不可复现——k-core 分解给确定性密度感知层级**；RAGU=提取与整合分离（两阶段 typed extraction→DBSCAN 去重→LLM 摘要→Leiden）；OMD=本体引导提取+多维聚类（边界节点补全+属性感知模块度）提检索准确率 3.17-3.43%；LightRAG 轻量可同栈部署。判据：**GraphRAG 适合全局/多跳问题，社区检测要可复现——知识库稀疏就上 k-core**。提升层：工具/工作流。

**7. 上下文检索（Contextual Retrieval）：每块前置文档感知前缀**（来源：anthropic-contextual + datarekha-contextual + habr + voyage-context-4 实拉）：**每 chunk 嵌入/BM25 索引前，用廉价 LLM 生成 50-100 token 文档感知前缀（"This chunk is from the 2026 Benefits Policy, Section 3 (Eligibility)..."）**——解决"它涨了 40%"不知"它"是谁的孤立块问题；**Anthropic 数据：仅 embedding 降 top-20 检索失败 35%，+BM25 49%，+reranker 67%**；**prompt caching 使索引成本 ~$1.02/百万文档 token——便宜到没理由不用**；2026 演进=**上下文化内建进模型：voyage-context-4（MoE 骨干+内建 auto-chunking，32K+ 透明处理）、Jina late chunking、Illuin ColPali（文档当图像不做分块）**——纯配方时代结束。判据：**"检索-检索的失败多数是块丢了文档身份"——上下文检索是最高杠杆的索引侧修复**。提升层：可复用 Skill。

**8. Late chunking：先整篇编码再按块池化**（来源：jina-late-chunking + wickedsmartdata + futureagi-chunking + redis 实拉）：**反向顺序=整篇文档一次过 long-context 嵌入模型拿全 token embedding 矩阵→按常规块边界识别 token→块内 mean-pooling 得块向量**——"块在全文语境下意味着什么"而非"孤立意味着什么"；关键=所有 token 相互注意（标准分块各块无跨界注意力）；**Redis 2026.4 基准=长文档检索平均 +3% 相对提升（四个 BeIR 数据集）**；**最常失败方式=offset_mapping 错位（慢 tokenizer 不支持字符偏移/清洗函数改写文本/Unicode 组合字符坐标不一致）——解决不是捕获异常跳过，而是入库前验证每个块至少映射到一个非特殊 token+随机抽样把 token 区间解码与原块对照**。判据：**长文档强指代/跨节定义场景用 late chunking；offset 校验是入库质量门**。提升层：工具/工作流。

**9. RAG 生产监控：五类漂移+检索质量月衰减 3.8%+MRR 告警**（来源：ephizen-drift-five + rag-about-it + digitalocean-mrr + futureagi-rag-eval 实拉）：**五类漂移=数据漂移（语料变了：文档增删未触发 reindex，旧块残留——固定参考查询每周对比命中率与相似度）/嵌入漂移（embedding 模型升级/分块改动改变检索分布，离线 golden 分平但生产 trace 讲故事）/查询分布漂移（新问题类型无覆盖——发布/监管/市场事件）/提示漂移/模型漂移**；**DataStax 1200 万企业查询研究=未维护系统检索质量平均月降 3.8%——不是模型变了是世界变了（文档过期/知识库更新/竞争者出现）**；**MRR 告警=基线 MRR vs 当前 MRR 对比，降幅超阈值告警提示查 embedding 模型/数据分布/索引**；golden set 每日/每周连续评测+按 slice（用例/应用版本）分组监控+确认失败回流测试集。判据：**RAG 会静默衰减——月降 3.8% 不算故障只是默认状态，监控+回流是常态运维**。提升层：工作流。

**10. RAG golden set 与评估实践：两失败面分开+合成题是 backstop**（来源：respan-rag-eval + ailearningguides + inductivee + confident-ai 实拉）：**六指标值得测=context recall/context precision/context relevance/faithfulness/answer relevance/citation accuracy**；**从真实生产日志建 100-300 题 golden set——合成题是 backstop 永远不是地基**，每季度刷新；**生产目标=faithfulness 0.9+/answer relevancy 0.85+（RAGAS）**；ground truth=200-2000 标注查询按用例成熟度；连续评测=每部署跑代表性 golden set+每日/每周跑采样+超阈告警+门禁发布；**confident-ai 生产回流=按用例与应用版本分组监控、评审受影响响应、确认失败加进未来测试集——生产与测试之间的闭环**。判据：**RAG 评估是 MLOps 纪律不是可选项——检索质量与生成质量分开盯，失败回流建套**。提升层：可复用 Skill。
