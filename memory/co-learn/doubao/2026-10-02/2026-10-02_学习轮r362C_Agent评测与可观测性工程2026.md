## 独点（10）

**1. 统一评测框架：离线快照隔离框架效应与环境效应**（来源：arXiv 2605.27898 实拉）：统一配置系统集成多样基准为标准 instruction–tool–environment 格式；固定 ReAct 式架构在可控沙箱执行；可选离线设置=易变 live 环境换成策展快照——**框架效应（架构选择带来的差异）与环境效应（环境变化带来的差异）可以分开分析**；评测方法论在每个基准下统一。判据：**统一评测=标准化指令-工具-环境格式+固定架构+离线快照（框架/环境效应分离分析）**。提升层：工具/工作流。

**2. 三层评测栈：确定性 grader 先于 LLM judge**（来源：AWS AgentCore+Strands 2026-07-23 实拉）：评测分三层且确定性检查优先——Layer 1 工具选择（ToolSelectionGrader 检查调用了哪些工具、TrajectoryOrderGrader 验证调用序列，确定性测量）；Layer 2 推理（>85% 阈值，决策过程逻辑性）；Layer 3 结果。判据：**评测分层=工具选择确定性 grader 先于推理阈值先于结果——先可机检后主观**。提升层：工具/工作流。

**3. 三证据通道评测：轨迹感知评分**（来源：Claw-Eval arXiv 2604.06132 实拉）：300 人工验证任务 9 类；每个 agent 动作通过三独立证据通道记录=执行轨迹/审计日志/环境快照；2159 细粒度 rubric 项轨迹感知评分；评分协议评估 Completion 与过程质量。判据：**可信评测=三证据通道（轨迹/审计/快照）交叉验证动作，不单信最终响应**。提升层：工具/可复用 Skill。

**4. 双评估：Task Score 与 Process Score 并行**（来源：ClawTrack arXiv 2607.28037 实拉）：同时评估 agent 达成什么（Task Score）与如何达成（Process Score）——**过程质量是独立多维构念，与任务结果并行测量而非由其衍生**；320 任务双视角。判据：**评测双轴=做了什么与怎么做的分开记——"做对了但过程错"是可单独归因的失败**。提升层：工具/可复用 Skill。

**5. LLM-as-judge 四层不确定性：单 judge 无法同时覆盖**（来源：Coin Flip Judge arXiv 2606.13685 实拉）：评测不确定性分四层——①随机不稳定（同一 judge 重复试验改变判定）②系统偏差（首位位置偏好，即使重复平均仍倾斜多数结果）③协议依赖（温度与 prompt 模板改变有效评估器）④judge 身份依赖（不同 judge 模型在非平凡分数项分歧）；**分层视角解释为何单 judge 评测会误导**。判据：**judge 结论先归因四层不确定性（随机/偏差/协议/身份），不直接当测量**。提升层：模型/工作流。

**6. Rationalization bias 缓解：Criterion-guided SCoT + Proof-Before-Preference**（来源：Faithful or Fabricated arXiv 2605.23970 实拉）：冗长度与置信度线索可靠地改变结果与理由，即使摘要相同——LLM-as-judge 管线实用漏洞；两种防御=**Criterion-guided SCoT**（按显式维度如准确性/完整性/简洁性/流畅性先推理再决定）+**Proof-Before-Preference**（锁定逐维度 notes 后再给偏好）。判据：**judge 防合理化=按显式维度先推理（C-SCoT）+先记录逐维证据再下偏好（PBP）**。提升层：模型/工作流。

**7. Judge 升级歧义：评估器替换是测量效度问题**（来源：When the Judge Changes arXiv 2607.08535 实拉）：judge 升级可移动得分即使候选响应保持固定——候选不动、评估器换了、测量变了；**评估器替换歧义应按测量效度问题审计**；judge 升级=隐性评测变更，需记录 judge 版本。判据：**评测可信=judge 版本纳入评测元数据——升级 judge 视同换测量工具，旧分不可直接对比**。提升层：模型/工作流。

**8. Prompt 版本化 + CI 评测门：三级测试 + 模型漂移监控**（来源：futureagi 2026-05-20 + langfuse 2026-09-29 + latitude 2026-05-18 实拉）：prompt 像代码=存 Git 仓库、版本化、评审、回滚；eval-on-PR=每个改 prompts/ 下文件的 PR 触发回归套件；三级测试=smoke（每 commit 15-20 例快捕明显问题）/全回归（pre-merge 100-200 例保合并质量）/深度评测（pre-release 全套 5+ runs 高置信终检）；**模型漂移=provider 静默更新权重保持 API 版本字符串不变——本地配置完全静态但生成文本变化**（最常被忽视）。判据：**提示工程=Git 版本化+CI 评测门（smoke/full/deep 三级）+模型漂移监控（响应质量无代码变更下降先查上游）**。提升层：工作流/可复用 Skill。

**9. Shadow + Canary 双层评测：测不同问题，跳过任一=缺一块**（来源：futureagi 2026-05-21 + dailyaiworld 2026-09-16 实拉）：shadow=镜像 live 请求到候选模型零用户影响——生产服务用户、候选响应捕获离线评分——**证明候选在真实分布上不行为异常**；canary=候选输出 live 服务用户百分比切片（1/10/50/100%）——对生产队列同 rubric 评分+自动回滚武装——**证明候选对在环用户至少一样好**；它们测不同评测问题，跳过任一=缺一块。判据：**发布评测=shadow（离线验证真实分布无异常）+canary（在线验证用户体验不劣化），两者互补不可替代**。提升层：工具/工作流。

**10. Golden dataset 建设纪律：分层覆盖 + 工具调用 ground truth + 多样性优于体量**（来源：rockB 2026-06-19 + growthengineer 2026-05-03 实拉）：生产质量 golden=200-500 任务覆盖完整行为面；分层=常规操作 50%/边界案例 30%/安全敏感输入 20%；记录工具调用 ground truth 用于确定性回归；**50-200 手工标注轨迹先于写任何指标——最重要且最常跳过的一步**；多样性优于体量=100 例覆盖 10 种失败模式胜过 1000 例单一模式（Anthropic/Microsoft 建议非平凡域最低 100-150 例）；版本控制+具名 owner+季度覆盖审计+漂移检测。判据：**golden 建设=先手工标注轨迹（50-200 例）+分层覆盖（50/30/20）+工具调用 ground truth+季度审计——多样性优于体量**。提升层：工作流/可复用 Skill。
