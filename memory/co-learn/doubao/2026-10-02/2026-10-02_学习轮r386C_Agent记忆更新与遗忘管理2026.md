## 落地 7 独点（每点标注提升层）

### 1. 记忆决策四阶段 + 写入门控三档 + 置信度锚定（工作流）
来源：devto-memory-decision-loop / joelclaw-memory-system / jatinbansal-memory-write-policies / arxiv-2605.30711-sage
- **四阶段管线，不是一步 embed+store**：Extraction（原始会话→候选事实）→ Retrieval（找可能相关的已有记忆）→ Decision（对每个候选定 ADD/UPDATE/DELETE/NOOP）→ Consolidation（写回解析后的状态，不只是 append）。
- **写入门控三档**：allow=持久事实信号（默认检索）/ hold=歧义或上下文相关（存储但排除默认检索，显式请求才给）/ discard=噪声（彻底不存）；观察者 LLM 判档 + 规则覆写。
- **置信度锚定刻度**：0.2=单个歧义回合的猜测、0.5=单个清晰陈述的推断、0.9=用户明确陈述、1.0=系统记录导入——不锚定，置信度聚集在 0.7±0.1 失去过滤价值；confidence<0.5 拒绝、0.5-0.7 标 pending_review 不默认浮出。
- **SAGE 新奇门**：vMF 密度估计打分候选事实+自适应阈值随记忆库几何调整——明确新颖=ADD、明确冗余=NOOP、只有不确定才送 LLM merge（省写时推理）。
- 判据：写入不是"存下来"而是"四步决策"；置信度必须带锚定刻度，否则下游过滤失效。

### 2. 写入时冲突裁决协议：检测在 write 不在 retrieval（工作流）
来源：aimemoryworks-conflicting-memories / zylos-memory-consolidation / sabaoon-temporal-supersession / arxiv-2606.26511-memstrata / xbstack-reflection-node
- **冲突检测必须在写入时**：retrieval 时才发现=已经把矛盾交给了决策层（晚了）。
- **裁决协议**：来源等级层次化在写入时裁决（rank the two sources）→ 同级用 recency 打破平局 → 记录裁决结果（不留到检索时决定）；四规则=recency wins（真变化）/ confidence wins（来源可信度+佐证数）/ merge（双保留带时间戳+变更摘要）/ human escalation（高利害矛盾标记人工）。
- **temporal supersession（时间性超越）**：事实带 validity window，检测到矛盾自动失效旧记录；Reflection Node 判断"这是故意的偏好更新吗"→ 是则标记旧向量 invalid 或物理更新。
- **MemStrata 结构检测**：入库事实与既有事实共享 (subject, relation) 键但 object 不同→新者超越旧者——**独立于 embedding 相似度**（过期检测必须是结构性的，不是相似性）。
- 判据：写路径裁决、读路径只消费；过期检测用结构键不用语义相似度。

### 3. 记忆毒化写路径防御：OWASP ASI06 五层（工具）
来源：vectorize-owasp-asi06 / arxiv-2605.15338-sleeper / datarekha-memory-poisoning / arxiv-2608.00426-maple-guard / chatforest-am-sentry / arxiv-2606.12703-smsr
- **OWASP ASI06（Memory and Context Poisoning）五层控制**：① 输入信任评分写路径筛查（prompt injection 标记/凭证与 PII 泄漏/受保护键修改/尺寸异常/编码载荷走私）② 记忆净化+provenance 追踪（每条观察打来源元数据）③ 用户输入不得直接写长期记忆（提取管线+净化中介）④ 检索时过滤与隔离 ⑤ 审计与监控。
- **写时验证非读时验证**：攻击者目标是让"干净外观"的记录进记忆——检索时过滤对它无效（已像自身历史）；strip 指令性内容 + write-ahead 第二 guardian 模型检查 + 拒绝"像指令不像事实"的内容。
- **MAPLE-Guard 四动作**：reject（forbidden）/ quarantine（风险≥θ）/ rewrite（指令性内容改造）/ private（其余）。
- **SMSR 认证防御**：写时 HMAC-SHA256 provenance 标签（对无签名注入的密码学硬边界）+ 查询时随机记忆消融+多数聚合（限制已验证攻击者影响）。
- 判据：写入路径必须是被治理的边界；"存什么"决定"以后信什么"——毒化一旦入库，读时过滤拦不住。

### 4. 记忆 GC：语义去重 + 半衰期域节奏（工作流）
来源：tianpan-memory-gc / hindsight-consolidation / arxiv-2605.08538-human-inspired / aws-agentcore-lifecycle / zylos-tier
- **语义去重 mark-and-sweep**：近似表达（"偏好 Python"/"主要语言是 Python"/"写代码用 Python"）不是相同字符串——hash 去重漏掉，却占 3 个检索槽给 1 条信息；mark 阶段主题簇内两两语义相似度，sweep 阶段超阈值合并保留最完整版本；**后台任务跑，不内联写入**。
- **四杠杆**：importance（什么值得成为记忆）/ merge（同实体事实统一为规范记录）/ decay（置信度随时间的衰减）/ eviction（何时彻底离场）。
- **半衰期=域节奏非日循环**：最优 λ=0.001（半衰期≈29 天，生产 agent 需要比人类生物学更长的记忆视野）；hot/warm 分级（hot=当前会话小时-天，warm=偏好/当前项目 2K-8K token 天-周）；架构决策 0.98/天衰减、阻塞项 0.90/天（AgentRecall）。
- **AgentCore 教训**：数月生产后 agent 把 4 个月前已解决的账单纠纷当活跃状态引用——无生命周期策略必然堆积过期上下文。
- 判据：去重按语义不按字符串、按后台不按内联；衰减率按业务域节奏调，不是随便设个值。

### 5. 双时态记忆：point-in-time 正确性（工具）
来源：zylos-zep-bi-temporal / arxiv-2606.09900-engram / sentra-bi-temporal / arxiv-2606.26511
- **Zep 双时态四时间戳**：t_created/t_expired（系统何时学到/失效该事实）+ t_valid/t_invalid（现实世界中事实何时真/假）——两套时间轴分离。
- **point-in-time 查询**：A 事实在 t1 被 B 超越时——A.invalid_at=t1、B.supersedes=A（失效不删除，历史与 provenance 存活）；"腾讯 as-of t0 / Moonshot as-of now" 各按当时有效事实解析。
- **lean context beats full history**：检索到的精简双时态上下文比全历史更准——根因是时间一致性不是召回。
- 判据：向量检索返回"语义接近"不是"当前为真"；要 as-of 正确性必须有双时态轴。

### 6. Auto Dream 四阶段整合：记忆的睡眠式 GC（可复用 Skill）
来源：claude-platform-dreams / decodethefuture-auto-dream / milvus-claude-code-memory / cc-bruniaux-memory-systems / claude-wiki-four-phase
- **四阶段**：① Orient（列记忆目录/读索引/略读主题文件）② Gather Signal（**窄 grep 会话 JSONL 1-3 天，不读全文件**，只找已知怀疑重要的东西）③ Consolidate（新信号合并进主题文件、**相对日期转绝对**"hier"→"2026-03-24"、删除矛盾项、去重重叠笔记）④ Prune & Index（重建 MEMORY.md ≤200 行、删过期指针、强制执行索引条目格式）。
- **输入 store 永不修改**：dream 产出重组后的新 store 供审阅，原 store 不动——可 diff 可回滚。
- **触发条件**：>20 会话后记忆质量退化（重复/矛盾/过期日期堆积）触发。
- **corrections 是金矿**："no, we stopped using that" 是记忆模型出错且人指出的位置——Gather Signal 阶段优先抓纠正。
- 判据：记忆维护用"睡眠式"批量整合（后台子 agent 按四阶段跑），不是每次对话都重写；相对日期必须转绝对否则三个月后失效。

### 7. 记忆检索作为控制决策：utility 评分 + hard filters（模型·工具）
来源：agentpatterns-memory-retrieval-as-control / arxiv-2605.04897-storage-is-not-memory / xbstack-retrieval-architecture / cognilium-retrieval-ranking / mem0-retrieval-strategies
- **utility-scored retrieval（MemRL）**：标准 RAG 按 embedding 距离（相似=有用，对 distractor 记忆失败——余弦高分但有失败历史的记忆会误导走向已知失败路径）；把**历史有效性**做成检索信号。
- **hard filters 先行**：候选相关≠候选合格——先硬过滤（他租户/项目范围外/过期/标记删除或撤销或超越/低于最低置信度/当前任务策略禁止/敏感数据不可发给所选模型/环境不匹配），再做相似度排序。
- **storage is not memory**：True Memory=保留事件 verbatim + 多级检索管道（丢弃的内容检索期无法找回——不要入库时过度结构化）；BEAM-1M 76.6%。
- **top-k 是查找，ranking 是生产检索**：默认 cosine top-k 是查找不是排序问题；复合评分（相似+行为+新鲜度+重要性）+ 硬过滤器 + 重排。
- 判据：检索是控制决策不是查找——先资格过滤再相似排序；历史绩效与相似度并列计分。
