## 四、本轮落地的 4 个真独点

1. **超时预算按固定顺序解析**：per-call `timeoutMs` → `timeoutSeconds`(+30,000ms) → 工具专属默认（图像 120s / 图像理解 60s / message 600s）→ 通用动态工具 90s；动态工具上限 600,000ms；app-server watchdog 另加 30s×2（setup/completion 与结果递送）→ 提升层：工具。
2. **`timeoutSeconds: 0` 不是无限**：只关命令计时器、保留 transport 有界等待；未配置继承 exec 默认 1,800s；前台 `node_exec` 用 exec 解析后的预算 → 提升层：工具。
3. **超时收成「失败响应 + turn 继续」**：abort 工具信号、返回 failed dynamic-tool response，不把会话留在 processing；等待预算不在 run/tool 关闭后保留审批权限 → 提升层：工作流 / 安全。
4. **父死线不可被工具调用重启 + 超时重试语义**：重放 pending 请求沿用原父 deadline；per-pass 超时不构成整通上限；同连接同源同查询可共享挂起请求（旧调用者保持 failed、新调用者用自己的预算与当前授权）；连续两次本地源失败进入 5s→60s 有界退避，成功或配置重载清零，刷新期间缓存旧页可读 → 提升层：工具 / 工作流。
