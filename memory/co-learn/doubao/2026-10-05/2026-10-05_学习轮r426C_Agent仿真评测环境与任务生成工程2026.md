## 落地 5 独点（每点标注提升层）

### 1. 终态状态评估（state-based evaluation）：真实状态变更 + 快照恢复 + 服务隔离（工具/可复用 Skill）
来源：arxiv-2604.05172-clawsbench / arxiv-2608.19741-thinkingbox / infoq-aws-bench / arxiv-2606.10394-stage-claw
- **ClawsBench 四要素**：①agent 动作经 API **变更真实状态**（如活服务）②**确定性快照恢复**（每任务前序列化数据库快照，执行后对比期望结果）③**服务隔离**（每 mock 独立进程无共享状态，多服务任务组合）④结局对比。
- **Thinkingbox**=隔离 MCP 工具会话+完整执行 trace+**terminal backend state 终态评估**；任务用**任务特定可执行检查**接受有效轨迹、拒绝错/缺/多余轨迹。
- **aws-bench**=真实 AWS 账号里创建**可弃置真实资源**跑任务——比静态 fixture 基准更贴近真实工作得分。
- **STAGE-Claw 任务三条硬性**：多步执行（≥3 不同操作）、跨工具落地（≥2 工具/信息源）、可复现（构造过程产同样状态）。
- 判据：agent 评测优先终态状态对比而非只看回复文本；任务设计必须多步+跨工具+可复现。

### 2. 环境隔离=公平+归因：每 trial 全新沙箱（工具/工作流）
来源：agentclash-dev / arxiv-2604.18543-clawenvkit / langchain-harbor-evals / kanopylabs-agent-testing
- **AgentClash**=每 agent 一个 **Firecracker microVM**（隔离文件系统/网络/无共享内核，跑完销毁）——**没有模型拿 warm cache、没有 prompt 泄露，唯一变量是被测 agent**。
- **LangSmith 云沙箱**=每 trial 全新沙箱，trial 间不共享状态，可横向跑数百并行（vs 单机串行）。
- **ClawEnvKit**=mock services 确定性/随时可用/可预测响应（自动化评估可靠）但**缺真实世界差距**——生成环境质量可匹敌人工 curation 且规模远超。
- **工具副作用=必须沙箱**：agent 调 API/写库/发邮件有真实且不可逆后果——不能重跑失败测试指望最好结果。
- 判据：评测隔离是安全也是公平——每 trial 全新环境，杜绝 warm cache/prompt 泄露/状态残留。

### 3. 模拟用户（user agent）+ 信息获取测试（模型/工作流）
来源：microsoft-thinkingbox / papernotes-agencybench / baai-uniclawsbench
- **Responsive user**：开场请求**不含全部必需值**，只有被问到时模拟用户才给（预订号/房型偏好）——**测 agent 是否主动收集完成任务所需信息**。
- **AgencyBench**=用户模拟 agent 全自动评估 138 真实任务（平均 90 次工具调用、100 万 token，Docker 沙箱模拟人机操作）。
- **UniClawBench 闭环三 agent**=executor + **hidden supervisor**（不泄露评分标准）+ user agent——不泄题的前提下真实模拟多轮拟人反馈。
- 判据：测 agent 时用"被动信息型"模拟用户，验证信息收集而非只验证执行；评分标准对被测 agent 隐藏。

### 4. 轨迹评估六维 + 四层指标栈（可复用 Skill/模型）
来源：futureagi-agent-eval-guide / futureagi-tool-calling-stack / frankx-agentic-evals / mech-llm-as-judge / pypi-agent-eval-forge
- **轨迹评估六维**=工具选择/参数提取/结果利用/错误恢复/计划连贯/任务完成——**不是只看最后字符串**。
- **四层指标栈**=TaskCompletion / StepEfficiency / ToolSelectionAccuracy / TrajectoryScore / GoalProgress / ActionSafety；heuristic scorers=确定性检查（必需工具/禁用工具/schema 有效性/延迟预算）。
- **轨迹 rubric 示例**：0.8-1.0=只调相关工具无重复逻辑顺序 / 0.5-0.7=大体正确小低效 / 0.2-0.4=无关工具或过度重复 / 0.0-0.1=完全错工具选择。
- **agent-eval-forge**=YAML 场景包+轨迹评分+安全门禁+回归检测（对比 golden baseline 于 scenario/family/pack 级）。
- 判据：轨迹评估按六维打分并配 rubric 区间；结局+过程双轨（终态检查管"做完没"，轨迹评分管"做得好不好"）。

### 5. 评测闭环与 judge 校准：CI/线上同 rubric + ratchet + 校准集（工作流/可复用 Skill）
来源：futureagi-agent-eval-guide / mlflow-performance-metrics / arxiv-2602.16246-proxy-state / langchain-harbor-evals
- **闭环架构**：**同一 rubric 跑 CI 与线上 spans**，聚类线上失败，**ratchet 离线集从生产已坏处扩**，喂优化器——"维度是诊断，循环是系统"。
- **Calibrate judges not just models**：维护 **50-200 例人工标注校准集**，每次更新 judge 模型或 rubric 重跑一致性检查——跳过=在噪声上设门禁。
- **Eval saturation**：数据集饱和=要轮换增新（防过拟合评测集）。
- **Proxy State-Based Evaluation**：无确定性数据库时，**LLM 状态追踪器从完整交互 trace 推断结构化代理状态**，judge 验证目标完成与工具/用户幻觉——产生稳定、模型区分度高的排序。
- 判据：离线评测集由线上真实失败反哺（ratchet）；judge 一致性随模型/rubric 变化重校准；评测集防饱和。
