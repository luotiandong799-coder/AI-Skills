## 落地 5 独点（每点标注提升层）

### 1. Continuous batching（迭代级批处理）：吞吐 2-4x 的机制（工具/模型）
来源：frontiercheckpoint-vllm / swfte-continuous-batching / ai-tldr-vllm / runpod-pagedattention
- **静态批**=收 N 请求一起跑、全批跑完最慢者才收新请求——GPU 空等慢成员、新请求不管容量多空都排队。
- **Continuous batching（Orca OSDI'22）**=每 decode 步重排批：序列 EOS 立即驱逐、KV 块即释放；等待请求下一步进空位——**每 forward pass 调度器重组成批**。
- 实测：高并发混合长度输出，vs 静态批吞吐 **2-4x**，尾延迟收紧（长序列不再挡短序列）；vLLM GPU 利用率 85-92% vs TGI 68-74%（100+ 并发）。
- 判据：serving 选型先确认引擎支持迭代级 batching——静态批是吞吐杀手。

### 2. PagedAttention + KV 缓存管理：内存像虚拟内存、碎片归零（工具）
来源：swfte-continuous-batching / cloudai-pagedattention / runpod-pagedattention / packet-vllm-tutorial
- **PagedAttention**=KV 缓存当虚拟内存：每请求 KV 拆固定块（典型 16 token），从**全局池按需分配**，消除碎片——**KV 内存浪费减 55-80%**，直接提高并发请求容量。
- **Automatic Prefix Caching（APC，--enable-prefix-caching）**=存已处理前缀的 KV，新查询共享前缀**跳过重算 prefill**——重复文档检索/多轮对话可消掉大部分 prefill 成本。
- **Radix cache**=跨请求共享前缀树（SGLang 特性）；speculative decoding 的 KV 记账必须高效否则损失理论优势。
- **JENGA（异构内存管理）**=只给注意力层活动 token 分配内存以最大化解码吞吐 vs 前缀缓存命中率（精确前缀才能命中）——两者取舍。
- 判据：KV 缓存=吞吐杠杆，先开前缀缓存再谈别的；碎片管理决定并发上限。

### 3. 引擎选型：vLLM / SGLang / TGI / TensorRT-LLM（工具/工作流）
来源：inferenceengineering-vllm-sglang-trt / llm-academy-vllm-sglang-tgi / pythondatabench-inference-servers / effloow-inference-engines
- **vLLM**=最宽硬件/模型覆盖+可预测性能（默认起点；dense 模型吞吐高 TGI 15-25%）；容器 5-8GB、75k+ stars。
- **SGLang**=RadixAttention+multi-call 调度，**高并发 MoE 工作负载胜**；前缀缓存命中 75-95% vs vLLM 15-25%。
- **TGI**=HF 集成顺滑+内置 OpenTelemetry+保守调度 → **P99 更可预测**；选它=运维 polish 优先。
- **TensorRT-LLM**=编译引擎路径，**NVIDIA 硬件最高原始吞吐**但运维复杂度显著。
- 判据：**"start with vLLM，profile 出瓶颈再迁移"**——别一上来选最重的。

### 4. 关键调优参数：gpu_memory_utilization / max_num_batched_tokens / TP / speculative decoding（工具/工作流）
来源：parasail-offline-batching / docs.vllm-optimization / runpod-inference-first-principles / redhat-distributed-inference / arxiv-2605.29639-rtp-llm
- **gpu_memory_utilization**=0.90 默认 / 0.95 专用硬件——更多空闲=更大 KV 缓存=更多并发；**别超 0.95**（activations+CUDA context 要 headroom）。
- **max_num_batched_tokens**=小值（2048）ITL 更好（少 prefill 拖 decode）；大值 TTFT 更好（更多 prefill 进批）；**最优吞吐≈设近 max_model_len**，收益约 32,000 递减。
- **Tensor Parallelism**（TENSOR_PARALLEL_SIZE）=权重跨 GPU 切分，超单卡 VRAM 的唯一实用路径（70B BF16≈140GB）。
- **Speculative decoding**=draft 小模型并行生成 k 候选+目标模型并行验证——**验证快于生成**，容易位置（常用词/重复模式）接受率高；vLLM 支持 EAGLE3/DSpark 多类，运维成本差异大。
- 判据：先调内存利用率与批预算两个参数，profile 再上 TP/投机解码。

### 5. P/D 分离与部署模式：disaggregated serving + 离线批处理（工作流/工具）
来源：vllm.ai-blog-disaggregated / vllm-minimax-m3 / sglang-hyperparameter / vllm-metal
- **P/D 分离（disaggregated serving）**=prefill 与 decode 各自独立部署、独立拓扑调优——MiniMax M3 经 P/D 分离+重调 prefill/decode 拓扑：**concurrency 512 时 6370.5 tokens/s/GPU、中位 TTFT 1.32s**。
- **离线批处理**=大 batch 是吞吐第一要务；SGLang 稳态日志看 `Decode batch #running-req/#token/token usage`（0.82 高水位），调 cuda graph 与 batch 到满载。
- **vllm-metal**=Apple Silicon 并发 serving 新路径：concurrency 2/4 时 TTFT 与端到端延迟低于 llama.cpp 与 oMLX（oMLX SSD offload 在 concurrency 1 领先）。
- 判据：在线交互=TTFT 敏感用 P/D 分离；离线批量=堆 batch 到满载；个人本机低并发=vllm-metal/oMLX。
