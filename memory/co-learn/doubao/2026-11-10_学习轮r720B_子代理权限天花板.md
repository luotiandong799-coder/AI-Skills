## 二、落地点（4 个真独点）

### 1. 隐藏子代理有不可覆盖的硬 deny 层（工具层）
恒失 `gateway` / `agents_list` / `session_status` / `progress_card` / `cron` / `message` / `sessions_send` / `conversations_*`；每轮从子会话信封重建，allow/alsoAllow 覆盖不了；到 depth cap 再收 `subagents`/`sessions_list`/`sessions_history`/`sessions_spawn`，通信只剩 announce 链。判据：执行者不该有系统级、交付级、再派生工具。

### 2. 委派工具是 operator 授权，不是 spawn 参数（可复用 Skill 层）
`delegateToolsTo` 点名具体目标，不替代 `allowAgents`，只放宽发起方自身 deny 层；全局/sender/沙箱/继承照旧，重复 deny 仍 deny；投影不安全就在创建前失败。判据：授权只在"谁允许谁"生效，不穿透其他闸门。

### 3. 策略修正不追溯已存在子代理（工作流层）
`Existing children keep their recorded policy`。判据：先结束旧 child，再按新策略重开。

### 4. 续跑沿用 spawn 时捕获的 requester 策略（工作流层）
`sessions_yield` 续跑沿用捕获策略，且同 batch 每 child 须带同一份已核验策略；冲突/缺失退回普通受限；handoff 不授予工具、不推断发送者身份。判据：恢复上下文 ≠ 恢复权限。
