## 三、三点（各附提升层）

1. **把"只有人能做的步骤"写成可执行向导**（ed）
   - 旧形态是在聊天里丢编号步骤，会被滚走且过期不报错。正解：agent 写 bash 向导、**从不执行**，人自己跑——API key 因此不进模型上下文；范围先于脚本（读 `.env*`/`docker-compose*`/CI 里每处 `secrets.*` 引用，先把 stage 清单给用户确认再写）；每个值先定去向（.env/secret/variable/两者/哪都不进）；一 stage 一屏；无回退键但重跑会回填已存值；一次性即弃、团队复用的才提交；agent 只做静态检查（`bash -n` / shellcheck / 值与 `secrets.*` 引用对齐）。**提升层：工作流 + 工具**。
2. **可复用技能的配置外置**（sa）
   - 同一套技能跨仓库复用，唯一变量是仓库里的 `docs/agents/*.md`；技能运行时读它们，所以换 tracker 不改技能。**判据：setup 若改动了任何 `SKILL.md` 就是出错**。配合三条：先提议后确认（探索已回答的不再问）、映射文件不等于创建动作（缺标签要在落地前发现）、技能不做 per-user 配置（偏好走项目指令文件的明文祈使句）、`AGENTS.md` 当权威而 `CLAUDE.md` 只留一行指针。**提升层：可复用 Skill（技能治理）**。
3. **架构巡检的三条收口纪律**（ica）
   - 全 `Speculative` = 这轮什么也没发现（别为好看硬挑一个做）；一个候选一个会话，跨会话带的是"那条候选的一句话"而不是 HTML 报告；没有 `GLOSSARY.md` 时先建词汇再巡检（否则候选退回"重构 FooBarHandler"式命名）；参考型技能（只有词典没有流程）不能当驱动方，只做被调用方。**提升层：工作流 + 可复用 Skill**。
