## 落地 5 独点（每点标注提升层）

### 1. 搜索规划与深度推理分离（工具/模型）
来源：glean-waldo / glean-search-planning / arxiv-2506.17188-ai-search-paradigm / arxiv-2601.04703-m-ask
- **核心原则：找信息与推理是两种资源需求不同的工作**——一个模型同时干两件事=烧时间烧 token；**Glean Waldo=专用信息收集模型**（只决定"检索什么+怎么查询"），交给 frontier LLM 生成最终答案——更快更便宜无质量回归。
- **AI Search Paradigm 四 agent 模块**：Master（评估查询复杂度）/ Planner（分解问题成可执行计划）/ Executor（执行检索）/ Writer（综合写作）——动态协作覆盖简单事实→复杂多阶段推理。
- **M-ASK 解耦**：**Search Behavior Agents（规划执行搜索）+ Knowledge Management Agents（聚合过滤维护紧凑内部上下文）**——搜索行为与上下文构建分离减少干扰；**turn-level rewards** 提供细粒度协调信号。
- 判据：搜索类系统把"去哪找"与"怎么想"拆到不同模型/层；上下文维护独立于检索执行（不互相污染）。

### 2. 查询规划与多存储路由工程（工作流/可复用 Skill）
来源：anshadameenza-websearch-agents / max-gherman-deep-research / essamamdani-agentic-rag / aliyun-opensearch-agentic-search / learn-azure-agentic-retrieval
- **原始问题直接丢搜索是错误**：把用户研究简报拆成子查询是**专用规划调用（强 frontier 模型）**的活——"东南亚 fintech 竞争格局对比印度 UPI"是研究简报不是搜索词。
- **Deep Research 三组件**：**query planner**（高层问题→初始子查询）+ **source router**（每子查询定向：web 搜索/向量库/结构化 DB/专用 API）+ **evaluator**（相关性/质量/权威性评估）。
- **多存储路由**：planner 生成协调子任务（SQL 子查询=结构化指标 + 向量子查询=文档 + 图子查询=实体关系）——不同查询配不同存储；Azure 查询规划按 reasoning effort 分级（low/medium 才生成子查询、minimal 直查）。
- **Adaptive mode 复杂度路由**：实时评估意图复杂度选对话模式或规划模式——先判复杂度再决定要不要规划闭环。
- 判据：任何搜索 agent 先规划拆查询（不用 raw question 直查）；子查询按类型路由（时间敏感→web、内部文档→向量、量化→SQL、实体关系→图）；复杂任务进 planning 闭环、简单任务直答。

### 3. re-retrieve loop 与迭代上限（工作流/可复用 Skill）
来源：futureagi-agentic-rag / syncsoft-agentic-rag-stack / dev-saaro-agentic-rag / dataaihub-agentic-rag / arxiv-2607.10463-grasp
- **re-retrieve loop 是好坏 agentic RAG 分水岭**：self-check 发现不支持的 claim→**改写查询重检索**；**2-3 次重试上限**，超限拒绝或升级——无重检索的系统=首次检索失败就幻觉。
- **8 阶段栈（2.3x 提升）**：metadata 感知去重 + cross-encoder reranker + contextual retrieval（**砍 67% 失败检索**）；Stage 7 Reflection loop=grader 拒绝 >50% chunk→重发查询/换工具/扩大 recall 窗口，**循环预算封顶 3 次**；Stage 8=Cited generation+eval gate。
- **状态机迭代上限**：子问题分解→源决策（vector/SQL/web/MCP）→评估→不达标新 pass，**典型 5-6 pass 上限**（LangGraph 编排）；GRASP=RL 训练协调 semantic/keyword/paragraph 三种检索，奖励=answer accuracy+grounded reading+complementary search+turn efficiency。
- **验证步骤**：is_relevant=False→重写查询换源；is_sufficient=False→补检索；两者过→生成；生成后验=所有 claim 有来源支持+citation 准确。
- 判据：agentic RAG 必须内置重检索循环（预算 2-3 次）；每轮检索后做相关性/充分性双查；超上限显式拒绝或升级而非继续烧。

### 4. Web grounding 量化收益与残留幻觉（模型/工具）
来源：firecrawl-hallucinations / multiai-hallucination-2026 / linkup-grounding / searchcans-grounding
- **web grounding 量化收益**：SimpleQA/FRAMES 上 web-grounded 比 ungrounded **+25-40 百分点**；收益最大=需当前信息或交叉多事实的查询（训练数据最易自信犯错处）。
- **残留幻觉实测（HalluHard）**：最强配置 **Claude-Opus-4.5+web search 仍幻觉 30.2%**、GPT-5.2-thinking+web 38.2%；无 web 时 Claude-Opus-4.5 高达 60%——**web grounding 减半幻觉但不消除**，别把搜索当幻觉终结者。
- **检索层是根因**：LLM websearch 不准=**检索层喂 stale/low-precision/uncited 上下文**，模型在坏输入上自信推理→幻觉；**修在 API 层**（fresh/high-precision/citation-backed 结果可测地减少错误，SimpleQA/SealQA-0 验证）。
- 判据：上线 web 搜索用 SimpleQA/FRAMES 类测 grounding 收益；接受"grounding 减半不消除"的残留幻觉率；先修检索层质量（新鲜度/精度/引用）再怪模型。

### 5. 检索 agent 安全与评估四轴（模型/可复用 Skill）
来源：36kr-retrieval-agent-trust / arxiv-2603.00801-synthetic-web / futureagi-search-eval-four-axes / arxiv-2606.02404-k-browsecomp
- **合成共识攻击（合成共识=多个看似独立来源指向同一结论）**：13 模型实测 claude-sonnet-4.6 ASR 0.0% 最稳、**gemini-3-flash 31.4%——单靠合成共识就能打到 73%**——**假源集群比单个假源更危险**，检索 agent 需来源独立性检测。
- **Synthetic Web 灾难性失败**：**单一假源进 top rank→GPT-5 准确率 65.1%→18.2%**（即使无限访问真实内容）；失败模式=①证据冲突时 minimal search escalation（很少扩大搜索）②广泛搜索仍 poor synthesis——**检索 agent 对源污染无天然免疫力**。
- **搜索增强评估四轴**（按 query 评分**不聚合**——单数字隐藏哪轴崩了）：①**Source diversity**=域跨度（citation monoculture=三 URL 同一域失败；unique-domain count/per-domain cap/primary-vs-secondary ratio）②Citation validity=URL 可解析+cited passage 含 claim+anchor 存在（防 404/paraphrase drift/fabricated reference）③④另两轴=相关性/及时性类。
- **K-BrowseComp（浏览 agent 基准）**：GPT-5.5 45.67% 最高——浏览类任务仍难，开放/闭源都拉不开。
- 判据：检索 agent 加来源独立性/多样性检测（防合成共识）；上线前跑四轴评估且按 query 逐条看；检索结果去重限域（per-domain cap）。
