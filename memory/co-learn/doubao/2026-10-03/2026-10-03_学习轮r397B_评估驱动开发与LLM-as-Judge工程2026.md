## 落地 5 独点（每点标注提升层）

### 1. LLM-as-Judge 偏差工程：位置/非语义扰动/模糊问题/先验偏见（工具）
来源：autorubric-arxiv / arxiv-fairjudge / csdn-judge-bias / promptlayer-judge / uiuc-prior-prejudice / iclr-biasscope
- **位置偏差检测（双次评审+swap）**：对同一样本评审两次（AB 再 BA），把第二次结果映射回原始候选——**两次指向同一才可信**；swap augmentation 只接受一致偏好，不一致算平局；多选 shuffle 选项顺序消除系统位置效应——弱模型位置偏差更严重但 GPT-4 也受影响。
- **非语义扰动 debias（FairJudge）**：保持语义等价下沿非语义维度扰动评估输入（answer order/length/formatting/reasoning style/provenance）——**显式约束 judge 对非语义因素不变**，把 debias 学成行为属性而非外部规则；BIASSCOPE 用 LLM 驱动自动化大规模发现偏差（主动探索而非手工预定义清单）。
- **模糊问题放大偏差**：问"这回答好吗"模型用自己的先验填空（verbosity/tone/自信感）——**修复=问最具体、可验证的布尔问题**："回答引用了至少一个提供来源"近乎确定性，"这有用吗"不是；把模糊题改造成布尔题收缩偏差表面积。
- **Prior beliefs prejudice（同意≠质量）**：LLM judge 把"同意模型被训练相信的断言"当质量——**裸断言评 6-7/7，精心构建的反方论证评 1-2/7（即使明确只判修辞）**；一致性≠质量，评判前先隔离立场偏好。
- 判据：judge 题项全部可布尔化；成对比较必须 swap 双评；跑 BIASSCOPE 类偏差扫描再上线 judge。

### 2. 锁定 Rubric 评分：固定 trait + checkpoint + 证据锚定 + 正负标准加权（可复用 Skill）
来源：arxiv-rulers / arxiv-positive-negative
- **Rulers 锁定 rubric**：① 固定 trait 数量（EXACTLY N 个，如 Content/Organization）② 固定 checkpoint 总数（0=not present/1=partial/2=complete 式刻度）③ **calibration anchors（few-shot 示例）**锚定评分——rubric 文本+锚例一起喂，评分不漂移。
- **正负标准加权评分**：positive criteria 对所有回答共享（正确答案必须包含的事实/文化元素，各带正权重，judge 判 PASS/FAIL）+ **negative criteria 按回答特化**（SME 只对实际观察到的错误填，各带负权重，judge 判 Error Present/0）——**同一 judge 同时执行"必须有的"和"必须没有的"两类检查**。
- 判据：rubric 三项固定（trait 数/checkpoint 数/锚例）；评分同时跑正标准（必须包含）与负标准（不应出现），两类权重分开记。

### 3. 双轨评估体系：capability 爬坡 vs regression 防倒退 + core set 治理（工作流）
来源：anthropic-evals / microsoft-eval-framework / infoq-golden-trajectories
- **两类 eval 分开跑**：capability evals=**低通过率起步**、专挑 agent 搞不定的任务（给团队一个坡爬）；regression evals=**接近 100% 通过率**、问"还能不能处理以前会的任务"——**爬坡的同时必须跑回归**，分数下跌=有东西坏了。
- **核心评估集（must-pass）治理**：core tests 每变更必跑，失败即回归；**保持稳定克制加测试**——新场景先放 variations/other 类目，证明必要后才毕业进 core。
- **Golden trajectories**：验证过的 agent 交互序列——**不只最终输出，还捕获完整推理链/工具调用/决策点**；LangChain/LangSmith 插桩工具函数获得可审计 trace。
- **触发场景**：prompts/models/retrieval sources/orchestration logic 任一变化都跑 regression（部署前抓行为漂移）。
- 判据：每套 agent 都有双轨 eval（capability 爬坡 + regression 防倒退）；core set 稳定、变更必跑；eval 用 golden trajectories 而非单点输出。

### 4. Golden Set 构建法：四桶 + 手标先行 + 多样性优于体量 + 人类评审驱动策展（可复用 Skill）
来源：futureagi-golden-set / growthengineer-evaluate / agentpatterns-verification
- **四桶 golden set**：production sample（真实生产采样）+adversarial（对抗）+edge cases（边界）+failure replays（失败回放）——四桶齐 CI eval gate 才真正证明生产。
- **手标先行**：写任何指标前先建 **50-200 条手标 traces**；Anthropic/Microsoft Copilot 团队都建议 nontrivial 域最少 100-150 条；**多样性优于体量**——100 条覆盖 10 个不同失败模式 > 1000 条同质案例。
- **人类评审驱动的 golden 策展（防漂移）**：采样生产 traces，把每个分歧归因到 scorer 或 agent——**只把 agent-failure 标签反馈进 golden set**（不把 judge 自己的错喂回去），保持 LLM-judge 套件与移动的生产分布对齐。
- **Pre-change impact analysis**：建 code-to-test 依赖图，agent 提交前验证 at-risk tests——砍 70% 回归。
- 判据：golden set 四桶齐+手标先行；指标前先有 50-200 条；分歧归因后再反馈（只回灌 agent-failure 标签）。

### 5. 评测 Harness 工程：harness 决定能力 + layer-isolated 无 LLM 断言 + 可执行红队（工具/工作流）
来源：openai-thirdparty / arxiv-layer-isolated / arxiv-redagentbench / arxiv-agentredbench / agentthreatrule-redteam
- **Harness 决定能力是否出现**：长轨迹系统（工具/状态/恢复）下 harness 保状态+重试失败动作可让模型完成多步任务——**评估的是 harness+模型组合，不是模型单独**；换 harness 会改变观察到的表现甚至决定能力是否出现。
- **Layer-isolated evaluation（无 LLM 回归锁）**：生产 agent 分解成架构层（ontology 预解析/intent 信号/路由/分解/升级/安全/记忆/防御），每层独立无 LLM 纯断言片——238 基线 23 片 2.39s 跑完，**确定性 scaffold 用无 LLM 断言锁死**。
- **可执行红队（回执验证）**：从显式安全约束+agent 漏洞派生攻击，隔离服务沙箱运行，**从服务回执和终态变化验证有害效果**（不靠 judge 猜）——REDAgentBench 1661 cases 5 服务面，宏平均 ASR 65.69%；AgentRedBench 用 LLM 驱动动态生成 215 个微妙未充分授权场景（24 企业集成 5 攻击类型）。
- **ship-readiness gate（all-green 规则）**：每项就绪状态记 🟢（完整闭环跑过）/🟡（部分，无端到端记录）/🔴（只有理想设计从未跑过）——**只有全部 🟢 才 ship+tag**。
- 判据：换 harness 必重跑基线（评估结果=harness+模型）；确定性逻辑层用无 LLM 断言锁；红队攻击在沙箱执行并从回执验证效果；ship 前逐项 all-green。
