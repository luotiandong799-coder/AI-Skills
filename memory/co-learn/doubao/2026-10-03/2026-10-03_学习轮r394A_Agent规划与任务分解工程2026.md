## 落地 5 独点（每点标注提升层）

### 1. 错误分类→重规划决策树 + node-local 重规划（工作流）
来源：zylos.ai（2026-05-15 backtracking-adaptive）+ arXiv 2601.07577（task-decoupled）
- **重规划前先分类，不是所有失败都重规划**：① 瞬态错误（网络超时/限流/临时不可用）→指数退避重试，不重规划；② 确定性错误有清晰替代（工具 not found/文件不存在）→局部适应替换该步骤，不全面重规划；③ 矛盾观察（步骤成功但结果使计划假设失效）→带全文重规划；④ 同一步骤 K 次连续失败→升级人类或干净补偿中止；⑤ 外部环境变化→按变化重新评估剩余计划。
- **node-local replanning（任务解耦规划）**：Planner 产高层计划枚举中间目标；Executor 逐步执行并迭代吸收观察；观察与计划预期**实质冲突**时只触发活动节点的重规划——**只修当前节点，不扩大范围**（重规划限制在活动节点：仅它的计划与本地执行轨迹）；与全文重规划的分工=单节点偏离→局部修，跨节点假设崩→才全文。

### 2. 规划器-执行器分离 + 计划即契约（工作流/工具）
来源：detached-node.dev / besthub.dev / naqeebali.me / futureagi.com / then euralbase.com
- **planner 在工具触发前端到端推理**，承诺结构而非逐 token 即兴；executor 逐步走计划，编排层把计划当**可对照检查的契约**——计划是单一工件，可在任何工具运行前被日志记录、审计、编辑或拒绝（Plan-then-execute 的 observability 胜出点）。
- **成本形态**：一次 planner 调用+五步便宜 executor+失败才 replan=赢在延迟、成本、长程一致性；规划用强模型、执行可用更弱更便宜模型（或确定性代码）。
- **计划先序列化存储再执行**（生产强制）：执行中计划陈旧→重规划触发器=跑 N 步后或工具调用失败→把执行日志送回 planner 修订剩余步骤；**限制重规划迭代次数防死循环**（emersonbraun）；AnovaX 恢复层=核心步骤失败时用更紧凑系统提示跑 batched ReAct 自治恢复，不打扰用户。

### 3. 三种规划循环选型：Plan-Execute / ReWOO / Reflexion（可复用 Skill）
来源：aiwisdom.dev / genai4a11 / besthub.dev
- **Plan-and-Execute**：先出全计划→执行器逐部执行→失败才重规划——适合可干净拆解、有明确依赖序的任务，赢在延迟与长程一致性。
- **ReWOO（Reason Without Observation）**：一次生成**整计划为工具调用的 DAG + 占位符**→按 DAG 执行→单次最终推理拼接结果——最大并行、最少 LLM 调用，适合子任务可并行、工具结果互不依赖的任务。
- **Reflexion**：跑任务→评估结果→写批评→带批评重试——**必须有自动验证器**（测试通过/schema 校验）才选它；无验证器时批评信号不可靠。
- 选型判据：有没有自动验证器？子任务可并行度？失败成本？（可并行→ReWOO；有验证器→Reflexion；顺序依赖→Plan-Execute）。

### 4. 子任务设计四要素 + JSON 计划五字段 + 验证模式（可复用 Skill）
来源：ralfstrobel/agentic-brownfield-coding（build.md）+ microsoft-learn decomposition + lobehub architect
- **子任务设计四要素**：① 同级抽象（每个任务在同一抽象层级，不许一个"重构数据库"一个"改一行字"混排）；② 每个任务执行后代码库/系统必须处于**可执行无错状态**；③ 每个子任务带明确**可量化完成标准**；④ 每个子任务附带**验证模式**（从最严到最松排序）。
- **JSON 执行计划五字段**：每个子任务含 唯一 ID / 指定执行 agent / 依赖引用 / 预期输出格式 / 成功判据——无依赖的子任务可并行执行。
- **3-5 个核心子目标**：规划层把高层目标拆成 3-5 个可落地核心子目标（再多反而失焦），全程监控进度校验达标、统筹 DAG 调度（CSDN 规划能力）。

### 5. meta-agent 反思三决策 + 规划层/执行层职责分离（工作流）
来源：microsoft-learn（aaai task decomposition）+ CSDN（规划能力）+ deepthink.ltd
- **反思三决策（continue / modify / replan）**：每执行一个任务（或并行批）后跑反射——反射提示含 原 query / 当前执行计划 / 已完成任务及结果 / 剩余任务；meta-agent 三选一：continue（计划仍有效继续）/ modify（调整剩余任务、保留已完成工作）/ replan（丢弃剩余计划、从当前状态新建）——多数执行是 continue，但能力到位才能优雅处理边界。
- **规划层/执行层职责分离**：规划层=接高层目标→拆 3-5 个核心子目标→设可量化完成标准→全局 DAG 调度→校验子任务达标；执行层职责**严格受限**=只做单个子任务闭环（工具调用/结果解析/信息汇总/标准反馈），不跨任务不全局决策。
- **DeepThink 计划形态**：planner 在任何工具调用前写出**结构化、人类可审**的 JSON 计划（步骤/需要哪些工具/哪些结果算成功），执行层是常规代码写的轻量编排循环——计划本身是产品，不是中间产物。
