## 落地 5 独点（每点标注提升层）

### 1. Vision token 预算：分辨率速查表 + 裁剪激进 + 缓存策略（工具）
来源：linhtruong.com VLM / thesimplifiedtech.com / claudexia.tech
- **每图 token 估算**（工程速查）：512×512≈1,024 token（图标/简单图/UI 截图）/ 1024×1024≈4,096 token（文档/详细图表）/ 2048×2048≈16,384 token（高细节/工程图）；Claude 近似成本=宽×高÷750；A4 200dpi PDF 页≈1.5k-4k tokens（视 tiling）；4K 桌面截图≈4k-16k tokens——**cap 降采样到 2K 除非 OCR 关键**；手机快照 1024²→256-1024 tokens。
- **分辨率是成本旋钮**：原始 12MP 照片直接发=浪费（模型反正降采样）；降采样到长边 ~1280px 文字仍可读省大量 token；1568px 长边=一般内容推荐上限（更高不提升识别只增成本），2000-2500px=密集文字/小字；低/固定 detail=粗分类、高/tiled detail=密集表格/小字/序列号。**裁剪激进**：只发需要的图表区域=半价像素。
- **缓存与批量**：系统 prompt 开启缓存后文字部分变便宜，图像 token 成为主导成本（每轮图像都在变，缓存天然适合文字）；多图输入统一尺寸（混合尺寸破坏缓存层）；token-dropping（FastV/VisionZip/PruMerge）可靠省 40-70% 视觉 token 且 <1% 质量损失（需在自己数据上测）。
- **量化决策**：聊天场景每图 cap 1500-2000 tokens（除小字 OCR）；文档 QA 每页 tiling 串行传，绝不一张巨图。

### 2. 多页文档三分策略 + 每页计费（工作流）
来源：niteagent.com / thesimplifiedtech.com
- **多页 PDF 三策略**：独立提取后合并（1-2 页发票类）；顺序提取带前页上下文（合同/报告——把已提取摘要传进下一页 prompt，"只提取未捕获的新信息"）；整档单图（仅 <5-10 页且供应商无尺寸上限）。
- **每页是独立计费单位**：30 页合同满分辨率发送=prompt 成本数倍；只发需要的页，或先路由便宜模型找相关页再精读；预算与裁剪按页做，不按整档做。
- **页序上下文增量提取**：上一页提取结果（JSON）作为下一页的 context 前缀，避免重复提取和跨页字段遗漏——比每页独立提取更省 token 且更准。

### 3. OCR+视觉混合双管道：OCR 精确层 + 视觉语义层（工作流）
来源：thepromptbench.com / ai-tldr.dev
- **混合形态**：先 OCR 做批量文本提取（便宜、快、可扩展到百万页）→文本索引入库→语义问题检索相关页→把页面图像+OCR 文本**一起**送视觉 LLM（结构来自图像、文本来自 OCR，比任一单独更好）——=文档版混合检索（OCR 如 BM25 精确层，视觉 LLM 如语义层）。
- **何时用哪条**：高容量统一格式/纯字符精度=专用 OCR（Tesseract/Textract/Google Doc AI）更快更便宜；变体布局/印刷+手写混合/需要推理提取含义=视觉模型；**合规与审计场景要能辩护"某个字符为什么这么读"→OCR 置信度比"LLM 说的"更可辩护**；固定表单模板批量=Textract Forms/Document Intelligence 常胜过通用 LLM。
- **视觉模型误用清单**：不问供应商是否保留分辨率就发高分辨率扫描（会被激进降采样）；长文档一次性"提取所有重要的"（几乎不完整，拆分）；合规关键提取单靠一次响应（视觉 LLM 会自信地错——对照源页+第二模型/人工复核低置信输出）。

### 4. 目标提示 + 页面计数确认 + 结构化带引用（提示工程/可复用 Skill）
来源：zylos.ai / thepromptbench.com / skillmd.ai
- **目标提示（Target Prompting）**：聚焦图像特定区域而非整图——"关注右下表格，只提取 Product 与 Price 两列"；可行先裁剪感兴趣区再处理；坐标引用（模型支持时）；复杂文档多遍处理。表提取：先问 Markdown 表再单独 parse（视觉读表准，JSON 序列化出错），比直接要 JSON 可靠。
- **页面计数确认**：提示写明 "本文档共 N 页，阅读后确认你实际分析的页数"——视觉模型偶尔漏页/乱序，此技巧抓住错误（高价值且零成本）。
- **结构化提取带引用**：不泛问"总结合同"，改问"列出合同所有当事人及其角色与首次出现页码"——引用可验证、可路由异常；字段不确定时输出 `"uncertain": true`。
- **复杂布局 CoT**：prepend "Think step by step: 先识别所有章节，再逐节提取字段"；多页两遍处理=第一遍识别结构（哪些页含财务）→第二遍只精读相关页，比全档一遍便宜且全。
- **每页前置锚定**：页图像放 prompt 文字前；150 DPI 平衡文档、300 DPI 细节图；PDF 逐页转 PNG（文本 PNG 优于 JPEG）。

### 5. 多模态 agent 路由：工具描述量化 + 离线特征缓存 + 结构化返回（工具/可复用 Skill）
来源：theneuralbase.com multimodal-rag
- **工具描述必须量化，否则 agent 跳过文档**：描述写"文档含图表时用"→agent 会跳过 12 个图像文档；改写为"页面 >10% 有视觉内容时用"——量化标准可判定。
- **批量处理离线算特征、缓存复用**：agent 推理每步加 0.5-2s；对 10,000 文档批量处理，先离线一次计算文档特征（页数/图像数/布局类型）缓存，别让 agent 反复调 document_characteristics 工具。
- **生产工具必须返回结构化输出**（dict/Pydantic）而非字符串，下游 embedding 管道才能可靠消费；同质语料（全文本无图）或 <10 种文档类型/延迟 SLA<100ms 时不用 agent 路由（0.5-2s/决策不值），固定路由管道更简单。
- **混合路由判据**：文档同时有大量文本+视觉（图像 >10% 页）→hybrid 处理（提取文本+视觉分析+图表标签与邻近文本关联）；先调特征工具了解输入再选工具。
