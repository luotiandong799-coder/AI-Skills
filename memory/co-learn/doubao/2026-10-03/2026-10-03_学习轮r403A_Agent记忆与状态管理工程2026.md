## 落地 5 独点（每点标注提升层）

### 1. 记忆系统七阶段分解 + MemTier 五信号加权检索（可复用 Skill/工作流）
来源：arxiv-2606.06448-agent-memory / arxiv-2605.03675-memtier / zylos-ai-agent-memory-architecture
- **任何记忆系统可分解为七阶段**：ingestion（收原始交互流，定义记忆单元=单轮/固定窗口）→ memory construction → storage → retrieval → prompt assembly → generation → maintenance——**先按七阶段画架构再选组件，不按组件拼架构**。
- **MemTier（OpenClaw 运行时）**：结构化 episodic JSONL 存储 + **五信号加权检索引擎** + attribution-based 认知权重更新循环 + **异步 consolidation daemon（episodic→semantic 提升）**。
- **检索权重学习的条件（重要反模式）**：**PPO 适配在 raw-BM25 主导下失败**——检索权重学习只有在检索信号多样、非单信号主导时才可行；先诊断信号分布再决定要不要上学习型权重。
- 判据：新记忆系统先画七阶段图；检索加权至少 3+ 信号（BM25/语义/时间/来源/频率）才考虑学习型权重。

### 2. LLM 策展知识：Context Tree + AKL 生命周期（模型/可复用 Skill）
来源：arxiv-2604.01599-bytterover / arxiv-2601.06377-himem / hillpublisher-memory-model
- **ByteRover 反向管线**：**同一个 LLM 既推理又策展/结构化/检索知识**（invert the pipeline）——知识表示为文件级知识图 **Context Tree=Domain>Topic>Subtopic>Entry**，每 entry 带显式 relations + provenance + **AKL（Adaptive Knowledge Lifecycle）=重要性评分+成熟度层+recency decay**。
- **HiMem 双通道分段**：**Topic-Aware Event–Surprise Dual-Channel Segmentation** 构建事件记忆（认知一致性）+ Note Memory 多阶段信息提取管线捕获稳定知识——两类语义链接成层级结构。
- **认知三层准入**：sensory short-term/task medium-term/semantic long-term 按保留时间/应用环境/语义重要性定义**准入标准、保留规则、适用环境**——记忆边界不清=信息分布混乱的根因。
- 判据：知识树按 Domain>Topic>Subtopic>Entry 四级组织（对标用户"按标题层级分块"），每条带 provenance；用重要性+成熟度+衰减三轴管生命周期。

### 3. 段级记忆合并替代轮级合并（工作流/可复用 Skill）
来源：arxiv-2608.12990-lycheememory-v2 / zylos-memory-consolidation / zylos-episodic-narrative
- **LycheeMemory V2**：**语义段级合并替代轮级合并**——把多次交换批量成段、**语义边界检测**（比固定窗口保留连贯事件级与时间证据）、段完成后编码为上下文无关的类型化记忆记录。
- **收益**：降低 LLM 编码频率（不是每轮都调 LLM 固化）+ 保留事件级连贯性 + **轻量结构化索引 + query-planned evidence retrieval（先查索引再取证据）**。
- **无界保留退化三机制**：proactive interference（旧记忆干扰新记忆）/ context dilution（上下文稀释）/ contradiction accumulation（矛盾积累）——**必须选择保留与遗忘，不能只增不减**（MemGPT/Letta、OpenAI Dreaming V3 均含遗忘/合成机制）。
- **睡眠式整合**：多图架构（时间/因果/语义/实体四维分离）+ sleep-consolidation 管线压缩原始经验为持久知识。
- 判据：记忆写回按"语义段"批量而非每轮；固化频率=段边界不是轮边界；设计时显式留遗忘/降级出口。

### 4. 三温记忆与七面状态可移植（工具/工作流）
来源：zylos-conversational-state / zylos-live-upgrades / aiworkflowlab-memory-state / devtoollab-memory
- **三温记忆**：**hot tier**=当前对话（working memory，会话内）；**warm tier**=跨会话语义（向量库存摘要+提取偏好+已解决问题，Mem0 类自动化提取/冲突解决/多后端）；**cold tier**=不可变 SQL/对象存储（审计/合规，只读回查）。
- **七面状态必须一起 survive 升级**：conversation transcript / tool-call history / persistent memory / **scheduled-task ownership** / **credential bindings** / background process handles / behavioral conditioning——换模型或 harness 时七面任一丢失=回归；Claude Code 现路径=graceful-shutdown-plus-restart+手动 memory sync（社区推 in-process upgrade，issue #14114）。
- **线程级检查点模式**：thread ID + 每交互步骤后保存全部状态（LangGraph PostgresSaver）——会话连续 + 故障恢复（从最后检查点恢复）+ **时间旅行调试**。
- 判据：记忆分热/温/冷三档存放（温=可检索摘要、冷=不可变审计）；升级前核对七面状态清单；长任务每步落检查点。

### 5. 记忆退化、语义泄漏与存储选型（工具/工作流）
来源：dev-memorysync-benchmark / ai-tldr-memory-storage / streamzero-memory-architecture / xelionlabs-persistent-agents / augmentable-state-of-memory
- **语义泄漏（semantic bleed）失败模式**：agent 跨 50 轮重构多服务时，语义搜索会召回**过时或冲突的草案**（相似度近但已废弃）——**语义召回必须带版本/时间过滤，防"旧稿伪装成现状"**（对标 KB 已有"旧版本保留一周期 A/B"与 pin hash）。
- **存储三方案权衡**：vector=语义模糊召回/百万级/无显式关系+可能幻觉连接+需 metadata 过滤；files=零基建/人可读/可版本控制/无相似搜索+并发写损坏；knowledge graph=关系事实/实体追踪/时间版本/低幻觉/冷启动贵+更新贵——**按查询模式选，不是按流行度选**。
- **生产记忆层**：episodic 层 10-600ms 检索/保留 30-90 天（合规）/event stores（Kafka→Iceberg）；archival=一切可检索。
- **框架对照**：LangGraph=episodic+semantic（checkpointers+Stores）；Mem0=semantic 混合多信号检索+**usage-based decay**+多范围标签（user/session/agent 级）——单层跨工具共享用 Mem0 类，需调试/人机回环用 LangGraph 类。
- 判据：语义检索一律带时间/版本过滤；归档层保留全量可检索但永不注入上下文；记忆框架按"调试需求 vs 共享需求"选。
