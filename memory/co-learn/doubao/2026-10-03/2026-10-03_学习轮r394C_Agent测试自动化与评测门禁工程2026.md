## 落地 5 独点（每点标注提升层）

### 1. 四层测试框架 + 分层运行频率 + 任务回放录制（工作流/可复用 Skill）
来源：AWS AGENTOPS06 / agentixforce / max-gherman / openlegion-testing
- **四层覆盖面**：Unit=组件隔离（prompt 模板/工具调用逻辑/记忆检索/决策路由），LLM 可 mock 保持快可复现；Integration=agent-工具与 agent-agent 交互（staging 真实端点，**很多有趣失败在这里出现**）；E2E=完整轨迹；Human Eval=真人或强 LLM judge 多准则评分（~10% 测试投入，贵但唯一能抓微妙质量退化）。
- **按提交频率分层**：Unit 每 commit；Integration 每晚或 release candidate；E2E 夜间；Human Eval 发布前。
- **任务回放测试（task replay）**：录制生产 agent 运行——捕获每个工具调用/参数/返回值→CI 用录制响应作 stub 回放=高保真回归测试镜像真实使用模式；生产失败自动变永久测试用例（每未来变更都评估）。
- **组件测试四清单**（max-gherman）：工具实现已知输入返回正确数据？prompt 组装对给定状态产生预期串？护栏分类器放过干净输入挡已知坏输入？输出解析器从模型响应提取结构化数据？

### 2. 三级评估框架 + LangChain 五步发布管线（工作流）
来源：kunalganglani.com / langchain.com（readiness checklist）
- **三级评估**：L1 assertion 单元测试（快确定性，每 commit，抓明显回归）→ L2 trace-based LLM-as-judge（慢概率，curated datasets，抓人会注意的微妙质量问题）→ L3 online 评估与 A/B（持续生产流量，抓数据集还没覆盖的）——每级抓不同的东西，不能只上一级。
- **LangChain 五步发布管线**：① 代码或 prompt 变更触发（git push/PromptHub 更新/手动）→ ② **离线 evals**跑单元+集成+curated 数据集用便宜快 grader → ③ 过→preview 部署 → ④ **在线 evals**用真实流量 LLM-as-judge → ⑤ 全质量门过才 promote；否则失败轨迹进 annotation queue 转成测试用例。
- **生产轨迹回填**：监控期 eval 给真实生产轨迹打分，暴露问题的轨迹变成带输入+pass/fail 判据的可测例子（不是工单里一张截图）。

### 3. per-metric 回归门禁 + 五维质量门 PROMOTE/HOLD/ROLLBACK（工具）
来源：mlflow.org / llmci（PyPI）/ arXiv 2603.15676 / terminalskills ai-eval-ci
- **每改 prompt/换模型/加工具，eval 套件自动跑**（CI/CD 回归门禁拦部署失败）；**按 metric 定义阈值，不只 TSR**——TSR 维持但延迟翻倍仍该拦。
- **五维质量门（PROMOTE/HOLD/ROLLBACK）**：task success rate / P95 latency / safety pass rate / evidence coverage / research context preservation——基于证据的发布决策，不靠感觉。
- **llmci 形态**：pre-merge 安全门（不是可观测性工具）——定义 eval 数据集+质量阈值，CI 拦坏变更（prompts/models/pipelines）；`npx eval run --ci` 给红/绿构建，不用人盯 dashboards。

### 4. 评测数据集四要素 + golden pairs 语义等价 + 风险分级测试（可复用 Skill）
来源：openlegion-eval-dataset / langchain-checklist / agentpatterns.ai / juejin（AI Agent 评测实战）
- **任务四要素**：① 输入精确到无歧义正确解 ② 预期工具调用序列（工具+顺序+可接受参数范围）③ 成功标准（程序化或 rubric）④ 元数据（复杂度/域/期望轨迹长/已知边界）；**正负例都测**（该发生要发生、不该发生绝不能发生）；无生产数据先用 seed 生成（dogfooding 错误+改编外部 benchmark）。
- **golden query pairs**：领域专家手写已知好答案，持续跑 agent 变更；**grader 用语义等价而非字符串匹配**（正确答法的不同措辞仍算对）；golden pair 优先覆盖"agent 最可能错的模式"与"历史上失败过的边界"。
- **风险分级测试（掘金实战）**：每条测试带 category/expected_intent/required_tools/**forbidden_tools**（绝不可调用的工具）/expected_answer_points（必须覆盖的要点+禁止暴露的内容）/risk_level——不只测"会做"还测"不会做"。

### 5. 轨迹评估三指标 + 多成功轨迹原则 + 数据集不可变版本化（工作流）
来源：harness-engineering / braintrust / AWS Bedrock AgentCore
- **轨迹评估三指标**：task completion rate（达成目标了吗）/ step efficiency（相比最优路径多走几步）/ error recovery（失败后怎么恢复）——测 agent 作为系统而非组件。
- **多成功轨迹原则**：agent 可走不同合法路径到同一任务，exact-match 测试不可靠；评估测 工具选择/参数/执行顺序/最终结果 跨重复运行，允许多条成功轨迹。
- **数据集不可变版本化**：评测用例集发布为 immutable 编号版本，运行中不漂移；mutable draft 自由迭代→锁 checkpoint 发布；生产失败→变永久测试用例（AWS AgentCore 把评测基线当 versioned test fixtures 管理）。
- **非确定性管理**：集成测试用真实/类真实 LLM 调用贵且非确定——控制 LLM 随机性（固定 temperature/seed）或对非关键路径 mock；评测脚本可复现优先。
