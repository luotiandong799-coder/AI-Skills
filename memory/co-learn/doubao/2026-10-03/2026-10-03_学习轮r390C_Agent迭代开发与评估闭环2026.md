## 落地 7 独点（每点标注提升层）

### 1. EDD 评估驱动开发闭环：grader 先于 agent 存在（工作流）
来源：ilyaisaev-eval-driven-development / ai-tldr-eval-driven-development / helpmetest-edd-loop / agentpatterns-agent-lifecycle / channel-edd-cx-agents / raftlabs-agent-testing
- **核心顺序**：先写评估判据（正确交互什么样/失败什么样/中间怎么打分），再写第一版 prompt——grader 存在早于 agent 存在，这是 "driven" 的含义；反序=把活 agent 的 bug 嵌进"正确"的定义。
- **循环五步**（LLM 版 TDD）：write failing evals → iterate prompts/model → pass evals → refactor → run on holdout；传统 TDD 的测试换成 evals，实现换成 prompt/模型迭代。
- **一次只改一个变量**：记录基线分→改恰好一件事（重写一条指令/换模型/调 temperature）→重跑全量套件（不只改的那条 case）→看两个数：总分升了吗？先前通过的案例有挂吗？仅当"升且零新回归"才保留改动。
- **专家抽样校准**：每期由人类专家随机抽 5% 输出打分；人机一致率 <90% → rubric 太主观需细化。
- **eval 套件起点**：Anthropic 建议从 20-50 条真实生产失败任务起步，不用合成 benchmark；失败聚类成模式，修一个模式=修一类问题。
- **两模式（Google CE）**：Discovery mode（1-10 输入，人眼 vibe check，高延迟容忍）vs Defense mode（50-10,000 输入，自动化 evaluator，低延迟 SLO）——同一 agent 两个阶段两种评估。
- 判据：评估判据先于实现；改动一次一个变量并全量回归；人机一致性是 rubric 质量的度量。

### 2. 回归测试纪律：每个修复和投诉都变成用例（工作流）
来源：beam-eval-ai-agents / ai-tldr-edd / futureagi-self-learning-agents / vibeready-ai-evals
- **回归库规则**：每个修好的 bug 变成回归用例，每个客户投诉也变成一条；任何 prompt 改动 merge 前自动全量跑。
- **决策规则**：pass rate 达标 + 零回归 → ship；任何高影响案例回归 → hold；pass rate 掉超阈值 → investigate。
- **失败编码四步**（vibeready）：ship behind existing gates → watch it fail（读真实 trace 和 support threads，error analysis 是人人跳过、好 eval case 的唯一来源）→ encode the failure（一个生产失败=一行 repo 里的 golden case）→ gate it（进 CI 回归层，该失败永不再来）。
- **Simulate-Evaluate-Optimize**（futureagi）：synthetic users 打活 agent → 对话转 pass/fail signals → 从真实失败重写 prompt；eval suite 100% 过但生产静默失败=离线套件失真，用 simulate 补。
- 判据：失败必须被编码进套件才算闭环——"修好了"不落回归用例等于没修。

### 3. 生产失败→回归测试管道：失败模式分类学 + trace fingerprint（工作流）
来源：futureagi-agent-failure-modes / growthengineer-failure-modes / braintrust-failures-to-regression / aws-strands-rca / zylos-trace-driven-debugging / latitude-why-agents-break / microsoft-rca-training / arxiv-2606.14589-silent-failures
- **五类失败分类学**（futureagi）：planning errors / tool errors / retrieval errors / reasoning errors / safety-policy violations——按顺序从前到后走 trace；没有分类学的 incident review 是 theater。
- **修复循环**：cluster（同类失败聚类）→ judge（打标签）→ promote（晋升数据集）→ gate（进回归门禁）。
- **失败模式标签驱动晋升**（braintrust）：trace 先有可靠失败模式标签（instruction-follow failure=忽略系统/用户约束返散文、跳过必填字段；format violation=无效 JSON/缺字段/错类型/畸形引用），高置信 trace 才晋升数据集。
- **trace fingerprint 诊断表**（growthengineer）：Premature Termination=stop_reason=end_turn 但 goal predicate 未满足→补 goal-completion eval；Context Bloat=prompt_tokens 超线性爬升→滑窗摘要+工具输出压缩；Prompt Injection=工具输出含 'ignore previous'/系统文本→不可信数据打标+工具输出脱敏；Cost Runaway=$/trace p95=10×p50→每 trace 硬 token 预算+熔断器。
- **工具误用=静默腐化者**（zylos）：调错参数/选错工具/错误响应当成功继续——step 2 的畸形参数静默腐化依赖它的每一步；trace 签名=工具调用 span 成功响应但输出对下游语义错误。
- **RCA 分层**（Microsoft）：symptom（监控发现 checkout 完成率掉 15%）→ observable failure（客户遇到支付错误）→ proximate cause（支付 API 拒收价格值）→ root cause（定价 agent 模型部署新格式化行为）——修 symptom 不防复发。
- **静默失败分类**（arxiv 2606.14589）：A 环境/平台怪癖 / B 设计假设错配 / C 错误吞没稀释 / D 链式幻觉编造（LLM 特有、最危险——不只不报错，还主动把错误改写成看似合理的叙事）/ E 操作遗漏与取证盲区。
- **Strands 九父类**（AWS）：hallucination/incorrect actions/orchestration errors/task instruction non-compliance/execution errors/context handling errors/repetitive behavior/LLM output issues/configuration mismatch——每失败返回 span 位置+类别+置信分+证据。
- 判据：失败分类学是回归管道的地基；trace 签名让同类失败可自动识别。

### 4. 自动化优化器组合：GEPA / MIPROv2 / SIMBA / TextGrad（工具）
来源：dspy-optimizers / futureagi-prompt-improvement / futureagi-dspy-explained / dspy-gepa / arxiv-2608.16068-capo / arxiv-2606.18902-sage / preprints-adas-survey
- **三阶段优化循环**（futureagi）：从当前最佳 prompt 采样失败例 → teacher LLM 写 num_gradients 条不同 critique（解释为何失败）→ 每条 critique 产 prompts_per_gradient 个改进变体 → beam_size 束搜索打分。
- **四优化器分工**：BootstrapFewShot=保留成功 demo（基础）；MIPROv2=每步生成指令+few-shot，Bayesian search 组合打分（几百 labeled examples 时最佳）；GEPA=reflective evolutionary，读执行轨迹→自然语言反思失败→Pareto front 进化（报告比 MIPROv2 高约 13% 且 rollout 更少）；SIMBA=随机小批量采样输出高变异的困难例→LLM 内省分析。
- **TextGrad**：LLM 当 gradient oracle 建议如何编辑 prompt 降 loss——激进的差异化 prompt 优化，每步成本高（很多 LLM 调用），研究级/硬 benchmark 适用，生产主流是 DSPy。
- **DSPy 生成反馈三阶段**：trace（每模块调用记录中间态）→ feedback（metric 返回标量或富文本反馈）→ update（按分数更新可学习参数：保留成功 demo/提出新指令变体）。
- **Capo**（arxiv 2608.16068）：constraint-aware——让测得的约束残差决定搜索中哪些失败受关注，不预先固定相对重要性；DCAPO=从行为反馈学重写（pool-based GRPO）。
- **SAGE/SPO**：形式化自动 prompt 优化为结构化黑盒搜索；agentic 实例=每个 prompt 编辑 grounded in 诊断性代码分析；**无单一策略主导**——有效性取决于 landscape 结构×错误类型；生产 recipe=把单独无力的在线 A/B 测试链成稳健累积效应。
- 判据：优化器按数据量选（少=手动、几百=Bayesian、多且要强=GEPA/TextGrad）；自动化优化结果仍要人审（约束/风格/可解释性）。

### 5. Eval 数据集治理：版本化、三腐化、无污染（可复用 Skill）
来源：mlflow-eval-datasets / koji-golden-set / qaskills-dataset-versioning / barkingiguana-golden-dataset / ashvin-eval-checklist / theneuralbase-data-leakage / futureagi-golden-dataset / arxiv-2606.21631-dedup
- **eval 集当受管制的测试工件**：cases+参考答案+评分规则+数据集成员=整体版本化；每次 eval run 指向不可变 dataset revision；修正创建新 revision 带可审来源；eval 集原地编辑无版本→每个历史数字失效，月同比不诚实。
- **golden set 三种腐化各有修法**（koji）：distribution drift=真实使用变了，生产桶不再代表流量→季度重采样生产桶、保留 failure-replay 桶永久；criteria drift="好"的定义变→criteria 与 items 一起版本化、从不静默重写判据（改了记为新版本，否则历史比较无效）；overfitting→holdout。
- **split 比例**（ashvin）：~100 例起；每 trace 按失败类别打 binary 标签（不是单个总分）；train/dev/test=15%/40%/45%（train 供 judge few-shot、dev 调 judge prompts、test 只测一次）；test 永不进 few-shot 或训练；按失败模式分层抽样。
- **无污染三重防线**：validate_no_overlap() 只抓精确 hash 匹配（不足，要语义 overlap 检测）；golden 留 10-15% 新鲜切片防微调污染；**entity-rename probe**=每次微调后对 gold 行样本重命名实体，原名/改名准确率差距大=模型记住了 gold 答案。
- **构建流程**：pilot batch 测 IAA（一致率低于阈值就改标注指南）→ 抽查批次 → 争议解决流程 → 自动 dedupe（SHA-256 规范化文本）→ 与训练语料 overlap 检测 → 每条 schema 合规校验 → 时间敏感事实钉 reference_date。
- 判据：分数变化要说清来源（模型变了/prompt 变了/judge 变了/测试集动了）——版本化是唯一办法。

### 6. HITL 评估：on-loop 而非 in-loop + 单一权威（工作流）
来源：myengineeringpath-hitl / confident-ai-hitl-guide / futureagi-humans-in-loop / humansignal-yext / jatinbansal-human-feedback / sourcebae-hitl-annotation
- **on the loop vs in the loop**：in=每 case 人判（慢/贵，仅高风险）；on=人监控聚合行为，pattern 触发阈值才介入，per-case 决策保持自动——生产默认 on。
- **有效性四指标**：override rate / inter-annotator agreement / queue throughput / eval-score lift after retraining on human-corrected labels。
- **Active learning feedback**：人批准/拒绝信号=训练数据——reviewer 修改或拒绝 agent 动作=一个 labeled example（agent 提案错、正确动作=reviewer 的修改）；聚合后用于微调模型/校准置信阈值/识别系统错误模式。
- **单一权威（Hamel Husain 建议）**：任命单个领域专家当标签质量最终法官 + rubric owner；分布式标注无单一权威→一季内 kappa 掉到 <0.5；benevolent dictator 职责=抽查标签/解决分歧/编辑 codebook/拥有 IAA 指标。
- **LLM as third annotator**（Yext）：双人标注保留，LLM 只标两人不一致的任务当第三标注者——人成本只花在有分歧处。
- **HITL 四阶段**：model prediction（带置信分）→ human review → correction → improved model。
- 判据：人只处理机器搞不定的（分歧/高风险/新失败模式）；权威必须单一否则标注质量漂移。

### 7. 持续评估与漂移检测：能力是时变信号（可复用 Skill）
来源：google-ce-reliable-agents / zylos-longitudinal-eval / agentmode-production-eval / futureagi-prod-eval-framework / microsoft-drift-regression / agentixforce-drift-alerting / niteagent-quality-monitoring / layerlens-advanced-eval / futureagi-evals-fail-prod
- **连续评估四层**（futureagi）：online traffic eval=采样活输出，continuous；safety guardrails=100% 输入+输出，inline；drift monitoring=eval 分数随时间，daily；trace observability=agent 轨迹，每次运行。
- **漂移五因**（futureagi evals-fail-prod）：user-distribution drift（eval 集来自发布月流量，6 个月后用户输入带俚语/多语混编/截图/长追问——judge 对活流量低 15 分）/ prompt drift（v17 prompt 配 v3 的 rubric=评错东西）→ 修法=手标生产 trace 抽样与 judge 分歧 15+ 分即报警。
- **分数分布漂移检测**（agentmode）：response-length shifts（常指 prompt 变更或模型升级）/ structure shifts（格式变化/列表 vs 散文/引用模式）/ content-distribution shifts（词表/语气/主题漂移）——检测频率小时到日；score-distribution drift=对部署时基线检测 mean-score 下降。
- **语义漂移**（agentixforce）：把 agent 输出嵌入向量空间，比较基线期与当前期 embedding 分布（KL/Wasserstein/JS 散度）——输入相似但输出含义漂移即触发。
- **统计漂移**（niteagent）：今天均值 vs 14 天滑动窗口 Z-score（阈值 2.5）——抓 step-change 回归（模型更新全线下滑），实测约 3% 天数触发。
- **后果感知发布门禁**（Microsoft Foundry）：precedence 而非加权平均——任何 C3 failure=BLOCK；新 C2 regression=REVIEW；模型评估与人工标签实质分歧=REVIEW；C1 movement 仅诊断报告；传统 CI 问"能编译吗"，agent CI 问"行为还达标吗"（Harness 案例：build 通过 endpoint 活着但行为 65%<70% bar → deploy 停）。
- **Shadow eval gate**（zylos Gate4）：新版本跑回放 24-72h 生产流量，judge 打分对比当前生产版——抓 offline 数据集漏的 distribution shift。
- **纵向评估**（zylos）：质量不是发布时认证的固定属性，而是时变信号——regression cadence+drift detection+production-feedback loops（失败 live 交互→未来测试用例）。
- 判据：agent 无代码变更也会漂移（新模型部署/上下文窗口调整/训练数据渐变）——持续评估是唯一防线，发布门禁用后果分级不用加权平均。
