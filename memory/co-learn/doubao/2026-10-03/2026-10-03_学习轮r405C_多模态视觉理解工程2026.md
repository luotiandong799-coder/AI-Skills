## 落地 5 独点（每点标注提升层）

### 1. 像素同上下文心智 + 分辨率-token 成本关系（模型/工具）
来源：thesimplifiedtech-multimodal / ai-tldr-llm-ocr / stochasticsandbox-multimodal
- **VLM 不做"OCR 后读文本"**：它直接看**像素+tokens 同一上下文窗口**——布局、颜色、字符同时参与回答；**图像不是预处理步骤，图像就是输入**（转成 image tokens 与文本 tokens 并置跨注意）。
- **三阶段架构**：图像编码（ViT 切 patches→embeddings）→跨模态投影（线性/MLP adapter 映射到 LLM token 空间）→LLM 解码（联合注意）——理解这三点利于设计管道与排查失败。
- **分辨率直接决定 token 数，token 数决定成本与质量**：tile/detail 模式按需选择——**不无脑最高清**（超高分辨率=超高 token=高成本）。
- 判据：设计视觉管道前先想"像素是输入不是前置 OCR"；分辨率/tile 按任务需要选；Debug 从三阶段定位（编码/投影/解码）。

### 2. 文档提取管道：normalize→分类→schema 提取→校验重试（可复用 Skill/工作流）
来源：aiagents-codeguides-document-agent / ai-tldr-ocr-vision / anhtu-intelligent-document / thepromptbench-document-images
- **结构化提取 prompt=文档视觉 AI 最重要变量**：模糊 "extract the data" 结果不一致；**清晰任务+明确输出格式+JSON schema 示例**可靠胜出。
- **管道顺序**：normalize 输入（PDF→页图 / HEIC→JPEG / deskew/resize 在模型限制内）→**先分类文档类型**（invoice vs receipt vs ID）→类型匹配 schema 的 JSON 提取 prompt→**代码校验**（失败带校验器错误+同图重试，有界）→可选跨校验 totals/日期/ID。
- **Schema-based extraction**：映射预定义 JSON schema（invoice number/date/total/line items）——**VLM 按 schema 提取每字段，非返回文本 blob 再 regex**（旧法脆难维护）。
- **页数确认**：告诉模型 "This document has N pages. After reading, confirm"——模型会漏页/乱序；**带引用的提取**（"列出每个 party+首次出现页"）可验证并路由异常。
- 判据：文档提取走五步管道（归一/分类/按 schema 提取/校验重试/跨校验）；prompt 给 schema 示例；要求页码引用防漏页。

### 3. Validation 层与置信度路由：可信度的分水岭（工作流/工具）
来源：mixpeek-structured-extraction / arxiv-2602.24134-agenticocr
- **Validation 层=最易跳过但决定系统可信度**：①业务规则检查（**line items 求和=total**）②数据库交叉引用（实体存在？）③算术一致性（数量×单价=行项总额）。
- **置信度评分**：token 级概率——**低置信区域标记潜在错误**；**高利害提取（法律合同/财务文件）低置信路由人工审查**（human-in-the-loop）。
- **AgenticOCR=按需解析**：把 OCR 从静态全文过程变为 **query-driven on-demand 提取**——"thinking with images" 分析文档布局，**选择性识别 ROI**，**on-demand 解压视觉 token 精确处**——解耦检索粒度与页面级分块。
- 判据：提取完必过业务规则/交叉引用/算术一致性三查；低置信标记+高利害人工路由；长文档用按需解析不全文 OCR。

### 4. 多模态 RAG 三架构与索引遗漏定律（工具/工作流）
来源：anhtu-multimodal-2026 / openrouter-send-image / bestin-it-chart-vlm / hub-baai-lanla-rga / arxiv-2607.24748-vld-rag
- **三架构**：①Caption-and-index=**VLM 描述每图/表→文本索引**（最简，复用文本 RAG 基建，但 **captioning 步丢信息**）②Unified vision embeddings=多模态 embedding 模型（Cohere Embed 4/voyage-multimodal）图文本**同向量空间**，文本查询直接匹配图像（保留更多细节，需多模态 embedding+支持向量库）③混合=页保留多模态索引+稀疏/稠密混合检索+verifier 引导 agent（VLD-RAG）。
- **索引遗漏定律**：**"Anything the VLM leaves out at index time can't be found later"**——caption 策略的丢失=永久不可检索。
- **图表描述进 RAG**：VLM 把柱状图转结构化散文（类别标签/近似值/趋势观察）→**同文本 chunk 流程嵌入存储**→自然语言查询语义匹配图表描述；澜舟多模态 RAG 在 FinRAGBench-V 69.6%→**90.7%**（+21pp）。
- 判据：视觉检索选架构看"细节保留 vs 基建复用"；图表先转结构化描述再入库；关键视觉信息别只在 caption 里（丢=永久丢）。

### 5. GUI grounding 工程：像素+结构融合与不确定性引导（工具/可复用 Skill）
来源：dev-wonderlab-gui-testing / frankx-computer-use / arxiv-2605.02630-autofocus / sage-gui-openreview / dev-agdex-desktop-gui
- **GUI grounding 是桌面/浏览器 agent 瓶颈，不是任务理解**：gpt-4v 仅 12.24% vs 高精度系统——差距 ~60pp，论文明确归因 grounding 与操作知识。
- **OmniParser=像素视觉+DOM/accessibility tree 融合**：识别按钮/字段/图标/菜单+坐标归一化映射（0-1000→物理分辨率，亚像素精度）。
- **AutoFocus=训练-free 不确定性引导**：**token 级 perplexity（PPL）在坐标生成中相关于空间歧义**——把 PPL 当内在不确定性信号引导主动视觉搜索（UI-Venus-7B 50.3%→67.8% ScreenSpot-Pro）。
- **SAGE-GUI=结构-视觉仲裁**：解析 UI 元素→**动作级 UI 图**（可引用接口对象+局部范围+结构关系）→动作意图解析为结构化查询（语义/角色/范围/关系约束）→**结构结果不确定时调视觉 grounding（SoM 标记局部区域），结构候选与视觉证据保守仲裁**。
- 判据：GUI agent 先解 grounding 再谈任务理解；像素与 DOM/accessibility 双通道融合；坐标生成高 PPL=先缩放/裁剪再点；结构解析与视觉证据冲突时保守仲裁。
