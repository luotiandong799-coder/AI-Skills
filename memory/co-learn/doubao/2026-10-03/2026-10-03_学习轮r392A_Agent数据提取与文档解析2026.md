## 落地 5 独点（每点标注提升层）

### 1. 提取模式决策树五模式 + 三档结构化生成方案（可复用 Skill）
来源：cs.wm.edu Prompt Patterns for Structured Data Extraction / genai4a11.github.io Structured Outputs / dev.to retry-repair loop
- **五模式决策树**（选模式先答五问）：①数据格式一致吗？→Pattern Matcher（正则/规则最省）；②有固定关键词触发吗？→Keyword Trigger Extractor（按"Name:"/"Date:"等 cue 词定位，长文档快速过滤不必扫全文）；③范围窄且需过滤吗？→Specify Constraints（只取与当前目标对齐的部分）；④属性因实例而异吗？→Dynamic Attribute Extractor；⑤需要语义理解吗？→Semantic Extractor（LLM 完整理解）。
- **三档结构化生成**（按鲁棒性需求/延迟预算/模型能力选）：Native JSON Mode（一个 API 参数，快，但只保证合法 JSON 不保证 schema 合规，仍需客户端校验）；Post-Processing+Retry（Instructor 绑定 schema，兼容任意模型，retry 加 100-500ms，覆盖 90% 场景）；Constrained Decoding（Outlines/LMQL token 级约束，**保证**合法且 schema 一致零 retry，需 logits 访问仅 vLLM/Ollama 自托管）。判据：默认 Instructor+JSON mode，硬 schema 保证才上 Outlines。
- **schema 设计五律**：schema 先于 prompt；缺失/不确定显式表达（Optional/None 优于异常，LLM 可省略不确定数据）；**String over number 保原始语义**（"approximately 500" 用字符串不强迫整数）；字段加 description 描述（"total invoice amount in USD" 优于字段名 "amount"）；Enum 约束分类字段。
- **三层结构强度顺序**：Constrained decoding（采样层保证）> Tool/function calling（同机制换帽子）> prompt+validation（最弱，老模型/代理回退）——即便最强层仍需自己的验证（schema 表达不了业务规则：日期先后/数组非空/邮箱域名）。

### 2. 多 Agent 提取管线：提取/验证/Judge 三模型分工 + 置信度校准（工作流）
来源：dzone.com multi-agent LLM extraction / codeables.dev fail-closed
- **单 agent 提取 5 文档行、5000 不行**：幻觉值填缺失字段/上下文窗口限制/无可靠置信度信号/旧记忆自动假设——单 agent 提取注定失败，要架构分解。
- **管线**：PDF→预处理→提取 Agent→验证层→Judge Agent→结构化输出；每阶段独立服务用结构化 JSON 消息通信，横向可扩展（一文档失败不阻断其他）。
- **三个不同 LLM 分工**（提取/验证/judge 各用不同 SoTA 模型）：提取=低 temperature+显式 schema 强制+chunk 级语义分段（非定长 token）+carrier 无关提示；验证=确定性（JSON schema 完整性/必填可选/类型/范围/NULL 检查）**+** 上下文 LLM 二遍比对原文（检出幻觉值与缺失项）；Judge=接收提取+验证结果，产置信度分数/错误分类/最终决策（PASS/REVIEW/FAIL），置信度阈值按历史已处理数据集分桶校准。
- **prompt 工程当软件工程**：prompt 版本化+黄金数据集基准+持续评估（文档格式演进 prompt 精度会退化）；强通用 base prompt+从历史数据集派生的特定 carrier prompt。

### 3. Fail-closed 提取工作流：硬/软失败分离 + 逐字段证据锚定（可复用 Skill）
来源：codeables.dev / digitalinsight.cloud / next-gen.cloud PromptForge / pdf.ai
- **fail-closed 原则**：LLM 是采样引擎总会在缺失时编造——包装进确定性管线：严格 schema+逐字段置信度+业务规则交叉校验+异常路由；"mostly accurate 是 bug"。
- **hard vs soft failure 分离**：hard=无效 JSON/缺必填/不可能日期（重处理或人工）；soft=低置信度/小额不符/货币不清（可带 flag 继续流转）。
- **逐字段置信度+交叉校验**：不只一个整体 confidence；逐字段打分；sum(line items) vs total、日期一致性、已知税率等业务不变量；低置信度/边界字段进人工审查不进生产。
- **字段级证据锚定**：prompt 要求每个关键字段返回 source_quotes/evidence snippets（支持提取值的原文片段）——审查更快、调试有据、精度更高；"模型声称存在但原文找不到"=幻觉检测拦截。
- **验证外置五层**（模型外确定性代码）：schema（必填/类型/枚举/数组形态）/格式（日期/币码/小数精度）/跨字段（subtotal+tax=total 容差内）/文档（发票号出现在原文）/业务（到期日不早于开票日）。验证规则窄、可解释、版本化；失败不静默通过。

### 4. 六段式文档提取工作流：先分类后提取 + 预处理规范化 + 语义分块（工作流）
来源：digitalinsight.cloud / neuralbase.com pre-processing / sysart.consulting / xbstack.com
- **六段管线**：摄取（文件+元数据）→分类→预处理→schema 提取→验证→交接（下游/人工队列）——不要在一个 prompt 里混 OCR+提示设计+业务逻辑+QA，分层可独立改进。
- **先分类后提取**：小模型/轻量分类器先答"这是什么文档"（发票/合同/表格/表单）→路由到对应 schema 与 prompt；一个文档族一个 prompt 比一个万能 prompt 好维护；分类也省成本（BERT 级分类器 95%+ 毫秒级，GPU 留给提取）。
- **预处理规范化**（质量提升主要来源，比无限改 prompt 更有效）：去重复页眉页脚/标记页码/表格用布局感知表示/分拆无关长线程/附件单独标记；OCR 300 DPI 基线（小字表多上更高）。
- **预处理决策树**：编码标准化（UTF-8）→去结构噪声（HTML 标签/表单伪影）→空白归一→语言特定构件→**语义边界分块**（页断/章节，非字符数——字符切分切半表格毁语义）；10% 预处理改进防 40% 提取失败。
- **语义分块与布局感知**：RAG 摄入不按固定字符切（切坏表格数据链/法律条款层级）；用 H1/H2 标题作物理块边界，父标题层级（Chapter 4→4.2→4.2.1）附加为元数据提供完整结构上下文。

### 5. 表格提取三路径 + 跨页表合并 + 可审计字段锚定（可复用 Skill）
来源：arxiv PDFTable / codesota.com / unstract.com agentic table extractor / mixpeek.com / xbstack.com
- **表是最难提取目标**：跨页表/合并单元格/隐藏表头是财务 agent 计算逻辑的灾难；OCR 常把表识别成碎片空格/管道符乱文，LLM 看不懂行列关系。
- **三路径**：规则式 PDF 表解析（pdfplumber，有边框表）；DNN 表结构识别（Table Transformer/DETR，无线表）；多模态视觉直接输出（LlamaParse 等，渲染式）。无边框表（财务常见）无视觉分隔符最难——多模态或 DNN。
- **合并单元格处理**：转标准 HTML `<td>` 带 rowspan/colspan，或填空单元格保证每行数组长度对称。
- **跨页表合并**：先检测续表（重复表头/缺表头行/列宽一致/行号连续）再 post-processing 合并；或 Agentic 六 agent 管线（检测提示生成→并页屏检→表结构识别→逐页提取+跨页行合并→代码生成 JSON 映射→沙箱执行）。
- **VLM 两遍法**：第一遍检测表区域提 HTML→第二遍验证 HTML 结构（列数一致/无孤儿单元格），失败换 prompt/模型重提。
- **可审计锚定**：合规场景提取字段必须带原文位置（page_number/bbox 坐标/context_text 片段）——"total_amount 5000000.0" 要能双击回溯到 PDF 第 42 页红色高亮；前端渲染系统据此定位，人工审计成本大降。无锚定的字段提取不能用于高安全内控/合规审计。
