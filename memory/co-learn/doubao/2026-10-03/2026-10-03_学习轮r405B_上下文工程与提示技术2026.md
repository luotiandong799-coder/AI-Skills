## 落地 5 独点（每点标注提升层）

### 1. Context engineering 栈与四层提示架构（工作流/可复用 Skill）
来源：aipromptlibrary-context-engineering / lobehub-prompt-mastery / ailearnings-prompt-techniques / wasilzafar-openai-sdk
- **2026 从 prompt engineering 转向 context engineering**：把整个上下文窗口设计成**结构化信息架构**——system prompt（角色/约束）+ 动态检索文档（RAG）+ 相关对话历史 + 工具定义 + 结构化示例；**prompt 只是多层 context stack 的一层**。
- **四层提示栈**：Layer1 System Context（你是谁/约束/语气）→Layer2 Task Definition（做什么/输出格式）→Layer3 Input/Context（用户数据/文档/变量）→Layer4 Output Shaping（格式/示例/guard）。
- **上下文注入**：注入相关事实/文档/数据——模型对**提供的内容**推理而非训练数据；**只注入与特定问题相关的**（聚焦不灌满）。
- **Responses API instructions 优先级**：instructions 参数=系统级渠道，**在用户消息之上的优先级层级**（应用开发者意图，不受用户请求左右）。
- 判据：提示设计按四层组织；注入只留相关上下文；系统级规则走 instructions 渠道不放用户消息区。

### 2. Lost-in-the-middle 放置策略（模型/工作流）
来源：sureprompts-long-context / gh-matteoscurati-ai-prompting
- **attention 不均匀**：长上下文开头与结尾内容被更可靠检索使用，**中间衰减**（lost in the middle）——效果强到决定承重内容放哪。
- **顶部=prime real estate**：system role、输出格式、规则、schema 等模型必须注意的内容放开头。
- **长文档场景**：**文档放前面，指令放后面**；多文档任务 **query 放末尾可提升质量 ~30%**。
- **Quote-then-answer**：长文档先提取相关 `<quotes>`，再基于 quotes 回答——先引后答。
- 判据：承重指令放顶部；文档/材料中段、任务指令末尾；长文档强制 quote-then-answer 而非整段塞。

### 3. Prompt 版本化工程（工具/工作流）
来源：respan-prompt-versioning / dev-edo911-master-prompts / next-gen-prompt-versioning / csdn-prompt-test-framework
- **版本元数据**：version int（每次变更+1）/ template_body（模板+变量）/ **change_notes（改了什么为什么）** / rendered_hash（**sha256 模板体=缓存键**）/ stage（dev/staging/prod）/ created_by / created_at。
- **版本档案**：golden_set.json + rubric.md + **CHANGELOG.md**——v3→v4 记：加了 Verification 节、Role 从 120 词砍到 40、格式分 1.4→1.8、**原因**（executor skipped done_when）。
- **回归测试**：对**上一版本**跑回归不只新用例；**捕获副作用**（响应更长/延迟升高/工具调用更频）；**分阶段 rollout**（内部→小生产切片→广发）；**每请求日志记录服务的 prompt 版本**（支持/工程可追溯）。
- 判据：prompt 当代码管（版本+CHANGELOG+stage）；改动跑上一版本回归；上线分阶段；线上日志带版本号。

### 4. Eval loop 与评测指标（工作流/可复用 Skill）
来源：futureagi-llm-prompt-format / ailearningguides-context-engineering / socialanimal-prompt-patterns / moweb-enterprise-prompts / getmaxim-prompt-guide
- **无 eval 的 prompt 变更是 vibes change**：旧 prompt vs 新 prompt 跑同一标签集、两者评分、**要求有意义 delta 才上线**。
- **三型评测**：golden-set testing（回归检查 curated 示例）/ LLM-as-judge（主观质量）/ A/B testing（真实流量对比）。
- **golden dataset ≥50-100 对**；工具=Braintrust / Promptfoo / Langsmith。
- **指标分两类**：结构化输出=schema conformance rate / field accuracy（对 ground truth）/ field completeness；生成文本=相关性（是否回答问题）/ 准确性（事实是否成立）/ 格式合规 / 长度合适。
- 判据：每次 prompt 变更跑同集对比要求 delta；golden set 50+ 对并随生产边缘 case 扩充；结构化与文本指标分开选。

### 5. Output contract 与链式刺激（可复用 Skill/工作流）
来源：novakit-context-over-cleverness / agent-cookbook-top30 / futureagi-stimulus-prompt / skillgen-advanced-prompting / promptrefinery-agent-prompts
- **模糊输出="model is dumb today" 主因**：output contract 要残酷具体——**字段、顺序、类型、省略 vs 包含、输入畸形时的失败响应、最大长度**全指定。
- **系统提示像合同**：You are（角色一行）/ Goal（成功长什么样）/ Constraints（逐条）/ **If unsure: Say so explicitly and ask 1 clarifying question** / Output format（精确格式规格）。
- **Chain-stimulus=2026 生产默认**：分类器→leading prompt（预载推理框架）提取→校验→格式化；**Prompt chaining** 复杂任务拆连续链（输出为下输入），减少手动迭代 4.5x。
- **Edge Case Explorer**：工作流开始前生成 10 个会让典型 AI 失败的边缘案例+触发条件+**推荐 prompt 修改**——红队内建。
- 判据：机器消费输出先写死 contract（字段/类型/失败响应/长度）；系统提示按合同结构；多步任务用链式刺激；上线前跑边缘案例红队。
