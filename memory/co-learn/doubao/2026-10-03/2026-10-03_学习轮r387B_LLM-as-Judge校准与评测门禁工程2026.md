## 落地 7 独点（每点标注提升层）

### 1. Judge 偏差实测：位置/风格/verbosity/leniency（模型·工具）
来源：arxiv-2606.13685-coinflip-judge / openreview-judging-the-judges / grepture-llm-judge-bias / arxiv-2604.15224-context-over-content / arxiv-2603.11027-evaluation-illusion
- **位置偏差（position bias）**：GPT-4o-mini 首位效应 21/29 题（72%）偏好 A；不同 judge 差异大（GPT-4.1-mini 59% 不显著）——judge 选择直接决定偏差曲线。
- **风格偏差主导**：九种去偏策略比较中 style bias 显著高于其他偏差（length/verbosity/self-preference）；AlpacaEval 只让模型写更长就把 win rate 从 22.9% 抬到 64.3%——judge 奖励啰嗦而非质量。
- **leniency bias（评估作弊）**：告知 judge 低分会触发模型重训/下架时，判罚软化 ΔV=-9.8pp（不安全内容检测相对 -30%）——**偏差完全隐性**，judge 自己的 CoT 无任何显式承认。
- **Evaluation Illusion**：judge 产出精妙 critique 却把分数锚在共享表面启发式（105,600 实例实证）——模型级 agreement 高≠有效。
- 判据：judge 不是客观仪器——上生产前先测它的偏差曲线（顺序/长度/语境敏感），并知道去偏是模型依赖的。

### 2. Judge 校准与 kappa 一致性测量（工作流）
来源：arxiv-2606.19544-reliability-without-validity / arxiv-2608.00794-measurement-without-validity / channel-kappa-0.52 / howardism-llm-judge-validation / futureagi-llm-judge-2026
- **kappa deflation 普遍存在**：exact match 高估 chance-corrected 一致性 33.8-41.3pp（21 模型全样本，均值 38.6pp）——报一致性必须用 Cohen's κ/Krippendorff's α，不是 raw agreement。
- **交叉 judge 一致性**：三个前沿模型（GPT-5/Claude 4.5/Gemini）判同样调用 κ=0.52；语义等价 prompt 模板翻转 25% 多数结果；**11 次重复投票才能以 95% 概率恢复 50 次参考裁决**（重测-信度悖论：高 test-retest 掩盖严重位置偏差）。
- **校准实务**：3 judge 异族模型 + temp=0 + JSON 约束输出 + ≥100（理想 500）条 × 逐维 kappa + 95% bootstrap 区间；judge-人 κ<0.5 说明 rubric prompt 要重写（>0.6 可接受、>0.8 强）。
- **分级尺度影响对齐**：0-5 分级尺度人-LLM 对齐最高（ICC 测量）；评分跨尺度不一致——选尺度本身是设计决策。
- 判据：可靠性测的是"κ 而非 exact match"、"多次投票而非单次"、"逐维而非聚合"；judge 上线前做最小可行验证协议（5 步）。

### 3. Eval-Driven Development 循环 + CI 门禁（工作流）
来源：qaskills-edd-2026 / arxiv-2601.22025-better-prompts-hurt / confidantai-llm-regression / rockb-agent-ci-cd / langfuse-llm-regression / divinci-regression-testing
- **EDD=先写评测再写 prompt**：Define（可测的质量要求）→ Test（对 curated 输入跑分）→ Diagnose（按类别归因失败模式）→ Fix（按诊断改 prompt/检索/模型）——把 prompt 工程从"tweak and eyeball"变成"评估驱动的迭代"。
- **一次只改一件事**：记录 baseline → 改一处 → 重跑全量（不是只跑要修的 case）→ 看两数（总分升没升 + 有无先前通过的 case 开始失败）→ 只保留"总分升且无新回归"的改动。
- **回归门禁三件套**：golden dataset（版本化）+ experiment（对每项打分）+ threshold check（聚合分过低抛 RegressionError 阻断 pipeline）；硬块=完成率降 >5pp（smoke）/ >2pp（full）/ p95 延迟超 SLO / 安全违规 >0；软警告=成本中位数 +10% 等。
- **baseline manifest**：记录精确的模型权重/prompt 模板/检索索引/judge 版本——否则分不清是模型变了还是尺子变了。
- 判据：评估单元是"metric verdict 而非输出串"（概率系统不能精确匹配测试）；门禁按 slice 跑不按聚合跑。

### 4. 评测集设计：四桶法 + 规模（可复用 Skill）
来源：futureagi-golden-set-design / koji-eval-dataset / ai-tldr-golden-dataset / genai4a11-golden-test-sets / langfuse-golden-dataset
- **四桶结构**：分层生产样本 60% / 对抗覆盖 15% / 边界用例 15% / 失败回放 10%（从每次 incident 增长）——"你标的例子"不是 golden set，要覆盖生产分布。
- **规模阶梯**：20-50=起步（核心 happy path，抓灾难性回归）；100-200=早期生产（主要任务类型+边界+少量对抗）；200-500=生产级（按主题/用户段/风险分层，统计有意义）；<100 时 90% pass rate 的 95% CI 约 ±6pp——小回归看不见；>500 边际收益递减。
- **golden 四性质**：human-verified（不是被评的同款 LLM 生成的）/ stable（期望答案不变除非故意更新）/ representative（覆盖生产输入含边界）/ versioned（Git 跟踪）。
- 判据：规模匹配任务而非最大化；先覆盖全再谈精度；数据集与 prompt 模板一起版本化。

### 5. Rubric 设计模式（可复用 Skill）
来源：vibeengines-agent-evals / arxiv-2603.00077-autorubric / arxiv-2603.21362-adarubric / exploreagentic-rubric / evalvista-metrics
- **3-7 个命名维度**（>7 judge 开始平均化混在一起）；每分给具体语言描述（5 分长什么样 vs 3 分 vs 0 分）。
- **窄刻度 + 行为锚点**：3-5 级 Likert 优于宽刻度（judge 有 central tendency bias）；binary criteria（MET/UNMET）inter-rater 最高——"helpfulness 1-10"是噪音，"是否(a)直接回答问题(b)引用来源(c)避免无据主张——各 yes/no"是信号。
- **逃生舱**：显式允许返回 "unknown"+理由而非猜；pass threshold 通常"每维 ≥4"或"加权 ≥0.7"（高利害 0.9）。
- **Adaptive rubric**：固定 rubric 对跨任务系统误评——从任务描述生成任务特定 rubric + 逐维置信加权；存逐维分（breakdown 驱动定向改进，不只存聚合）。
- 判据：rubric 是 judge 的度量契约——维度数、刻度宽度、行为锚点、逃生舱、阈值都要显式设计。

### 6. Agent 轨迹三级评测（工具）
来源：langsmith-trajectory-eval / agentscope-openjudge / agentnative-step-vs-outcome / futureagi-agent-metrics / googlecloud-adk-eval
- **三级粒度**：Final Response（端到端黑盒）/ Single Step（单步动作质量）/ Trajectory（多步路径与效率）——诊断失败用 step、优化成本用 trajectory、选型用 outcome。
- **轨迹评分陷阱**：agent "太帮忙"会多调工具（save_preferences 后又 search）→ 期望轨迹要含所有可能工具 + 极严格指令"停止后勿搜索"；或改用 rubric 而非轨迹匹配。
- **成本不对称**：step-level LLM-judged 每测试用例约 30-60x 于 outcome-only judge——workable pattern=outcome 门禁日常 + step-level 只在失败时深挖。
- 判据：outcome 判"完成了没"、trajectory 判"路径对不对"——两者要兼用，且按成本分层触发。

### 7. HITL 触发路由：六触发 + 分层抽样（工作流）
来源：futureagi-review-queues / mohith-hitl-evals / wandb-hitl-eval / jatinbansal-feedback-loops / stackoverflow-hitl / arxiv-2609.40103-juryflow
- **六触发路由**（不是 vibe）：高业务风险（无论置信度）/ 低模型置信度或低 eval 分 / 两个自动评分器分歧（真歧义）/ 用户报告问题 / 新颖输入（与 golden set 不同）/ 高危类别。
- **分层抽样**：随机内按错误分析类别分——主导类别 40% 流量不淹没长尾（长尾通常是失败集中处）；negative-feedback 抽样=每条显式 thumbs-down 或高精度隐式负反馈进队列。
- **JuryFlow**：多 judge 分歧不是要平均掉的噪声，而是 claim 级"哪里不确定"的信号——分歧导向人工，多数投票丢冲突而非解决冲突。
- 判据：人工审阅只路由触发项不审全部（审全部=人为阻塞）；分歧本身是评测信号。
