## 落地 5 独点（每点标注提升层）

### 1. 任务分解=强类型结构化计划，不是 to-do list（工具/可复用 Skill）
来源：xbstack-agent-planning / atomictaskgraph / arxiv-2601.07577-decoupled-planning / arxiv-2605.25233-meta-agent / one dayagent-arxiv-2608.05013
- **任务分解必须产出结构化 JSON**（依赖/工具映射/风险控制），不是自然语言 to-do list——"很多 demo 让模型列个自然语言清单"是反模式。
- **可验证计划**：每步有清晰 **success criterion**，不是模糊指令（"handle the issue"）。
- **Atomic Task Graph**：复合节点递归拆到叶子**原子**（一个工具调用/一个检查/一个转换）——直到每叶原子。
- **Task-Decoupled Planning**：supervisor 分解为语义连贯子任务+推断前置关系→**有向依赖图**（每节点独立规格）→**拓扑调度反复选前置满足的 ready 节点**——全局一致+独立执行。
- **Meta-Agent**：task planner 分解为 DAG 的 agent 规格（**显式 I/O 契约+验证标准**）；构造期验证触发定向再生成。
- 判据：分解产物=结构化（依赖/工具/风险）+每步 success criterion；复合节点拆到原子；并行执行按依赖图调度 ready 节点。

### 2. 计划五对象分开测量：Plausible ≠ Executable ≠ Adaptive ≠ Verified（工作流/可复用 Skill）
来源：cs-ubc-long-horizon / arxiv-2603.11445-vmao / dataaihub-planning
- **中心命题：plausible plan ≠ executable plan ≠ adaptive replanning ≠ verified completion**——计划、执行、调度、委托、终态验收**必须分别测量**；否则高 pass rate 无法指出瓶颈在哪。
- **Plan-Execute-Verify-Replan 循环（VMAO）**：DAG 子问题→领域 agent 并行执行→**LLM 评估验证结果完整性**→自适应重规划补缺口。
- **Replanning 不是可选**：工具失败/数据意外/第一计划常错——生产 agent 必须检测失败并修订。
- 判据：汇报成功率时拆成计划质量/执行质量/重规划质量/终态验收四槽；复杂查询用验证驱动循环（执行→验证→补缺口）不只一次执行。

### 3. 规划成本模型与模式选型（模型/工作流）
来源：decodethefuture-ai-agent-architecture / aiwisdom-planning-loops / myengineeringpath-agentic-patterns / bestaiweb-planning-limits
- **Plan-and-Execute 成本模型**：1 次规划+N 次执行——长任务比 ReAct 便宜 **30-50%**；planner 有全任务上下文，executor 每步清晰范围；**规划用强模型，执行用便宜模型**（分离规划与执行）。
- **ReWOO（Reason WithOut Observation）**：占位符 DAG 工具调用→并行执行→单次最终推理拼接——**~5x 更少 LLM 调用**（工具密集可并行工作流）。
- **Reflexion**：运行→批评→带批评重试——**+30% 延迟、+10-30% 质量（于失败子集）**（重复失败模式/质量敏感）。
- **Plan-and-Solve 原意**：解决零样本 CoT 三失败（计算错误/缺步/语义误解）。
- 判据：成本敏感+可分解→Plan-and-Execute；工具密集可并行→ReWOO；质量敏感重复失败→Reflexion；按延迟/成本/质量三轴选型不混用。

### 4. 计划校验与重规划：本地退回 + 滚动窗口反思（工作流/工具）
来源：xbstack-agent-planning / theneuralbase-reflection-plans / reactiveagents-reasoning
- **校验器两层**：①参数完整性与格式审查——解析每步 input_arguments，**缺必要参数（order_id）本地退回让模型重提取，不真调数据库接口**（防无效网络延迟）；②权限与高危动作拦截——规划期就拦，不等执行。
- **Replanner 保留完成步为 Checkpoint**：严重工具错误**不立即停**——错误上下文传 Replanner 动态修订剩余计划，已完成步保留。
- **滚动窗口反思**：计划 >5 步时模型丢依赖——**只反思下 2-3 步（rolling window）**而非整计划；单轮 embedded reflection 只用于 ≤5 步（每反思 =1-2 次额外 LLM 调用，100+ agent 规模变贵）。
- **Plan-Execute-Reflect-Refine**：执行→对照原计划评估→发现缺口生成修订计划重执行。
- 判据：计划先过校验器（参数/权限）再执行；缺参退回重提取不真调工具；>5 步计划滚动窗口反思；重规划保留已完成步。

### 5. 自适应规划与规划组件复用（模型/可复用 Skill）
来源：arxiv-2604.23194-adaplan-h / arxiv-2606.10507-hipif / arxiv-2605.06957-hcl-gp / arxiv-2511.20993-subgoal-tracker / arxiv-2510.23822-recap
- **AdaPlan-H 渐进精化**：先粗粒度宏计划→按任务复杂度**渐进细化**——缓解 **overplanning**（计划过度），提升成功率。
- **HIPIF 信息折叠**：显式子目标组织长时执行+**折叠已完成子目标历史**减少长上下文干扰——执行侧信息折叠（与 r404C 持久化互补）。
- **HCL-GP 组件库复用**：从成功执行**自动提取可复用组件**→组件库→组合生成策略——规划组件像代码组件一样复用。
- **subgoal tracker 双向反馈**：规划模块与执行器双向（子目标完成检测+奖励+权重更新）——规划不脱离学习进度。
- **ReCAP plan-ahead 回溯**：递归分解+**子问题失败回溯精化**——失败不只是重试，回退重规划该分支。
- 判据：复杂任务先粗后细防 overplanning；长执行折叠已完成历史；成功轨迹提炼可复用组件入库；规划与执行双向反馈。
