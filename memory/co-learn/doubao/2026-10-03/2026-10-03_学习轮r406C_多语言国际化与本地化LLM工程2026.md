## 落地 5 独点（每点标注提升层）

### 1. 跨语 RAG 四策略选型：Query Translation / 跨语嵌入 / SHIFT 偏移 / Pivot（工具/工作流）
来源：rioworld-multilingual-rag / arxiv-2504.03616-crossrag / apxml-cross-lingual-scale / qdrant-shift-multilingual / sthambh-multilingual-rag
- **Query Translation**：用户查询翻译成所有文档语言再分别检索——**recall 极高（"什么都不会漏"）但慢且贵**（5 语言=5 次索引检索）。
- **Cross-Lingual Embeddings**：**共享嵌入空间**（BGE-M3/Cohere Embed v3/Jina v3 双语语料训练、跨语语义对齐）——推荐起点；中英企业场景同源文档双嵌入+hybrid 双空间 top-k+reranker。
- **SHIFT（Semantic Harmonization via Index-side Feature Transformation）**：把每语言建模为**意义之上的固定语言偏移**——减去德语偏移向量→德语向量移到英语等价位置且保留意义放置；**索引侧变换，一个偏移拖整个语言簇对齐**。
- **Pivot Language 检索**：任意语查询→译到 pivot（常用英文）→单语检索→（可选）结果译回——用成熟单语模型。
- **CrossRAG**：检索后文档翻译到单一语言再生成——**提升准确率且不显著增加算力**。
- 判据：要极致 recall 用 Query Translation；默认基线用跨语嵌入；语种簇偏移明显时试 SHIFT；资源受限走 Pivot+CrossRAG。

### 2. 翻译质量标注进 RAG（QTT-RAG）+ 生产多语 RAG checklist（工具/可复用 Skill）
来源：arxiv-2510.23070-qtt-rag / dev-hoverbot-multilingual-rag
- **QTT-RAG**：显式评估翻译质量三维度——**语义等价/语法准确/自然流畅**——作为 metadata 附加且**不改原文**；XORQA/MKQA 六模型上优于 CrossRAG/DKM-RAG。
- **生产 checklist**：选基础语言（工具成熟度，常为英文）→**do-not-translate 术语表+术语映射**→**实体保护先于任何翻译调用**→CJK/Thai 的 **script-aware chunking**→翻译置信阈值+fallback widening→cross-encoder rerank 缩小上下文→生成侧 groundedness 验证→**并行查询的跨语评估套件**→全程日志。
- 判据：多语 RAG 把翻译质量当一等 metadata 进检索决策；本地化管线按 checklist 逐项过（术语/实体保护先行）。

### 3. 原生 prompt 非直译：直译 F1 显著衰减（模型/提示工程）
来源：csdn-locale-adaptation / github-langdrift / rasepi-think-in-english
- **实测衰减**：德语直译 F1 78.2→原生 85.6（-7.4）；日语 69.1→82.3（**-13.2**）；西语 81.5→86.9（-5.4）——**直译 prompt 是隐性质量税，需 locale 原生改写**。
- **langdrift 方法**：英文 prompt 先验证到 **3/3 pass**，再写 11 语**等价自然语言表达**——消除"基础任务本身有歧义"这一混淆变量。
- **Think in English**：最终答案本地化回去，但中间推理可用强语言——单语能力差异是**可靠性悬崖不是小波动**。
- 判据：多语 prompt 不许机翻直用——先过英文基线再逐语原生改写并测 F1；工具/结构化输出用强语言。

### 4. 工具调用跨语可靠性悬崖 + 本地化=行为验证非字符串翻译（模型/工具）
来源：rasepi-think-in-english / ajing-llm-i18n-tool-use / github-langdrift
- **MASSIVE-Agents**：52 语、47,020 样本、21 模型评估多语函数调用——**最佳平均分仅 34.05%；英文 57.37%；阿姆哈拉语掉到 6.81%**——跨语工具调用质量悬崖。
- **本地化=行为验证**：agent 的"本地化体验"只有**意图/工具选择/结构化输出跨语保持**才正确，不只是 UI 渲染成另一种语言（langdrift）。
- **GAIA-v2-LILT**：复审翻译任务提升 agent 分数——部分语言差距源于答案对齐/文化语境/难度变化，**先审计任务与答案键再归因语言**。
- **SEATauBench**：对话本地化<策略/工具/完整业务上下文本地化——分三种强度分别测。
- 判据：跨语 agent 先测工具调用分（MASSIVE-Agents 式）再谈 UI；归因前审计任务键；本地化强度=对话/工具/全业务三档分开验证。

### 5. 翻译质量评估与 QE 经济：BLEU 局限 / COMET / 后编辑成本 / QE 路由（可复用 Skill/工作流）
来源：intlpull-translation-benchmark / aiagentstore-localization-qa / multilingual-ai-glossary / futureagi-translation-quality / arxiv-2509.26601-menlo / shipi18n-uistringbench
- **BLEU 惩罚有效变体**、与人类判断相关性弱——**只宜追踪相对表现**；**COMET 神经指标更贴近人类判断但重算**；**最佳=测后编辑成本（post-edit effort）**。
- **QE（Quality Estimation）**：无参考预测质量→决定 **auto-approve / APE / 路由人工 / 拒绝**——**"没有 QE，AI-first 本地化基本靠 vibe"**（本地化经济学看门人）。
- **流式翻译**：200-500ms/chunk 预算，**COMET-Kiwi 抽样（每 20 chunk 采一次）**，完整 rubric 离线跑。
- **Menlo 原生质量四维**：语言质量与连贯/语言文化变体对齐/事实正确与本地接地/整体文风与有用性（47 语）。
- **UIStringBench**：基准语料先于评审器提交 git（228 对含 54 个植入错误）——**先有语料再有 judge，防评审器反向拟合**。
- 判据：翻译评估用 COMET/后编辑成本不用 BLEU 拍板；QE 分数驱动 auto-approve/human 路由；本地化 QA 用先于 judge 的固定语料。
