## 落地 5 独点（每点标注提升层）

### 1. OTel GenAI 语义约定与 trace 树（工具/可复用 Skill）
来源：tobias-weiss-otel-agents / openobserve-monitor-agents / zylos-agent-observability-prod / inference-llm-tracing / devops-gheware-otel-ai
- **OpenTelemetry GenAI 语义约定**：`gen_ai.*` 标准化 span 属性覆盖 LLM 调用/工具调用/agent 步骤——跨框架、跨 provider 可比；OTel 2026-05 CNCF 毕业，OTLP 成通用遥测协议。
- **trace=span 树，不是扁平日志**：**一条请求 = 一棵 span 树**（每个模型调用/工具调用/检索/框架步骤 + timing + inputs + outputs + metadata）——trace 告诉你 not just 回应了但 why 这么做；request logs 扁平（一条 HTTP 记录无关系）做不到。
- **单请求扇出 10+ 内部操作**：日志 alone 看不出哪步慢/失败/烧 token 预算；agent 结构本身记为 span（`create_agent {name}` CLIENT 类）；LangGraph 每 graph 节点与边迁移各建 span=可视化决策流。
- **自动插桩**：OpenAI/Anthropic/LangChain/LlamaIndex 已有 auto-instrumentation 包——几行设置即出 spans；跨 agent 节点 context propagation 是调试多步工作流关键。
- 判据：agent 上 OTel 插桩先于规模化；用 trace 树（非日志）定位慢/失败/烧 token 步骤；指标/日志/trace 三层一起看。

### 2. Agent 调试循环：Detect→Attribute→Recover→Rerun（工作流/可复用 Skill）
来源：arxiv-2607.18754-agentdebugx / respan-agent-debugging / developersdigest-debug-agent
- **AgentDebugX 调试闭环**：Detect（识别可观测失败+关联结构化失败模式）→ Attribute（回溯到"改哪个 agent/步骤最有效"）→ Recover → Rerun——先把框架特定事件转成**可移植轨迹表示**再调试。
- **五 bug 形状覆盖大部分生产失败**：stuck loops / hallucinated tool arguments / lost context / wrong-path planning / silent degradation across deploys。
- **print 调试对 agent 无效**：agent 非确定性多步决策——print 只显示一次运行的一条路径；**需要树**（整棵轨迹）。
- **trace span 必备八字段**：model name + prompt hash + tool name + full arguments + full result + token counts + latency + error mode——**缺任何一项=该 span 无法归因**。
- 判据：调试从 trace 树入手不靠 print；新失败先归类到五 bug 形状再归因；span 八字段齐了才算有效观测。

### 3. 时间旅行回放与 trace 签名失败识别（工具/工作流）
来源：zylos-workflow-replay / learn-ms-agent-replay / zylos-trace-driven-debugging / aws-debugging-agentcore / befailproof-session-replay
- **滞后失败需要回放**：bug 在 step 12（畸形 API 响应静默污染 working memory）只在 step 47 显现——**把每次执行当事件日志**：可倒带、可分叉、可任意中间点重执行（event sourcing + time-travel debugging）。
- **确定性回放**：debug 环境产生与生产**完全相同行为**——断点设 agent 边界、检查上下文状态、注入不同工具响应；时间旅行调试=暂停→检查→回退到早期状态。
- **trace-driven 回归**：生产事故→trace 签名→回归测试（事件驱动的调试闭环）；**Retry Loops（Token Burner）签名=连续相同/近似相同工具调用 span + 累计 token 上升无进展 + reasoning span 无适应**——从 trace 直接识别，生产表现为成本尖峰+超时。
- **三层可见性**：metrics/traces/structured logs 三层一起（AWS AgentCore）——跟随推理步、检查工具调用、定位偏离点，即使无显式错误。
- 判据：长任务每步留事件日志可回放；重试环用 trace 签名自动告警（相同调用+token 上升无进展）；生产事故先转回归测试再修。

### 4. Eval-to-guardrail 生命周期与失败四桶（工作流/可复用 Skill）
来源：galileo-eval-guardrail / latitude-llm-failures / futureagi-evaluating-genai-prod / galileo-eval-framework / ailearningguides-observability-evals
- **Eval-to-guardrail 四阶段**：**Evaluate**（离线 eval 数据=test fixtures，覆盖核心场景+对抗场景）→ **Codify**（eval rubric/阈值转成运行时策略）→ **Enforce**（拦截 agent 输入输出）→ **Monitor**（连续反馈）——**离线评估标准转成生产拦截策略**。
- **失败四桶**：ops / quality / structure / safety——每 issue 绑定 traces + live scoring + review + alerts + regression tests；**HTTP 200 ≠ 工作**；用**小标签集**（hallucination/truncation/timeout/rate_limit…）命名失败。
- **五层并行评估**：CI evals（deploy 前）+ online evals（live traffic）+ inline safety guardrails + drift monitoring（跨时间）+ trace-level observability——五层并行不是选一。
- **offline vs 生产监控**：offline=固定数据集质量门；生产=连续捕获 drift/emerging patterns/edge cases；**两环境用相同 metrics+thresholds**；eval 三分层=offline（deploy 前）/online（sampled traces 连续）/continuous（每个相关事件）。
- 判据：离线 eval 标准 codify 成生产 guardrail；失败按四桶分类+小标签集；评估分层跑全（offline+online+continuous）。

### 5. 生产实时指标与行为+推理监控（模型/工具）
来源：futureagi-real-time-monitoring / fiddler-llm-metrics / mlflow-llm-tracking / dev-llm-observability-platforms
- **六指标承载真信号**：**Eval pass-rate**（faithfulness/groundedness/task completion/plan adherence，滚动 5 分钟窗口=领先质量指标）/ **Hallucination rate by topic and persona**（按主题细分捕获 knowledge-cutoff 失败——聚合指标会平滑掉）/ Latency p50/p95/p99（first-token+full-completion 分开）/（token 成本/错误率/安全率）。
- **TTFT 感知**：**5s TTFT 即使 8s 完成也感觉慢；500ms TTFT 即使 10s 完成感觉快**——TTFT 按 P50/P95/P99 分位测，同时测 tokens/sec（吞吐）与 full-completion。
- **行为+推理监控结合**：**同时做 behavioral monitoring 与 reasoning（trace/chain-of-thought）monitoring，威胁检测准确率提升 35%**（对比只做行为监控）——推理痕迹是安全信号不是噪声。
- 判重边界：与 r402B 的分工——那条管**开发期**评测工程（Golden Set/离线 vs 在线），本条管**生产期**实时指标与 guardrail 集成。
- 判据：生产监控五层并行；eval pass-rate 滚动窗口做领先指标；hallucination 按主题/角色细分不聚合；TTFT 与全完成延迟分开测分位；推理+行为双层监控。
