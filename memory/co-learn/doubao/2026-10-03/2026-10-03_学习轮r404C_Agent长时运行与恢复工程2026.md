## 落地 5 独点（每点标注提升层）

### 1. Durable execution 运行时模式：每步持久化+精确恢复（工具/可复用 Skill）
来源：learn-ms-durable-task / langchain-runtime / pypi-duralang / dailyaiworld-ai-sdk7 / zylos-durable-execution / diagrid-durable
- **durable execution=每完成一步即持久化**——崩溃/重启/宕机后从**最后完成持久步骤**重建恢复，不是从零重跑。
- **Temporal replay event history**：进程死（OOM/硬件/部署）Temporal 仍持工作流——重启从精确失败点恢复，**已执行步骤不重执行**。
- **Durable Task 自动 checkpoint**：每个状态转换（LLM 响应/工具调用结果/控制流决策）写持久存储——**已完成的 LLM 调用不重跑=省 token 与墙钟时间**。
- **LangGraph 超步 checkpoint**：每 graph 超步写 checkpoint（PostgreSQL 默认），thread_id=持久游标；run 可 retried/replayed/resumed from exact interruption point；支持 indefinite interrupts（human-in-the-loop 暂停恢复）。
- **AI SDK 7 WorkflowAgent（Vercel）**：每个工具调用包装为持久化可重试步骤——崩溃/回滚/重启从最后完成步骤恢复零数据丢失。
- 判据：长任务用带自动 checkpoint 的运行时（Temporal/Durable Task/LangGraph），不自己写状态管理；恢复语义=从最后完成步骤继续而非重跑。

### 2. 记忆≠执行状态保护：崩溃恢复的真实边界（模型/工作流）
来源：dev-agdex-durable / intuitionlabs-long-running-agents / slavadubrov-runtime / diagrid-durable
- **对话记忆只解决会话回忆，不保护执行状态**：进程崩溃在 11 步迁移工作流第 7 步——memory 无法恢复 active call stacks / pending async futures / 调用栈。
- **in-memory saver 陷阱**：LangGraph in-memory saver 进程重启即丢 checkpoint——生产必须持久化 saver（Postgres/Redis）。
- **可恢复会话的持久记录必须含全部已发生内容（不只最终答案）**——否则下一个 worker 只能从零重放；模型上下文窗口满需压缩/续跑机制。
- **非确定性长任务不能从头重跑**：50 步推理 agent 丢进程=丢工作丢钱——**重跑不会产生相同路径**。
- 判据：恢复设计针对执行状态（调用栈/未完成操作/中间结果）而非仅对话记忆；生产用持久 saver 不用内存；长记录写全量事件不只终态。

### 3. 写操作三分法 + 副作用补偿（工作流/可复用 Skill）
来源：tencent-cloud-state-persistence / aws-agentrel03-idempotency / moai-durable / brightlume-durable
- **写操作三分**：**read**=纯读，重试永远安全；**idem_write**=幂等写（带幂等键的创建/更新），重试安全——前提是**下游真的认幂等键**；**non_idem_write**=非幂等写（发消息/发起审批/触发通知），**重试不安全需手动补偿**。
- **无幂等保证的 checkpoint 恢复是危险的**：外部调用需幂等键、状态变更需条件写、事件发射需去重逻辑——三条缺一不可。
- **副作用补偿**：非幂等写失败后手动补偿（如通知发了两次→补偿撤/改状态），不靠盲目重试。
- **重试逻辑在长任务里是可靠性分水岭**：10 分钟直连工具/写数据/花钱——重试逻辑=可恢复小故障 vs 坏工作流的差别。
- 判据：每个外部副作用标三分类型（read/idem_write/non_idem_write）；重试安全仅限前两类；非幂等失败进手动补偿队列。

### 4. 幂等键 per logical action + 租约防双跑（工具/工作流）
来源：moai-durable / brightlume-durable / learn-ms-resilience / aws-agentrel03-bp03
- **幂等键按逻辑动作而非每次尝试**：自然键优先（"invoice for order-123"）；上游无去重能力时自己维护 dedup cache。
- **双身份设计**：**work identity**（逻辑任务/多轮对话）+ **input identity**（其中一轮输入）；handler 启动前持久化输入并获取 **lease**，运行中续租，进程停止放弃租约→**后续进程 reclaim 记录并以相同身份+输入调 handler**——租约机制防双跑。
- **幂等步骤=同输入跑一次与五次同结果**——重试/恢复不添重复副作用。
- 判据：幂等键稳定按动作生成（不每次新建 UUID 当尝试 ID）；长任务加租约/心跳防双 worker 同时执行；恢复前验证步骤幂等性。

### 5. 错误发生后恢复：回退与部分进度评估（模型/可复用 Skill）
来源：arxiv-2608.14380-agentrewind / cloudflare-durable-execution / cloudflare-project-think / octagono-durable-meta-agent / learn-ms-crash-resilient
- **AgentRewind=错误发生后恢复而非只预防**：已有方法主要靠 plan refinement/safety checks **减少错误**，错误发生后支持少——AgentRewind 记录 agent context+环境对齐 checkpoint，**允许回到更早状态并以之前尝试的信息恢复执行**。
- **MettleBench**：长时工程任务基准——**任务完成与部分进度分开评估**（失败不全是零，部分完成有分）。
- **Cloudflare fibers**：`startFiber()`=持久接受后台工作+快速返回+安全去重重试+稍后查状态+可取消+自动 keepalive——**周/月级 agent 的持久原语**。
- **迭代计数持久化**：`last_completed_iteration` 存 Redis——崩溃在迭代 17/25，下次读 16 从 17 续跑，零数据损失零重复工作。
- 判据：长任务支持回退到更早 checkpoint 再续跑（不只从头/只从最后）；评估长任务给部分进度分；后台长跑用可取消+自动 keepalive 的持久原语。
