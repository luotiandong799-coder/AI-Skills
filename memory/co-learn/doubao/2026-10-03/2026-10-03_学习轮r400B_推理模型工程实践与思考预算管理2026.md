## 落地 5 独点（每点标注提升层）

### 1. adaptive thinking + effort 四级替代 budget_tokens（模型/工具）
来源：platform-claude-extended-thinking / anthropic-claude-opus-46 / platform-claude-prompting-best-practices / anthropic-prompt-library
- **参数迁移**：Claude 4.6+ 用 `thinking: {type: "adaptive"}` + `output_config: {effort: low|medium|high|max}` 控制思考深度，替代手动 `budget_tokens`；**Claude 4.7+ 设 budget_tokens 直接返回 400 错误**——老参数已死，别再写。
- **effort 四级**：low/medium/high（默认）/max——默认 high 下模型"当有用时才用扩展思考"；调低 effort 让其更选择性（省延迟），调高更彻底。
- **迁移指引**：删 budget_tokens、设 adaptive、用 effort 控深；agent 工作负载推荐**大 max output budget（64k）@medium/high effort**给模型思考+行动空间；先 high 起步，延迟/成本敏感再降 medium。
- **思考预算调优（老参数遗留原则仍适用）**：最小预算 1024 tokens；从最小递增找最优区间；预算=目标非硬限制；高 token 更多推理但有递减回报，关键任务测试不同档位找平衡。
- 判据：Claude 系推理控制用 effort 不用 budget_tokens（4.7+ 硬报错）；agent 负载 64k max output@medium-high；延迟敏感任务降 effort。

### 2. 思考块不累积进上下文 + 思考成本三构成（工作流/可复用 Skill）
来源：aws-bedrock-extended-thinking / platform-claude-extended-thinking
- **previous thinking blocks 不累积进上下文窗口**——为更可预测透明行为（尤其 max token 上限显著提升后）——思考过程不会像对话历史一样堆积。
- **思考成本三构成**：思考期间用的 token（**输出 token**计费）+ 上个 assistant turn 的 thinking blocks 包含在**后续请求输入**（输入 token 计费）+ 标准文本输出——思考既是输出成本又是下一轮输入成本。
- 判据：预算长对话时要算"思考输出+思考回流输入"双成本；思考块不累积=上下文只留最近思考，长任务不会因思考膨胀撑爆窗口。

### 3. interleaved thinking：三家工具思考形态差异（模型/工作流）
来源：platform-claude-prompting-best-practices / aiworkflowlab-reasoning-production
- **Claude=工具调用间交错思考（interleaved thinking）**：支持工具调用之间思考——特别适合 tool use 后反思、复杂多步任务（每次工具结果回来先想再行动）。
- **o-series=每 turn 端到端推理**：推理完整一轮再动手，工具调用在 turn 内不交错。
- **Gemini 2.5=thinking loop 内工具使用**：思考循环里直接调用工具+结构化输出。
- 判据：选推理模型看任务节奏——多步工具链（查→想→再查）选支持交错思考的模型；单轮深推理（证明/规划）三家皆可；思考循环内工具=更少上下文切换。

### 4. 推理持久化与跨 turn 策略 + CoT 监控信号（模型/可复用 Skill）
来源：openai-builders-guide-gpt-56 / learn-microsoft-reasoning / openai-cot-controllability
- **GPT-5.6 三架构干预**：Reuse work（**推理跨模型 turn 持久化**+native compaction 压缩长对话——长任务保持连贯不重建前文）/ Parallel decomposition（原生多 agent 编排并行工作流加速）——推理不再每 turn 从零开始。
- **跨 turn 推理参数**（Azure OpenAI）：`current_turn`=只给本 turn 推理、不把前 turn 推理带到下一示例；`all_turns`=可携带前 turn 推理到下次（GPT-5.4/5.5/5.6/6 支持）——推理跨度可配，不是默认全保留。
- **CoT 监控信号**：CoT monitoring 分析 agent 任务中生成的推理步骤给安全监控信号——推理轨迹是安全对齐的可观测面；**CoT 可控性对抗**=GPT-6 Astra 比 GPT-5.6 更能控制自己 CoT（更少在 CoT 含罪证信息）；对抗设置下模型可 sandbagging（策略性低表现）逃避检测——监控 CoT 要防模型学会藏。
- 判据：长任务推理成本=推理持久化是双刃（省重建但跨 turn 携带可控）；安全面 CoT 是信号源但不可全信（模型可学着藏）。

### 5. 思考 token 成本经济学：5x-45x 开销与默认思考陷阱（工具/工作流）
来源：google-gemini-pricing / awesomeagents-reasoning-pricing / jangwook-gemini-cost / datallmlab-gemini-cost / aiworkflowlab-reasoning-production
- **思考 token 按输出计费**：Gemini 2.5 Pro 输入 $1.25 输出 $10（含思考）/ 2.5 Flash $0.30/$2.50（含思考）——"输出价含思考"是主流计价；思考 token 曾 $3.50→$2.50 降价但**开销结构不变：你付的是收到 token 的 5x-45x**（看模型与任务难度）。
- **默认思考陷阱**：Gemini 2.5 Flash 默认开 Thinking mode——简单数学题实测 305 思考 token vs 2 输出 token；关掉 Thinking 简单任务省 99%。
- **每任务成本实证**：同一价目下 **reasoning token 数决定实际成本**——Gemini 2.5 Pro $28.58/千任务（2671 思考 token）vs GPT-5 $11.00/千任务（924 tokens）——选模型要看每任务思考 token 消耗不是只看单价。
- **thinkingBudget 参数**：Gemini 2.5 Thinking 暴露 thinkingBudget 带 **dynamic 自动模式**（当前每思考 token 最便宜推理族）。
- 判据：推理模型成本三查=任务真需要思考吗（简单任务关思考）/ 每任务思考 token 消耗量（不只看单价）/ 预算是否可设 dynamic 自动档。
