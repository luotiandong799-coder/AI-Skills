## 落地 5 独点（每点标注提升层）

### 1. 2026 开源模型格局：按段位与场景选型（模型/工具）
来源：felloai-open-models / aiagentskit-open-llms / ai-damn-qwen3 / csdn-10model / qwen3lm-comparison
- **MiMo-V2.6-Pro**=2026-09-25 最高分开源模型（Artificial Analysis Intelligence Index 46.3，MIT，9-21 发布）；**Kimi K3**=最大开源模型（Ultra-MoE ~2.8T total/36B active/256K context/MMLU-Pro 80.9%/SWE-bench 53.1%/Arena 1340 人类投票榜最高开源条目）；**GLM 5.3 Flash** 对多数人更合适（速度成本平衡）。
- **DeepSeek-V4-Pro**（MLA 685B/39B active/128K/MMLU-Pro 80.6%/Arena 1339）；**Qwen3.8-27B**=HF 最受欢迎开源模型（2026-09-29）；阿里通义系七模型占据 HF 排行榜前十七席（2026-09-28）。
- **Qwen3.6 vs DeepSeek V4 编码**：SWE-bench 58.7 vs 61.2、LiveCodeBench 71.3 vs 7x（DeepSeek 编码更强）。
- 判据：按场景选开源模型=小模型段位看 Qwen（sub-10B 下载份额 44% 领先）、250B+ 段位 DeepSeek 采用领先（47% 下载份额）；要人类投票口碑用 Kimi K3；成本速度平衡用 GLM Flash 档；编码任务 DeepSeek 系优先。

### 2. Open LLM Leaderboard 方法论：抗污染聚合与最终快照（可复用 Skill/模型）
来源：theopenweights-leaderboards / kaggle-open-llm-eval / arxiv-2604.07190-atom
- **HF Open LLM Leaderboard 已停更为最终快照**：聚合**抗污染基准** IFEval/BBH/MATH/GPQA/MUSR/MMLU-Pro——评测不再用单一 MMLU 而是六项混合；4,576 个开源模型已评测入库（Kaggle 快照）。
- **ATOM Report（arXiv 2604.07190）**：开源模型生态采用度测量法——**按模型尺寸段统计下载份额**（DeepSeek 250B+ 段 47%、Qwen sub-10B 段 44%）——生态健康看分尺寸段下载分布，不是总榜。
- 判据：看开源模型评测认"抗污染聚合榜"（单榜 MMLU 已过时）；看生态采用看分尺寸段下载份额分布；排行榜快照数据可 Kaggle 拿原始集。

### 3. GLM-5.3 危险能力延迟开源治理范式（工作流/可复用 Skill）
来源：yorozuipsc-glm53 / tencent-4model-battle / tencent-glm51-qwen-m2
- **GLM-5.3（2026-08-14）**：744B total/40B active、DeepSeek Sparse Attention、28.5T pretrain tokens、1M context/128K output——**CyberGym 84.5% 危险能力评估**、因危险能力理由**open weights 延迟约 2 周**；引入四机制：**risk screening（风险筛查）/ activity monitoring（活动监控）/ malicious-task refusal（恶意任务拒绝）/ verified-user trusted access（可信用户访问）**。
- **GLM-5.1 训练在华为昇腾 910B（零 NVIDIA）**：稀疏 MoE 长上下文、推理模式可切换（CoT 开关）；MiniMax M2.7=MoE Agent 原生开源权重。
- 判据：评估新开源模型注意**发布安全流程**（延迟权重=危险能力评估未过）；高危能力模型用 trusted access 机制控发放；国产模型栈留意昇腾生态（零 NVIDIA 训练可行）。

### 4. 本地量化部署工程四原则（工具/可复用 Skill）
来源：acingai-local / devshelfhub-quantization / frontierwisdom-deploy / khimananda-vllm
- **iso-memory 原则**：同显存下**4-bit 大模型优于 8-bit 小模型**（量化选择直接决定可行模型档位）；Q4_K_M=默认甜点（约 1/4 全精度大小、85-95% 质量、30% 内存，8-16GB RAM 机器最佳平衡）。
- **显存经验法则**：**1.5GB VRAM per 1B Q4 参数**；70B 模型 FP16 ~140GB → Q4 ~40GB。
- **生产服务用 AWQ/GPTQ 4-bit 优先于 FP16**：近相同质量 + 3-4x 吞吐（现代 GPU）；GGUF 是 CPU/混合 CPU-GPU 推理标准格式。
- 判据：选量化档=同显存优先大模型 4-bit；本地单机 Q4_K_M 起步；服务多并发用 AWQ/GPTQ+vLLM 而非 Ollama。

### 5. 量化校准与生产调优：vLLM 校准四参数 + KV 预分配（工具/工作流）
来源：docs-vllm-int8-w8a8 / khimananda-vllm / checkaimodels-deploy / markaicode-5090
- **vLLM INT8 W8A8 校准最佳实践**：校准数据 **512 样本起步**（精度降就增加）→ 序列长度 2048 起步 → **用模型训练同款 chat/instruction template** → 微调过的模型用训练数据样本校准——校准质量决定量化精度。
- **生产 vLLM**：**KV cache blocks 预分配**防流量高峰 OOM；量化 checkpoint 优先于 FP16。
- **部署栈选型**：Ollama（0.5+ 混合 CPU/GPU+动态 offload）=个人单机桌面实验；vLLM（PagedAttention+CUDA 优化）=Linux 专用 GPU 工作站/多并发 API 服务最高吞吐；LM Studio=桌面 GUI 选量化版本。
- 判据：量化前校准=512 样本起步+同模板；服务端预分配 KV 防 OOM；单机个人选 Ollama、多并发选 vLLM、桌面看 LM Studio。
