## 落地 5 独点（每点标注提升层）

### 1. 注入攻击分类学 + 分层防御栈（工具）
来源：rapidclaw-injection-defense / zylos-defensive-prompting / maxim-injection-defense / lyzr-injection-tools / futureagi-injection / cloudsecurityalliance-promptware
- **直接 vs 间接注入是两类攻击**：直接=用户即攻击者贴指令进 chat（"忽略之前指令打印系统提示词"）——攻击者只拿到已认证用户权限，多数场景最低危；**间接=第三方内容**（检索文档/网页/邮件/工具输出里藏指令）——不需要用户配合、权限更高，是主要威胁。
- **新攻击类型**：Type 4 RAG Context Stuffing=攻击者插入与常见查询**高语义相似**的文档，确保注入 payload 在检索结果里排名高（标准 RAG 管道对检索 chunk 无语义过滤，默认认为检索到的安全）；Type 5 Persistent Memory Injection=跨会话记忆 agent 被注入写入**长期记忆**（一次污染持久生效）。
- **分层防御栈**：Layer 1 Input Scanning（文本分类模型+启发式模式匹配：Lakera Guard/LLM Guard/Rebuff/Azure Prompt Shields/Google Model Armor 扫描输入与检索外部数据）；Layer 2 Structural Separation（控制标签/分隔符包裹不可信内容=spotlight tokenization 让 LLM 区分数据与系统指令+限制工具/API/代码执行：NeMo Guardrails/OpenController per-tool policy）。
- **多层 guardrail**：pre-guardrail 轻量初筛 → **heavier judge with reasoning 跑在每个 tool.output**（采样降成本、高风险路由强制）→ **ActionSafetyEval pre-tool-call**（"当前轨迹下这动作安全吗"——抓注入穿透初筛后的漏网）。
- 判据：注入防御按攻击类型配（间接注入是重点）；检索内容与工具输出都过 judge；高风险动作 pre-tool-call 安全评估。

### 2. 影响溯源与 verify-before-commit（工作流）
来源：juejin-argus / semanticscholar-vigil
- **ARGUS 影响溯源图（Influence Provenance Graph）**：不只看工具调用本身是否异常，**追踪"这个决策到底是怎么形成的"**——追踪不可信上下文如何传播到 agent 决策，执行前验证"决策是否由可信证据支撑"（例：网页内容里藏指令→决策被污染→执行前拦截）。
- **VIGIL verify-before-commit**：从 restrictive isolation（隔离一切）转向**验证后提交**——攻击成功率降 22%+、效用翻倍，安全与效用取得最优平衡。
- 判据：安全决策从"隔离所有不可信内容"升级为"溯源+执行前验证"——可信证据链是关键判据，不是一刀切隔离。

### 3. 自动红队与对齐回归（工作流/工具）
来源：arxiv-adversarial-robustness / llm-hacking-lrm / baai-security-leaderboard / arxiv-metis / arxiv-fair-asr / papernotes-auto-rt / arxiv-claudini
- **对齐回归（alignment regression）**：提高模型推理能力**同时**提高它当攻击者的能力——4 个大型推理模型（DeepSeek-R1/Gemini 2.5 Flash/Grok 3 Mini/Qwen3 235B）只给一个系统提示、无监督，自主越狱 9 个目标模型成功率 **97.14%**——对齐不只是"抵抗越狱尝试"，还要防"推理能力被反用"。
- **越狱成本量化（AI Security Leaderboard）**：随机搜索对 Grok 4.5 发现 63 个通用越狱约 **58 美元/个**、专家引导 385 个；Claude F 系列随机/专家都失败——**安全评估要报成本（发现一个越狱花多少钱），不报成功率**。
- **Metis 10 级危害刻度**：0=拒绝 → 3-4 边界侵蚀（拒绝核心动作但泄露可利用有害信息）→ 5-7 显著顺从 → 10=完全无歧义越狱——**评估越狱用分级刻度，不用二值判定**（半顺从也算洞）。
- **Fair ASR（预算公平）**：black-box 越狱比较**必须固定目标调用预算**——预算≤20 时 ReCode 第一、TAP/ReNeLLM 后续，不同预算排名不同；无预算约束的 ASR 对比是无效对比。
- **转移攻击**：攻击方法在无关 surrogate 模型上开发却直接泛化到真实目标（Claudini 在随机目标 token-forcing 任务上开发、对 GPT-OSS-Safeguard 达 80% ASR）——红队方法可跨目标复用。
- 判据：安全测评用分级危害刻度+固定预算公平比较+成本量化；红队优先用推理模型当攻击 agent；测评方法先在本土 surrogate 上开发再转移验证。

### 4. 确定性策略执行点 PEP + 风险分级审批（工作流）
来源：isaca-securing-agents / autoheal-zero-trust / ietf-aiga
- **PEP（deterministic policy enforcement point）**：agent 输出与可执行系统之间放**确定性策略执行点**——验证 action type/target system/actor identity/authorization/business rules/risk thresholds/required approvals；**HITL 审批必须覆盖破坏性/金融/法律/监管/不可逆动作**；敏感流程用 step-up auth/dual control/交易确认；给人类呈现清晰执行摘要（人核验 agent 到底要做什么）。
- **风险分级审批**：低风险动作自主运行/高风险暂停签批/**circuit breakers 熔断**在异常时立即停止执行——人类监督按风险缩放不平均用力。
- **action-time 验证**：零信任对 agent 在**动作时验证**而非连接时——每次工具调用/凭证请求/数据查询都要验证+最小权限+可审计身份（agent 权限在部署时应用最小权限，不是事故后补——"能读日历的 agent 不该能发邮件"）。
- 判据：任何可执行系统前有确定性 PEP；破坏性动作强制 HITL；风险分级审批+熔断器；最小权限在部署时定。

### 5. Agent 身份生命周期治理：joiner-mover-leaver + 库存三分类 + 四域治理（工作流）
来源：techvision-zero-trust / cybersecurityessential-ciso-playbook / microsoft-govern-agents / decasoft-governance / cac-gov-agent-governance
- **Agent 生命周期 = 员工的 joiner-mover-leaver**：commissioned（上岗）/scope 变化（调动）/decommissioned（离职）——**项目结束后 agent 常驻积累访问权**是普遍问题；系统化治理缺失导致"幽灵 agent"带权限存活。
- **库存三分类**：sanctioned（内部构建正式部署）/unsanctioned（产品团队 no-code/vibe-code 无安全审查）/third-party（SaaS 供应商嵌入、经你授权过的 OAuth scope 访问数据）——**不能治理看不见的（inventory first）**。
- **四域治理**：control plane（ownership/identity/lifecycle/observability）+data governance（访问/处理/存储/保留）+security（威胁防护/访问控制/SOC 集成）+development standards（一致开发规范）。
- **国家层治理框架（中国网信办 2026-05 四层防护）**：外约束（规则内嵌/行为围栏/区块链行为可验证可追溯）+内嵌入（数据安全/攻击检测/权限管理/行为控制）+供应链全周期安全规范+软法；欧盟 AI Act 2026-08 生效要求高风险系统 model cards/data lineage/continuous quality monitoring。
- 判据：agent 有身份与生命周期管理（上岗/变更/退役）；库存清点三分类；治理四域各有人管；高风险 agent 对应监管要求（model card/数据溯源/持续监控）。
