## 落地 5 独点（每点标注提升层）

### 1. 语音 Agent 三级管线与流式架构（工具/工作流）
来源：retellai-real-time-voice / assemblyai-voice-architecture / evalgent-voice-stack / ijarcce-callmind / arxiv-2508.04721-voice-telecom / arxiv-2603.05413-voice-tutorial
- **STT→LLM→TTS 三级链是 2026 主导架构**：完整栈五层=STT/LLM/TTS/**orchestration/telephony**——每层独立 provider/成本/失败模式，调试按层定位；CallMind 实测（Azure 流式 STT+Groq LLaMA 3.3 70B+Azure Neural TTS）端到端约 **780ms**。
- **流式重叠降感知延迟**：每个完整句立即送 TTS 而 LLM 继续生成；TTS `stream()` 边合成边返回音频块（ElevenLabs eleven_turbo_v2_5）——**TTFA 被有效缩短，不等整段合成**。
- **完整管线**：音频 16kHz mono 捕获→**VAD（Voice Activity Detection）检测说话停止做轮次判定**→LLM→逐句流式 TTS。
- **电信低延迟变体**：流式 ASR+**4-bit 量化 LLM**+RAG 文档+实时 TTS——量化是语音管线省延迟的标准手段。
- 判据：建语音 agent 按五层拆（每层独立预算/监控）；TTS 必须流式（逐句边生成边播）；轮次判定交给 VAD 不靠静音阈值猜。

### 2. 语音延迟预算表：自然/可感知/破碎三带（工具/工作流）
来源：zylos-turn-taking / bitbytes-voice-latency / futureagi-sub-500ms / softwareseni-latency-benchmarks / softcery-latency-budget
- **人类感知三带**（跨 10 语言研究，句间间隔约 200ms）：**200-300ms 自然；~500ms 可感知；800ms-1s 用户开始盖过 agent——多余延迟制造假 barge-in；>1.5s 对话破碎**（用户重复/打断/转 DTMF/挂断）。**行业共识：sub-500ms TTFA 是生产底线，premium 冲 sub-300ms**。
- **四段预算表**（sub-500ms 目标）：LLM TTFT 200-300ms（前缀缓存+模型大小，GPT-4o-mini/Claude Haiku/Gemini Flash）；TTS first-audio 80-150ms（Cartesia Sonic/ElevenLabs Turbo v2.5）；orchestration 20-40ms；inline guardrail 50-80ms。
- **平台基准口径不可直接比**：Retell ~600ms 端到端（200+ 生产通话、$0.07/min）vs Twilio=STT 350+LLM 375+TTS 100=1115ms（限 1400ms）vs Telnyx 600ms-1.7s——**读基准先看测量口径（从哪到哪、是否含网络）**。
- 判据：语音产品预算按四段分配并逐段监控；目标 <500ms TTFA（消费级 <400ms、互动容忍 <500ms 三档）；跨平台对比前先核对口径。

### 3. 打断处理与假打断防御（工作流/可复用 Skill）
来源：growwstacks-awkward / aiagentcafe-300ms / zylos-turn-taking / genai4a11-voice-agents
- **假打断根因**：VAD 把 backchannel（"okay"/"got it"/在听信号）当打断→agent 说到一半停下，双方尴尬沉默——**VAD 无法区分"插话"与"在听"**。
- **修复=转录式打断检测**：等 **2+ 个可识别词**才判定打断 + **backchannel 忽略清单**——假打断降 **30-50%**（领先平台实践）。
- **真打断处理三步**：检测到语音 **~100ms 内杀掉 TTS 播放**、flush 排队音频、**跟踪"实际听到 vs 已生成"**——对话状态不得包含用户没听到的 claim。
- **人类 200ms 句间间隔**是轮次调参锚点——VAD 阈值与打断窗口都按它校准。
- 判据：打断判定用转录+词数门槛而非纯 VAD；backchannel 清单必须维护；打断后状态只保留用户真实听到的内容。

### 4. 全双工安全与语音评估（模型/可复用 Skill）
来源：evalgent-full-duplex / arxiv-2604.04847-full-duplex-bench / nvidia-video-fdb / aiagentcafe-300ms
- **打断是注入向量**：AdvBench 上固定延迟打断把攻击成功率抬到 **40.3%（PersonaPlex）/48.7%（PersonaPlex-RL）**——比基线高 33.8/39.3 点——**全双工=更大的攻击面，语音是文本 eval 完全测不到的**。
- **语音评估=时序+正确性一起在音频上测**：文本 eval 漏掉重叠/打断；纯时序基准漏掉"是否做对了事"。
- **Full-Duplex-Bench-v3 延迟三件套**：①First Response Latency（任何语音含 filler"Let me check on that"）②Tool Call Latency（首次 API 调用）③Task Completion Latency（事实答案）——三个延迟分开测，filler 不算完成；GPT-4o 分析 ASR chunks 隔离信息句与 filler。
- **VideoFDB（NVIDIA 全双工视觉-语音）**：Conversational Flow 人 4.20 vs 闭源 AV2A 2.20-2.81 vs 最佳 MiniCPM-o 4.5 3.54；人 90% TOR-Alignment 1.4s vs 最佳模型 73%/720ms；**级联延迟约 2.8x**。
- 判据：语音 agent 安全测试必须含打断场景（打断窗口可被恶意利用）；上线前跑 Full-Duplex 类基准（三延迟分开报）；"说对了"与"说快了"是两个指标。

### 5. 原生多模态交互模型（模型/工具）
来源：dataforcee-interaction-models / arxiv-2606.25041-wan-streamer / arxiv-2607.04443-wan-streamer-v02 / callsphere-llm-latency / skill4agent-parlor / mer-vin-qwen3-8-omni
- **Interaction Models（Thinking Machines Lab）**：原生多模态实时架构——**200ms 输入块与 200ms 输出块连续交错处理**（不消费完整 turn）——模型能**边说边听、对视觉线索即时反应、真同时说话、对话中调工具上网**。
- **Wan-Streamer**：端到端流式交互基础模型——单 Transformer 交错视觉/音频/文本输入输出 token，**block-causal attention** 增量生成；160ms 单元同步（处理观测+更新状态+生成语音视频 latent+解码上一单元）；350ms 网络预算下远程交互延迟约 **550ms**。
- **首响应延迟榜（2026-05）**：xAI Grok Voice 0.78s（最快）→ OpenAI gpt-realtime-1.5 0.82s → Amazon Nova 2 Sonic 1.14s → Gemini 3.1 Flash Live 2.98s——**语音 LLM 选型看 TTFA 不看通用榜**。
- **端侧多模态**：Parlor=Gemma 4 E2B+Kokoro TTS 全本地（FastAPI WebSocket，无 API key）；Qwen3.8 Omni Flash=单模型文本/图像/音频/视频——端侧语音成 2026 新档位。
- 判据：实时多模态选原生流式模型（interaction model 类）而非级联；"边说边听+对话中工具调用"是下一代语音产品分水岭；预算敏感场景看 TTFA 榜+端侧模型。
