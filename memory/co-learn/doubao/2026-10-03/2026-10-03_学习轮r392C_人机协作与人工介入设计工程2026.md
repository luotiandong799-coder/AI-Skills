## 落地 5 独点（每点标注提升层）

### 1. 拒绝路径设计 + fail-closed 超时 + 审批时序十步（工作流）
来源：waxell.ai / praesidia.ai / gingerlabs.ai / DZone
- **拒绝路径要先于队列设计**：异步审批的硬问题是拒绝恢复——agent 等审批时已做其他假设"审批通过"的动作，人类拒绝后恢复路径是什么；**map 拒绝场景再建队列，不能 retrofit**；大多数团队只测 happy path，reject 和 timeout 路径才是生产事故点。
- **审批超时=自动拒绝（fail-closed）而非自动批准**，再配升级路径（主审批人不可用→次级）；批准无人应答=stale decision，绝不静默重试（取消并通知或升级）。
- **审批时序：准备在前、审批只留最终决策**：Receive→Gather data→Validate identity/permissions/workflow state→Generate proposed action→Evaluate policy/risk→Request approval→Execute→Verify→Audit log——agent 完成全部准备工作，人类注意力只用于最终决策。
- **审批屏幕给 plain-language 一段话 + 相关结构化数据**，raw JSON 墙无效；审批者需要足够上下文在定义时间窗内做知情决策（AWS AGENTSEC04）；审批决策带时间戳+审批人身份入不可变审计日志。

### 2. 置信度阈值路由 + ECE 再校准 + logprobs 信号（模型）
来源：anhtu.dev / viviscape.com / openlegion.ai / elementum.ai / galileo.ai
- **阈值起点（非标准）**：不可逆动作置信 ≥0.85 才自动跑（held-out 校准集 false negative <1%）、可逆 ≥0.70；30 天生产后按 **Expected Calibration Error（ECE）** 再校准——测"agent 的 0.8 置信是否真的 80% 正确"；阈值按失败成本校准而非平均精度（平均高但少量高额 case 灾难性错误的模型需要不同阈值）。
- **自报告置信度最坑**：LLM 自我声称的 confidence 不可信；用客观信号——top-token 概率 <0.7 触发升级 hook（completion handler 读 logprobs，滚动平均跌破阈值即升级）、输入与训练数据相似度、冲突信号数、请求歧义度；多信号组合优于单信号。
- 分级域默认：healthcare/legal/compliance 升级阈值 95%+；多步推理/模糊请求/"it depends" 逻辑触发复杂度升级（livekit）；升级到人前把候选动作+上下文打包，人的任务是"最终裁决"不是"从零理解"。

### 3. 分级代理授权四档 + 自主性逐动作毕业（可复用 Skill）
来源：qu3ry.net / pickaxe.co
- **四档授权词汇表**（交接的本质=降到低一档代理权）：fully autonomous（生成+评估+提交）/ guided（生成候选+评估，交人类确认后才提交）/ constrained（只建议与分析，无可执行变更）/ observer（只监控记录，外部授权才升档）；escalation=向低代理档移动 pending 人类决策。
- **逐动作毕业制**：按 action type 跟踪错误率，某动作错误率降到舒适阈值（常见 ~5%）就从 in-the-loop 毕业到 on-the-loop；**agent 用可靠性挣自主性，action by action，不是第一天全给**；前提是好 agent 分析（错误率按动作类型分桶）。

### 4. 升级决策链携带 + HEM 状态机 + 五触发器 + 升级量监控（工作流）
来源：moai.team / IETF draft-sato-soos-hem / gingerlabs.ai / galileo.ai / viviscape.com
- **升级触发器**：超时 / 重复拒绝 / 风险重分类 / 异常；路由到更高权限评审（可批准/编辑/取消）；**升级请求必须携带完整提案+决策历史**，不能只带"卡住了"。
- **HEM（IETF 标准草案）**：把会话置正式 `HEM_PENDING` 状态→按有序指定链路由结构化升级请求→**人类决策前禁止一切状态转移**→处理六种人类决策类型；用一个受治理路径替代三种失败模式。
- **五个必停触发器**：不可逆性 / 规模 / 歧义 / 合规要求 / 新颖性（gingerlabs）。
- **升级量增长快于人类容量**：规划 10 次/日的手动交接，落地常变 100 次/日——架构第一天就要算人类审批容量；加 escalation rate monitoring 作安全网（不只阈值触发，还要监控升级率异常）。

### 5. 原子交接状态机 + 明确同意（可复用 Skill）
来源：dev.to/susiewang（Tencent RTC coordinator）
- **交接原子性**：AI 参与需显式用户同意；**任一时刻只有 AI 或人类代理一方持有回复权**——交接做成状态机（谁持有权威、切换原子），防"AI 和人类同时回"或"两边都不回"；AI 离场时把完整上下文打包移交，离场后不再发声。
- 与 §4 分工：那条管"什么时候升级、升级带什么"；本条管"升级/交接这个动作本身怎么做才原子"。
- 反模式：交接靠口头约定（"我把这事交给人类了"但 AI 还在响应）；交接后 AI 继续在旁插话；升级请求丢失上下文（人类接手要从零理解）。
