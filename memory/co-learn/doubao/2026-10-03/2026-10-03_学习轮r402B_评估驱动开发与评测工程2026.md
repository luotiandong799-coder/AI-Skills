## 落地 5 独点（每点标注提升层）

### 1. EDD 工作流与 eval 三件套（可复用 Skill/工作流）
来源：qaskills-edd-guide / helpmetest-edd / agentropic-evals-contract / chiraghasija-edd-2026
- **EDD=LLM 版 TDD**：写 LLM 功能**之前**先写 evals 定义"好"；**failing evals 就是 spec**；迭代 prompt/model 对照 eval 套件；**CI 门=分数超阈值**（非精确断言）——把 prompt 工程从"tweak and eyeball"变成可测量、可门控。
- **eval 三件套（shipping contract）**：①labeled golden dataset ②scoring method ③**pass-rate threshold（构建必须达到才能上线）**；旧 Gherkin 验收标准（Given/When/Then）**不消失，变成 eval cases**——接受标准从"例子"变成"分布上的阈值"。
- **golden set 是最重要工件**：分数成为可随时间追踪、可门控部署的数字；golden_dataset.jsonl 每行一例（id+input+expected+category）。
- **反模式=Goodharting evals**：指标变目标后失真——red-teaming+回归检测+定期核对指标与真实质量相关。
- 判据：新功能开工先写 eval 套件（failing=spec）；每个变更（prompt/model/参数）过 CI 阈值门；eval 三件套齐才算有验收。

### 2. Golden Set 工程：四桶/规模/按能力组织（工作流/可复用 Skill）
来源：futureagi-golden-set-design / latitude-regression-testing / datarekha-evals-work / anup-golden-dataset / logic-llm-evals
- **四桶 golden set**：production sample（真实流量）+ adversarial（试图打爆）+ edge cases（边界）+ **failure replays（每次生产事故回放）**——四桶齐 CI eval gate 才证明生产。
- **规模路径**：25-50 例起步抓早期失败 → 扩到 **200-500 行**（含 normal happy path/adversarial/edge/regression）；**按能力组织多个小 set 而不是一个大 set**（"从发票提取字段""拒绝对某类有害请求""修这类 off-by-one"各 50-500 例，人写细标注）。
- **regression 桶从 0% 增长**：每次生产/测试发现 bug 必加一条——"你的 golden dataset 比你的 prompts 更值钱"，拥有它的团队杠杆最高。
- **部署门**：低于前一版本分数即**阻断合并**；accuracy/safety/faithfulness 阈值作硬门，低于生产基线部署暂停。
- 判据：golden set 按能力分桶、production 桶从真实流量挖、每个生产 bug 当天回放进 regression 桶；200+ 例后才可信做门。

### 3. 离线 vs 在线评估分工（工具/工作流）
来源：qaskills-offline-online / futureagi-genai-production / langchain-llm-evals / nisai-evaluating-apps
- **离线评估**答"新版比旧版好吗"——覆盖**只想到测的**（已知失败模式/回归）；低延迟敏感（可批量跑过夜）；成本=数据集大小×每变更次数。
- **在线评估**答"线上系统在退化吗"——覆盖**用户实际做的**（未知未知/漂移/稀有边界）；高延迟敏感（采样运行不拖慢响应）；成本=流量×采样率。
- **2026 生产=五层并行评估**：CI evals（部署前）+ online evals（活流量）+ inline safety guardrails（输入输出）+ drift monitoring（跨时间）+ trace-level observability（agent 全链路）。
- **在线信号**：100% 采样日志（按隐私策略脱敏）+ 自动异常旗标（**响应长度突增/工具调用率突降/拒答率突增**）+ 用户 thumbs up/down 直接回喂 golden set（最便宜信号）。
- 判据：上线前用离线门、上线后用在线监控；两者并存不是二选一；每个 AI 响应带反馈入口并回流 eval 集。

### 4. Eval 数据漂移与版本化（工具/工作流）
来源：futureagi-eval-drift / latitude-data-quality / braintrust-eval-guide / ayinedjimi-llmops
- **版本化元数据**：把 **prompt-template hash + embedder 版本 + retrieval-corpus 快照** pin 进数据集元数据——否则"哪个 prompt 配哪个数据集"不可复现；旧版本（如 golden-v3-2026-05）**保留至少一个发布周期做 A/B**；换新集后**重基线 CI 阈值**。
- **漂移信号清单**：embedding distance / intent mix 变化 / prompt hashes / retrieval overlap——监控这些而非只看分数。
- **质量告警阈值**：污染 10-30%（标注泄漏进训练/评测）、**分数通胀 5-20 点**（judge 漂移）、eval 集**超过 6 个月未更新**=陈旧。
- **两类漂移**：prompt drift=小措辞积累改变行为；**model drift=上游 provider 更新改行为而不改代码**——定期 eval 对比历史基线才抓得到。
- **生产挖掘闭环**：采样 traces→embedding 聚类（Phoenix/Arize）看语义空间低覆盖区→补进数据集。
- 判据：数据集每次变更记 hash 三件套；旧版本保一周期；分数异常先查 judge 漂移与污染再怪模型。

### 5. 评测成本效率与工具选型（工具/工作流）
来源：scrolltest-ollama-ci / benchmarkingagents-cost-per-eval / promptquorum-prompt-testing / awesomeagents-eval-tools / dupple-eval-tools
- **本地评测省 90%+**：Tekion RAG eval 套件 $87/月云 API→**$6 电费本地 Ollama**——更快、数据不出网、无 rate limit 卡周五部署。
- **自托管基准成本**：SWE-bench Verified 自托管 Llama-3-70B 级约 **$5-30/全跑（GPU 时间）** vs per-token API——开放权重与前沿闭源差距真实（15-25%），评测可承受、生产未必。
- **工具分工表**：Promptfoo=**秒级单元测试/回归、CI/CD 原生、免费 MIT**；Braintrust=batch 分钟-小时+**人工评审**、$0/$249；DeepEval=**50+ 研究指标、pytest 集成、Apache-2.0**、RAG 指标（RAGAS 免参考评分）；LangSmith=实时 tracing、$0/$39 座席——**快测用 Promptfoo、正式门用 Braintrust/DeepEval、排查用 LangSmith**。
- 判据：CI 频繁跑用本地/自托管模型控成本；单元回归用 Promptfoo 秒级、发布门用带人工评审的 batch eval；评测工具选型按 CI 集成度与人工评审需求定。
