## 落地 5 独点（每点标注提升层）

### 1. 大文件/大输出治理四件套：Claim-Check 分离 + 硬上限截断 + 续读提示 + 摘要文件（可复用 Skill）
来源：zylos-envelope-artifact-patterns / filesystem-context-skill / arize-context-harnesses / csdn-mini-agent-sandbox / agentskills-recursive-decomposition / aimadetools-context-packing / developersdigest-98percent-reduction
- **Envelope-Artifact 分离（Claim-Check）**：大负载存外部存储，受限通道只传小引用（claim ticket），消费端凭票取全量——经典 EIP 模式；agent 处理 50 文件不必贴 50 个全文，写 `.agent-work/`（findings.json/failing-tests.txt/candidate-files.txt/summary.md）按需读紧凑摘要=98% 上下文削减。
- **大工具输出重定向到文件**：单次搜索/DB 查询可 dump 几千 token 进消息历史并持续整个会话；写 scratch 文件+紧凑摘要+文件引用，之后用定向检索（grep 模式/行范围 read）只取所需。
- **硬上限截断**：read 硬上限=2000 行或 50KB 先到者；head 截断；工具输出尾部显式续读提示"[Showing lines 1-2000 of 50000. Use offset=2001 to continue.]"；工具描述同时声明"output truncated to 2000 lines"——模型据此知道要继续读而不是以为读完了；>2000 行/50KB 必须 view_file(start_line/end_line) 或 head/tail 局部读。
- **repo map（Aider）**：不加载整文件，用 tree-sitter 解析代码库成 AST 地图（函数签名/类定义/imports 无实现），~500-2000 token 覆盖中等代码库，需要细节再请求具体文件。
- 判据：上下文进得去才谈得上处理——大文件第一原则是"别让全量进上下文"，第二原则是"截断必须带续读提示，不能静默截"。

### 2. 搜索优先文件读取协议：code_map→grep→offset/limit 最后手段（可复用 Skill）
来源：arxiv-CodeGrep / zap-context-manager / arxiv-RARG / gsd-scout / arxiv-LARGER / agent-booster / arxiv-grep-harnesses
- **读取分层**：① code_map（符号/结构总览）→ ② search_code（ripgrep 模式匹配，符号名未知或需非定义匹配时）→ ③ read_file(offset/limit) 最后手段且只读 code_map 给出的行范围——**绝不整文件通读**。
- **检索-读取解耦**：检索结果大小与上下文压力解耦——任意大结果集写盘不占上下文；grep 全缓存范围扫描（path 省略=一次搜所有累积文件，会话绑定接口做不到的）；搜索结果按文件分组带回 20 条命中，每条带 ±上下文行。
- **symbol index+smart read**（agent-booster）：tree-sitter 解析所有 .py/.ts/.js 提取函数/类入 SQLite，embedding 编码符号语义，给定文件+任务跑 per-file 向量检索只返回匹配符号的行范围——精确到行，不整文件。
- **先侦察再交接**（scout）：grep/find 定位相关代码→读关键段落（非整文件）→识别类型/接口/关键函数→记录文件间依赖→返回结构化发现供另一 agent 用，不重读一切。
- 判据：文件读取优先级=结构地图 > 搜索 > 精准行读取 > 局部通读 > 整文件；搜索工具是第一工具，read 是最后手段。

### 3. 精确编辑与状态漂移防护：apply 前校验 + 升级策略 + diff 强制（工作流）
来源：yuxiangwu-reliable-file-editing / kondasamy-how-agents-edit / codex-v4a / npm-diff-apply / aitoolsguidebook-unified-diff / cursor-apply-model / detached-node-code-agent
- **状态漂移是一等失败模式**：apply 前 hash/version 检查，mismatch 强制重读再 apply；并发漂移=worker A 改文件而 worker B 基于原版规划编辑——多 agent 共享文件时必须校验基线。
- **升级策略五级**：minimal edit → wider context → switch representation → file rewrite → rollback；多数"编辑失败"不是推理失败，是 representation↔applier 不匹配（brittle localization）。
- **diff 输出强制最小变更**：要求 patch 形式输出（unified diff），再生未触及代码是浪费——diff 可直接管道进 git apply；Cursor apply model=planner 发 terse hints→小型微调模型用原文件当 speculative draft 转精确 diff，多文件近原子落地，逐块 accept/reject。
- **专用 patch 语法**（V4A/Codex）：模型专门训练产出目的型 patch 语法，所有修改经单一 apply_patch 机制；diff-apply 类库多策略定位，源文件微改后仍能应用。
- **测试门序列**：read→plan→apply→test 循环，失败继续，测试绿后终止并提最终 diff 给人审。
- 判据：编辑前校验基线、编辑以 diff 表达、升级按五级阶梯——"看起来对了"的整文件重写是最危险形态。

### 4. 文件系统安全：realpath 先于 containment + Symlink 先于权限决策（可复用 Skill）
来源：zylos-secure-file-serving / adversa-symjack / codex-symlink-defence / bswen-path-containment / egoistai-filesystem-safety / neelmishra-agent-security
- **解析顺序铁律**：先 realpath() 再断言包含（containment）——Anthropic MCP server 修复即改此顺序；string-prefix 检查不足（工作区内路径可以是通向外部的 symlink）；resolve 真实父路径、拒绝意外 symlink、用 OS 原语避免 follow links；注意 TOCTOU race。
- **SymJack 攻击**：批准提示撒谎——symlink 指向外部，用户批准"看起来在工作区内"的写入实际写到外部（六个主流 coding agents 受影响）；修复=任何文件写路径（含 shell cp/mv/install/tee/重定向/dd）在权限决策前先解析 symlink 到真实目标；Codex 沙箱先 canonicalise 可读写根再建 mount points，apply_patch 拒绝写通向外部的 symlink。
- **双层 path containment**：Layer1 发现时校验（skill 注册时验证路径再加入 registry）/Layer2 运行时校验（实际读文件时）——两层都防。
- **沙箱纵深**：容器隔离/网络限制/只读挂载/资源限制（CPU/内存/时间）；即使注入成功也被限制在沙箱内——沙箱是最后一道网。
- 判据：任何路径进入系统前先解析真实路径再做包含判断；shell 文件操作与工具写入走同一校验（攻击者专挑工具不查的 shell）。

### 5. Checkpoint 回滚 + Git 治理：快照还原四语义 + 工具盲区 + 分支纪律（工作流）
来源：cursor-checkpoints / hermes-rollback / claude-file-checkpointing / agent-zero-time-travel / stordai-undo / npm-agent-rollback / vscode-review-revert / codebuddy-checkpoints / dev-claude-rewind-bash / travis-ai-agents-branch / vibecoding-git-practices / gitleaks / skillmd-git-project-setup / tencent-wip-squash / vibegov-git-hygiene
- **Checkpoint 快照**：重大变更前/每 turn 前自动快照受影响文件；还原语义四规则=存在文件恢复内容/不存在文件删除（agent 创建的）/目标之后所有 checkpoint 丢弃（revert 后无 redo）/父目录按需重建；对话时间线点 checkpoint 预览→restore。
- **工具盲区（关键限制）**：Claude 只跟踪 Write/Edit/NotebookEdit 工具——**bash 删除的不在 checkpoint 内**（"Claude Code's /rewind Won't Bring Back What Bash Deleted"）；快照只覆盖编辑工具，shell 破坏无法回滚，故破坏性操作前仍要人工防线。
- **Time travel 未来不擦除**：回退到历史 commit 时系统在后端 history refs 保留之前 head——回退 5 个 commit 后悔仍可恢复；content-addressed snapshot（无 git 也能用）。
- **Git 治理规则**：agent 绝不直接干 main（分支或 worktree，`git checkout main` 是你的 undo 按钮）；**绝不传 --no-verify**（hook 失败要调查修复不是绕过）；.gitignore 先于生成任何构建产物；commit 生成的锁文件（package-lock/迁移）但绝不 commit 构建输出（dist/.next）、.env、IDE 配置；gitleaks pre-commit 抓 secret（最后一道网）；WIP commit 每完成一接口/测试一次，收尾 squash 成干净原子提交；每个实质 turn 结束做 full working-tree accounting（工作区账目=执行正确性的一部分）。
- 判据：快照是给编辑工具的，shell 破坏靠分支纪律兜底；git 规矩=不 main 直改、不 --no-verify、ignore 先行、锁文件入 commit 产物不入。
