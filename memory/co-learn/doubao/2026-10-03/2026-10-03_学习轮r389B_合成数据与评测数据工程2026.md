## 落地 7 独点（每点标注提升层）

### 1. 合成数据生成三法 + 四步过滤管线（可复用 Skill）
来源：futureagi-definitive-guide-synthetic-data / futureagi-how-to-generate-synthetic / arxiv-2406.15126-survey / ai-tldr-synthetic-data
- **三生成法**：persona-prompted（措辞与意图变体）/ taxonomy-stratified（按分类单元保证覆盖——生产流量自然覆盖不到的格子）/ evolution（deepen/broaden/obscure/adversarial 制造多跳与对抗尾部）。
- **四步过滤（缺一步都算跳过）**：① embedding dedupe（语义去重，string 去重不够——生成器常用同义措辞表达同一内容）；② cross-family LLM judge（跨模型族，防同族 judge 批准同族生成器的失败模式）；③ mode-collapse 检测（pairwise cosine distance / entropy / HDBSCAN 聚类数）；④ human spot-check 5%（校准存活集分布对真实参考集）。
- **多 teacher 模型**：数据一半由一个模型生成、另一半由另一个——防单一模型风格主导导致分布坍缩。
- **temperature 0.8-1.0**：提高词法多样性；temperature 0 会得到近相同输出。
- 判据：合成数据管线是否"生成容易、过滤是真正工程"——缺过滤机制时生成越多模型越差；唯一落点可复用 Skill（数据管线构建法）。

### 2. Mode collapse 检测与防退化：混合比例 + 语义去重 + 多样性度量（模型）
来源：arxiv-2608.21366-reviewing-collapse / genai4a11-synthetic-data / shyankdev-frontier-synthetic / prem-diversity-scoring / alpeshnakrani-synthetic
- **模型坍缩检测指标**：held-out 真实数据上的 perplexity（不应升高）+ 真实基准任务精度 + 人类评估 1-5% 样本；n-gram diversity 与 topic coverage 逐轮不应下降（每轮须保持或增加多样性）。
- **安全混合比例**：合成与真实 20-80% 混合、绝不纯合成多轮训练；真实数据锚定分布；混比存在任务相关的安全上限（λ=1 全合成在理论上不稳定）。
- **避免尾部裁切**：非常低 temperature / 很小 top-p/top-k / 很短候选列表会剪掉稀有 token——把缩放偏离幂律。
- **语义去重而非字符串去重**：MD5/SHA256 精确 hash 抓不到语义重复；SemDeDup（embedding 聚类去重）才是必需；k-center-greedy 从过滤后集合选最大多样性子集（嵌入后迭代选"离已选集合最远"的样本）。
- **DCE 机制**：verbalized tail sampling（模型自标"这个想法多明显"，明显者丢弃）+ semantic memory（持久 embedding 索引跨批拒绝近重复）+ adaptive prompt evolution（每批按记忆状态与轮换多样性策略重建生成 prompt）。
- 判据：合成数据每轮都要"多样性不降 + 分布对齐真实 + 混合比例受控"三查——缺一就是向 model collapse 滑。

### 3. 评测数据污染（contamination）检测与防护（工作流）
来源：neelmishra-eval-data-curation / futureagi-gsm8k / syncsoft-swe-bench-contamination / backfield-conda-ledger / awesomeagents-soft-contamination
- **污染类型**：逐字包含 + 改写近义（soft contamination）+ 语义等价不同表面细节 + 由 benchmark prompt 派生后进入微调集。
- **soft contamination 杀伤**：Spiesberger 发现 78% CodeForces 问题、50% ZebraLogic 在训练数据中有语义重复（非精确拷贝）；**在语义重复上微调的效果与精确重复微调相同（~20% 提升）**——"近期能力增益被 soft contamination 混淆"。
- **10% 污染的代价**：GPT-4 技术报告标注主要 benchmark 污染率 1-25%；eval 集 10% 被污染时记忆这些条目的模型获得 5-10 分虚增。
- **检测手段**：① 13-gram 重叠序列扫描（对训练语料）；② 后截止时间戳探针（模型对公共 GSM8K 98%、对私有 post-cutoff 数学 78% = 记忆非推理）；③ 数字换值探针（换值后模型仍复述原答案=污染信号）；④ 私有/held-out 轮换集 + 冻结的私有关键集；⑤ CONDA 公共账本（566 条污染记录、91 数据集/模型）查"某 eval 是否已漏进某模型训练"。
- 判据：任何"X% on benchmark Y"宣称先查污染账本，再问数字可信度；污染检查必须在每次数据集发布与每次用新数据训练前跑。

### 4. 数据飞轮：六阶段闭环 + 轨迹四复用（工作流）
来源：prakashkagitha-data-flywheel / futureagi-data-flywheel-glossary / zylos-data-flywheels / alibabacloud-agentloop / arxiv-2510.27051-adaptive-flywheel
- **飞轮是闭环不是流水线**：live 模型(vN)服务并记日志 → 日志被人工/代理评分 → 评分数据经 SFT/RLHF 训练新候选 → 候选过 eval gate 才部署为 vN+1 → 新部署模型产生下一轮更丰富的训练信号。
- **飞轮第三个月停滞是普遍规律**：简单模式学完、标注质量退化、用户行为比重训周期变得快。
- **轨迹一次采集四场景复用**：observability / audit / evaluation / optimization——轨迹价值随应用场景增多而增长。
- **四型沉淀**（codejunkie99）：episodic memory（发生了什么）/ semantic memory（学到了什么）/ context cards（可复用工作流规则）/ eval cases（什么必须保持工作）——各自服务不同下游。
- **MAPE 控制环分类失败**：retriever error / reranking error / hallucination / citation error / answer generation error——自动检测并修正系统失败。
- 判据：飞轮五要素（采集→标注→训练→eval 门→部署）缺一就不是闭环；标注质量与用户漂移是两大衰减点，需持续投入而非一次性搭建。

### 5. 黄金轨迹数据集：三步构建法（可复用 Skill）
来源：swarmsignal-golden-trajectory / innovatiana-trajectory-annotation / syncsoft-coding-trajectory / qaskills-openai-evals
- **构建法**：每任务类别人类专家完成 20-50 个代表任务并标注步骤——记"调了哪个工具为什么/什么上下文信息支撑该决策/捷径在哪为何取或不取/每个决策点错路长什么样"。
- **三级标注**：结局（outcome）+ 轨迹（turn/step 序列）+ 步骤（每动作四标签：工具选择正确性 / 参数正确性（日期格式 bug 住在这）/ grounding（推理是否从真实观察出发）/ 信息使用（读了工具输出还是忽略））；跨三级横切 safety/policy 标签（有害动作尝试）。
- **过程奖励标注**：5 轴评每推理轮（relevance / factual grounding / tool selection / redundancy / unsafe edits），IAA 目标 κ≥0.78；binary test-pass + stepwise process reward 结合——process-reward 层是 PRM 型 verifier 的使能器（Apple SWE-Gym 推理时 verifier 驱动 32% 提升）。
- **负例来源**：黄金轨迹即 judge 训练的负例来源；TraceLift-Groups 用目标扰动产 plausible-but-flawed 轨迹同锚一个问题。
- **PII 处理**：测试用例进代码仓库前脱敏（人名/邮箱/订单信息换保留结构的合成值）；expected_final_answer 是每个 grader 对照的 ground truth——它错了整套就错了。
- 判据：轨迹 ground truth 要"人类专家逐决策点标注 + 过程层与结果层双标注 + 负例同锚"，单靠 answer-only 标注训不出过程级 judge。

### 6. 评测集版本治理：hash 快照 + 分层采样 + manifest 清单（工具）
来源：futureagi-eval-data-drift / qaskills-golden-versioning / theneruralbase-contamination-training / latitude-stratified-sampling / mlflow-eval-datasets
- **不可覆盖命名数据集**：golden-v4-2026-06 新命名而非覆盖；pin prompt-template hash / embedder 版本 / retrieval-corpus 快照到数据集元数据；旧版留活至少一个发布周期供 A/B。
- **版本治理目的**：能回答"分数变了是因为模型/提示词/judge/测试本身哪个动了"——每次 eval run 指向不可变数据集修订，修正建新修订带可审阅 provenance。
- **分层采样替代随机采样**：随机采样让常见输入淹没数据集、稀有失败被挤出；按 intent 聚类后按簇成比例抽、小簇过采样；同时采 latency/cost 离群。
- **manifest 机制**：每个样本入口分配密码学 hash → 固定 seed 生成 train/val/test 分裂并记录 seed+分裂时间戳到 versioned manifest → 训练脚本加载时校验样本 ID 与 manifest 一致（不一致 fail loudly）→ 最终评估前冻结分裂。
- **RAG 污染最小检查**：记录 QA 对来源文档，来源文档也在检索语料中则 flag；每次 eval run 前对 store 内容算聚合 hash（如文件名排序哈希）与分数同记。
- 判据：eval 集是"受治理的测试工件"不是 demo prompt 堆——不可变修订 + 分层采样 + manifest 校验三件套缺一，分数变化不可归因。

### 7. 失败飞轮与自改进：从失败痕迹到 harness 更新（工作流）
来源：neosigma-self-improving / theairuntime-vertical-agents / agentpatterns-agentic-flywheel / futureagi-pass-evals-fail-production / aitechmonk-learning-loop
- **垂直 agent 的可靠改进不动权重**：Harvey 十二个法律任务、模型权重冻结、靠闭环把生产失败转成 harness 更新（prompts/tools/sub-agents/memory files/judge rubrics/routing logic），成功率 40.8%→87.7%。
- **失败飞轮阶段**：批量模拟生产流量 → Failure Mining（扫描 trace 分类根因、浮现主导失败模式）→ 聚类失败（按共享根因、按复发率与严重度重排）→ 优化环（分析失败模式→提议并实施 harness 变更→针对修复）——固定迭代预算。
- **Error Feed 实操**：HDBSCAN soft-clustering over span embeddings（存 ClickHouse）把每个失败 trace 聚成命名 issue；Judge agent 30 轮调查跨 8 个 span-tools。
- **学习环四 gap**：团队动了修复没生效=部署 gap（改错根因或缺 eval）；修好又复发=substrate-rot gap（GC 没剪掉被取代的旧版本、仍在影响检索）——每个失败模式有明确修复且各成 harness 一部分。
- **evaluators 评分产生新标准**：生产 trace 进 trace store → evaluator 按团队标准评分 → 新失败模式成新标准 → 某行为簇分降→regression 候选 → 针对该簇生成 prompt/工具变更、对产生它的 trace 历史测试、赢则发布。
- 判据：自改进循环的"人类在关键路径"与"完全自动"是谱系不是二选一；垂域最可靠路径=冻权重改 harness + 失败簇驱动，先验证再谈模型重训。
