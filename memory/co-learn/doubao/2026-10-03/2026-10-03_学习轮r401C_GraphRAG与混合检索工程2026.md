## 落地 5 独点（每点标注提升层）

### 1. GraphRAG 社区检测与查询策略（可复用 Skill/工作流）
来源：mintlify-graphrag-community / mintlify-graphrag-overview / aipromptshub-graphrag-2026 / theneuralbase-community / hazeljs-graphrag
- **社区检测是 GraphRAG 核心创新**：Leiden 优于 Louvain（内部连通性更强保证）；多级社区=C0 顶层（广而快）/C1 中层（平衡）/C2 叶子（细而全）——global 用顶层摘要、local 用细粒度。
- **查询四策略按问题类型选**：**Global search**（map-reduce 社区摘要，答"全数据集主题/趋势"）/ **Local search**（实体级细节）/ **DRIFT search** / **Basic search**；local 展开流程=语义相似找相关实体→取实体社区 ID→展开同社区成员→加社区报告→合并文本单元。
- **社区摘要缓存=global search 的"记忆"**：GraphRAG v2.7 对 <3 节点小社区自动 pruning；1M-token 语料最粗粒度约 50-200 社区、每社区一次 LLM 摘要调用（离线成本大头）；调参 resolution_scale 可调粒度（提升质量但影响可复现性）。
- 判据：语料级"主题/趋势"问题用 Global search（社区摘要 map-reduce）、实体级细节用 Local search（社区展开）；图构建成本预算按"社区数×LLM 调用"估。

### 2. GraphRAG 演进：k-core 层级替代 Leiden + 本体引导双通道（模型/工作流）
来源：arxiv-2603.05207-core-graphrag / arxiv-2603.25152-omd / aiworkflowlab-graphrag-neo4j
- **k-core 分解替代 Leiden（arXiv 2603.05207）**：**确定性、密度感知、线性时间**层级——解决 Leiden 随机性与成本；配轻量启发式构建尺寸受限、连通保持的社区+**token-budget-aware 采样**降 LLM 成本（财报/新闻/播客实测三 LLM 验证）。
- **OMD-GraphRAG（arXiv 2603.25152）**：本体引导提取（ontology-guided extraction）+**多维社区聚类**（边界节点补全/属性感知模块度优化/多跳关系子图）→社区报告更完整——**MultiHop-RAG 检索精度 +3.43%**；**双通道融合**=实体级图遍历+社区级语义检索自适应合并。
- **查询时轻量 LLM router 选模式**（GraphRAG 2.7，通常 GPT-mini 级）——运行时成本可控。
- 判据：图构建成本敏感→k-core 层级（线性确定性）；领域实体关系复杂→本体引导+边界节点补全；多跳问题用实体遍历+社区语义双通道融合。

### 3. ColPali 视觉文档检索工程（工具/可复用 Skill）
来源：vespa-colpali / arxiv-2407.01449-colpali / mixpeek-visual / qubittool-cross-modal / bigdataboutique-multimodal-rag
- **ColPali**：PaliGemma-3B 扩展、**ColBERT 风格多向量表示、late-interaction**——页面图像直接编码（**无需 OCR 管线**）；离线 PDF 渲染成图像→多向量补丁嵌入→PLAID/HNSW 压缩索引；在线查询 token 向量 **MaxSim 检索 top-k 页面图像**（raw pixels）→喂 VLM 生成带页引答案。
- **MaxSim 公式**：Score(q,d)=(1/M)Σᵢ max_j(qᵢ·dⱼ)——查询每 token 对文档每补丁取最大点积再平均，恢复文本 RAG 丢失的细粒度相关性。
- **2026 多模态检索三架构**：caption-and-index（最简单）/ 统一视觉嵌入（Cohere Embed 4/voyage-multimodal-3.5）/ 页面为图像+late-interaction（ColPali/ColQwen2.5/ColNomic）——**单向量模型现已与多向量竞争**；图表/表格/扫描件/复杂版式语料文本 RAG 有上限，**无 chunking 策略可修复**。
- 判据：图表/表格/扫描 PDF 密集语料→ColPali 系页面级视觉检索（跳过 OCR）；预算低用统一视觉嵌入；MaxSim 晚期交互做重排候选池提精度。

### 4. 混合检索调优与测试时查询精炼（工具/工作流）
来源：arxiv-2605.00631-hrag / csdn-hybrid-reranker / papernotes-gqr / arxiv-2512.02660-spatial / prakashkagitha-llm-stack
- **混合检索配比**：H-RAG（SemEval-2026 Task 8）用 Weaviate hybrid **α=0.7（70% dense/30% sparse）**；bge-large-en-v1.5 嵌入 + **bge-reranker-v2-m3 重排**（余弦重打分）——分层父子检索：3 句子块（2 句 stride 重叠）索引，父文档补充上下文。
- **GQR（ICLR 2026）**：Guided Query Refinement——测试时用**轻量文本检索器得分作引导信号，梯度下降迭代精炼视觉检索器（ColPali 系）查询嵌入**——小模型逼近/超越显著更大模型（保持小 footprint）。
- **ColPali patch 级空间过滤 OCR 区域**（arXiv 2512.02660）：补丁相似度分数作空间相关性过滤器，坐标映射到 OCR 边界框——统一"OCR 结构化文本+视觉语义定位"两范式。
- 判据：混合检索默认 α≈0.7 起步；重排用 bge-reranker 系；视觉检索质量不足时用 GQR 式测试时精炼而非换大模型。

### 5. Chunking 多目标评测与 LLM 元数据前缀（模型/工作流）
来源：arxiv-2608.16586-chunking / semanticscholar-chunking-not-bottleneck / arxiv-2512.05411-llm-metadata / startmatter-rag-right / lrec-adaptive-chunking / google-advanced-rag
- **复杂 chunking 不总是值得（arXiv 2608.16586）**：8 策略×2 语料×3 embedding×多规模——**计算昂贵方法很少稳定优于简单 chunking**；最佳策略依赖 embedding 模型/数据集/语料规模/目标指标；相似性能方法操作成本差异大——**chunking 是多目标优化不是单点最优**。
- **RAG 评测须报告方差分解**（ANOVA）+**效应量**（Cliff's δ/Cohen's d）区分统计显著与实践显著——"显著"不是"有用"。
- **LLM 元数据前缀融合最强**：naive chunking+prefix-fusion=MRR 0.750/NDCG 0.813/precision 0.798/Hit@10 0.900——**统一块大小让前缀元数据一致影响**，变量长块会埋没元数据。
- **工程默认值**：chunk 300-800 token（<300 丢上下文、>800 伤检索精度）；语义 chunking 尊重结构（标题/段落/列表项）；adaptive chunking 五内在指标（References Completeness/Intrachunk Cohesion/Document Contextual Coherence/Block Integrity/Size Compliance）指导策略选择。
- 判据：chunking 选型按"embedding+语料+指标"实测而非追复杂策略；评测报方差分解+效应量；企业知识库加 LLM 元数据前缀用统一块长。
