## 落地 5 独点（每点标注提升层）

### 1. 沙箱=安全边界不是功能；生成代码=最高爆炸半径（模型/工具）
来源：dev-claude-sandbox-guide / langchain-choose-sandbox / beyondscale-enterprise-guide / openlegion-agent-sandboxing
- **沙箱是安全边界不是功能**——"它是把 agent 生成/运行的代码与未授权资源隔离的安全边界，不是可选项"。
- **真正沙箱的五个特征**：隔离文件系统 / 受限网络访问 / 资源限制 / **受控复用** / 与宿主的内核级隔离——**自称 sandbox 但不提供这些的不算沙箱**（LangChain 点名）。
- **AI 生成代码不可预测**：防它访问生产系统/网络/数据；agent 化改变了威胁计算——user→LLM→**工具调用决策→工具执行**循环，注入成功=直接工具执行。
- **数字**：50%+ 企业 agent 无安全监管或日志；**1/8 已报告的 AI 安全事件涉及 agentic 系统**（HiddenLayer 2026 AI Threat Landscape）。
- 判据：选沙箱先对五特征逐项核对；agent 安全按"工具执行可被注入劫持"设计，不按"只是文本生成"设计。

### 2. 最小权限运行加固清单：非 root 是最高 ROI 单点（工具/工作流）
来源：openlegion-agent-sandboxing / dev-claude-sandbox-guide / nvidia-four-ways / richards-sandbox-capability
- **非 root（UID≥1000）**：**多数容器逃逸 CVE 要求容器内 UID 0**——非 root 执行是**最高 ROI 的单点加固**。
- **cap_drop: ALL** 再加回 agent 真正需要的（**多数 agent 一个不需要**）；no-new-privileges 防提权。
- **沙箱不能自改配置**：环境不得能通过写/编辑环境或 agent 配置文件来自配置。
- **只读输入挂载+独立可写 scratch**：分隔输入与输出区；**无宿主 secrets 进 env**（env 是注入面）。
- 判据：沙箱镜像先过加固清单（非 root/cap_drop/禁自配置/读写分离/无 secret env）；容器逃逸防护从"非 root"开始。

### 3. 双层/内核级隔离：容器不够，microVM 兜底（工具/模型）
来源：richards-sandbox-capability / genaiprotos-e2b / e2b-dev / google-cloudrun-sandboxes / redhat-openshell
- **生成代码是 agent 产出的最高爆炸半径产物——纯容器边界不足以防逃逸**；对坚决的逃逸尝试需 **gVisor / Firecracker microVM 或等价内核隔离运行时**。
- **Firecracker=独立内核 vs Docker=共享内核**：硬件虚拟化边界——沙箱有自己的 OS 内核，与宿主/其他沙箱完全隔离；E2B 每沙箱一 microVM，10 亿+ 沙箱启动，毫秒-2 秒起。
- **OpenShell 双模式**：Mode1 沙箱包裹整个 agent（所有工具调用+代码执行在单一边界内，无凭据、出网仅经策略代理）——适合开发笔记本/CI（宿主有真实凭据 agent 永不见）；Mode2 沙箱=执行环境。
- 判据：跑 AI 生成代码选内核级隔离运行时而非裸容器；host 有真实凭据时选"沙箱包裹 agent"模式；逃逸防线=最小攻击面+内核隔离。

### 4. 出网代理注入凭证 + 资源硬限制与临时沙箱生命周期（工具/工作流）
来源：langchain-agents-computer / langchain-choose-sandbox / e2b-effectiveai / likeclaw-sandbox-bet
- **出网代理注入凭证**：沙箱内出站请求经代理在网络层注入 token——**agent 做调用但永远看不到凭据**；default-deny 出网+最小白名单。
- **资源硬限制**：CPU/内存/进程/磁盘/墙钟限制=**每任务成本上限**，防 runaway 循环（agent 循环可消耗惊人资源）。
- **受控复用权衡**：复用沙箱=跨执行持久状态的便利，但**被攻破一次伤害可延续**——由你决定是否值得。
- **临时沙箱生命周期**：仅载入工作流所需文件→完成即整体销毁→持久文件存平台；workspace 文件复制进沙箱，AI 只在其内读写改。
- 判据：agent 需要外部 API 时用代理注入凭据（不把 token 放进沙箱 env）；每任务设 CPU/内存/时长上限；跨执行状态与隔离风险二选一，默认临时销毁。

### 5. 审计记 Provenance 不记调用 + 沙箱/审批联动（可复用 Skill/工作流）
来源：richards-sandbox-capability / openai-codex-safely / redhat-openshell
- **审计记 provenance 不只是调用**：用户请求/任务策略/**能力授权**/工具调用/工具参数/**结果标签**/**影响每次调用的数据来源**/策略决策/人工批准记录/沙箱 ID/外发目标/**脱敏内容 hash**——**没有 provenance，事件响应无法区分"谁给的指令/谁授权的/数据从哪来"**。
- **沙箱与审批相辅相成**：沙箱定义技术执行边界（Codex 可写位置/能否访问网络/哪些路径受保护）；**审批策略决定何时必须请求跨边界操作**——单次批准或按会话批准该类操作。
- **能力按需授予与撤销**：风险转换时可见（grant→verify→**revoke**），能力授权本身进审计。
- 判据：审计字段按 provenance 清单设计（含数据来源与批准记录）；跨沙箱边界动作走审批（单次/会话级）；能力生命周期=授予→验证→撤销全程留痕。
