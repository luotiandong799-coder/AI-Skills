## 落地 5 独点（每点标注提升层）

### 1. SWE-bench Verified 失效与 SWE-Bench Pro 替代（可复用 Skill/模型）
来源：openai-signal-noise / arxiv-2608.20446-vibe-coding / swebench-verified / gpt56-announcement
- **OpenAI 官方调查（2026-07-08）**：SWE-bench Verified 有**基本设计缺陷与数据污染**，不再提供软件开发能力的有效信号——官方明确"已无法给出有意义的信号"，建议社区迁移到 **SWE-Bench Pro**。
- **SWE-Bench Pro 规格**：**1,865 多语言任务**（GPL 许可+专有代码库）、**覆盖四种语言**、数据污染更抵抗、更长视野+更真实编码任务（Scale AI 2026）——用于追踪 agentic 编码能力。
- **SWE-bench 2026 榜现状**：EPAM AI/Run 76.80、Claude 4.5 Opus high mini-SWE-agent 76.80 $0.75（2026-02-17）；GPT-5.5 82.7%（OpenAI 官方）——**官方数字与第三方复测常不一致**。
- 判据：看编码能力优先 SWE-Bench Pro（四语言/抗污染/长视野）；老 SWE-bench Verified 数据仅作历史参考；任何榜单一律核对评测方与复测差异。

### 2. Harness 决定编码得分：同模型不同数字的根因（工具/可复用 Skill）
来源：nvidia-six-harness / arxiv-2608.27969-openjiuwen / aifuturefront-benchmark / datacamp-best-llm-coding
- **不同 harness 产生不同数字**：DeepSeek V4.1 Flash Terminal-Bench 2.1=90.6%（vendor 自报）vs 74.5%（Vals AI 独立）——**同一模型差 16pp**；Anthropic Opus 4.7 SWE-bench 69.4%（Anthropic/AWS 报）vs 第三方不同。
- **NVIDIA NOOA**：六种 agent harness 能力（253 行通用 agent、无基准特定提示）SWE-bench Verified 82.2% GPT-5.5 超公开 SOTA 79.2%、79.8% Opus 4.6——**harness 能力可以抬升模型得分**。
- **openJiuwen（arXiv 2608.27969）**：静态 harness 超越——82.6% vs 最强公开榜 79.2%（+3.4pp），最强先验系统也用 Claude 4.5 Opus——**性能差异不能归因模型，是 harness 设计**。
- 判据：对比模型编码能力必须**固定 harness**（同 scaffold 才可比）；模型得分请同时看"哪家 harness 跑的"；vendor 自报数字打折扣（16pp 级差异常见）。

### 3. Terminal-Bench 2.1：系统级评测（agent+scaffold 一体）（工具/工作流）
来源：codetalenthub-coding-assistants / morphllm-coding-agent / datacamp-best-llm-coding
- **Terminal-Bench 2.1 评估完整 agent+scaffold 系统**（模型+harness 一体）——终端真实工程任务，**比模型单独得分更贴近 Claude Code/Codex CLI 日常使用行为**。
- **2026 榜单**：Codex CLI+GPT-5.5 Terminal-Bench 83.4%（leader）；Claude Code v2.1.238+Opus 5=89.1% TB 2.1 且 Fable 5 80.0% SWE-Pro；Gemini CLI/Antigravity+Gemini 3.1 Pro=70.7% TB 2.1（Apache-2.0 开源）。
- 判据：选编码 agent 看系统级评测（Terminal-Bench 类），不是单模型分；CLI agent 对比用"agent+默认模型"组合分。

### 4. 编码基准分类路由：先选工作单元再选基准（可复用 Skill/工作流）
来源：codesota-task-router / benchmarkingagents-livecodebench / llmreference-benchmarks / spec-weave-coding-benchmarks
- **CodeSOTA 路由法**：先选编码工作单元再选基准——**function 生成→HumanEval/LiveCodeBench（prompt-to-code）；真实 repo patch→SWE-bench（repo repair）；diff 编辑→Aider（diff editing）；工具使用 agent→harness 评测；测试循环→test loop**——基准随工作流变，一个数字不能概括编码能力。
- **LiveCodeBench 2026 状态**（LeetCode/AtCoder/Codeforces 三源无污染）：2025-11 frontier 过 70% pass@1（强 agentic scaffold+测试执行反馈出现）；2026-05 frontier 72-78%——**按难度：easy ~90%/medium ~75%/hard ~50%**。
- **Codeforces Elo 是竞赛能力**：DeepSeek V4 Pro Max 3206、Gemini 3 Pro 2439（Grandmaster 级）、GLM 5.2 软件工程领先 vs DeepSeek 算法数学统治（5x 便宜）——**竞赛分≠工程分**。
- 判据：评估编码能力先定义工作单元（函数/补丁/编辑/agent），再挑对应基准；一个榜单分数不可外推到所有编码任务；竞赛 Elo 与 SWE-bench 是两个正交能力面。

### 5. 编码评测的成本效率面：token 数/缓存/每任务成本（工具/工作流）
来源：swe-rebench / gpt56-announcement / opencodex-benchmarks / codingfleet-deepseek-kimi
- **SWE-rebench 评测含成本与缓存**：GPT-5.6 Sol medium 62.9%±1.19%、$1.40/任务、**92.1% 请求命中缓存**（5,524,892 tokens）——评测报告成本/缓存复用率，不只是通过率。
- **GPT-5.6 Sol**：Coding Agent Index SOTA 80、超 Fable 5 高 2.8 分，**用少于一半输出 token/一半时间/约 1/3 成本**——同等分数比效率成为新维度。
- **opencodex CLI 编码基准按 cost/task 排名**：gemini-3.1-pro 37% $8.75 / glm-5.1 29% $2.9 / deepseek-v4-pro 27% $2.4 / kimi-k2.6 25% $2.13——**性价比排序与纯分排序不同**（差 4x 成本）。
- 判据：编码模型选型看"每任务成本+通过率"组合（差 4x 成本很常见）；评测报告要求附缓存命中率与 token 消耗；同等分数优先 token 效率高的。
