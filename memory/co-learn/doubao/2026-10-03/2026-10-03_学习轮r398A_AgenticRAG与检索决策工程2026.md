## 落地 5 独点（每点标注提升层）

### 1. 自适应路由决策：查询分类 → 四路径分派（工作流）
来源：tencent-agentic-rag / aliyun-agentic-search / andrew-rag-frameworks
- **路由决策器先分类再分派**：简单查询→单次向量检索（低延迟低成本）；复杂查询→多步迭代检索（高准确高成本）；关系推理→知识图谱遍历；数值计算→SQL 查询引擎——**自适应路由确保简单查询不过度消耗资源**。
- **复杂度实时评估决定处理路径**：直接答案（快速响应）vs 复杂任务（深度分析）——路由模块是 Agentic Search 的决策中枢。
- **路由粒度**：向量/BM25/web 搜索/SQL/reranker 每个 query 每次选（tool routing）——**按查询类型选检索工具而非固定管道**（futureagi 五模式之一）。
- 判据：任何 RAG 入口先跑路由（分类+选路径）；数值查询不进向量库。

### 2. 多跳分解两模式：有序子查询 + 先骨架后实体（工作流）
来源：arxiv-agent-orchestrated / arxiv-stride / acm-multihop-planning
- **Query Decomposer 四步**：①检测多跳结构（涉及多实体或链式依赖）→②生成**有序子查询**（前序结果喂后续检索）→③各子查询独立检索→④聚合中间答案为连贯答案——多跳不是并行拆，是有依赖序的拆。
- **STRIDE（先骨架后实体）**：Meta-Planner 先构建 **entity-agnostic 推理骨架**捕捉查询抽象逻辑，**推迟实体落地直到推理结构确立**——避免过早词法承诺导致的消歧错误；Supervisor 依赖感知编排子问题执行。
- **全局计划先行**：规划模块先生成结构化全局计划（逻辑连贯的子问题+推理模板建模子问题依赖），每个子问题引导检索方向——**检索跟随推理路径而非自由发挥**。
- 判据：复杂查询先判多跳再拆；子查询按依赖排序（不是并行一把抓）；先定推理骨架再落实体名。

### 3. RASER 可恢复性路由器：one-shot 六特征决定 stop/escalate（工具）
来源：arxiv-raser
- **廉价路由器**：基于一次 one-shot RAG 和从中提取的**六个特征**做决策——RASER-2 决定 stop 还是升级到 PRUNE（额外检索动作）；RASER-3 在 one-shot RAG/PRUNE/迭代检索 IRCoT 三者间选择。
- **显式成本-精度权衡**：路由器不白做额外检索动作——"不花 extra retrieval cost 除非特征显示 recoverability 高"；**一次检索的失败可恢复性**（能否用更多检索救回）是升级决策的依据。
- 判据：检索失败先问"再检索能救回来吗"（recoverability），救不回就停或换路径，不盲目迭代。

### 4. 引用验证与 Grounding 全链路：强制引用 + 事后校验 + 证据六步（可复用 Skill）
来源：sourcescore-grounding / baai-citeguard / ragaboutit-fabrication / cyfuture-wrong-answer / aistackinsights-naive-rag-dead / arxiv-arc-citation / dzone-rag-guardrails / learnixo-rag-hallucinating
- **引用强制 + 事后校验**：SYSTEM 要求每个事实主张跟 [^N] 匹配上下文块 + **post-hoc 检查引用真的匹配**——经典 RAG 失败是"检索对但模型输出错数字"，光要求引用不够，要校验；**模型会伪造引用**（编造不存在的案例/页码/条款——法律场景最危险），校验是硬门槛。
- **CiteGuard 验证模块**：答案依据验证器（grounded-answer accuracy 98.3%）——**消融证明：移除验证模块即便检索准确率不变，答案依据准确率也急剧下降**——验证是独立于检索的必要环节。
- **证据六步**：①噪声阈值以下移除②冲突检测+新鲜度/完整性检查（**上下文不足→路由到 abstention 而不是幻觉**）③grounded generation（grounding prompt+引用要求+abstention 允许）④答案与证据分离的结构化输出（供审计）⑤post-generation 忠实度校验⑥不 grounded 就带显式指令重新生成（"只陈述上下文直接支持的事实，不推断不外推"）。
- **两阶段防护**：generation 前过滤 chunks + generation 后强制生成主张严格 entail 引用材料。
- 判据：RAG 输出必须可审计（答案与证据分离）；不 grounded 的 claim 触发重生成或 abstention；引用存在性校验（引用必须能在检索证据里找到）。

### 5. 自纠正检索循环：Self-RAG grading + 单工具循环 + 多工具编排（工具/工作流）
来源：rapidclaw-self-reflective / alok-self-correcting / markaicode-selfquery / redis-agentic-retrieval / pypi-retrievalagent / futureagi-agentic-rag
- **Self-RAG 显式 grading 步骤**：检索后生成前，模型评估 chunk 相关性/充分性——不够就**换 query 重检**，或决定"知识库没有答案"（可弃答）；self-critique 每一环：需要检索吗→检索相关吗→答案 grounded 吗。
- **自纠正循环两模式**：Pattern 1 单检索工具循环（每轮按上轮结果精化 query——最简单，处理模糊查询和轻度失败）；Pattern 2 多工具编排（关键词/语义/过滤/外部查询——agent 每迭代选工具，**需小心工具设计防无限循环**）。
- **SelfQueryRetriever（元数据过滤）**：naive RAG 把每个问题当纯语义相似度、忽略结构化元数据——LLM 自动分解成"语义搜索+metadata filters"，元数据过滤命中率远高于纯向量。
- **Agentic retrieval 定义**：LLM 控制的 agent 决定何时检索/查什么/用哪些工具/结果够不够——**不够就迭代、改写、再试直到证据足或命中停止条件**（与传统固定管道单遍取档对照）。
- 判据：检索结果生成前过相关性评分；低置信度自动重查；停止条件显式（证据足/知识库无/达重试上限）。
