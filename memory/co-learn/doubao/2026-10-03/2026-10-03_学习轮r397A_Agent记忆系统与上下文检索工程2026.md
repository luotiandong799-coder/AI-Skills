## 落地 5 独点（每点标注提升层）

### 1. 三层记忆模型架构 + STIM 全量注入 + STM/LTM 工程对照（工作流）
来源：augmentable-state-2026 / arxiv-adaptive-memory / mem0-stm-ltm / nisai-memory-guide
- **三层记忆模型**：episodic（短时会话状态=what happened when）+semantic（长期事实与偏好）+procedural（静态指令文件）——**context window 是 buffer 不是 memory**；Claude 缓存工作记忆/Cursor Merkle 树索引代码/LangGraph checkpoint 图状态，各工具都在分层。
- **STIM/MTEM/LTSM 三层层级**：STIM 缓冲最近对话——**检索时 STIM 全部内容直接并入生成上下文不过滤**（最近上下文通常最相关），但无界缓冲是问题（用滑动窗口/摘要压缩）；MTEM/LTSM 按需检索注入。
- **STM vs LTM 工程对照表**：latency（STM 亚毫秒实时 vs LTM 100ms+ 可接受）/representation（raw tokens vs indexed embeddings/documents/graphs）/update pattern（高频临时会话内写 vs 低频持久写）/eviction（**STM=FIFO/LRU/token 裁剪，LTM=merge/summarization/archival**）。
- **semantic memory 别盲目上向量库**：结构化 case（"用户用 pnpm 不用 npm"）用普通 SQL `user_facts` 列**远更易调试**——向量检索只在非结构化内容值得时才进。
- 判据：先按三层模型分存储（episodic 会话库/semantic 向量或 SQL/procedural 指令文件）；STM 用裁剪策略 LTM 用合并策略；能 SQL 的事实不上向量。

### 2. SimpleMem 三阶段压缩流水线（可复用 Skill）
来源：arxiv-simplemem / openreview-simplemem / mem0-icml2026
- **阶段① Semantic Structured Compression（语义结构化压缩）**：把无结构交互蒸馏成紧凑、多视图索引的记忆单元——**分层聚类交互片段 + 小模型逐簇生成简洁摘要**，压缩摘要构成长期记忆（而非逐字保存）。
- **阶段② Online Semantic Synthesis（在线语义合成）**：会话内即时把相关上下文整合进统一抽象表示——**消除冗余不攒到收尾**（类比记忆巩固的在线版）。
- **阶段③ Intent-Aware Retrieval Planning（意图感知检索规划）**：推断检索意图（来自任务标签/API 调用/工具使用/显式目标）+ 学习 intent centroids 低维空间——**动态确定检索范围、精确构建上下文**而非固定 top-K。
- 判据：记忆写入走"压缩→合成→按意图索引"三步；检索范围由意图推断决定，不是无脑全量 top-K。

### 3. query-time 记忆构建 + LLM-judge 压缩决策（工作流/工具）
来源：arxiv-lazymem / arxiv-memrefine / arxiv-memorycpt
- **LazyMem（延迟记忆构建到查询时）**：不预先构建压缩记忆——检索候选池后用轻量模型**并行重叠窗口**处理，选择性保留只与 query 相关的内容并压缩；reward 联合鼓励"识别相关消息+压缩忠实可答"；LongMemEval 上 LazyMem-4B 效果优于预先构建方案——**先检索后压缩，比先压缩后检索省且准**。
- **MemRefine（相似度只提候选，压缩决策交 LLM judge）**：表面相似度反映不了事实价值——相似度只用来**提出候选对**，delete/merge/preserve 决策由 LLM judge **按事实内容**判断，迭代直到预算达标；紧预算下优于 rule-based 基线。
- **MemoryCPT 两阶段**：QAD（query-agnostic 蒸馏把模块化记忆构建流水线蒸馏成紧凑模型）+ QAR（query-aware 检索+RRF 融合+LoRA 摘要 GRPO 训练）；用 **Quality per Cost（QPC）** 量化单位推理成本下的答案质量——记忆系统也按成本-质量记账。
- 判据：记忆构建可以延迟到查询时（先检索后压缩）；压缩取舍决策用 LLM judge 按事实价值做，相似度只当候选生成器；记忆系统评测用 QPC 类成本感知指标。

### 4. 检索式压缩 + 记忆巩固（工作流）
来源：zylos-compaction / zylos-consolidation
- **检索式压缩（Retrieval-Augmented episodic memory）**：不把既往 turn 留在活跃上下文——**每个对话 turn 嵌入索引到外部向量库，每步新查询对索引发语义查询，只注入 top-K 检索到的 turn**（LoCoMo 评测模式）。
- **记忆巩固（consolidation，类比生物睡眠）**：长期 agent 的原始经验累积成无限增长的 event logs，但 context window 有限且推理质量随数千未压缩轮次退化——**巩固 = 把短时 episodic 痕迹（对话轮/工具调用/传感器输入）变换成压缩、语义丰富、可查询的长期知识结构**，定期整合而非每轮都改长期记忆。
- **AdMem 多 agent 记忆框架**：agent state = S_short × S_long（actor agent + memory agent 分离）——记忆管理本身可以是一个独立 agent，不混在主 agent 里。
- 判据：活跃上下文只放当前轮+检索命中的 top-K；event logs 定期巩固进长期记忆（睡眠类比：日记天天记档案定期整理）。

### 5. RAG 检索优化组合拳：hybrid α 加权 + reranker + raw mode + late chunking + query 变换（工具/可复用 Skill）
来源：H-RAG / arxiv-hybrid-rag / microsoft-rerank / furst-hybrid / acl-ukrainian-rag / google-codelabs-advanced / arxiv-structured-rag / aws-graphrag
- **Hybrid dense-sparse α 加权**：语义相似+BM25 关键词匹配融合，α 控制相对权重（0.9/0.7/0.5 网格调）——**BM25 40%+语义 60% 加权融合是常见好起点**；GraphRAG/LightRAG 上做 triple-hybrid（lexical+semantic+graph 三路融合到一个排名上下文）。
- **Reranker 一行改动 ~15% 质量提升**：先高召回拿少候选，再用 cross-encoder（第二模型逐对打分）重排提精度——"lost in the middle" 问题靠 rerank 缓解；**raw retrieval mode**：LLM 看到前先检查管道检索到了什么。
- **Late chunking**：上下文化 chunk 显著提升检索——每个 chunk 生成时访问全文上下文（先全文编码再按 chunk 位置池化），比先切后嵌好。
- **Query 变换三件套**：query rewriting（改写模糊查询）/HyDE（假设文档嵌入）/step-back prompting（抽象化后退提问）——查询侧优化与检索侧优化缺一不可。
- 判据：检索管道默认 hybrid（α 可调）+cross-encoder rerank+raw mode 可检视；chunk 策略优先 late chunking；模糊 query 先进变换再检索。
