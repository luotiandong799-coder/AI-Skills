## 落地 5 独点（每点标注提升层）

### 1. 多 Agent 经济性账本：token/成本/延迟三档数字（工具/工作流）
来源：babybots-patterns-cost / llmversus-supervisor-worker / ranksquire-production-blueprint / omnithium-coordination-cost
- **Anthropic 实测数字**：多 agent 系统消耗约 **15x 单 agent chat 的 token**，token 使用解释约 **80% 性能方差**；Supervisor 模式比单 agent 多 **3-5x 成本、5-15x 延迟**；顺序 pipeline 便宜但传播错误、并行快但难协调——**复杂度必须挣回它的成本**。
- **并行 vs 顺序**：并行 worker 总延迟 5-30s vs 顺序 60-120s；10K 任务/月成本 $150-400；失败 worker 重试上限 3 次（指数退避）后标记子任务失败并返回部分结果给 supervisor。
- **单调用 vs 编排循环**：单 LLM 调用平均 800ms；Orchestrator-Worker+Reflexion 循环 10-30s——**可靠性差距两个数量级**。
- **协调的真实成本不止 token**：状态检索 3×50ms + handoff（序列化 2ms+队列 10ms+反序列化 2ms）+LLM 500ms median/1500ms p95——**预算按"检索+交接+LLM"三段估，不是只估 LLM**。
- 判据：上多 agent 前先算 token 倍率（15x 起步）与延迟倍率（5-15x）；交接是显式成本项。

### 2. 结构性失败模式清单与检测信号（可复用 Skill/工作流）
来源：rizz-production-what-works / ranksquire-production-blueprint / channel-tel-supervisor-vs-swarm / xbstack-a2a-deadlock / swfte-6-patterns
- **死锁**：两 agent 互相等对方输出——看起来都 active、无崩溃无报错，只有 API 成本在涨零产出。**修复=每条 agent 间消息设 30s 超时，无响应编排器重指派**。
- **假共识**：reviewer agent 同意 coder agent 的错误答案——评审 agent 没有独立证据基线。
- **上下文溢出**：长会话接近容量时模型**静默丢弃信息**（无报错）；检测=context 占用率告警。
- **Swarm 质量悬崖**：超过 8-10 次顺序对等交接质量崩（Tau-bench pass@8 base <25%）——**结构性开销，模型升级不动**。
- **6 模式失败检测信号表**：Fan-Out-Reduce=静默同意偏误（检测 worker 输出多样性分数低，缓解=注入不同模型/温度）；Cascade=过度自信低价层接受（tier-1 准确率漂移，标定器周训+阈值护栏）；Speculative-Race=输出不一致（可复现性测试，钉确定性赢家）；Saga-with-Rollback=补偿失败（回滚成功率 <99% 报警+人工升级队列）。
- 判据：编排系统上线前先建"失败模式→检测信号→缓解"表；每个 agent 间消息必须有超时与重指派路径。

### 3. Fork Tax 三大元成本与防御（模型/工作流）
来源：mech-fork-tax / xbstack-a2a-deadlock / loooop-agent-orchestration
- **过早分解（3x token 预算）**：coordinator 在理解任务结构前 spawn 子代理→子代理 thrash 返回 blocked→重计划——**先探明结构再 spawn**（orchestrator 先拿 repo map、可 read_file/grep 探测再承诺计划）。
- **报告契约不匹配（2x token 预算）**：子代理返回非结构化文本而非 JSON→coordinator 无法解析→再 spawn 一个"清理报告"代理——**交接强制类型化结构化输出**（typed structured output，下游可解析）。
- **深度限制抖动**：coordinator 反复撞 depthCap 重计划。
- **A2A 死循环**：两 agent 在拼写错误/状态确认上无限客套争论——需循环检测（交互轮次上限+`Fatal: MAS_COMMUNICATION_DEADLOCK` 类信号）。
- 判据：spawn 子代理前先完成依赖图/结构探测；子代理输出 schema 预先定义并强制；每次交接检查类型化。

### 4. 预算化编排五规则（工具/工作流）
来源：clawhub-fl-orchestrator / vibeengines-design / midaslabs-what-works / babybots-patterns-cost
- **依赖图先行**：分解前把复杂任务建成依赖图再 spawn——不是边拆边干。
- **最小共享状态**：agent 拥有自己的文件/资源，重叠不可避免时用锁——无共享可变状态是 Anthropic 默认（子代理无 peer-to-peer 通道）。
- **优雅失败**：每个 agent 都可能失败；编排器管重试/回退/部分结果——"活干完一半也能交回"。
- **预算感知**：跟踪每 agent 成本+硬限制防失控；**能设预算、定义 SLA、保证终止**（terminate=每运行预算+循环检测+审批门）。
- **质量门分层**：计划与评审用贵模型（Opus 级），执行用便宜模型（Haiku/S 级）——**贵模型当管理层、便宜模型当执行层**。
- 判据：编排器上线前提必须有成本上限与终止保证；agent 间默认无共享状态。

### 5. 分解并行性判据：通信-计算权衡（模型/可复用 Skill）
来源：arxiv-2606.00953-cohesion / arxiv-2605.05007-uno-orchestra / agentpatterns-fanout-synthesis / tentoro-parallel-fanout / midaslabs-what-works
- **Cohesion-Aware 图划分（arXiv 2606.00953）**：多 agent 编排=图划分问题——**任务分解缩短关键路径计算，但跨 agent 依赖需要昂贵上下文传递**；并行只在"跨分区依赖稀疏、上下文传递成本 < 关键路径节省"时值得——Co-Coder 静态分析依赖图/隔离结构枢纽文件/社区检测分区/依赖感知调度（28 真实仓库验证）。
- **Uno-Orchestra（arXiv 2605.05007）**：统一编排策略=选择性分解+每子任务派发给可接受 (model, primitive) 对，**两决策一起从真实 worker 交互的 RL 轨迹学习**——13 基准 22 基线 77.0% macro pass@1——委派不是手写规则，可以学。
- **Fan-Out Synthesis**：N 独立 agent 同解一题→合成 agent 合并各 attempt 最强元素——并行多样性对抗单一错误。
- **DAG of planners 不是 DAG of steps**：lead agent 静态计划、子代理在自身范围内动态计划——层级=计划嵌套而非步骤串行。
- 判据：拆不拆先问"跨分区依赖稀疏吗/上下文传递便宜吗"；委派策略可用 RL 学而非手写；响应时间是硬约束且任务独立可分解→parallel fan-out with merge。
