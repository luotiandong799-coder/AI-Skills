## 落地 5 独点（每点标注提升层）

### 1. LangGraph HITL 实现机制：interrupt 原语 + checkpointer 硬前置 + thread_id 续跑（工具）
来源：langchain-interrupts / langchain-checkpointers / langchain-hitl / rentierdigital-hitl / markaicode-approval-gates / besthub-langgraph-hitl
- **interrupt() 是 HITL 原语**：暂停图节点→序列化状态→等待外部信号再继续——审批工作流（SQL 写/支付 API/删数据/发布内容/法律金融品牌决策）的标准机制，resume 恢复。
- **持久化 checkpointer 是硬前置**：没有 checkpointer 时 interrupt() **直接报错**——生产用 AsyncPostgresSaver/MongoDBSaver（或 SqliteSaver 本地开发），测试原型才用 InMemorySaver/MemorySaver；**全图必须配置 Checkpointer**，否则 interrupt() 无法持久化状态。
- **thread_id 是把暂停运行链接到恢复续跑的关键**——每次运行都要有，它当 key 把 paused run 接到 resumed continuation；恢复时传同一 thread_id。
- **interrupt_before 模式**：保存状态并在特定节点运行前暂停——进程可以退出，恢复时被暂停节点才执行（比节点内 interrupt() 更细的暂停点控制）。
- **检查点无界增长治理**：长对话/长工作流中 checkpoints 持续累积，增加延迟与存储成本——**定期剪枝旧 checkpoint 或设保留策略**（retention policy），不能放任无限增长。
- 判据：做审批型 HITL 用 interrupt()+持久化 checkpointer+thread_id 三件套；生产持久化选 Postgres/Mongo，不用内存。

### 2. Magentic-One Orchestrator：内外双循环 + 四子 agent 分工（工具/工作流）
来源：arxiv-magentic-one / aiwiki-autogen / aiwiki-magentic-one / microsoft-magentic / hivebook-magentic-one
- **Orchestrator 双循环**：外层循环做**高层规划**（创建计划/委托任务/跟踪进度/动态修订），内层循环做**逐步执行**（决定每步调哪个 agent/错误恢复）——先计划再执行、边执行边修订。
- **四子 agent 分工**：WebSurfer（浏览器操作：导航/点击/填表/提取，Playwright 底座）/ FileSurfer（本地文件读写）/ Coder（写 Python 代码）/ ComputerTerminal（shell 执行）——通用 open-ended 任务团队标配。
- **Magentic manager 模式**：专用 manager 根据**演进上下文+任务进度+agent 能力**选下一个行动的 agent；维护共享上下文、实时调整工作流（Microsoft Agent Framework 的 Magentic 编排）。
- **工程配套**：AutoGenBench 做**可重复基准**；OpenTelemetry 可观测性（traces 导出 Azure Monitor/Datadog/Grafana 像任何服务一样）。
- 判据：复杂开放式任务用 Orchestrator+专职子 agent 团队（浏览器/文件/代码/终端四件套）；评测跑 AutoGenBench、观测走 OTel。

### 3. AutoGen 维护模式与 Agent Framework 迁移路径（工作流）
来源：companyview-autogen / microsoft-autogen-migration / tencent-autogen
- **AutoGen 已于 2026-10 进入 maintenance mode**（微软正式声明）；Microsoft Agent Framework 是官方继任者（2026-04 发布）——新项目直接选 Agent Framework，存量 AutoGen 按迁移指南走。
- **迁移路线图已明确**：基本 Magentic 工作流（标准协调多代理）/ 检查点放大（持久协调工作流）/ 人机循环计划评审；未来模式=群模式（基于交接的代理协调）/ SelectorGroupChat（LLM 驱动扬声器选择）/ 带请求响应的人机循环。
- 判据：2026 起新多 Agent 工程评估 Agent Framework；用 AutoGen 的存量项目提前规划迁移（框架维护模式=安全与特性更新放缓）。

### 4. Claude Code hooks 生命周期事件：确定性执行机制（可复用 Skill/工作流）
来源：anthropic-power-user-tips / claude-steering-blog / code-claude-sdk-overview
- **hooks=在 agent 生命周期事件点确定性运行逻辑**——比提示词叮嘱强：命令/HTTP endpoint/LLM prompt 三类，注册在 settings.json、managed policy settings 或 skill/agent frontmatter。
- **四大高频模式**：SessionStart（**每次启动动态加载上下文**）/ PreToolUse（**记录每个 bash 命令**——审计全量日志）/ PostToolUse（写/编辑后**自动格式化防 CI 失败**）/ PermissionRequest（把权限提示**路由到 Slack/WhatsApp/Opus 审查**——分布式审批）。
- 判据：需要"必然执行"的机制（加载上下文/审计/格式化/审批路由）用 hooks 注册事件，不写进提示词靠模型自觉。

### 5. Auto mode：权限分类器中间地带（工具/工作流）
来源：anthropic-auto-mode-engineering / claude-auto-mode / code-claude-whats-new
- **auto mode 是权限中间地带**：介于"批准每个文件写操作"与 `--dangerously-skip-permissions` 之间——模型分类器替 Claude 做权限决策，安全动作自动放行、破坏性动作拦截。
- **双层防御**：输入层（服务端）管 Claude 读什么 + 输出层管 Claude 做什么——**每次工具调用前分类器检查潜在破坏性动作**（批量删文件/敏感数据外泄/恶意代码执行）；被判危险的阻止并让 Claude 换路径，**持续被阻止则让出**（不再硬闯）。
- 判据：长任务想少打断又不想全跳过权限→auto mode；破坏性动作兜底靠分类器双防御；与 §权限审批（PEP/HITL）分工=那条管"必须人批的"，这条管"批量放行但分类器守门"。
