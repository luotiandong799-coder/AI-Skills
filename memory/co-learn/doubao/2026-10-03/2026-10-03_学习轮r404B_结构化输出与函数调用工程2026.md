## 落地 5 独点（每点标注提升层）

### 1. Constrained decoding 机制与原生结构化输出选型（工具/模型）
来源：tensoria-structured-output / kanopylabs-structured-patterns / kalvium-json-vs-function / thepromptbench-reliable-json / zylos-constrained-decoding / devtoollab-structured-outputs
- **Constrained decoding=token 级掩码生成**：每步模型只能从与当前语法状态兼容的 token 中选——**schema 违反数学上不可能（不是"不太可能"）**；JSON Schema 编译成形式语法跟踪生成位置；XGrammar（CMU）token mask 生成 <40 微秒、比旧法快 100 倍。
- **原生 structured output 三选**：OpenAI `response_format:{"type":"json_schema","json_schema":{"strict":true}}`（Responses API）/ Anthropic tool use / Gemini response_schema——生产首选原生而非 prompt 技巧。
- **量化对比**：仅 JSON mode 无 schema 定义=**8-12% schema 违反率**；function calling+strict schema=**<0.3%**（代价 +80-150ms/调用）；schema 编译首请求 +10-15ms 延迟。
- **"100% JSON schema 可靠性"声明是语法保证，非语义保证**。
- 判据：需要保证解析先用原生 structured output（strict/工具）不用 prompt 技巧；可接受 schema 编译延迟；别把"100% 语法合规"当"100% 正确"。

### 2. 静默 schema 漂移与"结构合法≠语义正确"（模型/工作流）
来源：kalviumlabs-json-vs-function / arxiv-2607.18261-orderbench / arxiv-2603.27905-atlas-rtc / arxiv-2508.07935-shield-a
- **最难失败模式=静默 schema 漂移**：模型返回合法 JSON 匹配 schema 但**语义值错**——无错误信号（结构校验抓不到）。
- **ORDERBENCH 实证**：最强模型两模式都 100% schema validity 但**语义成功仍 ~80%**；弱模型 schema-valid 不安全接受双位数——**结构化输出是必要接口层，不是领域验证与 fail-closed 执行的替代**。
- **ATLAS-RTC 边界**：强制执行结构输出契约（JSON 合法/必需字段）但**不保证语义正确**——输出可满足 schema 却空值/默认值/不完整。
- **SHIELD-A 级联**：结构合理但语义错误（tomato 误标 apple）→下游规划步骤无效——**工具错误级联**。
- 判据：schema 校验通过≠值正确——关键输出加领域验证+fail-closed（不符即拒绝执行）；结构校验只当第一道闸。

### 3. 验证先于执行 + 结构化失败返回协议（工作流/可复用 Skill）
来源：mudassirkhan-function-calling / ai-tldr-tool-calling / theneuralbase-invalid-args-model / dev-aiwave-function-calling / togetherai-function-calling / llmversus-function-calling
- **第一原则=验证先于执行**：模型返回函数调用→**先跑参数校验逻辑再调真实函数**；缺字段/值出范围/引用实体不存在→**返回结构化错误描述给模型**——**模型能从显式结构化反馈恢复，不能从吞掉的异常恢复**。
- **工具失败返回结构化 error**（不抛未处理异常）：error code + plain-English message + suggestion——模型决定重试不同参数/调 fallback 工具/告知用户。
- **绝不跳过 tool result**：工具失败也返回结构化 error result——**跳过会导致模型幻觉**；配 max-tool-calls guard（10 次/会话上限）；可并行工具并行调用减 50-70% 延迟。
- 判据：工具调用两步=先校验后执行；失败永远以结构化错误返回（带 code+message+建议）；设置调用次数上限防死循环。

### 4. 工具 schema 四设计错与参数强制（可复用 Skill）
来源：openlegion-tool-use / loooop-tool-use / aiworkflowlab-function-calling / theneuralbase-invalid-arguments / alivedise-tool-use-patterns
- **schema 设计四错**：① categorical 值用 `"type":"string"` 无 enum→**模型发明无效值**（用 `"enum"` 约束）②参数缺描述→模型猜语义（**写显式描述+示例**）③全部参数 required→**模型在可选字段未知时拒绝调用**（只列真 required）④模糊工具名（process/handle）→模型无法区分（**用动词-名词**：submit_form/parse_date）。
- **参数强制**：模型可能给数字字段发字符串——用 Zod/JSON Schema coercion 或显式解析；coercion 失败返回结构化错误让模型处理。
- **provider 差异**：OpenAI 返回字符串 JSON 需 parse；Anthropic/Gemini 返回已 parse 对象；**Anthropic tools 每请求 +313-346 token 系统提示开销**。
- **tool use 新失败类**：schema compliance（约束解码消除/校验拦截）+ tool selection（错工具/该调不调/多余调用=提示与 schema 设计问题）+ mismatched ids/delayed replies（编排 bug 主要来源）。
- 判据：schema 每个 categorical 字段必有 enum；参数带描述与示例；required 只留真必需；工具名动词-名词；数字字段显式 coercion。

### 5. 自纠错重试环与小模型结构化救援（工具/工作流）
来源：spring-ai-self-correcting / pypi-llm-output-guard / pypi-providercontract / arxiv-2610.02001-mingbird / arxiv-2603.29848-agentfixer
- **自纠错重试环**：模型响应→schema 校验→失败把校验错误（"missing required field actor"）**回喂模型重试**（Spring AI validateSchema）——错误信息是重试输入不是丢弃原因。
- **llm-output-guard 模式**：自动 JSON 提取（**剥离 markdown fences 与散文包裹**）+ 可配置重试（固定/指数/线性退避 + jitter）。
- **providercontract 模式**：**一次定义期望形状，跨 provider 统一验证**（OpenAI/Anthropic/Mistral/LiteLLM）——schema contract 测试。
- **Mingbird 小模型救援**：**拒绝的 false-finish 消息总携带下一步可执行动作——最低成本恢复路径嵌入拒绝本身**；畸形调用结构化救援=识别三种形状（placeholder-quoted/bare-JSON/double-quoted pseudo-calls）转真实调用。
- **AgentFixer 输出验证**：事实一致性/代码语法/异常检测/reasoning-action 对齐+跨阶段一致性（提示-输入/指令-输出/管线完整性）——轻量规则+LLM-as-judge 混合。
- 判据：校验失败的错误信息结构化回喂模型重试（不是只记日志）；JSON 提取先剥 fences；小模型场景把恢复动作写进拒绝消息。
