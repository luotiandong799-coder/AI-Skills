## 三、核心方法与关键事实提炼（带来源）

1. **模式选择矩阵+三种 shapes 频率排序**（n8n）：deterministic pipeline 大多时候对→single agent with tools→orchestrator 最后；成本数学（orchestrator 调 1 specialist 调 2 tools ≥4 round-trips；嵌套第 3 层前问底层是否 deterministic；深度=不可观测+贵）；单 system message 自相矛盾=拆分信号。
2. **supervisor 纯路由+记忆架构**（n8n）：提示越小越好、工具=其他 agents、路由由 intent 描述决定；supervisor 独持 conversation memory、specialists stateless（每 agent 自己的 memory=对话版本分歧）；步骤顺序已知则 sequential pipeline 更优。
3. **多 agent 失败模式**（Anthropic research）：turf war（sabotage/伪装/杀进程）；成功协调=thoughtfulness+corrigibility；冲突解决=bake-off 可验证客观判据；rubric 明确性；grader 绝不看 scratchpad。
4. **编排平台硬限制**（Anthropic managed agents）：delegation depth=1、roster ≤20、concurrent ≤25、thread 持久、配置 pinning 快照固定、{"type":"self"}。
5. **Dify Agent/Workflow 分层+Invite 复用**：Agent 决定怎么做、Workflow 决定何时+周边；Invite 中央更新 vs one-time copy；New Agent 输出变量全集（调试可观测）。
6. **CUGA 上下文手法**（Langflow）：大对象存变量不进消息历史、短记忆只存变量摘要；Pipedream 解耦流水线（Generate 只用 key points）；Make Text aggregator 前处理。
7. **多 agent 成本与 traceability**（n8n）：Max Iterations 处处上限、按 conversation 成本跟踪、端到端 ID、agent 间边界注入防御。
8. **Skills 供应链安全**（Snyk/arXiv/USENIX）：SKILL.md 是 operational text；注册表侧三阶段攻击；三攻击向量；检测面缺口（*.test.ts）；description 是激活条件；read_only/read_write 隔离。
9. **Agent 一等资源与工具语义**（Activepieces/Make）：agent 命名/brief/复用/Publish 更新所有 flow；工具 name+description 决定使用时机；honest no-match；fix data before prompts。
