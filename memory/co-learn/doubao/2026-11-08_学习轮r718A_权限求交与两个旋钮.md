## 二、落地点（4 个真独点）

### 1. 权限逐层求交（工作流层）
tool allow/deny **先于**沙箱规则生效，被 deny 的工具沙箱救不回来；`tools.elevated` 是显式逃生门（默认 gateway）。判据：收紧向下叠加，放松必须显式开洞；排障先问「是谁 deny 的」。

### 2. 位置与批准是两个旋钮（工具层）
`tools.exec.host` 决定跑在哪，`tools.exec.mode` 决定怎么被批准，原文明确二者独立。判据：被拦先分两问——位置不对还是批准不对；别靠改位置绕过批准。

### 3. 模式名是 (security, ask) 预设组合（工具层）
每个 mode 解析成 security + ask 一对值（deny = deny/off、allowlist = allowlist/off）。判据：改模式名同时改两维；想「放宽但仍问人」时模式名表达不出来，要回到底层字段。

### 4. 只认 effective policy（工作流/可复用 Skill 层）
`approvals get` 打印 requested / host sources / effective；`exec-policy show` 验实际；重启才生效。判据：多源合并下「我写的」≠「生效的」，权限变更汇报引用 effective 值。
