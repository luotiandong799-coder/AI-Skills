## 本批独点（真独点，双键查重通过）

### ctx 系（并入 wb-context-compressor）
1. **会话生命周期 reset 三模式**：no reset（持续复用+compaction 管理上下文）/ daily reset（按配置小时换新会话，基于 sessionStartedAt 而非元数据写入）/ idle reset（真实用户交互超时换新，心跳/cron/exec 系统事件不延长寿命）；daily 与 idle 先到先赢。
2. **跨会话私密回忆检索**：rememberAcrossConversations=true 时跨该 agent 的其他私密会话检索相关上下文，只检索**不合并** transcripts；group/channel 默认隔离（groupScope per-group 双向隔离）。
3. **会话存储治理**：pruneAfter 30d / archiveDashboardAfter 7d / maxEntries 5000 / preserveRecent（可保护近期活跃会话）；**归档≠删除**（超 disk 预算才物理删除最老归档）；pinned 根会话、活跃工作、model-locked 会话受保护；清理先行 dry-run 预览。

### ed 系（并入 wb-execute-discipline）
4. **委派四要素**：每个 subagent 需要 objective + output format + 工具/来源指引 + 明确任务边界；含糊指令（"研究半导体短缺"）导致重复劳动、覆盖缺口、错误分工。→ 判据：**委派描述四要素缺一即返工**。
5. **effort scaling 规则**：简单事实=1 agent 3-10 次工具调用；直接比较=2-4 subagent 各 10-15 次；复杂研究=10+ subagent 明确分工；**把缩放规则写进 prompt**，防简单查询过度投入（早期失败模式）。
6. **工具自我改进闭环**：工具测试 agent 拿有缺陷 MCP 工具反复测试→重写工具描述→后续 agent 避开失败；实测任务完成时间降 40%。→ 判据：**工具描述与代码同等需要迭代测试**。
7. **先宽后窄搜索策略**：短宽查询→评估可用性→逐步收窄；防默认过长具体查询（返回极少结果）。
8. **thinking 双时点**：行动前 thinking 规划（选工具、定复杂度与 subagent 数）；工具结果后 interleaved thinking 评估质量、找缺口、精化下一查询——不是只在开头想一次。
9. **端态评估**：多轮改状态的任务按**最终状态**评估，不逐轮判过程（agent 可走不同合法路径到同一目标）；复杂流程拆离散检查点验证状态变化。
10. **rainbow deployments**：agent 部署新旧版本灰度共存、逐步转移流量，防打断运行中 agent（agent 可能在任何流程位置）。
11. **subagent 输出直写文件系统防传话游戏**：subagent 用工具把产出存外部系统、传轻量引用给协调者——防多阶段信息丢失（game of telephone）+省 token（不复制大输出过历史）；适合代码/报告/可视化等结构化产出。
12. **计划器前置注入**：AgentPlanner 在每次迭代前规划全部任务、把逐步计划**注入任务描述作为前缀**（CrewAI planning=True）——计划不是独立输出，是任务描述的一部分。
13. **评估立即开始用小样本**：约 20 个真实用例即可见大效应（prompt 调整 30%→80%），别等几百用例的大 eval 才启动。

### sa 系（并入 wb-skill-authoring）
14. **工具 docstring 三要素**：agent 靠工具名称+参数+docstring 判断用途与是否适用；type hints 决定预期参数与返回类型——**docstring 是 agent 的接口文档**，必须描述性、帮助性（与 ACI 工具设计同族补强）。
