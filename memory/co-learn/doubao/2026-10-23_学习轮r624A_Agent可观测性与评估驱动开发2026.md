## 四、提炼核心方法与关键事实

1. **评估与可观测分工**：Observability=run 期间发生了什么（traces/cost/tool calls）；Evaluation=结果好不好（LLM-as-judge/code checks vs known correct answer）——两个不同问题都要用；agent observability=传统 APM+AI 特定信号（工具调用轨迹）。
2. **行为评估与 calibrated 判据**：measure behaviors not just outputs（traces 验证工具选择/API 顺序/业务策略/验证步骤/引用证据）；calibrated judges（binary/rubric）胜过 Likert；success metrics 映射业务 outcomes 非 benchmark；多 trial 报 success rate 非 binary（100% 确定性可疑）。
3. **生产 traces 回流 eval**：数据管线两步（study public benchmark→mine production traces 从 incidents 起再挖无人审 transcripts）；dedicated evals teams+domain experts 自己跑；trace→dataset case 测变更；skill-on/skill-off 双跑配对评估证明技能编辑安全；production traces+feedback 变下一轮 test cases。
4. **可观测性基建**：structured logging（trace_id+span_id+timestamp+operation type）；五类日志（input/output/tool call/decision/cost）；MCP tool calls 默认落盘 jsonl；OTel GenAI 语义约定早标准化（最便宜可靠性投资）；每 turn 标准 OTel trace 先窄后宽。
5. **回归门控与 drift 检测**：metrics 随时间 degrade 触发（例 correctness 92%→84% 因 tool API deprecated silently failing）；每 6h 50 输入偏移 >5%；regression gating 任何下降阻断发布；同测试集对比隔离效果防 anecdote-driven。
6. **可观测指标与告警阈值**：P50/P90/P99 全跟踪（串行工具链 P99 剧增）；degradation alert 3 连续失败内触发+假阳性 ≤40%+TTL 30 天；RED metrics+LLM 层/依赖层分开；响应流程五步（alert→logs→review→fix→deploy→verify）+rollback 文档化。
