### 独点判据原文（逐条，不缩水）

- **r733A-1 ★编排失败是分布式系统故障，错误必须上浮且在交接边界做输出校验**：Microsoft 官方逐字把多智能体编排归入 "classical distributed systems problems such as node failures, network partitions, message loss, and cascading errors"，并给出两条硬动作："Validate agent output before you pass it to the next agent"、"Surface errors instead of hiding them, so downstream agents and orchestrator logic can respond appropriately"；原因逐字 "Low-confidence, malformed, or off-topic responses can cascade through a pipeline"，接收方应 "retry, request clarification, or halt the workflow to avoid bad input propagation"。判据：① 子 agent 结果进入下一跳之前必须有质量门（重试 / 请求澄清 / 中止三态），"看起来合理"不构成验收证据；② 错误不允许被中间层吞掉——隐藏错误等于让下游在脏输入上继续推理；③ 输出非确定性 ⇒ 验收用 "scoring rubrics or language-model-as-judge evaluations rather than exact-match assertions"，逐字精确匹配断言是错误验收方式；④ 隔离还须带 "Security trimming must be implemented in every agent in the pattern"——每个 agent 各自裁权限，不能指望编排器统一裁剪一次。与 r728A「完成投递积压 / 静默关停」分工：那条管结果交付与关停语义，本条管内容污染与故障传播。

- **r733A-2 ★子 agent 缺信息是任务书漏字段，不是上下文给少了；会话键复用会覆盖编排器 persona**：WSO2 官方逐字："By default a sub-agent is isolated: it receives only the task the orchestrator composes in its tool call, and runs in a fresh session"；"the trade-off is that results depend entirely on the orchestrator writing self-contained subtask specifications, which is also the pattern's main failure mode"；"Because the sub-agent cannot see the conversation, anything it needs must be in the task description"。⇒ 排查「子代理答非所问 / 缺信息」的正确动作是补全 handoff 字段并写进工具描述，而不是放开全量上下文（那会同时毁掉故障隔离）。存储侧逐字："Never reuse the orchestrator's session key"——"A sub-agent writing into the orchestrator's session pollutes it with the sub-agent's internal turns, and the store keeps only the latest system message per key, so the sub-agent's persona overwrites the orchestrator's"；"Never let two concurrent runs share the same memory instance and session ID"（两 run 交错成 "a single corrupted conversation"）。判据：① 默认无状态子 agent，确需记忆则按「子 agent × 会话」独立取键；② 会话键是身份容器不是聊天室编号，共用会把 persona 写没；③ "workers do not see each other's outputs" 是编排模式的显式属性，跨 worker 共享事实必须经编排器显式下发。与豆包自留地 `wb-context-compressor` 的 session key（n8n 多用户跨 run 混串）不同面：那条管跨用户隔离粒度，本条管父子 persona 覆盖与并发 run 交错损坏。

- **r733A-3 ★迭代预算按层级相乘、token 复利；交接载荷按 schema 而非 transcript，编排器不得当累加器**：WSO2 逐字："Every delegation is a full agent run with its own prompt, its own tool-calling loop, and its own tokens. A sub-agent that averages four reasoning steps turns one call into five"；"Token spend compounds. The orchestrator pays for the sub-agent's entire run, then pays again to reason about the result"；"Latency is additive"；"Iteration budgets multiply. Each agent enforces its own maximum iterations, so the worst case is their product, not their sum"。⇒ 两层各设 10 次迭代上限，最坏是 100 不是 20；层级越深越要逐层压上限并保持浅。LMVersity 逐字："A transcript records how an agent got somewhere, not where things stand"（整段转录把探索路径与已定结论同等可信地喂给下游）、"The orchestrator ends up holding the sum of everyone's context instead of the sum of everyone's conclusions — the single-bloated-agent failure mode rebuilt with extra hops"、"merge and discard once a worker's result has been folded into the plan, keeping the merged conclusion and a pointer back to the worker's original payload, not the payload itself"。判据：① handoff 按 schema（goal / decided facts / pointers / next steps）构造，每次交接自问「我是不是直接粘了 transcript」；② 每个跨交接的 finding 带指针（文件路径 / 查询 / 来源标签），否则出错只能全链路重跑；③ 共享黑板必须带单写者 + 时间戳 + 已定/半成形区分，"An unmoderated blackboard is a design that was never actually chosen, just defaulted into"；④ 验收看编排器上下文是随 worker **数量**增长还是随 worker **输出量**增长——后者说明上游没做合并。与 r732C「压缩不可逆 ⇒ 上下文做成窗口外可查询对象」互补：那条给可恢复性架构，本条给编排器在窗口内就别堆全量的合并纪律。
