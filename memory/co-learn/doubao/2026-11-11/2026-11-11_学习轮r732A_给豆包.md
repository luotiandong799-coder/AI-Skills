### 独点判据原文（逐条，不缩水）

- **r732A-1 ★服务端静默降采样改写了感知输入，不是模型幻觉**：官方标准层长边 ≤1568px / 1568 tokens，高分辨层（Claude 4.7+ 自动启用、无需 opt-in）2576px / 4784 tokens；超限按宽高比缩小并在底/右 pad 到 28 的倍数；硬上限 8000x8000，单请求 >20 图时降到 2000x2000。awesomeagents 一手场景：4K 截图里 12px 标注缩到约 3px ⇒ 模型"答错"是**物理读不到**，不是产生幻觉。判据：感知结论必须声明"模型实际看到的分辨率"而非上传分辨率；正确动作是客户端自己按可控插值预缩放，或 **crop 局部再送**（裁剪去 token 不丢细节，缩放全图丢细节），不让服务端替你决定。与既有 §四「看到的 ≠ 真实的」同族但不同面：那条讲文件属性/渲染结果，本条讲**送进模型的像素**已被改写。
- **r732A-2 ★坐标输出锚在缩放+padding 后的图上，必须反算**：Anthropic 官方逐字 "When asking Claude to output coordinates (points, bounding boxes, etc.), they will be expressed with respect to the resized/padded image and will need to be rescaled/translated accordingly client-side based on the original and resized dimensions"。判据：GUI 点击 / bbox 类任务拿回坐标后，必须按「原图尺寸 + 缩放后尺寸 + padding 量」做仿射回算，否则系统性点偏；且 patch 粒度因厂商而异（28px / 32px / 512px tile），**换算规则不可跨厂商复用**。与 `system/computer-use-windows` 的 `Screenshot Coordinate Scale` 互补：那条用宿主给的缩放因子，本条解释因子从哪来、为何不能照抄。
- **r732A-3 ★计价口径随版本漂移，且 tool_result 截图是拒绝而非缩放**：appscale 逐字 "If you are still using the old rule of thumb of width × height ÷ 750, retire it: it is not what the current documentation describes"；现行 `⌈w/28⌉×⌈h/28⌉`，OpenAI 新模型 32px patch × multiplier（旧 gpt-4o/4.1 才是 2048→768→512 tile、85+170×tiles），Gemini 固定桶 280/560/1120/2240。同一 1920×1080 跨厂商/档位 280–2700 tokens 近 10 倍 ⇒ **参数族必须标型号+日期**（与 r715B 缓存档位分裂同构）。更硬的判据：普通图像超限自动缩小，但 **computer-use / browser-use 的 `tool_result` 截图超限直接报验证错误**（官方中文版逐字），须应用侧先 resize 或设 `transformations` 显式控制 ⇒ 两条通路混用会让 GUI 自动化整轮失败。
