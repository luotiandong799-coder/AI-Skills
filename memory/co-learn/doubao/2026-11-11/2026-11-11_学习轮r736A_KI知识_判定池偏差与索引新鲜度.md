### 独点判据原文（逐条，不缩水）

- **r736A-1 ★未判定 ≠ 不相关：评测集本身带着建池检索器的偏见**：qrels 不可能穷尽所有 (query, doc) 对，只能用既有检索器的 top 结果组池，池外一律当无关。TREC-COVID 已用多系统 pooling 仍偏向词汇法：BM25 Hole@10 6.4%、TAS-B 31.8%。判据：① 换召回策略/embedding/加语义检索后**禁拿旧 qrels 直接判优劣**；② 报告必带 Hole@10 或等价未判定率，判定池覆盖所有参评系统 top-k；③ 本机自建评测集若只由字面 Grep 产候选，等于把字面偏见固化进标尺，须混入向量路或人工补标；④ 与 §三「结果可溯源」互补——溯源证明命中来自哪，本条证明「没命中」不等于「不存在」。
- **r736A-2 ★二元判定 + 跨库宏平均：一个总分同时抹平两种差异**：nDCG@10 按 ideal DCG 归一化解决 recall@10 不可比，但二元标签让 graded relevance 退化（全面回答与顺带提及同分）；18 库宏平均把生物医学/短 query 单域崩塌藏起来。判据：① 分库分桶报分，禁只报单一均分作上线依据；② 报分同时声明判定粒度（binary/graded）与每 query 相关篇数分布；③ 与 r736A-1 合起来是「评测有效性双门」：先看判定池覆不覆盖，再看指标配不配题型。与 `engineering/wb-agent-evaluation` r735A 的 SRM 分工：那边管对照组有没有被污染，本节管标尺认不认得新答案。
- **r736A-3 ★可查 ≠ 已落盘，且冷索引不会自动变新鲜**：refresh 让段在 filesystem cache 可打开被搜，无 fsync；持久化由 flush/translog 承担。current 默认每秒刷新**仅对近 30 秒有搜索请求的索引**。判据：① 「刚写入查不到」有两个独立成因（未 refresh / 冷索引未自动刷新），不要都当写入失败；② 验收分两点：可检索（显式 `_refresh`/`?refresh`）与可恢复（flush/translog/快照）；③ 批量重建期 `refresh_interval:-1` 提速，完成必须显式恢复并 refresh；④ 本机语义检索增量建库后核「索引时间戳 + 条目数 + 一次抽样查询」三件套，不凭脚本 exit 0 宣布新鲜。
