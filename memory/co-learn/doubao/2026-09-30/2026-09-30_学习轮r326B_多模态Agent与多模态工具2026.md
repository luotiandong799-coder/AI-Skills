## 独点（10）

1. **多模态输入层纪律：按任务加模态，别为了有而有**（来源：aikolhub《Multimodal AI Agents Guide》+ max-gherman.dev《Multimodal Agents》）——**输入层决定 agent 能感知什么（text/image/audio/files/screen state）；不要只因为模态可用就全加——每种额外输入类型都增加测试面、成本与幻觉风险**；**视觉输入三模式=直接观察（工具返回图像，如浏览器截图，模型直接看）/显式视觉工具调用（图理解子工具）/转录（OCR/ASR 先转文本再入循环）**。判据：**每个模态必须有对应任务才加；视觉进循环的方式按"直接看/调工具/先转录"三选一**。提升层：工作流。
2. **视觉只用在决策点 + 二次工具校验：plan in text, vision at decision points**（来源：aiagents.codeguides.io《How Vision Models Extend an Agent Beyond Text》+ max-gherman.dev）——**计划用文本推进，只在决策点用视觉（确认设置与工单一致/部署后断言 error toast 可见/图表类 PDF 表格提取失败时读图）**；**不可逆动作前必须第二工具交叉验证（schema validate / DOM re-query / human approve）**；**视觉提取→schema validator 工具是生产文档 intake 的赢家模式（需强 schema 与重试）**。判据：**视觉是决策点的感知器不是每步都开；视觉提取结果必过 schema 校验才可不可逆动作**。提升层：工作流。
3. **视觉工具组成式调用（VC-Tooler 式）**（来源：arxiv 2608.02217《VC-Tooler: Learning Compositional and Adaptive Visual Tool Use》）——**组合式视觉子工具集：rotate（纠正方向）/ enhance（提对比度亮度）/ code（跑 Python 做精确数值计算、几何作图、坐标视觉模型）/ multimodal search（文本或图像搜实体与实时知识）——模型学习按任务自适应组装工具而非固定调用**。判据：**视觉理解拆成可组合原子工具，模型按需组装，数值计算交给 code 工具而非目测**。提升层：工具。
4. **多模态工具执行三规约：per-modality timeout / 输入 hash 缓存 / 路由日志**（来源：theneuralbase《Multi-modal agents》production version）——**每模态独立超时（vision 5s / audio 10s / text 2s）**；**结果缓存按输入 hash 键控（同一张图不重复分析）**；**结构化记录模态路由决策（调了哪些工具、为什么）；独立模态并行异步执行**。判据：**多模态执行按模态隔离超时、缓存与日志，独立模态并行**。提升层：可复用 Skill。
5. **原生视觉模型取代传统 OCR 管道，accuracy-critical 保留校验层**（来源：zylos.ai《Multimodal AI Agents in Production》+ niteagent《Document Understanding Agent》+ madebyagents《Best Open Source OCR for AI Agents》）——**GPT-5.4/Claude Opus 4.6 单次模型调用取代 Tesseract+layout detector+table parser+post-processor 组合，标准文档直接 VLM 读**；**法律合同/医疗记录等 accuracy-critical 仍要二次校验（人审或规则）**；**开源本地管道=Docling/PaddleOCR/GLM-OCR/Qwen3-VL 提取 + LangExtract 结构化 + agent 审批或标记，全本地私有**。判据：**标准文档直接 VLM 读，关键流程加校验层；本地隐私场景走开源 VLM 管道**。提升层：工具。
6. **AgenticOCR：查询驱动的按需解析，替代静态全文 OCR**（来源：arxiv 2602.24134《AgenticOCR: Parsing Only What You Need》）——**OCR 从静态全文处理变为 query-driven 按需提取：模型"thinking with images" 分析版面，只识别与查询相关的兴趣区域；按需解压视觉 token；检索粒度从固定页级 chunk 解耦**。判据：**文档解析先问"这次检索需要哪部分"，按需提取而非整页全量 OCR**。提升层：工作流。
7. **多模态 RAG 三条路线：统一 embedding / 图增强多跳 / 双图解耦**（来源：aws bedrock multimodal retrieval + blog.google Gemini Embedding 2 + arxiv 2512.20136 M³KG-RAG + arxiv 2604.04969 MG²-RAG + arxiv 2607.28580 DualG-MRAG）——**路线1=多模态 embedding：文本/图像/音频/视频单模型统一编码进同一语义空间（1408 维，可图搜文/文搜图/视频搜图）**；**路线2=多模态知识图谱多跳：轻量文本解析+实体驱动视觉 grounding，文本实体与视觉区域融合为统一多模态节点保留原子证据，按模态检索**；**路线3=宏推理/微匹配双图解耦：宏观图做全局拓扑路由、微观图做细粒度证据验证，把全局结构推理与局部证据匹配隔离以抑制检索噪声**。判据：**多模态检索先定路线：统一 embedding（简单跨模态搜索）/ 图增强（多跳推理）/ 双图解耦（噪声抑制）**。提升层：模型/工作流。
8. **视觉文档摄取五步流水线：每步有可测失败模式**（来源：redeepseek.io《Turn a Screenshot Into Structured Data》）——**五步=捕获与归一（EXIF 旋转/deskew/统一 PNG 格式）/预处理/视觉模型读+JSON schema 结构化/校验（必填字段检查）/写库——每步有明确输入、输出与可测失败模式**。判据：**每个摄取步骤有可测失败模式，五步闭环才让截图像数据一样进库**。提升层：工作流。
9. **多模态评测 2026：MMMU 饱和转 MMMU-Pro、Video-MMMU 无人达人类基线、MMI 测模态成熟度**（来源：benchmarkingagents.com《MMMU Benchmark》+ Stanford AI Index 2026 + arxiv 2608.26317《Modality Maturity Index》+ videommmu.github.io）——**MMMU frontier 高 70s-80% 接近饱和、MMMU-Pro（frontier ~60%）成为活跃基准（双层报告成标准）；Video-MMMU（ACL 2026）无模型达人类基线 74.4%（最佳 Keye-VL-1.5-8B 66%，Claude-3.5-Sonnet 65.8%）**；**MMI=五模态×最多三模态组合 893 题，专测 omni 模型跨模态整合**；**provider self-report 是可展示证据，不是独立运行**。判据：**多模态评测认准未饱和基准（MMMU-Pro/Video-MMMU/MMI），self-report 分数不算数**。提升层：模型/评测方法。
10. **语音 Agent 五阶段管道与 800ms 预算**（来源：globussoft《Voice AI Agents Definitive Guide》+ irejournals《AI Voice Call Assistant》+ NVIDIA《Voice Agent with RAG》+ OpenAI Realtime API 系）——**生产语音 agent 五阶段顺序执行=Audio Capture+VAD→ASR→LLM 推理→工具执行→TTS，从语音到回复端到端预算 <800ms，每阶段独立优化（VAD/ASR 流式 200-300ms）**；**S2S（speech-to-speech）agent 模型直接消费音频原生特征（韵律/语调/说话人意图），在语音会话内直接触发工具调用/检索/handoff**；**2026-05 OpenAI 三个新音频模型=GPT-Realtime-2（GPT-5 级推理语音）/GPT-Realtime-Translate（70+ 输入→13 输出语言实时翻译）/GPT-Realtime-Whisper（流式 STT）**。判据：**语音 agent 按五阶段独立做延迟预算，总预算 800ms；能 S2S 直连就少一次文本转换**。提升层：工具。
