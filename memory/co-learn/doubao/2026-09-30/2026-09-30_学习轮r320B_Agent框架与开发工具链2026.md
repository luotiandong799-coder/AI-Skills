1. **三大 Agent 框架心智模型与选择矩阵**（来源：marsdevs 2026-05 + yuzec 2026-06 + bigaiagent×2 2026-05/06 + aiintegrator 2026-06 + the-agent-report 2026-07 + aiworkflowlab 2026-07 + decodethefuture 2026-06）——**AutoGen（Microsoft）=agent 协调=参与者对话；CrewAI=专家团队（角色+任务）；LangGraph（LangChain）=有状态有向图（编译器/工作流引擎抽象）——不是语法差异是心理模型差异**；**选择矩阵：LangGraph=确定性分支/长运行 state 持久化/human checkpoints/完整审计轨迹/生产标准（JPMorgan/Uber/LinkedIn），同任务比 CrewAI 省 18% token；CrewAI=本周出原型/非工程师可改/工作流简单（20 行第一个 crew）；AutoGen→Microsoft Agent Framework（AutoGen+Semantic Kernel 合并 GA 1.0，C#/Python first-class，Azure-native）=代码生成+迭代评审**；CrewAI Flows（自 1.0）=event-driven 条件分支+state 处理，把 agent 自主性包进确定性业务逻辑；LangGraph 学习曲线陡（ReAct ~120 行 vs CrewAI 20 行）。判据：**先问"要确定性还是要速度"，再选框架**。提升层：工具。
2. **Durable execution 与 HITL interrupt 模式**（来源：agentnative 2026-07 + aws eks 2026-06 + callsphere 2026-05 + anhtu 2026-05 + vadim 2026-06 + pythondatabench 2026-08 + arxiv 2607.19297 + xbstack 2026-04 + zylos 2026-05）——**run 是 store 里的一行不是活进程：state durable 后 process 死/pod 重调度/几天过去都行**；**interrupt() 暂停 graph+持久化 state+返回控制，API 层把 interrupt value 给人类（approve/reject/edit/pick），人类回应用 Command(resume=reply) 从精确 checkpoint 恢复不重启 workflow**；**注意：interrupt 前已跑的 node 代码在 resume 时重新执行——node 必须幂等**；**checkpoint=time-travel anchor（每 node transition 提交 backing store；thread_id=长会话；可 fork 新分支/replay 成 eval dataset/rewind 调试）**；生产用 SqliteSaver/PostgresSaver，MemorySaver 只测试；StateGraph=shared typed state+Nodes 函数变换+Edges 条件路由。判据：**HITL=持久化 workflow 边界不是 callback**。提升层：工作流。
3. **MCP 生态 2026：规模、信任模型与生产防御**（来源：dev nishilbhave 2026-06 + explainx 2026-06 + contextstudios 2026-09 + loooop 2026-04 + chatforest 2026-03 + dev x4nent 2026-04 + vibetoolstack 2026-06 + daily.dev 2026-04）——**规模：公开 MCP servers 1200（2025Q1）→9400+（2026-04），SDK downloads 97M/月（2026-03），OpenAI/Google 都采纳**；**三层信任模型=user→host（应用层）/host→client（host 管理 clients）/client→server（every server untrusted until verified）**；**生产四层防御=Authentication（OAuth 2.1+PKCE bearer，无硬编码 key 用 Vault）→Input validation（每 tool 参数 Zod/JSON Schema/Pydantic，never pass raw AI strings to shell/SQL）→Rate limiting+audit logs→fail closed on unexpected input**；**十大风险=token 管理+secret 暴露/scope creep 权限升级/command injection/tool poisoning（工具描述藏恶意指令）/供应链攻击/context injection+过度共享**；治理四阶段=AuthN/Z+输入校验（prompt injection defense+PII detection+minimum-privilege scopes）+server evaluation（源码审计/version pinning/供应链验证）+per-request token logging 成本追踪；实现=path validation（resolved.startsWith(SANDBOX_ROOT)）/process isolation（child_process.fork stripped env）/outbound allowlist/memory caps 128MB+30s timeout。判据：**每个 MCP server 默认不可信，装=扩权限按装权限流程审**。提升层：工具。
4. **Code-first 智能体与轻量框架**（来源：1337skills 2026-07 + madebyagents 2026-09 + innonexa 2026-06 + pypi smolagents + opensourceai 2026-07 + morphllm 2026-06 + cell-devlog 2026-06 + aigentlab 2026-07 + kdnuggets 2026-07 + futureagi oss 2026-05）——**smolagents（Hugging Face）CodeAgent=行动即 Python 代码（写+执行代码调用工具循环计算），核心 ~1000 行可读一个下午，任何 LLM 都行，MCP 集成最高水平；复杂 benchmark 上比标准 tool-calling 少 ~30% LLM 调用**；**CodeAgent vs ToolCallingAgent 选择：输出可预测性/安全性重要→ToolCalling；任意计算→CodeAgent；生产安全执行→E2B/Docker**；**smolagents vs Pydantic AI=generated Python vs structured tool calls（JSON）——任意计算 smolagents 强，严格 API 面 Pydantic AI 类型安全优；tradeoff=透明度+power vs 生产 polish**；LlamaIndex AgentWorkflow=workflow agents over data（FunctionAgent 包装 function-calling/ReActAgent ReAct loops），知识查找/转换/引用任务自然选。判据：**任务要任意计算还是严格 API 面，决定 code-first 还是 typed**。提升层：工具。
5. **Agent 可观测性：span-per-tick 与非确定性**（来源：langchain 2026-06 + databricks 2026-09 + logic 2026-07 + braintrust 2026-05 + dev kuldeep 2026-09 + mlflow×2 2026-06 + toutiao 钛媒体 2026-09）——**agent 非确定性：same input→不同 tool sequences/retrieved documents/responses——传统 APM 看 200 但看不到 looped twice/called wrong tool/hallucinated policy**；**span-per-tick：每个离散推理步骤=独立 span，parent trace（agent run）含 child spans（LLM call/tool invocation/memory read-write/sub-agent handoff）；每 tick 抓 input/output tokens/model ID/latency/token usage/cost**；**四大多步错误模式=agent loops（重复同动作无进展）/context overflow（超窗静默截断）/tool hallucination（发明未定义参数）/planning drift（弃初始 plan 追子目标）**；工具矩阵=MLflow（end-to-end GenAI 生命周期）/LangSmith（LangChain）/Arize Phoenix（RAG 调试）/Langfuse（self-hosted）/AgentOps（autonomous 监控）；**技术指标与业务留存关系随阶段变化——初期提正确率改善体验，达水平后继续优化同一指标未必同收益（边际递减）**。判据：**先修 observability 再谈诊断其他层**。提升层：工具。
6. **Agent 失败模式分类与修复**（来源：futureagi 2026-05 + mohithg 2026-05 + aws agentcore 2026-06 + mohakdeep 2026-06 + aikickstart 2026-05 + growthengineer 2026-05 + acingai 2026-04 + sherlocks 2026-09 + metacto 2026-04 + agentic-academy 2026-03）——**五大类=检索（corpus 2× 阈值重评估 chunker+embedding）/推理错误（retrieval 干净+plan 对+工具全好答案仍错——confabulated/算错/忽略 system instruction）/工具/记忆/规划；11 模式=tool hallucination/infinite loops/premature termination/context bloat/prompt injection/cost runaway/schema drift/stale memory/parallel tool race/partial-state corruption/eval-prod skew（每个有 trace fingerprint 可 grep+已知修复）**；**88% agent 失败=基础设施缺口非模型质量（Arize 2026）**；**Agent Failure Stack 六层=tool calls/retrieval/memory/planning/permissions/observability——无 reasoning traces 的 incident 平均 MTTR 显著更高**；**语义失败=tool 成功+model 处理但解释错（检索到表面相关实为不同版本）——单 tool 失败可能 retryable/skippable/process-ending，agent 需知区别**；**tool call ledger：orchestration 层维护自己账本——模型输出含 tool result 但无对应 tool call 记录=视为编造强制重跑**；自检=回应前生成"应做什么 checklist"逐项验证+eval 罚早退+查 response 不只 trajectory；**无限循环三根因=prompt 未设终止条件（多少次合理/何时宣布不可能/何时升级人）/识别错误失败/缺终止**；**风险分级=低（读/搜）自动，中（写 staging/草稿）log+可审，高（写生产/外部通信）强制人批**。判据：**失败模式先分类再对症，observability 优先修**。提升层：工作流。
7. **Agent 内存三层架构**（来源：upenn vldb 2026 + zylos 2026-04 + data-gate 2026-05 + arxiv 2608.00009 + programming-helper 2026-04 + neolabhq + sickn33 + arxiv 2603.07670 + aipromptshub 2026-06）——**三层=In-context working memory（当前会话原始消息 buffer/tool calls/active state，ephemeral 会话结束清）/Session-scoped compressed memory（摘要+事实按需读）/Long-term persistent store（跨会话知识/用户偏好/学到的 workflow，vector+structured）**；**长时四类=episodic（事件）/procedural（怎么做）/semantic（事实）/personal（偏好）；工具=Mem0/Zep（semantic）/Letta/Zep（episodic）**；**三种架构模式=A Monolithic context（全内存进 prompt——零基础设施全透明但容量上限+摘要漂移，短命 agent/原型）/B Context+retrieval store（working 在窗+long-term 外部 store+retrieval pipeline 注入）/C 分层混合**；**AgentMemBench 方法=CBS（Compression-Based Summarisation 周期压旧 context 成稠密 NL 摘要释放窗口）+WAM（Web-Augmented Memory 内部对话+实时外部知识 via web search/MCP——ChatGPT browsing/Claude MCP）**。判据：**短命原型用 A，多会话关系用 B/C**。提升层：工作流。
