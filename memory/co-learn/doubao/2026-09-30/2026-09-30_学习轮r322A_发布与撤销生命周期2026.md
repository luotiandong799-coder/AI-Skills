## 独点（10）

1. **撤回四模式对照：npm 真删 / PyPI·crates.io 禁删 / Go 软撤回**（来源：docs.npmjs.com 2026-07 + doc.rust-lang.org 2026-08 + golang retract 2026-08 + algomaster 2026-05 + blocksnetwork RELEASING 2026-09）——**四生态对"撤回"语义定义完全不同：npm=真删（registry 删条目+tarball，72h 内新包无依赖可任意撤，超过 72h 需全部满足=无依赖+周下载<300+单一 owner/maintainer）；PyPI=不支持真 unpublish（yank release+publish fixed version，禁新装）；crates.io=permanent archive 目标（永不删版本，yank 只从 index 移除、不删数据仍可下载——"no new dependencies can be created against that version, but all existing dependencies continue to work"）；Go retract=软撤回（retract 指令让 @latest 跳过，但显式请求 retracted 版本仍可得）**；**yank 语义精确化=新依赖禁建、旧依赖（有 lockfile 的）继续工作**。判据：**引用生态撤回语义前先查"它是哪种模式"（真删/禁新装/禁新依赖/软撤回）**。提升层：可复用 Skill。
2. **撤回资格机检与时间窗（npm 政策）**（来源：docs.npmjs.com/policies/unpublish 2026-07 + npm-unpublish CLI 2025-10 + docs.npmjs.com deprecating 2024-06 + moana-cli 2026-05）——**72 小时时间窗=新包无依赖随时 unpublish（72h 内）；>72h 走三资格机检**；**npm registry 未登录返回错误；unpublish 删 entry+tarball；deprecate 是推荐退休路径（不删、加 warning 到 metadata 消费者 install 时可见；undeprecate=把 message 换成空字符串）**；**"Always bump the version instead"——多数坏版本的正解是发补丁版而非撤回**。判据：**想退休用 deprecate；真正必须消失且过 72h 才走三资格机检**。提升层：可复用 Skill。
3. **版本撤销可恢复性与下载量门槛**（来源：learn.microsoft.com Azure Artifacts 2026-07/09 + docs.github.com packages 2026-09）——**Azure Artifacts 删包进 Recycle Bin 30 天，期间仅 feed owner 可恢复（误删/仍有团队依赖）——撤销≠销毁**；**retention policies=max versions per package+未下载 N 天自动删（可配置自动治理）**；**GitHub Packages 门槛=public package 整包>5000 下载或单版本>5000 下载不可删（下载量=保护伞，被广泛依赖的版本不允许消失）**。判据：**删包先进回收站并设恢复期；高下载量版本直接禁删**。提升层：工具。
4. **撤回信息传播不可逆：告知是义务**（来源：npmjs.com/policies/privacy 2026-02 + pm-claude-skills api-versioning 2026-07 + apiscout 2026-03）——**npm 会发布已擦除数据的 notice，但"npm can't make everyone who has downloaded published package data erase it"——撤回无法撤销已传播的数据，因此告知通道是撤回流程的强制组成**；**API 弃用 T-0 清单=决策日批准+新版本确认 stable+sunset date 设定→更新 docs 加 deprecation banner→所有 v[N] 响应加 Deprecation 与 Sunset response headers（格式：`Deprecation: Sat, 01 Nov 2026...`）**；**通知内容四件套=what 被弃用/why/替代迁移路径/sunset date**。判据：**撤回必须配 push 告知；API 弃用必须在响应头带 Deprecation+Sunset**。提升层：可复用 Skill。
5. **弃用通知三通道与目标化通知**（来源：docsie 2026-06 + talkthinkdo 2026-04 + releasepad 2026-06 + semver.org 2026-08 + theneo 2026-09）——**通道=文档 banner/changelog+sunset date/email 直接通知注册消费者/developer portal 显示弃用状态**；**目标化>广播：用 telemetry/API usage logs 识别"仍活跃调用被弃用端点"的消费者，定向直邮——比广播所有用户有效**；**semver 弃用规则=弃用公共 API 做两件事（①更新文档告知 ②在适当时机通过新次版本发布弃用信息）；主版本完全移除前至少要有一个次版本包含弃用信息（平顺迁移）**；**tiered update policy=auto-update patches/test minors/plan a migration project for majors**。判据：**弃用按"文档+响应头+定向通知"三管齐下；消费者按 semver 分档升级策略**。提升层：工作流。
6. **Sunset 时间表与支持窗口数字**（来源：alicinaroglu 2026-01 + beefed 2026-09 + releasepad 2026-06 + toughcrowdhq RELEASING 2026-09）——**6 个月 playbook=T-180 announcement（v2 上线+v1 弃用宣布+迁移指南就绪+通知消费者）→T-120 响应头加弃用警告+按消费者 usage 仪表盘→T-90 主动联系主要消费者+迁移协助+进度跟踪→T-60 v1 日限流开始递减（warning stage）**；**EOL 三阶段=Announcement（90-180d，email/blog/dev portal/in-product banner）→Reminder（60d，迁移工具）→Escalation push（30d，phone/CSM 定向高价值客户）**；**真实窗口对照=Twilio 24mo（12 support+12 deprecated）/Shopify ≥12mo 每版本+≥9mo 重叠/Stripe 不强制 sunset（版本 pin 到升级）/GitHub CLI 支持窗口=current major 收全修复、前一个 major 只收 critical+security 90 天（下一 major GA 后）、更旧 unsupported（除非 exceptional disclosure）**。判据：**sunset 提前 6 个月分阶段推进；支持窗口写进发布策略并显式文档化**。提升层：工作流。
7. **锁文件供应链基线：提交+CI frozen+PR 审 diff**（来源：dev trknhr 2026-04 + Z-M-Huang vcp 2026-05 + vulert 2026-06 + lidge-jun 2026-06 + codetreknomad 2026-04）——**lockfile（package-lock.json/yarn.lock/pnpm-lock.yaml/poetry.lock/Cargo.lock/go.sum）必须提交——记录实际解析的精确依赖树，无锁文件每次安装都可能不同**；**npm ci 围绕锁文件设计=package.json 与 lockfile 不同步即失败（CI 用 npm ci 不用 npm install；bun install --frozen-lockfile/poetry install --no-update）**；**每个 PR 审 lockfile diff（新依赖/升级泄露）**；**基线配置=.npmrc min-release-age=7/ignore-scripts=true/save-exact=true；pnpm v10 默认禁 lifecycle scripts（allowBuilds 显式放行）；CI 跑 audit（npm audit/pip-audit/osv-scanner）+SBOM；自动更新 PR 用 Renovate（preferred）或 Dependabot（auto-merge 限 patch/minor）**。判据：**锁文件是防守第一线——提交+frozen+审 diff 三连**。提升层：可复用 Skill。
8. **零日窗口排除：exclude-newer 滚动时间缓冲**（来源：kfchou 2026-03 + bastion 2026-03 + eshlox 2026-04）——**多数供应链攻击在发布后数小时内被检出，但 XZ backdoor 活跃数月——滚动时间缓冲排除"刚发布未经审查"的包（pyproject.toml 配 exclude-newer 永久默认）**；**Axios 攻击案例=caret range（^1.14.0）自动拉入恶意 1.14.1——用精确版本+hash 而非浮动范围**；**版本号 pin 防投毒=save-exact=true+save-prefix=''（.npmrc）**。判据：**新发布包设审查缓冲窗；生产依赖 pin 精确版本**。提升层：工具。
9. **发布侧信任面：staged publishing+provenance+OIDC**（来源：infoq npm staged 2026-08 + docs.npmjs.com trusted-publishers 2026-09 + colony-sdk RELEASING 2026-08 + pypi blog 2026-07）——**npm staged publishing GA=预构建 tarball 上传暂存队列（npmjs.com+CLI 均可见）→人工维护者过 2FA 才正式放行（staging 本身不需 2FA）——发布前加人工审核环节**；**trusted publishing（GitHub Actions/GitLab CI）自动生成 provenance attestations（默认无需 --provenance flag；CircleCI 不支持）——tarball 加密链接 git commit+workflow run，消费者 npm audit signatures 可验证链**；**OIDC 替代长期凭证=泄露的 NPM_TOKEN 让攻击者无限发布任意版本，OIDC tokens 分钟级过期+scoped 单 workflow run，无轮换负担**；**PyPI 2026-07=releases 拒绝对 >14 天旧的 release 上传新文件（防 token/工作流泄露后旧稳定版被投毒）**。判据：**发布走 staged+2FA；凭证用 OIDC 短时凭证；旧版本禁追加新文件**。提升层：工具。
10. **AI 代码评审开源落地与差分模糊测试**（来源：toutiao 2026-09 云易创智 + infoq npm staged 2026-08）——**阿里开源 OpenCodeReview=AI 辅助代码审查 CLI，内置空指针/线程安全/SQL 注入/XSS 漏洞检测规则+大模型动态代码分析——接入 CI 流水线在提交阶段自动扫描，减少人工 CR 重复量**；**Google 安全团队=AI+差分模糊测试方案（对比新旧版本行为差异找回归漏洞）**。判据：**代码审查自动化按"规则预检+LLM 动态分析"双层接 CI**。提升层：工具。
