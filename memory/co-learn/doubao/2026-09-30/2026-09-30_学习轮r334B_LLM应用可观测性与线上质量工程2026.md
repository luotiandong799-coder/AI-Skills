## 独点（10）

1. **trace 深度=嵌套 spans + 非确定性使 tracing 不可协商**（来源：marktechpost + mlflow + microsoft foundry）——trace 含用户输入/每次检索/每次模型调用（精确 prompt 与参数）/每个工具执行/最终输出；agent traces 深度嵌套+重 payload（单对话几十次 run 可产生 MB 数据）；同一 prompt 不同输出→必须 trace 才能 debug；OpenTelemetry GenAI 约定第一天埋点让 telemetry 存活于供应商切换。判据：**第一天埋 OTel GenAI 约定，trace 覆盖检索层+工具执行不止模型**。提升层：工具。
2. **三类评估器分层：确定性/统计/judge**（来源：dev.to + galileo）——确定性（正则/JSON schema/关键词黑名单）瞬时验证结构与合规；统计（BLEU/ROUGE/嵌入余弦）量化输出漂移 vs 基线；LLM-as-judge 评估幻觉/毒性/策略遵循/答案相关；SLM 可跑运行时护栏省成本。判据：**先确定性打底、统计量漂移、judge 管语义，按层分配成本**。提升层：工具。
3. **生产 trace 自动策展成评估数据集**（来源：confident-ai×2 + holmes）——生产 trace 自动转入评估集→测试覆盖率随真实使用演化、无需手工写测试用例；下一个回归跑用真实生产失败而非合成占位；"生产问题→测试覆盖"闭环无需手工管道。判据：**回归集从生产 trace 自动生长，不用合成占位**。提升层：工作流。
4. **线上评估采样 5-10% + 幻觉风险时间序列告警**（来源：valuestreamai + futureagi）——采样 5-10% 生产 trace 过评估器模型，faithfulness<0.7 告警；幻觉风险分时间序列跟踪、统计显著上升才告警；7 天滚动均值+标准差：today 均值跌>1.5σ 告警；安全指标跌=分页、质量跌=ticket。判据：**线上评估=采样+时间序列+1.5σ 告警，安全与质量分级响应**。提升层：工作流。
5. **失败四桶分类：ops/quality/structure/safety**（来源：latitude + dev.to 错误分类器）——HTTP 200 不代表工作——四桶：ops（rate_limit/timeout）/quality（幻觉/截断）/structure（JSON 无效）/safety（越狱/毒性）；每问题绑 trace+实时评分+审查+告警+回归测试；错误分类器预映射 retry 决策与严重度（rate_limit retry=True/medium、auth_error retry=False/high）。判据：**失败先入四桶再处理，每个问题绑全链路五件套**。提升层：工具。
6. **eval 成本可超推理成本：judge 调用必须采样**（来源：futureagi + respan）——frontier judge 4k rubric+2k output=3-10 cents/call；每个 span 全跑=成本爆炸（eval 成本>推理成本）；judge 分级（便宜快模型跑高频、frontier 跑抽样）+judge 调用预算 per pipeline tier。判据：**judge 调用按层预算，全量跑 judge 是成本陷阱**。提升层：工作流。
7. **prompt drift 检测=查询嵌入分布监测**（来源：mlflow + ayinedjimi）——基础模型更新让 Q1 好 prompt 在 Q3 降级——持续回归测试唯一防线；prompt drift=用户查询分布逐渐偏离评估集覆盖分布，检测靠监测查询嵌入分布显著偏离；prompt 变更也要 feature flag（5% 流量看指标再 ramp）。判据：**prompt 漂移靠嵌入分布监测+持续回归测试，变更走 feature flag**。提升层：工具。
8. **反馈捕获=主动循环：隐式信号免费且被低估**（来源：holmes + dev.to + amirteymoori）——eval 集静态/可观测被动/反馈捕获主动——把真实行为转下一代 eval 集+微调集+prompt 改进，无它系统上线日停止进步；隐式信号（编辑生成文本/重试问题/后续问题）比按钮免费；显式信号=thumb up/down+report 点击。判据：**反馈闭环=显式+隐式双信号，隐式信号要主动采集**。提升层：工作流。
9. **关键指标集 + 告警阈值模板**（来源：mlflow + aiworkflowlab + buyersprint）——error rates per tool/model/ai.error.type、token 趋势 per run/feature/tenant、cost per run+per successful task、cache hit rate；告警模板：p99>2×7 天基线 10 分钟、成本/分钟>3×24h 基线（runaway loop 或 prompt injection）、fallback>50%（provider 宕机）、cache hit 跌>30%（invalidation bug 或 prompt 模板变更）；TTFT+完整响应（流式靠 TTFT）。判据：**监控=指标集+阈值模板，成本突变先查 runaway loop/注入**。提升层：工具。
10. **管线预算分型：按管线类型定延迟/成本目标**（来源：zalt + respan）——Simple Q&A（RAG 单检索）P50 800ms/P99 2500ms/$0.003；Multi-step agent（2-4 工具调用）P50 3000ms/P99 8000ms/$0.02；每管线类型定义预算并告警突破；P95 尾延迟是用户可见慢所在（不在均值）。判据：**延迟/成本预算按管线类型分型，超预算告警**。提升层：工作流。
