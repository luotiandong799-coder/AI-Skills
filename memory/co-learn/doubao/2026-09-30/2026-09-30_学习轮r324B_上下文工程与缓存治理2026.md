## 10 独点（含提升层）
1. **context engineering 四动词分类法**——Write（窗外持久化：scratchpad/notes 存活不占活 token）/Select（只拉相关切片：retrieval/动态工具选择）/Compress（摘要历史/缩工具输出/state-schema 摘要替代全文）/Isolate（多 agent 或多沙箱拆上下文）；定义=“策展与维护推理期间最优 token 集”，核心工作=“最小可能的高信号 token 集”；与 prompt engineering 分工：prompt 答“怎么措辞”，context 答“模型现在应看到什么”。（提升层：可复用 Skill）
2. **三层内存层级 + 八层上下文权威**——Working memory（agent state/active goal/最近 N 轮/即时工具结果；LRU 默认+重要事实 pinned）/Session memory（1000-3000 tokens：compaction 摘要/关键决定/约束列表，会话恢复或压缩后注入）/Persistent memory（跨会话知识，按需检索只带小切片）；上下文优先级 8 层=provider policy→organization→product→workspace→domain runbooks→user task→active plan→loaded skills。（提升层：可复用 Skill）
3. **prompt caching 工程（生产最高杠杆）**——immutable prefix pattern=稳定前缀（System Prompt→Tool Definitions→Project Instructions）+增长尾；cache breakpoint 放“跨请求保持一致的最后一个块”；cache hit 需 byte-for-byte 前缀匹配；杀命中率五模式首位=system prompt 里时间戳（每秒变字节序→每调用 miss）；automatic vs explicit（最多 4 breakpoints）；TTL 5min/1h（extended）；Gemini CachedContent 最小 32768 tokens；cache hit rate=“生产 AI agent 最重要指标”（uncached vs cached 10× 价格差）；10K system prompt × 100-turn 会话仍拿 10× 收益锚定在 system block；pre-warm cache。（提升层：工具）
4. **rolling buffer cache-aware 与客户端镜像截断**——保留最近 N 张截图，旧 image blocks 批量换短占位符（“[Image omitted]”）保持前缀稳定（naive 一张张丢=每轮变前缀毁缓存）；服务端 compaction 发生时客户端必须 truncate_to_last_compaction（丢 compaction marker 前消息）保持双端视图对齐。（提升层：工具）
5. **compaction 实证损失与对策**——平均 83% 用户约束在压缩后消失（含“未确认前别删”这类安全指令）；Reclaim=“有损记忆比空记忆更糟”（brittle memory：保留错误结论丢推导过程→自信重发过期值，空记忆反而 abstain——关键=保留 re-derivation basis）；Slipstream=同步压缩两成本（静默降准确率+阻塞延迟）；ARC 可寻址召回压缩 Needle-in-Haystack 99.40% vs 基线 88.12%；LANTERN=零 LLM 调用归档每轮+压缩后混合检索恢复（<25ms/轮）；compaction 收益依赖模型（BrowseComp：Sonnet 4.5 平 43%，Opus 4.6 84%）。（提升层：工作流）
6. **上下文预算五分配**——C_sys（system prompt）/C_msg（消息历史）/C_tools（工具 schema）/C_aux（检索知识/记忆/技能）/C_reserve（输出 headroom）；实测参考=user profile 200-500 / RAG 4000-8000 / tool results 1000-4000 / history 4000-12000；A2C-RAG=intent 分类+多级自适应压缩+relevance 选择，prompt token 最高 -71%（多跳推理有准确率权衡）。（提升层：工作流）
7. **harness 级工具结果治理**——Tool Result Eviction=工具结果超 20000 tokens 自动 dump 文件系统+替换简洁文件引用（agent 需要时再读）；Deep Agents 四层 harness=Skills（按需渐进加载）/Memory（AGENTS.md 启动加载）/Summarization+offloading/Prompt caching；initializer agent+coding agent 跨窗口桥接（首跑设环境+每会话增量+留 artifacts）。（提升层：工具）
8. **compaction 必须点名保留什么**——Deep Agents 加 session intent+next steps 字段；Claude Code re-read 最近 5 文件；结构化 anchored iterative compaction（持久节模板）；provider-native summarization API 与 retrieval-augmented episodic memory 组合使用（无一主导）；compaction on demand vs threshold 选型；后台线程+prompt caching 组合（session memory compaction）。（提升层：工作流）
9. **lost-in-the-middle 机理与缓解**——U 型回忆曲线是架构性（residual-aware cumulative attention rollout：有限深度 causal Transformer 诱导早期+晚期注意力集中）；扩大窗口未解决；缓解=Send less（有效上下文当窗口分数非填满目标；40 chunks 6 相关就送 6）/关键内容放边缘+文档后重申指令/Found-in-the-Middle dummy 文档推理时校准（RAG 精度 +15 点无训练）/important-chunks 检索机制（相关性高+更近中间→更关键）；不同模型偏置模式不同。（提升层：模型/工作流）
10. **selective context injection（just-in-time）**——外部 store 维护全历史（vector db/结构化消息 store），每步只按当前查询语义相似检索 K 条最相关先前消息=复杂长工作流最高质量模式；轻量标识符（file paths/stored queries/links）而非预载全部文档，运行时按需加载=从 pre-retrieval RAG 转向 just-in-time。（提升层：工作流）
