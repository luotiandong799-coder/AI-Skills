## 独点（10）

1. **成本优化四杠杆分工**（来源：bestaiweb + finout + collabnix）——model routing 管单请求层/prompt caching 管重复上下文层/batch API 管工作负载时间层/context discipline 管上下文规模层；先定 spec（哪个杠杆管哪类工作负载）再配 config；各杠杆独立、相乘复合。判据：**先分杠杆归属再调配置，杠杆不是堆在一起**。提升层：工作流。
2. **metering first：trace 级成本可观测先行**（来源：aisuperior + callitdev）——先每 run 记录 input/output tokens、model、tool calls、retrieval chunks、unit-cost 货币值，按 tenant/intent/agent version/time 可查——回报最快的单笔埋点投资；不知道钱花哪就无从优化。判据：**成本可观测先于任何优化动作**。提升层：工具。
3. **成本按 outcome 优化，不按 session**（来源：builder.aws）——cost per outcome 是唯一值得优化的数；prompt caching 砍输入成本/context engineering 砍重试（复合成本大头）/修剪工具输出保缓存热；per-invocation tagging 把花费变成 per-workload 可行动数字。判据：**优化目标是"每次结果的成本"不是"每次会话成本"**。提升层：工作流。
4. **预算硬上限三层 + 原子授权**（来源：gettarmac + azure blog + microsoft365）——per-run/monthly/yearly caps 作硬限制（模拟卡网络原子授权，花钱前强制）；provider 级 spend ceiling+邮件告警；tenant/group/user 层 scoped billing policies；超限 429/403 而非放行后算账。判据：**预算=执行前硬强制（原子授权），不是事后账单**。提升层：工具。
5. **会话级 caps（run-scoped）+ poison pill**（来源：nerdleveltech + commandline microsoft + novapixel）——2026-08 AWS Bedrock AgentCore 发货 spend/behavior ceilings、Anthropic 单会话硬美元上限（首方从月/账号级降到单次运行级）；TokenOps 带 run id 贯穿执行图实时共享预算；poison pill 每 tool call 前评估累计成本、超预算立即终止。判据：**预算绑定 run 而非账号，每次工具调用前查余额**。提升层：工具。
6. **预算触发降级三路 ALLOW_WITH_CAPS**（来源：runcycles pdf）——预算紧张时先换更便宜模型/收窄工具集/降重试深度，无路可走才 alert/stop；两路系统直接 allow→deny 会造成可避免的工作流失败；三路系统给降级路径。判据：**预算触发先降级再停止，降级序列预定义**。提升层：工作流。
7. **prompt caching 静态前缀纪律**（来源：dev.to + softtechover + digitalocean + cnblogs）——缓存只作用于静态前缀（开头、跨请求完全相同）；write 1.25×/read 0.1×（-90%），break-even 1.4 次命中；变化内容（时间戳/随机/顺序敏感）放前缀后；命中率 7%→74% 靠稳定上下文+修剪工具输出。判据：**前缀稳定是缓存前提，变化部分后置**。提升层：工作流。
8. **成本护栏模式三件套**（来源：agentnative）——per-run guardrail+provider 级 spend ceiling+cost telemetry pipeline（按 tenant/agent/model 归因异常告警）+kill switch（与部署管线无关的独立急停，撤网关 key 或暂停 workspace）。判据：**护栏=上限+归因+急停三件套，急停独立于部署**。提升层：工具。
9. **路由成本分布目标 60/30/10**（来源：aiexpert + pristren + kunalganglani + rockb）——60% 请求小模型/30% 中档/10% 旗舰=60-80% 降本（配合缓存 90%+）；分类/抽取/格式化/短查询在便宜模型上等价；RouteLLM 2x+ 降本无质量损失；默认全旗舰=为便利付钱。判据：**流量按难度分层分布，便宜模型接走大头**。提升层：工作流。
10. **重试是复合成本大头**（来源：builder.aws + finout + claude blog）——每次重试=完整输入+输出重跑；context engineering 减重试比压缩单次更省；agent 循环每多一轮=输入重算（缓存命中除外）；cap output length+显式要求简洁；effort 校准到任务（CLAUDE platform 三修复：缓存命中率+去反模式+effort 校准）。判据：**省重试>省单次，agent 轮数是成本放大器**。提升层：工作流。
