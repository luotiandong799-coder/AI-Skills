## 独点（10）

1. **技能硬配额与命名规范（Claude API 侧）**（来源：platform.claude.com skills-guide 2026-09-28×8 语言版）——**每请求最大 20 skills；Skill 上传最大 30MB（所有文件合计、非压缩）；name 最大 64 字符=小写字母/数字/连字符 only、无 XML 标签、无保留字（"anthropic"/"claude"）；description 最大 1024 字符**；**与 WB r321A 已落 OpenClaw 配额（64 技能/256 files/1MiB per file/8MiB total）对照=不同平台数字体系不同，但"name 字符集+保留字限制"与"description 长度上限"是通用规范**。判据：**写技能前先查目标平台的配额与命名约束**。提升层：可复用 Skill。
2. **技能漂移=契约违反：主动维护**（来源：arxiv 2605.10990 2026）——**"Skill Drift Is Contract Violation"——技能随环境/模型变化悄悄失效（契约破坏）**；**SKILLGUARD=已知漂移验证 100% precision/76% recall；49 个真实技能预注册研究 86% conservative precision 发现 live drift；违反契约让修复可操作（one-round success 10%→78%）；DRIFTBENCH=880-pair 技能退化 benchmark**。判据：**技能有可验证契约（输入/输出/行为声明）；定期跑漂移检测，修复按契约定位**。提升层：可复用 Skill。
3. **技能健康五指标与执行遥测**（来源：agent-skill-bus 2026-07 + lobehub agent-self-improvement 2026-09 + ServiceNow 2026-07）——**自改进五指标=①all-time average score（基线质量）②recent average（分析窗默认 7 天）③trend direction（improving/stable/declining/broken）④consecutive failure count（从最近往前连续失败数）⑤flagged status（需要关注）**；**遥测六维=usage frequency/execution time/error rates/trigger accuracy/user satisfaction——从 SQLite/JSON 日志收集，含 unused-skill detection 与 cross-skill dependency mapping**；**ServiceNow=Tool choice accuracy（Excellent→Moderate 下降=agent 指令或 tool description 缺口）与 Tool calling correctness（参数格式/值）**。判据：**技能健康用"基线+窗口+趋势+连续失败+标记"五指标量化，不只靠感觉**。提升层：可复用 Skill。
4. **分层技能评测与风险分层：绝不 collapse 成一个模糊分**（来源：iwoszapar Agent Skill Evals Manual 2026 + ubos 2026-06）——**每个技能 eval 建成分层 case= routing/deterministic contract/trajectory/final state/semantic quality/repeated-run reliability/cost/security——只用需要的层，但绝不合成为一个模糊分数**；**风险分层=P1 business critical（triggering precision+recall≥90%；behavior 无超出声明边际的回归，pass³ 报告；judge≥85%+分歧人审）vs P2 low risk（precision+recall≥85%；contract suite 通过+effect 非负；advisory 除非校准）**；**Tool-call accuracy=首次即正确的工具调用占比——每次失败调用加 retry turn 增加推理成本（Hermes 新部署 67%→30 天技能积累 80%）**。判据：**评测分层不合并；按风险等级设定触发/行为/裁判门槛**。提升层：可复用 Skill。
5. **技能审计四工具与 policy-as-code**（来源：skillscheck.ai 2026-04 + spec-weave 2026-09 + mech.app 2026-09 + openclaw.direct 2026-07）——**技能审计=staleness report（markdown/JSON 给 team/CI）/audit（幻觉包/prompt injection/dangerous commands/dead URLs）/lint（metadata 完整性/结构质量/格式）/policy（.skill-policy.yml policy-as-code 组织信任规则）/budget（token 测量）**；**skill allowlist=预批名单（名单内免审安装，名单外需安全团队 sign-off）+skill scanning 进 CI（critical/high severity 阻断 merge）**；**marketplace 模型优化 discovery+volume，registry 优化 trust boundaries——13% 漏洞率问题催生 validated skill marketplace**。判据：**装第三方技能走 allowlist+扫描+审计四工具；组织信任规则 policy-as-code 化**。提升层：可复用 Skill。
6. **权限模式谱与 subagent 分类器三检查点**（来源：code.claude.com permissions/security 2026-09 + sub-agents 2026-09 + permission-modes 2026-09）——**权限模式=default（manual）/acceptEdits/auto/dontAsk/bypassPermissions/plan——bypassPermissions 跳权限提示（含 .git/.claude 受保护路径写入）但 cross-session messaging safeguards 仍生效；Manual=read-only 起步，编辑/测试/命令先问（approve once 或 always），内置 read-only commands 集合**；**subagent 权限分类器三检查点=①启动前评估委托任务描述（危险任务 spawn 时阻断）②运行中每动作过分类器同主会话规则（subagent frontmatter 的 permissionMode 被忽略）③完成时复核——权限由父会话强制，subagent 自声明无效**；**未设置 permissionMode=继承主会话（Pro/Max/Team 默认 auto）；maxTurns 达限返回 partial 标记可续跑**。判据：**子 agent 权限不可自声明，父会话分类器三检查点强制**。提升层：工具。
7. **Hook 强制与沙箱兜底：bypass 也拦**（来源：code.claude.com agent-sdk permissions 2026-09 + settings-example 2026-09 + safeguard 2026-07）——**PreToolUse hook 在每一步前执行，hook 拒绝在 bypassPermissions 模式下同样生效（唯一不被 bypass 的拦截层）；被阻断的 agent 配对 allowedTools+permissionMode:"dontAsk"**；**sandbox 配置=sandbox.enabled/failIfUnavailable=true（沙箱建不起来就拒绝启动）/allowUnsandboxedCommands=false（被阻命令不许在沙箱外重试）/network.allowedDomains 限定（默认 npm+GitHub，用户不可加域）**；**检查第三方技能能否 auto-update 不经 re-review——能自动更新=每次更新都是新的未审代码**。判据：**hook 是 bypass 也生效的强制层；沙箱失败即拒绝运行；禁 auto-update 免审**。提升层：工具。
8. **执行隔离四模型：reasoning 与执行分离/可销毁环境/内核级强制/gVisor**（来源：learn.microsoft sre-agent 2026-07 + docker blog 2026-06 + developers.redhat ring model 2026-07 + google gke 2026-04 + azure container apps 2026-09 + aws lambda microvms 2026-09）——**模型①推理与工具执行分离计算边界=agent reasoning 在主 runtime 处理消息/选工具，tool execution 在 sandbox micro VM 跑文件操作/bash/代码分析/MCP 工具**；**模型②每 agent 独立可销毁环境=有真实工作环境（可装包/跑服务/改文件）但不能达 host 或其他 agent——出错毁掉重开（"fundamentally different from permission-based"——这是隔离不是权限）**；**模型③内核级强制=Ring 1 sandbox supervisor 用 seccomp/Landlock/network namespaces per-binary/per-path/per-endpoint 强制，策略在进程外（agent 被攻破也不能覆盖）→Ring 2 pod 安全标准/SELinux/NetworkPolicy**；**模型④gVisor=每容器专用 guest kernel 拦截 syscalls（容器内 breach 不升级到节点）；Azure Container Apps Sandboxes GA（优化 bootable disk image 含 agent harness/runtimes/toolchain）**。判据：**工具执行与推理分边界；隔离环境可销毁重建；策略放进程外内核级强制**。提升层：工具。
9. **凭证网络边界注入与 egress 白名单**（来源：redhat openshell 2026-05 + nvidia openshell 2026-09 + telleroutlook agentkit 2026-07）——**credentials 永不进沙箱=inference routing proxy 在网络边界注入凭证——即使 agent 被攻破也无可窃取（exfiltrate nothing）**；**policy 可表达"agent runtime 可达 api.github.com 但沙箱内其他进程不可"——OpenShift driver 每 agent 一个 K8s pod 全策略执行**；**allowedHosts: string[] 空=网络全关（不能 DNS-resolve/fetch/WebSocket；WASM kernels 无 socket primitive）**；**未覆盖面=经 allowed hosts 外泄（agent 把偷的数据上传到允许读的同一文档 host）——mitigation=allowedHosts 限具体路径+governance 层 egress monitoring**；**NVIDIA OpenShell=gateway/supervisor/sandbox 管理 agent fleets、检查出站请求、kernel 级文件系统/进程控制**。判据：**凭证在边界注入不入沙箱；egress 白名单空=全关；外泄经允许 host 是盲区需监控**。提升层：工具。
10. **基础设施监控≠agent 有效性监控**（来源：aws blog agent lifecycle 2026-09 + ubos 2026-06 + MMEHDI0606 skill-optimizer 2026-08）——**CloudWatch 等基础设施指标显示"系统执行正确"，但不显示"agent 是否帮用户达成目标"——"requests to the unintended specialist while the infrastructure metrics stay green"（发错专家但基础设施全绿）——agent 有效性监控需要不同方法**；**skill-optimizer=8 维度审计只读不修改（skills 不触发/质量/上下文 token 浪费），数据不足报 "N/A — insufficient session data" 不硬编**。判据：**绿的基础设施指标不能证明 agent 有效；技能审计只读出报告不擅自改**。提升层：工作流。
