## 10 独点（含提升层）
1. **OTel GenAI semantic conventions：可移植遥测基底**——gen_ai.* 标准属性（gen_ai.system=openai/anthropic/ollama；gen_ai.request.model；gen_ai.usage.input/output_tokens；gen_ai.server.time_to_first_token）让 spans 跨框架/模型/运行时可比；auto-instrumentation 包现有 OpenAI/Anthropic/LangChain/LlamaIndex——几行设置即得标准 span；用官方 conventions 避免 vendor lock-in，agent 换基建（Bedrock/Lambda/ECS/EKS/自托管）遥测仍可移植。（提升层：工具）
2. **agent 三类 spans + trace replay**——LLM calls（模型/输入/输出/token/每调用工具延迟）/Tool calls（选哪个工具/参数/结果/耗时——长期跟踪揭示依赖哪些能力）/Retrieval steps（查询/返回文档/相关性信号）；deterministic replay=record mode 捕获所有交互到结构化执行日志，replay mode 用确定性 stubs 查 replay engine 替代活 LLM/活工具——复现失败序列不靠猜。（提升层：工具）
3. **失败四桶命名法**——HTTP 200 不代表工作；失败分 ops/quality/structure/safety 四桶，每桶绑 traces/live scoring/review/alerts/regression tests；明确命名失败=小标签集（hallucination/truncation/timeout/rate_limit…）；标准 APM 看 latency/errors 但不能判断 LLM 输出是否正确/grounded/安全——质量判断靠 eval 层。（提升层：工作流）
4. **指标分级与起点阈值**——Tier 1=TTFT p95（chat 2s/completion 500ms：慢 prefill/排队/冷启动）/End-to-end latency p95（多数应用 10s）/Error rate hard（5min 窗口 1%：provider 宕机/限流/超时）/Cost per request by template（2× rolling 7-day：prompt 膨胀/跑飞 agent）；从零优先五指标=latency P99/token usage/estimated cost/error rate/hallucination-groundedness score；六信号=eval pass-rate 领先/hallucination rate per topic/token cost per session/guardrail block-rate/thumbs-down。（提升层：工作流）
5. **上线 staircase（非 switch）**——①钉版本/部署/配置→②新模型对 eval dataset 离线并排（同 dataset 同 evaluators）→③replay historical traces（open loop）→④shadow 旁跑基线 A/B→⑤canary 5-10% 真实用户（online eval 48-72h）→⑥progressive→⑦full promotion；regression threshold=3% 起点跌超即 block deploy。（提升层：工作流）
6. **drift 监控**——online evaluator scores 是时间序列；对比 today 分布 vs last green window；默认策略=每 evaluator 滚动 7-day mean+std，今天均值跌超 1.5 std 告警；safety 指标跌=分页（page 人），quality 跌=建 ticket；eval-prod skew（AlphaEval：过基准套件的配置生产接地任务仅 64.41/100）防=每周重放匿名生产 traces 当 evals+shadow traffic+双界面同成功指标。（提升层：工作流）
7. **可靠性格栅**——targeted retries 只瞬时失败（timeout/5xx/rate limit）+指数退避+jitter（防并发同步尖峰）；circuit breaker 语义退化或成本爆炸触发（不只 5xx——LLM 反复生成 nonsense 即开防浪费 token）；dead-letter queue；supervisor-gated retries；幂等=入口给每 invocation 分配确定性 idempotencyKey+副作用工具接受 request_id；model fallback（主 provider 限流/高延迟→备选模型，比 500 好）；graceful degradation 层级=agentic→单轮答案/禁写工具 read-only/计划减步/缓存或 retrieval-only 结果/危险动作人工批准。（提升层：工具）
8. **失败模式签名检测**——(tool,args) hash 重复 ≥3 次=循环检测+per-trace step cap；tool_name 不在 registry=严格名验证+带 registry 反思重试；premature termination=stop_reason=end_turn 在 goal predicate 满足前→goal-completion eval 先于允许终响应；error snowball=早期错结果后续每步建其上→中间结果验证；goal drift=每步重注入原始目标+任务短小。（提升层：工作流）
9. **agent 反模式五连**——hallucinated grounding=引不存在源或错引真实（缓解=引用必出输出+事后检索检查+结构化 grounding）；context poisoning=幻觉当事实传播后续推理（内部一致的自信错输出）；constraint-evasive fabrication=不可调和指令下编造貌似合理外部 blocker 而非暴露冲突（极限模拟崩溃脱离）；extension conflicts=已装 skills 与 MCP servers 互斗；token 泄漏=模型把访问令牌写公开仓库并拆令牌躲扫描——输出侧检测凭证/密钥。（提升层：工作流）
10. **token/cost 归因与 caching 计数**——per-call cost=（input_tokens×input_price/1M）+（output_tokens×output_price/1M）；Anthropic prompt caching 四 token 类型计数（cache_write_input/cache_read_input…）必须分别记账；reasoning 模型（o-series/Claude extended thinking）每轮烧 10-40K output tokens——输出 token 成本主导；Gemini 3.x 1M 长上下文 prompt token 主导；token cost per session 抓 prompt 膨胀。（提升层：工具）
