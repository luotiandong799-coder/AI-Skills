## 独点（10）

1. **Context engineering 取代 prompt engineering：显式打包相关代码/docs/约束再 prompt**（来源：AI Coding Agent Practitioner Update 2026）——context packing=显式把相关代码/文档/约束倒进窗口，别让 agent 猜；investigation 用 subagents。判据：**prompt 前先做 context packing，相关文件/约束显式入窗**。提升层：工作流。
2. **Spec-first prompting：先写 spec 再写 prompt**（来源：blink.new + KDnuggets + dev.to Spec-Driven）——spec 回答四问（做什么/不做什么/成功定义/验收）；15 分钟 spec vs 2 小时返工；改变计划比改代码便宜 10 倍；SPECIFY→PLAN 四阶段。判据：**写码前先产出 SPEC（范围+非目标+验收），prompt 只是 spec 的搬运**。提升层：工作流。
3. **Goal-Constraint-Example 三段式 coding prompt**（来源：AI Bytes 9 best practices）——Goal=要什么结果/Constraints=必须遵守什么（库/模式/性能）/Example=相似代码或输入输出对；与工程化指令同源但这是 coding 专用形态；弱 prompt（"解析 CSV 求和"）vs 强 prompt 对照。判据：**coding prompt 固定三段：目标+约束+示例，缺一即返工源**。提升层：模型。
4. **多并行会话：3-5 sessions 各占独立 git worktree**（来源：Claude Code 高级用户技巧）——最大生产力解锁=并行跑 3-5 会话，各自 worktree 互不污染；原生 --worktree 支持。判据：**并行编码任务按 worktree 隔离，冲突面最小化**。提升层：工作流。
5. **AGENTS.md 评审规则四原则：覆盖从 58%→98%**（来源：Codex 知识库）——target consequential non-obvious invariants（评审者反复解释的检查：兼容性/数据边界/安全敏感模式）；scope appropriately（仓库级根文件/服务级嵌套文件）；state the safe path（不只说 don't）；规则分层。判据：**仓库评审规则按"重要非显然不变量+分层放置+给安全路径"写，四原则缺一覆盖就掉**。提升层：可复用 Skill。
6. **评审 rubric scope：告诉模型忽略什么，与大 diff 分块**（来源：modeldatabase）——rubric 写忽略项，与 linter 重叠=重复噪音；大 PR 按文件分块审再合并评论；severity discipline（只报某级以上）；选择性加 repo 上下文（diff 歧义时含函数所在文件，别全发）。判据：**评审 prompt 显式声明忽略范围，diff 分块保上下文聚焦**。提升层：工作流。
7. **确定性注入三处：agent 化代码评审的反非确定性设计**（来源：OpenCodeReview arxiv 2608.09290）——rule-guided dispatch 多层规则系统确定性选文件与评审准则消除自由发挥；三处确定性=选文件/评审准则/评论可靠；比"最大自由度"便宜且深。判据：**评审 agent 用规则系统锁定"审谁+审什么"，确定性先于自由发挥**。提升层：工具。
8. **6 并行评审 agent：按关注面分模型分 agent**（来源：/review-changes Claude Code）——Code Quality（bugs/逻辑/类型）/Accessibility（WCAG 2.1 AA）/Repo Style（AGENTS.md 合规/i18n/feature flags）/Performance（re-render/N+1/bundle size）各配不同模型档位；并行+焦点单一。判据：**评审拆成关注面单一的并行 agent，焦点越窄噪音越少**。提升层：工作流。
9. **钩子+技能固化工程流程：ECC 模式**（来源：CSDN GitHub 周报 + dev.to sarantoon）——用 hooks 把规划/测试/审查固化成工程流程（不是提示词叮嘱）；Ponytail 懒人阶梯约束少写代码；system-prompts-and-models 收集各工具系统提示词做逆向工程。判据：**工程流程用钩子机制固化，替代提示词叮嘱**。提升层：可复用 Skill。
10. **harness 化生产 agent：端到端控制 agent 执行**（来源：vibecoding radar strands-agents/harness-sdk）——open-source SDK 构建 agent harness 端到端控制（任意模型/任意云）；比 framework 更底层=控制执行不是调用。判据：**生产 agent 优先 harness 端到端控制，不靠 framework 黑盒编排**。提升层：工具。
