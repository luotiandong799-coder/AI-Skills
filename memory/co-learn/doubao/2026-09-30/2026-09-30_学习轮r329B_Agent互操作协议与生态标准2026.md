## 独点（10）

1. **MCP 与 A2A 分层定位：管工具 vs 管 agent**（来源：a2a-protocol.org a2a-and-mcp + agentprotocol.ai）——MCP=agent 调工具（描述工具能力、传输入收结构化输出、LLM 调外部 API/查库/连函数）；A2A=agent 间协作（标准化独立、常不透明的 agent 如何协调达共同目标）；agentprotocol.ai 三层=Agent↔Tool（MCP）/Agent↔Agent（A2A，HTTP+JSON-RPC/SSE，原语=Agent Cards/tasks/messages）/Agent↔LLM。判据：**先分层再选协议——MCP 解决"agent 用工具"，A2A 解决"agent 用 agent"，不是二选一**。提升层：可复用 Skill（协议选型）/工作流。
2. **A2A v1.0 原语：Agent Card / Task / Message + 多绑定 + 版本协商**（来源：a2a-protocol.org v1.0 博客 + 2606.31498）——Agent Card=JSON-LD 元数据描述能力/skills/端点（agent 发现）；Task 委托、Message 交换；v1.0 强调成熟非再造：多协议绑定（HTTP/SSE 等）、无缝版本协商、共同语义模型让跨栈跨组织 agent 可预测互操作；由 Google 开发、2026 捐给 Linux Foundation。判据：**接 A2A=暴露 Agent Card（能力声明）→ 接任务 → 换消息，三原语打通 agent 间协作**。提升层：工作流。
3. **协议治理缺口 G1-G6：MCP/A2A/ACP 表达不了的治理语义**（来源：arxiv 2606.31498）——G1 准入/移除协议缺失；G2 商议缺失（路由协议无商议语义）；G3 投票缺失；G4 异议缺失；G5 人工升级缺失（无升级机制）；G6 审计缺失（协议无审计原语，只有实现层日志）。判据：**协议解决通信，治理（准入/商议/投票/异议/升级/审计）必须在协议之外自建**——别假设协议能管行为。提升层：工作流。
4. **身份缺失：2000 个 MCP server 全无认证；82.4% agent 服从恶意 inter-agent 指令**（来源：arxiv 2603.24775 AIP + knowyouragent.network）——AIP 扫描 ~2000 MCP servers 全部缺乏认证；A2A/MCP 都未验证 agent 身份，"连接本身就是凭证"；无身份验证→82.4% 的 agent 会服从来自其他 agent 的恶意命令；AIP=公钥可验证委托 + holder-side 衰减 + 链式策略 + MCP/A2A 传输绑定。判据：**接 agent 网络默认不可信对方身份——身份验证层（AIP 类）必须补上，不能靠"连接即凭证"**。提升层：工作流（安全）。
5. **Signed Agent Card：Claim 与 Proof 的间隙**（来源：futurumgroup + heybeagle）——A2A v1.0 的 Signed Agent Cards 提供密码学可验证的能力声明（证明卡片由域主签发）；但不证明"执行期间 agent 行为在声明范围内"——Claim↔Proof 间隙需要尚不存在的运行时 attestation；MCP 架构=策略执行插入点 + 通过工具响应做提示注入的扩大攻击面。判据：**签名证明"谁签的卡"，不证明"agent 正在按卡执行"——运行时行为验证要单独设计**。提升层：工作流（安全）。
6. **审计防篡改：应用层日志可被改写，必须密码链+外部锚定**（来源：IETF draft-sharif-agent-identity-framework）——应用层审计默认非防篡改：维护自己审计日志的 agent 可改写成对操作者有利的条目；只有密码链（引用前记录）与外部锚定（跨 agent 一致的锚点）提供防篡改证据；跨 agent 一致性是基础。判据：**审计日志=链式引用+外部锚定；只写本地日志等于可被自证的日志**。提升层：工作流。
7. **技能注册表生态：2026 公开注册表 >180,000 技能，SkillsMP 聚合 200,000+**（来源：mr.technology + spec-weave + github johnku2011 + skills.sh API）——skills.sh=每技能 id/slug/name/source/installs 的稳定唯一标识 API（`{source}/{slug}` 格式构造详情路径）；SkillsMP=跨源聚合元目录（质量信号=来源归属+跨平台去重）；2026 公共注册表（Skills.sh/Claude Registry/HF Skills Hub/GitHub awesome-agent-skills 等 40+ 小注册表）合计 >180,000 技能。判据：**选技能先看注册表稳定 id 与来源归属，聚合目录只当发现层不当信任层**。提升层：工具。
8. **Skilldex 两档信任模型：verified/community，无自动升级路径**（来源：arxiv 2604.16911）——verified=仅限 Anthropic 官方发布技能，手动分配，无自动晋升；community=任何认证 GitHub 用户可发布；二元模型的刻意简化——星级/ karma/多级晋升都会引入通胀动力学侵蚀层级信号价值；schema：id/name/description/source_url/trust_tier/score(0-100)/spec_version/tags/install_count。判据：**技能信任=二元（官方 or 社区）比多级评分更抗通胀；发布走社区、要官方就得人工认证**。提升层：工具/可复用 Skill（技能治理）。
9. **dot-skill 协议：protocol_version 精确匹配 + skillerr 密封/签名/审计**（来源：dot-skill PROTOCOL + FAQ + skillerr-com）——协议规格独立版本化（1.0.0 Stable，RFC 流程演进非静默修订）；skill.json 带 protocol_version，`skill validate` 与运行 CLI 精确比较——不 semver 范围、不放宽，不匹配=硬错误；skillerr=skill 包的信任/完整层：seal/sign/记录 provenance/运行前 inspect；`npx skills add owner/repo` 装的是无完整性校验的未验证指令+可执行脚本。判据：**技能包协议版本必须精确匹配；从任意仓库裸装技能=执行未验证脚本**。提升层：工具/可复用 Skill。
10. **Trust Root：技能验证=HTTPS URL 前缀信任边界 + 跨平台可移植开放标准**（来源：IETF draft-zzn-dvs + claude.com building-agents-with-skills + skillmd.ai）——技能视为 verified 当且仅当其 URL 以声明的 Trust Root 开头（品牌一方域=域源；UGC 平台=平台不担保个人发布者）；Agent Skills 开放标准（Anthropic 首创、25+ agent 产品采用）让同一技能跨 Claude/Codex/Gemini CLI 等平台可移植；跨平台兼容=适配多 agent 产品的技能价值最大化。判据：**技能信任=URL 前缀域绑定；做可移植技能先按开放标准写 SKILL.md，别锁单平台特性**。提升层：可复用 Skill。
