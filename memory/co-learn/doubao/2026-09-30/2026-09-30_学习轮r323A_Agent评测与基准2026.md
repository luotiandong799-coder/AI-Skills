## 独点（10）

1. **评测数据三来源与生产故障永久用例**（来源：LangChain readiness checklist 2026-03 + AWS AgentCore dataset management 2026-05 + raftlabs/Anthropic 2026-03）——**每任务无歧义+参考解证明可解；正例（行为应发生）+负例（行为不应发生）都测**；无生产数据时生成 seed examples（来源=dogfooding errors/adapted external benchmarks）；**Anthropic 推荐 20-50 个来自真实失败的任务——不是 synthetic 不是 benchmark：从 support tickets/escalation logs/user complaints 找 agent 失败处，每条=Input（触发失败的精确查询）+Context（相关状态）+Expected**；**生产故障→永久测试用例（AWS AgentCore：版本化 test fixtures，故障成 permanent test case 每次变更都对照）**；synthetic+trace-based 结合（synthetic 填 launch 前缺口+边界 case，traces 反映真实行为——两者是互补不是替代）。判据：**评测起点=真实失败用例；故障发生后立刻固化为测试用例**。提升层：工作流。
2. **评测集版本化与三区分区锁定**（来源：iwoszapar manual + MS synthetic dataset 2026-09）——**三分区=train 上调 prompts/graders，development 上对比方案，test set 锁定（不 tune）**；scenarios=versioned immutable numbered versions（inputs/expected outputs/assertions/tool sequences——draft 迭代到 lock checkpoint，不随 run 漂移）；**agent 指令显著变化→重生成并版本化评测数据**（旧 prompt 版本生成的数据变 stale）；数据与指令版本绑定。判据：**评测集=版本化不可变夹具；prompt 大改必须重生成数据**。提升层：工作流。
3. **LLM judge 校准三规则与可观察证据**（来源：vibeengines 2026-05 + exemplar 2026-06 + iwoszapar + openrouter 2026-09）——**人先手评 ~20 trials，judge 跑同 20，Cohen's kappa<0.6 即 judge 不可靠→修 rubric 重跑**；**提供 "Unknown" escape hatch——强制二值隐藏判断不确定性，judge 应能说"不确定"**；校准集含 clear positives/negatives/borderline/difficult slices，报告 confusion matrix/balanced accuracy/agreement corrected for chance/bootstrap CIs+per-slice（language/length/domain/risk/model）；**criteria 写可观察证据**（弱="The response is accurate and helpful"；强="The response states the 14-day refund window, uses the retrieved order date"——换成 judge 能在响应中定位的要求）；模型/prompt/rubric/domain 变化→重校准。判据：**judge 上线前必须过人工校准；rubric 写可定位证据不写宽标签**。提升层：可复用 Skill。
4. **Task+Process 双评分与三证据通道**（来源：ClawTrack arxiv 2607.28037 + Claw-Eval 2604.06132 + GroundEval 2606.22737）——**双评估=Task Score（agent 达到了什么）+Process Score（怎么达到的：goal alignment/efficiency/information utilization/result verification 四维逐轮打分，12,541 rubric 项锚定）**；每 run 三独立证据通道=execution traces+audit logs+environment snapshots（trajectory-aware grading 基础，2,159 细粒度 rubric）；**answer score+trajectory score 用 track-specific weights——路径中心的任务轨迹权重大**（GroundEval：Perspective/Silence 类轨迹权重重）；Claw-Eval 评分协议=Completion+Safety+...。判据：**只评结果不评路径会漏掉"结果对但走错路"的失败**。提升层：工作流。
5. **确定性轨迹匹配与 LLM 判断分离跑 CI**（来源：aiworkflowlab 2026-03 + evalview 0.4.1 + genai.qa 2026-04）——**评测结构化为 pytest 用例进 GitHub Actions；确定性 trajectory matching tests（快/免费/每次 push 跑）与 LLM-judged evals（慢/贵/PR 或定时跑）分开**；pytest markers 控制哪个上下文跑哪批；quality gates=分数低于阈值阻塞部署；evalview=golden baseline diffing 回归检测（支持 LangGraph/CrewAI/OpenAI/Claude/HF/Ollama/MCP）；**AgentClash=重放每步找行为分歧点（每个 think/tool call/observation 捕获，回退到分歧时点看 prompt+tool）**。判据：**快慢评测分离；回归 diff 进 CI；分歧可回放定位**。提升层：工具。
6. **工具调用五维评测**（来源：microsoft agent evaluators + Future AGI four-layer stack 2026-04 + agentest）——**五指标=Tool Call Accuracy（正确调用+正确参数+无冗余）/Tool Selection（正确且必要）/Tool Input Accuracy（参数正确）/Tool Output Utilization（正确使用工具结果于推理与最终响应）/Tool Call Success（无技术错误）**；四层 stack=①Tool selection（选对或正确不选——irrelevance bucket）②Argument extraction（schema-valid+语义正确）③Result utilization（Groundedness+ContextAdherence with tool result as context）④（高层）；**扣分式 evaluator（TaskCompletion -0.25 per issue/Safety -0.2 per violation/Cost binary/Latency 1.0 pass 0.5 fail）**。判据：**工具评测按"选择-参数-利用"三层走；"正确不调用"也是评分项**。提升层：工具。
7. **成本与延迟指标：cost-per-success 与分布报告**（来源：exploreagentic 2026-06 + kunal 2026-08 + getwidget 2026-06）——**Cost per task=总 tokens+tool invocations per job——最被低估的 agent 指标，悄悄毁单位经济学**；**cost-per-success=总花费/成功结果数——捕获 retries/tool fees/long trajectories 的真实成本；公平比较报分布（median+P90）不只平均值**；**Latency 报 p95 不报 mean——agent tail latency brutal（一个慢工具/一个额外推理循环主导）**；**gate releases on 少数高信号指标=schema validity/safety canaries/cost-per-success drift**；实测读值=safe-refusal rate 0.97/cost per resolved task $0.11（$0.38 p95）。判据：**成本按成功计费口径+分布报告；发布闸用少数高信号指标**。提升层：工作流。
8. **评估 harness 层与可移植控制标准**（来源：agentic-ai 2026-09 + microsoft ACS Build 2026-06）——**评估 harness 不只模型——模型在 benchmark 高分仍可因 harness 弱点灾难失败**；harness 级类别=Task success/Tool selection precision（选对+避免不必要）/Permission correctness（权限检查在正确时机触发）/Approval correctness（审批请求在正确风险级发出）；**ACS 五检查点=input/LLM/state/tool execution/output——确定性控制逻辑（classifier endpoints/LLM judges/custom filters）放在需要处；policy YAML 表达=portable/versionable/auditable，框架无关**。判据：**评测含 harness 级类别（权限/审批触发正确性）；控制规则 policy-as-code**。提升层：工作流。
9. **轨迹六指标与 golden trace 重放**（来源：genai.qa 2026-04 + claudexia production playbook 2026-04）——**轨迹六指标=①Trajectory accuracy vs golden（exact/semantic match）②Tool-call precision/recall（调用对工具）③Path efficiency（步数 vs 最短正确路径）④Cost efficiency（tokens/tool calls/wall-clock per successful trajectory）⑤Safety（拒绝不当动作+抵抗 prompt injection）⑥Recovery metrics（注入失败后的成功率）**；**golden trace replay=100 真实生产 traces 冻输入重放 diff 对照记录（exact match 可用处用，不能处 structural diff）——回归检测的主力**；Claw-Eval 300 任务 9 类三组（general service orchestration/multimodal perception/multi-turn professional dialogue）。判据：**轨迹评测含恢复类指标；golden trace 重放做回归主力**。提升层：工具。
10. **多 agent 评测四类与协作盲区**（来源：Galileo 2026-03 + Zylos 2026-03 + padiso 2026-04 + Future AGI CrewAI 2026-05 + AAAI 2026 judge）——**四类=performance（latency per agent step/task completion）/coordination quality（handoff success rate/tool selection accuracy）/cost（token per agent）/reliability（error clustering/drift detection）**；**最未解挑战=inter-agent collaboration assessment（平台善量单个 agent，不善量协作）**；**role adherence 是主指标+task delegation/crew coherence/manager-worker fidelity**；补充指标=Agent utilization（active vs idle）/delegation depth distribution/review convergence rate（max_iterations 前收敛比例）/Team throughput（更多 agents 是否 diminishing returns）/Failure propagation（一 agent 失败影响多少下游）；两 tier judge=agent 级（observation alignment/tool selection/state consistency）+system 级（task completion/role distribution/complexity——MASComplexityMetric 管多步分解+层级问题求解）。判据：**多 agent 评测单独量协作质量（handoff/role adherence/失败传播）**。提升层：工作流。
