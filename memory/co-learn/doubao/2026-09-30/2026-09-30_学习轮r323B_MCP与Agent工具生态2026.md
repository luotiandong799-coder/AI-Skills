## 独点（10）

1. **MCP 2026-07-28 规范：stateless 核心+扩展框架+授权对齐+弃用政策**（来源：modelcontextprotocol 官方 blog 2026-07-28 + AWS agentcore gateway 2026-07）——**stateless core=普通 HTTP 基础设施上扩展（Netlify 等平台一键托管）**；**extensions 框架=MCP Apps（server-rendered UIs）+Tasks（长运行工作）加入**；授权对齐 OAuth 2.0/OpenID Connect 企业实践；**formal deprecation policy+lifecycle guarantees=协议演进不破坏已有构建**。判据：**2026 最大修订——新 MCP 部署按 stateless HTTP 建模，长任务走 Tasks 扩展**。提升层：工具。
2. **传输迁移路线与缓存稳定**（来源：MCP roadmap 2026-03/08 + blog index.xml 2026-07）——**目标=本地服务器也统一 Streamable HTTP over stdio——单一传输简化 server/client**；SEP-1442 把 stateful sessions 迁向 stateless requests（stateful 与负载均衡冲突/horizontal scaling 需 workaround）；**list responses 带 cache hints+deterministic order——客户端可缓存工具目录并跨重连保持上游 prompt 缓存稳定**；**server-to-client requests（sampling/elicitation）改用 Multi Round-Trip Requests (MRTR) 移除常开双向流**。判据：**新 server 优先单一传输；目录缓存=跨重连稳定性的关键**。提升层：工具。
3. **MCP 远程安全基线：OAuth 2.1+resource indicators+aud 验证**（来源：moai.team 2026-06 + tomodahinata 2026-07 + DZone 2026-09 + aiworkflowlab）——**OAuth 2.1+resource indicators（RFC 8707）从第一天实现——token 绑定特定 server 不可重放于其他**；PKCE 全客户端强制；远程 server=OAuth 2.1 resource server：**验证收到的 access token 的 aud（audience），只接受给自己的，且 never pass tokens downstream（规范禁止）**；Streamable HTTP 验证 Origin header（DNS-rebinding 防御）+TLS termination；**OAuth 2.1 完全丢弃 implicit flow（遗留客户端必须重写）**；claim exp+scope=token 未过期+含被调工具要求的 scope。判据：**远程 MCP=资源服务器语义（aud 校验+token 不下传）+Origin 校验**。提升层：工具。
4. **工具=任意代码执行：最小权限+人批+输入校验四层**（来源：tomodahinata 2026-07 + Context Studios 2026-09 + arXiv 2603.13417）——**工具当任意代码执行设计：least privilege，破坏性操作路由人工审批**；认证与工具授权分开（每个工具单独 scope）；**四层防御=Authentication（API keys 或 OAuth/OIDC bearer）→Input validation（Zod/JSON Schema/Pydantic 验证每个参数——never pass raw AI-generated strings to shell commands or SQL）→Rate limiting+audit logs（agent 突发调用工具）→（高层）**；**per-request 遥测记 sanitized input_params+audit fields（principal/tool/resource/trace）+p50/p95/p99 latency per tool/success rate/error rate/cache hit rate/circuit breaker state+/health+/ready**。判据：**工具调用前参数 schema 校验；日志记脱敏参数与审计字段**。提升层：工具。
5. **MCP Registry 风险与组织级治理**（来源：dev.to 2026-09 + CYFIRMA 2026-06 + thepromptbench 2026-07 + blamejs 2026-09 + Corvus arxiv 2608.00150）——**官方 registry 最小化审核（主要 namespace 验证，非深度安全审计）；恶意/buggy 工具易进公共索引；~38% 社区 servers 无原生认证；9,400+ servers 任何开发者可发布无身份验证/安全评审**；**组织级治理=维护 approved MCP server registry（name/version/hash/approved scopes）→MDM 分发 approved configs→阻止 unapproved 安装→监控 endpoint config 新增**；**pin exact versions+验证签名/hash（registry 有则用；server 无任何完整性机制本身是信号）**；优先官方 vendor org（modelcontextprotocol org 或 vendor 自己 GitHub）；Corvus=开源 34 测试模块（13 static+21 dynamic）覆盖 MST-10 全 10 类+SARIF 输出。判据：**装 MCP server 前按 registry 治理清单核（版本钉死/hash 验证/approved scopes）**。提升层：可复用 Skill。
6. **事件驱动 agent 自动化：MCP events spec**（来源：IT之家 OpenAI 插件 2026-09-30 + MCP docs draft architecture 2026-09 + swoofer mcp-coordinator 2026-09）——**OpenAI 支持拟议 MCP 事件规范——插件在已连接应用发生事件时启动自动化**（如关注项目看板新任务→新任务出现 ChatGPT 读关联文档起草计划）；用户始终自主选择插件；**real-time notifications=servers 通知 clients 变更不需轮询——change notifications opt-in（subscriptions/listen 请求+notifications filter 命名主题）**；**topic pattern 订阅（coordinator/+/consultations/new、/+/messages、/+/agents/+/status）=事件驱动多 agent 编排实例**。判据：**事件驱动代替轮询；agent 编排可基于事件主题订阅**。提升层：工作流。
7. **工具目录的上下文成本与语义路由**（来源：Zylos adaptive tool composition 2026-06-01 + Zylos context engineering 2026-06-20 + OpenAI Agents API 2026-09 + Dynamic ReAct arxiv 2509.20386）——**每个工具定义消耗 context tokens——单个 YNAB 交易工具≈663 tokens；整个 Playwright MCP server 持续消耗 14,300 tokens 即使浏览器自动化从不用**；**Taskade：移除不相关工具=准确率 80%→100%+token 用量 -40%**；**Layer 1 Semantic Tool Routing=注册时把每工具描述嵌入向量索引→每 turn 嵌入当前意图→cosine similarity 检索 top-K→只注入 K 个进模型 context**；OpenAI tool search=按需加载相关 tool definitions 减少 token+保留模型缓存；Dynamic ReAct=Search and Load 架构最优（只多 2 次 LLM 调用+高选择准确率；Fixed Tool Set 靠缓存省成本但长对话退化）。判据：**工具目录不全文注入——语义检索 top-K；无用工具是纯负债**。提升层：工作流。
8. **工具描述与 schema hygiene**（来源：BestHub 2026-05 + Viblo 2026-07 + Preprints survey）——**Tool description 是 top-3 高优化潜力区（1000-3000 tokens，与 system prompt/history 同级）**；**弱模型 schema hygiene=inline $refs（不引用外部）/恢复 double-encoded JSON args/scrub framework internals from validation errors/split overloaded schemas（拆过载 schema）**；**typed route plan 作为数据（哪个模型/哪些 provider/fallback order——loop 永不 branch 在模型名）+provider stream 归一化为一个 chunk contract+native tool calling 唯一调用路径**；工具空间限制=GeckOpt/SING intent-based selection 先缩工具空间，Less-is-More/SkillLens 多级搜索留更小子集。判据：**工具描述按 token 高价值区对待；弱模型配 schema hygiene 清单**。提升层：可复用 Skill。
9. **Agent 工具闭环优化：observe-evaluate-optimize-deploy**（来源：AWS AgentCore release notes 2026-09-17 + Microsoft Foundry Agent Service 2026-06-03）——**三能力闭合环=Optimization（分析生产 traces+evaluator outputs 推荐更新 system prompts 和 tool descriptions，内置 A/B 测试验证再上线）/Batch evaluation（重放 curated/historical sessions 比 pre/post 分数抓回归）/User simulation（LLM-backed actors 生成真实多轮对话）**——持续用生产数据改进 agent 无需重训；**换模型不改 agent 代码+端到端 tracing 看 agent 每个决策+Entra ID/RBAC/content filters+版本化 agents 发布稳定 endpoints**。判据：**agent 改进闭环=生产 traces 分析→工具描述/system prompt 更新→A/B 验证→回归重放**。提升层：工作流。
10. **工具目录缓存与重连稳定策略**（来源：agiflow 2026-07 + Zylos 2026-06-20 + LangChain Deep Agents 2026-05）——**Anthropic prompt caching=cache reads 0.1x base input price/5-min cache writes 1.25x/1-hour writes 2x；OpenAI=prompt prefixes 完全匹配自动缓存**；**缓存不修复糟糕 workflow shape（cache misses/output 仍贵）**；**目录缓存策略=Fixed Tool Set 靠缓存省成本但长对话性能退化（agent 倾向直接工具调用）→长对话用 search-and-load**；**code interpreter=轻量 runtime 让 agents 组合工具/管状态/控制什么进模型 context（无全沙箱开销）+harness profiles=per-model tuning（含 open-weight Kimi/Qwen/DeepSeek）**。判据：**缓存优化排在 workflow 形状修正之后；长对话别依赖固定目录缓存**。提升层：工具。
