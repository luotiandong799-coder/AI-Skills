## 独点（10）

1. **HITL/HOTL/Out-of-loop 三模式选择**（来源：anhtu.dev + superkind + gainam）——In-the-loop（每风险动作前 approve/reject/edit，agent 暂停：不可逆高风险）；On-the-loop（实时监控、出错介入，agent 运行：可停可回滚的快流）；Out-of-loop（事后日志审计：可逆、高量、低风险）。判据：**介入点位置=动作不可逆性与回滚成本决定；三种模式不是偏好是风险适配**。提升层：工作流。
2. **人工审批主判据：不可逆或爆炸半径>暂停成本**（来源：zalt + agentpatternscatalog + openlegion）——单一原则覆盖 90% 决策；其余是设计期风险矩阵，不是运行时让模型自己判断。判据：**审批规则在设计期编码，不是运行时模型判断**。提升层：工作流。
3. **升级四触发：规则违例/新颖性 OOD/置信度低/异常统计**（来源：superkind + waxell + opennash + openlegion）——规则违例（agent 永不执行，升级并点名违例规则）；新颖性 OOD（未见过的输入分布：陌生发票格式/供应商名不在库）；置信度（top-token logprobs<0.7 触发升级钩子）；异常统计（agent 平时 5-10 封邮件突然 400 封——行为分布外，与置信度无关）。判据：**升级触发四类齐备：规则/新颖/置信/异常**。提升层：工具。
4. **按动作粒度渐进授权：错误率 5% 毕业**（来源：pickaxe + aivanguard + ai-crescent）——跟踪每动作类型错误率，低于阈值（~5%）从 in-the-loop 毕业到 on-the-loop；agent 通过可靠性逐动作挣自主权而非第一天全给；好 analytics 才可毕业。判据：**自主权按动作类型渐进授予，用错误率数据毕业**。提升层：工作流。
5. **HEM 协议：升级是内核级会话状态**（来源：IETF draft-sato-soos-hem + arxiv 2605.27628 + openlegion）——HEM_PENDING 状态+结构化升级请求路由到指定人（有序指定链）+状态转换禁止直到人类决策+5/6 种人类决策类型；失败模式（无限运行/自动继续/永挂起）被单一受控路径替代；Mandatory Escalation=本地恢复超时必升级，不得无限停留。判据：**升级是会话状态机一等公民，不是 prompt 叮嘱**。提升层：工具。
6. **升级超时三策略 + 拒绝恢复预映射**（来源：openlegion + waxell + aiagents.codeguides）——超时策略按成本配比：auto-reject（成本=错误执行，适合外部高风险）/auto-approve（成本=延迟≥错误执行，适合内部可逆低影响）/escalate secondary reviewer（关键动作双不能接受时）；异步升级后拒绝的恢复路径必须显式设计（agent 已做假定审批的后续动作时被拒=啥恢复）。判据：**每个审批点预设超时策略+拒绝恢复路径，不能临时补**。提升层：工作流。
7. **agent↔agent 升级与 agent↔人类升级分开**（来源：AWS AGENTOPS01-BP02）——agent-to-agent=能力不足=路由决策；agent-to-human=置信度低/高赌注/重试预算耗尽=判断决策；混在一起→人类疲劳或高风险自动过。判据：**两类升级走不同队列，不混流**。提升层：工作流。
8. **授权梯度与自治级别选型**（来源：etisframework + franrodrigo + arxiv 2606.20630 + 2605.12105）——authority gradient assist→coordinate→execute→operate 每级递增负担；五级自治（类比驾驶 0-5）按任务关键性/可预见性/成熟度/恢复成本/法规选；negotiate shared control=混合主动，人机协商任务所有权（Horvitz mixed-initiative）。判据：**自治级别是设计期选型，随成熟度渐进降低监督**。提升层：工作流。
9. **审批疲劳与橡皮图章防御**（来源：pickaxe + waxell + agentpatternscatalog）——升级量过高→人类变橡皮图章；风险逐动作小到自动护栏就够→不该升级；action map 先把每个动作映射风险评级，只有不可逆/敏感/昂贵才暂停；低风险层用抽样审查（如 5% 审计）。判据：**升级频率与风险匹配，防橡皮图章=不是靠人更认真而是减少低价值升级**。提升层：工作流。
10. **风险分级矩阵与金额阈值**（来源：lawr.io + COMPEL + AWS tiered + CSA + ai-crescent + rtslabs）——四档：低（≤$1k，抽样 5% 审计）/中（$1k-25k，例外审批+每日批量）/高（$25k-250k，每动作审批）/极高（>250k 或不可逆，双人授权+高管签字）；COMPEL=impact×autonomy 矩阵定风险级；AWS 三档 autonomous/notify/approve 编码为 Cedar 策略在网关边界强制（分类执行在网关而非文档）；Green/Yellow/Red 框架（红=预执行审批+双人）。判据：**分级用明文金额阈值+影响×自主矩阵，策略编码到网关而非文档**。提升层：工具。
