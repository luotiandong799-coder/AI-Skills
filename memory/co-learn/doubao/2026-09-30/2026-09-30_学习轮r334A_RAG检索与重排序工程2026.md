## 独点（10）

1. **候选池数量决定重排上限**（来源：arxiv 2604.01733）——Recall@5 从 20 候选 0.458 → 50 候选 0.826 → 100 候选 0.888；重排只在候选池含相关文档时有效——候选不足先扩池再谈重排；10→20 结果边际收益小。判据：**重排前先验证候选池深度，池浅时重排无效**。提升层：工作流。
2. **混合检索 dense+sparse 双路 + RRF 融合**（来源：SemEval 2026 Task 8 多队 + arxiv 2602.22216）——混合检索平均最佳（answer relevance 0.69/context recall 0.56 vs naive 0.61/0.51）；RRF 无参融合 dense/sparse 分数；learned sparse（LSR）+listwise 重排再升（nDCG@5 0.5396 vs 基线 0.4795）。判据：**双路召回取并集再融合，单路召回有盲区**。提升层：工具。
3. **RAG 评估六指标套件 + 目标值**（来源：lobehub rag-architect + dev.to）——Faithfulness≥0.90/Context Relevance≥0.80/Answer Relevance≥0.85/Precision@K≥0.70/Recall@K≥0.80/MRR≥0.75；Context Recall 82%=18% 相关信息不可见（向量/搜索策略漏）；Faithfulness 抓幻觉（声称无出处）；领域专家标注 200+ 查询-分块对（合成标签不可信）。判据：**RAG 评测=检索质量+生成忠实度双面，缺一不可**。提升层：工具。
4. **分块五内在指标文档级评估**（来源：LREC 2026）——References Completeness/Intrachunk Cohesion/Document Contextual Coherence/Block Integrity/Size Compliance——文档级分块质量评估与 chunker 选择；LLM-guided regex + split-then-merge 递归切分器。判据：**选 chunker 先过五内在指标，不只看下游检索**。提升层：工具。
5. **多轮查询重写：欠指定是检索头号杀手**（来源：SemEval Task 8 多队）——最后轮查询常含未解析指代/省略/隐式依赖→直接用不可靠；用完整对话历史重写为自包含查询（温度 0.3 控制）；轻量模型（Qwen-0.6B）可完成指代解析+隐式实体恢复+领域术语强调。判据：**多轮 RAG 先重写查询再检索，重写模型宜轻不宜重**。提升层：工作流。
6. **embedding 选型三属性优先于榜单**（来源：levelop + sfailabs + databricks）——维度驱动存储/查询成本；Matryoshka 截断=少量召回换大量成本；通用 text-embedding-3-large（3072 维）"输最少"非最优；领域专用（金融/法律/代码）5-10% 提升；诊断 embedding 问题先 A/B 比两模型。判据：**embedding 按维度成本+领域匹配选，不按 MTEB 榜选**。提升层：工具。
7. **Late chunking：先整文档嵌入再切**（来源：Jina AI + pkhamdee + aiworkflowlab）——整文档过长期上下文嵌入模型→token 嵌入均值池化为 chunk 向量——每个 chunk 继承跨文档上下文；非 ColBERT late interaction；每 chunk 一向量存储量与普通切分相同。判据：**要跨 chunk 上下文先用 late chunking，存储成本不变**。提升层：工具。
8. **分块策略阶梯：从 512-token 递归起步**（来源：sukruyusufkaya + aiworkflowlab）——recursive ~512-token（token 精确计数）起步、匹配查询类型；检索指标证明才升级 semantic/hierarchical/late/contextual；semantic splitting 用嵌入相似度下降找断点，散文胜固定尺寸但代码/Markdown 输给文档感知切分器；最优 chunk 尺寸任务特定。判据：**分块从简单可维护起步，升级由指标驱动**。提升层：工作流。
9. **Agentic RAG：模型控制检索循环**（来源：professionaldeveloper + eduresearchjournal）——LLM 从被动消费 chunks 变为控制检索：规划/拆子查询/检索/评估够不够/重写再检索/自检后回答；Self-RAG 反射 token 决定何时检索+批判相关支持；IRCoT 检索与推理交错每步发更聚焦查询；多跳/复杂/准确率不可妥协（法律医疗金融）才值得额外成本。判据：**简单查询被动 RAG 够用，多跳复杂查询才上 agentic 循环**。提升层：工作流。
10. **检索后上下文压缩 + 结构化证据提取**（来源：A2C-RAG + HLLC + ACM multi-hop）——相关性感知上下文选择器（A2C-RAG）压缩送入 LLM 的上下文；HLLC 索引期压缩（语言特征+词汇显著性+嵌入语义贡献，检索前压缩、索引跨查询复用、不重训检索器）；多跳检索后结构化证据提取过滤噪声。判据：**检索结果先压缩过滤再入上下文，噪声会拉低推理**。提升层：工具。
