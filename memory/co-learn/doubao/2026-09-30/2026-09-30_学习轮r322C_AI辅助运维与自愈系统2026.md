## 独点（10）

1. **自主运维成熟度与自治线**（来源：anhtu.dev AI SRE 2026-03 + arvokas 2026-08 + devops.com three tiers 2026-09）——**进化=2024-25 copilot（summarize/suggest/draft postmortem，人驾驶）→2026 Agentic SRE（agents 在 policy guardrails 内跑 investigate-act loop，MTTR 降 40-70%，多数团队 L2-L3 部分安全动作 L4）**；**2026 自治线四家厂商同界=agents 可自主调查，但任何 mutate production 的动作需人批（NeuBird "earned autonomy"=ladder of trust）；三级自治=Tier1 proven+reversible 自动/Tier2 人批/Tier3 人指挥——tier 基于 familiarity/blast radius/reversibility/evidence strength；最终自治决策放 LLM 外（deterministic policy controls 执行权限+升级规则）**。判据：**自治等级按可逆性+爆炸半径+证据强度分档；最终授权决策不由 LLM 自己下**。提升层：工作流。
2. **修复签名门：诊断-执行分离防幻觉修复**（来源：devpost Self-Healing SRE Agent 2026-09）——**诊断层生成推理的加密 "Thought Signature"，执行层只运行被诊断层签名的命令——防止 hallucinated fixes**；**pinpoints=自主 git bisect 定位引入 bug 的 commit；heals=决定 Revert 或 Hotfix 并经 Kubernetes 执行**。判据：**诊断与执行分层，执行命令必须带诊断签名**（与执行隔离互补：隔离管计算边界，签名门管命令合法性）。提升层：工具。
3. **补救四阶段闭环：验证步不可省，回滚是生存属性**（来源：CASP semanticscholar + novaaiops 2026-05）——**自主闭环=detection/diagnosis/remediation/verification 四阶段**；**naive automation 跳过 verification→"auto-fix" 无限循环或对仍坏的服务宣布胜利**；**verification 失败→动作自动反转+带完整上下文升级到人；"Rollback is the property that makes autonomous execution survivable. An action you cannot cleanly undo should never be autonomous."**（CASP 还支持 air-gapped 部署——数据驻留环境）。判据：**任何自主修复必须带验证步；不可干净撤销的动作不做自治**。提升层：工作流。
4. **回滚阈值有意低于最高严重级**（来源：IETF draft smith-opsawg 2026-04）——**自动回滚 SHALL 在 post-action verification 检测到 warning 级及以上回归时触发——阈值有意设在 critical 之下留安全边际：等 critical 才回滚会让可预防损害累积，warning 级回滚抓住萌芽问题**。判据：**回滚阈值=warning 不=critical；越早越安全**。提升层：工作流。
5. **爆炸半径感知沙箱验证（GuardedAct）**（来源：arxiv 2609.11264）——**sandbox-first remediation：blast-radius-aware verification layer 插在 LLM action generator 与生产环境之间；四阶段=①ingest 诊断报告+live topology+recent telemetry ②LLM 产 ranked 候选 remediation actions ③每动作在 lightweight digital-twin sandbox 模拟→估 blast radius+风险标签 ④（执行门）**。判据：**生产动作先过 digital-twin 沙箱估爆炸半径再放行**。提升层：工具。
6. **告警漏斗八阶段与信号-事件比**（来源：struct 2026-03 + clankercloud 2026-09 + devops.com 2026-05）——**有效告警削减八阶段漏斗=ingest/deduplicate/correlate/prioritize/enrich/route/auto-remediate/learn——跳任一阶段失败往下游推**；**fatigue 来自 poor signal-to-incident ratio 非 raw volume——测 pages per incident+false positive rate**；**correlation=33 条 DB 故障告警→1 个 incident（根信号+下游症状），调优后噪声降 60-85%；实测 5000+ 告警/天→~100 可行动项（95% 降幅），MTTR 降 40-58%**；**anomaly detection 用动态基线（夜间备份窗口 CPU spike 正常）非静态阈值**。判据：**告警治理按八阶段漏斗走；指标=每次 incident 的 pages 数与误报率**。提升层：工作流。
7. **历史 incident 记忆检索而非幻觉修复**（来源：dev.to 2026-09×2 + brainupgrade 2026-04 + xbstack 2026-05 + debugg.ai 2026-06）——**把 runbooks+近 2 年 PIRs+服务依赖图+历史 PagerDuty 的 alert→root cause→fix tuples 进向量库；alert 触发时 agent 不请 LLM 幻觉 fix——它检索历史模式**（devopsboys=RAG for Runbooks：Alert→Extract→向量搜 runbook 段落→LLM 用检索上下文生成步骤→Slack 呈现）；**xbstack 二分判据=Match found 提取规定动作序列（SOP-DB-CON-01：查死锁→扩容连接池→无效则回滚最近部署）/No match 只输出故障分析报告不编造修复**；**RAG 反模式清单=一个索引装一切（伤 recall+governance，用 domain-specific indexes）/过度依赖 dense search（logs+code 需精确匹配，never skip BM25）/stale indices（索引滞后几分钟 assistant 就像玩具）/unchecked context（敏感片段漏进 context）**；log 所有 queries+responses 供 postmortem+增长 ground-truth。判据：**运维修复=检索历史模式+规定动作序列，无匹配时只报不编**。提升层：可复用 Skill。
8. **AI 编码代理治理控制框架**（来源：digitalthought 2026-08 + aws blog control framework 2026-07 + nvidia nemo 2026-07 + thecodew 2026-09 + particle41 2026-05）——**coding agent 进 CI/CD=untrusted change producer 非 privileged developer account——ephemeral sandbox/read-only repo access/writable workspace/controlled egress/no deployment credentials/no direct path to protected branch；agent 产 patch+evidence bundle，separate clean runner 应用+确定性 test/security gates+人审**；**NeMo Guardrails=human-only paths（authentication/payments/cryptography）在模型调用前拒绝；CI verification gate 标签 ai-assisted=unit tests/SAST/secret scanning/hallucinated-dependency detection/license checks 在人类 reviewer 前；commit trailers 捕获 assistant name+scope→测 defect escape rate/rollback frequency/review latency**；**最小必要权限=只需重启的 agent 不给停止权限；短时凭证替代永久 token；dev/staging/prod 权限分离；destructive/high-impact 审批门；失败部署自动回滚路径；访问 secrets/db/prod 前 policy 检查**；**部署门定义=哪些环境可自动部署（dev/staging 可 prod 不可）/什么条件必须满足/什么触发自动回滚（error rate spike/health check fail）/什么要人批（prod 部署/安全相关/schema migrations）；review depth scale to risk（低风险 agent-assisted/auto，高风险人工）**。判据：**AI 代码=untrusted 变更生产者；部署门显式写清；评审深度随风险缩放**。提升层：工作流。
9. **部署可观测性与候选标识**（来源：tabnews release agent 2026-09 + viblo 2026-05）——**候选按 SHA+digest 标识（不只 branch 名）；diff+changelog 分类 impact/uncertainty/contract changes；每个强制 check 含 URL/ID+SHA+时间+可验证结论；agent 默认只读+无生产凭证；migrations 有兼容性+staging evidence**；**部署后可观测=Sentry release 打标/Slack #deploys/部署日志/5 分钟内 prod smoke tests（一个 GitHub Action 设置一次）**。判据：**部署候选=可验证标识+可验证 check；部署后 5 分钟内有 smoke 证据**。提升层：工作流。
10. **渐进自治五维信任分与 stage gates**（来源：aws graduated autonomy 2026-08 + augmentcode scaling 2026-07 + arxiv 2604.12986 Parallax）——**五维权重=Accuracy 25%/Safety 20%（边界尊重+对抗内容检测+允许工具遵守）/Consistency 20%（行为可预测=工具使用模式漂移的反面）/Compliance 20%（行动前推理质量+guardrail 遵守）/Efficiency 15%（无不必要 retry/资源浪费）——composite 驱动 dashboards 与自治等级晋升**；**evidence-based stage gates=shadow mode→supervised operation→canary rollout→fleet operations——pilot controls collapse when agent output 增长快过 reviewer 吞吐（reviewer throughput 是第一约束）**；**Parallax Principle 4 Reversible Execution=任何 destructive/irreversible 动作前捕获足够回滚状态——"No action within the system's domain of control is truly irreversible"（前三条是执行前防御，第四条处理全部前防御被绕过的残余风险）**。判据：**自治等级晋升按五维信任分+阶段门；不可逆动作前必须捕获回滚状态**。提升层：工作流。
