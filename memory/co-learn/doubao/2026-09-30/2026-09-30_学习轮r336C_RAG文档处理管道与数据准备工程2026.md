## 独点（10）

1. **解析先恢复结构：结构化元素流而非平坦文本**（来源：unstructured + Docling）——parse 转 titles/paragraphs/tables/images 元素流，恢复文档形状（阅读顺序/层级/多栏）——只有字符的 parser 丢掉检索系统依赖的结构；每元素带元数据（页码/坐标）保留来源，使能引用与 scoped retrieval。判据：**解析输出结构化元素流+每元素页码坐标，别只出字符流**。提升层：工具。
2. **布局感知提取+OCR 扫描页：避免 pdf2text 直 dump**（来源：beefed + lemon）——layout-aware extraction 保阅读顺序；扫描页 OCR 先行；PDF→GROBID→修连字符/换行→组 section→token-aware chunker；页号+图表锚点进元数据。判据：**PDF 走布局感知管道，扫描页先 OCR，直 dump 文本丢结构**。提升层：工具。
3. **D-RAC 归一化：任意格式先转 PDF 再统一处理**（来源：arxiv 2609.24220）——DOCX/PPTX/XLSX/扫描图/原生 PDF 统一归一化为 PDF——几乎每格式都有忠实确定性 PDF 渲染；然后单多模态 LLM 转换+分块。判据：**多格式语料统一先转 PDF 中间态，别每格式写一套解析**。提升层：工作流。
4. **chunking 两失败模式：太小丢上下文、太大嵌不动**（来源：ailearningguides + microsoft）——相关事实跨两 chunk 被拆散=明显答案丢失；chunk 太长=嵌入不连贯检索错 chunk；先 PDF→干净 Markdown 再分块（纯文本摊平表格/标题/段落边界结构线索）；拆分超大表格保留表头。判据：**分块先转结构化 Markdown，别在纯文本上盲切**。提升层：工作流。
5. **策略按数据选型：四类数据四种分块**（来源：mixpeek + stochasticsandbox）——结构文本=递归/层级分块尊重标题；非结构长文=语义分块（embedding 相似度；chunk 大小不一致+摄入慢+提升边际小——长非结构文档才值得）；PDF 扫描件=layout-aware；多模态=modality-specific（场景检测/对象裁剪/说话人分离）；Parent-Child=小 chunk 检索+父 chunk 生成上下文。判据：**分块策略按文档类型路由，无全局最优**。提升层：工作流。
6. **表格分块纪律：行级 chunk+每行带表头**（来源：arxiv 2506.16035）——表格跨 chunk 延续保持同列结构/宽度/格式；每行一个 chunk、每个行 chunk 必含表头（前 chunk 或图片中的）+单行数据；隔离表格/图表/图为独立对象，LLM 生成密集文本摘要向量化+指针回原始表格。判据：**表格按行分块且行块带表头，图表隔离+摘要化+指针回原**。提升层：工具。
7. **多模态三选一：OCR 文本化/多模态 embedding/hybrid**（来源：theneuralbase）——(1) OCR+text-only 图经视觉转文本；(2) 多模态 embedding 图按图嵌；(3) hybrid chunking 表格结构化+图片留元数据——选择取决于文档复杂度/embedding 模型能力/生成时 LLM 能否处理图。判据：**含图 PDF 先定三策略再建管道，按能力选不默认**。提升层：工作流。
8. **规范化跨格式标准化：下游无需 per-format 逻辑**（来源：unstructured + databricks）——提取后规范化统一字段（一致 JSON shape）——下游组件不需要每格式分支；清洗剥离页眉页脚页码 boilerplate（膨胀 token 降检索精度）+修编码/空白/日期格式+折叠 OCR 近重复伪影+PII 检测。判据：**多格式语料统一 JSON shape 输出，清洗页眉页脚**。提升层：工具。
9. **事件驱动摄取：Claim Check 模式+staged topics**（来源：confluent）——每文档上传触发流式工作流（非 batch ETL 或同步 API 链）保持 RAG/agent 新鲜；二进制存对象存储、Kafka 只放 URI/元数据/处理状态；流经 raw→refined→curated_ai 阶段 topic。判据：**文档摄取走事件驱动+Claim Check，别同步 API 链**。提升层：工作流。
10. **增量重处理：段落哈希对比只重处理变更**（来源：airbyte）——增量更新保持提取内容新鲜不每次全量重处理；静态内容提取一次、频繁更新内容 SHA-256 哈希对比——incoming 段落哈希 vs 已存哈希只重处理变更。判据：**文档更新用哈希增量检测，只重处理变更段落**。提升层：工具。
