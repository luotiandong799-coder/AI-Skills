## 独点（12）

1. **Skills 生态市场：SKILL.md 是 agent 的 package.json，市场是新软件供应链**（来源：mr.technology 2026-07 + rywalker 2026-06 + ailinklab 2026-05 + agentify 2026-04 + socialscript 2026-04 + agentskills.leo 2026-07 + zylos 2026-05 + everydev 2026-05 + toolworthy 2026-08）——**skills.sh（Vercel，MIT CLI+web directory）=npm for agent skills：任何 GitHub repo 可发布，20+ agent 平台（Claude Code/Cursor/Cline/GitHub Copilot）一条命令 `npx skills add owner/repo` 安装；91k+ skills indexed/410k+ installs（find-skills 1.5M/frontend-design 420K 前三）；usage analytics=all-time+24h trending+weekly installs by agent platform；免费浏览**；**agentskill.sh=CLI 商店（search/info/install/一次装整套）**；**四大 marketplace=skills.sh/Claude Skills Registry/Hugging Face Skills Hub/Microsoft Copilot Studio；平台分化=skills.sh（package manager）/AgentExchange（cross-platform compatibility ratings）/Agentspace（enterprise SOC2 governance）/ClawHub（OpenClaw 最大社区+最大攻击面）/Agensi（curated 8-point security checklist）/HiMarket 阿里（Nacos-integrated governance）**；**AgentSkillOS（arxiv）=capability tree 组织 skills 供高效发现+Solve Tasks 用 DAG-based pipelines 检索编排执行多技能**。判据：**技能安装=一条命令，安全=装前按攻击面审**。提升层：工具。
2. **技能编写工程：四坑+Gotchas 节+先无技能试跑+配置优于代码**（来源：agentic-ai readthedocs 2026-09 + claude blog 2026-06 + firecrawl 2026-05 + skillgen 2026-07 + arxiv 2603.02176）——**四坑=Idempotency（技能可能同状态被调多次——指令写成重跑同结果，写前查已有输出）/Argument handling（自由参数歧义——显式文档格式+$args 缺失给默认）/Scope creep（one skill one purpose，复杂拆可组合子技能）/Stale instructions（版本与 codebase 同步，PR 里同 structural changes 一起审 skill 文件）**；**Gotchas 节=技能最高信号内容——从 agent 用技能时常见失败点构建并随时间更新捕获**；**先无技能试跑：写 YAML 前先无 skill 跑任务——已处理得好就不需要；成功但绕路或特定失败=skill 该填的 gap，nothing more**；**配置优于代码：技能用 YAML/JSON 配置非硬编码值（target list 从 config 取，非技术用户可改）；明确错误处理=#1 生产技能失败原因（API down→retry backoff/data malformed→skip continue/auth fail→alert admin channel）**；Claude 心智模型=**mcp=神经系统/skills=手册/projects=记忆/subagents=工作**。判据：**写技能前先证明存在 gap，写完把失败点固化成 Gotchas**。提升层：可复用 Skill。
3. **Skills 三级渐进披露与装载预算**（来源：claude blog 2026-03 + docs.langchain 2026-09 + cognizant 2026-07 + langchain deep agents 2026-01 + deepwiki）——**Level1 metadata（name+description frontmatter 仅 ~100 tokens，agent startup 每配置技能都载）→Level2 full SKILL.md body（激活时 <5k tokens）→Level3 resources（scripts/references/assets 懒加载只在指令引用时）——50 技能库 Level1 总开销可控**；**Cognizant Neuro San=startup 扫所有 skill source 只载 metadata→on demand 调 tool 拉 full content→selective 拉引用文件**；**Deep Agents 模式=❌ upfront 给几十工具（email_agent 挂 send_email/web_search/database_query/file_upload 不聚焦）——skills 提供 progressive disclosure 替代**；**Pattern1=Subagent Uses Skill（custom subagent 带 skills 字段列所需技能，内容注入 subagent context）；Pattern2=Skill Runs in Subagent（YAML frontmatter 设 context: fork）**。判据：**技能元数据只进系统 prompt，正文按需载**。提升层：工具。
4. **Context 工程：write/select/compress/isolate 词汇与三层架构**（来源：zylos 2026-06 + zylos 2026-07 + logic 2026-04 + professionaldeveloper 2026-07 + stanford + danilchenko 2026-07 + trantorinc 2026-04）——**context engineering=信息供给的架构（broader than query phrasing）——full stack=system prompts/conversation history/tool definitions/parameters，app-layer levers=memory/RAG/uploads/tools；更多 context 不是免费的**；**shared vocabulary=write（外存 NOTES/memory stores）/select（适时拉对 context：retrieval/memory selection/which files matter）/compress（只留 step 需要的 token：summarisation/compaction/返回 references 非 blobs）/isolate（隔无关 context：sub-agents 自己窗/per-task stores/filesystem 作外存）**；**三层架构=L1/L2 处理大多数 context 压力无需 LLM 调用（结构/规则/裁剪）→L3 LLM Summarization threshold-triggered 单 LLM call 压几百条为结构化摘要，保留最近 10% turns 原文做 active working memory——贵（一次额外推理）但千 token 压到百**；**四大 moves=compaction/structured note-taking（agent 写外部 NOTES read back when needed）/sub-agents（干净窗）/just-in-time retrieval（context 只留 pointer 按需载全文）**；scratchpad=中间结果/关键决策/重要观察持久化窗外。判据：**先 L1/L2 结构层省，L3 是 backstop**。提升层：工作流。
5. **Offloading 与 harness 上下文预算**（来源：anhtu 2026-08 + marktechpost 2026-09 + zylos 2026-06）——**Offloading=tool response 进 context 前先总结+全量存外部（file/object store）留轻引用——实测可 cut 99% tokens 在进窗之前**；**harness 不是 model 才是 fix 所在（shallow agents 死于 context overflow+goal loss）**；**预算先行：Deep Agents offload >20k tokens tool results+85% window 时 evict old edits**；**Compaction 必须命名保留什么：Deep Agents 加 session intent+next steps fields，Claude Code re-read 5 recent files**。判据：**工具输出先 offload 再进窗，压缩时显式声明保留项**。提升层：工作流。
6. **Prompt 版本化与 CI/CD：prompt 与模型不可分离**（来源：chiraghasija 2026-07 + aws wellarchitected 2026-09 + futureagi×2 2026-05/07 + dev nainikmehta 2026-09 + alivedise 2026-06 + promptlayer + newdata 2026-06 + aws docs + sukruyusufkaya 2026-09）——**prompt 版本=prompt-plus-model 版本：prompt 与 tuned 的模型不可分离（claude-sonnet-5-20260115 上好的 prompt 在后 snapshot 漂移）；生产禁 floating alias（alias 只实验不发布）；版本号与评估结果 intrinsically linked**；**四阶段生命周期=Draft→Review→Active→Archived，gate 用 approval workflows 非 convention；每 entry 必需 metadata=purpose/target agent/expected behavior/evaluation criteria/owner；parameterization 减重复**；**双层防线=eval-on-PR（prompts/ 下任何 PR 触发 regression suite 防坏候选进生产）+canary（防 CI-passing 候选打破 golden set 没预见的生产分布）**；**registry 字段=prompt_id+immutable version（content hash 或 semantic）+author+changelog+golden-dataset pointer+model hint+parameters——immutable content 与 mutable pointer table 分离**；**candidate 进生产前 MUST 跑自动评估（Promptfoo 标准开源：candidate vs baseline current production）**；LLM-as-judge 自身会 bias 必须校准+与人类评估 cross-check。判据：**prompt 变更走 commit→test→promote，标签只在 green 结果后打 Production**。提升层：可复用 Skill。
7. **Agent 评估方法论：full-turn 三维与 TSR 分层阈值**（来源：langchain blog 2026-03 + mastra 2026-06 + mlflow 2026-05 + langfuse 2026-09 + dataaihub 2026-08 + exploreagentic 2026-06 + heym 2026-05 + hku 2026-05 + qiyanjun + 腾讯云 2026-08）——**full-turn evals 三维=Final response（输出正确有用）/Trajectory（合理路径不必精确）/State changes（files written/db updated/meeting scheduled——state change 常被忽略但对做事的 agent 关键）**；**MLflow 分层=TSR（Task Success Rate）主信号：capability suite <80%=fundamental gaps，regression suite <95%=backsliding（阈值刻意不同）；Tier2 trajectory metrics**；**工具调用逐层评估=Tool selection（right capability）→Arguments（types/required/IDs bound from context）→Execution（timeouts/errors/idempotency——executor 不是 model）→Result interpretation（下一 step 用 payload 非 prior guesses）→Recovery（structured retries vs blind loops——合法瞬态失败+正确重试=recovery quality 非自动 fail）→Permission/safety**；**离线 vs 在线双轨都需：离线=固定 dataset 部署前（regression+mock 工具=CI gate）；在线=真实流量（drift/edge cases/real load）；Replay=重跑记录生产 traces（cached tool responses）对新 build**；评分=Exact Match（labels/IDs）/Contains（substring）/LLM-as-Judge（open-ended 0-100+explanation，judge 指独立模型减 bias）。判据：**先 outcome 再 trajectory 再 state change，离线在线都跑**。提升层：工作流。
8. **Agent prompt 结构：loop 化+模板化+五部分契约**（来源：promptrefinery×2 2026-06/08 + crewsmith 2026-05 + ceotudent 2026-05 + a practical guide to building agents + dev vijay 2026-09 + techdailyshot 2026-05 + cloudflare 2026-09）——**Agent loop 结构=task→action→verification→approval→next step——one-shot prompts 逼 AI 猜 scope 一次给完整答案常坏；loop 镜像人类专业工作方式契合 reasoning models**；**模板策略=单个 flexible base prompt 接收 policy variables（{{user_first_name}}），新 use case 只更新变量不改写整个 workflow——简化维护+评估，管理复杂度不必切多 agent 框架**；**Agent prompt 五部分=Role（agent 拥有什么）/Input contract（开始前期待什么信息）/Process（怎么思考）/Output contract（返回格式）/Escalation rule（何时停下要更多 context）——缺任一 agent 仍会响应但不可靠；chatbot prompting ≠ agent prompting**；**PRS 生产就绪分数=full-effort run（high reasoning_effort）sample dataset→collect hidden CoT logs for audit→iterate until PRS≥0.90→commit prompt files/tag version/deploy via CI**；metadata tagging=system+user metadata 附 prompts 引导行为+审计合规。判据：**五部分缺一即不可靠，loop 优于 one-shot**。提升层：可复用 Skill。
9. **RAG 2026：chunking>embedding，分层 reranker 与 agentic retrieval**（来源：scale RAG lessons 2026-09 + arxiv 2607.27523 + microsoft learn 2026-08 + arxiv 2605.05538 + google codelabs 2026-07 + arxiv 2606.28352v1 + cnblogs 2026-04）——**chunking 策略比 embedding 模型选择更重要：固定大小+overlap 对表格/代码块/嵌套列表破坏严重；semantic chunking（自然节边界切+表格保持整块）比换 embedding 模型提升检索精度更大**；**两级分层 reranker=小快模型粗词法剪枝全候选池+大准模型深语义裁决小幸存集——breadth/depth 解耦，贵计算集中到最高边际价值处，避免 monolithic reranker**；**agentic retrieval=LLM 拆复杂 query 成聚焦 subqueries+并行执行+结构化响应（grounding data）+context-aware query planning（对话历史）**；**switcher 路由=复杂多意图 query→agentic harness 深析，简单 query→传统 RAG 快答（UX/cost/模型可用性权衡）**；**混合检索=dense+sparse 双检索+controlled query rewriting+cross-encoder reranking（SemEval-2026 Task 8：0.5453 nDCG@5 第 3/38）**；Advanced=reranking 解 lost-in-the-middle+HyDE+Step-back Prompting+post-retrieval filter/compress 只留 salient。判据：**先修 chunking 再调 embedding，reranker 分层不 monolithic**。提升层：工作流。

12. **生产 Agent 接入现有系统：桥接层模式与确定性/不确定性分离**（来源：toutiao 钛媒体 2026-09 + logic 2026-07 + anhtu 2026-05 + agentic-ai readthedocs）——**满帮桥接层模式=两套生产系统协同：传统系统负责确定性流程稳定（货源发布/撮合下单），Agent 系统负责目标理解+持续执行，桥接层=tool 适配+鉴权+安全控制+数据交互——企业现有系统有不可取代价值，Agent 接入这些能力避免把自身不确定性直接带进**；**意图识别教训：试图用意图分类增加确定性再主 Agent 分发——但真实对话一句话同时含问答+执行要求+议价条件，简单分类丢失关系限制理解——Agent 必须记住已确认条件理解后续要求与其关系继续行动（stateful 对话非一次性分类）**；**harness 工程=组织模型周围上下文与工具+管理任务状态+约束执行+处理失败恢复——工具用途描述清楚/参数校验/失败可执行反馈/交易动作检查授权与业务条件，模型给出判断后企业需机制放进可靠执行过程**；**技能错误处理（agentic-ai）：同状态被调多次=幂等；指令写给旧结构=stale 静默失败**。判据：**确定性归传统系统，不确定性归 Agent，桥接层管适配与鉴权**。提升层：工作流。
