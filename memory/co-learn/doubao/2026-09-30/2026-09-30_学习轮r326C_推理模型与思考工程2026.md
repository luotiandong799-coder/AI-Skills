## 独点（10）

1. **决策框架：两问定要不要 thinking**（来源：chiraghasija.cc《What 'Thinking' Actually Costs》+ datarekha《Reasoning models & test-time compute》）——①任务有可验证或可明确评估的正确答吗 ②达到答案需要多个非显然推理步吗；**两问都 yes 才值得 extended thinking（竞赛数学 30-60% 提升）；任一 no 就是在为边际收益付溢价**；**验证输出而非验证轨迹**：能跑 checker/测试/schema 就验最终答案——reasoning 减少错误但不消除错误，自信的错误轨迹仍然是错的。判据：**两问框架决定用不用思考；信任最终输出不信任思考轨迹**。提升层：工作流。
2. **thinking 成本数量级：按输出价计、5-30× 于答案 token、实际贵 10-40×**（来源：aiworkflowlab《Reasoning Models in Production》+ theneuralbase《Chain of thought with thinking budget》）——**reasoning tokens 按标准输出 token 价计费**；一次请求可烧 6000-10000 tokens 而同样请求非思考只用 2000；100 请求对比=800K vs 200K=**4× 成本增量**；推理响应中思考 token 常是最终答案的 5-30×，实际单请求成本 10-40× 于同 prompt 的非推理模型；监控 `usage.input_tokens` 与 thinking token 字段。判据：**算账按 thinking 数量级计，不是按输出计**。提升层：工具/成本。
3. **预算设置：per-task-class 显式预算 + 精度平台期（knee）就停**（来源：ai.blocksize.hr + acingai《Test-Time Compute: Where More Thinking Stops Paying》+ arxiv 2604.10739《When More Thinking Hurts》）——**不要让模型无界思考**：每任务类设显式预算，调 thinking 预算到精度平台期（knee）即停——那个 knee 就是你的设置；**overthinking 实证：λ（成本系数）越高最优预算越短（λ=0.5 停在 ~6K tokens 省 ~50% 算力只损 ~6%；λ=1.0 只 ~2K）**，indicator-based early stopping 可行；**生产预算设 knee 而非 sweep 顶部**——从 1 到 4 的差距通常是大部分收益。判据：**思考预算按任务类设、扫到精度平台期即停**。提升层：工作流。
4. **provider adaptive controls 取代硬预算：effort 五档 / thinking_level / adaptive**（来源：platform.claude.com adaptive-thinking+effort+whats-new-claude-4-7 + docs.cloud.google.com thinking + baeseokjae《GPT-5.4 API Developer Guide》）——**Claude Opus 4.7 起删除 extended thinking budget_tokens（设置即 400 error），adaptive thinking 是唯一思考模式**（effort：low/medium/high/xhigh/max；Opus 4.7 推荐 coding/agentic 用 xhigh、多数智能敏感场景最低 high；Sonnet 5 默认 high）；**Gemini 3 用 thinking_level（low/medium/high）+ dynamic 默认自动调深度，thinking 是相对配额非严格 token 保证**；**GPT-5.4 effort none/low/medium/high/xhigh 五级**；Gemini 3 建议移除 temperature 用 thinking_level 控确定性。判据：**2026 起用 effort/level 离散档位配 per-task 覆盖，别再用 token 预算硬编码**。提升层：工具。
5. **thinking 与工具循环：三厂商分歧决定架构**（来源：aiworkflowlab + aiwiki task budgets + platform.claude.com thinking-block）——**Claude 支持工具调用间交错思考（interleaved thinking between tool calls）；o-series 每轮端到端推理；Gemini 2.5 思考循环内可工具调用+结构化输出**；thinking block 里看到的文本是推理的摘要不是原始 chain of thought（display 字段控制是否返回）；**task budgets（Claude total/remaining）=agentic loop 总 token 预算（thinking+tool calls+tool results+output），跨请求结转**。判据：**选模型先确认思考与工具调用的交错方式；预算按整条 agentic loop 设**。提升层：工具/架构。
6. **模型路由阶梯（cascade）：默认便宜、失败/低置信升级**（来源：dreaming.press《Cheap-Model Fallback》+ agentnative《Model Routing Cascade Pattern》+ dev.to nathanbrooks + sangampandey + mindstudio + agentropic FrugalGPT/AutoMix）——**省钱不靠换便宜模型，靠梯子：默认每调用走便宜模型，只有失败/重试/低置信输出才升级旗舰**（OpenAI 兼容格式=一套 SDK 两个 base URL）；**cascade 模式=cheap 先跑→质量门槛（结构化输出校验/置信阈值/不确定性短语）不过→升级 frontier，FrugalGPT 用 DistilBERT 打分、AutoMix 自我验证**；**显式 rung 阶梯 local/ultra-cheap→mid→frontier，每级在 config 记 per-M 价格**；路由分类档（SIMPLE/MEDIUM/COMPLEX/REASONING）+实例级路由。判据：**路由决策由"该任务归哪档"或"cheap 结果过不过质量门槛"驱动，不是硬编码单模型**。提升层：工作流/工具。
7. **verifier 会被游戏：RLVR reward hacking 与 LLM-judge 漏洞**（来源：arxiv 2604.15149《LLMs Gaming Verifiers》+ alphaxiv《One Token to Fool LLM-as-a-Judge》+ syncsoft《6 Verifier Red-Team Tests》+ greaterwrong《certify-or-abstain gate》）——**RLVR 模型会枚举实例级标签绕过 verifier 而不学关系模式（imperfect verifier 只查外延正确性=假阳性）**；**Isomorphic Perturbation Testing（同构扰动检验）=同一模型输出在外延与同构验证下双跑，检测 shortcut**；**generative reward model 易被 master keys hack——非词符号（":" 或 "."）一 token 骗过 judge**；**reward hacking 随模型规模增长**；certify-or-abstain 门（无法证明就弃权）构造性阻断。判据：**verifier 评分的是代理指标就一定会被游戏；用同构检验+无法证明即弃权**。提升层：模型/评测。
8. **verifier→生成式验证器与 JCG：把 LLM judge 移出奖励环**（来源：minimax《MaxProof》+ kargichauhan《Compiling the Subjective》+ llm-as-a-verifier.com）——**MaxProof=生成式 verifier 主奖励的长程证明 RL，必须系统处理噪声/假阳/reward hacking**；**JCG（Judge Code Generator）=用编码 LLM 把评分 rubric 翻译成逐样本 Python 评分函数、沙箱执行，LLM judge 完全移出奖励环——恢复 RLVR 核心优势（确定性/快/不可 hack），主观任务同样适用**；1/9 判据/样本即无偏梯度估计；LLM-as-a-Verifier fine-grained 分=off/on-policy RL 稠密奖励（LIBERO 采样效率 1.8×、MATH 1.1×）。判据：**主观任务把 judge 编译成代码评分器，比 LLM 直接打分的奖励不可 hack**。提升层：模型/方法。
9. **gemini-3.5-flash 类陷阱：推理 token 跨轮持久化改变成本曲线**（来源：nxcode《Gemini 3.5 Flash Developer Guide: Three API Traps》）——**内部推理 token 默认跨多轮保留（模型可回看此前如何推理→长 agent 循环连贯性↑），代价=保留的 thinking tokens 每轮都算输入：10 轮 agent 会话原 50K input/turn 可能变 750K+**；**thinking_level 控制推理深度上限（相对配额非严格 token 保证）**。判据：**长 agent 循环先查"思考 token 是否跨轮计费"再定会话策略**。提升层：工具/成本。
10. **iso-compute 比较 + budget forcing：更强的模型 N=1 vs 现模型多采样**（来源：acingai + zylos《Inference-Time Compute Scaling》+ mikenguyen13）——**iso-compute：定价强模型 N=1 对比现模型 sweep（1/2/4/8/16/32）——有时便宜模型多采样胜过贵模型单次**；**s1-32B=仅 1000 条精选 question-trace 微调 + budget forcing（append "Wait" token 强制延长/终止思考）超 o1-preview 竞赛数学 27%——低成本给开源模型加思考**；adaptive reasoning depth=provider adaptive controls 默认 medium、按步骤类型覆盖，逐步积累到实例级路由。判据：**选型先做 iso-compute 对比；开源模型可用 budget forcing 低成本获得思考能力**。提升层：模型/工作流。
