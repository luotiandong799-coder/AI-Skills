## 独点（10）

1. **平台选型判据：80% AI 选 Dify，80% 管道选 n8n**（来源：theplanettools + n8n vs Dify + ayautomate）——**n8n=通用自动化平台（400+ 集成），LLM 是链条中一个节点**（处理完传下游）；**Dify=LLM-first 平台，模型居中、RAG/工具/记忆/输出格式化围绕模型**；判据=**工作负载 80% AI（聊天/知识库 agent）选 Dify，80% 是管道（Slack→CRM→email）选 n8n**；Dify 的 RAG=文档上传/分块/embedding/索引/混合检索+rerank 引导式一站式；n8n 的调度/触发/错误处理更成熟。判据：**用 80/20 负载分布选平台，不是看功能清单**。提升层：工具/选型。
2. **n8n 六类触发器对应六种 AI 员工行为**（来源：aisuperthinkers《n8n AI Agent Triggers》）——Webhook（响应外部系统，实时）/ Schedule（时间间隔，批处理）/ App Event（应用事件）/ Chat（对话式）/ Form / Manual；**触发器选错=建了永不执行的 agent**；webhook 配 Respond to Webhook 节点返回 AI 结果；每类对应不同 AI employee 行为模式。判据：**先定"AI 员工行为模式"再选触发器**。提升层：工具。
3. **子工作流 execute 触发器 + queue mode 生产化**（来源：n8n production best-practices + aiworkflowlab）——**Execute Workflow 触发子工作流=比 webhook 更安全（不暴露外部系统）**，可定义参数保证子工作流收到预期格式数据；MCP Trigger 节点秒建 MCP server 供 agent 调用；**单进程 n8n 够 <500 执行/天，之上必须 queue mode：主进程接触发写 Redis、worker 独立执行节点，graceful restart 不丢进行中工作流**。判据：**内部调用走子工作流触发器；>500 执行/天切 queue mode**。提升层：工具/工作流。
4. **三层错误处理：节点重试 / 错误工作流 / 保留失败执行**（来源：xbstack《Productionizing n8n AI Workflows》+ n8n tool-calling guide）——**节点级 Retry On Fail 只用于有界瞬时失败**；最终失败路由到 Error Workflow 记录+告警；**保留失败执行以便用当前或原始工作流重试**；任何副作用步骤（DB 写/发消息/建 ticket）仍需幂等键；LLM 步骤重试默认=**3 次尝试、初始 1s、乘数 2x、最大 8s、抖动 20%**；同步用户面路径 cap 重试 2 次并表面化。判据：**重试分层管：瞬时靠节点重试，终局靠错误工作流，副作用靠幂等键**。提升层：工具/工作流。
5. **账单爆炸真凶：失败步骤重跑**（来源：dev.to lars_winstand + zalt + xbstack）——**AI 账单爆炸通常不是 token 贵，是同一失败步骤重跑 3 次**（如 Code 节点超时→整链重试→LLM 步骤又烧钱）；修法=**超时类错误不进重试循环**（区分超时与逻辑错误）、按调用设重试预算、同步路径 cap 重试并表面化。判据：**先查"失败步骤重跑了几次"再谈 token 优化**。提升层：工具/成本。
6. **数据契约 + 死信队列（DLQ）**（来源：novapixel + williamspurlock）——**无论怎么 prompt，AI 终会生成非法数据**；编排层设严格数据契约（schema 校验）并把失败路由到 DLQ 自动化——**坏数据进死信队列而非丢弃/硬重试**；自愈分层=L1 步骤断言（schema/必需实体/结果范围/副作用回执/延迟预算，断言失败 fail closed）+ L2 运行级评测（面向客户/资金 agent 打分最终输出）。判据：**AI 输出设契约+DLQ，非法数据进死信队列不硬重试**。提升层：工作流/工具。
7. **AI 失败自动分诊：分类瞬时/逻辑决定重试或建单**（来源：n8n workflow 16744）——触发 n8n 执行错误→**LLM 分类失败是瞬时（transient）还是逻辑（logic）**→瞬时用指数退避重试（调 n8n API）、逻辑建 Jira issue→OpenTelemetry 遥测→**per-incident 重试计数器（上限 3）**决定是否够格自动重试。判据：**AI 分诊失败类型再决定重试 or 建单，带重试计数上限**。提升层：工具/工作流。
8. **指数退避+全抖动+Retry-After 解析**（来源：n8n tool-calling error handling + latenode）——生产标准=**指数退避配全抖动（防 thundering herd 惊群）**；**主动解析限流端点的 Retry-After 头覆盖默认间隔**以遵守第三方速率限制；**电路断路器防级联失败**（服务连续失败时熔断暂停请求）。判据：**重试=指数退避+全抖动；限流端点必须解析 Retry-After**。提升层：工具。
9. **自托管成本账：固定基建 vs 按执行计费**（来源：baeseokjae + layer3labs + pickaxe）——n8n Community Edition=开源自托管、**零平台费零用量上限（无任务上限/无活跃工作流上限）**、400+ 集成；云版按执行量扩展；**PII/财务/专有文档 agent 处理=自托管是正确的选择**（数据不出网络、控制 LLM 提供商可达性、控制并发）；Pipedream=每步可写 JS/Python/TS/Go/Bash 全语言、serverless 运行时托管、内建可观测性。判据：**敏感数据 agent 必须自托管；高执行量时自托管固定成本胜出**。提升层：工具/成本。
10. **AI agent vs 简单自动化：先问"需要自主决策吗"**（来源：dev.to sam《AI Agents vs Automations》+ aivanguard 四层架构 + langchain-runner + mindstudio hermes）——**能确定性完成的用 plain workflow（webhook→OpenAI 节点→响应），不需要 agent 循环**；四层架构=Trigger（Webhook=实时/Schedule=批处理）→处理→AI 动作→交付；langchain-runner=零配置把 LangChain agent 暴露成 webhook endpoints+cron schedules+HTTP triggers（后台执行不阻塞响应）；**cron 触发必带 timezone（不写=UTC，业务小时自动化几乎总错）**。判据：**确定性任务用 workflow 不用 agent；调度永远显式时区**。提升层：工作流。
