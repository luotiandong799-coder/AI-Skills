## 独点（10）

1. **本地 LLM 隐私审计：Ollama 零遥测，LM Studio 默认开遥测**（来源：local-llm.net privacy-audit + promptquorum installers + vucense）——**Ollama=MIT 开源、零遥测**（Wireshark 验证：模型下载后可完全断网运行；网络活动仅两个场景=模型拉取+版本检查；不存会话历史——它是 API server 不是 chat app；日志记录需自查配置）；**LM Studio 默认收集匿名使用分析，隐私敏感必须立刻关**（Settings→Privacy→Send anonymous usage data→off）；Jan/GPT4All 零遥测；**四工具同用 llama.cpp/GGUF，可切换不重下模型**。判据：**隐私敏感场景选零遥测工具并自查网络行为**。提升层：工具。
2. **本地推理的网络足迹：模型下载暴露 IP+模型名**（来源：insiderllm + local-llm.net）——运行本地解决最大问题但仍有缺口：**每次 ollama pull 都暴露你的 IP 和下载的模型名**（registry.ollama.ai/Hugging Face 可见）；**"数据不出机器"≠"元数据不出机器"**；对策=代理/镜像拉取、air-gapped 部署、防火墙阻断 ollama.com 域。判据：**本地≠零网络足迹，模型下载元数据要单独治理**。提升层：工具/安全。
3. **量化四档：Q4_K_M 甜点 + 显存公式**（来源：pinggy + promptquorum hardware + devtoolreviews + calmops）——**GGUF 量化 Q2_K~Q8_0**；显存=Q4_K_M ~5GB(7B)/9GB(13B)/20GB(34B)/42GB(70B)、Q8_0 ~8/14/34/70GB、FP16 翻倍；**Q4_K_M 是质量/速度甜点**；**7B 需 8GB、13B 需 12-16GB、70B 需 35-48GB VRAM**；Ollama 支持 K/V cache 量化（OLLAMA_KV_CACHE_TYPE 默认 f16）进一步省显存。判据：**先按 Q4_K_M 算显存再选模型档位**。提升层：工具。
4. **本地硬件选型三档**（来源：checkaimodels + tutorials.technology + awesomeagents + dev.to lingdas1）——**入门 8-16GB VRAM**（RTX 4060/4070，7B-14B INT4，DeepSeek-R1-Distill-Qwen-7B 是甜点）；**主力 24GB**（RTX 4090，32B INT4 或 14B FP16，真能干活）；**8GB VRAM 首选 Qwen3 8B（5.2GB Apache 2.0）**、4090 单卡 Qwen3 32B（20GB）或 30B-A3B（19GB 256K 上下文）；Mac 统一内存跑大模型（M4 Max 128GB 可跑 70B Q4）；**无 GPU=16GB RAM 笔记本跑 1-8B Q4_K_M 舒服**。判据：**按 VRAM 三档定硬件预算，8GB 起步、24GB 是实用线**。提升层：工具。
5. **本地 RAG 全本地组件：ChromaDB + nomic-embed-text**（来源：zero-to-ai + aimadetools + dev.to jovan + morphllm）——**本地 RAG 六步全在机器上**：Ingest（512 token 固定块切分）→Embed（nomic-embed-text 768 维本地嵌入）→Store（ChromaDB 进程内持久化）→Retrieve（question 嵌入→向量匹配→top-k）→Answer（LLM 只用检索上下文回答）；**ChromaDB 进程内零服务端**、Qdrant/pgvector 生产级；**中文文档用 BAAI/bge-small-zh-v1.5**（中文优化本地运行）；组件全本地=文档永不出机器。判据：**本地 RAG=Ollama（嵌入+LLM）+ChromaDB+本地嵌入模型**。提升层：工作流/工具。
6. **混合路由架构：85-95% 本地 + 5-15% 云**（来源：localaimaster + muthu notes + zylos）——**路由层把请求分类**：简单/分类/提取/格式化/简单推理（70-80% 的 agent 查询）→本地量化 7B-14B；复杂推理/长上下文/创意/多模态→云前沿模型；**结果=云质量输出 80-95% 低成本 + 本地 <100ms 首 token**；网关="聊天 UI 与模型之间的薄层"：看请求复杂度本地 or 升级云端。判据：**先按敏感度+复杂度路由，85% 走本地**。提升层：工作流/工具。
7. **本地 vs 云决策框架：四问**（来源：gridex + codesota + theaiselect + llmlounge）——①**敏感数据？**（专有代码/个人信息/内部文档→本地——"永不出机器"比 DPA/SOC2 更好推理）②**深度推理/超长上下文？**（架构决策/复杂调试/500 页文档→云前沿）③**延迟要求？**（<50-100ms、不容忍网络抖动→本地）④**成本形态？**（高量常态化、API 成本超 GPU 租金 $2K/月→自托管固定成本）；本地还适合 air-gapped、100% 可用性、专有数据微调。判据：**四问定路由：敏感/低延迟/高量→本地，深推理/长上下文→云**。提升层：工作流。
8. **本地模型能力边界：分类/提取/格式化/简单推理，不做深推理**（来源：zylos + entuit + muthu notes）——**70-80% 的 LLM 查询不需要前沿模型**（分类、提取、格式化、简单推理，量化 7B-14B 本地等价质量）；**"用 Claude Opus 重排 JSON=请高级架构师刷墙"**；正确分工=云前沿模型做"思考"（深度推理/多步规划/复杂判断）+本地模型做"执行"（跑通后固定任务）；**本地模型仍会幻觉——小模型验证事实后再行动**。判据：**执行类任务本地化，思考类任务留云端**。提升层：工作流。
9. **本地合规账：GDPR 架构隐私 + 哈希日志**（来源：quelllm + promptquorum qwen-gdpr + dev.to cursuri）——**本地模型把"处理"留在内部、完全掌控**：权重下载一次（Hugging Face/Ollama），推理 100% 本地、无跨境传输；**GDPR 工作流标准配置=Ollama+qwen3:14b（12GB VRAM）+阻断推理进程出站+全盘加密+记录 prompt/response 哈希（不记内容）用于 Article 30 处理记录**；欧洲采纳驱动力=消除"提供商拿我数据做什么"的合同谈判问题。判据：**本地合规=出站阻断+全盘加密+哈希日志替代内容日志**。提升层：工具/合规。
10. **OpenAI 兼容 API：改一个 URL 切换本地**（来源：aideck + findaiverse + calmops）——**Ollama 暴露 OpenAI 兼容 API，大多数 LLM 应用改 base URL 即切本地**；自动 GPU 检测（NVIDIA/AMD/Apple Silicon）回退 CPU；**零持续成本——下载后无 API 费/订阅/按 token 计费**；Ollama 自家云=零数据保留（US/EU 托管、不记 prompt、不训练你的数据）——纯云替代方案。判据：**本地接入=换 base URL；先本地后云是默认梯度**。提升层：工具。
