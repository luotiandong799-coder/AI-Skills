## 独点（10）

1. **分治分解两步行：decompose + subplan**（来源：arxiv 2510.09244 + OneDayAgent）——复杂任务→子任务集合（decompose），每个子任务单独制定计划（subplan）；超载长时程请求→有界可执行单元（有序子任务列表）；日常请求隐含要求+工件级约束混合。判据：**先拆成有界单元，再逐个制定子计划**。提升层：工作流。
2. **层次规划树：粗到细渐进细化防过度规划**（来源：AdaPlan-H + STEP Planner + ReAcTree）——先粗粒度宏观计划，按任务复杂度渐进细化；子目标树粗到细缩小逻辑与上下文 gap；ReAcTree 动态建 agent 树+控制流节点协调+双记忆（子目标级示例/经验）；过度规划（overplanning）是真实失败模式——细化到需要的粒度就停。判据：**计划先粗后细，细化粒度匹配任务复杂度**。提升层：工作流。
3. **计划与执行统一表示（ReCode）**（来源：arxiv 2510.23564）——计划和动作统一为 Python 函数调用表示，消除抽象规划与具体动作的刚性分离；决策粒度可灵活控制（粗=计划级、细=原语级）；计划=可执行代码，执行=调用计划。判据：**计划和动作同一表示层，粒度可升降**。提升层：工具。
4. **AND/OR 规划树交错执行**（来源：OpenReview hierarchical planning）——动态构建有序 AND/OR 规划树：AND 节点=必做子目标/OR 节点=备选子策略；规划与执行交错（不是先全规划再执行）；组合节点把复杂任务分解成子目标推理。判据：**必做与备选分节点建模，边规划边执行**。提升层：工作流。
5. **计划验证：无 LLM 校验层 + LLM-Modulo 外部验证器**（来源：docs.reactiveagents + aiwiki）——Plan（1 次 LLM 调用发整 DAG+#E1/#E2 证据引用，schema 强制让本地小模型也产出合法计划）→Verify（无 LLM：验证 DAG、修复可修 gap、不可用降级 ReAct）→Execute（无 LLM：按依赖序执行、独立步并行）；LLM-Modulo=每个候选计划路由外部验证器，反馈回模型（捕获缺失前置条件/违反约束/不可能动作序列）。判据：**计划生成后过无 LLM 校验层，验证器反馈回模型**。提升层：工具。
6. **反思式规划三决策：continue/modify/replan**（来源：microsoft learn + xbstack + Goal2Skill）——meta-agent 反思（原始查询+当前计划+已完成任务结果+剩余任务）产出三决策：continue（计划仍有效继续）/modify（调剩余任务保留已完成）/replan（丢弃剩余计划从当前状态新建）；多数执行 continue 不重规划，但具备能力处理边界。判据：**反思产出三态决策，modify 保留已完成工作、replan 才重建**。提升层：工作流。
7. **失败定位回溯：最低共同祖先=重规划起点**（来源：ATG arxiv 2607.01942 + PreFlect + ACM survey）——ATG 显式图暴露依赖+支持复用；失败先定位到失败原子节点（或小集合），沿图演化历史回溯找最低共同历史祖先=原始重规划起点；PreFlect=环境揭示意外障碍触发动态重规划，重规划后再前瞻评估新计划风险。判据：**失败先定位原子节点再回溯到最近公共祖先处重规划**。提升层：工具。
8. **重规划指标分层 + 步骤数双看**（来源：xbstack + UBC）——replan_success_rate（触发重规划后最终完成原始目标比例）按错误类型+模型/版本分层记录；steps_per_task 平均/分位用于发现异常长链路，但步骤少≠好——同时看成功率/工具调用/成本/结果质量；对照实验隔离变量（静态计划 vs 反馈条件重规划/固定工具 vs 证据限制发现/全局账本 vs 约束计划/单 agent vs 委派）。判据：**重规划质量按错误类型分层度量，步骤数不单独当好坏**。提升层：工作流。
9. **执行前预测失败（proactive replanning）**（来源：IFAAMAS + Goal2Skill + REMAC）——执行子任务前先查前置条件（视觉前置条件+参考图相似度阈值），低于阈值触发轻量诊断生成修正子计划；每执行步后验条件评估+记忆验证预期成果，不一致→反思诊断→调当前子任务（带更新约束重试）或修订剩余计划；pre/post-condition 双检查在环。判据：**执行前查前置条件、执行后验后置条件，双检查驱动修正**。提升层：工作流。
10. **脆性规划是主导失败模式：backtrack + 动态重规划内化**（来源：zylos + Reactive Agents + UBC）——部署 agent 主导失败=脆性规划（提交线性序列、现实偏离时不能修订）；稳健 agent 必须内化回溯/探索备选路径/动态重规划；ReAct 降级=计划层不可用时退回逐动作循环（Thought/Action/Observation）；证据引用（#E1/#E2）把计划绑定可验证事实。判据：**默认带重规划能力，计划不可用降级 ReAct 逐动作**。提升层：工作流。
