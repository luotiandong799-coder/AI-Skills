## 独点（10）

1. **路由收益基准：RouteLLM 矩阵分解 85% 成本降/95% 质量**（来源：LMSYS RouteLLM + klymentiev + effloow + cloudai + gingerlabs）——MT-Bench 85% 成本降、MMLU 45%、GSM8K 35%（质量保持 95% 的 GPT-4）；矩阵分解路由器最佳——MT-Bench 只送 14% 请求给 GPT-4（75% 优于随机基线）；收益按负载类型变化（简单 chat 路由收益高、数学重负载低，成本节省 30-85% 区间）。判据：**路由收益按负载分布测算，不是固定百分比；简单任务占比高才值得投路由器**。提升层：工具。
2. **路由开销计入总账：路由器自身延迟 50-200ms**（来源：dev.to artem42 + gingerlabs + kamya_shah）——托管活跃打分模型给每个请求加 50-200ms 分类延迟，路由成本=节省-路由开销；路由因此更适合做"算法引擎"而非每请求前置（高吞吐场景用启发式/静态路由）。判据：**路由器的延迟与运行成本计入总账，净收益为正才上；延迟敏感场景走静态规则**。提升层：工作流。
3. **Routing Collapse：预算越大越默认旗舰，小模型被荒废**（来源：arxiv 2602.03478 EquiRouter + bestaiweb + mesuvash + tristancode）——路由器随用户成本预算上升系统性默认最贵模型，即使便宜模型已够——objective-decision mismatch（预测标量分数 vs 需要离散比较）；EquiRouter 决策感知路由器直接学模型排序恢复小模型作用，RouterBench 降成本约 17%；类比 MoE expert collapse（富者愈富正反馈：梯度全给 1-2 专家）。判据：**监控小模型利用率与路由决策分布，防"路由器退化为恒定旗舰"**。提升层：工具。
4. **子任务级路由 vs 请求级路由**（来源：arxiv 2609.22951 AgentRouter + 2607.11399 Harness-Native + ACM AIMS）——同一轨迹内子步复杂度变化大：AgentRouter 12M 分类器每步选最便宜够用档，72% 成本降 <3% 质量降（优于单轮路由适配与 agent 级优化器）；Harness-Native=每次路由决策自然产生结构化数据记录（query+harness state+model choice+execution trace+outcome+cost），标签由环境而非路由器提供=数据飞轮；AIMS position-aware=路由决策在链早期改变后续子任务（级联路径），需考虑子任务在推理过程中的阶段。判据：**agent 工作流按子步路由；每次决策记录成可回放数据；路由考虑位置效应**。提升层：工作流。
5. **Default Down Escalate Up + 级联验证**（来源：betonai + xyzbytes + naqeebali + dreaming.press + agentnative）——默认从最便宜档开始，只有 eval 失败/schema 错/置信度低于阈值才升级（反向"默认旗舰降级"永不真降级）；升级上限（escalation cap）防病态输入一路弹到旗舰；级联=便宜生成+verifier 打分，置信才接受否则升级（升级请求付双模型费但买质量保证，非猜 query）；~10-20% 升级率时省 80%。判据：**路由=默认降级+验证驱动升级+升级上限；验证比猜测 query 更可靠**。提升层：工具。
6. **语义缓存：40-80% 成本降 + 阈值是精度/召回旋钮**（来源：zylos + valuestreamai + masterprompting + redis + agdex + semacache）——语义缓存 40-80% 成本降、命中 15x 延迟改善；AWS 63,796 真实查询评估=86% 成本降/88% 延迟改善/准确率>91%；余弦阈值 0.93-0.96 生产平衡区（<0.90 假阳性风险陡升、>0.97 退化为精确匹配）；精确匹配先查（零风险）→语义匹配后查（风险调整）；命中采样 1-5% 用 LLM-as-judge 评分，FP>1-2% 报警升阈值。判据：**语义缓存=先精确后语义；阈值按领域校准；FP 率是首要监控指标而非命中率**。提升层：工具。
7. **GroundedCache：四门齐开才允许复用答案**（来源：arxiv 2605.27494）——输出级语义答案缓存脆弱：相似 prompt 可映射不同正确答案、语料更新导致证据漂移、对抗碰撞可劫持缓存响应；GroundedCache 只在多道门同时满足才放行（query 相似+检索证据一致+…），"答案复用不是怎么更快而是何时安全"。判据：**RAG 场景答案复用必须验证证据仍一致，不能只看 prompt 相似**。提升层：工具。
8. **缓存分层：L1 精确/L2 prompt 缓存/L3 语义，独立按序**（来源：valuestreamai + respan + sukruyusufkaya + techearl + zyvop）——L1 精确匹配（hash 全请求 model+system+messages+tools，命中 100% 省）；L2 prompt 缓存（共享前缀：Anthropic 写 1.25x/读 10% 折扣、5min TTL 默认 1h 显式、破平约 1.4 读；OpenAI 自动 1024 token+ 50% 折扣）；L3 语义缓存；分层独立按序执行，命中一层跳过其余。判据：**缓存三层独立按序；共享前缀稳定比数量重要；TTL 按场景选**。提升层：工具。
9. **Provider Failover 失败模式分治与韧性**（来源：kuldeep_paul + truefoundry + channel.tel + nerdlevel + aiworkflowlab + arxiv 2607.15899 ContinuityBench）——故障四类：硬错误（5xx/连接拒/超时：短暂重试后转 provider）/限流（429+Retry-After：尊重头部退避换池，绝不立即重试）/延迟退化（200 OK 但慢：按 SLO 超时对冲或转）/流式中断（SSE 断了 50/300 token：重试出半截内容）；熔断器（连续失败阈值后跳过冷却窗口再试一次）；健康评分胜二值 up/down（滚动错误率+p95 延迟）；首 token 800ms 超时取消转 fallback；**突发 failover 会打爆 fallback 配额**（C=100 并发直接 429）。判据：**failover 按错误类型分治；熔断+健康评分+突发配额预留**。提升层：工具。
10. **成本治理架构：硬预算在调用前强制**（来源：zalt + linhtruong + truefoundry + redis + programstrategyhq + dreaming.press）——成本控制是架构决策不是运行时调优：语义缓存避免重复跑、路由器送简单任务给便宜模型、per-user/per-tenant 硬上限在 API 调用前强制、cost-per-outcome 指标上仪表盘抓漂移；预算三层=step budget（工具/LLM 迭代上限如 10）/token budget（累计 token 上限由 runtime 强制非模型自觉）/dollar budget（per-tenant per-feature 日支出上限，超限 429+告警）。判据：**预算=调用前强制+分层设限+成本结果指标可见**。提升层：工作流。
