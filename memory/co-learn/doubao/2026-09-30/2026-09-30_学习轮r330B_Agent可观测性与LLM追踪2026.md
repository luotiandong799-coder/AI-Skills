## 独点（10）

1. **可观测性 vs 监控二分**（来源：futureagi）——LLM 可观测性=完整遥测模型（理解系统如何运转：trace/质量分/延迟/token 成本/安全事件/漂移信号）；LLM 监控=持续盯这些信号的操作层（阈值化、告警路由、补救）——两层都建，先可观测后监控。判据：**可观测性回答"系统为什么这样"，监控回答"现在该不该报警"**。提升层：工作流/工具。
2. **三层 span 层级：会话→推理→工具**（来源：mlflow + microsoft learn）——agent 推荐模式：顶层 span=agent 会话/用户轮次；推理 span=每步规划/思考；工具调用 span=触发它的推理 span 的子级、结果作为 span 属性——分布式父子 span 还原"哪步推理选了哪个工具、结果是什么"；子代理的 API 与工具 span 嵌套在父 agent 的 span 下。判据：**trace 树=会话→推理→工具三层，工具结果落 span 属性**。提升层：工具。
3. **token 与成本属性挂 span**（来源：dev.to nainikmehta）——每个 span 附数字属性：输入/输出 token 数 + 计算成本（USD）——成本在进程内或 span processor 计算，sampler/collector 可用成本决定保留昂贵 trace（成本感知采样）。判据：**每个 LLM span 必带 token 计数+计算成本，采样器按成本保 trace**。提升层：工具。
4. **OpenTelemetry GenAI 语义约定**（来源：mlflow）——标准属性 `gen_ai.system` / `gen_ai.request.model` / `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` 跨厂商一致捕获模型调用——标准属性名让 trace 可移植、可跨平台比较。判据：**trace 属性用 OTel GenAI 标准名，别自造字段**。提升层：工具。
5. **四维遥测指标**（来源：dev.to kuldeep_paul）——Tokens（prompt/completion/cached/reasoning：暴露上下文膨胀、无限生成循环、缓存效率）；财务成本（每请求成本/累计用户消费：margin 侵蚀/预算耗尽）；延迟（TTFT、inter-token、网关开销）；可靠性（429 率、5xx 率、fallback 激活数：上游故障/配额耗尽/熔断触发）——每维配对应遥测类型（counter/gauge/histogram/span event）。判据：**监控四维=tokens/成本/延迟/可靠性，缺一维就看不见一类故障**。提升层：工作流。
6. **请求不平等：token 是成本单位 + 漂移信号清单**（来源：usenix SREcon26）——输入 token/请求突跳、空检索率上升、finish reason 长度增加、质量分下降=漂移与回归信号；p95 TTFT 上升、队列时间上升、GPU 内存逼近上限、等待请求增加、工具成功率下降=容量与可靠性信号。判据：**token 与成本按"每请求"归因；输入突跳/空检索/finish 变长=提示漂移，TTFT/队列/工具成功率=容量故障**。提升层：工作流。
7. **trace 数据治理：落湖仓、可审计、可进 eval**（来源：databricks unity catalog）——agent 产生海量 trace，传统观测工具昂贵难治理难用于 eval；方案=trace 经托管 serverless 摄取路径直接落 Unity Catalog 表（Lakehouse）——受治理、长期留存、统一 eval 与分析。判据：**trace 是数据资产不是日志：落受治理表、长留存、可回灌 eval**。提升层：工具/工作流。
8. **golden set 三件套：金迹+校准 judge+基线清单**（来源：divinci + autoolize）——golden trace=（真实生产输入+人工锁定输出+日期锁定+领域专家评审）元组；校准 judge（测过 Spearman ρ≥0.7 vs 3 个人工评审、每周重校）；baseline manifest（确切模型权重+prompt 模板+检索索引+judge 版本）——没有 manifest 无法判断分数变动来自模型变化还是尺子变化。判据：**回归测试三件套=锁定金迹+校准 judge+基线 manifest，缺 manifest 无法归因**。提升层：工作流/可复用 Skill。
9. **CI eval 门禁与阈值**（来源：testquality + dailyaiworld + futureagi）——回归 eval=冻结 golden set + rubric 评分 + 对 7 天滚动基线做 Welch t-test（per-example delta）；门禁=整体语义相似度 <95% 或幻觉率超容忍即自动 block merge；5% delta 规则（质量超过 5% 回归即拦）；金集刷新后重跑基线更新阈值（区分"数据集腐烂"vs"真模型漂移"——30-50% 的分数变动其实是数据集）。判据：**CI 门禁=金集+delta 阈值（≈5%）+幻觉率容忍；刷新金集必须重基线**。提升层：工作流/工具。
10. **LLM-as-judge 校准阈值**（来源：halla.ai + futureagi）——校准流程：采样 100-300 生产 trace → 2-3 人按 rubric 标注 → 算人-人 Cohen's kappa（>0.6 可接受、>0.8 强）→ 同 trace 用 LLM judge 打分算 judge-人一致性（<0.5 重写 rubric）；Spearman ρ≥0.7 + p<0.05=已校准、0.4-0.7=仅作辅助、<0.4=重写 rubric/prompt——**校准不是一次性：金集→盲评→相关性→错误分析→rubric 更新→重测循环**。判据：**judge 上线前先过 ρ≥0.7 校准；人-人 kappa 是 judge 可用性前提；校准是循环不是一步**。提升层：工作流/可复用 Skill。
