## 独点（10）

1. **span 分类三型：invoke_agent/chat/execute_tool 覆盖整轮**（来源：aws agentcore + otel）——gen_ai.operation.name 分类：invoke_agent=每轮顶层 span（带 user prompt+final response）、chat=inference span（读消息历史+回复）、execute_tool=工具调用；重建 session 后评估 framework-agnostic。判据：**agent 遥测最少三型 span：invoke_agent 顶层+chat+execute_tool 子 span**。提升层：工具。
2. **OTel 语义约定四域：System/Token/Retrieval/Reasoning**（来源：ietf + opensearch）——gen_ai.request.model/usage.input_tokens/output_tokens/finish_reasons（stop/tool_calls）等标准化元数据标签；跨四个域自动记录（系统上下文/token 经济/向量检索/agent 推理）。判据：**span 属性按 GenAI 语义约定命名，四域元数据齐**。提升层：工具。
3. **数据平面统一：monitoring 与 evaluation 同一 trace 流**（来源：foundry data plane）——监控与评估是 trace stream 的消费者，非独立 instrumentation 路径；token/latency/success-rate 仪表盘图表=同一 span 数据聚合。判据：**先产统一 trace 流，监控/评估/仪表盘都从它聚合，别重复插桩**。提升层：工作流。
4. **token 级追踪：prompt/cached/completion/reasoning 四类分记**（来源：braintrust + ietf）——每模型调用记录 prompt tokens/cached tokens/completion tokens/reasoning tokens；token_input_total 含 user input/system prompts/history/tool outputs re-injected——成本归属到步骤。判据：**token 追踪分四类分记，步骤级成本归属**。提升层：工具。
5. **上下文传播跨节点：W3C traceparent extract/inject**（来源：dr-021 + devops.gheware）——agent 节点间 context propagation 是调试多步工作流关键（LangGraph/AutoGen/CrewAI）；HTTP 请求头 extract/inject traceparent 串链；manual spans 显式控制（无 auto-instrumentation）。判据：**跨 agent 节点传播 traceparent，链路串起来再谈调试**。提升层：工作流。
6. **agent 执行图：线性 trace 不够，可视化委派/并行**（来源：gurutech）——多 agent 通信/任务委派/并行执行分支线性 trace 视图表达不了；dashboard 须画 agent 图（谁调用谁/数据流/瓶颈）。判据：**多 agent 可观测性用执行图呈现，不用线性 trace 硬凑**。提升层：工作流。
7. **instrumentation 先行：扩展前先插桩**（来源：devops.gheware）——每 LLM 调用/工具执行/推理步都是 trace span+语义约定；instrument before you scale——扩展前先插桩，后补插桩最难。判据：**规模扩展前先插桩，每调用每工具都是 span**。提升层：工作流。
8. **sensitive data 开关：默认关内容记录**（来源：microsoft）——enable_instrumentation(enable_sensitive_data=False)/enable_content_recording 显式开；内容记录默认关避免 PII 进 trace。判据：**插桩默认关内容记录，需要时显式开**。提升层：工具。
9. **四 API 覆盖：agents/LLM/group chat/A2A 四类插桩**（来源：ag2）——四函数 instrument agents、LLM calls、group chats、A2A servers；共享 trace ID 连接全部。判据：**插桩覆盖 agent/LLM/群聊/协议四类调用，共享 trace ID**。提升层：工具。
10. **vendor-neutral 标准替代专有 SDK**（来源：devops.gheware + toolradar）——OpenTelemetry 是供应商中立标准，用它替代专有 agent SDK；framework-agnostic instrumentation（不绑单个厂商 orchestrator）；Grafana Tempo+Prometheus 开源栈。判据：**可观测性走 OTel 中立标准，不绑厂商 SDK**。提升层：工作流。
