## 独点（10）

1. **工具命名与 schema 纪律**（来源：ai-tldr + explainx + alicelabs）——命名=verb_noun/snake_case/<64 字符；参数命名清晰（q→search_query、id→customer_id、type→notification_type）；描述写"何时用/何时不用"（负空间如正向空间重要）；只有真正必需才 required（过度必填逼模型编造值）。判据：**命名具体一致；描述含 not-to-do；required 只留真必需**。提升层：工具/工作流。
2. **并行 vs 顺序：依赖判据**（来源：machinelearningmastery + aibuzz + ai-tldr）——B 需 A 输出→顺序；两者都能用已知信息调用→并行候选；并行独立调用降延迟 3.7x（LLMCompiler）或 50-70%；并行结果矛盾（两价格源不一致）→模型综合前先定义解决策略。判据：**依赖判据=输出是否互为输入；I/O 绑定+独立→并行，矛盾结果先定裁决**。提升层：工具。
3. **工具结果全部返回、单一消息、带 call_id**（来源：aiworkflowlab + loooop.dev + developersdigest）——提取所有 tool_use 块→并行执行→所有 tool_result 放回**一个**用户消息；每个 result 配对的 call_id 必须对应；拆多条消息隐式训练模型乱接；**绝不跳过某 call 的结果否则模型幻觉**。判据：**结果=全量+单消息+call_id 配对；缺一即乱**。提升层：工作流。
4. **工具失败=一等公民观察，JSON 信封统一**（来源：codeguides + genai.club + ai-tldr）——失败规范化为 `{ok:false, typed error, retryable flag, short message}` 包进 tool_result；host 端 try/except+timeout 包裹；重试分类放工具注册表元数据而非重试逻辑；单调用重试 3 次上限、整个任务总重试 10 次上限，耗尽升级。判据：**失败=类型化信封+retryable 标记+预算；绝不省略结果**。提升层：工作流/工具。
5. **幂等键 + 不可重试错误类型**（来源：tomodahinata + agentnative + channel.tel + spinnable）——副作用工具必配幂等键（hash(tool_name+session_id+step_number)）；服务器首次见 key 执行、再遇返回缓存结果不重执行；显式标记 non-retryable（Temporal non_retryable_error_types / Inngest NonRetriableError）让语义失败终止循环不烧预算。判据：**写操作=幂等键；语义失败标 terminal 不重试**。提升层：工具。
6. **工具定义缓存：前缀稳定比工具数量重要**（来源：developersdigest + tpiros + agentpatterns）——工具定义进 system prompt 每请求都付；prompt caching 缓存块内后续请求省 90%；**任何工具定义变更使 KV 缓存全失效**——动态工具获取/RAG 工具定义=缓存破坏反模式；审计 JSON 序列化键序（意外缓存破坏者）。判据：**工具定义入缓存块；动态改定义=缓存失效，宁用固定核心集+延迟加载**。提升层：工具。
7. **工具渐进披露：defer_loading/tool search**（来源：vscode + microsoft foundry + kaman + cursor）——静态绑定全量定义=每请求付全量（741 工具=127K tokens/请求输入开销）；on-demand=模型只见轻量元数据（name+description 或 namespace），需要时按需载入——Claude tool search 砍 85% 定义 token、Opus 4 准确率 49%→74%；GPT-5.4+ defer_loading flag。判据：**大目录工具=轻量元数据+按需载入；工作集保持 3-5 工具**。提升层：工具。
8. **ToolHijacker：工具选择可被投毒**（来源：arxiv 2504.19793 + mywrittenword + lobehub）——恶意工具文档注入工具库→检索-选择流水线 96.7% 选攻击者工具（GPT-4o 靶+Llama-3.3-70B 影子）；无盒攻击不需访问 target LLM/retriever/库布局/top-k；工具 schema 每个字段都是注入点（CyberArk 注入 extra field 执行恶意指令）。判据：**工具库是注入面：第三方工具描述先审、schema 字段全可疑、关键路径不走自动选择**。提升层：工具。
9. **条件执行 + 服务端校验**（来源：theneuralbase + loooop.dev + tomodahinata）——不盲执行模型建议的每个工具调用——按 tool_call 响应决定是否真调用；服务端 validate tool name（allowlist）+参数（Pydantic，additionalProperties:false 拒额外键）；LLM 输出是外部输入、边界验证。判据：**调用前服务端校验名字+参数；条件执行=不一定全执行**。提升层：工作流。
10. **工具循环状态复位**（来源：theneuralbase + ai-tldr + arxiv 2609.33315 AgentLoop + genai.club）——tool_executor 执行后不清理 state.tool_call → 无限循环同一工具调用（生产级 bug）——执行后必须复位；重复相同调用=循环信号；AgentLoop=紧凑运行时状态+结构化验证（答案完整性/缺失证据）+有界稳定性信号→三动作（继续/综合/终止）。判据：**工具循环=执行后状态复位+重复调用检测+终止判据三件套**。提升层：工作流。
