## 独点（10）

1. **LLMOps 六原则：依赖会变、成本异样增长**（来源：dev prakruti 2026-09 + dev sri2614 2026-09 + llmdevpro 2026-07 + gravitydevops 2026-06）——**LLM 应用两个反常性质=①依赖会变（provider 更新模型/废弃版本/调行为——你的应用一行代码没动也会回归）②成本随用量异样增长（长 prompt/大 retrieved context/chatty outputs 快速累积）——LLMOps 就是让这些性质可控的实践集：versioning/evaluation/monitoring/cost control/security/feedback loops**；**六条操作原则=①自动化评估（每个 prompt/model/index 变更先跑离线评估再进生产）②prompt+model ids per deploy 版本化（能 pin/diff/rollback）③trace 每次调用（prompt version/model id/tokens/latency/cost——不 trace 就是盲调）④guardrails 验证输入输出（PII/jailbreak/injection/schema/policy）⑤永远有 fallback：retry→backup model→safe canned answer——never leak the failure ⑥gate on thresholds and trends 而非精确相等（quality is a distribution）**；**release rule=改 prompt/retrieval/model 前跑 eval 文件——"无关键安全失败且 ≥90% 样例通过"；每周 review 坏答案+高成本 traces，把重要失败加入 eval set（这是 LLMOps 的进化机制）**。提升层：工作流。
2. **生产 LLM 栈参考架构：传统层+AI 控制平面**（来源：ai-tldr 2026-06 + ephizen 2026-06 + linhtruong 2026-05 + llmdevpro 2026-07）——**生产 AI 系统=传统 system-design 层（caching/queues/autoscaling/CI-CD/reliability）仍适用，新增 AI-specific control plane=LLM gateway/semantic cache/retrieval/guardrails/evals/observability**；**linhtruong 默认架构=Gateway（one place, one auth, one cost meter）/Models（2 hosted tiers+1 self-hosted OSS）/Retrieval（pgvector→Qdrant when >10M vectors，always rerank——hybrid retrieval+cross-encoder reranking 是 RAG 默认）/Orchestration（typed graphs：LangGraph/native SDK agents）**；**Evals 是 LLM feature 的自动测试套件（labeled dataset of prompt-response pairs 测 correctness/tone/safety/task-specific quality——模型/prompt/检索逻辑变更时抓质量回归，作用=常规代码的单元测试）**；**生产栈 6 层=Evals（Braintrust/Deepeval/LangSmith 内建）/…（gateway/semantic cache/retrieval/guardrails/observability）**。判据：**先立 gateway 与语义缓存，retrieval 永远带 rerank，eval 进 CI**。提升层：工具。
3. **延迟与成本指标集：TTFT/P99/每用户成本**（来源：technologypulse 2026-05 + billionhopes 2026-07 + aiworkflowlab 2026-07）——**延迟三指标=TTFT（streaming UI 的感知延迟，目标 <800ms）/Total latency P50/P95/P99（P99>10s 是 UX 问题）/tokens per second（吞吐）**；**成本追踪维度=cost per request/cost per user/input tokens/output tokens/embedding cost/vector database cost/GPU utilization/cache hit rate/model latency/cost by provider/cost by feature/cost by customer or business unit**。提升层：工具。
4. **成本控制手段清单（12 项）**（来源：billionhopes 2026-07 + llmdevpro 2026-07 + dev prakruti 2026-09）——**prompt compression/response length limits/semantic caching（语义等价查询缓存响应）/embedding caching/smaller models for simple tasks/model routing（简单任务路由小模型）/batching/quantization/distillation/retrieval filtering/context-window management（+dependencies 变更管理）**；**semantic caching=对语义等价查询缓存响应降延迟与成本**。判据：**缓存命中率与路由是两大杠杆——语义缓存+按难度路由小模型**。提升层：工具。
5. **Drift 三类型与信号：shift ≠ harm**（来源：latitude 2026-06 + aktsk 2026-07 + aws prescriptive 2026-09 + promptassay 2026-08）——**Drift 分类表=Data Drift（PSI scores/null-rate spikes/embedding centroid distance→查数据管道/刷新 context）/Concept Drift（accuracy decline/user correction pressure/proxy metrics→retrain 或更新 retrieval grounding）/Prompt-or-model-driven drift（trace-level versioning/eval score drops/behavioral diffs→revert prompt/pin model version/fix tools）**；**嵌入比较用统计两样本检验=MMD/KS/PSI（Population Stability Index>~0.25=强信号）——shift 不是 harm：Layer-1 报警只告诉"变了"，不告诉"坏了"**；**drift alert 触发后=采样该时段 prompts→judge LLM 语义分析分类（如 "Emergence of a new topic"）——判"性质"而非仅"有无"**；**三信号节奏（不需要连续 drift monitor）=①golden set 重跑回归（输入与 rubric 固定，只有模型行为会动——此前通过项掉分=最干净信号）②production complaint clustering ③（模板哈希对照）**。提升层：工作流。
6. **Drift 检测四统计信号成本对比**（来源：insightfinder 2026-04 + promptcanary 2026-09 + ctiber 2026）——**四信号（检测提前量/假阳率/每日成本）=KL Divergence（8-12d/~4%/~$0.02）/Embedding Drift（11-16d/~7%/~$0.30）/LLM-as-Judge（5-8d/~12%/~$15-40）/Refusal Fingerprint（3-5d/~2%/~$0.05）——便宜信号先跑（KL/Refusal Fingerprint），贵信号（LLM-as-Judge）只做确认**；**CUSUM 检测器可隔离 provider 静默部署 aggressive quantized 更新（质量 0.85→0.40 的分布位移在 t=500 被检出）**；**promptcanary=检测 LLM provider 静默行为漂移（不换 model string 不公告——`promptcanary compare --provider openai/gpt-...`）**。判据：**分级部署漂移检测——廉价统计信号常开，贵 judge 仅确认**。提升层：工具。
7. **静默模型漂移与 pin 版本：2026 最阴险的回归源**（来源：ailearningguides 2026-05 + futureagi 2026-05 + martinuke0 2026-06）——**2026 非明显 drift 源=silent model version changes——provider API 的 alias endpoints（claude-opus/gpt-4o/gemini-pro）路由到"当前默认模型"，默认模型定期变——两周前正常的工作流今天行为不同**；**best practice=显式 pin model versions（claude-opus-4-7 之类精确 id），alias 只留实验**；**eval 数据集漂移=CI gate 用不再匹配生产的 contract 重新评分——hash active prompt template nightly，与 eval dataset 存储的 template hash 对比，mismatch 报警；每个 dataset version 钉住其 authoring 时的 template hash**。判据：**生产 pin 精确模型 id；eval dataset 与 template hash 绑定**。提升层：工具。
8. **Canary/blue-green/A-B 部署模式**（来源：ephizen 2026-06 + mlflow 2026-07 + llmdevpro 2026-07 + aws startups 2026-04 + martinuke0 2026-06 + linhtruong 2026-05）——**Canary=5-10% 流量给新版本，监控后渐进放量——对 RAG 尤其有价值（prompt 或 embedding model 升级的质量回归在单元测试看不见，只在真实用户查询里显现）；feature flags 配合=新 prompt 模板/检索策略可按用户/百分比 toggle 无需代码发布**；**blue-green=新旧并存→最终验证→一次全切（instant rollback）**；**A/B=不同模型版本服务不同用户段，比较业务 outcome（satisfaction/task completion）**；**embedding service 升级=blue-green+canary 组合（v2 与 v1 并存，5% 新文档路由 v2，已有向量留 v1）**；**release gate=no regression on golden metrics+cost delta within budget+safety classifiers green；canary=shadow-mode 5-10% traffic auto-rollback on metric breach；Nightly=全 eval set 跨候选模型跑，发布 quality+cost+latency report**。判据：**发布三件套=canary 小流量+golden metric 自动回滚+nightly 跨模型报告**。提升层：工作流。
9. **Guardrails 分层：模型边界+工具边界双 checkpoint**（来源：aws bedrock guardrails 2026-08 + openlegion 2026-07 + kunalganglani 2026 + pypi llm-trust-guard 2026-04 + arxiv 2603.13247 + lakera 2026-05）——**把 guardrails 从 model boundary 扩展到 tool boundary=三个 validation checkpoints，每点可调验证强度**；**schema separation 防注入（injected content 难与模型视为系统级信号的结构元素混同）；tool 返回不匹配预期 schema=错误或注入，两者都按 hard-stop fail mode**；**llm-trust-guard 五守卫=TokenCostGuard（token+dollar budget 财务熔断）/OutputFilter（PII/secret masking）/OutputSchemaGuard（schema+injection scan）/ToolResultGuard（tool 返回值验证 injection+state claims）/ToolChainValidator（危险工具序列）**；**ILION=确定性 pre-execution gate（五组件级联=TII/SVRF/IDC/IRS/CVL 分类 BLOCK/ALLOW——零标注零 API 依赖零统计训练）**；**上线前清单=10 个已知 jailbreak 直注入/恶意 doc 间接注入/schema 校验 fail closed（畸形输出不静默通过）/合成 PII 验证脱敏/会话中途切用户验证工具授权**；**风险映射=prompt_injection→ASI01 Goal Hijack；jailbreak→ASI01/ASI06；pii→ASI02 Memory Poisoning；moderation→ASI05**。判据：**输入输出+工具返回值三层校验，schema 不匹配一律 hard-stop**。提升层：可复用 Skill。
10. **2026 agent 可观测与 eval 前沿：OTEL 标准+行为/推理双轨监控**（来源：openlegion 2026-07 + langfuse×2 + langchain×2 2026-04/08 + mlflow 2026-05 + microsoft foundry 2026-06 + futureagi 2026-07 + braintrust 2026-05 + dev kuldeep 2026-09 + montecarlo 2026-07）——**OTEL GenAI semantic conventions（v1.29+，2024-11 merge，首个稳定版）定义标准 span attributes（gen_ai.system/request.model/response.model/token usage/cost...）——之前 draft 变体使不同工具 traces 不兼容；v1.29 后收敛为通用词表**；**OTEL collector fan-out=emit spans once→collector 路由多后端（LANGSMITH_OTEL_ENABLED=true）；Langfuse 映射规则=gen_ai.* spans→generations（model/token/cost 从 semantic conventions 映射），其余→regular observation**；**传统 log 调试对 LLM 不够——需 exact reproduction of call sequences+tool invocations（非确定性系统）；behavioral+reasoning monitoring 双轨=35% 检测准确率提升、4x 更可能抓到 autonomous agent 的 nuanced attacks**；**Multi-turn evaluation（public preview）=评估全多步对话质量而非单响应——catch 只在 context 累积时浮现的退化；User Simulation=自动生成 realistic multi-turn 对话场景**；**prompt 管理平台=每个 agent 的 system prompt 独立版本为 template（triage/resolver 各自 history+labels 不捆绑）；pin 真实任务 eval set+expected outcomes；gate on Task Completion+function-calling evaluator 非 manual read；promote by label 永不 in-place editing**；**Promptfoo=开源 CLI prompt eval+security testing，内建 red teaming 50+ 漏洞类型（prompt injection/PII/jailbreak），GitHub Actions 每 commit 自动安全扫描，YAML/JSON 配置版本进 Git**；**LangSmith=Braintrust=datasets/experiments/scores/eval runs 组织质量；Datadog=已有监控栈者选**。判据：**trace 按 OTEL 标准打点；行为+推理双轨监控；prompt 按 label 晋升**。提升层：可复用 Skill。
