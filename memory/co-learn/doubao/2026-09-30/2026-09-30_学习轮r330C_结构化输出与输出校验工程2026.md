## 独点（10）

1. **结构化输出三层架构**（来源：jvoltci + dev.to aifrontierpost）——可靠结构化输出=三层：schema 定义层（Pydantic/TypeBox/Zod）→ 服务端约束解码（XGrammar/Outlines）→ 客户端验证+重试（Instructor/structured-outputs API）——现代栈把 100% 结构正确作为默认（schema 进、验证过对象出、无重试）；"只是让模型返回 JSON"必炸（尾逗号/缺引号/多余说明段落包住 payload）。判据：**三层缺一不可：定义 schema→服务端约束→客户端验证重试**。提升层：工具/工作流。
2. **约束解码机制：JSON Mode 已成 legacy**（来源：effloow + dev.to tech_nuggets）——约束解码在采样循环内把会产生非法下个字符的 token 概率清零——输出保证匹配 schema，不是"通常"而是**每次**；JSON Mode/提示请求 JSON 视为旧方案，新代码别用。判据：**能上约束解码就别用 JSON mode 提示；本地模型用 grammar 约束采样**。提升层：工具。
3. **厂商支持现状与 Claude 路径**（来源：channel.tel + aiworkflowlab）——2026 约束解码可用：OpenAI GPT-5 系、Gemini 2.5；Claude 无 response_format，结构化输出走 tool use 机制；不支持约束解码的模型（含 Claude）=schema 进 system prompt + Zod 验证 + 失败带错误重试（可移植跨厂商）。判据：**先查厂商原生约束解码；没有就用「schema 入提示+验证+带错重试」可移植路径**。提升层：工具。
4. **应用侧仍需校验，HTTP 200 ≠ 合格**（来源：infini-ai + microsoft learn）——即使 strict:true/原生约束解码，应用侧仍校验返回内容：截断、空结果、服务异常；HTTP 200 只表示请求被接受，要查 finish_reason（stop 才算完整）。判据：**约束解码降失败率不消除失败——应用侧照常校验，finish_reason 必须查**。提升层：工作流。
5. **修复 vs 重试二分：先 repair 后 retry**（来源：ai-tldr + pypi outputguard）——schema 检查失败两个选项：修复=启发式补丁（json_repair 补缺逗号/未转义引号/截断结构，免费无模型调用）→ 重试=带验证错误重发让模型自纠——实践先 repair（快、免费）再 retry（贵、有效）。判据：**失败先尝试免费启发式修复，修不了才带错重试**。提升层：工具/工作流。
6. **失败三选一按序执行**（来源：zalt + ai-tldr）——解析/验证失败三选项：带错误反馈重试 / 安全 fallback 值 / 升级人工队列——生产系统三者按序用；**绝不把解析失败的结果传向下游**。判据：**失败路径=重试→fallback→人工，顺序固定，失败结果不过墙**。提升层：工作流。
7. **语义验证器：schema 通过 ≠ 业务正确**（来源：belsoftsolutions）——schema 解析通过后加领域规则验证器：日期范围断言 start ≤ end、概率分数断言和=1.0——捕获"结构合法但语义错"的输出。判据：**结构验证管形态、语义验证管业务，两层都要**。提升层：工作流。
8. **重试提示必须带具体错误消息**（来源：openlegion + wickedsmartdata）——不带错误的重试=相同提示重试白费；把具体验证错误追加进下一次请求（"action 必须是 ['search','navigate','click'] 之一，得到 'go_to'"）——自纠率 >90%。判据：**重试=原输出+具体验证错误+schema 期望，三要素**。提升层：工作流/工具。
9. **内禀自纠不可靠：必须外部接地**（来源：zylos + arxiv 2606.21724）——提示 LLM"再检查一遍"无外部接地会**退化**推理任务性能（2024-2025 研究一致）；自纠只在外部反馈接地时才可靠（单元测试结果/检索验证/工具输出比对/验证器信号）；DISC 式验证循环用二元判断门阻止重写破坏已正确回答。判据：**自纠无外部信号=退化；有验证器/测试/检索接地才启用**。提升层：模型/工作流。
10. **反思循环四终止条件**（来源：tencent cloud techpedia + genai4a11 + aitutorialmaker）——无限制反思循环=无限迭代+质量退化；必须设终止：固定迭代次数（2-3 轮）/ 质量阈值判定（评估分达标即停）/ 收敛检测（连续两次修订变化量低于阈值）/ 外部验证（单元测试/API 验证结果正确）——3 轮反思=4 次 LLM 调用，质量换成本。判据：**反思循环必配终止条件，四选一至少有一个**。提升层：工作流。
