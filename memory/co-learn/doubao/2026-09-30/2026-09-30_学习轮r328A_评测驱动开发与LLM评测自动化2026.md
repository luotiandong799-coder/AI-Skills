## 独点（10）

1. **EDD=先写评测再写提示词，CI 门禁得分**（来源：qaskills《Eval-Driven Development for LLMs》+ deepeval + cell-devlog）——评测驱动开发=**在为 LLM 功能写提示词之前先写评测**；TDD 适配非确定性模型：不断言精确输出，**断言标注数据集得分高于阈值**；三步循环=**curate ~100 金标数据集（含期望输出）→定义 3-5 个与 agent 表现强相关指标→迭代直到所有指标通过**；把提示工程从"tweak and eyeball"变成工程流程。判据：**评测先于提示词；得分阈值替代精确断言**。提升层：工作流。
2. **金标数据集构建：真实流量压缩而非快乐路径**（来源：techearl + claudelab + tensoria + chiraghasija）——**从真实生产失败构建而非快乐路径**；50-100 例起（新项目 50），**压缩生产输入分布**（客服机器人=过去一月日志 top10 类别×每类 5 例）；构成=**快乐路径 60%（常见 60% 查询）/边界 20%（长/短输入、怪字符、多语言）/对抗 10%（注入、跑题、应拒绝）/否定例（正确答案="不在知识库"）**；50 个精心挑选的例胜过 500 个合成例。判据：**数据集从生产分布压缩，覆盖失败模式优先于数量**。提升层：工作流/工具。
3. **金标集四桶结构独立版本化**（来源：futureagi golden-set-design + baeseokjae）——**桶1=常规操作 50%（真实流量）+桶2=对抗覆盖 15%（jailbreak 语料/注入变体/ai-evaluation SDK 8 Scanners）+桶3=专家手写边界 15%（受监管域/歧义/稀有类）+桶4=生产失败回放 10%（Error Feed 聚类+历史事故）**；**每桶独立版本化、独立面板评分**；生产级=200-500 任务覆盖完整行为面，按任务类型/难度/边界类别分层；季度覆盖审计+漂移检测。判据：**金标集分桶管理、每桶独立版本；季度覆盖审计**。提升层：工具/工作流。
4. **LLM-as-Judge 校准：kappa 指标+启动/月度/改 rubric 后**（来源：futureagi judge-best-practices + ai-tldr）——校准=**度量 judge 与人类在标注金标集上是否一致，然后调整直到一致**；指标=**Cohen's kappa（双标注者）/ Krippendorff's alpha（多标注者）**；校准时机=**启动时（验证开始一致）+每月（验证保持）+改 rubric 或 judge 模型后**；金标 50-200 例即可覆盖易/难/edge 三类；**无参考答案时 judge 系统性过宽（over-credit 错误答案）**——低资源语言尤甚，引入参考信息后得分下降。判据：**judge 必须校准到与人类一致才可信；无参考评分天然偏宽**。提升层：工具/方法。
5. **Judge 偏差四类：位置/长度/自我偏好/先验偏见**（来源：uiuc prior-prejudice + csdn 校准实战 + BabelJudge + arxiv 2607.12885）——**位置偏差**（总选首位/末位——诊断须控制变量换位、分别统计方向，只报整体换位一致率会掩盖方向性）；**长度偏差**（为同一正确答案做等义长短版、做"短而正确 vs 长但含一处错误"对照）；**自我偏好偏差**（judge 在自己的 benchmark 上偏袒）；**先验偏见**（**LLM 把"与模型训练信念一致"当质量**：模型训练相信的裸断言 6-7/7、写得很好的反方论证 1-2/7——即便被告知只判修辞）；每种偏差用控制变量样本对检查。判据：**judge 上线前先跑四类偏差诊断**。提升层：工具/方法。
6. **双条件门禁：均值阈值 + 单例不低于基线**（来源：vibeengines《Evals in CI Handbook》+ totalshiftleft）——**真实门禁有两个条件：聚合分过阈值（抓整体质量下降）+ 无单例显著低于其基线（抓窄幅隐藏回归）**——第一个守整体门槛，第二个守每个已做对的案例；**两条件同时满足才合并**；**每轮运行与 main 基线对比，2pp 下降在发布前可见**。判据：**门禁=均值阈值 AND 单例基线，两个都要**。提升层：工作流。
7. **三层评测频率：PR 阻挡 / 夜间全量 / 预金丝雀红队**（来源：futureagi testing-methods + agenticai M18 + futureagi voice-regression）——**Layer1 回归=50-200 金标对话每 PR（确定性扫描+廉价分类器 rubric，<3 分钟、几分/次）**；**Layer2 夜间全量=100 场景全 rubric 扫描+对 7 天基线 Welch's t-test delta 门禁（15-30 分钟）**；**Layer3 预金丝雀红队=合并构建上跑红队套件（如 50-100 场景/红队原型），过了才推 canary 1-5% 流量带自动回滚**。判据：**PR 跑轻量回归、夜间跑全量、金丝雀前跑红队**。提升层：工具/工作流。
8. **在线评测：采样 5-10% 流量异步打分**（来源：langchain agent-evals + kunalganglani production + aws agentcore + braintrust）——**离线测试测不出真实用户输入**（真实用户带来俚语/多语混码/长提示/截图/连续追问）；在线评测=**采样 5-10% 实时流量、异步跑 evaluator（启发式+采样 LLM judge）、低于阈值告警**；AWS 推荐采样率 1-5%、最多 10 个 evaluator；**低分例直接回灌离线评测集=生产→系统改进闭环**；不评估每条 trace（贵且慢）。判据：**在线评测采样 5-10% 异步打分；低分例回灌离线集**。提升层：工具/工作流。
9. **评测四层分离：离线基准 / CI 回归 / 内联护栏 / 生产可观测**（来源：futureagi llm-eval-2025 + callsphere）——**离线基准**（held-out 集打分：lm-evaluation-harness/OpenAI Evals）→**CI 回归**（合并前挡坏改动：pytest 集成）→**内联护栏**（运行时挡响应：NeMo Guardrails/GuardrailsAI）→**生产可观测**（trace+每调用打分：OpenTelemetry/OpenInference）；**2026 评测=持续管道不再单次离线**（离线发布前/内联高价值路由/异步每条 live trace/连续模拟）；**一次数字隐藏根因——format/faithfulness/relevance/safety/ops 指标分离，不合并**。判据：**评测四层并行，指标分维度不合并成一个数**。提升层：工具/工作流。
10. **生产失败→评测案例循环：agent quality loop**（来源：prefactor + insights.reinventing + braintrust）——**agent quality loop=trace→eval→feedback→change→re-eval**：生产 trace 显示实际行为（含失败会话）→**失败/可疑会话成为评测案例（带完整上下文）**→评测给每个改动打分→循环；**上线前先跑两周 trace 理解真实失败模式再谈评测**（第一周目标不是评测是理解失败模式）；自动生成平台（Latitude GEPA/Braintrust Loop AI）减维护负担。判据：**生产失败自动回灌评测集；先 trace 两周再建评测**。提升层：工作流。
