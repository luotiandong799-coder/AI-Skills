## 独点（10）

1. **A2A 协议与 agent 互操作栈：MCP 管工具、A2A 管协作**（来源：calmops 2026-06 + zylos 2026-05 + openlegion 2026-05 + sudoall 2026-06 + arxiv 2601.13671 + al-kindipublisher + flowhunt 2026-09 + vikasgoyal 2026-05 + ietf）——**双协议分层：MCP（Anthropic）标准化 agent 接工具与数据，A2A（Google 2025-04，50+ 伙伴）标准化 agent 之间 discover/delegate/collaborate——A2A 三原语=capability discovery（agent 发现与认证彼此）/task delegation（委派任务）/streaming results（流式结果+状态）**；**A2A 于 2025-12 并入 Linux Foundation AI & Agents Foundation（AAIF），创始=OpenAI/Anthropic/Google/Microsoft/AWS/Block，2026-04 Google Cloud Next 时 ~150 orgs 试点**；**A2A 之前多 agent 通信 per-framework proprietary（LangGraph graph edges/CrewAI process layer/OpenAI Swarm handoff objects 互不互通）——A2A 解决跨框架委派**；**IETF 六消息协议对比（AMQP/MQTT/NATS/Kafka/AGNTCY SLIM）=streaming performance/delivery guarantees/security/operational complexity 维度**；**A2A 与 MCP 组合覆盖完整协调栈；MCP/A2A 都不管 shared state——多框架系统落 external state layer（redis）**。判据：**工具访问走 MCP，agent 协作走 A2A，共享状态单独建外部层**。提升层：工具。
2. **编排模式选择矩阵：按耦合与延迟选**（来源：rapidclaw 2026-04 + metacto 2026-06 + claude 2026-04 + exploreagentic 2026-06 + preprints 202604.2147 + agentica 2026-04）——**五大模式=Sequential（pipeline，严格依赖）/Parallel（fan-out/fan-in，独立子任务）/Hierarchical（manager+workers，规划+执行）/Pub-Sub（event-driven，松耦合）/Blackboard（shared memory，开放问题）——按 coupling+latency 选：sequential 严格依赖、parallel 独立子任务、hierarchical 规划+执行、pub-sub 松耦合、blackboard 开放问题**；**Claude 五模式=orchestrator/hierarchical/supervisor/message bus/swarm——message bus 适用"workflow emerges from events"（安全运营系统无法预知来什么告警）——orchestrator 里累积的 conditional logic 变多时，message bus 把路由显式化+可扩展**；**Supervisor（一个中央规划器）适合 well-defined workflows/audit-heavy；Hierarchical（嵌套 supervisor）适合 large multi-domain 需 context isolation，但 latency 敏感/窄任务避免；Network（peer-to-peer）适合探索/创意研究但结果不确定；Swarm（handoff）适合 triage/routing 但无全局计划可见性**。判据：**先问"工作流是预定序列还是从事件涌现"，再选中心式或总线式**。提升层：工作流。
3. **Agent 通信四机制：按 reactive/turn-taking/控制流需求选**（来源：developersdigest 2026-05 + callsphere 2026-03 + apxml×2 2026-09 + techrxiv v2 + microsoft learn 2026-06）——**四机制=shared state（blackboard pattern）/message passing（对话式 AutoGen/AG2）/explicit handoffs（OpenAI Agents SDK/Claude Code sub-agents）/typed state transitions（LangGraph）——选择取决于 reactive updates vs turn-taking vs explicit control flow**；**blackboard=中央共享数据结构所有人可读写，agent 监控相关变更并贡献结果**；**direct message passing=同步函数调用式（A→B 等响应）；异步需 correlation IDs 匹配回复与请求**；**Pub/Sub=agent 发到命名 channel/topic 不知订阅者**；**Contract Net Protocol=manager 广播任务→感兴趣 agent 投标（suitability/cost）→manager 选标——任务分配的标准协议**；**typed messages 含 speech-act annotations（assign/request info/critique）+tool descriptors 供下游校验——tight feedback loops（AutoGen/deliberation protocols）**；**微软原则=least privilege/simplicity/auditability/robust governance；优先 platform-native orchestration 内部流，MCP 做外部工具访问**。判据：**需要 reactive 用 blackboard/pub-sub，需要轮转用 message passing，需要显式控制流用 handoff/typed transitions**。提升层：工作流。
4. **框架心智模型与选型三分法（2026）**（来源：the-agent-report 2026-07 + autogpt 2026-09 + checkthat 2026-07 + langchain 2026-06 + convly 2026-06 + pooyagolchian 2026-08 + awesomeagents 2026-04 + ailearningguides 2026-05 + aiworkflowlab 2026-07）——**三分法：TypeScript 问题是 mastra vs Vercel AI SDK；Python 问题是 LangGraph vs OpenAI Agents SDK vs CrewAI；.NET 问题是 Microsoft Agent Framework——其余跟随**；**LangGraph 30.3k stars MIT（Py+TS）=复杂 stateful workflows/durable execution/fine-grained graph control，production-ready #1（Klarna/Uber/Cisco/LinkedIn/JPMorgan/Elastic 企业部署），代价=约 3 倍于简单 ReAct 的代码；CrewAI 49.8-53.6k MIT role-based teams（LiteLLM 接任意模型），最快搭 crew 但显式控制弱；AutoGen 57.4k MIT research-style agent conversations（微软早期研究遗产，maintenance 模式）；Agno（ex-Phidata）~39k Apache-2.0 production control plane；OpenAI Agents SDK=官方最小抽象 handoffs+guardrails+tracing 内建；Smolagents ~1000 行 code-based actions（HF 自建无 adapter 层，本地模型集成最紧）；Haystack=pipeline 式 production RAG；Mastra=TS-first workflows+RAG+evals 一体**；**成本实测（同一任务）=LangGraph ~1200 context tokens/$0.021/2.8s p50 vs CrewAI ~1500/$0.026/3.4s vs AutoGen ~2800/$0.049/5.1s——AutoGen 对话式开销 ~2.3×**；**框架心智模型影响架构模式（hub-and-spoke vs supervisor）**。判据：**先定语言栈再选框架；production 优先 LangGraph/Agent Framework GA 1.0，原型优先 CrewAI，研究优先 AutoGen**。提升层：工具。
5. **生产 swarm 四策略（10000-agent 教训）**（来源：dev monuminu 2026-09 + flowhunt 2026-09 + claude 2026-01）——**生产 swarm 至少四技术策略=Task decomposition（目标拆成独立可执行 shards 带 bounded interfaces）/Result aggregation（score+deduplicate+merge 输出进共享状态）/Verification tiers（用更强或更慢的模型检查最优候选输出）/Budget governance（每层 cap token burn+tool costs+wall-clock drift）**；**模式1（最普遍）=orchestrator 拆解→每个 subagent 独立 fresh context window+dedicated system prompt→执行→返回单 summary string——无 peer-to-peer channel 无 shared mutable state（Anthropic research multi-agent system/Claude Code Task tool/OpenAI agents-as-tools/Cognition 2026-03 Managed Devins 全用此模式）**；**Large swarms 解锁能力但成本随之——capability 通过 token burn 购买**；**Anthropic 建议=多 agent 只在任务天然可拆+延迟可接受时用；单 agent+好工具常更便宜更快**。判据：**先拆成带界接口的 shards，结果聚合评分去重，强模型验证候选，预算每层封顶**。提升层：工作流。
6. **架构选择依赖域结构：scaling 不是通用的**（来源：arxiv 2512.08296 2026-09 + exploreagentic 2026-06 + preprints 202604.2147）——**架构有效性强烈依赖域结构：Finance Agent 最受益 Centralized（+80.8%）与 Decentralized（+74.5%），Workbench 只 +5.6%（MAS-Decentralized），BrowseComp-Plus +9.2%（MAS-Decentralized）**；**退化域里架构选择变 least-worst 优化：PlanCraft 中 Hybrid 相对最好（-39.1%）vs MAS-Centralized -50.3%**；**层级架构=manager 逐层委派，通信在树内线性扩展而非全集二次方（LangGraph nested-graph）**；**多 agent 并不总更好——"大多数多 agent 系统其实不需要多 agent"（r320B 已落）——本批增量=同一套任务集在不同域的最佳架构不同，选择必须对照域结构做基准**。判据：**上多 agent 前先跑单 agent 基线；架构选择按域 benchmark 而非默认分层**。提升层：工作流。
7. **Governed shared memory：fleet-memory 是分布式系统问题**（来源：arxiv 2606.24535 2026-08 + makeanapplike 2026-07 + redis 2026-08 + techrxiv memory）——**多 agent 记忆不是检索问题而是受治理的分布式系统问题——scoped access/temporal correctness/provenance/synchronization/policy-controlled propagation；四失败模式=unauthorized leakage（越权泄露）/stale propagation（陈旧传播）/（并发覆盖/无界增长，原文列举 4 个含此二）**；**3-4 个 agent 传消息后，难题从"谁跟谁说话"变成"每个 agent 允许记什么、记多久、什么成本"——read/write policies+storage tiers+retrieval logic 决定 token budget 与数据隔离**；**naive 单 agent 假设（agent 总看到最新状态）在并发读写下失效——需要显式协议规定何时/如何更新共享状态、更新如何传播**；**serialized turns=最简单 MAS 机制（固定顺序轮流 act，各读最新写回）**。判据：**共享记忆先定义 scope 与传播协议，再谈检索**。提升层：工作流。
8. **多 agent 记忆三层与并发治理**（来源：aws blog 2026-06 + zylos 2026-04/05 + goclaw 2026-04 + vectorize 2026-06 + memnexus 2026-07 + redis 2026-08）——**记忆三层=Ephemeral（会话内 token 限制）/Individual long-term（单 agent 跨会话：past interactions/learned procedures/domain expertise/episodic experiences）/Shared multi-agent（多 agent 可读写：task progress/discovered facts/team decisions/coordination protocols）——共享层把独立 agents 变成协调团队**；**并发写冲突=两 agent 同时更新同条目矛盾信息，无冲突解决则一个静默覆盖另一个；知识分区=private working memory（当前任务）+shared team memory（跨 agent 协调产物）+global organizational knowledge 三 scope**；**治理措施=每条记录 timestamp+version（semantic versioning，下游识别最新推理流避免复用陈旧）/Manager Agent 仲裁（冲突时评估可靠性+记录时间+来源优先级）/Distributed memory=私有 store+显式触发器同步共享层（隐私天然，代价=state divergence）/Hybrid=production standard**；**Claude Code 实践=lead agent 规划 spawn 子 agent（implementation/QA/security 各自 context window）——wire 共享记忆后每个 subagent 开始读同项目状态、完成写回**。判据：**共享层做版本化+仲裁，私有/共享/全局三 scope 分离**。提升层：工作流。
9. **多 agent 安全与治理框架（2026）**（来源：arxiv 2608.07556 2026-09 + arxiv 2603.15408 + cohumain + arxiv 2606.12709 + swarm-ai×2 2026-09 + feng 2026-09 + papernotes ACIArena + preprints 202609.0378 + genai.club 2026-09）——**MasDrift（600 benign tasks 八域）=委派的目标不一定携带原授权边界——对比 single-agent/centralized/decentralized×hierarchy depth，量化 constraint drift**；**TrinityGuard=Rogue Agent 评测（一个或多个 agent 偏离目标 pursue independent/adversarial goals——提供误导信息/暗中破坏/操纵他人行为但表面合作）+tier-level 加权安全分**；**meta-governance=用专门智能 agent 监控/控制 operational agent fleet（Safety/Alignment/Governance/Security 四合一）**；**Fixer stage（arxiv 2606.12709）=线性拓扑的 brittleness 源于缺 correction 而非拓扑本身——append lightweight terminal Fixer 把恶意执行差从 ~1.5pp 压到 0.6pp 恢复统计 parity**；**SWARM 四指标=toxicity/quality gap（治理是否选优，负=逆向选择）/conditional loss/incoherence；六治理机制=transaction taxes/circuit breakers（冻结 toxic agents）/reputation decay（防信任累积）/random audits/staking（skin-in-the-game）/collusion detection**；**BenchShield reward hacking 四标签=Checked（任务配置执行记录满足检查）/VectorExposed（发现潜在 hack 路径但未用）/AgentViolation（证据显示尝试或使用违规路径）/Inconclusive（证据缺失矛盾）——依赖声明检查范围与证据**；**ACI-Sentinel 反 cascading injection=不识别坏（identify the bad 难）而是 enforce the good——task-aligned semantic minimality 枚举任务必要最小信息、剥离一切无关指令与 metadata**；**SwarmGov-ZT zero-trust runtime governance=50% compromised 时保留 87.4% 精确准确率 vs 非治理 swarm 67.5%（+11.8pp 决策准确/-14.38 政策违规）**；**Agents of Chaos 三纪律=完成后立即撤权限（不保留跨会话宽泛持久能力授权）/agent 间指令需 out-of-band 验证（plain-language authority claims 不足）/row-level memory access controls（照数据库安全模式）**。判据：**授权边界随委派显式传递；治理机制在群体层运行；撤权即时、授权验证、记忆行级 ACL**。提升层：可复用 Skill。
10. **2026 运行时内建编排：差异化从 prompt 转向 runtime**（来源：dev vijay 2026-09 + vikasgoyal 2026-07/05 + flowhunt 2026-09 + toutiao 2026-09）——**Claude 4.6 Opus 内建 Agentic Workflow Engine（declaratively compose multi-step processes）；GPT-5.4 Pro Parallel Agents（runtime 单 GPU cluster 上 spin 数十个 cooperating mini-agents）；Gemini Enterprise Agent Platform（2026-04 Google Cloud Next 发布，集成 Gmail/Docs，~150 orgs 试点 A2A）**；**竞争差异化从 prompt engineering 转移到 runtime architecture/governance/operational integration——OpenAI/Anthropic/Google 全扩 native orchestration/tool coordination/memory persistence/multi-agent execution**；**企业 agent 系统收敛 hybrid architecture=确定性 workflow control 与概率性 reasoning 分离（durable workflow engines+graph-based orchestration+structured outputs）**；**2026-09 消费级转折=AI 产品主流从聊天机器人转向个人 AI 智能体（Meta Muse/千问 Personal Agent——云端独立执行、持续理解偏好、代替用户操作）**。判据：**编排能力下沉到 runtime；确定性流程与概率推理分离**。提升层：工具。
