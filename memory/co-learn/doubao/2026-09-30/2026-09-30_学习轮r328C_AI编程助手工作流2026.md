## 独点（10）

1. **工具分工判据：Cursor 日常编辑 / Claude Code 终端调查 / Codex 审计式改动**（来源：aipedia + zero-to-ai + freeaitool）——Cursor=IDE 内日常编辑+agent 工作；Claude Code=刻意终端调查（deliberate terminal investigation）；Copilot=GitHub 原生团队；Codex=让 OpenAI 编码 agent 检查本地项目、跑检查、准备可审计改动；工作流矩阵=大仓日常编码→Cursor/Copilot Agent Mode；自主功能实现→Windsurf Cascade/Copilot Workspace；CI/CD 维护→Aider 非交互；开源自主编码→OpenHands/OpenCode。判据：**按工作流需求选工具，不押单一工具**。提升层：工具。
2. **Plan Mode 四阶段工作流：Explore→Plan→Code→Verify**（来源：cursor blog + claude docs best-practices + openhands）——**Explore（plan mode 只读探索：Shift+Tab 或 --permission-mode plan，读文件回答问题不改代码）→Plan（详细实现计划含文件路径和代码引用，等批准）→Code（批准后对着计划写代码、跑测试修失败）→Commit（描述性提交信息）**；"explore only"只读子会话隔离探索与执行；复杂任务先探索后动手=省返工。判据：**复杂任务必走 plan mode，探索与执行分离**。提升层：工作流。
3. **TDD-by-Delegation：测试先行消除歧义**（来源：cursor blog + baeseokjae + vscode docs + matt pocock）——**显式告诉 agent 你在做 TDD，避免它为不存在的功能写 mock 实现**；流程=写失败测试→确认失败→提交测试→让 agent 写通过代码（禁止改测试）→迭代到全绿→提交实现；**"写代码让这些测试通过"消除 AI 编码错误的大部分歧义——agent 不能猜意图，测试即规格**；VS Code 自定义 agent 每 TDD 阶段（red/green/refactor）独立 role 定义。判据：**先写测试再让 agent 实现；测试是 agent 可验证的规格**。提升层：工作流。
4. **闭合测试环：测试结果即 ground truth**（来源：kanopylabs + explainx）——**agent 写代码→生成测试→运行→用结果做反馈，这是迭代环不是"生成测试文件碰运气"**；测试失败 agent 有两个选项：代码错要修，或测试错要调——**必须判断是哪个**；**测试先于实现=逼自己思考输入输出与边界**（哪些输入该出哪些输出、哪些边界）。判据：**agent 把测试结果当 ground truth，失败先归因代码 or 测试**。提升层：工作流。
5. **CLAUDE.md/AGENTS.md 指令文件：200 行上限 + 可复制命令 + 随改动同 PR 更新**（来源：notes.hasanarief + formation + ai-tldr + codex.danielvaughan）——**目标每文件 <200 行**（长了消耗上下文降低遵从度——"臃肿的 CLAUDE.md 让 Claude 忽略你的指令"）；三高 ROI 区块=项目描述（3-5 行）→Setup & 可复制命令（install/build/dev/test/lint/format）→约定与边界（always/never、安全规则）；**指令文件当代码对待：与文档化的改动同 PR 更新**（build 命令过时=agent 跑错命令浪费轮次调试自己的指令谎言）；手写不要自动生成；monorepo 用层级（根 AGENTS.md 共享约定+子目录覆盖，最近的胜）。判据：**指令文件 <200 行、命令可复制、随改动同步更新**。提升层：可复用 Skill/工作流。
6. **git 纪律：每个 agent 会话一个分支+书面任务**（来源：aipedia + developersdigest + aidenapp）——**"没有 git 纪律不要跑 agentic session"**——每个正经 agent 会话=分支+书面任务+只读探索先于改动；**同一仓库 checkout 跑多个 agent=分支碰撞、stash 破坏、同文件编辑冲突**。判据：**agentic 会话必开分支，任务书面化**。提升层：工作流。
7. **并行 agent=git worktree 隔离**（来源：support.claude + developersdigest + botmonster + claude docs）——**最大生产力解锁=3-5 个并行 Claude 会话、各自独立 worktree**；worktree=每 agent 自己的目录/分支/index/端口，共享同一 git 历史与 remote；**claude --worktree feature-x 一条命令=建隔离目录+检出新分支+在里面启动**；可扩到 5-10+ 会话无冲突；切换分支不中断运行中的 agent（会话绑定目录）。判据：**并行 agent 必须 worktree 隔离，一命令一个会话**。提升层：工具/工作流。
8. **权限模式分档：plan/auto/sandbox，auto 靠护栏成熟**（来源：claude ai-native-sdlc + support.claude + futureproofing）——**auto 模式=工程师批准计划后 Claude 应用每个改动无需逐次提示**，分类器评估每个动作——安全操作自动批准、风险操作仍标记；**但 auto-accept 的前提是护栏成熟**（调好的 CLAUDE.md、编码政策的 skills、阻断危险动作的 hooks、可跑的测试套件）；**无人值守硬门禁=目标条件每轮复查或确定性 Stop hook（"轮次结束前必须通过才放行"）**——Claude Code 8 次连续阻断后 override，门禁需要逃生阀。判据：**auto 模式护栏成熟才默认；硬门禁要带逃生阀**。提升层：工作流/工具。
9. **CLAUDE.md vs skills vs hooks vs subagents 分工**（来源：claude.com steering blog + thepromptshelf）——**CLAUDE.md=常驻项目指令**；**skills=按需加载的可复用能力包**（名称+描述+工具列表会话开始加载，正文大上下文按需展开）；**hooks=必然执行机制**（block 不安全的动作）；**subagents=隔离助手**（.claude/agents/ 里 YAML frontmatter：name+description+模型+工具访问，正文成为系统提示词）；**description 是 agent 条目最重要的字段**——弱描述"Reviews code" vs 强描述"Reviews TypeScript 代码的空指针/缺失错误处理/项目 API 约定违反，在提交到 packages/api 前使用"——决定自主调用与否。判据：**常驻用 CLAUDE.md、能力用 skills、强制用 hooks、隔离用 subagents；description 写触发场景**。提升层：可复用 Skill。
10. **新鲜上下文对抗性 AI 评审**（来源：futureproofing + aipedia）——**评审者在全新 subagent 上下文只看到 diff 和标准，不看到实现过程的对话——"不看实现过程的评审"是 2026 评审模式**；评审者持对立方立场攻击 diff；消除"实现会话里的共识污染"；与五连查互补（那条管"AI 交活前怎么查"，本条管"换新鲜上下文评审消除过程偏见"）。判据：**重要 diff 用新鲜上下文对抗性评审，不沿用实现会话**。提升层：工作流。
