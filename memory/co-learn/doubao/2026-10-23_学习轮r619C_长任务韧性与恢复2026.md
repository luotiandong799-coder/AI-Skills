## 四、提炼核心方法与关键事实

1. **上下文分层压缩**：先清旧工具结果→再总结旧历史→保近期上下文；Redis 热（LRU 1h TTL）/Postgres 冷；sliding-window summary。
2. **Context anxiety**：模型临限提前收尾；context resets 解决；换模型后死重补偿该删（按模型行为裁剪 harness）。
3. **失败四类分治**：transient 退避+jitter / persistent 超窗停止 / semantic 需 saga 逆序幂等补偿 / non-retryable 不重试；失败态先存库再通知+去重；OOM 升级资源重跑失败 turn（cutoff 不重处理完成 turns）；单项失败隔离（dead-letter+UPSERT+只重试失败项+一项一执行）。
4. **Checkpoint 工程**：crash-durable 写模式（temp+fsync+原子改名+checksum+schema_version）；checkpoint-resume vs event sourcing 取舍；incomplete executions（blueprint+Resolved/Unresolved）；worker 轮换防泄漏；durable event log（环境死不抹叙事）；queue worker 崩溃从头重启限制认知。
5. **执行状态替代会话历史**：SKILL.state O(1) prompt（丢验证过的中间推理）；CaveAgent 持久 runtime 对象跨 turn（+10.5%/-28.4%/-59% token）；GCC context 版本化（COMMIT/BRANCH/MERGE/CONTEXT）。
6. **预算与连续性**：planner 估子任务 token 预算+progress file；cache-aware rolling buffer（keep_n=3/interval=25+150k 触发）；压缩后 CLAUDE.md/auto memory 重注入；traces→skills 学习闭环。
7. **幂等重试精细化**：重试三要素=次数+延迟+条件；1s/2s/4s 上限 3-5 次；idempotency keys+correlation IDs 短路；UPSERT；升级路径（到限≠静默，告警+人工 triage）。
8. **平台限制认知**：EXECUTIONS_TIMEOUT/30s/60s 执行上限；worker slot 占用；队列无 checkpointing。
