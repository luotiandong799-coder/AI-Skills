### 独点判据原文（逐条，不缩水）

- r713A-1：**写入端不预筛，容量是检索侧的问题** —— memory stream 时间驱动 append-only，「不管成败每一步都记」、不预先筛掉不重要的；写入时判重要性会丢掉事后才显出价值的上下文且一次性不可重算 ⇒ 容量旋钮放检索/剪枝侧；但必须连成本量级一起报（25 agents / 2 天 / 数千美元 token），不自动迁移轻量场景。与既有「写粒度由 ingestion 单元决定」互补：那条管怎么切，本条管要不要在写入时丢。
- r713A-2：**派生层回写同一条流** —— reflection 与 plan 都存回 memory stream 并参与检索（讲义逐字 `Plans are also stored in memory stream and included in retrieval process`）；冲突时只 `replans the affected segment`；派生结论须带指回原观察的指针。⇒ 高层结论不能另存到检索不到的地方，计划改向不该付出「重跑一遍」的代价。
- r713A-3：**组件必要性要消融证明 + 连成本一起报** —— 摘要逐字 `We demonstrate through ablation that the components ... observation, planning, and reflection -- each contribute critically to the believability`；逐项缺失后果（陈旧信念 / 交互表层 / 反应式噪声）。⇒ 不能只给「架构包含三件套」的清单；可行性结论必须附量级。
