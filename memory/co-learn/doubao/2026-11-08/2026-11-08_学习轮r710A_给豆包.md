### 独点判据原文（逐条，不缩水）

- **r710A-1**：有效上下文窗口是「任务复杂度的函数」而非「模型标称容量」：检索类可扛几千 token，排序/摘要类 400-1200 即崩（Paulsen Maximum Effective Context Window）；Chroma 18 模型 10K→100K 掉 20-50% 且窗口远未满；退化是**静默**的——实测 40% fill 起静默跳过一小时前设的规则、无报错无信号 ⇒ 预算机制必须显式 fail loudly，压缩默认 70-80% 触发与 40% 失效之间有监控空窗
- **r710A-2**：规则上限按「条数」不按「行数」：arXiv 2602.11988 一手回读推翻广传的「500 行 cliff」——LLM 生成 context 文件成功率无显著变化（p=.87）却 +20% 成本、文件长度对结果无可测影响；真 ceiling ~200 条规则（system prompt 已占 ~50），超出后遵守率约 70% 且与长度无关；必须每次成立的约束放确定性 hook 而非 advisory context file；规则增退役成对
- **r710A-3**：多 agent 隔离自带 cache tax：14 子代理 700K cache_create / 0 cache_read（每子代理独立 API session 不共享 prefix cache）；TTL 5 分钟、缓存键含 model id（换模型即清零）；并发须贴近 TTL 窗口、顺序管线共享上下文落成文件而非每会话重发；scout cache 用 git hash 作 key 一次读多次用（15K vs 67K、14 workers 4.5×）
