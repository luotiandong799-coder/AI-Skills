## 二、落地点（5 个真独点）

1. **结果逐级上传** —— 后代只向直接父宣布，父先综合自己的子再向上；每层只看直接子的 announce；深度 5 是叶子且无递归工具；要汇总就在父层做，或把 maxSpawnDepth 降到 1。
2. **等完成靠事件不靠轮询** —— 不建 sessions_list / sessions_history / subagents list / exec sleep 轮询；已结束子会话只留短期窗口，陈旧 store-only 链接过期即忽略，避免重启后幽灵子代理复活。
3. **完成投递不是再发公告** —— 子结果直接交 requester；`expectsCompletionMessage:false` 跳过投递；子必须给有意义结果或具体 blocker，`NO_REPLY`/空输出不能结算，触发 missing-answer recovery；无可见结果按 `(no output)` 交回。
4. **迟到结果要复核** —— 最终答案发出后到达的子完成要 review 并继续未完工作，但不重复已交付更新；去重靠完成事实与源消息投递事实，不用 silent token。
5. **认证按 agentId 解析** —— 子会话 key 是 `agent:<id>:subagent:<uuid>`，auth overlay 取自该 agent 的 agentDir，共享 profiles 加性回退且冲突时 agent 覆盖、**无法隔离**，子不继承父账号；记忆归属字段（spawnedBy / spawnedBySenderIsOwner）是宿主事实，owner 不从子的合成权限推断。
