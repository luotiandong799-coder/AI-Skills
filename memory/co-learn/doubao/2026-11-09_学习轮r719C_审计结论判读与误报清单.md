## 二、落地点（5 个真独点）

### 1. 审计分两级，plain 没跑代码扫描（工具层）
`Some checks only run with openclaw security audit --deep`：`plugins.code_safety*` / `skills.code_safety*` / `gateway.probe_*` 仅 `--deep` 跑。判据：先报级别再报结论，plain 结果不能宣称"代码已审"。

### 2. scan_truncated 只表示没查完（工作流层）
原文明确 `does not identify dangerous code`；边界数字：500 源文件/插件·技能、跳过 >1 MiB、100,000 目录项、workspace 2,000 文件/40,000 访问。判据：报告必须带覆盖率，截断既不是"有问题"也不是"没问题"。

### 3. 同一 checkId 严重度随配置变化（可复用 Skill 层）
`warn/critical ... depending on config`（如 Gateway 是否远程暴露）。判据：按当前暴露面排序，不按 severity 字面。

### 4. auto-fix 只覆盖权限位类（工具层）
`fs.*.perms_*` = yes；`fs.state_dir.symlink` / `fs.config.symlink`（another trust boundary）= no。判据：跑完 auto-fix 仍需按 primary fix key 逐项关结构问题。

### 5. 先过 no-action 清单再报漏洞（可复用 Skill 层）
`Not vulnerabilities by design`：仅注入链无策略/认证/沙箱绕过、假定同主机敌对多租户、operator 正常读路径当 IDOR、仅 localhost 缺 HSTS、节点配对元数据当第二层审批等均按设计不成立。判据：报前先问"缺陷还是设计选择"。
