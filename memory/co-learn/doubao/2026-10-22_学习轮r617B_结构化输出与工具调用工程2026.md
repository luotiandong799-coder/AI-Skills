## 四、提炼核心方法与关键事实

1. **三层验证防线**：结构层（Structured Output Parser 管 valid JSON/字段名/enum）→语义层（validation Code node 管业务语义）→非 LLM 层最终验证（Pydantic 强制 agent 忽略的业务逻辑）；结构对≠语义对。
2. **验证前置**：Dify 在 execute_tool 前验（不消耗 MCP 资源）；Trigger schemaTask 运行前验（不匹配不执行）；n8n "catch hallucinated arguments before they hit your backend"；fernando "Never let an unvalidated object enter the downstream system"。
3. **失败重试闭环**：重试带错误消息进下次上下文+上限（n8n 4 次）+降级安全默认值记日志——三件套缺一不可。
4. **消息协议硬约束**：tool_use/tool_result 配对（每 tool_call_id 对应响应，缺失/乱序 400）、result 在前文本在后、tool_choice 强制工具调用不靠 prompt。
5. **模型能力判据**：模型不支持 strict tool calling 就不能依赖（vLLM/Qwen 实测）；Function Calling vs ReAct 按模型能力选；能力字段显式开启。
6. **strict 判据**：response_format+strict-schema flag（enforcing vs hoping）；JSON Mode vs Schema Mode（constrained decoding）；strict:true 直喂强类型函数时才用。
7. **约束窗口论**：additionalProperties:false 防额外键；Pydantic 使 agent 无法把任意字符串传进 shell/DB。
8. **provider 无关分层**：wire format 因 provider 而异，validation/authorization/idempotency/business rules 保持 provider-independent。
9. **大响应上下文削减**：post-tool 动态代码提取只传 Message；description 声明输出格式→模型反序列化；schema-only tool map 与 execute 分离。
10. **输入侧验证与白名单渲染**：withClientData 到达 agent 前验；固定 component catalog+validateSpec 第二道网。
11. **输出验证交付纪律**：临时文件防覆盖；eval 工具 mocked；七层 CI 门禁；SkillSpec 规则结构化版本化。
