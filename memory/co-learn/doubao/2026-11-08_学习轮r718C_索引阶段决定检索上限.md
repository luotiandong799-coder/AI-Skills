## 二、落地点（5 个真独点）

### 1. 1,200 字符硬上限 + 表格按行切（可复用 Skill 层）
`Chunks are capped at 1,200 characters`，长代码块在限长处直接截断；多行价格表每行一个 chunk。判据：结构迁就切块——一标题一主题、必须同出的内容放同一标题下且不超限。

### 2. 节摘要质量决定可检索性（工作流层）
索引时每节写摘要，摘要抓不住要点会让相关内容更难被找到；修法是源文档标题更清晰、主题句更明确。判据：命中率差先查摘要，再查参数——索引阶段的错检索端救不回。

### 3. 换模型重建代价不对称（工具层）
换 reasoning model 不花 token（旧索引保留，要按新模型生效需手动 Re-index）；换 embedding 全库重算并计费。判据：换模型先分两问——是否全量重算、谁付费。

### 4. 纯文本 embedding 下图片只靠 caption/alt 被检索（工具层）
无 caption 的图检索不到；要按图内容检索必须换 vision embedding 并 Re-index。判据：先补 alt 再谈换模型。

### 5. 同名上传是新增第二份（工作流层）
同名文件不覆盖，会多出一份文档。判据：更新走删旧再传或源同步 `Sync now`，别靠同名覆盖。
