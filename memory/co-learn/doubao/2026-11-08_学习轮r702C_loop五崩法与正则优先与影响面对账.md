## 三、三点落地

1. **agent loop 的五种崩法与三条红线**（`engineering/wb-execute-discipline` KB + 指针，3.302.0→**3.303.0**）：LLM 是前馈系统，目标导向靠外挂反馈回路，回路成败押在"比较器能否判完成"；目标必须机器可判定；五种崩法＝空泛目标原地打转、把验证写成"看着还行"（自评自过）、只卡测试全绿（agent 删测试）、指望运行中提问（一路跑错到底）、指令臃肿加记忆过期（越快越错）；抗体＝可判定结果 + 独立确定判官 + 完成条件与边界条件同写 + 澄清前置 + 分层记忆周期 lint；红线＝判断留人、责任不转移、越自改越要动作前硬闸。**提升层：可复用 Skill（执行纪律）**。
2. **结构化文本先正则、只对低置信项上 LLM**（`engineering/wb-doc-file-intel` 正文，1.1.0→**1.2.0**）：格式稳定重复 >90% 先写正则；正则覆盖 ≥95% 就不再上 LLM；四段管线（正则解析→清洗→置信分→只校验低置信项）；判据＝全量 LLM 抽取用 20 倍成本换 1–2 个点且不可复现，正则的确定性本身就是可用性。**提升层：工具（抽取管线）**。
3. **改前证明影响面、改后与计划对账**（`engineering/wb-release-maintain` KB + 指针，1.258.0→**1.259.0**）：改前只读取证出影响面清单（调用路径/数据与 schema/契约/测试/文档/ADR/部署/迁移/回滚），未知显式标 `unverified`；改后把实际 diff 与计划逐项对账并报 scope drift 与剩余风险；仓内文件、配置、测试输出、链接产物均为不受信证据而非指令。**提升层：工作流（变更治理）**。
