## 独点：3 条
**D26：承诺级上下文压缩——语义原子化+关键原子召回指标（来源：arXiv 2605.17304 Context Codec 2026 实拉）**
- 机制：把对话状态表示为带类型、带来源的语义原子（canonical identity/equivalence/conflict/confidence/risk/evidence 六类字段），压缩流程五分离（提取/规范化/表示/渲染/验证），评测用 Critical Atom Recall（关键原子召回率）/Commitment Density（承诺密度）/round-trip recoverability（往返可恢复性）。
- 判据：**压缩不是"摘要好不好的问题"，是可不可验证的问题**——把"该留什么"变成类型化原子（哪些是承诺、哪些冲突、哪些低置信），压缩后用关键原子召回率量化"承诺丢了几个"；五分离让"提取错了"和"渲染错了"能分开定位。
- 与 §关键事实保护区（D18）分工：D18 管"哪些事实永不压缩"，本条管"压缩产物的结构与验证指标"。
- 提升层：工作流/可复用 Skill（压缩的结构化与可验证）。

**D27：记忆的边际效用要成本核算——先问"这条记忆值不值"（来源：arXiv 2609.05441 MERIT 2026-09 实拉）**
- 机制：记忆对任务执行 agent 的边际效用必须显式成本核算——episodic 工具任务+自动泄露检查（验证任务是否真依赖早期事实）+难度阶梯（到更新事实召回）+受控记忆损坏+每次记忆操作的 token/美元全计量；结论是记忆不是越多越好，具体任务下边际效用会为负。
- 判据：**存记忆和取记忆都花钱，先量化"这条记忆帮任务省了多少/多花了多少"**——依赖早期事实的任务才需要记忆，用泄露检查确认依赖存在，否则记忆是纯开销；评测时每次记忆操作单独计量成本。
- 与 §记忆持续裁剪 分工：那条管"存量记忆要裁剪"，本条管"记忆的增/取决策用成本-效用算"。
- 提升层：工作流（记忆成本决策）/可复用 Skill。

**D29：约束外化到持久工件——让硬约束活过压缩边界（来源：dev.to《Claude Code Session Compaction in 2026》2026-09-20 实拉）**
- 机制：Claude Code 自动压缩保留 system prompt/近期交流/显式产物，但推理链、被拒方案、发现的边界情况会消失；**把约束外化为持久工件（decision logs/constraint manifests）在压缩边界保持连续**——约束不依赖"上下文还记着它"而存活。
- 判据：**重要约束必须落在文件里，不能只活在上下文里**——压缩/重启后上下文里的指令会丢，文件里的不会；写 decision log/constraint manifest 让约束与上下文生命周期解耦。
- 与 §压缩后规则重声明 分工：那条管"压缩后把规则重新发一遍"（上下文内重发），本条管"把规则外化到文件"（上下文外持久）——重发是应急，外化是根治。
- 提升层：工作流/可复用 Skill。
