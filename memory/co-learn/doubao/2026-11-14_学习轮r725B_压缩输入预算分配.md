## 二、落地点（5 个真独点）

1. **分层配额填充** —— 单次摘要输入上限 160,000 字符（约 40k token）；最新原文占半、用户旧消息占 1/4（每条 ≤2,000 字符且均匀铺开）、最旧消息占 1/10、其余均匀取段每段 ≤6,000 字符；CJK 按近似 token 权重。
2. **缺口标数并不许猜** —— 每个缺口标注省略了多少条，并要求 summarizer 不猜缺口、保留上一份摘要事实。
3. **"没改"要显式证据** —— 只有匹配 tool result 明确报 `changed: false` 才能省略该次编辑；结果缺失或只报错一律保守保留（报错不证明文件没变）。
4. **截断摘要整条拒收** —— 被输出上限截断的摘要即使含文本也拒收；默认模式自动重试一次，手动只报失败；无有效摘要则原历史留用、不写条目；分支导航同样保持原分支。
5. **预算耗尽先查 thinking，省略要可数** —— 无可见文本时可能是推理吃掉额度（可 thinkingLevel=off / 换 summarizer）；非文本输入打固定标记，前 8 条各 ≤2 标记、之后汇总，新增标记总量 ≤847 UTF-8 字节并计入 token 估算。
