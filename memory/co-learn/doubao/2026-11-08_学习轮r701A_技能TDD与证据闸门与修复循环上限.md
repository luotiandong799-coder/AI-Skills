## 三、三点落地

1. **写技能＝给流程文档做 TDD**（`engineering/wb-skill-authoring` KB + 指针，1.301.0→**1.302.0**）：RED 先不带技能跑 ≥3 个压力叠加场景并逐字记录借口；GREEN 只写挡得住这些失败的最小内容并带技能复测；REFACTOR 堵新借口；纯参考型技能不测；反合理化靠封死具体绕法 + "违反字面即违反精神"；description 写入"即将违规的症状"。**提升层：可复用 Skill（技能编写）**。
2. **完成声明前的证据闸门**（`wb-artifact-verification` KB + 指针，2.446.0→**2.447.0**）：本条消息没跑验证就不能声称通过；五步闸门（哪条命令证明→完整跑→读全输出与退出码→输出是否支持→才说）；lint ≠ 编译、agent 自报 ≠ diff；回归测试红-绿验证；"应该/大概/看起来"出现即停下。**提升层：工作流（交付前验收）**。
3. **修复循环的上限与换人**（`wb-subagent-delegation` KB + 指针，1.64.0→**1.65.0**）：每任务 5 轮上限；1–3 轮回原实现者、4–5 轮换新实现者并升模型；交"覆盖测试 + 命令 + 输出"三件才复审；复审只审 fix diff，越界只记账；Minor 只记账交最终 triage；控制者不自修；第 5 轮仍开着就自裁（park 或收下改计划）。**提升层：工作流（多 agent 收敛）**。
