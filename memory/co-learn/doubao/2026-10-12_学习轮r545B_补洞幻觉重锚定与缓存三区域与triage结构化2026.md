## 落地 4 个真独点（全部带提升层）

1. **压缩后模型不知道自己忘了什么：默认补洞且补得和真知识一样自信，怀疑压缩就重锚定；重锚定从工件走不从记忆走** → compressor 3.655.0→**3.656.0**。要点：best guess 与真实知识一样自信→验证/重读/重述/确认理解再继续；checklist=重读 PLAN.md/HANDOFF.md→重查 git diff --stat→确认目标/未解风险/下一步→从最新待办继续不从记忆继续；工件是客观锚点记忆是主观复述；checklist 可写进 CLAUDE.md Compact Instructions。提升层：工作流（压缩后恢复/认知盲区防护）。
2. **前缀缓存三区域布局：不可变前缀+只增日志+易失暂存，字节级稳定保缓存** → compressor 3.656.0。要点：规范布局 stable→volatile（system prompt→tool schemas→skills index→……→对话）；ImmutablePrefix 会话开始冻结不中途 mutate / AppendOnlyLog 只增不重排 / Volatile scratch；工具结果格式化固定；前缀指纹从字节 0 开始，命中成本约 miss 1/50-1/120；与技能重注入预算分工（缓存布局管排请求、重注入预算管压缩回填）。提升层：工具（上下文布局/缓存工程）。
3. **错误 triage 走结构化出口：LLM 返回分类+置信度+修复建议 JSON，结合 telemetry 与 incident 级重试计数** → execute 3.59.0→**3.60.0**。要点：category+confidence+remediation 结构化输出让下游按类路由；错误上下文先抽结构化字段（execution URL/HTTP status）再交 LLM，诊断是 enrich 不是 replace；per-incident retry counter 以 incident 为单位计数封顶，区分新错误与同一个错第五次；与 r545A 错误分析代理分工（那条管告警形态、本条管结构化+计数）。提升层：工作流（错误后处理/可观测性）。
4. **LLM 依赖代码的测试断言纪律：断 schema 不断值，快照 prompt，真实 API 加 flag，温度归零，多次 trial 测成功率** → execute 3.60.0。要点：断言"代码拿模型输出做了什么"不断言模型返回字符串（值断言把模型自由度写死进测试）；prompt 快照防悄悄改坏+真实 API flag 防 CI 烧钱；temperature=0/本地确定性模型跑推理链测试；真实 API 5-10 次量成功率（92%→78% 是回归、单次失败是噪声）；与 flaky 治理分工（那条管测试稳定、本条管断言与度量）。提升层：工作流（LLM 测试/CI 纪律）。
