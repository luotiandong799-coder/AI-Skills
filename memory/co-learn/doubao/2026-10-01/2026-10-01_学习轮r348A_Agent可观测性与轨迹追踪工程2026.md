## 独点（10）

1. **OTel GenAI 语义约定 2026 稳定版：span 类型 gen_ai.client.chat/gen_ai.agent.invoke/gen_ai.tool.execute、属性词汇（token/model/finish_reason/agent 元数据）、四领域（system context/token economics/vector retrieval/agent reasoning）、gen_ai.conversation.id 跨 span 复用、parentSpanId 必设**（来源：belsoftsolutions + Microsoft Learn + IETF + AWS agentperf01）——语义约定。判据：**用官方约定不 framework 私有 schema，跨框架可比**。提升层：工具。
2. **session replay 四要素：每 LLM 请求响应全文（非摘要）+ 每工具参数与结果 + 每轮上下文窗口状态（或可重建的 patch log）+ 时序与模型参数**（来源：zylos + aicoolies AgentOps）——重放四要素。判据：**能不用重跑 LLM 调用就重建完整执行**。提升层：工具。
3. **time-travel debugging=event sourcing（append-only 日志为真相源）+durable execution（副作用记忆化）+交互调试器（任意断点状态检查/修改）三综合**（来源：zylos）——时间旅行调试。判据：**agent 执行视为可倒带/分叉/从任意中间点重执行的事件日志**。提升层：工作流。
4. **非确定性根源深于采样：batch 组合（共享 GPU 上矩阵归约顺序不同浮点结果不同）+硬件异构（H100/A100 数值精度不同，temperature=0 相同输入也可能不同 token）**（来源：zylos）——非确定性根源。判据：**复现 agent 行为必须锁定服务版本+硬件+批次环境，不能假设 temperature=0 确定**。提升层：模型。
5. **五 bug 形状覆盖多数生产失败：stuck loops/幻觉工具参数/上下文丢失/规划走错路径/跨部署静默退化；静默退化无错误信号，靠持续评估不靠错误率监控**（来源：respan + schrijfhuis）——五形状。判据：**错误率监控对静默退化是零信号**。提升层：工作流。
6. **eval-to-guardrail 生命周期：evaluate（离线评估固定数据集）→codify（评估 rubric 转运行时策略）→deploy（拦截输入输出）→observe（trace 反馈）四阶段连续循环**（来源：galileo）——评估转守卫。判据：**离线评估标准转运行时拦截策略，不另起一套**。提升层：工作流。
7. **在线评估分层：确定性规则（schema/PII/引用检查）跑 100% 流量，LLM judge 只跑 1-10% + 100% 高危；agent 场景对每个工具调用打分**（来源：latitude + codeables）——评估分层。判据：**先便宜全覆盖，贵评估按风险分层采样**。提升层：工作流。
8. **tail sampling 保留策略：100% 错误 trace+100% 低于评估阈值+100% 高成本（P95 延迟或 token 以上）+1-10% 随机基线**（来源：bestaiweb）——尾部采样。判据：**保留调试需要的信号，存储成本可控**。提升层：工具。
9. **行为失败类型学：AgentCore 11 类（幻觉/错误动作/指令违反/编排错误/上下文处理等），分析政策合规与行为正确性而非错误信号，每个失败产出 trace 位置+类别+自然语言描述**（来源：AWS AgentCore）——失败类型学。判据：**失败检测按行为类别不靠异常信号，才能抓静默失败**。提升层：工具。
10. **trace 聚类错误分析：把失败 trace 汇总→embed+聚类成命名 issue→根因到精确 span 与字段；会话摘要嵌入聚类读真实使用分布**（来源：futureagi + saulius + latitude）——聚类分析。判据：**未知失败模式靠聚类发现，不靠预设 taxonomy 盲搜**。提升层：工作流。
