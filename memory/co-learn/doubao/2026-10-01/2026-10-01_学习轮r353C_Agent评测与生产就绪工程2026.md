## 独点（10）

**1. 发布就绪五关 checklist（Eval/Safety/Cost/Monitoring/Docs）**（来源：AgentFlow Release Checklist 2026-09-24 + Brightlume 40 项 2026-04-17 + Pickaxe 2026-06-30 实拉）：上线前逐项签核——Eval Pass（quality tests green）/ Safety（no PII leaks、no harmful outputs）/ Cost（budget alerts configured）/ Monitoring（logs/metrics/alerts working）/ Docs（API docs/user guide/runbook complete）；成功指标必须可测化（"agent resolves queries 92%+ first attempt"、"P95 latency<2s"、"cost per inference<£0.15"）；定义"normal"基线再部署（cost spikes/error rates/repeated tool failures 设 alert）；Pickaxe 补：verified stop conditions/error recovery（无无限重试循环）+RAG faithfulness+access control（user A 不能达 user B 数据）+staged rollout（sandbox→internal→production）。判据：**上线前五关——eval 绿/安全无泄漏/成本告警/监控齐/docs 齐；成功指标必须可测（准确率+延迟+成本三件套）；先定 normal 基线再设告警；渐进上线（沙盒→内部→生产）**。提升层：工作流。

**2. CI 评测门禁四关（assertions/golden/judge/baseline）+ 双阈值表**（来源：eCorpIT 2026-07-16 + RockB 2026-06-19 + Openlayer 2026-07-21 实拉）：四关分层——①Deterministic assertions（schema/required tool call/cost-latency budget/forbidden strings，必挡 merge）②Golden set（core features/past bugs/known edge cases，必挡）③LLM-as-judge（semantic qualities assertions 够不着，borderline 挡）④Baseline compare（vs last marked-good run per scorer，回归挡）；阈值双层——CI Gate（task completion 85%/grounded 95%/policy violations 0/regression delta 0.05 tolerance/cost block 15%↑）vs Production SLO（90%/98%/0/alert 10%）；Openlayer 三阈值型（absolute floor 如 groundedness<85%、relative delta、…）。判据：**eval gate 是 CI 一等基础设施——四关分层（确定性→golden→judge→baseline），每关独立阈值；任何 rubric 掉点挡 merge；gate 阈值比 SLO 严**。提升层：工作流/可复用 Skill。

**3. canary 渐进发布四阶段 + 自动回滚触发（soak + kill switch）**（来源：Microsoft Learn 2026-06-25 + Future AGI 2026-05-20 + rapidclaw 2026-04-20 实拉）：5%→24h→25%→50%→100%，每步 soak 至少 1h（高风险 4h）等慢失败；质量门 eval 分数掉过基线阈值停+自动回滚；四触发器发布前写好——guardrail trip rate>1.5× trailing 7-day 率（15-min window）/per-rubric rolling mean 掉过 noise floor（Groundedness 1-5 分掉 0.5 有意义、0.05 没意义）p<0.05 Welch's t-test/p99 latency 超标；kill switch 单 flag 秒切回；**版本化五件套 immutable artifact（prompts/tool definitions/model pin/memory schema/configuration）一起滚**；never use "latest" model IDs。判据：**canary=切流+soak+统计显著门+kill switch——回滚触发阈值发布前定义；agent 版本五件套钉死不可变，禁用 latest 模型 ID**。提升层：工作流。

**4. capability vs regression evals 两型分离（低通过率起点 vs 近 100% 锁）**（来源：Anthropic 2026-01-09 + memexlab 2026-05-22 实拉）：capability evals 答"能做好什么"——从低通过率开始、target agent 挣扎的任务、给团队 hill to climb；regression evals 答"还能不能处理以前能处理的"——应近 100% 通过、防 backslide（掉分=坏了要修）；pass@k（k 次至少一次成功，随 k 上升）vs pass^k（k 次全部成功，随 k 下降）——pass@1 优化首试，pass^k 是端用户必须每次可靠场景。判据：**能力评测从低起点爬坡、回归评测锁近 100%——两型分开建；首次成功率看 pass@1，端用户可靠性看 pass^k**。提升层：模型/工作流。

**5. 三类证据评测（结果/过程/体验）**（来源：IceYao 2026-04-30 实拉）：agent 评测三类证据齐查——**结果证据**（最终环境状态正确：测试通过/订单完成/文件生成/页面状态符合预期）/ **过程证据**（工具调用合理、不绕流程、无危险行为、不异常消耗轮次与 token）/ **体验证据**（语言清楚、解释风险、产品 tone、合规）；只看最终文本 agent 可能"以错误方式达成结果"。判据：**agent 评测看三类证据不只最终文本——结果+过程+体验三证齐，防"答对了但干得不对"**。提升层：模型/工作流。

**6. 分层测试成本金字塔（五层频率×成本 + judge 三档分流）**（来源：Future AGI 2026-05-20 + CheckAgent 2026-07-26 + LobeHub 2026-09-23 + Future AGI Judge Tier 2026-05-14 实拉）：五层按频率与成本排——unit（mock，free，every commit）→ regression eval（golden set rubric，cents，every PR sharded）→ integration（tool/retrieval/multi-turn，cents-dollars，nightly）→ red-team（adversarial/jailbreak/OWASP，dollars，pre-canary）→ canary（1-5% live，eval cost，every release）；judge 三档——heuristic ~$80/100K traces 管 99% 高频连续评测 / cheap judge ~$2,000 分层采样 flagged / frontier judge ~$24,000 只打失败 1% 硬 rubric；garak 成本锚（narrow 200-800 prompts $2-10，full 数千 $25-80+）。判据：**别为每次 commit 付 LLM 钱——分层跑（commit 免费 mock→PR cents→nightly 集成→release 前 red-team→canary）；frontier judge 只用在失败 1%**。提升层：工具/工作流。

**7. golden dataset 生命周期管理（版本化 gate + 补 gap + 季度剪枝）**（来源：AWS AgentCore 2026-05-28 + Future AGI Golden Dataset 词条 2026-05-19 + Alibaba AgentLoop 2026-08-26 实拉）：版本化数据集——inner loop 把失败 curate 进 draft，outer loop published version 变 gate（immutable ground truth intact；"内循环告诉你修好没的分数，就是外循环决定发不发的分数"）；维护三动作——ScenarioGenerator 填 cohort gaps（multilingual edge cases/rare intents/adversarial inputs，标 source=synthetic+audit sample）、季度剪枝（在 gateway routing pool 所有模型上都过的行失去区分度还涨成本——删但留归档）、BadCase Set 单独跟踪（失败样本定向优化+质量门）；Alibaba 三集（Golden/BadCase/Manual Annotation）。判据：**评测数据集像代码一样版本化+治理——失败晋升 draft→发布成不可变 gate；合成行补 gap 须标记审计；季度剪枝失去区分度的行（保留归档）**。提升层：工作流/可复用 Skill。

**8. trajectory-first vs task-completion-first 评测框架**（来源：Future AGI 2026-05-20 + TRAJECT-Bench ICLR 2026 实拉）：trajectory-first 评完整有序 trace（tool selection/arguments/plan/recovery/task completion）——多步 agent、工具密集型、>3 tool calls/task 必须用；task-completion-first 黑箱公开基准（BFCL/tau-bench/ToolBench）适合模型选型/能力下限/厂商对比，但"对你的 registry、schemas、error codes 一句话不说"；TRAJECT-Bench 轨迹级指标——EM（工具名 exact match）/Inclusion（ground truth 工具覆盖比例）/Tool Usage（参数匹配）/序列依赖满足；识别 similarity confusion/parameter blind selection 具体失败模式。判据：**多工具任务用 trajectory-first（工具选择/参数/顺序/依赖逐项诊断），公开基准只回答模型选型——两者答的问题不同**。提升层：模型/工作流。

**9. step-level vs outcome-level 评测（回归二分定位）**（来源：agentnative 2026-07-26 + Mastra 2026-10-01 实拉）：outcome eval 告诉你 agent 失败了，step-level 告诉你为什么（step 7 用 customer name 调 search_orders 而非 ID）；40-step run 只挂 outcome 是最差调试循环（红标+不知道修哪步）；Phoenix OTel-native trajectory evals 把分数挂到具体 span（regression bisect 到特定 tool call）；Mastra 双 scorer——code-based（exact step matching+ordering 确定性）/LLM-based（semantic 轨迹质量）。判据：**多步 agent 必须 step-level——评分挂到具体 span/tool call，让回归二分定位到具体步骤；outcome-only 在长轨迹上是红标+无头绪**。提升层：工具/工作流。

**10. 成功指标与分级阈值（hallucination budget 定 task success 阈值）**（来源：SF AI Labs 2026-07-09 + Anthropic Define Success 2026-03-23 + Claude Managed Agents 2026-09-28 实拉）：task success rate 阈值由场景幻觉预算定——draft generator 60%/customer-facing 98%；四指标齐（task success/tool-call accuracy/output quality/cost）；成功标准 Specific/Measurable/Achievable（"good performance"→"accurate sentiment classification"）；Claude managed agents：定义 outcome 时 harness 自动配 grader 评估产物→explanation 反馈给 agent 迭代，直到 outcome 达成。判据：**任务成功率阈值按场景幻觉预算定（草稿 60%/对外 98%）；成功标准 Specific+Measurable；outcome 定义后自动配 grader 循环反馈迭代**。提升层：模型/工作流。
