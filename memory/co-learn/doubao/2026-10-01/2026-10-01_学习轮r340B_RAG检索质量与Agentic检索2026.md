## 独点（10）

1. **自反思 RAG（Self-RAG）：检索后显式评分步骤——模型评估块相关性/充分性，不足则换查询重检索或判定知识库无答案**（来源：rapidclaw）——检索与生成之间插入 judge。判据：**检索后先评相关性/充分性再生成，不足就重查或声明无答案**。提升层：工作流。
2. **检索预算显式化：embedding/search/rerank 各阶段延迟单独跟踪预算，检索不能静默吃掉推理/工具调用时间**（来源：AWS agentperf03-bp03）——查询改写前置每次检索（agent 措辞与语料词汇偏离时保 recall）；hybrid+rerank 按需堆叠非默认。判据：**检索延迟按阶段设预算；hybrid/rerank 按语料与查询匹配度决定要不要，不默认全上**。提升层：工作流。
3. **检索质量三指标与生产阈值：Answer Relevancy≥0.80 / Context Precision≥0.75 / Context Recall≥0.80**（来源：腾讯云 techpedia + krunalkanojiya RAGAS）——RAGAS 度量直接映射失败模式（faithfulness↔缺失上下文约束、answer relevancy↔rerank miss、context precision↔词汇不匹配）；发布前跑 golden set。判据：**RAG 上线前用固定指标+golden set 过门，不是靠感觉**。提升层：工作流。
4. **递归幻觉级联（F30）：幻觉中间结果触发后续查询→级联递增虚构**（来源：taxonomy F30 + ini8labs）——agentic RAG 循环特有失败模式；中间结果必须挂证据/置信度，否则错误传播成链。判据：**检索循环里中间结果先验证再驱动下一步，防幻觉级联**。提升层：模型。
5. **知识缺口金丝雀（knowledge-gap canaries）：用故意不在语料里的问题测 RAG，错答大多带着检索证据（98% CustomGPT/100% Gemini 错答都引用来源）**（来源：arXiv why RAGs hallucinate）——主失败模式不是无中生有而是"检索上浮误导证据"；评测加金丝雀集测 gap 场景。判据：**RAG 评测要含知识缺口金丝雀：测"语料没有时是否诚实不答"**。提升层：模型。
6. **硬限流终止条件：max_iterations=3~4（单 KB 3/多 KB 4-5）+ wall-clock timeout + 查询级循环检测（相同改写查询出现两次即断环升级 fallback）**（来源：aloknecessary + jahanzaibai + AWS bedrock + kanopy）——自纠正循环无界会每次请求跑满迭代吃成本；cap 后仍不足→带低置信标记进合成，诚实回答"部分信息"。判据：**检索自纠循环必须硬 cap+超时+同查询循环检测，cap 后降级为诚实部分回答**。提升层：工作流。
7. **cross-document 实体解析崩塌：检索到同名实体属不同语义上下文（Project Phoenix 工程/HR/设施），embedding 相似度无法区分，模型混答**（来源：ragaboutit + Stanford IR 2026-07）——跨文档实体解析需显式上下文消歧（metadata/domain 标签），不能只靠向量相似。判据：**同名实体跨文档必须显式消歧（域标签/元数据），向量相似度兜不住**。提升层：工具。
8. **护栏贪食症（guardrail gluttony）：过度堆叠输出校验/关键词过滤/相似度检查/拒绝提示，44% 系统开始拒绝合法问题**（来源：ragaboutit AILuminate）——安全≠越多越好；护栏加一层测一层误拒率。判据：**每加一层护栏都要测误拒率（合法问题被拒比例），护栏有成本**。提升层：工作流。
9. **检索质量评审器（judge retrieval with retry）：检索→judge 评分（相关性/充分性）→is_sufficient 通过即 break，否则用 judge 建议的改写查询重查**（来源：aistackinsights + AWS opensearch）——judge 输出结构化判断（含建议 query）比纯阈值更有信息量；maxRetries 从 1 起步，重试率<10% 说明检索已稳。判据：**judge 给结构化"充分/改写建议"，重试率当健康度指标监控**。提升层：工具。
10. **两阶段规划+小 agent 任务执行+质量门：scope-discovery 先探语料有什么（歧义查询）→answer-planning 产出具体检索任务；每个任务跑 retrieve-answer-retry 小循环；合成后质量门查覆盖缺口/含糊/不实**（来源：NVIDIA agentic RAG + futureagi multi-hop）——agentic RAG 四模式可组合：routing/corrective/self-reflective/multi-hop。判据：**复杂查询先探语料再定任务，合成后过质量门查覆盖/含糊/不实**。提升层：工作流。
