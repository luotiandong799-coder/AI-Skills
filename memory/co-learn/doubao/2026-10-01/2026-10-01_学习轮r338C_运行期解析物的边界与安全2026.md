## 独点（10）

1. **opaque handle 模式：agent 只持引用不持值，vault proxy 在网络层解析注入**（来源：openlegion vault-proxy + keyrunner）——agent 持 `$CRED{stripe_key}` 引用串标识凭据不解析它；调用 API 带 handle 时 proxy 拦截、解析、网络层注入、转发；agent 永不见明文。判据：**运行期解析物=持有引用不持有值，解析发生在边界层**。提升层：工具。
2. **JIT secret resolution：解析只在 Runner 安全边界内，不经控制平面**（来源：planton）——encrypted at rest、按名引用不按值、无明文传输/落盘；secrets resolved just-in-time within Runner security boundary，never transiting control plane。判据：**解析点=执行边界，解析前不出现明文**。提升层：工具。
3. **SecretRef 引用模式：资源规格按名引用、永不用内联值**（来源：planton + agentcli value_from）——`value_from` 是可复用模式：inputs/proof/provider_config 里引用敏感值不嵌入 manifest；SecretRef pattern 按名引用。判据：**manifest 里只有引用没有值，值永远在运行时解析**。提升层：工具。
4. **secret provenance 三阶段生命周期：激活（解析时）→传播（随数据流经工具与块）→投影（跨边界前替换为变量名）**（来源：sim.ai）——投影把原值替换为变量名，trace 显示 `{{STRIPE_KEY}}` 而非 key 本身，比通用 [REDACTED] 更有用（可区分两个不同 secret）。判据：**运行期解析物要有来源追踪：何时激活、如何传播、跨边界投影**。提升层：模型。
5. **执行期表达式解析 vs 保存时绑定：prompt 动态化走执行时解析**（来源：harness）——Instructions 字段表达式在 pipeline 执行时解析而非保存 agent 时；repoName/prNumber 等运行时值使 prompt 动态化而不改 agent 定义；Agent step 只指定 agent 名字版本+运行时输入值，不定义 prompt。判据：**区分"保存时绑定"与"执行时解析"：prompt 动态化走执行时解析**。提升层：工作流。
6. **eager 验证是默认，lazy 门是半懒：懒解析只延迟校验器不延迟存在性检查**（来源：komirka P8）——`bind(tesserae, sources)` 验证明确列出的集合、现在、聚合一个错误；`bind.lazy()` 仍 eager 解析 raw presence（缺失变量在 bind 时即死），只延后 validator 执行。判据：**解析物绑定默认全量即刻校验，懒解析不跳存在性检查**。提升层：模型。
7. **上下文窗口隔离 SEC-01：凭据永不进模型上下文**（来源：airuntimesecurity + credential provider plugin RFC）——凭据不出现于 prompt/system prompt/对话历史/注入上下文的工具结果；engine 注入 process.env 供工具执行，但 LLM 永不见原始值（否则会在输出/日志/未来 prompt 泄漏）。判据：**运行期解析物的最高边界=上下文窗口；解析到 env 不进上下文**。提升层：模型。
8. **短租期凭据：每请求唯一 API key + lease ID 自动过期**（来源：zylos vault enterprise）——agent 从不持有长命凭据；被攻破也只是几小时有效的 token。判据：**运行期解析物配合短租期，值解析后快速失效**。提升层：工具。
9. **per-service 凭据分权：每服务只读自己的凭据文件，爆炸半径限单一服务**（来源：wbaconsulting）——不要一个服务能读全部凭据（交易系统读 CRM、CMS 读金融 key=单点妥协全爆）；每个生成文件只含该服务所需 secret、owner-read-only；运行期从 vault 解析。判据：**运行期解析按服务分文件分权，不是全局一把抓**。提升层：工作流。
10. **execution identity 全链路：static binding→approval→proof→identity→authorization→sandbox→execution→postcondition→evidence→audit→cleanup**（来源：agentcli）——本地执行管线从静态绑定到清理完整；value_from 贯穿 inputs/proof/provider_config。判据：**运行期解析物要过完整执行身份链，引用模式贯穿全流程**。提升层：工作流。
