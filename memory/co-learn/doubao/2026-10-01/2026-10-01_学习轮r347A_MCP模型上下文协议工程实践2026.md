## 独点（10）

1. **MCP 2026-07-28 无状态化：协议层最大变更——删除 initialize 握手与 Mcp-Session-Id，每请求自带版本/能力/客户端身份元数据（_meta+新协议头），服务器不得从前序请求推断状态；收益=round-robin 负载均衡、serverless 部署、Mcp-Method 头路由与响应缓存**（来源：MCP spec basic + blog 2026-07-28 + awswell-architected）——无状态化。判据：**无状态=可水平扩展；服务端状态一律由客户端显式持有（state handles）**。提升层：工作流。
2. **工具发现客户端最佳实践五条：多细节级别（name-only/name+desc/full-schema 让模型选）/缓存工具定义避免重复 tools/list 往返/list_changed 时重建检索目录/按来源服务器分组呈现让模型推理相关能力/渐进式发现阈值=工具定义占上下文 1%-5% 时切换**（来源：MCP Client Best Practices）——发现实践。判据：**工具定义进上下文前先问"全量还是渐进"；list_changed 是重索引信号**。提升层：工具。
3. **渐进式工具发现三实现：层次 meta-tools/语义工具搜索/意图捆绑——复杂度-精度-延迟三角权衡；MCP-Zero 两阶段分层路由把复杂度从 O(n) 降到 O(m+|T_filtered|)；contextweaver 把全部 schema 换成 ChoiceCard 短名单+artifact 防火墙，42-84% prompt token 减少**（来源：chanl + arXiv 2506.01056 + contextweaver）——渐进发现。判据：**全量加载只在工具面很小时合理；先过滤服务器再匹配工具**。提升层：工具。
4. **固定 tools 前缀与提示缓存的反直觉实测：固定 3-tool 前缀在 36 次运行中 0 次命中缓存，而"先渐进发现再注入"模式缓存命中率最高 93%——缓存不因前缀固定而存活，工具列表的稳定前缀假设不成立**（来源：tpiros.dev 实测）——缓存反直觉。判据：**缓存命中的前提是"前缀在多次调用间不变"，工具列表变动即破坏；用实测数据否决直觉假设**。提升层：模型。
5. **MCP primitive 三件与使用纪律：tools=执行/resources=只读上下文/prompts=用户显式调用的模板（非自动触发）；AWS 英雄建议=把重复工作流的确定性核心变服务器执行步骤（constant/from_step 绑定）、判断步骤留给 LLM 引导**（来源：MCP server-concepts + AWS Heroes）——primitive 纪律。判据：**prompts 是用户控制的，不被自动触发；确定性步骤下沉、判断步骤留模型**。提升层：工作流。
6. **工具面命名空间三故障：M2 namespace collision（≥2 服务器同信任层广告同名工具，静默选一可能路由错）/M3 tool shadowing-rug pull（低信任服务器广告高信任工具名，如社区服务器广告 delete_file）；ecosystem-wide 775 个名字冲突（search 在 32 个不同服务器出现）；last-registered-wins 无警告策略=静默覆盖**（来源：arXiv 2609.19425 + theorydelta + agentthreatrule）——命名冲突。判据：**多服务器合并注册表前先做命名空间解析；last-wins 是危险的默认**。提升层：工具。
7. **命名空间防御四件套：前缀命名空间（Claude 双下划线 serverKey__toolName）/作用域优先级 most-specific-wins（local>project>user>plugin>connector）/CVE-2026-30856 教训（mcp_{service}_{tool} 命名惯例本身可被利用）/IETF 注册表提案防 ad-hoc 表面名**（来源：markaicode + agentpatterns scoped + GitLab advisory + IETF draft）——命名防御。判据：**命名空间解析要显式策略（前缀或作用域），不能静默覆盖**。提升层：工具。
8. **MCP 授权硬化：OAuth 2.1+PKCE 对远程服务器强制；iss 参数按 RFC 9207 校验防 authorization-server mix-up（单客户端多服务器部署模式下高发）；DCR 设 application_type；MCPS 加密层四原语=Agent Passport 密码学身份/签名信封（完整性+不可否认）/工具定义签名（防投毒篡改）/nonce+时间戳重放保护+transcript binding 防降级**（来源：MCP blog + IETF MCPS draft + cameta 团标）——授权硬化。判据：**远程 MCP=OAuth 2.1 PKCE+iss 校验；工具定义签名防投毒**。提升层：工作流。
9. **MCP 观测缺口与补法：老 logging/setLevel 退役→_meta 的 modelcontextprotocol/logLevel+notifications/message 按级过滤+Mcp-Method 头关联；生产观测=结构化日志+correlation ID（x-agent-id/JWT claim）+OTel span provider 跨工具调用关联；云网关内置 token 成本分析与端到端 trace（user query→agent→MCP 全链路）**（来源：aws bedrock-agentcore + azure apim + dev.to×2 + alibabacloud）——观测缺口。判据：**观测缺口=没有工具名/栈/时延的信号；每个 MCP 调用带 correlation ID**。提升层：工作流。
10. **MCP 网关四部署模式+政策评估：hub-and-spoke（单 region 简单、单点故障）/federated mesh（多 region、控制面复杂）/ambassador 边车（每 agent 组细粒度隔离、开销高）/virtual server（按角色/团队划工具集、schema 管理重）；网关=薄组件截获每个 MCP 调用、评估政策捆绑（permit/deny/modify/escalate）；虚拟 MCP 捆绑+SCIM 同步+工具更新策略（auto-enable vs admin approval）**（来源：gingerlabs + swfte + mintmcp）——网关模式。判据：**网关是政策执行点不是代理；选型按 region/隔离/开销三角**。提升层：工作流。
