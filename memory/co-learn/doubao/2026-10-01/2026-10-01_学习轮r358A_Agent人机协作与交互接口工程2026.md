## 独点（10）

**1. 审批中断模式（interrupt 挂起+状态序列化恢复，审批面覆盖整条运行链）**（来源：OpenAI Agents SDK 2026-09-17 + LangChain HITL 2026-09-20 + Agentmelt 2026-07-29 实拉）：工具调用需审批时 SDK 暂停运行、返回 interruptions、从同一 RunState 恢复——审批表面 run-wide 不限于当前顶层 agent（工具属于当前 agent 或经 sub-agent 委托同样适用）；LangGraph interrupts+checkpoints 持久化——pause 中断、checkpointing 持久化完整图状态、Command 恢复（或修改）运行；页面刷新/数分钟或数天后异步响应后从精确检查点恢复；load-bearing primitive=暂停 mid-run 不丢状态。判据：**HITL 审批=工具声明 require_confirmation→中断挂起→完整状态检查点→批准后从精确断点恢复；审批入口覆盖整条运行链**。提升层：工作流/可复用 Skill。

**2. 预执行审批门（结构级中断，agent 不可绕过）**（来源：OpenLegion 2026-06-01 + LangChain 2026-09-20 实拉）：pre-execution approval gate 在不可逆动作紧前阻塞——agent 组合提议动作、展示、暂停；无明确批准信号前不可逆动作零执行；interrupt 编码在 workflow 结构里——agent 无法绕过（prompt 级提示可被忽略，结构级中断不能）；唯一对不可逆动作提供真正保护的模式。判据：**不可逆动作=结构级预执行审批门（编码在工作流），非 prompt 级提示；发邮件/删记录/金融交易/任何不可逆操作先人工审**。提升层：工作流/可复用 Skill。

**3. 确认门 UX 五则（动作具名/对象可见/完整范围/diff 预览/拒绝易）**（来源：AgentPatterns.ai 2026-09-30 + byaiteam 2026-03-09 + 人人都是产品经理 2026-08-26 实拉）：确认时展示 exact action and data——summaries 会掩盖注入 artifacts；界面写清动作（"准备运行测试命令""准备修改两个文件"而非"Codex 希望运行工具"）→展示对象（文件操作给路径+diff、网络访问给目标域名、对外发送展示接收方）→涉及多项对象展示完整范围（不用"等三个文件"隐藏）；approve-and-execute=dry-run 摘要+diff/模拟（发邮件前显示最终草稿+收件人列表+附件；删文件显示哪些文件哪些文件夹）；make rejection easy——默认批准的 UX 破坏 gate 目的；high-sensitivity 用 watch mode 逐个动作观察；日志记录 confirmed+rejected 供审计（异常模式可能指示活跃攻击）。判据：**确认 UX=动作具名+对象可见+完整范围+diff 预览+拒绝成本低；确认与拒绝双侧入审计日志**。提升层：工作流/可复用 Skill。

**4. 三态人机交互模型（In-the-loop/On-the-loop/Out-of-the-loop 按风险选）**（来源：anhtu.dev 2026-05-25 实拉）：HITL=每个高风险动作前批准/拒绝/编辑，agent 暂停——fit 不可逆高风险动作；HOTL=实时监控、不对劲就介入，agent 继续跑——fit 可停止/可回滚的快速流；OOTL=事后审计日志——fit 可逆高频低风险；欧盟 AI Act Article 14（2026-08 生效）对受监管领域高风险 AI 强制 HITL。判据：**人机介入模型按风险选（环内审批/环上监控/环外审计），不是一律 HITL；不可逆高风险才值得暂停**。提升层：工作流/可复用 Skill。

**5. 人类交互=结构化工具调用（approval/input/escalation 三型）**（来源：James Phoenix 12 Factor Agents Factor 7 2026-09-16 + omnithium 2026-06-01 + IETF HEM draft 2026-07-03 实拉）：把人类接触当结构化工具调用而非 plaintext——三型：approval（批准）/input（收集信息）/escalation（升级）；escalation 特征=agent 已试替代方案/context 含失败原因/可能需要调查/无超时（需解决）；触发=三连错/意外系统状态/缺权限/矛盾需求；HEM 把会话置入正式 PENDING 状态+沿指定链路由结构化升级请求+收到人类决定前禁止所有状态迁移。判据：**人类介入三类结构化（approval/input/escalation）；升级=已尝试替代+失败上下文+无超时等待解决**。提升层：工作流/可复用 Skill。

**6. 超时≠批准（timeout 应=拒绝或升级；审批通知必带上下文）**（来源：omnithium 2026-06-01 + Truto 2026-05-13 实拉）：timeout-equals-approval 反模式=严重治理失败——agent 靠等过审稿人获得批准=不是受治理而是有耐心；decontextualized notifications 反模式（"需要批准"Slack 消息不带上下文）；action proposal 带 full context（做什么+为什么）；审批与执行解耦（state-managed interruption：暂停→完整状态序列化到持久存储→返回控制→批准信号到达从精确检查点恢复——执行从 in-memory call tree 变成 database row）。判据：**审批超时=拒绝或升级，绝不=批准；审批通知必带动作+理由上下文**。提升层：工作流。

**7. 自主度拨盘（Autonomy Dial/渐进授权/摩擦匹配风险）**（来源：Smashing Magazine 2026-02-11 + Mrs Internet 2026-03-16 + FRPROTECH 2026-07-23 实拉）：信任是谱系非二值——低风险任务可自主、高风险要求完全确认；Autonomy Dial=用户设 agent 独立程度（progressive authorization）——内部会议可"自主行动"、给高价值客户发邮件需"完全确认"；gradient of consent=确认量匹配做错成本（低风险可逆自动做、高风险难撤销暂停确认）；over-confirm 让 agent 烦人、under-confirm 让用户不安——calibration 是 agentic UX 最重要决策；setting churn 高=拨盘需重新校准。判据：**自主度按任务风险配置（拨盘式渐进授权）非全局二值；确认频率=做错成本校准线**。提升层：工作流/可复用 Skill。

**8. 四时刻披露（before/during/controls/after 各配真实 UI surface）**（来源：aiuxdesign.guide 2026-04-02 实拉）：agent 半自主/环境式时单次 consent event 不够——披露须在四时刻发生：before（将做什么/将访问什么——命名动作+使用点确认，不在 onboarding 流）/during（正在做什么）/controls（怎么停/改）/after（做了什么+审计）；设计任务=每时刻都有真实 UI surface，不是 buried settings toggle。判据：**自主 agent 披露四时刻（前/中/控制/后）各配 UI surface，非一次性同意；控制面随时可见**。提升层：工具/工作流。

**9. 进度流=步骤卡片栈（状态/输入输出/时序/展开）+渐进披露**（来源：aydesign.ai 2026-05-23 + Claude Agent view 2026-05-11 + Cursor CLI 2026-09-30 + blink.new 2026-05-13 实拉）：step card=agent run 原子单元——status（pending/running/done/failed）+inputs+outputs+timing+expand affordance；step cards 堆成 agent timeline=agent UI 脊柱（无它进度不可读）；Claude Agent view 每行=状态图标（spinner 工作中/yellow 等输入/green 完成/red 失败）+一行动态摘要（Haiku 类模型生成、每 15s 刷新）+最后交互时间；progressive disclosure=surface 摘要、按需钻取详情（别暴露全部 47 个子动作，surface 3 个决策点）；Cursor=working status pinned above prompt（进度/token 数/提示稳定一处）+长 shell 输出从顶部截断（看最新）。判据：**进度 UI=步骤卡片栈（状态+输入输出+时序）+渐进披露（摘要→按需钻取）+稳定状态区；多会话用一行动态摘要+状态色标**。提升层：工具/工作流。

**10. 撤销架构（可逆优先→补偿事务→动作审计+每动作 Undo→跨墙见证幂等键）**（来源：uxatlas.io 2026-03-23 + supik 2026-05-27 + backfield.net 2026-06-09 + Smashing 2026-02-11 + Horizon Labs 2026-09-29 实拉）：recovery=agentic UX 最被低估的承载面——reversibility first-class：drafts 而非已发送邮件/软删而非永久删/沙箱预览而非实时编辑；不可字面撤销（邮件已发/记录被下游消费）→compensating transaction（发更正邮件/取消错订）而非假装 undo；Action Audit log+每动作 prominent Undo=终极安全网；inline diff+undo 为主要 affordance（行/块/会话级）；rollback snapshot 有 perimeter（transfer/send/publish 跨墙不快照）→dedup key+undo ledger 脱离 agent 控制流（witness-issued idempotency key）+human-notified delay；失败降级层级=全 AI→AI 辅助（人监督）→AI 增强（人主导）→传统功能→优雅失败（清晰错误态+替代路径）；Agent 模式容错=阻断转带选项的兜底（支付失败→暂存订单+保留座位+重试/换支付方式）。判据：**撤销架构=可逆优先（草稿/软删/预览）→不可逆补偿事务→动作审计+每动作 Undo→跨墙动作需见证幂等键+人工通知延迟；失败按层级降级且阻断转兜底引导**。提升层：工具/工作流/可复用 Skill。
