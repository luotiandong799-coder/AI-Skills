## 独点（10）

**1. Prompt 是 agent 的整个 policy（版本管理对象=策略不是文本）**（来源：Future AGI prompt management 2026-07-02 + Respan 2026-05-19 实拉）：agent prompt 是 agent 的整个 policy——产生推理步骤+工具调用轨迹；因为质量依赖整条轨迹，好 prompt management 不只是存文本——每个版本绑 evaluators（task completion/instruction adherence/tool-call accuracy）、每个 run 链接到其版本；"Prompt Versioning Without Evals Is Just Diff Tracking"（无评测的版本管理只是 diff 追踪）；标准功能集已收敛=集中 prompt store+分环境标签+完整追踪（LLM 调用/工具使用/输入输出/token/延迟）。判据：**prompt=agent 策略，版本管理=策略版本（每版绑评测器+每 run 链接版本）；没绑评测的版本管理只是 diff 追踪；追踪要全栈（LLM/工具/输入输出/token/延迟）**。提升层：工作流/可复用 Skill。

**2. SemVer for Prompts（MAJOR/MINOR/PATCH 三档 + 版本不可变）**（来源：omnithium 2026-06-01 + CallSphere 2026-09-20 + Microsoft dev lifecycle 2026-08-21 实拉）：prompt 语义化版本——MAJOR=输出格式/行为/接口破坏性变更；MINOR=向后兼容的新能力；PATCH=bug 修复/措辞改进/小澄清；每版本 immutable hash+semver tag（ID）；版本不可变性（Microsoft）——未保存变更只能在 agent playground 测试，要看对话历史/监控性能/跑完整评测必须保存为版本；系统确保所有变更 tracked/testable/comparable across versions。判据：**prompt 版本语义化——MAJOR 破坏行为/输出、MINOR 兼容新能力、PATCH 措辞修复；版本不可变（未保存变更只能在 playground 试，评测/监控必须用保存版本）**。提升层：工作流/工具。

**3. Agent 配置 bundle（manifest 钉组件版本，部署 promote 整包非单件）**（来源：Zylos agent-native CI/CD 2026-05-17 + AWS prompt lifecycle 2026-09-16 实拉）：agent configuration bundle=manifest 文件 checked in git，钉住每个组件（prompt/model/tool 定义/guardrail policy version）到特定版本；部署 promote 一个 bundle 不是单个组件——确保"通过所有 eval gate 的精确配置"到达生产；rollback 一等操作（"rollback support-bot to bundle v42" 原子性同时回滚所有组件）；AWS——每个生产 prompt 有 documented version history/evaluation record/clear owner，prompt 独立于应用代码部署、几分钟内回滚前一版本（防 unnoticed prompt drift）。判据：**部署单位=bundle 不是组件——manifest 钉住 prompt/模型/工具/策略版本，promote 整包；回滚=原子切回 bundle v42；prompt 更新独立于代码分钟级回滚；每生产 prompt 有版本史+评测记录+owner**。提升层：工作流/可复用 Skill。

**4. prompt 变更=deploy（Agent DevOps 铁律）**（来源：agentswarms playbook 2026-05-28 + Daniel Broadhurst 2026-05-01 实拉）：prompt change 是 deploy、model swap 是 deploy、甚至重建 knowledge base 也是 deploy——都按版本化+eval gate+canary+traces+cost budget+一键 rollback 走；跳过任一=没有 DevOps for agents 只是 wish；git workflow for prompts——prompts 存 version control 带 frontmatter metadata（version/model/temperature/author/requires_review），prompt 变更当代码变更：branch→test with evals→require reviews→deploy via CI 到生产 registry；prompt 形状 agent 行为比其他任何 config artifact 都直接（AWS Well-Architected）。判据：**prompt/模型/知识库变更都按 deploy 流程（版本化+评测门+canary+成本预算+回滚）；prompt 进 git 带 frontmatter（版本/模型/温度/作者/需评审），变更走分支+评测+评审+CI 部署**。提升层：工作流/可复用 Skill。

**5. CI eval gate 配对比较（paired per-case delta 判定回归）**（来源：DEV prompt registry 2026-09-17 + Future AGI lifecycle 2026-05-20 实拉）：每个触 prompts 的 PR 跑 golden set 测 groundedness/factuality（hallucination proxy）/latency/utility；核心=candidate vs 当前生产版本**同用例配对 per-case delta**（不是独立跑分），delta 超阈值 fail build（如 groundedness drop>3%）；Future AGI 双触发——Trigger 1=floor 设为过去一个月稳定流量下 rubric 观测范围下界；Trigger 2=paired CI——bootstrap 95% CI on per-case delta vs prior pinned version 完全低于 0（任意 monitored rubric 上即触发）。判据：**评测门=候选 vs 生产同用例配对 delta（非独立跑分）——groundedness 掉 3% 挡合并；paired bootstrap CI 完全低于 0 触发回滚；floor=过去一月观测范围下界**。提升层：工作流/工具。

**6. Champion-Challenger 发布（5% 流量→24-72h 测量→auto-rollback）**（来源：CallSphere 2026-09-20 + DEV prompt registry 2026-09-17 + Future AGI versioning tool 2026-07-08 实拉）：stage=challenger 拿 5% prod 流量、champion 持 95%；measure=主 KPI（tool-call accuracy/CSAT proxy/latency/cost）观察 24-72h；promote 或 rollback——KPI drop>阈值自动回滚；shadow rollout 1-5% 或镜像（无用户影响）；promote 机制=git-like version registry 重指 Production label（passing version promoted by repointing，不重建）。判据：**发布=champion/challenger（challenger 5% 流量→主 KPI 测 24-72h→promote 或 KPI 掉阈值自动回滚）；promote=重指 Production label 不重建；shadow 1-5% 无影响预演**。提升层：工作流。

**7. 可复现世界（pinned world + canonical hash + 盲跑拒绝变更）**（来源：NexBench docs 2026-07-28 + AgentRecall-X spec 2026-08-17 + leantoken measurement 2026-09-14 实拉）：NexBench 每次 run 对完全相同的钉死世界重放（8 条链固定高度：Ethereum block 22,481,930 等）；envPinsDigest=sha256(canonicalJson(environments))；harness 拥有全部熵（确定性）；记录哈希=sha256(canonicalJson(record))——canonicalJson=sorted keys/UTF-8 NFC/LF/无无意义空白（须 pin with unit-test vectors，两实现必须一致）；tree_hash=sha256(sorted record_hashes join "\n")；_rejected.jsonl 排除 hash 但记录行数（capture-rate 必须含 rejects）；leantoken 盲跑——benchmark 拒绝未 commit 的运行时变更（验证 src/manifest.lock 匹配候选 revision），报告记录 harness revision/dirty state/manifest BLAKE3 identity。判据：**可复现=钉死世界（固定链高度/环境）+canonical JSON 哈希（sorted keys/NFC/LF，双实现一致性 pin 测）+盲跑拒未提交变更；rejected 记录排除哈希但计入捕获率**。提升层：工具/工作流。

**8. 评测可比性三决定因素 + executable checks 优先 + 固定层级汇总**（来源：NVIDIA《How to Evaluate AI Agents》2026-09-21 + ResearchGym arXiv 2602.15112 实拉）：benchmark 可比性取决于 task complexity/environment statefulness/verification methodology 三件；executable checks 优先于 reference-based/LLM-as-judge；metrics 固定层级汇总（benchmark→trial→task→turn→step），accuracy/verbosity/cost 轴配对报告（success rate with consistency ranges）；ResearchGym 防污染架构——保留论文仓库的 datasets/eval harness/baseline、withhold 论文提出的方法（agent 必须提出新颖假设，5 容器环境 39 子任务）。判据：**评测可比性=任务复杂度×环境状态性×验证方法；可执行检查优先于参考/LLM 评审；指标按固定层级汇总且精度/冗长/成本配对报告；基准防污染=保留 harness 扣方法**。提升层：工作流/模型。

**9. Binding Drift 锁（多步工具绑定错误级联放大）**（来源：arXiv 2607.18316《Binding Drift in Multi-Step Tool-Augmented Agents》+ NVIDIA 六能力 2026-07-27 实拉）：dependent-chain（D3）模式锁效果 16.6×——baseline 61 wrong actions vs lock 下错误绑定级联成 1011 个（错误账户绑定传播到末步邮件发错人）；distractor-injection 模式同样放大；工具结果 pass by reference（不序列化进 context window）→不需要 context compaction（NOOA SWE-bench Verified 82.2% with GPT-5.5，约一半 token 和 LLM 调用）。判据：**多步工具绑定=依赖链错误级联放大（错误绑定→末步发错人），关键绑定需锁（lock）；工具结果引用传递省上下文（半 token 不需压缩）**。提升层：模型/工具。

**10. Prompt 模板变量注入（参数化评测 + 跨 prompt 依赖校验）**（来源：AWS prescriptive guidance 2026-09-16 + omnithium 2026-06-01 + Zylos 2026-05-17 实拉）：prompt templates with variable injection——减少硬编码重复、提高可维护性、支持参数化评测（context windows 与 entity substitution 可变量化测）；跨 prompt 依赖管理——validate_prompt_dependencies(prompt_version, environment) 追踪跨 prompt 依赖与外部系统版本防不兼容组合；guardrail policy version/tool 定义与 prompt 同 bundle 齐步升（版本要一起管，不能单飞）。判据：**prompt 用模板变量注入（消除硬编码+参数化评测：上下文窗口/实体替换）；跨 prompt 依赖校验防不兼容组合；guardrail/工具/prompt 版本同 bundle 齐步升**。提升层：工具/工作流。
