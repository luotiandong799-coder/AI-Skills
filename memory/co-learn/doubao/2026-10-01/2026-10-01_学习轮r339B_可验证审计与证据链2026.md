## 独点（10）

1. **hash chain 验证规则：prev_hash 必须等于前一条的 hash、genesis prevHash==null、checkpoint 权威绑定 genesis key**（来源：IETF SCITT AI-Agent Receipt）——修改/删除/插入/重排任一记录，持有记录+公钥的验证者即可检测；chain.seq 单调（genesis=0）。判据：**篡改可检测性=链上每环校验，不依赖信任存储方**。提升层：模型。
2. **篡改证据 ≠ 全集完整性：tamper-evidence 是逐 receipt 的保证，不是"没有遗漏"的保证**（来源：arXiv Notarized Agents）——Merkle 根保证改动可检测，但只覆盖被查询的 receipts；遗漏事件与篡改事件是两类缺陷。判据：**链保证防篡改不保证全量捕获，遗漏与篡改要分开审计**。提升层：模型。
3. **接收方见证签名：被调用的服务用自己密钥签回执，加密给 owner，发公开 transparency log**（来源：arXiv Notarized Agents Sello）——owner 在不信任 agent 或 operator 的前提下重建篡改可检测链；四属性：receiver-attested/confidential/transparent/verifiable。判据：**接收方见证签名=逆信任边界，审计不依赖被审计者自证**。提升层：模型。
4. **canonical JSON + 全字段签名：任何字段改动都破签**（来源：traceseal + agenticrail）——Ed25519 签名覆盖所有字段（payload/decision/timestamp/step name）；receipt 含 skill identity/content-addressed manifest/input-output hashes/sandbox profile/operator signature。判据：**签名的覆盖域=全字段，不是摘要**。提升层：工具。
5. **两类可验证明：inclusion proof（O(log n) 验证事件存在）+ consistency proof（验证旧日志是新日志前缀）**（来源：arXiv Right to History）——可导出任意时间范围+ Merkle 证明作为独立可验证审计包。判据：**可验证审计要能导出独立验证包，不依赖原系统**。提升层：工具。
6. **四层密封架构：SHA-256 content hash + RFC 3161 可信时间戳 + 机构签名 + Merkle 结构**（来源：IETF Veridom OMP）——修改任一历史 trace 使后续所有 chain hash 失效；第三方可无需访问机构密钥验证每次决策的问责性。判据：**时间权威+签名+哈希三层密封，第三方独立可验**。提升层：工具。
7. **逐范围 attestation 而非逐行：session/多步 plan/工具序列整体签名**（来源：ai-identity.co）——HMAC-SHA256 链 + range attestation；篡改任何一行从该点起链断。判据：**证明单位=执行范围而非单条记录，降低验证成本**。提升层：工作流。
8. **chain tips 锚定 WORM：内部哈希可重算，外部不可重写**（来源：agnys + scien.cx）——S3 Object Lock（WORM）周期锚定链尖，即使重算全部内部哈希也无法匹配外部摘要；PostgreSQL 两哈希字段实现（row_hash=canonical fields+prev_hash）。判据：**防篡改=哈希链+外部 WORM 锚点双保险，WORM 防"全部重算"**。提升层：工具。
9. **证据链与执行引擎绑定：Evidence 只证"记录了什么、记录未被改"，不证"动作正确/合法"**（来源：IETF SCITT AI-Agent Execution）——Evidence Chain=有序 hash-chained AgentInteractionRecord；证明完整性/来源/时序，不是是非判断。判据：**证据链的价值是完整性与时序，正确性判断在验证者**。提升层：模型。
10. **双边界捕获：reasoning step 在模型提供方边界捕获、tool invocation 在执行边界捕获，链绑定 metadata**（来源：IETF NHE Reasoning-Audit Log）——alteration/omission/reordering 均可被独立验证者检测；content-optional（内容可选，只链元数据 model/provider/subject identity）。判据：**捕获点在边界（模型入口/工具出口），元数据入链、内容可选**。提升层：工作流。
