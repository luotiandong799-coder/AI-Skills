## 独点（10）

**1. Dual-LLM 隔离落地（quarantined reader 无工具 + privileged orchestrator 持权）**（来源：OpenClaw privilege separation arXiv 2603.13424 + agent-works 2026-06-09 + AuthGraph arXiv 2605.26497 实拉）：Agent 1（隔离模型）读不可信内容（邮件/网页/搜索结果）——不能调工具、不能改计划，只返回 schema 校验的结构化提取（字段/摘要/yes-no）给编排者；Agent 2（特权编排者）决定调哪些工具、持有用户真实权限，不读原始不可信内容；tool isolation 是硬约束（无论注入内容隔离侧不能动作，模型能力改变不覆盖此约束）；AuthGraph 双图对齐——injected reasoning graph（真实执行轨迹含可能被操纵归因）vs authorization graph（隔离干净上下文从用户意图导出，信息论上不可能被注入影响），图对齐检查器检测工具级+参数源级偏差。判据：**读不可信内容的模型无工具权限（注入路径物理断裂）——隔离侧只回 schema 校验的结构化结果，特权侧持权决策；授权意图从隔离干净上下文导出不受注入影响**。提升层：工作流。

**2. 工具调用运行时验证七维 + candidate act 状态机（CCS/DAS）**（来源：IETF CCS draft-correctover 2026-09-14 + IETF DAS draft-das 2026-09-29 实拉）：CCS 七维运行时验证——Structure/Schema/Latency/Cost/Identity/Integrity/Security；receipt 格式带 Ed25519 签名；三判词 allow/deny/escalate；四 executor 生命周期态；DAS candidate act 状态机——non-effective/under-validation/escalated/capability-issued/effectuated/denied/quarantined，流程 validate→commit validation evidence→release scoped finality authority→FinalitySink verify+consume。判据：**工具调用过运行时验证七维（结构/模式/延迟/成本/身份/完整性/安全）+ 签名 receipt；高危行为走候选状态机（验证→留证据→发 scoped 终局权→核验消费）**。提升层：工具。

**3. pre-action 授权 hook + 确定性门（框架层实现，不在模型层）**（来源：arXiv 2603.20953 + IETF Asimov 2026-07-24 + AWS control framework 2026-07-30 + Microsoft AGT 2026-04-22 实拉）：blocking hook 在每次工具调用前触发、工具不执行直到策略决定返回（Cursor/Claude Code sync、LangChain/CrewAI async）；hook 在框架/平台层实现不在模型输出解析——注入说服模型请求危险工具也没用；Asimov 双门——Gate 1 确定性 pattern denylist + Gate 2 stateless context-free LLM judge，四层优先级（"单个 LLM 不会可靠自监管"）；AWS——能表达成规则就用确定性缓解（linters/SAST/secrets detection/policy-as-code 定义安全不变量）；AGT 治理层管 agent actions 不是 model outputs（definition scanning→policy evaluation→response inspection）。判据：**安全门在框架层不在模型层——工具调用前阻塞 hook 等策略；确定性 denylist 先行 LLM judge 兜底；能成规则不用 LLM（linter/SAST/secrets 先行）**。提升层：工作流/工具。

**4. 输入预处理（Unicode Tags/零宽/同形字）+ typed envelopes（数据即数据）**（来源：aitoolsguidebook 2026-05-25 + navi-sanitize 2026-05-20 + prompt-canon 2026-09-30 + rapidclaw 2026-04-20 + enison 2026-06-03 实拉）：Unicode Tags block（U+E0000–U+E007F 每个 ASCII 字母映射一个 tag 字符，渲染不可见但到达 tokenizer）+HTML comment 载体；零宽字符（U+200B/U+200C/U+200D/U+2060/U+FEFF）+Bidi override+Zalgo+同形字；规则——自然语言中间出现零宽（非文件开头/emoji 序列/CJK）标可疑、3+ 连续零宽=几乎肯定编码 payload、U+FEFF 仅文件开头合法、输入混 3+ scripts 额外验证（Lao/Thai 相似调整阈值）；canonicalize before guard——strip invisible→map cross-script homoglyphs to ASCII skeleton→locale-independent case fold（守卫/分类器看到一种规范形）；typed envelopes——工具结果/RAG chunks/抓取 URL/文件内容包进明确分隔类型信封，模型只当数据；Unicode normalization NFC/NFD 统一。判据：**输入侧先净化再守卫——剥离零宽/Unicode Tags/Bidi/同形字、统一 Unicode 归一化、3+ scripts 混用额外验证；不可信内容一律 typed envelope 标注"数据非指令"**。提升层：工具/工作流。

**5. 记忆投毒纵深（provenance tagging + staging write + 回滚）**（来源：BeyondScale 2026-04-25 + SMSR arXiv 2606.12703 + Vectorize OWASP ASI06 2026-06-12 实拉）：写入时打 source/author/trust classification 标签；最小权限记忆访问（任务不需要时 agent 无长期记忆写权）；写走 staging buffer 验证再入 live store；影响未来会话行为的修改要人批；SMSR——HMAC-SHA256 写入时签名（对 unsigned 注入的密码学硬边界）+ query 时 randomized memory ablation+verdict-based majority aggregator（限制认证敌手影响）；skill creation 通道无内容检查是结构漏洞（agent 合成交互成 procedural skill 直接提交无过滤审批，procedural memory 直接控制未来执行）——必须过滤+审批；行为异常检测（agent 开始维护它不该学到的信念=投毒成功信号）+forensic snapshots+rollback 恢复 known-good。判据：**记忆投毒四防——写时打来源/信任标签、写走 staging 验证、procedural/skill 写入必须内容检查+审批、快照可回滚 known-good；行为异常（捍卫不该学到的信念）作投毒信号**。提升层：工具/工作流。

**6. Trojan Hippo 防御权衡（匹配任务分布，无免费午餐）**（来源：AgentPatterns Trojan Hippo 2026-05-27 + Christian Schneider 2026-02-26 实拉）：dormant memory payloads 由敏感话题触发；Gemini memory attack——延迟工具调用绕过运行时 guardrail（触发词 yes/sure 几乎每对话出现）；防御对比——user-prompt-only writes（ASR 0-5%，代价=失去 assistant 输出/工具返回的记忆）/no-untrusted-write（0-5%，不可信会话不累积）/80-char 记忆长度上限（15-30% 残差，payload 放得下）/provable IFC 污点标签（0% 但阻塞合法 send_email，harmonic utility≈0）；最强防御消除攻击也消除激励记忆的用例——"防御必须匹配任务分布，没有免费修复"。判据：**记忆投毒无免费午餐——最强防御（IFC）会杀掉合法功能；按任务分布选：不可信会话禁写记忆、记忆条目短标题化降 payload 空间、信任标签按源过滤**。提升层：模型/工作流。

**7. 输出侧泄漏检测（differential PII + 生成时风险三区）**（来源：Future AGI 2026-05-20 + Prism arXiv 2605.10614 + Elsa guardrails 2026-08-17 + OpenLegion 2026-07-01 实拉）：differential PII scan——每个响应过 data_privacy_compliance adapter（RailType.OUTPUT），承重检查=输出含输入/检索上下文都没有的 PII 实体→模型从训练或先前轮次产出（拦）；Prism 生成时检测——逐解码步 16 信号（lexical/structural/information-theoretic/behavioral/contextual）校准风险分，绿/黄/红三区逐 token 干预；关键观测=凭据复现前常有可测的生成动力学转变（entropy collapse+logprob 上升）；数据外泄三探测器（secrets/bulk sensitive data/abnormal output patterns）warn mask 敏感 span/block 停响应；审计——log 原始（sanitize 前）工具响应+sanitized 版 diff，索引 task_id/iteration，位置=工具执行与 context append 之间。判据：**输出侧三防——差分 PII（输出中不在输入/检索的实体=模型产出要拦）、生成时逐 token 风险分（entropy collapse 预警凭据外泄）、原始 vs 净化 diff 审计（raw 留档 sanitized 交付）**。提升层：工具/工作流。

**8. MCP 供应链与工具投毒（description/schema/响应三变体 + 参数净化）**（来源：General Analysis 2026-05-02 + CSA 2026-07 + Microsoft AGT 2026-04-22 + SHIELDMCP ACL 2026 + ShieldNet arXiv 2604.04426 + OWASP MCP Top10 2026-03-15 实拉）：tool poisoning 三类——tool description poisoning（隐藏指令在描述里）/rug-pull attacks/tool shadowing（同名拦截）；共同结构因=MCP clients 从 servers 继承信任且无连续验证；无原生 MCP 机制检测注入；防御——schema scanning/output classification/破坏性动作不自动跑（approval flow）；SHIELDMCP 出站参数净化——对声明 schema 做 type/range 校验+扫描字符串参数中的 SQL 注入片段/shell 命令注入模式/指向链中其他 LLM 的 prompt 注入 payload；ShieldNet 网络级——MITM proxy+event extractor 观测真实网络交互检测供应链攻击（F-1 0.995/0.8% FP）；MCP STDIO 接口 RCE 缺陷（命令执行无论进程是否成功，7000+ 服务器受影响）；代理治理层（AGT definition scanning→policy→response inspection）。判据：**MCP 工具面四防——工具描述/schema 装前扫描、出站参数净化（防 SQL/命令/注入链）、破坏性动作必须审批流、网络层观测交互防 typosquat；clients 不无条件继承 server 信任**。提升层：工具/工作流。

**9. AgentDojo 指标体系（BU/UuA/ASR）+ 自适应攻击暴露浅层防御**（来源：AgentDojo arXiv 2406.13352 + AutoDojo arXiv 2606.15057 + GPT-Red 2026-07-15 + arXiv 2606.26479 实拉）：指标四件——BU（benign success rate）/UuA（utility under attack）/ASR（injected goal 执行率）/Safety=1-ASR；动态有状态环境四域（Workspace/Banking/Travel/Slack）97 现实任务，US AISI+UK AISI 联合红队扩展；AutoDojo——黑盒自适应攻击用 frontier LLM 迭代优化注入把 ASR 抬到静态注入测不出水平（"许多防御只有有限保护"）；GPT-Red 自动化红队 84% vs 人类 13% 攻击成功率；带外防御（CaMeL/FIDES/Progent/RTBAS/FORGE）capabilities+信息流标签+reference monitor 在 AgentDojo 近消除攻击——组织为经典 Biba integrity/reference monitoring/least privilege 实例。判据：**agent 安全评测四指标（BU/UuA/ASR/Safety）——只测静态注入高估防御，必须自适应攻击红队；防得住靠带外确定性监控（reference monitor/信息流标签）不是拒答训练**。提升层：模型/工作流。

**10. guardrail 五层拓扑（input/context/pre-tool/tool-response/output）+ 便宜检查先行**（来源：Kalvium 2026-04-12 + Future AGI 2026-05-21 + allexcloudstar 2026-05-05 + OpenLegion 2026-07-01 + Exemplar 2026-10-01 实拉）：system prompts 不是 guardrails（建议，大多数时间遵守关键时刻忽略）；五层拓扑——input guardrail（user message）/context guardrail（retrieved chunks）/pre-tool guardrail/tool response guardrail/output guardrail；cheap checks 先跑——schema validation/length checks/forbidden-phrase regex/PII scanners/URL validation/JSON parse（确定性毫秒级抓大多数明显失败，malformed JSON 要 parser 不要 LLM）；architectural containment 是最少人做的层（限制模型能做什么比过滤更根本）；structural guardrails 在 LLM context 外执行（regex 过滤器在 Python 跑，不请 LLM 检查注入——模型 context 内的内容影响不到 enforcement）；Prompt Builder 强制 XML wrappers+RAG Context Firewall 评估过滤+Policy Engine 工具权限+PII redaction。判据：**guardrail 五层缺一不可（输入/上下文/工具前/工具响应/输出）——便宜确定性检查先跑（JSON 解析器/PII 正则/长度）；结构性护栏在模型上下文外执行；限制模型能力比过滤更根本**。提升层：工作流/可复用 Skill。
