## 独点（10）

1. **结构化输出四层栈：schema design → provider enforcement → constrained decoding → validation loops，四层都要**（来源：dev aifrontierpost + ai-tldr）——不可只靠 prompt 要求。判据：**生产级结构化输出=四层栈；prompt 设意图、约束强结构、监控抓失败**。提升层：工作流。
2. **Validation-Retry 三环：generate → validate → retry；重试时把错误消息显式喂回 prompt；valid JSON 但违反 schema（缺必填/类型错）要显式列出 schema violation 而非泛化 parse error——两类失败不同重试策略**（来源：codemia + oneplaceforai + techearl）——区分语法失败与语义失败。判据：**校验失败重试时附具体错误（parse error 或 schema violation 分开对待）；max 2-3 次**。提升层：工作流。
3. **schema 即指令：每个字段写 description（模型把 description 当指令不只当文档）；schema_description 参数引导抽取；保持扁平（4+ 层深嵌套增加模型丢失目标对象概率）**（来源：nisai + lobehub）——schema 不只是约束还是提示面。判据：**schema 字段全带 description；避免 4+ 层嵌套；描述里写清格式要求（如 ISO 8601）**。提升层：工具。
4. **constrained decoding 是采样层保证：JSON Schema 编译成 FSM，非法 token 对数概率设负无穷——模型物理上无法产出畸形输出（OpenAI GPT-5/Gemini 2.5 可用；Claude 不支持→prompt+schema+retry 可移植方案）**（来源：ai-tldr + channel.tel + dev devshakib）——采样层 vs prompt 层。判据：**能用服务端约束就用（native structured output）；Claude 类不支持时用 schema+Zod+retry 方案**。提升层：工具。
5. **截断处理：max_tokens 截断可产生合法前缀非完整结构；流式连接断 StreamInterruptedError 同理——绝不把部分工具参数喂给工具执行；显式捕获 stop_reason=max_tokens 与流中断**（来源：zylos + csdn）——结构保证不防截断。判据：**结构化输出管线显式处理截断/流中断；部分对象不进工具执行**。提升层：工具。
6. **跨 provider 类型强制差异：Gemini 常把 integer 返回为 1.0（过 JSON.parse 但失败严格 schema）；用 lenient validator+声明式模型校验（Pydantic field_validator/model_validator）**（来源：aijsonmedic + precisionai）——provider 间行为差异。判据：**结构化输出校验按 provider 行为适配（Gemini 用 lenient 数值校验）；业务规则校验用声明式 validator**。提升层：工具。
7. **提示面工程：few-shot 2-5 例优于 zero-shot（展示期望 I/O 格式比自然语言描述可靠）；语义标签五域分域（task/context/examples/output_format/constraints）；system prompt 是版本化代码不是设置（存仓库）**（来源：vucense + ai-pedias + futureagi）——示例、分域与版本化。判据：**域特定任务给 2-5 个 I/O 示例；复杂 prompt 用语义标签分五域；prompt 模板入版本库**。提升层：工作流。
8. **CoT 治理：前沿模型内部默认做 CoT（Claude Opus 4.7/GPT-5/o4），外部不必显式要"let's think step by step"；显式 CoT 按任务难度选择性启用（多跳推理/数学/规划才用，加延迟与成本不作为默认）**（来源：ai-pedias + hustletoai）——模型层 CoT 策略。判据：**按模型代际选择是否显式 CoT；简单任务不显式要求推理链**。提升层：模型。
9. **reasoning_effort 调档联动动态安全条款（IBM 2026）：高 effort prompt 自动触发 self-audit；reasoning effort tuning 成新领域**（来源：dev vijay）——推理成本与审查联动。判据：**reasoning_effort 按任务难度调档；高 effort 档自动附加自审计条款**。提升层：模型。
10. **工具 schema 是声明面：tool_use+JSON schema 声明函数（名称/描述/参数形状）；模型把参数描述当指令——工具描述本身是提示面（与安全注入邻接：描述可被注入利用）**（来源：futureagi）——工具 schema 双角色。判据：**工具参数写清类型/枚举/描述；工具描述内容视为会被模型当指令执行的文本来审**。提升层：工具。
