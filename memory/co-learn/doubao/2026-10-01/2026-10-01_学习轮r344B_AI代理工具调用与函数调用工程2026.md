## 独点（10）

1. **工具描述工程三问（做什么/何时用/不用什么）——description 是每次请求都发送的提示文本，不是文档；单责任一句 + 1-2 具体示例 + 模糊时澄清"它不用于什么"；避免 vague 语言（utility/helper）**（来源：explainx + theneuralbase description engineering + aiworkflowlab + zylos description engineering）——描述工程。判据：**描述三问写全：动作资源/触发条件/明确排除的混淆场景；"Retrieves the current USD-to-EUR exchange rate" 胜过 "Gets currency info"**。提升层：工作流。
2. **Schema 收紧：required 全标 + enum 约束有限集 + pattern/maxLength/min/max 参数边界 + additionalProperties:false——必填字段留在 optional 是调用错误第一主因；枚举在 schema 层强制则模型不会幻觉第三个选项**（来源：ai-tldr + stackviv + mudassirkhan + max-gherman + compelframework）——schema 工程。判据：**类型不模糊、有限集必枚举、required 逐字段标、additionalProperties 关掉**。提升层：工具。
3. **工具命名 verb_noun snake_case ≤64 字符；读写分离（query_database vs update_database）——工具名是模型选择的第一信号；冗余工具=混淆面，说不清"一句话为什么选 A 不选 B"就不能上线**（来源：ai-tldr + zylos + machinelearningmastery）——工具命名。判据：**动词开头命名；读写分拆工具消歧并缩小 schema 表面积；工具边界可一句话说清**。提升层：工具。
4. **模型自纠错模式：参数校验失败把错误返回给模型作为工具响应——实证 80% 情况下模型第二次尝试自行修正参数错误**（来源：dev.to aiwave）——自纠错循环。判据：**校验失败不终结会话，错误作为工具结果回喂模型让其自纠；与"可疑结果打标交还模型"分工：那条管结果断言，本条管参数校验**。提升层：模型。
5. **verify-before-retry 包装器：不确定的工具结果先查后置条件是否已满足再决定重试——非原子失败（工具调用成功但工作流失败）下避免重复副作用；重试/投机执行/并发下同一逻辑动作可能发生两次**（来源：arxiv 2608.02645 + arxiv 2609.15397）——重试前置验证。判据：**重试前先验证后置条件：动作已成功则免重试，未成功才带更佳证据重试**。提升层：模型。
6. **幂等键工程：每个可变状态工具必带 idempotency key（按意图唯一、跨重试与重启稳定）；durable-execution 运行时仍需它——它们只去重步骤结果，无法去重 checkpoint 前已落地的外部副作用；工具缺键时适配器派生稳定键；exactly-once 是神话，at-least-once+幂等消费是基线（0.5% 重复率×2 万日动作=100 个重复副作用）**（来源：dzone + tianpan + arxiv 2602.14849 Atomix + agentnative + cordum）——幂等键。判据：**幂等键=意图唯一非尝试唯一；外部副作用先于 checkpoint 落地的重复无法靠运行时去重**。提升层：工具。
7. **并行工具调用纪律：一次性执行响应中全部 tool_use 块（asyncio.gather/Promise.all）+ 结果合并成单条有序消息返回；parallel_tool_calls=false 用于协调挑战场景——丢弃模型同时返回的其余调用=扔掉模型最优直觉+强加额外往返**（来源：chiraghasija + aiworkflowlab + loooop）——并行调用。判据：**模型返回多块工具调用时全量并行执行；协调困难才关并行**。提升层：工作流。
8. **工具循环守卫：per-session max_tool_calls（10 次覆盖 99% 合法用例）+ per-turn 预算（loop guard 防几何增长）+ per-tool 预算（input sanitizer，search_docs 可回 50KB）+ 终止条件写进 system prompt（"同一动作尝试三次失败即停止"）——AWS 实测 177-span 循环根因是无终止条件的 never-give-up 提示**（来源：llmversus + 72technologies + aws + mudassirkhan）——循环守卫。判据：**计数器+双层预算+显式终止条件三件套；与"stop_reason 检查"分工：那条管每轮检查，本条管会话级封顶**。提升层：工作流。
9. **工具路由分层：registry 为源 + embedding 路由层（50+ 工具按查询选子集，stateless 快速先于主模型）+ 执行层（校验/并行/收集）；"笨"路由层（关键词/域分类）常胜过"聪明"模型在全部工具中选择——语义工具选择 top-K 注入；HGMF 两级 GMM 过滤（server 级聚类→tool 级）**（来源：zylos + vllm semantic router + theneuralbase too-many-tools + arxiv 2508.07602 HGMF + 阿里云工具精炼）——工具路由。判据：**50+ 工具必加路由层；Top-K 高于相似度阈值才注入；约束系统快过无约束**。提升层：工具。
10. **MCP 安全护栏：OAuth 2.1+PKCE 强制（远程 HTTP server 无例外）+ per-server/per-tool 最小权限 + 工具描述人工审阅（mcp-scan 检测 poisoned tools）+ 进程级隔离（bubblewrap 沙箱）+ 版本 pinning（自动更新可注入恶意代码）+ 网络出口代理（MCP gateway/egress proxy 是最高杠杆控制）**（来源：OWASP MCP cheat sheet + akto + zylos MCP security + generalanalysis + aicw playbook + truefoundry）——MCP 安全。判据：**装 server 前查四件套：权限范围/工具描述逐条读/版本钉死/传输隔离；远程 server 强制 OAuth 2.1**。提升层：工具。
