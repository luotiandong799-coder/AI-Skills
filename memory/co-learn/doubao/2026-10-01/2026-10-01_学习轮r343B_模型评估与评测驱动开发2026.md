## 独点（10）

1. **judge 校准五步（部署前必做）：100-200 例人类标注（<100 置信区间淹没信号）→ 同 rubric 同尺度 → judge 跑同批 → 算 Cohen's kappa（非 raw accuracy——纠正瞎猜正确率）/MAE/exact match → kappa≥0.6 才可信；更验证 judge 与人偏好相关 Spearman ρ>0.7 可接受、>0.85 好**（来源：aiworkflowlab + qaskills + iamulya + futureagi）——judge 校准。判据：**LLM-as-judge 规模使用前必须过人工校准门（kappa≥0.6）**。提升层：工作流。
2. **judge 四偏与对策：self-preference（judge 给自己模型族高分——用更强/不同模型判）；position bias（输入顺序随机化）；verbosity bias（显式 rubric 数字刻度+worked examples）；format bias（2026 量化 judge 偏好 markdown 标题/项目符号/代码块——输出格式化会影响分数）**（来源：futureagi + chatbench + kraghavan）——judge 偏差。判据：**judge 用不同模型族+顺序随机化+rubric 带示例；警惕格式偏好污染评分**。提升层：工具。
3. **judge 两隐藏失效：奖励自信权威语气（"definitely X" 高于 "likely X though Y" 即使后者更准——rubric 显式奖励适当对冲可缓解）；rubric-hacking/instruction leakage（评分标准可见时系统优化输出匹配标准——rubric 不进 judge 上下文或脱敏）**（来源：arxiv 2601.22025）——judge 失效模式。判据：**rubric 含对冲奖励条款；评分标准对被测系统不可见**。提升层：工作流。
4. **judge 强制 CoT：judge 先生成推理 trace 再打分显著提升准确与可信；hybrid 最佳——自动化 judge 管规模与回归、人管校准与边界 case**（来源：chatbench）——judge 结构。判据：**judge prompt 要求先推理后打分；校准与边界 case 走人**。提升层：模型。
5. **golden set 从 traces 起：生产/类生产 traces 含真实用户意图/失败模式/工具调用/检索上下文——全系统测试原料；synthetic 只补缺口不当基础；MVES 分级（通用/RAG/agentic 三套组件）、版本控制 golden set 常 50-200 例**（来源：langchain + arxiv 2601.22025）——数据集构建。判据：**golden set 首选生产 traces；synthetic 仅补缺口；数据集进版本控制**。提升层：工作流。
6. **eval 集四段混合：happy path 60%（常见查询）+edge 20%（长/短/怪字符/多语）+adversarial 10%（注入/离题/应拒）+regression 10%（每个修过的 bug 记为 case——用户报告修完即捕获）；200-500 真实查询按意图聚类（分类/提取/总结/生成/拒绝）比例采样**（来源：techearl + zalt + galileo）——评测集构成。判据：**eval 集按 60/20/10/10 混合；回归 case 从修复事件持续追加**。提升层：工作流。
7. **分层评估成本治理（tiered evals）：快便宜子集每 PR（<30 秒、<50 例）、全套 nightly/merge main、deep eval 每周；成本量级——pairwise judge 800 例 GPT-4o≈$4-8/实验、20 实验/周≈$500/月、5k 例 multi-judge≈$5k/月——按 PR/nightly/weekly 分派评估器**（来源：ailearningguides + callsphere）——评估成本。判据：**评估分三层（PR 子集/全套/deep）；成本按层预算，不在每 PR 跑全套**。提升层：工作流。
8. **agent 评估三层面：Layer 1 Tool Usage（工具选择参数>95% 阈值）、Layer 2 Reasoning（逻辑决策>85%）、Layer 3 Output Quality（helpfulness/accuracy>90%）；三层全过才部署；trajectory scoring 打路径非仅终答（工具选择/参数质量/步效率）；safety gating 部署前抓禁用工具/策略违规/数据边界**（来源：aws + pypi agent-eval-forge + microsoft learn 85% task adherence）——agent 评测。判据：**agent 按工具/推理/输出三层分层评估+分层阈值；路径与安全也评**。提升层：工作流。
9. **contamination 抗性三策：优先私有/新构建任务（公开 benchmark 任务/答案/近变体可能进训练数据或 agent 可浏览找到→性能反映记忆非能力）；真实 commit/CVE/业务场景改写为角色扮演自然语言请求（题面 web 搜不到，searchable-prompt 路径从构建时关死）；测试模型能复述任务细节前不认可得分；broken problems（任务意外不可解）检测**（来源：openai + arxiv 2607.20911）——评测集防污染。判据：**评测优先私有/改写任务；防搜索可复现题面；检查任务可解性**。提升层：工作流。
10. **技能级 eval 五类 case family：Collision（重叠技能归属）、Ambiguous（澄清与弃权——"handle outreach" 不指明 draft 还是 send）、Adversarial（越权保护——不可信内容让技能忽略审批规则）、Stateful failure（重试与幂等——写成功但工具超时）、Version mismatch（陈旧指令——引用 API/仓库布局已变）**（来源：iwoszapar）——技能评测。判据：**技能评测覆盖五类 case；每类一票否决式回归**。提升层：可复用 Skill。
