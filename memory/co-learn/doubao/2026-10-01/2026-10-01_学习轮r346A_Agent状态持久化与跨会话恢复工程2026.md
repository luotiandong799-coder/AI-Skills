## 独点（10）

1. **Durable execution 三支柱：checkpoint 自然边界 + idempotent 步骤 + 持久游标（thread_id）——无 checkpoint 的工作流任何时刻失败都付全量重启动成本；LLM 响应/工具结果/控制流决策每个 super-step 写 checkpoint 到持久层（PostgreSQL 默认），thread_id 作持久游标；worker 崩溃从最后 checkpoint 恢复，已完成的 LLM 调用不重复（省 token 与墙钟）**（来源：AWS wellarchitected AGENTREL03-BP03 + LangChain runtime 后台 + Microsoft durable-task）——恢复三支柱。判据：**恢复只从最后完成点而非开头；每步幂等（同输入同结果）；thread_id 键控持久层**。提升层：工作流。
2. **两条恢复路径：确定性重放（Temporal/Inngest：state=输入+副作用日志，重放从 line 1 重执行工作流代码但命中已记录副作用的步骤直接返回日志结果、微秒快进）+ checkpoint 快照（LangGraph Cloud：周期序列化 plan/工作记忆/部分输出/待处理工具调用，重启恢复）；两种都要求把确定性幂等键传给不可逆调用**（来源：agentpatternscatalog resumption + dev.to Temporal 对比）——恢复路径。判据：**选确定性重放则副作用必须有日志且可跳过；选快照则定期序列化 agent 状态；都要求幂等键传不可逆调用**。提升层：工作流。
3. **Resume Contract 六属性（机器可检查）：prefix continuation/effect exactly-once/fork determinism/checkpoint validity/consume-once/recovery determinism + fork-intent 协议义务 + liveness 义务——5 个主流框架行为违反其声明片段；TLA+ 模型穷举检查**（来源：arXiv 2608.03836）——恢复契约。判据：**持久层语义要能机器检查不能只信文档；检查六属性+fork 意图+活性义务**。提升层：工具。
4. **HITL 跨刷新恢复：frozen cognitive state 七元组 F=(循环计数,待批动作,完整认知输出含推理轨迹与置信度,记忆快照含事实与来源,证据缓存,执行上下文含任务与累积约束,当前策略状态)——暂停时冻结的不只是消息历史而是完整认知状态；恢复三分支 proceed/modify-then-proceed/cancel 从精确暂停点**（来源：TechRxiv + anhtu HITL 四件套）——认知冻结。判据：**暂停时冻结推理轨迹+证据+策略状态；恢复三分支从精确暂停点**。提升层：模型。
5. **中断必须 durable：同步 HITL 在 HTTP 超时/进程重启/token 过期下断裂（人可能几小时甚至几天审批，云 LB 数秒断连）；状态化中断=持久 agent 状态到 durable 存储、释放计算、审批信号到达才恢复；LangGraph interrupt() 是协程暂停点，冻结上下文持久化到 Checkpointer（生产=数据库），resume 用 Command(resume=value)**（来源：Truto + BestHub + LangChain interrupts）——状态化中断。判据：**审批等待不是进程等待——状态化中断持久化+释放计算；恢复靠信号驱动**。提升层：工作流。
6. **语义回滚攻击 ACRFence：LLM agent 恢复后必然产生不同的工具调用（静默绕过基于标识符的重复检测）；轻量 analyzer LLM 在工具边界做语义比较，在每个不可逆工具调用处强制 replay-vs-fork 语义——durable 引擎假设确定性调用者，对 LLM 不成立**（来源：arXiv 2603.20625）——语义回滚。判据：**工具边界做语义比较而非标识符比较；不可逆调用处强制 replay-vs-fork**。提升层：工具。
7. **四种恢复策略分级：naive rerun（无状态，正确但非幂等副作用不安全除非有围栏）/framework checkpoints（持久化响应快照，从 checkpoint 输出后继续）/upstream-owned resume（从框架 checkpoint 或数据库重建）/watermark overlay（小元数据水印，结合任意策略防上游无法去重的副作用重复）**（来源：Microsoft Foundry recover-long-running-work）——恢复分级。判据：**按副作用可去重程度选级；watermark 兜底防重复**。提升层：工作流。
8. **at-least-once 与 exactly-once 的真相：引擎只保证至少一次（Two Generals 问题——任何确认都可能丢失）；exactly-once = dedup 标识符 + 幂等设计 + 原子确认的组合；Temporal 文档明说 activities 至少一次，"实际只跑一次"是调用方通过幂等做出来的**（来源：dreaming.press + dataopsschool + durable-workflow.com）——执行保证。判据：**不要相信"引擎保证只执行一次"；每个副作用自己幂等+dedup id；committed durable facts 对同一 durable id 不重复**。提升层：模型。
9. **沙箱级 checkpoint/restore：CRAB 语义感知 C/R（shell 密集与代码修复负载恢复正确性 8%→100%，checkpoint 流量降 87%，距无故障执行 1.9%）；DeltaBox DeltaState 把文件系统+进程内存当事务变更对，毫秒级回滚；适用=故障恢复/抢占式 spot 实例/RL**（来源：arXiv 2604.28138 + arXiv 2605.22781）——沙箱 C/R。判据：**需要环境状态恢复时走 OS 级 C/R 而非对话级快照**。提升层：工具。
10. **恢复安全五故障模式：内部状态覆盖不完整/checkpoint 状态不一致/外部状态失配/无界非确定性重放/未记录外部效应——正当恢复的 checkpoint 也会使安全相关决策失效（不需要 checkpoint 损坏或恢复机制被攻破）**（来源：arXiv 2608.29381）——恢复安全。判据：**恢复前检查五模式；安全相关决策不得仅靠恢复状态支撑**。提升层：模型。
