## 独点（10）

**1. 429 重试三纪律（Retry-After 优先·jitter 打破同步·限次限时）**（来源：Microsoft Azure quota 2026-05-27 + AI Workflow Lab 2026-07-29 + AI/TLDR 2026-06-12 + tokenpapa 2026-06-29 实拉）：429 响应先读 retry-after-ms/retry-after 头（服务器自己的建议）否则 exponential backoff with random jitter；1000 个 agent 同一毫秒失败+每个等恰好 1s→1000 个同一毫秒重试再击垮 API（thundering herd 锁步）——jitter 打破同步；限制最大重试次数（5-10）与总重试时间。判据：**429 重试=Retry-After 头优先→指数退避+随机抖动→限次数（5-10）限总时长；防 thundering herd 锁步重试**。提升层：工具/工作流。

**2. 指数退避参数模板（full jitter / ±25% / 封顶 60-120s）**（来源：DEV promptra 2026-06-29 + AI Learning Hub 2026-03-11 + tokenpapa 2026-06-29 实拉）：两种实现——full jitter（从指数增长窗口随机抽等待时间：0.5-1s/1-2s/2-4s/4-8s/8-16s 不超 60s）或 ±25% jitter（delay=min(base*2^attempt, max_delay)，jitter=delay*0.25*rand(-1,1)）；base=2^attempt，jitter=random(0, min(base,60))，cap 120s；stop_after_attempt(5)=5 次含首次即 4 retry；只对临时错误重试（retry_if_exception_type）。判据：**退避参数=指数基 2^attempt+随机抖动（full jitter 或 ±25%）+封顶（60-120s）+限尝试次数；首次失败后短暂随机延迟再加倍**。提升层：工具。

**3. OS 调度五原语（HiveMind 透明代理）**（来源：arXiv 2604.17111 HiveMind 2026-09-16 实拉）：并发 LLM agent 负载应用 OS 调度原理五原语——admission control via condition variables（准入控制）/provider-aware rate-limit tracking（provider 感知限流跟踪）/AIMD backpressure with circuit breaking（AIMD 背压+熔断）/per-agent token budgets（每 agent token 预算）/priority queuing with dependency DAGs（依赖 DAG 优先级队列）；组合消除并行 agent 执行失败模式；透明代理架构零改动现有 agent=drop-in 改进。判据：**并发 agent 调度=准入控制+provider 感知限流跟踪+AIMD 背压熔断+每 agent token 预算+依赖 DAG 优先级队列；透明代理零改动集成**。提升层：工具/工作流。

**4. 有界队列背压（admission window 是刻意容量决策）**（来源：A2A backpressure 2026-07-12 + Zylos 2026-02-25 + arXiv AiFlow 2608.00558 2026-09-16 实拉）：consumer 边缘有界队列（admission window）——每个到达任务决定是否有房间；bounded queue 的边界是刻意容量决策不是内存意外；消息队列背压=消费者拉动（consumer-controlled polling，有容量才拉）而非 broker 推送；inFlight/maxConcurrency 并发控制；输入队列声明容量 q_n、至多 k worker 并发、|Q_n|=q_n 时背压向上游传播、ordering buffer 恢复顺序。判据：**背压=有界队列+消费者拉动（pull 非 push）+并发上限；队列容量是刻意决策；满时向上游传播（|Q|=q_n 触发）**。提升层：工作流/工具。

**5. 内部 DDoS 防线（背压是缺失的控制回路）**（来源：negiadventures 2026-05-16 + A2A credit signals 2026-07-12 + AI Tools Guidebook 2026-05-25 实拉）：模型变快+编排变干净→一个不稳定的依赖变慢→所有 worker 一起堆积=agent 舰队把自己变成内部 DDoS；可怕处=起初"没 down"——队列增长/单个重试看合理/延迟悄悄从一个工具蔓延到每个工作流；agent 间背压用 credit signals 流控（consumer 宣告 credit 像 TCP/gRPC）；一个 agent 的 rate limit 会级联成链式失败。判据：**一个依赖慢→所有 worker 堆积=内部 DDoS（无声劣化）；agent 间用 credit 信号流控（consumer 宣告容量）；背压=缺失的控制回路**。提升层：工作流。

**6. 提前节流（traffic light）而非 429 后反应**（来源：Tamir Dresher 2026-03-21 + AI Tools Guidebook 2026-05-25 实拉）：agent 只在命中 429 后反应=整个配额窗口已经没了；恢复要等 60s 所有 agent 空转；直接 API 调用每个响应含 x-ratelimit 头——读头提前节流（traffic light throttling）而非事后反应；共享 rate limiter 放在高流量 agent 前面；stages 间解耦用 async queue+宽 timeout（consumer timeout 长于最坏 retry-after 链）防一个 stage 限流延迟直接超时下一个。判据：**限流读响应头提前节流（traffic light）不是 429 后反应；共享限流器前置；阶段间队列解耦+timeout 宽于最坏 retry-after 链**。提升层：工作流。

**7. 静态限流的失败（噪声邻居饿死+挡合法工作）**（来源：DZone Agent QoS 2026-02-26 实拉）：静态 rate limit 假定所有调用可比——工具调用并不如此；真实使用下静态限流要么挡合法工作要么让噪声邻居 agent 饿死其他人（尤其 agent 激进重试或进入循环）；智能负载管理=管理并发+优先级+多信号准入控制（Agent QoS）使分析 agent 公平、符合策略、成本敏感。判据：**静态限流对工具调用失效（调用不可比）；多信号准入+优先级+并发管理（Agent QoS）替代静态限流**。提升层：工作流/工具。

**8. 预算五层（request/session/key/model-tier/circuit breaker 全在 gateway）**（来源：aisecuritygateway 2026-04-16 + Zylos token budget 2026-06-30 + kissapi 2026-06-02 实拉）：五层预算——per-request ceilings（抓巨型 prompt/无界输出）/per-session rolling budgets（滚动窗口）/per-key monthly caps（抓泄漏 key/噪声服务）/model-tier routing（按特征路由便宜模型）/circuit breakers（抓 provider 事故/定价意外）；全在 gateway 层执行（客户端只改 base_url+API key 两行）→agent-framework-agnostic+agent 无法绕过；硬预算耗尽→新请求 blocked/reroute 便宜模型/升级人工审核。判据：**预算五层（请求顶/会话滚动/密钥月帽/模型分级路由/熔断）全在 gateway 执行；耗尽→阻断或降级到便宜模型或人工**。提升层：工具/工作流。

**9. 三独立刹车（provider 额度 + 虚拟 key 网关预算 + 循环硬界）**（来源：dreaming.press 2026-07-21 + Daily AI World 2026-08-30 + RockB 2026-07-08 实拉）：可靠封顶 agent 成本=三个独立刹车（任何一个都可能失效）——provider spend limit（账户级后盾）/gateway budget per virtual key（每 agent 刹车）/hard bound on agent loop（max turns+per-run dollar cap）；$47,200 runaway 事故 root cause=无 per-task budget（3.2m input+890k output tokens）；runtime limits（max turns/max wall-clock time/max tool repetition）+spend limits（每 root request 美元预算在模型调用前强制）+fan-out policy（子 agent 与并行工具显式 cap）。判据：**成本三独立刹车（账户额度/每虚拟 key 网关预算/循环硬界 max turns+美元上限）；任一可失效故三层齐备；子 agent 扇出显式 cap**。提升层：工作流。

**10. 速率熔断（spend-rate circuit breaker，每分钟 token 阈值）**（来源：Get Ready for AI Agents 2026-08-29 + rapidclaw 2026-04-18 + niteagent 2026-05-16 实拉）：token budget ceiling 抓绝对超支；circuit breaker 抓速率超支——每分钟 token 消费速率 vs per-agent-type 阈值（参考实现 10,000 tokens/min 抓到 runaway loop）；四个 runtime guardrails（token-based throttling 抓 context-window blowups/request-based throttling 抓 retry loops/circuit breakers trip 重复相同调用/budget caps 美元阈值硬停）；三层配置 agent/service/infra——任何单点失效不能烧预算。判据：**绝对预算+速率熔断（每分钟 token 阈值）；runtime 四件套（token 节流/请求节流/熔断/美元上限）；三层配置单点失效不烧预算**。提升层：工具/工作流。
