## 独点（10）

1. **失败分类路由表：transient→retry backoff / validation→retry once 更严格式→fallback / authorization→暂停告警 / policy→停止升级 / unknown→保留状态转人工**（来源：dev.to n8n + williamspurlock）——先分类失败类型再决定动作，不同失败不同处置。判据：**错误处理第一步是分类失败（瞬时/校验/授权/策略/未知），五类五种路由，不做一刀切重试**。提升层：工作流。
2. **结构化错误响应：agent/子工作流失败不 throw 未处理异常，返回结构化失败响应让父工作流可行动；隔离失败域——billing agent 失败不级联到 orchestrator/其他 agent**（来源：n8n production playbook complex agent patterns）——每个组件自管错误。判据：**每个 agent/子工作流自管错误并返回结构化失败响应，失败不级联**。提升层：工作流。
3. **HITL 审批门模式：agent 可做研究/准备动作但不授最终权给不可逆操作——执行暂停、通知带上下文、阻塞直到人工确认/拒绝**（来源：mech.app + claude-magazine Dify）——审批门是让 agent 能安全上线的功能不是自动化不完整的补丁。判据：**不可逆操作必须过审批门：agent 准备、人拍板；审批门是发布功能不是缺口**。提升层：工作流。
4. **格式失败回环重试：AI 输出不符合预期结构→不回退不失败，带错误信息更新 prompt 回环，模型通常第二次自纠；max 2-3 次防无限循环**（来源：n8n deterministic steps playbook）——与 r340A 输出治理 corrective prompt 同源但这是平台节点级做法。判据：**格式失败回环=错误信息+更新 prompt 再试，上限 2-3 次**。提升层：工作流。
5. **三段式 AI 工作流：context gathering→inference→action validation 分阶段；Set 节点先 pin 数据再推理（调试不烧 API credit）**（来源：synta.io）——把 AI 工作流拆三段，推理前数据固定。判据：**AI 工作流按 取上下文→推理→动作校验 三段拆分；推理输入先固化再跑**。提升层：工作流。
6. **平台级错误处理三选：stop / typed default value / fail branch（附带类型化错误信息转入恢复分支）**（来源：Dify 官方 + deepwiki）——每个 LLM/HTTP/代码/工具节点可配失败行为。判据：**节点失败行为三选一：停止/类型化默认值/失败分支，按节点关键度配**。提升层：工具。
7. **LLM 节点单一职责：每个 LLM 节点只做一件事（分类/生成/抽取分开），narrow responsibility；工具描述写清何时怎么用；迭代上限防 runaway 成本**（来源：Dify 官方 + dify-hosting）——大 prompt 拆多个窄节点。判据：**工作流里每个 LLM 节点单一职责，工具描述写清触发条件，设迭代上限**。提升层：工作流。
8. **webhook 三安全件：幂等键+correlation ID 存表检测重复短路、签名验证、schema version 字段按版本路由（旧路由保持激活直到生产者迁移）**（来源：Activepieces webhook 自动化）——webhook 入站三件套。判据：**webhook 工作流必须配幂等键/签名验证/schema 版本路由，防重复处理与破坏性变更**。提升层：工具。
9. **prompt 版本管理即交付：prompt 存表带 version/owner/rollout flags，回归工作流采样输入比较结构化输出，失败阈值自动回滚**（来源：Activepieces LLM workflows）——与 r340C 评估即交付契约互补，这是"平台表格存储的 prompt 版本治理"。判据：**prompt 版本=表记录+回归采样+失败阈值自动回滚，不是文件草稿**。提升层：工作流。
10. **每步 pin 精确版本：flow 永不自动升级，版本 bump 显式（builder 里手动选，跨 minor/major 有警告）**（来源：Activepieces piece-syncing）——与 r337C 技能供应链钉死版本同源但这是平台运行默认。判据：**工作流每步钉死精确版本，升级显式手动，防供应链静默变更**。提升层：工具。
