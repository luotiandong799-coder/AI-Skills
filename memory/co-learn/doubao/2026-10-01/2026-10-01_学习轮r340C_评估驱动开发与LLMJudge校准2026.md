## 独点（10）

1. **judge 三大偏见量化：position bias（成对比较 A 位胜 10-15pts/naive 设置 60%+）/ verbosity bias（更长答案赢）/ self-preference（自家模型族高 10-25%，perplexity 机制）**（来源：futureagi + qaskills + alpeshnakrani）——先量化偏见再信任 judge。判据：**LLM judge 在投产前必须量化三大偏见（位置/冗长/自我偏好），有数字才谈得上校准**。提升层：模型。
2. **position bias 机械消除：双交换（A/B 与 B/A 各跑一次）+一致性过滤（两次不一致判平局）+方向标准化（评分量表方向中途不变）**（来源：ai-tldr + chanl + futureagi）——成对比较标准做法；id 偏见用中性标签 A/B 且 judge prompt 不含模型名。判据：**成对判断必须双交换+一致性过滤；judge 只评文本不评来源**。提升层：工具。
3. **verbosity bias 校准：长度惩罚进 rubric 或按 token 归一化——length-controlled win rate 已成成对比较事实标准**（来源：futureagi + ai-tldr + kishorek）——"改进"让输出变啰嗦时 naive judge 会鼓掌而用户叹气；校验分数与 token 数相关性。判据：**judge 分数必须与 token 数做相关性抽查，防"啰嗦即高分"**。提升层：工具。
4. **额外偏见面：authority bias（自信语言压过校准的不确定性）/ format bias（judge 偏好 rubric 自带格式：表>要点>散文）/ evaluation criteria drift（提示词/模型/语料变化导致 judge 行为漂移）**（来源：arize + futureagi）——除三大经典外，权威/格式/漂移三类要一并监控。判据：**judge 校准面=位置/冗长/自我偏好/权威/格式/漂移，六类一起测**。提升层：模型。
5. **raw agreement 高估可靠性：MT-Bench 85% agreement≈κ0.48；21 模型 κ 通缩 33.8-41.3pp；52% 模型跨基准移 4+ 位**（来源：layerlens + arXiv reliability without validity）——必须报 chance-corrected kappa，且 judge 排名跨基准不稳定。判据：**judge 可靠性只报 kappa 不报 raw agreement；单一基准的 judge 排名不可外推**。提升层：模型。
6. **中度一致性是甜区：Fleiss κ=0.68 联合失败率 2.1%——评估者"比随机好但保留独立性"才能互查盲点；κ≈0.42 属系统性偏差需修**（来源：ACM Jo.E + arXiv AgentJudgeBench）——多评估者协作时追求适度一致非最高一致。判据：**多评估者目标=中等一致+低联合失败率，不是压到最高一致（会失去互查盲点）**。提升层：工作流。
7. **评估驱动开发（EDD）：先建评估再写 agent——评估任务=压力测试需求是否具体到能开工；迭代到 agent 表现良好**（来源：Anthropic via toutiao）——评估像单元测试一样例行维护；"早期通过的有效测试"可能漏掉设计良好评估早该发现的隐性期望。判据：**EDD 顺序=先建评估定义能力→再迭代到过门；评估缺失=需求不具体的症状**。提升层：工作流。
8. **评测集四类用例+通过标准：正常/边界对抗（模糊指令/诱导幻觉/安全合规）/能力/工具流程；先 20-50 个高价值真实场景做最小集；每场景定义通过标准不是"像不像答案"**（来源：toutiao 产品经理 ×2）——3 类评分逻辑：质量/能力/工具流程。判据：**评测集按正常/边界/能力/流程四类设计，每场景有显式通过标准**。提升层：工具。
9. **评估器双型：criteria（无参考，用户体验类）+ labeled_criteria（有参考，基于标准答案事实校验）**（来源：InfoQ）——事实校验必须有参考；无参考只用于体验类。判据：**事实类指标用有参考评估，体验类才用无参考评估，别混**。提升层：工具。
10. **评估即交付契约：regression set（从事故长成，近 100% 过门，掉=硬阻断）+ adversarial/red-team set（jailbreak/注入/伪造引用/NIST guardrail 类别）+ 确定性状态阈值（12 例 passCount：1.00 verified/≥0.85 needs_review/≥0.60 needs_iteration/<0.60 failed）**（来源：agentropic + OpenCoworkAI）——评估进 CI 当门禁；分级状态给"能发/要审/要改/失败"。判据：**评测进 CI 当门禁，回归集掉=硬阻断；状态分级（verified/needs_review/needs_iteration/failed）**。提升层：工作流。
