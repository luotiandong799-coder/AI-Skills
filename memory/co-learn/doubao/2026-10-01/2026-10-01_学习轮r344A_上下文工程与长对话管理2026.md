## 独点（10）

1. **三态分层上下文预算：Write（窗外交互持久化：摘要进库/推理写文件/偏好进记忆）+ Select（只拉相关子集：3-5 chunk、记忆只取匹配当前任务）+ Compress（降 token 保信息：摘要/抽象/observation masking）——窗口当成本行项管，不"填满"；按路由设工作预算（system/retrieved/history 各配额度）**（来源：sureprompts 12-point checklist + devtoollab + muratcankoylan context-degradation skill）——上下文预算框架。判据：**窗口=预算不是空间；每个动作前选 Write/Select/Compress 其一介入**。提升层：工作流。
2. **缓存前缀匹配工程：稳定前缀在前、易变内容在后；避免 cache busters（时间戳/乱序 JSON key/shuffled few-shot/动态工具列表）——72% 团队在支持缓存的模型上仍付全价重处理；Anthropic 显式 breakpoint（cache_control）开发者控制、OpenAI 自动缓存 ≥1024 token 前缀 50% off、Google 隐式；多级缓存=按变化速率分段设 breakpoint**（来源：softwareletters + tokenoptimize + syedmoinuddin + dreaming.press + 腾讯云）——缓存工程。判据：**缓存命中率是 prompt 布局的直接函数；静态内容放最顶、易变内容沉底**。提升层：工具。
3. **token 经济学 4 档相对成本：输入 1× / 输出 3-6× / 缓存写 1.25-2× / 缓存读 0.1×——输出是最贵 token，压缩目标优先减输出与新鲜输入，优化排序=输出>新鲜输入>缓存写>缓存读**（来源：zylos context window economics）——token 成本排序。判据：**预算优化先看输出与新鲜输入，不是先省缓存读**。提升层：模型。
4. **分级记忆摘要：micro-summaries 每 20 turns 200 词入 episodic log + macro-summaries 每 10 个 micro 用 reflect 蒸馏为语义事实——上下文恒含 system+macro+recent micro+last N turns，大小有界；压缩只总结新截断区间并与现有摘要合并、不整体重生成；结构化摘要（session intent/文件修改/决策/next steps 分段）让摘要器逐格填充防静默信息丢失**（来源：prakashkagitha + muratcankoylan context-compression + theneuralbase hierarchical）——分级摘要。判据：**增量合并优于整体重生成；结构化分段防漂移**。提升层：工作流。
5. **压缩触发时机=rubric 驱动（模型自触发）：子任务已解决/轨迹收敛时触发、推导中途/卡住时抑制——"什么时候压"比"怎么压"更难；ACM teacher-guided 双约束数据生成（when to invoke + when to refrain）；SelfCompact 轻量 rubric 判据；85% 输入驱逐阈值留压缩余量、2025 共识 70% 触发**（来源：arxiv 2607.23809 ACM + arxiv 2606.23525 SelfCompact + zylos + aiwiki）——压缩触发。判据：**触发=子任务边界/轨迹收敛点，非固定百分比盲触发；80-85% 是兜底防线**。提升层：模型。
6. **可寻址压缩（ARC）：append-only 地址存储（历史轮+工具输出逐字保留）+ 有界活跃视图（旧内容替换为显式指针）+ 按需 recall 工具解析指针——任何历史 needle 可无损回访但不超活跃预算**（来源：arxiv 2607.25066 ARC）——可寻址压缩。判据：**压缩≠丢弃：指针化保访问能力、视图保预算**。提升层：工具。
7. **滑动窗口+摘要组合：最近 N 轮逐字（典型 5-10 轮）+ 更早滚动摘要；窗口尺寸=任务参考视野（agent 通常要回看多远），不是固定 5——sliding window 是最简单最可靠的多轮策略**（来源：harshith + sureprompts + agentixforce）——滑动窗口。判据：**窗口尺寸按参考视野校准，随任务类型调整**。提升层：工作流。
8. **分层摘要树（LSM-tree 形）：最近 5 轮全文 + 5-20 轮分组摘要 + 更早一行摘要；map-reduce 并行化（map 分块独立摘要 → reduce 合并）；树形支持 20x+ 压缩比；触发按 token 预算（如 1000 token）非条目数**（来源：hub.cissychen + skillmd session-compression + zylos rolling summary + theneuralbase）——摘要树。判据：**摘要分层按 token 预算触发、多粒度并存；大树形用于 1M+ 场景**。提升层：工具。
9. **上下文腐烂（context rot）诊断与缓解：context management 七法三类本质是 test-time scaling（减少过早终止以允许更多探索）；parallel sampling + 行为感知过滤聚合 +2.6-4.9%——缓解方法按"是否允许更多探索"选型**（来源：arxiv 2606.29718 + 掘金上下文腐烂 + di37 failure modes）——context rot。判据：**rot 缓解按探索容量选方法；并行采样必须带行为过滤**。提升层：模型。
10. **上下文可观测性：拦截 LLM 请求分析 prompt 组成（ContextSpy）+ token 级追踪（prompt/cached/completion/reasoning 分离）+ Trace Replay 确定性回放（mock 工具输出隔离 LLM vs 工具 bug）+ Differential Testing 双版本 diff（Langfuse/LangSmith）——"谁吃掉了预算"可测**（来源：pypi contextspy + arxiv 2604.08290 Tokalator + neelmishra + openlegion OTel）——上下文可观测。判据：**上下文出问题先测预算去向：token 级追踪 + trace replay 定位**。提升层：工具。
