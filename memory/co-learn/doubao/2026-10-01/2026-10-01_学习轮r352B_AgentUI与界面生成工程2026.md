## 独点（10）

**1. 生成式 UI 协议定位三分（MCP 连工具 / A2A 连 agent / AG-UI 连用户）**（来源：copilotkit agentic protocols landscape + docs.ag-ui.com 2026-09-24 + a2ui.org ecosystem 2026-08-12 实拉）：协议分工——**MCP** 连 agent 与工具/数据；**A2A** 连 agent 与 agent；**AG-UI（Agent–User Interaction）** 连 agent 与用户（面向用户的应用）；generative UI specs（MCP-UI / Open JSON UI / A2UI）让 agent 返回 UI 而非纯文本。判据：**要交互界面先问"界面从哪来"——agent 运行时生成（A2UI 类）还是 server 预建（MCP Apps 类），两类协议不混用**。提升层：可复用 Skill/工作流。

**2. MCP Apps：ui:// 声明式 UI 资源 + 双向 JSON-RPC + 渲染前可审计**（来源：MCP SEP-1865 2026-08-23 + MCP 2026-07-28 release candidate + 2026-01-26 官方扩展 实拉）：SEP-1865——server 用 **ui:// URI scheme** 声明 UI 资源、通过工具 metadata 关联、host 在 **sandboxed iframe** 渲染；工具**预声明 UI 模板**供 host 预取/缓存/安全审查后运行；渲染出的 UI 用同一 JSON-RPC 回话 host，**UI 发起的每个动作走与工具调用同一套审计与同意路径**。判据：**交互界面当一等资源声明（ui://），渲染前可缓存可审，UI 动作复用统一审计——别让界面绕过安全路径**。提升层：工具/工作流。

**3. A2UI 协议：流式 JSON UI 契约 + 传输无关多载体**（来源：a2ui.org v1.0 candidate + v0.9.1 + AG2 docs 2026-08-29 实拉）：A2UI（Agent to UI）是 JSON-based streaming UI 协议（Apache 2.0），设计给 LLM 动态渲染；可经 MCP（tool outputs/resource subscriptions）、SSE+JSON RPC、WebSockets、REST 多传输承载；跨平台 web/mobile/desktop/native；LLM 输出 conversational prose + **校验过的 A2UI message block**，框架序列化为传输无关线格式。判据：**agent 生成 UI 走流式协议（LLM 输出文本+校验过的 UI 块），别用"一大段 markdown 让用户脑补界面"**。提升层：工作流/可复用 Skill。

**4. 坐标归一化 [0,1000] 契约（GUI grounding 工业标准）**（来源：duvo-eye-1 toolify 2026-06-14 + duvo-eye-1.5 friendli 2026-09-13 + Holo-3.1 ollama 2026-07-01 + frankx.ai 2026-08-18 实拉）：grounding 模型输出坐标**归一化到 [0,1000] 空间**（原点左上），client 按**原始截图**换算 `px = round(x/1000*width)`——不是 downscaled 输入；duvo-eye-1 各评测 0.0% malformed；物理分辨率（如 1920x1080）sub-pixel 精度映射。判据：**GUI grounding 一律用归一化坐标契约 + 按原图尺寸换算，别让模型输出像素坐标——分辨率一变就全废**。提升层：工作流。

**5. 屏幕解析三源融合（a11y 树优先，vision 只补 gap）**（来源：pnt.jacbex OmniParser 实践 2026-05-22 + Microsoft OmniParser V2 + dev.to desktop GUI agents 2026-09-29 实拉）：**accessibility tree > DOM**（a11y 树原生见 shadow DOM）；**vision 是 fallback 不是 primary**（慢且不准，只填结构化树拿不到的 gap）；**功能标签 > 类型标签**（agent 要 "submit_button" 不是 "button"）；**关系提取使能推理**（知道 input 属于哪个 form 才懂用途）；OmniParser 组合（finetuned icon detection + icon description + OCR）输出 DOM-like 结构 + bounding box 覆盖层；标准适配器防供应商锁定。判据：**能拿结构化树就拿树（a11y/DOM），vision 永远当 fallback；无树场景用 OmniParser 类工具"tokenize 像素为元素"**。提升层：工具/工作流。

**6. GUI grounding 不确定性驱动缩放（test-time 免训练）**（来源：GUI-Lens arXiv 2608.03270 2026-08-04 + UI-Zoomer arXiv 2604.14113 + AutoFocus arXiv 2605.02630 实拉）：GUI-Lens coarse-to-fine cropping——先 OCR/检测器输出 coordinate-aware 屏幕参考，VLM 选越来越聚焦的 crops，执行前视觉验证、局部坐标映射回原屏；UI-Zoomer 把**zoom 触发与缩放尺度都当 uncertainty quantification 问题**（confidence-aware gate 融合空间共识+token 级置信度，law of total variance 分解方差推导 per-instance crop 半径）；AutoFocus 用 density field 建模方向不确定性 + Shape-Aware Zooming，纯 test time 无需训练。判据：**先全屏粗定位，不确定才放大聚焦；缩放与否由置信度触发不是每步都放——省 token 且提精度**。提升层：模型/工作流。

**7. 坐标脚手架提示（Dots+Coords 显式坐标标注最高精度）**（来源：arXiv 2509.11548 How Auxiliary Reasoning Unleashes GUI Grounding 实拉）：给 VLM 屏幕图做 grounding 时叠**坐标脚手架**——三配置对比：Dots（锚点）/ Dots+Indices（锚点+符号索引）/ **Dots+Coords（锚点+显式数值坐标）**，显式坐标标注精度最高；Axis-Grid 变体同样验证显式坐标优于抽象标记。判据：**让 VLM 定位 UI 元素时，图上叠加显式坐标锚点标注，比纯图或符号索引精度高**。提升层：模型/提示工程。

**8. AI 视觉回归 ≠ pixel-diff（语义感知 + baseline 自主维护）**（来源：scrolltest 2026-06-01 + TMCnet Applitools Visual AI MCP 2026-09-15 + karate labs 2026-09-21 + buildbetter Playwright 2026-05-08 实拉）：传统 snapshot 测试逐字节比对、对 anti-aliasing 差异**哭狼**；VLM 理解 layout/typography/color contrast/semantic structure 像人审；Applitools Visual AI MCP tools 让 agent（Claude Code/Cursor/Copilot）**自主做 baseline 维护**（接受/拒绝变更/动态数据 masking，维护开销降 ~95%）；Playwright 用 `maxDiffPixelRatio: 0.01` + `mask`（动态数据区）收敛噪声。判据：**视觉回归用"语义对比+agent 自主维护 baseline"，pixel-diff 只当第一道哨兵；动态区域显式 mask**。提升层：工作流/工具。

**9. 生成式 UI 运行时工程（Harness4GenUI：渲染契约+可观测+治理，不止生成质量）**（来源：awesomegenerativeui Harness4GenUI ASE 2026 workshop 2026-09-08 + awesome-generative-ui 2026-07-25 实拉）：ASE 2026 官方 workshop——把动态界面当**运行时系统**而非"生成得好不好"：稳定上下文模型、UI schemas、**渲染契约**、测试、可观测性、安全、治理七大支柱；生成质量只是及格线。判据：**做动态 UI 先定"渲染契约与治理"（schema/可观测/安全），再谈生成效果——没契约的动态 UI 上线即失控**。提升层：工作流/可复用 Skill。

**10. OSWorld 长程桌面评估与噪声鲁棒性（ENVS 环境原生验证搜索）**（来源：arXiv 2606.22948 ENVS 2026-08-26 + aiwiki computer use 2026-06-21 + tmtpost 实在 Agent 2026-07-29 + yutori OSWorld-Verified 2026-08-31 实拉）：OSWorld 是 multi-app long-horizon 桌面基准，暴露**长期漂移/坐标分辨率失真/状态识别失败**；ENVS（environment-native verified search）30.3 pass@8 vs UI-TARS-1.5 22.7，OSWorld-Noisy 29.0 vs 20.3；2026-07-27 实在 Agent 90.2% 登顶（首破 90%，双冠）；人类基线 ~75%。判据：**桌面 agent 用 OSWorld 系基准测长程+噪声，pass@8 多 rollout 是标配；别只看单轮成功率**。提升层：模型/工作流。
