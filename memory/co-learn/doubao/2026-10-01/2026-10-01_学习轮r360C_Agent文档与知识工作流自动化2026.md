## 独点（10）

**1. 文档生成-检测-评审流水线（代码合并→agent 生成文档→平台检测+PR 建议→人类评审合并）**（来源：effloow 2026-04-07 实拉）：doc 自动化流水线=代码 ship→coding agent 从变更代码生成文档（API 参考/更新指南/新示例）→文档平台检测变更（Mintlify Autopilot/GitBook Agent 识别文档需更新+建 PR 建议）→技术写手评审准确性/语气/完整性后合并。判据：**文档流水线=代码合并→agent 生成→平台检测+PR→人类评审合并**。提升层：工作流/可复用 Skill。

**2. AI 生成文档验证阶段（草稿不立即发布→沙箱跑码+比较文档输出与真实输出；防幻觉关键步）**（来源：specswriter 2026-09-22 实拉）：AI-native 文档工作流=上下文喂 LLM 生成受影响文档草稿（API 参考/用户指南/发布说明）；草稿不立即发布→验证阶段 AI 检查生成内容对照真实软件行为——沙箱跑代码+比较文档输出与真实输出；验证关键因 LLM 易幻觉，无验证直接发布是错误。判据：**文档生成=草稿→沙箱验证（跑码比较真实输出）→发布；防幻觉关键步**。提升层：工作流/可复用 Skill。

**3. Agent 原生文档（为 agent 写的 wiki/ERP/SOP；先转规范 10% 页面（80% 问答）+XHTML→markdown 无损导出）**（来源：Superkind 2026-05-05 实拉）：agent-native docs=为 AI agent 写的 wiki/ERP/SOP——可被 agent 检索消费；先选规范 10%（10% 页面答 80% 问题——分析/搜索日志/问支持团队识别）转写、长尾后置；导出 markdown（Confluence/SharePoint REST API XHTML、pandoc 无损转 90% 情况、PDF OCR+markdown）。判据：**Agent 原生文档=先转规范 10% 页面（80% 问答）+XHTML→markdown 无损导出**。提升层：工作流/可复用 Skill。

**4. 知识漂移检测（对照源渠道交叉引用：矛盾=漂移；持续监控优于日期过期；检测+起草自动、批准人工）**（来源：Slite 2026-05-18 + Dewstack 2026-08-08 + Kipwise 2026-07-20 实拉）：知识漂移检测=文档对照连接源交叉引用（Slack/GitHub/Linear/Intercom/Google Drive）——wiki 与源渠道矛盾=漂移；持续监控优于日期过期（过期说旧不说错）；自更新 KB=从信号检测陈旧/缺失内容（失败搜索/未答问题/数月未碰页面）→路由修复给人类评审——检测与起草自动化、批准不自动化；内容衰变=业务运行快于文档实践→小遗漏累积。判据：**漂移检测=对照源渠道交叉引用（矛盾=漂移）；持续监控优于日期过期；检测+起草自动、批准人工**。提升层：工作流/可复用 Skill。

**5. 生产安全模式（AI 检测+强制人工批准是自更新 KB 唯一生产安全模式；KB 30 天内过时率 64%）**（来源：The Neural Base 2026-04-21 + Fini/Gartner 2026-04-20 实拉）：auto-update articles=AI 检测+强制人工批准仍是唯一生产安全模式；业务风险真实——单条 AI 发布错误产品主张可致监管责任/客户流失/支持升级成本远超工程努力；人工瓶颈非限制而是防级联失败的检查点；架构=（1）AI 生成草稿（2）人工批准（3）批准后自动发布；Gartner 2025：64% 客服领导 KB 发布 30 天内过时、仅 9% 有自动化刷新。判据：**KB 自动更新=AI 检测+强制人工批准（唯一生产安全模式）；30 天过时率 64%**。提升层：工作流/可复用 Skill。

**6. 反馈→文档所有者维护闭环（用户反馈→文档所有者改→webhook 增量索引更新→答案纠正；文章有用寿命≈6 个月）**（来源：XBSTACK 2026-05-17 + TechTarget 2026-09-08 + happysupport 2026-05-01 实拉）：长期活力依赖用户反馈→文档维护的闭环流；反馈指示内容过时→文档所有者登录 Notion 修改→更新 webhook 触发增量索引更新→AI KB 纠正答案；只把人类反馈转成文档所有者维护动作才能防知识库 agent 随时间降级为过时信息；知识文章有用寿命约 6 个月（KCS 方法论）；GitLab 报告 65% 文档过时。判据：**KB 闭环=用户反馈→文档所有者改→增量索引更新→答案纠正；文章有用寿命≈6 个月**。提升层：工作流/可复用 Skill。

**7. 研究 agent 三阶段流水线（Research 并行→Synthesis 合并→Formatter 结构化；单职责可独立测）**（来源：SuperML 2026-06-01 + CSDN GPT-Researcher 2026-09-23 实拉）：研究报告 agent=三 agent 流水线——Research（每个子问题搜索可并行跑）/Synthesis（合并研究发现成连贯散文）/Formatter（结构化 markdown 报告含来源/章节/执行摘要）；每 agent 单一职责→可独立测试/迭代；GPT-Researcher=多阶段任务划分/搜索链路执行/内容抽取与合成输出模块化——学术综述/市场研究/企业情报。判据：**报告流水线=Research 并行→Synthesis 合并→Formatter 结构化；单职责可独立测**。提升层：工作流/可复用 Skill。

**8. 共识与争议候选识别（共识=3+ 独立同结论记数；争议=分歧+性质（事实证据 vs 价值观优先级）；透明标不确定性）**（来源：LobeHub vinicius91carvalho-research 2026-09-29 + Swfte 2026-02-16 实拉）：研究合成=识别共识候选（3+ 研究者独立同结论即使不同角度——记数）与争议候选（显式/隐式矛盾——记谁分歧+性质：事实性=不同证据 vs 价值观=不同优先级）；构建合成简报（原始问题+全部 N 研究者结构化输出）；合成 agent=分组相关发现成主题簇→按重要性组织洞见→连接数据点成解释性叙事→透明标注源材料不确定/分歧（不掩盖）。判据：**合成=共识候选（3+ 独立同结论）+争议候选（分歧+性质）；透明标不确定性**。提升层：工作流/模型/可复用 Skill。

**9. orchestrator-worker 研究设计（lead 规划→3-5 subagent 并行+独立引文 pass；广度优先 +90% 质量≈15x token；复杂度先分类）**（来源：TechieHub 2026-09-08 + skillmd quick-research 2026-08-16 + LobeHub deep-research 2026-09-23 实拉）：Claude Research=orchestrator-worker 设计——lead agent 规划策略、生成 3-5 特化 subagents 并行探索线程、独立 citation pass；Anthropic 自评 lead+subagent 优于单 agent 90%+（breadth-first research）约 15x token 成本；deep-research 技能=先分类输入（Question/Brief/Seed）+评复杂度（Focused/Broad）→分解 3-5 独立 agent 任务→agents 单消息启动写发现到文件返回简洁摘要→最终合成委托 sub-agent 组装 citation-backed markdown——内建约束保 orchestrator 上下文预算。判据：**研究编排=lead 规划→3-5 subagent 并行+独立引文 pass；广度优先 +90% 质量≈15x token；复杂度先分类**。提升层：工作流/模型/可复用 Skill。

**10. 知识 agent 接入与治理（KB 暴露 MCP endpoint+toolbox 发现 retrieve 工具+grounded+引文+RBAC）**（来源：Microsoft Learn Foundry IQ 2026-06-24 + IBM watsonx 2026-09-10 + Mintlify/Kapa 2026-04-24 实拉）：知识 agent=一次供给（Python 脚本建搜索索引+种子文档+建 knowledge source/base）+toolbox 连接指向 KB 的 MCP endpoint+托管身份认证→部署 hosted agent 通过 toolbox 发现 knowledge_base_retrieve 工具、grounded 答案于检索源；IBM=每答案 grounded 仅自己内容+引文+RBAC+治理；Kapa=检索层叠加现有文档栈（索引技术文档/代码/GitHub issues/Slack 历史/Confluence/网站→widget/Slack bot/Discord bot/托管 MCP server）。判据：**知识 agent=KB 暴露 MCP endpoint+toolbox 发现 retrieve 工具+grounded+引文+RBAC**。提升层：工具/工作流/可复用 Skill。
