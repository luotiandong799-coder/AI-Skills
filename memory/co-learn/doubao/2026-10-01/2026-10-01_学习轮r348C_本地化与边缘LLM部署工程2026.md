## 独点（10）

1. **量化层级决策：文本任务 Q4_K_M 最高 quality-per-GB（消费硬件 6-16GB VRAM 默认）；复杂逻辑/代码升级 Q5_K_M/Q6_K；Q3 及以下仅批处理+验证层兜底**（来源：ainexislab + promptquorum + frontierwisdom）——量化档决策。判据：**按任务类型选量化档，不一律最激进**。提升层：工具。
2. **内存需求三要素：模型权重+KV cache+运行时头空间——运行内存常远超下载文件大小，按文件大小预算必爆**（来源：cognity + orderstack + ailearningguides）——内存三要素。判据：**预算头空间，KV cache 是长上下文内存大头**。提升层：工具。
3. **KV cache 四项优化：短上下文优先+前缀 prompt 缓存复用+sliding window 注意+KV 量化（llama.cpp -ctk）**（来源：ailearningguides + localai）——KV 优化。判据：**长上下文内存大头是 KV cache，先量化它**。提升层：工具。
4. **llama.cpp server 侧 prompt cache：重复 system prompt（agent/编码助手）命中缓存跳过 prefill——cache_ram 存槽位 KV 状态到主机 RAM，命中时重载**（来源：localai）——服务端提示缓存。判据：**系统提示固定时缓存命中即免 prefill**。提升层：工具。
5. **本地不等于私密五泄漏点：未认证 localhost 端口（任意进程可访问）/pickle 权重（执行任意代码）/swap 文件（PII 落盘）/遥测（默认外连）/共享 GPU 内存**（来源：bitbytecore + privacyscrubber）——五泄漏点。判据：**部署后逐项封堵，本地运行不等于数据安全**。提升层：工作流。
6. **恶意 GGUF 权重：Bleeding Llama CVE-2026-7482（Ollama 0.17 之前，恶意模型文件内存耗尽/任意代码执行）→ 校验和验证+sandbox 运行+签名权重**（来源：kahma + dev.to jfisher）——恶意权重。判据：**从不可信源拉模型等于执行不可信代码**。提升层：工具。
7. **边缘度量换轴：joules per token 而非 tok/s——Hailo-10H 1.5B 9.45 tok/s 在 2.1W 热包络是强结果；桌面 VRAM 指标对嵌入式产品无意义**（来源：promptquorum）——度量换轴。判据：**先定热/功耗设计点，再选模型**。提升层：模型。
8. **4GB VRAM 甜点：3B 模型是甜点；Qwen 2.5 1.5B Q4_K_M 167 tok/s + 95.7 百分 JSON parse rate 约 1.2GB；7B 需 Q3_K_M 或部分 CPU offload**（来源：gingerlabs）——4GB 甜点。判据：**小模型量化后结构化输出质量可追大模型，按任务选**。提升层：模型。
9. **Docker sandbox 隔离三件套：内部 bridge 无默认网关（仅连主机 API 端口）+只读挂载源文档+tmpfs 易失临时区**（来源：sapirex）——沙箱三件套。判据：**文档摄取与提取全在临时沙箱跑，数据不出隔离区**。提升层：工作流。
10. **benchmark 三透镜：速度/内存/保真分开测——speed-only 排名忽略质量回归（SiliconBench 用分类任务对照 NVIDIA 参考查退化）；运行时内存/热节流/加载慢被基准漏掉**（来源：arXiv 2609.19169 + orderstack）——三透镜。判据：**三透镜同跑，速度第一不验收**。提升层：工作流。
