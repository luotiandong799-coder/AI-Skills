## 独点（10）

1. **Spec-Driven Development 六要素 + 三层边界系统：spec 至少答六问（feature name/用户故事/验收标准 checklist/涉及文件/API 契约/约束如性能目标、可访问性、既有模式）——留空任何一问 agent 就"填空"；Always（提交前跑测试/遵循命名约定/Zod 校验所有输入/正确 HTTP 状态码）/Ask First（数据库 schema 变更/新增依赖/认证流程修改/JWT 轮换）/Never（明文存密码/提交密钥/记录敏感数据）三层边界；spec 错误向下游传播是最贵错误——实现用中档模型（Sonnet 级），验证用快模型（只需准确+低成本）**（来源：kanopylabs + augmentcode + umesh-malik + anhtu + 抖音 OpenSpec）——SDD。判据：**spec 六问齐全才让 agent 实现；三层边界显式写入；实现与验证用不同档模型**。提升层：工作流。
2. **验证税与评审崩溃：高 AI 采纳团队 PR 评审时间中位数涨 5 倍、每 PR 事故翻三倍、评审者 skim 而非读；人类评审效力在 400 行后崩溃——机械修复=编译器与类型门/diff-scoped SAST/依赖存在性检查/mutation-tested 套件/post-merge canaries 持续跑，评审深度按变更风险缩放（低风险可自动化审批，高爆炸半径强制人审+扫描结果+LLM 预筛+spec 上下文）**（来源：augmentcode + aws control framework + devsandlogics）——验证税。判据：**超 400 行 diff 必须拆；机械门优先于人工 skim；审批深度按风险缩放**。提升层：工作流。
3. **上下文盲与文件-函数 gap：agent 在错误或不完整代码库模型上写引用不存在 API/变量名的代码（依赖在上下文 2-3 层之外）；RepoNav 实证存在持续的文件-函数 gap——agent 能到达相关文件但定位不到正确函数；修复=把检索 snippet 重组为文件中心导航脚手架（简单暴露更多文件结构信息不够，收益来自把检索证据组织成可导航结构）**（来源：adaline + arxiv 2609.08355）——上下文盲。判据：**长任务先建文件导航层；失败定位时先查"在错文件还是错函数"**。提升层：模型。
4. **Tree-sitter 增量解析 + 代码图索引：语言无关 AST 解析 25+ 语言（函数签名/类层级/导入链/调用图）；增量解析文件变更只重解析受影响 AST 节点；代码知识图（typed nodes+edges）区别于简单向量索引；MCP 代码索引工具（code-intel 38k 星/ABCODER UniAST）只把任务相关 snippet 排行返回给 agent，不把整库读进上下文窗口**（来源：zylos + cognee + sentra + arxiv 2604.18413 + npm code-intel）——代码索引。判据：**大库先建图索引再问答；索引保持增量更新；查询只回排行 snippet**。提升层：工具。
5. **Git 原生 agent 记忆：agent 的持久知识以仓库内 Markdown 文件+YAML frontmatter 存储，git 作唯一同步后端——记忆像代码一样版本化、可 diff、可回滚、随分支走；OKF 4 周 700+ stars 实证（2026-09 起）**（来源：okf-agent-memory dev.to + zylos）——git 记忆。判据：**agent 长期记忆放仓库内文件而非散落外部；每个记忆条目带 frontmatter 元数据；用 git 历史作记忆审计**。提升层：工作流。
6. **编码 agent 三层权限：Tier1 只读操作（内网 fetch 等）/Tier2 项目内文件写入编辑免分类器调用（常规编码不付分类器延迟，可经版本控制审查）/Tier3 转录分类器看全部其余（shell/网页抓取/外部工具集成/子代理）；沙箱定义技术执行边界（可写哪/能否联网/哪些路径受保护），审批策略决定何时必须请求（跨边界请求可单次批准或会话级批准该类型）；内容范围 ask 规则（如 Bash(git push *)/gh pr create）在分类器前强制询问**（来源：anthropic + openai + code.claude.com + techtaek）——权限。判据：**项目内编辑免分类器但可审查；跨边界动作走审批；高危命令写 ask 规则优先于分类器**。提升层：工具。
7. **GhostApproval 信任边界漏洞：恶意仓库利用 symlink following（CWE-6）把"已批准的文件编辑"重定向到项目工作区外的敏感位置——影响 6 大 AI 编码助手（Amazon Q/Claude Code/Augment/Cursor/Antigravity/Windsurf）；"批准了编辑"不等于"批准了写这个位置"**（来源：CSA research note + Wiz）——信任边界。判据：**文件写入前解析真实路径并核对在工作区内；对符号链接目标做边界校验**。提升层：模型。
8. **自愈 CI/CD Pipeline Doctor：CI 失败事件触发专门修复 agent 而非只通知——错误签名隔离→隔离环境复现→AST 变异生成补丁→测试套件验证→打开 PR 供人审；triage agent 先给结构化裁决（回归判定+错误签名+git diff）再交修复 agent；e2e 选择器重命名自愈需 CI 门禁（脚本失败若出现新断言 matcher 或 test.fixme，防断言退化）**（来源：niteagent + dailyaiworld + bugstack + startdebugging + codex）——自愈管线。判据：**失败先 triage 再修复；补丁必须过测试套件才开 PR；自愈门禁防断言退化**。提升层：工作流。
9. **编码 agent 失败三机制：ClayBuddy 分解为 underspecification（默认模型行为不安全）/capability errors（安全动作可得但模型不遵守）/agent harness errors（安全动作执行失败——harness 层）；WOWHOW 14 型四族 taxonomy（Perception/Planning/Execution/Integration），每型带签名+仪表点+已验证缓解；最危险失败=agent 自信地完成错误任务**（来源：arxiv 2606.19380 + wowhow）——失败机制。判据：**修失败先归类机制（默认行为/能力/执行层）；每型有仪表点可检测**。提升层：模型。
10. **错误路径注入与 GitInject：错误帧携带隐式权威绕过标准安全启发式——sandwich 注入错误上下文使 IPI 成功率翻三倍、四个 frontier 模型 100% 遵从；GitInject=默认形态 AI 评审器在 GitHub Actions 里持 repo-write token 且同一 runtime 摄入 PR/issue 文本（每条消息都是注入面）**（来源：agentpatterns + grimoire）——注入。判据：**错误消息视为不可信输入不进特权路径；CI 评审器用最小权限 token 且与仓库内容隔离**。提升层：模型。
