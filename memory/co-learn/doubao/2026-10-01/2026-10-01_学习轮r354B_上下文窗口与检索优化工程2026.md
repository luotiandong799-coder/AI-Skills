## 独点（10）

**1. 上下文四杠杆 + context 是注意力预算（有效容量 60-70%）**（来源：Atlan 2026-09-21 + lobehub context-fundamentals 2026-09-23 实拉）：context window management 四杠杆——selective injection/active pruning/compression/hierarchical memory architecture；context=finite attention budget 不是 storage bin——每 token 竞争模型注意力、耗尽不可中途补；三约束——hard token limit/soft effective-capacity（实际约广告窗口 60-70%）/U-shaped attention curve（惩罚中间信息）；context quality 不是 window size 决定推理正确还是幻觉；freshness-stamped context。判据：**context 是注意力预算不是储物箱——四杠杆管理（选择性注入/主动剪枝/压缩/分层记忆）；实际有效容量只有窗口 60-70%，别按广告窗口规划**。提升层：工作流。

**2. lost-in-the-middle 数字与修复（80%/60%/50% + 'V' 重排）**（来源：hub.cissychen 2026-05-25 + ai-tldr 2026-06-12 + zeroentropy context rot 2026-05-17 实拉）：U 形召回——关键事实在 100K 上下文 start ~80%、1/4 处 ~60%、middle ~50%、end 最高；上下文越长 U 越深（生产叫 context rot，RoPE/ALiBi 训练长度短于部署最大+attention dilution 二次方两成因）；修复——关键内容放边缘、指令顶部问题底部（sandwich）、检索块重排成 'V'（最重要放两端，别按相关度顺序堆 20 块）、payload 短到几乎没有 middle；reranking 架构对抗。判据：**信息位置决定召回（80/60/50 U 形）——指令置顶、问题置底、检索块排 'V'（最重要放两端）；上下文越长中段越废，宁可短**。提升层：工作流/可复用 Skill。

**3. ContextCurator 模式（上下文管理与任务执行解耦，RL 降熵）**（来源：arXiv 2604.11462 ContextCurator 实拉）：symbiotic framework——轻量专用 policy model（ContextCurator）为强大冻结 foundation model（TaskExecutor）主动 curate working memory；active information entropy reduction——aggressively prune 环境噪声、meticulously preserve "reasoning anchors"（未来推理关键的稀疏数据点）；RL 训练 curator；WebArena 显著增益。判据：**上下文管理可与任务执行解耦——轻量 curator 模型替主模型主动降熵（剪噪声留推理锚点），主模型冻结不动**。提升层：模型。

**4. 双粒度上下文治理（ingestion-aware compaction + lifecycle-aware eviction）**（来源：TokenPilot arXiv 2606.17016 + ZenML-Mastra observational memory 2026-09-30 实拉）：TokenPilot 双粒度——全局 Ingestion-Aware Compaction（在 ingestion gate 稳定 prompt prefixes+消除 open-world 环境噪声）/局部 Lifecycle-Aware Eviction（监控上下文段的残余效用，conservative batch-turn schedule 只在任务相关性过期时卸载）；Mastra observational memory 连续早期压缩 5-40x 保语义与时间上下文（对比三坏法：截断丢信息/向量库加复杂度延迟/最后一刻 wholesale compaction 阻塞交互+context drift）。判据：**上下文治理双粒度——入口稳定前缀+消除环境噪声，运行期按残余效用批量卸载过期段；连续早期压缩（5-40x）优于最后一刻整体压缩**。提升层：工具/工作流。

**5. goal drift 与 harness 工程（task-state 外置 + Manage-Execute-Audit）**（来源：Zylos 2026-04-03 + LongHorizon-Harness arXiv 2608.01964 + harness engineering survey 实拉）：目标漂移是长时程 agent 独特失败模式（context 累积/竞争压力/环境变化导致微妙偏离原目标）；目标持久=架构问题（声明目标须在窗口重置/handoff 间存活，OpenAI Codex /goal 命令）；LongHorizon-Harness——task state 显式维护在 execution 之外、只用从环境独立验证的事实更新；MEA 循环（manager 维护 task state 决定下一 subtask/fresh-context executor 执行/read-only auditor 验证环境状态后再下一轮）；性能瓶颈已从模型权重移到 harness（modest model+well-engineered harness 胜过 large model+poor harness）。判据：**长任务目标漂移靠 harness 治——task state 外置且只按已验证事实更新（Manage-Execute-Audit，auditor 只读）；瓶颈在 harness 不在模型权重**。提升层：工作流。

**6. 检索停止/重试条件=证据覆盖（不是生成置信度）+ 失败模式改写**（来源：HALT arXiv 2608.02009 + A2RAG arXiv 2601.21162 + LangChain agentic-rag 2026-09-15 实拉）：HALT——检索停止按 evidence coverage 而非 generator confidence，给定 expected hop claims 只在累计证据支持每个必需 claim 时停（再检索只加成本/延迟/干扰）；失败时同 query 重跑会重复同样错误——按失败模式改写 query+有界重试预算（A2RAG failure-aware rewrite）；LangChain 回路——grader 标 retrieved docs irrelevant→rewrite 成更清晰 search query→控制回 generate-query-or-respond 重检索（retry loop 是恢复弱首次检索的方式，不停止不幻觉）；Azure reasoning effort medium——高精度语义分类器判首次结果不足才做一次修订查询计划迭代。判据：**检索停/重试按证据覆盖判定（每个必需 claim 有支撑才停）；失败改写 query 而非同 query 重跑；重试有界预算；弱首次检索必须重试不硬答**。提升层：模型/工作流。

**7. KV 缓存友好设计（prefix 稳定 + span 级编辑 + suffix 复用）**（来源：genta.dev 2026-04-23 + tokenoptimize 2026-06-14 + KVEraser arXiv 2606.17034 + Leyline arXiv 2606.01065 + vLLM-K3 2026-07-27 实拉）：prompt caching 经济——Anthropic 写缓存 +25% premium/读 -90%/最小可缓存块 1024 tokens/max 4 cache breakpoints/5-min TTL（另有 1h TTL）；KV-cache-friendly 设计——稳定内容先波动内容后、工具/schema 确定性排序（非确定性排序是 cache-busting bug）、从稳定指令移除 timestamps/request IDs、避免 compaction churn（压缩即失效缓存）、中途不换模型；span 级编辑——KVEraser 只替换编辑 span 的 KV 状态复用 suffix cache（成本 O(|e|(|p|+|e|)) 与 suffix 长度无关）、Leyline 声明式 (span,replacement) 分离编辑与位置正确（replay cache-hit +11.2pp latency -241ms）；vLLM K3——prompt boundaries 是最佳 checkpoint（agentic 下 turn 通常重放上 turn prompt）；Subconscious——压缩复用 cached suffix，被剪信息隐式存活于 retained suffix states。判据：**缓存友好=prefix 稳定（静态在前波动在后/工具确定性排序/去时间戳/不中途换模型/避免压缩 churn）；压缩与编辑走 span 级 KV 复用（成本与 suffix 无关）避免整链重算**。提升层：工具/工作流。

**8. progressive disclosure + 上下文外置（offload 写文件按需读回）**（来源：arXiv 2604.08224 externalization + omkarray 2026-05-22 + innobu 2026-05-01 实拉）：skill 系统——存在性先暴露、深层细节按需加载（长上下文不保证更好性能，详细指令变 reasoning noise 而非 guidance）；offload context——tool results/plans 写文件需要时读回（avoid lossy summarization，外部化把内部回忆变外部识别）；git=经过验证的 durable recovery mechanism（无需新基建）；Anthropic Mar 2026——长任务 clean reset（带 handoff artifact）胜过继续 compaction；skills progressive disclosure+just-in-time retrieval 对抗 context rot。判据：**上下文外置三术——技能渐进披露（先暴露存在再按需加载细节）、工具结果写文件按需读回（避免有损摘要）、长任务干净重置胜过继续压缩；git 作恢复机制**。提升层：工作流/可复用 Skill。

**9. summary collapse（handoff 压缩失守边界元数据=结构隐私泄漏）**（来源：UIUC EMNLP 2026 Wang2026 + AHP handoff 2026-09-27 实拉）：多 agent 协调把 upstream interaction 压缩成 handoff artifact 当共享状态——这是结构性隐私泄漏源：摘要优先保留 operational facts、弱化 boundary metadata（这些事实如何被使用的规则），称 summary collapse；marker survival 人验 judge κ=0.74；AHP handoff bundle——task state/intent/relevant documents 或 data pointers/partial outputs（带 version IDs+timestamps）。判据：**handoff 摘要系统性丢边界元数据（事实怎么用的规则）——压缩 artifact 必须显式保留 use-policy 元数据；交接用带版本 ID+时间戳的 bundle 防泄漏**。提升层：工具/工作流。

**10. agentic retrieval 循环（LLM 控检索：子查询/评分/循环到 grounding 足够）**（来源：Redis agentic-retrieval 2026-08-10 + syncsoft 2026-05-16 + KGP Talkie 2026-07-12 实拉）：LLM 把检索当 callable tool 控 when/what/which tools/whether good enough——planning sub-queries、grading results、looping until grounding sufficient（多跳准确率 34%→78%）；hybrid 四件套——dense embeddings+sparse BM25+metadata filters+Cross-Encoder reranking（精确数字/财季/公司名在 dense vectors 会丢）；腾讯云三步（query rewrite→hybrid search→generate）；Azure——subqueries 并行+语义重排+source references/activity log。判据：**检索升级为 agent 循环（规划子查询/评分/循环到 grounding 足够，替代单次 top-k）；hybrid 必须 sparse+dense+metadata+重排四件（精确实体 dense 丢）；重写→混合检索→生成三步**。提升层：模型/工具。
