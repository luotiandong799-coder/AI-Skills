## 独点（10）

1. **TTFT/TPOT 健康目标与感知延迟：TTFT 是感知速度之王（<500ms@4K prompts），TPOT 30-60ms，30-80 tok/s 会话感——streaming 让"5 秒响应 300ms 出首字"快过"3 秒全静默"；TTFT 由 prefill 成本驱动（输入 token 数与模型参数线性扩展）、decode 受内存带宽约束；选模型部分看 TTFT 特征**（来源：futureagi + ai-tldr + generalcompute + valuestreamai）——延迟指标。判据：**TTFT 目标 500ms 内（4K prompt）；TPOT 30-60ms；流式必须开**。提升层：模型。
2. **模型路由-级联混合：路由（一次决策映射查询到模型）+ 级联（先小模型后质量评估升级）——60/30/10 分层（60% 小/30% 中/10% 旗舰）典型省 60-80%，叠加缓存 90%+；Classifier 路由先于任何贵模型运行比级联更省；级联质量估计（QE）只让难/低置信案例触达贵模型；识别 50-70% 不需要 frontier 的查询可 98% 成本降**（来源：aiexpert + arxiv 2606.27457 + arxiv 2603.04445 + zylos + dev.to nathanbrooks）——路由级联。判据：**路由按复杂度分类先行；级联带 QE 升级；先跑单模型基线再决定是否建级联**。提升层：工作流。
3. **语义缓存：embedding 相似度匹配（非精确前缀）+ ANN 索引 + 余弦阈值——AWS 实证最高 86% 成本降、88% 延迟降；腾讯云客服机器人命中率 57% 降本 62%；RAG 场景跳过整个管线（embedding lookup+context assembly+LLM call）；30% 命中率=30% 成本降**（来源：aws + arxiv 2411.05276 + 腾讯云 + portkey + redis + maxim + zeroentropy）——语义缓存。判据：**高频重复查询场景加语义缓存；阈值决定成败（双网关 exact hash+vector similarity）**。提升层：工具。
4. **输出 token 控制：max_tokens 收紧（p95 合法长度+10%，分类任务设 50 非 4096）+ stop sequences 切断冗长结尾 + 结构化输出强制 JSON 防叙述 + 流式启用 early stopping（用户离开/输出明显错误即中止流省未需要输出 token）——输出 token 是最贵 token（3x 输入），无界响应=无界账单；TALE 按问题复杂度给推理预算**（来源：aws tokenomics + cadence + tokenoptimize + tokenia + microsoft tokenomics + redis TALE + neuraltrust）——输出控制。判据：**max_tokens 按 p95+10% 设定；分类/抽取任务 50 token 级；流式+early stopping 双开**。提升层：模型。
5. **Prompt 压缩分类：无损重述（散文→结构化 YAML/JSON/要点化，400 词散文→8-12 条指令 <100 token）+ 有损删除（丢可选示例/边缘用例）——LLMLingua 类研究级压缩 20x 但长上下文才有回报（<数千 token 不划算）；多数团队 30-50% 缩减靠"不聪明的赢"：收紧 system prompt/检索代替倾倒/封顶输出/摘要滚动历史；ProCut 归因估算逐段量化影响剪低效用组件**（来源：dzone + sitepoint + tokenoptimize + thepromptbench + arxiv 2508.02053 ProCut + 腾讯云）——prompt 压缩。判据：**删一句跑 eval，质量不变则该句不属于；先无损后研究级**。提升层：工作流。
6. **投机解码：小 draft 模型提议多 token + 目标模型并行验证——无损（输出分布不变）2-3x 提速；NVIDIA 五准则（GEMM 推入 compute-bound、attention 主导时 draft length=128/G-1、对齐 128 tile 边界）；EAGLE-3/DFlash 并行块草稿 6x+**（来源：nvidia + arxiv 2607.08690 + neurips + redis EAGLE-3 + dev.to）——投机解码。判据：**无损加速先确认；draft length 按 attention 特性校准；长上下文用 SpecStream 类方案**。提升层：模型。
7. **量化经济账：INT4 降 VRAM 75%（70B→35GB），质量损 1-3%；GGUF Q4_K_M CPU 推理（32-vCPU $200-400/月 vs GPU $2000+/月）；AWQ 比 GPTQ 小 10-15%（免 desc_act per-channel scales，冷启动更快）；FP8 0.1-0.3 点质量损 40-60% 降本——1-bit 崩塌到随机水平（校准盲区）**（来源：index + fungies + booleanbeyond + spheron + pythondatabench + theagenttimes）——量化。判据：**本地/自托管先上 INT4（质量损 1-3%）；低吞吐 CPU 场景 GGUF；别碰 1-bit**。提升层：工具。
8. **连续批处理（continuous batching）：吞吐 23x（naive 220→vLLM 5100 tok/s），加 PagedAttention 28x——GPU 内存带宽是真实瓶颈；延迟感知调度（请求按等待时间+估计处理时间优先）p99 降 29.5%；SLO 容量公式：300ms TTFT P99→峰值利用率 ≤63%，400ms→70%，500ms→75%；离线在线共服会 59.7x P99 TTFT 暴涨**（来源：swfte + semanticscholar + spheron + arxiv ConServe + markaicode）——批处理。判据：**自托管必须连续批处理；容量按 SLO 利用率上限反推；离线在线分池**。提升层：工具。
9. **prompt/前缀缓存分层复用：KV cache 计算一次十次复用（十用户同一 100 页 RAG 文档/相同巨大 system prompt 不跑十次 prefill）——context routing 是多数团队最大的未用杠杆；5 分钟 TTL 精确匹配降 90%+；前缀缓存 2026 是基础**（来源：google cloud + aws tokenomics）——KV 缓存。判据：**巨大静态前缀必开缓存；共享文档场景先算一次 KV 再复用**。提升层：工具。
10. **路由失败模式与业务价值维度路由：订阅层/功能层/请求紧迫性/风险等级/账号价值/内外部/人工升级可用性——免费层用户 casual 问题不配企业管理员生产事故同成本；无 eval 的路由=降质叙事（routing without measurement is just quality degradation with a cost story）；90% 到 mini 10% 到旗舰省 86%，99%/1% 升级 98.5%**（来源：lunartech + xyzbytes + hackernoon + agentnative 单模型基线）——路由治理。判据：**路由前先建 eval 基准；按业务价值维度设路由策略；先跑单强廉价模型+重试对比级联**。提升层：工作流。
