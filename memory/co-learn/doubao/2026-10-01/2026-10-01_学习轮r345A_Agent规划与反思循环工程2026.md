## 独点（10）

1. **规划两阶段与 plan-and-execute 隔离：upfront plan（执行前生成完整计划）+ adaptive replanning（执行中按新证据修订）——计划器先产完整步骤清单写入共享存储，执行器只收单个步骤窄上下文执行——隔离减少幻觉工具调用（executor 上下文窄到只见一步）；计划写成人类可审阅的 JSON 式文档（步骤/所需工具/成功判据），任何工具调用前先出计划**（来源：llmversus + openlegion + deepthink + sitepoint + xbstack）——规划器。判据：**长任务先出可审计划再执行；executor 只见当前步；计划含成功判据**。提升层：工作流。
2. **分解四规则 + 可验证步骤 + 关键步骤保护：每步一个能力（"查询 /checkout 日志"非"调查并修复错误"）、可观测输出（每步产出可验证数据）、最小依赖链（独立步骤并行化）、显式验证步骤（"在 staging 确认修复"作为最后一步）；递归分解限深（过深产生无法执行的碎片）；认证/输入验证类关键步骤永不跳过**（来源：dataaihub + brightlume + frameworksagents）——分解。判据：**分解出的每步必须能回答"输入是什么/动作是什么/成功标准是什么"**。提升层：工作流。
3. **Reflexion 反思循环：Actor 执行→Evaluator 评分→Self-Reflection 生成反思文本→存入情景记忆→下一轮读取累积反思调整策略——跨尝试的 verbal reinforcement（不更新权重），GPT-4 coding 80→91%；反思失败模式=强化错误推理（degeneration of thought），需限制反思次数**（来源：stackviv + 腾讯云 + aisrc + niteagent + ai-tldr）——反思。判据：**反思文本必须存进跨尝试记忆并下一轮读取，否则是自说自话**。提升层：模型。
4. **工具失败恢复赤字：TOOLMAZE 基准（DAG 拓扑复杂度 × 显式/隐式 × 瞬时/永久 2×2 扰动）证明 agent 从工具失败恢复的能力远差于 happy path 完成任务；隐式语义失败降幅最大；三独立基准（TOOLMAZE/ToolBench-X/ToolFailBench）收敛结论——单纯放大模型规模不缩小恢复差距，系统性过度信任损坏的工具输出**（来源：arxiv 2606.05806 + codex + hyper.ai）——恢复。判据：**重规划能力必须单独评测（扰动注入），不能只测 happy path**。提升层：模型。
5. **Repair vs Replanning 三级判定：当前产物错但目标与路径对→Repair（就地修产物）；Critical Assumption 失效/目标被误解/数据源无法回答/依赖改变/多下游步骤失败/验收契约授权改变/剩余预算不足→Replanning（修剩余计划）；无可行替代（所有工具试过仍败/任务超出能力/约束矛盾）→升级给人或返回部分结果——replanner 输入=failed step ID+具体失败原因+剩余目标**（来源：danielcanfly + xbstack + agentixforce + grubenwald）——重规划。判据：**失败时先判定该修产物还是修路径；重规划必须保留已完成步骤状态**。提升层：工作流。
6. **DUPLEX 双系统规划：Fast 符号规划器（PDDL）+ Slow 大模型只在 Fast 失败时激活——错误消息路由到大 LLM 分析并迭代修改规划文件直至出解；只在失败案例上花推理成本，语义/逻辑错误可恢复**（来源：arxiv 2603.23909）——双系统。判据：**符号+LLM 互补时，LLM 修复只对准失败案例，不做全量重规划**。提升层：工作流。
7. **Structured reflection 训练化：把"从错误到修复"变成一等公民、可控制、可训练的动作——模型基于上一步证据诊断错误并提出正确可执行的下一个调用；训练用 DAPO+GSPO 目标函数与工具调用专用奖励；反思是 loop 是"跑模型→评分→喂批评再跑"，不是模型内置特性**（来源：arxiv 2509.18847 + ai-tldr）——结构化反思。判据：**反思环节可训练、可控（有次数上限）、有专用奖励**。提升层：模型。
8. **HITL 中断与审批工程：interrupt 基于 LangGraph 持久层可安全暂停/刷新页面后恢复；gate write actions 不 gate 每个 token（只读研究/起草自主，退款/邮件/部署/数据库写中断）；两个暂停点可选（reasoning 后 acting 前看工具名与参数 / acting 后看结果决定是否继续）；审批面 run-wide 非仅当前 agent；approval UX 四组件=中断机制+通知路由（按类型/风险）+上下文丰富审核界面（confirmation card 带完整参数）+恢复机制；高风险动作（改密码/永久删除）强制人工审批**（来源：langchain + dataaihub + agentscope + openai agents + anhtu + macha + toutiao Dots）——HITL。判据：**写动作才中断；中断必须可持久恢复；审核界面要能看完整参数**。提升层：工作流。
9. **Agent 观测性六层与五类并行评估器：tracing（每步输入/LLM 调用/工具选择/工具输出/下一推理）/evaluation/cost tracking/latency/action audit；未来式并行评估器=ToolSelectionAccuracy（每步选错工具）/TaskCompletion（端到端目标未达）/TrajectoryScore（全轨迹质量）/Groundedness（答案漂移检索上下文）/HallucinationScore（自信声明无工具/记忆支撑）；OTel agent-specific spans（tool calls/handoffs/MCP）成主导标准；replay 可逐 span 定位长任务（数小时/天、重试/循环/子代理交接）故障点；生产监控连真实用户结果**（来源：exemplar + futureagi glossary + skillgen + honeyhive + braintrust + aws agentcore）——观测。判据：**评估器并行跑在轨迹上（非事后）；生产监控必须关联真实用户结果而非只测测试集**。提升层：工具。
10. **Agent 记忆认知三层 + 会话末整合：Working（最近 5-10 轮、2K-8K token、会话/任务期、<100ms）/Episodic（带时间戳的事件序列、跨会话、time-series/vector）/Semantic（蒸馏事实与用户偏好、HNSW 向量索引）；consolidation 在会话末 short-term→long-term；实证（AdaMem 四记忆+三 agent LoCoMo 44.65 F1 vs LangMem 41.76；Amory 叙事式工作记忆接近全上下文推理；dual-process=常驻 10 消息窗口 + 长期以约 3 token/消息增长）**（来源：agentixforce + zylos + memorypapers + arxiv 2601.06282 + arxiv 2605.17625 + headgym）——记忆架构。判据：**三层按内容类型分（经历/知识/技能），窗口量化（5-10 轮 2K-8K），会话末做整合**。提升层：工作流。
