## 独点（10）

**1. RAG 三板斧（混合检索+重排+查询改写，各管一类失败）**（来源：腾讯云 WorkBuddy 2026-09-18 + metafiedlab 2026-06-08 + Stochastic Sandbox 2026-04-28 实拉）：Demo 到生产差距全在检索——混合检索解决「语义对但关键词漏」（dense-only 上 +17% recall、p50 增加 <6ms 延迟；RRF fusion 是 robust default）/重排解决「候选多但最相关排不上」（one-line 变更 ~15% quality；cross-encoder 30-50 候选选 top 3-5=最高 ROI）/查询改写解决「用户问得烂导致搜不到」；向量检索单独会漏精确匹配、BM25 单独漏语义相似——两者对生产都不够。判据：**生产 RAG=混合检索（RRF 融合）→重排（30-50 候选选 top 3-5）→查询改写；三板斧各管一类检索失败**。提升层：工作流/工具。

**2. 查询改写五要求（语义短语/领域术语/宽窄兼顾/去歧义/单一连贯段）**（来源：Microsoft Learn RAG info retrieval 2026-03-07 + ACL Caraman SemEval 2026 实拉）：rewritten query——incorporate natural language phrasing 抓语义/domain-specific terminology 适用则含/覆盖 broad+specific 两面/remove ambiguous unnecessary words 防混淆/single coherent paragraph 自然流动；平衡 keyword richness 与 semantic clarity；domain-specific temperature tuning for query generation 有实质增益（适配领域词汇特征）。判据：**查询改写=自然语言语义+领域术语+宽窄兼顾+去歧义+连贯单段；按领域调温度**。提升层：工作流/工具。

**3. 查询变换技术谱（改写/HyDE/multi-query/step-back/decomposition 各配质量增益）**（来源：LobeHub RAG Engineering 2026-09-28 + ACL Caraman SemEval 2026 实拉）：查询变换按型选——query rewriting +10-15%（模糊/对话式查询）/HyDE +5-15%（生成假设答案再 embed——factual QA）/multi-query +10-20%（3-5 变体复杂题）/step-back +5-10%（抽象到更高级问题）/query decomposition +15-25%（拆子问题多部件，增益最高）；反直觉负结果——larger reranking candidate pools 降质量、base 组件 well-tuned 时 domain-aware prompting/multi-query expansion/reranker fine-tuning 都是负（simplicity over complexity）。判据：**查询变换按型选（改写/假设答案/多查询/退一步/分解），分解增益最高；候选池并非越大越好**。提升层：工作流/工具。

**4. 检索后置控件（metadata filtering 前置+reranker 选型+候选池按延迟预算）**（来源：thesimplifiedtech 2026-06-01 + Databricks vector search 2026-05-21 + webscraft 2026-06-24 实拉）：metadata filtering 在 similarity 之前限定（right text wrong product/version/tenant——结构化过滤器先于相似度）；cross-encoder reranker 读 query+doc 一起打真实 relevance（embedding top chunk 常是 related 非 relevant）；reranker 选型=Cohere Rerank 3.5（API 高质 ~600ms/50 docs $2/1K queries 生产 SLA）/bge-reranker-v2-m3（self-hosted 保密数据 ~80ms GPU/~350ms CPU）/mxbai-rerank-large-v2（开源 BEIR 榜首 ~150ms GPU Apache 2.0）；整体 RAG 质量 +15-40% 不换模型。判据：**检索=元数据过滤前置→reranker（选型按质量/保密/开源）→候选池按延迟预算 10-20 或 30-50 选 3-5**。提升层：工具/工作流。

**5. 上下文注入结构（retrieved content 视为不可信数据+包裹元结构）**（来源：DEV jasminshukla 2026-09-15 + explainx 2026-06-28 实拉）：prompt injection 是 context problem——KB article 或 email body 可含 ignore previous instructions；system 必须 assume retrieved content=data not authority；三控件=system instructions 与 retrieved passages 用 clear delimiters 分离/tell model documents are untrusted evidence/block 非允许列表的工具调用；retrieved chunks 不 self-explanatory——context injection=wrap in structure（来源/用途/怎么用）帮模型正确对待；reranking 只应用到 top 10-20 候选（latency-sensitive）。判据：**注入结构=检索内容与系统指令清晰分隔+声明不可信证据+工具白名单；chunks 包裹元结构（来源/用途）非裸塞**。提升层：工作流/可复用 Skill。

**6. 上下文工程四操作（Write-Select-Compress-Isolate）**（来源：professionaldeveloper 2026-07-05 + Oracle 2026-09-28 + Codex DanielVaughan 2026-09-25 + Stanford CS224G 2026 实拉）：context engineering=decide what model sees at every step（instructions/live task state/retrieved evidence/memory/tool definitions）——prompt engineering 写 instructions、context engineering 决定其余一切+保持成本；四操作——Write（AGENTS.md/memories/scratchpad/OKF bundles 持久化窗口外）/Select（决策时只 surface 相关——codebase retrieval/memory selection/readable_roots/directory-scoped AGENTS.md/MCP knowledge servers）/Compress（只留步骤需要的 tokens——summarisation/compaction/diff-only hooks/返回 references 非 blobs）/Isolate（分离无关上下文防干扰——sub-agents 自己窗口/per-task stores/git worktrees）；同一底层模型 frameworks 实际性能差巨大——scaffolding=context engineering 是差距源。判据：**上下文工程四操作（写窗/按需选/压缩保信号/隔离防干扰）；prompt 工程写指令、context 工程决定其余一切**。提升层：工作流/可复用 Skill。

**7. chunk 语义单元原则（sentence/header 边界+400-600 tokens+parent-child）**（来源：Logic 2026-04-16 + Stochastic Sandbox 2026-04-28 + futureagi 2026-05-20 + heeya 2026-05-16 + nexios 2026-06-03 实拉）：chunk=atomic unit of retrieval=attribution unit——boundary 切半 clause 引用也切半；sentence boundaries/section headers 分块保连贯（fixed-size 字符分块切 thought 迫使从残缺信息推理）；structure-aware recursive splitting 400-600 tokens+parent-child retrieval 保上下文；metadata extraction before chunking（document title/author-source/category tags/publication date/doc ID dedup）使 filtered retrieval 受限；chunk 太大=irrelevant context 稀释 relevance、太小=缺 coherent answer 上下文。判据：**分块按语义边界（句/节）非固定字符数；400-600 token+父块回引用；元数据先于分块提取以支撑过滤检索**。提升层：工具/工作流。

**8. 索引版本化（doc_chunk_registry 表：hash/version/status superseded）**（来源：arpitbhayani 2026-05-15 + hrushikedar 2026-06-01 + next-gen 2026-06-10 + LobeHub rag-production 2026-09-26 实拉）：chunk 注册表——doc_id/chunk_vector_id/content_hash/version/indexed_at/status（'active'|'deleted'|'superseded'）主键(doc_id, chunk_vector_id)；update 时旧 chunk 标 superseded 不硬删；embeddings as versioned dependency——记录 embedding model identifier/preprocessing rules/chunking strategy version/index schema version/embedding timestamp——检索退化时定位是 chunking/normalization/schema drift/embeddings；blue-green full re-indexing（separate index names/aliases）+validation gate（golden eval recall@5 threshold）+safe rollback retention+embedding-model hot-swap。判据：**分块索引版本化（content hash+version+superseded 状态）；embedding 链全记录；重建索引蓝绿+recall@5 门控可回滚**。提升层：工具/工作流/可复用 Skill。

**9. 增量索引（CDC/事件驱动+chunk 级 hash 定向删除）**（来源：LobeHub rag-production 2026-09-26 + nexios 2026-06-03 实拉）：incremental indexing——CDC/filesystem-S3 document diffing/event-driven doc.* events；chunk-level hashing+targeted chunk deletes（不整库重建）；async ingestion pipelines（Kafka/Pub-Sub）高吞吐；预处理坑——whitespace normalize（collapse multiple spaces/trailing/line endings）+PDF 提取 artifacts（ligatures "fi" 被抽成 "f i"）；fixed-size character chunking 只作廉价确定性 baseline。判据：**增量索引（CDC/事件驱动）+chunk 级 hash 定向删；预处理清空白/PDF 粘连字符合并**。提升层：工具/工作流。

**10. 源数据先于检索（dated+signed off corpus；chunking/rerank 不能修坏源）**（来源：atlan 2026-09-21 + arXiv MDKeyChunker 2603.23533 实拉）：dated+signed off source data 给 retrieval 值得检索的 corpus——chunking/reranking/prompt engineering 是 secondary levers，不能修坏源数据；语义 enrich 分块（MDKeyChunker 三阶段：structure-aware chunking 把 headers/code blocks/tables/lists 当原子单元→单 LLM 调用 enrich title/summary/keywords/typed entities/hypothetical questions/semantic key+rolling key dictionary 保 document-level context→同 semantic key 合并 bin-packing）。判据：**知识库源数据需日期+签核（检索无法修复坏源）；分块可做语义 enrich（标题/摘要/关键词/假设问题/语义键）**。提升层：工作流/可复用 Skill。
