## 独点（10）

**1. 编排四模式选型（supervisor/swarm/hierarchical/network）**（来源：AIPromptsHub 2026-06-21 + QubitTool 2026-05-21 + augmentcode 2026-06-18 实拉）：四模式权衡 coordination overhead/parallelism/flexibility/cost——supervisor（单一控制器路由给专家 worker）/swarm（peer handoff 无单点故障）/hierarchical（嵌套 supervisor）/agent network（全去中心共享内存或消息总线）；选型三轴=agent count×task dynamism×fault tolerance；≤5 sub-agents 用 supervisor 最易懂；3-8 agents 确定性工作流 supervisor、15+ 企业级 hierarchical；任务相互依赖度决定架构——独立工作负载用 swarm（路由逻辑内嵌任务）、复杂依赖用 supervisor；生产主流 hybrid=supervisor 规划+并行执行。判据：**编排选型按 agent 数×任务动态性×容错三轴——≤5 用 supervisor、独立负载用 swarm、15+ 用 hierarchical、生产常用 hybrid（supervisor 规划+并行执行）**。提升层：工作流。

**2. hierarchical 隔离复杂性（顶级管业务逻辑，子编排管细节）**（来源：dev.to alex_aslam 2026-09-22 + anhtu 2026-04-21 实拉）：top-level orchestrator 管业务逻辑（"做市场分析，然后查合规"）不必知道市场分析内部是三个专家 agent 并行；一个 supervisor 上下文不够管每个 worker 时升级多层；CEO(Opus)→Manager(Backend, Sonnet)→workers 分层顺带降模型成本；核心收益=isolation of complexity。判据：**supervisor 上下文管不过来时拆层级——顶级只知业务逻辑不知内部并行细节；层级=隔离复杂性的机制，同时允许下级用便宜模型**。提升层：模型/工作流。

**3. 协调税量化（58%/285%）+ Supervisor Tax（确定性状态机替代 LLM 路由）**（来源：agor.me 2026-07-27 + clawdbytes 2026-09-24 + augmentcode 2026-06-18 + AgentSlimming arXiv 2605.08813 实拉）：每个 worker 有自己的 context window、每次 handoff 同一问题定义写两遍、每次 check-in 返回加倍——peer-to-peer 协调开销约 58%、centralized orchestrator 约 285%；supervisor LLM call 是每任务额外推理步骤；对 defined workflows hub-and-spoke LLM 协调常是反模式——typed state machines 更可靠便宜（实测 -70% token）；轻量 supervisor 设计 GAIA 减 29.68% token 保持相当成功率；AgentSlimming 估计每 agent importance score 删冗余或替换。判据：**多 agent 有协调税（集中式可到 285%）——简单路由用确定性状态机不用 supervisor LLM；按 importance score 裁剪冗余 agent；工具结果缓存/prompt 缓存/early exit 七术降本**。提升层：工具/工作流。

**4. checkpoint 持久化（super-step + pending writes + time-travel 调试）**（来源：LangGraph 官方 + LangChain 2026-06-23 + OpenLegion 2026-06-01 实拉）：每 super-step 存 checkpoint，per-task pending writes 同持久化（mid-step 崩溃部分进度存活）；同 thread_id 重新调用从断点续（崩溃/部署/中断不丢已完成工作）；time-travel debugging（inspect/replay 任意历史状态）；后端选型——MemorySaver dev only（重启全丢）/SQLiteSaver 单进程（并发写不安全）/PostgresSaver 生产（并发多进程写/崩溃恢复/水平扩展）/RedisSaver fast ephemeral；四决策——后端/什么进 state vs 外部 store/全 node 还是选择性 checkpoint/失败恢复（replay with modified state）。判据：**长运行 agent 必须 durable execution——每步 checkpoint+pending writes 持久化，崩溃从断点续；生产用 Postgres checkpointer；time-travel 重放任意历史状态改错路径**。提升层：工具。

**5. handoff 契约（五类上下文退化 + 携带六件）**（来源：usewire 2026-05-01 + loooop 2026-05-27 + inematds 2026-09-27 实拉）：每个 handoff 是有损压缩事件——五类上下文可预期退化（causal reasoning/implicit constraints/uncertainty signals/temporal ordering/negative space）；退化跨跳复合（第 1 跳可靠、第 5 跳不可靠）；fix=结构化 handoff 契约不是更大上下文窗口；handoff 携带——target agent/context（累积状态或外部 store 指针）/instructions/metadata（routing reason/priority/constraints）/auth（user-delegated 或 service-account）/model_hint；非正式 handoff（A 结束 B 开始）是上下文与数据丢失的主源——正式化（状态一致确认+接收确认）保证连续性。判据：**handoff 是有损压缩事件——五类上下文逐跳退化，用结构化契约（目标/上下文指针/指令/元数据/权限/模型提示）代替裸传；正式控制转移保证状态一致**。提升层：工作流/可复用 Skill。

**6. 委派血统链（actchain + 每跳收缩 scope + RFC 8693）**（来源：IETF draft-araut 2026-04-22 + scrambleid 2026-06-11 + Zylos 2026-05-25 实拉）：多跳委派 Human→Agent A→Agent B→Tool C→Resource D——每跳独立身份、携带链、资源看到完整委派历史；actchain claim（JWT top-level 提供委派路径加密 trace，ordered array 每对象=调用链前一个 agent）；token exchange at delegation boundaries（A spawn B 换新 token scoped to B 的任务，B 只能行使 scoped 权限不能行使 A 全部权限，每次交换记审计）；传统 OAuth 假设单 human-to-app 委派——多跳必须保留原始委派者归因+每跳收缩 scope+审计全链。判据：**委派=权限链——每跳换新 scoped token、actchain 记加密委派路径、资源看到完整链；子 agent 永不行使父 agent 全部权限**。提升层：工具。

**7. 共享状态三问题 + 冲突治理（CONFLICTED/ACTIVE + 人工升级）**（来源：callsphere 2026-03-16 + Governed Memory 2026-08-17 + agenthold 2026-09-22 + omegamax 2026-06-20 实拉）：分布式共享记忆三问题——storage（共享状态住哪）/consistency（agent 看最新）/coordination（避免冲突动作）；冲突处理——两 agent 写矛盾值→标 CONFLICTED、keep last known good 作 ACTIVE（case 不停摆）、fire callback 人工评审选赢家（policy ESCALATE 默认/RAISE/LAST_WRITE_WINS）；OCC 版本号写冲突即拒（agenthold ConflictError；同 Postgres UPDATE...WHERE version=N、DynamoDB conditional writes）；破坏性操作（deploy/force push/migration）走原子 action gate——检查+claim 单持有者，另一 agent 并发被 block；deadlock detection（circular wait）；Manager Agent 冲突裁决按可靠性/记录时间/来源优先级。判据：**共享状态防 race——OCC 版本号写冲突即拒；矛盾值标 CONFLICTED 保留 ACTIVE 不 halt 再人工升级；破坏性操作走原子 action gate（单持有者）+死锁检测**。提升层：工具/工作流。

**8. brittle planning 是主失败模式 + 规划三指标**（来源：Zylos 2026-05-15 + 规划层指标 2026-08-07 + XBSTACK 2026-04-24 + BRACE arXiv 2608.01428 实拉）：部署 agent 主导失败模式不是幻觉/缺能力而是脆计划——线性动作序列无法在现实偏离预期时修订；规划三指标——规划成功率（计划完整执行比例）/重新规划次数（优秀 agent 不频繁推翻自己的计划）/步骤效率（实际步骤数 vs 最优步骤数比，简单任务拆几十步=规划差）；工具失败重规划流程——捕获物理报错状态→保持已完成步骤状态不变→触发 replanner 带失败 step ID+失败原因+剩余任务目标→LLM 生成修正计划（弃 search_google 用本地只读缓存等替代方案）；BRACE budgeted replanning 减 replanning-call token 62-92%。判据：**agent 失败主因是脆计划——规划质量看成功率/重规划次数/步骤效率三指标；工具失败重规划保留已完成步骤、只带失败 ID+原因+剩余目标；replan 也要预算**。提升层：模型/工作流。

**9. 恢复动作三型（rollback/delegate/refuse）+ 各自必须避免**（来源：UBC long-horizon agents 2026-07-12 实拉）：恢复动作三型——Rollback（系统支持可验证回退边界时；必须避免假装外部副作用已撤销、丢审计证据）/Delegate-escalate（子问题与权限边界清楚或需人/更高权限判断时；避免不受控复制上下文、凭据、写权限）/Refuse-safe stop（任务不可解/信息不足/风险过高/预算耗尽时；避免编造完成、沉默超支、绕过审批）；恢复动作写入规范供长时程执行参考。判据：**失败恢复三选一且有边界——回滚须可验证、升级须权限边界清楚、拒做须坦承（不编造完成不超支不绕过审批）**。提升层：模型/工作流。

**10. A2A Agent Card（capability 声明 + 发现 + trace 贯通）**（来源：A2A Protocol Spec v0.3.0 2026-08-28 + Future AGI A2A 词条 2026-05-22 + IETF AgentCard 2026-04-28 实拉）：Agent Card JSON——identity/capabilities/skills/service endpoint/auth 要求/securitySchemes（Bearer 等）；capabilities 显式声明（streaming/pushNotifications/extendedAgentCard）——客户端用未声明 capability 必须返回错误；发现机制（well-known 路径/mDNS proto=a2a 取 cardUrl 全卡/注册表）；A2A trace 集成——capability discovery/task creation/message exchange/streamed artifacts/cancellation/completion/error 作 OTel spans 同一分布式 trace，W3C traceparent 骑每条 A2A message（跨公司保持同一 trace id）；IETF 命名空间 a2a.*（a2a.delegate/a2a.negotiate）。判据：**跨框架 agent 协作用 A2A——Agent Card 声明能力与认证、未声明能力必须报错、发现走 well-known/mDNS；traceparent 跨 agent 边界贯通可观测**。提升层：工具。
