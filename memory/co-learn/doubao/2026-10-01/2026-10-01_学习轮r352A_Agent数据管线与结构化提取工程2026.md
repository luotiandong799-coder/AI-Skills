## 独点（10）

**1. 抓取 API 统一 Markdown-first + JSON schema 结构化（context API 模式）**（来源：Firecrawl 官方 docs 2026-09-26 + Firecrawl 101 2026-05-18 + context.dev 2026-06-27 实拉）：`/scrape` 一次调用 formats 数组同时返回 markdown+html+screenshot+links+JSON；PDF/Word 走 `/parse` 同管线；传 JSON schema 即返回 typed JSON（JS 渲染/代理轮换/限速由服务端处理）；`/agent` 无需 URL 描述需求 agent 自找自提；P95 延迟 3.4s 单调用 SDK 模式。判据：**抓网页先问"我要什么格式"，多格式一次拿，不要裸 HTTP 再自己清洗**。提升层：工具/工作流。

**2. 抓取管线反模式五连（RAG 数据卫生）**（来源：lobehub web-scraping skill 2026-09-23 + spider.cloud docs 2026-05-29 实拉）：①raw HTML 直接当 RAG 块（错）→ 先 trafilatura/readability 提取正文；②无去重（错）→ hash 规范化文本 + MinHash-LSH 近重复检测；③无界并发打一个域（错）→ DOWNLOAD_DELAY + AutoThrottle；④重复爬同一 URL（错）→ 持久化 `{url: last_modified, hash}` 用 If-Modified-Since；⑤盲目信 sitemap URL（错）→ 验证 status 200 + Content-Type 再解析。判据：**五条反模式逐一自查，中一条就是数据质量问题源头**。提升层：工作流。

**3. 增量同步三态协议（fingerprint skip / re-index / delete）**（来源：context.dev 整站爬取与 sitemap 摄取 2026-08-23 实拉）：fingerprint 匹配存储状态则**跳过 chunking 和 embedding 整段**（该文档 API 成本归零）；fingerprint 不同则删旧向量块（按 canonical ID 关联）→ 处理新 Markdown → upsert 新向量；完整 sitemap 运行中缺失的 URL 标记 deleted；安全护栏不可协商。判据：**文档更新走"比对指纹→只重索引变化的"，别整库重灌——同内容重嵌入是纯浪费**。提升层：工作流。

**4. 浏览器代理双通道：vision+DOM 结合，可编辑 harness 优于固定动作菜单**（来源：browser-use docs/changelog 2026-07-01 + thebestaitools 2026-07-30 + techiehub 2026-09-08 实拉）：browser-use 102k stars Python MIT，**vision+DOM 双通道**结合提升交互可靠性；CLI 3.0 给 agent 一个**小可编辑 Python harness 而非固定浏览器动作菜单**（"The Bitter Lesson of Agent Harnesses"——固定菜单是死路，agent 需要能改的工具）；复用真实 Chrome profile 让 agent 继承已有登录态；WebVoyager 89.1% 成功率（586 任务）。判据：**浏览器自动化优先"可编辑 harness 而非固定动作菜单"，登录态复用真实 profile 不重登**。提升层：工具/工作流。

**5. 正文提取函数四档权衡（精度/速度/召回谱系）**（来源：trafilatura usage-python 2026-06-08 + Unstructured.io GenAI mindmap 2026-06-06 + kanopy 解析对比 2026-04-27 实拉）：Trafilatura 四函数——`extract`（平衡精度召回）/ `bare_extraction`（裸变量）/ `baseline`（快速文本段落+JSON 元数据）/ `html2txt`（最大召回）；Unstructured `partition_html` 输出**语义元素**（Title/NarrativeText/Table/ListItem）供 LLM chunking 管线，Cloud API 100-500ms vs Local SDK 10-100ms（GPU）；30+ 文件类型 auto 路由到正确 partitioner。判据：**正文提取按"精度优先/速度优先/召回优先"选函数，不一律用默认；要语义分块用元素类型输出**。提升层：工具。

**6. 结构化输出三层：JSON mode / strict schema / constrained decoding**（来源：codercops 2026-06-03 + Claude structured outputs 2026-09-30 + niteagent 跨 provider 2026-06-04 + logic.inc 2026-05-20 + kanopy patterns 2026-04-17 实拉）：JSON mode=合法 JSON 但**语义结构不可预测**；strict schema（tool calling/response_format）=约束到确切 schema，生产系统标准；跨 provider 映射——OpenAI `response_format`、Claude `output_config.format`（JSON outputs+strict tool use）、Gemini `response_mime_type`+`response_json_schema`、Ollama `format` 字段；schema 设计三原则——**enum 代替开放字符串**（模型不会幻觉第四个选项）、**一任务一 schema**（不一次提 30 字段）、**默认必填**。判据：**生产系统要语义可预测就用 schema 强制，别用 JSON mode 赌；schema 字段用 enum 钉死合法值**。提升层：模型/工作流。

**7. schema 版本化与验证-重试（schema 当 API 契约）**（来源：precisionaiacademy 2026-04-16 + pydantic-ai-harness PyPI 2026-09-12 + guardrails-ai 0.8.0 2026-08-21 实拉）：response schema 像 API contract 一样**版本化、可部署、可回滚**；strict mode 不返回 malformed 但 API 本身会失败（限流/超时/瞬断）→ 调用包 retry + 指数退避；Instructor `max_retries` 在 SDK 内处理 validation-fail 重试；pydantic-ai-harness 提供 **Repair Tool Arguments**——在 schema 验证前修复 malformed JSON 工具参数。判据：**schema 升版要有兼容策略；验证失败走"修复→重试"而非裸抛给用户**。提升层：工作流/工具。

**8. 实体解析多信号分步（确定性优先，LLM 仲裁兜底）**（来源：kanopy 数据提取富化管线 2026-05-24 实拉）：生产级实体解析四步——①normalize 名称（小写/去 Inc LLC Ltd 后缀/去标点）②**domain 匹配**（公司最可靠标识符）③无 domain 记录用 fuzzy（Levenshtein 或 TF-IDF 名称+位置）④LLM 只做最后仲裁（"Are these the same company?"处理歧义）。判据：**能确定匹配的先确定，fuzzy 是第二选择，LLM 只做兜底仲裁不做主匹配——LLM 主匹配又贵又不可复现**。提升层：工作流。

**9. 摄取管线免独立状态存储（状态跟着源走）**（来源：seehiong n8n+Dify 知识摄取 2026-06-01 + n8n RAG docs 2026-04-16 + LlamaIndex ingestion pipeline 2026-09-17 实拉）：n8n+Dify 摄取**不用 PostgreSQL/Redis 单独追踪已摄取文档**——用源系统自身状态（网站变更检测/文件元数据）驱动增量；Dify 知识库 4 数据源（file upload/online drive/online documents/web crawler）编排管线；LlamaIndex IngestionPipeline = transformations 数组（SentenceSplitter→TitleExtractor→OpenAIEmbedding）+ IngestionCache + persist_dir 持久化。判据：**摄取状态跟着源走（源变了重摄取），不另起状态库——状态库本身会失步**。提升层：工作流。

**10. 2026 反爬评估面与 stealth 分层配置**（来源：mobileproxy.space 2026-04-29 + crawl4ai SDK 2026-09-24 + pkgpulse 对比 2026-05-19 实拉）：反爬评估面=IP 信誉+TLS 签名+请求序列+速度+HTTP/2 优先级+header 稳定性+重定向行为+cookie 管理；Crawl4AI stealth 三分——`magic=True`（组合多 stealth 特性）/ `simulate_user=True`（模拟鼠标移动+随机延迟）/ `override_navigator=True`（覆盖 navigator 指纹）；headless 模式更易检测 → `headless=False`；Firecrawl 服务端限速**自动排队**（无法意外打爆目标，但牺牲 per-domain 礼貌策略控制——托管 vs 自托管是取舍）。判据：**stealth 是分层组合不是单开关；托管 API 自动排队 vs 自托管控制礼貌策略，按目标敏感度选**。提升层：工具。
