## 独点（10）

**1. trace-to-dataset 闭环（失败 trace→回归数据集→CI 门禁）**（来源：Braintrust 2026-05-29 + Latitude 2026-06-27 + CallSphere 2026-05-05 实拉）：生产 LLM 评测是纪律不是一次性 vibe——**observe live traces → 采样 hard failures → 把 golden spans 晋升进数据集库 → 用自动 grader 门禁部署**；五步闭环：Locate trace（按 user/session ID/timestamp 定位精确 run）→ Reproduce（pull trace inputs 本地同模型+工具重放，确定性复现或刻画方差）→ label failure mode → promote span 进 versioned regression dataset → write task-specific scorer（同一 scorer CI 和 live traffic 双跑）；"每次事故留下永久数据集行，同一回归不能二次上线"。判据：**生产 trace 是回归评测的事实来源——失败 trace 标故障模式→晋升数据集→写 scorer→CI+在线双跑，闭环才防漂移**。提升层：工作流/可复用 Skill。

**2. trace-eval gap（rubric 老化 vs production 移动）**（来源：Future AGI 2026-05-19 + CallSphere 2026-05-05 实拉）：agent 过了 per-turn faithfulness 却在生产失败——拉出失败会话每条都过 rubric，每条都让用户失望；"instinct 是怪 rubric，right read 是 rubric 三月的标准四月的生产已经变了"；六阶段 pipeline（instrument→trace→dataset→evaluator→score→CI gate）跳一步就发回归。判据：**评测标准按生产周期保鲜——production 变了 rubric 就得重校准，"过了评测"≠"能上线"；六阶段链路缺一段就会发回归**。提升层：工作流。

**3. OTel GenAI 语义约定（instrument once switch backend）+ 六层扩展**（来源：Greptime 2026-05-21 + LangSmith Trace with OTel 2026-09-15 + DEV 纠偏 2026-06-23 实拉）：标准属性 gen_ai.request.model / gen_ai.usage.input_tokens / gen_ai.response.finish_reasons——插桩一次后端可换（Langfuse→Phoenix→Datadog 不重写代码）；2026 core attributes 出 experimental 但 **NOT stable**（DEV 纠偏：别信"went stable"帖）；六层扩展：LLM/inference、agent orchestration（gen_ai.agent.*）、MCP tool calling、content capture、quality evaluation（gen_ai.evaluation.score.value/label 挂 span，同分数记 histogram 追踪质量趋势）；OTel CNCF 2026-05 毕业。判据：**统一按 OTel GenAI 语义插桩、工具链可移植是验收标准；评测分数挂到 span+histogram 双记；core 约定仍未 stable 别锁死**。提升层：工具/工作流。

**4. MCP 调用可观测性（Trace Context 跨 MCP 传播 + execute_tool span）**（来源：Future AGI 2026-05-14 + Zylos 2026-05-29 + OTel GenAI 规范 2026-09-30 实拉）：MCP-specific semantic conventions——mcp.method.name/session/transport；gen_ai.operation.name=execute_tool（span name 应为 execute_tool {gen_ai.tool.name}，kind INTERNAL）；W3C Trace Context 经 MCP `_meta` 字段传播（SEP-414：traceparent/tracestate/baggage）让 MCP 调用链跨 server 不断。判据：**MCP 工具调用必须带 execute_tool span+Trace Context 传播——否则跨 server 调用链断裂无法归因**。提升层：工具/工作流。

**5. AI gateway 层可观测性（watches AND acts）+ 合规审计日志**（来源：Future AGI LLM Gateway 词条 2026-05-21 + Maxim 2026-05-20 + BeyondScale 2026-06-29 + prompthalo 2026-06-16 实拉）：gateway 是 agent 系统唯一能放 loop detection/per-step budgets/tool-call audit 的地方——10-100 model calls/task 无 gateway=没人能调试/归因/安全；gateway 不只观测还拦截（脱敏/阻断/日志）；PII 可逆脱敏（reversible tokens [EMAIL_001]）provider 调用前+响应再脱敏；审计日志记 classification event/redaction outcome/enforcement decision——**不存脱敏前的原始值**（NIST SP 800-92：脱敏器剥掉的值别存第二份）；structural redaction 只留 metadata（token counts/latency/error codes/model ids）零暴露选项。判据：**gateway 热路径可逆脱敏+审计记决策不记原始值（log the decision, not the values）——合规审计五要素：元数据/策略决策/身份/不可变保留**。提升层：工具/工作流。

**6. Agent trace 四支柱（tool calls/reasoning steps/state transitions/memory operations）**（来源：Braintrust 2026-06-21 + laminar.sh 2026-09-22 + Langfuse 2026-07-15 实拉）：四支柱——**Tool calls**（name/args/returns/latency/retries）/ **Reasoning steps**（中间 CoT、plan-act-observe 转换、分支）/ **State transitions**（每步前后 working memory、session-level context）/ **Memory operations**（reads/writes/semantic search hits/retrieval scores/freshness）；span 嵌套子 agent 是含其产出子树的容器；Langfuse agent graph 从 observation timing+nesting 自动推断节点与边。判据：**agent trace 必须含工具/推理/状态/记忆四支柱——少一柱就无法定位"哪一步错了"；嵌套 span 树是执行图**。提升层：工具/工作流。

**7. 多 agent 归因（per-agent identity + root_run_id 传播 + 五维成本账）**（来源：Zylos 2026-06-14 + traccia 2026-07-28 + WOWHOW CAL 2026-06-24 + AgentConn 2026-08-27 实拉）：每 agent 分配 identity 连续追踪 token——无 per-agent 归因时成本尖峰找不到责任 agent；root_run_id 显式跨 agent 边界传播（header X-Run-Id）；WOWHOW CAL 五维（Phase/Agent Role/Tool-Call Type/Context Carry bucket/Retry Tax）典型省 60-65%；agentic coding 实测 **25:1 input:output token 比**——输入定价才是大头；50-turn 会话上下文累积（turn 1-10≈5K/turn→11-30≈20K/turn）。判据：**多 agent 成本按 agent identity+root_run_id 传播归因，五维账本（阶段/角色/工具类型/上下文携带/重试税）——input 占比才是成本大头**。提升层：工具/工作流。

**8. eval theater 与 benchmark gaming（评测要防被游戏化）**（来源：Singularity.Kiwi Berkeley BenchJack 2026-04-13 + CallSphere 2026-04-26 + acingai 2026-06-13 实拉）：Goodhart（measure→target）；vibe check（看三个输出点头就发布=默认失败模式）；**BenchJack**——10 行 conftest.py 打爆 SWE-bench、发送 {} 打爆 FieldWorkArena（基准分数可被游戏到近满分零能力）；vendor vs independent 复跑差 5-20 点（五 gaming 技术）；污染检测四法：n-gram 漏改写、成员推断假阳性、canary 需合作、**扰动测试（改写/换序/重测）最可靠但最贵**。判据：**评测分数可被游戏化——独立复跑对比+扰动测试防污染，别拿单方报告的分数当能力**。提升层：模型/工作流。

**9. LLM-as-judge 偏见与去偏（position/verbosity/self-preference + 校准）**（来源：Future AGI 2026-08-27 + hub.cissychen 2026-05-24 + Formalism Trap arXiv 2607.28641 实拉）：position bias（slot A 赢 10-15 点，随机化位置或双序运行判定序依赖为平局）；verbosity bias（长答案 +15-30 点）；self-preference；**uncalibrated judge 不是评测是放大器**（放大 prompt 自身偏见成 90% 假通过率）；Formalism Trap——LLM-as-judge 在对抗负载下混淆结构程序主义与语义真值（Evaluative Dissonance Index 量化）。判据：**LLM-as-judge 偏见有方向（位置/冗长/自偏）——随机化位置+双序平局+校准，未校准的 judge 是放大器不是评测**。提升层：模型/工作流。

**10. 决策级遥测第三层（Layer 3 cognitive tracing）**（来源：Observability Summit NA26 2026-10-01 + Amazon Science RE-AIM 2026 实拉）：OTel 三层——Layer1 infrastructure & LLM tracing（tokens/latency/cost/model id，stable）/ Layer2 protocol tracing MCP（gen_ai.tool.name/conversation.id，merged 2025）/ Layer3 cognitive/decision tracing（deviation/baseline/scope/risk，社区缺口）；"Layer 2 说调了哪个工具，Layer 3 说该不该调"；Amazon 实测 **behavioral telemetry 测不出幻觉**——每个 signature 是 effort-outcome imbalance，流畅自信的错误响应无 detectable deviation（15% 错误低于人群 median 三个 effort signals，分类器 4 false negatives 平均约一半 median effort）。判据：**遥测三层缺认知层——工具调用记录≠工具选择正确性；行为遥测测不出流畅幻觉，需决策级偏差检测（deviation vs baseline）**。提升层：模型/工具。
