## 独点（10）

**1. Prompt Registry 单一事实源（immutable version+作者+变更日志+golden 集指针）**（来源：DEV nainikmehta 2026-09-17 + Ascheriit BEE-30028 2026-06-30 + exploreagentic 2026-06-28 实拉）：registry 存 prompt_id/immutable version（content hash or semver）/author/changelog/golden-dataset pointer/model hint/parameters（temperature/max_tokens）；产品 ship 给依赖输出质量的用户后 SHOULD 从源码提取到 versioned registry——解耦 prompt 变更周期与应用发布周期；运行时拉 production-tagged 版本（默认 cached 300s）；每版本 label（production/staging），改 prompt=cut new version，undo=移动 label。判据：**prompt 存 registry 不存代码字符串——不可变版本+作者+变更日志+golden 集指针；运行时拉 labeled 版本；变更周期与应用发布解耦**。提升层：工具/工作流/可复用 Skill。

**2. prompt 语义版本（MAJOR=breaking 输出格式/MINOR=新能力兼容/PATCH=措辞修复）**（来源：Databricks 2026-05-14 + theneuralbase 2026-04-22 + digitalinsight 2026-05-05 实拉）：semver 适配 prompt 行为变化——typo fix=patch；改 output wording 不改 schema=minor；rework 返回新结构/边 case 行为不同=major；metadata 带 owner/intended model family/last evaluation date/compatible schemas（多消费者跨服务/区域/产品线时尤其关键）；semantic versioning 追踪哪个 prompt 产了哪个 output+安全 rollback；部署 prompt 时记录运行哪个版本。判据：**prompt 用 semver（MAJOR 破坏输出格式/MINOR 新能力兼容/PATCH 措辞修复）+元数据（owner/目标模型族/最后评测日/兼容 schema）；部署记录运行版本以回滚**。提升层：工作流/工具。

**3. PR 触碰 prompt 自动跑 golden eval（CI eval gate）+shadow rollout**（来源：DEV nainikmehta 2026-09-17 + AIPromptsHub 2026-06-08 实拉）：每个 PR 触碰 prompt 自动对 golden set 跑 eval——prompt 编辑 auditable/testable/reversible；shadow rollout（影子发布）新旧对比再全量；eval 作为 CI/CD gate；回滚=移动 label 无 redeploy；git-native prompts（.txt/.md/.yaml 文件在应用仓库）——commit history=version history、与 code review 集成、rollback 一个 config change。判据：**prompt 变更走 CI eval gate（golden 集自动评估）+shadow rollout 对比；回滚=移动 label 无重新部署；git-native 存 prompt 复用评审流**。提升层：工作流/可复用 Skill。

**4. prompt 依赖管理（跨 prompt 依赖+外部系统版本验证防不兼容组合）**（来源：omnithium 2026-06-01 + datawizard 2026-06-11 实拉）：跨 prompt 依赖与外部系统版本要验证——prompt_dependency_check 函数验证 prompt_version+environment 组合防不兼容；semver 定义细化（MAJOR=breaking output format/behavior/interface；MINOR=new capabilities 向后兼容；PATCH=bug fixes/phrasing improvements）；git for prompts——clear history/review/branching/deployment consistency、text-based formats 可读 diff、code changes 与 prompt 变更天然链接。判据：**prompt 依赖验证（跨 prompt 引用+外部系统版本组合检查防不兼容）；git-native 存 prompt——diff 可读、与代码评审/发布一致**。提升层：工作流/工具。

**5. DSPy 联合优化（MIPROv2：instructions+few-shot 一起 + 贝叶斯搜索）**（来源：DSPy MIPROv2 官方 2026-09-13 + DSPy choosing-an-optimizer 2026-09-12 实拉）：MIPROv2=Multiprompt Instruction PRoposal Optimizer Version 2——bootstrapping few-shot example candidates+proposing instructions grounded in task dynamics+Bayesian Optimization 找最优组合（联合优化指令与示例或仅指令 0-shot）；三阶段（预览 program code/data/traces→draft 候选 instructions→discrete search mini-batch 采样组合评估）；optimizer 选型表：BootstrapFewShot（刚起步）/KNNFewShot（大训练集不同 demos）/COPRO 或 GEPA（指令看着错）/MIPROv2 或 GEPA（都弱有预算）/SIMBA 或 InferRules（失败模式可命名）/BootstrapFinetune（prompt 平台期模型可调）。判据：**提示优化=instructions+few-shot 联合（MIPROv2 贝叶斯搜索）；按情境选 optimizer（起步/大集/指令错/都可/失败可命名/模型可调）**。提升层：工具/可复用 Skill。

**6. APO 双轨（instruction optimization vs exemplar optimization 独立演化）**（来源：arXiv 2406.15708 + arXiv 2507.03620 + arXiv 2506.19773 实拉）：自动提示优化（APO）分 IO（指令优化）与 EO（示例优化）两大轨独立演化——性能严重依赖 prompt 工程故需自动化；DSPy=programming not prompting——用户定义 what they want 而非 craft prompts，compiler 自动生成优化 prompt；signature 定义 input/output behavior+module 选 predict/Chain-Of-Thought/ReAct；DSPy natives 按预定义 signature 解析 LLM 输出。判据：**自动提示优化=指令轨+示例轨分别处理（IO/EO）；编程式声明（signature+module）而非手写字符串——输出按 signature 解析**。提升层：工具/工作流。

**7. 安全提示优化（SAPO 约束多目标：性能最大化受安全约束）**（来源：ACM SAPO 3786335.3813128 实拉）：SAPO=Secure Automated Prompt Optimization 多 agent 框架——prompt optimization 作为 constrained multi-objective problem（maximizing task performance subject to explicit security constraints）；四 agent 经中央编排：Prompt Generation Agent（候选生成）/Security Check Agent（adversarial robustness 评估）/Performance Evaluation Agent（任务准确率）/Critic Agent（合成跨 agent 反馈自适应重平衡优化权重）；安全约束保证每迭代优化不降安全。判据：**提示优化是约束多目标（性能 max 受安全约束）；四 agent 分工（生成/安全检/性能评/批评重平衡）每迭代保安全**。提升层：工具/工作流。

**8. 前缀缓存锚定（byte-for-byte identical prefix + cache-anchor 静态段）**（来源：Respan 2026-05-11 + naivigate 2026-09-17 + alicelabs 2026-08-03 实拉）：caching 是 prefix-based——prompt 必须从位置 0 byte-for-byte identical；cached input tokens 定价≈regular input 的 10%（90% reduction；Anthropic 10% read/125% initial write）；long system prompts/tool schemas/static context 应 cache-anchored——常减半总开支；+model routing 常规任务小模型→70-85% cost reduction；窗口 5 分钟默认可延 1h、第二次 read 内回本；语义缓存（embedding 相似命中）省 30-70% 调用与前缀缓存互补。判据：**缓存按前缀命中——静态段（system/tools/示例）放最前锚定；cached 读≈1 折；第二次 read 内回本（窗口 5min-1h）；语义缓存互补**。提升层：工具/工作流。

**9. 缓存监控三指标（hit rate/cache writes/inference cost）与发布判据**（来源：OpenAI GPT-6 cache 2026-09-22 + CSDN 2026-09-25 实拉）：GPT-6 缓存优化实证——hit rates 83%→91%、cache writes 减约 2/3、inference 成本减 36%；新工具监控 cache 性能诊断 misses；发布判据=只有缓存更省且质量不变或更好才扩大流量——不凭 cached token 上升发布；回滚通过路由恢复旧不可变版本（TTL 内可能立即命中=好事；已过期=一次冷写——发布系统应接受短暂成本而非为避免冷写继续用有问题的新 prompt）；多区域发布分别预热观察（缓存不跨区）。判据：**缓存三指标（命中率/写入量/推理成本）监控；发布判据=省且质量不降；回滚=路由切旧版本接受一次冷写；多区域分别预热**。提升层：工作流/工具。

**10. 升级前沿模型的 prompt 反模式清理 + effort 校准**（来源：Claude 2026-09-08 + askantech 2026-04-09 实拉）：降低成本不牺牲性能三 fixes——maximize prompt cache hit rate（最大化缓存命中）/remove anti-patterns from prompts when upgrading to frontier models（升级前沿模型前清理 prompt 反模式）/calibrate effort to the task（按任务校准 effort）；prompt caching=最被低估 latency+cost lever——静态部分 provider 缓存处理表示跳过 reprocessing；Claude 官方 claude-api skill 固化此指导。判据：**三 lever=缓存命中最大化+升级前清反模式+effort 按任务校准；静态前缀缓存省延迟+成本双项**。提升层：工具/工作流。
