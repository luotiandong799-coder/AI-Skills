## 独点（10）

1. **共享状态 vs 显式 handoff 二选一：shared state（所有 agent 读写中央结构——简单但并发写 race，一更新覆盖另一）；isolated state（每 agent 自己的工作记忆，只经显式 handoff payload 通信——安全但难丰富往返）**（来源：klementgunndu + ailearningguides）——状态拓扑是首要设计决策。判据：**多 agent 系统先选状态拓扑（共享黑板 vs 隔离 handoff）；并发写同 key 需显式 reducer/锁**。提升层：工作流。
2. **immutable state snapshots+append-only log：A 产 state v1 密封不可变，B 验 schema 匹配数据契约再处理，产 v2 insert 新行不更新 v1——状态可审计、可重放**（来源：zenml）——防覆盖。判据：**agent 间状态交接用不可变快照+append-only log；接收方先验 schema 再处理**。提升层：工具。
3. **handoff 三件套：handoff verifier（接收 agent 开工前轻量检查齐活——缝隙处抓缺）、per-hop 上下文预算（封顶+摘要，token 成本按 hop 计、尖峰当缺陷）、幂等可重放（每 handoff 记离散事件，失败 hop 单独重试）**（来源：syncsoft + peppereffect）——8-10 次 handoff 后上下文损失可测量（15-20% 长工作流降级）。判据：**每次 handoff 配验证器+预算+幂等日志；长链 handoff（8+）主动压缩上下文**。提升层：工作流。
4. **blackboard 模式判据：适用诊断推理/迭代规划/设计空间搜索（松耦合、可替换、读共享状态）；避免需清晰排序/问责时——控制流隐式、并发写需显式 reducer/锁；要求每 agent 写结构化更新（facts/hypotheses/decisions schema）不写不透明 prompt 历史**（来源：exploreagentic + future-of-software）——模式选择与审计。判据：**选 blackboard 前问"要不要清晰排序/问责"；黑板内容用结构化 schema 写入**。提升层：工作流。
5. **编排者三不：orchestrator 收顶层任务分解路由 subagent，自己不执行工具；分解错误级联全系统——不是省模型成本的地方（用 GPT-4 class/Sonnet/Opus 级）；supervisor 持高层目标防 worker 漂移**（来源：aiintegrator + knowlounge）——编排者成本与职责。判据：**编排者不亲执行工具；编排者用顶级模型，worker 可降档；supervisor 持有目标防漂移**。提升层：模型。
6. **传 structured artifacts 不传 raw context：共享 store 存任务结果与中间工件，agent 按需读+写结构化输出，无单上下文承载一切；拒绝把每个 agent 全转写串进下个 prompt（上下文爆炸+拖慢）**（来源：vibeengines）——工件化交接。判据：**agent 间交接结构化工件（schema 化结果），绝不拼接全转写**。提升层：工具。
7. **A2A+MCP 双协议覆盖协调栈：A2A 标准化 agent 间发现与任务交换，MCP 标准化 agent 调工具；A2A 前多 agent 通信各框架私有不可互操作**（来源：sudoall）——协议标准。判据：**跨框架多 agent 协作走 A2A；工具调用走 MCP；新框架评估先查 A2A/MCP 原生支持**。提升层：工具。
8. **模式-框架适配：Router（轻量分类器——LangGraph 或自定义代码，CrewAI 过度、AutoGen 错配）；Planner-Executor（LangGraph 状态机原生处理 plan revision/retry/partial completion）；Hub-and-Spoke 的失败模式=hub fragility+中心翻译损失，加 governance layer 缓解（防御 0.32→0.89）**（来源：internative + niteagent）——选框架=选架构模式。判据：**按模式选框架；hub-and-spoke 必须配治理层兜底路由失败**。提升层：工具。
9. **幂等是事件驱动前提：pub/sub 中 agent 发 typed event 到 topic、订阅者收到相关事件才反应——要求每 agent 幂等（同事件收两次安全）；所有 agent 动作幂等化+幂等键**（来源：alicelabs + innovativeais）——事件驱动安全。判据：**事件驱动或网络重试场景，agent 动作全幂等+幂等键；收两次与收一次效果相同**。提升层：工作流。
10. **框架成本对照（选型速查）：ReAct 低（$，1-2 周）；Reflection/Critic 低（$$，2-3 周）；Plan-Execute-Replan 中（$$，4-6 周）；Swarm/Blackboard 高（$$$，6-10 周）——模式复杂度决定成本与构建时间**（来源：weekonelabs）——模式成本预判。判据：**选模式前查成本对照（复杂度/运行成本/构建时间）；简单任务不上重模式**。提升层：工作流。
