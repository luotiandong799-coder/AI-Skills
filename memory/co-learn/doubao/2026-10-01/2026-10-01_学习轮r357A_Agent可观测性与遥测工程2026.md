## 独点（10）

**1. OTel GenAI 语义约定（跨框架可比的可移植遥测）**（来源：OpenTelemetry-CNCF 2026-05-14 + AWS Well-Architected AGENTPERF01-BP02 2026-08-19 + MLflow 2026-05-22 + IETF draft-wnd-opsawg-icon 2026-07-09 实拉）：OTel=portable substrate；GenAI semantic conventions 定义 LLM 操作/model/input-output tokens/request params/finish reasons 标准属性——span 跨 framework/model/runtime 可比；用约定而非框架特有 schema→telemetry portable（agent 在 Bedrock AgentCore Runtime/Lambda/ECS/EKS/self-hosted 间迁移）；四领域自动记录：System Context/Token Economics/Vector Retrieval/Agent Reasoning（gen_ai.request.model、gen_ai.usage.input_tokens/output_tokens）。判据：**遥测用 OTel GenAI 语义约定（gen_ai.system/operation.name/request.model/usage tokens）——vendor-neutral、agent 换运行时遥测仍可比；自建 span 属性也按此命名**。提升层：工具/工作流。

**2. span tree 三型结构（invoke_agent/chat/execute_tool）**（来源：AWS Bedrock AgentCore Evaluations 2026-08-26 + Microsoft Agent Framework 2026-09-19 + Tobias Weiss 2026-08-02 实拉）：span 分类从 gen_ai.operation.name——invoke_agent=每轮顶层 span（携带 user prompt+final response）/chat=inference span（读 message history+model reply）/execute_tool <function_name>=工具调用 span（function arguments+result 作 attributes，enable_sensitive_data 控制是否记录敏感数据）；"为什么停"（finished/tool-call limit/error out）只有 traces 能回答，log grepping 回答不了。判据：**agent 遥测 span 树=invoke_agent（每轮顶层）→chat（每 LLM 调用）→execute_tool（每工具调用）；工具参数/结果记录受 sensitive-data 开关控制；停止原因（限次/报错/完成）靠 trace 不靠 grep 日志**。提升层：工具/工作流。

**3. 先 tracing 后优化 + span 级成本归因（feature/user_tier/model/prompt_version 维度）**（来源：AI Workflow Lab 2026-02-16 + valuestreamai 2026-05-07 实拉）：先 tracing——不能优化看不到的（instrument 在干任何优化前）；span.set_attribute("user_tier") 等维度→cost 按 feature/user tier/model/prompt version/time window 聚合；per-feature ROI 分析而非 opaque total cloud bill；识别哪些 prompt version/agent step 不成比例贵；token-level cost attribution 数周内回本（暴露低效 prompt/不必要 context/runaway agent loops）。判据：**成本遥测=span 级（带 user_tier/feature/model/prompt_version 维度）按特征聚合 ROI；不做整体账单级**。提升层：工作流/工具。

**4. 输出 token 变异性成本尖峰（per-request cost by template 最可行动）**（来源：AI/TLDR 2026-06-12 + DevOps 2026-08-13 实拉）：output tokens 更贵且你控制更少（模型决定多啰嗦）——变异性创造成本尖峰；最可行动成本指标=cost per request by feature/prompt template（不是 total monthly spend——总额只告诉你账单）；system message 一次 copy edit 200→2000 tokens；token-level tracking per request type+每 workflow 平均 token 数实时可见+异常告警在累积成大账单前（账单到达时伤害已造成）；TTFT/total generation time 依赖 server load 多变。判据：**成本监控看 per-request cost by template（输出 token 变异性是尖峰源）；每 workflow 平均 token 实时告警，不等账单**。提升层：工作流。

**5. eval-as-observability（evaluator 结果附到 span + 采样 10-20%）**（来源：FutureAGI 2026-05-22 + MLflow 2026-05-22 + New Relic 2026-09-17 实拉）：AI observability 覆盖 eval scores——evaluator results（Groundedness/ToolSelectionAccuracy）attach 到 OTel-compatible spans；LLM-as-judge 采样生产流量 10-20%（质量覆盖 vs 评估成本平衡）抓幻觉回归在用户报告前；quality monitoring 自动化=第三支柱（tracing 先行→cost 从第一天→eval 采样自动化）；工具选型标准=tracing/span depth+quality scoring+cost by model/feature/user+integration effort。判据：**评估结果作为遥测附到 span（groundedness/tool-selection 分数）；生产采样 10-20% LLM-as-judge 抓回归，非 100% 全量**。提升层：工作流/工具。

**6. 四类 agent 输出监控（数据渗漏/有状态合规/内容合规/性能）**（来源：Microsoft Azure gateway monitoring 2026-09-18 实拉）：监控 model outputs 四用例——data exfiltration detection（分析输出防未授权敏感信息转移）/stateful compliance（跨同会话多次交互监控防 stealthy 累积泄漏——单次看不出跨轮才看出）/compliance（输出符合企业政策与法规——不提供法律建议/不做出财务承诺）/model performance（output+input 组合信号评估 groundedness）。判据：**输出监控四类：渗漏检测/跨轮有状态合规/内容政策合规/性能；单次合规不够——跨会话累积泄漏要 stateful 检测**。提升层：工作流/工具。

**7. 治理日志四件套（输入上下文捕获/决策链/输出/索引版本标识）**（来源：Openlayer 2026-06-29 实拉）：governance logging——input/context capture（exact prompt/retrieved context chunks/tool call parameters/preprocessing applied before model；retrieval index version identifiers 随请求记录→context drift 可追溯）；decision chain logging（每中间步 tool invocation/intermediate reasoning outputs/branching decisions；每步 timestamp+model version hash+trigger 下一动作的 output）；output 记录。判据：**治理日志=输入+上下文+决策链（每步带时间戳/模型版本 hash/触发输出）+输出；检索索引版本标识随请求记录以追 context drift**。提升层：工作流/可复用 Skill。

**8. 行为漂移检测基线（guardrail block rate / judge flag rate）**（来源：airuntimesecurity LOG-05 2026-09-19 + octopusbuilds 2026-04-20 实拉）：Behavioral Drift Detection——baseline metrics：guardrail block rate（per category/per time window——同时检测 model drift/policy changes/attack campaigns）、judge flag rate（per evaluation criterion——quality drift/emerging risks）；漂移按型分类——Behavioral（changed tool selection frequencies/altered planning patterns→execution trace comparison vs 历史基线）/Value（risk threshold breaches/policy violations in outputs→实时 value alignment scoring）/Context（context fidelity checks）。判据：**漂移检测基线=guardrail 拦截率（按类/按时窗）+judge 标记率（按判据）；行为/价值/上下文三类漂移各有检测信号**。提升层：工作流/工具。

**9. model version 上 span（provider 静默变更抓漂移）**（来源：mrgulshanyadav 2026-09-01 + MLflow production AI management 2026-06-27 实拉）：silent provider-side change 降级一个客户段——model version 在每个 span 上→版本翻转恰在 accuracy 下降时被看见；同 tool call 重试 5 次/对话账单翻倍——cost spikes tied to loops；agentic AI monitoring 与传统 model monitoring 不同——必须跟踪多步推理循环/工具调用/会话内状态迁移（silently fail 或 drift 出政策边界→级联错误在告警前）。判据：**每个 span 记 model version（含 provider 内部版本）——静默换版本时 accuracy 下降可归因；重试循环成本尖峰从 trace 查**。提升层：工作流。

**10. 签名审计轨迹（enforcement 副产品非事后日志+毫秒级时间戳+approver identity）**（来源：Lyzr OpenController 2026-09-24 + 极客公园 2026-10-01 实拉）：signed audit trail——每个 agent lifecycle event/model call/tool execution 时间戳到百分之一秒、每个 promotion 带 approver identity；不是事后查询的 log 而是 enforcement 的副产品已在 request path 里生成（记录 agent registration/version history pinned to source commit+container image/deployment）；agent 高自主性涉及数据增删改查高风险操作→在可控制/可回滚/可审计的数据沙箱运行。判据：**审计轨迹=签名+请求路径内生成（enforcement 副产品非事后日志）+毫秒级时间戳+promotion 审批人身份；版本钉 source commit+镜像；高风险数据操作在可回滚沙箱**。提升层：工具/工作流。
