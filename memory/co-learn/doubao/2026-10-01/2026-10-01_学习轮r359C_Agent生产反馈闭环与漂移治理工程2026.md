## 独点（10）

**1. 生产-评估闭环（offline eval→CI 门→生产 trace eval→Error Feed→优化→回 CI；静态端点漂移、闭环复利）**（来源：Future AGI 2026-03-21 + Microsoft Foundry 2026-06-03 + AWS AgentCore 2026-05-04 实拉）：agent eval 指南缺闭环=离线 eval 喂 CI 门、CI 门喂生产 trace eval、trace eval 喂 Error Feed、Error Feed 喂优化、优化回 CI——把 eval 当静态端点 agent 漂移、当闭环则复利；Foundry 四能力持续贯穿生命周期=Trace（每步端到端遥测：prompt/模型调用/工具调用/sub-agent hop）→Evaluate（单轮+多轮粒度质量/安全/任务完成评分）→Monitor（Azure Monitor 实时问题检测+告警）→Optimize（生产信号→排序的循证改进）；AgentCore 建议=分析生产 trace+eval 输出优化 system prompt/工具描述。判据：**闭环=offline eval→CI 门→生产 trace eval→Error Feed→优化→回 CI；静态端点漂移、闭环复利**。提升层：工作流/可复用 Skill。

**2. 纵向评估与能力漂移（质量=随时间变化信号非固定属性；滚动分 vs 基线统计距离）**（来源：Zylos 2026-04-14 + Chanl 2026-03-31 实拉）：longitudinal evaluation=跨时间测量 agent 能力（非单点）——组合软件工程回归节奏+ML 监控漂移检测+新一类生产反馈环（失败 live 交互转未来测试用例）——把 agent 质量当时间变化信号追踪而非发布时认证的固定属性；漂移检测=滚动质量分对比已知良好基线、算统计距离、超阈值告警；窗口选择是微妙处。判据：**质量=时间信号非固定属性；漂移=滚动分 vs 基线统计距离超阈告警**。提升层：工作流/可复用 Skill。

**3. 五种生产漂移（eval 集分布漂移→judge 对 live 流量低 15 分；人工抽查生产 trace 校准 judge）**（来源：Future AGI 2026-05-19 实拉）：agent 过 eval 挂生产的原因=漂移——eval 集 hand-authored/上线月流量采样，6 个月后真实用户俚语/多语码混/长 prompt/截图/连续追问数据集中没有；judge 对 curated set 校准→live 流量评分低 15 分；tell=生产 trace 抽查人工评分与 judge 分歧 15+ 分——步骤=手工评分生产 trace→与 judge 对不上→扩充/重新校准数据集。判据：**eval 集会漂移（分布漂移→judge 低 15 分）；人工抽查生产 trace 校准 judge**。提升层：工作流/模型。

**4. 四阶段门禁发布（Shadow 镜像弃输出→Canary 1-5%→百分比 t 检验门→Stable；写操作配策略模拟+幂等）**（来源：Future AGI 2026-05-20 + cordum 2026-06-01 + Microsoft Learn 2026-09-20 实拉）：四阶段门=1.Shadow（100% 镜像真实流量、丢弃输出+抑制副作用、零爆炸半径；eval 问题=候选在真实流量上是否行为迥异；门=per-rubric 分布 24-72h 内与生产差 ≤1 分）→2.Canary（1-5% live 分层；门=Containment*(1-False Resolution) 在基线噪声内）→3.Percentage（10/25/50%；门=per-rubric delta Welch's t-test p<0.05 vs 7 天基线）→4.Stable（持续监控后归档旧版本）；对写操作/工具调用的 agent=策略模拟+幂等重试+审批。判据：**发布=Shadow（镜像弃输出）→Canary（1-5%）→百分比（t 检验门）→Stable；写操作配策略模拟+幂等**。提升层：工作流/可复用 Skill。

**5. 无标注偏好表示（用户编辑成对：原输出弱拒/改后弱喜；内容寻址存储+质量过滤；客服四类实时标注）**（来源：Zylos 2026-06-02 + arXiv AITL 2510.06674 2026-10-01 实拉）：个人助手最可扩展偏好信号=用户编辑——改消息草稿/调日程/改代码片段→原输出弱 rejected、改后弱 preferred；实现=内容寻址存储映射 session ID→(original, modified) 对+质量过滤器（排除琐碎过短）；AITL 客服=四类实时标注集成 live 运营=成对响应偏好/agent 采纳决策与理由/知识相关性检查/缺失知识识别——直接喂回模型改进。判据：**无标注偏好=用户编辑成对（原弱拒/改弱喜）+内容寻址存储+质量过滤；客服反馈四类实时标注**。提升层：工作流/模型/可复用 Skill。

**6. 隐式信号集成（改写查询=失败、复制输出=成功、放弃会话=沮丧；hooks 持续采集结构化信号）**（来源：Zylos 2026-04-16 + aitechmonk 2026-05-31 + Agentimise 2026-04-13 实拉）：反馈环三阶段=显式收集（赞/踩+修正界面+满意度调查→有标签成功失败例子，月度跑+人工策展）→隐式信号（改写查询=失败信号、复制 agent 输出=成功、放弃会话=沮丧——远超显式规模）→生产遥测集成；hooks 观察+发出、channel observers 把 Slack 线程/支持工单/邮件归档解析成结构化信号记录——只做数据采集、持续不断（数据获取阶段不做分析）。判据：**反馈=显式（评分/修正界面）+隐式（改写=败/复制=成/弃=恼）；hooks 持续采集结构化信号**。提升层：工作流/可复用 Skill。

**7. 漂移检测管道（40-60 场景覆盖失败模式+滚动窗口统计距离告警；回答"是否随时间变差"）**（来源：Chanl 2026-03-31 + Zylos 2026-04-14 实拉）：生产 agent eval 三管道=场景维护（六个月实践后 40-60 场景覆盖所有失败模式）→漂移检测（跨窗口拉 scorecard 结果、算与已知良好基线统计距离、跨阈值告警——窗口选择是微妙处）→信号闭环；回答一个问题=agent 是否随时间变差；场景库滚动扩充防单一失败模式漏网。判据：**漂移管道=40-60 场景覆盖失败模式+滚动窗口统计距离告警；回答"是否随时间变差"**。提升层：工作流/可复用 Skill。

**8. 在线 eval 金丝雀（采样 judge+用户反馈+KPI+guardrail+成本异常多维；成本随规模真金白银→采样策略）**（来源：interpretai 2026-05-04 + AWS AgentCore 2026-09-11 实拉）：online eval=金丝雀（sampled judge scores、user feedback、business KPI deltas、escalation outcomes、guardrail triggers、cost/latency anomalies、input/output drift detection）；1M traces/天在线 judge 成本真金白银——即使 1% 采样用 frontier judge 也贵；去污染=agent 不被自己训练过的内容评分；AgentCore Evaluations=持续评分 live 交互抓错工具选择/任务失败/质量回归（基础设施指标看不见的）；组合 AWS DevOps Agent 自主基建事件调查。判据：**在线 eval=采样 judge+用户反馈+KPI+guardrail+成本异常多维金丝雀；成本随规模真金白银→采样策略**。提升层：工作流/工具。

**9. 反馈附接 trace（反馈作为 assessments 附到原始 trace 一起分析；改进过 eval 门才部署防回归）**（来源：Microsoft Learn Databricks 2026-05-06 + Arize 2026-05-01 + Wicked Smart Data 2026-08-19 实拉）：agent 上线后持续监控改进——真实使用暴露新行为/边界/问题；收集生产终端用户反馈→把反馈链接到具体 trace（作为 assessments 附着在原始 trace）→与模型行为一起分析；AI Gateway=guardrails/routing/一致 logging——每条新版本可在真实流量上评估无操作摩擦；Arize 闭环=生产 trace→富化数据集→改进（更新 prompt/微调/改工具配置）→对比算子验证修复有效且不回归其他维度→门禁部署（CI/CD gate 算子程序化强制、无未验证变更上线）。判据：**反馈作为 assessments 附到原始 trace 一起分析；改进过 eval 门才部署（对比算子防回归）**。提升层：工作流/可复用 Skill。

**10. 偏好记忆个人化三环（澄清→偏好记忆 grounding→反馈更新；垂直闭环=失败转 harness 更新权重冻结提 47 点）**（来源：personalized-ai 2026-05-13 + theairuntime Harvey 2026-05-02 实拉）：PAHF=持续个人化框架——agent 从 live 交互在线学习用显式 per-user 记忆；三环=①行动前澄清解决歧义②行动 grounding 在记忆检索的偏好③行动后反馈整合更新记忆（偏好漂移时）；四阶段协议评测（embodied manipulation+在线购物：初始学习→跨会话→偏好转移→扰动鲁棒）；垂直 agent 闭环=生产失败转 harness 更新（prompt/工具/sub-agent/记忆文件/judge rubrics/路由逻辑）——Harvey 12 个法律任务模型权重冻结平均成功 40.8%→87.7%（+46.9 点）。判据：**个人化=澄清→偏好记忆 grounding→反馈更新三环；垂直闭环=失败转 harness 更新权重冻结提 47 点**。提升层：工作流/模型/可复用 Skill。
