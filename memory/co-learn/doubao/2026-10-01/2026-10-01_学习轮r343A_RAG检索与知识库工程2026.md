## 独点（10）

1. **hybrid retrieval=BM25+dense+RRF 融合：dense 捕获语义、BM25 精确匹配专名/产品码/法律引用/罕见专名——生产上 hybrid 系统性优于纯向量；RRF(k=60) 归一化 dense 相似度与 sparse TF-IDF 尺度差异**（来源：memia + zalt + besthub2 + aclanthology）——检索基础。判据：**生产 RAG 默认 hybrid（dense+BM25+RRF）；纯语义在专名/标识符场景必漏**。提升层：工具。
2. **分块策略是最大被低估因素：默认 1000 字符/200 overlap 常败于结构化文档；生产甜点 200-500 token/chunk+10-20% overlap；semantic chunking 按自然边界（段落/节/标题）非字符数；表格必须在分块前抽出+带表头行（否则值丢列含义）；密集文档（医疗/法律）256、稀疏代码库 1024+**（来源：technologypulse + promtable + rajatgautam + theneuralbase + yuzec）——分块工程。判据：**分块按文档类型选策略；表格先抽+表头；chunk 大小随文档密度调（256-1024）**。提升层：工具。
3. **hierarchical chunking 多粒度检索：小块（200-500 token 精确检索）+中块（1000-2000 token 上下文）+文档摘要（50-100 token 高层匹配）——匹配小块返回周围中块：LLM 得精确相关性+足够上下文；parent document retriever 同理**（来源：aiexpert + kunalganglani + promtable）——多粒度。判据：**检索精度与上下文需求冲突时用层级分块（小块召回、中块返回）**。提升层：工具。
4. **每 chunk 前置上下文元数据（它在文档中位置/来源/标题链）——chunk 脱离文档后仍可溯源；EnsembleRetriever RRF：vector 第 1+BM25 第 3 > 两者都第 2（融合不是平均）**（来源：younggao + infosys variable size）——chunk 溯源。判据：**每个 chunk 带位置/来源元数据；多路检索用 RRF 不是简单平均**。提升层：工具。
5. **RAGAS 2026 事实标准四指标：faithfulness（答案是否源自检索上下文——最重要）、answer relevancy、context precision（检索 chunk 是否真相关）、context recall（检索是否覆盖回答所需）——各由小型 evaluator LLM 计算；faithfulness 阈值 ≥0.85**（来源：ailearningguides + futureagi + lobehub）——评测。判据：**RAG 上线前跑 RAGAS 四指标；faithfulness<0.85 视为不合格**。提升层：工作流。
6. **query rewriting 五补全各治失效模式：Minimal（消解指代/省略/自包含——多轮最新查询改写）、Corpus-Specific（适配领域术语）、HyDE（LLM 幻觉完美答案嵌入检索，绕过查询-文档措辞差异）、Step-back（先抽象概括再具体）、分解（复合查询拆多信息需求）——改写自包含后检索**（来源：arxiv 2603.10524 + google codelabs + kunalganglani + tencent）——查询理解。判据：**多轮/欠规定查询先改写自包含再检索；专名查询先扩展同义词/上下位词**。提升层：模型。
7. **agentic RAG 插两组件：retrieval grader（拒绝不相关 chunk 进上下文窗口）+ reflection loop（grounding 弱时重新检索）——幻觉率 12-18%→2.5-4%；传统 RAG 检索一次塞 prompt 赌 top-k 碰巧含答案（无自纠正/首检 miss 无法恢复）**（来源：syncsoft + dzone + galileo）——agentic 控制环。判据：**高准确率需求用 grader+reflection 控制环；首次检索 miss 时能重新检索而非硬答**。提升层：工作流。
8. **少 chunk 高质量优于多 chunk 混合：3-5 高质量 chunk 优于 8 个混合相关；rerank 后最高分 chunk 放最前不中间（lost-in-the-middle）；多 chunk 用 sandwich（最相关第一/支撑中间/次相关最后）；reranker 用 cross-encoder（top-20→top-5）**（来源：krunalkanojiya + google codelabs + lobehub）——上下文组装。判据：**检索 top-20、rerank top-5、最多喂 3-5 chunk；最高分放最前**。提升层：工作流。
9. **GraphRAG 适用判据：实体丰富语料（人物/组织/关系密集）——向量+知识图谱组合显著提升多跳问题精度；实体稀疏语料收益小不上图谱**（来源：ailearningguides）——图谱选型。判据：**多跳/实体关系查询多的语料才上 GraphRAG；纯文本知识问答 hybrid 足够**。提升层：工具。
10. **generation 侧三件套：结构化 prompt 带引用要求（citation accuracy 指标）、高 stakes 输出做 faithfulness 验证、context assembly 用 sandwich——RAG 质量=检索质量×生成纪律**（来源：ailearningguides + futureagi + krunalkanojiya）——生成纪律。判据：**RAG 生成要求逐句引用来源；高风险输出过 faithfulness 验证**。提升层：模型。
