## 独点（10）

**1. Agent Skill BOM（ASBOM，技能依赖闭包清单）**（来源：arXiv 2603.00195《Formal Analysis and Supply Chain Security for Agentic AI Skills》2026-05-21 + agent-bom PyPI 0.75.2 2026-03-24 实拉）：Agent Skill Bill of Materials=CycloneDX 1.6 兼容文档，记录 agent 依赖闭包内每个 skill——(s,v) 身份（skill name/version/format：Claude/MCP/OpenCl…）；AST 分析可从源码自动提取 system prompts/guardrails/tool signatures（LangChain/CrewAI/OpenAI Agents SDK 等 7+ 框架）生成 AI BOM；agent-bom 工具：发现 25 客户端类型的 agent+MCP server（从配置文件自动探测）、扫描 CVE 覆盖 15 生态。判据：**技能供应链用 ASBOM——agent 依赖闭包内每个 skill（名/版本/格式）结构化清单（CycloneDX 1.6）；AST 可自动提取 prompt/guardrail/工具签名**。提升层：工具/可复用 Skill。

**2. Slopsquatting 防御（幻觉包名 24-48h 抢注窗口）**（来源：DZone 2026-07-10 + Development Curated 2026-05-06 + runtimeai 2026-05-25 + CSA Shai-Hulud 2026-05-14 实拉）：AI coding agent 幻觉生成不存在的包名→攻击者在 24-48h 窗口内注册同名恶意包（slopsquatting）；防御三层——检测"低流量依赖却出现在生产路径"（low-traffic dependency in production path）+SBOM 生成与验证；威胁转向机器而非人（vibe coding 引入依赖发现漏洞）；TrapDoor 活动针对 Lang 系传播凭证窃取；TanStack npm worm（CVE-2026-45321 CVSS 9.6）7 分钟攻陷 42 包 5.18 亿+下载——用合法 OIDC-attested provenance 通过所有 SLSA Build Level 3 检查（劫持合法 GitHub Actions release pipeline）。判据：**新包名先查"是否幻觉产物+低流量却进生产路径"；抢注窗口 24-48h；provenance 证明本身可被劫持（合规证明≠安全）**。提升层：工作流/工具。

**3. AI-BOM 组件五类清单（模型/数据/微调/框架/评测）**（来源：CloudSEK 2026-09-18 + Glacis 2026-08-26 + Systems Hardening 2026-05-07 + KodeKloud 2026-07-24 实拉）：AI-BOM 记录每个生产组件——Base Model（ID/version/source repo/hash→provenance verification/backdoor detection）/Training Data（name/version/collection date/size→poisoning/licensing）/Fine-tuning Data（source/size/labeling process/filters→data poisoning/quality）/Framework（PyTorch/TensorFlow/CUDA version→vuln tracking/reproducibility）/Evaluation（benchmarks/metrics/test set provenance→performance/bias）；微调数据集须记录 SHA-256 digest of exact snapshot——不是 live reference（可能变的引用）；训练代码记录 Git commit SHA（完整可复现声明）；清单打破盲目——团队只防御他们知道存在的组件。判据：**AI-BOM 覆盖模型/训练数据/微调数据/框架/评测五类（CycloneDX ML-BOM 或 SPDX 3.0 AI profile）；微调集钉快照 digest 非 live 引用；训练代码记 commit SHA**。提升层：工具/工作流。

**4. 模型签名门控晋升（L1 记录→L2 签名→晋升门）**（来源：asleekgeek SBOM-signing 2026-06-26 + Systems Hardening 2026-04-04 实拉）：L1=训练任务把 dataset version/code commit SHA/hyperparameters/output artifact digest 记录为 run metadata 存进模型注册表（provenance 存在、任何人可读、无签名）；L2=训练平台用自己的 workload identity（keyless via OIDC）给 provenance attestation 签名；registry 晋升到 production-eligible stage 门控=有效签名存在——未签名模型不可晋升；训练后 cosign 签名（annotations 带 training_run/dataset_digest）、serving 前验证签名。判据：**模型晋升门=有效签名（L1 记录 provenance→L2 平台身份签名）；未签名模型不可 promote；训练后签名、serving 前验证**。提升层：工具/工作流。

**5. Sigstore keyless 签名（无长期密钥可泄漏）**（来源：IoT Digital Twin PLM 2026-06-28 + asleekgeek 2026-09-07 实拉）：Sigstore keyless 流=cosign 从 Fulcio 请求短期证书（绑定 OIDC 身份）→签名模型 digest→记录进 Rekor 透明日志；无长期签名密钥可泄漏；ML 有意义 SBOM=serving image（ML framework/CUDA/cuDNN/Python 依赖树）+模型工件声明依赖（Syft 产 SPDX/CycloneDX）；SBOM 签名附为 Cosign attestation 随工件旅行。判据：**签名用 keyless 流（Fulcio 短期证书绑定 OIDC 身份+Rekor 透明日志）——无长期密钥可泄漏；SBOM 作为 Cosign attestation 随工件**。提升层：工具。

**6. 依赖钉哈希（版本 tag 可伪造，hash 不可）**（来源：Systems Hardening 2026-04-23 + breachline 2026-05-27 + OWASP A03 2026-06-30 + GitLab 2026-09-22 实拉）：pin 每个依赖到精确版本+内容 hash——版本 tag 可 force-push、hash 不可伪造；go.sum 含每个依赖密码学 hash、每次 build `go mod verify`（失败 build 停）；Python `pip install --require-hashes`/`pip-compile --generate-hashes`（hash 不匹配 pip REFUSE）；`npm ci`/`yarn install --frozen-lockfile` 代替 install；commit lockfiles 并从它们安装；GitHub Actions 按完整 commit SHA 钉、不用 @v1/@latest（pinned digest 不能静默重指——TeamPCP tag-rewrite 败于此）。判据：**依赖钉到 hash 级（lockfile+CI 强制 verify——npm ci/pip --require-hashes/go mod verify）；Actions 按 commit SHA 钉不用可变 tag；hash 不匹配即 fail**。提升层：工具/工作流。

**7. 容器镜像 SHA256 pin + 上游静默污染防线**（来源：Docker 2026-06-08 + MatterAI 2026-07-28 + AquilaX 2026-03-19 实拉）：镜像按 SHA256 digest pin 不用 tag——:latest 基础镜像一夜之间上游变更静默流入 build；上游被攻陷或意外变更静默流入构建；构建系统拉依赖若 hash 与提交的不匹配 build 应失败；language 依赖 lockfile 钉精确版本并在 CI 验证 lockfile 完整性。判据：**镜像按 digest 钉不用 tag；构建验证依赖 hash 与提交一致，不符即 fail（防上游静默污染）**。提升层：工具/工作流。

**8. 部署时四证据门（cosign 签名+SLSA≥L2+SBOM 无禁用包+无 critical 漏洞）**（来源：Systems Hardening deploy-time policy 2026-05-07 实拉）：部署准入四证据——①镜像被预期构建管线签名（Cosign signature in OCI registry，证明来源、阻断直接推 registry）②SLSA provenance ≥L2（证明构建不可伪造可审计）③SBOM attached 且无 banned packages（SPDX/CycloneDX attestation，实时 license 与供应链策略执行）④漏洞扫描无 critical CVEs（Grype/Trivy 扫描 attestation，执行前最后防线）。判据：**部署准入=四证据门：签名（来源）/SLSA≥L2（构建）/SBOM 无禁用包（策略）/无 critical 漏洞（扫描）**。提升层：工具/工作流。

**9. PR 依赖审查（Dependency Review 阻断脆弱依赖）**（来源：HelpMeTest 2026-05-17 实拉）：GitHub dependency review action 在 PR 引入脆弱依赖时阻断合并；branch protection 四件套（require_code_owner_reviews/required_status_checks strict/require_signed_commits/enforce_admins）；security-scan+dependency-review 作 required status checks。判据：**依赖变更走 PR 依赖审查（脆弱依赖即阻断）；分支保护=所有者评审+严格状态检查+签名提交+管理员强制**。提升层：工作流。

**10. 模型供应链攻击面三入口（模型/数据集/推理依赖）**（来源：Systems Hardening attack surface 2026-04-04 + SDLC Corp 2026-09-22 + Preprints MBOM-PQC 2026-05-01 实拉）：AI 供应链攻击面=模型工件/数据集/推理依赖三入口；对策=配置+签名+验证三动作（训练后 cosign 签名带 annotations，serving 前验证）；model provenance=可验证证据（哪里来/谁产/怎么创建修改）——生产前看到 parent models/datasets/versions/licenses，不信任 publisher metadata；provenance（一个工件来源）vs lineage（血缘链）vs data provenance（数据来源）跟踪不同部分；MBOM-PQC 提出后量子安全签名扩展与 SCAMM 五级成熟度模型。判据：**供应链攻击面=模型/数据集/推理依赖三入口；provenance=可验证证据链（父模型/数据集/版本/许可证）不信任 publisher 元数据**。提升层：工作流。
