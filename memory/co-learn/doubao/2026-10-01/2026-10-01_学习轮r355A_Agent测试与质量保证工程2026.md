## 独点（10）

**1. 行为契约代替精确输出断言（非确定性 agent 测试第一原则）**（来源：Mahmoud Zalt《How to Test a Non-Deterministic AI Agent》2026-07-04 + CallSphere《Regression Testing: Silent Breakage》2026-05-05 实拉）：放弃精确输出断言→behavioral contracts——eval suites 查意图、LLM-as-judge 评分质量、trajectory checks 验证 agent 走了正确步骤（不管具体措辞）；"输出每次运行都变，行为不应变"；可测的断言形如 "Did the agent use the refund tool?"（用了退款工具吗），无益的断言形如 "Did the agent produce exactly this paragraph?"（逐字一致吗——每次都会变且多数变不是回归）。判据：**非确定性输出的断言层=行为契约（意图/步骤/不变量），不是精确文本——输出变是常态，行为不该变**。提升层：工作流。

**2. Golden trajectories 结构五件（2026 轨迹评测标准）**（来源：genai.qa《Agent Trajectory Testing 2026》2026-04-22 + Google ADK Codelabs 2026-04-16 + DeepEval ToolCallMatchMetric 2026-06-15 实拉）：golden trajectory=curated known-correct 多步执行轨迹，捕获五要素——①原始用户输入 ②预期工具调用序列（工具名、参数、中间输出）③步骤间预期状态迁移 ④预期审批门及 pass/fail 标准 ⑤最终输出；创建昂贵需 SME 逐条评审；典型回归检测=改 prompt 后 agent 突然不再检查"退款前资格"→轨迹不匹配；DeepEval 的 ToolCallMatchMetric 直接比对实际工具调用序列 vs golden 期望序列。判据：**黄金轨迹=输入+预期工具序列+状态迁移+审批门+终输出五要素；改 prompt 后轨迹不匹配即回归；工具序列匹配用结构化比对（工具名+参数）**。提升层：可复用 Skill/工作流。

**3. 评测三层指标 + 轨迹→测试套件闭环**（来源：slavadubrov《Agent Evals: From Traces to Test-Suites》2026-06-10 + eCorpIT 2026-07-16 实拉）：agent evals 三层指标——Outcome metrics（最终结果）/Trajectory metrics（过程轨迹）/Component metrics（单组件）；核心循环 trace→label→cluster→dedupe→versioned dataset→CI gate→online monitoring；确定性检查用于工具顺序/参数/循环/不变量；LLM-judge 只在检查依赖解释性判断处用（贵且慢不滥用）。判据：**评测三层（结果/轨迹/组件）缺一单独漏；闭环 trace→标注→聚类→去重→版本化集→CI 门→在线监控；确定性检查覆盖工具顺序/参数/循环，LLM judge 只在解释性判断处用**。提升层：工作流。

**4. 失败即测试（生产故障转永久测试用例）**（来源：AWS AgentCore dataset management 2026-05-28 + CallSphere golden dataset 2026-05-05 实拉）：测试用例作 versioned fixtures——场景=输入/期望输出/断言/工具序列；发布为 immutable numbered versions（run 期间不移位、不因后续编辑漂移）；draft 自由迭代、lock checkpoint 后锁定；生产故障=永久测试用例（"every future change gets evaluated against it"），下次任何变更都过一遍；golden dataset=versioned/auditable/evolving，从真实生产 traces 挖、领域专家标注、agent 以新方式失败时刷新。判据：**失败即测试——生产故障转永久测试用例；测试集 immutable 版本化（run 中不移位），draft 迭代 checkpoint 锁定；golden 集随新失败形态持续刷新**。提升层：工作流/工具。

**5. CI 四门（Assertions→Golden→LLM-judge→Baseline）**（来源：eCorpIT《4 gates that catch silent failures》2026-07-16 + Future AGI testing tools 2026-07-17 实拉）：四门顺序——①Assertions：确定性属性（schema、必需工具调用、成本与延迟预算、禁止字符串）②Golden set：小规模精选（核心特性、过去 bug、已知边界）③LLM-as-judge：语义质量（事实正确/完整性/语气——断言达不到的），仅边界情况挡 merge ④Baseline compare：本次 run 对比上次 marked-good run（逐评分器），回归时挡；pre-deploy gate=pass rate 阈值规则（如 no ship below 95%），读 report.pass_rate 机器自动失败，不靠人记得检查。判据：**CI 四门=确定性断言→黄金集→LLM 评审（仅边界挡合并）→基线对比（对上次 good run 逐评分器）；发布门=pass rate 阈值机器自动挡**。提升层：工作流/可复用 Skill。

**6. 评测沙箱纪律九条**（来源：Microsoft《Your AI coding agent evaluation is only as good as its sandbox》2026-09-16 实拉）：①定义要测的能力与 agent 可用信息 ②每次 run 干净工作区只含预期 fixtures ③中立工作区路径（不泄漏评测相关词——路径名不能带被测能力提示）④测内部知识时限制外部知识源 ⑤文件系统访问强制在工作区边界 ⑥所有可用工具同等限制（不偏心）⑦评审 surprise passes 与完整轨迹 ⑧为 agent 发现的每条新路由加回归探针 ⑨评测结果与生产指标并列可见。判据：**沙箱=干净工作区+中立路径（不泄漏评测词）+边界强制+工具同等限制+为发现的每条新路由加回归探针；surprise pass 必须审完整轨迹**。提升层：工作流/工具。

**7. 仿真环境三架构（保真/多样/解耦）**（来源：ClawsBench arXiv 2604.05172 + ComplexMCP arXiv 2605.10787 + AutoControl Arena arXiv 2603.07427 实拉）：ClawsBench=五个高保真 mock 服务（Gmail/Slack/Calendar/Docs/Drive）完整状态管理+确定性 snapshot/restore（测完恢复）；ComplexMCP=300+ 系统验证工具 7 个 stateful sandboxes，seed-driven 架构模拟动态环境状态+不可预测 API 失败（确定性又多样）；AutoControl Arena=logic-narrative decoupling——确定性状态用可执行代码落地、生成性动力学委托 LLM（减幻觉保灵活），三 agent 框架 98% 端到端成功、60% 人类偏好，变环境 Stress/Temptation 引出潜在风险。判据：**仿真三架构——mock 服务+快照恢复（保真）、seed 驱动模拟动态失败（多样性）、逻辑-叙事解耦（状态代码化+动力学 LLM，减幻觉保灵活）**。提升层：工具/工作流。

**8. Shadow mode CI（隔离生产环境依赖全 mock）**（来源：DevOps《Shadow Mode CI》2026-07-09 + rapidclaw CI/CD pipeline 2026-04-20 实拉）：agent 在隔离 production-like Docker 环境跑——相信在执真实工作流，但每个依赖 local/mocked/seeded/disposable；构建"将被 promote 的同一镜像"（不另造）；prompts/policies/tool schemas 打包为可部署产物（release control 下，不是松散的编辑文本）；CI runner 建临时 Docker 网络（agent 旁跑 mock tool APIs）。判据：**shadow CI=隔离 production-like 环境（依赖全 mock 且 disposable）、评测用将 promote 的同一镜像、prompts/策略/工具 schema 作可部署产物进 release 控制**。提升层：工作流。

**9. 发布四级阶梯与阈值（staging→shadow→A/B→全量）**（来源：HKU SPACE《Production Blueprint》2026-07-24 + RockB CI/CD 2026-06-19 实拉）：四级——①staging validation：合成流量对 staging 数据按需评测 ②shadow mode：真实生产流量并行（agent 无用户影响），至少 4 小时+2% 偏差阈值 ③A/B：5% 实时流量路由候选 agent 测真实结果 ④production rollout：100% 流量+连续在线评测监控；阈值参考=task completion CI 85%/prod 90%、grounded response 95%/98%、policy violations 0、regression delta 容差 0.05、cost regression block 15%/alert 10%；smoke eval（20-30 真任务无 mock）gate=completion rate drop>5 点。判据：**发布四级阶梯（staging 合成流量→shadow 并行 4h→A/B 5%→全量+在线监控）配每级量化阈值（完成率 85/90、grounded 95/98、违规 0、回归容差 0.05、成本涨 15% 挡 10% 告警）**。提升层：工作流。

**10. 容器与运行时安全评测（AI-vs-AI 攻防 + 可编程评分）**（来源：SandboxBench SPAR 2026 + AgentS4D arXiv 2607.27294 + EVMbench OpenAI 2026-02-18 + Azure Foundry 2026-09-25 实拉）：AI-vs-AI 攻击框架实测——defense-in-depth 100% 保护 vs baseline 70% 脆弱（社交工程+多轮攻击最有效）；AgentS4D 运行时安全四维=六风险入口来源×六诱导策略×九目标伤害指导案例构建、七生命周期检查点组织事后证据（328 risk-injected cases、4 harnesses×5 LLMs 20 组合）；EVMbench 程序化评分=交易重放+链上验证（Rust harness 部署合约/确定性重放/限制不安全 RPC）；工具维度三 evaluator=Tool Output Utilization/Tool Input Accuracy/Tool Call Accuracy。判据：**容器评测要 AI-vs-AI 攻防（社交工程/多轮最有效）；运行时安全按生命周期检查点组织证据；可编程评分优先（交易重放/链上验证）；工具级三维=输出利用/输入准确/调用准确**。提升层：工具/工作流。
