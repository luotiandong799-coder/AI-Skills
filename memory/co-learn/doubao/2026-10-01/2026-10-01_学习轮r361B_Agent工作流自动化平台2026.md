## 独点（10）

**1. Agent 节点最佳实践（工具描述清晰+迭代限制+详细指令+记忆平衡）**（来源：Dify 2026-08-27 实拉）：Dify Agent 节点最佳实践=清晰工具描述（帮助 agent 理解何时+如何有效用每工具）/适当迭代限制（防 runaway 成本同时允许复杂任务灵活）/详细指令（提供 agent 角色/目标/约束/偏好上下文）/记忆管理（按 use case 平衡上下文保留与 token 效率）。判据：**Agent 节点=工具描述清晰+迭代限制+详细指令+记忆平衡**。提升层：工作流/可复用 Skill。

**2. 多 agent 协调两种模式（并行执行快需聚合；层级 gatekeeper 路由简单自办复杂委托）**（来源：n8n 2026-01-08 实拉）：多 agent 协调=并行执行（多 agent 同时运行结果合并——比顺序快但需仔细结果聚合：一个分析情感另一个抽实体）+层级协调（gatekeeper agent 按意图/复杂度路由请求——简单直接处理、复杂委托专门化）；n8n 用 Execute Workflow 节点调子工作流。判据：**多 agent=并行执行（快需聚合）或层级 gatekeeper 路由（简单自办复杂委托）**。提升层：工作流/可复用 Skill。

**3. AI Agent Tool 委托（agent 作工具被调；单 agent+工具=顺序依赖输入，orchestrator+子 agent=分离技能域）**（来源：n8n 2026-06-09 + n8nlogic 2026-06-05 实拉）：多 agent 架构用 AI Agent Tool=orchestrator agent 接收初始输入决定做什么→工具列表含一个或多个 AI Agent Tool（配置第二个 agent 作为工具）；模式选择=单 agent+工具（行动顺序真依赖输入且不能硬编码时）/orchestrator+子 agent（有清晰分离技能域、各需自己 prompt/模型/工具集时保留）。判据：**AI Agent Tool=agent 作工具被调；单 agent+工具=顺序依赖输入，orchestrator+子 agent=分离技能域**。提升层：工作流/可复用 Skill。

**4. 守卫节点与慢操作隔离（守卫捕坏输入防长无用路径；慢操作隔离子工作流防阻塞）**（来源：n8n 2026-09-19 实拉）：AI 工作流延迟降低=守卫节点捕坏输入（防 agent 走长无用路径——配置检测违规如 URL/正则/密钥/PII 用占位符消毒，或全套守卫任何违规送 Fail 分支）；慢操作隔离子工作流（vendor API 8 秒等无法修复的慢步→隔离到子工作流不阻塞主流程）。判据：**延迟=守卫节点输入消毒+慢操作隔离子工作流**。提升层：工作流/可复用 Skill。

**5. 输出漂移修复环（收紧 prompt+示例+窄工具；每 run 日志；角色特定 prompt+JSON 输出+回退分支+执行上下文）**（来源：Chris Alarcon 2026-06-14 + GeekChamp 2026-05-23 实拉）：输出漂移=有时结构化有时散文；真实输入比测试输入脏；修复环总=收紧 prompt+加 1-2 个正确输出示例+窄化工具范围；无聊可靠性=任何计划保留的工作流每 run 日志到 Sheet/Airtable 表/Postgres 行/Notion 数据库；prompt 角色特定（triage/extraction/writing/action 分离比一个通用 prompt 好维护）；结构化输出 JSON 字段（intent/confidence/required_action/customer_message）验证后才继续；回退分支处理低置信度/缺数据/工具错误/限速/不支持请求；保留执行上下文（request IDs/user IDs/源记录/时间戳/工具）。判据：**漂移修复=收紧 prompt+示例+窄工具；每 run 日志；角色特定 prompt+JSON 输出+回退分支+执行上下文**。提升层：工作流/可复用 Skill。

**6. workflow 三阶段拆分（收集/推理/动作验证；pin 数据防调试烧信用；错误触发通知）**（来源：Synta 2026-06-28 + BigAI 2026-05-08 实拉）：AI 工作流拆分三阶段=context gathering/ inference/ action validation；Continue on Fail+重试环使 LLM 失败不污染下游数据；inference 前 Set 节点 pin 数据（调试不烧 API 信用）；单任务开始（越窄越可靠——避免一个 agent 做所有事）；System Message 指示 JSON 返回格式干净传下一节点；Error Trigger 节点失败发 Slack/email；pinned test（固定测试数据）。判据：**工作流=三阶段（收集/推理/动作验证）+pin 数据+错误触发通知**。提升层：工作流/可复用 Skill。

**7. Routines 三触发类型（timer 单次/recurring 排程/event 事件；排队+记录可查）**（来源：Microsoft Foundry 2026-09-24 + 2026-09-09 实拉）：Routines 自动化 agent=命名自动化规则在排程/特定时间/外部事件触发 agent；触发类型=timer（未来日期时间一次：发布日准备/截止提醒）/recurring（重复排程：每日摘要/周报/合规检查/积压审查/运营监控）/event（连接系统事件：GitHub issue triage/Teams 消息响应）；Foundry 排队调用、跑 agent、存 run record 后续可查。判据：**Routines=三触发（timer 单次/recurring 排程/event 事件）；排队+记录可查**。提升层：工作流/工具。

**8. 事件驱动延迟掩蔽与渐进信任（并行上下文填充响应防静默；信任随对话增量升级权限）**（来源：AWS Bedrock AgentCore 2026-08-26 实拉）：事件驱动延迟掩蔽=把感知延迟当一等设计关注而非优化每组件原始速度——agent 需调工具（如查可用性）时并行生成上下文填充响应（患者听自然确认而非静默）；渐进信任模型=认证与记忆访问随对话推进增量升级（非一开始全给）。判据：**延迟掩蔽=并行上下文填充响应；信任渐进=按对话增量升级权限**。提升层：工作流/可复用 Skill。

**9. Agent 生命周期四级环境（Dev 沙箱/Staging 合成数据+红队/Canary 减流量/Prod；promote 需 evals 通过）**（来源：COMPEL 2026-04-06 + Prefactor 2026-09-15 实拉）：Agent 生命周期=Dev（每开发者沙箱：全模型工具访问/无真实客户数据/每 commit 单测+小规模行为测试）/Staging（共享团队环境：合成或脱敏客户数据/全集成测试+小规模 golden-task 评测+每 RC 红队电池/记忆 store 非生产每部署重置）/Canary（生产环境减流量：真实客户数据）/Prod（全流量）；像软件一样 ship agent——版本化、分阶段、promote 只在 evals 通过（dev→staging→prod，schema 追踪）。判据：**生命周期=Dev 沙箱/Staging 合成数据+红队/Canary 减流量/Prod；promote 需 evals 通过**。提升层：工作流/可复用 Skill。

**10. 版本化审批门与评测门（自动门=单测/契约/基准/安全扫描；eval-gated 部署失败阻塞 CI；行为套件 50-200 用例≥95%）**（来源：Microsoft Learn 2026-08-11 + Alice Labs 2026-08-03 + OpenLegion 2026-07-01 + gorka 2026-06-19 实拉）：agent 版本化审批=基于变更风险评估的分层审批门——自动门无人工验证客观质量（单元测试工具集成/契约测试 agent 输出 schema 匹配编排期望/评测基准≥上一版 manifest 基线/安全扫描无凭证泄漏漏洞依赖）；任一门失败拒绝版本不部署；eval-gated deployment=LLMOps 工件（prompts/检索配置/模型提供商设置/评测阈值）全版本控制+同行评审+自动测试；LLM-as-judge 标准 CI/CD（确定性字符串比较不适用于 agent 输出）；失败离线 eval=阻塞 CI 检查；行为评测套件 50-200 固定输入输出用例（主要/边界/历史失败模式）→新版本须≥95% golden 通过率（任何安全关键测试失败=阻塞）；执行记录 prompt+workflow 版本、secret 不进 prompt、staging/prod 分离、回滚定义。判据：**版本门=自动门（单测/契约/基准/安全扫描）+eval-gated 部署（LLM-judge+失败阻塞 CI）；行为套件 50-200 用例≥95% 通过**。提升层：工作流/可复用 Skill。
