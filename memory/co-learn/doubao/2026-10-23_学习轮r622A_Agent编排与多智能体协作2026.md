## 四、提炼核心方法与关键事实

1. **编排形态与交接机制**：agent 即工具（嵌套节点互调，涌现行为取代全能单体）；子工作流打包（可预测路径/跨工作流复用→打包成可调工具）；三交接方式（subagents 委派读报告/dynamic workflows 写程序/advisor 咨询——宿主决定可用性 agent 决定时机）；一层嵌套上限+Conversation ID 续聊。
2. **动态工作流**：主 agent 写 JS 编排脚本传 Workflow tool 后台执行；并行/分阶段 spawn+结果变量+连接逻辑代码化；协调/启动/聚合职责下放——降主 agent 运行时负担。
3. **子 agent 折叠与拆分**：逐个折叠（prompts→skills+API→MCP tools）+翻转任务对比评估（不只总分）；单 agent 起步协调失败才加；三病拆分（context 过多/指令过多/难调试）+context overflow/capability sprawl/team boundaries 触发；每 agent 有 turns 预算。
4. **隔离与路由**：agentId 全隔离人格（账号+AGENTS.md/SOUL.md）；单实例多 agent YAML 路由矩阵（channel/user/group/keywords）；权限四件套（角色+边界+系统提示+沙箱路径）；gatekeeper 前置安全层（注入/脏话/PII 扫描，威胁即停）。
5. **编排者模式**：manager 评估委派/coordinator 只路由/lead 拆件扇出+并行合成；置信度路由（高→简单/复杂分流，低→人工评审）；每 agent 预算。
6. **多 agent 评估**：有无对比+翻转任务分布；组件级评估+错误分析优先序；单窗口串行 vs 多专用上下文并行合成的架构影响。
