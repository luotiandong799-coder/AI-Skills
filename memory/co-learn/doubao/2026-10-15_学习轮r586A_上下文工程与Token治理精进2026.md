## 二、核心方法与关键事实（带来源）

- **Token 预算分配基准表**：system prompt 5-15% / 工具 schema 10-40% / 检索文件 20-60%（最大杠杆）/ 历史 20-30% / buffer 5-15%（context-fundamentals/context-optimization 2026-09）
- **名义窗口≠有效容量**：200K 名义窗口 ~120-140K 开始退化，按 60-70% 当可用容量；超阈值是突降非渐降；~4 字符/token 启发式会漂移（context-fundamentals/zyvop 2026-08）
- **触发式优化非周期式**：token 利用率 >80% 触发压缩、总利用率 70% 阈值、attention degradation 信号（Agent-Skills-for-Context-Engineering）
- **max_tokens 按任务型**：分类/是否=10、事实查询=256、摘要分析=512-1024、长文生成=2048-4096；反模式=不设或一刀切（understandingdata/codex.danielvaughan）
- **Cost levers 量化排序**：prompt caching −70% input、semantic caching 60% hit −60%、model routing −42%、截断历史 −40%、精简 prompt −30%、限输出 −30%、batch −50%（varunsingla ai-tokenomics）
- **缓存生效三条件**：发射 cache-control 标记、TTL 扛住人类停顿、前缀字节稳定跨 turn；缓存写是满价 write 1.0×/read 0.1×（Cache Wars white paper）
- **提供商差异**：OpenAI GPT-6 起 ≥1024 token 前缀自动缓存、最高 90% 折扣、30 分钟复用窗口；Anthropic 显式 cache_control 最多 4 breakpoints、90% 折扣、TTL 5min/1h；Azure cache read 打折、Provisioned 最高 100%（Cache Wars/OpenAI 2026-09）
- **rollout_budget 跨线程记账（Codex）**：weighted_charge=sampling_tokens×sampling_token_weight+prefill_tokens×prefill_token_weight，默认权重 1.0，100K/会话硬顶+每 10K 提醒；解决 prefill（缓存/输入）影子消耗；63 生产事故复盘
- **task_budgets（Anthropic beta）**：模型可见的倒计时预算（Opus 4.7 起引入），覆盖思考+工具调用+工具结果+输出，模型据此优先工作优雅收尾；Gemini managed agents max_total_tokens（输入+输出+思考总量 cap，达限安全暂停）；Gemini thinking_budget 默认动态 ≤8192（软限制）
- **Missing Memory Hierarchy（arXiv 2603.09023）**：L1 上下文窗口是快小贵的一级缓存，缺 L2/缺分页/缺驱逐策略/缺工作集估算；实测 44.5 亿 token 中 21.8% 结构性浪费、陈旧内容 84.4× 放大重处理
- **TokenPilot（arXiv 2606.17016）**：PinchBench/Claw-Eval 连续模式降本 56-87%；Aether idle compaction=缓存过期前一小时对大型终端对话做空闲压缩、path-only 文件提及延后加载内容
- **Anthropic server-side compaction**：context_management 参数（input tokens 超触发阈值自动摘要）；instructions 参数完全替换默认摘要 prompt；client-side compaction 走 compact_20260112 edit + tool runner；三层实战组合=稳定前缀一个 cache breakpoint+尾部工具结果三个 breakpoint 每轮清放+cache-aware rolling buffer keep_n=3 interval=25+150K 触发服务端压缩+客户端截断保持两视图对齐；LLM-based compaction=先摘要整对话再丢旧图（保留做了什么/用户要什么/完成什么/从哪恢复+少量最近截图）
- **MCP/A2A token bloat 四问题**：重复 schema（GitHub 官方 MCP server 60 工具 9.84% 重复）、过量 optional、过长服务器响应、低效工具选择（IETF draft-chang-agent-token-efficient-01 2025-12）
- **ADOL 四机制**：JSON $ref schema 去重、tool/list --short 客户端条件省略 optional、requireOutput 让模型声明要的输出字段子集客户端过滤、语义/tag 双路检索式工具选择收敛工具暴露面
- **工具写法纪律**：description 按词边界截断、深层嵌套参数扁平化、删只复述参数名的描述、有默认值的 optional 参数从 schema 移除硬编码进实现、杀 <1% 调用率工具、稳定工具 def 放前缀让缓存摊销（dreaming.press/promptise/aipromptshub 2026）
- **Deferred Tools（jotoai 百炼账单 −88%）**：常驻工具+多 MCP server 完整 schema 可能比 system prompt 还大；Anthropic/OpenAI 原生支持 stub 只占 name，tools 数组每请求字节相同→前缀缓存永远命中，完整 schema 按需读取
- **Toolgz Level-3**：整工具列表换成 2 个 wire-level 工具+system prompt 紧凑查找表，80% 削减，4 frontier models 保调用正确
- **GitHub Copilot 成本效率四法**：保留有用上下文同时削减重复输出/删无价值格式/缩短指令不改有用行为/后台完成工作免额外检索步；Copilot 实测 −62%（剪未用 MCP 工具+用 CLI 替换 MCP 调用+每日审计优化 agent）；/context 可视化细分明细、/compact 手动压缩、95% 触发自动压缩、--resume 恢复；SWE-Pruner 自适应用户感知式裁长代码上下文（arXiv 2601.16746）；百万窗口与 reasoning level 按复杂度选
- **virtualme 降级顺序（034-agent-context-budget spec）**：预算不够时 ①只留最近 4 轮工具轮 ②旧普通工具结果裁到前 512 字节 ③删更老工具轮；预留 512 token 模板误差+≥1024 completion
- **OpenClaw**：compaction enabled/reserveTokens 16384/keepRecentTokens 20000/reserveTokensFloor 20000 安全下限；contextTokens cap 低于模型全窗口（Claude 32-64K 合理）提前激进压缩；bootstrap 截断 20000 字符/文件+150000 字符总量≈50K token，/context list 显示 raw vs injected 并标截断；CLAWVM=预留输出/system/schema/安全余量后剩余容量=paged state 预算，resident set 满足 minimum-fidelity invariants，typed pages+multi-resolution 降级+生命周期边界提交脏状态；NO_REPLY silent token 门（2026.1.10+ 流抑制修复）
