## 本批独点（真独点，双键查重通过）

### ctx 系（并入 wb-context-compressor）
1. **checkpointer vs store 分工**：checkpointer=线程内短期记忆（图状态快照、对话连续/HITL/时间旅行/容错）；store=跨线程长期记忆（用户偏好/事实/共享知识，custom namespace）。MemorySaver/InMemorySaver 不跨重启（生产用 PostgresSaver/SqliteSaver）；PostgresSaver 的 thread_id 需 <255 字符；checkpoint 会无限累积需定期裁剪（cron 删 N 天前）；subgraph 各自独立 checkpoint namespace，跨图共享数据走 Store。
2. **semantic memory 的 profile vs collection 取舍**：profile=单个持续更新 JSON（越大越易错、需严格解码或 JSON patch）；collection=逐条新增（LLM 更易生成新对象、下游召回更高，但删除/更新/检索复杂、模型有过度插入或过度更新倾向）；episodic=few-shot 示例按输入检索注入；procedural=reflection/meta-prompting（当前指令+近期对话/反馈自我改写并存回 store）；写记忆分 hot path（实时但增延迟）与 background（解耦但频率需设计）。
3. **记忆四文件分工 + 偏好就地 supersede + 压缩前记忆冲刷**：USER.md（用户模型层，指令式、带观察日期与 active/superseded 元数据，偏好改变时**就地 supersede 而非追加矛盾指令**）/ MEMORY.md（长期、会话启动加载）/ memory/YYYY-MM-DD.md（工作层、不注入 bootstrap 每轮、只索引检索）/ DREAMS.md（梦境评审）；compaction 前自动跑静默轮提醒保存重要上下文到记忆文件（memory flush）。
4. **compaction 工具配对保真 + safeguard 质量门 + overflow 恢复不重放**：split point 落在工具块内时移动边界保持 tool call 与 toolResult 配对；safeguard 模式审计摘要质量、无效则停止写入口保留原历史；provider 拒绝请求时从已记录的工具结果继续，不重放已完成动作；CJK 字符计入 chunk 估算；图片省略用 `[image data omitted]` 标记不假装处理过。
5. **上下文三中间件分工**：SummarizationMiddleware（溢出前压缩）/ MemoryMiddleware（启动加载持久指令）/ SkillsMiddleware（按需表面领域知识，不全部 upfront 加载）——总结/记忆/技能三分工。

### ed 系（并入 wb-execute-discipline）
6. **interrupt 动态中断纪律完整版**：resume 时节点**从头重跑**→中断前副作用必须幂等（upsert 而非 create、副作用放 interrupt 后、或拆独立节点）；**不要用 try/except 包 interrupt**（会吞中断异常）；同节点多 interrupt **严格索引匹配**（不重排、不条件跳过、不用非确定性循环逻辑）；payload 必须 JSON 可序列化（不能传函数）；校验循环（interrupt 循环直到输入有效）；静态 breakpoint（interrupt_before/after）只用于调试不用于 HITL。
7. **return_direct 批量语义 + Command 写状态 + 返回类型三选一**：同批并行工具调用**全部** return_direct 才短路，混合批全部结果送回模型；工具写状态用 Command 且必须配 ToolMessage（tool_call_id 匹配，否则 ValueError）；工具返回三选一：string（人读文本）/ object（结构化供推理）/ Command（写状态）。
8. **并行工具调用多 handoff 冲突**：模型并行工具调用可能同时生成多个 HandoffMessage，需禁用 parallel_tool_calls 规避（AutoGen Swarm）。
9. **检索块与合成块解耦**：embed 句子/摘要（小块检索）→ 链接到大窗口/文档（大块合成）；small-to-big / auto-merging 检索；metadata filters + auto-retrieval（LLM 推断过滤条件）处理大规模文档集。
10. **trace/event 双 logger 分工**：低层 trace logger（逐消息/运行时事件）与结构化 event logger（agent 间消息）分开记录（AutoGen）。
11. **query engine vs chat engine 判据**：单问无状态用 query engine；多轮对话需历史上下文用 chat engine（stateful）。
12. **声明式管线 vs 命令式代码**：QueryPipeline 声明式链/DAG（少样板、可读、可序列化、回调可观测）vs 命令式手写编排——复杂度低时命令式更直接。

### sa 系（并入 wb-skill-authoring）
13. **Agent Skills 渐进式披露三阶段**：Discovery（启动只加载 name/description）→ Activation（任务匹配才读完整 SKILL.md）→ Execution——大量技能可常驻只占小上下文。
14. **CLAUDE.md 精简判据**：每条指令问「删掉会导致犯错吗」，不会就删；文件过长规则被淹没=规则失效；可按 @import 拆分（docs/git-instructions.md 等）。
15. **ACI 工具设计五则 + poka-yoke**：工具定义投入如 HCI；给模型足够 token 想清楚；格式贴近自然文本（diff 难写、JSON 转义开销大）；避免格式开销（如行数计数/转义）；poka-yoke 参数（改成难犯错的形态，如绝对路径替代相对路径——SWE-bench 实测绝对路径零失误）。
16. **审稿新鲜上下文 Writer/Reviewer 双会话**：评审用全新 context 避免对刚写代码的偏见；两轮修正失败就 /clear 重开（不继续污染上下文）。
17. **知识分级预载**：agent 级知识（角色专用）vs crew 级知识（全员共享）独立 collection；预载知识不需要 retrieval persona/task；results_limit + score_threshold 控制召回。
18. **/btw 弹出式问答不进上下文**：快速查细节的答案显示在可关闭浮层、不进入对话历史，检查细节不增长上下文。
