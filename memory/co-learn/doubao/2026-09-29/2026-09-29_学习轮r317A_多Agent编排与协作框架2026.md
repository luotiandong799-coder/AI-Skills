1. **多 Agent 框架选型表**（来源：devdigest 2026-05 + langchain frameworks 2026-06 + groovyweb 2026-06 + alicelabs 2026-05 + mslearn 2026-08，增量合 r315C 五种编排模式点）——**按场景选框架：显式控制流+可调试状态机→LangGraph（state graphs：nodes=agent 调用，edges=条件转移，state object 流经图——先画工作流再写代码）；role-based teams+shared memory→CrewAI；对话协调→AutoGen/AG2；客服 handoff→OpenAI Agents SDK；Google Cloud→ADK；dev 工作流→Claude Code 原生 sub-agents；多数团队从 raw API 起步别急着上框架**；**五模式：sequential（A→B→C 线性）/parallel（并发合并）/hierarchical（manager 委派 specialists）/state-graph（LangGraph 状态节点）/swarm（对等协作）——按任务是否有自然顺序/能否独立/是否有权威/是否要显式状态管理选**。判据：**先按任务形状选模式，再选框架；supervisor 模式是多数 enterprise 起点**。提升层：工具。

4. **supervisor-worker mesh：窄工具面委派**（来源：autonode 2026-06 + groovyweb 2026-06，增量合 r315C 共享知识层/按技能建 agent 点）——**生产赢家架构不是 star 拓扑一个 mega-agent 干所有：轻量 orchestrator agent 持 task state 委派 specialized sub-agents，每个 sub-agent 拥有窄工具面（own a narrow tool surface）；orchestrator-workers 与 parallelization 区别=subtasks 运行时动态定（orchestrator 决定"改 auth.py/create login.html"）而非预定义**。判据：**每个 sub-agent 的爆炸半径=它的工具面；窄工具面+轻 orchestrator 比 mega-agent 稳**。提升层：工作流。
5. **Swarm/黑板协作：环境痕迹优于消息**（来源：zylos swarm 2026-05 + agentpatternscatalog 2026-06 + decodethefuture 2026-05 + max-gherman 2026-08 + codefinity 2026-03 + openlegion 2026-05 + lovex MIT 2026-09 + arxiv Agensh 2026-09）——**swarm=peer agents 自主无全局视图，协调通过 shared environment（blackboard/job queue/pheromone store）；适合并行可变结构/自适应负载/韧性（web crawling/分布式代码分析/大规模标注/仿真）；无单点故障+专业分工**；**blackboard 实现：共享数据结构（vector store/Redis/SQLite WAL+pub-sub），agent 发现信息"pin"到黑板，其他 agent 监控自主捡起（Agent B 看到 Agent A pin 的 raw dataset 自主决定清理）——收敛（convergence）是难问题**；**MIT SwarmWorld 实证：几百 identical agents 无角色无消息，靠 shared environment 留下的 traces 协调建起社会——留下环境痕迹优于 agent 间聊天**；**Agensh=1,024 agents：shared workspace+message interface+shared context，self-organized workers 认领子任务+交换发现+整合贡献，无 central orchestrator**。判据：**inherently parallel 任务才用 swarm；协调走黑板不靠消息风暴**。提升层：工作流。
6. **共享状态四异常与并发纪律**（来源：agentpatterns 2026-09 + dev tamizuddin 2026-09 + techrxiv 2026-07 + vectorize 2026-06，增量合 r315C 接口契约/不可变中间产物点）——**多 agent 共享可变 memory/tool registry 命中四并发异常：stale-generation（旧代读写覆盖新代）/phantom-tool（幻影工具）/causal-cascade（因果级联）/tool-effect reordering（工具效应重排）——除非写入带隔离纪律；无版本/乐观并发控制的 shared state：Agent A 读→计划→被抢占→Agent B 写→A 恢复写覆盖 B——两个 agent 都以为状态是自己的**；**修法=versioning+optimistic concurrency control；最简单 MAS 机制=serialized turns（固定顺序 one at a time 各读各写）**；**scope-composing retrieval：agent 查询时指定 scopes（user/agent/session/org），检索按 scopes 组合——research agent 的私有观察不泄漏到 sibling**。判据：**共享状态必须带版本控制；拿不准并发就 serialized turns；按 scope 隔离读写**。提升层：工作流。
7. **多 Agent 失败模式：预算/熔断/上下文漂移**（来源：swarmsignal 2026-03 + exploreagentic 2026-06 + zenml 2026-09 + agentcorps 2026-06 + sudoall 2026-06 + newsletter agentbuild 2026-05 + devstacktips 2026-09 + arxiv channel-fracture 2026-08）——**14 种失败模式三聚类：system design（41.8%）/inter-agent misalignment（36.9%，最该担心——agent 失去共享上下文/误读 peer 输出/把未验证 peer 工作当完成）/task verification（21.3%）**；**三大生产失败：turf war（角色边界重叠）→per-agent resource isolation+每 agent 恰好一个不重叠职责；handoff failure（数据丢失/格式不兼容）→先定义 handoff protocol 含失败模式；shared state contention（最难查——looks like agent problem 直到 trace writes）**；**成本爆炸：递归 spawn/chatter loop 无界账单→orchestrator 硬 token/dollar 预算（gateway 层也可）超限 abort；lost-in-the-middle/context poisoning→forward summaries+保持 context 不相交**；**circuit breaker：fail fast（不轰炸失败 agent 防级联）→60s 后 half-open 单请求试探→成功 close/失败 reopen**；**context desynchronization：Researcher 分析 50 页 PDF 只传 outline 给 Writer→Writer 编造细节——传摘要同时给 source access 或关键 chunk**；**sub-task 委托缺 dedup/depth-limit→无界 spawn；修法=parent task idempotency hash 引用+深度限制**；**channel fracture：scheduled (cron) agents 因硬编码 memory isolation guards 静默无法写入目标 agent 持久记忆——与我们自己的 cron 学习体系直接相关，注意隔离守卫与调度写入冲突**。判据：**预算/熔断/幂等三件套先装再跑多 agent；交接必须带 source access 不只带摘要**。提升层：工作流。
8. **Agent 记忆五层存储映射与 checkpoints**（来源：zylos memory 2026-05 + aws s3 vectors 2026-06 + makeanapplike 2026-07 + aiorbitx 2026-08，增量合 r315B 记忆分层点）——**存储映射表：episodic（跨会话时间戳事件日志）→time-series/vector DB；semantic（提炼事实+偏好）→vector DB with HNSW；knowledge graph（实体/关系/temporal edges）→Neo4j/Graphiti；procedural（技能/可复用工具调用模式）→key-value/structured store；checkpoints（agent 状态快照恢复）→S3/filesystem**；**episodic vs semantic 分开 namespace 防检索返回重复对话 chunk 而非相关事实（episodic='what happened' append-only log；semantic='what is true'）**；**多 agent 三层记忆：working（context window 会话内短暂）/individual long-term（跨会话个体）/shared multi-agent memory（多 agent 读写 task state/成果）**。判据：**按记忆类型选存储后端；checkpoint 快照是长任务恢复的底线；多 agent 共享层单独设计**。提升层：工作流。
