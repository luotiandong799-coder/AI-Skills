## 独点（12）

1. **重复→确定性脚本 meta-prompt**（来源：chatbotx 2026-04 + spunk 2026-05 + aimadetools 2026-04）——**第二次重复意味着第三第四次——每次付 LLM token 成本浪费——转 deterministic script/lightweight function**；**meta-prompt（每周跑一次）："Based on the tasks you've completed for me this week, which 3 workflows are good candidates to be codified into scripts or functions? Explain why each one qualifies."**；**模式选择（spunk）：Single Agent（Swiss Army Knife）是 solo founder 起点——复杂度/预算/自主度决定架构，不 one-size-fits-all**。判据：**同一工作流第二次重复即评估转脚本；周度 meta-prompt 主动挖 codify 候选**。提升层：工作流。
2. **A2A 能力广告与中间件路由**（来源：piotrdelikat 2026-08）——**agent 通过 JSON-LD schema 广告能力：{"agent_id", "output", "schema"}——middleware（n8n）消费 schema 路由到目标 agent**；**context passing=输出 schema 契约化，下游 agent 知道能收到什么结构**。判据：**agent 间交接=结构化 schema 契约，中间层按 schema 路由**。提升层：工作流。
3. **个人 stack 四分类与起步法**（来源：agent-finder 2026-09 + aimultiple 2026-08 + sista 2026-06）——**四分类：research agents（信息收集）/scheduling agents（日历管理）/automation agents（重复工作流）/knowledge agents（笔记组织）**；**起步法：start with one category→automate one high-friction task→then expand（单个高摩擦任务起，不一次全上）**；**Zapier 连接层模式：8000+ apps 连接，确定性工作流保持可靠，唯一需要判断的步骤交给模型**。判据：**个人自动化=一类别一高摩擦任务起步，验证后再扩**。提升层：工作流。
4. **smolagents Python-native agent**（来源：agentify 2026-07 + andrew 2026-04 + geekchamp 2026-05）——**HF smolagents（Apache 2.0 v1.26，~1000 行）：agent 直接写并执行 Python 而非 JSON tool calls——steps 减少 ~30%，去掉抽象层**；**code execution sandbox 集成；ReAct loop+maxSteps 链推理**。判据：**工具调用密集的轻量 agent 用 code-first 库（Python native）比 JSON tool-calling 省 step**。提升层：工具。
5. **Hooks 五类型与确定性信任模型**（来源：claude.com steering 2026-06 + code.claude.com features-overview ×3 + businesstechnavigator 2026-08 + wowhow 2026-05）——**hooks 五类型：command/HTTP/mcp_tool 确定性触发；prompt/agent 用 Claude 判断**；**注册位置：settings.json/managed policy settings/skill 或 agent frontmatter**；**hooks 低上下文成本（只执行不常驻窗口）**；**关键信任差异：hooks move enforcement out of the model and into the harness——hooks 由事件确定性触发（无论模型说什么），其他所有方法依赖 LLM 遵守指令**。判据：**必须执行的自动化用 hooks（确定性），依赖判断的用 prompt/agent 型**。提升层：可复用 Skill。
6. **Hook 事件清单与适用判据**（来源：腾讯云 2026-04 + claude.com subagents 2026-04）——**事件：PreToolUse/PostToolUse/Stop/SessionStart/SessionEnd/PreCompact（压缩前保留关键信息）/UserPromptSubmit/SubagentStop（子任务完成度验证）/Notification（权限请求/空闲提示桌面提醒）**；**适用判据：每个 commit 自动评审/安全检查无需有人记得/CI-like 质量门进本地开发流程**。判据：**PreCompact hook 保关键规则；SubagentStop hook 验子任务完成度**。提升层：可复用 Skill。
7. **个人财务 agent 模式**（来源：uniclaw 2026-04 + flaex 2026-03 + domywork 2026-08）——**五步：扫描邮件 bills/receipts/subscription notices→CSV 记账（数据自己控制）→跟踪循环收费续费前提醒→月度比较 flag 异常→周报**；**分类规则化（"Amazon.com"→"Shopping"）+autonomy=background read-only access**；**KYC 续期串联：重命名请求发 Gmail+更新 Sheets+5 天 follow-up task+合规 Slack——多系统单 agent 串联**。判据：**个人财务 agent=只读后台+规则分类+续费提前量+周报**。提升层：工作流。
8. **触发式个性化邮件 2.5×**（来源：alexander 2026-03 + echelon 2026-04 + n8n templates 2026-05 + calbot 2026-03）——**触发式个性化邮件 open rates 18%（batch）→35-45%（triggered personalized）——2.5× 提升**；**费用审批链：Email/Slack intake→GPT-4 Vision 读 receipt→policy rules engine→Accounting API→Slack 通知（省 6-10h/月）**；**draft-and-approve 模板：monitor→draft→human approve（人保留最终确认）**。判据：**邮件/通知类=事件触发+个性化（非批量）；涉钱动作保留人审**。提升层：工作流。
9. **Skill frontmatter 硬规范与 description 三要素**（来源：platform.claude.com agent-skills best-practices 2026-09 + anthropic complete guide + support.claude 2026-07 + skillmd 2026-06）——**硬规范：name ≤64 字符（小写字母/数字/连字符，禁 XML 标签，禁 reserved words anthropic/claude）；description 非空 ≤1024 字符禁 XML**；**description 三要素：what it does AND when to use it+trigger phrases（"sprint"/"Linear tasks"/"create tickets"）+clear value proposition**；**5 原则：keep it focused（多个聚焦技能比一个大技能好组合）/clear descriptions/incremental tests/examples/start simple**；**目录结构：SKILL.md+scripts/（可执行）+references/（按需载入）+assets/（模板图标字体）**。判据：**description=what+when+trigger 三件套；一个技能一件事**。提升层：可复用 Skill。
10. **自由度原则与 skill-creator 迭代流程**（来源：skillmd agentskills 2026-07 + agenticskills skill-creator 2026-04 + skilld）——**include only context it doesn't have（技能里只写模型没有的上下文）；set appropriate degrees of freedom——高自由度开环任务（creative）/低自由度脆弱操作（精确格式/财务）**；**use workflows for complex tasks（clear sequential steps+checklists 让 agent 可靠完成多步）**；**implement feedback loops（结果反馈回路）**；**skill-creator 流程：decide→draft→test prompts→claude-with-access-to-skill 跑→qualitative+quantitative 评估→后台补 quantitative evals**。判据：**自由度与任务脆弱度匹配；新技能=草稿→测试 prompt→双维评估迭代**。提升层：可复用 Skill。
11. **Rule of Three Passes 与 exit conditions**（来源：lobehub agentic-patterns 2026-09 + agentpatterns 2026-06 + practical guide 2026-09 + knowlee 2026-05）——**五支柱：Decompose/Orchestrate/Recover/Manage/Assess；Rule of Three Passes（scope→subtasks→dependencies）把问题拆 3-7 步+确定并行性+定义 exit conditions**；**四结构模式：sequential chains（严格依赖）/parallel fan-out（Scatter-Gather/Orchestrator-Worker）/staged pipelines/supervisor coordination**；**run=loop till exit condition（tool calls/structured output/errors/max turns）**；**编排起点：sequential pipeline（defined repeatable）→supervisor/worker（动态分解）→HITL/kanban（consequential real-world actions）**；**先问 single optimized LLM call（with retrieval and examples）是否够——predictable patterns（Prompt Chaining/Routing/Parallelization）vs model-driven（Evaluator-Optimizer）**。判据：**拆解=scope/subtasks/dependencies 三遍；每次 run 必须定义 exit condition**。提升层：工作流。
12. **Boris 四习惯与单 agent 扩展优先**（来源：ranjankumar 2026-04 + practical guide 2026-09 + reinventing 2026-09）——**四习惯：Delegation（像 brief 工程师一样 brief Claude——Plan mode first then auto）/Parallelism（5 worktrees round-robin——等待 Claude 的延迟归零）/Automation（手动跑=跑太慢）**；**单 agent 先扩工具：incrementally adding tools 保持可管理简化评估维护——每新工具扩能力，不必过早编排多 agent**；**三层架构：perception（视觉/文档解析/API 理解输入）/reasoning（LLM 决策规划异常处理）/action（API/DB/UI 执行）——分离可独立升级**。判据：**先单 agent 加工具，能力不够再编排；并行=多 worktree round-robin**。提升层：可复用 Skill。
