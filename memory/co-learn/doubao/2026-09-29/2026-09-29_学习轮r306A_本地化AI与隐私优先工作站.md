## 独点（12）

1. **本地推理引擎选型阈值：Ollama vs vLLM**（来源：dev.to ollama-vs-vllm 2026-06-02 + markaicode local-ai-production 2026-07-27 + aimastery 2026-07-03）——**~10 并发/GPU 以下：Ollama 单进程（llama.cpp 包装，桌面/边缘/单用户，低成本、无排队头寸）；~10 并发以上：vLLM（PagedAttention+continuous batching 集群层）**；Q4_K_M 是最佳平衡量化；**OpenAI-compatible API 让你自由切换后端**（本地与云端同代码）。判据：**先按并发量定引擎，再按显存定量化，最后靠 OpenAI 兼容接口保切换自由**。提升层：工具。
2. **量化>参数 + 量化分级阶梯**（来源：specpicks small-model-failure 2026-04-30 + contracollective m5-max 2026-05-24 + ai4u 2026-08-04）——**q5_K_M 比 q4_K_M 工具调用准确率高 ~6 点，超过 8B→13B 参数差距——量化档位比参数量更值钱**；**Q5_K_M 保留 ~99.5% 模型能力，生产推荐；Q6_K 接近 FP16 但收益极小，仅 Q5 失败才用**；量化省 40% 电、+5-15ms 延迟、INT8 1-2% perplexity 损失（输出几乎不可见）。判据：**升档位（q4→q5）优先于换大模型，成本几乎为零**。提升层：工具。
3. **grammar-constrained sampling 质量悬崖**（来源：specpicks rtx-3060 2026-06-19 + blog.redlinesoft 2026-08-19 + thenerualbase 2026-04-22）——**7B 级开源模型+grammar-constrained sampling：工具调用 JSON 有效率达 95%+；无约束只有高 70s-80s——质量悬崖完全是工程选择不是模型限制**；Gemma 4 原生 function calling + constrained decoding 让结构化输出生产可用；**工具调用结构完整校验后再用（validate structure + 可解析参数，不可靠时 fallback 策略）**。判据：**本地模型结构化输出差？先上约束解码，别急着换模型**。提升层：工作流。
4. **本地小模型失败模式 #1 = tool-call hallucination**（来源：dev.to pitambarmahato 2026-09-07 + promptquorum 2026-09-01）——**约 38% 小模型 agent 失败源于无效工具参数而非烂代码**；Llama-3.2-3B 恢复正确率 48%、**31% 时间幻觉出"修复"**（编造错误响应不支持参数改动，对 coding agent 是毒药）；Qwen3 恢复 65%；Llama-3.3-70B 最高可靠（~97% 良构调用）。判据：**小模型接工具前先测"错误恢复率"，幻觉修复率高的模型不能进自动循环**。提升层：工作流。
5. **嵌入式向量库选型三档**（来源：dreaming.press sqlite-vec 2026-07-22 + 腾讯云 2026-06-24 + dev.to hypernexus 2026-07-29 + sitepoint 2026-02-25）——**sqlite-vec：零依赖默认（SQLite 扩展、向量与数据同 .db、暴力 KNN 无 server），个人/单应用 RAG 上限约几万 chunks**（实测 14,200 vec/s 写、2.1ms p50、空闲 RAM 8MB，超 Chroma/Weaviate）；**Chroma：原型快（内存索引、~500K 向量、最友好 API）；LanceDB：超 RAM（磁盘原生、Lance 列式、内置版本化/time-travel、混合 vector+fulltext、1M+）**。判据：**个人 RAG 默认 sqlite-vec；要元数据过滤和快原型用 Chroma；数据超 RAM 或要版本化评测用 LanceDB**。提升层：工具。
6. **PKM 反固定 512-token 块 + raw/wiki/output 目录法**（来源：readerfi obsidian-local-rag 2026-04-17 + modemguides 2026-04-04 + lhusser Karpathy 2026-04-01）——**笔记有结构：用 heading-aware chunking（一个 H2/H3 节+列表项=一个块），不要固定 512 token**；Karpathy 方法：**CLAUDE.md=每会话自动读的"大脑"（vault 规则），raw/（不可变源文档）+ wiki/（LLM 生成维护页）+ output/（查询结果）分目录**；未整理笔记造成"上下文污染"（context pollution）。判据：**本地知识库的检索质量先靠分块策略，再靠检索算法**。提升层：工作流。
7. **OpenJarvis 五原语 + 本地评测把能效当一等公民**（来源：marktechpost 2026-06-03 + everydev llms.txt 2026-06-17 + privatemind 2026-06-13）——Stanford+Lambda Labs：**推理/agent/记忆/学习全设备内，开源模型距最佳云端模型 3.2 百分点内**；**五核心原语拆解 agent 功能，让"智能/逻辑/状态在哪"可审计**；**评测把 energy/FLOPs/latency/dollar cost 与 accuracy 同为一等公民**；用本地 trace 数据的学习循环改进模型。判据：**本地 agent 的评测维度 = 准确率+能效+延迟+成本四维，不只比质量**。提升层：可复用 Skill。
8. **Gemma 4 12B encoder-free 多模态**（来源：google blog 2026-06-03 + gizmodotech 2026-06-04 + modelscope OpenVINO 2026-06-22）——**视觉音频直接进 LLM backbone、无中间编码器**（图片轻量嵌入层+位置编码，音频投影到文本 token 空间）：低延迟、小内存、一模型全模态；**16GB 内存笔记本可跑**，OCR/图表/UI 理解/语音转录/音频问答/多说话人分析；OpenVINO 部署离线条。判据：**设备端多模态选 encoder-free 架构，省的就是延迟和显存**。提升层：工具。
9. **本地语音全离线栈**（来源：localaimaster 2026-06-20 + vietanh edgevox 2026-05-30 + promptquorum 2026-08-28）——**faster-whisper（CTranslate2 重实现：GPU 4x/CPU 2x）+ 本地 LLM + Kokoro/Piper TTS**；**Kokoro 82M（主流语言）+ Piper/超通 ~99M ONNX（长尾语言，CPU 实时）**；链路 **Audio→VAD(Silero)→STT→LLM→TTS→Audio**；wake word（pymicro-wakeword）防噪声误唤醒；RTX 3060 12GB 桌面端到端延迟可用。判据：**本地语音四件套 VAD/STT/LLM/TTS 分开选型，别让一个套件锁死**。提升层：工具。
10. **本地能效指标：tok/s/W 与 J/token**（来源：arXiv 2608.00008 2026-09-08 + specpicks qwen-3.6 2026-05-06 + arXiv 2605.03111 2026-05-04）——**能耗与参数量不线性：gemma3:1b 0.56 J/token vs 7B-Mistral 4x 多**；同硬件 Qwen 3.6 27B 0.056 tok/s/W vs Llama 3.1 70B 0.022（**2.5x 能效差**）；**3-shot prompting 提升运行时与能效（对比 0-shot）不损质量**；高 MMLU 不一定必要（Granite4 Tiny Hybrid 54.6% MMLU 但教学评分强，人类验证 Pearson r=0.967）。判据：**选本地模型看 tok/s/W 和 J/token，光看 MMLU 会选错**。提升层：可复用 Skill。
11. **本地多模态三模型管线 + BrowserAI WebGPU**（来源：vucense 2026-09-13 + thenextgentechinsider 2026-07-11）——**本地多模态 = 视觉（Llama 4 Scout）+ 音频（Whisper Medium）+ 文本合成（Qwen3 14B）三模型组合管线**，文档 OCR/音频转录/产品分析/结构化提取零云端 API；**BrowserAI SDK：WebGPU 让浏览器直接跑本地多模态推理**（文本/视觉/语音在客户端硬件，降延迟省服务成本）。判据：**本地多模态不追求单模型全能，三模型组合管线成本更低**。提升层：工作流。
12. **ModelScope 本地生态 + 端侧推理全栈优化**（来源：modelscope learn 2026-05-19 + modelscope-hub pypi 2026-09-22 + 今日头条 2026-09-29）——AI PC 上 35B 模型跑通"需求→代码"完整链路（不联网无 API 费）；**modelscope-hub CLI：下载/缓存/离线模式（local_files_only）/部署 Studio space 或 MCP server/CI 集成**；端侧 APXInf 全栈优化：不改模型、FP8 配置下推理延迟降 10.7x，成功率持平参考实现。判据：**本地部署选 ModelScope 管模型生命周期（下载/离线/部署一条龙），比手搓 git clone 省**。提升层：工具。
