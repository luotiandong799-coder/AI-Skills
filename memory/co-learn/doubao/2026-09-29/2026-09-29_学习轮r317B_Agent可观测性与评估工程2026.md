## 独点（12）

1. **OTel GenAI 语义约定与 span kinds**（来源：mlflow 2026-05 + aws wellarchitected 2026-08 + futureagi 2026-05 + otel blog）——**vendor-neutral schema：gen_ai.system / gen_ai.request.model / input-output tokens / request params / finish reasons——spans 跨框架模型可比较（agent 在 Bedrock/Lambda/ECS/自托管间迁移 telemetry 保持 portable）**；**span kinds：LLM/CHAIN/RETRIEVER/TOOL/EMBEDDING/AGENT/RERANKER/GUARDRAIL/EVALUATOR——稳定属性名**；**traces 跟踪每次模型交互（温度/top_p/token 数/错误）；metrics 聚合 request volume/latency/token counts 管成本与性能**。判据：**用 GenAI 语义约定别用框架私有 schema——telemetry 才能跨 runtime 比较**。提升层：工具。
2. **三属性绑定 agent run 与静默失败**（来源：base14 2026-09 + futureagi 2026-05 + dev kuldeep 2026-09）——**三属性设到每个 span：gen_ai.conversation.id（共享 ID 链接 run 内全部操作）+gen_ai.agent.name（哪个 agent 产生）+gen_ai.operation.name（什么操作）——一个 run 读成一条 timeline**；**LLM observability vs APM：APM 抓 HTTP latency/error rates/exceptions；LLM observability 加 token usage per call/prompt versions/span-attached eval scores/retrieval quality/tool outputs/drift detection/agent graph topology——生产 AI 系统失败于 hallucination/prompt drift/reasoning loops（静默失败），不是 HTTP exceptions**。判据：**只记 HTTP 层指标=看不见 agent 质量退化；三属性必设否则 run 无法重组**。提升层：工具。
3. **agent observability 执行图与手动埋点**（来源：dev kuldeep 2026-09 + aliyun 2026-09 + dev nainik 2026-09）——**simple tracing=单轮 request-response；agent observability=多步执行图：多轮会话/递归工具调用/动态路由 sub-agents/状态转移的关系——preserving context 才能调试级联逻辑失败**；**自定义框架/多语言架构时探针不自动收集→OpenTelemetry GenAI Utils 手动生成符合 GenAI Semantic Conventions 的标准 spans**。判据：**agent 系统按执行图可观测（非单请求）；探针不覆盖的手动埋点补**。提升层：工具。
4. **Eval 工具链选型与 LangSmith Engine 闭环**（来源：futureagi eval-frameworks 2026-08 + mcplato 2026-05 + handpickedai 2026-07 + langchain tools 2026-08 + langchain engine 2026-05 + langfuse 2026-06）——**选型：LangSmith=原生 trajectory semantics（agent runs 是 LangChain/LangGraph 时）；Braintrust=数据集/实验/人工 review/回归+UI；DeepEval=CI 集成；Langfuse=OSS 最强 all-around（MIT+self-hostable Docker/K8s+OpenTelemetry based 任何框架+LLM-as-judge/custom rubrics/dataset versioning/human annotation queues+prompt management one-click rollbacks——cost+data control 两障碍一次解决）**；**LangSmith Engine 闭环：线上 evaluator 提议（scoped 到精确问题）→再触发自动 resurface issue→失败 production traces 拉进 dataset 作 ground truth→offline eval suite；每个 resolved issue 增加 eval coverage（确认修复也生成持续监控 evaluator）**。判据：**个人/自托管选 Langfuse；LangChain 生态选 LangSmith；eval 要闭环到 dataset 持续改进**。提升层：工具。
5. **Phoenix/OpenInference 实操**（来源：arize phoenix docs 2026-09 ×8）——**本地启动：pip install arize-phoenix + phoenix serve，或 uvx arize-phoenix 免安装**；**埋点：pip install openinference-instrumentation-openai / -openai-agents + arize-phoenix-otel（>=0.16.0）+ opentelemetry-sdk + exporter-otlp → register()+OpenAIInstrumentor().instrument()**；**TS：@arizeai/openinference-core 的 withSpan/traceChain helpers（wrappers 解析默认 tracer 便于换 provider 的实验）**；**Agent Spec：AgentSpecInstrumentor + pyagentspec[langgraph] adapter 用 LangGraph 作 backend**。判据：**零改代码的 instrumentor 优先；自定义函数用 withSpan/traceChain 包一层**。提升层：工具。
6. **Judge 可靠性：四失败模式与校准**（来源：arxiv JRH 2603.05399 + openreview + arxiv BabelJudge 2606.22329 + langchain calibration 2026-06 + arxiv agentjudgebench 2608.26623，增量合 r315A LLM-as-judge 点）——**judge 可靠性=consistency+discriminative accuracy 的组合；没有单一 judge 全基准稳健（task-conditioned robustness）**；**四失败模式：position bias / verbosity bias / order inconsistency / cross-lingual degradation——gold-labelling by degradation（高质量 reference+受控扰动→pairwise gold label 已知，无需人工偏好标签）**；**calibration：judge 可以 directionally useful 仍 wrong——human-labeled seed set→judge vs labels→revise rubric→track agreement over time；LLM judges 在 agentic tool-calling 有 fundamental limitations**。判据：**judge 上线前先测可靠性（四失败模式）；与人类标签校准过再用；agentic 场景 judge 需 task-conditioned 验证**。提升层：工作流。
7. **RAG 生产评估工程**（来源：respan 2026-07 + dev mryadavgulshan 2026-09 + futureagi glossary/blog 2026-05 + slavadubrov 2026-05 + mslearn 2026-04 + theneuralbase 2026-04 + arxiv LongEval 2607.14400，增量合 r316C RAG 评估点）——**双失败面分离：retrieval（找对上下文了吗）与 generation（模型用对了吗）分开测分开修；六指标=context recall/context precision/context relevance/faithfulness/answer relevance/citation accuracy；golden set 100-300 问来自真实生产日志（synthetic 是 backstop 非基础）**；**分层评估表：Query rewrite（AnswerRelevancy on rewrite）/Retrieval（ContextRelevance/Recall，secondary MRR/NDCG）/Chunk-level（ChunkAttribution/ChunkUtilization，Attribution=Failed 触发）/Rerank（ContextPrecision/NDCG）**；**guardrail 最小集：Faithfulness/HHEM score below threshold on rolling sample / p95 latency above SLO / filter false-exclusion rate / regeneration rate above baseline**；**三层 drift 检测：gold set 盖不住 real users/real queries/distribution shifts→cloud evaluators tied to OTel spans（fast judge 在线采样 bulk+deep judges async attach scores）+Weekly human calibration（50-100 production traces 领域专家）**。判据：**gold set 只做基线，生产 drift 靠在线采样+人工校准补**。提升层：工作流。
8. **Prompt 版本治理**（来源：aws lifecycle 2026-09 + compel 2026-06 + alibabacloud 2026-04 + devopsboys 2026-06 + dev nainik 2026-09 + markaicode 2026-03 + futureagi 2026-07 + alivedise 2026-06，增量合 r315A Prompt 版本化点）——**版本=性能身份：version number 必须内在关联 comprehensive evaluation results（customer-support-summarisation-v2.1 指的是 v2.1 的评估记录）——不只文本变更**；**registry 记录结构：唯一标识（semantic name+version）/标题/owner（named individual+backup）/model binding（哪些 model versions 批准跑）/retrieval binding（哪个 retrieval source at which version）/guardrail binding**；**canary 标签切换：canary 指向新版+stable 指向生产→验证过切换→出问题切回秒级回滚；deterministic bucketing=hash(user_id:name)%100 同用户同版本；按 prompt version 分段跟踪质量指标（user feedback/downstream success/manual review）**；**CI Eval Gates：treat prompts like code（Git versioning+eval suites 每个 PR 自动跑+one-command rollback）——prompt changes 是最常见生产事故源（NPS -12 案例）**；**per-agent 独立 registry：triage/research/resolver 失败原因不同改进节奏不同→各自 immutable version history+commit messages+deployment labels——永远知道哪个 agent 哪个版本在某 run 存活**。判据：**prompt 按代码治理；版本与评估记录绑定；回滚按标签切换不做代码发布**。提升层：可复用 Skill。
9. **Agent Chaos 工程**（来源：arxiv AgentChaos 2608.06790 + developersdigest 2026-08 + floritange + amarchaudhari 2026-06 + arxiv OrchestraBench 2608.05263 + dev anusha 2026-09 + pypi balagan + zylos 2026-04，增量合 r315A 失败注入点）——**AgentChaos：LLM API HTTP 层注入 fault（crash/omission/value faults on content+tool call fields），不改源代码；验证 fault 是否触发过滤 untriggered 防低估；实测 pass@1 掉最多 50 点且 ranking 与底层 LLM 无关——鲁棒性是 systems problem 非 model problem**；**四类注入问题：tool 返回 errors/timeouts/plausible wrong answers（agent 检测？重试？还是围着幻觉？）；retrieval 给 contradictory/empty（说 I don't know 还是 confabulate？）；latency 到 deadline 风险（graceful degrade 还是 hang？）；corrupt 一步输出看传播多远**；**OrchestraBench：retry 修不了 latent failure modes（retrying while failure present 只拉长 time-to-detection）——retry 修 retryable tool faults 但修不了需 attribution/state repair/semantic validation 的失败**；**over-injection 反模式：crank fault rate→agent 学会唯一安全动作是拒绝一切——把安全失败换成可用性失败**；**measure MTTR+score reliability like SLA（flakestorm 四支柱=Environment Chaos/Hostile Inputs/Malformed Inputs/contract 验证）**。判据：**注入在 dev 不在生产；故障率别拉太高；retry 不治的失败要归因/状态修复/语义验证**。提升层：工作流。
10. **Eval 数据治理**（来源：langchain checklist 2026-03 + kunalganglani 2026-07 + arxiv agencybench 2601.11044 + arxiv Counsel 2606.21627 + arxiv implicit 2602.20424 + arxiv MM-ToolSandBox 2607.11818 + mslearn mlflow 2026-09，增量合 r315A golden dataset 点）——**无生产数据三来源：synthetic scenario generation（手写 20-30 真实请求）+adversarial inputs（edge cases 试图打破）+persona-based testing（5-7 用户 persona×top workflows）→50-100 labeled traces；source from dogfooding errors/adapted external benchmarks/hand-written behavior tests；trace-to-dataset flywheel 持续改进**；**正负例都测：positive cases（应发生）+negative cases（不应发生）——没负例 eval 偏 be helpful**；**三组件任务设计：专家手工构建 Query（需求）+Deliverables（期望输出/终态）+Rubrics（客观标准）+executable eval scripts，另一 4 人专家小组独立验证**；**Counsel 三向标注（评 judge 输出）：Spot On（位置+critique 都对）/Poor Reasoning but Correct location（位置对 critique 错）/Should Not Have Flagged（都错）**；**Implicit Intelligence 难度门：场景必须 unanimous consensus+至少一个 frontier model 失败（≤70%）且至少一个通过（100%）——全模型都过的丢弃**。判据：**数据集=正负例+三组件+难度门；judge 输出本身也要被评（Counsel 三向）**。提升层：工作流。
11. **Agent 质量指标与 SLA 定义**（来源：prefactor 2026-08 + kunalganglani 2026-07 + aws strands 2026-07 + aws wellarchitected 2026-08 + infoq 2026-06 + spinnable 2026-08 + nvidia 2026-09 + channel.tel 2026-05 + futureagi 2026-05 + exploreagentic 2026-06，增量合 r317A 生产监控点）——**核心启动集：task completion rate（north star，无 human escalation 全解决率）+cost per session+一个质量指标匹配主失败模式（groundedness for retrieval-backed / tool-call accuracy for action-taking）——不需要 12 个 day one；quota burn（per-agent/per-customer 预算消耗）在账单前抓住 runaway agents**；**SLA 参考表：task completion 95% / tool selection accuracy 95% / helpfulness 0.83 / latency P50 5s P99 15s / hallucination rate 5% / cost per interaction 2x baseline**；**四维度：Latency（TTFT streaming/end-to-end task/分阶段预算）+Throughput（并发会话/RPS/queue depth）+Quality（completion/tool selection+parameter accuracy/grounding/faithfulness）+Efficiency（tokens per task/cost per completion/cache hit rate）**；**四支柱：End-to-End Task Success Rate/Token Cost per Task/Human Escalation Rate/Step Latency Distribution（NIST AI RMF MEASURE 2.1+OpenAI Evals——raw public LLM benchmarks 不能衡量部署后性能）**；**GCR 局限：二元指标掩盖边缘情况（技术上成功但耗时过长/路径非最优）——Anthropic 建议多评分器类型**；**completion 精确定义：launch 前定义（support="ticket resolved+24h 未 reopen"；booking="booking confirmed+payment processed"）；NVIDIA 双层评分=step-level process scoring（链条哪断）+end-to-end outcome scoring（终态匹配目标）；success rate with consistency ranges 配对报告**。判据：**三个起步指标先跑；completion 定义写进 launch checklist；质量指标按分布跨 release 对比非只看均值**。提升层：工作流。
12. **轻量评估实践**（来源：vibeengines 2026-05 + growthengineer 2026-05 + macha 2026-07 + qaskills 2026-07 + futureagi smolagents 2026-05 + mindstudio 2026-03 + meta-trendy 2026-05 + mslearn agent-evaluators 2026-08 + itail archetype，增量合 r315A 评估点）——**正负例一半一半（负例=拒危险请求/拒 out-of-scope/歧义要澄清）——没负例 eval 的赢家是"总在帮忙"的模型（包括不该帮时）**；**judge prompt 五要素：短、rubric 内联、一个正例一个负例、verdict 在 rationale 之前（长 prompt 产生 verbose biased rationales）；3-judge consensus+majority vote ~97% macro F1（high-stakes 用）**；**Macha 混合矩阵：Grounded/On-task/No overpromising/Correct escalation/Tone=Judge，Right tool called=Deterministic——judge+deterministic 混合**；**activation precision/recall：计算技能触发精度与召回（recall="需要技能时选中频率"）——正负例边界标注（Usually do not activate vs Activate）**；**smolagents code-as-action 分层：Execution success（deterministic step_log 检查）/Result interpretation（groundedness with execution output as context）/Trajectory recovery（TrajectoryScore+TaskCompletion+ActionSafety）**；**2h 评估协议：80+ 合格进 30 天 trial；65-79 条件付再评；≤64 不采用；30 天定着测试=4 个轻 KPI**。判据：**eval criteria Specific/Binary/Tied to user value；judge prompt 短+verdict 先行；技能触发按 precision/recall 评**。提升层：可复用 Skill。
