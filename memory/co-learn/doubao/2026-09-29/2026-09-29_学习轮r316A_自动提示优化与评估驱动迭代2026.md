## 独点（12）

1. **DSPy 四优化器选择表**（来源：futureagi dspy-optimizers-explained 2026-05 + dspy.ai MIPROv2/GEPA + ai-tldr + fzeba 2026-05）——**BootstrapFewShot**（调 few-shot demos，bootstrapped 成功轨迹，低算力分钟级，小数据）/ **MIPROv2**（调 instructions+demos 联合，Bayesian joint search，200+ 例子，demo-heavy 单指标任务）/ **COPRO**（仅 instructions，coordinate ascent，无 demos 小中数据）/ **GEPA**（整程序，reflective Pareto evolution，多目标管线）；**optimizer=studying labeled examples against a scoring rule——你供 trainset+metric，optimizer 负责研究**（compile 动词）；**GEPA reflective evolution：用 reflection 演化文本组件，实证可超 RL**；Morph 实证：DSPy 评估准确率 46.2%→64.0%，refinement 85.0%→90.0%。判据：**按数据量×算力×指标复杂度选优化器，不默认一个**。提升层：工作流。
2. **CROP 成本感知提示优化**（来源：arXiv 2604.14214，2026-09）——**response adaptive textual length penalty 在 prompt 发现阶段把 reasoning accuracy 与 generation verbosity 解耦**——输出 token 减最多 80.6%（GSM8K/LogiQA/BIG-Bench Hard）同时保精度。判据：**提示优化时把"推理准"与"输出短"当两个正交目标，加长度惩罚项**。提升层：工作流。
3. **Meta-prompt 的失败记忆结构**（来源：futureagi automatic-prompt-optimization 2026-05 + AWS prescriptive-guidance 2026-09 + Promptomatix arXiv 2507.14241）——**meta-prompting 的可靠结构=memory of failed attempts：teacher 拿到 current prompt+它做错的例子+已试过且得分更差的 prompt→诊断重写；没有失败记忆，teacher 每轮提出同一个看似合理的改写**；AWS 定义=metaprompt 让能力模型当 prompt 工程专家，基于失败例子批判+建议（自动反馈环）。判据：**迭代优化 prompt 时把"更差的尝试"也喂给优化器，否则原地打转**。提升层：工作流。
4. **MemAPO 双记忆与 ESPO 三阶段**（来源：arXiv 2603.21520 MemAPO 2026-08 + 智源 ESPO 2026-09 + arXiv 2608.11219 SAPO 2026-07）——**MemAPO：把成功推理轨迹蒸馏成 strategy templates、错误生成归组织成 error patterns（双记忆），新 prompt 检索两者组合——promote 有效推理+discourage 已知错误**；**ESPO 三阶段：Diagnose（一轮把全部训练错误聚类为结构模式）→Propose（四种互补候选生成策略保证多样性）→Select（bootstrap 稳定性选择）**；**SAPO：prompt 分解 role/context/tasks/output format 四段，用 top-5/bottom-5 例子驱动针对性改进，单 LLM+静态 meta-prompts+结构化输出**。判据：**自动优化=先结构化诊断错误，再多样候选，再稳定筛选**。提升层：工作流。
5. **ProTeGi 文本梯度与 PromptWizard 三阶段**（来源：futureagi what-is-prompt-engineering 2026-05 + arXiv PromptWizard 2405.18369 + scispace + nlp.korea.ac.kr 2025-09）——**ProTeGi（Pryzant 2023）：自然语言批评当"梯度"，沿语义相反方向编辑 prompt，beam search+bandit selection——最高 +31%**；TextGrad=其后继（prompts 作为参数受文本梯度更新）；**PromptWizard（Microsoft）：三阶段循环=mutate（混合 thinking styles 生成变体：chain-of-thought/step-by-step/role-play）→critique（teacher LLM 批评）→error-driven self-reflection（分析已选例子）；省 API 调用/token；45+ 任务平均 +5% over GPT-4/Gemini/PromptBreeder**；**GSM8k 实证表：GPT-4 92→95.4 / GPT3.5 57.1→75.6 / Llama-70B 56.8→90.2——小模型收益更大**。判据：**优化收益在小/弱模型上最大；强模型边际小**。提升层：工作流。
6. **动态少样本与顺序敏感性**（来源：nerdleveltech ICL 2026-07 + gemilab dynamic few-shot 2026-04 + prompt.university ICL + arXiv 2602.12123 Meta-Sel + then euralbase few-shot cheat sheet）——**ICL 顺序敏感：easy→medium→hard 85% vs hard→medium→easy 78%（recency bias：最后一个例子影响最大）——最复杂/代表例放最后**；**动态少样本：向量检索每请求选 3-5 例子，生产反馈增长例子库（手写硬编码例子在输入漂移后不扩展）**；**Meta-Sel：轻量监督元学习学 (candidate,query) 打分函数，每查询低价选例**；**ICL 最佳实践：5-10 例子足够、质量>数量、多样性提升泛化、consistent format、representative cases（典型场景非 edge case）、大模型收益更多**。判据：**例子按"越靠后越关键"排序；例子库用检索不用硬编码**。提升层：工作流。
7. **Prompt 压缩技法**（来源：dzone token-frugality 2026-05 + terseai 12 技法 2026-07 + varunsingla tokenomics 2026-08 + dev anoop 2026-09 + arxiv DiffuMask 2604.06627 + pypi twotrim）——**句子移除测试：删一句跑 eval，质量不变=这句不属于**；**Bullet 压缩：400 词散文指令→8-12 条祈使句 bullet（<100 tokens）——prose 连接组织是高冗余**；**"be concise" 指令减输出 57-59%；"one paragraph/two sentences/bullet points only" 减输出 token 40-70% 不丢信息**；**DiffuMask：扩散模型 token 级 pruning，GSM8K 80% 长度减、1 分钟内（vs 顺序 pruning 10-48h）**；**TwoTrim 中间件：LongLLMLingua 提取+句子语义评分+lost-in-the-middle 重排，reverse proxy 减 80%**。判据：**压缩=逐句实测价值（删了不降分才删），指令改 bullet，输出加长度约束**。提升层：工具。
8. **Prompt 版本化生命周期**（来源：futureagi regression-testing+versioning 2026-03/05 + stochasticsandbox 2026-05 + mhtechin 2026-09 + promptassay drift 2026-08 + dev nainik 2026-09 + markaicode ×2 + aipromptshub + Microsoft Learn）——**回归套件=prompt_version_id 打在每个 trace/eval 行，baseline JSON 在 promote-to-main 重生成，parent: v23 链**；**eval-on-PR：每 PR 触 prompts/ 回归，candidate vs 当前生产同用例 paired per-case delta（groundedness 降>3% fail build）**；**canary：5%→25%→50%→100%——CI 防坏候选进生产，canary 防 CI 通过但 golden set 没预料的生产分布**；**golden set 规模：不需要 10,000 例——20-50 高质量多样化的 must-work 场景**；**模型 pin 用日期形式（claude-sonnet-4-5-YYYYMMDD 而非 bare alias）防 prompt drift**；**每 LLM 调用记录 prompt 版本=解决最大调试问题；one-click rollback（需 code deploy 就不算有 versioning）**；**语义版本映射：formatting/typo→patch，behavioral tuning→minor+full eval suite，breaking（推理结构/输出格式/范围）→major**。判据：**prompt 当代码管：git 存储+CI eval 门+canary+日期 pin+每调用记版本**。提升层：工作流。
9. **自动优化的失败模式与 Bitter Lesson**（来源：groundy judge-drift 2026-06 + arxiv STEVES 2609.23716 + mindstudio bitter-lesson 2026-04 + futureagi agent-optimization 2026-05 + then euralbase promptops 2026-04 + try.llumo 2026-04）——**Judge drift 是最大失败：自调优管线优化你给的信号——metric noisy/incomplete/gameable 时，自动化更快更一致地做错；judge 质量决定一切**；**STEVES 观察：持续多轮只在 hard examples 上优化不稳定（初期提升后衰退）——prompt 空间过拟合：prompt 变冗长 convoluted、累积过多特定约束，解决 target hard cases 但变 brittle**；**Bitter Lesson 危险信号：system prompt >500 词对简单任务/每次失败加规则而不重想整体方法/相似输入输出波动/无法一两句解释 prompt/改一段导致无关区域失败/不敢编辑**；**eval-set overfit/judge contamination/prompt drift/cost runaway 四监控**；**<20 cases 无法检测过拟合；review test set 必须独立于迭代集**。判据：**自动优化先保证 judge 质量；危险信号清单任一命中即重构而非加规则**。提升层：工作流。
10. **跨模型可移植 prompt 与契约 hand-off**（来源：promptquorum portability 2026-08 + ketelsen hand-off packet 2026-06 + mindstudio tool-agnostic 2026-05 + then euralbase portability 2026-04 + prompt-architects 2026-08）——**三规则：显式输出格式（JSON schema/XML/markdown，禁"preferred format"——各模型默认不同）；system prompt 与 user message 分离（role/constraints/schema 在 system，请求在 user——模型区别对待，混用降可移植性）；避免 model-specific features（thinking 标签/assistant prefilling 除非测过）**；**契约 hand-off：prose+JSON Schema 写契约（universally understood），格式规则顶部底部都放，单一分隔符约定，不依赖任何单厂商 JSON mode 开关，re-ingestion 总验证+修复（temperature 0 也无厂商确定性）**；**XML 信封包 JSON payload=最可靠跨模型输出容器**；**markdown 主模板通用，仅 Claude 长多节丢线索才转 XML heading；必要时分模型变体（feedback_summarizer_claude/gpt4/gemini）由 workflow 选择；至少两个模型测过才当稳定**。判据：**prompt 可移植=显式格式+角色分离+不依赖厂商特性+重入验证**。提升层：可复用 Skill。
11. **Agent 系统 prompt 契约六问与四工程面**（来源：luismori prompt-contract 2026-04 + swarmsignal production-guide 2026-06 + alejandrorioja five-layers 2026-07 + musketeerstech 2026-07 + maisumhashim 50+ deployments 2026-04 + sureprompts 2026-06 + aiunpacking 2026-04 + skillgen 2026-05 + arxiv SePO 2606.04465）——**契约六问：agent 干什么/允许做什么/绝不该做什么/不确定时怎么办（prefer explicit abstain states over hidden uncertainty）/输出什么形状（prefer enums over free text）/如何对待外部内容**；**四工程面各有失败签名：system prompts/tool descriptions（每次调用前 schema+文档）/output format instructions/context management——四个全对不保证可靠，一个错了几乎保证不可靠**；**生产五层：identity/context/task（step by step success）/output format（最被低估层）/edge cases——先写输出格式再写别的**；**思考放 scratchpad/thinking block（下游代码忽略）——2026 reasoning 模型只需不压制思考**；**实测成功标准：eval set=100-200 生产实例人工标注=ground truth，每个改动对比 baseline 不提升不 ship**；**SePO：prompt agent 用与 task agent 相同程序改进自身 system prompt（自参照）——手工固定件变可学习组件，两阶段（multi-task pool→per-task fine-tune）**。判据：**agent prompt=契约六问全答+四工程面逐一检查+先写输出格式**。提升层：可复用 Skill。
12. **Prompt 库管理纪律**（来源：prompt-architects organize 2026-07 + promptly multi-tools 2026-06 + promptanthology templates 2026-03 + getaiworkspace guide 2026-08 + aipromptshub share 2026-06 + supaprompt tagging 2026-05 + prompthub.click 2026-08）——**Tag sprawl：15 tags/prompt=过滤返回一切，cap 5-7；无"last tested"日期=无法知道哪些 prompt 随模型更新漂移——date everything；一处存储（三处=保证漂移）；12 个 prompt 建复杂分类=拖延**；**一次一个 source of truth，按任务组织（一个条目跨所有 assistant 用），verb+object 命名（summarize_weekly_report）+bracket placeholder（{{audience}}），月度 review+prune+merge duplicates 保持 lean**；**static prompt 只服务一个用途，template with {{persona}}/{{topic}}/{{tone}} 服务该用途每个变体**；**pinning/favorites 比容量重要（几百存着，每周用的单手屏幕放得下）**；**PromptHub=个人 AI asset vault：prompts+skills+rules+MCP+plugins+model config 放一起按 agent/project 搜索编辑测试备份同步分发**。判据：**prompt 库=单源+任务组织+5-7 tag+last tested 日期+月度 prune**。提升层：可复用 Skill。
