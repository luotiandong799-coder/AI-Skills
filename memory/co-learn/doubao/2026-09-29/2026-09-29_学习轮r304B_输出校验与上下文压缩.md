## 独点（12）

1. **结构化输出三层层级 + 语义失败需应用级校验**（来源：jvoltci.github.io《Structured Output》2026-05-27 + Tensoria《Structured Outputs in Production》2026-05-15 + OpenLegion 2026-07-01）——三层：schema 定义（Pydantic/TypeBox/Zod）→ constrained decoding（服务端 XGrammar/Outlines/OpenAI Structured Outputs）→ client validation+retry（Instructor）。核心反直觉点：**JSON 语法合法 ≠ schema 合规 ≠ 语义正确**——JSON mode 只保证语法，幻觉 key 造成静默 KeyError；语义失败（错值/错字段/幻觉数据）必须应用级 Pydantic field_validator 域约束。提升层：工作流。
2. **错误回注自纠循环**（来源：baeseokjae.github.io《LLM Structured Outputs Guide 2026》2026-05-10 + nodellm.dev + Wicked Smart Data 2026-08-06）——校验失败时把 ValidationError 转成 follow-up prompt 告诉模型具体错在哪并请求修正（Instructor 机制），比"捕获 JSON 解析异常盲目重试"稳健得多，自纠率 90%+；NodeLLM Schema Self-Correction Middleware 自动把错误发回 LLM 重试 maxRetries；repair ladder 用尽报 SCHEMA_NONCOMPLIANCE 不可恢复错误。判据：**重试必须携带错误上下文，盲目重试是浪费**。提升层：工作流。
3. **Hermes 上下文压缩不变量**（来源：akjamie.github.io《Designing Context Compression for Production Agents》2026-05-24）——压缩不是"长了就总结"，是带严格不变量的一次转录重写：① head/middle/tail 分区（system prompt 与首轮完整保留、中段总结、尾部按 token 预算保护）；② **active task anchoring：最新用户消息必须留在 summary 外**——被总结的"待办"是参考资料不是活的 user turn；③ tool-aware compaction（旧工具输出优先丢/offload，不动推理链）。提升层：上下文管理/工具。
4. **Deep Agents 三级压缩顺序**（来源：LangChain《Context Management for Deep Agents》2026-01-28）——① offload 大工具结果（一发生就写文件系统）；② 上下文超阈值后 offload 旧 write/edit 工具参数；③ 无 eligible 内容可 offload 才做 summarize。判据：**先 offload 后 summarize——能搬出去的不压掉，summarize 是最后手段**。提升层：工具。
5. **n8n 默认重试状态码集合 + 指数退避公式**（来源：n8n.io/workflows/15459 2026-04-28 + n8nlogic 2026-06-03）——可重试：408/409/425/429/500/502/503/504；不重试：400/401/403/404/422。退避公式 waitSeconds=min(maxDelaySeconds, baseDelay*2^n)+jitter；重试至少等 5 秒给外部服务恢复时间；永久错误（401/403/unauthorized）直接告警不做无谓重试；AI triage 模式（Anthropic 诊断+OTel 遥测+per-incident 重试计数上限 3 次）判断瞬时错误才自动重试。提升层：工具。
6. **技能写作：适度细节 + 渐进披露 + 先写 eval 再写 skill**（来源：agentskills.io/best-practices 2026-09-11 + firecrawl.dev《Agent Skills Explained》2026-05-26）——过度全面的技能反而有害：agent 难以提取相关部分、被不适用的指令引到歧路；concise stepwise + working example 优于穷尽文档，edge case 多数交给 agent 自身判断。**先写 eval 再写 skill**：识别真实缺口后先编码评测任务拿基线（当前模型/harness 怎么处理），写完技能再测有没有真提升——没有 eval 就是在猜。提升层：可复用 Skill。
7. **Claw-Eval 多试次评测：区分平均/最佳/可靠性**（来源：arXiv 2604.06132《Claw-Eval》2026-08-27）——300 个人工验证任务、9 类；full-trajectory 审计、Completion/Safety/Robustness 三积分、2,159 条可独立验证 rubric；**multi-trial 评测区分平均表现、最佳能力与可靠性**——单次跑分把三者混成同一个数。提升层：可复用 Skill。
8. **DeepSeek Harness 插件验收三证据**（来源：腾讯云开发者社区《怎么给 DeepSeek Harness 写个插件》2026-08-15 + CSDN 2026-09-07）——插件可用性三关卡：① 加载证据（终端出现 plugin loaded）；② 能力证据（对话中出现真实 Tool call）；③ 执行记录（Trajectory 输入与结果和聊天答案一致，调用可复核）。判据：**"插件能跑"要三证据齐才算——加载≠注册可用≠可复核**。提升层：可复用 Skill。
9. **OpenClaw memoryFlush：压缩时记忆刷新用本地模型**（来源：docs.openclaw.ai/concepts/compaction + /concepts/memory，2026-09-27 实拉）——compaction.memoryFlush.model 可指定 ollama/qwen3:8b，**memory-flush 那一个 housekeeping turn 用本地廉价模型，不继承活动会话的模型 fallback 链**；memory flush 防止压缩期间上下文丢失；压缩触发阈值≈剩余 4000 tokens 时自动 pre-compaction 记忆保存。提升层：工具。
10. **Langflow memory base：向量化长期对话记忆按语义检索**（来源：docs.langflow.org/memory-bases 2026-09-08）——memory base 把消息嵌入向量库、按语义相似度检索最相关上下文；**区别于 Message History 组件（messages 表按时间顺序取最近）与 knowledge base（手动填充）**——对话记忆取"相关"而非"最近"。提升层：工具。
11. **OpenClaw dreaming 成本警示：Deep Sleep 全量重载**（来源：tryopenclaw.ai《dreaming 悄悄烧预算》2026-04-22 + toolify 2026-05-28）——consolidation 每 pass 全量重载记忆语料，默认最多 4 passes；memory 目录长到 50-100k tokens 时单次就 200-400k 输入 token；cron 默认 0 */8 * * *。判据：**启记忆整合前先算"每 pass 重载量 × pass 数"的输入成本**；记忆大时降频或关闭。提升层：工具。
12. **多 agent 交接：schema 即契约 + 错误累积合法性**（来源：zylos.ai《Structured Output Validation in Multi-Agent Workflows》2026-06-21）——一个 agent 的输出是另一个的输入，**错误静默传播、经重复引用累积表面合法性、到最终步伪装成确认事实**；修法=把 inter-agent schema 当 handoff 边界强制执行的契约（constrained decoding + schema gates + orchestrator 级 circuit breaker），不是给开发者看的文档。提升层：工作流。
