## 独点（12）

1. **混合检索三阶段管线：candidate → RRF 融合 → cross-encoder 重排**（来源：aiworkflowlab 2026-05-03 + 72technologies 2026-06-03 + infoworld/infoq 2026-06-02）——**并行双路召回（BM25 top-50/100 + dense top-50/100）→ Reciprocal Rank Fusion 纯排名融合（无视分数不可比，BM25 0-40 无界 vs cosine 0-1）→ cross-encoder 对 query-doc 联合打分取 top-5/10**；**BM25 靠 IDF/词频饱和/长度归一化补 embedding 的精确匹配短板（SKU/法条引用/罕见词/编号）**；RRF 是"无聊但赢"的默认融合。判据：**纯向量检索在 SKU/编号/精确词查询上必然漏，混合是生产基线不是选项**。提升层：工作流。
2. **RAG 检索评估指标族 + 显著性检验**（来源：nvidia nemo 25.11 2026-09-16 + ragas 0.3.9 + arXiv 2604.01733）——**检索质量：Recall@k（覆盖率）/MRR（首个相关位置）/nDCG（多级相关排序质量）**；**RAG 专项（RAGAS）：context_precision（检索上下文精准度）/context_recall（覆盖参考信息）/context_relevance（相关性）/context_entity_recall（实体召回）+ 生成侧 faithfulness/answer_relevancy**；端到端数字类任务用 Number Match；**paired bootstrap significance testing（配对显著性检验）**；实测两阶段（混合+重排）Recall@5 0.816/MRR@3 0.605 大幅领先单阶段；BM25 在 text-and-table 文档上反超 SOTA 神经方法。判据：**评估分检索侧与生成侧两组指标，混在一起无法定位是检索差还是生成差**。提升层：可复用 Skill。
3. **分块策略光谱：固定/语义/结构化/adaptive**（来源：arXiv 2602.16974 + redis 2026-04-13 + datasciocean 2026-07-22）——**语义切分：相邻句 embedding 相似度低于阈值=主题边界（自适应内容流）**；结构化切分按 Markdown headers/code fences/tables/lists 保原子单元；**adaptive chunking：shred（按预排名分隔符递归切碎到 <S）→ greedy merge（按 token 上限合并）——消灭无意义小碎片**；MDKeyChunker：**LLM 单调用提取全部 metadata+语义 key，rolling key 字典跨 chunk 继承，按 key 合并**；元数据必须保留（无元数据即使好 chunking 也无法可靠引用来源）。判据：**chunking 按文档类型选策略，统一固定切分是大多数 RAG 检索差的第一来源**。提升层：工作流。
4. **查询改写与假设文档检索：HyDE 家族**（来源：arXiv 2412.17558 + microsoft learn + arXiv 2607.29402 + arXiv 2509.16369）——**HyDE：LLM 生成假设文档→embedding→answer-to-answer 相似检索；事实错误的假设文档也提供有用信号（语义结构匹配）**；**Reverse HyDE：索引期为文档生成"它能回答的问题"，检索变 question-question 匹配**；**HyPE：索引期预计算多个假设 prompt 嵌入，零延迟问题-问题匹配（不增加运行时成本）**；**Multi-HyDE：多视角假设文档提升检索准确率不增 token 成本**；多轮 RAG 查询重构：LLM 改写/分解子查询/拼接最后用户轮。判据：**问答语义鸿沟是检索漏检主因之一，假设文档把 query 投影到文档侧空间**。提升层：工作流。
5. **GraphRAG 双检索：local（实体邻域）+ global（社区）**（来源：AWS 2026-09-14 + graphrag.openml + arXiv 2404.16130）——**摄入期 LLM 逐 chunk 提取实体+关系→Leiden 层级社区检测（模块度优化，比 Louvain 保证社区内连通）→每社区 LLM 生成 community report**；查询时 local retriever 沿实体邻域走，global retriever 用社区报告回答"全局性问题"；**索引成本 10-50x 标准 RAG（每 chunk 多次 LLM 调用）**；**适用关系遍历场景：合规/供应链/组织架构/研究综述；普通问答仍用 vanilla RAG**。判据：**GraphRAG 是"关系推理"特化，不是 RAG 的通用替代——先问查询是否依赖多实体关系链**。提升层：工作流。
6. **Agentic RAG 三层：CRAG / Self-RAG / Adaptive-RAG**（来源：dev.to saaro 2026-09-13 + aiworkflowlab 2026-02-12 + fordelstudios 2026-09-02）——**CRAG：检索后轻量评估器把每个 chunk 分 Correct/Ambiguous/Incorrect → Correct 正常生成/Ambiguous 知识精炼重排/Incorrect 重写查询+web 兜底（成本 +40-80% 每检索循环）**；**Self-RAG：生成期嵌入 reflection tokens——Retrieve（要不要检索）/IsRel（段落相关吗）/IsSup（生成被支持吗）/IsUse（有用吗）**；**Adaptive-RAG：查询难度分类器前置——简单事实直接答/中等单跳向量/复杂多跳全 agentic 循环；60-70% 生产查询是简单事实=跳过检索省钱**。判据：**三层的共同点是把"检索好不好"从假设变成显式判断，再据此分支**。提升层：工作流。
7. **re-retrieval on failure：自检→重写→再检索**（来源：futureagi 2026-05-14 + aloknecessary 2026-06-17）——**自检标记未支持声明→围绕未支持声明重写查询→再检索；2-3 次上限，超限拒答或升级**；**无 re-retrieval 的 naive 系统在首次检索漏掉时直接输出幻觉**；五种 agentic 检索模式：单工具检索 agent（默认，够用就别升级）/分层 agent 分解（planner 拆多跳子查询+child agents+父合成，最高质量最高成本）。判据：**"检索一次猜一次"是最常见的生产 RAG 反模式——自愈循环是 agentic RAG 与 naive RAG 的分水岭**。提升层：工作流。
8. **引用验证：claim-level citation + citation-shaped hallucination**（来源：arXiv 2609.15830 + ragaboutit 2026-06-28/07-17 + ai-tldr 2026-06-12）——**每个 claim 映射到 chunk ID；引用生成只是一半，验证是另一半**；**citation-shaped hallucination：模型输出 [Source 2] 但 Source 2 并不支持该 claim——引用看起来可信但 grounding 断了**；**VERA：Claude 3.5 68.3%→93.8% 事实准确率（错误率 -73%），数字事实 59%→94%**；**NLI entailed 检查（FLAN-T5/DeBERTa）标志未蕴含 claim，只让模型重生成那部分（cut hallucinated bridges -67%）**；provenance metadata（URL/更新日期/作者/置信度）端到端可审计。判据：**生成引用不验证=给幻觉镀了层可信的壳；验证循环与生成同等重要**。提升层：工作流。
9. **RAG 可观测性：三 spans 隔离 + 抽样线上评测 + 漂移**（来源：mlflow 2026-05-22 + metafiedlab 2026-06-08 + galileo 2026-06-09 + ephizen 2026-06-08）——**embedding span/retrieval span/generation span 离散 spans，隔离"检索差还是生成差"**；**抽样 5-10% 线上查询跑全 RAG 评测，七日均值 faithfulness<0.75 告警；任何基础设施变更（embedding 模型/LLM/chunking）前后跑 RAGAS**；**cohort drift：reranker 更新提升中位却伤长尾查询，按查询组隔离回归**；**索引漂移：新文档进入+源更新+chunking 变更；加事实不删旧陈述，reindex 后过期信息仍浮现（旧新事实共存）**；golden eval set 定时跑检测慢召回下降（HNSW 图质量退化）。判据：**没有 trace 的 RAG 出问题只能靠用户投诉发现——可观测性是生产 RAG 的地基**。提升层：可复用 Skill。
10. **语义缓存：prompt caching vs semantic caching**（来源：zylos 2026-05-30 + heliosdb 2026-06-17 + pavlo 2026-07-04 + neuraltrust 2026-07-16）——**两类缓存：prompt caching=基础设施级复用同前缀计算（Anthropic 90% off/OpenAI 新模型最高 90%）；semantic caching=应用级相似问题直接返回旧答案跳过整个推理（100% 省输入输出 token）**；**Neural LSH：SimHash on 降维 embedding（768D→128D 投影，3 独立哈希函数，Hamming≤2）检测语义等价查询，实测 71% 命中率**；**40-80% 成本削减 + 命中时最多 15x 延迟提升**；**guardrail 检查必须放在 cache 检索层之后（否则被缓存绕过）**；RAGCache prefix-aware GDSF 替换策略。判据：**先按前缀打 prompt caching，再按意图打 semantic caching，两层叠加才接近成本上限**。提升层：工具。
11. **生产 RAG 架构：异步摄入 + 多租户四模式 + multi-vector embedding**（来源：markaicode 2026-05-10 + swfte 2026-05-04 + truto 2026-04-29 + CEUR 4211）——**异步摄入：消息队列（Kafka/RabbitMQ）解耦 embedding 生成与 vector 写入，batching+retry；最小 shard_key 多租户**；**多租户四模式：namespace per tenant（~10K/索引撞墙）→index per tenant（严格隔离开销大）→shared index+tenant filter（多小租户）→federated（复杂查询规划）——从 namespacing 起步，10K 墙后迁混合**；**webhooks first polling 兜底（cron 轮询必 429+数据永远旧）**；**multi-vector embedding：每 chunk (a) 直接 embedding + (b) 3-5 个 LLM 生成"该 chunk 能回答的问题"嵌入——桥接问答语义鸿沟**。判据：**先定多租户形态再选库，10K 租户是 namespace 模式的硬墙**。提升层：工作流。
12. **多跳查询与生成质量：可答性校准优先**（来源：arXiv 2603.10524 + ragaboutit 2026-07-17）——**92% RAG 系统多跳查询失败**；**answerability calibration（可答性校准）比检索覆盖更关键——检索到但模型不会"承认答不出"是端到端性能主瓶颈**；**query diversity（查询多样性）胜过异构检索器集成**；多跳拆解：把"跨段落组合推理"拆成子查询链，每跳独立检索+验证。判据：**多跳失败先查"该拒答时是否拒答"，再查检索——顺序反了会白修检索**。提升层：模型/工作流。
