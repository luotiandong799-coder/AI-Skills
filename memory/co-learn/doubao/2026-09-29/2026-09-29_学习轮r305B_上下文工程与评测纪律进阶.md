## 独点（12）

1. **context rot 实证 + 上下文工程四操作**（来源：zylos.ai 2026-04-19 + blogs.oracle.com 2026-09-28）——2025 年跨 18 个前沿模型研究：**上下文窗口没满之前，噪音累积已使每个模型性能可测下降**（context rot）；上下文工程=决定模型每一步看到什么（指令/实时任务状态/检索证据/记忆/工具定义），prompt engineering 只写指令、context engineering 决定其余一切+留在窗口里的成本；**可把同模型任务完成率从 ~30% 提到 ~90%**。判据：**"还能塞下"不等于"还该塞"——按任务步骤组装窗口，不 append 一切**。提升层：工作流。
2. **Claude Compaction 机制与工具结果清理**（来源：platform.claude.com compaction/context-editing 2026-06-24+2026-09-22 + CSDN 2026-04-07 + nathanonn 2026-05-01）——server-side compaction 是长对话+agentic 工作流推荐策略：接近窗口上限自动摘要旧上下文，`compact_20260112` 策略加进 `context_management.edits`；压缩后回到 ~2-3k tokens；**Claude Code 四层压缩按固定顺序触发、前一层能解决就不启动后一层**：HISTORY_SNIP（历史裁剪）→ CACHED_MICROCOMPACT（缓存微压）→ CONTEXT_COLLAPSE（上下文塌缩）→ REACTIVE_COMPACT（响应式压）；**tool-result clearing：丢旧的可重新获取的工具结果，但保留"调用发生过"的记录**；1M 窗口当保险：~120k 就重置（Nate Herk 启发式）保持全质量。判据：**工具结果按"能否重新取回"分层，能重取的旧结果只留调用记录**。提升层：工作流。
3. **结构化输出三层防御 + 5% 失败率数据**（来源：sureprompts 2026-07-30 + futureagi 2026-05-14 + baeseokjae 2026-05-10）——**单独 "respond in JSON" 在旗舰模型上也有 ~5% 失败率**（1 万条/天=500 条坏提取）；三层防御：原生 structured-output 特性 + schema-in-prompt 带工作示例 + validate-and-retry 兜底；strict mode 把 schema 编译成状态机在解码时掩码非法 token；**嵌套 ≤2-3 层**；reasoning 字段放 answer 字段前；字段描述模型可见、是 prompt 的一部分。判据：**解析方必须有 validate-and-retry 层，不能信任"提示了 JSON 就合法"**。提升层：工作流。
4. **Agent 评测 grader 纪律：评产物不评路径**（来源：anthropic.com demystifying-evals 2026-01-09 全文实拉）——grader 类型：llm_rubric / state_check（环境终态）/ tool_calls / transcript 约束（轮次上限）/ tracked_metrics（n_turns/n_toolcalls/延迟）；**outcome 是环境终态不是 agent 的话**（说"已订票"≠数据库里有预订）；**别查"特定工具调用顺序"——agent 常找到评测设计者没预料的合法路径，太脆；评"产物"不评"路径"**；多组件任务给部分学分（正确识别问题+验证客户但没处理退款，显著好于立即失败）；**LLM judge 每个维度独立评、不一个 judge 评全部维度；给 judge 出路（信息不足返回 Unknown）防幻觉**；LLM judge 与人类专家校准。提升层：可复用 Skill。
5. **eval 陷阱清单 + eval saturation + eval-driven development**（来源：anthropic.com demystifying-evals 全文）——Opus 4.5 CORE-Bench 42%→95%：修复 rigid grading（惩罚 "96.12" vs 期望 "96.124991"）、歧义任务说明、不可复现随机任务；METR 发现任务要求优化到分数阈值、但评分要求超过阈值（**惩罚了照指令做的模型、奖励无视目标的模型**）；**eval saturation：SWE-Bench 30%→80% 接近饱和，大能力提升只显示为小分数增长**（Qodo 一次性编码 eval 没抓到长任务增益）；读 transcripts 验证"失败是否公平"（agent 真错 vs grader 拒了合法解）；**eval-driven development：先建 eval 定义计划能力、再等 agent 达成；capability evals 低通过率让模型进步可见**；dedicated evals 团队管核心基建、领域专家贡献任务。判据：**分数不直接采信，先读几条 transcripts 再下结论**。提升层：可复用 Skill。
6. **RAG 生产管线：RRF+精排两阶段**（来源：tensoria 2026-05-15 + arpanet 2026-06-18 + dev.to 2026-09-01 + 腾讯云 2026-09-18）——dense（语义）与 BM25（精确词，产品码/缩写）互补失败；**粗排（向量+BM25，快、召回面大、管"别漏"）→ RRF（k=60）融合 → 精排（cross-encoder 重排 top 100-150，管"别错"）→ top 5-10 给 LLM**；精排 +10-30% 精度，是最高 ROI 步骤；pgvector 单库同时支持向量+全文索引（免单独向量库）。提升层：工具。
7. **记忆三存储 + 遗忘治理**（来源：data-gate 2026-07-19 + zylos 2026-06-03 + growthengineer 2026-05-04 + AWS 2026-06-05 + metacto 2026-04-14）——**episodic 记忆存带结构化元数据（任务类型/成败/用户满意度）支持过滤检索，不只相似度**；value-scored forgetting：按新颖性/任务相关性/时效性打分修剪，优于无限增长与滑窗淘汰；定期记忆整合（episodes→semantic 提取）；**Mem0 报告 90% token 减少 vs 全上下文、Letta ~83.2% LongMemEval**；HLTM（LinkedIn Hiring Assistant）：统计用户历史问题分布，调整"下次提取记住什么"；**Anthropic Memory for Managed Agents（2026-04-23 public beta）：文件存储+per-write 审计日志+跨会话跨 agent 共享，Rakuten 97% 错误率下降——不是模型变聪明，是不再每会话重学教训**。提升层：工作流。
8. **Magentic-One manager + DAG Plan & Execute + routing 归类 agent**（来源：learn.microsoft.com magentic 2026-09-22 + arXiv 2606.20058 + astraeus 2026-04-28 + future-of-software 2026-06-01）——Magentic-One：manager 根据演化上下文/进度/能力选下一个 agent，维护共享上下文；DAG Plan & Execute：Planner 前置生成执行图 + Executor 派发 + **Replanner 条件变化时调整——计划与执行分离、可并行、可恢复**；**routing 本身是认知任务应属于 agent 而非编排核心**（分类器 agent 返回类型化结果，可测试可版本化）；supervisor+worker 最小清单：单决策所有者、外部调用全走该 agent、每条 job 一个 trace。提升层：工作流。
9. **task-aware retrieval：按任务类型路由检索**（来源：fordelstudios 2026-09-02 + dev.to lusivision 2026-08-28）——事实查询→向量库紧相似度阈值；推理任务→知识图谱查实体关系；**工具调用→只加载相关工具定义（不是全部 50 个工具）**；查询改写+按元数据上下文过滤（时效/来源权威/域）；**cached input $0.30 vs uncached $3（Manus 报告，10 倍价差）——cache hit rate 是关键成本变量**。判据：**检索层按意图分流，不是所有查询走同一管线**。提升层：工作流。
10. **Hallucination Loop + Tool-Call Storms 两故障模式**（来源：businesstechnavigator 2026-05-03）——**幻觉循环：agent 出错→观察到错误→用导致错误的同一推理修错→无限循环直到预算或窗口耗尽**，需要独立 Sovereign Auditor 打断；**工具风暴：agent 不确定怎么办时同时调所有可用工具→自我 DDoS**；修法：审计者与执行者分离+工具调用速率限制+每工具白名单。提升层：工作流。
11. **GitHub agent 生态：并行 agents 与技能蒸馏**（来源：agentconn 2026-09-01 + osrepos 2026-09-21 + startupcorners 2026-09-23 + trendshift 2026-09-24）——**Orca ADE（59k stars）：Agent 开发环境，并行 25+ coding agents 跑在 worktrees**；scientific-agent-skills（41k stars）：165 个验证过的生物/化学/医学技能、190,000 科学家在用；**AREX-Skill：从 1,000+ 热门仓库蒸馏 5,000+ 可执行技能**（把仓库知识变成 coding agent 直接可用的操作知识）；agent-browser（43k，Rust 浏览器自动化 CLI）；langgraph 42k。判据：**技能库来源从"手工写"转向"从优秀仓库蒸馏+验证"**。提升层：工具。
12. **评测运营养护：读 transcripts + 防绕过 + 开放贡献**（来源：anthropic.com demystifying-evals 全文）——评测套件是活物：dedicated evals 团队管核心基建+领域专家/产品团队贡献任务；**grader 防绕过：通过必须真解决问题，不能 exploit 漏洞**；PM/客服/销售可用 Claude Code 以 PR 形式贡献 eval 任务；自动化 eval 只是全貌一角（+生产监控/用户反馈/A-B/人工 transcript 审阅/系统化人类评估）。提升层：可复用 Skill。
