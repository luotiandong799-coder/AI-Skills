## 独点（12）

1. **失败分类驱动恢复 + verify-before-retry**（来源：arXiv 2606.01416 自愈编排 2026-06 + arXiv 2608.02645 2026-08 + channel.tel 2026-06-09）——每类失败不同响应不只不同重试次数：工具选错→重规划换工具约束候选；上下文过时/不足→刷新检索换源更新记忆；矛盾证据→独立来源交叉验证+verifier；执行错误→上下文感知重试（先把失败原因写进工作记忆再决定等/换路径）；**verify-before-retry：不确定结果先查预期后置条件是否已满足**——非原子失败下避免不必要重试（幂等扩展）。判据：**重试前先验证"动作是否其实已成功"，不盲目重调**。提升层：工作流。
2. **重试预算两级 + 熔断器 + at-most-once park**（来源：chiraghasija 2026-07-30 + dev.to 2026-07-14 + agentnative 2026-07-25 + n8n blog 2026-07-03）——**重试预算两级：per tool call（如 2 次）+ per run（如 max_steps 12 / max_cost $1）**；连续失败 3 次+60s cooldown 熔断停止升级（不烧 token 打注定失败的调用）；模型重试硬计数（超 3 次截断循环+显式告警）；**at-most-once 工具请求已发送后失败永不自动重试——workflow park，人工看 INTENT 记录+provider 证据决定是否重发**；不该盲重试：validation error/permission denied/副效应未验证的重复请求；每个工具设超时。判据：**"重试"必须有预算、熔断与人工兜底三层，否则就是烧钱循环**。提升层：工作流。
3. **prompt caching 断点结构 + write 成本溢价**（来源：octomind 2026-09-18 + aiworkflowlab 2026-07-15 + langchain deep-agents 2026-06-26 + datadog 2026-09-02 + openai GPT-6 2026-09-22）——**静态前缀（system+工具+示例+大文档）在前、动态部分（用户查询）最后**；Claude 显式 cache markers、5 分钟 TTL；**cache write 比无缓存贵：5min 1.25x / 1h 2.0x，read 仅 0.1x——断点设错反而更贵**；真实 agent 轨迹缓存省 49-80% token 成本（claude-haiku-4-5 -77%、gpt-5.4-mini -80%）；GPT-6 缓存默认更高命中率+30 分钟 TTL+断点确定化；Gemini 32k 最低、75% off。判据：**缓存失败是静默的（响应一样）——必须监控 cache hit rate，断点位置决定 write/read 成本结构**。提升层：工作流。
4. **渐进披露三级数字 + skill 是文件夹**（来源：claude.com skills-explained 2026-03-05 + claude.com Claude Code skills 2026-06-03 + resources.anthropic.com Complete Guide）——**三级：YAML frontmatter 常驻 system prompt（~100 tokens，够判断何时用）→ SKILL.md 命中时加载（<5k tokens 全指令）→ 捆绑文件按需读取**；**"skill 是一个文件夹不只是 markdown 文件——整个文件系统是上下文工程的一种形式"**（Claude Code 实践：告诉 Claude skill 里有哪些文件、它按需读）；400+ 设计技法只在需要选技法时才加载。判重：与 r304B"技能写作"重叠部分，三级具体 token 数字+文件夹观为独有增量。提升层：可复用 Skill。
5. **hooks 事件分类与确定性机制**（来源：zylos 2026-03-27 + getboris 2026-04-17 + AWS Strands 2026-07-09 + Azure SRE 2026-06-05）——事件分三级：session 级（SessionStart/SessionEnd）、turn 级（UserPromptSubmit/Stop/StopFailure）、tool 级（PreToolUse/PostToolUse/PostToolUseFailure/PermissionRequest/PermissionDenied/SubagentStart）；**PermissionRequest 可阻塞（exit 2）→ 自动 allow/deny 策略免人工；PermissionDenied 可 retry:true 提示重试**；BeforeModel 改系统指令/换模型/mock 响应；**确定性机制（command/HTTP hooks 由 harness 注入）与推断机制（prompt/agent hooks 靠模型判断）分开**；Azure SRE：Stop 钩子验证完整性拒绝强制继续。判重：r304C"hooks 九事件"重叠部分，阻塞语义+三级分类+deterministic/inferential 分型为独有增量。提升层：工作流。
6. **checkpoint 每节点粒度 + 幂等前提 + checkpoints≠durable execution**（来源：openlegion 2026-06-01 + ailearningguides 2026-05-06 + zylos 2026-03-04 + diagrid 2026-02-25）——20 步管线第 14 步崩→1-13 全白费（tokens/工具成本/时间重花）；**checkpoint 每节点粒度：至多重做 1 个节点**；三模式：SQLite（单进程中等规模）/ 远程 store PostgreSQL/DynamoDB（分布式）/ 混合（本地快路径+远程持久）；**幂等是 checkpoint 安全前提**（写工具非幂等则重放=重复副作用）；**checkpoints ≠ durable execution**：checkpoint 要手动恢复代码，durable execution（Temporal）自动重放事件历史重建状态。判据：**长任务按自然边界持久化+每步幂等，崩溃从最后检查点续跑**。提升层：工作流。
7. **GraphRAG 触发时机 + 向量 RAG 局限**（来源：channel.tel 2026-06-27 + neo4j 2026-09-23）——向量 RAG 按"读起来像不像问题"排序不按"事实如何关联"；**GraphRAG 超 2 倍事实准确率+更好 token 效率+可追溯源路径**；**触发时机：有文档化证据 agent 对"需连接多源事实"的问题答错——那些案例就是 GraphRAG 测试集，两种检索都跑对比准确率再决定**；简单文档问答不需要图（过早投资）；多 agent GraphRAG（AST 知识图谱→代码→部署物，65% 超向量基线）。判据：**先有"多跳失败的证据"再上 GraphRAG，不因热度投资**。提升层：工作流。
8. **LLM 可观测性三循环 + 成本尖峰=bug 信号**（来源：datadog 2026-07-10 + aidiveforge 2026-09-26 + mlflow 2026-06-18 + langchain 2026-08-16）——**trace→eval→monitor 循环：capture spans→对 traces 跑评分→cron 调度让回归在用户发现前暴露**；**token 成本尖峰常是 bug 信号**（agent 意外循环/检索误触发/上下文窗设到最大），设阈值或异常检测告警；**per-agent/per-run/per-user token 治理是生产底线**（一夜失控循环=意外账单）；**session 级评估优于单调用评分**（多数工具只评单调用、漏跨会话累积漂移）；message-bus 级可见性（只 trace LLM 调用会漏竞态与无限循环）。提升层：工作流。
9. **PromptArmor 注入检测数据 + OWASP Agent Memory Guard + egress 默认拒绝**（来源：zylos 2026-05-11 + owasp.org agent-memory-guard 2026-08-30 + exploreagentic 2026-06-09）——**PromptArmor（ICLR 2026）：让现成 LLM 当注入检测器（GPT-4o/4.1/o4-mini），AgentDojo 上 FP/FN 均 <1%，移除检测到的注入后攻击成功率 <1%**——检测器是防御第一层且很便宜；**OWASP Agent Memory Guard：持久记忆可被运行时写入并跨会话存续（与模型权重不同），被篡改导致跨会话恶意行为**——记忆要防投毒不只防注入；**egress allow-list 默认拒绝出站（只允许任务需要的端点）最直接防渗透**——注入让 agent 尝试外传也发不出去。判重：r304A"记忆投毒跨会话"已有概念，PromptArmor 数据+Agent Memory Guard 专门项目为独有增量。提升层：工作流。
10. **GitHub Agentic Workflows：Markdown→YAML + 免 PAT + 三重控制**（来源：github.blog 2026-06-11+2026-07-23 + gh-aw weekly 2026-07-13）——**自然语言 Markdown 文件定义自动化（.github/workflows/），编译成标准 Actions YAML**，复用 runner groups 与策略约束；issue triage/CI 失败分析/文档更新；**用 GITHUB_TOKEN 不再需要 PAT（消除长期 PAT 运维与安全风险）**，AI credits 账单到组织；gVisor 沙箱 runtime（处理不可信输入）；**agent automation controls 三重控制：Approvals（建议而非应用，问题面板等批准）/ Confidence（高置信度自动应用，中低留建议）/ Rationale（每个动作记录理由）**；fork PR 批准门可程序化解锁（带保护文件检查+作用域限制）。提升层：工具。
11. **层次化反思 + AND/OR 树规划 + leaf task 1-2 工具调用**（来源：arXiv 2606.10507 HIPIF + IFAAMAS ReAcTree + arXiv 2603.05294 StructuredAgent + agenticai.varasrinivas）——**层次化反思：agent 显式评估进度+诊断失败模式再决定下一步，反思成为 subgoal 终止/转换/执行的控制机制**（不是事后复盘）；StructuredAgent：AND/OR 规划树，Or 节点=备选策略，agent 能回退到备选路径并产出可解释计划；**leaf task 应小到 1-2 次工具调用**；顶层 3-5 phases→每 phase 具体行动；ReAcTree 从 episodic memory 检索 subgoal 级示例。判据：**长任务拆到"每个叶子 1-2 次工具调用"的粒度，反思挂在 subgoal 边界**。提升层：工作流。
12. **Planner/Executor/共享记忆三层 + 沙箱执行环境**（来源：dev.to 157 agent runs 2026-08-24 + codeguilds 2026-07-19 + 鞭牛士 2026-09-28）——**Strategy Planner（强模型长窗口：持全局上下文、拆解目标、派发、验证）+ Specialist Executors（小模型高通量：窄域单任务）+ 共享记忆层（知识图谱/向量库防冗余工作）**；规划结构应含 ownership metadata+资源预算+交接协议；**沙箱执行：agent 生成代码跑在 Docker/Wasm/microVM 短生命周期容器、无驻留内网/secret/主机访问权**；NVIDIA OpenShell（CPU 层锁操作权限）+Sentry（网络芯片独立监控）硬件级约束。判据：**凡是执行不可信输入的 agent，默认进沙箱+出站白名单，否则不接**。提升层：工作流。
