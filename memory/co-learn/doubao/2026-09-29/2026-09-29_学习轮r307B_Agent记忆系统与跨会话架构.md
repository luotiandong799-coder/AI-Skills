## 独点（12）

1. **记忆四层模型 + write-manage-read 循环**（来源：arXiv 2603.07670 + cdovey 2026-06-05 + mer.vin 2026-05-20）——**working（当前任务活动上下文，本 turn）/episodic（时间戳事件日志，长期）/semantic（蒸馏去重事实，长期）/procedural（可执行技能+工具契约）**；**naive 实现把三类全塞进一个向量库=错误形态**；**记忆是 write–manage–read 循环与感知行动耦合**；**五机制族：context-resident compression/retrieval-augmented stores/reflective self-improvement/hierarchical virtual context/policy-learned management**；**Pattern A monolithic context（全在 prompt，容量封顶易摘要漂移）vs Pattern B context+retrieval store（工作记忆在窗口+长期记录外置检索注入，生产工作马）**。判据：**先定记忆形态再选后端——向量库不是记忆，只是 semantic store 的一种后端**。提升层：工作流。
2. **三 store 分离与分层加载顺序**（来源：sangampandey 2026-04-16 + callsphere 2026-04-23 + agenticai.varasrinivas 2026-06-04）——**episodic 存事件日志（"上周二用户批准 Q3 预测"）、semantic 存蒸馏事实（"用户偏好 Python"）、procedural 存可复用动作序列模板（"search→filter→summarize→respond"）——存 Git/prompt registry/tool manifests**；**加载顺序：procedural 先（定义行为）→semantic 次（用户/域上下文）→episodic 最后（过滤相关性）——比纯 episodic replay 省约 70% token**；AdMem：procedural 检索用"记忆条目有效性评估+上下文相似度"双信号。判据：**每轮把三类记忆全量注入=把记忆做成上下文膨胀器；分层按优先级加载是 token 经济的关键**。提升层：工作流。
3. **记忆系统谱系：向量→KG→时序 KG**（来源：sickn33 memory-systems SKILL + anjangoswami survey + arXiv 2604.01707）——**simple vector stores 缺关系与时间结构→知识图谱保关系（reasoning）→时序知识图谱加 validity periods（时间感知查询）**；**MemGPT 操作系统虚拟内存：in-context/external storage 智能交换（层级上下文管理）**；**Titans neural long-term memory（神经长期记忆）**；A-MEM Zettelkasten 动态自进化知识网络（自动生成链接+精化表示）；GAM 层级图；HippoRAG 图记忆；**graph-based extraction：LLM 提 subject-predicate-object 三元组+创建/失效时间戳（Mem0g/Zep），支持动态更新与时序推理**；MemoTime 记忆增强时序 KG 让小模型达 GPT-4-Turbo 推理水平。判据：**查询复杂度决定记忆形态——简单回忆向量够，关系推理上 KG，时间敏感上 temporal KG**。提升层：工具。
4. **会话压缩三层架构 HOT/WARM/COLD**（来源：zylos 2026-06-08 + kunalganglani 2026-07-04 + vibeengines 2026-07-20）——**HOT=当前会话+即时相关事实（小时-天）/WARM=偏好+当前项目+近期决策（2K-8K token，天-周）/COLD=历史会话+完成项目（无限，vector-indexed，月-年）——减少约 60% 活动上下文**；**每 10-20 轮跑总结 pass（20 条消息压成 200-token summary 从 hot 移 warm）**；**rolling summary=近期逐字+滚动摘要+外部记忆=生产配方**；memory decay：低重要度事实 N 交互后过期丢弃；LazyMem：延迟到查询时构建记忆（retrieve broadly, construct selectively）。判据：**压缩不是丢信息是迁移层级——hot 保粒度，warm 保精华，cold 保可检索**。提升层：工作流。
5. **记忆评测基准：LongMemEval/Memora/FAMA**（来源：arXiv 2605.12493 + supermemory + ACL 2026 findings.1337）——**LongMemEval 五能力：information extraction/multi-session reasoning/temporal reasoning/knowledge updates/abstention（识别历史无法回答的问题）——商用助手与长上下文 LLM 持续交互记忆掉 30%**；**multi-session synthesis 是最难类别：多分离会话信息合成（要识别多片段相关→全检索→拼上下文）**；**knowledge updates：47 轮偏好变了，用新偏好吗**；Memora：周/月/季三时间跨度×remembering/reasoning/recommending 三任务；**FAMA 指标明确惩罚依赖过期记忆**。判据：**记忆系统评测必须含 knowledge updates 与 abstention——只测回忆率会漏掉"该忘没忘"与"该拒答没拒答"**。提升层：可复用 Skill。
6. **记忆工具选型：Mem0 vs Zep/Graphiti vs Letta**（来源：dev.to mukesh 2026-09-22 + aiworkflowlab 2026-05-25 + automem 2026-06-06）——**Mem0：LLM 驱动提取+比较+反射（ADD），存提取事实非原文片段，比 naive RAG 省 80-90% token；分层记忆 user/session/agent；向量+可选图**；**Zep/Graphiti：时序图跟踪"每个事实何时为真"，双时序建模（world-time vs acquisition-time）避免静默覆盖——需审计"当时什么为真"用**；**Letta（=MemGPT 生产框架）：agent 主导 read/write/edit 内存，层级访问虚拟内存分页，可审计**；**选择判据：LangGraph 已有→LangChain primitives；多用户事实变化+自动调和→Mem0；时间审计→Zep；自主长期 agent→Letta**；**RAG 管文档知识库，记忆系统管用户/会话记忆——聊天历史召回上记忆系统显著优于 naive RAG**。判据：**先问需求（自动调和/时间审计/agent 自主）再选工具，检索质量不是主要区分点**。提升层：工具。
7. **检索时机：两时刻 + 会话启动扫描 + hot-path/dreaming**（来源：mem0 voice 2026-09-03 + matthewjayhunter 2026-03-24 + datasciocean 2026-04-05 + mem0 proactive 2026-05-01）——**两时刻分离：LLM 调用前检索注入 + 响应交付后异步提取写入（不阻塞响应）**；**每 turn 检索有 50-200ms 语义搜索开销，亚秒响应需批量/混合检索**；**UserPromptSubmit hook 每提示并行召回（facts+context hints）**；**session-start scan：首条消息前用环境信号（时间/打开项目/最近文件）预取**；**just-in-time vs upfront retrieval 是上下文工程最重要架构决策**；**Hot-path（任务完成时刻更新即时纠错）vs Dreaming（离线批处理扫描 traces 总结高阶规则防 memory bloat）**。判据：**"何时检索"与"检索什么"同等重要——把全部记忆每次注入=91% 延迟浪费**。提升层：工作流。
8. **写入决策：三决策 + write gate 三分类 + 四操作**（来源：chiraghasija 2026-06-17 + joelclaw 2026-03-02 + chatforest 2026-03-28 + dev.to haoning）——**写路径三决策：extract→deduplicate→resolve conflicts；不是每条消息都值得存（写一切=在更慢数据库重建 buffer）**；**semantic facts 新覆盖旧；episodic events 都保留（不同时间点事件都是独立事实）**；**write gate 三分类：allow（持久事实默认检索）/hold（模糊或上下文相关，存但不默认检索）/discard（噪音直接丢）**；**四操作：Merge（相关记忆合成更丰富记录）/Supersede（新覆盖旧保留历史）/Deduplicate（语义相似检测——同一事实 4 条不同措辞是常见失败）**；**composite score（Generative Agents）：recency+importance+relevance 混合打分；significance-gated consolidation：累积重要性超阈值才触发反射（Smallville 每天 2-3 次）**。判据：**写入是记忆系统最容易烂的环节——不 dedup 的存储检索时全是噪音**。提升层：工作流。
9. **记忆毒化防御：injection-execution dissociation**（来源：arXiv 2605.08442 + arXiv 2609.13889 + meridian docs + agentpatterns trojan-hippo）——**注入成功与工具执行成功是可分离安全性质：阻塞注入≠阻塞执行——恶意指令存储率 97.5% 但执行率 0-95% 无相关性，防存储与防执行两个都要**；**PMPA：恶意指令嵌良性外部源→诱导 agent 写入持久记忆→后续会话检索触发+隐私泄漏（"Poison Once, Exploit Forever"）**；**Trojan Hippo：休眠载荷由敏感话题触发（无需查询控制/微调访问）**；**MERIDIAN：每次召回记忆进模型前筛查——standing directive（命令/覆盖/权威声明）且 provenance untrusted → 隔离**；**user-prompt-only writes 把 ASR 降到 0-5% 但失去助手输出/工具返回记忆**；**transient threats become persistent：单一被破坏交互静默塑造所有未来行为，XPIA 变连续 XPIA**。判据：**记忆是持久注入面——写入筛查+召回前筛查+provenance 标记三层都要**。提升层：可复用 Skill。
10. **文件式记忆最佳实践（Claude Code 系）**（来源：claude docs memory + yourdocs + claudify 2026-06-11）——**CLAUDE.md（用户写持久指令）+ Auto memory（agent 自写 notes：~/.claude/projects/<dir>/memory/MEMORY.md，上限 200 行/25KB 启动加载）**；**memory tool：agent 用文件操作 create/read/update/delete 跨会话积累，just-in-time 检索（记录-按需读而非 upfront 全载）**；**focused stores：小目的存储（每用户/共享域知识/项目上下文独立），每个独立 10K 上限防单店装满**；**memories.delete 清理陈旧/冗余——不主动管理会装满**；**会话无默认持久记忆是设计决策：隔离防跨会话污染**；claude-mem（AI 压缩会话日志注入）+ Claude Subconscious（Letta 后台 agent）。判据：**文件式记忆上限即约束（200 行/25KB）——主动剪枝是日常，不是偶发**。提升层：可复用 Skill。
11. **记忆生命周期治理**（来源：AWS AgentCore 2026-09-04 + metacto 2026-06-10 + besthub 2026-04-21）——**两写策略：turn-end extraction（小模型每轮读 transcript 提候选事实，typed semantic/episodic，dedup 写——Mem0/LangMem 模式）vs session-close reflection（大模型会话边界总结 episodic+更新 semantic）**；**不主动管理→过期上下文累积：客服 agent 引用 4 个月前已解决的账单纠纷当活跃问题**；**superseded 记录标 INVALID 不删除保审计（AgentCore）**；**Zep Graphiti 双时序建模（world-time vs acquisition-time）避免静默覆盖**；**namespace 设计：命名空间决定记忆组织/检索/谁能访问——设计错=无关上下文浮现或用户记忆互漏**。判据：**记忆治理=过期不删是合规风险，删了不可审计——标 INVALID 是中间态**。提升层：工作流。
12. **记忆系统生产五阶段管线 + 实体图**（来源：besthub 2026-04-21 + moai.team 2026-07-19 + futureagi glossary）——**五阶段：提取→关系判定（LLM 决定记忆间关系）→按类型存储（不同记忆类型不同后端，勿全塞一个向量库）→检索→审计（每条操作审计轨迹）**；**实体图连接人/账户/票据/文档/工具成可导航上下文**；**四层记忆全景：in-context（活 prompt 窗口）/external-vector（RAG 知识）/episodic-session（跨轮连续性）/parametric（模型权重编码）——各不同延迟/成本/持久/治理属性**；每层记忆独立 write semantics 与主信号（session buffer append+truncate；episodic append+summarize；semantic selective write+dedup+TTL）。判据：**记忆系统是管线不是存储——审计轨迹与实体图是"可解释记忆"的底线**。提升层：工作流。
