## 独点（12）

1. **GUI agent 两类架构：monolithic vs composed**（来源：AIMultiple《Computer Use Agents: Benchmark & Architecture》2026-06 + cua.ai《What is a Computer-Use Agent》2026-04 + calmops《GUI Agents Complete Guide 2026》2026-06）——**monolithic：感知+规划紧耦合——小视觉错误不易级联成全面失败（动作失败可重评估更新后的屏幕并自适应），但难 inspect 中间决策/隔离失败源；composed：把交互循环分阶段，每阶段不同模型/子系统——grounding 模型精确定位元素（屏幕坐标或窗口句柄），规划模型负责决策**。判据：**要可调试选 composed，要端到端自适应选 monolithic；grounding 与规划分离是生产主线**。提升层：工作流。
2. **Computer Use 范式+Agent S 三组件**（来源：walkinglabs《GUI Agent Training》2026-09 + evermx《Agent S》2026-09 + research.nikiv.dev CUA 2026-06）——**Computer Use 范式：整个 OS=agent 环境；Observation=屏幕截图（可叠加 window/cursor/accessibility-tree 辅助信息）；Action=模拟鼠标键盘或直接执行脚本——浏览器/Excel/OA/Photoshop/游戏无公开 API，只有屏幕与鼠标键盘事件**；**Agent S 三组件：Vision Encoder（UI-TARS-1.5-7B 元素检测+grounding）/ Planning Module（层级规划+子任务生成）/ Reflection Engine（动作后验证+错误恢复）**；CUA：跨模型（Claude/GPT-4o/Gemini/UI-TARS）+沙箱 VM（macOS/Linux/Windows）截图→推理→执行循环。判据：**GUI 自动化=视觉感知+动作执行+验证闭环三件套；无 API 的应用只有 GUI 一条路**。提升层：工具。
3. **GUI grounding 基准族与能力定义**（来源：arXiv 2410.05243 UGround + arXiv 2512.16501 VenusBench + arXiv 2511.04307 GUI-360 + arXiv 2606.06322 DragOn + arXiv 2603.15039 GUI-CEval + dev.to wonderlab《Visual Grounding/DOM/Computer Use》2026-09）——**grounding 定义：把自然语言指令映射到界面图像的 box/region/point；UGround 六基准三类（grounding 桌面/移动/Web+offline/online agent eval）超现有模型最多 20% 绝对**；**ScreenSpot 家族=最早 GUI grounding 基准（NL 引用+screenshot 测"定位"孤立能力）**；**GUI-360 三规范任务：①GUI Grounding（step-level plan→坐标/元素）②Screen Parsing（枚举可交互元素+属性）③Action Prediction（状态+意图→下一动作 click/type/select/API call）**；**GUI-CEval（中国移动）：201 主流 app×四设备，原子能力+应用级两层级，五维=perception/planning/reflection/execution/evaluation，全物理设备**；DragOn：drag grounding（文本高亮/单元格选择/元素缩放/滑块）286K 截图 3.5M 任务。判据：**评测 GUI agent 分 grounding/离线/在线三层；五维能力拆开测，不只看任务成功率**。提升层：可复用 Skill。
4. **元素定位两路：DOM/accessibility tree vs 像素坐标**（来源：anhtu.dev《When AI Clicks, Types》2026-05 + hub.cissychen《Computer Use & Browser Agents》2026-06 + aiagentskit《Playwright MCP》2026-09 + algomaster《Computer Use Agents》2026-06 + arXiv 2511.19477《Building Browser Agents》+ OpenLegion 2026-05 + TechieHub 2026-09）——**DOM-first：序列化页面为紧凑语义树（每元素 id/role/text/关键属性）→LLM 选 id→控制器（Playwright/Puppeteer/CDP）映射回真实元素执行（click(ref="e23") 而非坐标）——确定性/低 token/快**；**accessibility snapshot 优于 screenshot vision：结构化文本给确定性引用，token 少；banner 把输入框推下 4px→坐标点击失败、snapshot 不受影响**；**对比表：DOM-driven 强=稳定 app 干净 markup/可重复流程；弱=canvas/iframe/PDF/legacy 无 DOM；更快更便宜；可调试（失败 selector 可查）；Vision-driven 慢（每步截图+视觉调用）、"点错东西"难追踪**。判据：**浏览器内优先 DOM/accessibility tree，像素视觉只用于 DOM 不可用的场景**。提升层：工具。
5. **浏览器 agent 混合范式：browser-use**（来源：dev.to ifnodoraemon《Under the Hood of Browser-use 100k+ Stars》2026-09 + SkillMD.ai《Browser-Use Pattern》2026-09）——**browser-use（100k+ stars）=DOM tree distillation+vision grounding 混合：模型像人一样导航——眼睛看渲染截图+大脑理解交互语义+规划多步动作+遇到意外 modal/弹窗自愈；取代脆弱 DOM 路径匹配（2026 之前范式）**。判据：**网页自动化=结构优先+视觉兜底双通道，自愈能力是生产必备**。提升层：工具。
6. **GUI 错误恢复与完成验证**（来源：arXiv 2604.21375 VLAA-GUI + extrapolator 2026-09 + arXiv 2605.29447 GUI-RobustEval + OSWorld 2.0 官网 + Future AGI《Computer Use Agent Evaluation》2026-08）——**VLAA-GUI 模块化框架：Completeness Verifier 减少 False Done/Fail 达 5.7%；Loop Breaker 减少 Loop/Failed 4.5%+浪费步数近半；OSWorld 77.5%（Opus 4.6 100 步）超人类 72.4%**；**Loop Breaker 三阶：Level1 同元素重复失败阈值→切换交互模式（click→keyboard）逼出窄动作空间；Level2 屏幕状态 hash 连续步骤重复→检测视觉状态循环→策略变更；Level3 绑定自生成文本提示**；**GUI-RobustEval：1,216 可执行测试用例系统性测错误恢复，RoTS-32B OSWorld 47.4%+All-Pass@4 33.8%——长时错误恢复贡献鲁棒性与整体性能**；**OSWorld 2.0：108 长时工作流，人类中位 1.6 小时，Claude Opus 4.7 平均 318 工具调用（vs v1 的 30）；Opus 4.8 二进制完成仅 20.6% 但 partial 54.8%——长时任务用 partial credit 指标更反映能力**。判据：**长时 GUI 任务=完成验证器+循环检测器标配；评估用 partial score**。提升层：工作流。
7. **推理时失败驱动自我改进**（来源：alphaXiv/arXiv 2606.31270《Learning from Failure》2026-06 + blog.captcha.la 2026-06）——**LLM meta-controller 分析失败轨迹→识别结构化失败模式→合成目标代码级补丁（视觉搜索/终端命令执行/知识检索/重复检测）→轻量人工验证→升级 agent 推理时行为（无需再训练）**；**OpenCUA-72B 基线 42.3%→48.9%（4 轮失败循环）**。判据：**失败轨迹=训练数据：推理时补丁循环可作为无训练的性能杠杆**。提升层：工作流。
8. **视觉断言测试模式**（来源：markaicode《Vision Model QA》2026-04 + scrolltest《AI Visual Testing》2026-06 + arXiv 2507.10062 LLMShot + arXiv 2607.28750 DragonCrawl + docs.stably.ai aiAssert + mech.app Midscene.js 2026-05 + qiita《自律型VRTエージェント》2026-05）——**把截图当一等测试输入：vision model 建 QA 层测"感知"不测逻辑——自动化主观/人工密集 UI/UX 部分；AI 视觉测试理解布局/排版/色彩对比/语义结构（vs 逐字节像素对比对 anti-aliasing 狼来了）**；**aiAssert 三步：稳定化（等页面稳定+截图）→AI 分析（按 prompt 用 vision 模型评估）→断言结果（满足则过，否则自然语言解释缺什么）——每个断言一次 AI 调用**；**LLMShot：VLM 语义分类 snapshot 失败（真实 UI 变化 vs 预期变化，Gemma3 12B >84% recall）**；**DragonCrawl：意图驱动端到端测试——模型认为目标可能达成时触发 end-state detection 查询（"has user reached receipt page?"）→yes/no+解释**；**Midscene.js 六步纯视觉自动化：Capture→Annotate（可选叠加标签/bbox）→Infer（图+NL 查询）→Parse（提取 bbox 坐标）→Execute（坐标转平台动作 Playwright/iOS tap/ADB）**。判据：**视觉回归用语义判断替代像素 diff；end-state 用自然语言断言而非 selector**。提升层：可复用 Skill。
9. **合成 GUI 数据管道**（来源：arXiv 2602.07153 Anchor + arXiv 2512.10962 WebSTAR + arXiv 2604.14262 GUI-Perturbed + arXiv 2605.12501 CUActSpot + docs.voxel51 FiftyOne + fig.inc《Domain Randomization》2026-06 + arXiv 2607.14548 HyMobileAgent）——**Anchor 分支点扩展：小集验证 seed 演示→识别对应有意义状态变化的分支点→基于当前 GUI 上下文提出新状态接地任务变体→执行 agent 生成新轨迹→verifier 状态感知检查+轨迹一致性→任务条件步级过滤**；**域随机化（from robotics）：沿受控轴（颜色/布局/指令措辞）变化视觉场景与指令暴露脆弱行为；GUI-Perturbed：Mind2Web step+MHTML 渲染+视觉扰动+重定位 target bbox+生成直接/关系指令**；**WebSTAR：teacher CUA 真实网站 rollout（raw noisy）→thought augmentation（专有 CUA 无显式推理补 reasoning trace）→step-level filtering**；**CUActSpot 渲染合成：代码渲染工具出截图+元素坐标（bbox/形状）+LLM 生成指令与动作轨迹——Phi-Ground-Any-4B 训后超 <32B 开源模型**；**FiftyOne：739 真实→4,036 合成（灰度/色彩反转/色盲模拟+文本增强）保标注精度**。判据：**GUI 训练数据=seed 演示×分支扩展/域随机化/渲染合成三管道，verifier 保质量**。提升层：工具。
10. **VLM vs OCR 场景选型数字**（来源：Transformance《Vision Language Model》2026-05 + essenn.associates《VLM-Powered Document Understanding》2026-04 + ai-tldr《Vision Models for Document AI》2026-06）——**标准单格式文档（一供应商一致布局）：OCR+模板 96-99% vs VLM 95-98%——OCR 模板略胜；多格式（多供应商不同布局）：OCR 多模板 75-88%（随格式数退化）vs VLM 93-97% 与格式数无关；复杂文档（表格+混合内容）：VLM 胜**；**可变 AR 文档字段级准确率 VLM 95-99% vs 纯 OCR 75-85%；多行表格 95-97% vs 60-75%**；**五提示技术（70%→95% 提取准确率）：①显式 JSON schema（字段名/类型/null 说明——缺失字段给 null 防 schema drift，模型把 schema 当 checklist）**。判据：**选型按格式可变性：单一格式 OCR 模板更省，多变格式直接 VLM**。提升层：工作流。
11. **字段级准确率与置信度融合**（来源：imagetotable《Invoice Data Extraction Accuracy Guide》2026-09 + DZone《Accurate Invoice Data Extraction》2026-02 + arXiv 2608.01792 ConfBench + arXiv 2510.15727 INVOICE + jisem SmolVLM）——**字段级准确率=正确提取字段数÷总字段数（20 发票×10 字段=200，错 15→92.5%——这是关键数字）；还要算 recall=应提取字段里多少被找到（漏提字段必须算错）**；**多源信任系数加权置信：Gemini 与 Mistral OCR 选同值→信任系数和÷总信任系数（A90+B85+C80→175÷255）**；**ConfBench：OCR+Image 模态置信估计更准；模型能力是置信质量主导因素（Claude 家族随能力单调），跨家族参数数量预测性差；校准质量差异大（near-perfect 到严重过度自信）→per-model post-processing 必需**；LM-Kit：符号 AI 层+fuzzy logic+专家系统组合防 LLM 幻觉。判据：**文档提取用字段级准确率+recall 双指标；低置信单元格转人工复核（与视觉提取三纪律的置信度标注同源）**。提升层：可复用 Skill。
12. **视觉输入预算管理**（来源：promptz2h《Resolution & Detail Control》2026-06 + awesomeagents《AI Vision Input Limits》2026-04 + Google Cloud《MEDIA_RESOLUTION》2026-07 + arXiv 2603.16932《Look Where It Matters》+ max-gherman《Multimodal Agents》2026-08 + aiagents.codeguides 2026-07 + callsphere《Cost Optimization Vision Browser Agents》2026-03）——**分辨率-细节权衡：1024²≈600-800 token；2000²≈1500+ token；聪明分辨率选择提升精度 10-20% 降成本 30-50%**；**OCR/标注任务裁剪区域而非全图：读 4K 截图角落 12px 文字→裁剪角落单独发送——500×500 native crop 胜过 4000×3000 downscale 到 1568px（目标文字变 3px 高）**；**Gemini 分辨率档：HIGH 1120 / MEDIUM 560 / LOW 280 token**；**裁剪工具成本不对称函数：遗漏 HR 调用罚 α_miss、用工具罚 α_use+λ‖C‖——防模型要么乱裁要么不裁**；**多模态 agent 上下文预算：一张高分辨率图=数千 token——显式策略（何时全图/何时降采样/何时提取文本丢视觉）；观察类型倍增（screenshot 图/transcription 文）编排器处理异构格式**；**浏览器 agent 截图纪律：只拍 viewport 不全页滚动高度；只在需要时发图（导航后/点击前）；一张带标注裁剪>五张冗余全图；历史丢弃过期截图**。判据：**视觉输入按"任务需要的最小分辨率+裁剪+按需发送"管理，token 预算是多模态 agent 的第一成本约束**。提升层：工作流。
