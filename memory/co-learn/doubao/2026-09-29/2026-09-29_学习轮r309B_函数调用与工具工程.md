## 独点（12）

1. **并行工具调用协议**（来源：zylos 2026-04-16 + aiworkflowlab + claudexia + chenk）——**frontier 全支持并行：模型单回合可发多个 tool_use 块——正确模式=抽取全部块→并行执行（asyncio.gather/Promise.all）→所有 tool_result 一次返回同一用户消息；拆分结果到独立消息=隐式教坏模型（它学不到"一次拿全"）**；**量化：5-tool agent 串行 5×200ms=1s 纯工具延迟，并行=1 回合**；**"东京纽约天气"应同时两次 get_weather 而非两个回合**。判据：**并行是 API 层能力不是 agent 层选择——应用层必须会收数组并并发分发**。提升层：工具。
2. **工具税与 token 开销量化**（来源：getdraft + aiworkflowlab + dreaming.press + adarsha）——**开发者常见 5-15 MCP servers=100-300 工具；每轮全量加载 schema=50-140K tokens 输入、启动更慢、超 30-50 可见工具选择精度下降、部分 provider 128 工具硬拒绝**；**工具定义 token 开销对比：OpenAI function calling ~120-200/请求、Anthropic tool use 313-346/请求、Structured Outputs ~50（仅 schema）——工具定义是大头且随工具数线性涨**；**Anthropic：加载 3-5 个按需工具常省 85%+**。判据：**工具列表是每次请求的固定税——工具数涨一倍税涨一倍，任务复杂度不涨**。提升层：可复用 Skill。
3. **渐进工具披露**（来源：finisky + agentpatterns + channel.tel + usewire + developersdigest + agentpatternscatalog）——**三种实现：①deferred tools（只发名字不发定义，模型知道存在但看不到参数/用法——首轮可能需要的加载，可能整会话用不到的延迟）；②搜索式懒加载（单一 ToolSearch 原语替代 eager 列表，系统提示只列搜索原语+工具名/类别短索引，按需收 schema；搜索结果 schema 保留在上下文本会话其余部分重复使用不再搜）；③文件系统发现（模型原生导航目录树，按服务/域分组，Anthropic 98.7% token 降）；④intent-based bundles（按意图打包工具组）**；**实测：77,000→8,700 tokens（85%↓），精度 Opus 4: 49%→74%（更少可见工具=更准选择）**。判据：**工具税解法=延迟披露不是删工具——工具库全量可用但不在上下文**。提升层：可复用 Skill。
4. **Code Mode 编译工作流**（来源：Cloudflare + adarsha + entrans）——**整个 API 以约 1,000 tokens 固定 footprint 给 agent，无论多少端点；Cloudflare API 2,500+ 端点 Code Mode 降 99.9% tokens（等价 MCP 无 Code Mode=117 万 tokens 超上下文窗口）**；**Bifrost 网关编译工具操作 token 成本降 92.8%**；**模式：让模型写代码链式调用 API 胜过每个来回 tool call（一次代码执行含多次调用）**。判据：**工具集合大到 flat MCP 不可行时，代码即工具面——编译成一段可执行代码替换几百个 schema**。提升层：工具。
5. **工具调用失败四模式与参数幻觉**（来源：sureprompts + swarmsignal + inductivee）——**四失败模式：错工具（描述重叠/无何时优先指导——search 调用成 read_file）/不调工具（系统提示未要求该类用工具——训练数据直接答）/畸形参数（schema 不清/描述无示例）/无限循环（无停止条件/工具错误当"再试"）**；**参数幻觉最常见：结构合法但值编造（2025-13-45 日期/不存在的 user ID/枚举外值）——JSON 解析过，API 拒绝或更糟接受返回错数据**；**幻觉工具名（Type 4）：调用未注册工具——正确响应=结构化错误帮模型自纠，非通用异常**。判据：**多数失败根因在 schema 与描述层——修描述比修模型便宜且有效**。提升层：可复用 Skill。
6. **工具环境不可靠与可靠性复合**（来源：arXiv 2606.25819 + orderstack + nitinkc）——**首次工具调用失败后动作：重试同一工具占 44-76% 轨迹，直接终止 <12%；高重试率与整体准确率弱相关（最强模型也高重试）——重试不必然有效，盲重试是默认失败行为**；**可靠性复合：单工具 85-90% 成功，10 步流程降到 35%——多步失败率指数复合**；**7 大可靠性威胁：工具错误/模型拒绝/无限循环/上下文溢出/参数幻觉/错误工具/失败恢复不当**。判据：**工具环境不可靠是常态不是异常——评估必须含失败注入，恢复策略必须显式设计**。提升层：可复用 Skill。
7. **工具契约与可靠性清单**（来源：metacto + asoasis + raftlabs）——**工具契约：窄工具名（单一职责）、严格 JSON Schema、additionalProperties:false、闭集用 enum——防错工具选择与畸形参数**；**服务端验证：执行前参数校验——模型生成值到真实系统前必查**；**错误与重试：结构化错误类、有界重试策略、显式 retry_after_ms——防重试循环/限流循环/歧义失败**；**写操作：每个副作用操作配幂等键——防重复退款/邮件/更新**；**schema 标记仅真必需字段 required（可选字段给 LLM 灵活性）；enum 防幻觉输入**。判据：**工具契约是模型与真实系统之间的唯一防线——schema 松=系统接受垃圾**。提升层：可复用 Skill。
8. **错误恢复分型**（来源：kalviumlabs + axiomstudio + mcp-for-beginners + bestaiweb）——**错误恢复按型处理：瞬时错误退避重试（transient）/无效输入错误带上下文路由回模型（invalid-input）/致命错误立即 halt（fatal）——90% 生产事故归四类**；**schema 松紧实测：松散 schema 14% 工具调用失败，紧枚举/日期格式/受限字段类型降到 2.1%**；**MCP 错误语义二分：协议级错误（JSON-RPC error response：服务端失败——无效 JSON/未知工具名/内部崩溃）vs 工具级错误（正常结果+isError:true：预期领域失败——文件未找到/权限拒绝）——区分对 agent 恢复决策重要**；**MCP server：错误返回可操作消息绝不返回 stack trace；stdio 上参数可直通命令执行——验证约束每个输入绝不插值进 shell/SQL/路径**。判据：**错误信息是模型的自纠输入——stack trace 和含糊错误让模型只能盲试**。提升层：可复用 Skill。
9. **工具路由**（来源：vllm-sr + agentgateway + dreaming.press + arXiv Switchcraft + channel.tel）——**Semantic Router：嵌入式 mmBERT（2D Matryoshka ~130MB）分类 prompt 对照 YAML 模型/工具描述——无关键词无正则真 embeddings；替代"50 工具我该用哪个"的 LLM 自问（数学找最近匹配毫秒级）**；**确定性编排：Conductor（YAML+Jinja2，"first matching condition wins, no tokens spent deciding what runs next"）——结构已知的分叉用状态条件（零 token 可复现可 diff），唯一无法从状态知道的分叉做一个约束模型调用返回固定集标签（非 agent loop 一次调用=escape hatch）**；**Switchcraft 两阶段：预测正确模型集合（概率阈值）+成本感知选择（预测正确集合中最低档案成本=实际 token×每百万价格）**；**NeMo Switchyard stage router：每轮检查最近工具活动决定所需模型能力，严重错误升级模型**。判据：**能确定路由就不花 token 让模型选——路由是工程决策不是推理任务**。提升层：可复用 Skill。
10. **工具调用评估四层与工具数量衰减**（来源：futureagi + evalscope + channel.tel + PluginEval + TRAJECT-Bench + HammerBench + ragas）——**四层评估：L1 工具选择（右工具或正确不调——function_name_match/F1+irrelevance 桶）；L2 参数提取（schema 合法+语义正确——parameter_validation/function_call_exact_match/LLM judge 参数语义）；L3 结果利用（agent 用没用工具返回值——Groundedness+ContextAdherence 以工具结果为上下文）**；**四步契约含"调或不调"（irrelevance precision/recall on 10-15% no-call slice——正确安静是能力）**；**指标：tool_call_f1（决策 F1——该调不调/该不调乱调=agent 智能第一阈值）；schema_accuracy（参数格式——低=幻觉参数致崩溃）**；**工具数量衰减：>50 工具后 function-calling 精度悬崖（BFCL v4：Claude Opus 4.1 70.36%/GPT-5 59.22%——聚合不分层）**；**TRAJECT-Bench：从"最终答案对不对"细化到轨迹级诊断（工具选对/参数填准/序列依赖满足）**。判据：**评估到轨迹级不到答案级——L1-L3 分开测才能定位错在选工具/填参数/用结果哪层**。提升层：工作流。
11. **工具循环终止多层守卫**（来源：the-neural-base + agentnative + dev.to multigrid + openrouter + ai-tldr + agenticprep）——**max_iterations=步骤计数器非超时；框架默认：OpenAI Agents SDK max_turns=10、CrewAI max_iter=20、LangGraph recursion_limit 默认防跑野——尺寸让 agent 撞顶前退出**；**多层守卫：硬 max_steps 基线+成本/墙钟预算（单个贵步骤不能跑野）+重复检测（同工具同参数 2-3 次连续=卡住，停止报告）**；**状态机重构：AWAITING_APPROVAL（工具请求需人=停这，可停数天因为状态是行不是栈帧）/DONE（终态）/FAILED（预算耗尽/不可恢复失败/重复守卫——与 DONE 区分完成与放弃）**；**每 guard 收尾相同：stop, record why, return partial progress marked as incomplete never as success**；**每回合最大工具调用数防失控并行（MAX_ITERATIONS=5/MAX_TOOL_CALLS_PER_TURN=3）；无 tool_calls 即返回**。判据：**循环终结是代码硬边界不是提示词叮嘱——提示词说"别循环"是相信模型**。提升层：可复用 Skill。
12. **工具描述工程**（来源：explainx + zylos + gingerlabs + platform.claude.com + kansei-link + sickn33 + ai-tldr）——**好描述回答三问：做什么（动作+资源）/何时用（触发条件）/不做什么（排除混淆 case："Do NOT use for order status"）**；**命名：verb_noun snake_case（search_contacts/create_event）；跨服务命名空间前缀（github_list_prs/slack_send_message）——工具库增长选择无歧义，tool search 时尤其重要**；**MCP schema 四组件：name/description/inputSchema（JSON Schema 关键词非文本描述）/annotations（语义提示 read-only/destructive——几乎总缺失）**；**工具集合设计：描述重叠致模型混淆，更多工具不总更好——合理指南 10-20 工具多数应用，更多用命名空间分组**；**描述=AI-facing 接口：含约束（ticker 必须 NYSE/NASDAQ 有效）+边界声明（"will not provide any other information"）设预期；工具响应只返回高信号信息语义稳定**。判据：**描述写错=接口写错——LLM 靠描述选工具，含糊描述=随机选择**。提升层：可复用 Skill。
