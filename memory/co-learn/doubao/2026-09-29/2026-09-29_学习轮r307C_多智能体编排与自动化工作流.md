## 独点（12）

1. **五编排模式与适用性矩阵**（来源：novakit 2026-04-19 + metacto 2026-06-10 + shogo 2026-07-24）——**orchestrator-worker 是生产最广泛模式：orchestrator 分解/委派/合成，workers 互不通信、全部协调流经 orchestrator；orchestrator 用强模型+workers 用便宜任务专用模型省 40-60% 成本**；supervisor（central planner 路由，audit-heavy 域适用，风险=manager 瓶颈）；hierarchical（嵌套 supervisor，大域多任务需上下文隔离，延迟敏感窄任务避免）；swarm（对等 handoff，探索/创意，风险=无限循环+成本）；pipeline（固定顺序，文档处理/ETL，输入高度可变避免——错误级联传播）；**IBM Bob：orchestrator 不干活（plan/distribute/collect/arbitrate）**。判据：**先问"这活真的需要多个专家角色吗"——多数多 agent 系统其实单 agent 就够，多 agent 慢贵过度使用**。提升层：工作流。
2. **Fan-out/Fan-in 与并行化两子型**（来源：ncoblentz patterns + ai-tldr 2026-06-12 + alphacorp 2026-08-03）——**Fan-out：广播任务到并行 agents；Fan-in：收集聚合结果——同任务多独立输入，并行砍延迟，聚合需全部结果同时（map-reduce 变体）**；**并行化两子型：Sectioning（输入拆独立块并行处理合并——文档不同章节）vs Voting（同 prompt 多上下文独立跑多数投票——内容安全等正确性>成本场景）**；**Concurrent 模式：同输入多 agent 独立视角合并**；多模型投票（同 prompt 不同模型/温度并行，聚合选择）；每并行分支独立 checkpoint 可单独失败重试。判据：**并行前先确认子任务真独立——有依赖的"并行"只是把错误也并行**。提升层：工作流。
3. **控制流硬限制：max steps/token budget/timeout/circuit breaker**（来源：kunalganglani 2026-08-02 + openlegion 2026-07-01）——**agent 无限循环/失控是产品 bug，不靠 better prompts 修，靠 limits 修**；**四控制项：max steps 硬停（如 25 工具调用）/token budget 每运行硬上限/wall clock timeout（如 5 分钟）/circuit breaker（错误率>X% 最近 N 分钟→跳闸路由 fallback）**；熔断三态（Martin Fowler 2014）：Closed（正常，异常计数超阈值如 60s 内 5 次→Open）/Open（立即抛 CircuitBreakerError 不调 provider，30s 计时→Half-Open）/Half-Open（放 1 探测调用，成功回 Closed 失败回 Open）。判据：**先设上限再放权——没有硬边界的自主 agent 迟早烧穿预算或卡死**。提升层：工作流。
4. **重试-退避-补偿一体设计与 failure classes**（来源：williamspurlock 2026-07-14 + breyta 2026-02-05 + naitive 2026-06-21）——**重试管瞬态、退避防冲垮病依赖、补偿撤销部分工作——三模式必须一起设计，因为 agent 经工具产生副作用（CRM 写入/邮件/票据/付款），盲目重试会双扣/双发/重复记录**；**failure classes 分类再重试（瞬态网络/速率限制 vs 参数错/业务拒）**；**写操作必须幂等键**；checkpoint after each tool action 支持安全恢复+审计；strict I/O contracts（每个模型/工具调用验证 schema）；**概率链：五 agent 各 98% 成功→整链仅 90%——链越长越需要每环质量门**；七恢复模式：retries/circuit breakers/validation gates/sagas/checkpoints/budget guardrails/human escalation。判据：**agent 工作流的错误处理不是"重试几次"，是"失败后世界状态是什么"**。提升层：工作流。
5. **熔断器应用于 agent 层**（来源：luonghongthuan 2026-06-18 + compelframework 2026-04-06 + agentpatterns 2026-07-15）——**熔断器经典模式（Nygard Release It!/Hystrix 血统）很少应用到 agent 层，但每个外部工具调用都应包一个**；**三层熔断：工具级（连续失败 N 次禁用该工具）/agent 级/编排级**；**检测：per-message age/委托图循环检测/task-age alerting；缓解：agent 间等待超时/循环打破策略（N 次弹跳后断）/升级 supervisor/回退单 agent 模式**；fault injection（llmmas-otel）：在选定交互点注入故障，基线与故障执行可复现对比。判据：**工具失败是常态不是异常——熔断是 agent 生产化的第一道防线**。提升层：可复用 Skill。
6. **A2A vs MCP 分工**（来源：a2a-protocol 1.0 + announcing-1.0 + practicallogix）——**MCP 管工具与上下文集成（agent 内部：描述工具能力/传输入收结构化输出）；A2A 管 agent 间通信协调（横向：发现彼此能力/委派任务/交换结果/跨框架保持状态）——实践多用两者：MCP 在 agent 内，A2A 在 agent 间**；**A2A v1.0（2026-04）：Google 发起捐给 Linux Foundation**；**能力：signed agent cards（加密身份验证）/多租户/多协议绑定（HTTP/gRPC/WebSocket）/版本协商**；IBM 将 Agent 相关合并入 A2A。判据：**工具用 MCP、Agent 协作用 A2A——把 A2A 当工具协议用或反之都是层次错位**。提升层：工具。
7. **确定性骨架+agent 节点混合工作流**（来源：tasmela 2026-06-01 + dataaihub 2026-07-16 + openai community 2026-05-19 + mindstudio 2026-03-09）——**agent 赢：自由文本/文档/截图输入+下一步依赖意图解释；hybrid 赢更多：agent 推理非结构化输入→调 webhook（n8n/Make/Workato）执行确定性动作**；**确定性流水线：亚毫秒延迟/固定审计轨迹/合规结构性强制；agentic：2-15 秒/运行时动态选工具/需运行时监控**；**Agent Runtime 原则：模型放高不确定/语义密集/高利害决策分支；可重复/明确定界/可验证/低风险执行交程序/工作流/工具层**；**low-value foreach（批量抓取/整理/导出/转换）不该用 agent**；**canonical hybrid：agent 分类提取（非结构化/歧义/语言重）→输出结构化 JSON+置信度→RPA 执行确定性归档/仓库写入/审批路由——每步日志审计可见**。判据：**生产系统默认=确定性骨架+agent 节点；全 agentic 是特例不是默认**。提升层：工作流。
8. **七工作流拓扑与 Reflexion**（来源：spinnable 2026-08-04 + inductivee 2026-04-15 + langchain docs + google cloud 2026-05-28）——**七拓扑（Anthropic Building Effective Agents）：Prompt Chaining/Routing/Parallelization/Orchestrator-Workers/Evaluator-Optimizer/ReAct Loops/Human-in-the-Loop**；**prompt chaining：每步输出喂下一步+步间可选检查（翻译/一致性验证）——换点延迟换每步高准确率**；**Reflexion：ReAct 循环加自评——自问"我做了什么假设/哪里可能错/我会怎么做不同"→critique 追加上下文→重试；复杂推理/代码生成准确率提升，成本 2-3x LLM 调用**；**review-and-critique：generator→critic 按预定义标准（事实准确/格式/安全）评估→approve/reject/return with feedback**；**plan-and-execute（先计划全步骤再执行）+ ReAct（循环 reason-act）结合：plan 后每步 ReAct**；路由：分类输入→送最适 handler/模型。判据：**工作流模板选择=任务结构匹配，不是越复杂越好**。提升层：可复用 Skill。
9. **agent 评估五维 + 轨迹评估五项**（来源：dev.to tamizuddin 2026-08-15 + opennash 2026-05-28 + belsoft 2026-06-19 + AWS Strands 2026-07-23）——**五维：Correctness（golden outputs+LLM-judge rubrics）/Tool Use Accuracy（schema 校验工具与参数）/Efficiency（turns+tokens）/Robustness（对抗输入注入）/Safety（red-teaming 套件）**；**trajectory eval 每运行评五项：Tool choice/Tool arguments/Retrieval grounding（引用上下文真支持回答吗）/Step efficiency（路径合理还是循环）/Termination（该停没停）——任一项错，最终答案再漂亮也是失败**；**LLM-as-judge 需对标人类标注校准（Pearson 相关）**；**AWS 三层评估：Layer1 检索/工具→Layer2 步骤级→Layer3 Output quality（>90% 阈值）+GoalSuccessRate——三层全过才部署**。判据：**只看最终答案正确率会漏掉"路径烂但答案凑巧对"的 agent**。提升层：可复用 Skill。
10. **渐进式上线与生产监控**（来源：codelevate 2026-07-24 + edenai 2026-07-09 + kunalganglani 2026-08-08 + agiflow 2026-07-04）——**pilot→threshold（outcome-based 预先商定数字，如每千决策最大 override rate——"ready"是事前同意数字不是发布日感觉）→full production→持续评估（每周新真实失败加测试集，prompt/model 每次变更跑回归）**；**生产监控指标：success rate per task type（低于阈值告警）/cost per task trend（涨=prompt drift 或工具退化）/tool error rates（401/429/5xx）/tool-call mix shifts（突然 3x search 调用）/retry counts distribution/safety violation counters/token per step**；**成本延迟四杠杆顺序：observability 先（每步 trace）→model routing（按步骤风险分层，强模型留推理/评审）→context discipline（交接传结构化输出+artifact links 不传 raw history）→prompt caching（系统提示稳定）——不用 caching 给超大上下文找借口**。判据：**离线评测看不到漂移——生产监控是评估的延续不是替代**。提升层：工作流。
11. **任务分解工程化**（来源：agentixforce 2026-05-08 + kindatechnical 2026-03-01 + xbstack 2026-04-24 + agenticai M13）——**DAG 依赖图：节点=子任务，边=must-complete-before；无前驱立即开始，critical path（最长依赖链）决定最小执行时间**；**Kahn 拓扑排序验证循环依赖（A→B→A 死锁）→检测到 reject 计划回退顺序执行**；**分解产出结构化 JSON（dependencies/tool mappings/risk controls），不要自然语言待办清单**；**粒度：3-5 大阶段→每阶段拆任务；深度 3-4 层够，更深无价值；验证步骤必须包含（检查前序任务输出）；为失败规划替代路径**；**欠分割/重复/过分割执行前用检查程序落掉**。判据：**分解质量决定执行质量——"构建整个网站"式单 prompt 是幻觉温床**。提升层：工作流。
12. **委托契约四要素 + RSTD 规则**（来源：alexlavaee 2026-07-06 + codex RSTD 2026-09-26）——**DeepMind 判据：分解到每个子任务能写测试为止——无法程序化表达成功标准=粒度不够**；**委托契约四要素：子任务是什么/怎么验证（测试套件/类型检查/lint/构建/人工审查）/允许哪些工具（scoped permissions）/失败怎么办**；**RSTD 规则：>3 文件任务分解为 per-module 子任务；每子任务产 schema-validated checkpoint 再继续；子任务失败两次→升级父线程带结构化错误报告；上游子任务被修改则下游不重试**；**不要在单个 turn 尝试多文件重构**。判据：**能写测试的粒度=可验证的粒度；验证方式不明确的任务不该被执行**。提升层：可复用 Skill。
