## 独点（12）

1. **LLM-as-judge 校准与五大偏差**（来源：futureagi 2026-08-27/05-20 + aiworkflowlab 2026-08-02 + arXiv 2602.02219 + metacto 2026-06-14）——**校准目标：Cohen's kappa >0.6 vs 人工标签，>0.8 强；position bias 测量：pairwise 校准集（100-300 例已知胜者）每对跑两次（A/B 互换位置），顺序翻转导致裁决翻转的比例>5%=真偏差（frontier 典型 10-15%）——消解=每次随机化顺序并聚合**；**五大偏差各自消解：position（偏好第一 15-30% 偏移→跑双顺序）/verbosity（偏好长回答 ~15% 通胀→显式反长度指令）/self-preference（偏好同族 3-10%→跨模型族评判）/sycophancy（同意问题前提→中性提示）/instruction-following→分条 rubric 准则**；**rubric 本身也有 position bias（评分选项在列表位置偏好）——balanced permutation 把每个分数选项均匀分布到各位置，聚合多次排列既揭示偏差又提升与人类相关性**；**生产校准集 30-50 例 1-2 个 SME；pin judge 模型到精确快照版本；校准=迭代循环：标代表性集→跑 judge→复查分歧→更新准则/示例/标签→同集+holdout 重跑→跟踪一致性随时间**。判据：**judge 上线前先学它怎么失败——未校准的 judge 是新的不确定源**。提升层：可复用 Skill。
2. **Judge 选型：kappa per dollar + 级联**（来源：futureagi best judge 2026-05-20 + stacksweep JEV 2026-09-24 + arXiv 2604.13717 + apolloresearch + galileo）——**选 judge=在自家校准集上比 kappa per dollar；fine-tuned judge（Galileo Luna-2/Prometheus 2）在自己训练过的 rubric 上赢成本和延迟，frontier 通用模型赢未见过的开放式推理——生产常态=fine-tuned 第一层+frontier 升级复杂 case**；**decision-only judge（只返回裁决+标签概率）在常规偏好/事实验证上离 GPT-6 差 3 点内但费用 0.36%——置信分数可靠到能告诉你该不该升级（先跑便宜的，难的升级）**；**ensemble scoring+任务特定 criteria 注入：+13.5pp 到 85.8% 准确率，小模型获益不成比例——低成本高精度 judge 可达（cheap 2-model ensemble $0.044/grade vs 单 Opus $0.42，12x 便宜）**；**领域专用 reward model（1.5B-8B）可匹敌或超过大得多的 prompt judge，让 100% 流量覆盖可行**。判据：**judge 不是选"最聪明的"，是选"校准集上每美元 kappa 最高+能级联升级的"**。提升层：工具。
3. **Eval-driven 开发四要素与 CI 门控**（来源：qaskills 2026-06-15 + braintrust 2026-02-18 + confident-ai 2026-09-21 + futureagi CI/CD 2026-05-20 + latitude）——**eval suite=golden 输入集（从真实生产失败构建，非 happy path）+评分函数（便宜确定性检查优先，LLM judge 只在没别的办法时）+阈值（mean+尾百分位双门；常失败的阈值=无信号，只在真回归失败=可自信迭代）**；**CI 触发契约：每 PR 触及 prompt/model version/retrieval config/tool schema/agent loop 代码→跑全量 golden→比较 vs main 基线→非协商用例失败或通过率超容差则 PR 失败；结果附 PR 测试报告（哪些 case 翻转/哪些指标动/judge 推理）**；**环境晋升评估门：dev 子集快迭代→staging 全量 golden→生产前安全/合规评估，任何指标低于阈值 CI 阻塞**；**三级测试：smoke（每 commit 15-20 例，<3 分钟几美分）→full regression（PR 前 100-200 例）→deep evaluation（发布前全量 5+ 次/例）**；**statistical gate：Welch's t-test 连续 rubric/z-test 二进制/p95 尾部，对 7 天基线 delta；exit codes 0/2/3/6/7 硬契约（0 成功/2 断言失败/3 警告/6 API 错/7 超时）**。判据：**回归质量退化要像坏 build 一样失败 PR**。提升层：工作流。
4. **Eval 数据工程：三集分离与防泄漏**（来源：theneuralbase leakage 2026-04-21 + mlflow + eval.qa + apple + kindatechnical）——**train/dev（迭代）/eval（锁定）三集分离：eval 集系统开发前创建、开发期永不触碰——不看失败调 prompt、不在 eval 数据 fine-tune、不做 eval 特定失败模式人肉修复**；**污染检测：n-gram overlap（测试集泄漏进训练=性能无意义）；eval 数据绝不进被测模型训练数据；有时间分量则时间分离**；**分层采样：common/edge/adversarial/demographic slices/difficulty bins——95% 简单例子的数据集抓不住关键失败，故意覆盖长尾；70% 查询是主题 X→eval suite 反映该分布**；**golden 四类：happy path（质量底线）/edge cases（短/长/格式异常/含糊/矛盾约束）/adversarial（注入/有害/提系统提示）/known failures**；**gold-standard 答案要领域专家创建审阅——自动生成的 golden 不是 golden（最小 100-200 例）；警惕 10-30% 污染/5-20 分分数通胀/stale evals**。判据：**eval 集是锁死的法庭证据，不是可随时改的草稿**。提升层：可复用 Skill。
5. **在线评估与漂移监控**（来源：truefoundry 2026-07-07 + latitude drift + futureagi production 2026-05-14 + mlflow + futureagi drift 2026-05-20）——**online eval 评真实生产流量样本（after the fact）——补 offline 抓不到的：测试集外边界/渐进漂移/实时变更回归；offline=对已知 case 的 pre-flight，online=对现实的连续仪器（曾让两周回归无人察觉）**；**采样 5-10% 流量+永远给错误和升级（errors/escalations）打分（不是随机采样）；低成本统计检查决定何时跑更贵的重新评分（级联）**；**漂移策略：7 天滚动均值+标准差，今日均值跌超 1.5σ 告警；安全指标跌分页（page），质量跌开票（ticket）；对最后绿窗口比较**；**embedding 漂移：当前生产输入与训练分布余弦距离>0.15 信号分布转移；PSI 人口稳定性指数抓数据漂移（尤其 ground truth 延迟数天/周时）**；**分层抽样生产：200-500 最近 traces 按 intent（新 intent 过采样）/persona/语言，拉 14-28 天不是 7 天（防过拟合单次活动/发布）**。判据：**离线是体检，在线是心率带——两层都缺一层就漏一半回归**。提升层：工作流。
6. **Agent 评估：轨迹优先于结果**（来源：nvidia 2026-05-19 + google cloud + langchain evals + arxiv AgentLens/Claw-Eval + microsoft agent evaluators）——**模型评估（静态基准测能力）vs agent 评估（端到端系统行为：动态轨迹/工具调用/非确定性环境任务结果）——agent 评估优先 Task Success Rate per scenario，需完整轨迹日志（计划/工具调用/中间推理/副作用）算 Trajectory Efficiency 和 Tool Call Accuracy**；**轨迹匹配四模式：strict（消息结构+工具调用同序精确匹配——测特定序列如授权前查策略）/unordered（同结构工具调用任意序——检索顺序无关时）；顺序变体：exact order（只右工具无其他）/in-order（右工具右序可有其他）/any-order**；**工具调用四问：调用精度（右工具+右参数无冗余）/工具选择（右且必要）/输入精度（参数正确）/输出使用（正确用了结果吗）**；**trajectory recall：任务需查 Database+Wiki 只查了 Wiki=0.5**；**三证据通道（执行轨迹/审计日志/环境快照）+2159 细粒度 rubric 项轨迹评分**。判据：**agent 的质量在"怎么做到"，不在"最后那句"——只评结果的 agent 评估会漏掉工具滥用与低效轨迹**。提升层：可复用 Skill。
7. **多模态评估：MLLM-as-judge 与跨模态对齐**（来源：aws strands 2026-05-20 + arXiv 2603.07990 + papernotes WorldSense + AVBench/AVGen-Bench）——**跨模态对齐评分核心模式：rubric+文本输出+图像一起给视觉 judge；MLLM-as-judge 评估器：Overall Quality/Correctness/Faithfulness/Instruction Following——图像直接给多模态 judge+query+response+（可选）参考答案**；**grounded verification 三步：观察（O：描述图像内容）→声明提取（C：分解响应为声明）→一致性验证（V：每声明对照观察验证，二进制 1/0）——强制推理落到证据而非"看起来对"**；**幻觉检测任务形态：图像+3 陈述，标 True（grounded in image）/False（hallucinated）**；**WorldSense：真实世界全模态视频基准强制音视频协同（去掉任一模态必然答错）——最强 Gemini 2.5 Pro 仅 65.1%，开源接近随机；既有基准的问题=音视频弱相关、看一个模态就能答**；**AVBench 10 评估维度（视觉质量/音频质量/跨模态多层一致性）+偏好学习专用评估器；多粒度评估=轻量专家模型+MLLM 组合（感知质量到细粒度语义可控性）**。判据：**跨模态评估的关键是"模态间对齐"不是"单模态各自表现"——每维分开高分=可能接口处全崩**。提升层：可复用 Skill。
8. **失败分类学与 triage 纪律**（来源：futureagi failure modes 2026-05-20 + google cloud triage + aws strands detector）——**agent 失败 5 类分类学（计划/工具/执行/记忆/输出类），真实事故堆叠 2-3 类：诊断纪律=从头到尾走 trace，停在第一个坏掉的类别——早期错误污染下游一切（planner 选了错工具序列，跑在错 plan 里的工具不是 bug，planner 才是；修工具层=类别不匹配，补丁不泛化）**；**triage 四步：汇总指标找最低分→逐 case 下钻→失败聚类找系统性损失模式→traces 下钻找精确失败轮/工具调用**；**失败检测器输出结构：分类失败+置信分数+因果链（根因→下游症状）+修复建议（指定改动属于 system prompt 还是 tool definitions）**。判据：**postmortem 命名单一失败模式=漏掉链条——归因要到"第一个坏的类别"，不是"最后一个看到的症状"**。提升层：工作流。
9. **连续改进环与失败 trace 升级**（来源：theneuralbase loops + futureagi evals-vs-prod 2026-05-19 + almessadi + futureagi incident playbook）——**连续改进环：eval 失败+生产错误自动生成新测试用例→与 prompt 版本一起版本化→验证修旧失败不引起回归**；**失败 trace 升级：每周抽样失败 traces→按用户段/intent/judge 分 bucket→把最难的 5-10% 提升进 eval 集带版本标签——每个提升的 trace 是未来 PR 不能打破的回归**；**改进 loop 三问：用户/任务成功吗（用户视角的成功）/阶段级失败归因（retrieval/tool/truncation/guardrails/post-processing 哪级）/变更影响（部署新 prompt/模型/工具/reranker 失败概率动了吗）**；**事故行动项规范：具体/有主/有日期（"加 50 个代表失败到 golden 集 by EOW owner: Alice"）；先排高方差（perRunScores 不稳→重跑再下结论）再调 rubric；基线本就差（≤2/5）可能需简化场景**。判据：**连续的部分必须接回评估和门控——不是只看仪表板**。提升层：工作流。
10. **评估=发货契约（Evals as Shipping Contract）**（来源：agentropic 2026-06-12 + confident-ai）——**eval 在契约意义上正好三样东西：labeled golden dataset+评分方法+通过率阈值（build 必须达到才能发）——Gherkin 验收标准（Given X when Y then Z）不消失，变成 eval cases**；**接受=分布上的阈值（threshold on a distribution），不是单次示例表现**；**治理切分：谁定义 eval 集/谁定义阈值/谁能豁免——契约的强制力来自治理**。判据：**验收标准从"语句"变成"可跑的 eval"——每次变更都自动对全量 golden 重新判**。提升层：可复用 Skill。
11. **在线评估采样与离线-在线分工**（来源：latitude realtime + futureagi production + openai monitor）——**异步 evals：响应交付后评 faithfulness/答案质量/agent 行为——不阻塞用户**；**采样策略：正常流量抽一部分，但错误和升级必 100% 打分**；**feedback loop：标记 traces→review→label→加入回归集；release control：shadow tests/canaries/gating 在更广 rollout 前**；**OpenAI 内部编码 agent 监控：低延迟监控系统（最大推理努力）审查 agent 交互，告警与用户意图不一致或违反安全/合规策略的动作——monitor 记录并分析 chain-of-thought 和动作**。判据：**在线评估=对真实流量的事后连续仪器——100% 覆盖错误路径，抽样覆盖正常路径**。提升层：工作流。
12. **评估工具链选型**（来源：deepeval top5 2026-07-22 + calmops + cadence + scrolltest）——**框架对比：DeepEval（Python+pytest+CLI，50+ 指标 G-Eval/Faithfulness，Apache 2.0，综合 agent/RAG/chatbot）/Promptfoo（YAML+CLI+TS，MIT，prompt 对比+AI 安全红队）/RAGAS（Python，RAG 专用 5 核心：context precision/recall/faithfulness/answer relevance，reference-free）/Phoenix（OTel 原生可观测导向）/Braintrust（托管全生命周期）/Langfuse（生产 traces+评分一体化开源）/OpenAI Evals（官方 benchmark registry）**；**选型判据=evals 住在哪：terminal（Promptfoo CLI）/Python+CI（DeepEval pytest-native）/生产 traces（Langfuse/Phoenix）/托管仪表板（Braintrust）/安全与能力（Inspect AI）/受监管企业（Patronus）**；**promptfoo 结果留本地无集中实验跟踪；DeepEval 主导 Python 生态、Promptfoo 主导 JS 生态**。判据：**选框架先问"我的 evals 生命周期发生在哪"——单机迭代/CI 回归/生产监控/团队协作各配不同工具**。提升层：工具。
