## 独点（12）

1. **低代码平台许可与计费三维选型矩阵**（来源：n8n.io vs Activepieces/Dify 2026-07 + woshipm 2026-08 + recatools 2026-07 + botpress 2026-09 + composio 2026-06 + n8n blog）——**许可模式三分：Dify=Open Core（功能受限开源版+云/企业版盈利）；n8n=Fair-Code（源可查可自托管、防大型云厂商复制）；Langflow=纯 MIT（四者中唯一完全 OSI 批准无限制许可）；ComfyUI=Pure Open Source（商业化让给生态）**；**计费模型三型：execution 计费（n8n Cloud Starter $24/月含 2,500 executions、Pro $60/月——可预测成本结构适合后台自动化）/task 计费（Zapier 免费 100 tasks/月、MCP 2 tasks per call）/credit 计费（Pipedream 免费 100 credits/天、Gumloop per credit——随调用量涨高流量贵）**；**自托管复杂度：Langflow 最轻（Python 3.10-3.14）；Dify 最重（app server+DB+向量 DB 三件）**。判据：**选型先看许可能否自托管+计费模型匹配流量形态+自托管运维成本**。提升层：工具。
2. **错误处理分层系统与错误分类表**（来源：agent-works 2026-06 + williamspurlock 2026-07 + techfordev 2026-07 + spinnable 2026-08 + suhasbhairav 2026-05）——**错误处理是分层系统不是单个 try/catch：Layer 1=idempotency key 保重试安全（每个 state-changing 工具调用附 key，一次生成跨重试复用，下游去重）→重试（指数退避+jitter：立即/~2s/~8s/~30s；上限 3 次+backoff multiplier 2，不无限重试）→回退（切次要 model provider 或静态默认 handler）→升级人工**；**错误分类定默认动作：Model quality（低置信/failed eval/幻觉字段→repair prompt/re-ground/escalate）vs Permanent（404 required resource/删除对象→dead-letter+escalate，永久错误不重试）**；**常见错误=对业务逻辑错误重试（agent 返回 business logic error 时重试无用）**；**ESCALATED_ERROR 状态+通知人工，escalation rates 单独追踪**；**回退路由：agent A 失败→路由更简单 agent B（低质量但可靠）**。判据：**先分层再写重试；永久错误直接死信不烧重试预算**。提升层：可复用 Skill。
3. **HITL 检查点与持久状态恢复**（来源：clarion 2026-05 + ofeng 2026-07 + jinba 2026-06 + naitive 2026-06 + knowlee 2026-05）——**HITL 检查点触发=置信阈值/风险标记/显式失败耗尽——不是 AI 失败回退，是设计选择（法律/财务/声誉权重决策应主动暂停）**；**HULA 框架：所有自动恢复路径耗尽或动作不可逆时暂停路由到人**；**持久状态 checkpoint（生产必备）：review 可能几小时/几天、服务重启、新代码部署——workflow 必须能无限暂停+人类输入到达时精确恢复原处**；**per-step checkpointing=中间输出写盘；cursor-based state 让失败运行从最后成功步重启（resumability）**；**监控 exit codes+failed runs 告警**。判据：**任何可暂停工作流必须有持久 checkpoint+游标恢复，否则重启即丢进度**。提升层：工作流。
4. **Agent 可观测性：trace 树+采样评估+五指标**（来源：mlflow 2026-05 + marktechpost 2026-08 + logic 2026-06 + microsoft learn 2026-07 + ayinedjimi + dev.to 2026-09）——**trace=完整执行树（用户请求→工具调用/RAG/编排者决策/底层 LLM，每节点 span 带模型/temp/tokens/成本）——agent 特殊：HTTP 200 但选错工具/幻觉参数，status code 无意义必须 trace（非确定性使 tracing 不可协商）**；**每层仪表化：LLM 调用/检索步/工具调用都捕获 span→latency+cost 可归因到步**；**采样评估不是体积：LLM-as-judge 只跑 10-20% 生产流量（质量覆盖 vs 评估成本平衡）**；**存储前净化：自动 prompt/completion scrubbing（隐私源头保护）；OpenTelemetry GenAI 语义约定=版本化契约定期更新防静默数据破坏**；**五指标：Latency P50/P90/P99 / Token usage per request（spike 常意味检索注入太多上下文）/ Cost per execution（model+tokens+retries）/ Error rate（timeouts/malformed/rate limits）/ Hallucination rate**。判据：**agent 上线必配 trace+采样评估；指标五件套全监控**。提升层：可复用 Skill。
5. **MCP 技能生态工程：build 三 skill/按 intent 分组/运行时发现/分发工具**（来源：modelcontextprotocol 官方 2026-07 + claude.com MCP 2026-04 + microsoft foundry 2026-09 + anthropic complete guide + lobehub skillport 2026-09 + pypi skill-seekers 2.6.0）——**MCP 官方 build 三 skill：build-mcp-server（interrogate use case→选部署模型+工具设计模式→路由专门 skills）/build-mcp-app（chat 内联 UI widgets：forms/pickers/dashboards）/build-mcpb（本地 stdio server 打包 runtime——用户无需装 Node/Python 即可安装）**；**按 intent 分组工具不是按 endpoint——Fewer, well-described tools 胜过 exhaustive API mirrors；不要 API 一对一包 MCP server**；**远程 MCP server=最大触达（唯一跨 web/mobile/cloud-hosted agents 配置）**；**Microsoft Foundry toolbox：技能附到 toolbox，agent 从 toolbox MCP endpoint 运行时发现加载（不本地打包 SKILL.md）**；**技能三类之 3=MCP Enhancement（sentry-code-review：协调多次 MCP 调用+嵌入领域专家知识+提供用户本需指定的上下文+错误处理）**；**分发工具：SkillPort（uv tool install skillport：add/remove/lint/search/show）、skill-seekers（MCP 打包上传 Claude）**。判据：**MCP 工具按用户意图聚合命名；技能分发走打包工具而非手工复制**。提升层：可复用 Skill。
6. **确定性/AI 步交替 playbook 与 webhook 幂等**（来源：n8n Production AI Playbook 2026-04 + n8n community 2026-07 + mpstudio 2026-04 + renezander 2026-04）——**AI 步之后必挂确定性验证步：AI 分类/草稿 → Code node 校验分类对已知类别+检查置信分数 → Guardrails node 查 NSFW/secret keys → IF 分流——分类置信低于阈值转人工**；**webhook 幂等：Stripe webhooks 同一事件可多触发（replay/网络重试）——fulfillment 前查 processed_events 表防重复发送；Lead capture 同风险（webhook 双触发在 Sheets 写入前）**；**模板模式：AI Email Triage（每工作日定时触发→分类+草稿，人工确认后发）；YouTube→Social Repurposer（视频发布→拉 transcript→LLM 生成 3 tweets+LinkedIn post+email subjects→日历，30 分钟变两周社媒内容）**。判据：**任何 AI 步后必须有确定性校验闸；webhook 触发流程先查去重表**。提升层：工作流。
7. **token 成本表与模型路由 70/20/10**（来源：zylos 2026-05 + ruh 2026-05 + agdex 2026-04 + agentic-ai.readthedocs 2026-09 + infosys 2026-09 + microsoft host-platform 2026-07 + dev.to netflix 2026-08）——**token 类型成本表：Input fresh=1× 基线 / Output=3-6× input（顺序生成最贵）/ Cache write=1.25-2× input（一次性填共享前缀缓存）/ Cache read=0.1× input（90% 便宜，长会话主导）**；**模型路由 70/20/10（Mavik Labs）：70% 查询去 budget 模型/20% 中等/10% frontier——路由层先分类查询复杂度再调模型（Level 2 路由 40-70% 节省）；简单分类/路由用小快模型（GPT-4o-mini/Haiku）**；**Agent 成本倍增器：10 步 agent loop ≠ 10× 单调用（每步都带全上下文→成本复合爆炸；实测 $400→$12,000/6 周没加用户只加了 agent）；Netflix Headroom=app 与 model API 间上下文优化层（pruning+caching+routing）**；**确定性代码 vs 自然语言：actions/connectors 描述动作比自然语言指令便宜——代码跑一次经济可预测零 token 成本；自然语言每次推理付费+可能不一致；不要为固定指令付固定 token 成本**。判据：**成本三件套=前缀缓存复用（长会话省 90%）+70/20/10 路由+固定流程代码化**。提升层：工具。
8. **低代码平台安全 RCE 集群与凭证-运行时分离**（来源：endorlabs 2026-08 + pranava0x0 2026-09 + CSA langflow 2026-03 + cvereports 2026-09 + beyondscale 2026-06 + n8n sandbox 2026-08 + geordie 2026-03 + wotai 2026-04 + gitguardian 2026-09）——**n8n Ni8mare（CVE-2026-21858）：CVSS 10.0 未认证远程任意系统命令执行→全主机沦陷（1.121.0 修复）——低代码平台 RCE 是系统性威胁**；**Langflow CVE-2026-33017：未认证 RCE——公共 flow-sharing endpoint 把 attacker 控制 flow 数据直接 exec() 无认证无沙箱（结构性根因：代码执行当 feature 不当攻击面）；第四个关键未认证/近未认证 RCE**；**n8n expression sandbox escape（CVE-2026-86076）：ClassBody AST 遍历缺失→重定义 __sanitize resolver→RCE；CVE-2026-1470 expression injection（用户数据直接进表达式可触文件系统/网络/系统命令）**；**加密密钥泄露链：读 SQLite 数据库→提取 admin 凭证+N8N_ENCRYPTION_KEY→每个存储凭证可解密→伪造 _n8n-auth_ JWT（OIDC 空密码 coerced 空串；invited pending users null→空串）**；**官方解法=agent 运行时与凭证分离：agent 不直接访问凭证，凭证 DB 加密存储运行时用，轮换 secrets 不动工作流逻辑，限制被攻破 agent 影响面**；**审计=从每个外部输入 trace 数据流查 expression injection**。判据：**低代码平台=代码执行面，升级补丁+凭证与运行时隔离+表达式输入消毒是底线**。提升层：可复用 Skill。
9. **Agent 原生 CI/CD：canary 门+evals 进 CI+环境分版本**（来源：zylos agent-native cicd 2026-05 + n8n 15 practices 2026-01 + IBM wxO 2026-09 + lyzr 2026-09 + AWS AgentCore+GitHub Actions 2026-01 + mech 2026-09 + prompt flow 2026-08）——**Gate 5=Canary+Auto-Rollback：5% 流量到新版本，连续监控 error rate（tool call failures/guardrail blocks）/latency p50/p95/p99/output quality scores——异常自动回滚**；**环境分版本（三环境凭证隔离）：Development（mock/test 凭证+staging 外部服务+失败不影响用户）/Staging（镜像生产配置+测试账号+同 queue mode/worker 设置）——生产凭证永不进 dev**；**Git 分支→环境映射（IBM wxO）：develop（dev Draft）→qa-<version>（Live）→staging-<version>（prod Draft）→main（prod Live）；每阶段 version tags=完整审计轨迹，rollback=revert 版本 tag**；**Agent evals 进 CI/CD（AWS 参考实现）：部署 agent+OAuth MCP server→test prompts 调用→评分→行为回归 block PR——可复现 merge 前测试（多数 eval 在 notebook/一次性脚本=不可复现）**；**GenAIOps 四阶段：Initialization→Experimentation→Evaluation and refinement→Deployment**。判据：**agent 上线走 dev/staging/prod 三环境+canary 5%+evals 挡 PR；eval 必须代码化进 CI 而非 notebook**。提升层：工作流。
