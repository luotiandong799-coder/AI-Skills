## 独点（12）

1. **代码库混合索引双支柱**（来源：kilo.ai blog 2026-03-06 + cocoindex 2026-06-10 + rockb MCP 对比 2026-07-06 + samuelfaj 2026-07-17）——**两种索引都要：AST/代码图索引（函数签名/调用图/导入链/类型层次/依赖关系——回答"谁调用这函数""哪些模块依赖这接口"，不读文件）+向量搜索（语义查询"我们怎么处理支付..."）**；**分块策略：函数级（大函数保上下文）/类级（整个类一块，OOP 方法交互是理解关键）/重叠分块（相邻块加 10-20% 块大小重叠，防切片切断相关模式）**；**增量索引（CocoIndex Tree-sitter 原生解析+实时更新，100 行 async Python，省 70% token——别把可 grep 的代码烧 token 进上下文）**；**symbol 精确导航先于 embedding：embeddings 近似意义不替代精确导航——agent 要知道定义/使用/影响时走 symbol（GitHub code search symbol: 基于 Tree-sitter/SCIP），语义模糊才走向量**。判据：**先建结构图再谈语义——回答"谁调用"用索引，回答"怎么做 X"用向量**。提升层：工具。
2. **上下文工程三策略 + repo map + 最窄目录启动**（来源：baeseokjae 2026-04-30 + aimadetools 2026-04-20 + 13labs 2026-08-11 + morphllm 2026-02-15 + agentpatterns 2026-05-27）——**Write/Select/Compress 三策略：Write=主动持久化到窗口外（scratchpad/结构化笔记/todo 文件逐步更新让目标保持在近期注意力）；Select=动态检索只取相关（embeddings/RAG 拉代码片段，不预载全部）；Compress=总结轨迹剪旧消息**；**repo map（Aider）：tree-sitter 解析 AST map——模型看每个文件结构（函数签名/类定义/导入）不花加载每行成本（中等仓库 500-2000 tokens），要细节再请求具体文件**；**命名文件+从最窄目录启动会话>任何工具："在哪里启动 agent 决定它能看到什么"——packages/api/ 启动只加载该目录 CLAUDE.md+全部祖先，无兄弟包指令，文件访问限于子树**；**.claudeignore 排除 dist/.next/build 等 agent 永不需要读的文件；分层 CLAUDE.md（backend/frontend 各自规则+~/.claude 个人偏好）；把每机器上下文（cwd/OS/shell）移出 system prompt 让相同配置共享一个 prompt-cache 条目**。判据：**先决定"agent 该看到什么"再写任务——上下文选择是系统工程不是提示技巧**。提升层：工作流。
3. **高 AI 采用团队评审失效与机械化**（来源：augmentcode reviewing-ai-generated-code 2026-07-24 + github.blog 2026-05-07）——**高 AI 采用团队：PR 评审中位时间涨 5 倍、每 PR 事故翻三倍、遥测显示评审者略读不精读；人类评审效果在 400 行以上崩溃——修法是机械化：编译/类型门、diff 限定 SAST（只扫变更行）、依赖存在性检查（反 slopsquatting 幻觉包名）、变异测试套件、post-merge canaries（持续跑）**；**危险的 AI 代码不是编译不过的幻觉（CI 抓），是编译通过+测试全过但错的东西：分页 off-by-one/未测分支缺权限检查/边界短路校验/只在规模浮现的竞态——评审要 trace 它**。判据：**"看起来对"不是通过理由——机械门禁+人工查高风险路径，评审从读代码变成验证行为**。提升层：可复用 Skill。
4. **独立评审 agent 与审查顺序**（来源：exceeds.ai 2026-04-12 + rockb LLM coding workflow 2026-06-15 + explainx 2026-07-13）——**生成代码的 agent 不评审自己的输出：自我评估倾向自信夸中等结果（Anthropic 工程团队验证）——部署独立评审 agent**；**审查顺序：intent（解决对的问题吗）→behavior（用户可见/API 可见结果变了吗）→security（碰了 auth/输入验证/密钥/日志/依赖/权限吗）→maintainability（抽象局部/命名好/有测试/与代码库一致吗）；让 agent 解释 diff 但不把解释当证据**；**评审清单问句：只动了预期文件和依赖吗？测试挑战实现还是镜像实现？安全/数据/钱/身份/不可逆路径变了吗？人工看高风险路径了吗？行为在生成它的窄单元外测了吗？日志/指标/告警/功能开关/回滚够吗？出事故负责人能不用问 agent 解释变更吗？**。判据：**评审 AI 代码=评审生产代码，不是审"AI 的作品"——解释是线索不是证据**。提升层：工作流。
5. **AI 代码质量审计 rubric**（来源：dev.to 0-100 audit rubric 2026-09-26 + GitHub reusable prompt 2026-09-27）——**0-100 审计维度（rewrite likelihood 20 权重等）：diff 合现有架构/所有权清晰/低耦合/最小新表面积；"2 分钟能解释清吗"/新概念数/新文件数/所有权清晰度——三档 ship（85-100 仍要审）/refactor/rewrite**；**finding 分级：Blocking（bug/安全/数据损坏/资源泄漏，合并前必修）/Recommended（性能/韧性/设计改进，不阻塞）/FYI（留作后文）；每 finding 模板：severity+标题+路径:行号+何时何地出错+参考文档**。判据：**评审输出按严重度分级+可定位（文件:行），不是泛泛建议——分级让合并决策机械化**。提升层：可复用 Skill。
6. **TDD as agent 反馈机制**（来源：codex.danielvaughan TDD 2026-03-28 + aicoderscope 2026-05-16 + npm tdd-ai + sureprompts 2026-05-04）——**agent 最大的问题=不知道何时完成；失败测试套件是跨 agent loop 持续存在的外部真相源——没有测试 agent 用自己判断验证自己=静默错误的配方**；**先写测试→运行→确认"因正确理由失败"→最小实现→重构保持绿——四条窄指令，red 阶段禁止实现**；**循环测试警告：测试用被测函数算期望值=同义反复更糟（任何输入都"过"）——期望值必须来自 spec 不是代码**；**tdd-ai：TDD 状态机 CLI——agent 调 CLI 读状态（建什么/红绿/重构）决定做什么，做完 check-in；测试由 agent 自己用项目框架跑**。判据：**测试先于实现+期望值来自 spec——测试是给 agent 的验收接口，不是代码的注脚**。提升层：可复用 Skill。
7. **行为保持重构验证四层**（来源：bestaiweb 2026-05-23 + arXiv AgentModernize/REFINE + themodernblog + MoltQ）——**语义完整性=重构前后所有可能输入和状态下可观测行为（输出/副作用/API 契约）完全一致；跨文件挑战：隐式耦合（全局状态/DI 容器/React Context）+动态行为（运行时多态/反射/装饰器——静态分析追不全）**；**验证清单：①等价性测试对旧 seam（失败=对旧 seam 通过的测试现在失败；绿=公共契约保持）②diff 副作用面（以前写文件的模块不再写=回归）**；**验证组件四层：自动化测试双跑比对/形式验证（数学可证部分）/统计验证（差异可忽略概率）/差分测试**；**AgentModernize：行为规范图（BSG）强制业务逻辑显式可检视后才生成代码；REFINE 残余风险=弱 assert/fail-call 保留+公共方法删除**；**残酷现实：前端模型仅 5.4% 能完成整仓迁移不破坏任何东西，但团队在合并千 agent 重构进生产**。判据：**等价=逐输入输出相同（不是相似不是更好），直到确认旧行为正确且故意改**。提升层：可复用 Skill。
8. **编码基准饱和与多指标选型**（来源：presenc 2026-05-01 + aiwiki 2026-09-24 + platform.teamai 2026-09-16 + nimbalyst）——**SWE-bench Verified 饱和：2026-05 顶部 74-78%，2026-09 单 harness 七模型 95%+（最高 97%）——不再能区分模型；TerminalBench 52-58%（更真实终端任务设计）；现实世界 PR 通过率（人类评审接受的生产代码变更）35-50%，远低于 SWE-bench——gap=基准测不到真实因素（需求模糊/跨文件/评审标准）**；**选型看多指标：多文件准确率（8/8 vs 7/8 含 2 破坏变更）/首次接受率（82.5% vs 69%）/成本每实例/速度/可移植性（API+Claude Code vs Cursor-only）**；**SWE-bench ProMax：多语言大规模重构基准（170 实例 Pass@1+每实例成本）**。判据：**基准饱和后选型看真实 PR 通过率与多文件准确率，不看总分榜**。提升层：模型。
9. **Single-Push 多 agent git 工作流**（来源：wowhow 2026-06-18 + codex 33596 PR 冲突研究 2026-07-28 + nimbalyst worktrees + rockb cursor 并行）——**四阶段：Diverge（并行 agent 不能 push——PA 约束机械强制）→Signal（每 PA 完成写 .agent-done/ marker 文件+commit，不能 push）→Integrate（仅集成者 IL 串行：git pull 每 agent 分支+解决冲突+单 commit）→Ship（仅 IL：build 通过后 git push origin main 恰好一次）**；**冲突防御（33,596 PR 研究）：冲突率最高=agent 处理重叠问题域——按文件边界任务分解，每 agent 拥有不同文件/模块集；fan-out 前写下每会话拥有哪些文件，边界写进 prompt（"只在这条路径内工作"）；worktree 阻止两 agent 写同一文件，但**不阻止**从代码库两端改同一行为（干净合并运行期崩）——可靠修法是任务分解不是工具**；**共享配置文件（package.json/tsconfig.json/共享工具）是冲突高发区——预先分配文件所有权；pre-flight 检查每 agent 将改哪些文件**。判据：**多 agent 并行的安全边界是"文件所有权"，不是 git 工具——重叠即冲突**。提升层：工作流。
10. **编码提示工程：Context 最小充分 + Constraints 最被低估**（来源：aisrc 2026-09-29 + agentsroom 2026-09-27 + luismori 2026-04-22 + dev.to Anthropic 检查技巧）——**Context 给最小充分：栈/去哪找代码/哪些文件已相关/项目用什么模式；Constraints 是最被低估的块：不改 public API/不加新依赖除非万不得已/不碰无关模块/遵循项目现有规则**；**可移植 system prompt 形状：Identity→Mission→Operating rules→Tool policy→Output contract→Examples→Escalation and abstention（需求模糊立即停问，不静默选路径）**；**具体技术+版本（"React 19 with Server Components">"modern React"）；引用项目惯例（"Use Zustand for state"=告诉 agent 别用 Redux/Context）；质量期望（strict mode 无 any）；负面约束（Never...）**；**Anthropic 核心技巧：给 Claude "一个它能跑的检查"——测试套件/构建退出码/linter/脚本 diff 输出对 fixture/浏览器截图对比设计**。判据：**编码提示的验收标准必须是可运行的检查，不是"请仔细点"**。提升层：可复用 Skill。
11. **自愈恢复栈与监测定位**（来源：agentpatterns exception-handling 2026-07-15 + openhelm 2026-04-21 + codex 监测研究 2026-08-05）——**异常处理=渐进升级：self-correct（检测错误重试/调整，多数工具错误在此解决）→fallback→degrade gracefully→escalate——不丢失已积累工作**；**恢复栈：Level1 指数退避重试（瞬时失败/网络/限流）→Level2 回滚到最后事实收集步骤重跑 episode**；**定位监测实证：轻量 monitor 告诉 agent"哪里错了"（check name only）恢复率 45% vs 无指导重跑 16% vs 基线 0%（p=0.0005）——"告诉它哪错了"比重跑强 3 倍**；**scope check：每个主要动作前验证在任务定义范围内**。判据：**失败恢复的首选动作是"定位错误点"不是"重跑一遍"——重跑是最后手段**。提升层：工作流。
12. **编码 agent 可观测性**（来源：dev.to multi-agent telemetry 2026-09-28 + scien.cx Monocle + arXiv AgentDebugX + langchain 自愈 2026-04-03）——**OpenTelemetry 集成：每个 agent 转换/prompt-response 对/沙箱断言导出 span——工程领导可检视每个自动 PR 的推理轨迹（auditability）**；**traces 验证调用正确性不只输出：Monocle Test Tools 确保"做了正确调用"——测试验证 trace 不只看结果**；**生产证据闭环：产品捕获全路径（源材料→提取字段和出处→下游提交→专家修正）→生产问题结构化→发现→定向 eval→工程任务（Codex 自改进税 agent）**；**AgentDebugX：Detect-Attribute-Recover-Rerun 调试闭环，DeepDebug 多轮根因诊断（全局轨迹理解+结构化调查+交叉质询）**。判据：**可观测性=能解释"为什么这个 PR 这么做"——无轨迹的自动变更不可审计=不可合并**。提升层：可复用 Skill。
