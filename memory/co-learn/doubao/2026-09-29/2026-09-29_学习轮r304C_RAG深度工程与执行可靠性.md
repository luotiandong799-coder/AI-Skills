## 独点（12）

1. **Contextual Retrieval 生产管线 + 缓存成本结构**（来源：LobeHub contextual-retrieval 2026-09-23 + datarekha.com 2026-05-10 + dreaming.press 2026-08-04）——给每个 chunk 前加 LLM 生成的上下文摘要（"the error rate rose 3%" → "In Acme's Q2 report, revenue-team section: the error rate rose 3%"），修复切块丢上下文这个标准 RAG 静默失败。生产管线：chunking → per-chunk LLM context（prompt-cached）→ context+chunk 双索引（向量+BM25）→ RRF fusion top 150 → reranker top 20。成本：文档加载缓存一次，800-token chunks 约 $1.02/百万文档 token 一次性索引成本；50K 文档 100 chunks=首个全价、其余 90% 折扣。提升层：工作流。
2. **Prompt caching 两方式 + 90% 折扣**（来源：platform.claude.com/docs prompt-caching 2026-09-28）——automatic caching：顶层加一个 cache_control 字段，系统自动把缓存断点应用到最后可缓存块并随对话前移（适合多轮）；explicit breakpoints：手动放 cache_control 精确控制缓存边界（适合稳定前缀）。cached reads 约 $1.50/百万 tokens（90% 折扣）；1M 上下文窗口+1 小时 TTL 静态前缀使长上下文经济可行。提升层：工具。
3. **RAG 评测诊断性读法：四指标 + 0.7 检索阈值**（来源：ranjankumar.in 2026-05-11 + dev.to/saaro_net 2026-09-17 + qaskills.sh 2026-07-01）——Faithfulness（把答案拆成句子，LLM judge 逐句能否从检索上下文推断，支持语句/总语句）；Context Precision（无参考，检索到的 chunk 多少真正相关，5 取 3=0.6）；Context Recall（需 ground truth，必要 chunk 召回比例）。**检索低于 0.7 先查检索再测别的——生成指标在差检索之上无意义**。诊断读法：低 precision=噪声多、低 recall=缺 chunk 导致不完整答案。完美 faithfulness 不保证用户满意（漏语气/清晰度）。提升层：可复用 Skill。
4. **11 个 agent 失败模式 + 每个有可 grep 的 trace fingerprint**（来源：growthengineer.ai《11 Common AI Agent Failure Modes》2026-05-04）——tool hallucination / infinite reasoning loops / premature termination / context bloat / prompt injection / cost runaway / schema drift / stale memory / parallel tool race conditions / partial-state corruption / eval-prod skew；每个模式有特定 trace 指纹可 grep+已知修法。数据：**88% agent 失败归因基础设施缺口而非模型质量（Arize）**。提升层：可复用 Skill。
5. **生产输入分布漂移数据**（来源：dev.to/tamizuddin 2026-09-01）——测试输入 curated、生产输入 stochastic；Agent Reliability Collective 事后分析：平均生产 agent 每天遇到 **47 种测试集零覆盖的输入模式，其中 23% 导致失败**；测试通过≠生产可靠，靠代表性测试集无法捕获幂律分布的输入。提升层：工具。
6. **Agent 反模式：Assumption Propagation / Boring Technology Bias**（来源：agentpatterns.ai/anti-patterns 2026-05-27）——assumption propagation：早期误解级联贯穿后续所有工作，产出内部一致但解决错问题的输出（一致性≠正确性）；boring technology bias：LLM 推荐工具按训练数据频率而非问题适用性，流行默认打败最优。框架优先开发=在理解裸 LLM API 前加抽象层，掩盖失败并锁死架构决策。提升层：可复用 Skill。
7. **MCP 跨服务器数据流不受信 + Attested Tool-Server Admission**（来源：modelcontextprotocol.io client-best-practices 2026-07-28 + arXiv 2605.24248）——**一个服务器的工具结果对另一个服务器是不受信输入**，broker 必须对 brokered calls 应用与直接调用相同的输入审查策略；**输出截断不防外泄**；沙箱无直接网络访问。Attested admission 三机制：① 离线签名 clearance 断言（服务器发布在 well-known URI，host 对钉死信任根验证后才放行工具）；② deny-by-default per-server tool allowlist（接入服务器≠信任它的每个工具）；③ flavor-gated enforcement（检查从警告变硬拒绝，每个决策写防篡改日志）。提升层：工具。
8. **NVIDIA 沙箱强制控制清单 + 加固容器参数**（来源：developer.nvidia.com 2026-01-30 + code.claude.com secure-deployment 2026-09-16）——NVIDIA AI Red Team：**间接提示注入是执行用户级权限工具的 AI 编码 agent 的首要威胁**。OS 级强制三件套：阻断未知网络出口、禁止工作区外写、禁止写 agent 配置/扩展文件；推荐：沙箱整个 IDE+spawned functions、虚拟化分离沙箱内核与宿主内核、禁读工作区外文件。加固容器：`--cap-drop ALL --security-opt no-new-privileges --security-opt seccomp=... --read-only --tmpfs /tmp:rw,noexec`；强隔离选 gVisor（用户空间拦 syscall）或 Firecracker microVM（真 VM 隔离近容器启动速度）。提升层：工具。
9. **Hooks 九事件 + 护栏纪律**（来源：skillmd.ai agents-hooks 2026-04-06 + Microsoft Learn agent-hooks 2026-06-05 + totalum.app 2026-06-09）——事件全生命周期：UserPromptSubmit / PreToolUse / PostToolUse / PostToolUseFailure / PermissionRequest / SubagentStart / SubagentStop / Stop / SessionStart。纪律：**拒绝必须带理由——无理由的拒绝视同批准**；failMode: allow 除非严格强制；matcher 过宽引发性能问题；hooks 永远拒绝会造成循环；**PreToolUse 管护栏（可 exit code 2 block）/PostToolUse 管清理验证反馈（不能撤销工具调用）**；Stop 事件检查测试/build（CI 红不许停）；hook 三能力=deny/require approval/modify input。提升层：可复用 Skill。
10. **推理优化三技术 + 量化数据**（来源：Google Cloud 2026-03-28 + webcoderspeed 2026-03-15 + NVIDIA co-design 2026-09-02）——量化：FP16→INT4 内存减四分之一，decode 是 memory-bandwidth-bound 所以 4-bit 权重读取快 4 倍；AWQ 保护 1% salient channels；H100 FP8/Blackwell FP4 原生使量化从妥协变无损优化。speculative decoding：小 draft 提 K tokens、大模型批量验证，拒绝采样保分布等价，2-3x 加速、256 tokens 以上最有效。continuous batching：80-90% GPU 利用率 vs 静态 40%（"never deploy vLLM without it"）；prefix caching 省 15-20%。提升层：工具。
11. **记忆系统成本-精度实证：压缩精度比上下文量更决定准确率**（来源：arXiv 2601.07978 2026-09-16 + llm4agents.com 2026-05-12）——分布式多 agent 长记忆实测：Mem0/RAG/full-context 达 77-81%，Graphiti/cognee 仅 55-56%，**差距来自检索不完整而非推理失败**；**full-context 前传反而低于 mem0 的压缩提取**——压缩精度决定准确率。选型：要时间推理（事实何时为真）用 Graphiti（双时态图、事实自动失效，"user moved NYC→SF" 不会两事实同时为真）；要廉价规模化正确上下文检索用 Mem0。LongMemEval：Zep 63.8% vs Mem0 49.0%。提升层：工具。
12. **动态示例检索 + reasoning 模型内化 CoT 判断**（来源：LobeHub prompt-engineering-patterns 2026-09-11 + futureagi.com 2026-05-14）——few-shot 示例不写死，从知识库动态检索最相关示例（relation-aware example retrieval）；**reasoning 模型内化 CoT 后，可见 CoT prompt 可能浪费 token 甚至扭曲输出——先 eval 再假设**；few-shot CoT=2-5 个完整"问题+推理链+答案"示例教推理模式+输出格式。提升层：可复用 Skill。
