1. **模型路由三类型与级联架构**（来源：linhtruong AI-Cost-Control 2026-05 + prakashkagitha llm-stack 2026-08 + mudassirkhan playbook 2026-05 + jvoltci cost-latency 2026-05 + futureagi SLM-LLM 2026-08 + COMPEL 2026-04 + developersdigest 2026-06）——**路由三型：rule-based（最快）/classifier-based（< $0.0002/call 预测难度，需标注流量、可漂移）/cascade fallback（小模型先试，confidence/judge 不足升级——自纠错、好长尾、需便宜 judge）**；**cascade 链=classifier→simple?→small 7B/INT4→confident?→large 70B/FP16**；**well-implemented routing 减 25-40% API spend 无可见质量损失；~70% 客服/80% 代码补全/60% 摘要可被 7B 答（成本 1/30）；router 可把 40-70% 流量移到便宜档**；**超支主因=SDK 默认"全部发到硬编码的一个模型"——路由=用一个小决策（classify task→pick tier→不行才升级）替换硬编码模型**。判据：**先问"这个任务最便宜能干的模型是什么"，不行再升级**。提升层：工作流。

8. **Prompt 缓存架构：stable-prefix-first 与三 provider 差异**（来源：aipatternbook 2026-09 + aipromptshub caching 2026-06 + agentpatterns 2026-09 + datallmlab 2026-07 + respan 2026-07 + tokenoptimize 2026-06 + edenai 2026-07 + openrouter caching 2026-07 + aiworkflowlab 2026-07 + kanopy 2026-04，增量合 r315B 已落 cache 点）——**架构=stable-prefix-first：prefix=所有跨调用不变（system prompt/指令文件/工具目录/跨轮保留文档/固定历史），suffix=变了的部分（新 user turn/新工具结果/最新输出）——让 provider 缓存 prefix**；**三 provider：Anthropic=显式 opt-in cache_control 最多 4 breakpoints，read 0.1×（-90%），write 1.25×（5min TTL）或 2×（1h extended）；OpenAI=自动 exact-prefix ≥1024 tokens，顶部一个动态字符=0% hit rate；Gemini=implicit ~90% 或 explicit API（75% off，最小 32,768 tokens，hourly storage fee）**；**gateway 层 exact-match 缓存（同 system+messages+tools+model=免费响应零 provider token，TTL 30 天）**。判据：**prompt 架构按"不变的放前、变的放后"排；缓存策略按 provider 机制选（Anthropic 打 breakpoint/OpenAI 保前缀稳定/Gemini 大静态块走 explicit）**。提升层：工作流。
9. **缓存×路由冲突：session 边界路由**（来源：beri Manifest 案例 2026-08 + synthorai provider-drift 2026-06 + openrouter sticky-routing 2026-07 + haimaker OpenClaw 2026-08 + 钛媒体 Manus Cascade 2026-09）——**cache read 只花 10% 基础输入价：把 agent 步骤路由到 2.5× 便宜的模型反而贵 3.5×——Route at the session boundary, not the request（Manifest 四层路由 4 个月/7000 用户后弃用）**；**provider drift：默认多 provider 路由把 20 相同调用 spread 9 upstreams 只 hit cache 4/20（单 backend 19/20），drift 让 run 贵 3.9×，cache miss≈4× hit**；**sticky routing：同会话钉同一 provider 保住前缀缓存**；**Manus Cascade 实证：起步尽量轻、任务真正需要才调专业能力 → Token -23.2%/完成时间 -28.2%/运行成本 -32%**。判据：**路由决策在会话边界做；同会话钉 provider；缓存命中优先级高于绝对单价**。提升层：工作流。
10. **routing collapse 与 misrouting 静默失败**（来源：arXiv 2602.03478 routing-collapse 2026-02 + digitalocean infrastructure 2026-07 + agentropic 2026-06 + arxiv InfraMind 2606.11440 2026-06）——**routing collapse：成本预算上升时 router 系统性默认最贵模型（即使便宜的已够）——objective-decision mismatch，小模型被浪费**；**misrouting 静默失败更危险：router 把请求送错模型还报成功——无报错、日志无失败、用户得到更差答案（model fail 可见 vs router fail 不可见）**；**distribution overfit：router 调 benchmark 赢 benchmark，真实流量（intent/language/difficulty 混合不同）崩**；**静态路由负载失衡：优先小模型队列 130+ 而同等大模型闲置（低负载 67% 大模型 GPU 空置）；drift 监控漏最慢失败（0.3% 每日侵蚀当天不可见季度灾难）**。判据：**路由=基础设施决策非 feature；监控 misrouting 需要"正确答案对照"而非只看错误率**。提升层：工作流。
11. **SAAR 会话感知路由与 failover 破坏**（来源：vllm SAAR 2026-06 + arxiv ContinuityBench 2607.15899 2026-09 + dev kuldeep failover 2026-09 + dev shaam routing guide 2026-09）——**SAAR：语义路由+router-owned session memory+硬锁工具循环与非便携 provider state+safe reset boundaries+prefix-cache-aware switch pricing+replayable traces → 21,600 turns 减 79.29% 模型切换、eliminate 3,836 unsafe switches、减 78.71% 物理模型成本**；**failover 破坏清单：重放整个会话回合到次级 provider 常缺该回合工具执行的确定性 receipt（loss of intermediate tool receipts）+reasoning divergence+固定间隔重试（等 2.0s 再试 429）在 C=100 并发 failover 时自维持破坏循环（免费 tier 15 RPM 配额立即耗尽→fallback 也 429）**。判据：**会话感知路由=带记忆+硬锁+缓存感知定价；failover 用指数退避+幂等重放（先查该回合是否已执行）**。提升层：工作流。
