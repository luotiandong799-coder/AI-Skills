## 独点（12）

1. **EDD eval-driven development：评测先于提示写**（来源：qaskills.sh 2026-06-15 + bestprompt.art 2026-03-29）——**给 LLM 特性写评测先于写提示，迭代 prompt/模型过同一套评测集，CI 里每次变更按分数门控——TDD 适配非确定性**（不 assert 精确输出，assert 分数在标注集上高于阈值）；迭代纪律：**最小 prompt→跑 5-10 次（一次运行≠信号）→诊断失败模式→一次只改一个变量→版本化（存测试集+评分 rubric）**；**一致性检查：同输入跑 5 次方差大=提示欠规格化，加约束/示例直到方差收敛**。判据：**提示工程从"微调+目测"变成"评测驱动"的第一步是先把测试集建起来**。提升层：可复用 Skill。
2. **结构化输出四层栈 + constrained decoding 机制**（来源：dev.to aifrontierpost 2026-09-28 + codewithkarani 2026-06-26 + zylos 2026-04-11）——**可信 JSON 是四层栈：schema 设计→provider 强制→约束解码→验证循环，四层都要**；**constrained decoding：采样前把不符合语法的 token mask 成负无穷——模型物理上无法产出违反 schema 的输出**；XGrammar（vLLM/SGLang 默认后端）vocab partitioning+grammar caching 达 100x 吞吐，llguidance（Rust）~40-50 低延迟；**CRANE：约束解码可能降推理质量（把模型推离高概率 token 序列），交替约束/无约束窗口恢复最多 10 点符号推理**；Claude 无 strict 模式但 tool_use+input_schema 等价保证；JSON Mode 已属 legacy。判据：**约束解码是结构性保证不是提示技巧——但推理类任务要留无约束窗口**。提升层：工作流。
3. **parser-feedback retry loop（带错误反馈的重试）**（来源：velsof 2026-06-14 + ai-tldr 2026-06-12 + supergood 2026-03-10）——**验证失败→把具体错误信息喂回模型让其自校正（"Field start_date 无效：…请修正"），不是盲重试也不是报错给用户**；生产聊天约 8% 首轮验证失败，**把具体 Pydantic 错误放进 retry prompt 二轮失败率 <1%**；**repair 先（json_repair 快免费）再 retry（带错误重提示）**；**retry 上限 2-3 次——成功概率首次修正后骤降**；库默认 max_retries=0（Instructor/Pydantic AI）要显式设；**错误重写成具体指令而非原样贴错误**。判据：**验证循环的真正价值在语义校验（schema 表达不了的部分），结构性违规已被 provider 模式消灭**。提升层：工作流。
4. **prompt 版本化 = 运行时配置一起版本化**（来源：alldaystech 2026-01-02 + minixium 2026-05-31 + kindatechnical 2026-03-01）——**prompt 可复现必须同时版本化运行时配置：模型/参数/工具 schema/注入的 system policy 文本**；语义版本化：**MAJOR（格式/策略变化）MINOR（行为改进）PATCH（小澄清）**；changelog 记录改了什么/为什么/影响；**回归测试：同一套测试用例每次迭代都跑，与基线对比通过率，超线才部署**；PromptArchive：Git-native 本地离线版本管理，检测语义漂移/幻觉/输出约束违规。判据：**只版本化 prompt 文本=版本化了一半；模型换版即不可复现**。提升层：可复用 Skill。
5. **路由四模式 + 自评分级**（来源：swfte 2026-05-04 + nvidia switchyard 2026-08-11 + alibabacloud 2026-07-21）——**①Single Router（RouteLLM：固定质量省 48-75% 成本，+5-15ms）；②Cascade 便宜到强（质量下限：省 70-80%，级联时 +0-400ms，约 80% 真实查询小模型够）；③Speculative-Race（延迟目标：成本 +5~-20%，延迟 -30-60%）；④Escalation router（会话从小模型开始，LLM judge 逐轮监控，检测持续困难/循环/漂移升到更强模型——静态分类→自适应）**；**自评分级：无单独分类模型，Flash 自评 difficulty_score（<0.4 接受/<0.8 升 Plus/>升 Max）**；FrugalGPT 三组件：prompt adaptation/LLM approximation（缓存复用）/LLM cascade。判据：**路由先定目标（省成本/质量下限/延迟），四模式对应三个目标，别混**。提升层：工作流。
6. **动态 few-shot：random vs curated vs dynamic retrieval**（来源：theneuralbase 2026-04-15 + agentbus 2026-02-15 + kindatechnical 2026-03-01）——**输入 embedding→例子库 top-k 相似→运行时注入——覆盖无限输入分布不膨胀 prompt**；**3-5 个好例子最佳性价比；例子排序：最相似的最后（recency 效应）**；选 diverse/representative/correctly labeled + boundary cases；**MMR 最大边际相关兼顾相似+覆盖**；例子库从生产反馈增长（客服 200 标注例子动态拉 5 最相似）。判据：**静态 few-shot 在输入漂移时失效，动态检索是生产形态**。提升层：工作流。
7. **上下文注入纪律：Context > cleverness**（来源：novakit 2026-04-19 + explainx 2026-06-28 + toolsku 2026-07-03 + gitlab 2026-05-18）——**注入四类：过去相似任务/用户批准的三个风格输出/决策历史/领域术语表+负面例子（被拒输出+原因）——模型像老同事用机构记忆**；RAG 注入纪律：**相关性阈值（低于 0.7 不注入，噪音增幻觉）/重排序/检索内容放对话历史前（lost-in-the-middle 最相关在前）/去重同文档合并/动态 Top-K 按剩余预算/源标签+分数/embedding 模型领域验证**；**In-Context RAG：<10 万文档整个数据集放上下文比外置向量库更准更快**；**Retrieve-Compress-Inject：小模型把检索段落压成蒸馏结论再注入主上下文**；dynamic instructions：规则按当前状态装配（角色/步骤/检索到策略文档才注入）。判据：**2026 提示工程重心从措辞转到"注入什么、放在哪、注入多少"**。提升层：工作流。
8. **LLM-as-judge 校准：四偏差 + reference-inflated**（来源：futureagi 2026-08-27 + howardism 2026-06-15 + dev.to 2026-09-09）——**四偏差：位置偏差（rubric 列表特定位置被偏好）/自偏好（judge 偏爱同模型族——源于困惑度熟悉度）/自增强（生成+判断同模型偏高）/冗长偏差（长=好）**；**校准：labeled gold-set 上测 judge 与人类一致性（Cohen's kappa/Krippendorff's alpha），launch 时/每月/rubric 变更后**；**修正：位置交换跑两次取一致/跨族 judge 双判要求一致/rubric 显式冗长惩罚**；**reference-inflated：无金标准时 judge 系统性高估错误答案，加参考翻转高达 85% 判定（低资源语言最差）——阈值要按有参考的数字校准**；CoT +2-5% 准确率 +30% token。判据：**judge 上线前先校准，校准指标是 kappa 不是"看起来合理"**。提升层：可复用 Skill。
9. **prompt 注入硬分隔符：neutralize + randomize**（来源：ai-tldr 2026-06-13 + shyankdev 2026-07-14 + blckalpaca 2026-06-09）——**硬分隔符是第一防线：<user_input> 标签包裹+明确指示该块是数据**；**neutralize + randomize：插入前剥离/转义闭合标记 + 每次请求随机分隔 token（攻击者猜不到闭合串）**；spotlighting（微软）：编码/标记不可信文本让模型始终知道来源；**input classification drift：跟踪 NORMAL vs INJECTION 分类比率随时间变化——偏移=攻击模式在变**；**注入是 transformer 架构现实，提示工程不能单独解决——指令层级 System>Developer>User>Tool-Output 降序权威 + 最小权限工具**；剥离零宽 Unicode/HTML。判据：**分隔符+随机化挡 casual 攻击，架构级防御（权限/隔离）才挡 determined**。提升层：可复用 Skill。
10. **长上下文位置布局：U 形曲线 + Bookend**（来源：ai-tldr lost-in-middle 2026-06-12 + twnside 2026-06-11 + promptgenius 1m 2026-06-14）——**注意力 U 形：开头结尾高、中间低（lost in the middle）**；**布局：开头 5%（system 身份/规则/输出格式/核心任务）→中间（参考材料/检索文档/历史轮次）→结尾 5%（当前查询/具体指令/输出格式）**；**Bookend 策略：上下文块开头放关键点摘要、结尾重复关键点——两端高注意区重复强化，检索准确率近满**；**V 形重排检索块（不按相关性顺序平铺 20 chunks，相关度最高靠近两端）**；**payload 短到几乎没有中间可丢**；HiCI 层次注意力 5.5% 额外参数把 4K 扩到 100K。判据：**关键信息放哪比放不放更影响效果——放中间等于半丢**。提升层：工作流。
11. **评测工具链分工**（来源：promptquorum 2026-08-27 + futureagi 2026-04-04 + pypi promptarchive 2026-09-08）——**Promptfoo：CI/CD 秒级回归（90+ 提供商、67+ 攻击插件、本地 100% 隐私）→ 用它在每次提交抓回归；Braintrust：最终评测（分钟-小时、人+LLM judge）→ 上线前深评；DeepEval：RAG 专项（RAGAS 指标：检索+上下文+合成）；LangSmith：tracing（多步链调试/失败根因）**；promptry：断言语义回归（"Overall 0.910→0.720 REGRESSION，probable cause: prompt v3→v4"）。判据：**一套工具跑不完评测生命周期——CI 秒级/上线深评/RAG 专项/追踪分工**。提升层：可复用 Skill。
12. **生产提示调试清单**（来源：aiblog.mikel-ltd 2026-03-25 + next-gen.cloud 2026-06-08）——**捕获完整执行上下文（prompt/输入/输出/参数）→最小测试用例复现→识别失败类型（format/content/hallucination/incomplete）→验证输入有效性（非空/非畸形/在限内）→隔离导致失败的提示段落→判断模型特有还是普适→系统修复（约束/示例/CoT）**；测试集要含畸形文档/不完整记录/对抗性文本，不只干净例子；**失败模式分开度量：schema 无效/缺字段/幻觉字段/错误标签/拒答**；验证下游在模型返回空/不确定输出时行为正常。判据：**生产排障先捕获上下文再改提示，跳过诊断直接改=靠运气**。提升层：可复用 Skill。
