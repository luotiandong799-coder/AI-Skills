2. **SKILL.md 编写硬规则与技能组合性**（来源：anthropic complete guide + support.claude 2026-07-23 + claude.com lessons 2026-06）——**SKILL.md 命名硬规则：必须恰为 SKILL.md（大小写敏感——SKILL.MD/skill.md 均不接受）；技能文件夹 kebab-case（notion-project-setup ✅；Notion Project Setup ❌）**；**定制技能指南：含 examples（输入输出示例帮模型理解成功形态）；增量测试（每次显著变更后测，不一次建复杂技能）；技能可隐式组合——技能不能显式引用其他技能，但模型自动多技能共用——composability 是技能特性最强大之一**；**技能九类框架（Anthropic 内部 catalog 实证）：最佳技能干净落进一类，跨类尝试太多会 confuse agent**。判据：**建技能=单文件夹 kebab-case+SKILL.md 精确命名+必带示例；跨类技能是设计缺陷**。提升层：可复用 Skill。
3. **2026 提示工程转向：结构化输出/reasoning 分层/CoT 角色转变/Context Engineering**（来源：dev.to vijay 2026-09-22 + kdnuggets 2026-09-18 + aipromptlibrary 2026-05 + arXiv 2608.07494 + newsia 2026-04 + skillgen 2026-05）——**结构化输出新规：严格输出 schema（JSON Schema/Proto-Buf）；reasoning_effort 设 Medium/High（Low 只用于 cache lookup）；启用原生 structured mode 关 free-form；prompt 包进 agentic workflow（并行降延迟）；领域示例注入（few-shot 胜过 temperature 技巧）**；**CoT 角色转变（2026 关键）：2022 年 CoT 研究在非推理模型上增益巨大（+10-40%），frontier 模型已原生推理——显式请求 step-by-step 对已内部推理的模型价值下降；仍值成本处=需要中间步骤可见/输出结构需推理痕迹/模型非原生推理**；**reasoning 类模型（gpt-5-2025-08-07）reasoning effort 自动链**；**Context Engineering=整个上下文窗口设计成结构化信息架构（system prompt 角色约束/RAG 动态检索/相关历史/工具定义/结构化示例）——prompt 只是多层上下文栈的一层**；**reasoning-based prompting 族（prompt chaining/CoT/tree-of-thought/least-to-most）增推理长度需足够大模型支撑**。判据：**2026 写提示=先 schema 后 prompt；CoT 只在需要可见推理痕迹时显式加；上下文按层设计**。提升层：可复用 Skill。
