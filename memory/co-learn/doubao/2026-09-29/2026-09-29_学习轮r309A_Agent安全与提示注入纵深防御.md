## 独点（12）

1. **间接注入三类通道与运行时守卫**（来源：arXiv ClawGuard 2604.11790 + AgentVisor 2604.24118 + zylos 2026-05-11 + accuroai）——**注入三通道：直接（用户输入）/间接（RAG 检索文档、网页、邮件、工具输出）/MCP 工具投毒（恶意工具描述使恶意动作看似良性或任务相关）**；**ClawGuard 模式：运行时在每次工具调用边界强制 user-confirmed 规则集——把"对齐依赖"的不确定防御转成确定性可审计机制，在真实世界影响产生前拦截对抗性工具调用；从用户陈述目标自动推导任务特定访问约束（不靠模型修改/基础设施变更/手工规则）**；**AgentVisor：语义虚拟化=语义权限分离（经典 OS 原语适配 agent 层）+审计协议+语义故障恢复——近零攻击成功率保持高任务完成**；**持久记忆注入：注入写入长期记忆，后续会话静默执行（跨会话后门）——记忆写入必须认证+检查（OWASP GenAI Q1 2026 实例）**。判据：**间接注入是 agent 安全第一威胁——爆炸半径=工具面不是回复文本**。提升层：可复用 Skill。
2. **防御提示工程五模式**（来源：zylos + dev.to tamizuddin + ypyl.github.io）——**①显式信任标签：外部检索内容进上下文前包 wrapper（`<retrieved_content trust_level="untrusted" source="...">`）+元指令约束解释**；**②上下文分区（数据包裹）：用分隔符结构性分离指令与数据（LLM 被训练尊重）**；**③输入消毒：剥离/转义检索文档中的标记模式到达模型前**；**④输出验证（参数清洗）：工具执行层拒绝无效或越界参数——LLM 可被骗但工具执行层必须拒绝**；**⑤工具策略在模型外强制：策略进 runtime 不进 prompt**。判据：**"把用户数据视为数据而非命令"必须同时存在于提示架构与执行层，单靠提示语是相信对齐**。提升层：可复用 Skill。
3. **四点扫描蓝图：注入检测器放四个边界**（来源：Google Cloud Security 2026-07-23 + infodivelabs）——**User Ingress Scan（用户输入→agent runtime 之间）/Context Scan（外部 grounding 数据源→runtime，显式在拼接进 prompt 之前）/Tool Output Scan（动态工具调用输出→runtime）/Egress Response Scan（模型最终文本→用户）——四点覆盖直接+间接+工具面+输出面**；**输入消毒=第一道防线：剥离/标记已知注入模式（"ignore previous instructions" 等）到 LLM 前**。判据：**扫描点必须贴数据汇入 runtime 的每个边界——漏一个点就是一条注入通道**。提升层：工作流。
4. **沙箱执行规范**（来源：tetrate + Interrupt 2026 LangChain + Kata + AWS Bedrock + NVIDIA）——**agent 生成代码永不运行在 agent 进程自身的特权/网络/文件系统**；**ephemeral 容器参数：512MB/0.25 vCPU/180s 硬超时/无持久存储/仅目标云 API 网络**；**凭证运行时注入（平台 secrets 机制），永不烘焙进镜像**；**agent 生成文件写 ephemeral 层 teardown 销毁——主机文件系统永不暴露**；**受限 shell：无 sudo/root 升级、cgroup 资源限制（CPU/内存/打开文件）、进程数限制防 fork bomb、无主机网络命名空间**；**Kata Containers：每 agent 会话独立内核，即使被攻陷也逃不出内核边界（提示级护栏不够时平台层兜底）**。判据：**身份不够时沙箱兜底——被攻陷 agent 到达主机 OS 会危及同机所有工作负载**。提升层：工具。
5. **工具调用治理面**（来源：Microsoft AGT + agent-airlock + mcpkernel + NVIDIA OpenShell/Sentry）——**AGT 模式：MCP client 与 tool server 之间的运行时治理层，每个工具调用按策略评估——定义扫描（definition scanning）→策略评估（policy evaluation）→响应检查（response inspection）；治理 agent 的动作而非模型输出**；**agent-airlock：deny-by-default+幽灵参数剥离（ghost-argument stripping：工具调用里多传的非 schema 参数被剥离——攻击者/幻觉注入的隐藏参数）**；**mcpkernel：DLP Guard（跨工具多跳数据泄露：PII in→HTTP out=阻断）+确定性信封（hash 输入输出+Sigstore 签名 trace 可重放）+防篡改 append-only 审计日志（SIEM 导出）**；**NVIDIA OpenShell：不修改 agent 本体套在 Claude Code/Codex 外，运行时强制文件/网络/工具/凭证边界**。判据：**工具参数是注入的落地载体——调用前 schema 校验+调用后响应检查缺一不可**。提升层：工具。
6. **MCP/技能供应链投毒与防线**（来源：Snyk ToxicSkills + Antiy ClawHavoc + obot + aicodingpatterns + agentconn + OWASP AST10 + arXiv 2603.00195 + simonroses）——**实测数据：Snyk 扫 3,984 skills 发现 1,467 恶意 payload（36% 缺陷率、76 确认恶意）；ClawHavoc 投毒 1,184 skills；91% 恶意 skills 结合间接注入与 malware——"审查指令而非只审代码"**；**Markitdown MCP SSRF 读 AWS 实例元数据；.pth 文件每次解释器启动自动执行（恶意 MCP 版本存活 40 分钟）；MCP SDK STDIO 传输=配置到命令直接执行（设计缺陷非 bug）**；**能力模型缺失：MCP server 声明 tool schema 但不声明能力需求——声称"搜索文件"的 server 可能执行任意 shell 命令**；**OWASP AST10：ed25519 签名所有发布 skill 拒绝未签名安装；签名绑定可解析可撤销发布者身份（key id+域名/did:web+公开验证 key）不只裸 key；签名证明作者不证明安全——与行为分析组合**；**manifest 是 JSON server 是代码——查 command 字段引用的二进制可信吗/npx -y 不熟包吗/运行时下载吗**。判据：**装 skill/MCP=扩权限——clean manifest 指向恶意 server 仍是恶意；配置审查+代码审查+签名验证三层都要**。提升层：可复用 Skill。
7. **输出护栏八件事与 PII 工具链**（来源：web3aiblog + futureagi + OpenAI Privacy Filter + guardrails-ai + sentinelguard）——**guardrail 八件事：输入验证（畸形/超大/对抗输入在花 token 前拒绝）/内容审核（hate/violence/self-harm/sexual）/PII 检测脱敏（模型看到前或记录前 mask）/主题限制/…**；**Presidio：OSS PII 检测脱敏（NER+正则+规则+checksum 检测器：信用卡/SSN/姓名/电话/IBAN/加密钱包，多语言）；OpenAI Privacy Filter：开放权重小模型高吞吐 PII 检测脱敏**；**Guardrails AI：对 typed schema 强制验证+确定性数据校验+程序化输出纠正——非确定性 LLM 生成验证通过后才返回客户端逻辑**；**sentinelguard 网关：OpenAI 兼容 /v1 API+虚拟 keys+模型别名+复杂度路由+provider 池+成本感知路由+故障转移（虚拟 key=模型凭据不直出）**。判据：**输出护栏=输入消毒不够的第二层——越狱致有害代码或敏感数据输出必须到用户/工具前拦截**。提升层：工具。
8. **自动红队与对抗训练**（来源：OpenAI GPT-Red + HackAgent + Microsoft PyRIT + ADVERSA + STING + RIFT-Bench + arXiv 2605.04019）——**GPT-Red：自动红队模型用于对抗训练（前代模型对其注入攻击高度脆弱；用其对抗训练 GPT-5.6 显著更抗注入）**；**HackAgent：开源 agent 红队工具包（攻击者模型对目标模型+选定越狱算法+评分响应+记录每次尝试）；数十万尝试每个明显成功由 3 个 judge 模型小组独立复核（红队也要防假阳性）**；**ADVERSA：fine-tuned 70B 攻击者模型消除攻击侧安全拒绝（现成模型当攻击者不可靠会拒绝攻击）；把 guardrail 退化测成连续每轮合规轨迹而非离散越狱事件；victim 响应 5 点 rubric**；**STING：step-by-step illicit plan 基于良性人设+自适应跟进+judge agents 追踪阶段完成；time-to-first-jailbreak 随机变量建模（discovery curves/hazard-ratio 归因/新指标）**；**RIFT-Bench：发现（提取系统结构）→扫描（自适应对抗攻击）两阶段，105 自适应探针**；**agentic 红队 15 目标类别 3 风险域（安全 5 类：凭据泄漏/系统提示词泄漏/工具滥用/供应链/对齐完整性，Critical≥0.9）**。判据：**红队=自动化持续攻击+独立复核——攻击者模型要与被测对象同代或更强才有效**。提升层：工作流。
9. **Agent 身份与委托授权**（来源：IETF DAAP + Auth0 + ACAP + AAP + actor_chain + Microsoft Foundry + wowhow）——**委托授权：子 agent 每个需 parent 权限子集范围的 grant，整棵委托树可被原始主体撤销（DAAP）**；**AI Agents Are Not Users：委托上下文记录 agent 作为 actor+用户作为 subject——下游看到"agent X 代表 user Y 以委托权 Z 行动"而非"service account 做了事"；专属审计线索独立于底层工具日志**；**防篡改审计：ACAP hash-chained append-only（每 entry 承诺前 entry hash，按任务树分区）；actor_chain claim：可加密验证的有序 actors 记录替代仅信息的 act claim（agent-to-agent 高保证取证）**；**特权膨胀缓解：每个 agent 实例唯一/作用域/短生命周期身份——orchestrator 把自身凭证传给子 agent=所有子 agent 获得同 orchestrator 权限（ASI06 典型反模式）**；**OAuth 2.1 CIBA：敏感操作前人工审批+随时立即撤销**。判据：**agent 不是用户——身份模型必须同时记录"谁在行动"和"代表谁"，委托权必须逐级收窄可撤销**。提升层：可复用 Skill。
10. **OWASP Agentic Top 10 与 Least Agency**（来源：OWASP 2026 官方 + modulos + aisecurityplatform + aibuzz）——**ASI01-ASI10：planning（不可信规划）/tool use/identity/supply chain/code execution/memory/inter-agent communication/cascading failures/human-agent trust/rogue agents**；**Least Agency and Least Privilege for Tools：per-tool 最小特权 profile（scopes/最大速率/出口白名单）；数据库只读查询、邮件无 send/delete 权、最小 CRUD；尽量表达成 IAM 策略绑到每个工具**；**资源与成本放大=denial-of-wallet：per-agent/per-task 预算+运行时步骤预算+成本异常告警+halt-on-budget-breach 默认**；**级联失败：agent 递归深度硬限制+子 agent 生成限制+执行时间/资源上限+异常生成模式告警+熔断器**；**ASI09：agent 感知权威本身是攻击向量（通过可信接口做欺诈/钓鱼/社会工程）——组织与流程风险非纯代码风险**。判据：**自主性越大工具特权必须越小——least agency 与 least privilege 并列，不是二选一**。提升层：可复用 Skill。
11. **Agent 平台加固清单**（来源：Claude Code 官方 security/permissions + Anthropic auto mode + llm-safe-haven + quintai）——**sandboxed bash tool：文件系统+网络隔离减少权限提示同时保持安全（/sandbox 定义自主边界）**；**工作目录边界：Manual 模式只写启动目录+子目录，父目录需明确权限**；**permissions allow 列表：不推断命令是否危险（由目标路径/效果决定），protected paths（.git/.claude）永远保护**；**web 搜索摘要化：搜索结果摘要而非原始内容直入上下文——降恶意网页注入风险**；**auto mode 三层分类器：Tier1 只读低成本直接批准/Tier2 项目内文件操作无分类器调用（版本控制可审查）/Tier3 transcript classifier 看一切其他（shell/web fetch/外部工具/子 agent）——只有真实下行风险动作到最终层**；**hooks 拦截每个工具调用（PreToolUse/PostToolUse）强制策略=必然执行机制**；**cleanupPeriodDays 缩短明文会话 transcripts 留存**。判据：**agent 平台安全=权限分三态（交互/自动/旁路）+沙箱+钩子三层叠——提示词安全声明是最弱一环**。提升层：工具。
12. **Agent 数据合规要点**（来源：GDPR 12 点 + agent-works + onlypiece + EDPB Opinion 28/2024 + 香港 PDPO 指引 + 中国生成式 AI 办法）——**法律依据：文档化（合法利益需三阶平衡测试完成并记录）；同意=肯定动作（预勾选不算，沉默不作为不构成），对 agent 操作脆弱因为 scope 任务中途漂移**；**对话是个人数据：即使未识别身份，transcript 含可识别元素——保留策略明确/按工作区可配/默认应用，transcripts/embeddings/聚合指标不同保留期**；**删除=有效删除非逻辑删除+留文档痕迹（DPO 检查时可证）**；**记忆四义务：Art 6 法律依据/Art 13-14 透明（告诉用户记住什么记多久为什么）/Art 17 擦除（所有存储层包括向量索引真删）/Art 5(1)(c) 最小化（存必需事实不存全 transcript）**；**function creep：agent 聚合重组多源个人数据超原目的使用（香港 PDPO 新指引重点）**；**中国《生成式 AI 服务管理暂行办法》第 11 条：训练数据来源合法+个人信息去标识化**。判据：**隐私是默认架构不是事后选项——数据最小化+保留期+可证删除在 agent 记忆/日志/嵌入三层都要落实**。提升层：可复用 Skill。
