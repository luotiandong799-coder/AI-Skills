### 2. 缓存断点四层布局与 1024 token 最小块（来源：platform.claude.com/docs/en/build-with-claude/prompt-caching 2026-09-18 + then euralbase.com 2026-04-14 + markaicode.com 2026-03-12 实拉）
- **四断点**：① tools 定义（末工具 cache_control 缓存全部工具定义）② 可复用静态指令 ③ RAG context（独立缓存，更新文档不失效 tools/指令缓存）④ conversation history（final user message 增量缓存）。
- **最小可缓存块 1024 tokens**：更短静默忽略（cache_creation_input_tokens: 0），且需正确 model+cache_control ephemeral，缺一静默失效——用 response.usage.cache_creation_input_tokens 验证是否真激活。

### 5. Make 错误处理五指令矩阵与 Fallback/DLQ 模式（来源：use-apify.com/blog/make-com-error-handling-guide 2026-03-15 + help.make.com/rollback-error-handler 2026-09-08 + workflowpick.com 2026-05-12 + thinkbot.agency 2026-07-07 + keerok.tech 2026-05-18 实拉）
- **五指令**：Rollback（停止标失败+回滚已提交操作，默认）/ Commit（停止标成功保留已完成）/ Resume（忽略错误+替代值继续）/ Break（停止）/ Ignore（静默跳过）。

### 7. GitHub Actions 安全加固：self-hosted 风险模型与 token/secrets 治理（来源：docs.github.com/en/actions/how-tos/security-for-github-actions/security-guides/security-hardening-for-github-actions 2025-07-05 + learn.microsoft.com configure-self-hosted-runners 2026-07-06 + docs.github.com secure-use-reference 2025-07-24 实拉）
- **风险模型**：GitHub-hosted runner=临时干净隔离 VM 无法持久入侵；self-hosted 无此保证，**可被不可信 workflow 代码持久入侵**（fork+PR 即可攻陷，窃取 secrets 与 GITHUB_TOKEN）——**公有仓库几乎绝不用 self-hosted**，私仓也要谨慎（任何有写权限者可读全部 repo secrets）。
- **GITHUB_TOKEN 最小权限**：默认只读 repo contents，按 job 增加（permissions 块）；secrets 永不存明文 workflow 文件（org/repo/env 三级配置）；运行日志自动 redact（精确匹配+常见编码）。
- **runner 组治理**：runner groups 管控访问/工作负载分布/安全策略；ephemeral runners 自动移除防持久威胁；监控+审计日志+OS 补丁。
- 判重：r291B/r295B 安全已写，本点=自托管风险模型+token 默认只读+secrets 三级配置+runner 组（独有 ≥40%），合并保留。
- 提升层：工作流（安全）。
