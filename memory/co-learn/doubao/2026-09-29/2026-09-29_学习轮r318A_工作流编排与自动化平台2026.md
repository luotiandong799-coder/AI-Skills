2. **LangGraph checkpointer 持久化机制**（来源：langchain docs×3 2026-09 + openlegion 2026-06 + pythondatabench 2026-08 + ailearningguides 2026-05 + activewizards 2026-05 + skilld 2026-05 + xbstack 2026-06 + hivebook 2026-07）——**每 super-step 保存 graph state 快照（threads 组织）→enable HITL/time travel debugging/fault-tolerant execution/conversational memory**；**20-step 研究管道 step14 crash→1-13 浪费（token/工具成本/wall-clock 重来）——checkpoint 后 recovery targeted（load latest checkpoint for thread_id 从 14 resume）**；**granularity=per-node（至多重复一个 node 的 work）**；**Re-execution 语义：checkpoint 在 super-step boundary 不在 node 内——恢复后 affected node 从函数开头重跑，code+side effects before pause 会重跑→node logic 必须幂等**；**Functional API：resume 不从停的行继续——回 checkpoint boundary 重放到 pause，已完成 task/subgraph 结果从 checkpointer 恢复不重算**；**Checkpointer 选型：MemorySaver=本地 dev/unit tests（restart 丢状态，never production）；SqliteSaver/PostgresSaver=生产**；**Subgraph 隐式传播：编译父图传 checkpointer 自动传播所有 subgraph（复杂业务可独立持久化）**；**短长期分离：Short-term（checkpointer）=thread-scoped conversation history；Long-term（store）=cross-thread preferences/facts**。判据：**节点逻辑设计为可重跑（幂等）；选型 dev/prod 分开**。提升层：工作流。
3. **Workflow 错误恢复模式**（来源：n8n agentic patterns 2026-07 + n8n playbook 2026-06 + mindstudio 2026-03 + egoistai 2026-08 + ai-guide-expert 2026-03，增量合 wb-debug-loop 既有"transport/tool 分开+latent modes"）——**Error recovery 四件套=retry logic/fallback models/fallback providers/human escalation paths——不是立即终止 workflow，先尝试替代动作再涉及人**；**Retry decision tree：transient→短暂等待重试（带上限）；structural output failure→带 validation error context 重试（agent 知道哪错）；retry budget 耗尽→fallback；无 fallback→abort+log**；**可重试/不可重试分类：good retry=temporary network failures/rate limits with backoff/database deadlocks/LLM JSON formatting failures/API timeouts；bad retry=invalid user input/missing permissions/deleted account/declined payment/policy violation——用 NonRetriableError 标记永久失败**；**失败域隔离：每个 agent/sub-workflow 自己的 error handling（billing specialist 失败不级联 technical support 或 crash orchestrator）——wrap 每个 agent 调用返回 structured failure response 供 parent 处理**；**Error strategy 三档：abort（默认，恢复不能错误停整个 workflow）/default-value（非重要处理用预设默认值继续）/fail-branch（分到失败分支做恢复）**。判据：**先分类错误再定策略；父流程只处理结构化失败响应**。提升层：工作流。
4. **HITL 的 durable 实现**（来源：promptz2h 2026-06 + mslearn ag-ui 2026-07 + anhtu 2026-05 + devspedia 2026-06 + clarion 2026-05，增量合偏好人工审批/guardian 三问）——**HITL 基本模式：agent 决定动作→发出 approval 请求→workflow pause→人类 review 决策+reasoning→approve/reject/modify→带反馈恢复（financial agents 转账前 ask human）**；**Granular approval：individual sensitive action 单独 approval（@tool(approval_mode="always_require")）不要 batch 多个敏感操作；informative arguments=descriptive parameter names+context**；**Durable pause/resume：agent 可能等 hours/days 审批——不能 keep process alive+context window open；答案=state persistence+durable execution（LangGraph interrupt()+checkpointer）**；**approval gate 是 workflow state 不是 hidden chat message：store who can approve/what exactly/what happens next（typed ApprovalRequest）**；**HITL checkpoint 触发=confidence thresholds/risk flags/explicit failure exhaustion**。判据：**审批边界是持久化状态+明确的批准者/事项/后续，不是聊天消息**。提升层：工作流。
5. **Dify Agent Node 最佳实践与 Agentic RAG**（来源：dify workflows 2026-08 + mintlify agent node 2026-08 + dify blog agentic rag 2026-01 + marketplace legal agent + dify nvidia 2026-01 + dify multimodal 2026-01）——**Workflow Studio 画布节点类别=模型调用/知识检索/工具/代码/分支/触发器/人工审核——AI 应用像软件一样测试交付；模型只是其中一个节点，可靠 Agent=围绕它构建的 Workflow 体系**；**Agent Node 五 best practices：Clear Tool Descriptions（agent 知道何时怎么用每个工具）/Appropriate Iteration Limits（防 runaway cost 同时给复杂任务灵活性）/Detailed Instructions（role/goals/constraints/preferences）/Memory Management（平衡 context retention 与 token 效率）**；**Agentic RAG（Dify 实现）：Agent Node=centralized decision engine 组合 intent analysis/tool orchestration/source selection/retry logic；vs one-shot retrieve-then-generate RAG：迭代分析 intent/选工具和源/改写 query/评估证据/retry or fallback——提升 grounding+reliability 但加 latency/cost/complexity；工具=Qdrant（vector+hybrid）+Google Search+custom APIs；Legal Research Agent 模板=动态选 1-2 collections+insufficient 切 Google Search fallback**；**部署形态：自托管/VPC（SSO+SAML+RBAC+audit logs+SOC2+ISO27001+Helm K8s）；Inference=Ollama/vLLM/TensorRT-LLM 跑 Llama/Qwen/DeepSeek/Nemotron**。判据：**Agentic RAG 用迭代决策换 grounding，接受 latency/cost 代价**。提升层：工作流。
6. **Agentic Process Automation（APA）vs 传统 RPA**（来源：skyvern×3 2026-07 + uipath screenplay 2026-04/09 + aws agentcore 2026-08 + scored tools 2026）——**RPA=automates fixed path 静默失败当 portals 变；AI agents=pursue goal+每步 re-read page；RPA teams 30-70% effort 花在维护 broken bots（vendor 每次更新 compounding）**；**APA 三属性=goal-directed planning/live environment interaction/state-aware exception handling mid-task——layout-driven 维护近零（无 selector map）+非技术 ops 用 plain language 定义 workflow**；**选型：RPA 适合 stable controlled 环境；UI 会变/异常多/需要恢复→APA**；**UiPath ScreenPlay=自主 UI 交互+适应 UI 变化无需手动更新 selectors（self-healing）；AWS AgentCore Browser Tool=fully managed cloud browser，每 session 专用隔离环境（own CPU/memory/filesystem），session 完成环境终止+state sanitized，Playwright over WebSocket CDP**。判据：**页面常变选 APA（agent re-plan），环境稳定可控选 RPA（确定性更省钱）**。提升层：工具。
