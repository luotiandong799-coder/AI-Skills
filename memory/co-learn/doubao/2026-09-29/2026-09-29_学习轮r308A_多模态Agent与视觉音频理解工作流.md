## 独点（12）

1. **VLM-OCR 文档理解范式**（来源：madebyagents 2026-07-08 + codersera 2026-04-11 + promptquorum 2026-06-19）——**2026 的 OCR ≠ 像素转文字块，= 文档理解：布局/表格/公式/阅读顺序/结构化输出（Markdown/JSON 单 pass）**；**领先新 OCR 模型就是 VLM：Qwen3-VL-4B 支持 32 语言（含阿拉伯/希伯来/印地/泰），保留布局结构输出 Markdown/HTML/JSON/LaTeX，抗低光/模糊/倾斜退化输入**；**本地 VLM 选型：MiniCPM-V 4.5（6GB 显存级最高 OCR 精度）、Llama 3.2 Vision 11B（混合文档类型最佳）、Llama 4 Scout 17B（截图/图表/手写接近 GPT-4o）**；**失效场景清单：手写草书、低 DPI 扫描（<150）、重度压缩 JPEG、重叠文本**；**OCR 提示工程示例："Extract all text from this document exactly as written, preserving line breaks."**。判据：**选"OCR 模型"先看它是否输出结构化格式——能出 Markdown/JSON 的才是 2026 的文档理解，纯文字块输出是上一代**。提升层：工具。
2. **AgenticOCR 定向解析**（来源：arXiv 2602.24134 AgenticOCR 2026-08-24 + aiagents.codeguides.io 2026-07-17）——**AgenticOCR：解析只你需要的——image_zoom_and_ocr_tool 裁剪指定区域+可选旋转+按元素类型（文本/表格/公式/图）执行 OCR 或布局分析**；**用户问特定文本/数字/名称/日期/表格/方程式/事实细节时永远先用 zoom 工具而非全页 OCR**；**全页 OCR 是浪费：大量无关区域消耗 token 还稀释注意力；定向放大+局部解析精度更高**。判据：**"放大镜优先于全景扫描"——局部细节提取先 zoom 再解析，别把整页塞进去**。提升层：工作流。
3. **文档处理 agent 流水线**（来源：aiagents.codeguides.io 2026-07-17 + alibabacloud qwen-vl-ocr）——**六步：①normalize inputs（PDF→page images、HEIC→JPEG、deskew/resize 到模型限制内，构建时验证）②classify document type first（处理多种表单：发票 vs 收据 vs ID）③vision extract prompt 只请求该类型 schema 的 JSON ④validate with code；失败→retry 带 validator errors+同一张图（bounded retries）⑤可选：用 calculator/规则交叉核对 totals/dates/IDs ⑥模糊/被遮挡字符替换策略（如 Qwen-OCR 提示用占位替换模糊单字符再验证）**。判据：**文档提取的成功标准是"通过代码校验的 schema 化输出"，不是"看起来对的文字"**。提升层：可复用 Skill。
4. **多模态 RAG 三类实现路径**（来源：AWS Bedrock 2026-01-20 + Microsoft Learn + institutepm 2026-06-19 + martinuke0 2026-05-31 + arxiv 2607.24799）——**核心挑战：文本和图像 embedding 天然不在同一向量空间，两条解决路：统一多模态 embedding 模型（Bedrock：单模型原生支持 text/images/audio/video，甚至可用图像做查询）或检索时融合策略**；**路径 A：图像 verbalize（LLM 生成图片自然语言描述→走文本搜索/embedding）——最省，丢失视觉细节**；**路径 B：直接传文本+图片给多模态 embedding 模型**；**路径 C：fusion layer——把归一化文本/图像向量拼接进单 768 维空间→单一 ANN 查询返回混合模态**；**生产级：HNSW 语义+GIN 词汇双检索→RRF 融合→Cross-Encoder 精排；VLM（Qwen2-VL-2B）预生成表格/图表文本摘要入索引**。判据：**多模态 RAG 先决定"检索什么"——按文本摘要检索（verbalize）够用就别上统一向量空间**。提升层：工作流。
5. **长视频渐进式理解**（来源：arXiv ProVCA/LENS/VideoZoomer/VideoARM/SLICE/SpecTemp/AdaFocus 2026 系列）——**不做 one-pass 全量编码——全是 top-down 渐进证据获取：ProVCA 三步（Segment Localization 稀疏全局帧粗定位→Snippet Selection caption 级相似度分语义片段+MLLM 评估过滤→精细化）**；**SLICE：按语义能量质量分帧（信息密度分区）不按均匀时间间隔——复杂事件段集中帧、静态背景激进省略，对数平滑 σ=ln(N) 抑制视觉噪声**；**temporal zoom 工具（VideoZoomer/VideoThinker/LENS）：按查询自适应在空间 zoom-in（帧内相关区域）与时间 zoom-out（多帧聚合）间分配有限帧预算（30-150 帧合成紧凑表示）**；**SpecTemp：轻量 draft MLLM 快速提案候选帧+强 target MLLM 验证迭代收敛**。判据：**长视频理解=查询驱动的帧预算分配，谁把 30-150 帧花在最相关时间区/区域谁准**。提升层：工作流。
6. **语音 agent 四阶段管线**（来源：n8nresources 2026-07-20 + dev.to 语音栈基准 2026-05-18 + whisperpipe + f22labs 2026-08-03）——**四阶段：Receive（Twilio 录音→webhook）→Transcribe（Whisper→文本）→Reason（LLM 按系统提示生成回复）→Respond（TTS 返回音频播放）——每段可替换组件**；**Whisper Large V3 仍是开源 STT 参考点：WER 7.4% 平均/1.55B 参数/99+ 语言/普通推理硬件自托管；faster-whisper/WhisperX 15-50ms/chunk**；**whisperpipe：双缓冲架构+混合 VAD 最小化无用推理，纯本地无 API**；**语音管线工程：静音/背景噪声移除先于转写**；**流式选型：需实时流就用 Realtime 类模型（streaming STT/翻译/推理），批量转录 Whisper 足够**。判据：**语音 agent 先定"实时还是批量"——批量 Whisper 自托管就够，实时才上流式模型**。提升层：工作流。
7. **GUI grounding 与截图优先控制**（来源：dev.to visual grounding 系列 2026-09-22 + Microsoft Phi-Ground + techrounder 2026-03-30 + arxiv Tactile）——**GUI grounding 是专用于任务：不决定"下一步做什么"，只把自然语言引用（"the submit button"）精确映射到屏幕坐标/包围盒——UGround/Aria-UI/GUI-Owl/Phi-Ground；grounding 模型成功率目前仍有限**；**screenshot-first 是计算机使用 agent 主流形态：观察渲染屏→视觉推理/OCR 定位→预测低级鼠标键盘动作→观察下一屏；优点=对无 API/无 DOM 结构软件通用；代价=①隐藏软件可执行结构（看不到 DOM/accessibility tree）②每截图=一次多模态推理调用，规模化成本叠加快**；**三感知路径选型：Visual grounding（纯截图）/DOM semantics（有 DOM 时，更可靠）/Computer use（混合）**。判据：**能拿 DOM/accessibility tree 就别纯截图——截图是最后手段不是默认**。提升层：可复用 Skill。
8. **视觉 token 预算管理**（来源：theneuralbase budget-management 2026-04-23 + ai-tldr 2026-06-12 + token0 + dev.to Gemini 经济学 2026-08-06）——**视觉 token 是独立预算维度：图片成本由（1）分辨率（2）detail setting（3）格式（4）感兴趣区域决定——加倍分辨率可能 4-8x 成本，不能当文本 token 算**；**tile-optimized resize（token0）：OpenAI 把图切 512x512 块，1280x720→4 tiles（765 tokens）；调整到最优 tile 边界→2 tiles（425 tokens）省 44% 零质量损失；关键词分类器提前分流省 3-13x/图**；**分辨率物理阈值：patch 覆盖 28px 而需读字母 8px 高→细节被抹掉；小文本在低分辨率下消失——省 token 有极限**；**E-AdaPrune：奇异值谱能量决定 token 预算，信息密集场景多 token 冗余激进压缩；Gemini 定制 768px 管线**。判据：**图像按 tile 边界与目标字符大小缩放，不是按"看起来清晰"缩放——token 与可读性在此交汇**。提升层：可复用 Skill。
9. **图像预处理管线顺序**（来源：theneuralbase pre-processing 2026-04-21 + imagetotable 6-step + pdfexcel）——**OCR 模型在预处理得当的图上比原始扫描好约 40%**；**顺序重要：grayscale→denoise→binarization→deskew（denoise 必须在前防丢细节）**；**倾斜代价量化：5° 字符级准确率掉 15-20%，2° 已显著降精度**；**几何校正先做（deskew/perspective 在原灰度图上，避免多次变换插值伪影）→分辨率优化（按目标字符大小缩放）→噪声抑制（中值滤波 salt-pepper/Gaussian 复杂退化）→binarization**；**参数按输入类型分：照片→bilateral+adaptive threshold；扫描件→Gaussian+Otsu；按 DPI 动态 resize 不按固定宽；Hough 直线变换检测倾斜**；**置信度门：OCR 输出置信度 <0.75 用替代参数重试；记录用哪组参数供审计**。判据：**预处理=参数化的可审计流程（类型→参数组→置信度门→重试），不是"调一下试试"**。提升层：可复用 Skill。
10. **视觉工具调用编排**（来源：Orion arXiv 2511.14210 + docs.vlm.run + Google Agentic Vision 2026-01-27 + MM-ToolSandBox 2026-08-24）——**Orion 四步：Perceive（识别输入）→Plan（controller 推理需要哪些视觉能力+怎么编排）→Execute（工具按依赖约束顺序或并行执行）→Reflect（中间与最终输出对期望 schema 评估确保正确性一致性）**；**非单片 VLM：编排专门 CV 工具（OCR/检测/分割/keypoint/几何分析）执行多步视觉工作流；生产瓶颈不是感知是可靠编排（月百万级工具调用教训）**；**Agentic Vision（Gemini 3 Flash）：视觉推理+代码执行，模型制定 zoom/inspect/manipulate 计划用代码落地视觉证据——视觉理解从静态一瞥变主动调查**；**评估（MM-ToolSandBox）：500+ 工具 16 域有状态环境，多图多轮，agent 须把渐进到达的视觉输入落地成可执行工具调用（含目标修订/错误纠正/状态突变）**。判据：**视觉 agent 的复杂度在编排不在模型——工具链可靠调度比"看得准"更稀缺**。提升层：可复用 Skill。
11. **多模态评估失败模式**（来源：arXiv SynthDocBench 2607.10400 + KIE-HVQA + 评测三愿望 2601.02316 + IEEE 3982）——**SynthDocBench 揭示三个现有基准暴露不了的失败模式：①文档长度锐退化 ②位置敏感（六模型中五个中间三分之一最难，Early→Late 趋势最陡降 8.3pp）③长文档中图表理解崩溃——当前模型可能过拟合基准伪影**；**KIE-HVQA：首个专评 OCR 幻觉的基准（身份证/发票/处方+模拟真实退化+像素级 OCR 可靠性标注）——退化输入下区分可靠视觉信息并作答**；**评测三愿望：faithfulness（模态与应用忠实）/discriminability（区分模型质量）/efficiency（计算效率）——多选格式奖励猜测+饱和+不代表下游**；**IEEE 3982 VLM 评估标准（制定中）；选模型要在匹配目标文档的数据上评（METATR 29 语言）**。判据：**VLM 选型看目标域退化输入上的表现，不看公开基准总分**。提升层：可复用 Skill。
12. **多模态 agent 循环契约**（来源：max-gherman multimodal agents + ToolScope + 阿里云 2026-09-28 + Nemotron 3 Nano Omni）——**标准 agent loop（reason-act-observe）假设文本观察；多模态扩展：观察可以是图像/音频/视频帧/组合——模型须解释非文本数据、提取相关信息、折进推理；工具返回的"观察"从 JSON 变成媒体对象，循环契约要变**；**长程 VQA 的视觉上下文退化：ToolScope 用专用 Perceive 工具（局部多模态感知）缓解，Global Navigator 提供高层战略+Agentic Executor 迭代执行**；**自修正多模态 agent：模块化 perception+planning+tool use，修正有界额外计算；ABot-Claw critic 闭环（在线进度评估/局部精炼/动态重规划）**；**阿里云李飞飞三词：Model 决定智能上限/Context 决定读懂业务/Harness 决定调起工具做完事并一直跑**。判据：**多模态 agent 的观察层契约要先定——媒体观察进推理前必须提取成结构化信息，别把原始图像塞给规划器**。提升层：工作流。
