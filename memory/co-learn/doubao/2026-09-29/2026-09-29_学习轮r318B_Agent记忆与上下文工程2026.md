1. **记忆框架四族定位与选型**（来源：mem0 blog×3 + aiworkflowlab 2026-05 + awesomeagents 2026-05 + dev plur9 2026-07 + aiwiki letta 2026-06 + evermind 2026-04 + cognee 2026-05 + automem 2026-06）——**四族框架：Mem0=universal memory API（add/update/delete/retrieve 可插任意 agent，vector-first，~48K stars，不 self-host）；Letta（MemGPT）=stateful agent OS（显式 memory-block API，agent 自己可编辑记忆块，tiers 类 OS 内存管理，self-host，~21K stars）；Zep=时间知识图谱（Graphiti temporal KG 跟踪事实变化，~24K stars）；LangMem=LangChain-native SDK（BaseStore 集成，semantic+episodic+procedural 三类）**；**Benchmark 参照（LongMemEval）：Mem0 94.4%（token-efficient 算法，准确率在 practical token budget 下）/Zep 63.8-71.2%（GPT-4o judge）/Letta 未发布**；**判重维=定位：轻量可插拔→Mem0/Supermemory；长跑自治 agent→Letta/MemGPT；时间推理+合规→Zep/Graphiti；LangChain/LangGraph 团队→LangMem；graph-first+MCP→Cognee**。判据：**按"插入式 API vs agent OS vs 时间图 vs 框架原生"四族定位再选型；benchmark 分数结合 token budget 看**。提升层：工具。
2. **三类记忆映射与 procedural=指令非数据**（来源：langchain docs 2026-09 + langchain blog 2026-06 + github langmem conceptual 2026-09 + mastra 2026-06 + progressiverobot 2026-05 + zylos×2 + aiwiki 2026-06 + inductivee 2026-08）——**semantic=事实与知识（user preferences/knowledge triplets，Profile/Collection 存储）；episodic=past experiences（few-shot examples/过去对话摘要，Collection）；procedural=系统行为（core personality/response patterns/prompt rules）**；**procedural memory in LLMs best represented as instructions not data：学到"always validate JSON with schema X before calling API Y"应注入 system-prompt directive，不从 vector store 检索**；**LangMem 独有=self-updating instruction layer——agents modify their own prompts based on experience（更新行为通过 prompt optimization 不只 retrieve facts）；consolidate+deduplicate over time；episodic 每 example 从原始交互蒸馏**；**consolidation=episodic→semantic 正式过渡（保留抽象教训丢弃具体记录："user corrected date format on Jan 5"→"user prefers DD/MM/YYYY"）**。判据：**procedural 走指令注入不走向量检索；consolidation 是主动过渡不是攒着**。提升层：工作流。
3. **Bi-temporal 记忆模型与时间图**（来源：getzep graphiti×2 2026-09 + help zep×2 + getzep persistent memory 2026-05 + supermemory-alternative 2026-06 + zep vs graph rag 2026-09 + what is agent memory + product agent memory）——**Graphiti 把对话/业务数据/文档变 temporal Context Graphs（entities/relationships/facts）；bi-temporal=每事实两条时间线：valid time（世界真实时间）+ingestion/provenance time（何时学到）**；**superseded facts 被 invalidate（close）而非 delete——agent 用当前真理推理而历史保持可查（what's true now/what was true then/why 三类问题从数据模型直接答）**；**每 edge 带四时间戳：valid-from/valid-to/learned-at/learned-invalid-at**；**Zep=每用户一个 Context Graph，融合 chat/CRM/support/billing/documents/events 所有触点；extraction 把 episodes 变成 entities+facts/edges，每 fact 带 validity window+provenance 回源 episode；observations=跨 episodes 模式**；**Zep vs GraphRAG：GraphRAG=static document summarization，Zep=随时间变化数据的 context（语义+关键词+图三重搜索）**。判据：**时间敏感场景用 invalidate-not-delete+双时间线，可做 point-in-time 推理与审计**。提升层：工具。
4. **记忆基准三大体系与数字审计**（来源：mem0 benchmarks 2026-09 + hydradb 2026-09 + arxiv MOSAIC 2607 + AgentMemBench 2608 + TSM 2601 + benchd 2026-05 + llms3 BEAM 2026-09 + mempalace ch22 2026-05 + agentos 2026-04）——**LongMemEval=500 问 3 维度（recall/temporal reasoning/knowledge updates），最广为引用，数据公开（HuggingFace 可下载）→分数可直接比较（同一 ruler）**；**LoCoMo=long-term conversational recall 不比较记忆策略；BEAM=1M/10M token 规模鲁棒性（100K：RAG 32.3%/Honcho 63.0%/Hindsight 73.4%；10M：24.9/40.6/64.1——架构分化决定退化优雅度）**；**关键数字：GPT-4 Turbo 128K 全上下文 LoCoMo 仅 51.6 F1（人类 87.9，36.3 差距）——访问全部对话也不消除长记忆/推理问题，检索层是必要组件；历史增长带来 30-60% 准确率下降（LongMemEval）**；**审计：LoCoMo 2026-04 审计发现 6.4% ground-truth 错误率+LLM judge 接受 62.81% 故意错误答案→vendor 引用分数须审来源与判题方式**。判据：**评测分数先查 ruler 与审计状态再引用；全上下文不等于好记忆，检索层必须有**。提升层：工作流（评测方法）。
5. **官方记忆演进：ChatGPT Dreaming 与 Claude Memory**（来源：openai help×3 + dreaming blog 2026-06 + claude memory tool 2026-09×2 + support claude 2026-09 + openai personalizing）——**ChatGPT Dreaming 更迭=2024 saved memories→2025 +Dreaming V0→2026 Dreaming V3（解决 staleness/correctness/scalability 三挑战：百万用户+多年时间线）；引用聊天记录（Plus&Pro 2026-01）=提问时从过往聊天找具体细节，用到的过往聊天显示为来源可开原始上下文**；**Claude Memory tool=实现 memory tool 文件操作（create/read/update/delete 目录文件跨会话持久）→just-in-time context retrieval：不预加载全部相关信息，agent 记录所学进记忆文件并在需要时读取**；**Claude 对话记忆（个人版）=saved as individual topics as you chat（不是会话结束后总结）；提及 deadline moved→下个对话已知；"remember this" 直接保存；每 project 独立 memory space+dedicated project summary**。判据：**对话中即存即取（topics 粒度）优于会话末总结；just-in-time 注入优于全量预加载**。提升层：工作流。
6. **记忆注入演进：被动检索→主动干预**（来源：arxiv 2607.08716 + ProMem 2601 + InfMem 2602 + U-Mem 2602 + MRAgent 2606 + interactive memory learning 2609）——**Proactive Memory Agent（Memory as intervention）：memory agent 与未修改的 action agent 并行，固定间隔从近期轨迹更新结构化 memory bank，决定是否注入 concise reminder（被遗忘需求/稳定环境事实/失败尝试/诊断）到下次调用或保持沉默——不像被动系统按需检索，它决定记忆是否进控制环**；**ProMem=static summarization→iterative cognitive process：recurrent feedback loop 用 self-questioning 主动探测对话历史，恢复遗漏+纠正错误，提取质量与 token 成本更优权衡**；**InfMem=System-2 memory control：PreThink 触发检索，粗粒度 streaming chunks 阅读流+细粒度 globally indexed units，SEARCH 动作检索 top-k 总结成 concision context（可搜文档过去/未来部分）**；**U-Mem=cost-aware knowledge-extraction cascade（cheap self/teacher signals→tool-verified research→expert feedback 仅需要时）+semantic-aware Thompson sampling 平衡 exploration/exploitation 缓解 cold-start**。判据：**高价值长程任务用主动注入（memory agent 决定何时提醒），常规任务被动检索够用**。提升层：工作流。
7. **分层记忆生产共识与 MemGPT 虚拟内存**（来源：arxiv memory survey 2603 + survey 2602 + HiGMem + zylos×2 + papernotes TiMem + clawrxiv HMAT + csdn 2026-07 + memorypapers LightMem + H-MEM）——**三层生产共识：in-context working memory（当前 session 原始消息缓冲/tool calls/active state，ephemeral）→session-scoped compressed memory（摘要/提取事实 on-demand 可读）→long-term persistent store（跨 session 知识/偏好/学习工作流，vector+graph）**；**MemGPT 虚拟内存=main context（RAM：system prompt+recent messages+relevant records）+recall storage（disk：分页进出）——OS 分页思想给 LLM context window**；**H-MEM=四层按语义抽象度（section/subsection/subsubsection/content），每层向量嵌入下级位置索引编码；TiMem=五层 Temporal Memory Tree（base→session/day/week/profile），complexity-aware retrieval 平衡细粒度事实与高层 persona 且减少 recalled context（LoCoMo/LongMemEval-S 提升）；HiGMem=两层 turn layer（LLM 生成 metadata）+bidirectional links 双向互操作+provenance traceability**；**工具记忆专层=优化工具调用故障减少无效循环与 LLM 消耗**。判据：**分层=冷热分离+按需加载+经验沉淀；越上层越抽象越省 token，检索按复杂度路由**。提升层：工作流。
8. **受控遗忘与记忆隐私合规**（来源：arxiv MaRS 2512 + zylos×2 2026-04/06 + selina×2 2026-07 + Secure Forgetting 2604 + groundy 2026-06 + aipolicydesk 2026-07 + velsof 2026-05 + dev plur9 2026-07）——**六遗忘策略（MaRS）：FIFO/LRU/Priority Decay/Reflection-Summary/Random-Drop/Hybrid——复杂度分析+sensitivity-aware retention+可选差分隐私；FiFA benchmark 测 narrative coherence/goal completion/social recall/privacy preservation/cost efficiency**；**retention 分级模型：User preference=long-lived user-visible editable；Project decision=project active 期保留关闭后归档；Operational state=short TTL 任务完成过期；Customer context=contract-bound 严格租户隔离**；**Tag at write not at delete：每 memory entry 写时打 subject_id/data_class（PII/PCI/PHI/internal）/retention_policy/source_event_id**；**ChatGPT Dreaming 隐私：96% 存储记忆由系统单方创建（模型是持久个人数据首要作者）；删除非单一动作——memory 在独立于 chat logs 的 synthesis layer，删对话不删学到的，完全清除需清多个独立 store（EU/UK 不可用=GDPR 限制）**；**Secure Forgetting 三场景=state unlearning/trajectory unlearning/environment unlearning+自然语言 unlearning 请求→conversion model→unlearning prompts；ICML 2026：模型层 deletion=suppress 非 erase，最小微调可恢复原行为**。判据：**记忆写时打标分级；受控遗忘按策略过期；模型层删除不可信，记录层删除才可验证**。提升层：工作流。
9. **记忆 Token 经济学**（来源：mem0 playbook 2026-05 + arxiv distillation 2603 + zylos economics 2026-05 + kunalganglani 2026-07 + xyzbytes 2026-06 + tentoro 2026-06 + syncsoft 2026-06 + beam 2026-05 + niteagent 2026-05）——**naive injection vs retrieval（实测）：24 entries 全注入=594 tokens/call；retrieval-based=166 tokens/call（72% 节省）同答案质量；生产 51-72% 节省**；**记忆预算硬数字：1,000 conversation exchanges≈39,000 tokens（distilled）vs ≈407,000（verbatim）——11× 缩减保留检索；best pure distilled 保留 96% verbatim MRR（vector search 撑住，BM25 不行）；LoCoMo 记忆层检索≈6,956 tokens/call vs 全上下文≈26,000（3.7× 减）**；**context window 经济三策略=tiered memory（hot state cheap+cold state out-of-band）+prompt caching（稳定系统内容 90% 折扣）+selective compaction（保留推理连续性不带全历史）**；**lost-in-the-middle=长上下文 U 型注意力（开头结尾强中间弱）——大 context 不是万能**；**Mem0 两个最高杠杆=intelligent summarization（20 messages→200-token summary hot→warm）+memory decay（低重要性自动过期）**。判据：**默认检索式注入不全量注入；summarization+decay 是省 token 最高杠杆；大窗口也逃不掉中间遗忘**。提升层：工具。
10. **检索质量结构化索引**（来源：arxiv STITCH 2601 + Chronos 2603 + MemMachine 2604 + MRAgent 2606 + memsearch-o1）——**STITCH=每 trajectory step 用 structured retrieval cue（contextual intent：当前潜在目标/动作类型/显著实体类型）索引，检索按当前步 intent 匹配——disambiguate repeated mentions+reduce interference**；**Chronos=raw dialogue 分解 subject-verb-object 事件元组+resolved datetime ranges+entity aliases→structured event calendar+turn calendar；查询时 dynamic prompting 生成检索指导（retrieve what/filter time ranges/multi-hop iterative tool-calling loop）**；**MemMachine=ground-truth-preserving：STM 可配置 context window 最近 episodes；LTM=persistent searchable 全部退出 STM 的 episodes，四阶段索引（sentence extraction→…→store）**；**MRAgent=memory is reconstructed not retrieved：Cue-Tag-Content 图（associative tags 作语义桥连接细粒度 cue 与内容）+active reconstruction 机制随推理中发现的中间证据动态调整记忆访问——超越静态 retrieve-then-reason**。判据：**检索索引按意图/事件结构建（不是纯向量裸存），检索可随推理动态重构**。提升层：工作流。
