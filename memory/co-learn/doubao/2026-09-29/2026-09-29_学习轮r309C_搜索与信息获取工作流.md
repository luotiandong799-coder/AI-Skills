## 独点（12）

1. **Agentic Deep Research 范式三件套**（来源：arXiv 2506.18959 + max-gherman + aiworkflowlab + EigentSearch-Q+）——**范式转变：one-shot prompt+retrieve → 主动信息寻求 agent（计划系列步骤/迭代检索与推理精化查询理解）**；**三组件：查询规划器（高层问题分解为子查询集=初始 facet）→来源路由（每子查询定向合适源：web 搜索近期信息/向量库内部文档/结构化数据库定量数据/专用 API 领域知识）→评估器（评估每结果相关性/质量/充分性——决定信息够不够或继续搜）**；**规划器 prompt 要点：分解为 3-7 个自包含子问题，每个可独立回答不需读其他；优先非重叠覆盖而非穷尽覆盖；不回答问题只规划**；**Q+ 显式结构化推理工具：中间子问题/证据质量检查/提取步骤显式化——防欠分解、依赖高层面板或过时页、被信息密集页分心**。判据：**搜索的产出是查询序列+证据评估，不是单次查询——没规划器的"搜索"只是检索不是研究**。提升层：工作流。
2. **搜索轨迹类型学**（来源：arXiv 2601.17617 14M+ 真实请求）——**四种轨迹动作：Specialization 加约束缩小（21.76%）/Generalization 去约束扩大（9.02%）/Exploration 换方面或子主题（37.07%）/Repetition 语义等价或近重复查询（32.15%）**；**意图统计：Declarative 88.64%（事实寻求，短查询最高重复率——agent 落入近重复查询循环，试图验证特定事实或目标信息未找到时停滞）**。判据：**重复查询占 1/3 是搜索循环的默认行为——查询去重与防重述是 agent 搜索的首要优化点**。提升层：可复用 Skill。
3. **查询意图→模式路由**（来源：search-layer + DoorDash case study）——**意图分类映射模式与权重：Factual（"What is X"→answer 模式，权威 0.5 偏置）/Status（"Latest developments/Current status"→deep 模式，新鲜度 0.5）/Comparison（"X vs Y"→deep 模式，关键词 0.4+权威 0.4）/Tutorial（"How to"→answer 模式，权威 0.5）**；**多意图发射与消歧：模型输出有序意图集非单标签，确定性规则引擎按业务策略+个性化信号选最终意图或呈现消歧提示——核心推理模型不变，grounding 靠把检索实体+web snippets 喂回 LLM 作上下文（可插拔任意市场）**。判据：**意图决定模式/新鲜度/权重偏置——按类型选检索策略而非一刀切**。提升层：可复用 Skill。
4. **检索失败改述与去重模块**（来源：vadimall + arXiv 2603.12396 + AILS-NTUA SemEval-2026）——**失败判定：相似度全 <0.5=检索全漏（重试）；chunks 切线相关但不达具体问题=标 insufficient（改述）**；**改述规则：换角度不换说法（重述同一查询无效）；避免重复相似表述；broader 策略（问题太具体时拓宽）或 narrower 策略**；**检索去重模块：过滤前几步已检索文档——防模型因觉初始信息不足重复生成查询，强制纳入更宽文档集（EM +5.6% 且轮数降）**；**实证：查询多样性优于异构检索器集成；answerability 校准是端到端性能首要瓶颈而非检索覆盖**。判据：**"没搜到"要分"全漏"与"不够"两种修法；重复检索同一批文档=零信息增益还烧预算**。提升层：可复用 Skill。
5. **Deep research 幻觉评估四指标**（来源：DREAM arXiv 2602.18940 + ResearcherBench + DeepHalluBench + arXiv 2604.03173）——**Claim Attribution（CA：引用声明数/可验证声明总数——1.0=每可验证声明链源 URL，报告可审计性最大化）**；**Citation Faithfulness（CF：引用证据真实性——引用的声明真被源支持的比例）**；**ResearcherBench 双分：Faithfulness Sf（引用支持对应声明准确率）+Groundedness Sg（所有事实声明有显式引用支持比例）**；**DeepHalluBench：首个整研究轨迹评估 DRA 幻觉——聚合现有基准查询+对抗"无答案"查询（原子扰动）隔离最难查询**；**引用量不代表可信度：Claude 每问生成 18.4 URLs（仅 14.6 live）**。判据：**评估到声明级引用对——"有引用"与"引用真支持声明"是两个指标分开测**。提升层：工作流。
6. **引用验证五级匹配与移除纪律**（来源：NVIDIA AIQ Blueprint）——**报告 URL 对源注册表五级匹配：exact match（原始/归一化 URL）→truncation（前缀唯一注册 URL）→prefix（归一化前缀）→child-path（子路径需 2+ 段）→query-subset（同 host+path，查询参数子集）**；**无法匹配任何注册源的引用移除，每次移除记录在案**。判据：**引用匹配是确定性规则链不是模型判断——查不到源的引用宁可删不可留**。提升层：可复用 Skill。
7. **Evidence-grounded 工作流四门**（来源：dailyaiworld + SourceMinds CheckThat）——**Extract（声明提取器把草稿分解为离散可检查声明）→Resolve（引用解析器映射每声明到文档库候选源）→Verify（验证器确认源真支持声明）→Gate（证据门对照账本比较草稿声明——未验证声明阻塞/标记/路由回重新研究）；只有过每级的声明达输出**；**引用审计修复：缺引用句→embedding 相似短列→NLI 验证蕴含→置信阈值上附引用；修剪冗余引用（多源引用句去掉边际支持小的）；每次修复后重应用无效引用过滤**。判据：**生成与验证分离——草稿可以自由写，输出被证据门卡住**。提升层：可复用 Skill。
8. **来源层级与双源最小规则**（来源：BrowserAct + nuwtonic + veracity + cross-verified-research + web-research）——**来源层级：官方一手来源优先→直接报道→独立分析→社区证据；事实/来源声明/分析师推断/观点必须区分**；**双源最小规则：声明仅在至少两个高可靠独立源验证后标为既定事实；源冲突显式标记分歧+对冲置信度**；**冲突解决：T1>T2>T3 层级；"两个独立 T1 源"规则判 TRUE；检查源独立性（是否派生自同一主源）；真正不可调和冲突→DISPUTED 不强行判；未验证声明显式标 Unverified/Contested 不用对冲软化**；**每任务 ≥5 次不同搜索查询、最终输出 ≥5 已验证源；每关键声明 2+ 独立源**。判据：**单源=传闻，双独立源=事实，冲突=披露不裁决**。提升层：可复用 Skill。
9. **可信搜索停止条件**（来源：CSDN 联网研究可信 + social-media-skills source-check）——**每轮结束评估证据缺口：哪些子问题已有一手来源/只有转载/存在冲突/完全无公开资料——只有针对缺口继续搜，不在相似结果里无止境浏览**；**停止条件写进任务预算：每核心子问题至少一个合格一手来源；重要争议至少两个相互独立来源；达到时间/请求次数/费用上限后未解决项在答案中披露——搜索越多不一定越可信**；**source-check 硬测试每引用：存在（独立搜索）→诚实链接（DOI 解析到 THIS 论文）→说了它（文中找到声明）→当前→记录；任何一步失败→删除**。判据：**搜索的终点是证据缺口清单清空或预算耗尽，不是"结果页翻完"**。提升层：工作流。
10. **信息获取九阶段管线与验证边界**（来源：scrapeless 九阶段 + scrapeless LLM 训练验证 + webscraper + mrscraper + IT-S + scraper.page + webscraper.io fresh）——**九阶段：Source registry→scheduler/agent request→URL frontier→acquisition→content validation→normalization+dedup→structured storage→retrieval index→agent tool——每边界窄责任（未知权限/所有者=失败边界；过度或重复工作=失败边界）**；**验证在存储与模型摄取之前：拒绝或隔离记录当——最终 URL 超批准范围/响应非预期文本表示/提取空或异常薄或大部导航/语言异于声明语言/缺源 URL 或捕获时间/内容哈希已存在无批准版本变更/页面含需审查限制状态**；**归一化 6 项：大小写/日期时间/度量单位/地址/分类值对齐/缩写（"St." vs "Street"）**；**去重：稳定标识符（SKU/产品 ID/canonical URL）优先，无则复合键；模糊匹配=相似非身份证明需置信阈值；同一项可经分页/类别/搜索/过滤/备用 URL/跟踪参数出现——用 >1 key 检测**；**fresh RAG：依赖源变更正确达检索而非爬取频率——version-aware chain（discover/collect/preserve/normalise/validate/publish）**。判据：**垃圾进库的代价在后端十倍——验证与归一化在存储前做，不是检索时做**。提升层：工作流。
11. **清洗与提取纪律**（来源：context.dev + cngvng + easyparser + AgentIR benchmark）——**原始 HTML 直喂 LLM=上下文膨胀/幻觉/token 成本；现代管线转结构化 Markdown 80-90% token 降（16,180 raw→3,000+）**；**AI 提取器理解语义上下文非 div 类名——CEO 名字藏 alt 标签或 ul 也能提取；提取=结构化输出定义先行（JSON Schema 保证返回匹配规格）**；**AgentIR 基准：检索质量测 agent 推理轨迹产生的查询而非干净人类查询——query gap：嵌入模型把整轨迹编码单向量稀释检索意图（"找限速文档"意图被无关上下文淹没）**。判据：**喂给模型的是结构化证据不是原始网页；agent 发的查询≠人类查询，检索质量要按轨迹评测**。提升层：工作流。
12. **浏览器 agent 与反爬合规**（来源：zylos Chrome 132 + fastcrw + openlegion + arXiv 2606.30119 + aifuturefront + OpenClaw + browserless）——**Chrome 132+ "new headless"（全 Chrome 非轻量 shell）成默认，旧 headless 独立为 chrome-headless-shell；默认 headless 被多数生产网站屏蔽（Cloudflare 查几十个指纹信号：navigator.webdriver 标志/缺失插件/canvas 指纹异常/时序模式——stock Playwright 立刻收 challenge 页）**；**简单防御：真 Chrome 实例+显示（X-server/常规 Chrome）；移除 webdriver 标志+真实 UA+标准视口+真实 locale；蜜罐实测多层指纹可识别 LLM bot（Cloudflare 拦 BrowserUse 40 次/HTTP 爬虫 20 次）**；**浏览器工具设计：小而意见化的动作集（open URL/click/type/screenshot/拉结构化文本）映射人类行为——agent 是浏览器操作者不是 DOM 黑客**；**合规红线：robots.txt 允许路径、控制频率、反爬绕过只用于自己有权访问的公开页**。判据：**headless 检测是技术兼容问题但反爬绕过不是访问控制突破——能拿到内容的前提是合规**。提升层：可复用 Skill。
