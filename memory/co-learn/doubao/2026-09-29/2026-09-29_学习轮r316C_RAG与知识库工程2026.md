1. **混合检索架构：RRF+cross-encoder 流水线**（来源：infoq 2026-06 + tensoria 2026-05 + sukruyusufkaya 2026-09 + llmversus 2026-04 + irjet + ai-manual 2026-05 + aipromptshub rag 2026-06 + ragaboutit 2026-05 + markaicode 2026-05 + precisionai 2026-04，增量合 r315B 双路召回点）——**流水线：BM25 与 dense 并行→RRF（k=60）融合→cross-encoder rerank→top-K 给 LLM；具体参数：BM25 top-50+dense top-50→RRF ~100 候选→cross-encoder 减到 top-10（top-N 20-30→K 5-10）**；**hybrid 超纯 vector 10-25%（2026 真实检索任务）；dense 抓语义（laptop↔computer）但 embedding 空间保不住稀有 token 身份——'CVE-2025-47177'/'invoice #INV-20260512' 纯 dense 差，hybrid 一致赢**；**pre-fusion reranking=rerank 当 fusion gate 而非事后（各检索流 top-N 先验证事实对齐再融合，7 secrets 减幻觉 43%）**；rerank 默认 Cohere Rerank 3.5/BGE-Reranker-v2（预算 Cross-encoder MiniLM），metric NDCG@5。判据：**双检索流+RRF+rerank 三层缺一不可；术语/ID/代码查询必须带 BM25 流**。提升层：工作流。
2. **Chunking 策略基准**（来源：wayfinderai 9 策略 36,450 判断 2026 + arxiv 2603.06976 + aipromptshub chunking 2026-06 + superml 2026-06 + dataaihub 2026-07 + fast.io 2026-05 + pavlo 2026-06 + 博客园 2026-05 + 00011000 2026-07 + 超 tok 2026-05，增量合 r315B 按标题层级分块点）——**滑动窗口策略（512-token chunks/128-token step）赢每项 chunk 指标：LLM-judge 0.74 vs 次佳 0.61，全 15 分层单元横扫，P@10=0.53**；**semantic chunking（相邻句 cosine 显著下降处分块）recall@10 ~71% 技术文档/69% 支持 Q&A/62% 法律合同（最高单策略），代价=索引时全语料 embedding pass**；**Paragraph Group Chunking nDCG@5 ≈ 0.459/P@1 ≈ 24%/Hit@5 ≈ 59%（内容感知超 naive fixed-length）**；**chunk 大小映射：factoid 256/通用 512/长分析 768-1024；tech docs 400-1000/合同 300-800/学术 500-1200；避免 >2500 tokens（生成质量退化）；overlap=chunk 10-20%；128-256 精确但跨块答案被切；1024 起语义"平均化"混合主题块；2048+ 显著下降**；**sweet spot=300-500 tokens+50-100 overlap；用 tokenizer 计数，别用 len(text.split())**。判据：**先定查询类型再定 chunk 档位；overlap 10-20%；超 2500 必拆**。提升层：工作流。
3. **Agentic RAG：检索成为 loop 里的工具**（来源：syncsoft 2026-05 + dzone 2026-09 + microsoft learn 2026-07 + arxiv 2606.21553 + futureagi agentic 2026-05 + mastra 2026-06 + alok 2026-06 + dev saaro 2026-09，增量合 r315B Agentic 检索决策点）——**传统=embed→top-k→generate 一次；agentic=plan→retrieve→grade→re-plan→retrieve again→reason→answer（模型决策每分支；2026-03 论文形式化=finite-horizon partially observable Markov）**；**query decomposition：复杂问题先拆子查询（"比较 East US 与 West Europe SLA"=两独立查询+比较步骤），retrieval loop 前一次拆好提供结构化引导（local 7B 消融实证）**；**检索工具路由：dense（默认语义）/BM25（精确术语/ID/错误码/版本号）/hybrid（两者都重要）/web（语料过时近期事件）/SQL（结构化问题）——按 query 选工具，需 careful tool design**；**reflection=agent 审 draft answer 找 gap 触发补检索；short-term memory 跟踪已检索内容避免冗余调用，long-term memory 存历史 query 模式改进未来路由/分解**；**Self-RAG reflection tokens（要不要读/相关吗/证据支持吗/有用吗）显著减幻觉；层级分解=planner 拆多跳→spawn child retrieval agents→合并**。判据：**检索=agent 工具非前置步骤；先分解再检索；工具按查询类型路由**。提升层：工作流。
