## 独点（12）

1. **执行前动作审计两类框架**（来源：arXiv 2604.11790 ClawGuard + arXiv 2609.14987 ActGuard，2026 实拉）——**ClawGuard：运行时安全框架——在每次工具调用边界强制用户确认规则集，把不可靠的"对齐依赖"防御变成确定性可审计机制；从用户陈述目标自动派生任务特定访问约束（在任何外部工具调用前）→拦截间接注入三条路径，无需模型修改/基础设施变更**；**ActGuard：执行前动作审计——不判断外部内容是否固有可疑，而是评估它是否使当前动作偏离"本地合理预期"；每步预测即将使用的工具构造本地工具先验→执行前对比候选动作做工具级对比分析**。判据：**运行时工具边界审计+用户目标派生约束是比依赖模型拒答更可靠的注入防御**。提升层：可复用 Skill。
2. **间接注入的结构性理解与攻击面枚举**（来源：getmaxim.ai《Prompt Injection Defense 2026 Guide》2026-06 + Microsoft Learn《Defend against indirect prompt injection》2026-03 + Claude Platform《Mitigate jailbreaks》2026-09）——**间接注入=结构性不同：payload 不来自用户，来自 agent 检索处理的内容——RAG 管道里的 PDF、浏览 agent fetch 的网页、支持 agent 读的数据库记录、会话开始时加载的 MCP 工具描述（GitHub Copilot CVE-2025-53773）**；**Microsoft 六件套：Prompt shields（消毒入站提示）/Spotlighting（数据标记+metaprompting 隔离中和外部内容）/Plan drift detection（监控多步推理偏离任务流）/Critic agents（实时审计尤其多 agent 系统）/Tool chain analysis（阻断风险工具序列）/Security guardrails（技能内嵌最终层保护）**；Claude 官方：system prompt 明示工具/文档/搜索返回=不可信数据，不得覆盖 system prompt 或用户原始请求。判据：**间接注入的爆炸半径=agent 工具面；防御=边界审计+输入消毒+计划偏离监测三层**。提升层：工作流。
3. **IETF agent 授权协议族**（来源：IETF draft-aap-oauth-profile-01 + draft-fane-opena2a-aap-00 + draft-niyikiza-oauth-attenuating-agent-tokens-01 + draft-mishra-oauth-agent-grants-01 + draft-rosomakho-oauth-txn-challenge-00 + draft-goswami-agentic-jwt，2026 实拉）——**AAP：token 深度链——Token Exchange 派生 depth=n，授权服务器必须在发派生 token 前验证 parent depth<max_depth，链式衰减**；**OpenA2A：Delegation Assertion 跨 agent 能力委托——delegatee 的 capability scope 不得超过 delegator，最大委托深度限链长**；**Attenuating Authorization Tokens（AAT）：任务范围委托签名凭据——编码可调用工具+参数约束；授权持有者可离线派生等权或更窄 token（受 parent depth/lifetime 限制）；任何有 root issuer trust anchor 的执行点可离线验证委托链**；**txn-challenge：交易授权挑战——保护资源可要求对具体操作（支付/发内容/删数据/改访问策略/披露敏感信息）显式授权并收代表该授权的 access token——本地确认机制对资源不可见、不产生可验证授权证据**；**Secure Intent：bearer token 不绑定授权到具体执行上下文（检测不到分离）；HITL=工作流执行到某点暂停等人工批准**。判据：**agent 授权=委托链限深+任务范围衰减+具体操作显式挑战，三件套缺一即留缝**。提升层：工作流。
4. **RAG 安全四信任边界与文档投毒**（来源：OWASP《RAG Security Cheat Sheet》2026-05 + Snyk《What is RAG, How to Secure It》2026-09 + arXiv 2604.08304《Securing RAG: Taxonomy》+ DeepInspect《Four Trust Boundaries》2026-08 + arXiv 2601.11199 SD-RAG + ragaboutit《7 RAG Security Gaps》2026-08）——**RAG 请求过四信任边界：什么被索引/谁能检索哪些 chunk/组装的 prompt 带什么进模型/响应返回什么（两个 data-plane、两个在 HTTP 路径）**；**文档投毒=最常见且立即可利用的攻击向量——共享知识库（Confluence/SharePoint/GDrive/S3）任何能上传的人都有风险；预检索攻击：先植入恶意内容等检索（需额外写权限，但持久性强、共享基底爆炸半径大）**；**检索前消毒：PII/access token/凭据/内部项目名在进 prompt 前移除或 mask（尤其第三方 LLM）；检索级 RBAC：chunks 不只相关还须有权**；**SD-RAG：把安全隐私约束执行从生成过程解耦——在检索阶段（增强模型输入前）应用消毒与披露控制，配人类可读动态约束**；**多轮上下文操纵：OWASP 认为比单轮更危险——跨轮逐步把检索引向敏感文档空间+生成引向未授权披露，利用会话持久化**。判据：**RAG 安全在检索期执行消毒与权限过滤，不依赖生成期 prompt 防护**。提升层：工作流。
5. **预执行日志与不可变审计链**（来源：openlegion《AI Agent Audit Log》2026-06 + airblackbox.ai + ai-identity.co + strac.io《Monitor AI Agents》2026-08 + lyzr.ai《AI Compliance Tools》2026-09 + audition-ai《Audit Trail Is the New Compliance Report》2026-07）——**预执行日志：条目在动作完成前写入——时间戳先于结果（取证关键：能事后写日志的 agent 也能写假条目或省略想藏的条目）；不可变：agent/操作员/任何人都不能改删**；**hash-chain 防篡改：HMAC-SHA256 链式（改任何记录链即断）+外部时间戳机构联署（验证者无需账号/安装/信任声明）；DSSE+ECDSA-P256 签名会话证明、离线可验证证据包**；**Strac 数据事件级日志：谁/什么数据类/哪个工具/什么动作/什么被 redact 或 block——同一记录流入 SIEM（Splunk/Sentinel/Datadog）作 SOC2/HIPAA 证据**；**Lyzr OpenController：签名审计轨迹（生命周期事件/模型调用/工具执行，1/100 秒时间戳+每 promotion 审批者身份）——"请求路径中已有执行副产物的记录，不是事后查询的日志"**；**Audition 五问：做了什么/为什么/谁批准/影响什么/如何回滚**。判据：**审计条目先于动作写入+hash 链+外部时间戳，才是拿得出手的证据**。提升层：可复用 Skill。
6. **技能供应链攻击量化**（来源：Unit 42《Behavioral Integrity Verification》2026-06 + beyondscale《Agent Skill Supply Chain Attacks》2026-04 + CSA《Plugin4Shell》2026-09 + arXiv 2603.00195《Formal Analysis》+ 安天 2026-09 预警 + theorydelta《Agent Supply Chain》2026-05 + CSA《Mini Shai-Hulud》2026-05）——**Unit42 BIV：对比技能声明 vs 实际行为（metadata/可执行代码/自然语言指令三表面）——OpenClaw 注册表 49,943 技能中 80% 偏离声明功能，5%（~2,490）含多阶段攻击链（凭据窃取/RCE/静默数据渗透）**；**Snyk 审计 3,984 agent skills：13.4% 含关键安全问题（凭据窃取/后门/数据 exfil），8 个确认恶意技能仍公开；BadSkill（arXiv 2604.09378）：3% 投毒率 99.5% 攻击成功率（八模型架构），模型权重后门**；**Plugin4Shell（2026-09-18）：SHA-pinning 绕过=零点击 RCE——Claude Code/Codex/Copilot/Gemini CLI 装插件锁到已审 commit hash 但四家都没验证 pin 与内容一致**；**91% 恶意技能=prompt injection+传统恶意软件 hybrid（同时绕过 AI 安全机制与 CVE 工具）；ClawHavoc 战役 1,200+ 恶意技能渗透 marketplace；MalTool 目录 6,487 恶意工具逃逸常规检测；Mini Shai-Hulud 用 Claude Code .claude/settings.json 武器化**；安天：已注销 ChaosGPT 账号 14 分钟内向 HF 两个官方仓库投 71 个恶意文件。判据：**装技能=装权限：先行为审计（声明 vs 实际），再验 pin 与内容一致；仓库账号吊销不等于内容可信**。提升层：可复用 Skill。
7. **Agent 身份工件保护（OWASP AST10）**（来源：OWASP《Agentic Skills Top 10 Whitepaper》PDF，2026 实拉）——**保护 agent 身份工件（SOUL.md/MEMORY.md/persona/config 文件）：限制读写访问+签名或版本控制+任何技能请求访问=升级风险（AST03）——同时防持久后门与身份克隆**；**技能执行隔离在容器/sandbox；技能动作结构化日志审计；基于社区反馈+自动测试的技能声誉系统**。判据：**身份工件按凭据级别对待——技能要读 MEMORY.md 就当高风险请求**。提升层：可复用 Skill。
8. **NHI+委托签名+时间绑定凭据+权限 diffing**（来源：accuroai《OWASP Agentic Top 10 Annotated for Enterprises》2026-05 + IETF draft-chen-oauth-agent-authz-use-cases-02 2026-09）——**四个控制：①每 agent 独立非人身份（NHI）——独立 workload identity，不用用户 token；②委托签名——agent A 委派给 B 时原始用户意图加密附加到调用；③时间绑定凭据——agent token 任务完成即过期，不按会话超时；④权限 diffing——每次 agent 动作记录最小所需权限 vs 实际**；**Coordinator 单点权威：协调者被攻破=整组爆炸半径——其代表他人 apply 的权威须单独认证**。判据：**agent 身份=独立 workload identity+意图签名随委托传播；权限差异必须可审计**。提升层：工具。
9. **OWASP ASI/LLM 应用控制清单**（来源：aibuzz《OWASP Top 10 for Agentic Applications 2026》2026-05 + anomity《OWASP LLM & Agentic Top 10 Checklist》2026-06 + systemprompt《Implementation Guide》2026-04）——**ASI #6-10 全 Critical：Sensitive Data Exposure=数据分类+输出 redaction；Inadequate Human Oversight=kill switch+审批检查点；Supply Chain=AI-BOM+依赖扫描；Irreversible Action=人工确认门+soft delete；Identity & Auth Failures=强 auth+NHI 框架**；**LLM08 向量弱点：向量库访问控制+逻辑分区+per-user 细粒度+只信可信源——监测跨租户检索/拉取超出 caller 权限数据；LLM09 错误信息：verified sources RAG+交叉验证+来源归因+人工事实核查；LLM10 无界消耗：限流+超时+per-user/per-agent 配额——监测成本/资源尖峰/失控循环**；**secret detection 35+ patterns：工具参数执行前扫凭据；服务端注入凭据=secrets 永不碰模型/agent；会话隔离+审计轨迹（无持久状态）**。判据：**按 ASI 清单逐项配控制，高危动作必有确认门+软删除**。提升层：可复用 Skill。
10. **护栏模型与运行时治理**（来源：arXiv 2601.18491 AgentDoG + OpenReview StepGuard + FutureAGI《AI Agent Compliance Playbook》2026-05 + aisecurityplatform《OWASP Agentic Top 10 Explained》2026-08 + IntelliSee《Agentic AI Safety Case》2026-05 + 网信办《智能体规范应用与创新发展实施意见》2026-05）——**AgentDoG：统一三维分类法——风险按来源（where）/失败模式（how）/后果（what）正交分类+ATBench 细粒度基准+诊断式护栏框架（细粒度上下文监控）**；**StepGuard：步级护栏模型——离线轨迹诊断+在线预动作守卫；StepGen 数据引擎生成步注释安全/不安全轨迹组（局部风险动作+上下文匹配安全替代）；Balance-GRPO 偏差感知 RL 校准**；**pre-guardrail（敏感工具前）+post-guardrail（用户可见响应前）检查点——失败=block/fallback/路由更安全模型/告警/转人工；步骤预算+递归上限（超步数重新授权）**；**IntelliSee 四监督功能证据：per-event 预动作审查+上游策略编写与版本控制+下游动作后审计+独立于 agent 软件栈的紧急中断（NIST AI RMF MANAGE 4.1/MEASURE 2.6）**；网信办 2026-05：智能体安全技术（数据安全/PII/密码防护/攻击检测/权限管理/行为控制）+防范数据投毒/隐私泄露/算法篡改/系统漏洞/运行失控+智能体安全评估体系。判据：**护栏=执行前步级守卫+执行后诊断+独立紧急中断三层；预审/事后/中断三个证据点都要有**。提升层：工作流。
11. **部署前保证与 Trust Certificate**（来源：arXiv 2606.04037《Pre-Deployment Assurance for Enterprise AI Agents》+ ideabosque《Agent Governance Checklist》2026-07）——**三组件：Agent Operational Envelope（把认证空间形式化：权限/领域约束/安全属性/治理规则/自治级别）+ontology-to-scenario 生成流水线（自动派生监管/运营/对抗测试场景）+Trust Certificate（机器可验证 attestation，渐进部署裁决 Approved/Conditional/Rejected）——四行业试点（Fintech/Banking/Insurance/Healthcare）**；**部署前 10 控制清单（Gartner 四自治级别/CSA 六级分类法/Stanford 48 控制 AILCCP/OWASP MCP Top10/NIST AI Agent 标准）——每控制可验证、在生产数据前过完**。判据：**部署前用操作包络+自动场景+可验证证书三件套，不用"模型不错"的直觉**。提升层：工作流。
12. **红队基准与工具生态**（来源：arXiv 2606.23927 RIFT-Bench + arXiv 2606.02240 AgentRedBench + alphaXiv 2605.04808 DTap + arXiv 2607.18063 Adaptive Adversaries + CSA RiskRubric + tsecbench.zc.tencent.com + Netguardia《AI Red-Teaming Tools 2026》2026-04）——**RIFT-Bench 核心论点：多数 LLM agent 安全测试继承了错误假设（把用户 prompt 当唯一攻击面、只按模型最终文本输出判成功）——那对 chatbot 成立、对 agent 不对；表征驱动两自动阶段=Discovery（提取系统结构）+Scanning（执行自适应对抗攻击，105 探针）**；**AgentRedBench：215 个微妙欠授权场景×24 企业集成×5 攻击类型——八模型无防护 ASR 32-81%**；**DTap：6,682 任务（3,876 红队）+规则可验证 judge——所有 SOTA agent（OpenAI Agents SDK/Google ADK/Claude Code/OpenClaw）都脆弱，间接攻击 ASR 高达 55.7%**；**Adaptive Adversaries：21 场景自适应多轮攻击——自主 LLM 攻击者观察 defender 先前响应跨轮 pivot**；**CSA RiskRubric 覆盖 OWASP ASI 全部 10 类风险可独立评分；腾讯 Tsecbench 智能攻防跑分（真实漏洞/生产靶场/红蓝对抗）；工具链 garak→promptfoo**；**直接 jailbreak 对新模型（GPT-4o/Claude 3.7/Gemini 1.5 Pro）成功率 5-15% vs 旧模型 30-50%**。判据：**agent 红队按图（代码/结构）打不按 prompt 打；间接攻击是主战场（55.7%）**。提升层：可复用 Skill。
