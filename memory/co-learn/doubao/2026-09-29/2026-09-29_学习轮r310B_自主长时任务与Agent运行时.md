## 独点（12）

1. **Checkpoint 是契约不是状态更新**（来源：labs.adaline.ai + UBC cs.ubc.ca + arXiv 2607.11388 StructAgent）——**checkpoint=agent 序列化的状态 + 系统对该状态跑的验证器 + 下阶段失败时可恢复点；里程碑=契约**；**固定间隔压缩进度并从结构化存储重读，不依赖上下文连续性（context continuity 是薄弱假设）**；**Externalize state：每 checkpoint 写 goals/constraints/artifacts/dependencies/actions/observations/failures/resources；敏感内容保留前脱敏**；**StructAgent：统一状态保持紧凑可验证任务进度，verifier-backed 状态迁移调节进度，所有进度更新 grounded in verification**。判据：**"checkpoint 已保存"要说清三件事：存了什么状态/验证器判了什么/从哪恢复**。提升层：工作流。
2. **记忆是执行状态不是更聪明的检索**（来源：UBC blog + arXiv 2606.06090 Mage）——**外部副作用任务中最重要的 state 往往不是知识，而是对行动的约束**；**Mage：活动执行状态管理器把交互存层级状态树；agent 从活动根到当前路径派生状态（子目标摘要+近期轨迹+先前分支提示）；四操作：Grow 记录新轨迹 / Compress 压缩完成子目标 / Validate 验证摘要 / Revise 恢复目标边界并新分支续跑**——有界上下文且可回溯。判据：**长任务"记什么"的答案是执行状态（到哪了/什么约束在生效），不是把更多资料塞进上下文**。提升层：工作流。
3. **三状态存储：Git + checkpoint DB + artifact store**（来源：slavadubrov.github.io）——**Git 存 workspace 状态（代码/文档/进度文件——每 commit 给 harness 稳定恢复点+下会话紧凑历史）；checkpoint 数据库存图状态（什么被决定/哪些节点跑过/哪些结果返回/下一步该跑什么）；artifact store 存大最终输出（PDF/Parquet/截图）**——三个存储各管一种产物。判据：**别用单一存储装三类状态——恢复点/图进度/大产物生命周期不同**。提升层：工具。
4. **Durable execution：持久性由运行时保证不是应用逻辑**（来源：zylos.ai + databricks Temporal + agentnative.dev + dev.to agdex）——**工作流引擎每离散步骤后自动持久化运行状态；崩溃后从持久化事件历史重放，跳过已完步骤精确断点续跑；开发者写普通顺序代码**；**replay 中记录过的 Activity 结果直接返回不重跑——已完成的保持完成**；**稳定 run id（thread_id）+每 superstep 边界快照+durability 模式（write-before-continue / write-in-parallel / write-on-exit）+pending-writes ledger：部分失败并行批次只重跑失败者**。判据：**agent 可靠性围绕 durable step boundaries + 幂等工具执行 + 显式完成信号构建，不是靠"小心点别崩"**。提升层：工具。
5. **恢复边界安全：rollback 不是快照克隆**（来源：arXiv 2608.29381 + arXiv 2608.14380 AgentRewind）——**rollback 到 checkpoint C_K：K 内进程恢复记录状态；K 外进程不受该 checkpoint 控制——可能保留当前状态/从早期状态重启/从其他源重建**；**恢复连续性可能断裂：外部副作用（已发邮件/已付款）无法回滚**；**AgentRewind：每 LLM 决策边界记录执行状态为可恢复 checkpoint d_t=(c_t,s_t)，元数据描述两 checkpoint 间的执行段**。判据：**恢复策略要回答"哪些副作用在外、回滚不到"——只恢复 K 内不等于任务回到干净起点**。提升层：工具。
6. **验证循环纪律：弃权与过度纠正**（来源：dev.to danmercede + agentpatternscatalog + arXiv 2606.21724 DISC + futureagi）——**错误/超时/null=弃权，弃权重试不计数为干净通过——崩溃的评审者不是反驳（0-0 claim 不能报 refuted）**；**critique 必须具体可测："Is this good?"太模糊无法行动；"SQL 能跑且返回问题要的列吗"是可测试标准**；**DISC 二元判断门控制纠正精度——阻止破坏已正确答案的重写**；**循环三指标：pre-vs-post delta 每问 / 过度纠正率 / 每改进成本——"升 4 点却回归 8% 正确答案+延迟三倍"与"干净升 2 点"是不同系统**。判据：**验证循环的验收=是否修了该修的、没毁不该毁的、成本可控**。提升层：可复用 Skill。
7. **循环必须硬 cap：无界反思=负债**（来源：machinelearningmastery + trantorinc + richardewing）——**无界反思循环不是安全特性是负债（文档处理 agent 重试过夜 8 小时烧 $437 的 postmortem）；错误→重试→更长上下文（含错误推理）→更贵→再失败——$0.03 任务几分钟 $47 还在循环**；**每循环硬 cap + 硬迭代上限 + 每执行线程美元预算**；**成本失控对标准 APM 不可见（看起来在"努力干活"）**。判据：**任何循环（反思/重试/搜索）都要先问：上限在哪、烧钱怎么停**。提升层：工作流。
8. **失败模式根因表与自愈响应**（来源：zylos.ai + wowhow + growthengineer + AWS AgentCore observability）——**死锁/语义循环（重复分数高+进度指标平→注入目标重估 prompt；持续则重启）/ 上下文溢出（token 接近上限→摘要压缩+外部存储卸载）/ 依赖失败（工具错误超时→断路器该工具+降级继续）/ 无限递归（栈深或自调用计数爬升→硬迭代 cap+注入终止指令）**；**无限循环根因三：提示无终止条件（多少尝试合理/何时宣告不可能/何时升级人类）+不识别已犯错+无升级路径**。判据：**每失败模式配一个可观测信号+一个具体响应——不靠模型"自觉"**。提升层：可复用 Skill。
9. **上下文饱和是静默丢失**（来源：getreadyforagents + sista.ai）——**每工具返回/每推理步/每检索文档加 token；会话跨几十个工具调用窗口填满→模型静默丢弃早会话细节——不抛错，只是忘记开头给的约束**；**每工具调用处 token 计数器插桩**；**四复发原因：上下文耗尽/幻觉工具调用/脆弱工具接口/记忆漂移——都不是模型 bug 是工程问题；Anthropic 数据：context editing 减 token 8x**。判据：**长任务把"开头约束"当易失资产——要么重注入规则要么压缩时保留，不能假设还在**。提升层：工作流。
10. **自主度阶梯与风险分级审批**（来源：gainam + openlegion + iotdigitaltwinplm + r-sun + ms copilot cowork）——**自主度分层：L0 工具执行（每动作确认）/L1 仅建议/L2 预批准执行/L3 自主+例外升级/L4 自主+事后审计（自修改不可商用）**；**团队从低层开始证明可靠性，再按动作类毕业（per action class 而非整个 agent）**；**2026 主流=风险分级审批路由：分类动作进风险层——低风险自动化/中风险抽样审计/高风险同步人工批准，替代全量人工审查**；**bounded autonomy：明确操作限制+高利害交互人类升级路径+动作审计轨迹**；**个人 agent 实例：事件触发（新邮件/日历提醒/数据变动→自动工作流）+敏感动作（支付/发送）审批+dashboard 审查**。判据：**自主度是"按动作类"配的，不是 agent 整体一档——风险分级审批先于部署**。提升层：工作流。
11. **子代理价值两情形与安全工程**（来源：alexmercedcoder + langchain + mer.vin harness stack）——**子代理恰好两种情形值得：并行（多个独立调查同时跑）+上下文隔离（子代理烧自己窗口探索兔子洞，只返回结论，父上下文干净）**；**安全工程（naive 实现常跳过的部分）：每子代理重建上下文+自己的权限范围，不继承父的副本；结果通过结构化摘要返回而非原始轨迹**；**harness 组件分工：Context（决定模型每轮看到什么——组装/缓存/压缩/重注入规则）/Memory（跨轮跨会话——技能/进度文件/git 历史）/Orchestration（计划+委派——隔离子上下文/合并结果）/Tools（桥 JSON 到真实执行——验证 schema/执行/截断输出）**。判据：**子代理要么带来并行要么带来隔离，否则只是多花钱；且必须重建上下文+独立权限**。提升层：可复用 Skill。
12. **沙箱边界与后果性出口门**（来源：truefoundry + loooop + Best Practices harness + AWS AgentCore）——**工具访问≠沙箱访问：沙箱进程不应自动继承生产 MCP 凭据**；**后果性出口需要门：沙箱里建文件≠部署它/邮件它/写入系统记录——不同后果不同审批**；**三层防御：OS 级沙箱隔离执行环境 + 文件系统限制（仅项目目录）+ 命令 allowlist（shlex 解析防管道/链式，敏感命令单独验证）**；**每会话隔离 microVM（AWS AgentCore 默认 stateful 每会话一个）**。判据：**沙箱解决"代码跑哪"，出口门解决"结果去哪"——两层都要，缺一即泄露**。提升层：工具。
