1. **Agent 编排五大幸存模式与 loop 结构化栈**（来源：datarekha 2026-05 + shyankdev 2026-07 + ailearningguides 2026-05 + sudoall 2026-06 + Stanford CS224G）——**五大模式实证：augmented LLM/prompt chains/routing/parallelization/orchestrator-worker——"其余皆变体"；shipping reliable agents（Cursor/Replit/Devin/Anthropic）compose these five，追 fully autonomous multi-agent swarms 的几乎没 ship**；**DAG Routing=形式化任务图（节点+无环定向边）——执行从根节点按分支路由决策推进（确定性代码规则或 classifier LLM），限制循环保证终局**；**Stop-the-line 模式（制造业借来）：任何 agent 可 flag 关键问题（数据缺失/安全）→orchestrator 暂停升级——防坏工作传播**；**loop 结构化栈定位（sudoall）：输入→router（选 skill/prompt）→planner（拆任务列表）→executor（跑循环）→memory（跨会话持久）→MCP/function 层——routing/planning 在 loop 之上，tools/memory 在 loop 之下，loop 本身不变**；**Orchestrator-Workers vs Parallelization 区别=subtasks 非预定义，orchestrator 运行时定**。判据：**先选五模式之一再动手；编排栈按 router/planner 上、tools/memory 下分层**。提升层：工作流。

3. **RAG 2026 实证配方**（来源：CSDN contextual retrieval 2025 + ACL SemEval-2026 ×2 + arXiv 2511.01386/2504.19754/2601.15457/2605.01664/2507.12425）——**Contextual Retrieval（Anthropic）：给每个 chunk 加通用文档摘要——reranked Contextual Embedding+Contextual BM25 把 top-20 chunk 检索失败率降 67%（5.7%→1.9%）**；**chunk 精度-召回权衡（RAGSmith）：小 chunk=高精度（聚焦可直接喂生成器）大 chunk=高召回（答案更可能在单块内但含噪声）；overlap（stride<window）防跨边界丢失**；**hybrid 配方（SemEval-2026 冠军梯队）：SPLADE-v3 学习稀疏+dense embeddings→Reciprocal Rank Fusion→BGE cross-encoder reranker；训练自由版=dense+sparse+受控 query rewriting+cross-encoder rerank（nDCG@5 0.5453 排名 3/38 超基线）**；**证据检举架构：hybrid+rerank→最高排位证据生成受控回答→独立 judge 模型逐条事实 claim 对照检索证据**；**指标=Precision@5/Recall@5/MRR**；**Advanced RAG 实证：bi-encoder 检 10 候选→cross-encoder（ms-marco-MiniLM-L-6-v2）选 top 3→strict system prompt 禁外部知识**。判据：**检索栈=稠密+稀疏+RRF 融合+cross-encoder 重排；逐条 claim 证据检举兜底**。提升层：工作流。
4. **Context rot 四因与 context-editing API 参数**（来源：01.me AWS re:Invent 2025 + platform.claude.com context-editing ×2 2026-09 + di37 bootcamp）——**Context rot 四因：Poisoning（错误/过时信息）/Distraction（无关信息）/Confusion（相似信息混入）/Clash（矛盾信息）——四种质量退化机制**；**context-editing API 参数：enabled/context_token_threshold（默认 100,000）/model（摘要模型）/summary_prompt（自定义）——超阈值注入 summary prompt 作 user turn→Claude 生成 <summary> 包裹结构化摘要→SDK 提取替换整个 message history→continuation**；**compaction 触发=内置 ~80-86% utilization；Claude Code /compact（50K→5K token）/clear（全清）**；**定义：Context Window=总输入 token 容量；Context Engineering=设计管理进入窗口的所有信息；Prompt Engineering=单条输入文本**。判据：**压缩阈值/摘要模型/自定义 prompt 三参数显式配置；rot 四因排查输出退化**。提升层：可复用 Skill。
5. **Cache-aware rolling buffer 三层与缓存前缀纪律**（来源：claude.com computer use best practices 2026-05 ×3 + anasbarg fable 2026-06 + agentpatterns 2026-09）——**长地平线 CU 会话实测三层：①stable prefix 一个 cache breakpoint+trailing tool results 三个断点每轮清放；②cache-aware rolling buffer keep_n=3 interval=25——超 keep_n+interval 后旧截图批量换 placeholder 一次，两次 pruning 间消息数组 byte-identical 保缓存命中；③server-side compaction 150k input tokens+自定义 prompt+client truncation 对齐**；**缓存前缀纪律（anasbarg）：agent transcript append-only 每次调用重复整个前缀（system prompt+tools+所有前轮）——缓存只在前缀 byte-identical 时工作：稳定内容放前（system prompt/tool defs）会话中不 mutate；别每轮往 system prompt 注入当前时间戳**；**Static content first（agentpatterns）：静态内容开头变量内容最后；非确定性工具排序是常见缓存杀手——工具定义一致排序；会话中换模型破坏缓存（模型特定指令早注入）**。判据：**缓存三要素=稳定前缀不动+排序确定+轮间消息数组 byte-identical**。提升层：工作流。
6. **JIT 工具 schema 组装与 tool-heavy retrieval boundaries**（来源：AWS AGENTPERF03-BP02 2026-08 + negiadventures 2026-04 + 阿里云 context-cache 2026-09）——**AWS：每个 token 竞争模型注意力/消耗输入成本/加延迟——prompt 内容是一阶性能杠杆；tool schemas 动态组装（just-in-time selection）——不一次性塞所有工具 schema，对话历史与工具 schema 会挤占推理容量**；**tool-heavy 缓存四步（negiadventures）：可复用指令前缀固定+只检索最小任务相关上下文+检索结果注入稳定前缀之后+轮间激进过期/替换检索块——"如果模型丢了这项会不会做更差的下一决定？不会就压缩掉"**；**缓存 marker 20 block 回溯限制（阿里）：messages 数组超 20 content blocks 分隔 cache_control marker 与早期内容时 backward lookback window 够不到早期块→缓存失效**；**context engineering 共享词汇（zylos）：write/select/compress/isolate——实证 more context is not free**。判据：**工具 schema 按需注入不预塞；检索结果在稳定前缀后注入并轮间过期**。提升层：工作流。
7. **Credential-in-Context 安全失败与注入防御诚实立场**（来源：openlegion 2026-07 + romankryvolapov 2026-09 + gitgood 2026-07）——**Credential-in-Context 问题：最常见生产安全失败=把 API key/DB 连接串/JWT 注入 system prompt 供工具调用（工具执行代码需要 key，最简单实现是放 system prompt）——凭证与运行时混一处**；**注入诚实立场：指令与数据同一条 token 流，模型无法可靠区分——prompt 保护不了注入；adaptive attacks 绕过 prompt 级防御率高（arXiv 2510.09023）；关键词过滤（ignore previous instructions）漏掉绝大多数真实 payload（普通专业语言无触发词）——防御靠结构：系统提示权限分离/分隔不可信数据/输出校验/最小权限工具/重大动作 HITL**；**prompt injection 定义：不可信内容（用户输入/抓取页面/工具结果）含指令覆盖你的指令——防御分层且不完美**。判据：**凭证走运行时环境不走上下文；注入防御按结构分层不靠关键词**。提升层：可复用 Skill。
