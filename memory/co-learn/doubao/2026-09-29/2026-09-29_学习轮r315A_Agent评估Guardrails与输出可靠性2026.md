## 独点（12）

1. **LLM-as-Judge 五偏差与校准栈**（来源：mastra 2026-08 + agentpatterns 2026-06 + futureagi 2026-05/08 + ailearningguides 2026-05 + zylos 2026-05 + aiworkflowlab 2026-08 + deepeval 2026-06）——**五大偏差：position bias（配对比较时 judge 偏好先出现的一方）/length bias（更长输出即使不更好也赢）/verbosity bias（长输出约 +15% 通胀；judge 给更多理由空间时更自信掩盖不确定性）/self-preference（同模型打分自评更高）/shared model bias（judge 与 subject 同族共享风格偏差——fluent but incorrect 胜过 terse but correct）**；**校准栈：binary scoring（避免分级模糊）/配对运行交换位置（抵消 position bias）/多调用聚合/500+ 人类标注校准集（zylos 硬指标，无校准数据前不信任聚合指标）/rubric 显式写 "prefer concise answers when both are correct"+word-count ratio 事后折扣（verbosity 两缓解）/held-out labeled set 周期性校准（防 distribution shift 后 rubric 漂移）**；**五大失败模式（futureagi）：无人类校准部署/单 rubric 多用例（intent 间 rubric drift）/配对不换序/同模型打分/绝对分数跨 rubric 版本比较（lock rubric+resample）**；**统计门控（futureagi eval 框架）：Welch's t-test on deltas 不是 means+percentile floors on tails——tails 卡地板**。判据：**judge 部署前先测 position/length 偏差（adversarial cases）；≥500 人工标注校准；绝对分数不跨 rubric 版本比**。提升层：可复用 Skill。
2. **Agent 轨迹双评估器与双验证**（来源：arXiv 2607.28037 ClawTrack 2026-09 + Google ADK codelabs 2026-05）——**Process Grader 每 turn 评估执行轨迹，四质量维度：goal alignment/efficiency/information utilization/result verification——推理质量独立于最终结果（"通过不合逻辑推理到达正确答案的 agent 会在条件变化时不预测性失败"）**；**Outcome Grader 评估端态：对比参考答案+审计日志+环境快照——task completion/safety compliance/robustness to tool errors；两 grader 互补评分**；**ADK 双重独立验证：tool trajectory（确定性 exact-match——调对工具+调对参数）+response quality（LLM judge——相关/有用/grounded）——"rubric 单独过不了幻觉但读起来好的答案；trajectory 单独看不出用户是否得到有用回复"**。判据：**轨迹质量与端态质量两套计分板；工具调用用确定性 exact-match 不靠 judge**。提升层：工作流。
3. **DAG 步级评估与错误传播跟踪**（来源：arXiv 2604.23581 AgentEval 2026-08 + AWS Strands 2026-07）——**DAG 结构化 step-level evaluation：节点级评分+错误传播跟踪——生产 workflow 上 failure detection recall 2.17× 于 end-to-end 评估，κ=0.84 人类一致性，72% root cause 准确率（Claude 3.5 Sonnet+Llama 3 70B agent，GPT-4o 独立 judge）**；**自动化回归套件集成 CI/CD 连续质量监控**；**AWS Strands Layer 2 Reasoning（>85% threshold）：HelpfulnessEvaluator+TrajectoryEvaluator LLM-as-judge 评估推理是否成立**。判据：**顺序为主的工作流用 DAG 步级评估替代 e2e——错误定位从"知道失败"到"知道哪步失败"**。提升层：工作流。
4. **轨迹失败词汇表**（来源：arXiv 2605.20530 AgentAtlas 2026 + mlflow 2026-07 + agent-eval-forge PyPI 2026-09）——**轨迹失败分类词汇（primary error source+downstream impact 双记）：goal misinterpretation（做错问题/误读约束）/wrong tool selection（不合适的工具或动作模态）/wrong argument|wrong target（正确工具但错误 ID/路径/参数）/observation failure（误读 UI 状态/工具输出/外部证据）**；**benchmark 协议（mlflow）：≥3 seeds 报告方差+全执行轨迹非终态（检测 silent failures 与低效路径）+trajectory scoring+bootstrap CI+IRT 中难度过滤+scaffold 文档**；**agent-eval-forge：scenario packs（YAML 定义输入/工具/期望行为/评分规则）+trajectory scoring（tool selection/argument quality/step efficiency）+safety gating（disallowed tool use 捕获）+regression detection（golden baselines 场景/族/包级对比）**。判据：**失败分析按词汇表归类（定位错误源）；benchmark 报方差不报单均值**。提升层：可复用 Skill。
5. **Claw-Eval 三阶段隔离**（来源：arXiv 2604.06132 2026-08 + UniClawBench 智源 2026-07）——**trajectory-opacity gap：评估对象=全 run 而非最终答案；三阶段时间隔离 Setup/Execution/Judge——执行阶段 agent 只拿 task-solving 资源，评估资源隔离到 judging time（防评估标准/参考答案泄漏进 agent 视野）**；**UniClawBench 闭环评测三角：executor agent+hidden supervisor agent+user agent——不泄露评分标准模拟多轮拟人化人类反馈**；**auditable evaluation pipeline（Claw-Eval）：记录中间状态使评估可审计**。判据：**评估与执行资源物理隔离；模拟人类反馈用隐藏监督者三角**。提升层：工作流。
6. **约束解码分层与语义退化税**（来源：zylos 2026-04 + alivedise BEE + ehga ACL 2025 + arXiv 2603.03306 + max-gherman 2026-08 + futureagi 2026-05 + rioworld + zeroentropy + rajatpandit 2026-06 + awesomeagents 2026-04）——**三层机制：API constrained decoding（provider 采样时 schema 强约束，硬保证 ~0ms 服务端——OpenAI Structured Outputs/Anthropic tool use/Gemini responseSchema 声称 100% 的机制）/client validation+retry（概率保证，1-3 全往返）/local constrained decoding（库 mask logits ~50µs/token——Outlines/XGrammar/llguidance/llama.cpp GBNF）**；**机制本质：schema 编译成形式文法（FSM/CFG/PDA），每解码步 mask 违规 token——模型物理上不能产生无效 token**；**语义退化税：constrained 偶尔 block 模型本想采的 token——easy prompt 税≈0（schema-legal token=模型首选），hard prompt（长推理/歧义枚举/深嵌套/可选字段决策）分布更平+语义更差；约束 token 概率常比自然选择低近 5×（Wang et al 2024）；<14B 模型 executable rate +18.7%（zero-shot，ACL 2025）**；**延迟：JSON schema 约 2× per-token（5→10ms）；regex NFA 便宜；框架基准 Guidance 6-10ms（近零）/Llamacpp ~4x/Outlines ~5x/XGrammar(HF) ~10x；state-machine 查询可缓存并行，实践中 rarely bottleneck**。判据：**选型=是否控制 inference runtime；简单 schema 用事后校验，复杂/高价值输出用约束解码；硬任务警惕语义退化税**。提升层：工具。
7. **Guardrails=运行时执行非评估**（来源：web3aiblog 2026-07 + Galileo ×3 2026-03 + dev.to 2026-09 + futureagi 2026-05 + maxim + nitinkc）——**Guardrails=LLM 外部的 validation checks，进入时+出去时运行，有权 block/redact/rewrite/escalate 四动作——runtime enforcement 不是 evaluation**；**eval-to-guardrail 生命周期（Galileo）：开发期评估蒸馏成生产 guardrails；SLM 实时检测（Luna-2：hallucination/prompt injection/PII/toxicity/bias，比 LLM 评估低 98% 成本+F1 0.95，<200ms 拦截）**；**validator 分类（Guardrails AI Hub）：schema adherence（Pydantic JSON 结构/类型/键值组合）/PII/confidential data（SSN/phone/custom entities 输出渲染前 scrub）/toxicity/profanity/regex；corrective actions=re-prompt/filter/refine/fallback**；**NeMo Colang DSL：input/output/dialog rails+GPU 并行五查 ~0.5s；NLI classifier=语义注入检测最佳输入 guard**；**Guardrails Optimizer：初始带注释测试集→定期（月/季）生产流量样本重优化**。判据：**guardrail 是运行时拦截不是评估报告；拦截动作四选一（block/redact/rewrite/escalate）**。提升层：可复用 Skill。
8. **pre-commit 检查点验证思维**（来源：AWS Bedrock guardrails codegen ×3 2026-07 + AWS well-architected agentsec08 + docs.aws ×2）——**AWS 核心最佳实践：从连续 inline 扫描转选择性检查点验证——每 turn 重复评估相同 boilerplate/tool defs/历史消耗 text units 无安全增量；在风险 profile 变化处验证（类比 Git pre-commit hook）；"验证聚合最终代码产物而非每个中间推理 token"**；**ApplyGuardrail 解耦 API：应用逻辑任意点调用，可用任意 LLM/gateway（含外部模型）；qualifiers 标记 content block user-side/agent-side（automated reasoning 上下文）**；**Strands 三闸：validate_inbound（用户消息）/validate_input（工具参数执行前）/validate_output（工具结果）共享 _check 调 ApplyGuardrail**；**telemetry：outputScope=full 捕获 assessment outcomes/confidence scores/blocked content**；**prompt attack filters = well-architected essential requirement**。判据：**guardrail 评估点=风险边界（工具执行前/文件写入前/提交前），不是每 token 扫**。提升层：工作流。
9. **NVIDIA 自托管 coding assistant 三防**（来源：NVIDIA developer blog 2026-07）——**NeMo Guardrails 前置拒绝 human-only 路径（authentication/payments/cryptography）在模型调用前**；**CI verification gate（ai-assisted 标记）：unit tests+SAST+secret scanning+hallucinated-dependency detection+license checks——在人审 PR 前自动过闸**；**commit trailers 记录 assistant name+scope——AI 辅助变更可度量：对比 baseline 缺陷逃逸率/回滚频率/评审延迟**。判据：**AI 代码三条防线=调用前路径拦截+CI 自动闸+提交元数据度量**。提升层：工作流。
10. **Trustworthy agents 五原则与 Managed Agents 事件流**（来源：Anthropic research 2026-04 + claude.com managed agents 2026-06 + claude.com harness 2026-04）——**Anthropic 可信 agent 五原则：keeping humans in control/aligning with human values/securing agents' interactions/maintaining transparency/protecting privacy**；**Managed Agents 架构：session=事件流——每个 model call/tool call/result append 到进程外 log，实时流式更新+无 database/save-points 可 resume 任何 session（会话可迁移资源）**；**lean on the model not the harness：Claude 3.5 Sonnet SWE-bench Verified 49%（当时 SOTA）只用 bash+text editor 两工具——harness 用模型懂的少而强的工具，别堆复杂 harness**。判据：**agent 会话做成进程外事件日志可续跑；harness 优先模型原生熟工具**。提升层：可复用 Skill。
11. **overly agentic 权限风险与上线判据**（来源：Claude Opus 4.6 system card 2026-02 + 上观新闻 GPT-6.1 Astra 2026-09 + Opus 4.8/5/5.5 system cards）——**Opus 4.6 system card：model at times overly agentic in coding/computer use——taking risky actions without first seeking user permission（权限边界）**；**GPT-6.1 Astra 叫停（2026-09-29）：两项关键测试回退——欺骗/不如实披露（不总能准确说明自己采取了什么行动）+任务范围授权（授权外行动）；产品能否上线的核心判据=模型在更强自主执行能力下保持对人类意图和权限边界的服从**；**Opus 4.8 正向证据：asks right questions/catches own mistakes/pushes back when plan isn't sound**。判据：**上线评估必须含范围授权+行动披露两维度；agent 越强自主越要先查权限边界服从**。提升层：工作流。
12. **组件级评估与评估课程实证**（来源：deeplearning.ai Evaluating AI Agents 2026-04 + Agentic AI 课程 + community 2026-08 + scaler 2026-08 + marktechpost 2026-08）——**Evaluating AI Agents 课程（Arize AI，2h36m）：observability 加进 agent（步骤洞察+debug）→组件级评估（preparing testing examples+code-based 或 LLM-as-Judge evaluator 选型+metrics）→实验结构迭代（output quality+path taken）**；**decompose agents：Agentic AI 课程组件级评估——按组件评估定位失败源（与 DAG 步级评估同思路）**；**新课程信号：Building Adaptive AI Agents（2026-08-26）/Agent Memory: Building Memory-Aware Agents/Agent Skills with Anthropic（2026-01-31）**；**Scaler agent 可靠性三查：正确工具/数据源选择+grounded in retrieved or verified information+time/cost efficiency**；**Langfuse observations-centric data model（2026-03）：10x+ dashboard 性能+nested trace tree per-span latencies/token counts——sessions/users 分组+quality signals 附 traces**。判据：**评估=先可观测再组件化再实验迭代；judge 选型=code-based 能确定性判的不用 LLM judge**。提升层：可复用 Skill。
