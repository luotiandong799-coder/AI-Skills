## 三、三点（各附提升层）

1. **并行实现的三个具体坑**（bsd）
   - worktree 只把冲突推迟到 merge：不同部分的票仍共享消息目录/配置注册表/类型，还会命名撞车（`blockedSince` vs `blockedOn`）→ 碰同一共享文件时加阻塞边串行，或在探索笔记里钉死确切命名；worktree 只含 git 跟踪内容，读 gitignore 夹具/本地库/凭证的测试会静默跳过并报绿 → 这类票回主检出跑；报完成前先合集成分支 tip，落地应是 fast-forward。**提升层：工具 + 工作流**。
2. **一行委派型 SKILL 的三种静默失败**（sa）
   - 依赖全没加载=访谈退化（一次问完、无推荐、不提落盘）；部分加载=访谈好但无产物；套在别的编排层=访谈照跑、写文件那半不发生。判据：以"产物是否落盘"自检而非流程是否走完；怀疑时直接问"你这次加载了哪些技能"。**提升层：可复用 Skill（技能编写）**。
3. **有些决定只存在于对话里：先转 spec 再压缩**（cc）
   - 纸张三分只有术语与 ADR 落盘，其余（排序保证、否定式要求、数值默认）只在对话；下游 spec 合成会把它们软化成弱散文，成品看着完整却漏项 → 结束时先喂 spec 再 clear，并拿 spec 对着自己的回答逐条复核。**提升层：工作流**。
