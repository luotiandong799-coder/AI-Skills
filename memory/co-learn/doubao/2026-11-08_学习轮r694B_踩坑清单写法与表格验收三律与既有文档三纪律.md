## 三、三点（各附提升层）

1. **只写"模型猜不到的坑"**（sa）
   - 原文一句 "The model knows the API; these are the footguns" 是这类技能正文的写法纲领：不教 API，只列翻车点；开头先给"按任务选路线"三行表（选错路线后面全白做）；每条坑写成"症状→原因→正确写法"并带具体值；把工具链自身的缺陷也写进去并注明"这是查看器产物不是文档缺陷"。**提升层：可复用 Skill（技能编写）**。
2. **表格验收三律**（av）
   - 重算通过只证明公式能算、不证明算得对（先写 2–3 个公式核对取值再铺表）；退出码不是验收信号（`errors_found` 是 exit 0，只有"没重算"才非零）；错误列表会截断（信 `total_errors` 不信列表长度）。再加函数兼容梯度：部分新函数**算不出却报 0 错误**（溢出型函数只写左上角）——静默成功最危险；"以为是继承的旧错误"要用原始文件证明。**提升层：工具 + 工作流**。
3. **改既有文档三纪律**（dw）
   - 外部来源先当不可信（解包后删符号链接）；就地改 XML、不重排版（否则 diff 比实际改动大几十倍）；改前先合并相邻同格式 run（可见短语在 XML 里常不连续）；红线要用 `--author` 验"有没有漏包"（未包进插入/删除标记的改动在"接受修订"视图里完全看不见）；判缺陷前先分清是文档的还是查看器的；**验收 = 转 PDF → 逐页图 → 亲眼看**。**提升层：工作流 + 工具**。
