## 落地 5 独点（每点标注提升层）

### 1. 结构化输出四档强度阶梯与决策启发（工作流）
来源：sukruyusufkaya / mervcodes / precisionai / jsonic
- **四档由弱到强**：①prompt-only「return JSON」（fragile）②JSON mode（语法有效但非你的 schema）③Structured Outputs/schema-constrained decoding（provider 侧保证符合 JSON Schema）④function/tool calling（模型发结构化调用）。
- **决策启发**：要数据回传且 provider 支持 schema 约束→用它（最高可靠最少代码）；构建 agent/路由动作→函数调用；老模型或无结构化模式→prompt-and-parse+硬校验+重试——**三路常量为校验，把模型输出当不可信输入**。
- 提升层：工作流（强度选型）。

### 2. 约束解码机制（生成端强制）（工具）
来源：dev-structured-outputs-trust / datarekha / aiworkflowlab / aijsonmedic / effloow
- **每步 token 采样时把违反 schema 的 token mask 掉**（非法 token logits 置负无穷）——模型只能采 schema 有效续写，**按构造匹配，无重试无后处理**；自托管用 Outlines 等本地库。
- OpenAI strict mode=response_format json_schema+strict:true，服务端把 schema 编译成 FSM；**additionalProperties:false 在 strict 模式每个对象层必填（API 拒绝省略）**——杜绝幻觉额外 key；Claude 无 strict flag 但 tool_use input_schema 给同保证；JSON Mode 已视为 legacy。
- 提升层：工具（生成端保证）。

### 3. 三层验证流水线 + repair-then-retry（工具）
来源：kanopy / ai-tldr / cadence / spring-ai / belsoft
- **三层验证**：①syntax（有效 JSON？截断/编码错误/混自然语言）②schema（Pydantic/Zod 跑定义 schema）③semantic（值合理：价格为负 $50 拦下）——每层失败都拦。
- **失败两选项**：repair（json_repair 启发式补缺失逗号/未转义引号/截断结构——免费快、零模型调用）→retry（新请求带校验错误自纠）——**实践中先 repair 后 retry**；**retry with error feedback 首次修复 80-90% schema 违规**（Instructor/OpenAI SDK 自带此环）；简单同 prompt 重试只治瞬时故障、不治系统性问题。
- 提升层：工具（校验器栈）。

### 4. schema 版本化与输出门（可复用 Skill）
来源：velsof / aiwisdom / jsonic
- **每个输出 schema 必带 schema_version 字段**（整数单调 v1/v2/v3）；解析器=分发器**先读 schema_version 路由到匹配 validator+下游适配器**——加 v4 不动 v3 消费者。
- **输出离开系统前五查**：schema（匹配契约）/faithfulness（RAG 回答是否接地于检索上下文）/policy-toxicity（违反内容规则）/PII leak（回显个人数据）/action safety（工具参数 sane：无 DROP TABLE）——**schema 通过只是第一关**。
- 提升层：可复用 Skill（输出契约与门禁）。

### 5. 多 agent 交接 schema 契约与运行时控制（工作流）
来源：zylos / arxiv-2603.27905 / niteagent
- **一个 agent 输出=另一 agent 输入**——错误静默传播、反复引用累积表面合法性、最后一步伪装成确认事实；修法=**把 inter-agent schema 当每个交接边界强制执行的契约**，而非开发者参考文档。
- **ATLAS-RTC（token 级运行时控制）**：每 decode 步拦截 logit 分布、观察生成轨迹、对照正式输出契约打分结构漂移、**渐变干预序列**=logit biasing→温度调制→token masking→mid-step rollback+re-steering（不改模型权重）。
- 多 agent 场景=约束解码+schema gates+orchestrator 级断路器组合，可靠又快。
- 提升层：工作流（跨 agent 契约）。
