## 落地 5 独点（每点标注提升层）

### 1. Agent 可观测三支柱与 OTel GenAI 语义约定（工具）
来源：openlegion / niteagent / exemplar / devops.gheware / zylos / llm-academy
- **三支柱**：traces（层次化 trace+span 树——工具调用/sub-agent 步=活跃推理回合的 child span；**上下文层级断裂就失去"为什么走到这"的追踪能力**，父-子关系必须保留）/metrics（TTFT/latency P50/P90/P99/token 使用量）/logs（结构化、带 trace_id）。
- **OTel GenAI semantic conventions（v1.29+，2024-11 合并）**：标准化 span 属性=gen_ai.system（provider）/gen_ai.request.model/gen_ai.usage.input_tokens 等——与已有观测栈（Datadog/Honeycomb）无缝集成；2026 标配=OTel-GenAI+OpenInference+eval-as-span-attribute 三层。
- 选型：LangSmith（LangChain 原生零配置，SaaS 专有）/Langfuse（开源、框架中立、可自托管、细节更丰富但 overhead 更高）/OTel（团队已有观测栈就选它）——**不用专有 agent SDK 的专有格式，用厂商中立标准**。
- 提升层：工具（观测基础设施）。

### 2. Eval-Driven Development 四阶段流水线（工作流）
来源：braindrip / chiraghasija / dailyaiworld / arxiv-2601.22025 / kunalganglani
- **四阶段**：local dev（快速反馈）→PR check（挡回归）→deploy gate（预生产质量栏）→production monitor（漂移检测）——**替代静态 benchmark 的连续 eval 流水线**。
- **eval set 来自真实生产失败，不用合成数据**——把线上失败 case 变成 eval case 是最高杠杆；LLM judge 有可测偏置（verbosity/position）需机械修正。
- golden set=固定输入+标注期望输出（或质量标准），分数跨时间追踪、可门禁部署；**从生产采样并加权最难的 10% 输入**（模糊失败/边界 case）；prompt 当版本化 artifact，每次改动跑 golden set，按 slice（非整体）超回归阈值即失败构建。
- 提升层：工作流（评估驱动开发）。

### 3. trace-to-dataset 回环 + per-turn gate（工作流）
来源：dailyaiworld / autoolize / futureagi
- **生产 trace 转 eval 集**：把线上失败的执行轨迹变成回归用例（trajectory eval/工具使用正确性/成本/延迟预算）——"**能跑得快的团队是那些门禁先抓住自己回归的团队**"。
- **per-turn gate**：每次发布采样 30 条生产 turn 用 stripped judge 打分，最差样本决定过不过——5 分钟级快速套件。
- 3 层 harness：golden traces（夜间跑，50 条≈$10-15/月 judge 模型成本）+judge 校准+**季度重策展 golden traces**（每 agent 约 1 工程师日/季度）。
- 提升层：工作流（trace 闭环）。

### 4. 成本归因与预算执行（工具）
来源：sentry / agent-eval-harness / mlflow / aiworkflowlab
- **per-turn/per-trajectory 成本**（8 模型计价）+budget 执行与告警+延迟预算（P50/P90/P99 SLA 执行）。
- **按自定义维度切片 trace 数据**：user tier/feature flag/experiment group——回答"谁是最贵的用户""哪个 feature 值得花钱""缓存策略省多少"（默认 dashboard 答不了）。
- MLflow 模式=**每次 AI 调用一个 root trace**，llm.generate/chat、retrieval、tool.call、retries、auth、外部 API 全做 child span，**每个 span 挂 token+cost 属性**。
- 提升层：工具（成本观测）。

### 5. AgentTrace 三面结构化日志（可复用 Skill）
来源：arxiv-2602.10133 / tencent / machinelearningmastery
- **三面连续可检视的 trace 捕获**：operational（操作面=工具调用/状态变更/环境交互）/cognitive（认知面=推理步骤/决策）/contextual（上下文面=检索块/记忆读）——设计为**安全、问责、实时监控的基础层**，不是仅调试/基准（高敏领域采用障碍=静态审计对非确定性行为失效）。
- 腾讯云实战：logging_context={"trace_id":...}+span attribute+`_run_with_context(task, trace_id)`——**trace_id 贯穿所有后续操作**。
- 合规注意：把完整 prompt 文本倒进日志后端，在产生任何调试价值之前先制造合规问题——日志策略先审再记。
- 提升层：可复用 Skill（Agent 可观测日志规范）。
