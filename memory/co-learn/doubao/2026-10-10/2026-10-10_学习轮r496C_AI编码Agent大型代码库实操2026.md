## 落地 5 独点（每点标注提升层）

### 1. 代码库索引三策略（工具）
来源：zylos / danieljohnmorris / fp8 / theairuntime / cursor
- **无预索引 agentic search**（Claude Code）：给模型文件系统工具（Glob 模式匹配/Grep ripgrep 包装/Read 加载），按需探索，零预计算零背景索引——Anthropic 2026-02 实证。
- **全 repo embedding 索引**（Cursor）：首次打开建全仓向量索引、随编辑增量更新；**Merkle tree 检测变更文件→只重嵌变更块**+embedding 按 chunk 内容缓存+Turbopuffer 近邻检索；语义查询强、但漏结构关系。
- **AST 符号索引**：tree-sitter 解析提取函数/类/类型/常量存 flat JSON；agent 按**稳定 ID** 请求符号、工具 seek 到源码字节偏移；SymDex 叠加语义 embedding 支持按意图搜；**精确匹配叠 BM25 关键字排行**（Sourcegraph Cody 实证）补纯 embedding 短板。
- 提升层：工具（代码检索选型）。

### 2. 大型 repo 单 agent 三失效模式（工作流）
来源：dailyaiworld / aicostcheck / augmentcode
- **三失效**：context overflow（上下文溢出）/plan drift（计划漂移）/stale index（索引陈旧）——**大型 repo 打破单 agent**；并行 helper agent 把失效转成**隔离 per-lane 工作**。
- **每 helper 跑 typed contract+path slice**——contract 是 conflict converger 安全合并车道的**单一事实源**；checkpointing（Redis）+retry/backoff（重试前先重建索引）让 swarm 可恢复、重试诚实。
- 提升层：工作流（规模化失效认知）。

### 3. git worktree 物理隔离并行（工具）
来源：aitoolsguidebook / popularaitools / baeseokjae / developersdigest
- **`claude --worktree <name>`（2026 初原生）或 isolation:worktree frontmatter**——每个 subagent 独立 worktree（临时分支+repo 副本），**物理上无法互相覆盖**，最后合并；比协调锁更可靠。
- 教训：非并行任务别硬塞 swarm（用 sequential/autonomous 单 agent 长跑）；**共享 checklist 文件会变 merge conflict**——协调开销随 agent 数非线性增长；Worktree 纪律+更频繁 merge checkpoint 把破坏隔离到单分支（Grit 项目教训：未协调并行写差点毁测试基架）。
- 提升层：工具（并行隔离）。

### 4. Orchestrator-Subagent 模式与长跑上下文压缩（工作流）
来源：addyosmani / akshansh / david-cheong / arxiv-2610.02163 / mech
- **顶层 orchestrator 分析 repo 拓扑→拆独立架构单元→并发起 headless subagents**（先试 subagents 最简单模式）；**Task 工具子 agent 自带上下文窗口、只回摘要给父**——research 子 agent 读 20 文件只交摘要；层级 CLAUDE.md 四层加载（managed→user→project→directory-scoped）防 token 膨胀。
- **AutoCompact**：长轨迹编码 agent 把「何时压缩/保留什么工作态/如何继续」学进 policy——**早期探索变陈旧是常态，压缩不止防溢出**（与 r494B 上下文工程互补：那条管通用上下文，这条管编码长跑专用）。
- 提升层：工作流（编排+长跑上下文）。

### 5. 验证器门 + 多 agent 编码流水线（可复用 Skill）
来源：zeronoise / aicostcheck / mech / dailyaiworld / banegasn
- **validator gate 高于人审门**：只有**绿色测试报告**才把 merged changeset 推进到 diff 评审——机器门优先于人眼门。
- **多 agent 流水线**=repo scout（映射文件与依赖）→planner（实现计划）→coder（改文件）→test（跑命令总结失败）→reviewer（批判 diff）→security（查风险路径）→PR agent（写 PR/changelog/migration）——**像小工程团队而非单工具**；Open SWE=main agent 委托 code editor/test runner/doc writer 子 agent（状态机 handoffs+backpressure）。
- hard gates+**stack PR 堆叠冲突工作**（Ben Vinegar：6 checkouts 多小时作业，问 agent 哪些作业相交、不相交委托 subagent）；质量地板=coverage 94%（Ronacher Hunk 案例）。
- 提升层：可复用 Skill（规模化编码流水线）。
