## 落地 5 独点（每点标注提升层）

### 1. 并行工具调用运行时纪律（工作流）
来源：ai-tldr / langchain / 72tech / mlm / futureagi
- **parallel when independent, sequential when dependent**；read-only 工具（search/fetch/lookup）用 Promise.all/asyncio.gather 并行，有副作用/依赖的串行。
- **disable_parallel_tool_use: true（Anthropic tool_choice 上的标志）**限制每 turn 最多一个工具调用——副作用工具用；LangChain return_direct=True=批内所有工具完成才路由 END，最终响应含每个工具的 ToolMessage 输出。
- **并行开启时必须收集并一起提交全部工具输出**，否则实测触发 "No tool output found" 错误；把 parallel_tool_calls=false 序列化可减少该错误——性能 vs 可靠性按负载权衡。
- 提升层：工作流（并行调用决策）。

### 2. 函数调用五形状与 tool_choice 控制（工具）
来源：thepromptbench / loooop / cursuri / aiworkflowlab
- **生产收敛五形状**：①单强制工具调用（提取）②并行工具调用（一轮多查询）③tool_choice 控制（auto vs required vs named tool——按任务该给多少自由度）④extract-then-act 拆分（LLM 不进执行路径）⑤agentic 循环用**显式 done tool+固定迭代预算**终止——模型过调用工具，预算封顶是必要的。
- **server 侧校验工具名与参数再执行，别假设工具名可信**（同名工具防御，与已落工具面安全互补）；并行工具调用是主流模型标配（GPT-5/Claude 4.6/Gemini 2.x），多步工作流延迟可大幅削减。
- 提升层：工具（调用形态选型）。

### 3. MCP 2026-07-28 规范与授权硬化（工具）
来源：mcp-blog / rust-sdk / loooop / nerdleveltech / dev-production-mcp
- **2026-07-28 新特性**：server discovery & negotiation/transport-neutral subscriptions/long-running tasks/response caching/multi-round-trip requests/标准 HTTP routing headers。
- **Authorization Hardening**：客户端必须验证授权响应里的 **iss 参数（RFC 9207）**——低成本防 mix-up 攻击（MCP 单客户端多服务器部署更普遍）；OAuth 2.1 远程服务器/OIDC discovery/JWT 校验 aud/iss/exp/JWKS 轮换；**model tool capabilities 建模成 OAuth2-like scopes 映射 RBAC 角色**；每个工具调用发结构化审计事件。
- SDK 保持 patch：TypeScript SDK 1.26.0 修过跨客户端数据泄漏 CVE-2026-25536。
- 提升层：工具（协议工程）。

### 4. 工具错误三分流 + 失败分类矩阵（可复用 Skill）
来源：ai-tldr / niteagent / orderstack / genai
- **错误三分流**：①运行时 backoff（模型永远不见——模型也无能为力的错误，如瞬时网络）②surface 给模型（坏参数/无结果/校验错——返回清晰错误串，让模型修正下次调用——**LLM-friendly 错误处理核心**）③abort 任务（致命不可恢复）。
- **失败分类矩阵**：transient（秒级自愈）→指数退避+抖动 vs persistent（不会自然消失）→升级/降级/通知。
- **可靠性乘积效应**：90% 单调用可靠性=10 步后仅 35%——**可靠性必须逐工具设计**，不能只盯着单次调用。
- 提升层：可复用 Skill（错误处理规范）。

### 5. verify-before-retry + 三诚实选项（工作流）
来源：arxiv-2608.02645 / hidekazu / agentnative / aiflowreview / dev-idempotency
- **verify-before-retry 包装**：不确定工具结果时，先查预期后置条件是否已满足——已成功→免不必要重试；未成功→带更好证据重试——轻量系统级包装，不改 LLM 即提升可靠性（非原子失败场景）。
- **三诚实选项**（设计时每工具选一，远胜事故中决策）：compensate（语义逆操作：取消/删行/撤销授权——要求逆操作存在且安全）/幂等（同逻辑动作同 key）/escalate（无法确认安全时上报）。
- 幂等 key 从稳定业务意图生成（run ID+step ID+attempt 无关操作哈希），**永不由时间戳/重试计数/LLM 输出生成**；post-dispatch 超时进 unknown 状态做对账（不与已落他方幂等键生成重复——那条管 key 怎么算，本条管"不确定结果后怎么决策"）。
- 提升层：工作流（不确定结果决策）。
