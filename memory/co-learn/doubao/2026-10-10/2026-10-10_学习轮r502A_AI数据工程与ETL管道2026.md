## 落地 5 独点（每点标注提升层）

### 1. Agentic ETL 四代理编排（可复用 Skill）
来源：inductivee / callsphere / braindrip / csdn
- **四代理分工**=Schema Discovery（反解源 schema）/Data Quality（验证+异常检测）/Transformation（按 schema+业务规则写 dbt 模型）/Pipeline Orchestration（监控运行+诊断失败）——schema 变更故障 MTTR 从小时级到分钟级，消灭"没人知道坏了"类故障。
- **范式迁移**="管道即代码"→"智能体即管道"：确定性规则+静态 schema+批调度 → 概率推理+上下文感知+动态决策；**共识模式=agent 提议变换→确定性验证器（schema 检查/统计边界/结构化输出强制）确认→失败升级或拒绝；端到端全自主是童话**。
- 提升层：可复用 Skill（管道编排）。

### 2. LLM 变换代码生成与评审纪律（工具/工作流）
来源：dzone / datasumi / henrybernreuter / techdailyshot
- **清洗规则→LLM 生成 Pandas/SQL 代码+单元测试+注释→当代码工件走版本控制/代码评审/自有基础设施执行**——不是热路径黑盒 API 调用（其成本单独算）。
- **阶段分工**：Extract=确定性解析器+分块，LLM 只用于 OCR/格式歧义；Transform=AI 主场（抽取/分类/富化），配**硬 schema+短 max_tokens+按任务选对模型**；Load=哑加载，不放 LLM。
- 提升层：工具（生成）+ 工作流（评审）。

### 3. 验证层=断路器（可复用 Skill）
来源：getdbt / dredyson / henrybernreuter / enhancedmlops
- **验证层在 build 阶段跑测试查询**（SQL SELECT 验证 schema 完整性/null 约束/分布偏移）：0 失败行→通过；有失败→**管道 halt**——防止异常数据进推理引擎引发幻觉；配 dead-letter queue + null rate 监控 + Pydantic schema 强制。
- **逐步 schema 校验**：每步输出对照期望 schema 校验后再传下一步（案例：Great Expectations 质量分 91%→98.7%，关键=验证内建进工作流架构而非事后补）。
- 提升层：可复用 Skill（质量门）。

### 4. 语义漂移 vs 结构漂移（可复用 Skill）
来源：atlan / vexdata / ovaledge
- **语义可观测性**：监控字段"业务含义"随时间漂移——**列能通过全部结构检查而其业务含义已因上游变更/策略更新改变；语义漂移=对特定业务定义校准的 agent 产生自信的错误输出且无结构异常可触发告警**。
- **feature drift 监控**=推理分布 vs 训练基线；**null 率偏离训练基线 >10% 即告警**；**out-of-distribution 检测路由异常输入到回退/人工评审，而非用假自信打分**。
- 提升层：可复用 Skill（可观测性）。

### 5. 记录级验证 + 硬门禁（工作流）
来源：digna / databricks / hernanhuwyler / dataiku
- **记录级验证在入管道前执行**：不完整记录/无效值/复合键重复/引用完整性——**LLM 不可能比它读的记录更可靠**；自动化验证套件把质量期望写成代码（行数/null 率/引用完整性/关键字段统计属性），可复现可版本化每次跑。
- **硬门禁 vs 聚合分数**（ISO 5259/NIST）：关键质量要求用硬门禁替聚合分数——聚合分可被高分项掩盖单点致命缺陷；**AI 异常检测学"正常长什么样"再标记偏离**，不必维护易碎阈值库（捕获静默失败：技术合法但统计上不可能的取值）。
- 提升层：工作流（验证前置）。
