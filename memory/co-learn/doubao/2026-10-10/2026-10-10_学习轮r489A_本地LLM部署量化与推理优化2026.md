## 落地 5 独点（每点标注提升层）

### 1. 量化等级判据与非线性损失曲线（可复用 Skill）
来源：vucense / runaihome / inventivehq / runlocalmodel
- **选模型规则**：先选能在 Q4_K_M 装下的最大模型+目标上下文；VRAM 剩余>25% 升 Q5_K_M，再剩余>25% 升 Q6_K。
- **perplexity 损失实测**（Llama 3 8B vs FP16）：Q8_0 +0.003 / Q6_K +0.022 / Q5_K_M +0.057 / Q4_K_M +0.175 / Q3_K_M +0.657 / Q2_K +3.52——**损失非线性，约 4 bit 以下陡升**；Q4 对标准基准损失约 1-3%。
- 提升层：可复用 Skill（选型判据）。

### 2. VRAM 预算速查与甜点区间（工具）
来源：localllm / checkaimodels / gillilab / coursify
- **4bit 速查**：7B≈4.5GB / 13B≈8-10GB / 34B≈20-24GB / 70B≈26GB（Q2_K 70B≈25GB 但慢）。
- **甜点=8-12GB VRAM**：7-8B 模型 Q4_K_M 跑 40+ tok/s；入口卡 4-6GB 也可跑但慢；个人使用 INT4 起步（省 75% 显存、质量损失个位数百分比）。
- 提升层：工具（选硬件/模型）。

### 3. KV cache 量化与上下文内存治理（工具）
来源：markaicode / ollama 官方模型卡 / docs.ollama.com
- **KV cache 默认 f16，量化到 q8_0 或 q4_0 可减半（或更多）长上下文每 token 内存成本**：`OLLAMA_KV_CACHE_TYPE=q8_0`（或 q4_0 更激进），官方支持；`num_ctx` 控制上下文长度（默认较小）。
- 长上下文=内存大头，先量 KV cache 再算能装多大模型。
- 提升层：工具（Ollama 配置）。

### 4. Ollama 并发驻留与 Modelfile 调参（工作流）
来源：markaicode / gntech / sitepoint / docs.ollama.com
- **并发**：`OLLAMA_NUM_PARALLEL=2-4`（高显存卡饱和批容量，默认 1）、`OLLAMA_MAX_LOADED_MODELS=2`（默认 1 或 3）、keep_alive 高频用 30m/省显存 30s 释放 VRAM；`ollama ps` 看当前加载模型与驻留。
- **Modelfile 自建**：`num_gpu 32`、`num_ctx 4096`、`num_thread`=物理核数；`ollama create` 自定义 GGUF；吞吐目标 30-45 tok/s。
- 提升层：工作流（本地部署调优）。

### 5. 本地 AI 栈与 IDE 集成（工作流）
来源：gillilab / gntech / sitepoint / effloow
- **个人栈**：Ollama（推理引擎）+Open WebUI（聊天/管理 UI），docker compose 部署（nvidia 设备 reservations）；Open WebUI 的 embedding 模型移 CPU（`DEVICE_TYPE=cpu`）省显存。
- **IDE 集成**：Continue 扩展接本地端点做补全/对话；CUDA OOM 先量化 KV cache+embedding 移 CPU。
- 提升层：工作流（个人 AI 环境）。
