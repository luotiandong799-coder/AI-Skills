## 落地 5 独点（每点标注提升层）

### 1. 范围定义先行 + 60/40 分工（可复用 Skill）
来源：aiunpacker / felloai / firecrawl
- **打开搜索工具前先写范围定义**三件事：这次研究会支撑的决策（"建移动 App 还是 PWA"）、在范围内（市场数据/用户行为/性能基准/开发成本）、范围外（具体厂商谈判/内部团队容量）——书面边界告诉 AI 查什么、忽略什么。
- **60/40 分工**：Research 模式做前 60%（landscape 测绘/来源发现/术语/利益相关者/初稿综合——这阶段又快又准）；人类做后 40%（读源/逐条核查/解释/判断/写最终结论——专长所在，工具替代不了）。
- 提升层：可复用 Skill（搜索前纪律）。

### 2. 三档模式路由 + 引文纪律（工具）
来源：frankx / techsifted / aiclicks / discoverai
- **模式三档**：Quick Search（单次回答）→ Pro Search（多子查询+读更多源+跨源推理，**设为默认**）→ Deep Research（规划研究方案/跑几十次搜索/返回带引用的结构化报告，给"值得一份报告的问题"）。
- **引文纪律**：点开 2-3 条引文确认来源真的说了 AI 说的（尤其统计和具体主张）；"最重的习惯=别信"——每条关键点要求引文、开链接验证；**Academic 模式**留给需要同行评审的、**Reddit 模式**看真实用户情绪。
- 提升层：工具（搜索模式选择）。

### 3. 每日简报自动化管线（可复用 Skill）
来源：genai / agentroost / hermes / bvm / yyh211
- **核心管线**：RSS XML→HTTP GET 抓取→解析最近 24h 标题+描述→作为 user message 发给 LLM+system prompt（定义关心什么+输出格式）→LLM 摘要并给相关性 1-10 评分分类→结构化输出（JSON/编号列表）→投递（Telegram/Discord/邮件/Slack）。
- **n8n 落地**：Schedule Trigger 定时→RSS Feed Read 一次读多源→IF 节点过滤周末/低质→单 Chat Model 节点写摘要排序（**prompt 工程干重活**）；4 阶段工作流=收集（直抓 3-5 大站+带日期过滤的 web 搜索）→过滤→分类→呈现；92 源并发抓取+可配置时间窗。
- 提升层：可复用 Skill（简报自动化）。

### 4. 搜索模式与源权威排序（工作流）
来源：aofirs / lobehub / arai / sina
- **AI-guided dorking**：prompt 里嵌高级搜索逻辑（Boolean 运算符/site: 域限制/filetype:）绕过浅层聚合、直取权威域与特定文件类型——AI 帮你把"模糊念头变精准指令"（拆维度+组合限定词+明确意图三步）。
- **引用前源权威排序**：官方文档/API 最高→RFC/规范（标准权威）→GitHub issues/讨论/源码（库权威）→高票 Stack Overflow/维护者博客→普通博客教程（没更好的才用）→SEO 内容最低；**5 个高定向 query 优于 1 个模糊 query**，优先一手来源。
- 提升层：工作流（检索纪律）。

### 5. 模型路由 + 结果验证（工作流）
来源：getspike / tryanalyze / devtripathi / mslearn
- **任务匹配模型**：ChatGPT 构思/Gemini 生态数据/Perplexity 实时网络研究/Claude 深度分析——**prompt 有效性取决于匹配对模型**；最大杠杆=grounding（喂 Search Console 导出/竞品页面/站内爬取数据，换站级建议而非泛论）。
- **fan-out 机制理解**：AI 收到复杂 prompt 会拆成多个子查询分别跑（如"小 B2B SaaS 想…"被拆成若干定向检索）——你的 prompt 越结构化，子查询越准。
- **验证纪律**：每个输出关键词对照真实搜索数据验证、比较独立来源并标出矛盾、不信单一 AI 断言；prompt 有效≠泛化，仍须验证响应。
- 提升层：工作流（模型路由+验证）。
