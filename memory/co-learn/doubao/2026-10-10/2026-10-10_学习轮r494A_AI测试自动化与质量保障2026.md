## 落地 5 独点（每点标注提升层）

### 1. 测试生成的对抗化与变异验证（工作流）
来源：arxiv-2602.08146 / aitoolsguidebook-ai-test-generation / softwaretestpilot / theneuralbase
- **"给这函数加测试"产出的是镜像实现的测试——永远通过、什么都不抓**；修法=把生成做成对抗：①先问 AI edge cases ②再写测试 ③**变异函数确认测试会失败**；预算 15-30 分钟/非平凡函数。
- **ADVERTEST 双 agent 对抗**：测试生成 agent T 配 mutant 生成 agent M——M 持续造 mutant "hack" T 当前套件的盲区，T 迭代细化测试去"杀"难 mutant——交互由双方启发式引导。
- **AI 生成的测试默认太宽容**（AI 想让代码过、不想破坏）：生产代码库 500+ AI 辅助文件而不做变异验证的团队报告 2.3x 逃逸缺陷；property-based 测试（Hypothesis）补 AI 训练数据未覆盖的 edge case。
- 提升层：工作流（对抗式测试生成）。

### 2. 覆盖指标陷阱与变异分数 KPI（工作流）
来源：botmonster / softwaretestpilot-chatgpt / augmentcode
- **80% 覆盖陷阱**：2026 实验 AI 套件 93.1% 行覆盖、仅 58.6% 变异分数——**超 1/3 现实 bug 溜过且 CI 全绿**；行覆盖只测执行不测检测——套件能跑每行却不断言任何正确性。
- **覆盖强度阶梯**：行覆盖最弱（trivial 测试即刷）→分支（真实）→函数（≥90%）→**变异分数最强**（测试真的断言才杀 mutant）；100% 变异不值得，**75-80% 是行业甜点**。
- **变异分数当 KPI 而不是覆盖率**：覆盖变 KPI 时开发者/AI 用 trivial 测试刷数字；不断言真实行为的测试杀不掉 mutant，难刷。
- 提升层：工作流（质量度量选择）。

### 3. AI 生成测试五门验证（工具）
来源：scrolltest / aitoolsguidebook-tests-pass / softwaretestpilot / alexcloudstar
- **每份 AI 生成测试过五门（按成本升序跑）**：①能编译（type checker+dry-run）②断言有效——**断言必须查具体值，禁 bare toBeDefined/toBeTruthy**；要求测试引用外部 oracle（PR 描述/需求文档/先前稳定测试），只断言"函数返回函数返回的"拒收 ③**不 mock 数据库/HTTP/支付 API**（用 msw/Testcontainers 真依赖）④变异测试（npx stryker run）变异分数≥70% ⑤覆盖目标路径（能杀原 bug 的回归测试）。
- **false-green 最快修法**：手写一条回放真实失败输入的端到端测试（真/staging 库+API）——套件仍绿而它失败=证实单元测试从未走该路径，并成回归门禁；再审计 mock 清单、强化弱断言——1 小时内表面 50% 假绿。
- 提升层：工具（生成测试验收管道）。

### 4. TATG 追踪感知测试目标与 flaky 治理（工具）
来源：arxiv-2607.03194 / llmversus / augmentcode
- **TATG 统一目标表示**：每条测试需求记 evidence/setup/action/oracle/acceptance criterion/status/去重键——细粒度跟踪哪些需求已满足、哪些未决；两阶段工作流=静态分析+动态反馈，生成中持续更新目标状态。
- **flaky 治理**：每个失败测试**跑 3 次才报失败**；通过≥1 且失败≥1 的自动隔离（quarantine）；按测试文件跟踪 flake 率、**超 2% 报警**。
- **tautological assertions 与 coverage-effectiveness gap**：生成测试确认现有行为（含 bug）=确认偏差；通过但 0% 变异分=覆盖仪表盘跑行不验行为——前者靠 oracle 审查+变异测试，后者靠变异敏感性。
- 提升层：工具（测试目标追踪与 flaky 隔离）。

### 5. Agent 生产回归门禁与 eval CI（可复用 Skill）
来源：harness-ai-evals / harness-agenttrace / dailyaiworld / baeseokjae / pypi-evalview / devblogs-microsoft / futureagi
- **eval gate 进 CI**：候选与当前生产版本跑同一 golden set，**候选比生产统计显著差 >5% 即失败**（绝对阈值随数据集老化失效）；shadow mode+canary rollout 拦 65% 回归于用户之前；硬阻断=smoke eval 完成率掉>5 点/全量掉>2 点、p95 超绝对 SLO、安全集任何 guardrail 违规>0、任何单测/契约测试失败。
- **生产失败转回归用例闭环**：AgentTrace 把生产失败转成回归测试用例；traces-to-dataset 把生产 trace 转结构化评估数据集补离线覆盖；trace replay 可视化逐步回放执行。
- **evalview 模式**：snapshot agent 行为（工具调用/参数/顺序/输出/成本/延迟）diff golden baseline——行为一变立刻知道；评估结果与生产监控同看板、分数与错误率/延迟/用户参与度关联。
- 提升层：可复用 Skill（Agent 回归门禁管线）。
