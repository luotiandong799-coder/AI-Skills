## 落地 5 独点（每点标注提升层）

### 1. 工具 schema 质量与 strict subset（工具）
来源：aiworkflowlab / developersdigest / jeff-pdc / ai-tldr / futureagi
- **schema 质量是工具调用可靠性的最大预测因子**——写对去掉了生产中 60-80% 工具调用失败（幻觉字段/非法 enum/错误参数形状/静默丢必填）：动名词命名（search_web/create_ticket）、描述无歧义标注何时用、强类型参数+**enum 替代自由字符串**、required 显式。
- **strict subset 写法**：每个对象 `additionalProperties:false` 并枚举全部属性；每个属性进 `required`，**可选用 union 含 null 表达而非省略**（`type:["string","null"]`）；constrained strings 用 enum（`"celsius"|"fahrenheit"` 模型不会幻觉第三选项）；`format` 提示（ISO date）；数值 `minimum/maximum` 约束——模型尊重数值边界。
- 提升层：工具（schema 设计）。

### 2. 并行调用决策规则与 LLM Compiler（工作流）
来源：machinelearningmastery / ai-tldr / zylos / aipromptshub
- **并行判据=依赖**：工具 B 需 A 输出→串行；都能用已知信息→并行候选；I/O-bound（数据库/API）调用并行收益最大；LangGraph ToolNode 用 asyncio.gather 自动扇出多调用并单消息回结果；`parallel_tool_calls:false` 限单工具每轮。
- **并行结果矛盾→先定义消解策略**（两价格源不一致谁优先）再让模型综合；**LLM Compiler 模式**：多工具复杂流程让模型产出 DAG（显式依赖声明），编排器拓扑序执行——独立节点并行、依赖节点只等直接父节点。
- 提升层：工作流（并行编排）。

### 3. 失败分类矩阵与恢复架构（工具）
来源：niteagent / alicelabs / navendu / tomodahinata
- **失败分类两行**：Transient（秒级自愈=HTTP 429/网络抖动）→指数退避+jitter；Persistent（不自愈=provider 宕机/资源已删）→升级/回退/通知——**分类路由到对应恢复策略**。
- **重试逻辑/回退路径/显式错误处理建在编排层不在 prompt**；bound retries and loops（上限防死循环）；**幂等键防副作用工具双执行**，指数退避只用于幂等操作；Temporal 式 activity 包装=60s 超时+最多 5 次指数退避。
- 提升层：工具（恢复架构）。

### 4. 应用层边界验证四步（工作流）
来源：swarmsignal / tomodahinata / nalar
- **不把模型工具调用直接传给 API**：先验必填参数存在→验类型→enum 对照允许集校验→**拒绝畸形调用并让模型重试**（护栏可捕获大量参数幻觉错误）；LLM 输出是外部输入，边界用 Pydantic 验证+`additionalProperties:false`/`extra:forbid` 拒多余键。
- **工具结果当数据不当指令**（外部数据同样不可信，confine 到 tool_result）；权限从可信状态检查不信任调用者声明；敏感写操作比读更强执行控制（allowlist+人工确认闸门）。
- 提升层：工作流（边界安全）。

### 5. 结构化输出三级可靠性（可复用 Skill）
来源：baeseokjae / techearl / aiworkflowlab / kanopylabs
- **三级可靠性**：① prompting（低）→② function calling/tool use（成功率 95-99%，大多数生产应用够用）→③ native structured output（`response_format`/Structured Outputs，最高）。
- **供应商差异**：OpenAI 返回 JSON 字符串参数需 parse；Anthropic/Gemini 返回已 parse 对象；OpenAI 配 `strict:true`、用单工具模式提可靠性；失败回路=schema（Zod/Pydantic）校验→失败带错误重试。
- 提升层：可复用 Skill（结构化输出选型）。
