## 落地 5 独点（每点标注提升层）

### 1. 分块策略：结构感知优先，固定切分是反模式（工作流）
来源：saram / arika / convly / ms-databricks / arjunjaggi
- **固定 500 字符切分会断句子/分离标题与内容/拆表格——最快毁检索质量**；结构感知分块=按标题层级/自然段落/语义边界切，列表/代码块/表格保持完整，FAQ 按问答切。
- **2026 实证默认**=递归字符切分约 512 token+10-20% overlap（overlap 提 dense recall 最高约 14.5%）；文档类型→策略映射（API 参考按节/FAQ 按问答/长文按语义）。
- **别过度调 chunk size，优先做元数据信息抽取**（实体/主题/类别→精确过滤）——比调 size 影响更大。
- 提升层：工作流（分块策略）。

### 2. 嵌入模型选型与成本质量权衡（工具）
来源：aipromptshub / kunalganglani / sailokeshdevathi
- **text-embedding-3-large**（$0.13/1M，3072 维，MTEB 64.6）=英文企业安全默认；**3-small**=大模型约 80% 能力、1/6 成本（$0.02）；**Matryoshka 可降到 256 维不减查询质量**。
- embedding 精度在长段落下降→分块；**语言检测→路由正确嵌入模型**（多语料库必配）。
- 选型判据：先按语言/领域/预算圈定，再在自有数据上跑 MTEB 风格小评测，不靠宣传。
- 提升层：工具（选型方法）。

### 3. 混合检索+RRF+重排的实证收益（工作流）
来源：vortx / ms-databricks / lobehub / arxiv-2604.01733
- **72% 企业生产 RAG 用 hybrid**（dense+BM25+RRF 融合）——recall@10 91% vs dense-only 约 78%；两阶段 pipeline（hybrid+neural rerank）Recall@5 0.816/MRR@3 0.605，大幅超单阶段。
- **top-10-20 过 cross-encoder 重排**（BGE-Reranker-v2-m3 开源）——重排≈**一行改动约 15% 质量提升**（高 recall 低候选数）。
- 提升层：工作流（检索链路实证）。

### 4. 检索评估与查询工程（可复用 Skill）
来源：ms-foundry / arxiv-2606.28737 / arxiv-2604.03455 / aclsemeval
- **检索质量=Recall@k/MRR/nDCG；生成质量=faithfulness**（Fidelity/NDCG evaluator 现成可用）。
- **多轮 RAG 实证**：LLM 查询改写提 recall +14.5%、nDCG@1 +40%（扩覆盖）；LLM 重排 nDCG@5 +17.7%（精排序）——**改写与重排两阶段各司其职**。
- **查询路由实证**：TF-IDF+SVM 达 93.2% 准确率且省约 28.1% token——**词面关键词特征比语义嵌入高 3.1 F1**，简单路由先于昂贵 paradigm；answerability 校准比 retrieval coverage 更是端到端瓶颈（多轮 RAG 第一团队实证）。
- 提升层：可复用 Skill（评估与路由方法）。

### 5. 生产索引运维：hash 免重嵌/两级去重/增量 CDC/分批索引（工作流）
来源：arpitbhayani / arxiv-2601.05270 / ceur / yangyitao / lobehub-rag-production / borghei / premai
- **content hashing 第一闸**：文档到达算 hash 匹配 registry 即跳过——大多数"更新"只是元数据变化（标题/时间戳）不需重嵌；chunk 级 SHA-256 变化检测=跨文档自动去重+只重处理改过的内容。
- **两级去重**：MinHash LSH（近似重复文本）+SemHash（语义重复——措辞不同信息相同，130K 样本 7s）。
- **增量索引三通道**：源库 CDC（Debezium/Postgres logical replication）/文件 diff（sha256+last_modified 变更才重处理）/事件驱动（doc.created/updated/deleted 进队列）。
- **分批全量**：按优先级 P0（产品手册/FAQ）→P1→P2，每批独立可发布——P0 跑完就上线核心场景；**staleness 当 SLA 监控**（文档更新到索引可用时延）。
- **fallback 纪律**：主库挂用只读副本；检索低于阈值**明确说"没有"不说假话**；简单查询只走 BM25 省钱。
- 提升层：工作流（索引运维）。
