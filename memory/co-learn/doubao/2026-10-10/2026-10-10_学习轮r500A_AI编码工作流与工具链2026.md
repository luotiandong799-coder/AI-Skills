## 落地 5 独点（每点标注提升层）

### 1. 信任-验证缺口与无限探索治理（工作流）
来源：code.claude-best-practices / cursor-agent-best-practices
- **trust-then-verify gap**：AI 产出看似合理实现但没处理边界情况——修复=**总是提供验证（测试/脚本/截图），无法验证就不要接受**。
- **infinite exploration**：让 agent "调查"不设范围会读几百个文件塞满上下文——修复=**缩小调查范围或用 subagent**，让探索不消耗主上下文。
- 提升层：工作流（会话治理）。

### 2. 编码会话五步 + checkpoint 提交（工作流）
来源：developersdigest / blink / agenticbook / autohand
- **五步**=plan→build→review→test→ship；先 plan mode 列方案再写码；视觉审 diff+手动测功能；跑测试套件修失败。
- **每 3-5 任务或跨逻辑边界（完成 auth/开始数据库层/开始 API 面）设 checkpoint**=跑测试套件+审 diff+**git commit**——commit 是关键，给你回滚点。
- **PIV（Plan-Implement-Validate）**=写计划→审计划→执行单步→测试验证→commit→重复；后台 daemon 不阻塞主终端；简单起步，agent 重复犯同一错才加规则。
- 提升层：工作流（会话节奏）。

### 3. subagent 工作流与 PR 自动化（工具）
来源：claude-code-power-user / claude-prompting-best-practices / claude-code-sub-agents
- **drop .md 到 .claude/agents/**=build-validator/code-architect/code-simplifier/verify-app 等专用 agent——把最常见的 PR 工作流自动化。
- **模型原生编排 subagent**（无需显式指令）——确保 subagent 工具定义良好；**防过度使用**（Opus 4 会过度委托）；探索类任务用 subagent 保护主上下文。
- 提升层：工具（subagent 模式）。

### 4. 重构不变量纪律 + Strangler Fig 顺序（可复用 Skill）
来源：whizi / bestaiweb / ailearningguides
- **先命名不变量再动重构**：public 函数签名/路由行为/事件名/响应形状/分析/权限/可访问性/性能预期——声明"什么必须保持一样"。
- **构建顺序（Strangler Fig）**：叶（无入站依赖模块，AI 可整体重写其余代码无感）→中（只依赖已重构叶的模块，seam contract 保护上游调用者）→根（共享基类/配置/DI 容器）。
- pattern replacement/大规模改名/框架迁移=AI 机械工作+人类判断的表面案例。
- 提升层：可复用 Skill（重构纪律）。

### 5. 多 agent 并行与验证质量门（工具）
来源：tembo / augmentcode / cursor
- **两个 agent 同时写码=并发问题，git 先暴露**——标准修复=git worktrees（一仓库多检出工作目录，各自分支，共享历史）。
- **验证是 multi-agent 编码瓶颈**（agent 生成比人审快）——质量门把"看起来对"转成可执行证据（测试/静态检查/策略执行），分层管道挡大部分回归；AI 代码可以看起来对实则微妙错——**仔细读 diff**。
- 提升层：工具（并行与质量门）。
