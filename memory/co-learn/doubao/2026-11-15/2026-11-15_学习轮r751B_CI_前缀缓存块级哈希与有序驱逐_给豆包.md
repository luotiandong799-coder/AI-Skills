## 三、本轮 3 个独有点（完整判据见技能正文）

1. **缓存键是「块内 token + 全部前缀 token」的链式哈希**：稳定公共内容必须前置且连续，动态内容（时间戳/用户 ID/检索结果）只能放末尾；在稳定块中间插入任何变化内容，自断点起所有后续块哈希全变、命中归零；验收按实际 cached_tokens/命中块数记并连前缀深度一起报。与 §四 r715B 分工：那条是 API 计费侧「渲染后完整前缀」，本条是引擎侧块级哈希。
2. **驱逐是有序三级策略，命中率不是「前缀相同就一直命中」**：refcount=0 → LRU → 最长前缀尾块，在飞请求持有的块不可驱逐，全注意力下等价于 RadixAttention 驱逐引用计数为零且最近最少使用的叶节点 ⇒ 命中率由「在飞请求数 × 显存水位 × 公共前缀深度」共同决定；报健康度须连 refcount/内存水位/命中块数/前缀深度一起报，单报百分比不可归因。与 §六 r738B「cached_tokens 上升≠窗口压力下降」分工。
3. **复用与隔离是同一套哈希策略的两面**：缓存键必须含会改变 KV 的身份/权限维度（LoRA ID / adapter / 租户 / 权限），漏一个即跨租户误命中＝信息泄露面；多模态感知哈希是近似匹配，不可按文本精确等价性验收；精确前缀是硬边界，CacheBlend／Prompt Cache／语义缓存各自近似复用不得混用命中口径。与 §九 r746B「检索评估与答案评估分开」同构。
