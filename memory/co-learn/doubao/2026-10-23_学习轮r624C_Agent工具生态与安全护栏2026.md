## 四、提炼核心方法与关键事实

1. **MCP 配置即攻击面**：stdio transport 直接执行 command/args 无 allowlist=RCE（CVE-2026-105697 实案）；工具暴露=权限授予（two-gate authorization）；enforcement outside reasoning layer（模型提议、安全层裁决）；治理层前置（definition scanning→policy evaluation→response inspection）。
2. **per-tool 最小权限矩阵**：task-specific identity 非 owner/admin credential；begin read-only+write tools 显式 allowlist；scope 变 re-issue token 不 edit long-lived；双重授权（server 侧+host 侧）；data exposure restricted by design 非 verbal instructions。
3. **审批门与执行权限四模式**：deny/allowlist/ask/full；生产用 allowlist（miss 显示 exact command 求人批）；human approval 清单（messages/deploys/deletes/purchases/refunds/production mutations）；HITL gates 系统级命令全过门。
4. **secrets 管理纪律**：vault 非 config；日志前 redact secret-shaped fields；never return tokens in tool responses；定期 rotate+暴露即转；KMS>Vault>Env Vars；credentials encrypted at rest+no API to read back。
5. **沙箱与网络隔离**：sandboxing=baseline control 非 optional；agent loop 环境 never hold credential worth stealing（reverse proxy 注入 real credentials）；egress default-deny 只放行 tools 需要的 endpoints；resource limits；runtime 高危工具组默认 deny 受控开。
6. **四层护栏与工具链审计**：input controls/action gating/output verification/runtime observability——no single filter enough；per-server enabled_tools/disabled_tools 防 tool-chaining；tamper-evident hash-chained 日志；record every call+scan secrets+deny by default（54% org 已遇 incident）。
