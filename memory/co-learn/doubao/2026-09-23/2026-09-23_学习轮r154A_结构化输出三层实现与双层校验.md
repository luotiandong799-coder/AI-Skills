## 二、独点清单 + 判非重复理由（4 点，均≥40% 独有增量）

### 1. 结构化输出双层校验：结构层 + 语义层分开测（来源：logic.inc 2026-05-20 实拉）
schema 合规≠答案正确——**结构测试**（可解析/必填/类型/enum 匹配）与**语义测试**（答案对输入正确/符业务规则/下游行为正确）两层分开跑；只过结构层会放行"格式对但内容错"（错分类/幻觉置信度/提取错值）。
- 判非重复：WB av 管执行产物验证（回归）；r153-B 点 2 管触发断言（CI）；本点管 **LLM 输出契约的双层测试设计**。增量≥50%。
- 提升层：工作流（输出校验）。

### 2. schema 字段顺序是推理顺序约束：reasoning 字段必须排在答案前（来源：n8n Community 2026-08-31 实拉）
结构化输出 schema 的字段顺序**结构性地决定了模型先输出什么**——把 `category` 排在 `reasoning` 前，模型被迫先给答案再补推理（"essentially guessing before thinking"）；把 `reasoning` 排到前面后分类一致性完全修复。schema 不是死数据契约，是活推理编排。
- 判非重复：未见已有覆盖（r150-153 批无"字段排序影响推理"条目）。增量≥70%。
- 提升层：工作流（结构化输出设计）。

### 3. 结构化输出实现分层：模型原生硬约束优先于 prompt 软约束（来源：n8n Community + OpenAI + Outlines 实拉）
实现结构化输出有三层可选：**模型原生约束**（Ollama format:json / strict structured outputs / Outlines FSM 把非法 token 置 -∞——生成级硬保证、无效 JSON 不可能出现）；**修复层**（validate_json 先验后修）；**prompt 层**（软约束，最弱）。选错层=白付校验成本。注意局限：TGI 语法引擎忽略 email/pattern 格式校验，需显式写规则。
- 判非重复：r153-C 点 4 管工具返回尺寸治理；WB r152-B 管参数修；本点管**结构化输出的实现层选择（硬约束优先）**。增量≥50%。
- 提升层：工具（输出契约实现）。

### 4. 提取/结构化节点内置成功-失败状态信号：__is_success + __reason（来源：Dify Parameter Extractor 实拉）
参数提取节点输出**自带状态变量**：`__is_success`（1/0）+ `__reason`（失败原因文本），下游直接按状态分支——失败原因结构化进流程，不靠"输出为 null 猜失败"。
- 判非重复：WB r152-C 管执行态/交付态分开记账（状态归因）；本点管**节点级提取状态信号内建**（失败语义随结果走）。增量≥50%。
- 提升层：工作流（提取节点设计）。
