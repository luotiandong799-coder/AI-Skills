## 二、独点清单 + 判非重复理由（4 点，均≥40% 独有增量）

### 1. 评测先行的技能开发：先写 should/should-not 触发测试 + 测无技能基线 + 最小指令过测（来源：anthropics/skills skill-creator + arXiv 2607.25032 2026-09-17 实拉）
写技能前先建 20 条触发评测（should-trigger + should-not-trigger 混合）；先在**无技能**的模型上跑代表任务记录失败点做基线，再写"刚好能过测试"的最小指令并迭代。描述触发信息必须放 YAML frontmatter——正文触发后才加载，"When to Use"写正文对模型无效。
- 判非重复：WB r151-A"实现后独立评审"管"写完评"；WB sa"frontmatter 闭合"管描述结构纪律；本点管"**写之前先定测试、先测基线（消融前置）**"——技能开发顺序反转为 eval-first。增量≥50%。
- 提升层：可复用 Skill（技能开发方法）。

### 2. 循环安全熔断双轨：Max Iterations 按任务复杂度分档兜底，与裁判驱动退出互补（来源：Dify Agent node docs 2026-08-27 实拉）
Agent 循环设迭代上限作**安全熔断**（防死循环烧钱），按任务复杂度分档（简单 3-5、复杂研究 10-15）；同时保留质量判据退出（裁判/验证器）——**上限管"最多跑多久"、裁判管"何时算完成"，两轨并存**。上限是数量保险丝，不是质量判据。
- 判非重复：WB r152-A"裁判驱动循环退出不靠固定迭代上限"管质量退出；本点补"**迭代上限仍必须存在作安全熔断**，且按复杂度分档"——两轨互补非冲突。增量≥50%。
- 提升层：工作流（循环治理）。

### 3. 失败六型分类 + durable job record/幂等键 + 部分完成的补偿追踪（来源：n8n dev.to 2026-09-09 实拉）
失败不只"瞬态/永久"两型，细分为 transient/validation/policy/budget/semantic/side-effect 六型；每个 AI 任务有持久 job 记录+幂等键；模型输出触碰副作用前先验证；部分完成时追踪补偿动作（不把半成品当失败丢弃、也不当成功放行）。
- 判非重复：WB r152-A"瞬态才重试/永久上报"是两型粗分；本点扩为**六型细分**（validation/policy/budget/semantic 归属明确）并加"副作用前验证+部分完成补偿追踪"——分类粒度与补偿机制增量≥50%。
- 提升层：工作流（错误处理）。

### 4. 插件运行期运维四则：SecretRef/allowlist/doctor/update（来源：clawdocs plugin-system 2026-07-08 实拉）
装完插件不等于结束：凭证用 SecretRef 不硬编码；生产环境设 allowlist 不置空；`doctor` 定期体检；`plugins update` 保持更新。与"装前审查"互补——**装前查、装后养**。
- 判非重复：WB r151-C 插件安装 10 项清单管"装前审"；本点管"**装后运行期运维**（凭证引用/白名单/体检/更新）"——生命周期后半段。增量≥50%。
- 提升层：可复用 Skill（插件生命周期治理）。
