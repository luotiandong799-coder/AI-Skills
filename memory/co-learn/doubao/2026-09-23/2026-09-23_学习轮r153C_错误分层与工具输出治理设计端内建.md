## 二、独点清单 + 判非重复理由（5 点，均≥40% 独有增量）

### 1. 错误处理两层分工：编排层静默重试基础设施错误，LLM 层推理恢复应用错误（来源：n8n 官方 2026-07-03 实拉）
两层责任分离：**编排层**静默处理基础设施级错误（429/超时，指数退避不打扰 LLM）；**LLM 层**拥有基于推理的恢复——需要上下文判断的应用级问题（工具选错、参数语义错）交给 LLM 重规划。不用单一 hero（全 LLM 处理会烧钱且不可预测；全编排处理不懂语义）。
- 判非重复：r153-A 点 3 管"失败分类六型"（分什么）；本点管"**错误由谁处理**（两层责任归属）"。增量≥50%。
- 提升层：工作流（错误处理架构）。

### 2. 工具错误隔离包装：易错调用包成子流程，错误在子流程内消化返回干净响应（来源：n8n Community 2026-04-03 实拉）
Agent 的 Continue-on-error 捕获不到子节点工具错误（工具抛错会击穿主流程）。**把易错 HTTP 调用包成独立子工作流**、以 Execute-Workflow 作为工具暴露——子流程内 catch、返回干净响应给 agent，主上下文不爆炸、不崩。
- 判非重复：WB r152-B"畸形参数先修后验"管调用前修参；本点管"**工具执行失败的结构隔离**（子流程包装模式）"。增量≥50%。
- 提升层：工作流（工具封装）。

### 3. 错误后动作语义五选一：Resume/Rollback/Commit/Break/Ignore（来源：Make docs 2026-05-01 实拉）
失败之后做什么，不是只有"重试/放弃"：Resume 忽略继续下一条；**Rollback 撤销本次 bundle 全部操作**（跨系统建单失败不留下半建记录）；**Commit 验证已成功操作后停**；Break 存失败执行待重试；Ignore 静默跳过单项。选错语义=数据不一致。
- 判非重复：r153-A 点 3（六型分类）管"失败是什么"；本点管"**失败后动作语义**（恢复/回滚/提交/中断/忽略）"——分类到动作的映射。增量≥50%。
- 提升层：工作流（错误恢复语义）。

### 4. 工具输出治理内建于工具设计：分页/范围/过滤/截断默认 + ~25k tokens 上限（来源：Anthropic Building Effective AI Agents PDF 实拉）
工具输出治理不该是运行时的事后补救，**工具设计时就内建**：分页、范围选择、过滤、截断都带合理默认值，响应上限约 25k tokens 防上下文耗尽——一次返回撑爆窗口的锅在设计端。
- 判非重复：WB r152-B"工具大返回截断落盘"管运行端截断；本点管"**设计端内建治理默认值**（先于调用存在的输出契约）"。增量≥50%。
- 提升层：工具（工具设计规范）。

### 5. 评测维度权重类别化：同一套维度、不同任务类别不同权重（来源：Session Protocol marketplace 2026-02-25 实拉）
评测打分不搞一刀切：5 加权维度（task completion / factual accuracy / output quality / format compliance / originality），**权重按类别变**——内容写作 quality+completion 各 25%，数据/表格 accuracy+completion 各 30%。同一维度对不同任务的重要性不同，权重写死会系统性误评。
- 判非重复：r153-B 点 1（四角色流水线）管"谁执行评测"；WB r151-A（评测即规格）管"规格先行"；本点管"**评分权重如何设计**（类别化）"。增量≥50%。
- 提升层：工作流（评测设计）。
