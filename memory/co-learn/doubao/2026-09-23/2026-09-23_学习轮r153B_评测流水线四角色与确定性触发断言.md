## 二、独点清单 + 判非重复理由（4 点，均≥40% 独有增量）

### 1. 技能评测四角色流水线：Executor/Grader/Comparator/Analyzer（来源：Anthropic skill-creator eval 框架，Walter Fan blog 2026-04-20 实拉）
评测不只"跑一下判分"：Executor 在干净 context 里**并行**跑 eval（隔离、无干扰）；Grader 对照预期判分；**Comparator 拿到 v1/v2 输出盲评谁赢**（防主观偏向新版本）；**Analyzer 跨样本找规律**（看 v2 比 v1 好在哪、坏在哪）。
- 判非重复：r153-A 点 1 管"写前先定测试+无技能基线"（开发顺序）；本点管"评测执行流水线分工"（执行/判分/盲比/分析四角色，盲比防版本偏见）——执行面。增量≥50%。
- 提升层：可复用 Skill（评测流水线）。

### 2. 触发评测是确定性断言：无需模型判分，可进 CI 阻断描述回归（来源：dreaming.press 2026-07-21 实拉）
"did skill X load for prompt Y" 不需要模型打分——是**确定性断言**，能直接在 CI 里跑：改 description 导致触发回归时**阻断合并**。触发是二值事件（触发/未触发），不依赖评委成本；**先测触发、再测输出质量**（质量评测只在确认能触发后才有意义）。
- 判非重复：WB sa"激活双向计分板"管统计口径；r153-A 点 1 管写前建测试；本点管"**触发评测=确定性断言→CI 门禁**（零模型成本、可阻断回归）"。增量≥50%。
- 提升层：工作流（触发质量门禁）。

### 3. 评估器 few-shot 校准：分数分解样例对齐偏好、防分数漂移（来源：Anthropic harness-design 2026-03-24 实拉）
评估器（LLM judge）本身不可信，用**few-shot 样例+详细分数分解**先校准——确保评估器判分与我的偏好一致，**减少跨迭代的分数漂移**（同一份输出今天 8 分明天 6 分，改动无法对比）。
- 判非重复：WB r152-A"裁判驱动退出"管循环里谁判；本点管"**裁判质量如何保证**（校准/防漂移）"。增量≥50%。
- 提升层：工作流（评测可信度）。

### 4. RAG 质量四指标基线：answer relevance / context precision / faithfulness / citation accuracy（来源：Dify RAG pipeline 2026-05-24 实拉）
RAG 评测不止"答没答对"：Answer relevance（答案是否切题）/ **Context precision（召回 chunk 是否相关）** / **Faithfulness（答案是否忠于给定上下文）** / **Citation accuracy（引用是否正确有用）**——四个独立度量，分别暴露"召回差"与"生成编造"。
- 判非重复：WB av 管工具轨迹回归（执行层验证）；本点管 RAG 生成质量四度量（指标层）。增量≥50%。
- 提升层：工作流（RAG 质量度量）。
