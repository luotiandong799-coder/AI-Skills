## 二、独点清单 + 判非重复理由（4 点，均≥40% 独有增量）

### 1. Eval 数据集漂移四因与版本化纪律（来源：Future AGI《LLM Eval Data Drift Detection in 2026》2026-05-20 实拉）
四个静默腐烂点：①golden set 当 ground truth 而非 versioned artifact（永不刷新）②无输入分布监控（生产分布漂移、长尾失覆盖）③prompt 模板与数据集分仓版本化（模板上线而数据集还在评旧契约）④无检索语料快照（索引移动、数据集在测已不存在的检索）。配套缓解：changelog/provenance metadata/版本化发布、schema 校验、补生产日志样本。
- 判非重复：WB r153B 落"评测流水线四角色/确定性触发断言"（评测怎么跑）；本点管"**评测数据集本身的漂移与版本化**"（数据集层生命周期）。增量≥60%。
- 提升层：工作流（评测数据治理）。

### 2. Eval 集健康三信号 + 风险级切片（来源：Latitude《Managing Data Quality for LLM Evals》2026-06-25 实拉）
三个警告信号：分数停滞 90%+ 但用户影响不提升；eval 集超 6 个月（尤其来自 web）；安全项（注入/毒性/策略违例）在聚合分里隐形。**聚合指标会藏住安全失败，风险级切片立刻暴露**——安全类问题必须独立 edge set 单独评。
- 判非重复：点 1 管"漂移如何发生"；本点管"**哪些信号说明 eval 集已腐 + 安全项必须分层切片**"。增量≥50%。
- 提升层：工作流（eval 集健康检查）。

### 3. 评测-生产双路径隔离（来源：n8n 官方 Production AI Playbook《Evaluation and Monitoring》2026-05-05 实拉）
Evaluation node 设 "Check if Evaluating" 操作：**生产输入流向正常下游逻辑，评测输入流向指标评分，同一节点按运行类型分流**——防止测试数据污染生产输出，评测逻辑与生产执行物理隔离；评测专属步骤只在测试跑，不给生产加模型调用/延迟/成本。
- 判非重复：WB r153B"确定性触发断言"管"何时触发评测动作"；本点管"**评测轨与生产轨的运行时隔离架构**"。增量≥40%。
- 提升层：工具/工作流（评测管线架构）。

### 4. 三级评测闸门 + 失败 trace 自动回流（来源：Kunal Ganglani《Evaluate AI Agents in Production: 3-Level Framework》2026-07-12 实拉）
L1 单元测试（10-30 秒，失败阻 merge）→ L2 golden 回归（merge 后跑，超阈值阻 deploy）→ L3 线上评测（部署后 5-10% 采样+质量下降自动告警）；**失败 trace 自动回流离线数据集，成为下一版回归套件**；总开销 3-8 分钟/部署。
- 判非重复：WB r153B 落"评测流水线"与"确定性触发断言"（单次评测怎么组织）；本点管"**评测按 merge/deploy/线上三级分闸 + 失败样本回流闭环**"。增量≥40%。
- 提升层：工作流（评测-部署闸门）。
