## 独点清单 + 判非重复理由（4 点落地 mts 1.41.0→1.42.0）
1. **记忆按业务主体（actor）归属，能力随调用携带**（来源：n8n AgentCore Managed memory 官方 2026-09-23 实拉）：记忆作用域=actor（客户维度）×session，跨 agent 共享同一历史读写、活过单次执行；tools/skills/model/instructions 随 invocation 携带，一个 agent 服务多角色免重复部署。判非重复：已有 ctx §记忆分层（core/recall/archival 按 token 代价）管"记忆怎么分层"，§CODE 管"记忆怎么组织"；本条管"**记忆的归属维度（按业务主体而非按 agent 实例）与能力分发方式（随调用携带）**"——多 agent 共享记忆与免部署，无覆盖。提升层=工作流（多 agent 记忆作用域）。
2. **durable execution：父休眠子继续、崩溃不级联**（来源：n8n long-running-agents 官方 2026-09-23 实拉）：子 agent 独立 state/schedules/durable fibers、数据 colocated under parent；关键性质=父不必保持活跃，可 hibernate，子完成时被唤醒；单个崩溃不连带全家。判非重复：ctx §交接文档四要素/Gateway 会话可迁移管"上下文交接"；本条管"**执行耐久性**"——父休眠子继续、崩溃隔离是执行架构层，无覆盖。提升层=工作流（长时 agent 耐久性）。
3. **输出校验参数化：最终答案校验器 + 每步前后状态日志**（来源：smolagents DeepWiki 配置表 + Dify Agent Strategy Plugin 官方，2026-09-23 实拉）：框架内置 final_answer_checks=[validator_func]（最终答案专用校验钩子）与 step_callbacks（每步回调）；复杂任务每步调用前记起始状态、后记完成状态（create_log/finish_log_message），加速诊断。判非重复：wb-execute-discipline §步骤间质检-回退 管"每步之间过质检函数"；本条补"**最终答案专用校验参数 + 每步前后状态成对记录**"——位置（收尾 vs 每步）与形态（参数化 vs 流程节点）均不同，增量 ≥40%。提升层=工具（输出校验与可诊断性参数）。
4. **harness 全能力插件化：循环/调度/存储/UI 也是插件**（来源：DeepSeek Harness 官方 2026-09-23 实拉）：every capability is a plugin that can be swapped or recomposed——模型/工具/技能/会话/沙箱/存储/循环/调度/UI 全可替换，社区插件=GitHub topic `dsh-plugin`。判非重复：已有 §技能模块化（superpowers 可组合）管"技能层可组合"；本条把**循环、调度、存储、UI 等 harness 级能力也纳入插件化**——架构理念面扩展，增量 ≥40%。提升层=工具（可组合架构理念）。
