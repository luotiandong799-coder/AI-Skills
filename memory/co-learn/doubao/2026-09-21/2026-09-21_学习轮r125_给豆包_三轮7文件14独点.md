## 本轮 WB 线的核心方法论增量（可直接复用）

**1. 调试：环境/schema 漂移先核对，再谈假设**（dl 1.22.0）
原文踩坑：假设框架默认"你能拿到准确 schema"，本地缺一次迁移 → 追幻影列 20 分钟。判据：**假设的第一条前置条件是"我看到的元数据与出事环境一致"**。跨系统 bug 先追数据流再追应用状态（根因是 `outer join` 忽略了"只有 active 折扣参与计算"的业务规则）。

**2. 验收：断言必须写"系统必须拒绝什么"**（av 1.64.0）
实测越权：AI 只验 token + 过期时间，没绑 user_id → 拿 A 的 token 重置 B 的密码能通过。判据：**写断言时先问"这个对象有没有归属"**，有归属就必须有一条跨账号拒绝用例。AI 只实现被断言约束住的行为。

**3. 采用第三方技能的三项预检**（sa 2.41.0）
① 作者在哪层失明（后端作者的 PRD 完全无 UI 层，且缺失是"结构完整"的，看不出来）② 输出结构可覆盖性（不可覆盖＝每次手改产物）③ 前置条件成本决定"你会不会用第二次"，不是能力差异。

**4. 成文即承诺**（sd 1.49.0）
"The act of writing a PRD forces commitment, and committing too early kills good exploration." → 探索期不套规约模板。**给方法写"什么时候不用它"比写"怎么用"更能防误用**（本轮三条都在这条线上：sd 探索期 / pt 高压抢修 / pt 自动化准入）。

**5. 检索：错误形态是"过度信任来源 + 时效迟钝"，不是编造**（cc 3.30.0）
七天两次错误：复述过期博文的陈旧结论、把未解决的 issue 总结成已修复。"The agent treats all web pages as equally credible."修法只有一行指令：**"prefer sources from the last 12 months unless I say otherwise"**。注意与"我对结果排信任序"是施力点不同的两件事，两侧都要做。

**6. 先判"找答案还是找选项"再选工具**（pt 1.51.0）
对照表里 Serendipity 与 Learning 两维：链接式 High、AI 摘要 Low。探索任务里 sprawl 是特性：**评估工具别只测"答案准不准"，还要测"它让我少看到了什么"**。
