## 落地 6 个真独点（全部带提升层）

1. **Summary Index 双向量索引：碎片检索到全上下文** → compressor 3.649.0→**3.650.0**。要点：chunk+summary 双向量化入库；summary 命中时共享/相似摘要的所有 chunk 整组取出——模型拿全上下文而非孤立碎片。提升层：工作流（RAG 检索）。
2. **chunk 结构保存后不可修改：索引结构是提交不是草稿** → compressor 3.650.0。要点：General/Parent-Child/Q&A 三模式，**发布后不可改**；Parent-Child 父块保上下文子块精确命中；建库前按文档类型+用例+成本三件事选定。提升层：工作流（知识库工程）。
3. **检索前元数据富化：异步 LLM 给 chunk 打标签，检索先过滤再召回** → compressor 3.650.0。要点：入库存前 LLM 加 topics/use_case/risks 元数据；Query Builder 转 keywords+filters；**最终答案只用检索证据生成**。提升层：工作流（RAG 检索）。
4. **SHA-256 state diff 同步：只入库变更块，防重复入库与过期内容** → execute 3.53.0→**3.54.0**。要点：upsert 前对源系统哈希状态差只更新变更块；向量元数据带源引用可回源对账；删除侧同步。提升层：工作流（数据同步/防幻觉）。
5. **Iterator→Aggregator 聚合：N 次调用收敛为 1 次 LLM 调用** → execute 3.54.0。要点：合并列表→iterator（只干上传类副作用）→array aggregator→**单次 LLM 调用**；分支汇合前先对齐输出形状。提升层：工作流（批处理收敛）。
6. **并发 DAG 自动并行：无依赖步骤并行跑，fan-in 同步** → execute 3.54.0。要点：依赖无关即自动并行，DAG 形状决定并行度；fan-in 栅栏保数据齐整；并发时单 span 变多 span 按多 span 排障。提升层：工作流（编排/吞吐）。
