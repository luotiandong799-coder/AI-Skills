## 独点（5 个）
### B1：session_input_callback 是模型调用前最后一个裁剪点——喂模型可裁、存储不动（来源：OpenAI Sessions）
- 拿到 history + new_input 两个 list，返回实际喂模型的合并结果；**裁/重排历史不影响 session 里存的 items**——下次再取还是全量。
- 判据：**"存什么"和"这一轮给模型看什么"是两回事**；别为了省 context 删历史，用回调按轮裁剪。
- **提升层**：上下文。

### B2：自动 compaction 会阻塞 streaming 收尾（来源：同上）
- 流式最后一个 token 出来后 SDK 还要等压缩写完才算 run 完成；低延迟场景关掉自动 compaction，在空闲/轮间手动 `run_compaction()`。
- 判据：**压缩时机是产品决策不是默认**——用户在打字就别压，闲了再压。
- **提升层**：成本/延迟。

### B3：stale compaction 防护——历史被别的 run 改过就跳过过期压缩（来源：同上）
- 压缩 wrapper 记录自己属于哪一代 generation；启动时发现底层历史已被别的 run 改过，跳过这次过期压缩，不用旧摘要覆盖新历史。
- 判据：**多 run 并发改同一 session，压缩不能是最后写赢**——版本号/generation 比对，过期操作自动作废。
- **提升层**：工作流。

### B4：EncryptedSession 装饰器包装任意 backend 加加密+TTL（来源：同上）
- 选 SQLite/Redis/Mongo 当底层，外面套 EncryptedSession 透明加密+过期；存储后端与安全横切关注点解耦。
- 判据：**加密/过期是横切关注点，别混进每个 session 实现**；wrapper 模式套任意 backend。
- **提升层**：安全。

### B5：SessionSettings(limit=N) per-run 覆盖——只取最近 N 条（来源：同上）
- 默认拉全量历史；长对话时 RunConfig 里 per-run 设 limit=50，不改 session 默认。
- 判据：**裁剪粒度可以按 run 调**——总结性查询可能要全量，闲聊只要最近几轮。
- **提升层**：上下文。
