## 独点（5 个）
### M1：Claude Code 插件机制完整化：standalone→plugin 升级路径 + 后台监控 + 插件 A/B 评测 + skills-dir 免 marketplace 加载（来源：docs.anthropic.com/en/docs/claude-code/plugins 全文）
- **升级路径**：先在 `.claude/` standalone 快速迭代（个人工作流/快速实验），要分享/团队/版本化时 `claude plugin init` 转插件（manifest `plugin.json`：name/description/version/author）——**先独立后插件，不做第一个版本就打包**。
- **skill namespacing**：插件技能恒为 `/plugin-name:skill` 前缀防同名冲突（改 `name` 字段换前缀）。
- **background monitors**：`monitors/monitors.json` 声明 `{name, command, description}`，插件激活时**自动启动**后台监控（tail 日志/文件/外部状态），**stdout 每行作为通知喂给 Claude**——无需指示 Claude 启动监控，监控是声明式的。
- **claude plugin eval**：对一组测试 prompt 有/无插件各跑多次，看插件实际贡献 + 换模型/改插件后抓回归——**插件价值用 A/B 测量，不是"能跑就算数"**。
- **skills-directory plugins**：`claude plugin init` 到 `~/.claude/skills/` 自动加载（`my-tool@skills-dir`），无 marketplace/install 步骤——个人插件的零成本通道。
- 判据：**插件 = 可分享/可版本化的独立配置单元**；后台监控声明式而非指令式；价值用 eval 测量。
- **提升层**：工具 / 可复用 Skill。

### M2：API 中继层安全审计面：模型替换/工具调用改写/SSE 异常/错误泄漏（来源：deepseek-plugin.org #23 api-relay-audit）
- **AI API 中继/LLM 代理的本地安全审计**检测六类：**prompt injection / 模型替换（偷换模型）/ 工具调用改写 / SSE 异常 / 错误泄漏 / Web3 钱包风险**。
- 与既有工具面安全互补：之前管"工具描述注入/同名工具/最小权限/guardian"（调用侧）；本条管"**中继/代理层**"（模型与工具调用经过代理时可能被改写）——自建代理网关的审计维度。
- 判据：**用代理/中继跑 LLM 时，把"返回的模型与工具调用是否原样"当审计项**；错误响应也是泄漏面（不向终端回传堆栈）。
- **提升层**：工具 / 工作流。

### M3：GUI 行为变更的 PR 必须附录制 GIF 证据（来源：skillsmp #1605，deepseek-ai/deepseek-harness 231K record-browser-gif）
- **每个改变产品用户可见 GUI 行为的 PR 必须附 GIF**，且 GIF 必须录自该 PR 真实运行的服务器与模型流（不是 mock）。
- 工具链：browser-control 录制 → 可选 Playwright Videos 提高帧率 → 确定性编码（优化体积）→ `gh --attach` 附到 PR → attach 失败回退专用 assets 分支。
- 判据：**GUI 变更的可验证证据 = 真实环境录制**；GIF 确定性编码（非随机参数）保证可复现。
- **提升层**：工作流 / 可复用 Skill。

### M4：工具层错误处理：结构化错误对象，不在 agent 层 catch；复杂任务拆聚焦调用链（来源：Make AI Agent 最佳实践，help.make.com + Make 官方博客）
- **错误处理建在工具层不在 agent 层**：工具 catch 失败并返回**结构化错误对象（不抛异常）**，让 agent 决定重试/跳过/升级——**agent 收到意外错误常常幻觉化回退行为**（编造 fallback）。
- **复杂 AI 任务分解为多个聚焦 AI 调用链**：extraction call（"提取客户名/产品/投诉，Return JSON"）→ classification call（严重度 1-5 + 部门）→ response draft call——每个调用单一职责 + JSON 输出，可调试可缓存。
- **外部动作必须插人审检查点**：凡自动回复客户/公开发布/支付类外部动作，在 AI 输出与动作模块之间插 Human-in-the-Loop review request（Slack/邮件审）。
- **瞬时触发器优于轮询**：instant triggers 不消耗轮询 operations。
- 判据：**错误对象是决策输入不是异常**；一条 prompt 干一件事；外部副作用过闸门。
- **提升层**：工作流。

### M5：可视化编排三机制：Freeze 冻结输出 / 组件分组复用 / 实例版本化（来源：docs.langflow.org/components）
- **Freeze**：组件跑完后锁定其输出状态，防止依赖它的下游重跑时上游被无意重算——**已确认输出可冻结为常量**。
- **Group components**：Shift 拖选多个组件合并为单组件（如把 RAG+向量库大 flow 合成一块），命名保存进 sidebar 复用——**大流程先组块再用，降低画布复杂度**。
- **组件版本化语义**：组件状态存数据库，sidebar 是模板；拖出到工作区后两者**不再同步**，实例保持初始化版本，点 Update Component 才原地更新（更新前后对比 Python 代码验证）——**实例与模板的版本分离 + 显式更新**。
- 判据：**冻结已确认输出、组块大流程、显式更新实例**——可视化编排的状态管理三件套。
- **提升层**：工具 / 工作流。
