## 落地 5 独点（每点标注提升层）

### 1. ReAct 的弱点：近视（myopia），长任务会游走（模型/工作流）
来源：cissychen-agent-architectures / datarekha-planning-patterns
- **ReAct 核心弱点=近视**：一次只想一步，10+ 步任务（如"规划下周部门季度评审"）容易游走、做无用功、反复调同一工具。
- **Plan-and-Execute 修正**：先要求 LLM 把全局任务分解成有序子任务集，再逐条执行、边执行边更新计划——"先计划后行动"。
- 判据：一步探索型任务用 ReAct；稳定多阶段任务用 Plan-and-Execute；ReAct 在需要从实时结果发现下一步时用。

### 2. Plan-then-act 模式：结构化输出规划（工作流/工具）
来源：microsoft-agent-reflection-planning / docs-reactiveagents-reasoning
- **Plan-then-act 把分解与执行分离**：agent 先生成结构化计划再逐步执行——适合多步数据管线、跨数据源研究、需依赖管理的编排。
- **用 json_schema 响应格式做结构化规划**：agent 产出 JSON 计划，编排器解析执行——计划可验证可审计。
- **Plan→Execute→Reflect→Refine 循环**：生成步骤列表→逐步执行（用工具）→对照原计划评估→发现缺口则修订计划重执行。
- 判据：规划输出走结构化（json_schema），让"计划本身"可解析、可断言、可复算。

### 3. Reflexion：失败后生成反思并存入记忆（模型/工作流）
来源：openlegion-ai-agent-planning / growthengineer-reflection-vs-react
- **Reflexion（Shinn et al. 2023, arXiv:2303.11366）给任何规划模式加自评循环**：尝试失败后 agent 生成反思（自然语言诊断：哪里错了、下次如何避免）——**反思存进记忆，prepend 到下次尝试的上下文**。
- **代码领域是最友好的反思域**（测试运行器=免费确定性评估器）：Reflexion 在 HumanEval 上 pass@1 达 91%（该模式最干净的公开成绩）。
- 判据：有可靠检查器时用 Reflexion；反思要"诊断+规避策略"而非空泛总结，且必须存进记忆跨尝试生效。

### 4. 组合模式：Plan-Execute 外层 + ReAct 内层 + 副作用前反思（工作流/可复用 Skill）
来源：datarekha-planning-patterns / atlassignal-self-correcting
- **常用组合**：**Plan-and-Execute 在外层、ReAct 在不确定的证据收集步骤内层、最终副作用前过一遍 reflection**——只有实测失败证明需要时才加这些机制。
- **ReAct 增强反思**：每轮 Action→Observation 循环后加 Reflection（"观察回答了我要的吗？该修正方法吗？"），发现方向错就回溯换路——自动错误恢复。
- **昂贵/不可逆操作**：有界计划+自适应证据收集+提交前验证组合。
- 判据：不无脑全上——先量测失败，再加对应机制；可逆步骤不必上重反思。

### 5. 反思性能陷阱：自证偏见与成本（模型/工作流）
来源：theneuronbase-reflection-on-plans / taskade-self-improving-agents
- **Reflection 可能变成性能表演（performance theater）**：自我批判受自证偏见影响——批判时已知模型原始答案，倾向自圆其说。
- **实现选择**：独立 LLM 调用做反思（慢但彻底）vs 集成进规划 prompt（快但不够显式）；**把"产出答案"与"评判答案"分离**是反思能抓到错误的前提——生成→对照具体判据评判→修→到通过或达上限。
- 判据：反思要分离生产者与评判者（哪怕同模型分两次调用）；用具体判据而非"感觉"；设迭代上限防死循环。
