## 落地 5 独点（每点标注提升层）

### 1. 分块策略：语义分块 + late-chunking + Parent Document Retrieval（工具/工作流）
来源：tensoria-optimize-rag-5-levers / ailearningguides-rag-in-production / rsis-enhanced-rag-framework
- **语义分块**：用小型 embedding 模型计算相邻句子间相似度——主题相似度持续高就继续扩块，相似度骤降（主题转移）就封块开新块——保证每块是完整连贯的单一想法，直接提升检索精确率；替代字符数切块。
- **Late-chunking（2024+）**：用长上下文 embedder 嵌入整篇文档，再从 token 级输出切片提取块级嵌入——块"知道"周边文档上下文；适合跨块上下文重要的语料（法律/科学）；代价=需长上下文嵌入模型+摄入内存更高。
- **Parent Document Retrieval（高 ROI）**：**解耦"搜什么"与"给 LLM 什么"**——索引小块（parent chunk 的子块）用于检索，命中后把完整父文档交给 LLM——检索精确 + 上下文完整兼得。
- 判据：分块不是字符数问题而是语义边界问题；检索粒度与生成粒度可以不同（parent/child 分离）。

### 2. 混合检索：向量 + BM25 + RRF 融合是 2026 默认（工具/工作流）
来源：promtable-rag-production / thetoolstack-rag-pipeline-benchmark / dev-production-rag-hybrid / fanyamin-rag-optimization / rsis-enhanced-rag-framework
- **纯向量检索漏精确匹配查询（SKU/错误码），纯关键词检索漏语义意图**——2026 默认=稠密向量 + BM25 关键词双路，**RRF（Reciprocal Rank Fusion）融合**。
- **RRF 公式**：score = 1/(k + rank_bm25) + 1/(k + rank_embedding)，k=60 常用；**不改任何参数直接融合、提升召回**；可选加权（如 0.6/0.4）。
- **两阶段**：Stage 1 广召回（两路各取 top 50-100 候选）→ Stage 2 融合（RRF 或加权分数）。
- 判据：生产 RAG 先 hybrid 再谈其他优化；RRF 是零参数融合首选。

### 3. 重排（Rerank）：两阶段架构，精确率提升 15-30%（工具/工作流）
来源：agencyscript-embeddings-vector-search / rsis-enhanced-rag-framework
- **检索是召回导向，重排是精确导向**：对候选（20-50 对）用 **cross-encoder（慢，只应用于小集）** 重排——比向量检索贵 3-5 倍但 RAG 答案质量稳定提升，**典型 precision@3 增益 15-30%**（看领域）。
- 流程：广召回 → cross-encoder 重排 → **只把 top 3-5 重排结果给 LLM**。
- 判据：让 LLM 看"20 个相似结果"不如看"重排后 top 3-5 精确结果"；重排只在候选集上跑，控制成本。

### 4. MMR 去冗余 + 上下文缓存（工具/工作流）
来源：thetoolstack-rag-pipeline-benchmark / dev-production-rag-hybrid
- **MMR（Maximal Marginal Relevance）**：返回 top-5 最相似块可能全是同一主题——MMR 在相关性与多样性间平衡，减少冗余。
- **上下文缓存（context caching）**：生产 RAG 2026 组合=hybrid search（pgvector）+ RRF + context caching——对重复系统提示/常驻知识前缀缓存，省 token 省延迟。
- 判据：多块检索先过 MMR 再入上下文；长会话/重复前缀上上下文缓存。

### 5. embedding 选型：按成本/维度/上下文窗口/基准权衡（工具/工作流）
来源：aipromptshub-rag-pipeline / premai-production-rag
- **主流默认**：OpenAI text-embedding-3-large（$0.13/1M tokens，3072 维，**可经 Matryoshka 降到 256 维**）英文 MTEB 64.6 分领先，英文企业 RAG 安全默认；3-small 更便宜（1536 维）。
- **替代面**：开源 embedding 在部分领域超过 OpenAI（如特定评估域高 9.74%）并支持 **32K token 上下文（vs OpenAI 8K）**——长文档分块有意义；$0.06 更便宜。
- 判据：embedding 选型看四维=成本/维度（可压缩性）/上下文窗口（长块能力）/该领域 MTEB 基准；不是越贵越大越好。
