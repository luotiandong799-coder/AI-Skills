## 落地 5 独点（每点标注提升层）

### 1. 平台定位：n8n=通用自动化集成核心，Dify=AI 应用开发核心（工作流/可复用 Skill）
来源：csdn-n8n入门 / n8n-ai / dify-ai
- **选型判据**：需要把多个 SaaS 系统连起来、数据在系统间流转→**n8n 是更好的选择**；需要搭建以 AI 对话为核心的应用（客服机器人/RAG 知识库）→**Dify 是更好的选择**。
- **n8n 定位**：开源 AI Agent+工作流自动化平台，**连接 500+ 服务与 AI 模型**（可视化节点编辑器、支持 MCP、自托管、fair-code 许可）——200k+ GitHub stars、SOC2 合规。
- **Dify 定位**：生产级 Agentic Workflow 平台，托管/自托管/企业版（VPC、SSO/SAML、RBAC、审计日志），可发布为 web app 或 API。
- 判据：先问"核心是系统集成还是 AI 应用"再选平台；n8n 强调"AI 配对显式逻辑掌控输入输出"。

### 2. 生产部署 15 实践：错误工作流 + 优雅降级（工作流/工具）
来源：n8n-15-practices / techzeeno-n8n-review
- **错误必然发生**（API 失败/限流/网络超时）——工作流要**优雅失败不崩不丢数据**。
- **内置 error workflow**：工作流级错误捕获——节点失败时错误工作流触发并带失败上下文；**可配置重试逻辑+指数退避**（第三方 API 凌晨抖动时自动退避重试而非静默失败）——"把周末项目与业务关键工具区分开的运维特性"。
- 判据：生产工作流必须配错误工作流+重试策略；失败不丢数据、可审计。

### 3. Agent 节点：workflow 当工具调用，"思考+行动"闭环（工具/工作流）
来源：aistarmap-n8n / kalyna-n8n-ai-automation / n8n-ai
- **n8n 内置 AI 节点**（直接 API 访问 Claude/GPT-4o/Gemini）：构建邮件摘要器/Slack Q&A 机器人/反馈分类器/多工具 agent。
- **Agent 可把工作流中其他节点作为工具绑定**——"thinking + action"组合；**支持多 Agent 协作编排与 RAG**。
- 判据：可视化平台里 agent 不是黑盒——节点级可调试、按设计可解释、需求变化可维护（"n8n is about help, not hype"）。

### 4. 平台选型象限：按锁定/代码控制/许可/学习曲线（工作流）
来源：simstudio-n8n-alternatives / ayautomate-workflow-tools / noxus-dify-alternatives
- **选型象限**：Zapier=托管 no-code 优先、应用目录最广、非技术用户学习曲线最低（跨 SaaS 快赢）；**n8n=开源可自托管、全代码块+原生 AI 节点、高吞吐工作流定价更划算**（自托管/代码逃生舱/大流量）；**Pipedream=开发者要代码级控制又不管理服务器**（托管工作流服务里的代码步骤）；Activepieces=自托管社区版无软件许可费（MIT）。
- 判据：个人用户选型=自托管+代码控制+无锁死优先（fair-code/MIT），托管 no-code 仅当追求最快上线。

### 5. n8n 计费与运维真相：按执行计费 + 内置重试（工具/工作流）
来源：techzeeno-n8n-review / n8n-ai
- **n8n 按工作流执行计费（一次 run=一次 execution），不看内部做了什么**——高吞吐大批量时成本可预期。
- **自托管 fair-code**：无供应商锁死；SOC2 合规（企业场景可过审）。
- 判据：用"每次执行成本×执行量"做容量预估；自托管版本是个人用户规避订阅锁死的通道。
