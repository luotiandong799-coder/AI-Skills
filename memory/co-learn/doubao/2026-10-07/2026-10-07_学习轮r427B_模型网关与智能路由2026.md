## 落地 5 独点（每点标注提升层）

### 1. 网关 vs 路由器两层定义 + 两级容错（工具/工作流）
来源：dev-to-5-router-tools / tencent-multiprovider-routing / tencent-llm-gateway-five-levels / devopsboys-litellm
- **LLM router=功能组件**：按预定义逻辑为推理请求选目标模型/provider/API key；**AI gateway=完整基础设施平台**：路由之外还含认证、token 预算、限流、语义缓存、guardrails、分布式可观测。
- **两级容错必须分开**：**Provider Failover=供应商级**（模型不变、换提供方，OpenRouter 先保模型不变才切换）；**Model Fallback=模型级**（才换模型）——任务级模型路由改变输出行为，**必须经过业务验收**。
- **同模型名多账号声明**：调度器按账号优先级（数值小者优先）排序，上游报错自动故障切换；**可切换错误分类**=401/402/403/405/429/529/5xx 及特定 4xx（model_not_found/过载类）——**上下文超限类 400 永不切换**。
- 判据：先修 Provider Failover 保模型不变，再谈 Model Fallback；切换错误白名单明确，"上下文超限"这类请求级错误不触发换路。

### 2. 路由模式三档 + 分类器路由（工具/工作流/模型）
来源：microsoft-foundry-model-router / openrouter-auto-router / masterprompting-model-routing / pi-smart-router
- **三档路由模式**：**Balanced（默认）**=动态兼顾成本与质量；**Quality**=优先最大准确率（复杂推理/关键输出）；**Cost**=优先省钱（高量/预算敏感）。
- **OpenRouter Auto Router**=轻量分类器把每条 prompt 分 **~30 细粒度任务类型**（code:debugging / agent:multi_step_planning / qa_knowledge / math…）→ 选模型+推理 effort。
- **nano 分类器分 tier**=用最便宜的小模型当分类器把查询分档（最简单实现）。
- **pi-smart-router**=encoder 预测 prompt 的多维能力需求（任务复杂度/延迟约束/财务成本/实时供应商可靠性）再调度——模仿 Cursor "Auto" 模式的免手动配置。
- 判据：路由=把"选模型"从人/应用层上移到网关；分类器优先轻量小模型，任务类型粒度越细路由越准。

### 3. Cache-aware 路由 + 语义缓存（工具/工作流）
来源：llmgateway-cache-aware / dev-to-7-cost-tools / aliyun-tair-semantic-cache
- **Cache-aware provider selection**：不只按未缓存输入价格排名——**学项目近期 cached-input 与 output 比例**再比价（长 prompt/coding 会话估得更准；不承诺特定 prompt 必命中缓存）。
- **Cloudflare edge caching**：响应在边缘节点全局缓存，重复查询**零 token 消耗**毫秒级返回。
- **Tair 语义缓存网关**：**exact match + semantic match 双策略**自动缓存 LLM 响应（相似请求秒级返回减 token）；配合**上下文治理**进一步削减 AI Coding/Agent 场景的无效 token 请求。
- 判据：路由决策要"缓存感知"（同一模型名多个 provider 的缓存命中率不同）；重复/相似请求场景先上语义缓存再谈降级。

### 4. 网关治理面：token 限流 + 按消费者计量 + 安全（工具/工作流）
来源：azure-apim-ai-gateway / aliyun-ai-gateway / aliyun-apim-release-notes
- **Token 限额/配额策略**：按 API 消费者设 TPM 限额或 token 配额（小时/日/周/月/年）——**防止一个 app 吃光整个 TPM 配额挡住其他 app**。
- **按消费者节流**：by consumer / model name / request header 限 requests、concurrency、connections、tokens；**per-consumer 计量计费**=追踪某消费者某模型某时段的 token 消耗。
- **内容安全集成**：AI 网关内置内容安全检测，风险请求按风险类型与消费者分统计；**模型日志字段参数映射**把各模型返回字段统一到网关日志字段（跨模型类型统一可观测）。
- 判据：网关治理=token 级配额（不是裸请求限流）+按消费者记账；限流/计量/安全三件事在网关层一次配齐。

### 5. 运行时信号路由（EPP 加权评分）+ canary 发布（工具/工作流）
来源：aws-sagemaker-hyperpod-inference-gateway / aliyun-ack-gateway-canary / langchain-model-router-harness
- **Endpoint Picker（EPP）**：实时 Prometheus 指标加权评分选最佳 pod——**KV cache 利用率（避开近满）/ 队列深度（避深积压）/ LoRA adapter 驻留（优先已加载）/ 前缀缓存命中率 / 预测延迟 / 运行请求数**；**Body-Based Router**=从请求体读模型名路由到正确 GPU pool（单 endpoint 多模型，客户端零改动）。
- **Inference Extension canary**：更新基础模型/换 GPU/LoRA 版本时**增量切流**不断服（更新 InferencePool 切模型、更新 InferenceModel 切 LoRA 版本）——不用下线重起。
- **LangChain：路由决策放在 agent harness 而非通用网关**——"选对模型+对上下文的模型"与任务上下文强相关，harness 里才看得到。
- 判据：多模型/多 pod 场景用实时运行时信号（缓存/队列/驻留）评分路由；模型升级用 canary 切流；agent 场景路由贴近 harness。
