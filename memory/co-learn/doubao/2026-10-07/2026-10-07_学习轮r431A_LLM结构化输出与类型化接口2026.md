## 落地 5 独点（每点标注提升层）

### 1. 三条结构化输出通道：JSON mode / strict json_schema / function calling（工作流/工具）
来源：aiworkflowlab-structured-outputs-json-mode-pydantic / devto-function-calling-structured-outputs / infini-structured-output
- **三通道对比**：①`json_object`（response_format.type）——只保证"合法 JSON 对象"，字段结构靠 prompt 约束（轻量分类/状态返回/简单配置够用）；②`response_format={"type":"json_schema","json_schema":{...},"strict":true}`——**生成级约束匹配 schema，无效 JSON 变得不可能（硬保证）**；③function calling/tools——工具参数也需 JSON 解析校验，结构化结果直接驱动函数/任务/工作流时用。
- **生产推荐只选 strict json_schema**：另外两种要么不给 schema 保证、要么停在旧 API。
- 判据：需要硬保证选 strict json_schema；只求合法 JSON 用 json_object；结果要驱动动作选 function calling。

### 2. 生成级约束 ≠ 可信：客户端必验 + validate-repair 循环（工作流/工具）
来源：devto-structured-outputs-json / blog-codercops-reliable-json-2026 / aiworkflowlab-validate-retry
- **铁律：即使有原生 provider 强制，也永远不要信任裸解析**——**长度截断与拒答可以打断约束**；每次响应都要在客户端按 schema 校验。
- **循环=generate → validate → repair**：pydantic 校验失败→把**具体错误**回喂模型修复（"Missing required property 'price'"比泛泛"try again"修正效果好得多）。
- **重试预算**：超过 2+ retry 说明 prompt 或 schema 本身有错（每次 retry 都烧 token）——修 prompt/schema 而非加预算。
- 判据：native 约束是概率保证不是契约；客户端 schema 校验是最后一公里。

### 3. Pydantic 是 Python 生态主导 schema 定义方式（工具/可复用 Skill）
来源：kanopylabs-structured-output-patterns / openlegion-llm-structured-output / tutorials-structured-output-pydantic-instructor
- **Pydantic=类型化字段定义 LLM 输出 schema**：类+类型化字段，Pydantic 处理校验/序列化/JSON Schema 生成。
- **生产 schema 要点**：**字段描述会作为上下文传给 LLM**（写清字段含义）；**Literal 类型锁闭枚举**（action: Literal["search","navigate","click"]——模型返回集合外值即 ValidationError）；conint 锁有界整数；嵌套模型表达复杂结构；**可选字段用 anyOf**。
- **instructor 库**：Pydantic 模型当 schema、patch LLM client 强制 schema、校验失败自动重试——定义形状，其余交给它。
- 判据：schema 既是校验契约又是给 LLM 的上下文；枚举/边界用类型而非 prompt 描述。

### 4. 重试时把校验错误回喂 prompt（工具/工作流）
来源：techearl-reliable-json / blog-codercops-reliable-json-2026
- **retry-with-error 模式**：校验失败→带错误信息重试一次，模型大概率自纠；循环至多 3 次。
- **具体错误 > 泛泛重试**："Your previous response failed JSON validation: Missing required property 'price'"——比"try again"修正效果好。
- 判据：重试不是无脑重发，必须携带上次失败的具体原因；上限后抛异常而非无限重试。

### 5. constrained decoding：token 采样层面锁 schema（工具/模型）
来源：aiworkflowlab-structured-outputs-json-mode-pydantic / aiworkflowlab-structured-outputs-constrained-decoding
- **strict mode 原理**：后台把模型的 token 采样限制在符合 schema 的空间内——不是"生成后校验"，是"生成时就只能走合法路径"。
- **constrained decoding 通用化**：本地/开源部署可通过 constrained decoding（outlines/guidance 类库）对任意模型施加同样的生成级约束。
- 判据：能上生成级约束就别只靠 prompt 承诺；本地模型用 constrained decoding 补上 provider 原生 strict 的位。
