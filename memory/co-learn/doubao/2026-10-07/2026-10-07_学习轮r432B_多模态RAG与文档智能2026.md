## 落地 5 独点（每点标注提升层）

### 1. 纯文本 RAG 丢 30% 信息：多模态是显式选型而非增强（工具/工作流）
来源：llmversus-multimodal-rag-guide / bigdataboutique-multimodal-rag
- **文本抽取式 RAG 在典型企业文档里丢高达 30% 信息**（图表/表格/图示/布局信号被丢弃）；多模态 RAG 检索的是**锚定在图/表/版面上的答案而非只是段落**。
- **三大路线对比**：①**VLM 提取**（页渲染成图→vision LLM 抽结构化文本→正常索引，查询时可再送图做视觉 grounding，保留表结构/图形内容/空间关系，OCR 破坏的都能保住）；②**caption-and-index**（VLM 给每图生成详细文本描述→索引 caption→按图检索原图，精度≈90%、成本中高）；③**page-as-image 视觉检索**（ColPali/ColQwen2：整页渲染成图，用 late-interaction 视觉 transformer 直接索引，免 OCR、复杂版式最高精度）。
- 判据：文档含图/表/复杂版式时先问"走哪条多模态路线"，默认不再只抽文本。

### 2. 布局感知解析：结构化再入 embedding（工具/可复用 Skill）
来源：blckalpaca-multimodales-rag / ai-tldr-parse-pdfs-for-rag
- **布局感知解析=嵌入前先把结构分离干净**：识别表格/列表/标题/列并保留结构；2026 生产级工具=Docling（IBM 开源）/Unstructured.io/LlamaParse/Marker/PyMuPDF + OCR 引擎（Tesseract/Azure Document Intelligence/AWS Textract）。
- **表格两条路**：①序列化为文本/结构；②**多模态表格检索=干脆不序列化，把表格当图，查询时把页面图（或裁剪的表格区域）直接送多模态 LLM**——绕开序列化错误，代价=推理成本更高。
- 判据：复杂版式先布局感知解析再分块；表格宁可按图直通也别被 OCR 串行错乱。

### 3. CLIP 类联合 embedding：图-文同一空间（模型/工具）
来源：ayinedjimi-multimodal-rag-2026 / nvidia-nemotron-document-pipeline
- **CLIP 原理=联合训练文本与图像编码器，使图像与文本描述的向量在 embedding 空间靠近**——实践效果=可用文本直接搜图、图搜图。
- **统一多模态 embedding 模型**（Cohere Embed 4/voyage-multimodal-3/llama-nemotron-embed-vl-1b-v2）：把文本/表格/图表图编码进同一向量空间（如 2048 维）做相似度检索——免去"图要先转文字"。
- 判据：需要跨模态检索（文搜图/图搜图/图表现混合）时选统一 embedding 而非文本化。

### 4. 混合检索+交叉编码重排照搬到多模态（工作流/工具）
来源：arxiv-multimodal-hybrid-slm / bigdataboutique-multimodal-rag
- **多模态版本沿用混合检索配方**：HNSW 语义检索 + GIN 词法检索 → **RRF 融合** → cross-encoder 重排（与 r430A 文本混合检索同构，只是检索对象换成多模态向量）。
- **开源 SLM 实践**：Qwen2-VL-2B 生成图表/表格文本摘要→多模态 ingestion；检索阶段语义+词法融合统一 RRF、cross-encoder 精排——小模型即可支撑科研文档理解。
- 判据：多模态检索沿用"向量+词法+RRF+重排"四件套，别为多模态重造轮子。

### 5. 文档处理流水线：GPU 微服务拆解提取/嵌入/重排（工具/工作流）
来源：nvidia-nemotron-document-pipeline
- **NVIDIA NeMo Retriever 流水线**：把文档分解为结构化数据——GPU 加速微服务分阶段做**提取→嵌入→重排**；可解析复杂 PDF、抽嵌套表格、解读图表。
- **工程要点**：VLM 生成的表格/图摘要可被索引为文本（caption 路线），同时保留原始图像供查询时视觉 grounding——两路并存的混合索引。
- 判据：高吞吐文档库把提取/嵌入/重排拆成独立加速服务；摘要文本与原始图像双轨索引。
