## 落地 5 独点（每点标注提升层）

### 1. Deep Research 三子阶段流水线：plan→search→synthesize（可复用 Skill/工作流）
来源：agentlist-deep-research-architecture / wyattowalsh-research-skill / gyanbyte-build-deep-research / zylos-deep-research-architectures
- **三子阶段**：①iterative retrieval（query rewriting / parallel search / source quality ranking）②fact verification（multi-source cross-check / confidence scoring / citation tracing）③report generation（outline planning / section-by-section writing / citation embedding）。
- **通用模式**：**Plan → Search → Read → Reflect → Iterate → Synthesize 循环**；成熟实现都在其上叠 multi-agent 并行。
- **lead-agent 纪律**：plan before retrieval、start broad then narrow、parallel workers 经 lead 协调、**audit 引文是否真支撑每条主张**、synthesize 成报告而非 source dump。
- 判据：搜索智能体=循环不是单次搜索；报告=综合不是罗列来源。

### 2. 来源三角验证 + 确定性引用审计（工作流/可复用 Skill）
来源：raw-weiseberg-recursive-deep-research / nvidia-deep-researcher / lobehub-deep-research-skill
- **Source Triangulation**：**永不依赖单一来源**——Fact A 来自 Source X 时，专门搜 "Source X Fact A critique/corroboration" 找证伪或佐证；**recursive forking**=遇到密集子话题勿浅总结，分叉深挖。
- **引用即时嵌入**：每个事实性主张**同句紧跟 [N] 引用**；重要主张需 **2+ 独立来源**；区分事实（带引用）与推断（标注）；**单一来源主张标 "unverified from single source"**；明说找不到什么而非用常识填补。
- **确定性后处理审计**：报告产出后，**确定性流水线把所有引用与实际检索到的来源逐条核对**（NVIDIA Phase 5）——可审计性靠代码不靠模型自觉。
- 判据：引用纪律=同句内嵌+双源+缺口声明；引用审计=确定性机检而非 LLM 自查。

### 3. 证据充分性循环：consistency check + 缺口喂下一轮查询（模型/工作流）
来源：supernodes-deepsearch-verify / arxiv-2509.00761-L-MARS / alphaxiv-Argus
- **每轮后合并子问题置信度**：低于阈值→写更具体查询→再跑一轮——**"一次搜索+一次阅读+一次回答=带摘要的搜索工具；这一步才把它变成研究 agent"**。
- **L-MARS Judge 显式证据充分性清单（T=0）**：factual support / jurisdiction match / temporal specificity / contradiction analysis——Sufficient 即收，Insufficient 返回**结构化改进注记**seed 下一轮查询状态。
- **Argus Navigator**：解析 Searcher 轨迹、识别**未验证或矛盾的主张**、派发定向新查询补齐缺口——迭代验证是中心结构。
- 判据：研究 agent 的"完成"=每子问题置信度过阈；缺口检测（未验证/矛盾）驱动下一轮查询，不是机械重试。

### 4. 搜索与知识解耦：Search Behavior vs Knowledge Management 双角色（模型/工具/工作流）
来源：arxiv-2601.04703-M-ASK / arxiv-2605.14306-PaSaMaster / zylos-deep-research-architectures
- **M-ASK 解耦**：**Search Behavior Agents**（规划与执行搜索动作）vs **Knowledge Management Agents**（聚合/过滤/维护紧凑内部上下文）——**减少搜索与上下文构建互相干扰**，turn-level rewards 提供稳定协调。
- **PaSaMaster planning–retrieval 分离**：**前沿 LLM 只留给意图理解**，检索与打分委派轻量模型+定制语料库——成本与质量兼顾。
- **上下文预算纪律**：**避免把 200K+ token 爬取内容塞进单一上下文**（抓→过滤→紧凑摘要再进上下文）；中间步幻觉逃过端到端评测=需逐步验证。
- 判据：搜索动作与上下文维护拆给不同角色/模型；前沿模型做意图、轻模型做检索——按任务复杂度分配模型层级。

### 5. DAG 任务规划 + 蒸馏执行器 + 有限状态控制环（工具/模型/工作流）
来源：arxiv-2508.04604-TURA / arxiv-2510.02326-RA-FSM / parallel-ai-research-assistant / naskovai-agentic-search-training
- **TURA**：**DAG-based task planning**=子任务及其数据依赖建模成 DAG→最优可并行执行计划（多跳工具链）；**Distilled Agent Executor**=用 curated expert trajectories + mixed-rationale distillation 微调轻量 agent（解决生产推理延迟）。
- **RA-FSM 有限状态控制环**：Relevance→Confidence→Knowledge 三态包装生成——控制器过滤越界 query、打分可答性、拆解问题、**按需才触发检索**，输出带置信标签+去重引用。
- **五层管线**：query planning / web search / content extraction / LLM reasoning / output with citations；**把模型约束在检索载荷的证据内，证据不足明确说而不是猜**。
- **observe-reason-act harness**：LLM 读问题→写查询→执行→检查结果→决定（改写再搜/读全文/停止综合）——**把模型放进循环**是单遍 RAG 的修复。
- 判据：多跳任务用 DAG 计划保可并行；生产延迟用蒸馏小执行器；检索循环=observe-reason-act，模型必须被约束在证据内作答。
