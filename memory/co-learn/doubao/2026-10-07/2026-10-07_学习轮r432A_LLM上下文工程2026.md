## 落地 5 独点（每点标注提升层）

### 1. 上下文窗口按预算管理：按路由分配 + 保留缓冲（工作流/可复用 Skill）
来源：sureprompts-context-engineering-best-practices / zylos-system-level-context-design / aiexpert-context-engineering
- **"模型支持 200K"是天花板不是邀请**：每个请求都有 latency 与 dollar 预算，两者大致随输入 token 线性增长，注意力成本超过某窗口后非线性——**按路由定工作预算**（system/检索上下文/历史各占多少）。
- **成熟系统把窗口当显式预算而非开放桶**：生产典型分配=system 指令+工具 schema / 检索与长期上下文 / 对话历史 / 当前消息 / 输出预算，**显式保留 10-20% 缓冲**避免生成中途撞硬顶、保住首部空间。
- 判据：写每个路由的 token 预算表再进 prompt；缓冲是硬约束不是建议。

### 2. 注意力偏好位置：关键信息放开头与结尾（模型/工作流）
来源：github-muratcankoylan-context-fundamentals / cissychen-context-engineering
- **关键信息放注意力偏好位置（开头与结尾）**；**用清晰的章节边界组织 system prompt**；**监控上下文用量**（开发期持续看占用曲线）。
- **为退化设计而非希望避免退化**：窗口接近满时质量先于硬限退化——规划好"满了怎么办"。
- 判据：最重要的指令/数据不埋在中间；节段标题让模型可定位。

### 3. 渐进披露：只按需加载，三层延迟（工作流/可复用 Skill）
来源：lobehub-neolabhq-context-engineering-kit / zylos-system-level-context-design
- **渐进披露=按需加载管理上下文**：启动时 agent 只加载技能名与描述（足以判断何时相关），**完整内容在技能被激活时才加载**；原理适用于技能选择、文档加载、工具结果检索多层。
- **上下文质量 vs 数量**："塞更多"不等于"更好"——相关性加权，冗余与噪声稀释注意力。
- 判据：默认只注入"名字+摘要"，触发后注入全文；每层都问"这段现在需要吗"。

### 4. 工具输出 offload：进上下文前先摘要，省最多 99% token（工具/工作流）
来源：anhtu-context-engineering-2026
- **Offload=工具响应进入上下文前先摘要，全文存外部（文件/对象存储），上下文只留轻量引用**——实践可把工具输出 token 砍掉最多 99%。
- **Reduce=压缩对话**：历史增长时 compaction 摘要并初始化新窗口——长时任务最重要的技术；**摘要必须保留当前目标、关键工件、决策与理由、下一步**；只记"发生了什么"不记"下一步该做什么"=目标漂移。
- 判据：大工具输出一律先摘要再入窗；摘要五要素=目标/工件/决策/理由/下一步。

### 5. 压缩触发点与递归摘要：70-80% 触发（工作流/工具）
来源：github-muratcankoylan-context-fundamentals / uni-mannheim-context-engineering / agentpatterns-context-engineering
- **压缩触发点=70-80% 利用率**（不是撑到 100%）；**递归摘要**=反复把分块摘要再摘要（128K-1M 窗口也很快被反复工具调用填满）。
- **分级压缩**（LangChain Deep Agents 第一压缩级/OpenAI）：先 offload 工具输出→再摘要历史→最细粒度才截断；**摘要风险=objective drift**，防漂移靠把"下一步"写进摘要。
- 判据：利用率到 70-80% 主动压缩而非等满；压缩分级执行，摘要带"下一步"。
