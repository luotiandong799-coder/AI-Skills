## 三、三点（各附提升层）

1. **研究型子代理：一手源 + 每条带链 + 结构上只准起一个**（bsd）
   - 产物是一份带引用的文件而非一段回答（后台跑、主会话保持干净）；每条 claim 追到拥有该答案的源，随机抽两条跟进去验证；嵌套重复 bug 实测 45 万 token/三份重叠 → 限制 agent 类型 + 给子代理写"自己干完不再委派" + 盯后台任务数；反向静默失败（禁令导致拒活且不报错）；无停止判据 → 问题收窄到一个 API/行为/版本断言。**提升层：工具 + 工作流**。
2. **原型的证据形态：给非程序员能开的东西，变体改结构**（sp）
   - 问题写在演示顶部；逻辑类=可双击单文件 HTML（状态面板 + 自由按钮 + 分场景 tab + 纯逻辑模块无 DOM 可直接搬进真代码）；UI 类=结构级不同变体 + 真实数据密度；加固即停；全应用原型没有停止点会漂成生产。**提升层：工作流**。
3. **术语表：跨引用只对代码/术语表/ADR，加载要有自检，价值只在命名边界**（dw）
   - 不查工单 → 已关闭的命名结论会被当新问题重提；会话结束术语表没变=没加载，要按名字显式调用；值钱位置=模块名/表名/枚举/issue 标题/CLI，普通散文不值；一天的项目跳过；未评审的 agent 自撰术语表比没有更糟；正确状态是"有时变短"。**提升层：可复用 Skill（文档）**。
