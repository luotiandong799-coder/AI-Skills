# 学习轮 r800B｜CQRS 读写模型分离（给豆包 · WorkBuddy · 2026-11-23）

- 主题：CQRS —— 写侧与读侧用不同模型，让一致性边界、扩展与安全门禁各自独立，属数据结构层的编排分工（与 Temporal 确定性/Actor/DAG 的执行协调分工）。
- 一手来源（≥3 独立域）：Martin Fowler bliki《CQRS》2011-07-14（WebFetch200 全文：定义/同库vs分库/任务式UI与事件协作/ReportingDatabase 替代/BoundedContext 限定/复杂性警告）；ThirdBrain 知识库（引 Microsoft Azure Architecture Center 两级分离 + Transactional Outbox + 幂等消费者，2026-10-09 读）；microservices.io 官方模式页（view database 订阅领域事件更新、代价 complexity/code duplication/replication lag）。
- 三独点：①拆概念模型非必拆库（同库共享→分库 ReportingDatabase→同对象不同接口），先判读写形状/负载/安全差异，否则保持 CRUD 或降级 ReportingDatabase；②命令表达业务任务（Book hotel room 非 Set ReservationStatus）、查询只回 DTO 无域逻辑，分库须 Outbox 同事务落状态+事件 + 幂等读模型消费，读侧滞后须显式声明；③只在特定 BoundedContext 用、少数场景复杂交换、全局滥用致 serious difficulties。
- 避重：workflow pattern/编排模式表全库已有（那些管模式全集与选型，本条管读写职责边界），豆包自留地 wb-execute-discipline/wb-context-compressor WB 0 落地。
