## 落地 5 独点（每点标注提升层）

### 1. 语义缓存机制与实证收益（工具/工作流/可复用 Skill）
来源：valuestreamai / agdex / maxim / futureagi / zeroentropy / respan / arxiv-2411.05276
- **语义缓存=query 嵌入成稠密向量→ANN 相似度搜索缓存嵌入→cosine>0.92 返回缓存响应（非精确字符串匹配）；FAQ 场景命中率 35-45%、可三倍有效 QPS；AWS 研究缓存命中降 86% 成本+88% 延迟、生产部署 20-73% token 成本降**。
- **GPT Semantic Cache=Redis 内存存 query 嵌入（嵌入生成+内存缓存+ANN 三组件）；向量查找开销 5-15ms；30% 命中率=30% LLM 成本降；释义查询（"退款流程"vs"怎么退货"）精确缓存抓不到，语义缓存可命中**。
- 提升层：工具（缓存库）/ 工作流（命中率基线）/ 可复用 Skill（实现模板）。

### 2. 多层缓存架构与分层策略（工具/工作流/可复用 Skill）
来源：zylos / markaicode / gingerlabs / redis-langcache
- **三层=L1 精确缓存（哈希）、L2 语义缓存（嵌入+ANN，命中省 100% 推理成本毫秒级返回）、L3 边缘缓存（确定性 URL-keyed 输出用 Cloudflare KV/短 TTL 零模型）；多 tier 实证=61.6-68.8% 命中率、92.5-97.3% 正命中准确率、API 调用降 68.8%、成本降 40-80%、延迟 2-4×（高重复工作负载 25-250×）**。
- **Redis LangCache 托管语义缓存=推理成本降 73%、缓存命中响应快 15×；生产架构=三缓存组合（prompt prefix+embedding+full response）减推理调用 65-80%；RedisVL=官方向量库直接在 Redis 做相似度搜索（免独立向量库）**。
- 提升层：工具（分层缓存）/ 工作流（先 L1 后 L2 递进）/ 可复用 Skill（分层选型表）。

### 3. 失效策略四叠（工作流/工具/可复用 Skill）
来源：dev-rikuq / respan-invalidation / theneuralbase
- **四叠：TTL by workload class（便宜默认：客服 86400s、金融数据 3600s）+prompt-version keying（模型更新时全量换 key）+semantic-threshold tuning（误报控制）+explicit purge（紧急杠杆）；TTL 是安全网不是策略（24h-30d 按内容易变度）**。
- **语义缓存比精确难失效（key 是向量不是字符串）——先规划失效否则跳过语义缓存；上游数据变化时按 embedding_model_version 失效+重算受影响响应嵌入；返回带 cache_source 元数据（cached_at/live_generation）供审计**。
- 提升层：工作流（失效策略）/ 工具（版本 key）/ 可复用 Skill（失效决策表）。

### 4. 缓存投毒与质量门（工作流/工具/可复用 Skill）
来源：acethecloud / agentixforce
- **两类毒：个性化答案被当通用缓存（账户状态泄露）——PII 检测再存+动态槽位模式+答案类型分类器+工具衍生个人数据 deny-list；坏输出被缓存放大——存前过安全/质量检查、高流量 canonical 答案过审批门、签名源版本、admin 按 canonical intent purge**。
- **阈值太松=误命中（stale/off-topic 答案被自信输出）——按应用误报容忍度调阈值（0.90-0.95 区间权衡命中率 vs 误命中）；缓存返回必须带 provenance 标记（cached_at/live_generation）**。
- 提升层：工作流（质量门）/ 工具（deny-list）/ 可复用 Skill（投毒防护清单）。

### 5. 新鲜度感知与风险约束（工具/工作流/可复用 Skill）
来源：arxiv-2607.04281-FreshCache / arxiv-2602.13165-Krites / calmops-vCache
- **FreshCache 三层语义缓存把缓存复用当风险约束时序推断：命中前用指数衰减模型+MLP 估缓存结果过期概率，低于分层错误预算才放行（答案 ε=0.10/URL 列表 ε=0.20/页面内容 ε=0.35）——RAG 开放网页场景防 stale 答案**。
- **Krites=异步验证语义缓存：动态层 promotion 不修改驱逐策略、验证指针少用自然逐出（保容量与新鲜度属性）；vCache=每 prompt 学习相似度阈值+用户定义错误率保证——阈值不是全局常数，按查询学习**。
- 提升层：工具（新鲜度模型）/ 工作流（风险预算）/ 可复用 Skill（错误预算模板）。
