## 落地 5 独点（每点标注提升层）

### 1. 图工作流四种基础模式：按"分支如何选择"分类（工作流/可复用 Skill）
来源：google-cloud-adk-graph
- **Fan-out and fan-in**：独立任务后合并全部结果；**Deterministic router**：固定规则选分支；**Agent router**：语义理解选分支；**RequestInput**：人的决策后继续。
- **判据**：不需要预测每个请求走哪条路径——分支、循环、重复阶段都允许；按"分支由谁决定"选模式：规则→deterministic、语义→agent、人→RequestInput。
- 与 execute-discipline 五编排模式的互补：那条按角色拓扑（orchestrator-worker/supervisor/...），本条按"分支选择机制"。
- 提升层：工作流（模式选型）/ 可复用 Skill（编排模板）。

### 2. 并发原语语义：barrier vs no-barrier + named branch gates（工具/工作流）
来源：galaxyproject-foundry / fdsx-pypi / loomflow-pypi
- **parallel(thunks)=barrier**：并发跑、await 全部返回才继续；**抛错的 thunk 解析为 null（不毁掉整体调用）——使用前 .filter(Boolean)**。
- **pipeline 无 barrier**：item A 可在 stage3 时 item B 还在 stage1（流水线吞吐优先，不等待）。
- **named parallel branches + required-branch boolean gates**：关键分支必须成功才继续（非所有分支都必需）；**map state**：迭代数组跑子工作流；**keyed upsert merging** 合并结构化结果。
- 判据：需要"全部完成后合并"用 barrier；需要吞吐/流式用 no-barrier；关键路径用 required gate。
- 提升层：工具（并发原语）/ 工作流（并行设计）。

### 3. Langflow 1.8→1.11 平台能力演进（工具）
来源：langflow 官方 blog 多页
- **1.8**：全局模型 provider 配置（集中化）+ V2 workflow API（标准化端点）。
- **1.9**：Langflow Assistant（自然语言生成自定义组件/排障/实时文档指引）+ Flow DevOps Toolkit + MCP 支持 IDE/coding agents。
- **1.10**：Assistant 构建**整条 flow**（非单个组件）+ Memory bases（长期语义记忆）+ 可配置向量库后端 + 七语言。
- **1.11**：Human-in-the-Loop checkpoint（门控工具调用+评审）+ A2A 协议支持 + AG-UI streaming + Multi-Vector Retrieval（NextPlaid：ColBERT 式 late interaction + ColPali 视觉文档检索）。
- 判据：平台选型参考——低代码平台已从"拖节点"进化到"AI 建全流程 + HITL 门控 + A2A 互操作 + 多向量检索"。
- 提升层：工具（平台能力基线，选型用）。

### 4. 规则→可执行守卫：Policies 组件 + Agentics map/reduce 数据原语（工具/可复用 Skill）
来源：langflow-policies / langflow-agentics
- **Policies**：把自然语言业务规则（限额/限制/流程）变成**工具调用运行前检查的可执行 guard**——而不是当作 prompt 文本指望模型记住；"好意图不够，每次碰工具都要遵守"。
- **Agentics（逻辑转导代数，arXiv 2603.04241）**：aMap（逐行转换表格列）/ aReduce（多行折叠成一行）/ aGenerate（合成行）——LLM 处理表格数据的 map/reduce 原语。
- 判据：规则若需要在每次工具调用时稳定执行→固化为 guard 组件；表格批量转换→map/reduce 原语而非逐条 prompt。
- 提升层：工具（守卫组件）/ 可复用 Skill（规则固化模板）。

### 5. 动态工作流：模型驱动并行编排 + 热更新 DSL 化（模型/工具/工作流）
来源：vibe-coding-dynamic / cc-bruniaux-dynamic / csdn-dify-engine
- **Claude Dynamic Workflows**：单 orchestrator prompt，模型推理识别可并行子任务→spawn subagents、跟踪执行、聚合结果——**数百并行 subagents，代码不管理并发**。
- **canParallelize 标记**：并行安全处并行、不安全处顺序（filter 出 canParallelize 步骤）。
- **Dify 2026 引擎**（来源 CSDN 2026-07，标注为二手）：JSON Schema+元数据注解替代 YAML；动态分支 JS 表达式**运行时求值**（user.tier==='premium'）；Admin API PATCH /workflows/{id} **热更新免重启**；其声称"编排效率 +400%"未独立验证。
- 提升层：模型（动态编排）/ 工具（DSL+热更新）/ 工作流（并行拆分）。
