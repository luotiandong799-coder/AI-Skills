## 落地 5 独点（每点标注提升层）

### 1. Chunking 三策略与调参纪律：固定/语义/结构感知（工具/工作流）
来源：aipromptshub-rag-pipeline / web3aiblog-chunking-debug / stochasticsandbox-reliable-rag / yuzec-production-rag / ailearningguides-rag-prod
- **fixed-size（512 token/50 overlap）是基线**：快、可预测、均匀散文够用；overlap 处理跨块关键句。
- **semantic chunking**：按嵌入相似度切，主题连贯性低于阈值处断开；**structure-aware**：先按标题/段落/列表项切，超限段回退定长。
- **三大症状定位 chunk 问题**：长文档因多高相似 chunk 主导结果 / 表格列表被拆散导致结构答案不连贯 / 短问返回长而泛的 chunk。
- **调参纪律**：**sweep 256/512/1024/2048 + 10% overlap，用 eval 集 MRR@10 定胜负**；甜区经验 500-1000 token + 100-200 overlap（规则非定律）。
- 判据：先固定尺寸基线再换语义/结构；每次改动用 MRR@10 验证；小 chunk 精确但失上下文、大 chunk 保上下文但稀释嵌入（1024 token 三主题=三主题都平庸匹配）。

### 2. Bi-encoder vs cross-encoder 分工 + rerank 数字：检索宽、重排准、上下文精（工具/工作流）
来源：algorion-cross-encoder / lucioduran-rag-arch / superml-rerank / databricks-retrieval-quality
- **bi-encoder**：查询与文档分别编码比向量——快、可搜百万 chunk，但查询与文档不见面、丢交互信息；**cross-encoder**：查询+候选一起输入打相关性分——准、慢 10-100×。
- **生产架构**：**混合搜索快取 50-100 候选（~10ms）→ cross-encoder rerank top 20-30（~50-80ms）→ LLM 上下文 top 5-8**。
- **rerank 是一行改动 +15% 质量**（Databricks 实证）；配合过滤（metadata 过滤可先减 90%+ 搜索空间）。
- 判据：检索阶段用 bi-encoder 保召回、重排阶段用 cross-encoder 保精度；LLM 上下文宁少勿滥（5-8 块）。

### 3. RAG 评估指标体系：RAGAS 四核心 + 精度面/召回面双视角（工作流/可复用 Skill）
来源：docs-ragas-nvidia-metrics / microsoft-learn-rag-evaluators / arxiv-2604.23515-ragR / ragvue
- **RAGAS 四核心**：**context precision（检索排序准度，mean precision@k）/ context recall（相关信息不漏检，=检索到的相关 claim 数/参考中总相关 claim 数）/ faithfulness（答案每个 claim 都可由提供上下文直接推出）/ answer relevance（答对所问）**。
- **双面视角**：**Groundedness=精度面——响应不包含 grounding 上下文之外的内容；Response Completeness=召回面——不漏 ground truth 关键信息**（有 ground truth 时用）。
- **RAGVUE 单次调用**：**一次 LLM 调用把答案拆成最小原子 claim、逐条标 supported/partially hallucinated/fully hallucinated**——比多阶段多调用的评估便宜且可解释。
- 判据：检索段用 context precision/recall、生成段用 faithfulness/answer relevance；幻觉定位用 RAGVUE 式 claim 级标注。

### 4. GraphRAG 六步管线 + 图/向量分工（工具/工作流）
来源：aws-unified-graphrag-lightrag / essamamdani-graphrag-guide / progressiverobot-graph-enhanced / businesstechnavigator-rag2
- **六步管线**：实体提取（LLM+结构化输出）→ 关系映射（Subject→Predicate→Object）→ 图谱构建（Neo4j/Memgraph/RDF）→ 向量索引（实体描述+原 chunk）→ 混合检索（图遍历+向量相似）→ 上下文组装（ranked subgraph+支撑 chunk）。
- **分工**：**图遍历找实体关系/路径/层级（如企业关系随时间变化），向量找释义相似——hybrid 两者都找**；单一模式各缺一半。
- **按 query 切换策略**：search_strategy per query（graphrag simple/local/global/drift 多档）。
- 判据：多跳关系查询（"A 公司的供应商的竞争对手"）优先图路径；语义近义查询优先向量；复杂场景混合+重排。

### 5. 2026 生产 RAG = 多阶段检索系统：六部件 + 多 agent 变体（工作流/可复用 Skill）
来源：ailearningguides-rag-patterns / dailyaiworld-multi-agent-rag / 1337skills-production-rag
- **ship 形态（非 naive RAG）**：混合搜索跨向量+关键词+图三索引 / 查询改写与分解 / 交叉编码重排 / **分块级访问控制（chunk-level ACL）** / **带引用结构化 grounding（citations）** / RAGAS 式评估 / 从 prompt 到响应全链路可观测。
- **多 agent RAG 变体**：三个专职检索 agent（语义向量搜索 + cross-encoder rerank + 知识图谱遍历）+ judge agent 评估三路候选选最高置信输出（1500 企业 QA 基准实证）。
- 判据：上线前先补重排与引用（最高性价比）；数据含敏感字段先做 chunk 级 ACL；复杂问答用图+向量双路。
