## 落地 5 独点（每点标注提升层）

### 1. Agent trace tree：OTel GenAI 三层 span 模型 + agent 成本核算（工具/工作流）
来源：datallmlab-otel-genai-spec / niteagent-cost-table / langfuse-tracing
- **一个用户任务 = 一条 trace**：**invoke_agent 顶层 span → chat span（每次 LLM 调用）→ execute_tool span（每次工具调用）嵌套其下**（OpenTelemetry GenAI 语义约定，agent trace tree 是最有用的心智模型）。
- **agent 成本不按简单输入×输出算**：**每次工具调用、重试、guardrail 通过、评测检查都加成本**——单次 LLM 调用 $0.001-0.01 vs 多 agent 工作流 $0.05-0.75/次、延迟 ~1-3s vs ~8-45s。
- 判据：一任务一 trace；trace 里每个 LLM/工具步骤都成 span；成本按 trace 累计而非按调用。

### 2. Span-attached evals：评分挂到活 span，trace 自带质量判决（工具/可复用 Skill）
来源：futureagi-llm-observability / futureagi-blog / langchain-online-evaluations
- **生产可观测性要求 eval 分数挂到活 span 上**：span 捕获 LLM 调用→trace 继续→**后台 scorer（heuristic/LLM-as-judge/schema validator/citation grounder/embedding similarity）写评分事件嵌套或链接到该 span**。
- **score 四件套**：**rubric + verdict + explanation + judge model id**——每条 LLM 步骤自带质量判决，不是事后翻日志。
- **线上评估**：对生产流量采样子集跑在线评估器（LLM-as-judge 打分）；采样比例 10-20% 平衡覆盖与成本。
- 判据：eval 分数是 span 的附属事件；每条 span 可回答"这步质量如何、按什么标准、谁判的"。

### 3. Agent 行为质量指标集：行为层观测 ≠ 传统 APM（工具/工作流）
来源：next-gen-cloud-behavioral-metrics / galileo-non-determinism
- **行为质量指标**：instruction-fidelity score（指令保真）/ policy-violation rate / unauthorized-tool-call rate（越权工具调用）/ **hallucinated-tool rate（幻觉工具：调了不存在的工具）** / self-contradiction rate / **refusal correctness（拒绝正确性）** / plan deviation rate。
- **refusal 双向失败**：拒太多=过受限；该拒不拒=治理不足——两个失败模式都要看。
- **非确定性事实**：**temperature=0 时前沿模型仍产生 80% 输出差异**——agent 观测不能沿用传统 APM 的"相同输入→相同输出"假设。
- 判据：行为指标按双向失败模式看；观测层接受非确定性、用分布而非单值。

### 4. Evals 四层评估蓝图 + 评分器分层（工作流/可复用 Skill）
来源：aws-strands-agentcore / microsoft-agent-evaluators / csdn-dongnihao
- **四层**：**L1 outcome（任务完成）→ L2 reasoning（决策逻辑，>85% 阈值，Helpfulness/TrajectoryEvaluator LLM-as-judge）→ L3 tool usage（正确工具/合理顺序）→ L4 robustness（对抗/漂移）**；对的结果+错的推理=失败（会在条件变化时不可预测地挂）。
- **评分器分层**：正确性先确定性检查；语义质量用结构化 LLM 量表；**关键安全条件用不可被平均分抵消的硬门槛**（pass/fail 而非分数）；支持部分得分并区分失败层级。
- **agent 五维评估**：Task Completion / Task Adherence（守指令约束）/ Task Navigation Efficiency（步数效率）/ Intent Resolution。
- 判据：四层全过才算过关；安全项不进平均分；推理层有独立阈值（85%）。

### 5. 评测可复现性：clean state + 钉版本 + 多 trial（工作流/可复用 Skill）
来源：arxiv-2602.18029-standardized-eval / arxiv-2604.12162-alphaeval / csdn-dongnihao
- **deep agent 有状态**：**每个 trial 前环境擦除重种（fresh FS/DB 防 test contamination）**——评测环境不干净，分数无意义。
- **版本控制**：所有 task inputs / 评估脚本 / 参考答案 version-controlled；**harness 与 agent 脚手架版本钉死**（Claude Code 2.1.70、Codex 0.8 等）保证可复现；OTel GenAI 语义约定当版本化契约、定期更新防静默数据破坏。
- **同一任务跑多个 trial**：记录完整轨迹、工具参数、终态、延迟、成本；存储前先净化（scrub prompt/completion 保隐私）。
- 判据：评测=输入+脚本+harness 全钉版本；每 trial 从干净态起跑；结论基于多 trial 分布。
