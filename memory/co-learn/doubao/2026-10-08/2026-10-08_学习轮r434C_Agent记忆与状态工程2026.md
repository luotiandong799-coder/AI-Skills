## 落地 5 独点（每点标注提升层）

### 1. 记忆分层四层 + episodic→semantic→procedural 毕业过渡（模型/工作流）
来源：zylos-memory-architecture / superkind-ai-agent-memory / xelionlabs-persistent-ai-agents / arxiv-2603.07670
- **四层记忆**：**working**（模型上下文窗口=RAM，易失）；**core**（每次调用都可见的结构化小块——用户身份/偏好/当前任务状态/关键事实，无需检索）；**recall**（压缩会话记忆，按需检索）；**archival**（一切其他，可检索——每段历史对话/引用文档）。
- **三种长期记忆类型**：**episodic**（具体交互记录——"3 月 3 日用户问了部署延迟"，按时间序）；**semantic**（泛化知识/用户偏好/领域事实——"用户偏好邮件而非 Slack"）；**procedural**（可复用技能/可执行计划——Voyager 技能库把每个验证过的 Minecraft 例程存成可运行 JS、按 NL 描述索引、组合出新任务）。
- **毕业过渡策略=最难的问题**：episodic 何时升格 semantic——绝大多数 agent 混用至少两种；**过渡靠 consolidation 时确认**（用户确认修好了才把 playbook 计数器 +1）。
- 判据：core 只放每次调用都需要的；recall/archival 按需检索；procedural 独立技能库存。

### 2. 压缩策略三族 + 渐进总结百分比（工作流/可复用 Skill）
来源：zylos-agent-memory-compression / redis-horizon-ai-agents-memory-state-infrastructure
- **三族压缩**：**rolling summary**（周期把旧历史压成摘要，新轮次接在摘要锚点后）；**progressive summarization**（全文→关键句 ~40%→要点 ~15%→executive summary ~5%）；**task-conditioned compression**（当前 query 决定哪些部分保留全保真度）。
- **触发**：交互历史超阈值才压缩，不提前；**外部记忆层=模型本身装不下的上下文**，四件事同时做：保持当前任务连贯/回忆过去决策/随时间积累知识/中断后干净续跑。
- 判据：选压缩族按"是否需要保留细节供回溯"——要细节用 task-conditioned，只要概览用 progressive。

### 3. 检查点与会话恢复工具化：每 N 次调用自动快照 + 跨 agent 续跑（工具/可复用 Skill）
来源：memento-mcp / agent-checkpoint-mcp / lobehub-engram / tuskpoint / glama-mcp-memory
- **自动检查点**：每 25 次工具调用存全 L1 工作记忆快照；**会话中断（上下文上限/配额耗尽/关机）后，下个会话（同 agent 或不同 agent：Claude Code/Codex/Cursor）从最后子任务续跑而非重做**——SQLite 本地零成本，LLM-agnostic handoff prompts 支持会话在 agent 间转移。
- **可验证检查点**：LangGraph checkpointer 把每步存成可验证 blob——崩溃后从精确断点续跑、可回滚到任意时刻、哈希验证交接字节、分叉成新线程、diff/搜索/审计全历史。
- **Session Start 协议**：memory_get_last 取回上次工作位置（project_root 参数），agent 打开项目/启动会话即知道工作停在哪。
- 判据：长任务必须配检查点；中断恢复靠"最后子任务续跑"不是"从头再来"。

### 4. 记忆即基础设施：可靠性工程五部件（工作流/可复用 Skill）
来源：arxiv-2609.05510-memory-as-infrastructure
- **Six Harness 五部件**：**memory core + anti-recurrence stores（防复发存储，专记"别再犯"的纠正）+ precision-gated injection layer（精度门注入层，只注入不变量/近期纠正/近期决策）+ reliability layer + conventions templates**。
- **SessionStart 流程**：decay pass 维护记忆索引文件→health gate 探测全栈并打印一行 verdict→curated render 注入关键内容；**每个 prompt 上 intent detector 决定是否做检索工作**（不每轮都检索）。
- 判据：记忆系统按基础设施对待——健康闸+索引保鲜+按意图决定检索，不是把记忆当普通文件堆。

### 5. 记忆评估与租户隔离：召回率 + 零租户泄漏 + 上下文污染（工作流/可复用 Skill）
来源：elastic-agent-memory-elasticsearch / elastic-kr-ai-agent-memory / dev-tamizuddin
- **生产记忆层评估三维**：**召回（0.89 recall）**+**租户隔离（zero tenant leaks——多租户下 A 租户记忆绝不漏给 B）**+**上下文污染（episodic 是最动态最个人、最易污染上下文的一类）**。
- **procedural 带成功/失败计数器**：每个 playbook 携带 success_count/failure_count，consolidation 时用户确认修好/没修好则相应 +1，计数器作为上下文给 consolidation LLM——**记忆不是一次性写入，是带反馈循环的可量化资产**。
- 判据：记忆评估=召回+隔离+污染三指标；procedural 用计数反馈持续校准。
