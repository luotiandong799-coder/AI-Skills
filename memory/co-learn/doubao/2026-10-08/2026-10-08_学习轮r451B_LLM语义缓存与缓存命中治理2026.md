## 落地 5 独点（每点标注提升层）

### 1. 三层缓存架构+分层命中率（工具/工作流/可复用 Skill）
来源：provod / agentixforce / metacto / markaicode / wickedsmart
- **L1 exact-match=hash(prompt+model+temp) Redis GET ~1ms（精确重复 15-35%）；L2 semantic=embed 查询+ANN 搜索余弦阈值（改写问法 25-45% 叠加，20-100ms）；L3 provider prefix=长 system prompt 60-80% input 节省**。
- **三层顺序构建重复负载可省 70-95% token 开销；语义层命中=完全免模型调用（100% on hit）**。
- 提升层：工具（缓存栈）/ 工作流（分层）/ 可复用 Skill（架构模板）。

### 2. 语义命中阈值与盈亏平衡点（工具/工作流/可复用 Skill）
来源：respan / valuestream / metacto / alivedise
- **阈值=一切：0.95→20-40% 命中含边界、0.97→5%、0.90 危险误命中；生产命中率 40-70%**。
- **AWS 评测 63,796 查询=86% 成本降+88% 延迟改善+精度>91%；语义缓存 hit rate>15-20% 才值（embedding+向量搜索 20-50ms p50/100ms p99 开销）——miss 变慢换边际节省不划算**。
- 提升层：工具（阈值）/ 工作流（盈亏判断）/ 可复用 Skill（阈值调优模板）。

### 3. 缓存键治理：模型版本进 key+归一化（工作流/可复用 Skill）
来源：datarekha / agentixforce / alivedise
- **exact-match key=hash(prompt+model+temp)（不止文本）；embedding 模型升级产生不同向量=key 必须含完整模型标识否则旧向量被新模型服务**。
- **按 model/参数/租户/语言域隔离；miss 时写入=prompt+response+embedding 同 key 模式+TTL**。
- 提升层：工作流（键治理）/ 可复用 Skill（key 规范模板）。

### 4. 命中决策可审计+安全护栏（中毒缓存与 guardrail 位置）（工作流/可复用 Skill）
来源：acethecloud / dev-kuldeep / krites
- **命中决策可审计：eligible=cache_allowed+tenant_match+locale_match+source_versions_current+policy_version_current+similarity>=threshold+answer_type_safe+quality approved；近阈值 0.86-0.92 跑轻量 reranker/verifier**。
- **中毒输出风险=恶意 prompt 进缓存→相似 prompt 命中中毒输出；缓存绕过上游 LLM=下游 guardrail 若不在缓存后会被跳过→guardrail 必须放缓存层之后；Krites=静态-动态分层+灰色地带 off-path LLM judge 验证**。
- 提升层：工作流（安全）/ 可复用 Skill（命中审计模板）。

### 5. 缓存指标与治理：四指标+多租户作用域（工作流/可复用 Skill）
来源：antigravity / maxim / futureagi / zylos
- **上线即埋四指标：hit rate by time/tenant、similarity histogram（看阈值位置）、inferred cost savings=hit count×平均 token 成本、latency p50/p95 hit vs miss 分流**。
- **多租户 SaaS=cache scope 按租户隔离（不能跨租户命中）；近阈值加二次检查、TTL 按 workload profile 配置；把缓存命中率当成本治理指标进同一 dashboard**。
- 提升层：工作流（指标）/ 可复用 Skill（治理模板）。
