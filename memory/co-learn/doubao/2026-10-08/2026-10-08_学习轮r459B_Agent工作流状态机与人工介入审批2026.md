## 落地 5 独点（每点标注提升层）

### 1. Agent 即状态机：显式建模与 durable execution（工具/工作流/可复用 Skill）
来源：channel-tel / subhanshumg / zylos / ms-durable
- **agent 天然是状态机，不显式建模就隐式出 bug；显式状态机=5-7 状态+activities；durable execution=workflow 引擎每步自动持久化状态，崩溃后从 event history 重放跳过已完成步骤——开发者写普通顺序代码，durability 由运行时保证**。
- **orchestration 管控制流（sequence/branch/parallel/error handling）自动 checkpoint；activities 包非确定操作（LLM/tool/API）；checkpoint 后 suspend 最多一年不计费；LLM 调用/tool 调用/agent 循环每步都被持久化——不丢对话记录、不重复工具调用**。
- 提升层：工具（durable 引擎）/ 工作流（状态机建模）/ 可复用 Skill（状态机模板）。

### 2. HITL 审批门与 interrupt 机制（工具/工作流/可复用 Skill）
来源：openai-agents / langchain / ms-ag-ui / labs.ai
- **工具声明何时需审批；触发时 run 暂停、返回 interruptions 数组；RunState 可序列化暂停的运行、决定后从精确断点恢复（approve/reject/modify-then-proceed/cancel）；审批作用于整个运行（不只当前顶层 agent）**。
- **interrupt_on 参数声明哪些工具要审批（LangGraph）；approvalRequiredAI function 包装（MS AG-UI）；PAUSE_CONVERSATION 动作→AWAITING_HUMAN 暂停态；HITL 三层=工具层（执行前暂停单函数）/工作流层（流程间审查）/审批层（决策审批）**。
- 提升层：工具（SDK 机制）/ 工作流（审批流）/ 可复用 Skill（interrupt 配置模板）。

### 3. 审批门五要素清单（contract checklist）（工作流/可复用 Skill）
来源：bestaiweb / truto / anhtu / spillwave
- **每个 gate 写代码前定死五要素：Trigger（精确工具名+参数形状触发暂停）、Payload（人看到什么：动作描述/目标/金额/agent 理由）、Decision set（人能返回哪些决策）、Timeout（N 分钟无决策怎么办）、Audit row（每次决策写审计行含 reject+timeout）——外加 Resume contract（agent 恢复时看到什么状态）**。
- **现实约束=人类会花几天审批、OAuth token 会过期、同步 HTTP 会断——审批期间 workflow 空闲不能丢状态；审批 UX 也是设计一部分（approver 需要足够上下文，不能"盲点批准"）**。
- 提升层：工作流（gate 契约）/ 可复用 Skill（五要素清单模板）。

### 4. checkpoint 策略三模式与风险分层（工作流/工具/可复用 Skill）
来源：genai4a11 / dataaihub / truto / agno
- **三模式：固定 checkpoint（总是暂停——简单可预测但烦人）/风险基 checkpoint（满足风险条件才暂停：>10 收件人/含财务承诺——需先定义风险标准）/置信度基**。
- **gate 写操作不 gate 每 token——只读研究/草稿可自主，退款/发邮件/部署/DB 写要 interrupt；API 端点按风险分层（high/medium/low tier）防确认疲劳；不可逆动作用 Pre-Execution Approval Gate（执行前强制中断，结构上无法绕过）**。
- 提升层：工作流（分层策略）/ 工具（风险分类）/ 可复用 Skill（checkpoint 决策表）。

### 5. durable 引擎与生产编排细节（工具/工作流/可复用 Skill）
来源：temporal / aws-lambda-durable / alibabacloud / conductor / mech
- **Temporal 事件日志序列化每步，崩溃/分区/限流后从最后完成步恢复；AWS Lambda durable functions=context.step()/waitForCallback()/waitForCondition()**。
- **重试数组=错误码模式+最大尝试+初始间隔+退避乘数（不同失败类不同策略：网络错 5 次指数退避、验证错立即捕获不重试）；Sarvam 编排器=超时指数退避或路由 fallback、限流排队冷却、部分失败从最后 checkpoint 恢复、状态冲突 last-write-wins/merge、agent 崩溃重新分配子任务——每个 LLM/tool 调用都作为 durable workflow task 跑，全历史可查**。
- 提升层：工具（引擎选型）/ 工作流（重试编排）/ 可复用 Skill（重试数组模板）。
