## 落地 5 独点（每点标注提升层）

### 1. MemGPT/Letta 三层记忆架构：core/archival/recall（工具/工作流/可复用 Skill）
来源：aiwiki-letta / nthu-report / zylos-memory-consolidation / instagit / mem0
- **MemGPT 把 LLM 当 CPU、context window 当主内存、外部存储当磁盘：函数调用分页（core_memory_append/archival_memory_insert/conversation_search/conversation_search_date）让 agent 自主决定记什么忘什么——Recall=完整可搜索对话历史库，与消息缓冲区分（后者只在 context 窗口内）**。
- **Letta 三层=core（固定记忆块）/archival（可搜索外部存储）/recall（完整对话日志）；MainContext 维护固定大小最近消息列表+Prompt Buffer；A-MEM 采用 Zettelkasten 把记忆组织成自动互链的知识笔记网络；代价=LLM 管理分页给高频交互加延迟与 token 开销（Letta 官方基准承认）**。
- 提升层：工具（MemGPT/Letta）/ 工作流（分页式记忆）/ 可复用 Skill（三层记忆清单）。

### 2. 热/温/冷三档记忆 tier 与存储基质表（工作流/工具/可复用 Skill）
来源：zylos-selective-retention / zylos-persistent-state / konishi-memory-design / genai4a11
- **生产标准三档：HOT=当前对话+即时相关事实（小时-天）/WARM=用户偏好+进行中项目+近期决策（2K-8K tokens，天-周）/COLD=历史对话+已完成项目+旧决策（无限向量索引，月-年）——tier 化减少活跃上下文 60%+**。
- **每层配最优存储基质：episodic=时序日志/向量库、semantic=向量库 HNSW、知识图谱=图库（Neo4j/Graphiti）、procedural=KV/结构化库、checkpoints=对象存储（S3/文件系统）用于恢复**。
- 提升层：工作流（三档 tier）/ 工具（存储选型）/ 可复用 Skill（基质表）。

### 3. 记忆写入时机与遗忘策略（工作流/工具/可复用 Skill）
来源：besthub / arxiv-AdMem / agentixforce / aiorbitx / agentic-ai
- **写入时机：会话结束后异步提取高价值事实写结构化条目（best-effort——可能漏提或固化猜测，需标注置信）；写=语义记忆（单条、带重要度分）+episodic 单条目（带时间元数据）+冷归档压缩全文；不写=中间推理/工具调用日志/对话填充**。
- **遗忘策略：语义记忆由 LLM 管理更新（合并/删除冗余）；procedural 记忆设阈值 ε——低于检索频率即删，两条常被同时检索的合并；temporal decay（久未用降检索优先级）+relevance scoring+显式保留策略（会话级记忆按周期清、工作流实例关闭清对应类型）；增量摘要=周期把旧交互日志压成运行叙事/画像摘要**。
- 提升层：工作流（写入/遗忘时机）/ 工具（AdMem 阈值）/ 可复用 Skill（写入清单）。

### 4. 记忆投毒防御与审计闭环（工具/工作流/可复用 Skill）
来源：google-memory-bank / agentswarms / besthub
- **memory poisoning：错误信息存入长期记忆→未来会话被误信——用 Model Armor 检查进出 Memory Bank 的 prompt（双向输入输出防火墙）**。
- **生产审计闭环：system prompt 注入按轮次记录可回放（能看到模型当时看到什么）；golden recall set 每次部署跑、回归阻塞发布；用户可见记忆查看器+一键擦除+delete-by-user 端点；STM 摘要与 LTM 提取的 token 成本分开跟踪进观测；dev 循环里"禁记忆的 agent"作有用基线（对比记忆到底带来多少增益）**。
- 提升层：工具（Model Armor）/ 工作流（审计闭环）/ 可复用 Skill（防投毒检查表）。

### 5. 检索注入与 Mem0/Letta/Zep 选型对比（工具/工作流/可复用 Skill）
来源：mem0 / aiworkflowlab / mindstudio / codex / tetrate
- **检索注入时序：用户消息→嵌入→向量检索（score filter≥0.3）→top-K 相似过往消息注入 prompt 构建上下文；最简单 LTM 可只用 MEMORY.md——运行开始前 prepend 全文、结束时 append 一条事实，小而稳就走全量注入（include 侧）**。
- **三选型对比：Mem0=轻量层，提取事实进向量库（低延迟、实现快）；Letta=显式 memory-block API（MemGPT 商用化，分页可控但每交互加延迟）；Zep=时态知识图谱 Graphiti 跟踪事实随时间变化（适合事实频繁演变的场景）——按延迟/召回精度/运维成本三轴选**。
- 提升层：工具（三框架）/ 工作流（注入时序）/ 可复用 Skill（选型矩阵）。
