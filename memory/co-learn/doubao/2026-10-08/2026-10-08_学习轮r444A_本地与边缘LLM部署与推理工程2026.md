## 落地 5 独点（每点标注提升层）

### 1. 量化选型三律+GGUF 唯一跨端格式（工具/工作流/可复用 Skill）
来源：acingai / gingerlabs / checkaimodels / stackpractices
- **Q4_K_M 默认甜点位**：约 1/4 全精度大小、1-2% 质量损失，多数任务起点。
- **iso-memory 原则**：同显存下 4-bit 大模型胜 8-bit 小模型（更大模型低精度 > 更小模型高精度）。
- **GGUF 是唯一 CPU/Apple Silicon 可跑格式**（同一文件跑 Ollama/llama.cpp/vLLM）；**AWQ 保护约 1% 最关键权重**，MMLU 接近原精度。
- 提升层：工具（选型）/ 工作流（部署决策）/ 可复用 Skill（量化选型模板）。

### 2. 显存速算+量化档位对照（工具/工作流/可复用 Skill）
来源：specpicks / aimastery / promptquorum
- **Q4_K_M 下约 0.6-0.7 GB/十亿参数**工作估算（更激进 Q2 约 0.4 GB/B 但质量损失显著）。
- 档位对照：q6_K=5.8GB/q5_K_M=5.0GB/q4_K_M=4.3GB/q3_K_M=3.4GB（7B）；70B 对应 58/50/43/34GB；**6-8GB→Q4_K_M、16GB→Q5_K_M、24GB+→Q8_0**。
- 提升层：工具（预算计算）/ 工作流（硬件匹配）/ 可复用 Skill（速算表）。

### 3. 引擎选型三角+并发调优（工具/工作流）
来源：checkaimodels / stackpractices / markaicode / ai-manual
- **Ollama 个人一键 / vLLM 高吞吐服务 / LM Studio+llama.cpp Mac**。
- **OLLAMA_NUM_PARALLEL=4+OLLAMA_MAX_LOADED_MODELS=2** 并发调优；vLLM PagedAttention v3+FP8 支持，吞吐可比 llama.cpp server 高至 10x。
- 提升层：工具（引擎）/ 工作流（个人 vs 服务分界）。

### 4. 服务栈四件套+动态自适应投机解码（模型/工具/工作流/可复用 Skill）
来源：martinuke0 / jared-hpc / fatherofai / arxiv-nightjar
- **static→continuous batching 是单最高杠杆改动**（iteration-level scheduling，动态混 prefill+decode 每步重组）；PagedAttention v2 分页块级 KV 消除 HBM 碎片；**前缀缓存/RadixAttention 跨请求共享重叠前缀 KV**（40% 流量共享 1k system prompt 场景收益大）；**投机解码 2-3x**（draft 小模型生成 K tokens→大模型单 forward 验证，与 continuous batching 同一 scheduler tick 配合）。
- **Nightjar**：MAB planner 按 batch size 动态选投机长度；**投机不再有益时主动禁用并把 draft 模型 offload 到 CPU**（释放显存给 KV cache 扩大 batch）。
- 提升层：模型（投机解码）/ 工具（引擎特性）/ 工作流（共享前缀）/ 可复用 Skill（服务栈选型）。

### 5. 消费硬件边界+MoE offloading（工具/工作流/可复用 Skill）
来源：dzone / gingerlabs-70b / thomascherickal / spheron
- **单 24GB 跑 70B**：AWQ（需 ~38GB）走 device_map="auto" 跨 GPU/CPU 分载，或 **MoE offloading 让 Q4 变体在 24GB GPU+256GB RAM 跑 25+ tok/s**。
- **Qwen3 对照**：4B/8B 单 24GB FP16 可跑；14B/32B 需 INT4 或 48GB；72B+MoE 超单消费卡。
- laptop 可交互跑 30B=激进量化+带宽感知 kernel+单用户推理优化的模型设计（非魔法）。
- 提升层：工具（offloading）/ 工作流（硬件边界判定）/ 可复用 Skill（本地部署模板）。
