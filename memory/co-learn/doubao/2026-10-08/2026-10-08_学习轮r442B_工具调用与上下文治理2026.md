## 落地 5 独点（每点标注提升层）

### 1. 工具调用可靠性五件套（工具/工作流）
来源：belsoftsolutions / genai-club / dev-geminate
- **硬尝试预算**：每条工具调用路径最大尝试数——瞬态失败 2-3 retries+参数错误 1-2 self-correction；**超限触发结构化失败交给工作流编排器（不是再重试）**。
- **每上游熔断器**：下游依赖 5 连续失败/60s→停止尝试 30s 返回缓存/降级响应；**cap 步数+每工具 timeout**（LLM tool loop 安全五件）。
- **五层韧性**：retry budgets/fallback chains/error context/observability/chaos tests——**开源框架通常无结构化 retry/fallback；工具失败是 agent 任务放弃主因**。
- 提升层：工具（预算/熔断参数）/ 工作流（故障分层）。

### 2. 调用前校验+自动修复+fail-open（工具/可复用 Skill）
来源：pypi-cruxial / arxiv-ATLAS-RTC / dev-jeff-schema
- **拦截每个 tool call→args 对 schema 校验→幻觉参数自动修复（structured retry）**；本地校验无网络跳 <1ms p99；**fail open（校验器自己出错工具仍运行）**。
- **严格 JSON Schema 约束**：**additionalProperties:false 全列属性；每属性必进 required（可选用 union 含 null 表达，不靠省略）；type:["string","null"] 表示可空**。
- 提升层：工具（校验层）/ 可复用 Skill（schema 模板）。

### 3. 显式路径错误载荷回授闭环（工具/工作流）
来源：dev-shaurya / aaif / mcp-spec
- **SCHEMA_VIOLATION 错误码+instancePath+message+received+recovery_hint**（例："把 amount 参数转成不带货币符号的整数"）——**LLM 读显式路径载荷能自纠**。
- **schema 错误→feed 回模型→prompt 修正 payload→re-issue 调用（不记非法传输）**；**MCP Tool Execution Errors 含可行动反馈供模型自纠重试**；ATLAS-RTC token 级运行时控制（输出边界治理）。
- 提升层：工具（错误契约）/ 工作流（回授闭环）。

### 4. 上下文三分区+生命周期驱逐+自适应预算（模型/工具/工作流）
来源：arxiv-VISTA / arxiv-TokenPilot / arxiv-MemArchitect / mslearn-compaction
- **VISTA 工作台三区**：W_t=(V_t,A_t,P_t)——可见块发模型/存档负载存 prompt 外/阻断大结果不入活跃流；下一调用由可见块组装。
- **TokenPilot 段三状态**：active/completed/evictable 维护 registry，按段任务效用动态调节保留窗（保物理缓存连续性）。
- **MemArchitect 自适应预算**：高置信检索 Reasoning Reserve 30%（给 LLM 思考）/低置信 Recall Reserve 10%（找事实）；**TokenBudgetComposedStrategy=多策略顺序流水线，early_stop=True 满足预算即停，fallback 排除最老组**。
- 提升层：模型（compaction/驱逐）/ 工具（预算策略）/ 工作流（上下文装配）。

### 5. 幂等 key 生成位置+并行调用治理+原生 compaction+会话恢复（工具/工作流）
来源：inductivee / tomodahinata / loooop / openai-responses / infoq-project-think
- **幂等 key 由 agent framework 生成（非工具自身）**作为参数传入；基础 key=工具名+规范化参数哈希，**业务级唯一键（order ID）优先**（参数 alone 会吞两次有意订单）。
- **parallel_tool_calls**：模型并发调用造成协调挑战时 toggle 关掉；单条有序消息收集返回全部输出消除 race；流式内联满足工具输出免额外请求。
- **原生 compaction**：模型训练成分析前会话状态产 compaction item（加密 token 高效保留关键状态），压缩后窗口=compaction item+高价值前段；**runFiber+ctx.stash() 进度存 co-located SQLite，平台重启 mid-loop→onFiberRecovered hook 从最后 checkpoint 恢复**。
- 提升层：工具（幂等/持久化）/ 工作流（并行与恢复）。
