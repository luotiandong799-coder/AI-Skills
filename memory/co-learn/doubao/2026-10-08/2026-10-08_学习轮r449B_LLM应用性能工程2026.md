## 落地 5 独点（每点标注提升层）

### 1. 性能指标分层：TTFT/TPOT/ITL/TPS+两阶段归因（工具/工作流/可复用 Skill）
来源：valuestreamai / ayinedjimi / vllm / toutiao
- **TTFT（首 token 延迟）受 prefill 阶段主导、交互 UX 关键；TPOT/TPS（生成吞吐）受 decode 阶段主导（顺序逐 token）；ITL（token 间延迟）流式体验**。
- **优化先归因阶段再选手段；prefill token 预算减半（8K→4K）=新会话更快切入批次、排队中位等待 550ms→110ms、TTFT↓20%**。
- 提升层：工具（指标）/ 工作流（阶段归因）/ 可复用 Skill（预算调参模板）。

### 2. 批量与 KV 缓存工程：continuous/selective batching+paged KV+前缀缓存（工具/工作流）
来源：system-design-space / inferenceengineering / vllm
- **continuous in-flight batching=请求完成即出列、新请求即时补位（批不等最长答案、GPU 利用率高）**；**selective batching=只对正确的操作批量；paged KV cache=现代引擎基础（vLLM/TensorRT-LLM）**。
- **前缀缓存=消除重复 prefill 计算；应用顺序=先量化+连续批（最大收益最小成本）→投机解码/前缀缓存/解耦（高价值后置）**。
- 提升层：工具（批处理）/ 工作流（优化顺序）。

### 3. PD 分离+冷启动治理（工具/工作流/可复用 Skill）
来源：toutiao-prime / vllm-qwen38 / mlflow
- **Prefill/Decode 物理分离（独立实例/资源）：prefill 计算密集、decode 访存密集、各自最优配置；PD 分离在高吞吐场景=5000 token/GPU 总吞吐**。
- **多阶段模型（Omni 音频）=CUDA Graph capture+异步 chunk 交接（音频 TTFP 5884ms→655ms、RTF 1.15→0.63）**；**冷启动=权重加载/LoRA 加载几百 ms 尖峰（TTFT 核心 UX 时 300ms 也可察觉）→预热/保活**。
- 提升层：工具（部署拓扑）/ 工作流（冷启动对策）/ 可复用 Skill（PD 分离模板）。

### 4. 并发扫描与压测：找饱和点+真实负载（工具/工作流/可复用 Skill）
来源：aws-concurrency / nvidia-aperf / spheron / digitalocean
- **并发扫描=吞吐-延迟曲线 knee（吞吐平、p99 陡升）=饱和点（案例 25 并发）；p50→p99 差距拉宽=排队信号**。
- **压测=多进程客户端防瓶颈（AIPerf 替代 GenAI-Perf）+到达模式（constant/Poisson/gamma 突发）+真实 trace 重放（ShareGPT/Mooncake/WEKA AgentX）；覆盖 15+ 端点类型**。
- 提升层：工具（压测）/ 工作流（扫描方法）/ 可复用 Skill（knee 判定模板）。

### 5. 流式监控四指标+延迟感知扩缩（工具/工作流/可复用 Skill）
来源：zero-to-ai / together / spheron-keda / mslearn / digitalocean
- **流式专用指标=active_connections(Gauge)/ttft_seconds(Histogram)/tokens_per_second(Summary)/stream_errors_total(Counter)**。
- **扩缩信号=TTFT P99/队列深度/排队等待/in-flight 请求/GPU 内存/TPS（不是 CPU 利用率）；KEDA+Prometheus 直接盯 TTFT P99；队列深度阈值≈并发限 75%（案例 32 并发→24）；生产 TTFT 目标=chat p95<500ms/code 内联<100ms/文档分析<5s**。
- 提升层：工具（监控）/ 工作流（扩缩）/ 可复用 Skill（SLO 预算模板）。
