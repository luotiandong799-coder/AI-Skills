## 落地 5 独点（每点标注提升层）

### 1. 节点级错误处理：retry / Error Workflow / continueOnFail 纪律（工具/工作流）
来源：n8n 官方 docs + n8nautomation + witscode + dev-ciphernutz
- **节点 retry 设置**：2-3 次足够 + 指数退避（1s/2s/4s）；复杂退避=5 次 base 1s multiplier 2（1/2/4/8/16s）+ **0-1000ms jitter 防十次执行同步锤击同一恢复中的 API**。
- **Error Workflow**：以 Error Trigger 开头、可在 Workflow Settings 关联——跨多个工作流复用、失败集中告警（邮件/Slack）。
- **continueOnFail 慎用**（过度使用掩盖错误）；错误消息带上下文（含 execution link）；**故意触发错误测试错误场景**；重试过多延迟错误检测。
- 提升层：工具（节点配置）/ 工作流（错误设计）。

### 2. 人工审批门三纪律（工具/工作流）
来源：n8n-human-oversight / mech.app-approval-gates
- **只先给最高风险工作流加监督**（"让你睡不着觉的那条"）——别一次全加，学一条扩一条。
- **幂等键+Wait 节点按 execution ID 去重**——防重复退款/扣款（Stripe 等支付 API 支持）。
- **agent 拒绝后循环再请求→拒绝时给明确指令**（"不要重试，改为 X"）；**测试超时与升级路径**（reviewer 度假/Slack 消息没被看到时怎么办）。
- 提升层：工具（审批门）/ 工作流（HITL 设计）。

### 3. Dify 三层错误策略 + 节点类型差异化（工具/可复用 Skill）
来源：ai-guide-expert / lobehub / dify 官方
- **三策略**：abort（默认：错误停整个工作流——不可恢复错误）/ default-value（返回预定义默认值继续——非重要处理）/ fail-branch（错误走失败分支——需要替代逻辑/恢复）。
- **边配置**：success-branch/fail-branch 双 sourceHandle + 变量聚合器合并回主路径。
- **节点类型差异化**：LLM（无效响应→默认输出/条件分支）、HTTP（404/500/超时→重试间隔+详细错误消息）、Tool（主工具失败→快速切换备份工具）、Code（运行时错误→预定义值/逻辑分支）。
- **Code sandbox 违规**（超内存/执行时间被终止）→优化内存/分页/拆多 Code 节点/Step Run 模式定位资源密集操作。
- 提升层：工具（工作流节点）/ 可复用 Skill（错误模式模板）。

### 4. 生产运维：model gateway 熔断 + 背压 + 会话 TTL（工具/工作流）
来源：markaicode / deepwiki-dify
- **executor 无响应**（LLM provider 503）→**circuit breaker on model gateway→fallback 本地模型**；健康检查端点失败/p99 延迟飙升检测。
- **队列无界增长**（编排快于消费）→水平扩 executor + orchestrator 背压；Redis 内存饱和（会话历史无 TTL）→**每会话 TTL + 冷历史迁 PostgreSQL**（驱逐率 10% keys 告警）。
- **工具限流三源**：外部 API 限流 / 工作区配额 / 每工具调用限制——网络错误指数退避、API 错误消息回传、无效输入调用前验证。
- 提升层：工具（运维组件）/ 工作流（容量设计）。

### 5. LLMOps 工件版本化 + 评估门 + prompt semver（工具/工作流/可复用 Skill）
来源：alicelabs / omnithium / mlflow / databricks
- **LLMOps 工件=prompts/检索配置/模型提供商设置/评估阈值——全部需版本控制+同行评审+自动化测试**；**语义评估 LLM-as-judge 是 CI/CD 标准**（确定性字符串比较不适用 agent 输出）；**失败离线 eval=阻塞 CI check**（Braintrust/Latitude/Langfuse/LangSmith）。
- **prompt semver**：MAJOR（输出格式/行为/接口破坏）/ MINOR（向后兼容新能力）/ PATCH（bug/措辞）；跨 prompt 依赖+外部系统版本追踪防不兼容组合。
- **先自动化版本化与评估门，再自动化重训练触发**——"在坏数据上更快重训练=更快做错"；指标用异常检测抓固定阈值报警漏掉的慢回归。
- 提升层：工具（评估门）/ 工作流（LLMOps 管线）/ 可复用 Skill（版本化规范）。
