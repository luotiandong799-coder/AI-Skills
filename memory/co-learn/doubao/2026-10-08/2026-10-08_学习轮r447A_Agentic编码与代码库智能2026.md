## 落地 5 独点（每点标注提升层）

### 1. 代码知识图谱基建：Tree-sitter 增量解析+图谱+MCP 暴露（工具/工作流/可复用 Skill）
来源：10xdev / zylosai / sentra / code-graph-pro / mcprepository
- **Tree-sitter 增量解析=语言无关 AST（25+ 语言）、文件变更只重解析受影响节点**；图谱节点=函数调用/导入/类继承/接口实现/执行流；**经 MCP server 暴露给 agent（GitNexus 28k★/codebase-memory-mcp 38k★ C 实现 14 tools/CodeGraph 42 tools×38 语言）**。
- **实测收益=94% 更少工具调用/77% 更快探索/token 最多省 120×（分类查询：按模式找函数 ~200 vs ~45000 token=225×；调用链深度3 ~800 vs ~120000=150×；死代码 ~500 vs ~85000=170×；HTTP 路由清单 ~400 vs ~62000=155×）**。
- 提升层：工具（图谱栈）/ 工作流（先建图再问答）/ 可复用 Skill（图谱查询模板）。

### 2. 混合检索三支柱互补+检索漏斗四层（工具/工作流/可复用 Skill）
来源：arxiv-2607-AgentRetrievalBench / codex-corebench-funnel / aiproplaybook-semble / bytebell
- **嵌入/词法/RepoMap 互补=组合语义向量+词法路径信号+仓库图+源码-测试关系+任务感知重排**；**检索漏斗=grep→glob→符号→语义搜索四层逐层升级，别一上来就语义搜索**。
- **Semble=Tree-sitter 分块+Model2Vec 静态嵌入+BM25 混合：比 grep+read 少 98% token，2000 token 内召回 94%（对照 85% 满 100k 上下文）**。
- 提升层：工具（检索栈）/ 工作流（漏斗分层）/ 可复用 Skill（分块-融合模板）。

### 3. Agent Retrieval Bench：文件级上游检索评测（工具/工作流/可复用 Skill）
来源：arxiv-2607 / alphaxiv
- **patch 生成依赖更早的上下文获取阶段（找到任务所需仓库文件）——上游检索被低估**；**相关度定义=agent 下一步需要什么，而非 query-文件语义相似**；**覆盖四类正向检索任务（issue-to-code/bug-report-to-root-cause/migration 等）；冻结 base-commit 仓库上评测**。
- 提升层：工具（评测基准）/ 工作流（先检后改）/ 可复用 Skill（检索评测模板）。

### 4. 符号感知分块+增量索引实现机制（工具/工作流）
来源：zylosai / jetbrains-context / bytebell / pypi-codebase-index
- **语义搜索能找不同术语但同功能的代码（verify_token vs check_permissions）**；**符号感知分块=按 AST 符号边界分块而非固定长度；混合 BM25+向量+RRF 融合；BLAKE3 Merkle 树做增量索引（文件变更只重索引受影响子树）**。
- 提升层：工具（实现机制）/ 工作流（索引策略）。

### 5. 仓库级上下文工具选型判据（工具/工作流）
来源：sentra / jetbrains-context / npm / listicler
- **编码瓶颈不是模型是上下文**：选型判据=增量索引（自动保持最新）/语义搜索（免 grep 猜测）/大规模 monorepo 支持（百万文件级）/**每仓库本地作用域**/跨 harness 可查询（MCP 标准协议而非单一 IDE 绑定）。
- 提升层：工具（选型）/ 工作流（接入协议）。
