## 落地 5 独点（每点标注提升层）

### 1. 级联路由：训练小模型知道何时 defer（模型/工具/工作流）
来源：distillabs / arxiv-CRE / agentnative / xyzbytes
- **两梯队级联**：微调 SLM 解决简单多数+frontier 处理硬少数——质量匹配大模型+小成本（无 SLM 单独使用的静默错误）。
- **别建 router 先跑单模型基线**：单强便宜模型+retry 可能比三阶级联+路由维护更划算（MiniMax-M2.5 SWE-bench 80.2% @$0.30/$1.20，Opus 输出价 ~95% 更贵）；**Stage1 聚类分配最省模型+Stage2 质量估计级联低质量升级更强模型**。
- **小模型承担 80-90% 调用**（分类/提取/路由/模板生成是生产多数）；**路由无测量=降质伪装**。
- 提升层：模型（SLM 微调）/ 工具（级联）/ 工作流（基线先行）。

### 2. 路由评测：LLMRouterBench 关键发现+RouterArena（模型/可复用 Skill）
来源：zylosai / arxiv-2608.14641 / ulab-LLMRouter
- **LLMRouterBench（ACL 2026）**：400K+ 实例/21 数据集/33 模型/9 路由方法——**许多路由方法（含商业路由器）不能稳定胜过简单基线**。
- **RouterArena**：实时榜 9 域/44 类/3 难度（测量而非断言）；**LLMRouter 五协调拓扑：MFRouter 76.48 vs 最大模型 71.48——路由每个节点优于最大模型基线**；**四开源路由共接口评测（290 冻结任务/2,610 候选结果）——三路由发恒定或近恒定层级分配（未真正路由）**。
- 提升层：模型（基准认知）/ 可复用 Skill（路由选型判据）。

### 3. 工具调用专用路由（工具/工作流）
来源：arxiv-Switchcraft / langchain-switchyard / effloow-RouteLLM
- **Switchcraft**：工具调用路由 82.9% 匹配/超最佳单模型（GPT-5.3-chat 82.3%）+降本 84%（每百万查询省 $3,600）；**更贵模型不总优于更便宜**。
- **Switchyard（NVIDIA）**：Deep Agents 套件仅 7% 调用需 frontier（30B 处理 93%）；Nemotron 3.5 Lightning↔Claude Opus 4.8 降 74% 成本保留 93% 准确率。
- **RouteLLM（LMSYS/Chatbot Arena）**：预训练路由器（矩阵分解等）前置强/弱两模型按请求决策。
- 提升层：工具（路由器）/ 工作流（成本曲线斜率）。

### 4. Rubric 评测：显式性+任务自适应+图结构化（模型/工具/可复用 Skill）
来源：arxiv-Autorubric / arxiv-AdaRubric / semanticscholar-GSR / arxiv-Xpertbench
- **LLM 需操作性定义**：人类可凭直觉应用未细化标准；LLM 要求"响应正确回答用户问题如 prompt 所陈述"而非"响应有帮助"；binary/ordinal/nominal 标准+可配权重+单/多 judge。
- **AdaRubric**：评估维度应是任务函数而非评估者固定属性——静态 rubric 引入系统偏差、奖励无关风格属性；按任务 T 生成动态 rubric R(T)=N 个任务特定正交维度+校准 5 点评分。
- **GSR**：响应前把 rubric 编译成 typed evaluation graph（native tie/abstention 下 pairwise 准确率最高）；**Xpertbench**：专家级任务每任务 15-40 加权检查点+ShotJudge（LLM judge 用专家 few-shot 样例校准缓解 self-rewarding bias）。
- 提升层：模型（judge 校准）/ 工具（rubric 框架）/ 可复用 Skill（rubric 模板）。

### 5. 评审器分级+脆测试规避+judge 对抗审计（工具/工作流/可复用 Skill）
来源：anthropic-demystifying / arxiv-PReMISE / semanticscholar-ImpossibleRubrics
- **grader 分级**：能确定性 grader 用确定性；必要时 LLM grader；人工有判断地用（judiciously 补充验证）。
- **别检查 agent 按特定顺序调用工具**：太僵化→脆测试（agent 常达成目标但路径不同）。
- **PReMISE 审计四轴**：structural adequacy/reliability/preference fit/adversarial robustness——**无单一原始 rubric 源同时可靠+偏好匹配**；**ImpossibleRubrics**：黑盒对抗框架用语义保持编辑误导 LLM judge 虚增分数——**LLM-as-judge 范式根本弱点**。
- 提升层：工具（审计）/ 工作流（grader 选型）/ 可复用 Skill（对抗测试模板）。
