## 落地 5 独点（每点标注提升层）

### 1. 缓存友好 prompt 排序+byte-exact 匹配（工具/工作流/可复用 Skill）
来源：aiworkflowlab / baeseokjae / niteagent / datarekha / genta / braindrip / dev-fresh_interest
- **静态优先动态置后**：角色人格→核心指令→工具 schema→少样本→RAG 文档→对话历史→当前用户消息→时间戳/请求ID/会话数据（几乎所有 prompt 直觉写反）。
- **byte-exact 匹配**：改一个字符→该前缀起全部缓存失效（byte-level/token-level 形状）；**确定性序列化**：工具按名排序、JSON key 顺序稳定、schema 格式稳定、指令块顺序稳定、去时间戳/去随机示例/去 trace ID。
- **缓存阈值利用**：系统提示不足 4096 token 时补结构化文档/示例/推理准则越过门槛（追加 token 成本远小于解锁缓存收益）。
- 提升层：工具（构造规则）/ 工作流（prompt 结构）/ 可复用 Skill（缓存友好模板）。

### 2. 命中率监控与诊断（工具/工作流）
来源：baeseokjae / devtoollab / dev-ayinedjimi
- **生产目标 70-90% 命中率；<50% 提示结构性问题的信号**（动态内容泄漏进前缀）；命中率管道进 Prometheus/可观测栈。
- **RAG 会话级内容注入前缀=缓存杀手**；provider 暴露缓存指标但口径不一（都含命中/未命中计数）。
- 提升层：工具（监控）/ 工作流（诊断）。

### 3. 多租户缓存 key 分离（工具/工作流）
来源：dev-alexcloudstar
- **缓存含用户特定内容（用户名/工作区 ID/租户配置）→缓存按用户 key→每人首请求冷缓存+TTL 内不回来永不暖**。
- 修法：**租户特定上下文与稳定系统上下文分离，只缓存稳定部分**。
- 提升层：工具（缓存设计）/ 工作流（多租户架构）。

### 4. provider 缓存机制差异（工具/可复用 Skill）
来源：openai-gpt6 / aipromptshub / aiworkflowlab-hu
- **Anthropic 显式 breakpoint+最小缓存 4096 token；OpenAI 自动前缀缓存（GPT-6 起 30 分钟内复用共享前缀享折扣+新监控/诊断/选择缓存范围工具）；Gemini 显式缓存 ID+TTL（最小 4096+存储费 $4.50/MTok/时）**。
- **折扣幅度：Anthropic ~90% / OpenAI ~50% / Google ~75%**；先按现有 provider 起步。
- 提升层：工具（选型）/ 可复用 Skill（缓存配置模板）。

### 5. KV cache 机制+长上下文扩展技术（模型/工具/可复用 Skill）
来源：dev-fresh_interest / arxiv-2607-jetlong / arxiv-pose / arxiv-2402 / learnixo / arxiv-2409-landmark
- **KV cache：只算新 token 的 KV，前缀靠复用；attention 硬约束=每个 token KV 只依赖其前 token，前缀改一个字符其后全部失效重算**。
- **长上下文扩展技术**：位置插值 PI（长序列映射进训练范围，非外推）/ PoSE 位置跳过训练（固定窗口模拟长输入解耦训练长与目标长）/ Jet-Long 动态双焦 RoPE（免调零样本，短输入精确恢复+长输入外推）/ Landmark 分块+地标 token 两级注意力；超训练长后两种微调模型都退化（32K 后）。
- 提升层：模型（机制认知）/ 工具（上下文技术选型）/ 可复用 Skill（扩展方案）。
