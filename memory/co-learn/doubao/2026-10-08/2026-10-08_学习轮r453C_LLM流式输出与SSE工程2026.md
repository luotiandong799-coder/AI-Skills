## 落地 5 独点（每点标注提升层）

### 1. SSE 是 LLM 流式默认传输（工具/工作流/可复用 Skill）
来源：nisai / gyanbyte / stochasticsandbox / aiagentskit
- **SSE=W3C text/event-stream、单向 HTTP、代理/Cloudflare 友好、EventSource 自动重连；vs WebSocket=双向但代理兼容差、重连手动实现、可传二进制**。
- **LLM 流式默认 SSE（OpenAI/Anthropic/Google 原生）**。
- 提升层：工具（传输）/ 工作流（选型）/ 可复用 Skill（传输对比）。

### 2. TTFT/TPOT 双指标与流式感知（工具/工作流/可复用 Skill）
来源：metacto / redis / cissychen / theneuralbase / aws
- **TTFT 主导感知延迟：<300ms 瞬时/300-700ms 灵敏/>1.5s 需 thinking UX；TPOT=首 token 后平均 token 间隔**。
- **流式不省总时长（wall-clock 几乎一样），只是消除"盯空白"最差时段；生产前测 TTFT、单一 provider 也要先做 fallback 路由、熔断阈值 p95 TTFT>1.5× 基线宽松触发防误报**。
- 提升层：工具（指标）/ 工作流（阈值与路由）/ 可复用 Skill（指标模板）。

### 3. 背压三策略与断线恢复（工具/工作流/可复用 Skill）
来源：webcoderspeed / zero-to-ai / aiworkflowlab / atlosz
- **背压：无界缓冲=OOM 危险/丢 token=快但破坏响应/有界队列+断连=生产最安全**。
- **断线恢复：SSE id: 字段+Last-Event-ID 自动续传（而非重启生成），LLM provider 流不可回放→已到 token 存内存/Redis+客户端去重续接**。
- 提升层：工具（缓冲/恢复）/ 工作流（断线处理）/ 可复用 Skill（背压模板）。

### 4. 部分 JSON 解析与流式 tool call（工具/工作流/可复用 Skill）
来源：devto-codepy / llmversus / ai-tldr
- **token 中途落在对象中间（{"name":"Joh）→raw_decode 缓冲累积+可能完整时解码**。

- 提升层：工具（解析器）/ 工作流（增量渲染）/ 可复用 Skill（解析模板）。

### 5. 厂商流式格式差异与 chunk assembly 归一化（工具/工作流/可复用 Skill）
来源：machinelearningplus / datallmlab / prompt-architects / buildwithmostafa / iideas18
- **OpenAI Chat=chat.completion.chunk+delta.content、结束 data:[DONE]、usage 需 include_usage 且仅最后 chunk；Anthropic=typed events（message_start/content_block_delta(text_delta/input_json_delta/thinking_delta)/message_delta(输出累计 usage)/message_stop/ping）、输入 token 立即可见、错误显式事件 overloaded_error；Gemini=alt=sse URL 参数+finishReason**。
- **各家格式不同→chunk assembly 拦截原始 SSE 归一化 delta 按类型路由（text/tool call/thinking）组装最终 payload**。
- 提升层：工具（归一化层）/ 工作流（多厂商适配）/ 可复用 Skill（事件映射表）。
