## 落地 5 独点（每点标注提升层）

### 1. prompt 技术随模型族老化：策略必须按模型族适配（模型/工作流）
来源：arxiv-2608.24641
- **prompt 工程按模型族特定方式"老化"**：新 GPT 模型结构化提示边际收益递减甚至为负（instruction-following 与推理 scaffold 日益内化）；Qwen 仍从 Few-Shot/CCoT 大幅获益；Mistral CCoT 持续增益但 CoT/PoT 衰减。
- **含义**：同一 prompt 配方换模型族不能平移——**模型升级后必须复测 prompt 策略，按族适配**。
- 提升层：模型（策略选型）/ 工作流（升级复测纪律）。

### 2. prompt 版本化 + 金标集回归套件 + canary 部署（工具/工作流）
来源：aipromptshub / dev-to-golden-dataset / explainx / databricks / futureagi
- **每个 prompt 有版本，旧版可回滚，回滚=一次配置变更**（git-native：prompt 当代码管）；canary 部署渐进放量。
- **金标集=版本化的输入+ground-truth labels/rubrics，是 prompt 的回归套件**——改动劣化先于到达用户被抓住；**从真实用户任务起（真实工单含失败场景/多轮），非合成示例**。
- **模型更新破坏 prompt 三选项**：patch prompt（加示例/澄清歧义/调格式）/ pin 模型版本（API 支持）/ 接受回归并更新 evals 基线。
- **30-token 编辑不评估会静默回归长尾 cohort**；同模型同任务手调 vs 优化器调 TaskCompletion 方差 8-15 点。
- 提升层：工具（版本化+金标集）/ 工作流（发布管线）。

### 3. DSPy 优化器族：structured signature + 大模型优化小模型部署（工具/工作流/可复用 Skill）
来源：dspy 官方多页
- **结构化 signature 而非手写 prompt；compile against metric**——给示例+打分函数，自动调到质量收敛。
- **优化器族**：BootstrapFewShot（teacher 模块生成示范）/ BootstrapRS（按输入检索 k 近邻训练示例当示范——无单示范集通用时）/ MIPROv2（指令+few-shot 联合贝叶斯优化）/ GEPA（自然语言指令进化）。
- **大模型做 prompt 优化、小模型部署**（gpt-4o 调→gpt-4o-mini 跑）；**自我一致性投票抑制杂散错误**；stage 级验证（self-reflection/chain-of-verification）再提质量。
- 提升层：工具（优化器）/ 工作流（调参管线）/ 可复用 Skill（DSPy 模板）。

### 4. 推理 effort 旋钮三接口 + 按任务选档（模型/工具/工作流）
来源：dreaming.press / futureagi / airising / devtoollab / google-cloud / dev-to-monuminu
- **三厂商接口不兼容**：OpenAI reasoning_effort 离散级（minimal/low/medium/high，新模型加 none/xhigh）；Anthropic thinking.budget_tokens 连续；Gemini thinking_budget 软限制（-1=动态预算最高 8192）。
- **按任务选档**：确定性/格式化/检索分类任务=最低档（低档≈0-2K thinking tokens、跳过深链）；**生产监控 reasoning_ratio>0.7=effort 过高**——从最低 effort 起步，浅推理再升一级。
- **CoT 何时有害**：延迟/成本敏感端点、简单分类检索、<7B 模型。
- 提升层：模型（接口语义）/ 工具（成本控制）/ 工作流（选档规则）。

### 5. 预算化推理控制 + 元认知/弹性推理（模型/工具/工作流）
来源：techrxiv / arxiv-CoT2-Meta / arxiv-ACTS / papernotes-elastic
- **budgeted reasoning policy：C(q;π)≤B**（CoT tokens/采样轨迹/解码步数预算）——推理=精度-成本优化问题。
- **CoT²-Meta 元认知控制四件套**：strategy-conditioned 思考生成 / tree search / 在线 process oracle（步级评估）/ meta-controller 通过 expansion/pruning/repair/stopping/fallback 分配计算。
- **ACTS**：controller 观察推理轨迹+剩余预算，发出"推理策略+引导短语"的 steering action——预算感知的推理控制。
- **Elastic Reasoning**：thought/solution 段分开 token 预算 + GRPO 预算约束 rollout——训练模型在思考被截断时仍正确作答。
- 提升层：模型（推理控制）/ 工具（预算治理）/ 工作流（成本优化）。
