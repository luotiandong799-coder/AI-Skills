## 落地 5 独点（每点标注提升层）

### 1. n8n AI Agent 节点=有界执行环境+记忆子节点（工具/工作流/可复用 Skill）
来源：n8n-blog-memory / n8n-agents / n8n-vs-langgraph
- **AI Agent root node=有界执行环境：LLM（多 provider 含本地 Ollama）+工具+记忆+检索全部可视化接成 sub-nodes**。
- **记忆=canvas 可配置子节点（对话历史存储/持久时长/检索或清空时机）；记忆分层=会话记忆与长期记忆配置；Agent 与记忆/工具逻辑同在画布可见**。
- 提升层：工具（节点架构）/ 工作流（记忆配置）/ 可复用 Skill（节点接线模板）。

### 2. Manager Agent+sub-agent 分工模式（工作流/可复用 Skill）
来源：n8n-workflow-7158 / n8n-architecture / n8n-react
- **Manager Agent=评估用户输入→委托给专门 sub-agent（每个 sub-agent 自己的角色/记忆/模型）；ReAct 不再独立节点=内置 Tools Agent（迭代推理+工具选择+观察决策）**。
- **拓扑层模式=Orchestrator-Executor（sub-workflow+AI Agent Tool 节点）/Pipeline 顺序链/Parallel Fan-Out/Fan-In（分支+合并）——模式可切换可组合**。
- 提升层：工作流（分工）/ 可复用 Skill（模式模板）。

### 3. 生产化人工监督 Playbook（工作流/可复用 Skill）
来源：n8n-production-human-oversight
- **先识别最高风险 AI 工作流→在那先实现人工监督→学习后再扩展**。
- **测试 timeout 和升级路径（评审者度假了怎么办/Slack 消息没人看/邮件进垃圾箱）；happy path 好建、边界路径易忘**。
- 提升层：工作流（监督部署）/ 可复用 Skill（边界测试清单）。

### 4. Dify 错误处理四类节点+Agent 节点最佳实践（工具/工作流/可复用 Skill）
来源：dify-error-blog / dify-llm-node / dify-agent-node / deepwiki
- **四类关键节点可自定义错误处理（捕获异常保持工作流执行）；LLM 节点=最大重试/间隔/退避乘数+fallback（默认值/错误路由/备选模型）；HTTP 节点=超时配置+重试 2-3+Continue on Error+circuit breaker（不可靠 API）**。
- **Agent 节点最佳实践=清晰工具描述（何时怎么用）/适当迭代限制（防失控成本）/详细指令（角色+目标+约束）/记忆管理（上下文保留 vs token 效率）**。
- 提升层：工具（错误处理）/ 工作流（fallback 链）/ 可复用 Skill（Agent 节点模板）。

### 5. Dify 隐性配置断点+跨平台选型（工作流/工具/可复用 Skill）
来源：csdn-dify / aisa-dify / pipedream-review / activepieces / worldmetrics
- **Dify 隐性断点=Agent 节点未显式启用 use_llm_as_tool/enable_thinking（子任务结果无法回传）；工具输出走 prompt variable 不走 Context 字段（Context 拒收工具信封报 Invalid context structure）；LLM 节点必须有 User 消息（只有 System 消息部分模型返回空串）；并行 Iteration 内 knowledge-retrieval 报 Working outside application context→关并行**。
- **平台选型=Pipedream API-heavy serverless（managed OAuth 3000+、code steps、99.95% SLA）/Activepieces AI agent+自定义指令（ap_search_actions 按任务搜工具、checkpointed state 部分运行恢复、step-level logs）/n8n 自托管**。
- 提升层：工作流（断点清单）/ 工具（选型）/ 可复用 Skill（迁移模板）。
