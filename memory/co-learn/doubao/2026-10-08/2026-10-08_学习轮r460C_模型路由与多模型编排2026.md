## 落地 5 独点（每点标注提升层）

### 1. 路由三策略与 RouteLLM 路由器族（工具/工作流/可复用 Skill）
来源：alibabacloud-model-routing / openlegion / aks / pi-smart-router / swfte
- **三策略：rules（query 长度/关键词/任务类型：数学→强模型、闲聊→便宜模型）/classifier（小 BERT 或矩阵分解输出 P(strong_needed)，阈值转二值路由）/cascade（轻模型先答+validator 动态评质量，不足才升级强模型——"try-then-judge"顺序结构）**。
- **RouteLLM 四路由器变体=Matrix Factorization（MT-Bench 最优：低秩分解 query×model 预测性能）/BERT 分类器/相似度/Causal LLM；MF 达 GPT-4 的 ~95% 质量（MT-Bench）而仅 ~26% GPT-4 调用——成本降 48-75%，分类器 pass 开销 5-120ms**。
- 提升层：工具（RouteLLM）/ 工作流（策略选型）/ 可复用 Skill（路由器变体矩阵）。

### 2. fallback 链与多级模型混合（工具/工作流/可复用 Skill）
来源：clawrouter / avyay / coderouter / a3m-router
- **每 tier 配置有序 fallback 列表：主模型 402（付款失败）/429（限流）/5xx 时 proxy 走链；fallback 排序由 benchmark 通知（quality-first，如 COMPLEX tier=gemini-3-pro 优先）**。
- **多级混合实证：自托管层（Ollama $0：Qwen3 27B/DeepSeek R1 7B 做分类抽取/代码审查）+中端（Claude Sonnet/Haiku $3-8：中等复杂内容生成）+前沿（GPT-4o $2.50-10：fallback+专项）——成本降 73% 同时可靠性提升；A3M 四阶段=guardrails（注入/PII/内容过滤）→cache lookup（语义缓存）→routing decision（multi-signal 启发式复杂度评分→tier）→execution（routing metadata 附响应可审计）**。
- 提升层：工具（fallback 链）/ 工作流（多级混合）/ 可复用 Skill（fallback 模板）。

### 3. 自路由与动态难度感知（工具/工作流/可复用 Skill）
来源：alibabacloud-self-routing / microsoft-foundry / zylos-runtime
- **自路由：请求先到 Flash 级模型，返回 answer+difficulty_score+difficulty_band+confidence_score——低难低信才升级强模型（模型自报难度驱动升级，不靠外部分类器）**。
- **tool-aware routing=路由理解工具调用模式，选能结构化调用的模型（不是所有模型都擅长 function calling）；50-70% 企业请求可由最便宜 tier 无质量损失处理——前沿 $5-25/MTok vs 效率 $0.10-1/MTok=10-100x 价差；复杂多模态/推理请求才路由到专家模型（learned routing network 平衡成本质量）**。
- 提升层：工具（自路由）/ 工作流（难度升级门）/ 可复用 Skill（升级阈值表）。

### 4. phase-aware 与 task-type 路由（工作流/工具/可复用 Skill）
来源：coderouter / rapidclaw / apipulse
- **phase-aware：coding agent 按会话阶段分派不同模型（test 生成模板化→flash 级 $0.14/M 便宜；refactor 需大上下文窗口+结构推理→pro 级 1M ctx；每阶段配 primary+两级 fallback 并写清"为什么这个分配"）**。
- **task-type routing：代码生成→Claude、创意写作→GPT-4、数据抽取→Gemma、敏感 PII→on-prem Llama——agent 有清晰任务类型时最易实现；复杂度路由=任务 7-10 分才上 GPT-4/Claude（1-3 分走便宜模型）；quality-sensitive 排序：面向用户/复杂→中高端，内部/简单→预算模型**。
- 提升层：工作流（阶段/类型路由）/ 工具（复杂度评分）/ 可复用 Skill（分派表模板）。

### 5. 路由架构分层与成本实证：先跑单模型基线（工具/工作流/可复用 Skill）
来源：arxiv-2603.04444 / swfte / regolo-brick / agentnative / nvidia-nemo
- **三层路由架构=Signal Extraction（信号提取）→Decision Engine（决策引擎）→Plugin Chain（插件链），每层定义清晰接口、可独立替换（Deployment Configuration Γ 元组配置）**。
- **mixture-of-routers 实证对比：Single Router（RouteLLM）成本降 48-75% 加延迟 5-15ms；Cascade（便宜→强）成本降 70-80% 加延迟 0-400ms；Speculative-Race（并发竞速）延迟降 30-60% 成本略升；Brick 语义路由（HuggingFace 开源）：Max-Quality 76.98% 准确 0.9x 成本 / Balanced 74.11% 4.71x 低 / Min-Cost 63.17% 22.15x 低**。
- **关键判据：先跑单模型基线再决定要不要建 cascade——当出现"单强便宜模型+retry"（MiniMax-M2.5 SWE-bench 80.2% @ $0.30/$1.20，输出价比 Opus 低 ~95%）胜过三档 cascade 的场景，路由逻辑本身是维护成本**。
- 提升层：工具（路由架构）/ 工作流（成本实证对比）/ 可复用 Skill（基线先行判据）。
