## 落地 5 独点（每点标注提升层）

### 1. HNSW 参数调优对照与重建纪律（工具/工作流/可复用 Skill）
来源：heliosdb / ailearningguides / yuhodots / tencent / toolsku
- **M=16 通用/32 高召回（recall<95% 升）/8 内存受限/48 最大精度；ef_construction 建图质量（64-256，更高=更好图+慢建）；ef_search 查询质量（40-200，更高=高召回+高延迟）；生产推荐 M=32/efC=256**。
- **构建期参数变更需重建（pgvector CREATE INDEX 后改要 REINDEX）**。
- 提升层：工具（参数）/ 工作流（调优协议）/ 可复用 Skill（对照表）。

### 2. 删除与索引退化：lazy tombstone + 压缩 + 定期重建（工具/工作流/可复用 Skill）
来源：aws-pgvector / milvus / arxiv-2606.04196 / kenwalger / arxiv-2604.09173
- **HNSW 随删除/更新退化（每次变更留无效图条目→recall 漂移+索引膨胀；无就地压缩）→定期 REINDEX CONCURRENTLY 恢复**。
- **lazy tombstoneing=删除向量留图保证连通但过滤出候选集；Milvus append-only 标记删除+后台压缩回收空间合并小段物理删死数据；分段模型 hot/warm/cold+后台压缩**。
- 提升层：工具（删除机制）/ 工作流（压缩与重建）/ 可复用 Skill（退化治理模板）。

### 3. 量化索引不是银弹：PQ 损失与 TQ+oversample+rescore（工具/工作流/可复用 Skill）
来源：milvus-sq / qdrant / toolsku
- **PQ 量化最多 8% recall 损失；TQ 1-bit 无 rescore 仅 0.605 相对精确搜索，但 oversample 4+rescore 回到 0.988≈float32 基线且 1/32 向量大小**。
- **SQ4U/SQ6/SQ8=速度压缩与精度平衡档；超 RAM 时 mmap on-disk 降级优先于激进量化**。
- 提升层：工具（量化档位）/ 工作流（rescore 协议）/ 可复用 Skill（量化选型）。

### 4. 过滤性能是引擎分水岭（工具/工作流/可复用 Skill）
来源：dreaming.press / qdrant
- **filtered search 是区分向量引擎的核心问题：Qdrant 把 payload 索引融合进搜索（高基数过滤+低延迟最佳）；Weaviate 内置向量化/重排模块=电池全包；Milvus=亿级+GPU+运维人力**。
- **选型：已有 PG 且 <1M→pgvector 零额外成本；1M-100M 主流→Qdrant；100M+→Milvus/Weaviate；原型→ChromaDB；不要过度工程化（<1M 别上重型）**。
- 提升层：工具（引擎）/ 工作流（选型）/ 可复用 Skill（选型矩阵）。

### 5. 选型矩阵与基准数字（工具/可复用 Skill）
来源：aiworkflowlab-cs / iotdigitaltwin / techsaas / bytepane / devto
- **延迟/召回：Qdrant p50 ~4ms Recall@10 98.5%、Pinecone 8ms 97%、Weaviate 10ms 97.2%、Milvus 6ms(GPU) 97.9%、pgvector 25-40ms 95-98%；50M 规模三引擎调优后均 >0.99 recall（Qdrant 3.8ms p50/Milvus 5.9ms/Weaviate 4.9ms）**。
- **索引构建 Milvus 70s/1M×1536 vs Qdrant 666-1386s；成本 $60-90/1M 向量/月；Qdrant 最低 TCO 单节点 $388/mo**。
- 提升层：工具（基准数据）/ 可复用 Skill（benchmark 参考）。
