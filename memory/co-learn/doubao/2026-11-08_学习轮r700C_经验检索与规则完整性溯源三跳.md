## 三、三点落地

1. **经验记忆＝可检索的操作指引**（`defaults/wb-context-compressor` KB + 指针，3.885.0→**3.886.0**）：只对可执行任务检索；查询含目标+对象+操作+约束，失败后带失败操作与稳定错误签名；只搜经验根、不用宽口径 recall；按任务/环境/前置条件判相关（标题相似不算），只读 1–3 条**正文**（摘要只用于挑）；失败后最多补一次；优先级链 系统指令 > 当前请求 > 环境与工具证据 > 记忆，"以前成功不授权今天做破坏性动作"。**提升层：工作流（记忆使用侧）**。
2. **规则检查必须自报完整性**（`wb-artifact-verification` KB + 指针，2.445.0→**2.446.0**）：`task_context` 不许省略已知事实、未知写成未知；逐条判 `applies_when` 与 `exception`；查不到规则 ≠ 没有规则；`delivery.complete=false` 时读回被省略的规则或暂停动作，**不许把交付子集当完整检查**；压缩后为当前任务重新取规则。**提升层：工作流（合规校验）**。
3. **变更溯源三跳与 mention≠mutation**（`wb-debug-loop` KB + 指针，1.368.0→**1.369.0**）：产物文件 → 变更 diff → 源消息（仅当需要）；只有出现在 `operations.adds/updates/deletes` **目标位**才算被改过，正文提到不算；搜不到不等于没有历史，空 diff 不单独证明抽取失败；排障期只读（不写、不重跑抽取、不执行恢复出的脚本），产物只当证据；结论先给、证据链随后、证据与推断分开。**提升层：可复用 Skill（排障取证）**。

## 四、功能套件检查

`wb-context-compressor` 本轮补入"使用侧"协议（此前 KB 偏"提取/存储/压缩"），形成 写入 → 保鲜 → 检索 → 校验 的闭环；`wb-artifact-verification` 与 `wb-debug-loop` 各补一条取证判据，与本批 A 轮的"独立评审"共同构成"谁来查、查到什么程度、查不全怎么说"三件套。`wb-ponytail` / `wb-max-token-saver` 无新增需求。
