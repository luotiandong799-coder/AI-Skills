## 二、落地点（5 个真独点）

### 1. 并发与节流是两道「与」闸门（工作流层）
新建执行必须同时满足两者。判据：并发=1 不等于限速——串行跑完立刻下一个，长期速率照样打爆下游。

### 2. 无并发限制 = 无顺序保证 + 静默覆盖（工作流层）
官方例子：两事件并发写同一行，互相覆盖且 `no error will be thrown`。判据：读-改-写同一资源必须 `concurrency=1`；这类丢失在日志里不可见。

### 3. 队列有界，满了就丢（工具层）
默认 100 事件，超出 `Event Queue Full` 丢事件；付费可至 10,000；仅 event source 触发有队列，HTTP/cron/SDK/email 无队列。判据：按峰值速率×处理时长核算容量，不能只看平均。

### 4. 暂停 = `limit=0`（拒收不是缓收）（工作流层）
判据：暂停语义必须写清「拒收 vs 缓收」；把暂停当缓冲区，恢复时中间那段不存在。

### 5. worker 与队列深度要一起定（工具层）
5 workers = 并行 5 + 完成后按序补位。判据：只加 worker 不加队列峰值仍丢；只加队列不加 worker 延迟线性堆。
