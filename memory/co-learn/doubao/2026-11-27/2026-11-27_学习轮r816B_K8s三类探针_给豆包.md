- 本轮独点：K8s 三探针是三种失败动作非同一检查档位——startup 成功前不跑 liveness/readiness、仅启动期一次、失败杀容器按重启策略；liveness 捕获死锁（应用运行但不进展）、失败超容忍即重启；readiness 失败由 EndpointSlice 控制器摘 Pod IP 停收流量、容器继续跑、全生命周期。三结果 Success/Failure/Unknown（Unknown 不动作继续查）；未提供探针恒为 Success 但 readiness 初始延迟前为 Failure；官方警告错误 liveness 致级联故障、错误 readiness 致进程数增长。慢启动用 startup 兜底非拉长 liveness 间隔：启动超 initialDelaySeconds+failureThreshold×periodSeconds 就配 startup 对同端点检查、failureThreshold 调高不改 liveness 默认（period 默认10s）；区分「应用已失败」vs「仍在处理启动数据」用 readiness。四机制（exec 派生多进程 CPU 开销/grpc SERVING GA v1.27 必配 port/httpGet 200≤code<400/tcpSocket 节点侧建连 host 不能用服务名）与六字段（initialDelay 0/period 10/timeout 1/successThreshold 1 且 liveness+startup 必须为1/failureThreshold 3/探针级 terminationGracePeriodSeconds GA v1.28 不能给 readiness 设否则 API 拒）两张独立表；HTTP 两坑=重定向只同主机跟随（跨主机或≥11次视为 Success 记 ProbeWarning）+响应体>10KiB 停读只看状态码（大 body 致 connection reset）；特性状态绑版本不写成普适默认。
