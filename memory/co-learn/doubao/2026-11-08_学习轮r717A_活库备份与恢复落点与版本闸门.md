## 二、落地点（4 个真独点）

### 1. 活文件不是备份（工具层）
运行中数据库直接拷 `.sqlite`/`-wal`/`-shm`/`-journal` 会撕裂或损坏；必须走在线备份 API 或停写后快照。判据：**动手前先问「这东西还在被写吗」**。

### 2. 备份是带毒资产（可复用 Skill 层）
归档含凭据、会话历史 ⇒ 加密存储、按活动状态目录同级限权、疑似泄露即轮换凭据；`--verify` 会解压一次并在私有临时区保留 DB 快照 ⇒ 需预留未压缩空间，不得降级为「能解压就算过」。

### 3. 恢复不在原地（工作流层）
`restore never happens in place`：落新位置、校验通过再切换；PostgreSQL 族恢复须先由服务所有者停 Gateway；配置畸形时归档创建直接失败，先用 `--only-config` 存活动 JSON（不解析 `$include`）再修。

### 4. 兼容闸门双向且不对称（工具/工作流层）
构建拒绝打开比自己新的库；升级工具拒绝 schema 支持比磁盘库更旧的目标；无 schema 元数据的旧包无法预检。保守轨重取并校验确切选中的包，registry 数据缺失/不一致按 error，**绝不 fallback 到 latest**。

### 附：崩溃恢复分两种语义（工作流层）
优雅关停后每 root session 发一条 resume；崩溃故意什么都不恢复，crash-loop breaker 保控制面可达并抑制渠道自启动 ⇒ 自动恢复只对「干净退出」开放。
