- 模块：SI（安全治理）。上批 r807；本批 r808A/B/C=SI/AI/PDI，Qoder 已卸载仅 WB/豆包两写。
- 主题：框架自动把 HTTP 参数绑定进对象时，攻击者追加未打算写的字段造成越权写入（CWE-915）。

## 方法论三独点
1. **根因与成立条件**：OWASP 逐字「automatically bind HTTP request parameters into program code variables or objects to make using that framework easier」→「create new parameters that the developer never intended which in turn creates or overwrites new variable or objects」。别名按框架分裂：mass assignment（Rails/NodeJS）、autobinding（Spring MVC/ASP.NET MVC）、object injection（PHP），判重要三组都查。CWE-915 定性为「does not properly control which attributes can be modified」；OWASP「Field names may be guessed or discovered; source-code access is not required」；空构造器非前提（Spring 支持 constructor + setter binding），嵌套对象也在暴露面；2012 GitHub 用户把公钥传到任意组织即实证。
2. **白名单管可写面，但不替代授权**：优先 DTO（只含可编辑字段）+ 显式字段 allow-list；CWE「If possible, prefer allowlists over denylists」，denylist 因新增/漏掉敏感字段会重新可写。关键边界句「DTOs and field allowlists restrict writable properties; they do not replace authorization for the requested object and operation」⇒ 与 BOLA 两道门：BOLA 判主体+操作+具体对象，本节判这次绑定能写哪些字段。反模式：Spring `disallowedFields` fragile、Laravel `forceFill`/`unguard`/`$guarded=[]`、DRF `fields="__all__"`/`Meta.exclude`。
3. **检出与验收**：CWE SAST 走 source→sink，Effectiveness: High，但动态字段/嵌套/反射会漏；回归四步=正常字段写入成功 + 多塞敏感字段后保持原值 + 新增模型字段后重跑 + 对他人对象写入仍被授权拒绝。不防业务越用、BOLA、SQLi、反序列化 gadget；HMAC 签名只保证数据未篡改，不产生字段级授权。
