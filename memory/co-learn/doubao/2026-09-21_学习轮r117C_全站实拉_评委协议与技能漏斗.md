## 独点：3 条
**D33：评委可靠性操作化协议——翻转率标记不确定题+双评委+噪声预算（来源：arXiv 2606.13685《Coin Flip Judge》2026 实拉）**
- 机制：高利害评测协议——50 次试验；识别高翻转率题目（FR>20%）标记为"不确定"；至少用两个不同提供商的评委；最终分数旁报告噪声预算；硬题区 FR 平均 23.6%，需 15 次试验才达 90% 保真度。
- 判据：**评判者结论要自带置信边界**——同一题重复判结果会翻的（FR>20%）标"不确定"，不能混进总分；高分榜至少双评委交叉，分数旁必须报噪声预算。
- 与 §对照成对构造/裁判方差 分工：那条管"对照怎么构造、方差怎么防"，本条管"高利害结论的量化协议：翻转率阈值/双评委/噪声预算"。
- 提升层：工作流/可复用 Skill（评测可信度）。

**D34：技能恶意检测三层漏斗——便宜层先过滤，LLM 只花在可疑上（来源：arXiv 2604.06550 SkillSieve 2026 实拉）**
- 机制：L1 正则/AST/元数据 XGBoost 特征评分——过滤约 86% 良性技能，<40ms，零 API 成本；L2 可疑技能交 LLM，但拆成四个并行子任务（意图对齐/权限合理性等）而非一个大问题；L3 深度分析。
- 判据：**装技能前的检测按漏斗走：便宜确定性的层先筛掉绝大多数良性，LLM 分析只在可疑子集上花**；LLM 判断拆成并行小任务（意图/权限/行为/来源）比一个大问题更可定位。
- 与 §工具面安全 分工：那条管"工具描述可注入/同名拦截/per-tool 最小权限"（装后防御），本条管"装前检测的分层管线"（装前筛查）。
- 提升层：工作流/可复用 Skill（技能供应链安全）。

**D35：错误结构化提示优化——Diagnose-Diversify-Select，多样性必须有稳定性选择否则有害（来源：arXiv 2609.04197 ESPO 2026 实拉）**
- 机制：提示优化三步——Diagnose：一轮把全部训练错误聚类为结构性模式；Diversify：四种互补候选生成策略（各有独立偏差倾向）保障多样性；Select：bootstrap 稳定性选择；关键反直觉发现：加多样性但不做 bootstrap 选择反而伤害性能（-1.20%）。
- 判据：**改提示词按"错误聚类→多样化候选→稳定性筛选"走，不是凭感觉换措辞**；多样性本身不是目标——没有稳定性选择的多样性会引入更多不稳定候选。
- 与 §技能评测闭合邻域 分工：那条管"评测环境怎么圈死"，本条管"提示词本身怎么迭代优化"——错误驱动+候选稳定性是改提示词的方法论。
- 提升层：工作流/可复用 Skill（提示词迭代）。
