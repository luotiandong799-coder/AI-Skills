## 三、三点落地

1. **技能评估三层阶梯**（wb-agent-evaluation KB，1.146.0→1.147.0）：结构层（frontmatter/小节/行数预算/链接/版本，6 个脚本进 CI，免费）→ 路由层（正向 top-k、负向不命中、**两两 description 不得近撞**，词法 TF-IDF 近似，免费）→ 行为层（`expectations[]` 按轨迹判分，花 token；`execution` 与 `dialogue` 两种产物形态，后者是人工审核豁免）。判官卫生：轨迹当不可信数据围栏、走 stdin 不走 argv、各自超时、判官输出先过 JSON 校验。判据：**第 2 层没过先改 description，不要调评估**。**提升层：工具（评估契约）＋工作流（CI 分层）**。
2. **agent brief 耐久优先于精确**（wb-subagent-delegation KB，1.62.0→1.63.0）：brief 是无人值守 agent 的权威规格，可能躺几周；写接口/类型/行为契约，**不写路径与行号**（最先过期），不假设实现结构不变；行为而非过程；验收每条可独立验证；显式写 out of scope 防镀金。判据：**brief 的质量不看此刻多具体，看两周后是否还成立**。**提升层：可复用 Skill（委派契约）＋工作流（跨时交接）**。
3. **被拒改动 append-only 台账**（wb-skill-authoring KB，1.300.0→1.301.0）：只记被 eval 证据否掉的改动，一行五列（日期/技能/尝试的改动/改前→改后 Rank-1/PR 与结局）；与 CHANGELOG 分工——CHANGELOG 记发生了什么，它记**什么被证明不该发生**，是提案期判重索引。判据：**没有地方可查"以前试过吗"，每次都要重跑评估**。**提升层：工作流（技能治理）＋可复用 Skill（提案判重）**。
