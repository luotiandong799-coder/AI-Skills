## 二、落地点（5 个真独点）

1. **重试粒度按请求不按流程** —— 每条 HTTP 请求独立重试，保序靠只重试当前步；整条流水线不从头重跑。
2. **退避信封分三套** —— 渠道 3 次/10% 抖动/400ms 下限/30s 上限；Discord 500ms 与 REST 300s 上限；Gateway WS 另一套 50 次、2s→30s 指数、无抖动。
3. **回退预算与 deadline 耦合 + 成功才重置** —— 一半超时后停止接纳重试留给 fallback；16 次/15 重试、TPM 共享 2 次/15s、其他 8 次/90s；只有完整成功响应才重置计数、退避与窗口。
4. **恢复续跑不重发** —— 在既有 transcript 续跑，已记录 tool result 决定完成度，只检查结果未知的动作；计费/认证/refusal 不入瞬时预算，空错误体不能让永久 4xx 变可重试。
5. **steering 的作用点是工具边界** —— 顺序模式在后续调用前设检查点并跳过未启动尾部，并行批次不跳；被跳过的调用给合成结果保持配对。
