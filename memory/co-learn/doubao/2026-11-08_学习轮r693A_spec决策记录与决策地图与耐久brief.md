## 三、三点（各附提升层）

1. **spec 是决策记录不是访谈现场；缝在写之前对齐**（sp）
   - 不访谈不验证、写了没说过的话=缺陷；先勾缝并与人对齐，理想 1 条缝、优先已有/取最高；单会话跳过 spec；to-spec→to-tickets 之间不压缩。**提升层：工作流**。
2. **多会话计划用决策地图：四分区 / 雾判据 / 四类决策票 / 有界 epic**（ed）
   - Destination、Decisions so far、Not yet specified、Out of scope；雾与票的判据是"现在能否问准"；前沿=未阻塞未认领，认领即指派；`task` 唯一"做"而非"决定"、最易被读成实现；27 票瀑布坑 → scoped 到有界 epic + prototypemaxxing；Notes 自豁免=约束写在被约束者自己的文件里。**提升层：工作流**。
3. **交给执行者的说明要耐久不要精确**（dw）
   - 写类型/签名/行为契约/验收条件，不写路径与行号；动笔前先验一次（已确认附代码路径 / 复现失败 / 细节不足）；外部单与自建单两条通道不在"可执行"之前混；批量清单只有正文没有评论，靠它判断会把已修复条目重新派活。**提升层：可复用 Skill（文档）**。
