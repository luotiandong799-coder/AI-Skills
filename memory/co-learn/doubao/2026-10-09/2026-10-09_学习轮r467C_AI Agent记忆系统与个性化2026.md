## 落地 5 独点（每点标注提升层）

### 1. 四层记忆架构与存储职责（可复用 Skill）
来源：streamzero / zylos / augmentable / appliedai
- **working**：上下文窗口+活动状态（<100ms/会话期/token 受限）；**episodic**：时间戳经历（"用户 1 月 5 日纠正日期格式"）；**semantic**：抽象化事实（"用户偏好 DD/MM/YYYY"）；**procedural**：可执行技能/可复用计划（Voyager 存 Minecraft 例程为可调用 JS 函数）。
- **判据：context window 是 buffer 不是 memory**——跨会话/跨模型/跨重启持久的是 episodic+semantic+procedural 三层，各配专用存储引擎（Mem0/Zep/LangGraph checkpoints）。
- 提升层：可复用 Skill（记忆架构）。

### 2. 记忆写入过滤（工作流）
来源：arxiv-adamem / acl-memorai
- **学什么值得记是 role-dependent**（AdaMem）：Memory Policy 从 weekly QA feedback 精炼，patch-style self-reflection+failure rollback——不靠一次直觉。
- **MemORAI memory gate**：只留 user-persona-relevant 内容+dual-layer compression（段级摘要保全局）——存储效率和检索精度双升。
- **2026 共识：写前重要性评分，不是全量 dump**。
- 提升层：工作流（写入管线）。

### 3. 记忆检索注入策略（可复用 Skill）
来源：arxiv-trace-memory / arxiv-ppro / arxiv-personalized
- **TRACE-Memory utility-aware**：记忆只在"超出公共回答的增量效用"时用——两阶段=先查用户特有信息缺失→再按响应级增量效用准入证据子集，**可返回空集**（不该用记忆就别用）。
- **PPRO**：user profile 作显式个性化先验进记忆 ranking（覆盖稳定属性/偏好/关系）+GRPO 训练 query rewriter。
- 判据：检索注入=top-k 精选，不是全量历史进 prompt；个人记忆是条件增强不是默认噪音。
- 提升层：可复用 Skill（检索注入）。

### 4. 记忆污染威胁与防护（可复用 Skill）
来源：arxiv-sleeper / dev-poisoning / spar-latent / llm-hacking
- **Sleeper Memory Poisoning**：通用 payload 跨 ChatGPT/Claude/Gemini 诱导记忆写入，检索相关时影响行为（agentic 场景可影响工具使用）；**SpAIware 2024**=恶意邮件植入数据外泄指令进长期记忆，macOS 客户端无告警保存、之后每次对话自动携带——**记忆本身是被攻击目标**。
- **防护**：记忆写入/检索/响应三重 safeguard 治理（管"助手写什么/取什么/答什么"）；prompt hardening 单独用不足——**GEPA hardening+spotlighting 对 Claude/Gemini 近零但 adaptive 攻击在 Kimi/DeepSeek 可恢复**（ExpeL 激活率 28-63%）；记忆文件型攻击（payload 已在 memory file）引导当前会话+复燃+常驻，靠架构隔离不靠提示词。
- 提升层：可复用 Skill（记忆安全）。

### 5. 2026 产品记忆对比（工具）
来源：manthanguptaa / mindlock / gemini-notebookhub / teachaitools / mayhemcode
- **ChatGPT**：注入 profile（33 facts+近期聊天预计算摘要+会话元数据拼进每次 prompt）；容量约 1200-1400 词压缩摘要；自动但浅（事实带过 nuance 不带）；**无 memory profile switching**（agency 单账号多客户会串记忆）；project-only memory opt-in（默认非项目对话仍用全局记忆）。
- **Claude**：on-demand retrieval（小 userMemories 块常在但过往对话默认不注入，模型可调用）；**Project silo 自动且始终隔离** vs ChatGPT opt-in——跨项目隔离是默认安全姿态；精确按文档（无解释错误但无自动更新）。
- 判据：给个人工具选型看隔离与可控，不只是"记不记得"。
- 提升层：工具（选型矩阵）。
