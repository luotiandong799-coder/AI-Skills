## 落地 5 独点（每点标注提升层）

### 1. Spec→Plan→Execute→Verify 与 plan mode 分离（工作流）
来源：blink / kanopy / baeseokjae
- **spec=feature/user story/验收 checklist/触及文件/API contract/约束**；输入质量=输出质量最大单因子。
- **plan mode=分析先于执行（不改文件→人审→执行）**；checkpoint 每 3-5 任务跑测试+审 diff。
- 提升层：工作流（编码四阶段）。

### 2. Agentic coding 工具范式双轨（工具）
来源：claudhq / parallel / agentguides
- **Claude Code=CLI 自主 agent（仓库级重构/CI）；Cursor=编辑器内补全（人在环）**。
- **双轨=编辑器文件级+终端 agent 仓库级**；Codex=IDE+Cloud+CLI；TRAE Agent/IDE 双模式。
- 提升层：工具（编码工具选型）。

### 3. 高级编排：Subagents / Agent Teams / Symphony（可复用 Skill）
来源：anthropic-advanced-patterns / symphony / enso
- **三档=Parallel Claude（多 worktree）→Subagents（隔离上下文）→Agent Teams（独立 workstream 协调）**。
- **Symphony=issue→agent workspace 映射，在环直到完成，崩溃自动重启**；硬规则=PR 前测/5 次自纠/LSP 找引用。
- 提升层：可复用 Skill（agent 编排）。

### 4. AI 代码评审治理与风险分级（工作流）
来源：augmentcode / crashoverride / aws / theneuralbase
- **高 AI 采用=评审中位时间 ×5、事故 ×3、400 行以上人审失效**→机械化质量门。
- **风险分级=高风险强制人审/中风险抽查/低风险自动+审计**；许可证扫描不可协商。
- 提升层：工作流（评审治理）。

### 5. 反 slop linter 与 enforcement 评审（工具）
来源：agentconn / zylos / dev-enforcement / metacto
- **生成前护栏（AGENTS.md/brief 提问）+生成后确定性 linter（sloppylint/58 gates）+pre-merge 多 agent 评审**。
- **CI 不信同 PR 自加测试**；AI 评审 pass/fail 门控部署；requirement fidelity+real APIs only。
- 提升层：工具（质量门）。
