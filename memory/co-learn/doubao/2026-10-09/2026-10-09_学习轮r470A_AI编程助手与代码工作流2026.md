## 落地 5 独点（每点标注提升层）

### 1. 会话上下文卫生（工作流）
来源：claude-code-best-practices / claude-code-commands / cursor-agent-best-practices
- **/clear 在不相关任务之间清上下文**；**连续两次纠正仍错=/clear 后写更好的初始 prompt（吸收教训）**——context polluted with failed approaches 是反复纠正无效的主因。
- /context 看什么在占窗口；rules 只在重复犯同一错时加（start simple 逐步加）。
- 提升层：工作流（会话纪律）。

### 2. plan-before-build 与双 Claude 评审（工作流）
来源：anthropic-power-user-tips / claude-code-commands
- **复杂任务先进 plan mode（Shift+Tab）→打磨计划→切 auto-accept 让 Claude one-shot 执行**。
- **一个 Claude 写计划、第二个 Claude 以 staff engineer 身份评审计划**；出问题切回 plan mode。
- 提升层：工作流（计划闭环）。

### 3. TDD+agentic：先测试后实现（可复用 Skill）
来源：anthropic-engineering-claude-best / kanopy-cto-playbook
- **明确告诉在做 TDD——先按预期输入/输出对写测试→跑测试确认失败→明确禁止写实现代码→commit 失败测试→再实现**；避免 AI 创建 mock 实现。
- **AI 生成的测试是套套逻辑**（assert 函数返回它自己返回的值）——要验证测试含边界/错误态/恶意输入。
- 提升层：可复用 Skill（TDD 协议）。

### 4. AI 代码质量门禁（可复用 Skill）
来源：victorsaisse / augmentcode / axiomstudio / makitsol / exceeds
- **CCN 圈复杂度门**=LLM 爱写 120 行 15 嵌套 if，函数超阈值即 block；**diff coverage 而非全仓覆盖率**——要求改的行覆盖；**mutation testing gate**=行覆盖测执行不测检测（PIT）。
- **人类评审效率在 400 行以上崩溃**（AI 时代 PR review 时间涨 5 倍、每 PR 事故 3 倍）；**hybrid strict review（AI+强制人工）降缺陷、纯 AI-only 反增缺陷**；高风险区（认证/授权/支付/删数据）更严+人工审批。
- 提升层：可复用 Skill（门禁规范）。

### 5. CLAUDE.md 编写纪律（可复用 Skill）
来源：claude-code-best-practices-es / anthropic-claude-md-context / claude-context-engineering-5g / claude-agent-sdk-system-prompts
- **过长 CLAUDE.md 会被忽略一半**——重要规则淹没在噪声里，无情报复删除；Claude 已做对的事删掉或转 hook。
- **state outcome not steps**=告诉它想要什么和为什么，让它自己探索代码库（"用户没邮箱导致校验崩溃"而非"打开 userService.ts 第 42 行加 null check"）；新模型下 examples 约束探索空间→**design interfaces 替代给例子**。
- **subagent 路由**：claude/agents/ YAML frontmatter（name/description/model/tool access）+body=系统提示；用便宜模型路由侧任务。
- 提升层：可复用 Skill（指令文件规范）。
