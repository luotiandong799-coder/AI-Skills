## 落地 5 独点（每点标注提升层）

### 1. Obsidian×LLM 集成三模式（工具）
来源：fanyamin / datasciencedojo / sapirex
- **本地 Markdown 文件天然是 LLM 最易吃格式；个人知识库=把本地文件系统变成 LLM 工作目录**，不是"给笔记工具加 AI 按钮"。
- 三模式：**插件式**（Smart Connections/Copilot 类）→**MCP 式**（Claude Code/Cursor 直连 vault，10 分钟无 key）→**编译式**（LLM Wiki 思路）；按需选、可组合。
- 本地路径（Ollama+ChromaDB）：全本地无 key，私密知识脑。
- 提升层：工具（集成模式选型）。

### 2. CODE 四阶段与会议智能循环（工作流）
来源：shadow / thedigitalmagazine / leedeen / bibigpt
- **capture 与 second brain 不是一回事**——CODE（Capture→Organize→Distill→Express）中间三步没人设是通病；**criterion=永久笔记只收"改变理解的新信息/新框架/先例决策"**。
- Meeting Intelligence Loop：会前查相关上下文→会中自动捕获→会后提炼永久洞察→纪要归档；**/organize 工作流=Inbox 粘贴→AI 读源→按 frontmatter 模板写原子笔记+wikilink**。
- 会议产出结构化=摘要/决策/行动项+负责人+期限/风险/开放问题。
- 提升层：工作流（可复用模板）。

### 3. RAG 分块参数实证（可复用 Skill）
来源：datasumi / dev-brywritescode / besthub / aiwisdom / dzone
- **chunk 300-500 tokens + 50 token overlap**（或 400-512 + 10-20% overlap 达 **88-89% recall**，错策略差 9%）；**chunk_overlap=0 会切半句子**。
- >2000 tokens 稀释模糊（embedding 平均化六主题）、<100 tokens 缺上下文；单 chunk 不要跨主题；存储前去重相似块。
- 提升层：可复用 Skill（参数规范）。

### 4. 本地 RAG 的 num_ctx 与 RRF 融合（可复用 Skill）
来源：insiderllm / aiexpert
- **本地 Ollama num_ctx 默认 2048 太小——检索块+问题必超，模型静默丢上下文**，调 ≥8192/16384。
- **RRF 融合公式=1/(k+rank_A)+1/(k+rank_B)，k 通常 60**——vector 与 BM25 双路排序按位次融合（不看分数绝对值，天然可比）。
- 提升层：可复用 Skill（检索配置）。

### 5. 索引治理：策展与保鲜（工作流）
来源：aiexpert / authon / ofox
- **索引里的都是"标准"**——营销页/过时文档被当 canon，模型无法区分，需严格策展（只入高质量内容）。
- **索引过期=doc 变更后不更新→自信地给错答案**；定期 re-index 或自动同步。
- **retrieval 不足**：top3 不够重建上下文时用 top10；先诊断三环=分块/embedding 模型/检索数量。
- 提升层：工作流（治理纪律）。
