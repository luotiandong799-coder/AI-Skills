## 落地 5 独点（每点标注提升层）

### 1. 六种 drift 模式与黄金集自动晋升（工作流/可复用 Skill）
来源：futureagi-passes-evals-fails / ai-tldr-prototype / mlflow-importance
- **"eval 集是快照，生产是长河"**：eval 集从发布当天就开始老化——六种 drift 模式：①dataset drift（新用户意图，集里没有）②tool-API drift（第三方端点改 schema/错误形状/限流）③prompt drift（你改了 prompt，评估 rubric 没跟着动）④retrieval-corpus drift（索引增长/分块重排，同 query 浮出不同 chunk）⑤user-segment drift（新用户段不同写作风格/语言）⑥model drift（基础模型被静默更新）。
- **黄金集自动晋升**：生产输入随时间漂移，发布时冻结的 golden set 逐渐失真——**自动把失败的生产样例晋升进黄金集**：每个到达用户的失败模式成为永久回归测试。
- 提升层：工作流（drift 清单）/ 可复用 Skill（晋升机制）。

### 2. 分层 eval 门与 delta 门控（工具/工作流）
来源：dailyaiworld / futureagi-testing-playbook / ai-tldr-model-upgrade
- **三层 eval**：①10-20 输入 smoke（每次提交）②按风险分层的 50 条（每个 PR）③全量 500 条 nightly + main 分支——层越深越全越贵，频率递减。
- **gate on delta，不 gate 绝对阈值**：回归是相对"你今天在生产的基线"——对生产基线的差值门控（+x% 才拦），不是对固定分。
- **六个反复出现的错误**：多步 agent 只评最终响应、基准泄露进训练数据、LLM-as-judge 未校准就当真值、门控忽略成本与延迟、生产均匀采样而非按风险分层、测试夹具在 agent 出错时也通过（工具轨迹弱比较器/ROUGE 低阈值）——**修法=让门控在真实失败模式上失败，而不是在代理指标上**。
- 提升层：工具（eval 分层）/ 工作流（delta 门控）。

### 3. shadow→canary 量化 rollout 与自动回滚（工作流/工具）
来源：futureagi-shadow-canary / theneuralbase-new-model / bards / ai-zero-to-hero
- **两者测不同问题，缺一翻车**：shadow=镜像真实请求到候选模型、零用户影响、离线评分——证明"候选在真实分布上行为不异常"；canary=候选对一小片真实用户上线、按同一 rubric 对比生产队列——证明"至少不差"。
- **量化 halt 阈值**（shadow 周分析）：新模型 p99 延迟 > 旧 +200ms 或 token 数 > 旧 +15% 或错误率 >1% → 暂停 rollout 调查；**canary 流量阶梯**=1%→10%→50%→100%；自动回滚触发=错误率 >2% 持续 5 分钟立即回滚；guardrail 违规 30 秒内自动 revert（带人工覆盖）；有状态 agent/chat 用 per-tenant sticky-session canary。
- 提升层：工作流（rollout 阶梯）/ 工具（回滚触发）。

### 4. 失败四桶与关键监控指标（可复用 Skill/工具）
来源：latitude / amirteymoori / theneuralbase-quality / mlflow-deployment-strategies
- **HTTP 200 不代表工作**：失败分四桶=ops/quality/structure/safety，配小标签集（hallucination/truncation/timeout/rate_limit...），每桶连 traces/实时评分/人审/告警/回归测试。
- **关键指标清单**：fallback 率（"不知道"/升级人——上升=模型挣扎）；p50/p95/p99 延迟（**p95>3s 告警**）；每会话成本（翻倍=查 prompt 回归导致更长输出）；拒绝率；安全（100% 流量过 pre-call 输入屏+post-call 输出屏，采样只用于质量指标）；基础设施=队列深度（容量压力先行指标）+冷启动时间+KV cache 利用率。
- **分层语义采样**：100% 错误 + 100% 新 prompt 版本（48 小时）+ 5-10% 正常流量——自动指标告警走 PagerDuty/Slack 实时，不事后发现。
- 提升层：可复用 Skill（指标清单）/ 工具（四桶分类）。

### 5. 生产反馈闭环与月度审查（工作流/可复用 Skill）
来源：istoe / agencyscript / dev-sri2614
- **五步闭环**：捕获（显式负信号 thumbs down 或隐式行为标志）→triage（会话日志自动标记路由人审）→根因分析（领域专家查失败、识别缺口、更新系统）→数据增强（新输入+修正输出+若干合成变体追加进离线 Golden Set）→回归测试。
- **月度 prompt 审查**：生产 prompt 随世界/模型/任务演化漂移——每月至少审查+测试一轮；维护失败日志：每个到达用户的坏输出记录/分类/跟踪后续改动是否修复。
- **静默劣化防线**：模型提供商静默更新快照、数据分布偏移、上游 prompt 变更，而无漂移监控时质量不响亮地失败（"quality does not fail loudly"）——按周迭代闭环（周四跑 eval 修 bug→周五 10% canary→周末全量）。
- 提升层：工作流（五步闭环）/ 可复用 Skill（月度审查节奏）。
