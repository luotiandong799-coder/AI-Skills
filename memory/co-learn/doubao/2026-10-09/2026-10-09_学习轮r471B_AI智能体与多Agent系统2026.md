## 落地 5 独点（每点标注提升层）

### 1. 编排模式生产选型数据（工作流）
来源：metacto / rapidclaw / beam / niteagent / novakit
- **orchestrator-worker 约占生产部署 70%**；三 pattern（supervisor/pipeline/swarm）覆盖 ~90% 生产；workers 不互聊、单点问责。
- **mix models 激进=smart orchestrator+cheap workers 降成本 40-60%**（Wells Fargo）；**hub-and-spoke 失败模式=hub 脆弱+中心翻译损耗，治理层把 defense 从 0.32 推到 0.89**。
- 提升层：工作流（模式选型）。

### 2. 记忆 write-through 实现模式（可复用 Skill）
来源：mem0 / microsoft-redis / redis / agentmelt
- **五步 write-through=Ingest→Short-term write（session buffer）→Check（查长期索引注入相关）→Generate→Consolidate（async worker 提取有价值事实写长期索引）**。
- **短时=上下文窗口（128K-2M tokens）会话结束即失；长期=数据库语义相似检索；episodic=结构化交互记录（timestamp/user ID/query/response）**。
- 提升层：可复用 Skill（记忆实现模板）。

### 3. 工作记忆管理三策略（工作流）
来源：chatforest / techoral / developersdigest
- **sliding window（丢最旧）/ summarization（压缩旧轮）/ importance-based pruning（留高价值轮丢闲聊）**——上下文溢出时三选一按场景。
- **长期对话溢出不丢旧消息而是摘要化**（先摘要再裁剪）。
- 提升层：工作流（上下文管理）。

### 4. tool calling 可靠性：enum/Levenshtein/reprompt 退避（工具）
来源：datarekha / theneuralbase / csdn
- **enum everywhere=封闭集可能处必用 enum 并写进 description 限制**（自由文本枚举字段=下游 parse error）。
- **reprompt 用指数退避（2s/4s/8s）**（重复相同 prompt 常产生相同无效输出，改上下文/改写才迫使修正）；**fuzzy_match 用 Levenshtein < 2 抓 typo**（避免假匹配掩盖真错误）。
- 提升层：工具（参数治理）。

### 5. validate at boundary + 重试带错误自纠（工具）
来源：bswen / learnixo / lobehub / aijsonmedic
- **外部数据进入 agent 处用 schema 验证、抛 typed error 由 runtime 捕获而非 LLM**（工具 bug 返回损坏输出，LLM 会基于它产生幻觉）；**MCP outputSchema 声明验证工具返回值**。
- **重试必须把上次错误带进对话历史（checkpoint）让 LLM 自纠**（schema 放 system prompt+Zod 验证+失败重试一次带错误消息）。
- 提升层：工具（边界验证）。
