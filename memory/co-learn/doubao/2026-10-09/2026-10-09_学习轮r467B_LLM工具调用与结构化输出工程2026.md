## 落地 5 独点（每点标注提升层）

### 1. 工具 schema 设计第一性（可复用 Skill）
来源：aibuzz / zylos / aiworkflowlab
- **描述质量是 function calling 准确性单一最大变量**——超过模型选择/prompt/基础设施；模型读工具描述决定何时调/调哪个/怎么填参数。
- **命名拆分**：`query_database` / `update_database` 分开，不写 `execute_database_operation` 让模型猜读写——减少歧义同时缩小每个工具 schema 面。
- **描述必须含示例/边界/反例**（not just documentation, 模型当指令读）。
- 提升层：可复用 Skill（schema 编写规范）。

### 2. 结构化错误返回纪律（工作流）
来源：ai-tldr / llmversus / aiagents
- 工具失败**不抛未处理异常**，返回结构化错误串作为 tool result——模型决定重试/换 fallback/告诉用户。
- **绝不跳过 tool result**（失败也算）——跳过会让模型幻觉编结果；**secrets 从错误消息剥离**再进上下文/日志。
- **catch at host boundary 不在 agent loop 内**；每次调用 ID 都 append tool message（含失败）。
- 提升层：工作流（错误回路）。

### 3. JSON 可靠性四档与 constrained decoding（可复用 Skill）
来源：thepromptbench / devtoollab / effloow / niteagent
- **四档递增保证**：prompt+parse（最弱）→ provider JSON mode（保证可解析不保证形状）→ **schema mode/constrained decoding（保证精确结构）** → function calling（结构化参数副作用）。
- **constrained decoding 原理**：token 生成层把非法 token 掩码掉再采样——输出保证匹配 schema，不是"通常"；**XGrammar**（vLLM/SGLang 默认）vocab 分区+语法缓存最高 100× 吞吐提升（本地模型必备）；**JSON Mode 2026 已算 legacy**，新代码直接上 constrained decoding/native structured outputs。
- 提升层：可复用 Skill（输出保证档位）。

### 4. 三级验证管线+schema 工程（可复用 Skill）
来源：kanopy / precisionaiacademy / aiworkflowlab-id / nisai
- **三级验证**：syntax（合法 JSON？抓截断/编码错/混散文）→ schema（Pydantic/Zod 符合定义）→ **semantic（值合理？负价格是合法 JSON 匹配 schema 但语义错）**——即使 100% 结构合规也要跑业务规则。
- **schema 扁平化**：每层嵌套加错误率——4 层 schema 拆成两个 tool 后 validation failure **6%→0.4%**；**enum 优先 free-text**（categorical 字段 88%→100% 有效）；description 带格式示例（"ISO 8601 date, e.g. 2026-07-14" 胜过裸 type string）。
- 提升层：可复用 Skill（验证管线+扁平化规范）。

### 5. 并行调用与失败恢复（工作流）
来源：zylos / channel / loooop / niteagent / openlegion
- **并行降延迟 50-70%**：5 源各 200ms，顺序 1000ms vs 并行 200ms——agent 系统最大单项性能优化。
- **partial failure 策略**：Promise.all fail-fast（一个失败取消整批，适合"缺一不可"）vs 独立容错（各自降级）；**dependent 序列化 + independent 并行并 tag 结果 call_id**；call-result ledger 服务端持久化+幂等重试瞬时 4xx/400（防连接断后重复副作用）。
- **护栏**：max-tool-calls guard（10/会话）；no-progress loop 检测（无进展循环停止或升级）。
- 提升层：工作流（并行编排）。
