## 落地 5 独点（每点标注提升层）

### 1. 结构化输出=可靠集成的地基（工具/可复用 Skill）
来源：aiworkflowlab / aibuzz / futureagi-prompting
- **量化收益**：显式指定输出格式/schema（JSON/表格/CSV）——**输出变异性降 35%、生产系统错误减 27%**（2026 研究）。
- **无结构化输出的代价**：每个 LLM 调用都要一层解析（regex 提取/容错）——结构化输出让约束内建于 API 层（gpt-5/claude-opus-4-7/gemini-3 全支持 response-format/JSON schema 强制）。
- 提升层：工具（schema 强制）/ 可复用 Skill（模板）。

### 2. Few-shot 真知：标签空间>标签正确性（可复用 Skill）
来源：aiunpacker / futureagi-what-is / skillgen
- **Min et al. (2022) 关键发现**：few-shot 生效靠**标签空间与输入分布**，不靠单个标签正确——**随机标签的示例也优于 zero-shot**；示例覆盖多样性比示例对不对更重要。
- **实操**：3-5 个多样示例（Claude 用 `<example>` 标签包裹），格式/语气/结构化输出任务最值；类不平衡要平衡示例；**注意顺序效应**（示例顺序影响输出）。
- 提升层：可复用 Skill（few-shot 设计）。

### 3. Prompt caching 实操（工具/工作流）
来源：novakit / sureprompts / openai-gpt6 / wikiwalls
- **收益量化**：Anthropic/OpenAI/Google 全支持，用好了**成本降 70-90%、延迟降 30-50%**（重复工作流）。
- **模式**：①最大最稳定内容（system 指令/工具 schema/大参考上下文）放 prompt **最顶**②最后一个稳定块显式标记 `cache_control: {type: "ephemeral"}`③变化的 user 消息放标记之后——**别缓存 user turn，缓存它就废了**。
- **细节**：ephemeral 缓存 5 分钟 TTL，请求要持续或重置；OpenAI GPT-6 新缓存系统=30 分钟内复用的共享前缀享缓存折扣，**最高 90% 输入 token 折扣**，附带缓存性能监控工具。
- 提升层：工具（缓存标记）/ 工作流（prompt 布局）。

### 4. 2026 默认脚手架与简洁原则（可复用 Skill）
来源：novakit-structure / hustletoai / baeseokjae
- **RCTF 骨架**（Role/Context/Task/Format）：跨 Claude 4/GPT-5/Gemini 2.0 最可靠（2026）——角色/上下文/任务/输出格式四段。
- **前沿模型爱结构**：训练吃了大量 XML/Markdown/JSON——非平凡 prompt 默认脚手架=`<context>` 检索文档 + `<examples>` 示例对 + `<instructions>` 指令。
- **"更多细节=更好"是神话**：过度冗长 prompt 反而降指令遵循——**指令任务 <150 token 通常优于 >500**。
- **推理模型特例**：2026 reasoning 模型用 `reasoning_effort` 参数调推理强度，**别在 prompt 文本里重复推理指令**（重复反而干扰）。
- 提升层：可复用 Skill（脚手架模板）。

### 5. 迭代六步与 meta-prompting（工作流/可复用 Skill）
来源：skill4agent / kunal / happycapy
- **六步迭代**：①简单 prompt 起步（只抓核心任务）②10-20 个多样输入测试③识别失败模式（格式错/信息缺/幻觉）④针对每个失败模式加约束或示例⑤重测——确保修复没弄坏之前通过用例⑥记录 prompt 版本与测试结果；配套 eval 集 20-50 对输入/期望输出逐条打分。
- **meta-prompting**：用 LLM 生成/评估/精炼 prompt——给模型任务描述+好/坏输出示例，让它写更好的 prompt；配合每步日志（多数团队生产崩了才补日志）。
- 提升层：工作流（迭代闭环）/ 可复用 Skill（meta-prompt 用法）。
