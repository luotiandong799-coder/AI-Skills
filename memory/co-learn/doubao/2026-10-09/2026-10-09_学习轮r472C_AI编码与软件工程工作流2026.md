## 落地 5 独点（每点标注提升层）

### 1. Spec-Driven 四阶段与 task-prompting（工作流）
来源：blink / shiplight / javacodegeeks / dev-deterministic
- **Spec→Plan→Execute→Verify；spec 四节=What 一句/Why/Scope 做与不做/Success criteria 机械可验证**——agent 每次请求读它作上下文。
- **intent-prompting→task-prompting**（"build me X"→"implement X as defined…outputs I can verify mechanically"）；**改计划比改代码便宜 10 倍**；deterministic loop=生成→spec 派生测试→验证 checkpoint→证据日志。
- 提升层：工作流（编码流程）。

### 2. 三层评审闭环与 AI-on-AI（工作流）
来源：csdn-vibe-coding / baeseokjae / superdevresources
- **三层=AI 自评审（review Skill 查语法/安全/冗余/规范，自主修复）→自动化 CI（测试/规范扫描/依赖漏洞，高风险阻断合并）→人工顶层（只聚焦架构/业务逻辑）**。
- **三质量门=test-first+hooks（每次编辑自动 lint/type-check/test）+AI-on-AI（第二 LLM 审第一 LLM 输出）**。
- 提升层：工作流（评审闭环）。

### 3. AI 审查质量指标与 400 行崩溃点（工具）
来源：softwaretestpilot / augmentcode / refacto
- **审查质量=Actionable（带具体修复）/Severity-correct（P0/P1 只给真 bug/安全）/De-duplicated/FP 率 ≤25%（每周测）/planted bug recall 达标**。
- **人类 review 有效崩溃点 400 行**（超过即 skim）；**AI 高采纳=PR review 时间 ×5、每 PR 事故 ×3——修复靠机械门**（compiler/type gates、diff-scoped SAST、依赖存在检查、mutation suites、post-merge canaries）。
- 提升层：工具（审查治理）。

### 4. AI 代码验证纪律（工具）
来源：contextqa / augmentcode / dev-qa-checklist
- **AI 优化的是 prompt 不是结果——diff 不映射到那句话就停**；**读意图不读语法**（对空/巨大/畸形输入跟踪逻辑，AI 边界靠猜）。
- **验证每个 API/依赖存在**；**审查最小有用 diff；缺测试单独要+检查断言是否同义反复**（七门 QA=Scope/CI 变更阻断等）。
- 提升层：工具（收代码纪律）。

### 5. Refactor 四条件与 prompt chaining（可复用 Skill）
来源：aitoolsguidebook / reposition / dev-5-ai-tools
- **Refactor 四真条件=有测试/单模块单关注点/目标一句话/每个 diff 审查——全真才用 AI**；**先 plan 再 edit**（只读规划模式）。
- **prompt chaining=一交互输出作下一输入**（保持上下文、隔离关注点，优于一次性巨型 prompt）。
- 提升层：可复用 Skill（重构工作流）。
