## 落地 5 独点（每点标注提升层）

### 1. Spec-first 工作流（工作流/可复用 Skill）
来源：blink / datacamp / aifieldnotes / augmentcode
- **先写 spec 再写 prompt**：1-2 页结构化文档四节——**What**（一句话功能）/ **Why**（解决的用户问题）/ **Scope**（做啥明确不做啥）/ **Success criteria**（怎么验证做成了）；agent 在会话里每个请求都读它当上下文，省掉来回解释。
- **spec→plan→实现**：spec 转编号任务计划→agent 逐任务写代码→**每步之间人工 review**——与 TDD 结合（先写针对 spec 的测试，实现让测试变绿，重构以 spec 为安全网）。
- 提升层：工作流（spec 驱动）/ 可复用 Skill（spec 模板）。

### 2. Agentic coding 五阶段（工作流）
来源：rockb-llm-workflow / dev-ifnodoraemon
- **五阶段**：①spec-driven planning（读代码库+架构设计+PRD 拆 bite-size 任务）②context packing（CLAUDE.md/.cursorrules 打包栈细节/DB schema/约定/部署管线——**开工前最高杠杆动作**）③iterative implementation（一次一任务+测试）④automated quality gates（测试/lint/安全检查）⑤persistent tooling。
- **量化**：照此结构 25-39% 生产力增益 vs ad-hoc 提示（ad-hoc 把大部分价值留在桌上）；多文件任务先 Plan Mode（只读探索+架构设计给你审批）再动手。
- 提升层：工作流（端到端结构）。

### 3. 多角色 agent 代码审查（工作流/可复用 Skill）
来源：rockb-agentic-patterns
- **PR 人审前先过 AI 多视角审查**：不是"AI 审这个 diff"，而是 agent 依次扮演**security auditor → performance analyst → test coverage checker → style enforcer** 四个角色逐视角审。
- **配套**：Claude Code power tips——别接受第一个方案（"Grill me on these changes and don't make a PR until I pass your test"）、"Prove to me this works"（diff main 与 feature 分支行为）、"Knowing everything you know now, scrap this and implement the elegant solution"。
- 提升层：工作流（多视角审查）。

### 4. Vibe coding 纪律（可复用 Skill）
来源：0xminds / dev-sanskarcodes / aiwiki / eweek / zoer / byteverse
- **六错清单**：①一次性全建（"full e-commerce site"是产品 spec 不是 prompt）②接受代码不读（编译通过≠正确）③跳过版本控制（每次 working state 提交=30 秒回滚 vs 3 小时调试）④无安全审查（认证/SQL/API key 上线前必须审）⑤大提交（十个小提交比一个 4000 行提交好调试——每次 green run 后提交+真实 why 消息）⑥信任 AI 输出。
- **安全敏感区**：认证/授权/加密/支付**别 vibe**；适合 vibe=landing page/原型仪表盘/小工具/内部工具/数据转换/样板/测试脚手架/文档/小重构；**AI 代码 20-30% 更多安全缺陷**，仅 33% 开发者全信输出。
- **独立 AI 审查者**：写完让另一个 AI 审查器独立扫输出（bug/重复/安全缺口/缺测试/过度工程）——**审查者报告不修复**，人决定再让 AI 改。
- 提升层：可复用 Skill（vibe 纪律清单）。

### 5. 工具选型与模型分级（工具）
来源：claudhq / dev-mtahir27 / ai-portal
- **Claude Code vs Cursor**：Claude Code=CLI-first 自治 agent（读代码库/跑 shell/改文件/多步执行），**适合大重构、CI/CD 自动化、跨几十文件 agentic 任务**；Cursor=VS Code fork 编辑器内嵌 AI（快速内联补全/视觉 diff/编辑器流内），**适合留在编辑器流内**——按居住地选（终端人 vs 编辑器人）。
- **模型分级**：Sonnet（$3/$15）=工作马，标准模块化重构/复杂集成测试/校验 DB 查询；Opus（$15/$75）=架构级重构/复杂状态迁移/深度依赖瓶颈/高层审查——不无脑全用旗舰。
- 提升层：工具（选型）/ 工作流（模型分级）。
