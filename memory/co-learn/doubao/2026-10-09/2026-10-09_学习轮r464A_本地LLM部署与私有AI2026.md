## 落地 5 独点（每点标注提升层）

### 1. 本地引擎三选型与 GGUF 生态（工具/工作流）
来源：acingai / checkaimodels / daddaops / ringsafe / dev-mrsaynothing
- **三引擎各管一段**：Ollama=个人单机/桌面/实验首选（一条命令 `ollama run deepseek-r1:7b`，0.5+ 支持混合 CPU/GPU 推理与动态模型卸载，模型库现成；缺点是高并发吞吐垫底）；llama.cpp=最大控制（C++ 引擎，CPU+GPU，GGUF 格式，"当 Ollama 不够时"）；vLLM=生产级（UC Berkeley，PagedAttention+continuous batching，GPU-only，OpenAI 兼容 API，高并发吞吐 5-10× Ollama）。
- **GGUF=本地生态通用格式**：llama.cpp 引入的单文件模型格式，Ollama/llama.cpp/vLLM 全都读——同一个文件到处跑，从 HF 直拉即用。
- **vllm-metal**（Apple Silicon 并发服务）：prompt 长度分批下对比 mlx_lm/llama.cpp，短 prompt 场景并发领先。
- 提升层：工具（选型）/ 工作流（部署路径）。

### 2. 量化档位量化数据（工具/可复用 Skill）
来源：technologypulse / 1337skills / stackpractices / felixwang007 / daily-dev
- **档位表（7B 基准）**：F16 14GB（基准）→ Q8_0 8.5GB（~99% 质量，1.1× 快）→ Q6_K ~6.5GB（近原始）→ Q5_K_M ~5.7GB（good）→ **Q4_K_M ~4.9GB（推荐平衡 ~97% 质量 1.5× 快）** → Q3_K_M ~4.0GB（可接受 ~94%）。
- **选择口诀**：显存刚好够 Q4 选 Q4_K_M；有余量升 Q5/Q6 更值；追求极限质量且显存充足用 Q8_0（微调前测试也用它）；Ollama 默认 Q4_K_M 可调。
- **VRAM 需求对照**：1-3B=2-4GB（Phi-3 Mini/Gemma 2B）、7-8B=5-8GB（Llama 3.1 8B/Mistral 7B）、13-14B=9-12GB（Llama 3.1 14B/Phi-3 Medium）——**本地推理最重要的数字是可用 VRAM**。
- 提升层：工具（量化选择）/ 可复用 Skill（对照表）。

### 3. 本地嵌入模型选型（工具/可复用 Skill）
来源：runaihome / cloudstreet / promptquorum / local-ai-experts
- **三选型对比**：nomic-embed-text v1.5（274MB/137M/8192 token/MTEB 62.39，对比学习目标擅长检索，**CPU-only 机器首选/默认起点**，现代 CPU ~600 chunks/s）；mxbai-embed-large（670MB/334M/512 token/MTEB 64.68，高精度但上下文短，适合短文档块）；snowflake-arctic-embed2（~600MB/303M/8192 token，多语言文档）。
- **本地 RAG 双模型**：嵌入小模型（转文本为向量）+ 推理 LLM（读检索上下文作答）——两个模型，各司其职。
- 提升层：工具（嵌入选型）/ 可复用 Skill（对比表）。

### 4. 本地 RAG 栈与 num_ctx 坑（工作流/可复用 Skill）
来源：insiderllm / aimadetools / markaicode / botmonster / sitepoint
- **零云栈**：Ollama + 嵌入模型 + 生成模型 + 本地向量库（ChromaDB PersistentClient cosine 距离 / Qdrant）+ Python——内部文档/客户数据/敏感内容**不出机器**，无 API key 无订阅。
- **第一坑：num_ctx**——Ollama 默认 `num_ctx=2048` tokens，本地 RAG 检索内容+prompt 超限被截断——**必须显式调大上下文窗口**。
- **分块**：RecursiveCharacterTextSplitter 重叠分段；工具链 AnythingLLM/Open WebUI 免代码上传 PDF/text/markdown 即问答。
- 提升层：工作流（零云栈）/ 可复用 Skill（num_ctx 检查项）。

### 5. 本地≠自动安全（可复用 Skill/工作流）
来源：nerdleveltech / martinuke0 / arxiv-onprem
- **本地推理增强隐私但非自动安全**：①模型完整性=校验下载模型 checksum（防供应链投毒）②prompt 注入=消毒用户输入防恶意指令 ③访问控制=本地 API 端点加认证 ④数据保留=不记敏感 prompt 或输出——按 OWASP AI 安全指南。
- **边缘设备优化链**：按内存/算力/功耗选硬件 → 按精度/体积平衡选量化（GPTQ 快速 4bit / AWQ 更高保真）→ 匹配目标平台的运行时（llama.cpp/ONNX Runtime/MLX）→ threading/cache/profiling 调优——百美元级设备可达交互延迟。
- **OnPrem.LLM**：隐私优先文档智能 Python 工具包，离线/受限环境预建 RAG/抽取/摘要/分类流水线，多后端（llama.cpp/Ollama）。
- 提升层：可复用 Skill（安全清单）/ 工作流（边缘优化链）。
