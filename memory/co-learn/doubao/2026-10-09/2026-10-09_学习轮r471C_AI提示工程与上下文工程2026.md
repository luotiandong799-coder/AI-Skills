## 落地 5 独点（每点标注提升层）

### 1. few-shot 最优数量与 CoT 选择判据（工作流）
来源：futureagi-prompt-format / futureagi-practitioner / ai-pedias / aibuzz
- **few-shot 最优=分类/抽取 2-4 例>0 例>10 例**；超过 4 个模型过拟合示例表面形式（措辞/长度/用词），泛化下降；**开放式生成 0 或 1 例最好**。
- **CoT 选择判据=多步推理/规划/工具选择用，简单分类/抽取跳过；新推理模型内部自带 CoT，加可见推理指令反而有害**——commit 前必须 eval 验证。
- 提升层：工作流（提示选型）。

### 2. 上下文工程四动作与 offload（可复用 Skill）
来源：dreaming-press / anhtu / cnblogs / automater
- **四动作=Write（写出窗口，memory tool）/Select（只选本步需要）/Compress（压缩已有）/Isolate（隔离进独立 agent）**——每个映射 Claude API primitive。
- **offload=工具返回 5 万 token JSON 只需三行——总结进上下文、全量存外部留轻引用，可 cut 99% tokens**。
- 提升层：可复用 Skill（上下文动作清单）。

### 3. NOTES.md 文件模式与 selective injection（可复用 Skill）
来源：toolchew / atlan / contextstudios
- **NOTES.md 模式=每次 context window 开始读、结束更新，reset 后从文件重建**（跨多日项目/长跑 agent）。
- **selective context injection=先分类 query 意图再按类型检索注入**（context routing layer 映射 query 类型到上下文类别）；**token budget 先行=写任何 prompt 前先定义 token 分配**（静态/动态分离、静态层开 caching、动态层加 routing、治理可观测）。
- 提升层：可复用 Skill（注入与预算）。

### 4. prompt 评测体系（工作流）
来源：futureagi-prompting-llm / lobehub / colab
- **golden dataset=100-500 条+预期输出或 rubric→evaluator suite（groundedness/context adherence/toxicity/LLM-as-judge）→总分+worst-decile failures**（平均分好掩盖最差 10% 崩）。
- **六指标=Accuracy/Consistency（N 次输出方差）/Format compliance（99% production）/Latency（P50/P95）/Cost（tokens×单价）**；same model 好坏 prompt 常差 20-40% 准确率。
- 提升层：工作流（评测驱动）。

### 5. OUTPUT CONTRACT 与结构纪律（工作流）
来源：dev-master-prompts / aiunpacker / microsoft
- **OUTPUT CONTRACT 默认形状=## Plan/## Work/## Result/## Verification/## Risks Next steps**；Known Facts/Assumptions/Open Questions/Recommendations 四段模板。
- **recency bias=指令在内容前后影响输出**、few-shot 示例顺序也影响；**给模型一个 out**（无法完成时给替代路径）；**PLANNING=一步需 >3 tool calls 就拆分**+done_when；TRUTH=不编造、标 UNVERIFIED、缺关键上下文追问。
- 提升层：工作流（输出契约）。
