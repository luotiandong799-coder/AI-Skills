## 落地 5 独点（每点标注提升层）

### 1. 指令文件大小纪律与路径作用域（可复用 Skill/工作流）
来源：hasanarief / claude-steering / bestaiweb / tencent-claude-memory
- **200 行上限**（Anthropic 官方目标）：每份 CLAUDE.md 控制在 200 行内——更长消耗上下文且降低遵从度（"Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"）；违反规则时先怀疑规则文件臃肿，再怪模型。
- **path-scoped vs unscoped 规则**：`.claude/rules/` 下无作用域的规则每次会话开始加载+压缩后重注入，无关任务也烧 token；**path-scoped 规则加路径前缀，只在相关路径被触及时加载**——按需加载优于常驻。
- **读取机制**：Claude Code 从当前工作目录向上走树、把找到的每份 CLAUDE.md 按 root→cwd 顺序拼接；Codex 读 AGENTS.md 同样走树。
- **四级层级**：组织级（/Library/.../ClaudeCode/CLAUDE.md 编码标准/安全策略）→ 用户级（~/.claude/CLAUDE.md 个人偏好/快捷键）→ 项目级（./CLAUDE.md 架构/构建命令/工作流）→ 本地级（./CLAUDE.local.md gitignore：沙箱 URL/个人测试数据）。
- 提升层：可复用 Skill（文件写作纪律）/ 工作流（作用域加载）。

### 2. AGENTS.md 单文件标准与 override 机制（工作流/可复用 Skill）
来源：aikickstart / puritysb-agentharness / dev-laurel / dotagentsprotocol
- **单文件标准**：AGENTS.md 是 OpenAI·Linux Foundation 的通用格式，Claude Code 与 Codex 都读它——"一年前每个工具想要自己的文件，现在多数都读 AGENTS.md"。
- **合并规则**：从 git root 向下合并，**更深层文件胜出**（子服务 services/payments/AGENTS.md 覆盖根规则；显式 AGENTS.override 强制覆盖）。
- **根文件=共享地图**：monorepo 布局、build/test 命令、跨切面约定、agent 工作协议、验证范围、`paths → rule file` 索引——每个 agent 先读它。
- **内容结构**：Project Identity（一段话：项目是什么/服务谁/做什么+stack 一句话，如 Next.js 16/React 19/TS strict）→ Setup & commands（可复制命令：install/build/dev/test/lint/format，ROI 最高段）→ 约定（如 Server Components 不用 useState）→ Testing（覆盖率 80%）→ Always/Never 块 → 安全规则。
- 提升层：工作流（合并与覆盖）/ 可复用 Skill（内容模板）。

### 3. MEMORY.md 阈值与原生记忆结构（工具/可复用 Skill）
来源：code.claude-memory / claude-code-explain-memory / platform-claude-managed-memory
- **MEMORY.md 索引阈值**：前 200 行或 25KB（先到为准）在每会话开始加载，超阈值的主题文件不自动加载（按需读取）——索引必须瘦。
- **结构**：`~/.claude/projects/<slug>/memory/` 下=MEMORY.md 索引（每记忆一行）+ 每主题独立 md 文件（YAML frontmatter 类型标注）；**四类型记忆**=user_role（角色/专长/工作偏好）/feedback（纠正与确认的方法）/project（无法从代码或 git 推导的进行中工作/截止/决策）/reference（项目外信息的存放位置）。
- **managed agent memory store 上限**：单条记忆 ≤100KB（~25k token），store 最多 10000 条；**结构化为一组小而聚焦的文件，而不是几个大文件**。
- 提升层：工具（记忆结构）/ 可复用 Skill（索引纪律）。

### 4. Memory Bank 四层自动加载架构（可复用 Skill/工作流）
来源：ytrofr-memory-bank / centminmod / zander
- **四层**：①always/（via @ imports 每次会话自动加载——每次会话都需要的核心模式）②learned/（不自动加载、按需搜索——已解决问题/可复用模式）③ondemand/（需要时加载——领域参考文档）④blueprints/（极少用——全系统重建指南）。
- **层级判据**：频率越高越往上（always<learned<ondemand<blueprints），自动加载只给最高频层，其余全部按需——防止上下文被低频内容占满。
- **补充**：便宜模型需要的手把手说明放钉住该模型的 agent 文件里（frontmatter `model: haiku` 旁边），不污染主指令文件。
- 提升层：可复用 Skill（分层模板）/ 工作流（加载策略）。

### 5. Hooks 必然执行机制与定时任务文件化（工具/工作流）
来源：platform-claude-sdk-hooks / openai-agents-hooks / dotagentsprotocol / puritysb
- **Agent SDK hooks=回调函数在 agent 事件触发**（工具被调用/会话开始/执行停止），三个能力：①阻止危险操作执行前拦截（破坏性 shell 命令/未授权文件访问）②记录审计每个工具调用（合规/调试/分析）③转换输入输出（消毒数据/注入凭证）——**hooked 机制比提示词叮嘱必然执行**。
- **两级 hook**（OpenAI Agents SDK）：RunHooks 观察整个 Runner.run 调用（含 agent 间 handoff）；AgentHooks 附着特定 agent 实例；事件点=on_llm_start/end、on_tool_start/end。
- **定时任务文件化**（.agents Protocol）：`.agents/tasks/daily-review/task.md` 用 frontmatter（kind: task/id/intervalMinutes: 60/enabled）声明周期任务——**任务与指令文件同库版本化**，比 cron 配置外置可审计。
- 提升层：工具（hooks）/ 工作流（任务文件化）。
