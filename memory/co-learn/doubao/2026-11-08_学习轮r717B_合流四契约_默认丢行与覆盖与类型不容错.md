## 二、落地点（4 个真独点）

### 1. 先分清「合并哪一类」（工作流层）
① 一条流分裂后汇回 = 对齐/追加；② 两个独立节点的输出 = join；③ 同一节点多次执行 = Merge 拿不到，必须 Code node 收拢 items；④ 比较后合并 = Compare Datasets 最多四路。判据：合并对象错了，join 参数全在调错的模型。

### 2. 默认 join 会静默丢行（工作流层）
Matching Fields 默认 `Keep Matches`（inner）；Position 模式默认 `leave out the items without a match`，要保留必须显式 `Include Any Unpaired Items`。判据：行数变少不报错——跑完核「输入条数和 vs 输出条数」。

### 3. 同名字段默认被 Input 2 覆盖（工具层）
Clash Handling 默认 `prioritizes Input 2`，无任何提示；要留两侧选 `Always Add Input Number to Field Names`。判据：「值看起来对但来源不对」是被覆盖不是算错。

### 4. 类型不容错 + Append 是同步栅栏（工具/工作流层）
`Fuzzy Compare` 默认关 ⇒ `"3"` ≠ `3`，join 静默配不上；Append 等所有输入执行完才出结果 ⇒ 缺一路即阻塞；All Possible Combinations 是笛卡尔积，行数按乘积爆炸。
