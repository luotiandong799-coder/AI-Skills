## 三、核心方法与关键事实（带来源，摘录）

- 结构化输出=引擎侧 constrained decoding 保证（Anthropic 官方：Always valid/Type safe/Reliable no retries）；refusal 优先于 schema（HTTP 200 照常计费，输出不符 schema）；strict 不兼容 parallel function calls；response_format 与 tools 同一 request 互斥，agent 循环拆两 turn。
- 新 schema 首请求延迟（预处理缓存，复杂可达 1 分钟）；strict json_schema 可能禁用缓存写入（gpt-5.6 实测 cache_write 恒 0）；缓存可运维：断点/precaching/工具定义稳定（allowed_tools、tool_choice:none、developer message 尾加）。
- SDK transformation：不支持的约束（minimum/maxLength 等）被移除并以 description 承载，additionalProperties:false 自动补，原始 schema 仍做最终校验。
- 结构正确 ≠ 语义正确：parser 管格式，业务校验管值域；"AI pipelines run, return clean outputs, and pass downstream validation — except the answer is wrong"；Never pass raw AI output directly to a node that modifies external systems。
- schema 能约束形状不能证明事实存在（Make 实战：业务规则不是解析规则）；高险声明加人工审批即使 JSON 通过；测试 3 条故意坏输入。
- error-feedback retry：把结构化 validation error 回传模型（Field/Error/Your value），self-reflective API 结构化建议比纯英文诊断完成率 +36.7-40pp（Anthropic 模型）；上限 2-3 次；失败 typed 不 loud；同字段反复失败=schema 问题。
- repair 先于 retry：json_repair 免费第一遍（恢复 70-85%），修复后必须先 log 再校验防假阳性；repair→validate→retry 序列。
- LLM-as-judge 二值判决（pass/fail）降开销；guardrail 双向放置（输入+输出）；确定性管格式/PII、模型型管意图/语义；防幻觉五层架构（context→grounding→constraints→agentic validation→continuous evaluation）。
- Langflow Agent 双输出各一次独立 LLM 调用，只连需要的那个；Structured Response 不写 chat history；JSON Sidecar 双产物（human-readable+JSON）+ incremental writes 防压缩丢数据。
- 多步 agent 失败复合：每步 5% schema 失败率 × 12 步 ≈ 46% 至少一步失效——每步都要 schema validation+repair。
