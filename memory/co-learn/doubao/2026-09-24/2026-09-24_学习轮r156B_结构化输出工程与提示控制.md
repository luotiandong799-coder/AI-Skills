## 二、独点清单 + 判非重复理由（6 点，均≥40% 独有增量）

### 1. 结构化输出三层验证，业务层最常被跳过（来源：Logic 2026-05-20 + next-gen.cloud 2026-06-11 实拉）
结构测试（可解析/必需字段/类型/enum）之外必须跑**语义测试**：答案对输入正确吗、符合业务规则吗、下游工作流行为正确吗——"退款金额不应为负、cron 调度匹配产品限制"。反模式：只验证"是合法 JSON"却让错误值进下游。
- 判非重复：豆包/WB 各轮评测面管"评测集/回归/闸门"（系统级）；本点管"**单次结构化输出调用后的三层验证栈**"（输出校验层）。增量≥60%。
- 提升层：工作流（输出校验）。

### 2. XML 标签语义边界 + 结构化思考分离 <thinking>/<answer>（来源：Claude 官方 best practices 2026-09-03 + aiwithgrant 2026-04-30 实拉）
prompt 有 3+ 区块（指令/上下文/输入/示例）时必须用 XML 标签做语义边界（Claude 训练把它当语义分界，最强结构信号）；复杂推理用 <thinking>/<answer> 分离"推理过程"与"最终输出"——可编程提取答案、保留完整推理供排障。
- 判非重复：豆包早期轮落过"结构化提示"（方式二）若在（角色/技能/规则），本点管"**XML 标签语义边界与思考-答案分离两个具体机制**"；WB 各轮无此面。增量≥50%。
- 提升层：工作流（提示工程）。

### 3. over-prompting 反模式：旧模型的触发补偿指令会让新模型过度触发（来源：Anthropic 官方 prompt library 2026-03-20 实拉）
"如果有疑问就用 [tool]"这类补偿式指令在旧模型下补偿触发不足，但**在新模型下会导致工具过度触发**——指令与模型能力绑定，升级模型后必须重审指令而非沿用。
- 判非重复：WB wb-execute-discipline 管"执行纪律/重试/幂等"（执行层）；本点管"**提示层写工具的触发倾向会随模型换代失效**"。增量≥70%。
- 提升层：工作流（提示工程反模式）。

### 4. Self-consistency 多数投票的启用判据与参数（来源：AIPromptsHub 2026-06-08 + explainx 2026-06-16 实拉）
温度 0.5-0.8 采样 N 条（5-20）推理链，只看每条最终答案取多数——正确路径收敛、错误路径发散。判据：存在多条有效推理路径的任务才用（数学/逻辑/多步骤），成本线性（N 倍）；单路径任务用单次 CoT 更省。
- 判非重复：豆包早期若落过 CoT 基础面；本点管"**self-consistency 的启用判据、参数与成本边界**"。增量≥40%（若 CoT 已落，本点为采样-投票机制增量）。
- 提升层：工作流（推理增强）。

### 5. Schema 键名是指令通道，可调优生成质量（来源：arXiv 2604.14862 2026-08-31 实拉）
constrained decoding 下**仅改 schema 键名**（不改 prompt/参数/结构）就能显著改变结构化生成质量——schema 不只是约束也是指令载体；不同模型族对"prompt 通道 vs schema 键名通道"敏感度不同，需按模型调试。
- 判非重复：点 1 管"验证层"、点 2 管"提示结构"；本点管"**schema 键名本身的设计与调优**"。增量≥70%。
- 提升层：工作流（结构化输出设计）。

### 6. Token 级运行时控制：解码层干预而非事后验证（来源：arXiv 2603.27905 ATLAS-RTC 2026-03-29 实拉 + HF/Outlines/NVIDIA 约束解码面）
前沿：运行时控制器在 logit 分布层拦截生成，对结构漂移做渐进干预（logit biasing→temperature 调制→token masking→中程回滚重采样），把"输出契约"从事后校验提前到生成过程；配套约束解码栈：Outlines FSM mask、NVIDIA JSON-Schema/Regex/EBNF guided decoding、syncode 语法引导（开销低至 10%）。
- 判非重复：点 1 是"事后三层验证"；本点管"**生成期约束与运行时干预**"（机制互补：先约束再验证）。增量≥70%。
- 提升层：工具/工作流（约束生成）。
