## 独点清单（3 个真独点，均来自真抓页面原文）

### 独点1：高影响操作在工具调用级做硬审批，不靠 prompt；审批可跨渠道路由、按工具选择性 gate（工作流层）
来源：n8n release notes 2026-01-22「Human-in-the-loop for AI tool calls」原文："A gated tool cannot execute unless a human explicitly approves… removes the uncertainty of prompt-based safeguards and insulates you from probabilistic agent behavior."
- 判据：prompt 里写"删除前要确认"是概率安全，模型可能不遵守；**在工具/节点连接上加人审步骤是确定性控制**——gated tool 不批准就根本不执行。按工具选择性 gate：部分工具自主跑、删除/写生产/发高影响邮件这类必须审批。审批不限单人单界面——Slack 发起的动作可路由到另一人走邮件批。
- 与已有 guardian 分工：guardian 三问是执行前的判断层；本条是把"高影响工具"做成硬门（不批就调不到工具），比判断更靠后、更不可绕过。
- 提升层：工作流。

### 独点2：运行权与编辑/发布权分离——敏感工作流给"能跑不能改"的人（工具层）
来源：n8n release notes 2026-03「workflow:execute is now a distinct scope… granted run access without being able to modify」+「publish/unpublish split into two scopes」。
- 判据：最小权限不是"一个工作流整包给权限"，而是拆成 execute / edit / publish / unpublish 四个独立 scope——运维/值班角色只需 execute（看结果、排障），不能改流程；发布和下架也分开管。判据：**能跑和能改是两种人**，混在一个角色里会让值班账号误改生产流程。
- 提升层：工具。

### 独点3：agent 执行轨迹 → 人审过的可复用技能，自动沉淀（可复用 Skill 层）
来源：deeplearning.ai 新课「Building Adaptive AI Agents」(Oracle) 原文："turns agent traces into reusable, human-approved skills… agents often repeat the same mistakes because they carry nothing forward between sessions… result is agents that improve with every run."
- 判据：agent 跨会话重复犯同一错，是因为没把跑过的成功路径沉淀下来。做法：把每次执行 trace 自动提炼成候选 skill，**过一道人审门（human-approved）**再入库——不是自动把 trace 当规则（会把偶然成功固化），人审只放行真可复用的流程。配套还可建 code knowledge graph 提升大代码库检索、识别何时该适配模型本身。
- 与 wb-skill-authoring 分工：那个管"怎么写好一个 skill"；本条管"从真实执行 trace 里自动挖候选 skill、人审门放行"的沉淀流水线。
- 提升层：可复用 Skill。

## 判非重复理由
- HITL 此前覆盖的是概念，"工具级硬门（非 prompt）+ 跨渠道审批路由"是 n8n 2026-01 具体增量；权限四拆分（execute/edit/publish/unpublish）未见覆盖；trace→human-approved skill 沉淀流水线为新主题。均 >40% 增量。
