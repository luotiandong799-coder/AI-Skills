## 独点清单（4 个真独点，均来自真抓页面原文）

### 独点1：Skill 已形成"包管理器+排行榜度量"分发形态——npx skills add 单命令装、按安装量/活跃度排序（可复用 Skill 层）
来源：skills.sh 首页原文："Install them with a single command… `$ npx skills add <owner/repo>`"；Skills Leaderboard 显示 All Time 868,875 次安装活动、Trending(24h)/Hot 分榜；榜首 vercel-labs/skills·find-skills 2.5M 安装、anthropics/skills·frontend-design 660K。
- 判据：skill 不只是"文件夹+SKILL.md"，**分发与采纳度量**已成生态标配——装 skill 像装 npm 包（一条命令、按 owner/repo 引用），选 skill 看安装量与活跃趋势（All Time / 24h Trending / Hot 三榜）。自己维护可复用 skill 时，应给每个 skill 配"单命令安装说明 + 按用途归类"，并用安装量/复用次数判断哪个 skill 值得维护升级。
- 与 wb-skill-authoring 分工：那个管"skill 怎么写好"；本条管"skill 怎么分发、怎么用数据判断价值"。
- 提升层：可复用 Skill。

### 独点2：Codex + Draw.io MCP 零代码生成可编辑架构图——复杂多层架构图交给 agent 自动画（工作流层）
来源：WaytoAGI 知识库精选 2026-09-11《Codex 实战系列｜零代码画出复杂架构图》原文："用 Codex 搭配 Draw.io MCP 的工作流，能自动生成可编辑的图表，就算是多层、数十个模块的复杂大图也能搞定。文中还附带了完整配置教程、多种实战案例与绘图编辑技巧，做 PPT、项目方案的大家可以直接上手实操。"
- 判据：画架构图/PPT 图的最高效路径不是手绘也不是让模型直接吐图，而是 **Codex + Draw.io MCP：模型把结构描述给 Draw.io 工具，产出可编辑的 .drawio 文件**——之后要改只改文件再生成，不用重画。适合方案评审、PPT、迁移图等高频场景。
- 提升层：工作流。

### 独点3：四层长期记忆的工程实现——L1轨迹/L2策略/L3世界模型/skills，每轮自动检索、记忆以工具形式注册（工具层）
来源：deepseek-plugin.org 第 05 名 MemTensor/MemOS 插件原文："Provides local four-layer long-term memory… (L1 trajectory / L2 strategy / L3 world model / skills), with automatic retrieval each user turn and support for registering six memory tools."
- 判据：记忆不只是"存向量"，工程化做法是**分层**：L1 轨迹（原始执行记录）/ L2 策略（可复用打法）/ L3 世界模型（对领域/环境的认知）/ skills（可直接调用的流程），且**每轮用户输入自动检索**对应层，记忆读写以"六个记忆工具"形式注册给模型调用（不是塞上下文，是工具化访问）。这是 r181B"长期记忆与遗忘"的具体实现层增量。
- 提升层：工具。

### 独点4：spec-driven 从"写规约再开发"扩展到"Interview→Seed→Execute→Evaluate→Evolution"自我进化循环（可复用 Skill 层）
来源：deepseek-plugin.org 第 08 名 Q00/ouroboros 插件原文："Launch the Ouroboros Python engine via uvx to provide DSH with specification-driven AI workflows as MCP tools (Interview→Seed→Execute→Evaluate→Evolution loop), requiring no installation or additional code."
- 判据：spec-driven 不是一次性"先规约后写码"，可做成**进化循环**：Interview（向用户采需求）→ Seed（生成初始规约/方案）→ Execute（执行）→ Evaluate（按判据评估）→ Evolution（据评估改进规约）→ 再循环。且以 uvx 拉起、MCP 工具形式暴露，免安装免代码。与已有 SDD 覆盖的分工：那条管"先写规约再开发"的纪律；本条管"规约本身进入评估-演化闭环"的增量。
- 提升层：可复用 Skill。
