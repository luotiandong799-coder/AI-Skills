## 独点（4 个）
### B1：just-in-time 引用验证——"检索难，验证易"，不做离线记忆治理（来源：github.blog 2026-01-15 全文）
- 离线 curation（去重/冲突解决/分支过期追踪/过期清理）在 GitHub 规模下工程复杂且 LLM 成本高，仍需读时对账。**改为记忆自带 citations（指向具体代码行），命中时实时验证引用**——只读操作，无显著延迟。
- 判据：**记忆不是"存对了就行"，而是"存的时候附上可被未来验证的证据"**；过期风险用读时低成本验证消化，不用写时重型治理消化。
- 与 wb-context-compressor 记忆提取四策略分工：那条管"会话结束提取什么"；本条管"存的每条记忆必须带可验证引用，用时先验引用再采信"。
- **提升层**：记忆/工作流。

### B2：store_memory 作为 tool call 事件化写入 + 四元结构 + 自愈合（来源：同上）
- 写入不是会话结束批量提取，而是 agent 在执行中**发现"未来有行动价值"时主动调 store_memory**，结构：subject / fact / citations[] / reason（为什么值得记）。
- 自愈合：引用与代码矛盾→存修正版；引用有效且有用→**再存一次刷新 timestamp**（软过期，不靠删除）。对抗性测试：种子矛盾/无效引用记忆，agent 全部验出矛盾并更新，记忆池自愈。
- 量化：记忆使 code review precision+3%/recall+4%，coding agent PR merge rate 90% vs 83%（+7pt，p<0.00001）。
- **提升层**：记忆/工作流。

### B3：skills vs custom instructions 分工判据（来源：docs.github.com add-skills）
- **custom instructions**：几乎每个任务都相关的简单规则（如仓库编码规范），常驻注入。
- **skills**：只在相关时才加载的详细指令/步骤/脚本。
- 判据：**常驻的是"全任务通用的短规则"，按需激活的是"特定场景的长流程"**——把所有规则都塞进 skills 会激活即占满上下文，把长流程塞进 custom instructions 会每轮都付 token。与渐进披露三档（metadata/body/resources）是同一原则的两个面。
- code review 专用：skill 目录命名 `code-review` 可让 Copilot code review 必用。
- **提升层**：可复用 Skill（组织）。

### B4：gh skill CLI 版本锁定与 provenance（来源：docs.github.com add-skills）
- `gh skill search/preview/install/update/publish`；装时 `@TAG` 或 `@SHA` 锁版本，`--pin` 固定跳过更新；`--scope user/project`、`--agent claude-code` 装到对应目录。
- 安装时把 **provenance metadata（source repo / ref / tree SHA）写进 SKILL.md frontmatter**，update 时据此比对上游变更。
- 安全警示：allowed-tools 预批准 `shell`/`bash` = 移除每次确认步，脚本未审就预批 = 提示注入任意执行；**不预批准 shell/bash，留人工确认**。
- 与 r184-B（不可变修订指纹/stale edit 拒绝）分工：那条是客户端侧装后防并发改；本条是 CLI 侧装时钉版本+记录出处供比对。
- **提升层**：工具/可复用 Skill（分发与安全）。
