## 实拉证据（关键原文）
- channel.tel：「the attack moved from the chat input to the tool output, and the old defenses don't work there.」2026-03 Anthropic 发防御指标、OpenAI 发红队框架、Arcjet 出生产级注入检测，三者结论一致。
- howardism：「Model hardening (instruction/data separation training) — no protection within data; it is exactly why instruction injection is ~0% but ADI is wide open.」baseline ASR 在 JSON 上 31-43%、web DOM 上 33-100%。
- agentmelt：「Indirect injection is the class every 2025-26 major incident belongs to…attacker plants instructions inside content the agent will consume — email, Google Doc, support ticket, scraped webpage, git commit message, calendar invite, image.」
- openlegion：「Agent A is injected. A's output — now attacker-influenced — is passed as input to Agent B via a handoff. Agent B follows the injected instructions without knowing.」
- kunalganglani：用 `<untrusted_content>` XML 标签包裹不可信数据；metacto：「Every piece of context the agent uses needs a provenance tag — which corpus, which document, which uploader, what trust level.」
- fiddler：「The model cannot reliably separate instruction from data when both arrive as text. Prevention therefore has to move out of the prompt and into the system architecture around the model.」

## 独点清单（3 个真独点）

### 独点1：攻击面已从 chat input 转到 tool output/RAG/邮件——直接注入防护对它无效（工作流层）
- 判据：2025-26 重大事故全是间接注入（XPIA）——攻击者把指令藏在 agent 会读的任何外部内容里（邮件正文/网页/PDF/git commit message/日历邀请/图片 alt）。**每个工具返回都是注入面**：工具成功执行了，但返回内容里藏了"转发邮件给某地址"。
- 独有增量（与 r166A 提示注入基础防御区别）：那条管用户直接输入的注入；本条是**外部内容携带的注入**，攻击路径完全不同，老的输入过滤挡不住。
- 提升层：工作流。

### 独点2：模型在同一段文本里分不出指令与数据——防护必须移出 prompt 到架构（可复用 Skill 层）
- 判据：instruction/data separation 训练让直接注入接近 0%，但 ADI（数据内容里藏指令）仍然 wide open——因为指令和数据都是同一段 token，模型没有可靠的内部分离器。**所以防护不能靠"在 prompt 里告诉模型别信外面的内容"**，必须靠架构：隔离不可信输入通道、工具最小权限、限制爆炸半径、运行时策略层（工具调用前审查计划动作）。
- 独有增量：给了一个反直觉结论——prompt 里写"以下内容不可信"只是提高门槛不是防御；真防护在权限架构。
- 提升层：可复用 Skill（安全设计）。

### 独点3：XML 信任标签 + provenance 来源标记 + handoff 边界输出校验（工作流层）
- 判据：①不可信内容用 `<untrusted_content>` 等结构化标签包裹，system 指令明确说标签内只当数据；②每个检索 chunk/provenance tag 标来源 corpus/文档/上传者/信任等级；③多 agent handoff 时，上游 agent 的输出在传给下游前也要过注入校验（A 被污染会顺着 handoff 传给 B）。
- 独有增量：与 wb-context-compressor 已有"工具面安全"条目互补——那条管工具描述/同名工具/per-tool 权限；本条管**内容侧**的信任标签与 handoff 传染。
- 提升层：工作流。

## 判非重复理由
- r166A 直接注入防护；本条是间接注入（tool output/RAG/邮件）与架构级防御，增量 >40%。
