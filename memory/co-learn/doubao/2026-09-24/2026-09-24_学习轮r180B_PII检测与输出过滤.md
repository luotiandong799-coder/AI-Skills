# r180-B PII 检测与输出过滤：输入输出双闸、类型稳定占位符、间接标识符

## 实拉证据（关键原文）
- arXiv 2512.12914：「Input-only filtering is insufficient — need output level protection. Privacy redactor post-processes model outputs to remove sensitive content AND transform output to remain coherent and natural, without drawing attention to redaction.」
- arXiv 2604.12064：「Each span replaced with typed, stable placeholder (⟨EMAIL_1⟩). Two occurrences of same value map to same placeholder (coreference stability). Reverse map lives only in process memory — never persisted to disk.」
- playbooks.aip.gov.sg：「Avoid passing both direct identifiers (names, emails) and indirect identifiers (postal codes, DOB, gender, job titles) to LLMs — indirect identifiers alone don't point to a person, but combinations re-identify.」
- 腾讯云：Presidio = Analyzer（识别）+ Anonymizer（替换/遮蔽/哈希）。

## 独点清单（3 个真独点）

### 独点1：输入过滤不够，输出必须二次过滤（工作流层）
- 判据：训练时泄漏（CTIGuardian）证明 input-only filtering 挡不住——模型可能把训练记忆里的 PII 吐出来。输出侧加 privacy redactor：检测敏感 span 并重写为连贯自然文本，不能是生硬删掉留空洞。判据：输入闸管"别把别人的数据喂进去"，输出闸管"别把训练记忆里的数据吐出来"，两道都要。
- 独有增量（与 r172 注入/安全区别）：PII 泄漏源是训练记忆，不是提示词；输出过滤是新位置。
- 提升层：工作流。

### 独点2：类型稳定占位符 + 反向映射只在内存（工具层）
- 判据：PII 替换成 ⟨EMAIL_1⟩ 这种 typed stable placeholder——同一值出现两次映射同一占位符（共指稳定），下游还能当训练数据/检索用（比 [NAME] 生硬占位有用）。反向映射只存进程内存、绝不落盘。判据：placeholder 要可逆且稳定，但恢复表不能持久化。
- 独有增量：占位符设计细节（typed/stable/共指）+ 内存约束。
- 提升层：工具。

### 独点3：直接标识符和间接标识符都要管（工作流层）
- 判据：姓名/邮箱是直接标识符；邮编+出生日期+性别+职位是间接标识符——单个不指向人，组合能重识别。喂外部 LLM 前两者都该脱敏，不只"看起来敏感"的直接 PII。正则+NER（Presidio Analyzer）+ LLM 检测三层结合，单靠 regex 漏改写的。
- 独有增量：间接标识符组合重识别这个边界。
- 提升层：工作流。

## 判非重复理由
- r172/r178 讲注入与投毒（攻击进来）；本条讲 PII 脱敏（隐私出去），方向相反，增量 >40%。
