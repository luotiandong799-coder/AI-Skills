## 二、独点清单 + 判非重复理由（7 点，均≥40% 独有增量）

### 1. OpenTelemetry GenAI 语义约定与 Agent 标准操作（来源：OTel 2024-12 + cncfstack 2026-05-14 + MLflow 2026-05-22 实拉）
标准属性（gen_ai.system / gen_ai.request.model / gen_ai.usage.input_tokens/output_tokens）+ 标准操作（chat / embeddings / retrieval / execute_tool / invoke_agent）——跨厂商一致采集，span 树=invoke_agent 顶层 + chat/execute_tool 子 span。
- 判非重复：WB av（评测面）不涉遥测标准化；本点=可观测的语义基座。增量≥85%。
- 提升层：工作流（遥测标准化）。

### 2. 失败分层主因优先 + Fix Recipe 四要素（来源：AWS Strands Evals 2026-06-15 + FutureAGI 2026-05-14 实拉）
先修 PRIMARY 失败——次级/三级失败常随主因解决而消失；按 fix type 分组批量改（TOOL_DESCRIPTION_FIX 一起改、SYSTEM_PROMPT_FIX 一起改）减少迭代轮；每条修复=Fix Recipe 四要素（根因 / 长期结构性建议 / 立即修复的具体 prompt 或 schema 改动 / 验证脚本或 eval 模板）。
- 判非重复：WB ed"失败经验记忆按错误签名索引"管"记修复路径"；本点管"**多因并存时先修谁、怎么分组批量改**"（归因次序 vs 记忆索引）。增量≥55%。
- 提升层：工作流（调试纪律）。

### 3. 决策出处（decision provenance）记录：坏输入 vs 坏推理的判别（来源：Adaline 2026-05-27 + cordum 2026-04-01 实拉）
每个 span 记录影响决策的输入审计轨迹：检索了哪些文档、scope 内有哪些先前输出、收到哪些用户信号；decision tracing 用共享 trace_id 串起工具选择/策略规则/审批/执行结果——**没有决策出处，无法区分"错决策来自坏输入还是坏推理"**。
- 判非重复：WB cc 记忆面不涉决策审计；本点=归因正确性的前提。增量≥80%。
- 提升层：工作流（归因正确性）。

### 4. IETF AgentOps 事件模型：因果起源 vs 传播症状（来源：IETF draft-pei-opsawg-agentops-observability 2026-07-21 实拉）
AgentOps 观测事件模型与处理要求：公共 event/anomaly/assertion/diagnosis 四类记录；**区分因果起源（causal origins）与传播症状（propagated symptoms）**；提供证据模型支撑早期失败检测与事后归因。
- 判非重复：WB 无 AgentOps 事件建模面；点 2 管修复次序，本点管"**事件记录分类的协议级定义**"。增量≥85%。
- 提升层：工作流（事件建模）。

### 5. trace 消费三通道：人工调试 / 离线评测集 / 回归测试（来源：ITPUB 2026-09-02 + LangChain 2026-06-04 实拉）
trace 不只给人看：①人工调试（成功失败同任务并排 diff——retriever 输入输出/LLM prompt 与响应/工具参数结果/模型解码参数，多数时候一行红色即根因）；②经筛选/脱敏/清理/标注沉淀为离线评测集（用户报 bug 可从 trace 还原）；③生产 trace 转回归测试防复发；另含成本/延迟归因（定位某子任务占 80% token）。
- 判非重复：WB av"评测即回归"管"评测体系怎么搭"；本点管"**trace 作为评测集与回归测试的原料管道**"（数据来源面）。增量≥50%。
- 提升层：工作流（数据飞轮）。

### 6. 五类日志 + 三告警 + 三常漏清单（来源：Kaxo 2026-05-18 + RockB 2026-05-19 + Zylos 2026-04-29 实拉）
日志五类=agent decisions / token costs / tool calls / memory mutations / conversation threads；告警三信号=heartbeat 缺失（agent 静默）、成本速率异常（失控循环）、工具失败率（下游服务故障）；**最常漏三项=prompt-template 版本差异、模型版本跟踪、人工覆盖捕获**；可操作阈值：agent.iterations>8 / tool success rate<90% / token>模型限×0.9 / p99>30s / 5 分钟无 trace。
- 判非重复：WB ed 工具循环终止（stop_reason 检查）管"防无限循环"；本点管"**可观测告警面怎么配**"。增量≥60%。
- 提升层：工作流（告警体系）。

### 7. Claude Code OTel 观测 + cache diagnostics（来源：Claude Code 2026-09-22 + freeCodeCamp 2026-09-04 实拉）
Claude Code Agent SDK 原生 OTel：llm_request span、hook 执行包装；**子代理模型调用嵌套在其 Agent span 下——并行子代理的重叠执行时间可见（35s 组合 LLM 时间 16s 完成）**；cache diagnostics：传 diagnostics.previous_message_id 返回 cache_miss_reason，解释缓存前缀在哪发散（与 r157-A 点 1 联动）。
- 判非重复：点 1-6 管通用面；本点=具体工具的观测接口与缓存诊断（与 A 轮缓存面交叉增量）。增量≥70%。
- 提升层：工具/工作流（agent 观测接口）。
