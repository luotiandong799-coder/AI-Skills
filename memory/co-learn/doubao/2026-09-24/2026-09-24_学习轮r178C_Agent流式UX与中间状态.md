## 实拉证据（关键原文）
- CSDN：三层流式——token 流式（逐字）/步骤流式（在调哪个工具）/动作流式（工具参数边生成边拼、JSON 边生成边解析）。
- ai-tldr：「A skeleton with no status change during a 15-second tool call feels frozen — the status line is what differentiates a thinking system from a broken one.」
- masterprompting：「Non-streaming 15s looks broken, user clicks again, now two parallel runs. Streaming with status steps feels responsive at same 15s.」
- max-gherman：streaming 让用户在完整响应前就能打断纠正——early signal。

## 独点清单（3 个真独点）

### 独点1：三层流式——token/步骤/动作逐层透明（工作流层）
- 判据：不只是逐字输出。第一层 token 流式（逐字出现），第二层步骤流式（"搜索网页中→找到3个源→写答案中"），第三层动作流式（工具参数边生成边渲染、JSON 边生成边解析）。黑盒变玻璃盒。
- 独有增量（新角度，之前没做过 UX 层）。
- 提升层：工作流。

### 独点2：状态行区分"思考中"和"卡死"（工作流层）
- 判据：长工具调用期间不能只显示 spinner——要 inline 状态行更新（"读3个文档...""计算中..."）。15 秒无状态变化 = 用户以为系统坏了。非流式 15 秒用户会重复点按钮，产生两个并行 agent run。
- 独有增量：点出"空白等待=用户重复操作"这个具体反模式。
- 提升层：工作流。

### 独点3：流式给用户提前打断纠正的机会（工作流层）
- 判据：用户看到前几个 token 就知道 agent 理解对不对——错了可以在完整响应生成前打断纠正，不用等 15 秒看完再重来。这是流式 UX 不只是"显得快"的真正价值。
- 独有增量：流式的 UX 价值不只是感知速度，是提前纠错窗口。
- 提升层：工作流。
