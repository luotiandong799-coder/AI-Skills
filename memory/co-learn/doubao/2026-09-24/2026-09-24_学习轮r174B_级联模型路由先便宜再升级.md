# r174-B 级联模型路由：先便宜模型试再升级、升级门看输出不看输入、~35行不用训练

实拉时间：2026-09-24 20:20
信源：arXiv 2606.27457 ClusterRouteEscalate / 72technologies 2026-08 / jonathanding cascade self-verification / arXiv 2605.18796 UCCI / agentnative cascade pattern 2026-07 / RouteNLP conformal cascading / dreaming.press cost router 2026-07 / tianpan routeLLM / cometapi 2026-09 / vibeengines router design（级联组，满 10 站）

## 实拉证据（关键原文）
- 72technologies：「This is different from a router that picks one model up-front based on prompt classification. A router guesses which model…cascade lets the cheap model attempt it first, then verifies.」
- jonathanding：「~80% of real-world queries are simple enough for a small model; only the remaining difficult queries need expensive models.」
- UCCI：「at micro-F1=0.91, cost=2.08 vs 3.02 for large model alone, a 31% reduction.」升级门用 token-level margin uncertainty。
- dreaming.press：「A cascade router calls a cheap model first and only escalates on a failed verifier — it is ~35 lines and needs no trained classifier. Measure your own escalation rate before buying one.」
- tianpan 引 RouteLLM：「maintain 95% of frontier quality while routing 85% of queries to cheaper models, cost reductions 45-85%.」

## 独点清单（3 个真独点）

### 独点1：级联与前置路由的本质区别——决策基于输出不基于输入（工作流层）
- 判据：前置路由器看输入猜哪个模型合适（一次选定，猜错就把难题发给弱模型）；级联先让便宜模型答，**输出过质量门才返回，不达标才升级**。~80% 真实查询小模型能处理，只有难的那部分付大模型钱。
- 独有增量（与 r158B 模型路由区别）：那条讲路由策略；本条讲**级联这个具体模式**——先试再升级 vs 先猜路由，是两种不同架构。
- 提升层：工作流。

### 独点2：升级门用校准的不确定性信号，不是凭感觉（工具层）
- 判据：什么时候升级？先任务规则（明确需要推理的任务直接上大模型），再校准信号——token-level margin（模型对自己输出的不确定度）。用 500 个校准样本/任务/层级标定阈值（conformal）。UCCI 实测 0.91 F1 下成本降 31%。
- 独有增量：给了升级门的具体实现（token margin + 校准样本数），不是"看 confidence 字段"这种空话。
- 提升层：工具。

### 独点3：先量升级率再决定买不买路由产品（工作流层）
- 判据：自己写个 ~35 行级联（便宜模型→校验器→失败升级），量一下实际升级率。如果 85% 查询小模型就过，不需要训练路由分类器或买商业网关；只有升级率异常高/低才说明路由规则要调。
- 独有增量：反直觉——先不买 RouteLLM/Martian，先量自己的数据。
- 提升层：工作流。

## 判非重复理由
- r158B 模型路由讲选择策略；本条讲级联（先试后升）与校准升级门，增量 >40%。
- r170-B thinking 成本讲计费；本条讲运行时成本路由，互补。
