## 独点清单（3 个真独点）

### 独点1：shadow → canary → ramp 三阶段，各答不同问题（工作流层）
- 判据：shadow（生产响应用户、候选静默收镜像请求，输出离线比对）证明"在真实分布上不会行为怪异"；canary（候选对一小撮用户实时服务，同 rubric 评分+自动回滚）证明"有用户在循环里至少不差"；之后才 ramp。跳过 shadow 直接 canary = 把分布风险带进用户可见区。
- 独有增量（与 r176 生产监控 SLO/prompt 灰度区别）：那条管灰度与监控指标；本条管**上线前评估顺序与分工**。
- 提升层：工作流。

### 独点2：静态测试集测不出的东西只有 shadow 能暴露（工具层）
- 判据：fine-tune 模型在 test set 上达标、在真实流量上可能差异巨大——因为 test set 静态、production 非静态。shadow 用真实输入分布收集上千对请求/响应，零用户风险。这是 offline eval 和 shadow 的分工：offline 测能力上限，shadow 测分布现实。
- 独有增量：点出 shadow 解决的是"测试集静态 vs 生产动态"的鸿沟。
- 提升层：工具。

### 独点3：shadow 要对比什么——不只答案，还有延迟/成本/错误（工作流层）
- 判据：同时记录双模型 output + latency + token usage + cost + error + eval score。差异大的维度决定能不能放行。成本：shadow 是 100% 额外 compute 且无直接用户价值——设置时长窗口（如 1-2 周或 N 千请求）后必须决定进 canary 或放弃，不能无限 shadow。
- 独有增量：shadow 对比维度清单 + 成本窗口纪律。
- 提升层：工作流。
