## 独点（3 个）
### C1：记忆 ingestion 两阶段提交 + sync cursor + 消息去重 join（来源：docs.langflow.org/memory 表结构全文）
- **两阶段提交可恢复**：MemoryBasePreprocessingOutput 记录 LLM 蒸馏预处理输出（processed/ingested/skipped）——先 LLM call 蒸馏、落表，再写向量库；中断后从表续，不重跑 LLM。
- **sync cursor**：MemoryBaseSession 记每 session 的同步游标位置+已处理消息总数，增量追 ingestion 不重扫全量。
- **去重 join**：MessageIngestionRecord 记每条消息被哪个 memory base/哪个 job ingestion，保证每条消息只入一次。
- 判据：**记忆入库是事务不是动作**——LLM 蒸馏和向量写入拆成可断点的两阶段，游标追增量，连接表防重复；与 B2（事件化写记忆）互补：那条管"什么时候写"，本条管"写的管线怎么不丢不重可恢复"。
- **提升层**：记忆/工作流。

### C2：chat memory（时序/单会话）vs memory base（语义/跨会话）按查询模式分（来源：同上）
- chat history 存 messages 表只是聊天日志，不等于能给 LLM 提供上下文的 chat memory；chat memory 按 session_id 时序取最近 N 条。
- **memory base 才做跨会话语义检索**，且默认 `Filter by Session=true` 只查当前会话，**显式关掉才跨会话搜**。
- 判据：**"最近说过什么"用时序 chat memory，"很久以前那个结论是什么"用语义 memory base**；跨会话是显式开关不是默认——默认跨会话检索会把别人/别会话的上下文混进来。与 r184-C（按仓库共享记忆库）分工：那条管记忆库按 repo 隔离，本条管同库内按时序 vs 语义、单会话 vs 跨会话两种查询模式。
- **提升层**：记忆。

### C3：存 flow/文档前自动脱敏凭证（字段名启发式置 null）（来源：同上 LANGFLOW_REMOVE_API_KEYS）
- `LANGFLOW_REMOVE_API_KEYS=True`：保存 flow 到库前，凡 password 字段名里含 `api`/`key`/`token` 的一律置 null，防凭证随 flow JSON 落库。
- 判据：**凭证清扫按字段名启发式做在落库边界**，不依赖写作者记得删；与 per-tool 最小权限、guardian 三问分工——那两条管"调用时给多少权"，本条管"产物落盘时别把秘密一起存进去"。
- **提升层**：安全/工具。
