## 独点清单（3 个真独点）

### 独点1：预算用尽降级到便宜模型，不拒绝请求（工具层）
- 判据：spend 要超预算时不硬拒（402），而是 trip breaker 路由到 fallback 便宜模型——请求继续服务，agent 任务不中断。硬预算只在 fallback 也超不了时才拒绝。与 r173-A 熔断互补：那条管错误率，这条管钱。
- 独有增量（与 r170-B 成本工程区别）：那条讲省钱方法；本条讲**运行时怎么强制预算**——降级而非拒绝。
- 提升层：工具。

### 独点2：四层护栏 + 三层配置（工作流层）
- 判据：不只在 HTTP 边缘限流。四层：token 节流（抓 context window 爆炸）、请求节流（抓重试循环）、circuit breaker（抓重复相同调用）、美元硬停。在 agent/service/infra 三层各配——单层失败不至于烧穿。
- 独有增量：把"限流"拆成四种不同失控模式，各有对应机制。
- 提升层：工作流。

### 独点3：output token 不可预知，预算是 bound；双边界监控（工具层）
- 判据：input token 可精确算，output 要 max_tokens 封顶才能估。硬预算是"拒绝越过的边界"。双边界：per-turn delta 抓突刺（一次大扫描），cumulative escrow 守 session 绝对上限。预算用尽时 session idle 不崩溃（状态保留可恢复）。
- 独有增量：output 不可预知这个特性决定预算怎么算；双边界监控。
- 提升层：工具。
