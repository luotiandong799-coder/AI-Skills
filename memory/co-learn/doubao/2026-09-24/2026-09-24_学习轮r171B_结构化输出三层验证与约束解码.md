# r171-B 结构化输出与生成校验：三层验证、约束解码 vs 后验、错误回喂自纠

## 实拉证据（关键原文）
- next-gen.cloud：「separate validation into three layers: Syntax validation（JSON 可解析）/ Schema validation（必填键、类型、枚举）/ Business validation（领域语义：退款金额不应为负、cron 匹配产品限制）。Business validation is the layer teams skip most often.」
- dev.to aifrontierpost（2026-09-23）：「constrained decoding enforces structure during token generation. At every step, the sampler masks out tokens that would violate your schema… no retries, no post-processing.」库：Outlines / Guidance / XGrammar。
- channel.tel（2026-05-19）：「Prompt plus validation plus retry is what you use with models that don't support constrained decoding (including Claude)… constrained decoding is available for OpenAI GPT-5 family and Gemini 2.5, provider docs report near-zero schema mismatch。」
- futureagi（2026-05-20）：约束解码失败形态——optional 字段在 required-by-default 下静默丢弃；递归类型/动态属性名 schema 解码器无法表示会被拒；硬 prompt 下模型首选 token 被掩码→答案塌缩到更安全的枚举默认值。
- dev.to aifrontierpost + instructor/outputguard：「ValidationError 追加进对话历史重发，模型按错误自纠；实际 1-2 次重试内解决大部分验证失败，有效失败率低于 1%。」outputguard：retry_prompt 告诉模型缺哪些字段、错哪些类型。
- arXiv 2603.27905 ATLAS-RTC：「enforce structural output contracts but does not guarantee semantic correctness. Outputs may satisfy the schema while remaining incomplete, inconsistent, or uninformative (e.g., empty or default values).」

## 独点清单（3 个真独点）

### 独点1：输出验证分三层，business 层最常被跳（可复用 Skill 层）
- 判据：Syntax（JSON 能解析）→ Schema（必填键/类型/枚举）→ Business（领域语义：退款金额不为负、cron 匹配产品上限）。三层都要，**business 层是团队最常跳的**——schema 通过但语义错（负金额、超限计划）照样进下游。
- 独有增量（与 wb-execute-discipline「工具结果断言层」区别）：那条管**工具返回值**可疑打标；本条管 **LLM 生成文本的结构化校验分层**——把 business 规则提升为与 syntax/schema 并列的独立层，跳层是最常见故障。
- 提升层：可复用 Skill（输出校验分层）。

### 独点2：约束解码 vs 后验验证是两种哲学，按供应商选；约束解码有隐蔽失败（工作流层）
- 判据：约束解码（解码器级 grammar 掩码，结构合法 by construction，无重试）用于 OpenAI GPT-5 系/Gemini 2.5/NVIDIA NIM；Claude 等不支持→ prompt+validate+retry。**约束解码不万能**：optional 字段被 required-by-default 静默丢弃、递归/动态 key schema 解码器拒、硬 prompt 下模型首选 token 被掩→答案塌缩到安全枚举默认值——"结构必然合法"换来的是**静默语义塌缩**，比非法 JSON 更隐蔽。
- 独有增量：r168 系列没覆盖输出层机制选择；本条给"选哪种结构化方案"的判据 + 约束解码的隐蔽失败清单。
- 提升层：工作流。

### 独点3：验证失败回喂错误让模型自纠，1-2 次收敛；结构合法≠语义正确（工具/工作流层）
- 判据：ValidationError 连同字段级错误信息**追加进对话历史重发**（不是重新随机试）——模型按"缺了哪些字段/哪个类型错"自纠，1-2 次内解决大部分，有效失败率 <1%。同时记住：结构校验只保证形状合法，不保证语义正确（空值/默认值/无信息也能通过 schema）。
- 独有增量：错误回喂重试的具体形态（错误进上下文而非只报错）；结构-语义边界提醒。
- 提升层：工具/工作流。
