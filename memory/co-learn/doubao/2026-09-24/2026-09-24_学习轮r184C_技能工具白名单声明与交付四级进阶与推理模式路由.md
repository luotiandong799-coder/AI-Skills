## 独点（4 个）
### P1：技能预批准工具白名单声明 allowed-tools + 校验工具（来源：agentskills.io/specification；与 r175C"权限时效"增量合并）
- frontmatter 增加 `allowed-tools` 字段（Experimental）：技能**自声明**可预运行的工具有白名单，语法如 `allowed-tools: Bash(git:*) Bash(jq:*) Read`。
- 配套 `skills-ref validate ./my-skill` 校验：frontmatter 合法性与命名规范可机器验证。
- name 约束：1-64 字符、仅小写字母数字连字符、不得连续/首尾连字符、**必须匹配父目录名**——名字与目录强绑定可校验。
- 与 r175C 分工：r175C 管"allowed-tools 权限下条消息清除、常驻的是内容不是权限"（时效语义）；本条管"技能声明自己需要哪些工具 + 校验通道"（声明机制）。
- 判据：**技能把"我能用什么工具"写进声明而非靠模型猜**；声明配校验工具，命名违反规范可在装前机器拦截。
- 提升层：可复用 Skill（技能规范与自声明权限）。

### P2：交付能力四级进阶——Coding→Agent→Cowork→Autonomous（来源：智谱 2026 中期业绩会，caifuhao.eastmoney.com 转述）
- 四级交付逐级定义：**Coding**=交付可运行代码（已验证）→ **Agent**=交付执行完成的多步任务链（当前重心）→ **Cowork**=交付可由专业人士复核的工作成果（打开中）→ **Autonomous AI**=交付持续运行的能力（远期）。
- 每级跨越有具体技术门槛：Coding→Agent 需**长程规划与错误恢复**；Agent→Cowork 需**可靠性达专业人士复核标准**；Cowork→Autonomous 需持续运行可信。
- 判据：**衡量系统成熟度看"交付物级别"而不看"模型多强"**——先定义当前交付到哪一级，缺哪个门槛（长程规划/错误恢复/可靠性复核）就补哪个。
- 提升层：工作流（成熟度评估与路线规划）。

### P3：推理模式路由（reasoning-mode router）而非模型路由（来源：deepseek-plugin.org dsh-routing-suite，★6,979）
- dsh-routing-suite = **injector（运行时注入器）+ router-standard（任务感知推理模式路由预设）**，按任务感知选择推理模式（measured P1-P23 度量到 23 档）。
- 与既有"模型路由/级联路由"分工：模型路由选**哪个模型**；推理模式路由选**同一模型用哪种推理姿态**（深浅档位），先装注入器再装路由预设。
- 判据：**路由的第二维度是"推理模式"不是只有模型**——P1-P23 说明档位可被度量、可被任务类型驱动切换。
- 提升层：工具（路由维度扩展）。

### P4：按仓库共享记忆库（repository-scoped shared memory bank）（来源：deepseek-plugin.org hindsight，★20,431）
- hindsight：为编码 agent 加长期项目记忆——每会话自动召回知识页与上下文、会话自动保存、**每仓库共享记忆库**（记忆按仓库维度组织，而非仅按用户/会话）。
- 与既有记忆体系分工：r181B 管记忆提取/遗忘机制、r183B 管四层记忆分层；本条管**记忆的作用域边界（按仓库共享）**——同仓库多会话共享知识库，跨仓库隔离。
- 判据：**记忆要有作用域（scope）**——按仓库组织的记忆让"这个项目的上下文"在该项目的所有会话间复用，又不泄漏到别的仓库。
- 提升层：工具（记忆作用域）。
