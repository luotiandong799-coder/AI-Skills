# r178-A RAG 投毒：供应链攻击、混合检索提成本、分库隔离

实拉时间：2026-09-24 20:40
信源：arXiv CtrlRAG 2503.06950 / arXiv KB poisoning policy 2607.04379 / arXiv SilentRetrieval 2605.28074 / CodeSecAI 7 defenses 2026-05 / DEV roxdavi supply chain 2026-09 / DEV tamizuddin securing RAG 2026-09 / beyondscale attack 2026-03 / Repello vector security 2026-05 / beyondscale memory poisoning 2026-04 / thehackerstuff pipeline 2026-05（RAG 安全组，满 10 站）

## 实拉证据（关键原文）
- DEV：「RAG poisoning is a supply chain attack, not a prompt injection variant — adversarial content was indexed before any query existed. Defense must be built at ingestion, not at query time.」
- Repello：「Pure dense retrieval most vulnerable — one adversarial embedding dominates top-k. Mix BM25+dense raises cost: attacker must land in same lexical AND semantic neighborhood. One channel optimized wins, two doesn't.」
- CtrlRAG：5 篇恶意文档注入百万文档 MS MARCO 即可劫持目标问题。
- CodeSecAI：可信/不可信知识库分库，低可信集合检索要用户确认。

## 独点清单（3 个真独点）

### 独点1：RAG 投毒是供应链攻击，防御建在摄入时不是查询时（工作流层）
- 判据：恶意文档在查询存在前就被索引了。和 r172-C 间接注入不同——那是查询时 tool output 带毒，这是** ingestion 时知识库本身被污染**。防御要建在摄入管道：文档来源审、内容 sanitization、来源可信度分级。在查询时加"忽略不可信内容"的 prompt 救不了——文档已经在向量库里了。
- 独有增量（与 r172-C 间接注入区别）：那是运行时 tool output；这是离线知识库投毒，防御位置完全不同。
- 提升层：工作流。

### 独点2：混合检索 dense+BM25 提高投毒成本（工具层）
- 判据：纯 dense 向量检索最脆——一个对抗 embedding 优化就能霸 top-k。混合词法+语义后，攻击者要同时命中两个邻域，优化空间被大幅压缩。静态审计 embedding 向量抓不到攻击。
- 独有增量：把"为什么要混合检索"从召回质量提升，延伸到抗投毒——一举两得。
- 提升层：工具。

### 独点3：可信/不可信知识库分库 + memory 投毒持久化（工作流层）
- 判据：内部高可信文档和外部/UGC 不混一个索引，分集合管理。低可信集合检索前要用户确认。Agent memory 投毒是 poison once exploit forever——恶意内容写进持久化记忆后跨所有后续会话 corrupt 行为，比单次注入严重得多。
- 独有增量：分库策略 + memory 投毒这个新攻击面。
- 提升层：工作流。

## 判非重复理由
- r172-C 讲运行时间接注入；本条讲知识库/记忆投毒，防御位置和机制完全不同，增量 >40%。
