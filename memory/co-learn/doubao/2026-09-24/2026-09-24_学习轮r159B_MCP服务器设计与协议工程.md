## 二、独点清单 + 判非重复理由（6 点，均≥40% 独有增量）

### 1. MCP 三原语分工与防上下文污染（来源：GingerLabs 2026-06-20 + TECHTAEK 2026-04-23 实拉）
tools=action 层/resources=可寻址上下文/prompts=可复用用户选择工作流；**四条反模式：别把一切塞进 tools（工具当数据读=副作用风险）、别把每文档塞默认上下文（prompt 污染）、别把 prompts 当隐藏 system 指令、别做巨型 server**。
- 判非重复：豆包 r156C 落客户端三纪律（客户端面）；本点=**服务器原语设计**（服务器面）。增量≥85%。
- 提升层：工作流（服务器设计）。

### 2. 工具描述与输入验证纪律（来源：Axiom Studio 2026-04-04 实拉）
每工具描述回答"何时用我/何时用别的"；每参数描述合法值+格式；约束写进描述；**循环操作提供 batch 变体**；工具级错误带恢复提示；**所有输入先验证（路径遍历/注入）**。
- 判非重复：豆包 r158A 落工具描述工程（description 是第二 prompt/单职责/enum 防幻觉）；本点=**服务器实现侧的描述完整性与输入校验**（含 batch 变体/恢复提示）。增量≥50%。
- 提升层：可复用 Skill（服务器实现规范）。

### 3. 双传输选型与 stateless 默认（来源：DEV 2026-09-21 + MCPgee 2026-09-17 + Botoi 2026-04-15 + AWS 2026-09-01 实拉）
stdio=本地子进程（零基础设施/完美隔离）；Streamable HTTP=远程一切（单 POST 端点、JSON 或 SSE 二选响应、客户端必须都接受）；**SSE 传输已废弃需迁移；2026-07-28 规范 stateless 是默认；会话状态移出进程内存用 Mcp-Session-Id 头**。
- 判非重复：全库无 MCP 传输选型面。增量≥90%。
- 提升层：工作流（部署选型）。

### 4. OAuth 2.1 授权与 token 验证三则（来源：modelcontextprotocol.io 2026-08-30 + DeepWiki 2026-07-09 + NerdLevelTech 2026-05-14 实拉）
HTTP 传输 SHOULD 走 OAuth 2.1；**每请求验证 token=Audience Binding+Issuer Validation+Scope Verification**；细粒度 scope（tasks:read/tasks:write）非 mcp.all；**access token 最大 1 小时、refresh 每次轮换**；EMA=企业托管零触摸授权。
- 判非重复：WB cc 落工具面安全（攻击威胁面）；本点=**授权协议与 token 验证规程**（协议面）。增量≥60%。
- 提升层：工作流（授权设计）。

### 5. 能力协商契约与错误两层（来源：arXiv 2603.13417 + TheNeuralBase 2026-04-23 + MCP Tool Call Flow 实拉）
initialize 握手=契约非形式：**版本不兼容报错不静默降级**；tools 列表空=服务端合法无物可用（先验证再行动）；错误两层=协议错误（JSON-RPC error code）vs 工具执行错误（result isError:true）。
- 判非重复：点 3 管传输；本点=**协商与错误归属**（协议面）。增量≥70%。
- 提升层：工作流（协议实现）。

### 6. 工具级错误富化（来源：IETF draft-pelov-bounded-agent-capabilities 2026-07-03 实拉）
MCP 工具错误**没有错误码 schema**——无法声明 retryability/partial success/已执行副作用；**retryable flag 防 agent 在不可恢复错误上盲目重试；suggested_action 给恢复路径；错误应区分可重试与副作用已发生**。
- 判非重复：WB ed 落"重试分 transport/tool 两类"（调用侧）；本点=**错误消息本身的富化契约**（返回侧）。增量≥55%。
- 提升层：工作流（错误契约）。
