## 实拉证据（关键原文）
- Microsoft AgentRx：「Plan Adherence Failure — Ignored required steps / did extra unplanned actions」 vs 「Invention of New Information — Altered facts not grounded in trace/tool output」——这两类常被混为一谈但修法不同。
- channel.tel：「Production agents fail in four distinct ways: execution errors (tools fail), output errors (tools succeed but return bad data), reasoning failures (logic loops), and termination failures (stops before done). Each needs different detection and recovery. Treating all four the same way is why most retry logic falls short.」
- richardewing：「Semantic Failures Behind HTTP 200 — The agent calls an API. The API returns HTTP 200…」+「token budgets per task with hard ceilings, not soft limits…alert on any task exceeding 3x its historical median.」
- luizneto 引 Foundra 2026 telemetry：「~37% performance drop from benchmark to deployment, driven by seams rather than raw model capability」；失败聚集在 handoff 边界、pilot 没见过的脏输入、监控盲区。
- growthengineer 引 Arize：「88% of agent failures trace to infrastructure gaps, not model quality.」
- wowhow：「Most AI coding agent failures don't come from wrong answers — they come from the agent confidently completing the wrong task.」

## 独点清单（3 个真独点）

### 独点1：先分 Plan Adherence vs Invention，再谈修法（可复用 Skill 层）
- 判据：诊断失败时先问——agent 是**没按自己定的计划走**（漏步/多做计划外动作），还是**编造了 trace/工具输出里没有的事实**？前者修 plan 纪律/强制按计划执行，后者修 groundedness/引用校验。混为一谈会开错药。
- 独有增量：r168A 步骤纪律管"怎么写步骤"，本条管**失败归因的第一刀怎么切**——把"agent 出错"这个黑箱先劈成 plan 偏离 vs 幻觉两类，各自的 instrumentation point 和修法不同。
- 提升层：可复用 Skill（失败诊断）。

### 独点2：四类失败分治，不能一套 retry 打天下（工作流层）
- 判据：execution error（工具 429/超时，有明确信号，传统重试适用）/ output error（工具成功返回垃圾数据，最阴——HTTP 200 也可能坏）/ reasoning error（逻辑循环/重复调用）/ termination error（提前停没完成）。output error 是 APM 盲区（200 不代表成功），要在工具结果上加业务断言；reasoning error 要循环检测；termination error 要完成度检查。
- 独有增量：与 r166B transport/tool 重试分类互补——那条按错误来源分，本条按**失败在管线哪一段**分，且点出 output error（200 坏数据）是最容易漏的一类。
- 提升层：工作流。

### 独点3：88% 失败是接缝/基础设施不是模型；benchmark→prod 掉 37%（工作流层）
- 判据：agent 在 demo 里好、生产里坏，主要不是模型不够强，是工具/系统交接缝、pilot 没见过的真实脏输入、监控盲区这三处接缝。**别把生产失败默认归因到"模型不行"而急着换模型**——先查这三处。同时 token 预算硬上限（超了确定性失败不重试，中位数 3 倍告警）是防成本爆炸的标配。
- 独有增量：给了一个反直觉的归因优先级——先查接缝再查模型；有 Foundra/Arize 数字锚点。
- 提升层：工作流。
