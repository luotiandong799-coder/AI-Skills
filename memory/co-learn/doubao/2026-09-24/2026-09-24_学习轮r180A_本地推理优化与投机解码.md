# r180-A 本地 LLM 推理优化：speculative decoding、量化、边界损益

实拉时间：2026-09-24 20:50
信源：vLLM GLM-5.2 B300 2026-07 / vLLM docs speculative 2026-08 / vLLM blog / vucense latency 2026-09 / DigitalOcean spec framework 2026-07 / tensoria optimisation 2026-06 / mr.technology draft 2026-07 / localaimaster complete guide 2026-05 / NVIDIA forums Qwen3 study 2026-08 / NVIDIA Jetson edge 2026-09（推理优化组，满 10 站）

## 实拉证据（关键原文）
- localaimaster：「Speculative decoding = highest-ROI inference optimization for single-stream serving — 2-4x speedup with mathematically identical output. Small draft proposes K tokens, large target verifies all K in one pass, accepted tokens are free.」
- mr.technology：「Speculation loses at high concurrency — draft-verification work exceeds savings. 18.4→32.1 tok/s/user at concurrency 4, statistically identical at 16, auto-disable kicks in.」
- vLLM：「Mixed batches eliminated → TPOT 40ms→22ms. Largest loss may not live in any kernel but at subsystem boundaries (P/D disaggregation + speculative decoding interaction).」
- NVIDIA forums：「BF16→FP8 raises throughput 4.5→7.9 tok/s; NVFP4 only 9.7. Speculative decoding changes practical result much more — MTP takes configs that fail at every concurrency to configs that meet threshold.」

## 独点清单（3 个真独点）

### 独点1：speculative decoding 只在低并发/单流场景赚（工具层）
- 判据：draft 提 K 个 token，target 一次前向验证 K 个，接受的 token 白拿——单流 2-4x 提速且输出数学等价。但高并发时 draft 验证开销超过节省，收益归零（实测 concurrency 16 时与不开启统计无差异，框架自动禁用）。选型判据：结构化/低温/低并发任务用；高吞吐批量任务关掉。
- 独有增量（与 r173-B 断点续跑等工程项区别）：给出 spec decode 的适用边界，不是"开了就快"。
- 提升层：工具。

### 独点2：量化收益有天花板，spec decode 常比降精度更能改变结果（工具层）
- 判据：NVIDIA 实测 BF16→FP8 吞吐 4.5→7.9 tok/s，NVFP4 才 9.7——精度下降收益递减；而 MTP spec decode 把"所有并发都失败的配置"变成"达标的配置"。本地推理瓶颈是内存带宽不是算力：量化让模型从慢系统 RAM 进高速 VRAM 是第一步，spec decode 是第二步。
- 独有增量：量化 vs spec decode 的相对收益排序。
- 提升层：工具。

### 独点3：子系统边界的性能损失比单个 kernel 更大（工作流层）
- 判据：vLLM 实测混合批次消除后 TPOT 40→22ms——最大损失不在任何单个 kernel，而在子系统边界（P/D 分离 + spec decode 组合时请求状态/调度形状/CUDA Graph 执行模式的不一致）。优化本地推理别只盯 kernel/量化，先查子系统衔接处的一致性。
- 独有增量：把"性能损失在边界不在内核"这条系统工程经验落到 LLM serving。
- 提升层：工作流。
