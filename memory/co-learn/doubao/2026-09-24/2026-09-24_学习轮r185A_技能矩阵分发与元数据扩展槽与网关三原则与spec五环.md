## 独点（4 个）
### P1：技能矩阵分发 + setup 元技能一键装全套（来源：skills.sh 排行榜实拉）
- mattpocock/skills 以一组互补技能而非单技能分发：grill-me 542K / grill-with-docs 456.5K / improve-codebase-architecture 448.2K / tdd 429.9K / triage 358.9K / to-prd 356.8K / handoff 348.9K，并配 **setup-matt-pocock-skills（385.3K）作为元技能一键装全套**。
- larksuite/cli 官方包同样形态：lark-approval/okr/markdown/doc/shared/event 8+ 技能共 8.8M 总量。
- 判据：**技能不是孤岛，是按作者/平台组织的互补矩阵**——入口用 setup 元技能批量装，单技能各司其职；个人要扩能力时先看"这个作者的整包"而不是只装命中那一个。
- 提升层：可复用 Skill（分发与组织）。

### P2：metadata 扩展槽 key 唯一防冲突 + 文件引用一层深 + scripts 三要求（来源：agentskills.io/specification 全文）
- frontmatter 新增 **metadata 任意键值扩展槽**（存未被 spec 定义的属性），但要求 **key 名足够唯一避免意外冲突**——扩展槽不是垃圾抽屉。
- **文件引用保持一层深**：references/scripts/assets 从 SKILL.md 引用不要嵌套链式（A 引用 B、B 再引用 C），渐进披露三层之外不加深引用网。
- **scripts/ 三要求**：自包含或文档化依赖、带有用错误信息、优雅处理边界。
- 与 r184-C（allowed-tools）分工：那条管"声明能用哪些工具"；本条管"元数据怎么扩展不打架 + 引用图别太深 + 脚本怎么写"。
- 提升层：可复用 Skill（规范细节）。

### P3：trusted gateway / untrusted execution / deterministic policy 三原则 + 默认无遥测治理（来源：docs.openclaw.ai 首页与 Why OpenClaw）
- 架构三原则：**可信网关**（单进程持有会话/路由/凭证真源）+ **不可信执行**（agent 动作在受控沙箱跑）+ **确定性策略**（权限/白名单由配置文件决定而非模型临场）。
- 治理形态：OpenClaw Foundation 为 501(c)(3)、MIT、**无付费层、默认无遥测**（version check 可关）。
- 判据：**把"凭证与会话真源"集中在一个可信网关，把"动作执行"隔离成不可信域，权限写成确定性配置**——与 guardian 三问、per-tool 最小权限互补，这是部署拓扑层的分工。
- 提升层：工具/架构。

### P4：spec-driven 五环闭环 Interview→Seed→Execute→Evaluate→Evolution（来源：deepseek-plugin.org ouroboros ★5,588，uvx 零安装以 MCP 工具提供）
- 五环流程：**访谈需求（Interview）→ 种子规约（Seed）→ 执行（Execute）→ 评估（Evaluate）→ 进化（Evolution）**，作为 MCP 工具零安装接入。
- 与 r174A（spec-driven development）/r162（评估驱动）分工：那两条管"先规约后开发"和"评测怎么打分"；本条补全首尾两环——**开头有访谈把需求谈透再下规约，结尾有进化环把评估反馈回写规约/技能**，形成持续进化闭环而非一次性 spec。
- 提升层：工作流（闭环形态）。
