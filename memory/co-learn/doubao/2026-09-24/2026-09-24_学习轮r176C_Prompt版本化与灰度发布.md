## 独点清单（3 个真独点）

### 独点1：生产钉 dated snapshot 不钉 family alias（工作流层）
- 判据：`support_agent@prod` 这个 alias 指向具体 version id，不指向"最新版"。alias 自己会动=一次你没批准、也回滚不了的部署。rollback 时间是要优化的指标——prompt 从容器镜像里拿出来放进 registry alias，回滚从 14 分钟降到 8 秒。注意 alias 缓存默认 60 秒，rollback 后 fleet 最多不一致 60 秒。
- 独有增量（与 r168B 上线评估区别）：那条讲怎么评；本条讲**发布机制本身**——钉版本 vs alias、rollback 时间优化。
- 提升层：工作流。

### 独点2：drain traffic 不硬切（工作流层）
- 判据：退役版本流量在 10-60 分钟窗口渐降到 0，不硬停——硬停会让在途请求失败（一个 prompt 调用跑到一半版本没了）。回滚同理：新版本 drain，旧版本接回流量。发布流水线 validate→test→canary→rollout→full→monitor 六步每步有质量门。
- 独有增量：点出"硬切"对长 agent session 的破坏。
- 提升层：工作流。

### 独点3：A/B 判显著要样本量 + session 哈希 + 自动回滚阈值（工作流层）
- 判据：A/B 用 session ID 确定性哈希分流（同一会话始终看到同一变体）；每变体 200-500 个响应才判显著，否则别宣布赢家。自动回滚阈值具体：错误率>5% 或 P99 翻倍或满意度降 10%。先定主指标再跑实验，跑完看 per-case diff 不只聚合。
- 独有增量：给了样本量数字和回滚阈值，不是"做 A/B"这种空话。
- 提升层：工作流。
