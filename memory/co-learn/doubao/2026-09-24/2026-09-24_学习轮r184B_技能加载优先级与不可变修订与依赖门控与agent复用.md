## 独点（5 个）
### P1：技能加载优先级 8 级 + 同名最高源覆盖 + 分组发现（来源：docs.openclaw.ai/skills）
- 同名技能多源并存时按优先级表取最高：Workspace > Project .agents > Personal ~/.agents > Managed > Workshop > Bundled > Custodian > Extra dirs。
- 分组布局：SKILL.md 出现在 root 下任意 ≤6 层深处即被发现；发现到 SKILL.md 即停止向下遍历；name 取 frontmatter 的 name 字段（缺省用目录名）。
- 判据：**同名冲突时"谁赢了"必须有可解释的优先级表**，而不是靠扫描顺序碰运气；文件夹路径只是组织，名字与身份来自 frontmatter。
- 提升层：可复用 Skill（加载与冲突解析）。

### P2：技能修订不可变指纹 + 陈旧编辑冲突拒绝 + 会话级钉扎（来源：docs.openclaw.ai/skills；与既有"引用完整性/升级生效"增量合并）
- 保存发布完整不可变 revision，哈希含**可移植路径+内容+大小+可执行位**；只改 helper 脚本也变更 revision；ZIP 时间戳/归档顺序/共享权属不影响哈希；相同保存是 no-op。
- **stale edit 以冲突失败而不是覆盖新版本**；会话保留所选技能 ID+revision，换人接管不替换选择；rollback 回滚保留的 revision；禁用技能只影响新会话默认，不影响已选会话。
- 判据：**修订指纹要确定性可复现**（不含会被打包工具漂移的元数据）；**旧编辑撞上新版本必须显式冲突**，静默覆盖会把已审核内容换掉。
- 提升层：可复用 Skill（版本管理与协作安全）。

### P3：技能依赖门控 requires+installer specs + env 注入作用域 + 每会话技能上限（来源：docs.openclaw.ai/skills）
- 加载时按 `metadata.openclaw` 过滤：requires.bins / requires.anyBins / requires.env / requires.config / os 平台过滤；`always: true` 只绕过 bins/env/config 不绕过 os。
- 安装器规格：brew / node / go / uv / download，Gateway 偏好 Homebrew→uv→node manager→go→download；依赖缺失可一键装。
- env/apiKey 注入仅作用于 **host 运行**，sandbox 内无效（沙箱秘密走 skills config 单独传）；技能编译成 XML 块注入 system prompt，运行后恢复环境。
- 新会话最多选 64 个启用技能；managed bundle 限 256 文件 / 1MiB 每文件 / 8MiB 总。
- 判据：**技能声明依赖并带安装路径，缺失就不可见**（不报错硬跑）；**注入环境有作用域边界**（host 有、sandbox 无），秘密不能假设处处生效；技能数量与包体要有上限防膨胀。
- 提升层：工具 / 可复用 Skill（门控与分发约束）。

### P4：Agent 空闲复用模型——actor-worker 多路复用（来源：GitHub agent-substrate/substrate，Google GKE 团队开源，gstars.dev/refft/Google Cloud Blog 核验）
- 核心假设：**agent 大部分时间空闲**。把大量有状态 actor 复用到少量 ready worker（K8s Pod），~250 个会话/8 Pod（30x+ 超订），sub-second 激活延迟，完整状态跨休眠周期持久化。
- 分离 workload 生命周期与计算分配；把 K8s 控制面移出关键路径降延迟；zero-trust 内核（gVisor）与网络隔离 + 短时 X.509 证书。
- 判据：**"agent 闲时休眠、唤醒即续"替代"每次冷启动"**——对个人多 agent 场景可迁移为"共享运行时池 + 状态持久化 + 快速恢复"，成本随活跃度而非并发数走。
- 提升层：工作流 / 工具（运行时复用与成本）。

### P5：技能消费者侧安装四查（来源：skillsmp.com；与既有工具面安全增量合并）
- 市场不认证安全/质量，官方声明：inspect the source / review scripts and permissions / check recent activity / only install what you understand；装前先读 SKILL.md 与所有脚本。
- 增量（既有工具安全已含"审 description/核对来源/最小权限"）：**查最近活跃度（recent activity）** + **只装看得懂的（understand）** 补入安装前检查。
- 判据：**技能市场是渠道不是认证机构**——消费者侧检查清单要显式写：读源+审脚本权限+看活跃度+能理解才装。
- 提升层：工作流（安全安装实践）。
