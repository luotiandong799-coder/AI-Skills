## 实拉证据（关键原文）
- aipromptshub：「RRF computes fused score of sum(1/(k+rank_i)) for each document across retrieval systems, k=60 standard smoothing constant; 10 lines of Python; retrieval-system-agnostic.」
- aiworkflowlab：「Parallel candidate generation top 50-100 each → RRF fusion → cross-encoder scores top 50 fused candidates jointly, returns refined top 10.」

## 独点清单（3 个真独点）

### 独点1：RRF 融合公式——排名位置融合免分数归一化（可复用 Skill 层）
- 判据：BM25 和向量库分数量纲不同不能直接相加，RRF 用 sum(1/(k+rank_i)) 只看排名位置，k=60 标准平滑常数，10 行 Python 且检索系统无关（换任意检索器都适用）。判据：需要融合不同检索器结果时先上 RRF，别自己写分数归一化。
- 独有增量（与已有 RAG 覆盖互补）：RRF 具体公式与 k 值。
- 提升层：可复用 Skill。

### 独点2：三段式检索架构——并行候选生成→RRF 融合→cross-encoder 只 rerank shortlist（工作流层）
- 判据：BM25 top50-100 + dense top50-100 并行 → RRF 融合去重成候选集 → cross-encoder 只对 top50 联合打分出 top10。cross-encoder 看 query+doc 联合（比 bi-encoder 准但慢），所以永远只在 shortlist 上跑，不能全库跑。代价：p99 +30-50ms 换 recall +15-35%。判据：reranker 是精度层，只吃融合后的候选集。
- 独有增量：三段式明确分工 + 延迟/收益量化。
- 提升层：工作流。

### 独点3：dense-only 静默失败模式 + 单模型双向量实现（工具层）
- 判据：dense-only 在精确术语、代码、稀有 token 上**静默失败**（embedding 抓不到字面匹配）；BM25 补字面召回，向量补改写/释义，reranker 修双方 false positive——两者各有失败模式，单一信号会让另一类查询静默掉。实现选型：BGE-M3 单模型同时出 dense+sparse；Qdrant 单点双向量空间（dense+sparse 同 point）；reranker 可 ONNX FastEmbed 无 GPU 跑。判据：混合是防"静默失败"不是锦上添花。
- 独有增量：静默失败模式 + 具体实现选型。
- 提升层：工具。
