## 实拉证据（关键原文）
- LangChain deep agents：「When Command(resume=...) arrives—minutes, hours, or days later—the resume value becomes the return value of the interrupt() call, and execution picks up exactly where it stopped. resume accepts any JSON-serializable value, not just approve/reject.」
- agentnative：「code in the interrupted node that ran before the interrupt call executes again on resume—place side effects after the interrupt or make them idempotent.」
- callsphere：「every checkpoint is a time-travel anchor you can fork into a new branch, replay into an eval dataset, or rewind to debug.」AWS：small checkpoints (<350KB) in DynamoDB, large payloads to S3.
- ranjankumar：「checkpoint loop is a tight inner cycle—resume, execute, check idempotency, checkpoint, repeat. Process failure at any point loses at most one step.」

## 独点清单（3 个真独点）

### 独点1：interrupt/resume 是一等原语，恢复值不只是 approve/reject（工作流层）
- 判据：长时程任务不需要自己写状态机——框架提供 `interrupt()` 暂停执行，`Command(resume=任意JSON)` 在分钟/小时/天后恢复，resume 值作为 interrupt 的返回值。HITL 审批只是其中一个用途；可以是用户改的参数、外部系统回调结果、人工修正后的计划。
- 独有增量（与 r168C 状态持久化区别）：那条讲 handoff 边界；本条讲**可中断-可恢复的执行原语**，且 resume 值是结构化 JSON 不只是布尔审批。
- 提升层：工作流。

### 独点2：恢复时 interrupt 前的代码会重跑——side effect 必须幂等（工具层）
- 判据：从 checkpoint 恢复时，interrupt 所在节点里 interrupt() 调用之前的代码会**重新执行一遍**。如果那段代码有副作用（发邮件/扣款/写外部系统），恢复时会再做一次。→ 副作用必须放 interrupt() 之后，或本身做成幂等（带 idempotency key）。
- 独有增量：这是 checkpoint 模式最隐蔽的 bug——恢复不是"从中断点继续"，是"重跑该节点到 interrupt 处"。
- 提升层：工具。

### 独点3：每步 checkpoint 崩溃最多丢一步 + checkpoint 可 time-travel（工作流层）
- 判据：执行循环做成 resume→execute→check idempotency→checkpoint→repeat，任何一步崩溃最多丢一个 step，不用从头跑。每个 checkpoint 还是 time-travel 锚点：可以 fork 新分支（"从这步换个方案试试"）、replay 成 eval 数据、rewind 调试。小状态(<350KB)存 DB，大 payload 存对象存储。
- 独有增量：checkpoint 不只是崩溃恢复，还是**调试和 eval 的基础设施**（replay 历史轨迹成回归测试）。
- 提升层：工作流。
