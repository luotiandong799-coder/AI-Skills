## 实拉证据（关键原文）
- Microsoft：「Image verbalization — LLM 在 ingestion 时给每张图生成自然语言描述，存文本并和文档正文一起 embed。图被表达成语言后，标准文本检索就能命中。」
- theneuralbase：「Don't rely on similarity scores to rank hybrid results. Retrieve fixed k from each modality separately, merge by source (dedup), rerank combined with cross-encoder.」
- qubittool：「Pitfall: OCR as fallback — VLM 从 OCR 文本生成但 retriever 认为图像里别的部分相关，检索与生成不一致。Pass original page image to VLM, not OCR text.」
- bigdataboutique：统一 embeddings（Cohere Embed 4 / voyage-multimodal-3）vs page-as-image + ColPali/ColQwen2 晚期交互——后者对图表密集型文档 recall 最高但向量多 100-1000 倍。

## 独点清单（3 个真独点）

### 独点1：三种多模态检索架构按文档类型选（工具层）
- 判据：①统一 embeddings（文本图像同空间，单索引可跨模态查，便宜）②图像语言化（ingestion 时 LLM 给图写 caption，存文本——最省钱、文本检索即可命中）③page-as-image + 晚期交互（ColPali，图多文档 recall 最高，但每页 100-1000 倍向量）。图表/截图多的文档别只用纯 OCR 文本——直接索引图像。
- 独有增量（与 r167B chunking/RAG 检索区别）：多模态检索的三个架构选项与选型判据。
- 提升层：工具。

### 独点2：混合模态结果不能靠相似度分数排名（工作流层）
- 判据：文本和图像检索的相似度分数不可比。正确做法：各模态固定取 k → 按来源合并去重 → cross-encoder 重排（或全量给 LLM 选）。RAG 检索排序在跨模态时尤其要重排器。
- 独有增量：跨模态分数不可比 → 必须重排。
- 提升层：工作流。

### 独点3：检索与生成必须用同一模态（工作流层）
- 判据：ColPali 检索到图像，生成时却喂 OCR 文本 = 不一致（retriever 认为图里 X 相关，VLM 只看到 Y 的 OCR）。检索到图就把原图传给 VLM，别 fallback 到 OCR 文本。元数据过滤（表格/图表/截图类型标签）在多模态 RAG 里是标配。
- 独有增量：检索-生成模态一致原则，这是多模态 RAG 特有的失败模式。
- 提升层：工作流。

## 判非重复理由
- 此前 RAG 主题都是文本检索；多模态检索架构、跨模态重排、模态一致性是新角度，增量 >40%。
