# r167-A 上下文工程与提示词缓存（2026-09-24）

## 独点 1：Prompt Caching 前缀排序与边界位置纪律（提升层：可复用 Skill / 工作流）
- **内容按稳定性从高到低排**：tool definitions（极少变）→ static agent instructions（永不变）→ system prompt → document context → conversation history → per-request dynamic query。任何在 prefix 里的改动会 invalidate 后面全部——Claude Code 原文："Any change anywhere in the prefix invalidates everything after it. Design your entire system around this constraint."
- **缓存边界放在"两个请求之间完全不变的最后一块内容之后"**——对大多数 agent 就是 tool definitions 结束后；Anthropic 最多 4 个 breakpoint，breakpoint 本身免费，数量不影响定价，只有缓存内容量影响。
- **状态切换用 messages 不用 system prompt**：进 plan mode、改日期等，插 messages 进对话，不改 system prompt——改 system prompt 会让整个 prefix 缓存失效。不要中途换 tools 或 model，用 tools 做状态转换。
- 判据：**缓存不是优化项是架构约束**——system prompt 每次请求都重新写、动态内容插在稳定内容前面、状态切换改 system prompt，这三个动作直接把缓存命中率打到 0。
- 判非重复：现有 wb-context-compressor 讲"怎么压缩历史"，本条讲"怎么排 prompt 让 KV cache 命中"——正交，不重叠。

## 独点 2：缓存命中率是诊断信号，<30% 就是顺序错（提升层：工具 / 可复用 Skill）
- **cache-hit rate < 30% 几乎肯定是 prompt 顺序问题**——稳定内容（tool schemas/策略文本/角色描述）没放前面，动态注入插在了稳定内容之前。用 API 返回的 cached token count 做监控，不是猜。
- **system prompt tokens 占比 > 50% 说明该拆或该 RAG**——系统提示词膨胀到一半以上时，该把大块静态文档移到 RAG/检索，而不是塞在 prefix 里。
- **盈亏平衡点 = 第 2 次读回本**：5 分钟 TTL 写 1.25x、读 0.1x；1 小时 TTL 写 2x、读 0.1x。第 2 次读省下的 1.8x 已覆盖写成本，第 3 次起每次省 90%。会话间隔 < 5 分钟用默认 TTL，间隔 5 分钟到 1 小时用 extended TTL。
- 判据：**命中率是可观测的工程指标**，不是"应该缓存"的口号——每次发版后看一眼命中率，掉了就查 prefix 哪块变了。
- 判非重复：现有 wb-max-token-saver 讲"成本四层/进度流诊断流"，本条讲"用 cached token count 做缓存健康监控"——正交。

## 独点 3：记忆三范式选择 + 新记忆集成四分类（提升层：可复用 Skill）
- **三种记忆架构按场景选，不是越复杂越好**：
  - **Mem0**：提取事实存向量库，最简单 drop-in，单写毫秒级，适合用户偏好/个性化场景；数据模型是"这个用户喜欢什么/问过什么/怎么回应过"。
  - **Letta（原 MemGPT）**：可编辑 core-memory block + archival memory，agent 用专门工具自己决定什么留 context 什么存归档——OS 式虚拟内存，适合需要 self-editing persona-aware agent 的场景。
  - **Zep/Graphiti**：时序知识图谱，解决事实矛盾、追踪事实有效期窗口，LongMemEval 准确率领先，适合"用户改了偏好要知道旧偏好什么时候过期"的场景。
- **新记忆进来时四分类处理**：ADD（新事实）/ NOOP（重复）/ UPDATE（覆盖旧值）/ CONFLICT（矛盾，最难）。余弦相似度阈值 ≈0.82 找最近邻，LLM 判关系，审计轨迹必写。
- 判据：**记忆不是"存得越多越好"**——Mem0 适合偏好、Letta 适合自管理状态、Zep 适合时效与矛盾；选错范式，后续每次检索都在为错误的数据模型付税。
- 判非重复：现有 wb-context-compressor §记忆提取四策略讲"提取时按语义/摘要/偏好/情节分类"，本条讲"存的时候选哪种架构 + 新记忆进来怎么判重合并"——正交，一个管提取策略一个管存储架构与集成。
