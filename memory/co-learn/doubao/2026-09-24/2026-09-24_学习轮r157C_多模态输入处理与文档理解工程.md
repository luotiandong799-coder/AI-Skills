## 二、独点清单 + 判非重复理由（7 点，均≥40% 独有增量）

### 1. 混合式表格提取：OCR 文本 + LLM 重构，文本替代图像（来源：AI Engine 2026-05-30 + Mixpeek 2026-05-20 + TDCommons 实拉）
OCR 读 PDF 出逐页精确文本（不发明内容）→ LLM 收 OCR 文本（不收图）重构 HTML 表格、system prompt 禁止修改任何值；**文本替代图像把 LLM 输入从 ~51k token 降到几千**；两遍法=第一遍检测表格区域提取 HTML，第二遍校验结构（等列数/无孤儿单元格）失败换 prompt 或模型；复杂表用 HTML 输出（rowspan/colspan）优于 Markdown。
- 判非重复：豆包 r156-A 长文档分层索引管"分块与索引"，不涉"表格如何被提取"。增量≥85%。
- 提升层：工作流（文档结构化）。

### 2. 文档管线七阶段 + 预处理四项 + 复合误差纪律（来源：Harshith 2026-05-09 + Mixpeek 2026-05-20 实拉）
管线七阶段=ingestion/preprocessing/OCR/layout analysis/extraction/validation/output；预处理四项=deskew/denoise/contrast/分辨率归一；**每阶段引入复合误差**（倾斜扫描→坏 bbox→错识别）——质量在入口控制，越早修正越省；Transform 阶段是质量瓶颈。
- 判非重复：点 1 管表格单点；本点管"**整条管线阶段划分与误差传播**"。增量≥65%。
- 提升层：工作流（管线设计）。

### 3. 布局感知分块：结构边界 + 祖先上下文（来源：Google Cloud Document AI 2026-09-03 + Unstructured 2026-03-17 实拉）
chunk 边界尊重文档结构（标题/页/语义），**检索块携带祖先标题与表头上下文**（不只是文本还有结构上下文）；固定字符窗口混入主题漂移（topic drift）；chunk size=recall 与 precision 权衡。
- 判非重复：r156-A 已落"分层索引/块大小权衡"概面；本点=**结构感知 chunk 的祖先上下文携带**增量（Google layout parser 2026-09 新页）。增量≥45%。
- 提升层：工作流（分块策略）。

### 4. DeepDoc 三层解析架构与 TSR 表格结构识别（来源：RAGFlow docs 2026-08-29 + DeepWiki + PyShine 实拉）
三层=文件格式解析器（PDF/DOCX/Excel/HTML）+ 视觉模型层（YOLOv10 DLA 11-12 类布局 / CRAFT 文本检测 / PaddleOCR / TSR）+ 结构语义分块；**TSR 处理层级表头/跨行跨列/投影行头，把表格重组为 LLM 可理解的句子**；MinerU 选配复杂公式/排版。
- 判非重复：点 1 管 API 侧混合提取；本点=**开源引擎的模块化三层与 TSR 专门能力**。增量≥70%。
- 提升层：工具（文档解析引擎）。

### 5. 粗到细视觉处理：先版面预扫再裁剪细识别（来源：CVPR 2026 论文笔记 2026-08-01 实拉）
粗阶段=轻量 Valid Region Focus Module 扫整页检测版面元素（文字块/表格/公式/图表）、分类、预测阅读顺序——只做"在哪/是什么/先读谁"不识别，快且轻；裁剪有效区域（背景/空白/装饰直接剪掉）后细识别——效率与性能双提升。
- 判非重复：与点 2 预处理互补——本点=**"先定位后识别"的两段式视觉范式**（CVPR 2026 新）。增量≥90%。
- 提升层：工作流（视觉处理范式）。

### 6. 视觉 token 计费机制与降 token 纪律（来源：CostHawk 2026-03-16 + Roboflow 2026-05-04 + Neural Base 2026-04-23 + OpenAI 定价 实拉）
图像按像素与 provider tiling 逻辑转 token：GPT-4o low detail 恒 85 token（512×512 单 tile）、high detail 先缩 2048×2048 再切 512 tile；GPT-5.5 patch 化 32×32、上限 2500 patch；Gemini 1024×1024 基准 258 token/tile；**跨 provider 不可直接对比须查官方计数**；preprocess 到保留任务信息的最小分辨率，low detail 可省 90%+ token；KV 缓存效率是多模态成本核心驱动（同一图 870 vs 90 token 的模型差异在量级上被放大）。
- 判非重复：r157-A 缓存面不涉"图像如何计费"；本点=视觉 token 的成本核算与压缩纪律。增量≥85%。
- 提升层：工作流（成本治理）。

### 7. PDF 文本层优先：先取文本层再决定是否渲染图像（来源：token0 PyPI 2026-09-23 + Stochastic Sandbox 2026-07-21 实拉）
数字/typed PDF 几乎总有文本层——**先用 pypdf 提取文本层而非渲染成图**：2 页发票 ~1530 视觉 token→~80 文本 token；扫描件无文本层才回退图像/OCR；Anthropic/Google 原生 PDF 处理同时提取文本层与视觉元素，文本型文档比图像-only 更低 token 且结果更好。
- 判非重复：点 6 管图像计费；本点=**"PDF 优先文本层"的输入策略**（决策面 vs 计费面）。增量≥60%。
- 提升层：工作流（输入策略）。
