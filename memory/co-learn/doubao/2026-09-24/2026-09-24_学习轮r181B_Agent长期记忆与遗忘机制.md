## 实拉证据（关键原文）
- AWS：「Customer support agent referenced a billing dispute resolved four months earlier, treating it as active. Without lifecycle policies, agents accumulate outdated context and degrade.」
- besthub：「Time-based decay half-life ≈70 days lowers retrieval scores; TTL archive events 90 days / facts 180 days to cold storage, still queryable but excluded from default.」
- AgeMem：「Store/retrieve/update/summarize/discard as callable tools, optimize entire pipeline with RL — supervised warm-up → task-level RL → step-level GRPO.」
- dev.to：「TTL on episodic 30-90 days; recency weighting in retrieval; preference stated in frustrated debugging session is not representative.」

## 独点清单（3 个真独点）

### 独点1：记忆必须有遗忘策略，否则过期事实污染判断（工作流层）
- 判据：永不忘的记忆是负债——客服 agent 把四个月前已解决的纠纷当活跃问题引用。三层遗忘并行：时间衰减（半衰期~70天降检索分不删）+ TTL 归档（事件90天/事实180天移冷存储）+ 显式删除（agent 判断不相关主动删）。
- 独有增量（与已有 context-compressor 记忆提取互补）：那条管怎么提取记忆，本条管记忆怎么过期/遗忘。
- 提升层：工作流。

### 独点2：记忆操作（存/取/更新/总结/丢弃）本身就是工具（工具层）
- 判据：AgeMem 把五个记忆操作当 callable tools，用 RL 端到端优化——不是固定规则"每轮存什么"，而是 agent 自己决定何时存/何时丢/何时总结。偏好类记忆要小心：调试时愤怒说的"我讨厌X"不代表长期偏好。
- 独有增量：记忆操作工具化 + RL 优化整个记忆管线。
- 提升层：工具。

### 独点3：分层记忆架构——buffer/summary/semantic/entity 四层（工具层）
- 判据：全塞上下文~50轮就爆。四层：buffer（短期当前对话）→ summary（对话摘要）→ semantic（向量长期事实）→ entity（实体关系图）。生产栈 LangChain+Supabase pgvector，按用户 RLS 隔离。检索时按问题类型路由到对应层。
- 独有增量：四层记忆分工与选型。
- 提升层：工具。

## 判非重复理由
- context-compressor 已有记忆提取四策略/两级沉淀；本条补遗忘机制（半衰期+TTL+显式删）+ 记忆操作工具化 + 四层架构选型，增量 >40%。
