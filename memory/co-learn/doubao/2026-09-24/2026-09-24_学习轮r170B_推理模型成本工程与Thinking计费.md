# r170-B 推理模型成本工程：Thinking 计费纪律、Prompt Caching 静默失败、Reasoning Router 盈亏平衡

## 实拉证据（关键原文）
- Thinking 计费（Anthropic 官方）：「thinking tokens are billed as output tokens, even when the thinking text isn't returned to you」；上一轮 assistant 的 thinking block 进后续请求按 input token 计费；Claude 4.6+ 手动 `budget_tokens` 已 deprecated，推荐 adaptive——模型按请求复杂度自己决定 thinking 时长；practical budget：10K 日常/32K 多步/100K 最难规划。
- Prompt caching（octomind 2026-09-18）：「Cached tokens cost about a tenth of the normal input price... the single biggest cost lever for AI agents, bigger than model choice. The reason most teams never collect: the failure is silent. Nothing errors, nothing warns. The response is identical whether the cache hit or missed.」Anthropic 写缓存 1.25x（5min TTL）/2x（1h TTL），读 0.1x；OpenAI 自动缓存无写入溢价但折扣 ~50%；结构纪律=稳定 prefix 在前动态 suffix 在后。
- Reasoning 路由（theneuralbase/channel.tel/syncsoft）：o3-mini ~10x standard、o3 ~40-50x——**路由阈值 = 错误成本超过 reasoning 成本多少倍才值得**；reasoning 超时自动回退 fast model 不让用户等；纯关键词启发式路由会漂移，要监控"被路由到 reasoning 的请求真的受益了吗"，季度重训；不该用 reasoning：状态查询/简单 lookup/chat UX（用户 >3 秒就走）；该用：math/规划/novel problem/高风险/多条件约束。

## 独点清单（3 个真独点）

### 独点1：Thinking 也是计费面——别把 reasoning 当免费思考（工作流层）
- 判据：开启 extended thinking 后，thinking tokens 按 output 计费**即使不返回给用户**；上一轮的 thinking block 进下一轮上下文按 input 计费。多轮 agent 里 thinking 成本会滚雪球。
- 独有增量（与 r168-A「快慢模型分工」区别）：那条管选哪个模型，本条管**同一模型开 thinking 时的成本记账**——thinking 不是"模型内部免费琢磨"，是和正文一样计费的输出 token；Claude 4.6+ 已转 adaptive（模型自己决定要不要 thinking），开发者不再拍固定 budget。
- 提升层：工作流（成本工程）。

### 独点2：Prompt Caching 失败是静默的——必须主动监控 hit rate，别等账单（工具/工作流层）
- 判据：缓存 miss 不报错不警告，响应一模一样——大多数团队从没拿到缓存折扣，不是因为功能没开，是因为 prefix 结构不对但没人发现。结构纪律：稳定内容在前（system prompt/工具定义/少变上下文），动态用户输入在后；Anthropic 写缓存有 1.25x/2x 溢价，hit rate 不够高时写缓存反而亏钱。
- 独有增量（与 wb-max-token-saver「成本四层」区别）：那条是成本分类框架，本条是**缓存这一具体杠杆的工程纪律**——prefix 顺序、静默失败要主动测 hit rate、写溢价要算摊销。
- 提升层：工具/工作流。

### 独点3：Reasoning Router 按盈亏平衡选，不按"越难越好"（工作流层）
- 判据：reasoning 模型比 standard 贵 10-50 倍——路由阈值不是"问题看起来难就上 reasoning"，而是**算一笔账：错误代价 × 概率 是否超过 reasoning 溢价**。状态查询/简单 lookup/聊天 UX 用 reasoning 是纯浪费（用户 3 秒就走）；多条件约束决策/高风险/novel problem 才值得。
- 路由本身会漂移：纯关键词启发式在生产里腐化，要监控"被路由到 reasoning 的请求真的比 fast 好吗"，季度重训分类器；reasoning 超 latency budget 自动回退 fast model 而不是让用户干等。
- 提升层：工作流。
