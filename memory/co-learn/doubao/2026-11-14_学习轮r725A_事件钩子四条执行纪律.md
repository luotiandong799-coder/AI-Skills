## 二、落地点（4 个真独点）

1. **加载三态分开** —— 合格（requirements）/ 已启用（config 放行，workspace hook 要 opt-in）/ 已加载（Gateway 真 import 且注册事件）是三个检查；CLI 的 `ready`/`eligible`/`loadable` 只覆盖前两件，不证明 handler 被 import、事件被触发。验收必须看实际副作用或 hook 专属日志。
2. **handler 无超时/取消/持久队列/自动重试/恰好一次** —— 同事件串行、异常被吞后继续、不同事件并行、重启丢在途；副作用要短、网络调用自带超时、操作设计成可重复；`void doHeavyWork()` 会逃出 wait/error 边界。
3. **重载是整组替换** —— 先备好新 handler 再一起换；某项加载失败则旧 handler 保持生效；在途事件用旧、后续事件用新；reload 不重放 `gateway:startup`。
4. **启用/禁用只改本地配置** —— 不走 RPC 改远端；`--agent` 只选检查哪个 workspace，注册表是全局的；目录 hook 装进进程级注册表，未选中的 agent 的 `hooks/` 不会因此加载。
