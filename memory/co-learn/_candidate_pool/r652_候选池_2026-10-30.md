# r652 候选池（2026-10-30）

> 本轮入池 10 条，无出池。入池=有信号但判据不足或§5特定域排除；出池=满足「出池条件」时可转为正式落地。

## 1. P1 触发密钥的校验形态

- **来源**：Activepieces#16826 子点（webhook passcode SHA-256 + timingSafeEqual）
- **要点**：权重级校验要带常量时间比较；新增 OAuth scope 时须声明既有连接是重授权还是静默降级（命中找到 ssc 已落的主点，此二子点未覆）
- **出池条件**：出现第二个「密钥存在但未参与/未安全比较」的一手案例

## 2. P2 设备保障不等于身份

- **来源**：docs.openclaw.ai/gateway/audit.md（a paired device adds device assurance but never becomes a person）
- **要点**：设备侧证据只能提升设备保障等级，不得用于把一次操作归给某个人
- **出池条件**：需要在技能/网关侧做多因子归属判定时

## 3. P3 不可读证据判 unknown 不重建

- **来源**：docs.openclaw.ai/gateway/audit.md（an unreadable row is unknown, never reconstructed）
- **要点**：审计面遇到不可解析条目判 unknown 并保留，不得用邻近条目推断填补
- **出池条件**：需要设计审计报表缺数据处理策略时

## 4. P4 MCP 任务的四则协商细节

- **来源**：modelcontextprotocol.io/seps/2663
- **要点**：发 task 参数前必须 tools/list 打底；task 须绑授权上下文；resultType 仅用于 CreateTaskResult；不支持的请求类型收到 CreateTaskResult 判非法响应
- **出池条件**：第二来源给出同一组约束，或出现实际协商 bug

## 5. P5 沙箱出口枚举与签名

- **来源**：arXiv 2610.38458《Tracekit Box》
- **要点**：每条出沙箱的路径都要可枚举并由策略显式决定/签名；隔离与取证要同源
- **出池条件**：需要评估一个沙箱方案时

## 6. P6 不可信上下文影响 allow-rule 提案

- **来源**：arXiv 2610.22987《From Approval to Abuse》
- **要点**：不可信内容可以影响「被呈给审批者的那条规则」，规则提案面要当作攻击面
- **出池条件**：出现第二个同类一手证据（当前 ag SKILL:304/320 已覆审批权来源，本子点未覆）

## 7. P7 跨平台执行层的 shell 显式化

- **来源**：mastra-ai/mastra#28866
- **要点**：Windows 上 execa shell:true 会用 cmd 解析 POSIX 引号；必须显式传 Git Bash 可执行文件，并为 PATH 上缺失的 sh 提供显式回落
- **出池条件**：需要在 Windows 执行面做定型说明时

## 8. P8 opt-in 零成本检索诊断 tracer

- **来源**：deepset-ai/haystack#13427
- **要点**：诊断采集应可 opt-in、不写 pipeline-run 记录、零额外成本，只补 per-query 缺失文档诊断
- **出池条件**：需要给生产链路加诊断而不想付存储/性能代价时

## 9. P9 客户端不应复制服务端默认值

- **来源**：langflow-ai/langflow#15733 族（e2b#2057 同族）
- **要点**：SDK 复刻服务端默认值会产生第二处真相；默认值应由服务端单方面拥有
- **出池条件**：出现第三个同族案例
