# 本地文件内容级去重与安全清理

## 适用场景
- 用户要求扫描/清理个人目录（微信 `WeChat Files` / `xwechat_files`、QQ、下载目录等）里的重复文件。
- **高危操作**：必须走"只读扫描 → 出报告 → 明确确认 → 回收站 → 可还原"链路，禁止直接永久删除。

## 核心流程

### 1. 定位目标（只读）
微信数据目录典型位置（用户可能改到 D 盘）：
- 微信 3.x：`<盘>:\WeChat Files\<wxid>\FileStorage\{File,Image,Video,MsgAttach}`
- 微信 4.x：`<盘>:\xwechat_files\<wxid>_<hash>\msg\{file,attach,video}`
注册表可查但 `reg.exe` 常被安全策略黑名单拦截，改用直接探测已知路径。

### 2. 规模摸底
先统计文件数/总大小/扩展名分布，再决定策略。11 万文件 / 17 GB 量级：全量 MD5 约 9 分钟。

### 3. size 预筛（关键优化）
**只有 size 相同的文件才可能内容重复。** 先按 size 分组，只对 size 组内 >1 的文件算 MD5，
可把哈希量从 11.4 万降到 9.8 万（本例省掉 1.5 万个唯一文件）。

### 4. 危险类型必须排除
绝不能删：
| 类型 | 后果 |
|---|---|
| `.db` `.db-wal` `.db-shm` `.kvdb*` | 聊天记录本体，删了直接丢消息 |
| `.dat` `.thumb` | 聊天图片/视频的加密存储，删了聊天记录里对应图片变破图 |
| `.crc` `.material` `.mmkv` `.icon` | 索引/校验文件 |
可清理：`.docx/.xlsx/.pptx/.pdf/.zip/.mp4` 等文档 + 明文图片。

### 5. 保留哪一份
优先级：**新版目录 > 文件名不含 `(n)` 后缀 > 路径短**。删除前必须校验保留项存在，
否则跳过整组（防止把最后一copy也删掉）。

### 6. 删除走回收站
用 `send2trash`（pip 装到隔离 venv）。分批 + 批后校验原路径是否消失 + 失败即停。

### 7. 验证（必做，不能只看返回值）
解析回收站 `$I` 元数据文件，确认被删文件确实在回收站：
```python
# $I 格式: 0-7 版本, 8-15 大小, 16-23 删除时间, 24-27 名字长度, 28- 路径(UTF-16LE)
raw = open(ip, "rb").read()
orig = raw[28:].decode("utf-16-le", errors="ignore").split("\x00")[0]
```
必须三条独立证据：① 回收站条目数 == 计划数；② 文件名命中率 == 100%；③ 每组保留项仍在原位。

### 8. 硬链接检查（决定"能不能省空间"，必须在删除前做）
**聊天软件（微信/QQ）普遍用硬链接去重**——同一份内容在多个会话/目录出现时，是同一数据块的多个链接，
**逻辑大小叠加但物理只占一份**。删除这类"重复"不释放任何磁盘空间。
- 检测：`os.stat(p).st_ino`（Windows 上是 MFT 索引号）。**同组内 st_ino 相同 = 硬链接**。
- ⚠️ **必须在删除前检测**：删除硬链接后 `st_nlink` 会回落，删后再查会得出"不是硬链接"的错误结论。
- 实测：某微信 4.x 目录 3,000 个 `.dat` 重复组中 **65.7% 组内共享同一 MFT 记录**。
- 后果：清理后磁盘可用空间几乎不变（实测 3.7 GB 的"重复"只释放 0.12 GB）。
  **事前务必按 st_ino 区分"真重复"（占空间的独立副本）与"硬链接重复"（不占空间），只删前者才有空间收益。**

## 四个必踩的坑

### 坑 1：send2trash 抛假异常，实际已成功
Windows 下 `send2trash()` 会把文件成功移入回收站，**然后抛出**
`[WinError -2147024894] 系统找不到指定的文件`。
若按异常判定失败，会得到"3,941 个全部失败"的错误结论，而文件其实都进了回收站。
**判定依据只能是 $I 元数据 + 原路径消失 + 保留项存在，绝不能只看异常。**

### 坑 2：`$I` 路径解析偏移
路径在 **offset 28**，不是 24。用 24 会解析出乱码且命中率显示 0%，容易误判成"文件没进回收站"。

### 坑 3：安全策略限制单轮批量删除
环境有 `safe-delete` hook，单轮删除超过 **50 个文件**会触发
`SAFE_DELETE_BULK_CONFIRM_REQUIRED` 并中止脚本。清空回收站（数千文件）会被卡住。
→ 设计时要考虑：删除动作可能被阈值截断，脚本必须能**从断点续跑**（按 $I 匹配而非按索引），
并向用户说明剩余量，而不是假设一次跑完。

## 微信 `.dat` 加密格式（如需解密后比对）
- `f9 de f9 e6 …`：微信 3.x，单字节异或，key=**0x06** → 解出 `FF D8 FF E0`（JPEG）。
- `07 08 56 32 08 07 …`：微信 4.x，`\x07\x08V2\x08\x07` 容器格式，需单独解析。

## 报告产出
- HTML 报告（分类汇总 + TOP 重复组 + 风险说明 + 还原方式）
- CSV 逐文件清单（组号/大小/MD5/保留文件/待删文件）—— 用于人工核对与回滚
- 还原脚本：按 `$I` 元数据把 `$R` 文件搬回原路径，支持 `--dry-run`

## 给用户的必要提醒
- 微信每条消息的附件指向具体文件路径，**删副本后那条消息的文件会打不开**，即使内容相同。
- **如果同一内容在目录里是硬链接（多数情况），清空回收站也不会增加可用空间**；只有 st_ino 不同的独立副本被删才会真正释放空间。清理前先算清"真重复"的占比，别承诺空间收益。
- 文件进回收站 ≠ 空间释放；**要释放必须清空回收站（不可逆）**。
- 清理前关闭微信。

## 误删后的补救：重建硬链接
被删路径的父目录通常还在、且与保留副本同卷 → 可用 `os.link(keep_path, deleted_path)` **零额外空间**
把路径建回来（数据块由保留副本继续引用）。
适用：同组 keep 文件仍在。不适用：非硬链接的独立副本（数据已永久删除，只能靠回收站/备份还原）。
实测：3,984 个被删路径全部满足重建条件（父目录存在 + 同卷）。
