# wb-storage-audit（存储只读审计与三灯分级）

来源：GitHub `KKKKhazix/khazix-skills`·`storage-analyzer/SKILL.md`（7,941B，2026-11-08 一手实拉）+ 本机清理纪律。只取方法层，不复制其脚本。

## 一、铁律

- **扫描全程只读**：只跑 `df`、`du`、`stat`、`ls`、`os.scandir` 这类统计/列目录/读元信息命令；扫描阶段不删除、不移动、不清空回收站、不改权限。
- **清理必须逐对象授权**：用户说"看看什么占地方"只等于分析；要删必须点名具体路径并确认。已批准的对象可在同一边界内代为操作，不重复索取批准。
- **估算必须标注**："可释放约 X GB"一律是估算，受硬链接、压缩、回收站保留影响。
- **路径与命令保留原文**，不翻译、不改写。

## 二、三灯分级＝清理决策清单，不是全盘点

只把"存在要不要动它这个决策"的项放进三灯；日常在用的正常应用、操作系统本身、海量零碎小文件不进三灯，归"系统及其他"。

| 灯 | 判据 | 处置 |
|---|---|---|
| 🟢 可自动清理 | 纯缓存、临时文件、安装包残留、明确可再生且不丢用户数据（浏览器缓存、pip/uv/npm/cargo 缓存、Xcode DerivedData） | 给预估释放量 + 需先关闭的进程 + 可一键复制的安全命令 |
| 🟡 需人工判断 | 含用户数据或有判断成本（离线视频、文档、node_modules、聊天记录、设计稿） | 给内容画像 + 至少 3 条处置路径（应用内清理 / 系统工具 / 文件管理器手动审查）+ 风险提示；**只允许移到废纸篓（可逆），绝不直接删** |
| 🔴 有决策但不建议手删 | 重复安装的应用、想卸载的大应用、运行中应用的核心数据 | 给"为什么不建议手删"+ 具体卸载步骤（自带卸载器/启动台长按/右键移废纸篓/清残留）；**不给删除按钮** |

## 三、删除的安全边界（白名单）

- `rm`（不可逆）**只允许绿灯项的具体路径**；🟡 永远只可 `trash`（移废纸篓）。
- 拒绝主目录、盘符根、数据根目录、符号链接本身、项目/worktree 目录；应用安装目录只允许"打开"不允许删。
- 每次删除前先确认对象仍存在、仍在授权范围内；删后回读确认（删除报错后命令仍可能继续执行）。

## 四、绝不能当缓存的东西

- 项目目录、git worktree（含 `.git` 指针文件）、项目依赖、整个开发工具安装目录。
- Windows 二次统计大小要排除 junction / symlink，不能只看目录名或体积判断可删。
- 包管理器缓存走自身命令：`pnpm store prune`、`go clean -modcache`、`npm cache clean --force`（明确缓存子目录时才用 `rm`）。

## 五、符号链接与口径

- 清理目标被别的路径以符号链接引用时（如 `~/.cache` → `~/.dev-cache/cache`），**只清空内容、保留目录**（`find <dir> -mindepth 1 -delete`），不给整目录删除或移废纸篓，避免链接悬空。
- 顶层分组存在父子包含关系，**不能直接相加**；读不到的目录标 `denied` 并在报告里列出，说明遗漏体量。
- 挂载点/虚拟文件系统（如模拟器设备镜像）可能显示几十 GB 但不占本盘，不能当清理项。

## 六、报告阅读流（固定顺序）

现状 → 诊断 → 处方 → 操作 → 预防：

1. 磁盘总览（容量 + 已用/可用 + 三灯分段）；
2. 占用排行 Top 5（类型判定：系统资产/应用本体/应用数据/缓存/开发缓存/用户文件/媒体/下载/虚拟机镜像/回收站）；
3. 执行建议（一句话洞察：最大占用是什么、能释放多少）+ 优先级清单；
4. 三灯可折叠卡片（每项带命令，可一键复制）；
5. 长期建议（定期清理项、可视化工具、大文件归档）。

对话里只给结论先行摘要：总可释放估算、最该先清的 2–3 项、风险最高的一项；细节留给报告。

## 七、判据

**每条清理建议都必须同时具备：具体路径 + 可逆路径（废纸篓优先）+ 明确授权。** 三者缺一，就只能作为候选列出，不能执行。
