# wb-teaching — 跨会话教学工作区

来源：mattpocock/skills `teach`（skills.sh /hot 2026-09-15 榜单命中，1377 周装量榜首系同仓库）。用户要学的是一个**有状态的多会话过程**，不是一次性回答。

## 工作区五件套

教学状态落在文件里，跨会话续用：

| 文件 | 装什么 |
|---|---|
| `MISSION.md` | 用户**为什么**想学这个主题——所有教学围绕它锚定；使命变化要经用户确认并记一条学习记录 |
| `RESOURCES.md` | 高质量、高信任的资料清单；**资料不足先补资料，不靠参数记忆硬讲** |
| `learning-records/0001-<name>.md` | 学习记录，编号递增不回收——相当于 ADR：记**非显而易见的领悟**与可能要修订的旧结论 |
| `lessons/0001-<name>.html` | 课时：自包含、教**一个**紧扣使命的小东西，排版干净（Tufte 式），用户以后会回头复习 |
| `assets/` | 可复用组件：共享样式表是每个工作区的第一个组件； quiz/模拟器/图示助手等第二个课时能复用的都做成组件，**复用是默认，内联复制是例外** |

## 教学哲学

- **知识 / 技能 / 智慧三分**：知识来自高信任资料；技能靠相关的互动练习；智慧来自与同行交流。理论物理偏知识，学软件偏技能——按主题配比。
- **流利度 ≠ 存储强度**：当场能想起来（流利度）会制造虚假掌握感；**长期留存（存储强度）才是目标**。课时设计要制造"合意困难"：① 检索练习（先凭记忆回想再看答案）② 间隔（练习分散到时间中）③ 交错（技能类练习混入相关但不同的主题）。
- **最近发展区**：从学习记录计算用户当前在哪、下一步够得着什么——太简单是浪费，够不着是挫败。
- **课时要短、要有单点可赢**：工作记忆很小，一课时给一个**能立刻用上的小胜利**，且直接扣回使命。
- **每课时链回**：用锚点链接相关课时与参考文档；推荐一个该主题最优质的**一手来源**；提醒用户可以随时追问。

## 与本机技能系统的关系

- 要求可视化讲解时，课件配合 Visualizer（图表/交互件）产出；课件本体是文件（落 `D:\腾讯AI\yt\outputs\<日期>_<主题>\`）。
- 学习记录的写法与「经验固化」同源：**非显而易见才记，显而易见的不记**。（原指向的 `wb-loop-engineering` 已于 2026-09-13 删除，此处保留判据本身。）
- **与 `wb-doc-writing` 分工**：教学课时与学习记录走本技能；**写给人看的技术文档**（设计文档 / RFC / ADR / 评审报告）与其评审走 `wb-doc-writing`。学习记录里的"决定记录"格式可参考那边的 append-only 决策日志（写错不编辑，新增覆盖条）。
