# r817A · 点击劫持（Clickjacking / UI redress）：服务端授权头被客户端 frame 边界绕过

## 独点1 · 根因与三类机制（OWASP 官方逐字）
- OWASP 定义逐字：「Clickjacking, also known as a 'UI redress attack', is when an attacker uses multiple transparent or opaque layers to trick a user into clicking on a button or link on another page when they were intending to click on the top level page.」；按键同样可劫持（样式表+iframe+文本框使用户以为在输入邮箱/银行密码，实际输入攻击者不可见 frame）。术语由 Jeremiah Grossman 与 Robert Hansen 于 2008 提出、属 UI redressing 子集。
- 真实案例：Adobe Flash 设置页被透明 iframe 加载，诱使用户授权任意 Flash 动画使用麦克风/摄像头；Twitter 蠕虫（诱导 re-tweet 恶意页位置）；Facebook "Like" 劫持（已登录用户被任意点赞粉丝页/链接/群组）。
- 三道独立机制（纵深防御，能叠加不止一个）：①CSP `frame-ancestors` 响应头阻止其他域 framing，旧 `X-Frame-Options` 作优雅降级；②认证 cookie 设 `SameSite=Strict`（或 `Lax`，除非显式需要 `None`，很少）；③UI 防御代码确保当前 frame 是顶层窗口。
- **关键边界**：三机制仅覆盖 frame-based clickjacking；DoubleClickjacking 用**独立窗口**而非 iframe，`X-Frame-Options`/`frame-ancestors` 都挡不住 ⇒ 不能把「已配 frame-ancestors」写成「clickjacking 已治理」。

## 独点2 · 响应头细节与「头 vs meta」陷阱（Cheat Sheet 逐字）
- CSP 首选：`Content-Security-Policy: frame-ancestors 'none';`（推荐默认，禁止任何域 framing）/ `frame-ancestors 'self';`（仅本站点）/ `frame-ancestors 'self' https://*.somesite.com https://myfriend.site.com;`（HTTPS 主机表达式用默认 443；通配符只匹配子域、不匹配裸 `somesite.com`，裸主机须显式列出）。`'self'`/`'none'` 的**单引号必需**，其他 source expression 不得加引号。
- XFO：`X-Frame-Options: DENY`（推荐）/ `SAMEORIGIN` / `ALLOW-FROM uri`（**已废弃、现代浏览器不再生效，且不支持时 fail open = 完全没有防点击劫持**）。规范：CSP enforce 态 `frame-ancestors` 存在时 XFO **MUST be ignored**；但 Chrome 40/Firefox 35 等旧版违背此要求仍跟随 XFO —— 两头同发时须知旧浏览器行为不同。
- XFO 七类局限逐字：逐页配置烦琐；多域名站无法列白名单；`ALLOW-FROM` 浏览器支持问题；不能同时允许本站与第三方的同一响应（浏览器只认一个头一个值）；嵌套 frame 下 SAMEORIGIN/ALLOW-FROM 只看顶层浏览上下文（修法父子都写但破坏父页作顶层时的子帧加载）；XFO 已被 CSP L2 `frame-ancestors` 取代；**Web 代理增删头**（代理剥掉 XFO 即失去防护）。WSTG 另记最低支持版本 IE8/Firefox 3.6.9/Opera 10.5/Safari 4/Chrome 4.1.249.1042 与「移动版页面常漏配」。
- **meta 标签无效**：`<meta http-equiv="X-Frame-Options" content="deny">` DO NOT WORK；`frame-ancestors` 同样必须是 HTTP 响应头而非 `<meta>`。验收必须抓包看响应头，不能看 HTML 源码里有没有写。

## 独点3 · 验证、绕过与 DoubleClickjacking 的工程判据
- 检出（WSTG 逐字）：造 `<iframe src="http://www.target.site" width="500" height="500"></iframe>` 测试页，目标页能成功加载即判无防护；「不出现」只说明有某种防护，**不等于完全免疫**。
- frame-busting 可被绕：双重 framing（访问 `parent.location` 因 descendant frame navigation policy 触发安全违例、反制导航失效）；禁用 JavaScript（IE `security="restricted"`、HTML5 `sandbox`、Firefox/IE8 `document.designMode="on"`）；`onBeforeUnload` 弹确认框诱导取消导航，或对 204 No Content 页面每毫秒重复提交导航（无需用户交互）冲掉原导航；IE8/Chrome 4 XSS filter 把 frame-busting 脚本误判为反射 XSS 而禁用；IE7/8 把 `location` 重定义为变量、Safari 4.0.4 用 `window.defineSetter("location", function(){})` 绑定函数 ⇒ 读/写 `top.location` 失败。
- OWASP 仍给 legacy 浏览器的改良 frame-breaker（HEAD 里先 `<style id="antiClickjack">body{display:none !important;}</style>`，`self===top` 则删该 style，否则 `top.location=self.location`）；简单 `if (top!=self) top.location.href=self.location.href` 明确标 DO NOT USE。`window.confirm()` 只能作补充：沙箱 frame 无 `allow-modals` 时浏览器可抑制简单对话框、`confirm()` 返回 false，必须只在 true 后执行动作。
- SameSite 是纵深一层非替代：`SameSite=Strict/Lax` 不阻止 framing、也不对同站请求 withholding cookie；同 scheme 的攻击者兄弟子域 **same-site but different origin** ⇒ 仍须 `frame-ancestors` 限制允许 framing 的 origin。若攻击不需要登录态，SameSite 完全无效；2020-11 仍有约 6% 浏览器不支持。
- DoubleClickjacking（2024-12 Paulos Yibelo 披露）：双击过程中第二个窗口的敏感控件被激活；目标页是**顶层窗口**故 framing 限制全失效，`Lax` 允许安全方法顶层导航带 cookie、`Strict` 只拦初始跨站请求，二者都不验证「用户是否意图该动作」。对应用控制的同意屏/支付确认/账号安全设置：高风险动作要求复核动作细节 + 服务端强制 transaction authorization（仅加确认按钮不构成完整防御）；「先禁用敏感控件直到Prior interaction」仅为补充缓解——鼠标移动或按键本身不等于理解批准；控件应从初始即 disabled 并测试鼠标/键盘/触摸/辅助技术均可启用与激活（click events 支持全部输入方式，不能要求每个用户移鼠标/按键）。
- 与 §二十二 CSRF 的串链（WSTG PoC 逐字）：三步转账中第二步生成随机 anti-CSRF token 存 session、hidden field 带 token、只收 POST；攻击者用 CSS `opacity:0` 把 `transfer.php?account=ATTACKER&amount=10000` 的 iframe 精确叠在「Click and go!」按钮上，用户一点即提交含合法 token 的第二步表单（安全控制在最后一步，且参数可经 GET 传入）；高级手法可强制用户填充表单值 ⇒ anti-CSRF token 被 UI redress 绕过，证明「有 CSRF token」不等于「动作出于用户本意」。

## 不防什么
- 不防 DoubleClickjacking 等独立窗口 UI redress（须服务端 transaction authorization）；不防 XSS/服务端鉴权缺失/CSRF 本身；代理剥头或 meta 标签写法使防护失效；`ALLOW-FROM` 在不支持浏览器上 fail open；SameSite 对同站兄弟子域与无需登录态的攻击无效。
