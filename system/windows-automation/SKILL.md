# Windows 多引擎自动化路由（大脑层）

> 本技能是 Windows 操控的**引擎决策层**，串起识别/输入/命令行三层。它是路由器，**不重复实现任何引擎能力**，只判定"用哪个、何时降级"。

## 一、引擎优先级

| 顺序 | 引擎 | 适用 | 不可靠判据 |
|---|---|---|---|
| 1 | **UIA/UIA3/FlaUI** | 程序暴露无障碍树 | 元素为 0 / 识别空 / AutomationId 缺失 |
| 2 | **pywinauto** | Python 侧、Win32/UIA 后端 | 后端连不上 / 控件找不到 |
| 3 | **OCR / 视觉定位** | 自绘/Qt 类（微信等）、无树 | 置信度低 / 多次定位偏移 |
| 4 | **坐标兜底** | 以上全失败、且布局固定 | 仅最后一手，需实时取坐标 |

## 二、降级流程（不无限重试）

```
尝试引擎 N → 校验是否真的识别/操作成功
  → 成功：继续
  → 失败且属"确定性失败"（元素空/报错）：直接降级 N+1，不重试同引擎
  → 失败且属"瞬时"（动画未完/焦点被抢）：退避一次后重试同引擎
```

- 与 `personal-ai-os` §九·五 衔接：**单工具失败 2 次后必须换路**，不允许无限循环。
- 连续降级到底仍失败 → 停止并报告卡点，不堆叠无意义操作。

## 三、判定"不可靠"的依据

- 识别为空 / 操作无副作用（输入框未变、按钮未触发）
- 进程/窗口已不在预期状态
- 报错类型属确定性（权限/不支持/元素缺失）→ 换引擎；瞬时（超时/焦点）→ 退避重试

## 四、调用分工

- 控件识别 → `winapp-ui-automation`
- 鼠标/键盘/截图/视觉 → `computer-use-windows`
- 文件/进程/服务/网络/系统 → `powershell-windows-cli`
- 高风险（删/改/发/支付）→ 先回 personal-ai-os 三级权限判定
