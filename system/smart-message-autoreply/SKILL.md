# 智能消息自动回复（消息大脑）

**一句话结论：本技能只做「消息大脑」——判断该不该回、按谁的风格回、从真实结果学经验；读消息/发消息的驱动、Windows 操作方式、权限、记忆治理、验证一律走已有技能，不重复实现。**

## 〇、边界（不重复建设，先看这张表）

| 需求 | 由谁承担 |
|---|---|
| 读消息 / 发消息 / 未读红点识别 / 会话列表滚动 / `wechat-send.ps1` / 焦点与键盘注入 | **`win-native-app-automation`**（唯一驱动层） |
| Windows 操作方式择优（键盘 / 命令行 / 控件级 / 视觉）、操作经验进化 | **`windows-ops-experience`** |
| 权限分级 L0/L1/L2、停止条件、失败恢复、任务后清理、资源边界 | **`personal-ai-os`** |
| 通用记忆治理（去重 / 分层 / 防膨胀 / 过期） | **`knowledge-governance`**、跨 Agent 交接走 `agent-guild` |
| 交付物独立验证 | **`wb-artifact-verification`** |
| **本技能独占** | 消息识别与分类、是否回复判断、联系人×场景风格经验、连续对话上下文、经验库与可信度分级、经验检索、自学习/错误学习/效果学习/复盘、九步发送前检查、防重复与防回环 |

> **软件适配统一原则**：微信 / QQ / 企业微信 / 钉钉 / 飞书 / Telegram / Slack / Teams 等**只负责「读取消息 → 识别来源 → 发送消息」**三件事；判断、上下文、风格、学习、复盘**全部由本技能统一处理**，不为每个软件重复建一套消息大脑。换软件只换驱动层（`win-native-app-automation` 的同一套方法），大脑不变。

## 一、入口与最小可用条件

触发场景："帮我看下微信有没有要回的""自动回复我的消息""这个客户该怎么回"。

1. **驱动层就绪**：先按 `win-native-app-automation` §0.5 证明通道活着（探活 + 看屏），不在死服务上烧轮次。
2. **消息来源确认**：当前前台窗口 / 会话 / 联系人**必须截图肉眼确认**（UI 树读不到应用子控件是常态）。
3. **消息唯一标识**：每条消息取一个稳定唯一标识（会话 ID + 发送者 + 时间戳 + 正文摘要哈希；或消息列表里的 msg id），用于 §十三 去重。
4. **模式声明**（发送前必须明确，缺省为"仅草拟"）：
   - `draft`｜只生成草稿，人工确认后由人工发（**默认**）。
   - `auto`｜对**该联系人/该场景**已获用户授权，且通过 §九 全部检查后自动发送。
   - `skip`｜只读不处理。

> **授权是联系人×场景级的，不是全局一次性。** 用户说"以后这类消息你直接回"时，要落到具体联系人或具体场景（如"工作群里问排期的"），不要扩散到所有会话。

## 二、消息识别与分类

收到一条消息，先抽 5 个维度：

| 维度 | 内容 |
|---|---|
| 来源 | 联系人 / 群聊 / 服务号 / 系统消息；私聊还是群，群里是否 @我 |
| 类型 | 提问 / 请求 / 通知 / 确认 / 闲聊 / 转发 / 文件 / 广告 |
| 重要度 | 重要 / 普通 / 低价值 |
| 场景 | 工作 / 生活 / 客服 / 预约 / 售后 / 通知 / 闲聊 |
| 上下文 | 见 §五，取最近一段对话 |

**默认分类处置**：

| 类别 | 处置 |
|---|---|
| 重要 | 优先处理；拿不准 **先确认再回** |
| 普通、明确、低风险 | 可自动回复（须过 §九） |
| 低价值 / 闲聊 | 轻量回复或跳过 |
| 广告推广 / 垃圾 | **默认跳过**，不回复 |
| 群通知 / 系统消息 | 一般不回复；影响本人时才处理 |
| 无关消息 | 跳过 |

---

## 三、是否回复的判断（三态）

| 判断 | 条件 |
|---|---|
| **回复** | 明确提问/请求，且在 §一 授权范围内，风格与风险都清楚 |
| **先确认** | 意图不明、涉及 §十四 边界、或信息不足以答 |
| **跳过** | 广告、垃圾、系统通知、纯无需回应的信息 |

> 判据顺序：**对象正确 → 上下文清楚 → 确实需要回 → 风险允许 → 才进入生成**。任一不满足就先不动。

---

## 四、联系人 × 场景 经验模型

**键**：`联系人/群聊 + 消息类型 + 场景` → 回复方式。

每个键下学习维度：

- 回复长短（一句 / 展开）
- 正式程度（正式 / 半正式 / 随和）
- 常用表达与口头禅
- 称呼（名字 / 昵称 / 职务 / 省略）
- 语气（礼貌 / 直接 / 热情 / 克制）
- 沟通节奏（秒回 / 慢回 / 一次说清 / 多条短句）
- 常见场景（这个联系人反复出现的主题）

**硬规则**：
- **风格独立学习，绝不串用**——不把 A 的沟通习惯套到 B 上。
- **以近期实际交流为准**：联系人风格变化时，逐步降低旧习惯权重，**不永久套用旧规则**。

---

## 五、连续对话上下文

生成回复前必须先取"当前正在讨论什么"，至少覆盖：

- 当前正在讨论的问题
- 前文已经说过的内容
- 尚未完成的事项（承诺、待办、待确认）
- 近期关键内容

**目标**：避免重复、遗漏、前后矛盾。若与上文冲突或上文未解决 → 先回到 §三 的"先确认"，不硬答。

---

## 六、经验库

- **存储**：`messages-experience.md`（与本技能同目录，跨项目持久）。
- **单条经验结构**：
  `联系人/群聊 → 场景/消息类型 → 最优回复方式(含 why) → 易错点 → 历史失败原因+正确做法 → 可信度 → 验证状态 → 人工修改记录 → 更新时间`
- **可信度分级**：

| 状态 | 含义 | 可否覆盖高可信经验 |
|---|---|---|
| 候选 | 第一次成功 / 未验证 | ❌ 只能参考 |
| 已验证 | 少量场景验证有效 | ⚠️ 同场景可用 |
| 多次验证 | 多场景稳定有效 | ✅ 优先复用 |
| 失败 | 验证后被否定 | 降低优先级 |
| 过期 | 联系人习惯 / 软件 / 场景已变 | 自动降级 |

> 与 `knowledge-governance` 一致：**更新旧经验，不无限新建重复经验。**

---

## 七、经验检索优先级（收到新消息时按此顺序查）

1. 当前联系人经验
2. 当前群聊经验
3. 相似消息类型
4. 相似场景
5. 成功案例
6. 失败案例
7. 人工修改案例
8. 已验证策略
9. 最近形成的新经验

**高可信经验优先复用；没有合适经验时再生成新回复方式**（对应 absorbed-from：CUA Skill 的"检索复用优先于试错"）。

---

## 八、统一执行优先级

**回复内容链**：
`高可信经验 → 近期稳定联系人经验 → 当前场景已验证策略 → 已验证的更快方法 → 新生成方案 → 低可信经验 → 重新判断`

**软件操作方式链**（交给 `windows-ops-experience` 决策）：
`已验证成功路径 → 更少步骤路径 → 更快路径 → 备用路径 → 重新探索`

细化规则：
- 第一优先：当前联系人 + 当前场景**存在多次验证成功的方法** → 直接复用。
- 第二优先：**近期且稳定**的联系人经验。
- 第三优先：当前场景**已验证有效**的策略。
- 第四优先：多方案都能完成时，优先**步骤更少 / 更快 / 更稳 / 更少出错**。
- 第五优先：经验不足 → 按当前上下文生成新回复。
- 第六优先：**候选 / 单次成功经验只能参考，不能覆盖高可信经验**。
- 第七优先：历史经验与当前情况明显冲突 → **重新判断，不强行套用**。

## 九、自动发送前检查（九步，严格按序，不得跳过）

| # | 检查 | 通过条件 | 不通过动作 |
|---|---|---|---|
| ① | **对象检查** | 确认是谁发的、哪个联系人/群、**当前发送窗口正确**、没发给错人 | 对象不确定 → **不发** |
| ② | **消息检查** | 回复对应的是哪条、**是否已处理/已回复**、是否新消息、**是否 Agent 自己发的** | 有重复风险 → **不发** |
| ③ | **上下文检查** | 对方真正问什么、前面是否已答、有无未解决问题、是否与上下文一致 | 上下文不清 → 先重新判断，不直接发 |
| ④ | **意图检查** | 确实需要回复、回复能解决问题、不是广告/垃圾/系统通知 | 不需要 → 跳过 |
| ⑤ | **风格检查** | 用了正确联系人的风格、长短合适、语气自然、称呼正确、与近期习惯一致 | 明显不匹配 → 重新生成 |
| ⑥ | **内容检查** | 答到重点、无明显错误、无遗漏关键、无多余废话、无重复已说信息、不易被误解 | 不符合 → 修改后**重新检查** |
| ⑦ | **风险检查** | 不涉及 §十四 任一高危项 | 存在高风险 → **不自动发**，交用户确认 |
| ⑧ | **发送必要性** | 「现在发这句，会不会比不发更好？」 | 无实际价值 → **不发** |
| ⑨ | **发送** | 前八步全部通过 → 调用驱动层发送 | 发送后进入 §十 |

**统一原则**：`对象正确 → 消息正确 → 上下文正确 → 确实需要回 → 风格正确 → 内容正确 → 风险允许 → 确有发送必要 → 才发送。`

> 安全判断**调用已有安全/权限能力**（`personal-ai-os` §六 L0/L1/L2 + §三十八 敏感数据），本技能不重复实现。

## 十、发送后检查

1. 是否成功发送（驱动层证据：输入框清空 + 气泡出现在记录里，二者缺一不可）。
2. 是否发送失败。
3. 是否重复发送。
4. 是否仍在正确聊天窗口。
5. 是否需要进入后续观察（§十一 效果学习）。

**发送失败不盲目重复发送**：先辨失败类型——瞬时（网络/焦点）→ 退避重试一次；确定性（账号限制/控件缺失）→ 换路或停手上报。具体验证走 `wb-artifact-verification`。

## 十一、自学习（四类）

**A. 成功学习**（每次实际回复后提炼）
学习：什么情况该回 / 不该回、谁适合什么风格、什么回复最简洁有效、什么回复容易被误解、什么回复常被人工修改、什么回复能减少追问、什么时候一句话即可、什么时候必须详细说明、什么时候应先确认信息。
→ 新方法**必须与历史方法比较，并通过实际使用逐渐验证后才提高优先级**。

**B. 错误学习**（用户修改 / 重写 / 否定 / 纠正回复时）
分析：原回复哪里错、为什么错、修改后好在哪里、以后应怎么处理。
记录：`场景 → 原回复 → 问题 → 正确做法 → 应避免的方式`。
→ 遇相似联系人/场景/消息类型时，**降低错误方式优先级**。

**C. 效果学习**（观察回复后的实际结果）
观察：是否继续追问、是否需要再次解释、是否发生误解、是否被人工修改、对话是否顺畅、是否产生不必要来回。
→ 根据**多次真实结果**调整策略；**不因一次偶然成功或失败就改长期规则**。

**D. 复盘优化**（见 §十六 触发）
- 内容：是否答到重点 / 遗漏 / 重复 / 过长 / 过短 / 需更多解释 / 有多余解释。
- 风格：是否符合联系人 / 自然 / 正式度正确 / 符合历史习惯。
- 效率：是否一次解决 / 产生额外追问 / 有更短表达 / 有更快处理方式。
- 学习：有没有新经验 / 旧经验失效 / 更好的新方法 / 值得更新策略。

---

## 十二、越用越聪明

持续比较：旧法 vs 新法、快 vs 慢、准确 vs 不准确、自然 vs 生硬、一次解决 vs 多次追问、常被修改 vs 很少被修改。

三阶段目标：
1. **第一次**：按规则判断。
2. **第二次**：参考已有经验。
3. **多次后**：直接使用高可信策略。

随使用增加应减少：试错、人工修改、重复解释、无效沟通、错误回复。

---

## 十三、防重复与防回环（硬约束）

必须防止：同一消息重复处理、同一消息重复发送、**Agent 回复自己**、网络延迟造成重复发送、界面刷新造成重复识别、发送失败无限重试、**自动回复形成循环**。

措施：
- 每条消息用**唯一标识去重**（§一.3），处理过就跳过。
- **识别到 Agent 自己发送的消息立即忽略**（发送前先记录自己发出的正文哈希）。
- 发现**异常连续自动回复**（如同一会话短时间内自触发多次）→ **立即停止继续回复**并上报。
- 发送失败按 §十 分级处理，不无限重试。

---

## 十四、自动回复边界（不擅自代表用户决定）

涉及以下内容**不自动发送**，交给用户确认（走 `personal-ai-os` §六 L2）：

金钱 / 付款 / 转账 / 借款 / 合同 / 重要承诺 / 重大工作决定 / 账号安全 / 密码·验证码 / 敏感信息 / 争议事项 / 无法准确判断用户真实意图 / 可能造成重大后果的回复。

> 只做"该回什么"的**判断与草拟**；"能不能替用户答应"永远交回用户。

---

## 十五、经验精简 · 冲突处理 · 资源控制

**经验精简**：不追求保存更多聊天记录。重点保存——联系人风格 / 群聊风格 / 场景规律 / 成功策略 / 失败策略 / 人工修改规律 / 回复效果 / 策略可信度 / 最近变化。
自动：合并重复经验 / 降低长期无效经验 / 清理过期经验 / 保留高价值成功案例与关键失败案例 / 合并相似策略。
> 目标：**经验越来越精，而不是越来越多。**

**经验冲突处理**（优先级从高到低）：
`当前上下文 > 当前联系人近期习惯 > 当前场景经验 > 多次验证经验 > 普通历史经验`
> 不因很久以前的一次回复，覆盖近期稳定习惯。

**资源控制**：合并重复经验 / 清理无价值经验 / 降低过期经验优先级 / 保留关键经验 / 避免大量重复记录。（与 `personal-ai-os` §三十七 资源边界一致。）

---

## 十六、自动复盘触发

以下情况自动复盘：一段对话结束 / 用户修改回复 / 用户否定回复 / 回复后多次追问 / 回复出现误解 / 回复明显成功 / 重复场景再次出现 / 新策略首次验证 / 原有策略连续表现变差。

**普通低价值消息不复盘，保持轻量。**

---

## 十七、最终闭环

```
识别消息 → 判断是否回复 → 识别联系人与场景 → 获取连续上下文 → 检索历史经验
→ 统一执行优先级 → 选择回复风格 → 生成回复 → 九步发送前检查 → 判断是否允许自动发送
→ 回复 → 观察结果 → 学习成功 → 学习错误 → 优化复盘 → 更新经验 → 下次优先复用 → 持续优化
```

---

## 十八、核心目标

不是简单自动回复，不是单纯保存聊天记录，不是机械套模板。而是让 Agent 真正逐渐学会：谁该怎么回、什么该回、什么不用回、什么消息重要、谁喜欢简短、谁需要详细、谁适合正式、谁适合随和、什么情况直接答、什么情况先确认、以前哪里回错、为什么错、用户通常怎么改、哪种回复一次解决、哪种容易产生追问、哪种方式最快最自然、哪些旧经验已过期。

最终：**越用越懂用户 → 越用越懂联系人 → 越用越懂场景 → 越用越会回复 → 越用越少出错 → 越用越少人工修改 → 越用越快。**
