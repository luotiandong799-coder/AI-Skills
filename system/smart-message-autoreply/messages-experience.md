> 驱动细节（怎么点、怎么发）在 `win-native-app-automation`；操作方式择优在 `windows-ops-experience`。

## 十、本机巡检实测（驱动层事实 · 2026-10-06）

> 只记**跨会话可复用**的事实；操作细节同步进了 `win-native-app-automation` §9.2 / §10.1。

- **windows-mcp 本会话未接线**：`ToolSearch` 无 `mcp__windows-mcp__*` → 按 SKILL §2 降级走内置 PowerShell 跑 `.ps1`，`Add-Type` 在 `.ps1` 内不被拦。可行，无需 MCP。
- **★ 视觉通道已通（重要更正）**：`Read` 工具**能直接读 PNG 截图**，中文会话文本清晰可读。旧结论「Read 读 PNG 被模型侧过滤、只能靠 windows-mcp Snapshot」**已作废**。→ 巡检链路可简化为「截图落盘 → 裁剪放大 → Read 看图」。
- **微信主窗常驻托盘态**：`MainWindowHandle=0`、`IsWindowVisible=False`、`title=[]`。须 `EnumWindows` 按类名 `Qt51514QWindowIcon` 找主窗（本机本轮 hwnd=17762964，**随进程重启变化，禁硬编码**），再 `ShowWindow(9)` + `SetWindowPos(TOPMOST)` + `AttachThreadInput` 借前台线程置前，才能截到有效图。
- **未读角标阈值需按窗宽换算**：`#FA5151` 判定 `|R-250|≤12 && |G-81|≤30 && |B-81|≤30`；在 1438×1387 主窗下角标为 **15×16、fill≈0.79~0.82**；**带数字的角标（"1"）会到 20~27px**，别按尺寸上限剔除。判据须限定**头像列 x 区间**。
- **★ 左侧导航栏有两处红色物 ≠ 会话未读（本机实测误判源）**：① 「微信」导航图标的数字角标（本机 x≈62..86）② 「发现」图标的红点（x≈68..80）。会话未读角标在**头像右上角**（本机 x≈176..190）。只筛 `x>=150` 即可排除这两类假阳性。
- **PowerShell 5.1 C# 语法坑**：`GetWindowThreadProcessId(h, out uint z)` 内联 out 声明编译失败 → 必须 `uint z; ... out z`。写 `.ps1` 内联 C# 时一律用 C# 5 语法。
- **本轮（2026-10-06 10:56）实际结果**：巡检开工时微信在跑、已成功截屏并枚举；**中途 `Weixin.exe` 进程整体退出**（非本流程关闭；同机 Steam/雷神加速器在运行，疑用户主动关或异常退出）→ 未能逐条处理。退出前已确认的未读会话共 4 个：**日常用品（免打扰群）· 酒（免打扰群）· 吃喝（免打扰群）· QQ邮箱提醒（服务号）**，按 §二/§三 默认规则**全部属「跳过」**，即正常跑到也不是 0 回复之外的结论。
- **待人工决策项**：微信被用户关闭时，自动化**是否应自行拉起**。本机既有强制规则「不自动开关，开关只按用户明确指令」与巡检任务目标冲突 → 本轮按「长期规则优先」**未拉起**，仅记录并上报。
