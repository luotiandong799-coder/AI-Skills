## 二、硬约束（红线，全文任何一节不得违反）

1. 不虚构文献、DOI、页码、作者、出版信息。检索不到就标记「待补」，不编造。核验入口（Edge 知网）与逐条取证流程见 **§R01 六「引用真实性硬规则」**（全文单源，中英文文献同等核验）。
2. 不虚构数据、企业事实、案例细节。缺数据写缺口，不用行业均值冒充企业实际。
3. 不承诺通过知网、维普或任何 AIGC/查重检测；本地预检不能代替学校指定平台的正式检测。
4. 不用制造错别字、破坏语法、故意降质的方式处理检测问题。
5. 润色时数字、公式、术语、引用键、参考文献条目保持原样；确需改动必须逐条列出并请用户确认。
6. 每个识别出的问题必须有对应的原因分析与优化措施，禁止问题与对策不对应。
7. 不把行业普遍情况写成该企业的真实情况；不把其他企业数据替换研究对象数据。
8. 不同论文项目的资料必须隔离，禁止跨项目混用企业资料与研究数据。

### M01 · 01 选题与开题

#### 目标

产出一份能直接交给导师的开题报告，而不是一个听起来不错的想法。开题的本质是**证明这件事做得成**：有对象、有问题、有证据、有方法、有工作量。

#### 输入

先确认三件事，缺一件就先问，不要猜：

1. 方向：仓储管理 / 库存管理 / 仓储与库存综合优化。
2. 可获得的资料：入库单、出库单、库存台账、拣选记录、盘点表、仓库布局图、WMS 截图、访谈机会、实地观察次数。
3. 学校要求：字数、章节数、格式模板、是否要求外文文献、开题答辩时间。

#### 一、选题可行性四问

| 问题 | 不合格的表现 | 处理 |
|---|---|---|
| 研究对象可接触吗 | 只有「某电商企业」这种泛指，拿不到任何内部资料 | 改成可接触的具体仓库或公开资料充分的对象 |
| 问题真实存在吗 | 结论先行，先想好「库存过高」再找证据 | 先看数据，让数据决定问题 |
| 数据能支撑结论吗 | 想用 EOQ 模型但拿不到需求量和订货成本 | 降级方法，或换题 |
| 工作量匹配本科吗 | 要做全仓仿真、要建模求解多目标优化 | 缩到单仓、单品类、单流程 |

本科论文的现实约束：3–6 个月、1.5–2 万字、一人完成、不能长期驻场。任何需要全年数据、多仓对比、系统开发才能完成的题目都要降级。

#### 二、选题的三档资源条件

先判定属于哪一档，再决定研究设计。**不要用 A 档的写法包装 C 档的资料。**

| 档 | 条件 | 可做 | 不可做 |
|---|---|---|---|
| A | 有企业原始数据（≥3 个月） | 案例分析 + 指标计算 + 问题诊断 + 优化方案 | 无 |
| B | 只能实地观察、访谈、拍照 | 流程观察 + 作业环节拆解 + 定性问题 + 少量计数（如日均订单数、拣货次数） | 周转率、安全库存等需要台账的指标 |
| C | 无企业条件 | 文献研究 + 公开数据 + 行业对比 + 制度建议 | 任何声称「某企业实际数据」的定量分析 |

C 档不是不能写，但必须在开题时就说明资料边界，不能等到答辩被问。

#### 三、标题规范

结构：**基于〔方法/视角〕的〔对象〕〔问题〕研究**。

- 好：「基于 ABC 分类的 A 仓储公司库存结构优化研究」
- 差：「仓储管理优化研究」（无对象、无问题、无边界）
- 差：「基于大数据与人工智能的智慧仓储体系构建」（本科无法完成，方法无对应数据）

标题里的方法必须真的会用，不能只是装饰。

#### 四、研究背景四段式

1. **行业背景**：仓储/库存在供应链中的位置、近年成本或效率变化。必须有来源。
2. **政策与趋势**：相关国家标准、行业报告、政策文件。有就写，没有不硬凑。
3. **对象背景**：企业或仓库的规模、业务类型、仓储面积、SKU 数量、人员配置。必须是事实。
4. **问题引出**：由前三段自然推出「因此本文研究 X」，不要突然转折。

禁止：整段宏大叙事（「随着我国经济快速发展……」）超过 200 字仍无具体信息。

#### 五、研究意义

- **理论意义**：克制。本科论文一般不需要声称理论创新，写「补充了某类企业/某类场景的案例证据」即可。
- **实践意义**：具体到可操作。写「为同类企业提供货位调整参考」而不是「具有重要意义」。

#### 六、研究内容与技术路线

研究内容必须与章节一一对应，一章一条，不多不少。

技术路线用文字 + 一张流程图，节点就是章节：提出问题 → 现状描述 → 问题识别 → 原因分析 → 方案设计 → 可行性评估 → 结论。图里出现的每个节点，正文都要有对应章节。

#### 七、开题报告自检

- [ ] 研究对象具体到可核实的名称与范围
- [ ] 每个拟研究的问题都有证据来源指向（哪张表、哪次观察、哪份记录）
- [ ] 方法能回答提出的问题（问题问「为什么慢」，方法不能只做 ABC 分类）
- [ ] 数据来源与获取方式写明，含时间范围
- [ ] 没有「拟采用 XX 模型」却没有任何建模所需数据
- [ ] 研究内容与章节一一对应
- [ ] 字数与工作量匹配学校要求

#### 八、常见错误

1. 题目大而空，正文只能写行业综述。
2. 方法与问题不匹配：问题是布局不合理，方法却是问卷调查。
3. 开题写「将使用仿真软件」，实际不会用也没有数据。
4. 研究意义写成宣传稿。
5. 技术路线图画得很漂亮，但与正文章节对不上。


### M02 · 02 文献检索与综述

#### 目标

找到真实存在、能支撑论点的文献，并写成有判断的综述，而不是文献罗列。

#### 一、检索层级（按优先级）

| 层级 | 类型 | 用途 | 说明 |
|---|---|---|---|
| 1 | 硕士学位论文 | 结构与同类问题参考 | 优先，因为研究设计完整、方法可模仿 |
| 2 | 中文核心期刊 | 观点与方法依据 | 比硕士论文更凝练，适合引用观点 |
| 3 | 国家标准/行业标准 | 概念与指标定义 | 如仓储作业、库存管理相关国标 |
| 4 | 官方统计与行业报告 | 行业背景数据 | 需注明发布机构与年份 |
| 5 | 外文文献 | 满足学校要求时 | 不必强求，能读懂再用 |

本科论文不建议以网络文章、百科、公众号作为学术依据。

#### 二、检索式构造

主题词 + 同义词 + 限定。示例：

- 仓储方向：仓储管理、货位分配、货位优化、拣选路径、仓库布局、仓储作业效率、WMS
- 库存方向：库存管理、ABC 分类、安全库存、订货点、库存周转率、呆滞库存、补货策略
- 综合：仓储与库存、库存结构优化、作业效率与库存成本

组合方式：`(仓储 OR 仓库) AND (布局 OR 货位) AND 优化`。检索不到就换同义词，不要直接判定「没有研究」。

#### 三、文献真实性核验（强制，逐条做）

一条文献进入参考文献前，必须过四关：

1. **可检索**：在知网、万方或对应数据库中能查到。
2. **信息匹配**：作者、年份、题名、期刊/学校、卷期页码与检索结果一致。
3. **内容匹配**：文献确实说了你要引用的那句话，不是标题相近就引。
4. **可追溯**：有 DOI 就记 DOI；没有则记录数据库来源与检索日期。

任何一关不过，标记「待核」，不得写入正文引用。**宁缺不假。**

#### 四、文献矩阵

用 §T03，字段固定：

| 编号 | 作者 | 年份 | 题名 | 来源 | 研究对象 | 方法 | 核心结论 | 局限 | 与本文关系 | 核验状态 |
|---|---|---|---|---|---|---|---|---|---|

「与本文关系」必须写清是支撑、对照还是反驳，不能空着。

#### 五、综述写法

##### 结构

按**主题**组织，不按时间流水账。每个主题一段或一小节，内部结构：

1. 该主题下学界关注什么（有共识的部分）
2. 用了什么方法、什么数据
3. 得出了什么结论
4. 还有什么没解决（研究不足）
5. 本文在这个主题上做什么

##### 判断句要求

综述必须有作者判断，不能只有「A 认为……B 认为……C 认为……」。至少要有：

- 归纳：多数研究集中在哪类企业、哪类方法
- 对比：两种结论为何不同（样本、口径、行业差异）
- 缺口：哪类场景、哪类数据还没被覆盖

##### 禁止

1. 编造文献、DOI、页码、作者。
2. 写「研究表明」却不给出处。
3. 把硕士论文的结论直接当成本文结论。
4. 一段引 8 篇却没有任何归纳。
5. 文献综述与研究问题无关，只为凑字数。

#### 六、检索记录

每次检索记录：数据库、检索式、时间范围、命中数、纳入数、排除原因。写入项目资料夹。这样导师问「你怎么找的」时能答，也能证明没有选择性引用。

#### 七、自检

- [ ] 每条文献都过了四关核验
- [ ] 综述按主题而非时间组织
- [ ] 有归纳、有对比、有缺口
- [ ] 研究不足与本文研究内容对应
- [ ] 文内引用与文献矩阵编号一致
- [ ] 无编造、无无出处归因


### M03 · 03 仓储管理专业知识

#### 目标

把仓储作业讲成「流程 + 问题 + 证据 + 改进」，而不是抄教材定义。

#### 一、仓储作业主线

收货 → 验收 → 上架 → 存储 → 拣选 → 复核 → 出库 → 盘点。每一环都可以成为论文的问题点，但**一次只研究一到两个环节**，本科论文不要全流程铺开。

#### 二、各环节的问题诊断点

| 环节 | 常见问题 | 可观察/可取的证据 | 常用改进手段 |
|---|---|---|---|
| 入库验收 | 验收标准不清、抽检比例随意、单据与实物不符 | 验收记录、差错单、退货记录 | 明确验收标准与抽检规则、单据前置 |
| 上架 | 上架随意、未按周转率分区、重货高放 | 上架记录、库位图、现场观察 | ABC 分区、重下轻上、就近上架 |
| 存储 | 通道被占、混放、标识缺失 | 布局图、现场照片、通道宽度实测 | 分区分类、五五堆放、标识标准化 |
| 货位管理 | 固定货位导致空间浪费、随机货位导致寻找时间长 | 货位占用率、寻找时间记录 | 固定+随机混合、按周转率分配 |
| 拣选 | 行走路径长、找货慢、错拣 | 拣货单、行走路线、拣货时间 | 批量拣选、分区拣选、路径优化、货位重排 |
| 复核出库 | 复核流于形式、错发漏发 | 差错台账、客户投诉 | 复核清单、扫码校验 |
| 盘点 | 账实不符、盘点周期过长 | 盘点表、差异率 | 循环盘点、ABC 分级盘点频次 |
| 信息化 | WMS 只用基础功能、数据不回流 | 系统截图、功能清单 | 功能启用建议、数据看板 |

#### 三、常用效率指标（只引用编号，不重复列式）

公式与完整定义唯一来源：§R05。本模块只列指标编号与口径易错点，正文引用编号即可。

| 指标 | 编号 | 口径易错点 |
|---|---|---|
| 日均吞吐量 | W1 | 单位（件/箱/托/吨）与统计期必须写明 |
| 人均拣货量 | W2 | 是否含复核与补货 |
| 平均拣货时间 | W3 | 是否含找货、行走 |
| 拣货准确率 | W4 | 以行还是以订单为单位 |
| 订单满足率 | W5 | 「按期」「完整」的定义 |
| 空间利用率 | W6 | 按库位数还是按体积 |
| 库存准确率 | W7 | 抽查方法与样本量 |
| 盘点差异率 | W8 | 差异方向（盘盈/盘亏） |

使用时回到公式库核对参数来源；拿不到参数就写缺口，不用假设值冒充企业实际。

#### 四、布局与货位

- **布局**：功能区划分（收货区、存储区、拣选区、发货区）、动线是否交叉、通道宽度是否满足设备。
- **货位分配**：按周转率（快销靠近出口）、按相关性（常一起拣的放近）、按重量（重货低层）。
- 改进方案必须能落到「哪一类货移到哪个区」，不能只写「优化布局」。

#### 五、写作要求

1. 每个问题配一条证据（数据、观察、单据）。
2. 每个改进措施对应一个具体问题，不写通用建议。
3. 不堆理论：不要用大段篇幅解释什么是仓储，除非学校要求。
4. 引用教材定义时注明出处，但不要整节抄。
5. 涉及 WMS 时，只写你实际看到或资料证实的模块，不臆测功能。

#### 六、常见错误

1. 全文都是「应当加强管理」，没有一条可执行措施。
2. 用行业平均数据代替本企业数据。
3. 问题、原因、对策三张皮，互不对应。
4. 声称做了仿真或建模，实际没有。


### M04 · 04 库存管理专业知识

#### 目标

每个方法都写清**适用条件**，不为显得专业而强行套模型。没有数据就不做定量。

#### 一、库存分类

##### ABC 分类

- 依据：年消耗金额（单价 × 年用量），不是单价，也不是库存数量。
- 常规分界：A 类累计金额约 70%–80%，B 类约 15%–20%，C 类约 5%–10%。**具体比例由数据决定，写清所用口径。**
- 用途：分级管理，A 类严控、C 类简化。
- 边界：ABC 只做分类，**本身不是优化方案**。分类之后要有对应策略，否则等于没做。

##### 补充方法

- CVA（关键性分类）：按缺货后果分级，适合关键备件。
- VED（Vital/Essential/Desirable）：按重要性分级，适合医疗、设备维护场景。
- 二维矩阵：金额 × 周转率，用于识别「高价值慢动销」。

#### 二、安全库存

公式见 §R05 的 I6。本节只写用法，不重复列式。

- Z：服务水平对应系数（95% 约 1.65，97.5% 约 1.96，99% 约 2.33），取值依据必须写明。
- σd：单位时间需求标准差，与提前期的时间单位必须一致。
- 提前期也不稳定时需合并 σLT 的方差，属进阶用法，本科论文一般不要求。
- **没有历史数据就算不出 σ，不要硬套公式**，改为定性说明库存保障方式。

必须写清：服务水平取值依据、需求时间粒度、数据区间。

#### 三、订货点与补货

订货点公式见公式库 I7。本节只写策略选择。

- 定量订货：固定订货量、触发式补货，适合 A 类。
- 定期订货：固定周期、订货量浮动，适合 C 类或供应商有固定配送周期时。
- 双箱法：适合低值易耗、管理成本敏感的场景。

选择依据写清：需求稳定性、订货成本、供应周期、管理能力。

#### 四、EOQ（经济订货批量）

公式见公式库 I8。本节只写适用前提。

- 需求稳定、订货成本与持有成本可估、无数量折扣、无缺货。
- 本科论文常见问题是 S（每次订货成本）和 H（单位年持有成本）拿不到真实值却直接给一个数。**拿不到就说明是假设值并做敏感性说明。**

#### 五、周转指标

指标编号与口径见公式库 I1、I2、I3、W7，正文引用编号，不重复写公式。本节只列易错点。

| 指标 | 编号 | 易错点 |
|---|---|---|
| 库存周转率 | I1 | 分母用销货成本，不是销售额 |
| 库存周转天数 | I2 | 平均库存不能只取期末值 |
| 呆滞库存占比 | I3 | 呆滞判定天数阈值必须写明 |
| 库存准确率 | W7 | 抽查方法与样本量必须写明 |

常见错误：用销售额代替销货成本；平均库存只取期末数；不同品类混算一个周转率。

#### 六、呆滞库存

判定需要三个要素：时间阈值（如 90 天无出库）、数量或金额阈值、是否含备件。三者都要写明。处理路径：识别 → 分类（可退、可调、可折价、报废）→ 处置建议 → 预防机制（需求预测、订货审核）。

#### 七、写作要求

1. 每个方法先写适用条件，再写计算，再写结果解释。
2. 公式只写一次，放 §R05，正文引用。
3. 数据不足时降级为定性分析，不虚构参数。
4. 结论要能回答「所以应该怎么做」，不能只报数字。
5. 区分「行业通行做法」与「本企业实际做法」。

#### 八、常见错误

1. 把 ABC 分类当成优化成果。
2. 安全库存 Z 值不说明，直接给 1.65。
3. EOQ 参数全靠假设却不标注。
4. 周转率算出来但不解释高低的业务含义。
5. 用复杂模型掩盖数据缺失。


### M05 · 05 研究方法

#### 目标

选一个能真正回答研究问题的方法，并写清操作过程，让读者相信结果不是编的。

#### 一、方法—问题匹配表

| 研究问题 | 适配方法 | 不适配 |
|---|---|---|
| 现状是什么样 | 实地观察、单据统计、描述性指标 | 问卷（问不出流程细节） |
| 问题出在哪个环节 | 流程拆解 + 时间/差错数据 | 纯文献研究 |
| 为什么会出现 | 访谈、因果链分析、对比 | 单纯算指标 |
| 改进后是否更好 | 前后对比、试算、情景假设 | 无数据的建模 |
| 同类企业怎么做 | 多案例比较、公开资料对比 | 单案例强行推广 |

#### 二、常用方法

##### 文献研究法

用途：界定概念、找研究缺口、提供方法依据。写法：说明检索范围、筛选标准、纳入数量。不能只写「本文采用了文献研究法」一句。

##### 案例分析法

用途：单企业深入分析。要求：说明选它的理由（典型性、可接触性），说明资料边界，说明结论适用范围（不外推）。

##### 实地观察法

用途：流程、布局、作业动作。要求：观察时间、次数、记录方式、观察表。写「笔者于 X 年 X 月在 X 仓库观察 N 次，每次 X 小时」。

##### 比较分析法

用途：不同时段、不同区域、不同品类对比。要求：对比口径一致，说明差异来源。

##### 指标分析法（Excel）

用途：周转率、准确率、效率。要求：公式、口径、数据来源、计算过程可复现。

#### 三、硬规则

1. 没有数据不得做定量研究。缺数据就降级为定性或描述性分析，并在方法章节说明。
2. 不虚构访谈对象、观察次数、样本量。
3. 方法章节要写操作过程，不是方法定义。写「怎么做的」，不写「什么是案例分析」。
4. 多方法要说明分工：哪个方法回答哪个问题。
5. 三角验证：关键结论最好有两条证据来源（数据 + 观察/访谈）。

#### 四、方法章节写法

结构：

1. 研究思路（一段话串起全文逻辑）
2. 资料收集（来源、时间、范围、工具）
3. 分析方法（每个方法对应哪个问题）
4. 数据说明（口径、局限）

长度控制在全文 8%–12%，不要写成一门课程笔记。

#### 五、自检

- [ ] 每个方法都对应一个具体研究问题
- [ ] 资料收集有时间、地点、数量
- [ ] 没有无法执行的「拟采用」
- [ ] 数据局限已说明
- [ ] 结论没有超出资料范围


### M06 · 06 数据处理与分析

#### 目标

用 Excel 把数据变成可信的指标和图表，过程可复现，口径可解释。

#### 一、工具优先级

1. Excel：默认。清洗、透视、指标、图表够用。
2. workbuddy-sheetagent / workbuddy-sheet-generation：批量处理与成表。
3. Python：仅当数据量大（万行以上）、需要重复计算、或 Excel 公式难以维护时。
4. 不默认引入 SPSS、Jupyter、复杂预测算法。本科论文用不上，引入反而增加不可解释风险。

#### 二、数据清洗四步

1. **去重**：同一单据重复导入、同一 SKU 多条记录。
2. **缺失**：标出缺失比例；缺失超过 20% 的字段不用于核心结论。
3. **异常**：负库存、超大值、日期越界。逐条核对，不直接删除。
4. **口径统一**：单位（件/箱/托）、时间粒度（日/周/月）、金额口径（成本/售价）。

清洗过程要留记录：删了多少行、为什么删、补了什么。

#### 三、数据字典（必建）

| 字段 | 含义 | 单位 | 来源 | 口径 | 缺失率 |
|---|---|---|---|---|---|

没有数据字典，后面的指标都不可信。

#### 四、指标计算

- 公式统一在 §R05，正文只引用不重复定义。
- 每个指标写：公式、代入数据、结果、业务解释。
- 结果必须解释高低意味着什么，不能只报数。

#### 五、图表规范

1. 有标题、有单位、有数据来源。
2. 坐标轴从 0 开始（除特殊说明）。
3. 一张图只表达一个结论。
4. 图表正文要引用（「如图 4-1 所示」），不能只放图不说话。
5. 图表编号与章节对应：第 4 章用图 4-1、表 4-1。

#### 六、数据真实性检查

| 检查 | 方法 |
|---|---|
| 勾稽关系 | 期初 + 入库 − 出库 = 期末；账实差异能否解释 |
| 合计校验 | 明细合计 = 汇总表合计 |
| 时间连续 | 有无整月缺失、日期跳跃 |
| 单位一致 | 同一列是否混入不同单位 |
| 逻辑合理 | 周转天数是否为负、准确率是否大于 100% |

任何一项不通过，先查原因，不能带病进入分析。

#### 七、常见错误

1. 只给结果不给过程，无法复现。
2. 平均库存只取期末值。
3. 用销售额算周转率。
4. 异常值直接删除不说明。
5. 图表没有单位。
6. 数据来源写「公司提供」，没有时间范围和口径。


### M07 · 07 论文大纲与结构

#### 目标

让章节形成一条论证链，而不是六个互不相干的专题。

#### 一、标准章节（本科常用）

1. 绪论：背景、意义、国内外研究现状、研究内容与方法、技术路线
2. 相关概念与理论基础：只写用得到的，不写教材搬运
3. 研究对象现状：企业/仓库概况、业务流程、数据描述
4. 问题分析：问题表现 + 数据证据 + 原因分析
5. 优化方案设计：针对每个问题给措施 + 实施步骤 + 预期效果
6. 结论与展望：结论、不足、展望

章节数按学校要求调整，但**现状—问题—原因—对策**四段结构不能缺。

#### 二、字数分配（以 1.5 万字为例）

| 章节 | 占比 | 字数 | 说明 |
|---|---|---|---|
| 绪论 | 15% | 2200 | 文献综述不超过本章一半 |
| 概念与理论 | 10% | 1500 | 只写用到的 |
| 现状 | 25% | 3750 | 数据与流程为主 |
| 问题与原因 | 25% | 3750 | 全文核心 |
| 优化方案 | 20% | 3000 | 一一对应问题 |
| 结论 | 5% | 750 | 不重复摘要 |

2 万字按比例放大。学校有明确要求时以学校为准。

#### 三、论证链对应表（写作前必做）

| 问题 | 证据 | 原因 | 对策 | 预期效果 | 章节 |
|---|---|---|---|---|---|
| 拣货时间长 | 拣货时间记录 | 货位随机、动线交叉 | 按周转率重排货位 | 行走距离下降 | 4.2 / 5.2 |

这张表是全文骨架。任何一行填不出来，说明该问题不成立或证据不足。

#### 四、章节衔接

每章末尾用一段过渡说明「本章得出了什么，下一章要解决什么」。过渡段要具体，不写「综上所述，本章分析了现状，下一章将提出对策」这种空话。

#### 五、防失衡

- 绪论超过全文 20% → 头重脚轻，压缩文献综述。
- 理论章超过 15% → 在抄教材，删到只留用到的概念。
- 对策章比问题章短 → 说明对策是凑的，回头补对应关系。
- 某章只有 500 字 → 要么合并，要么说明为什么这么短。

#### 六、大纲自检

- [ ] 每章有明确任务，删掉任何一章论证链会断
- [ ] 问题、原因、对策一一对应
- [ ] 字数分配合理，无头重脚轻
- [ ] 章节标题是陈述句或名词短语，不是问句
- [ ] 图表编号规则统一
- [ ] 与学校模板章节要求一致


### M08 · 08 论文正文写作

#### 目标

按章节写出有论点、有证据、有解释的学术正文，不是把资料堆成段落。

#### 一、写作前先定三件事

每写一节，先写三行：

1. 本节要证明什么（一句话主张）
2. 用什么证据（数据、观察、文献）
3. 证据如何支撑主张（推理一句话）

三行写不出来，说明这节还不该写。

#### 二、段落结构

标准段：**主张 → 证据 → 解释 → 衔接**。

- 主张：段首一句说清这段干什么。
- 证据：数据、单据、观察、文献。
- 解释：这个证据说明什么，为什么。
- 衔接：与上段/下段的关系（可省略，但逻辑要连）。

一段只讲一件事。超过 300 字仍无新信息，就该拆或删。

#### 三、学术表达

- 用「本文」「本研究」，少用「我们」「我觉得」。
- 判断要有依据：「拣货效率偏低」后面必须跟数据。
- 避免绝对化：「完全解决」「彻底消除」改成「缓解」「降低」。
- 术语统一：同一概念全文一个词，不换说法。
- 数字与单位规范：阿拉伯数字用于计量，汉字用于概数。

#### 四、禁止

1. 大段「首先、其次、最后」机械分段。
2. 堆砌理论名词却不解释与本案例的关系。
3. 空泛总结句：「综上所述，仓储管理非常重要」。
4. 用行业普遍情况冒充本企业事实。
5. 段落之间无逻辑，靠「此外」「同时」硬接。
6. 一段里塞三个不相关的点。

#### 五、扩写与精简

##### 扩写（字数不够时）

优先扩「证据」和「解释」，不要扩形容词。具体做法：补数据细节、补计算过程、补业务背景、补与文献的对话。

##### 精简（字数超了）

先删重复总结、空泛评价、与主题无关的背景；再合并同义句；最后才动具体内容。**不要删证据。**

#### 六、章节写作流程

1. 读本章大纲与上一章末尾过渡。
2. 读项目记忆里的术语表与章节摘要，保持术语一致。
3. 先写每节三行主张。
4. 填证据，再写解释。
5. 写完通读，检查段间逻辑。
6. 更新章节摘要到项目记忆。

#### 七、自检

- [ ] 每个论断都有证据
- [ ] 每段只讲一件事
- [ ] 术语前后一致
- [ ] 没有空泛总结与机械编号
- [ ] 问题章与对策章能一一对应
- [ ] 引用处都有真实文献


### M09 · 09 内容去重

#### 目标

降低真实重复，不是把文章删短。必要的概念解释和前后呼应要保留。

#### 一、六类重复

| 类型 | 表现 | 处理 |
|---|---|---|
| 观点重复 | 同一判断在摘要、绪论、结论反复出现 | 保留最完整的一处，其余改为引用或删 |
| 段落重复 | 两段话意思几乎相同 | 合并，保留信息更全的一段 |
| 章节交叉 | 第 3 章讲了第 4 章的问题分析 | 按章节职责拆分，各归其位 |
| 论证反复 | 同一个理由用不同说法说三遍 | 保留一次，其余删 |
| 文献重复 | 同一文献在多处重复引用同一结论 | 合并到首次引用处 |
| 参考文献重复 | 同一文献在文末出现两次 | 去重，保留格式正确的一条 |

#### 二、必须保留的「重复」

1. 摘要与结论的呼应（但结论不能照抄摘要）。
2. 概念首次定义与后文使用（后文不再重复定义）。
3. 章节过渡的必要回指。
4. 图表与正文的对应说明。

判断标准：删掉后读者是否还能理解。能理解才删。

#### 三、检测方法

1. **关键词法**：把核心判断句提取出来，看是否在多处出现。
2. **段落首句法**：读每段第一句，若多段首句意思相同，多半重复。
3. **章节职责法**：给每章写一句话职责，若两章职责重叠，就是章节交叉。
4. **文献表法**：统计每个文献被引次数与引用位置，异常集中处检查。

#### 四、操作顺序

1. 先做章节级去重（结构调整）。
2. 再做段落级去重（合并）。
3. 最后做句子级去重（改写）。

顺序反了会白做：先改句子，后面结构调整又要重来。

#### 五、去重报告

每次去重输出：删除位置、删除原因、保留位置、是否影响论证。用户确认后再改文件。

#### 六、禁止

1. 为降重删掉必要论证与证据。
2. 把表格折成散文算作「合并」。
3. 删除后不检查上下文是否还通。
4. 用同义词替换伪装去重（这是改词不是去重）。


### M10 · 10 学术表达润色

#### 目标

让文字读起来像认真写过论文的人写的，同时一个字的事实都不改。

#### 一、唯一规则源

本模块不重复列规则。所有改写规则、阈值、自检清单以 §R06 为准。执行前先读该文件。

#### 二、工作流程

1. **备份原文**：另存原稿，不覆盖。
2. **诊断**：先指出这篇为什么像 AI 写的（列 3–5 条具体问题，带位置），不要直接改。
3. **改写**：按规则逐条改，每次改动对应一条具名规则。
4. **比对**：数字、公式、术语、引用键、参考文献条目逐项对照原文。
5. **报告**：列出改了哪些类型、删了哪些限定词、哪些地方需要用户确认。

#### 三、长文处理

论文通常 1.5 万字以上，不能一次改完。分章处理：

1. 建术语表：概念、缩写、符号，全文唯一写法。
2. 每章改完写一段 3–8 句的章节摘要（核心论点、固定术语、依赖的图表编号）。
3. 改下一章前先读术语表与已改章节摘要。
4. 发现前后矛盾：轻微措辞不一致自行统一；数据矛盾、逻辑断裂、缺图表则报告用户，不擅自编造。

#### 四、绝对保护清单

以下内容润色时不得改动，除非用户逐条确认：

- 数字、百分比、金额、日期
- 公式、符号、单位
- 术语与缩写
- 文内引用编号与作者年份
- 参考文献条目
- 图表编号与标题
- 学校模板要求的固定表述

#### 五、不做的事

1. 不承诺通过知网、维普或任何 AIGC 检测。
2. 不通过错别字、病句、乱标点规避检测。
3. 不新增文献、数据、案例来「让文章更充实」。
4. 不改变研究结论与论证方向。
5. 不把学术语体改成口语。

#### 六、自检

按 §R06 第七节逐项过。额外确认：

- [ ] 原文与改稿可对照
- [ ] 术语表已更新
- [ ] 章节摘要已更新
- [ ] 需用户确认项已单列


### M11 · 11 引用与格式

#### 目标

文内引用与文末参考文献一一对应，格式符合学校模板，且每条文献真实存在。

#### 一、优先级

1. 学校模板（最高）
2. 导师明确要求
3. GB/T 7714-2015
4. 学院惯例

冲突时以学校模板为准，并在项目记忆里记录版本与日期。

#### 二、GB/T 7714-2015 常用类型

| 类型 | 标识 | 示例结构 |
|---|---|---|
| 专著 | [M] | 作者. 书名[M]. 出版地: 出版社, 年. |
| 期刊 | [J] | 作者. 题名[J]. 刊名, 年, 卷(期): 起止页. |
| 学位论文 | [D] | 作者. 题名[D]. 城市: 学校, 年. |
| 会议论文 | [C] | 作者. 题名[C]//论文集名. 出版地: 出版社, 年: 页. |
| 标准 | [S] | 标准号 标准名称[S]. 出版地: 出版社, 年. |
| 电子资源 | [EB/OL] | 作者. 题名[EB/OL]. (发布日期)[引用日期]. URL. |

#### 三、文内引用

- 顺序编码制：按正文出现顺序编号，`[1]`、`[2]`。
- 著者-出版年制：`（张三, 2023）`。学校要求哪种就用哪种，不混用。
- 同一处引多篇：`[1-3]` 或 `[1,4]`。
- 引用具体观点要标页码（若学校要求）。

#### 四、核验流程

1. 导出参考文献列表。
2. 逐条核对：作者、年份、题名、来源、卷期页、DOI。
3. 检查文内每个编号在文末存在，文末每条在正文被引用（无「僵尸文献」）。
4. 检查重复条目。
5. 检查格式符号：中英文标点、作者分隔符、页码连接符。

#### 五、常见错误

1. 文内有 [12]，文末只有 11 条。
2. 文末有条目但正文从未引用。
3. 同一文献两条不同格式。
4. 学位论文缺学校所在地。
5. 期刊缺卷期或页码。
6. 电子资源缺引用日期。
7. 编造 DOI 或页码。
8. 中英文标点混用。

#### 六、不编造

任何字段缺失，标「待补」并向用户确认，不得凭印象填写。DOI、页码、卷期是最容易编造也最容易被查出的三项。


### M12 · 12 论文质量与答辩

#### 目标

交稿前把能查的都查一遍，答辩前把会被问的都想过一遍。

#### 一、五类核验

| 类型 | 查什么 | 工具 |
|---|---|---|
| 事实核验 | 企业信息、行业数据、政策表述是否有来源 | 人工 + 检索 |
| 数据核验 | 勾稽关系、合计、口径、异常值 | Excel / §C02 |
| 逻辑核验 | 问题—原因—对策是否对应，结论是否超出证据 | 论证链对应表 |
| 文献核验 | 是否真实、文内文末是否对应 | §C03 |
| 格式核验 | 章节、字体、行距、页码、图表编号 | 学校模板 |

#### 二、查重预检

- 本地只能做相似度自查（如段落比对），**不能代替学校指定平台**。
- 自查重点：大段引用未改写、文献综述罗列、方法章节模板化。
- 报告时明确写「本地预检，非正式检测结果」。

#### 三、AIGC 报告分析（只解释，不承诺）

若用户提供检测报告：

1. 定位高标记段落。
2. 判断属于哪类模式（套话、模板结构、空泛结论）。
3. 按 10 模块规则改写。
4. 明确告知：改写提升的是表达质量，不保证检测数值变化。

#### 四、答辩问题准备

按章节准备，每章 5–8 问：

| 章节 | 典型问题 |
|---|---|
| 选题 | 为什么选这个题目？有什么现实意义？ |
| 文献 | 你和已有研究有什么不同？ |
| 方法 | 为什么用这个方法？样本/数据够吗？ |
| 现状 | 数据从哪来？统计口径是什么？ |
| 问题 | 你怎么证明这是问题而不是正常现象？ |
| 对策 | 方案成本多少？实施难点在哪？ |
| 结论 | 你的结论能推广吗？局限是什么？ |

每个问题准备 3–5 句回答，必须有数据或事实支撑，不背套话。

> 答辩 PPT 的内容结构、设计规范与陈述/问答预案见 **§Z**（开题答辩 PPT 是开题报告定稿后的下一步实际产出）。

#### 五、答辩三条底线

1. 不承认没做过的事，也不否认做过的事。
2. 数据来源必须能说清。
3. 不会的问题说「这部分我还没有深入，后续可以补充」，不要编。

#### 六、交稿前清单

见 §C05，逐项打勾，不打勾不交。

### R02 · 仓储管理知识库

通用知识，不含任何具体企业资料。写作时按需取用，不要整节搬进论文。

#### 一、术语

| 术语 | 含义 | 易错点 |
|---|---|---|
| SKU | 最小库存单位，按品类规格区分 | 与「品项」「物料号」混用 |
| 库位 | 仓库中可存放货物的最小位置编号 | 与「货架」「区域」混用 |
| 收货 | 货物到库至入库前的作业 | 与「入库」不是同一环节 |
| 上架 | 将验收后的货物放置到指定库位 | 与「存储」混用 |
| 拣选 | 按订单从库位取出货物 | 与「分拣」不同，分拣是按去向分类 |
| 复核 | 出库前核对货物与单据 | 常被省略，是差错高发环节 |
| 盘点 | 核对账面与实物 | 循环盘点与全面盘点是两种方法 |
| 越库 | 货物不经存储直接转运 | 不适用于需要拆零的场景 |
| 波次 | 将多个订单合并为一批处理 | 与「批量」不完全等价 |
| 动线 | 作业人员在库内的行走路线 | 与「通道」不是同一概念 |

#### 二、作业流程与可控点

收货 → 验收 → 上架 → 存储 → 拣选 → 复核 → 出库 → 盘点

| 环节 | 可控点 | 常见失控表现 |
|---|---|---|
| 收货 | 到货预约、卸货月台分配 | 车辆排队、月台拥堵 |
| 验收 | 抽检比例、验收标准 | 标准模糊、凭经验判断 |
| 上架 | 库位分配规则 | 就近乱放、通道占用 |
| 存储 | 分区分类、堆码方式 | 混放、超高、重货高放 |
| 拣选 | 拣货单排序、路径 | 往返行走、找货耗时 |
| 复核 | 扫码校验、复核清单 | 流于形式 |
| 出库 | 装车顺序、单据交接 | 错发、漏发 |
| 盘点 | 盘点频次、差异处理 | 账实不符长期挂账 |

#### 三、布局类型

| 类型 | 特点 | 适用 |
|---|---|---|
| I 型（直线型） | 收货与发货在两端 | 单向物流、场地狭长 |
| U 型 | 收货与发货在同一侧 | 出入库频繁、共用月台与设备 |
| L 型 | 收货与发货相邻成直角 | 场地受限 |

布局分析要点：功能区是否完整（收货、存储、拣选、发货、退货、暂存）、动线是否交叉、通道宽度是否满足设备转弯半径、扩展余地。

#### 四、货位分配策略

| 策略 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| 固定货位 | 每个 SKU 固定位置 | 易记、易管理 | 空间浪费，淡季空置 |
| 随机货位 | 有空位就放 | 空间利用率高 | 找货慢、盘点难 |
| 分类货位 | 按品类或周转率分区，区内随机 | 兼顾效率与利用 | 需要定期重排 |
| 混合货位 | 快销固定、慢销随机 | 折中 | 规则复杂，依赖系统 |

改进方案必须落到「哪类货移到哪个区」，不能只写「优化货位」。

#### 五、拣选策略

| 策略 | 做法 | 适用 |
|---|---|---|
| 摘果式 | 一人一单，边走边拣 | 订单少、单量大 |
| 播种式 | 汇总拣货后按订单分播 | 订单多、单量小 |
| 分区拣选 | 按区域分工，订单跨区合并 | 库区大 |
| 波次拣选 | 按时间或线路合并订单 | 有配送班次约束 |

### R03 · 库存管理知识库

通用知识，不含具体企业资料。

#### 一、库存类型

| 类型 | 作用 | 判断线索 |
|---|---|---|
| 周转库存 | 满足正常需求 | 与采购批量相关 |
| 安全库存 | 应对需求与提前期波动 | 与服务水平设定相关 |
| 在途库存 | 已下单未到货 | 与提前期相关 |
| 季节库存 | 应对季节性需求 | 与销售曲线相关 |
| 呆滞库存 | 长期无动销 | 与出库记录时间间隔相关 |
| 备件库存 | 保障设备运行 | 与设备台账相关 |

#### 二、分类方法

##### ABC 分类

- 依据年消耗金额（单价 × 年用量）。
- 常规分界：A 约 70%–80% 金额、B 约 15%–20%、C 约 5%–10%，具体由数据决定。
- 结论必须落到差异化管理：A 类高频盘点、严控补货；B 类常规；C 类简化、放宽批量。
- 边界：分类本身不是优化成果。

##### 补充分类

| 方法 | 维度 | 适用 |
|---|---|---|
| CVA | 缺货后果 | 关键备件、停机损失大的物料 |
| VED | 重要性 | 医疗、设备维护 |
| 金额 × 周转率矩阵 | 价值与动销 | 识别高价值慢动销 |

#### 三、控制策略

| 策略 | 触发方式 | 适用条件 |
|---|---|---|
| 定量订货 | 库存降至订货点即订固定量 | 需求相对稳定、A 类 |
| 定期订货 | 固定周期盘点后订至目标位 | 供应周期稳定、C 类 |
| 双箱法 | 一箱用完启另一箱并补货 | 低值易耗 |
| 按需订货 | 接到订单再采购 | 定制、长周期高价品 |
| VMI | 供应商管理库存 | 供应商能力强、信息共享 |

选择依据要写：需求稳定性、订货成本、供应周期、管理能力、资金占用。

#### 四、成本构成

- 采购成本、订货成本、持有成本（资金占用、仓储、保险、损耗）、缺货成本。
- 论文中若做成本比较，必须说明哪些成本可获取、哪些是估算，不能只算持有成本就宣称「总成本下降」。

#### 五、指标

公式统一见 §R05：库存周转率、周转天数、呆滞占比、库存准确率、缺货率、服务水平。

#### 六、问题诊断路径

1. 看结构：金额集中在哪些品类（ABC）。
2. 看周转：哪类周转明显偏低。
3. 看呆滞：无动销天数与金额。
4. 看准确率：账实差异集中在哪些品类。
5. 看补货：是否凭经验订货、有无订货点设定。
6. 找原因：需求预测缺失、批量过大、退货未处理、系统数据不准。

#### 七、写作纪律

1. 每个方法先写适用条件，再写计算，再解释结果。
2. 数据不足时降级为定性分析，不虚构参数。
3. 行业通行做法与本企业实际做法必须分开表述。
4. 不用复杂模型掩盖资料不足。


### R04 · 研究方法库

每个方法一张卡片：用途、操作、需要记录什么、常见误用。

#### 方法卡 1 文献研究法

- 用途：界定概念、找研究缺口、提供方法依据。
- 操作：确定数据库 → 构造检索式 → 筛选 → 纳入 → 归纳。
- 记录：数据库、检索式、时间范围、命中数、纳入数、排除原因。
- 误用：只写「本文采用文献研究法」一句；把文献综述写成文献罗列。

#### 方法卡 2 案例分析法

- 用途：单企业深入分析。
- 操作：选案例（说明典型性与可接触性）→ 收集资料 → 描述现状 → 分析问题 → 提方案。
- 记录：资料清单、时间范围、访谈对象角色（可匿名化）。
- 误用：结论外推到全行业；资料不足仍下定量结论。

#### 方法卡 3 实地观察法

- 用途：流程、布局、作业动作、瓶颈环节。
- 操作：设计观察表 → 定时定点观察 → 记录 → 交叉核对。
- 记录：观察日期、时段、次数、每次时长、观察表编号。
- 误用：写「经过实地调研」但无时间地点；只观察一次就下结论。

#### 方法卡 4 比较分析法

- 用途：不同时段、区域、品类、方案对比。
- 操作：确定比较维度 → 统一口径 → 计算 → 解释差异。
- 记录：比较维度、口径、数据来源。
- 误用：口径不同直接比较；只报差异不解释原因。

#### 方法卡 5 指标分析法（Excel）

- 用途：周转、效率、准确率等定量描述。
- 操作：建数据字典 → 清洗 → 计算 → 图表 → 解释。
- 记录：公式、代入值、结果、口径。
- 误用：平均库存取期末值；用销售额算周转率；异常值直接删。

#### 方法卡 7 情景假设与试算

- 用途：无法实际实施改进时，估算方案效果。
- 操作：设定基准 → 设定假设 → 计算 → 敏感性说明。
- 记录：假设值来源、计算过程、敏感区间。
- 误用：假设值不标注；把试算结果写成「实施后下降 X%」。

#### 资料收集清单

| 资料 | 用途 | 需确认 |
|---|---|---|
| 入库单、出库单 | 吞吐量、作业量 | 时间范围、单位 |
| 库存台账 | 周转、呆滞、结构 | 快照日期、是否含在途 |
| 盘点表 | 准确率 | 抽查方法、样本量 |
| 拣货记录 | 效率、差错 | 是否含复核 |
| 布局图 | 动线、通道 | 版本日期 |
| 访谈记录 | 原因分析 | 对象角色、时间 |

#### 方法章节模板

1. 研究思路（一段话串起全文逻辑）
2. 资料收集（来源、时间、范围、工具）
3. 分析方法（每个方法对应哪个问题）
4. 数据说明（口径、局限）

长度控制在全文 8%–12%。


### R05 · 公式与指标库（全文唯一公式源）

正文只引用本节编号，不重复定义第二遍。每个公式都附口径说明，缺口径的公式不得写入论文。

#### 一、仓储效率类

| 编号 | 指标 | 公式 | 口径必须写明 |
|---|---|---|---|
| W1 | 日均吞吐量 | （入库量 + 出库量）/ 统计天数 | 单位（件/箱/托/吨）、统计期 |
| W2 | 人均拣货量 | 拣货总件数 /（拣货人数 × 天数） | 是否含复核与补货 |
| W3 | 平均拣货时间 | 总拣货工时 / 订单数 | 是否含找货、行走 |
| W4 | 拣货准确率 | 1 − 错拣行数 / 总拣货行数 | 以行还是以订单为单位 |
| W5 | 订单满足率 | 按期完整履约订单数 / 总订单数 | 「按期」「完整」的定义 |
| W6 | 空间利用率 | 已用库位数 / 可用库位数 | 按库位数还是按体积 |
| W7 | 库存准确率 | 账实相符 SKU 数 / 抽查 SKU 数 | 抽查方法与样本量 |
| W8 | 盘点差异率 | 差异金额 / 账面金额 | 差异方向（盘盈/盘亏） |

#### 二、库存类

| 编号 | 指标 | 公式 | 口径必须写明 |
|---|---|---|---|
| I1 | 库存周转率 | 销货成本 / 平均库存 | 平均库存 =（期初 + 期末）/2 或月度均值 |
| I2 | 库存周转天数 | 365 / 周转率 | 或 平均库存 / 日均销货成本 |
| I3 | 呆滞库存占比 | 呆滞金额 / 总库存金额 | 呆滞判定天数阈值 |
| I4 | 缺货率 | 缺货订单行数 / 总订单行数 | 统计粒度 |
| I5 | 服务水平 | 满足需求次数 / 总需求次数 | 周期服务水平还是满足率 |
| I6 | 安全库存 | SS = Z × σd × √LT | Z 取值依据、σ 的时间粒度、LT 单位 |
| I7 | 订货点 | ROP = d × LT + SS | d 为平均单位时间需求 |
| I8 | 经济订货批量 | EOQ = √(2DS / H) | D 年需求、S 订货成本、H 单位年持有成本 |

#### 三、公式使用纪律

1. 参数必须可追溯：每个字母对应哪张表哪个字段。
2. 假设值必须标注：拿不到真实参数时写「假设 S = X 元/次（依据：……）」，并做敏感性说明。
3. 单位一致：σ 用日则 LT 用日；σ 用周则 LT 用周。
4. 平均库存不得只取期末值。
5. 周转率分母用销货成本，不是销售额。
6. 结果必须解释：高或低意味着什么业务后果。
7. 不把试算结果写成实际效果。

#### 四、示例（仅演示计算结构，数值为假设）

某仓库统计期 30 天，出库 12,000 件，拣货人员 6 人：

- 人均拣货量 = 12,000 /（6 × 30）= 66.7 件/人/天（W2）
- 若同期拣货工时合计 1,440 小时，订单 3,600 单，则平均拣货时间 = 1,440 / 3,600 = 0.4 小时/单（W3）

示例中的数字是假设值，写论文时必须换成真实数据，并在数据字典中登记来源。


### R06 · 学术写作与去 AI 味规则（合并版）

来源：junbolian/Academic-Humanizer（MIT）、zczjyq/de-AIGC-skill（无 LICENSE，仅吸收方法论）、cangtianhuang/humanizer-academic-zh（MIT）、本地 writing/humanizer-zh（MIT）。三家重叠约 60%，已合并为一套，**禁止再叠加**。

#### 一、编辑纪律（优先级最高，任何改写先过这一节）

1. 每次改动必须对应一条具名规则；对不上就回退。说不出改的是哪个缺陷，就不要改。
2. 最小充分改动：只改规则命中的部分，相邻文字不动。
3. 不新增：人名、机构、数字、日期、引文、来源、因果、案例，只能来自原文或用户材料。
4. 不减：真实限定词（可能、通常、在某些情况下、部分样本中）必须保留；删除任何限定词都要逐条报告。
5. 结构不动：标题层级、章节顺序、段落数、列表、表格、图表、引用键保持原位；结构问题写进报告，不擅自重排。

#### 二、内容层模式（命中即改）

| 编号 | 模式 | 判据 | 处理 |
|---|---|---|---|
| C1 | 泛化结尾 | 「具有重要意义」「前景广阔」「提供了新思路」 | 删，或写清具体意义是什么 |
| C2 | 段末总结套句 | 「此案例印证了」「由此可见」「综上所述」 | 全文 ≤1 处，其余删 |
| C3 | 理论起笔 | 段落以「依据/基于 XX 理论」开头 | ≤20% 段落，其余移位到段中或段尾 |
| C4 | 模糊归因 | 「专家认为」「研究表明」无出处 | 0 处；具体化或删除 |
| C5 | 机械编号 | 首先/其次/再次 三段式 | 每段 ≤1 处，打破对称 |
| C6 | 填充短语 | 「值得注意的是」「不难发现」「在当前时间节点」 | 删 |
| C7 | 被动分析套话 | 「该处理体现了」「该设计基于」 | 改直接说明 |
| C8 | 模板化问题陈述 | 「面临的核心问题是」 | 换具体表述 |
| C9 | 三元对称并列 | 三项等长等重 | 打破，按重点分配篇幅 |
| C10 | 空泛升华 | 「深刻揭示」「充分体现」「彰显了」 | 删或换具体动词 |

#### 三、语言层模式

- **AI 高频词**：每段 ≤2 个。优先替换「深刻揭示了 / 具有重要意义 / 不可或缺 / 至关重要的 / 综合运用」。
- **系动词回避**：「作为……的重要载体」「扮演着……的角色」→ 直接用「是」「有」。
- **刻意同义替换**：学术写作同一概念用同一术语，不为避重复换说法。
- **虚假范围**：「从 X 到 Y」两端不在同一维度 → 改具体列举。
- **否定式排比**：「不仅仅是……更是……」全文不重复出现。

#### 四、风格层模式

- 破折号：一段 ≤2 处，且不主动添加。
- 加粗：正文全文 ≤5 处（不含标题、术语定义）。
- 表情符号：0 处。
- 内联标题列表：改连贯段落或简洁编号列表。
- 过度对冲：删同义叠加的限定词，保留真实不确定性。
- 协作痕迹：「希望对你有帮助」「当然！」→ 0 处。

#### 五、硬阈值（输出前逐项核）

| 项 | 上限 |
|---|---|
| 保量（默认档） | 润色后汉字数 ≥ 原文约 92% |
| AI 高频词 | 每段 ≤2 |
| 段末总结套句 | 全文 ≤1 |
| 三元对称并列 | 每段 ≤1 |
| 理论起笔段落 | ≤20% |
| 正文加粗 | ≤5 |
| 泛化结尾 / 模糊归因 | 0 |

用户明确说「可压缩」时才可低于 92%，且不得删数据、核心论点、引用，压缩建议不超过 15%。

##### 5.1 统计单位

保量阈值以**单次处理的全文或全章**为统计单位，不对单段、单句单独判定。短段落里套话占比天然偏高，删除后必然出现大幅字数下降；用单段判定会把合规改写误判为违规。抽样审查按章统计后记录比例，见 §C04。

##### 5.2 套话密集段的「需补料」分支

删除 C1/C2/C6/C10 等套话后，若按 5.1 的统计单位复核仍达不到保量要求：

1. 输出「需补料」清单，列出写清具体意义所缺的事实（统计期、口径来源、业务关联记录等），交用户补充。
2. 标记该处「阈值未达标，待补料后复核」——不判改写失败，也不判通过。
3. **禁止**为凑字数编造内容、重复同义句、回填空话、补写未经证实的评价，否则违反第一节「不新增」。
4. 补料到位后按 5.1 重新复核。

优先级：**不新增 > 保量阈值**。阈值用于防止润色丢信息，不是要求把空话补回来。

#### 六、噪声预算

不要过度清洁。每千字保留 2–3 处轻微人类特征（自然的口语化连接、个别长短句失衡）是正常的。把所有句子磨成同一种平滑风格，本身就是新的 AI 痕迹。

#### 七、自检清单

- [ ] 信息没有增加（无新事实/数据/人名/时间/引用）
- [ ] 数字、公式、术语、引用键、参考文献未改动
- [ ] 结构与块形态未变（表格仍是表格）
- [ ] 限定词未丢失，或丢失项已逐条报告
- [ ] 术语全文一致
- [ ] 长短句交替，无全长句段落
- [ ] 未过度清洁
- [ ] 套话密集段已按 5.2 走「需补料」分支，未为凑字数编造内容

#### 八、禁止事项

1. 不承诺通过任何检测平台。
2. 不通过错别字、破坏语法规避检测。
3. 不新增虚假文献、数据、企业事实。
4. 不改变研究结论。
5. 不把「去 AI 味」理解为「越短越好」。

#### 十、章节差异化处理（同一套规则，按章调力度）

| 章节 | 处理重点 | 不做什么 |
|---|---|---|
| 摘要 | 对象/方法/发现/结论准确，一句一事 | 不展开细节、不写意义升华 |
| 绪论 | 背景落具体事实（行业→领域→问题→选题） | 不空泛谈重要性 |
| 文献综述 | 真实归纳、比较、评价，末段有述评 | 不罗列作者不评价、不把他人观点改写后当自己结论 |
| 理论基础 | 概念一次讲准，术语锁定 | 不在后文重复释义（滚动摘要管这个） |
| 现状分析 | 真实流程与事实，标注来源 | 不虚构流程、不写未观察到的环节 |
| 问题分析 | 每个问题有证据、成因有链条 | 不先设结论再倒找证据 |
| 优化方案 | 一条对策对应一个问题，带适用条件 | 不写放之四海皆准的空措施 |
| 结论 | 按研究问题逐条回答，约 600 字三段 | 不抛新问题、不夸大成果 |

参考实测难度（houlaisan 29000 字样本）：实验/数据分析最易降，绪论较难，**摘要与总结展望几乎降不动**（结构本身与 AI 模板重合）。故：**摘要与结论以「写得准」为唯一目标，不为降率牺牲结构**。

#### 十一、内容去重与引用检查（每次润色必跑）

1. **观点/论证去重**：同一论点在多章重复解释 → 合并到首次出现处，后文只做交叉指引（「如 3.2 所述」），不做同义改写凑数。
2. **段落去重**：段首句高度相似（≥13 字重合）视为重复段落，合并或删其一。
3. **文献条目去重**：同一条文献重复著录 → 保留一条，正文角标统一指向它。
4. **文内引用 ↔ 参考文献逐条对应**：角标 `[n]` 必须有对应条目，条目必须被正文引用；断链与孤立条目各为 0。
5. **区分三种情形**：合理引用（有角标、有转述标记）｜规范转述（改述 + 标源）｜不当复制（连续 13 字以上无标注）。第三种一律改写并补角标。
6. **禁止**用同义词替换掩盖来源；改写后仍须保留原作者与出处。
7. **技术坑（必守）**：角标已做成 `fldSimple` 交叉引用域后，`python-docx` 的 `paragraph.text` / `p.runs` **取不到域内文字**，所有文本统计、字数、引用一致性检查都会失真。取字必须走 `p._element.iter(W+'t')`，校验角标必须遍历 `w:fldSimple//w:r`。

#### 十二、修改记录与版本对比（可追溯）

每次润色交付必须附下表，缺项视为未完成：

| 字段 | 要求 |
|---|---|
| 原文 / 改后文本 | 逐段对照，不合并展示 |
| 修改理由 | 对应本节的模式编号（C1–C10 / 语言层 / 风格层），对不上就回退 |
| 字数变化 | 原文汉字数、改后汉字数、保留率（≥92% 才算通过） |
| 保护检查 | 数字、引用角标、文献条目数、术语、专有名词是否变化（变化必须逐条说明） |
| 待人工确认 | 需补料处、判定不了的事实矛盾、可能误删的限定词 |

工具：`python scripts/polish_audit.py 原.docx --compare 改.docx` 直接产出上述四项（保留率/引用组数/数字个数/文献条目数）。

#### 十三、仓储管理专业适配（真实性检查，润色时同步做）

- **作业链六环**：收货验收 → 入库输送与上架 → 在库保管与盘点 → 拣选与复核 → 包装分拨 → 出库，写清每环的岗位、单据、系统动作。
- **库存三项**：库存结构（品类/ABC）、库存准确性（账实一致、盘点差异）、周转与补货（安全库存、补货触发）。
- **人机覆盖**：智能设备实际覆盖哪几环、哪些环节仍靠人工、交接处谁负责（这是混合型仓库最有价值的细节）。
- **三条红线**：未观察到的流程不写成事实；未取得的数据不写成指标；未访谈到的岗位不写成「据某岗位反映」。
- 缺料时输出「需补充真实资料」清单（观察时段、单据类型、访谈对象），**不自行编造**。

#### 十四、检测能力边界（写死在流程里）

1. 第三方检测分数**不等于**作者身份证明，也不等于文本质量评分。
2. **不承诺**维普/知网/学校 AIGC 检测降到某个百分比；引用他人实测数据必须标注为他人样本。
3. 不以「规避检测」为目标做机械改写；一切修改先对应本节的表达缺陷规则。
4. 不伪造错别字、经历、实验、数据、引用。
5. 本地检测（如 Gx664 这类离线工具）只作**段落级风险提示**，与学校系统结果无等价关系。

### R07 · 引用与格式规则

#### 一、优先级

学校模板 > 导师要求 > GB/T 7714-2015 > 学院惯例。冲突时以学校模板为准，并在项目记忆记录版本与日期。

#### 二、文内引用

| 制度 | 写法 | 注意 |
|---|---|---|
| 顺序编码制 | 按出现顺序编号 [1] [2] | 多篇 [1-3] 或 [1,4] |
| 著者-出版年制 | （张三, 2023） | 同年同作者加 a/b |

同一篇论文只用一种制度，不混用。引用具体观点或数据时按学校要求标页码。

#### 三、GB/T 7714-2015 常用格式

- 专著：作者. 书名[M]. 出版地: 出版社, 出版年.
- 期刊：作者. 题名[J]. 刊名, 年, 卷(期): 起止页码.
- 学位论文：作者. 题名[D]. 城市: 学校, 年.
- 会议论文：作者. 题名[C]//论文集名. 出版地: 出版社, 年: 页码.
- 标准：标准号 标准名称[S]. 出版地: 出版社, 年.
- 电子资源：作者. 题名[EB/OL]. (发布日期)[引用日期]. URL.

作者三人以内全列，超过三人列前三人加「等」或「et al.」，按学校模板执行。

#### 四、核验流程

1. 导出参考文献列表。
2. 逐条核对作者、年份、题名、来源、卷期页、DOI。
3. 文内编号与文末条目双向对应。
4. 检查重复条目。
5. 检查标点与分隔符统一。

#### 五、双向对应检查

| 问题 | 表现 | 处理 |
|---|---|---|
| 悬空引用 | 正文有 [12]，文末只有 11 条 | 补条目或改编号 |
| 僵尸文献 | 文末有条目但正文未引用 | 删条目或补引用 |
| 编号错位 | 插入新文献后未重排 | 全文重排并复核 |
| 格式不一 | 同一文献两种写法 | 统一为学校模板格式 |

#### 六、绝不编造

DOI、页码、卷期、作者顺序是最容易编造也最容易被查出的四项。缺失一律标「待补」，向用户确认后填写。

#### 七、与文献矩阵联动

文献矩阵编号与文内引用编号建议保持可追溯映射，改稿时同步更新。

### W01 · 工作流 · 论文项目启动

#### 触发

用户第一次提出要写供应链毕业论文，或要开新题目。

#### 步骤

##### 1. 建项目资料夹

路径由用户指定；未指定时建议 `论文项目/<年份>-<题目关键词>/`。目录结构：

```
<项目>/
├── 00-项目记录.md      题目、边界、学校要求、导师意见、待办
├── 01-资料/            原始数据、单据、布局图、观察记录
├── 02-文献/            文献矩阵、检索记录、PDF
├── 03-草稿/            分章节草稿
├── 04-成稿/            排版后文档
└── 05-审查/            核验报告、去重报告、润色对照
```

##### 2. 填项目记录（必填七项）

| 项 | 内容 |
|---|---|
| 题目 | 暂定题目 + 备选 |
| 方向 | 仓储 / 库存 / 综合 |
| 研究对象 | 具体名称与范围 |
| 资料条件 | A / B / C 档，附证据清单 |
| 学校要求 | 字数、章节、模板、外文文献要求 |
| 术语表 | 概念、缩写、符号，唯一写法 |
| 待办 | 按阶段列 |

##### 3. 判定资料档位并告知用户

按 本文件附录 M 的 01 的三档表判定。若为 B 或 C 档，明确说明哪些定量分析做不了，请用户确认后再继续。

##### 4. 确认下一步

给出阶段清单：开题 → 文献 → 大纲 → 正文 → 去重 → 润色 → 引用 → 终审。让用户选起点。

#### 产出

- 项目目录
- `00-项目记录.md`
- 资料档位判定结论

#### 停止条件

资料档位为 C 且用户仍要求定量分析 → 停下说明冲突，不硬做。


### W02 · 工作流 · 文献检索与综述

#### 步骤

##### 1. 拆检索主题

从研究问题拆出 2–4 个主题块（如「货位分配」「拣选效率」「仓储布局」）。每个主题块单独检索、单独综述。

##### 2. 构造检索式

主题词 + 同义词 + 限定。写入检索记录表：

| 序号 | 数据库 | 检索式 | 时间范围 | 命中 | 纳入 | 排除原因 |
|---|---|---|---|---|---|---|

##### 3. 筛选

按标题 → 摘要 → 全文三层筛。纳入标准：与研究主题相关、方法可参考、来源可核实。排除标准逐条记录。

##### 4. 真实性核验（逐条四关）

可检索 → 信息匹配 → 内容匹配 → 可追溯。任一不过标「待核」，不进入正文引用。

##### 5. 建文献矩阵

用 §T03，填「与本文关系」与「核验状态」。

##### 6. 写综述

按主题组织，每主题五段式：关注什么 → 用了什么方法 → 得出什么 → 还有什么没解决 → 本文做什么。

##### 7. 自检

- 每主题有归纳、对比、缺口
- 研究不足与本文研究内容对应
- 无编造、无无出处归因
- 文献矩阵编号与文内引用可映射

#### 产出

- 检索记录表
- 文献矩阵
- 综述初稿（Markdown）

#### 停止条件

核心主题文献不足 5 篇 → 报告用户，说明是检索式问题还是选题过窄，不靠编造补足。


### W03 · 工作流 · 章节写作

#### 前置

已有大纲与论证链对应表（本文件附录 M 的 07）。没有大纲先写大纲，不直接写正文。

#### 步骤

##### 1. 读上下文

读项目记录中的术语表、上一章末尾过渡、本章大纲条目、对应模块（03/04/05/06）。

##### 2. 写本节三行

- 要证明什么（一句话）
- 用什么证据
- 证据如何支撑

三行写不出 → 回大纲补，不硬写。

##### 3. 写正文

段落结构：主张 → 证据 → 解释 → 衔接。一段一事，超过 300 字无新信息就拆或删。

##### 4. 配图表

图表编号按章节（第 4 章用图 4-1），有标题、单位、来源，正文必须引用并解释。

##### 5. 局部自检

- 每个论断有证据
- 术语与术语表一致
- 无空泛总结、无机械编号、无堆砌理论
- 数字单位规范

##### 6. 更新项目记录

追加本章摘要（3–8 句：核心论点、固定术语、依赖图表编号）。

#### 产出

- 本章草稿（Markdown 或 txt）
- 更新后的章节摘要

#### 停止条件

发现证据不足或数据矛盾 → 停下报告，不用推测补齐。


### W04 · 工作流 · 长文档编辑（润色/去重/一致性）

适用于 1.5 万字以上的论文整体处理。核心是分块 + 记忆 + 比对。

#### 步骤

##### 1. 备份

原稿另存为 `orig-<日期>.md`，改稿写新文件，不覆盖。

##### 2. 建术语表

扫描全文，提取概念、缩写、符号，确定唯一写法。写入项目记录。

##### 3. 分块

按章切分，一章一块。超过 5000 字的章再按小节切。记录块顺序。

##### 4. 逐块处理

每块：

1. 先读术语表与前面各块摘要
2. 按目标执行（去重 / 润色 / 两者）
3. 处理完追加本块摘要（3–8 句）
4. 记录本块改动类型与需确认项

##### 5. 全文比对

- 数字、日期、金额逐项对照原文
- 公式、符号、单位对照
- 术语全文一致性检查
- 引用键、参考文献条目对照
- 章节衔接是否仍然成立

##### 6. 出报告

| 块 | 改动类型 | 删除内容 | 需用户确认 |
|---|---|---|---|

#### 停止条件

出现数据前后矛盾、逻辑断裂、缺图表 → 报告用户，不擅自统一或补写。

#### 禁止

1. 一次改全文不建术语表
2. 改后不回读上下文
3. 把压缩篇幅当作润色目标


### W05 · 工作流 · 内容去重

#### 步骤

##### 1. 章节职责表

给每章写一句话职责。两章职责重叠 → 章节交叉，先处理这个。

##### 2. 段落首句扫描

读每段第一句，意思重复的成组标记。

##### 3. 关键词扫描

提取核心判断句（含结论性词汇的句子），看是否在多处出现。

##### 4. 文献引用统计

统计每个文献被引次数与位置，同一结论重复引用处合并。

##### 5. 参考文献去重

同一文献多条 → 保留格式最完整的一条，统一编号并全文重排。

##### 6. 分级处理（顺序不可颠倒）

1. 章节级：拆分或合并章节内容
2. 段落级：合并同义段
3. 句子级：删重复句、改写衔接

##### 7. 保护清单

必须保留：摘要与结论的呼应（但不照抄）、概念首次定义、章节过渡回指、图表与正文对应说明。

##### 8. 出报告

| 类型 | 位置 | 处理 | 保留位置 | 是否影响论证 |
|---|---|---|---|---|

用户确认后再落盘。

#### 禁止

1. 为降重删证据
2. 把表格折成散文
3. 用同义词替换冒充去重
4. 删完不检查上下文


### W06 · 工作流 · 终审

#### 顺序（不可跳步）

##### 1. 事实核验

逐条检查企业信息、行业数据、政策表述是否有来源。无来源的标出，请用户补或删。用 §C01。

##### 2. 数据核验

勾稽关系、合计、口径、异常值。用 §C02。

##### 3. 逻辑核验

对照论证链对应表：每个问题有证据、有原因、有对策、有效果预估。缺哪环补哪环。

##### 4. 文献核验

真实性 + 文内文末双向对应 + 格式统一。用 §C03。

##### 5. 表达审查

按 §R06 第七节自检，用 §C04。

##### 6. 格式检查

对照学校模板逐项核对，用 §C05。

##### 7. 查重预检

本地相似度自查，输出「疑似重复段落清单」。明确标注：本地预检，非学校正式检测。

##### 8. 出终审报告

| 类别 | 发现数 | 严重度 | 位置 | 建议 |
|---|---|---|---|---|

严重度定义：BLOCKER（不能交稿：事实无来源、数据矛盾、引用造假）、WARNING（很可能返工）、OBS（细节）。

#### 停止条件

存在 BLOCKER 且用户未处理 → 明确告知不能交稿，不写「已完成」。

## 附录 C · 检查清单（全文并入，共 5 项）


### C01 · 检查清单 · 事实核验

#### 一、按事实类型分列

| 类型 | 核验方法 | 可接受来源 | 不通过的处理 |
|---|---|---|---|
| 企业基本信息 | 工商信息、官网、公开年报、用户提供的材料 | 工商系统、官网、用户材料 | 标「待核」，不写 |
| 企业运营数据 | 与用户提供的单据、台账对账 | 原始单据 | 无单据则不写具体数字 |
| 行业数据 | 查原始发布机构 | 统计年鉴、行业协会报告、官方公告 | 找不到原始出处就删 |
| 政策法规 | 查发布机关原文 | 政府网站原文 | 不引用二手转述 |
| 国家标准 | 查标准全文数据库 | 标准原文 | 不凭记忆写标准号 |
| 他人研究结论 | 读原文确认 | 文献原文 | 未读原文不引用其结论 |
| 概念定义 | 教材、标准、权威文献 | 可核实出版物 | 注明出处 |

#### 二、逐条核验记录

| 序号 | 位置（章节/段落） | 事实表述 | 来源 | 是否可核实 | 处理 |
|---|---|---|---|---|---|

「是否可核实」只有三档：可核实 / 待补 / 不成立。不允许写「大概」「应该」。

#### 三、BLOCKER 判定

以下任一项出现即不能交稿：

- 关键数据无来源，且影响结论
- 企业事实与用户提供材料矛盾
- 引用他人研究结论但未读原文
- 编造标准号、政策文号、DOI

#### 四、常见伪事实

1. 「据某机构统计，我国仓储成本占 GDP 的 X%」——来源说不清。
2. 「行业平均水平为 X」——没有行业口径定义。
3. 「该企业年吞吐量约 X 万件」——用户没给，凭印象写。
4. 「研究表明……」——没有具体文献。
5. 「根据国家标准规定……」——没查原文。


### C02 · 检查清单 · 数据完整性

公式一律以 §R05 为准，本清单只查「有没有做对」，不重复列公式。

#### 一、八项必查

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 勾稽关系 | 期初 + 入库 − 出库 = 期末，差异有解释 |
| 2 | 合计校验 | 明细合计 = 汇总合计，误差为 0 |
| 3 | 时间连续 | 无整月缺失、无日期跳跃、无重复日期 |
| 4 | 单位一致 | 同列不混用件/箱/托/吨 |
| 5 | 口径一致 | 金额用成本还是售价，全文统一 |
| 6 | 逻辑合理 | 周转天数不为负、准确率 ≤100%、占比合计 ≈100% |
| 7 | 缺失处理 | 缺失率 >20% 的字段未用于核心结论 |
| 8 | 可复现 | 他人按数据字典与公式能算出同样结果 |

#### 二、数据字典核对

| 字段 | 含义 | 单位 | 来源 | 口径 | 缺失率 | 是否已登记 |
|---|---|---|---|---|---|---|

数据字典缺项 → 该字段的所有指标不可信，先补字典再算。

#### 三、异常值处理记录

| 记录 | 异常值 | 判定依据 | 处理方式 | 是否影响结论 |
|---|---|---|---|---|

处理方式只有三种：保留并说明、修正并说明、剔除并说明。不允许静默删除。

#### 四、BLOCKER 判定

- 勾稽不平且无法解释
- 关键指标计算口径与公式库不一致

### X.1 引言：CARS 三语步（本科适配版）

**来源**：Swales 1990 / Swales & Feak 2012；UMass Amherst、Lund AWELU、MacEwan、Swales 2004 修正（逐条见 §X.8）。

| 语步 | 要做的事 | 可选步骤 | 本科论文落点 |
|---|---|---|---|
| Move 1 确立领域 | 说明主题为何属于一个学术讨论，并回顾既有研究 | 宣称重要性 / 主题概括 / 回顾既有研究 | 研究背景 + 国内外研究现状（引文须在此出现） |
| Move 2 确立缺口 | 指出既有研究的不足或需延伸处 | 反驳 / 指出缺口 / 提问 / 延续传统 | 研究述评末段的「尚待解决的问题」 |
| Move 3 占据缺口 | 说明本文如何回应缺口 | 说明目的 / 介绍本研究 / 主要发现 / 全文结构 | 研究内容、方法、创新点、章节安排 |

**三条本科适配纠偏（比模型本身更重要）**：

1. **本科生不被要求创造新知识**（MacEwan 原话：*Undergraduates are not expected to create new knowledge*）：Move 2 写「本文针对某类场景的证据不足」即可，不要拔高成「填补国内外空白」。
2. **Move 2 可能超纲**（Lund AWELU：*This move may be more advanced than is necessary for some undergraduate essays*）：若学校模板无「研究缺口」独立位置，压成综述末段 1–2 句，不新设标题。
3. **语步可重叠、可乱序**（MacEwan）；Swales 2004 把三语轮改述为「提出领域论题 → 收窄论题 → 介绍当前研究」。不要机械按三语步切三个小节。

**自检**：

- [ ] 引言末段能让读者一句话答出「本文要做什么」
- [ ] Move 1 的每个主题概括都有文内引用，不是「随着…的发展」空起笔
- [ ] 缺口由文献推出，不是凭空断言「目前研究较少」
- [ ] 三语步没有改变 §R01 模板规定的标题、顺序与编号

### X.2 文献综述：结构选择、学术会话与矩阵转段落

**来源**：UNC Writing Center《Literature Reviews》、UMass《Creating a Research Space》、QUT synthesis matrix、Pautasso 2013（§X.8）。

**一、先选组织方式，再动笔**（§M02 已定「按主题不按时间」，此处补**选择判据**）：

| 判据（按顺序问） | 选 | 理由 |
|---|---|---|
| 研究问题关心「认识如何随时间变化」？ | 时间式 | 仅当顺序本身呈现趋势才有意义（UNC） |
| 文献自然分成几个子问题 / 议题？（多数本科论文） | 主题式 | 围绕议题而非单篇文献组织 |
| 结论分歧主要来自**方法**差异？ | 方法论式 | 按研究设计分组，解释分歧来源 |
| 以上混用 | 主题为大节，节内按方法或时间排 | UNC 允许，但全篇只声明一个主组织原则 |

综述引言须写明主组织原则与**刻意排除的范围**；否则导师分不清「有意设边界」与「没查全」。

**二、把「摘要」变成「整合」的可数化自测**：

- 段落主题句主语是**某作者**（「王某发现…」）→ 摘要；主语是**概念或争议**（「关于 X 的效果，现有结论并不一致」）→ 整合。
- 一段只引 1 篇 → 多半仍是摘要；整合段以对领域的判断起笔，引 ≥2 篇并置为证据，收于比较得出的结论。
- **只呈现互相一致的文献是缺陷**：真实领域存在争议；点名两项研究的分歧并给出原因（样本 / 口径 / 方法）才是批判性阅读。
- 保持作者声音：段落以自己观点起、以自己观点收，文献作支撑（UNC 的 Falk & Mills 范例）；少用直接引语，除非原措辞本身是证据。
- **学术会话提问**（UMass 逐字：*What would X author say to Y author?*）：「X 作者会对 Y 作者说什么？是延伸、还是批评？」答不出，说明还没到整合层。

**三、矩阵转段落**（与 §T03 文献矩阵并用，不新建表）：一行一源、一列一主题；**读一列即得一段整合文字**。空白格有信息：某列仅 1 条 → 该主题太窄不足以成节；几乎每源都涉及 → 该节不可省。

### X.3 学术 hedging：语言强度对齐证据强度

**来源**：曼彻斯特大学 Academic Phrasebank「Being cautious」、Hyland（1998 / 2005）分类（§X.8）。

学术传播最显著的风格特征之一，就是在存在微小不确定性时**避免绝对确定**、在存在例外时**避免过度概括**；这种削弱命题认识强度的手段称为 hedging，讨论章（解释发现处）密度最高。

| 证据强度 | 应用语 | 中文例 |
|---|---|---|
| 定义、既有共识 | 直陈，不 hedge | 「是」「表明」 |
| 强、可复现的发现 | 自信 | 「显示」「证实」 |
| 本研究单次结果 | 中等 | 「结果提示」「本文结果说明」 |
| 趋势、部分证据 | 试探 | 「可能」「趋于」「在该样本范围内」 |
| 超出数据的推测 | 明确标注 | 「有待后续研究验证」 |

**功能分类**：缓和（seem / appear / tend to）｜推测（may / might / possibly）｜引用转责（according to / 有研究提示）｜范围限定（generally / 就本案例而言）｜建议保守化（可考虑 / could involve）。

**两类失败模式**：

- **过度断言**：`prove / clearly / obviously / 必然 / 充分证明` → 把证据抬到它撑不住的高度。
- **过度对冲**：`could perhaps possibly ... might seem to suggest`，或同义限定词叠加 → 论点消失。§R06 四已给删法，此处补判据：**一句里出现 ≥2 个同义限定词即判过度**。

**何时不 hedge**：既定事实、术语定义、研究方法描述、本人已明确验证的结果，一律直陈。

**与 §R06 的关系**：R06 编辑纪律第 4 条要求「真实限定词必须保留、删除逐条报告」。本节是它的**分级校准表**，不是替代品；**严禁以「去 AI 味」为由删限定词**——两者冲突时 R06 优先。

### X.4 AIGC 检测：原理与已知缺陷（纠偏，非规避指南）

**来源**：Liang et al. 2023《Patterns》(Cell Press)、ScienceDirect 2024 大样本复验、Cell《Patterns》评论、Weber-Wulff et al. 2023、THE 报道（§X.8）。

**原理（只作解释，不作操作目标）**：多数检测器基于 **perplexity**（下一个词的可预测程度：越易预测＝越低＝越判为模型生成）、**burstiness**（句长与结构的变化度）与文体计量特征。

| 结论 | 数据 / 出处 |
|---|---|
| 非母语写作者被系统性误判 | 7 个公开检测器把 **61.3%** 非母语英语作文误判为 AI；母语组仅 **5.1%**（Liang et al. 2023, Stanford / Patterns） |
| 误判机制 | 非母语写作词汇与句法多样性低 → perplexity 偏低 → 与模型输出混淆；ICLR 2023 论文中非英语母语第一作者论文 perplexity 亦更低 |
| 检出率极易被操纵 | 一句「用更文学化的语言改写」的自编辑 prompt 使检出率降至近零；说明分数衡量的是**表层统计特征**，不是作者身份 |
| 商业宣称不可核验 | 多数检测器闭源、无公开测试集，「99% 准确率」缺乏独立验证条件 |
| 复验与总体判断 | ScienceDirect 2024 用 GRE 大样本系统检验偏差；Weber-Wulff 2023 测 14 个工具无一准确可靠；Cell Patterns 评论认为检测器与 LLM 是「军备竞赛」，纯技术方案不足，关键是**透明使用的规范** |

**由此得出本技能的四条写作层结论（可执行）**：

1. 检测分数既不是作者身份证明，也不是学术质量分（§R06 十四已有此条，此处补权威依据）。
2. **绝不为降分数而破坏学术表达**：删限定词、砍论证、把术语换同义词、人为制造句长波动，都是用检测器偏好取代学术正确性。§R06 十五已留存实证失败案例（首版 224 字虽「更像人写」但删掉实践意义 → 判失败回退）。
3. **不迁移英文检测逻辑到中文**：上述 perplexity 证据全部来自英文语料与英文检测器；中文本科论文的检测机制、分词与训练语料均不同，不据此推断中文改写策略。
4. **不提供规避操作、不承诺分数**（§二 / §M10 五 / §R06 十四红线不变）。

**实拉诚信登记**：本轮 WebSearch 中出现的商业 humanizer 站点（WriteMask / HumanizerTech / TrueSight / HumanizeThisAI 等）以「降 AIGC 率」为营销话术，**全部不采纳为方法论来源**，仅登记其存在；Purdue OWL 目标页返回 404，未冒充抓取，改用 UMass / Lund / MacEwan 三源交叉。

### X.5 学术诚信与生成式 AI 使用声明

**来源**：COPE 2024 作者资格立场、Curtin Research Toolkit「Acknowledging use」、UPC 图书馆声明要素、University of Louisiana 2025 GAI 指南、ICAI 六价值（§X.8）。

**一、五条硬规则**

1. **AI 工具不能列为作者**：无法对作品负责、无法声明利益冲突、无法管理版权与许可（COPE 2024 逐字立场）。
2. **学位论文必须代表本人原创工作**：使用过 GenAI 须披露**软件名 + 版本**（放方法或致谢），建议附录列出所用 prompts，并与导师保持透明（Curtin）。
3. **不得把 AI 输出当作权威来源引用**：一律回到原始文献、官方数据或一手资料（Curtin）。与 §M02 三「文献真实性四关」联动——AI 生成的参考文献必须逐条核验，编造文献属伪造。
4. **敏感数据不得进入开放 AI 工具**（Louisiana 2025）：企业真实单据、库存与作业指标、未公开的企业名与地名、受访者信息，一律不贴入外部模型；拿不准就按「非安全环境」处理。**供应链论文尤其适用**（本技能 §M08 / §R06 十三的三条红线同源）。
5. **作者对全文负全责**，包括 AI 参与产生的部分；未披露地提交 AI 生成的实质章节，多数高校按抄袭或代写处理。

**二、声明六要素（UPC）**：工具及版本 ｜ 使用目的 ｜ 涉及的具体章节 ｜ 作者对生成结果的复核与编辑 ｜ 作者对内容的责任声明 ｜ 有永久链接时的书目引用。

**三、过程留证优于检测分数**：保留笔记、大纲、草稿版本历史、检索记录、AI 对话日志，是面对质疑时最有力的自证。

**四、本科适配边界**：是否写声明、写在哪一章、用何种措辞，**一律以学校 / 导师当期规定为准**；本技能不替用户决定、不编造校方政策，只提示核对并给出上述要素清单。

### X.6 结果与讨论：图表信息完整性与结论边界

**来源**：浙江大学本科生毕业论文（设计）编写规则、浙江工业大学参考格式、Manchester Phrasebank（§X.8）。

1. **图表与正文分工**：表承担精确值，正文承担解释——不逐格复述表中数字，只点趋势、例外与含义。
2. **自明性（信息层，非版式层）**：不看正文也能读懂——变量、单位、样本量 / 统计口径、时间范围、数据来源齐备。§R01 已规定三线表、题注、续表、交叉引用等**版式**，本条只管**信息完整性**，不重复格式条文。
3. **讨论章 hedging 密度最高**：解释异常与差异用「可能的原因是…」「不能排除 X 的干扰」「由于样本限制，结果需谨慎解读」。
4. **结论边界**：准确、完整、明确、精炼；交代局限；不写资料不足以支撑的推论、不成熟论断；不把单案例结论推广到全行业。与 §M12 四答辩题「你的结论能推广吗？局限是什么？」同源。

## 附录 Y · 开题报告可行性、证据链与一致性校验

> 本附录补的是「减法与校验」，不重复 §M01 选题、§M07 大纲、§R01 零版式、§X.1–X.6 学术写作方法论。

### Y.1 资料可得性决定标题存废

每个三级标题都必须能回答「用什么材料写这一节」。答不出，就删、并或降级，不能先留着标题等后面补数据。

四类高危标题（无一手材料时不得出现）：

| 类型 | 典型措辞 | 缺什么 |
|---|---|---|
| 定量指标 | 作业效率、准确率、及时率、观测口径 | 连续实测数据与计算口径 |
| 内部日志 | 设备故障、系统数据脱节、WCS 运行 | 运维台账与系统日志 |
| 时序波动 | 业务量、到货节奏、订单波动 | 分时段单据 |
| 跨仓比较 | 多仓对照、区域对比 | 被允许混用的多仓数据 |

降级手法：把定量承诺改成可观察的作业写实——「作业效率情况」→「作业情况」，「盘点准确性」→「盘点」，「业务量与到货节奏」→「入库作业情况」。研究对象本身的特征（设备、WMS/WCS）保留在现状章，不因缺数据整章删除；也不为体现智能化而强行新增故障、数据脱节、复杂效率指标。

减法不改回结构：导师已确认的结构性调整（如 4.1 问题 / 4.2 原因分开）不因删减而回退。

依据：UNC Writing Center《Grant Proposals》逐字「Be realistic in designing the project.」「Does your project seem feasible? Is it overly ambitious?」；并要求「Make explicit the connections between your research questions and objectives, your objectives and methods, your methods and results」，时间线表格是评审判断 planning and feasibility 的依据。

### Y.2 问题—原因—对策三链闭合

- 4.1 每条问题 → 4.2 恰一条原因 → 5.x 恰一条对策，一一对应。
- 删问题时**必须级联**：同步删对应原因与对策，再整体重编号。禁止留下没有对应问题的独立对策（孤儿对策）。
- 问题减少后，不得为凑章节丰满度新增无证据原因。
- 与 §二 硬约束 6、§M07 论证链对应表的分工：那两处规定「要对应」，本条补的是**删减时的级联动作与编号完整性**。

### Y.3 引用分组：国标允许不等于导师允许

- GB/T 7714—2025《信息与文献 参考文献著录规则》**2026 年 7 月 1 日实施**，当前已生效。
- 顺序编码制国标口径：同一处引多篇，各文献序号在方括号内**完整列出**；连续序号用半字线 `-`，不连续用英文半角逗号 `,`；序号置于点号前；正文引文处用上角标。**国标没有「每组最多几篇」的上限**。
- 国标另规定：文献序号作为句子成分出现时与正文平排、不作上角标。本校口径（§R01 零之八）要求正文角标一律上标，此处以本校为准。
- 导师项目口径（本会话 CHH 批注）：**每组最多 2 篇，且按首次出现顺序**。这是更严的项目级约束，优先于国标的宽松规定。
- 冲突优先级：导师当期书面要求 > 学校格式规则 > GB/T 7714—2025 > 网传教程（与 §R01 零一致）。
- 实操：把 `[1-6]`、`[3-5]`、`[7-26]` 这类长区间拆成 ≤2 篇/组的多组并列，保持首次出现顺序；改完必须按 §R01 零之八第 8 条验每个 run 的**作用范围**，不能只验开关。

## 附录 Z · 开题答辩 PPT 制作与陈述 + 写作方法补强（2026-11-10 实拉，P02）

> **定位**：本附录只补一个实际缺口——开题报告定稿后，**下一步要做的开题答辩 PPT 怎么搭、怎么讲**。不是毕业答辩（讲结果），是开题答辩（讲计划与可行性）。写作方法补强见 Z.6。

### Z.1 开题 vs 毕业答辩 PPT 的本质区别
- **开题答辩 PPT**：核心是「为什么做 / 做什么 / 怎么做 / 可行性」，**不要求有结果**，重点是研究设计与资料可得性。
- **毕业答辩 PPT**：核心是「做了什么 / 得出什么 / 创新点」，结果页是重头戏。
- 混用后果：开题放一堆"预期成果"被导师质疑空洞；毕业还大讲背景被嫌啰嗦。

### Z.2 开题答辩 PPT 标准结构（逐页清单，约 10–12 页 / 5–8 分钟）
按"口头陈述逻辑"组织，**不要直接抄论文目录**。
1. 封面：题目（最大字号）、答辩人、导师、学院、日期；可加校徽，背景简洁。
2. 目录：3–5 个板块（研究背景 / 研究内容 / 方法 / 进度 / 预期），给评委预期。
3. 研究背景与意义：从现实问题或理论缺口切入，用数据/图强化，回答"为什么做"。
4. 文献综述与研究缺口：前人做了什么、还有什么没解决，**引出你的切入点**（与 §X.2 综述写作同源）。
5. 研究内容：条目化"研究谁+在哪+研究什么"，对应已定稿提纲 3/4/5 章。
6. 研究方法与技术路线：流程图/框架图优先（"用图说话"），标注资料来源与边界。
7. 进度安排：甘特式时间轴，须与本论文进度表一致（届次—时间线校验，见 §Y.4）。
8. 预期成果与创新点：2–3 点，不夸大，实事求是。
9. 可能存在的困难与对策：主动说明资料边界（呼应匿名/资料可得性，§Y.1）。
10. 致谢：简短真诚。

### Z.3 每页设计规范（一页一观点）
- **一页只讲一个核心观点**，页间逻辑衔接清晰（UNC Speeches：用 preview/summary 口头 cue）。
- **字少图多**：每页正文 ≤6 行，删到只剩关键词和结论句；详细解释留口头。图表必须含标题、坐标轴标签、图例、数据来源。
- **字号**：标题 ≥32pt、正文 ≥24pt、备注 ≥14pt，保证后排看清；特殊字体勿用（答辩教室电脑可能缺），或提前嵌入字体。
- **配色**：全篇 ≤3 色，学术稳重色系（深蓝/深灰/白，可借校徽主色）；忌红绿撞色、彩虹渐变、浅底浅字。
- **动画克制**：每页 ≤2 个，仅"出现/淡入"强调重点；转场统一。
- **禁忌**：论文整段复制到 PPT；缺页码；低分辨率截图；3D 图表/渐变填充。

### Z.4 陈述节奏与问答预案
- 语速 180–250 字/分钟；5–8 分钟自述约 1000–2000 字讲稿。时间分配：背景 15% / 内容方法 30% / 进度预期 40% / 总结 15%。
- 图表页停留 1–1.5 分钟，文字页 30–45 秒。
- 问答预案（结合 §M12 四 + 本论文实际）：
  - "为什么选 S 公司/上海智能仓？" → 实习可得一手资料，但仅作形态参考原型，不坐实单一企业（§R01 六匿名口径）。
  - "资料够吗？怎么来？" → 平台名+样本量+主动承认一个无关痛痒局限（㊱）；不写无实测的效率/设备故障（§Y.1）。
  - "为什么问题与原因分开写（4.1/4.2）？" → 导师明确要求，避免成因与问题机械重复。
  - "进度表为什么是 2026–2027？" → 本届时间线统一（§Y.4）。

### Z.5 生成路由
- 实际生成 .pptx 走 `workbuddy-pptx` 技能（本文件只管内容与结构，不并排版引擎）。
- 终稿开题报告 `终稿_雒天栋开题报告_*.docx` 是 PPT 内容源，先定稿再提取。

### Z.6 写作方法补强（段落层面，UNC Paragraphs 实拉）
- **一段一个控制性观点（controlling idea）**：段落统一于一个主题，所有句子回指论文 thesis（Rosen & Behrens）。
- **主题句（topic sentence）**：多数段落首句点明控制性观点；位置可首/中/尾，但必须在场，否则证据散落读者不知所以。
- **多控制性观点 → 拆段**：一段出现第二个主观点，删冗余或拆分。
- **反向大纲（reverse outline）**：长文修订时对每章提炼一句主旨，检验逻辑流（UNC Honors Theses）——直接服务 §M08 章节写作修订。
- 证据强度对齐语言强度（与 §X.3 hedging 同源）：段落内论断须有证据支撑，无证据不写绝对判断。

### Z.7 来源（2026-11-10 实拉，逐条真实）
- 方法论锚：UNC Writing Center《Speeches》（口头陈述：受众分析、hook、thesis 前置、preview/summary、一图胜千言、练习计时）— writingcenter.unc.edu，CC BY-NC-ND。
- 写作方法锚：UNC Writing Center《Paragraphs》（一段一观点、主题句、反向大纲）— 同上。
- 中文结构惯例：多份商业/模板站（WPS、schooltools、orcapaper、6k6k）对"开题/毕业答辩 PPT 10–25 页、一页一观点、字少图多、字号配色"高度一致，但**均非校方规定、非学术方法论来源**，仅作通行惯例参考，不采纳其自造框架/营销话术（沿用 §X.4 / §Y 判非口径）。
- 优先级：校方模板 > 写作中心方法论 > 通行惯例参考。

- 本附录不并入 `workbuddy-pptx` 的"生成引擎"职责，只沉淀"开题答辩 PPT 内容结构"这一论文域知识。

## 附录 AA · 论文通用小细节速查（2026-11-11 并入，P02）

> **定位**：把「交稿前逐条对照」用的碎片化小细节收成一张速查清单，补 §M10 去 AI 味之外的**语言层**与**报告层**操作动作。路由见 §三 路由表。
> **口径（用户 2026-11-07 定，优先级高于任何来源）**：排版只按学校下发指导手册与本校模板，**本附录不收录外部排版技巧**——原 13 条（分节符、页码罗马数字、题注、三线表、表格跨页续表、图片嵌入型、修订批注等）已停用，不进本文件。版式仍以 §R01 零为唯一准绳。
> **来源性质**：抖音口播与开源 Skill 文本，属**操作提示**，不是规范来源。与校本手册、国标、导师批注冲突时一律以后者为准；不因本节改动任何既有硬规则（§二 八条红线照旧）。

### AA.1 引用与角标（11 条）

1. 角标必须**交叉引用**（引用→交叉引用→类型「编号项」→内容「段落编号」）**再点上标**；手打的不能 Ctrl+点击跳转，查重还会被标红。
2. 参考文献从知网「导出→GB/T 7714」直接复制，**只删前面的序号**，别自己拼；国标版本与生效日按 §Y.3。
3. 类型标识记牢：期刊 **[J]**、学位论文 **[D]**、专著 **[M]**、会议 **[C]**；学位论文写「**城市 + 学校**」。
4. 最常漏三项：**卷、期、起止页码**；有 DOI 就带上。
5. 同一文献多处引用：先设自定义编号 `[1][2][3]`，各处都走交叉引用；检查法＝按住 Ctrl 点编号能否跳转。
6. 一段话引多条**连续**文献：交叉引用**只插首尾两篇**→改域代码→**F9**→中间补短横线设上标；**别手工删括号**，一更新或转 PDF 就复原成乱码。
7. 增删或调序文献后：选中含标注段落→**F9 更新域**；不更新就会出现「文献已删、正文还写 [2]」。
8. **已知内容反查引用**（报告驱动）：论文进查重→拿详细报告→点「详细报告」→选标红句→看右侧「查看来源 / 相似来源」→跳到被比对原文→核对后按 GB/T 7714 著录，再走交叉引用插角标。
9. **此路径第一坑**：报告的「相似来源」**不等于该引的原始文献**，常常正是别人论文里的转述。要么顺藤找到原始出处引一手，要么按规范写「**转引自**」并注明——不得把他人表述直接当自己的引用凑数（否则就是视频开头批的「瞎标＝学术造假」，见 §二 1–2）。
10. **标红≠一律补引用**：确属借用他人观点/数据才补；只是常见表述或自己写得太「标准」，**改写更快**，硬加引用只会稀释文献质量并抬高引用率。
11. **「自动补引用」必须复核**：作者顺序、文献类型标识、卷期页码、年份、DOI 逐项查；商业工具最爱漏卷期页码，也最容易把「相似来源」当原始文献。

> 与 §M11 / §Y.3 的分工：著录格式、多篇著录写法、上角标例外以 §Y.3 为准；本节只管检索路径、Word 操作与交稿自检动作。
> 与 §AA.3 的顺序：**先补引用、再降重**（引用规范化会改变重复率计算口径），理由见 AA.3 第 7 条。

### AA.2 学术表达（20 条，含防御性写作）

**通用（1–11）**

1. 扫第一人称：I / We /「我认为」→「本研究」「本文」「可以认为」「有观点认为」。
2. 换低级口语词：a lot of / big / really /「特别」「很多」「挺好的」。
3. 绝对化断言降级：「证明了 / proves」→「表明 / 暗示 / suggests / indicates」；证据强度与语言强度对齐（§X.3 / §Z.6）。
4. **AI 味三特征自查**：小标题后爱加冒号、爱用破折号；一段拆成 ①②③④；爱用「从多维度探讨」「建立协同机制」这类帽子词——把帽子删掉看还剩什么。
5. **连接词体检**：删掉「因此 / 然而 / 值得注意的是」，段落照样通顺＝这些词是硬搭。
6. 高发句式一：**动宾 +「了」扎堆**（梳理了、明确了、论证了、揭示了）→ 换语序：「对……进行梳理」「将……明确」「针对……总结」。
7. 高发句式二：**「A 的 B 与 C」**（升级版「A 的 B 与 C 的 D」，名词一串套一串）→ 拆成两个动宾短句，换主语换结构。
8. **AI 高频词表对照**：`delve`（深入探讨）、`highlight / underscore / emphasize`、`pivotal`、`intricate`；同篇出现 **2 次以上就换掉或删掉**。
9. **句尾「逗号 + 现在分词」**（`…, highlighting the complexities…`）一篇最多留 1–2 处；一段连着挂，是最易被认出的语法痕迹。
10. **拆「空心句」**：「强调了 X 的作用」只说明「关于什么」、不说明「主张什么」→ 改成「在什么条件下、对谁、产生了什么结果」。
11. **形容词副词全删一遍**：删完句子照样成立＝这些词只是装饰，删。

**防御性写作（12–20，来源见 AA.6）**

12. **删掉「预防质疑」的句子**：一句话既不提供依据、也不说明范围，只为防别人误解，直接删。
13. **否定式限定改正面范围**：不写「这些案例不代表所有情境」，写「本文分析 2015—2023 年某市案例」。
14. **一处分层**：一条主张**最多留一个实质限定**；「可能 / 或许 / 在一定程度上」不许叠三层。
15. **限定只写一次、写在对的地方**：方法、讨论、局限各说一次；摘要、段首句、贡献段、结论里清干净。
16. **删回辩句式**：「值得注意的是」「需要强调的是」「为避免误解」「有人可能会说」——直接说事实。
17. **别为「公平」辩护，直接写控制条件**：写「所有方法使用同一骨干」，不写「为保证公平，所有方法使用同一骨干」。
18. **促销形容词换测量值**：robust / comprehensive / promising /「显著提升」→ 换成数字、协议或具体性质。
19. **删 AI 式自动总结句**：「综上，这些结果充分表明……」类句子删掉；要留就只留一条数据支持的推断。
20. **中文谦辞清一遍**：「仅仅做了初步尝试」「只能提供有限参考」「仍有很大提升空间」→ 直接写做了什么、发现了什么。

**两条判据**

- 正确姿态：**结论 → 证据 → 一句边界**；错误姿态：**预想反对 → 免责 → 理由 → 削弱结论 → 再免责**（后者就是防御性写作）。
- 必留 vs 可删**五问**：①删了会让人误解吗 ②它报告了支持条件吗 ③它是不是在回答想象中的审稿人 ④能不能改成正面陈述 ⑤这句限定是否已重复出现。

> **边界（硬）**：必要限定不得删——影响观点是否成立、如何理解证据、结论适用范围、研究设计、读者能否正确使用结果的限定必须留，只要求只写一次、写进方法/讨论/局限。不得为「显得有力」删掉真实不确定性，不得把相关关系写成因果，不得补造数据与机制（§二 1–3 红线）。

### AA.3 查重与报告解读（9 条 + 红线段）

1. 知网：**连续 13 个字**重复即标红，**同时看段落整体相似度**；维普/万方更偏语义。
2. **改字没用**：换同义词、互译、让 AI 重写在新版上基本失效，必须**改写**（重组织表达、换句式）——方法见 `writing/thesis-aigc-rewrite`。
3. 报告有四个数：**总文字复制比 / 去除引用文献复制比 / 去除本人文献复制比 / 单篇最大重复比**；先问清学校用哪一个，别自己按最严的算。
4. 一般不计入：封面、独创性声明、目录、参考文献；**但中英文摘要算，致谢与作者简历也算**。
5. **表格算重复**；转成图片才不计数——属规避手段，学校要求可编辑数据时**不得使用**（§二 4）。
6. 总相似比＝复写率 + **引用率**；角标不规范会把「引用」算成重复→**先修引用（AA.1）再做降重**。
7. **顺序（已裁定）**：先降 AI（改句式）→ 再按报告降重。两份资料说法相反，取此序的理由是降 AI 动句式会牵动重复率；**最终以本校指定平台实测为准**。
8. AIGC 报告抓的是**句式特征概率**，不是「内容像 AI」；「知网 2026-10-24 升级」「14.6%→74.7%」出自博主实测，**未独立核实，不得当事实对外说**（§二 3）。
9. 免费 AI 检测不可信（实测有工具把知网 80% 判成 0%）；降到学校线以下即可，不必追 0%，**也别为过检测写病句、加口水话**。
10. 红线段（不采纳）：零宽字符、批量替换同义词规避检测 → 学术不端。

### AA.4 通用小细节（13 条）

**题目**：一句话说清「研究谁 + 在哪 + 研究什么」，说不清＝过大；限定词只留 2–3 个，别缩到单个企业，选一类群体。
**文献与综述**：先只看摘要决定下不下；检索切「学位论文」；看被引量与下载量判质量；**开题报告走「国内→国外→述评」，论文正文才用主题式**（已锁例外，见 §X.2）；综述结尾必须有述评。
**绪论与章节**：背景层层收窄（行业→领域→现存问题→落脚选题）；研究意义**理论、现实分开写**；每章开头几百字无标题「导入」；每段第一句是观点句；标题**最多三级**。
**摘要与结论**：摘要只写目的/方法/主要结果/结论；结论约 600 字三段，不再抛新问题；「不足」要具体（「样本仅覆盖某市」而非「样本量小」）。

### AA.5 答辩（18 条）

**现场与应答（1–6）**

1. PPT 15–20 页、每页停留不超 1 分钟，只放结论和图表。
2. 回答走**总分总**（一句话答→分点→一句话收住），不会就老实承认。
3. 被问「数据哪来的」＝平台名 + 样本量 + 主动承认一个无关痛痒的局限。
4. 必带纸质论文（页码与电子版一致）、原始数据/记录本、纸笔。
5. **三备份**（自己电脑 + U 盘两个版本 + 手机一份），提前 15–30 分钟到场拷好 PPT。
6. 5 分钟稿 800 字、讲 4 分半留缓冲，逐字稿不贴 PPT，**只答不辩**，结尾 30 秒谦虚收。

**逐页话术（7–11，毕业答辩）**

7. **首页六要素**：论文标题、校徽/学校 logo、姓名、导师、学院、专业；开场白一句模板——「我是来自 XX 专业的学生 XXX，今天向各位老师汇报我的论文」。
8. **目录固定六板块**：研究背景与意义 → 研究思路与方法 → 创新点 → 研究内容与过程 → 结论 → 不足与展望；后面每页按这六块走，别抄论文目录。
9. **背景页配图**（纯文字显单薄）；**研究意义别说「填补空白」**（老师反感），改说「某方面问题比较突出 + 本研究丰富了该领域研究」；忌「有重大理论价值」这类空话。
10. **研究内容与过程讲足、突出工作量**，过程配流程图；**结论分四点**讲；不足**只提两点**点到为止，展望放最后一页；收尾「谢谢各位老师，请批评指正」。
11. **创新点写给「这题有没有必要做」看的**：切合实际、别喊大，让老师看到研究必要，而不是堆形容词（呼应 §X.3 与 §AA.2 第 18 条）。

**AI 辅助出 PPT（12）**

12. **顺序优先于工具**：别一上来排版——先让 AI 从论文提**大纲**（明确说明「这是做 PPT 用的」），有实验数据必须要求「数据完整进大纲」，再追加本校答辩要求；大纲先校验**数据准确、无遗漏**，通过后才生成 PPT。学校有模板就直接把模板/风格一起给。

**应答骨架（13–18，12 问归并）**

13. **所有问答题共用一个骨架**：先接住（感谢 / 认下那一处）→ 给**具体动作**（不是「会努力」）→ 落到「**哪一章、改什么**」。
14. **三道必背题**：①选题＝自身原因（专业兴趣 + 学术积累）+ 外部价值（学术 + 现实）；②创新点＝内容上属理论/观点/应用创新、方法上属新技术/新模型/跨学科，**一句一个、可验证**；③数据来源＝权威库（知网/万方/国家统计局）+ 导师提供文献 + 调查法的**样本量与覆盖范围** + 同类课题数据必注来源（否则有抄袭嫌疑）。
15. **框架题**按「**由表及里、由浅入深**」讲，落到章节顺序（背景与意义 → 现状分析 → 创新方法），让老师听出逻辑链，别只报目录。
16. **方法题**讲「适配」：定量=数据驱动、定性=理论/案例、文献归纳法打底；每种方法说清**应用场景 + 得出什么结果**，别只报方法名。
17. **改进/不足题**走「**真诚且有方向**」：承认（研究深度、方法多样性、数据丰富度）+ 给客观限制（时间、实验条件）+ 给具体改法（梳理对应章节 → 查经典与最新研究 → 补文献/案例 → 定学习计划）。
18. **完全不会 / 被批评 / 被说考虑不周**：感谢 + 认下具体那一处 + 一句「作为后续延伸方向」或「整理成改进清单逐一落实」；**不辩解、不硬编、不加假引用**（§二 1–3 红线）。

> **12 问 → 一句话骨架（速查）**：选题（兴趣+积累／学术+现实）｜创新点（内容哪一层 + 方法哪一层，可验证）｜数据（库+导师文献+样本量与范围+注来源）｜框架（由表及里，落到章节链）｜方法（定量/定性/文献法，说场景与结果）｜可改进（承认 + 客观限制 + 具体改法）｜不会（谢 + 认 + 后续方向）｜被批评（接受 + 整理清单逐一改）｜需要纠正（梳理章节 + 查经典与最新 + 修正有支撑）｜不够透彻（学习计划：精读专著 + 听讲座）｜有遗漏（先讲遗漏与核心观点的逻辑关联 + 文献/案例补）｜考虑不周（思维导图从时间/空间/主体多维重梳逻辑）。
> **冲突裁定（2026-11-14）**：该文档第 1 问把「填补研究空白」列为可说的学术价值，与本附录第 9 条相反。裁定：**不自称「填补空白」**，改说「该方面研究尚不深入 / 本研究补充了……」，确证无人做过时才用「空白」；理由是与导师「别喊大」口径一致，且评审对「空白」最敏感。

> **AI 流程补充（同源口播经验，非硬规则）**：① 第一版只审**内容框架与数据展示**，不满意内容先改内容，别先动美化；② 内容挤在一页就让它**拆页**；③ 视觉只盯三项——**模板风格统一、标题层级清楚、关键数据/关键词加粗或提亮**，文科偏简洁沉稳、理工科偏图表与流程感；④ AI 生成的**讲稿默认机械**，必须改成「严格控制时间 + 口语自然 + 逻辑清晰」，导出后手工改细节。
> **图文未收录**：抖音图文作品（`note/7580224221429161588` 答辩模板、`note/7572915724395417972` 答辩暗号）平台只返回标题，正文在图片内**抓不到**，未解析、不臆造；模板样式按用户口径（排版只按学校模板）不采。

> 开题答辩（讲计划）与毕业答辩（讲结果）的结构差异见 §Z.1–§Z.4，§Z.2 是开题 10–12 页结构；本节只补毕业答辩逐页话术、应答骨架与现场细节。
