# writing/defensive-writing-audit

## 一、它解决什么

同一句话有两种写法：

- 正确姿态：**结论 → 证据 → 一句边界**
- 防御姿态：**预想反对 → 免责 → 理由 → 削弱结论 → 再免责**

后者读起来「心虚」，不是因为观点弱，而是因为作者在替假想的审稿人打自己的稿。本技能把后者识别出来，改成前者。

## 二、核心判据（三问定性质）

对每一句可疑的话，依次问：

1. **删了会不会让人误解？** 会 → 必要限定，保留；不会 → 进第 2 问。
2. **它报告了支持条件、不确定性或局限吗？** 报告 → 必要限定；不报告 → 进第 3 问。
3. **它的主要作用是不是回答一个想象中的批评？** 是 → 防御性写作，改。

四种判级：`必要限定 / 防御性 / 混合 / 干净`。

严重度：**Critical** = 像回辩、道歉、法务免责；**Major** = 反复限定、为结果开脱、为省略实验辩护、促销形容词；**Minor** = 局部措辞。

**概率判据（觉得模棱两可时用）**：对一句可疑的话，分别估两个概率 —— P1 = 读者会误读该主张，或对该主张发起质疑/攻击；P2 = 读者会提出建设性的追问或延伸建议（不反对原主张）。P1 与 P2 独立、不必互补。
- P1 高 → 必须回应，但回在对应章节一次，不进摘要与段首；
- P1 低、P2 高 → 这是「可延伸」，写进未来工作或讨论，**绝不写进正文当免责**；
- 两者皆低 → 删，不要替读者发明问题。
先估概率、后决定改不改，顺序不能倒；不允许「因为想改所以把概率估高」。

## 三、十四种模式（逐句打标）

| 代号 | 模式 | 典型信号 | 处理 |
|---|---|---|---|
| D1 | 预防式回辩 | 「需要强调的是」「值得注意的是」「为避免误解」「有人可能会说」 | 直接说技术事实 |
| D2 | 重复非主张 | 「本文并不声称……」「这不应被理解为……」 | 正面陈述一次，只划一次范围 |
| D3 | 限定语堆叠 | 一句里 although/while/despite/only/may/might/potentially 叠三层 | 留最强结论，实质限定只留一条并挪到对应章节 |
| D4 | 替弱结果开脱 | 「分数较低可能是因为……」「结果仍令人鼓舞」 | 先报数字；原因有证据才写 |
| D5 | 为省略实验辩护 | 「未做 X 是因为……」「这种比较不公平」 | 重要就在局限里写一次，否则只写评估协议 |
| D6 | 公平性自我辩护 | 「为保证公平，所有方法使用同一骨干」 | 「所有方法使用同一骨干」 |
| D7 | 初步/有限重复 | preliminary / exploratory / 仅初步 | 技术必要时才用 |
| D8 | 法务式免责 | 一长串「不得被解读为」 | 改成一句正面范围 |
| D9 | 无关自我披露 | 不影响效度与复现的过程波折 | 只留科学相关，其余进附录/日志 |
| D10 | 促销补偿 | robust / comprehensive / promising /「显著提升」 | 换测量值、协议或具体性质 |
| D11 | AI 式自动总结 | 「综上，这些结果充分表明……」 | 删；或只留一条数据支持的推断 |
| D12 | 边界过度声明 | 「支持 X，但不能确立 Y」 | 「在评估设定下，X」；Y 放局限说一次 |
| D13 | 绝对化防御 | 「任何方法都会失败」「这保证了」 | 补精确经验或理论条件 |
| D14 | 换词造贡献 | 给标准操作起新名、反复辩护新颖性 | 直接写技术增量 |

## 四、五步审计流程

1. **检测**：逐句标 D1–D14。
2. **定性**：每句判 `必要限定 / 防御性 / 混合 / 干净`。
3. **读者反应**：对「防御性 / 混合」，写一句「审稿人读到会怎么想」。
4. **改写**：先事实→正面范围→一处主张最多一条实质限定→形容词换测量值→写控制条件而非「公平」→弱结果不擅自解释→不越过证据加强→必要时直接删。
5. **全文级**：查重复局限、摘要免责、贡献条里的限定、结论自我削弱、为省略辩护、空泛褒词、重复的 AI 式总结句。

## 五、输出格式（照此交付）

| 位置 | 原句 | 类型 | 严重度 | 是否必要限定 | 为什么像防御 | 审稿人可能反应 | 建议动作 | 改后 |
|---|---|---|---|---|---|---|---|---|

后附三项：
- **防御性写作评分 0–10**：0–2 干净 / 3–4 轻微 / 5–6 明显 / 7–8 强 / 9–10 像回辩或免责通篇。
- **优先删除清单**（3–10 条，按提升读者观感的幅度排序）。
- **必须保留的限定清单**（写明它保护哪一项：观点成立、证据理解、适用范围、研究设计、结果可用性）。

## 六、中文专项

- 习惯性谦辞：**「仅仅做了初步尝试」「只能提供有限参考」「仍有很大提升空间」** → 直接写「本文在两个数据集上评估该方法」。
- 「初步」「可能」「提示」若证据确实如此就保留；不许为显得有力加「显著」「全面领先」。
- 限定只写一次，放方法/讨论/局限；摘要、段首、贡献段、结论里清干净。

## 七、英文专项

- 删叠加 hedge（may potentially suggest that X could possibly...），但**不机械删除 may / suggests / under these conditions**，按证据判断。
- 观察性研究只发现关联，不许写成因果。

## 八、边界（硬规则）

1. **不删必要限定**：影响观点是否成立、如何理解证据、结论适用范围、研究设计、读者能否正确使用结果的，必须保留。
2. **不用「显得有力」换真实性**：不许把不确定写成定论、把相关写成因果。
3. **不补造内容**：示例只示范措辞，不得据示例补数据、机制、因果关系、优势（「三种制度环境」「最适用」这类说法要有原稿依据）。
4. **不替代证据**：观点太大就缩小范围、补证据、理清推理，不允许只在后面加一句「当然也存在局限」。
5. **不改研究操作**：只动表述，不动实验设计、参数与结论指向。

## 十、叙事层：发布会原则（结构级，句子改完再上一层）

§二至§九 处理的是「一句话怎么改」，本节处理「整篇为什么这么组织」。同一批结果，按发布会组织与按工作汇报组织，读者结论完全不同。

**一句话**：论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。任务不是平均呈现所有方面，而是识别最值得发表的那个价值，围绕它组织全部材料。

**六条叙事规则**
1. **只围绕优势组织**：优先找真正领先、独特或不可替代处（新能力/新问题/新机制/更强适用性/更低成本/更优权衡）。不构成优势的内容不进主线。
2. **不写成工作汇报**：不按「先做什么、又试什么、哪些失败」展开。只留最终成立的链条：问题为何重要 → 现有方法为何不够 → 本文给什么新解法 → 证据如何支持。
3. **打不过的维度不设为比赛项目**：某指标不占优，就不要把叙事建立在该指标上；改任务定义、评价维度、应用场景、约束条件或比较口径，明确「本文赢的是另一场更有意义的比赛」。不争夺不属于本文的冠军。
4. **优势必须主动说出来**：不要指望读者自己从表格里发现贡献。写明在什么条件下最好、优势为何出现、解决了什么实际问题。
5. **控制比较范围**：不追「所有数据集所有指标全面领先」。说服力来自主张与证据一致，不是比较项最多。
6. **允许重构故事**：现有结果撑不住原叙事时，不要围着原叙事防守；可重定义问题、重排贡献、重选主结果、重做标题摘要与实验结构。故事服务于最强证据。

**实验必须是论证工具**：每个实验须承担一项职责 —— 证明方法有效 / 证明优势来自关键机制 / 证明在目标场景有价值 / 排除最可能的替代解释。不承担职责的实验删掉、降级、移位或重设计。

**摘要与引言 = 发布会开场**：四件事按序出现 —— 一个重要且未解决的问题 → 现有方法的关键缺口 → 本文独特思路 → 最有分量的结果。不从实现细节、研究过程或大段背景起手，贡献未建立前不提前谈不足。

**结论只强化记忆点**：解决了什么、提出了什么、证明了什么、为何重要。最后一段不得突然新增自我否定或扩大局限。

> 闸门（本技能硬边界，覆盖本条）：重构故事 ≠ 夸大证据。「打不过就不比」只能换**更能反映真实价值的维度**，不能藏结果、改数字、把没做的说成做了；允许不写，不允许写反。

## 十一、不理想材料的处理优先级（照顺序走，不许跳到第 7 条）

1. 删除与核心主张无关的内容；
2. 缩小主张，避免无意义的正面对比；
3. 换更能体现价值的评价维度；
4. 把结果解释为目标差异或合理权衡（须有证据）；
5. 重组实验，让优势成为叙事中心；
6. 重新定义论文故事；
7. **只有在无法回避且确实影响核心结论时**，才做必要说明（写进局限一次）。

先跳到第 7 条（先写一段免责再解释），是这个技能要治的原始病。

## 十二、交稿前八问（不主动给审稿人递刀子）

1. 这句话是否无意中扩大了本文要承担的责任？
2. 是否提出了一个本来没人要求回答的问题？
3. 是否把局部现象描述成了普遍缺陷？
4. 是否用了比证据更宽泛的负面判断？
5. 是否在按「我们做了什么过程」展开？
6. 是否把不领先的指标设成了主战场？
7. 摘要前五句里，问题与贡献都出来了吗？
8. 结论里有没有突然的自我否定？

## 十三、可直接粘贴的短提示词（对话里用，不装 Skill 时）

```
你在协助我写/改论文，全程遵守【发布会原则】：论文是学术发布会，不是项目总结、实验日志或自我审查报告。
1 只围绕本文最强优势组织叙事，不构成优势的内容不进主线；
2 不按"做了什么、试过什么、哪些失败"的过程写，只留：问题为何重要→现有方法为何不够→本文给什么→证据如何支持；
3 禁止自我削弱表达（"遗憾的是""仅""仍明显落后""效果有限""存在严重不足"），不替审稿人总结弱点，不把局部现象写成普遍缺陷；
4 打不过的指标不设为比赛项目，换评价维度/应用场景/比较口径，明确本文赢的是哪一场；
5 不占优的结果不说输：先判断是否必须讨论，再从目标差异、约束或合理权衡解释，或收缩主张避免正面对撞；
6 优势要主动说清：在什么条件下最好、优势为何出现、解决什么问题，别指望读者从表格里发现；
7 每个实验须承担明确论证职责（证明有效/证明机制/证明场景价值/排除替代解释），不承担职责的删或重设计；
8 摘要与引言按"重要问题→现有缺口→本文思路→最硬结果"，不从实现细节起手；结论只强化记忆点。
遇到不理想材料按序：删除→缩小主张→换维度→解释为权衡→重组实验→重定义故事→最后才必要说明。
现在检查下面文字里的防御性写作，逐处指出并给改法；保持原作者用词与段落结构，只做最小改动，不整段重写，没问题的不要动。
```
