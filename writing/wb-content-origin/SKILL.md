# wb-content-origin（选题与内容原型）

来源：GitHub `KKKKhazix/khazix-skills`·`khazix-writer/references/content_methodology.md`（6,171B，2026-11-08 一手实拉，白皮书 v2.0 摘录）。只取选题与结构方法，不复制其风格参数。

## 一、选题交集模型

**好选题 = 你的专业领域 + 读者的普遍兴趣 + 当下的时间节点。** 三者缺一即衰减：只有专业→曲高和寡；只有兴趣→流于肤浅；只有热点→昙花一现。

## 二、HKR 质检（动笔前的唯一闸门）

- **H（Happy）** 有趣、有悬念？标题和开头能让人想点开？
- **K（Knowledge）** 有信息量？看完能学到新东西？
- **R（Resonance）** 能戳中情绪？让人"对对对我也这么想"？

S 级选题三项兼备；及格至少两项；**只占一项必须重审，零项直接放弃**。

## 三、发散：角色代入三视角

- 一个很忙的普通用户：能帮我省时间/解决具体麻烦吗？
- 一个爱玩的朋友：够有趣吗？能让我"卧槽还能这样？"吗？
- 一个焦虑的学习者：能让我学到新东西、有新角度吗？

三视角都无感，说明选题只有"我想写"，没有"他想看"。

## 四、四类写作原型（先定原型再动笔）

| 原型 | 写法核心 | 常见失败 |
|---|---|---|
| 调查实验型 | 亲自下场做一件事，边做边报道发现，每一步带真实反应 | 只讲结论不讲过程，没有层层发现 |
| 产品体验型 | 场景驱动 + 自己的真实感受 + 与其他产品的自然对比，像"跟我一起玩" | 写成参数评测报告 |
| 现象解读型 | 观察→好奇→研究→知识掉落→升维（连接到更大参照） | 停在"这个现象很火" |
| 工具分享型 | 个人故事铺垫 → 自然引出工具 → 自己怎么用 → 效果展示 | 直接"推荐一个好用的 xxx"，等于广告 |

## 五、三类锚点 + 微型故事四拍

锚点：**热点**（流量最大公约数）/ **痛点**（最高频最头疼的问题）/ **炫技点**（工具本身最颠覆的功能）。一个选题至少占一类锚点，最好两类叠加。

包装成微型故事四拍：① 亮出挑战（想解决什么问题）② 展示脑洞（想到什么骚操作）③ 秀出过程（怎么一步步实现，附截图/关键 Prompt）④ 引爆结果（那个让人"卧槽"的作品）。

**准则**：案例必须有独立的观赏价值、创意价值和启发价值；自己都 High 不起来，就不发。

## 六、节奏：偏出去一点，再拉回来

节奏不是文笔，是推进系统。每次围绕主线偏出去一点点（喘口气、长见识、看案例），再用一句话拉回来。**扣主线句要高频出现，一句就够。**

最忌讳：突然偏离主线很远再硬拽回来——读者要花脑力"顺逻辑"，心流断掉。

优先级：专业（底子）→ 观点（方向）→ 主线（绳子）→ 节奏（牵引力）。

## 七、判据

- 选题不过 HKR 两项，不写；过不了角色代入三视角，说明是自嗨题。
- 工具分享没有个人故事包裹，一律按广告处理、退回重写。
- 一篇文章只能有一个主线；出现两次以上"远跳硬拽"，就是结构问题不是文笔问题。
