# 默认工作流：需求驱动·市面搜索

## 核心原则（本技能命中时执行）

1. **需求者视角优先**：不做技术自嗨。方案必须围绕用户的真实场景、痛点、约束条件展开。
2. **市面资源拉满**：动手前先大范围搜索可用的工具、库、服务、API、数据集、开源方案。
3. **证据驱动决策**：搜到的方案给出来源，做优劣对比，推荐必须有依据，不脑补。
4. **复用优先**：能用现成的就不自研，能调 API 就不本地跑，能轻量就不重型。

## 执行流程

### Step 1 — 澄清需求（本技能命中时执行）
- 用户的真实场景是什么？
- 核心痛点/目标是什么？
- 有什么约束？（预算、隐私、离线/在线、性能、平台限制）
- 输出格式和使用方式？
- 如果信息不全，先问清楚再动手。

### Step 2 — 市面搜索（本技能命中时执行，强度与决策代价成正比：选个库 → WebSearch + 1–2 个来源即可；要做长期技术选型 → 才上多源交叉）
- **WebSearch**：搜索相关工具、库、服务、开源项目、教程。
- **社交/社区平台**：微信公众号、知乎、小红书、微博、B站、Twitter/X、Reddit、GitHub Discussions（深度中文舆情 / 近 30 天趋势 → 路由 `research/last30days-cn` 执行器，本技能不重复造抓取）、Discord、Telegram、V2EX、掘金、CSDN 等——搜真实用户经验、踩坑记录、最新动态。
- **电商/生活应用**：
  - 小红书：搜产品测评、使用体验、教程（优先用网页版/分享链接，或 WebSearch 间接获取）。
  - 淘宝/天猫：搜商品规格、价格区间、用户评价（网页版/搜索快照）。
  - 拼多多：搜低价替代品、商品信息（有限，主要靠 WebSearch 间接获取）。
  - 京东：搜数码产品参数、用户评价。
  - 抖音/快手：搜视频教程、产品演示（WebSearch 间接获取或分享链接）。
  - **注意**：这些应用多为封闭生态，优先通过 WebSearch 抓取已索引内容，或使用 `browser-automation` skill 模拟访问。
- **技能市场**：检查是否有现成 skill 可用（`find-skills`）。
- **插件/连接器**：检查是否有 connector 可直接接入数据源。
- **本地环境**：检查用户已装软件、已有脚本、已有数据是否可以复用。
- **多源交叉**：至少搜 2-3 个不同角度，避免单一来源偏见。

### Step 3 — 对比与推荐（本技能命中时执行，强度与决策代价成正比：选个库 → WebSearch + 1–2 个来源即可；要做长期技术选型 → 才上多源交叉）
- 列出候选方案（名称 + 一句话描述 + 适用场景）。
- 用表格对比关键维度：功能覆盖、成本、易用性、维护度、隐私/安全、与当前环境兼容性。
- 给出推荐（首选 + 备选），说明理由。

### Step 4 — 执行或交付（本技能命中时执行，强度与决策代价成正比：选个库 → WebSearch + 1–2 个来源即可；要做长期技术选型 → 才上多源交叉）
- 如果复用现成方案：给出接入/使用步骤，必要时写示例代码。
- 如果必须自研：说明为什么市面方案不满足，给出最简实现。
- 交付物必须可直接使用或运行，不遗留手动步骤。（本技能命中时执行）

## 输出标准（本技能命中时执行）

- 每个推荐方案附来源链接或搜索关键词。
- 对比表格必须包含至少 3 个维度。
- 不确定的地方明确标注「待验证」「信息不足」「基于假设」。
- 禁止只给一个方案而不解释为什么排除其他方案。

## 反模式（本技能命中时禁止）

- ❌ 不问场景直接写代码
- ❌ 只搜到一个方案就停止
- ❌ 推荐没有来源或无法验证的方案
- ❌ 为了炫技选择重型方案
- ❌ 忽略用户已有的工具链和环境
## 评分卡：同一把尺把"谁更强"变成可复核的分（来源：GitHub `affaan-m/ECC`·`.agents/skills/benchmark-methodology/SKILL.md` 9,694B，2026-11-08 一手实拉；逐串命中 `No single composite score` / `score BOTH poles, report separately` / `Calibrate across the set` / `Asserted vs proven`）

对比多家方案时，最容易产出的是"感觉 A 比 B 好"，最难的是**同一证据对任何对象都得到同一个分**。四条纪律：

- **五级锚点先定死，再打分**：1＝缺位/模板化（是负资产）；2＝低于水准（经不起并排看）；3＝合格、行业底线、谁都不拥有；4＝明显强于同行、客户会主动提及；5＝定义品类、对手被迫跟。锚点必须按维度改写，但**每一级的含义全表统一**。
- **禁混合总分**：维度分与张力图分开展示。九维权重只用来决定"叙述详略"，不用来合成一个总分——加权平均会把真正重要的不对称抹平（"某项 5、另一项 1"和"两项都 3"在总分上一样，战略含义完全相反）。
- **张力两极各自打分、永不平均**：客户若以"A × B"定位，就分别给 A、B 打 1–5 并画 2×2；**两极点之间的差距才是洞察**，平均掉等于销毁结论。
- **每分一行理由 + 一条来源**：没有证据的分数是观点，不是基准。自述战绩（"我们交付过 X"）标 asserted，有客户名/可核指标/可验证案例才算 proven；asserted 一律降级。
- **先控三种偏差再定分**：审美亲和（同风格高估、对手的商业强度低估）；新近/炫技（获奖作品可能没有商业深度）；幸存者（营销声量大的不是全部市场，要经评论目录找"安静但强"的）。定分后**跨集并排重读校准**：同一个 4 分对所有对象必须同义，离群的要拉回。
- 判据：**评分卡的价值在可重放**——换一个人拿同一批证据，应得出同一组分数。
## 需求访谈纪律：一次一问、追到具体证据、两次无新增即饱和（来源：GitHub `affaan-m/ECC`·`.agents/skills/brand-discovery/SKILL.md` 7,497B，2026-11-08 一手实拉；逐串命中 `One question at a time` / `Laddering` / `5 Whys` / `two consecutive probes produce no new information` / `projective techniques`）

- **一次只问一个问题**：给出问题清单只会换来清单式回答；每问之后先一句复述，再选"深挖一问"或"收线"，**不许静默跳题**。
- **Laddering**：对每个"是什么"的答案追"这对你为什么重要"，通常 2–4 层才落到真正的价值判断；**5 Whys** 专用于信念/定位类主张，追到根因而非口号。
- **薄答案检测**：泛泛、堆术语、含糊其辞 → 当场要一个具体例子、一段客户故事或一个数字；追问不到具体证据就算这题没问出来。
- **投射技术破僵局（每模块最多一次）**：拟人化（"如果它是个人，会怎么走进这个房间"）；讣告式（"五年后关门，客户会怀念什么、你会后悔没说什么"）；竞争对照（"举一个你佩服但绝不想变成的同行，具体哪里不对"）。
- **饱和信号**：连续两次追问都没有新信息 → 复述收束、写模块；还有新信息就不算完。
- **落盘两段式**：`Raw` 存原话与例子，`Synthesis` 存解读、三个候选表述、开放问题、参与者之间的矛盾；状态文件记录已完成/进行中/下一个模块，支持跨会话续接。
- 判据：**访谈质量不取决于问了多少题，而取决于薄答案有没有被追问成可核验的具体证据**。
