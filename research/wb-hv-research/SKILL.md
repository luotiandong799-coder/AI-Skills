# wb-hv-research（横纵分析法深度研究）

来源：GitHub `KKKKhazix/khazix-skills`·`hv-analysis/SKILL.md`（21,351B，2026-11-08 一手实拉）。只取研究方法，不搬其写作人设。

## 一、取证：三路并行 + 来源分级

- **三路分工**：纵向（起源/创始人背景/发展历程/关键事件/版本迭代/融资/战略转向/危机）、横向（竞品识别/特点与口碑/对比评测/份额）、补充（创始人深度背景/行业环境/社区讨论：GitHub issues、Reddit、X、知乎）。
- **一手优先，二手的循环印证要识别**：产品更新看官方博客 / Release Notes / 创始人推文；融资看官方公告与监管文件；口碑看 issues / 社区原帖；行业看**原创报道而非转载**；原理看 arXiv / 会议论文集。**多家媒体引用同一个错误＝循环印证假象**，不是多源证实。
- **三个时间分开记**：事实发生时间、页面发布时间、页面更新时间——混成一个就是后面所有"当时为什么这么选"的错因。
- **标注纪律**：只有单一二手来源标「单一来源」；各方冲突标「有分歧」并**对称归属**；缺证据标「暂缺」，**不补造**；预测与推断显式标注。价格/规模/现状优先用当前有效来源，旧资料只用于历史叙事。
- **充分性自检三问**：纵向能不能讲成一个完整故事、有没有断层？横向竞品列表全不全、每个够不够做对比？关键事实有没有只靠单一来源就下判断？

## 二、纵向：沿时间轴还原全貌（报告主体）

五要件：**起源追溯**（背景、技术/理念/需求来源、为什么是这批人、当时行业环境、有没有关键触发事件）→ **诞生节点**（首次发布/成立时间、最初形态与今天差在哪）→ **演进历程**（版本、融资、团队、战略、架构、用户规模、合作收购、危机，按时间排）→ **决策逻辑**（每个节点为什么选 A 不选 B、当时约束是什么、哪些早期决策**锁死**了后来路径、什么机制让它越走越深：网络效应/生态绑定/技术栈）→ **阶段划分**（萌芽/快速增长/转型，每段给核心特征与核心矛盾）。

篇幅：完整长报告 6,000–15,000 字，历史越长越靠近上限；宁可写细，不要蜻蜓点水。

## 三、横向：以当下为切面做对比

先判竞品数量再决定写法：
- **场景 A 无直接竞品**：不硬凑对比，改答"为什么没有竞品"（品类太新/壁垒太高/市场太小）、"最可能从哪个方向冒出竞争者"、"有没有间接替代或上一代方案可参照"。
- **场景 B 1–2 个**：逐个深入。
- **场景 C 3 个以上**：取 3–5 个最具代表性的深入，其余简要提及。

四个维度：**核心差异**（技术路线/方法论、产品形态/商业模式、目标用户、优势与短板、定价与体量）；**用户视角**（真实口碑、被提最多的优点与槽点、实际用法与官方定位的偏差——不要写成参数对照表的文字版，要讲清"它活成了什么样、用户选它的真实理由"）；**生态位**（填补了什么空白、在跟谁正面竞争、当前是百花齐放还是两强/一家独大）；**趋势判断**（机会与风险）。

篇幅：3,000–10,000 字。

## 四、交汇：横纵合起来才叫洞察

必答五问：① 纵向里哪些决策/事件，决定了它今天在横向中的位置？② 把主要竞品也放上时间线，起源与演变路径差在哪、这些差异如何造成今天各自的特点？③ 今天的每个**优势**能追溯到哪个历史节点？④ 每个**劣势**能追溯到哪个决策——**当初的"好决策"有没有变成今天的包袱**？⑤ 未来三剧本：最可能的 / 最危险的 / 最乐观的，每个都要有逻辑支撑。

**禁止写成前文缩写版**；篇幅 1,500–3,000 字，用户预算优先。

## 五、判据

- 每个优势与劣势都必须能指到一个具体历史节点，指不出来就是没做完交汇。
- "为什么没有竞品"必须给出机制解释，不能只写"暂无竞品"。
- 事实与判断分开放：先摆事实，再给判断；判断用"我的判断是"，不用定论口吻。
- 取证不全时交付"已有证据 + 明确缺口"，**不许用模型记忆冒充实时检索结果**。
