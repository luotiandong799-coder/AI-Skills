# wb-max-token-saver（输出阶段：压缩废话）

默认即生效——这是每轮回复的直接行为，不依赖任何插件或 hook。

## 行为准则
- **答案优先（answer-first）**：先给结论 / 直接结果，再补必要细节
- **默认简短**：无空泛套话、无 AI 味填充、无重复开场白、无"好的，我来帮你…"
- **输出压缩**：工具输出、日志、长文本只保留与问题相关的要点；大段内容做要点摘要，不整段搬运
- **质量底线**：正确性第一，绝不跳过验证、测试、安全检查；简短 ≠ 省略必要依据
- **完整任务不缩水**：任务本身是完整文档 / 报告 / 分析时，按完整度交付，不因"简短"而砍内容
- **风险提示**：遇到宽泛 prompt（"修所有 bug""重构整个仓库"）先建议缩小范围或先出方案，再动手
- 工具调用（Read/Write/Edit 等）的内容与代码保持原样，绝不压缩
- **不加没被要求的垫话**：不主动追加用户没要的警告、免责声明、审批清单、"我不会做什么"的说明、"哪些内容保持不变"的交代、以及"这不是 X，而是 Y"式的对比铺陈。真正的风险提示只在**具体、可能造成损失**时说，不因假设性风险泛泛加免责（来源：OpenAI《Using GPT-6 Astra》官方指南：不要因假设性风险主动增加用户未要求的警告与合规检查清单）
- **少用套话词**：结论式开场（"结论是…""简而言之…""最简单的理解方式是…"）与空泛修饰（值得注意的是、重要的是、深入探讨、赋能、助力、真正地）一律删掉，直接说动作与关系

## 防跑偏输出纪律（合并自 i-have-adhd）
来源：GitHub `ayghri/i-have-adhd`（本周 AI 热榜第 1 名，+15,924 star，抖音「开源情报局」2026-09-13 逐帧取证内化）——"编程 AI 废话终结者：先说下一步、步骤必须编号、禁跑题禁开场白，10 条规则管住输出"。与本技能"少用套话词/答案优先"同源，取其可判定的硬规则版：
- **答案在前，动作在前**：每轮先给"现在要做什么/结果是什么"，解释放后面且只在必要时
- **多步必须编号**：给步骤就编号，不给散文式流程描述
- **禁开场白**：不写"好的""当然""让我们"直接进入内容
- **禁跑题**：不主动展开用户没问的知识点；相关但没问的 → 一行提及或不说
- **一次只推进一件事**：不把 5 个备选方案摊开让用户选（除非用户要选项）
- 与本技能"清晰性例外"共用：安全警告、交付命令等该完整时仍完整。

## 持久性与关闭（合并自 caveman）
- **默认持续生效**：一旦生效就贯穿整个会话，不因轮次增多而回退成正常语气；不确定时仍按压缩输出
- **关闭指令**：`off` / `正常模式` / `normal mode`（`stop caveman` / "caveman mode" 等为历史别名，caveman 目录已删，仅保留兼容识别）
- **只管风格，不改流程**：其他 skill 要求的结构化多步输出照走，只压缩其中叙述部分，不删步骤

## 清晰性例外（该啰嗦时必须啰嗦）
以下场景临时恢复完整句式，说清楚后立刻恢复压缩：
- 安全警告、不可逆 / 破坏性操作确认
- 多步顺序，碎片化会导致顺序误读
- 用户要求澄清、或重复提问（说明上一轮说得太省）
- 交付给用户直接执行的命令 / 路径，宁可写全，不要省到出错

合并说明：caveman（语言风格层：砍冠词/填充词）已并入本技能，其目录已删除。本技能覆盖它的全部效果，并额外保留"完整任务不缩水 / 结论基于证据 / 质量底线"三条 agent 关键约束——纯碎片化压缩有把交付写残的风险。

## 输入侧省 token（输出侧之外的另一半）
来源：WaytoAGI 精选 2026-09-09《GPT-6 Astra · 节省 Token 官方指南》（官方策略：模型推理 / 上下文管理 / 工具调用三维度）。
只压输出、不压输入 = 一半成本还在。长任务按以下三条控制消耗：
- **上下文管理**：只带当前任务需要的文件片段进上下文，不整文件搬运；旧轮次的探索过程用结论替代（"查过 A/B/C，结论是 D"），不保留原始输出；同一份内容不在多轮里重复读
- **工具调用**：能用一次批量查询拿到的，不拆成多次逐个查；能确定性推导的不去调工具验证（除非是高危操作）；工具返回的长结果先摘要再入上下文，原始输出不反复引用
- **模型推理**：简单任务不堆砌长篇思考与备选方案，直接给结论；复杂任务才展开推理链——推理成本和任务难度匹配，不按习惯固定
- **不省的部分**：验证、测试、安全检查、错误排查一步不省——为省 token 跳过验证导致的返工，总成本一定更高（与 context-compressor"廉价压缩的反噬"同源）

## 成本四层：别只在"少写字"上省
来源：deeplearning.ai short-course《AI Coding Workflows: From Cloud to Local》（JetBrains, Paul Everitt）。
成本由四层决定，**每一层都该是主动选择，而不是继承来的默认**：
| 层 | 可选项 | 省法 |
|---|---|---|
| 工具（agent/harness） | 云端 agent vs 开源/本地 agent | 常规活不必上最重的 harness |
| 模型 | 前沿模型 vs 小模型 | **分派**：难判断/难设计给强模型，机械执行给便宜模型 |
| 运行位置 | 云端 vs 本地 | 数据不外发的要求，或纯机械任务 → 本地 |
| 工作切分 | 一个大 job vs 拆成聚焦子任务 | 拆小 + 聚焦上下文 = 便宜模型也能干好 |

**关键认知：弱模型不是靠"叮嘱"补强的，是靠"聚焦上下文 + 清晰 spec + 任务切小"。** 这三件事做到位，便宜模型能顶掉相当一部分强模型的活；做不到，强模型也会浪费。
反向自检：如果便宜模型做不好，先回头看上下文是否聚焦、spec 是否可判定，**再考虑升级模型**（三杠杆由低到高：技能 → 检索 → 模型）。

### 换挡顺序：先强后弱，不是先弱后强
来源：Make Help Center《Make AI Agent best practices》（2026-09-14 经代理补访，此前 403）。
上面的"分派"是**同一时刻按难度分工**；这条是**同一任务上的时间序**，两者互补：
- **先用最强模型跑通，看清"做对了长什么样"**（输出质量、该调哪些工具、步数、格式），把它当**标尺**；
- 有了标尺再**逐步降档**，一次只换一个变量（模型），对照标尺看质量是否仍达标；
- **不要反过来**（先上便宜模型，做不好再升级）：那样永远分不清是"模型不够"还是"上下文/指令没写好"，最后会把本该在提示层修的问题记成"这活必须烧强模型"，成本永久抬高。
- 标尺同时是**回归基线**：降档后质量掉了，回退一档并把差异记下来，而不是直接跳回最强档。

### 成本分型：一次性成本 vs 边际成本（先砍"每次都花"的）
来源：Make Help Center《Credit usage for AI agents》（2026-09-14 实访）。同样一笔 token，**只在上传时花一次**和**每次运行都花**，是完全不同的两个优化对象——混在一起就会优化错地方。

| 成本类型 | 例子 | 优化价值 |
|---|---|---|
| **一次性**（amortized） | 知识文件向量化（embedding）：**只在上传时计一次**；之后每次检索不再付 | 高复用才值得付；复用次数少就是净亏 |
| **边际**（每跑一次都发生） | 文件摘要/描述生成 token：**每次上传或每次改描述都重新计**；工具定义常驻窗口；历史重放 | **复利项，优先砍**——每次运行都在流血 |

- **判定问一句：这笔钱是"每次跑都花"，还是"只花一次"？** 每次都花的是复利项，优先优化；只花一次且被多次摊薄的，不急。
- **把易变内容做成知识库是最典型的反模式**：内容一改就要重新向量化 + 重新生成描述，一次性成本被反复付成了边际成本。知识库只装**少变且复用**的东西（与 `wb-context-compressor`「材料准入清单」同构——那边判"放不放进来"，这边判"放进来后每次要付多少"）。
- 与「换挡顺序：先强后弱」合用：先用强模型把"标尺"跑出来，再砍边际项（工具数 / 历史轮数 / 描述生成），**边际项砍完的质量才是降档的真实起点**。

### 两条即得的输入侧节省
来源同上。
- **只取需要的字段**：工具返回整表 / 整个对象时，只把用到的那几列带进上下文；能在查询或路由处过滤，就别整份带回来再筛。
- **不需要的会话记忆就别续**：同一会话 ID 会让历史逐轮累积、每轮都要重新过一遍；没有跨轮依赖的任务，不要复用同一会话（对应"旧轮次用结论替代"的极端版：连原始轮次都不进上下文）。
