# wb-ui-visual-qa（界面视觉检查：截图说话，不靠描述）

## 核心原则

**界面问题要靠截图定位，不靠模型脑补布局**。打开页面 → 截图 → 看渲染结果 → 指出问题位置，比"我猜这里可能有问题"可靠得多。

## 与 browser-automation 的分工

| 场景 | 用谁 |
|---|---|
| 打开网页、填表、登录、抓数据、点按钮 | browser-automation |
| **验证页面长什么样、截图找 UI 问题、双端视觉回归** | 本技能 |

判断标准：**任务是"操作"还是"检查"**——操作走 browser-automation，检查走本技能；视觉检查发现异常后要改页面再操作，两个技能配合。

## 执行流程

1. **明确检查面**：桌面端、移动端、还是双端？关键页面/路由清单是什么？改动点是哪块（有 diff/变更列表时按改动点聚焦检查，不整站漫游）。
2. **打开并截图**：逐个页面打开、等渲染完成（JS 内容至少等 2-3 秒或等关键元素出现）、截图保存。
3. **逐张看图定位问题**：对每张截图检查——
   - **布局**：元素重叠、溢出、错位、空白异常、滚动条异常
   - **样式**：颜色/字号/间距不一致、圆角/阴影异常、字体加载失败（豆腐块）
   - **文案**：错别字、截断（...）、换行错乱、中英文混排问题
   - **响应式**：移动端窄屏是否单列换行、触控目标是否过小、是否横向溢出
4. **改动前后对比**：有改动前截图就并排对比；没有就凭页面预期检查。对比时先看"改动影响区"再看全局。
5. **输出问题清单**：每条问题带——位置（哪个页面/哪个区块）、现象（看到什么）、证据（截图）、严重度（阻断/明显/轻微）、修复建议。

## 双端检查要点

**桌面端**：宽屏布局、hover 态（如果可触发）、多列是否正常。
**移动端**：320-390px 窄屏、触控目标 ≥44px、文本不溢出、图片自适应、不依赖 hover。

## 判定纪律

- **截图是证据，描述不是**：没截图不写"看起来没问题"——没看就是没看，标注"未检查"。
- **改动区优先，全局兜底**：有变更时先查改动影响区，再扫全局；无变更时按清单过关键页。
- **分清视觉问题与功能问题**：布局/样式/文案归本技能；点击无响应、接口报错归功能测试，转 browser-automation 或调试流程。
- **不脑补修复**：只定位问题+给建议，具体改法交给开发流程，不越权直接改页面。
