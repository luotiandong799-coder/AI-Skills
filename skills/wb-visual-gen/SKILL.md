# 生成类视觉任务工作流

核心原则：**先定验收标准，再生成**；出错时**定向改**，不重抽卡碰运气。

## 一、五步流水线

| 步 | 动作 | 产出 |
|---|---|---|
| 1 定标 | 把模糊需求拆成可检查项（主体/场景/光线/构图/文字/用途/尺寸），与用户对齐 | 验收清单（见第三节） |
| 2 备料 | 收集参考图、品牌色、文案原文、真实地名/人名；**没有参考就先问或先找，不脑补** | 素材清单 |
| 3 写 prompt | 按通用公式 + 取案例库骨架；默认英文，中文场景保留中文原词 | prompt + 负向约束 |
| 4 生成 | 一次出 1–4 张候选，参数与 prompt 一并记录 | 候选 + 生成记录 |
| 5 验收迭代 | 逐条对照清单自评 → 定位到具体哪一项不达标 → 只改对应变量/参数 → 重生成 | 通过 / 明确卡点 |

**改图（图生图 / 局部编辑）比重新生成高效**：整体构图对、局部不对 → 走局部编辑；整体跑偏 → 才重生成并改 prompt。

## 一·五、输出形态：可控性与灵活性成反比
来源：deeplearning.ai short-course《Build Interactive Agents with Generative UI》（CopilotKit, Atai Barkai）。
**先选产物形态，再选生成方式。** 三档，越往右越灵活、越不可控：
| 档 | 做法 | 可控性 | 什么时候用 |
|---|---|---|---|
| **受控** | 自己造固定组件（图表 / 卡片 / 表单模板） | 最高，样式与字段完全掌握 | 结构固定、要品牌一致、要能长期复用 |
| **声明式** | agent 从一套可复用积木里组合布局 | 中，组合自由但积木受控 | 内容结构多变但要素有限（如报告页、看板） |
| **开放式** | 从零生成界面 / 图形 | 最低，最容易跑偏 | 探索性、一次性、无既有模板可用 |

判断口径：
- **能用受控/声明式解决的，不要上开放式**——开放式看似方便，返工与验收成本最高
- **用户要"能看见、能操作"的产物时，别只给纯文字长段**：该出表格出表格、该给图给图、该做可交互页面就做（这也是 `show_widget` 存在的原因）
- 用开放式生成时，必须先有验收清单（本 skill 第三节），否则无法判断"生成得好不好"

## 二、通用 prompt 公式（生图）

```
主体（人/物 + 具体特征：脸型、发型、肤质、服装）
+ 场景（地点 + 时间 + 环境细节）
+ 光线（光源类型 + 方向 + 色温/色偏）
+ 镜头（焦段/画幅/景别/构图比例 9:16 或 16:9）
+ 材质与质感（胶片颗粒、皮肤毛孔、布料褶皱）
+ 风格参考（35mm film / watercolor / studio photobook）
+ 负向约束（no plastic skin, no airbrushing, no watermark, no text）
```

硬性写法：
- **只替换变量，保留句式结构**——句式是可迁移骨架，改句式 = 丢效果
- 画面有文字：写明「字迹清晰完整 / no watermark」**并重复强调**（最易出乱码字）
- 多图一致：必须带 `100% consistency in ..., identity across all frames`

## 三、验收清单（生成后逐条过，不过就改）

| 检查项 | 不通过的表现 | 定向改法 |
|---|---|---|
| 主体对不对 | 人物/产品特征错、数量错 | 改主体描述，细化到脸型/服装/数量词 |
| 文字对不对 | 乱码、缺字、多字、错字 | 减少画面文字量 + 重复强调清晰；长文改后期排版叠加 |
| 构图/尺寸 | 主体被裁、比例不符 | 显式写画幅比例 + 景别（wide/close-up） |
| 风格一致性 | 多张风格漂移 | 固定风格参考词 + 一致性约束句 |
| 光影质感 | 塑料感、过曝、脏 | 加负向 `no plastic skin / no airbrushing` + 光源描述 |
| 用途适配 | 好看但不能用（无留白、无安全区） | 补用途约束（留白/横竖版/印刷尺寸） |
| 合规 | 伪造截图、真实人物代言、无 AI 标识 | 见第五节红线 |

**"什么算做完"**：清单全过 + 用途可交付（尺寸/格式/标识齐全）。用户没说用途 = 未定标，先问。

## 五、合规红线

第 5、6 类本质是伪造截图/伪造内容：
- **不得**用于造谣、诽谤、诈骗、伪造证件/票据/官方公告、捏造真实人物言论
- 仅限虚构/娱乐/创意演示，**必须主动加可见标识**（水印 "AI 生成" / 图注）
- 用户要求生成可能被误认为真实的截图 → 先提示风险并加标识，不默默生成
- 真实在世人物形象：避免虚假言论/代言场景

## 六、反模式

- 没定验收标准就连抽 10 张，靠"看起来还行"挑 → 返工率最高
- 结果不对就整段重写 prompt → 荡掉原本对的部分；应逐项定位后改对应变量
- 只给一句"帮我画个好看的图"就开工 → 缺素材必返工
- 视频/网页：跳过"对照原稿逐帧/逐区块检查"，直接交付

## 七、与相邻技能的分工

| 场景 | 走谁 |
|---|---|
| 生成图片 / 视频 / 3D / 网页 | **本技能**（生成方向） |
| **读取 / 取证**已有视频画面（抖音链接、逐帧分析、无字幕视频里有什么） | `wb-media-forensics`（反向链路，别混） |
| 确定性图像编辑（裁剪 / 压缩 / 水印 / 格式转换） | `image-processor` |
