# wb-execute-discipline（执行纪律：覆盖零省略，失败不放弃，错不过三）

来源：用户 2026-09-13 三条原话指令（当日学习循环实测提炼）：
1. **"我让你打开的都必须全部学完 一个都不能少"**
2. **"失败了你要继续进去学习 不能失败了就放弃"**
3. **"如果失败2次以上要思考为什么错 不能一直错误的方式进行下去 然后纠错改正优化以后不再一样错"**

## 一、覆盖零省略（原则一）
- 用户点名过的**每一个**目标（站点 / 仓库 / 文件 / 清单项），本轮都必须**真实执行、真实评估**：
  - 不得用"每轮抽 N 个轮换"代替全表
  - 不得用"上轮已做过 / 已评估过"代替本轮实做（结论必须来自本轮）
  - 不得以"预计无价值"为理由预跳过——判定必须来自实做后的证据
- **"完成"的判定** = 真实执行 → 逐条评估 → 有产出就落地 / 无产出记录判据。三项缺一不算完成。
- 目标清单要**显式列出并逐项打勾留痕**，不靠脑子记；漏项 = 违规。

## 二、失败持续攻坚（原则二）
失败（访问失败 / 超时 / 被拦 / 报错）**不等于放弃**，按路径阶梯逐级换路：
1. **直连**（WebFetch / curl 默认路径）
2. **换端点**：镜像站、备用域名、API/JSON 端点、无 www 域名
3. **浏览器渲染**（agent-browser / playwright，可过部分 bot 检查）
4. **替代入口**：站点官方镜像、缓存页、聚合页
- 每级试过仍失败才可标注"本轮未达"；**只要还有一级路没试，就不许写"放弃 / 跳过 / 略过"**。
- 失败必须**如实留痕**（哪级、什么错误、何时），失败项不算完成，下轮优先补。

## 三、失败 ≥2 次必根因诊断（原则三）
同一目标失败 **2 次及以上 → 立即停手，禁止第三次原样重试**：
1. **写假设**：为什么错？（缺依赖？子进程被杀？目标本身不可达？参数/顺序错？前一步污染？）
2. **最小探针验证假设**：查安装态 / 查进程残留 / 单独测可达性 / 退最小参数——用证据否掉或证实假设，不靠猜
3. **纠正后走新路径**：改的是根因（缺 Chromium 就先装，不是延长超时硬冲）；验证新路径通了再继续
4. **根因 = 环境结构性限制**（如沙箱禁 GUI、需 VPN、需人工装依赖）→ 留痕标注"非重试可解 + 解法归属（用户 / 手动步骤）"，不无限重试烧上下文
- 纠错后把教训写进相关技能（如浏览器技能补"前置检查"），**保证同类错不再犯**——这是原则三的终点，不是修完就完。

## 与相邻技能的分工（防抢触发）
| 场景 | 走谁 |
|---|---|
| 单个 bug / 报错的技术诊断循环（重现→最小化→假设→验证→修复→回归） | `wb-debug-loop` |
| 周期任务 / 自进化循环的框架设计（四段循环、沉淀、反馈） | `wb-loop-engineering` |
| **任务级执行纪律：点名目标全量覆盖 + 失败换路攻坚 + 失败≥2次根因诊断** | **本技能** |

## 反模式
- 名单 11 项只做 6 项，把"轮换"当合规 → 违反原则一
- WebFetch 失败一次就写"该站无法访问，跳过" → 违反原则二（还有 3 级路没试）
- 同一条 `open` 命令挂 120s 超时，第二次还原样跑 → 违反原则三（应先查 Chromium 是否已装）
- 失败根因写"网络问题"就结案 → 根因要具体到"哪个依赖/哪个通道/谁的权限"
